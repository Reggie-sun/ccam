ccam એક નાનું કમાન્ડ-લાઇન ટૂલ છે, એવા લોકો માટે જેઓ એક જ કમ્પ્યુટર પર એક કરતાં વધુ Claude Code એકાઉન્ટ વાપરે છે: એક અંગત અને એક કામનું એકાઉન્ટ, અથવા એક લાંબા પ્રોજેક્ટ માટે ઘણાં એકાઉન્ટ.

## સમસ્યા

Claude Code `CLAUDE_CONFIG_DIR` દ્વારા ઘણાં એકાઉન્ટને સમર્થન આપે છે: દરેક એકાઉન્ટ માટે એક ફોલ્ડર. વ્યવહારમાં દરેક ફોલ્ડર એક ટાપુ જેવું છે. સેટિંગ્સ, `CLAUDE.md`, MCP સર્વર, agents અને skills દરેક ફોલ્ડરમાં ફરીથી સેટ કરવાં પડે છે અને હાથથી સરખાં રાખવાં પડે છે. વાતચીત જ્યાં શરૂ થઈ હોય ત્યાં જ રહે છે. અને જ્યારે કોઈ એકાઉન્ટ તેની વપરાશ મર્યાદા સુધી પહોંચે, ત્યારે તમને વાપરવાનો પ્રયત્ન કરતાં જ ખબર પડે છે.

## ccam શું કરે છે

- `ccam add` ફોલ્ડર બનાવે છે, લૉગિન ચલાવે છે અને એકાઉન્ટને શૉર્ટકટ આપે છે: `claude1`, `claude2` વગેરે.
- `ccam work` અને `claude2` તે એકાઉન્ટ તરીકે Claude Code શરૂ કરે છે અને દરેક આર્ગ્યુમેન્ટ કોઈ ફેરફાર વગર આગળ આપે છે.
- MCP સર્વર, સેટિંગ્સ, `CLAUDE.md` અને એક્સટેન્શન્સ લિંક દ્વારા શેર થાય છે, આઇટમ પ્રમાણે અને એકાઉન્ટ પ્રમાણે. લૉગિન ક્યારેય શેર થતાં નથી.
- `ccam usage` દરેક એકાઉન્ટનો 5 કલાકનો અને સાપ્તાહિક વપરાશ બતાવે છે; `ccam next --continue` વાતચીતને આગલા એકાઉન્ટમાં આગળ ચલાવે છે.

## અડચણ ન બનવું

દરેક સેશન પહેલાં ચલાવાતું ટૂલ એવું ન હોવું જોઈએ કે તેનો ખર્ચ તમને દેખાય. ccam એક કૉન્ફિગરેશન ફાઇલ વાંચે છે, દરેક શેર કરેલી લિંકને એક જ system call વડે તપાસે છે, અને પછી પોતાની જગ્યાએ `claude` ચલાવે છે. તે લગભગ 4 મિલિસેકન્ડ ઉમેરે છે, અને તમે કામ કરો ત્યારે તે ચાલતું નથી.

તે તમારી ફાઇલો સાથે પણ કાળજી રાખે છે. શેરિંગમાં દરેક ફેરફાર શરૂ થતાં પહેલાં યોજના છાપે છે અને મૂળ ફાઇલો બૅકઅપ ફોલ્ડરમાં રાખે છે. `ccam doctor` લિંક, પરવાનગીઓ અને લૉગિન તપાસે છે, અને જે સુરક્ષિત રીતે સુધારી શકાય તે સુધારે છે.

## અજમાવી જુઓ

```sh
curl -fsSL https://ccam.dev/install.sh | sh
ccam add
```

ccam ઓપન સોર્સ અને બિનસત્તાવાર છે: તે Anthropic સાથે જોડાયેલું નથી અને Anthropic તેને સમર્થન આપતું નથી. તમે ઘણાં એકાઉન્ટ વાપરી શકો કે નહીં, તે દરેક એકાઉન્ટની શરતો પર આધાર રાખે છે. પ્રતિસાદ અને અનુવાદનું [GitHub](https://github.com/jhyunwoo/ccam) પર સ્વાગત છે.
