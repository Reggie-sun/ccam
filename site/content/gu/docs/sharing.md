દરેક એકાઉન્ટ પોતાનું લૉગિન અલગ રાખે છે. બાકીનું બધું **ગ્રુપ** દ્વારા શેર કરી શકાય છે: ગ્રુપ તે શેર કરે છે તે આઇટમ અને તેમાંનાં એકાઉન્ટ નક્કી કરે છે, અને ccam એ દરેક એકાઉન્ટની ફાઇલોને ગ્રુપના ફોલ્ડર સાથે લિંક કરે છે, તેથી એક એકાઉન્ટમાં કરેલો ફેરફાર એ બધાંમાં દેખાય છે.

## શું શેર કરી શકાય

| આઇટમ | શું શેર થાય છે |
| --- | --- |
| `mcp` | MCP સર્વર: ગ્રુપની `mcp.json`, જે શરૂઆતમાં Claude Code ને આપવામાં આવે છે |
| `settings` | `settings.json`: પરવાનગીઓ, hooks, મૉડલ, સ્ટેટસ લાઇન |
| `memory` | ગ્લોબલ `CLAUDE.md` |
| `extensions` | `agents/`, `commands/`, `skills/`, `plugins/`, `output-styles/`, `rules/` |
| `history` | વાતચીતનો ઇતિહાસ: `projects/` અને `history.jsonl` |

તમારું પહેલું એકાઉન્ટ `default` ગ્રુપ બનાવે છે, જે વાતચીતના ઇતિહાસ સિવાય બધું શેર કરે છે, અને પછીનાં એકાઉન્ટ તેમાં જોડાય છે.

લૉગિન ફાઇલો `.credentials.json` અને `.claude.json` ક્યારેય શેર થતી નથી. ccam ફક્ત નિશ્ચિત યાદીના પાથ જ લિંક કરે છે, અને આ બે ફાઇલો તે યાદીમાં નથી.

આ પેજ રોજિંદાં કામ સમજાવે છે. દરેક ઓપ્શન સુવિધાનાં પેજ પર વર્ણવેલો છે: [ગ્રુપ વડે શેરિંગ](/features/share), [શેર કરેલા MCP સર્વર](/features/mcp) અને [હાલનું સેટઅપ કૉપિ કરવું](/features/migrate).

## ગ્રુપ

```sh
ccam group                                   # the groups, what they share, their accounts
ccam group set default --add history         # every account in default shares history
ccam group add team --items history --members work,side
```

એક એકાઉન્ટ ઘણાં ગ્રુપમાં હોઈ શકે છે, પણ દરેક આઇટમ ફક્ત એક જ ગ્રુપમાંથી આવે છે. તેથી `work` અને `side` વચ્ચે ઇતિહાસ શેર કરવા, પણ તમારાં બીજાં એકાઉન્ટ સાથે નહીં, ઇતિહાસને `default` થી બહાર રાખો અને ઉપર પ્રમાણે એ બેને તેમનું પોતાનું ગ્રુપ આપો. `ccam share work` બતાવે છે કે એકાઉન્ટ શું શેર કરે છે અને કયા ગ્રુપ દ્વારા. [ડેશબોર્ડ](/features/dashboard) તેના Groups ટૅબ પર એ જ કરે છે.

## જ્યારે એકાઉન્ટ શેર કરવાનું શરૂ કરે

જ્યારે કોઈ એકાઉન્ટ કોઈ આઇટમ શેર કરવાનું શરૂ કરે છે (તે કોઈ ગ્રુપમાં જોડાય, કે તેનું ગ્રુપ એ આઇટમ ઉમેરે), ત્યારે ccam:

1. દરેક એકાઉન્ટ માટે જે દરેક ફાઇલ તે ખસેડશે, કૉપિ કરશે કે લિંક કરશે તેની યોજના છાપે છે, અને શરૂ કરતાં પહેલાં પૂછે છે;
2. જો ગ્રુપ હજી ખાલી હોય તો એકાઉન્ટની ફાઇલો ગ્રુપ ફોલ્ડરમાં ખસેડે છે, નહીં તો ગ્રુપમાં હજી ન હોય તેવી ફાઇલો ઉમેરે છે;
3. જ્યારે એક જ ફાઇલ જુદી હોય, ત્યારે પૂછે છે કે ગ્રુપનું વર્ઝન રાખવું, તમારું વાપરવું કે JSON મર્જ કરવું;
4. તમારી મૂળ ફાઇલ એકાઉન્ટ ફોલ્ડરની અંદર `.ccam-backup/<time>/` માં રાખે છે;
5. મૂળ ફાઇલની જગ્યાએ ગ્રુપની લિંક મૂકે છે.

વાતચીતની ફાઇલોનાં નામ તેમના session ID પરથી હોય છે, તેથી ઘણાં એકાઉન્ટનો ઇતિહાસ કોઈ ટકરાવ વગર ભેગો થાય છે.

Claude Code કોઈ એકાઉન્ટ તરીકે ચાલી રહ્યું હોય ત્યારે, ભલે Claude Code ગમે તે રીતે શરૂ થયું હોય (બૅકગ્રાઉન્ડ સેશન પણ), ccam તે એકાઉન્ટ બદલતું નથી, કારણ કે સેશન ખસેડાતી ફાઇલોમાં લખવાનું ચાલુ રાખે છે. પહેલાં તેને બંધ કરો. ccam સેવ કરતાં ઠીક પહેલાં ફરી તપાસે છે, તેથી યોજના રાહ જોતી હતી ત્યારે શરૂ થયેલું સેશન પણ પકડાય છે.

## જ્યારે એકાઉન્ટ શેર કરવાનું બંધ કરે

```sh
ccam group leave team work                   # work leaves the group
ccam group set default --remove history      # nobody in default shares history any more
```

લિંક દૂર થાય છે અને એકાઉન્ટને ગ્રુપની હાલની સામગ્રીની પોતાની નકલ મળે છે; ગ્રુપના MCP સર્વર તેની પોતાની `.claude.json` માં, તેના પોતાના સર્વરની બાજુમાં જાય છે. તેના બદલે ખાલીથી શરૂ કરવા માટે `--fresh` ઉમેરો; ત્યારે યોજના લોડ થવાનું બંધ થતા MCP સર્વરની યાદી આપે છે. `~/.claude` જેવું ઇમ્પોર્ટ કરેલું ફોલ્ડર હંમેશાં નકલ રાખે છે. બીજાં એકાઉન્ટ માટે ગ્રુપ પોતાની સામગ્રી રાખે છે.

## હાલનું સેટઅપ કૉપિ કરો

જો તમે ccam પહેલાં Claude Code વાપર્યું હોય, તો તમારાં સેટિંગ્સ `~/.claude` માં છે. `ccam migrate` તેમને એક ગ્રુપમાં કૉપિ કરે છે, જેથી તે આઇટમ શેર કરતા દરેક એકાઉન્ટને તે મળે:

```sh
ccam migrate
```

ટર્મિનલ પર, ccam પહેલાં આઇટમનું ચેકલિસ્ટ બતાવે છે. વાતચીતના ઇતિહાસ સિવાય બધું ચેક કરેલું હોય છે; કોઈ આઇટમ બદલવા Space અને યોજના જોવા Enter દબાવો. જે આઇટમ માટે ફોલ્ડરમાં કંઈ નથી તેના પર `not found` લખેલું હોય છે.

તે શું કૉપિ કરે છે:

- `settings.json` અને ગ્લોબલ `CLAUDE.md`;
- એક્સટેન્શન્સ `agents/`, `commands/`, `skills/`, `plugins/`, `output-styles/` અને `rules/`;
- તમારા user MCP સર્વર, એટલે કે `~/.claude.json` ની `mcpServers` એન્ટ્રી, ગ્રુપની `mcp.json` માં;
- વાતચીતનો ઇતિહાસ (`projects/` અને `history.jsonl`), પણ ફક્ત તમે `--history` ઉમેરો ત્યારે જ.

સ્રોત ફોલ્ડર ફક્ત વંચાય છે: તેમાંનું કંઈ પણ ખસેડાતું, લિંક થતું કે બદલાતું નથી, અને સાદું `claude` પહેલાંની જેમ જ કામ કરતું રહે છે. લૉગિન ફાઇલો `.credentials.json` અને `.claude.json` ક્યારેય ગ્રુપમાં કૉપિ થતી નથી.

OAuth થી સાઇન ઇન કરતા MCP સર્વર તેમના ટોકન સર્વર યાદીમાં નહીં, પણ લૉગિનમાં રાખે છે. ccam એ સાઇન-ઇન કૉપિ કરતું નથી: કૉપિ કરેલા સાઇન-ઇનમાં એ જ refresh token હોય છે, અને પહેલી વાર તે રિન્યૂ થાય ત્યારે બાકીના દરેક ધારક તે સર્વરમાંથી લૉગઆઉટ થઈ જાય છે, `~/.claude` પણ. યોજના અને સારાંશ એ એકાઉન્ટનાં નામ જણાવે છે જેમણે `/mcp` વડે જાતે સર્વરમાં સાઇન ઇન કરવાનું છે.

કંઈ પણ કૉપિ કરતાં પહેલાં ccam યોજના છાપે છે અને પૂછે છે:

```console
$ ccam migrate
Copy from /home/me/.claude into group default (/home/me/.local/share/ccam/groups/default):
  mcp         ~/.claude.json  new: context7, fs
  settings    settings.json   new: 80 B
  memory      CLAUDE.md       new: 31 B
  extensions  agents/         add 1 file the group lacks (17 B)
              commands/       add 1 file the group lacks (15 B)
              skills/         add 1 file the group lacks (32 B)
              not found, skipped: plugins/, output-styles/, rules/
  Conversation history (projects/, history.jsonl) is not included; add --history to copy it.
Copy these into group default? [y/N] y
✓ Copied into group default: 2 MCP servers, settings.json, CLAUDE.md, agents/, commands/, skills/
Group default: personal
To share them:
  ccam group join default work
```

અંતે ccam ગ્રુપનાં એકાઉન્ટની યાદી બતાવે છે. જો ગ્રુપ હજી કોઈ આઇટમ શેર ન કરતું હોય, અથવા કેટલાંક એકાઉન્ટ તેમાં ન હોય, તો તે બદલતા `ccam group` કમાન્ડ છાપે છે.

જ્યારે ગ્રુપમાં કોઈ ફાઇલની જુદી કૉપિ પહેલેથી હોય, ત્યારે ccam શેરિંગ ચાલુ કરતી વખતે પૂછે છે તેમ જ પૂછે છે: ગ્રુપની કૉપિ રાખવી કે તમારી વાપરવી. `settings.json` અને બીજી JSON ફાઇલો મર્જ પણ કરી શકાય છે, અને `history.jsonl` લાઇન પ્રમાણે. ગ્રુપની અગાઉની કૉપિઓ ગ્રુપ ફોલ્ડરની અંદર `.ccam-backup/<time>/` માં સાચવાય છે.

| ઓપ્શન | અસર |
| --- | --- |
| `--settings`, `--memory`, `--extensions`, `--mcp`, `--history` | ફક્ત તમે નામ આપેલી આઇટમ કૉપિ કરો, ચેકલિસ્ટ વગર; તેમના વગર અને ટર્મિનલની બહાર, વાતચીતના ઇતિહાસ સિવાય બધું |
| `-g`, `--group <group>` | `default` ને બદલે આ ગ્રુપમાં કૉપિ કરો |
| `-y`, `--yes` | પૂછ્યા વગર કૉપિ કરો; કોઈ ફાઇલ જુદી હોય ત્યારે ગ્રુપની કૉપિ રાખો |

કંઈ પણ કૉપિ કર્યા વગર યોજના જોવા માટે કમાન્ડની આગળ `--dry-run` મૂકો, જેમ કે `ccam --dry-run migrate`. બીજા ફોલ્ડરમાંથી કૉપિ કરવા તેનું નામ આપો: `ccam migrate ~/.claude-work --group work`.

## MCP સર્વર

Claude Code MCP સર્વરને લૉગિન સાથે `.claude.json` માં રાખે છે, તેથી એ ફાઇલ શેર કરી શકાતી નથી. ccam શેર કરેલા સર્વર ગ્રુપની `mcp.json` માં રાખે છે અને Claude Code ને `--mcp-config=<group>/mcp.json` સાથે શરૂ કરે છે. તમારા પોતાના `--mcp-config` ઓપ્શન તેની ઉપર લાગુ પડતા રહે છે.

```sh
ccam mcp add fs -- npx -y @modelcontextprotocol/server-filesystem ~/code
ccam mcp list
```

સેશનની અંદર `claude mcp add` વડે ઉમેરેલો સર્વર ફક્ત તે એકાઉન્ટ માટે, અને તમે જે ફોલ્ડરમાં હતા તેના માટે સેવ થાય છે (Claude Code નો local scope; `-s user` તેને દરેક ફોલ્ડરમાં એકાઉન્ટનો સર્વર બનાવે છે). તમે તે એકાઉન્ટ આગલી વખતે શરૂ કરો ત્યારે ccam સર્વરનું નામ, તેના ફોલ્ડર સાથે, અને તેને ગ્રુપમાં ખસેડવાનો કમાન્ડ બતાવે છે:

```sh
ccam mcp import work gh
```

જો ગ્રુપમાં એ જ નામનો બીજો સર્વર પહેલેથી હોય, તો ccam તેને છોડી દે છે અને તેમ જણાવે છે. `--force` ગ્રુપનો સર્વર બદલે છે અને જૂની `mcp.json` ગ્રુપના `.ccam-backup/` ફોલ્ડરમાં રાખે છે.

OAuth થી સાઇન ઇન કરતા MCP સર્વર તેમના ટોકન એકાઉન્ટના લૉગિન સાથે રાખે છે, તેથી દરેક એકાઉન્ટમાં `/mcp` વડે તેમને એક વાર અધિકૃત કરો. જે સર્વરમાં કોઈ એકાઉન્ટ સાઇન ઇન નથી પણ બીજું એકાઉન્ટ છે, તેમનાં નામ `ccam ext` અને `ccam doctor` જણાવે છે.

જો તમે ઇચ્છતા હો કે સર્વર `claude mcp list` અને `/mcp` માં સામાન્ય user સર્વર તરીકે દેખાય, તો `~/.config/ccam/config.toml` માં સૌથી ઉપર, પહેલા `[[group]]`, `[[profile]]` કે `[[folder]]` ની ઉપર, `mcp_strategy = "sync"` સેટ કરો. પછી ccam શરૂ કરતાં પહેલાં તેમને દરેક એકાઉન્ટની `.claude.json` માં લખે છે, Claude Code ના પોતાના file lock હેઠળ અને બૅકઅપ સાથે. એ જ નામનો એકાઉન્ટનો પોતાનો સર્વર એકાઉન્ટનો જ રહે છે, અને ccam તેમ જણાવે છે.

## એક જ ફોલ્ડરમાં બે એકાઉન્ટ

વાતચીતનો ઇતિહાસ શેર કરતાં એકાઉન્ટ એક જ ફાઇલોમાં લખે છે. જો તમે એવા ફોલ્ડરમાં બીજું Claude Code શરૂ કરો જ્યાં એ જ ગ્રુપનું બીજું એકાઉન્ટ પહેલેથી ચાલી રહ્યું હોય, તો ccam તમને ચેતવે છે અને આગળ વધવું કે નહીં તે પૂછે છે.

## જ્યારે કંઈક તૂટે

```sh
ccam doctor
ccam doctor --fix
```

જો કોઈ શેર કરેલો પાથ સામાન્ય ફાઇલ બની ગયો હોય, ઉદાહરણ તરીકે તમે હાથથી બૅકઅપ પાછો મૂક્યો હોય પછી, તો ccam Claude Code શરૂ કરતાં પહેલાં અટકી જાય છે અને `ccam doctor --fix` તરફ નિર્દેશ કરે છે, જે તેને ફરી ગ્રુપ સાથે લિંક કરે છે: ગ્રુપ પાસે કૉપિ ન હોય ત્યારે ફાઇલ ગ્રુપની કૉપિ બને છે, નહીં તો ગ્રુપ પોતાની કૉપિ રાખે છે અને તમારી ફાઇલ બૅકઅપમાં જાય છે, જેનું નામ `--fix` જણાવે છે. અધવચ્ચે અટકેલો ગ્રુપનો ફેરફાર પણ `ccam doctor --fix` પૂરો કરે છે.
