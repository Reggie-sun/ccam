`ccam usage` બતાવે છે કે દરેક એકાઉન્ટે 5 કલાકની અને સાપ્તાહિક મર્યાદામાંથી કેટલું વાપર્યું છે. `ccam next --auto` સૌથી વધુ જગ્યાવાળું એકાઉન્ટ ખોલે છે, અને `--continue` હાલની વાતચીત ત્યાં લઈ જાય છે.

```console
$ ccam usage
 Account     5-hour        Resets    Weekly        Resets    As of
 1 personal  ██████░░  72% 1h 40m    ███░░░░░  41% 3d 6h     just now
 2 work      █░░░░░░░   8% 4h 12m    ██░░░░░░  19% 5d 2h     just now
 3 side      ████████ 100% 22m       █████░░░  68% 1d 9h     12m ago (cached)
→ Most headroom: work   (open it with ccam next --auto)
```

કૉલમ આ પ્રમાણે છે: એકાઉન્ટ, 5 કલાકનો વપરાશ, તે રીસેટ થવામાં બાકી સમય, સાપ્તાહિક વપરાશ, તે રીસેટ થવામાં બાકી સમય, અને આંકડા કેટલા જૂના છે.

## આંકડા ક્યાંથી આવે છે

ccam દરેક એકાઉન્ટના પોતાના લૉગિનનો ઉપયોગ કરીને, બધાં એકાઉન્ટ માટે એકસાથે Anthropic ના usage endpoint ને પૂછે છે. તે દરેક એકાઉન્ટ માટે વધુમાં વધુ 3 સેકન્ડ રાહ જુએ છે અને દરેક એકાઉન્ટનો જવાબ આવતાં જ તેને બતાવે છે.

આ endpoint જાહેર રીતે દસ્તાવેજીકૃત નથી અને બદલાઈ શકે છે. જ્યારે કોઈ request નિષ્ફળ જાય, ત્યારે ccam છેલ્લા જાણીતા આંકડા બતાવે છે અને તેમને કૅશ તરીકે ચિહ્નિત કરે છે. તે આંકડા સાચવ્યા પછી રીસેટ થયેલી વિન્ડો 0% બતાવે છે. જો જવાબનું ફૉર્મેટ બદલાયું હોય તો `ccam doctor` તમને જણાવે છે.

60 સેકન્ડ કરતાં ઓછા સમય પહેલાં મેળવેલા આંકડા ફરીથી વપરાય છે. ઓપ્શન:

| ઓપ્શન | અસર |
| --- | --- |
| `--watch [seconds]` | સતત રિફ્રેશ કરો, ડિફૉલ્ટ રીતે દર 60 સેકન્ડે |
| `--json` | મશીન વાંચી શકે તેવું આઉટપુટ |
| `-v` | મૉડલ પ્રમાણેની સાપ્તાહિક મર્યાદા અને દરેક આંકડો ક્યાંથી આવ્યો તે પણ બતાવો |
| `--no-cache` | હંમેશાં ફરીથી પૂછો |
| `--source cache` | ક્યારેય ન પૂછો; ફક્ત સેવ કરેલા આંકડા બતાવો |

## સમાપ્ત થયેલાં લૉગિન

જ્યારે કોઈ એકાઉન્ટનો access token સમાપ્ત થઈ ગયો હોય, ત્યારે ccam તેને રિન્યૂ કરતું નથી, કારણ કે કોઈ Claude Code સેશન એ જ લૉગિન વાપરતું હોય ત્યારે તેને રિન્યૂ કરવાથી તે સેશન સાઇન આઉટ થઈ શકે છે. એકાઉન્ટને `ccam <name>` વડે એક વાર શરૂ કરો, અને Claude Code તેને રિન્યૂ કરે છે.

`ccam usage --refresh` સમાપ્ત થયેલા ટોકન જાતે રિન્યૂ કરે છે, પણ ફક્ત એવાં એકાઉન્ટ માટે જે ચાલી રહ્યાં નથી. તે macOS Keychain માં કે ઇમ્પોર્ટ કરેલા `~/.claude` માં રાખેલાં લૉગિન ક્યારેય રિન્યૂ કરતું નથી.

## સ્ટેટસ લાઇનમાં વપરાશ

```sh
ccam statusline install
```

પછી Claude Code સ્ટેટસ લાઇનમાં એકાઉન્ટનું નામ અને તેનો વપરાશ બતાવે છે, ઉદાહરણ તરીકે `[work] · Opus · 5h 24% · 7d 41%`. જો તમારી પાસે પહેલેથી સ્ટેટસ લાઇન કમાન્ડ હોય, તો ccam તેને રાખે છે અને તેની આગળ એકાઉન્ટનું નામ મૂકે છે. સ્ટેટસ લાઇન પોતાના આંકડા પણ સેવ કરે છે, જે endpoint જવાબ ન આપે ત્યારે `ccam usage` વાપરે છે.

## સ્વિચ કરવું

```sh
ccam next             # the account after the one you used last
ccam next --auto      # the account with the lowest 5-hour usage
ccam next --continue  # the next account that shares your conversation history
```

`ccam next` લૉગિન ન થયેલાં એકાઉન્ટ છોડી દે છે, અને `--auto` 100% પર પહોંચેલાં એકાઉન્ટ છોડી દે છે. વાતચીત ચાલુ રાખવા માટે બંને એકાઉન્ટ વાતચીતનો ઇતિહાસ શેર કરતાં હોવાં જોઈએ; [શેરિંગ](/docs/sharing) જુઓ.

[વપરાશ મર્યાદા વર્કફ્લો માર્ગદર્શિકા](/guides/usage-limit-workflow) એક પૂરું ઉદાહરણ પગલું દર પગલું બતાવે છે.
