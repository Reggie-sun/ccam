`ccam next` તમે નામ આપ્યા વગર Claude Code ને બીજા એકાઉન્ટ તરીકે ખોલે છે. જ્યારે કોઈ એકાઉન્ટ તેની વપરાશ મર્યાદાએ પહોંચે ત્યારે તેને વાપરો: સાદું `ccam next` છેલ્લે વાપરેલા એકાઉન્ટ પછીનું એકાઉન્ટ લે છે, `--auto` તેની 5 કલાકની વિન્ડોમાં સૌથી વધુ જગ્યાવાળું એકાઉન્ટ લે છે, અને `--continue` છેલ્લી વાતચીત નવા એકાઉન્ટમાં આગળ ચલાવે છે.

## ઉપયોગ

```sh
ccam next                       # the account after the one you used last
ccam next --auto                # the account with the lowest 5-hour usage
ccam next --continue            # the next account that shares history, with claude --continue
ccam next -c --auto             # both: lowest usage among accounts sharing history
ccam next -- -p "summarize"     # pass arguments to claude after --
ccam --dry-run next --auto      # print the choice and the command, start nothing
```

```console
$ ccam --dry-run next
→ personal → work
CLAUDE_CONFIG_DIR=/home/you/.local/share/ccam/profiles/work /usr/local/bin/claude
```

ccam સ્વિચને standard error પર `→ <from> → <to>` તરીકે છાપે છે, પછી `ccam <name>` ની જેમ જ Claude Code ને નવા એકાઉન્ટ તરીકે શરૂ કરે છે. `<from>` એ તમે છેલ્લે વાપરેલું એકાઉન્ટ છે. `--` પછીના આર્ગ્યુમેન્ટ્સ કોઈ ફેરફાર વગર `claude` ને જાય છે.

## ઓપ્શન

| ઓપ્શન | શું કરે છે | ડિફૉલ્ટ |
| --- | --- | --- |
| `--auto` | સૌથી ઓછા 5 કલાકના વપરાશવાળું લૉગિન થયેલું એકાઉન્ટ પસંદ કરે છે, 100% પરનાં એકાઉન્ટ છોડીને | off |
| `-c`, `--continue` | ફક્ત એવાં એકાઉન્ટ ધ્યાનમાં લે છે જે છેલ્લે વાપરેલા એકાઉન્ટ સાથે વાતચીતનો ઇતિહાસ શેર કરે છે, અને `claude --continue` શરૂ કરે છે | off |
| `-- <claude args>` | ccam ના પોતાના આર્ગ્યુમેન્ટ્સ પછી `claude` ને આપવામાં આવતા આર્ગ્યુમેન્ટ્સ | કોઈ નહીં |
| `--dry-run` | માનવામાં આવે છે: Claude Code શરૂ કર્યા વગર કે શરૂઆત નોંધ્યા વગર, `→ <from> → <to>` અને જે કમાન્ડ લાઇન ચલાવશે તે છાપે છે | off |

`--auto` અને `--continue` સાથે કામ કરે છે. `--continue` સાથે, `--continue` તમારા પોતાના આર્ગ્યુમેન્ટ્સ પહેલાં મુકાય છે.

## તે કેવી રીતે કામ કરે છે

ccam દ્વારા થતી દરેક શરૂઆત સમયને `~/.local/state/ccam/last-used/<name>` માં લખે છે. `ccam next` આ ફાઇલો વાંચે છે, કયાં એકાઉન્ટ લૉગિન થયેલાં છે તે તપાસે છે, અને પસંદ કરે છે.

1. `cli.candidates` `config.toml` પરથી દરેક એકાઉન્ટ માટે એક `next.Candidate` બનાવે છે: એકાઉન્ટ, તેની છેલ્લી શરૂઆતનો સમય (`launcher.LastUsed`) અને તેની પાસે લૉગિન છે કે નહીં (`creds.Has`: વાંચી શકાય તેવી `.credentials.json`, અથવા macOS પર Keychain આઇટમ).
2. `--auto` વગર, `next.Rotate` એકાઉન્ટને સ્લૉટ નંબર પ્રમાણે ગોઠવે છે અને સૌથી તાજેતરમાં શરૂ થયેલું એકાઉન્ટ શોધે છે. એ જ એકાઉન્ટ છે જેમાંથી તમે સ્વિચ કરી રહ્યા છો. જો હજી કોઈ એકાઉન્ટ શરૂ ન થયું હોય, તો તે સૌથી નાનો સ્લૉટ છે.
3. ત્યાંથી તે સ્લૉટના ક્રમમાં આગળ વધે છે, છેલ્લા સ્લૉટ પછી ફરી પહેલા પર આવે છે, અને લૉગિન થયેલું પહેલું એકાઉન્ટ પાછું આપે છે.
4. `launcher.LaunchWith` પસંદ કરેલું એકાઉન્ટ બરાબર `ccam <name>` ની જેમ તૈયાર કરે છે અને શરૂ કરે છે: તે એકાઉન્ટની લિંક તપાસે છે, MCP શેરિંગ લાગુ કરે છે, સેશન નોંધે છે અને `syscall.Exec` દ્વારા ccam ને `claude` થી બદલે છે.

આ શોધ છેલ્લે વાપરેલા એકાઉન્ટથી શરૂ થાય છે અને તેના પછીના લૉગિન થયેલા પહેલા એકાઉન્ટ પર અટકે છે:

<!-- motion:next-rotate -->

`work` સૌથી તાજેતરમાં શરૂ થયું હતું, તેથી શોધ તેના પછીથી શરૂ થાય છે. `side` પાસે લૉગિન નથી અને તે છોડી દેવાય છે, અને `lab` પસંદ થાય છે. જો `lab` પણ લૉગઆઉટ હોત, તો શોધ ફરીને `personal` પર આવત (ડાયાગ્રામમાં `% len`). rotation ક્યારેય તમે જ્યાંથી શરૂ કર્યું તે એકાઉન્ટ પાછું આપતું નથી: લૉગિન થયેલું બીજું કોઈ એકાઉન્ટ ન હોય, ત્યારે તે ભૂલ સાથે અટકે છે.

### --auto

`--auto` સ્લૉટના ક્રમને બદલે વપરાશ પરથી નક્કી કરે છે. `cli.pickAuto` લૉગિન થયેલાં એકાઉન્ટ રાખે છે, `ccam usage` જે વાપરે છે તે જ `Fetcher.FetchAll` વડે તેમનો બધો વપરાશ એકસાથે પૂછે છે, અને `usage.Best()` ને પસંદ કરવા દે છે:

<!-- motion:next-auto -->

`usage.Best()` સૌથી ઓછી 5 કલાકની ટકાવારી લે છે અને 100% પરનાં કે અજાણ્યા 5 કલાકના વપરાશવાળાં એકાઉન્ટ છોડી દે છે. lookup `ccam usage` ના નિયમો અનુસરે છે: 60 સેકન્ડથી ઓછા જૂના આંકડા ફરી વપરાય છે, દરેક એકાઉન્ટ પાસે 3 સેકન્ડ હોય છે, અને જે એકાઉન્ટ જવાબ ન આપે કે જેના લૉગિનની મુદત પૂરી થઈ ગઈ હોય, તેને તેના સેવ કરેલા આંકડા પરથી મૂલવવામાં આવે છે. જે સેવ કરેલી વિન્ડોનો રીસેટ સમય વીતી ગયો હોય તે 0% ગણાય છે, તેથી ત્યાર પછી જેની વિન્ડો રીસેટ થઈ હોય તે એકાઉન્ટ અવગણાતું નથી. `--auto` ક્યારેય ટોકન રિન્યૂ કરતું નથી. સાદા rotation થી વિપરીત, `--auto` છેલ્લે વાપરેલું એકાઉન્ટ પણ પસંદ કરી શકે છે, જો તેની પાસે હજી સૌથી વધુ જગ્યા હોય.

### --continue

Claude Code નું `--continue` હાલના ફોલ્ડરની સૌથી તાજેતરની વાતચીત ખોલે છે, જે ત્યારે જ કામ કરે છે જ્યારે નવું એકાઉન્ટ એ વાતચીત જોઈ શકે. તેથી `--continue` સાથે, ccam ફક્ત છેલ્લે વાપરેલા એકાઉન્ટના એ જ `history` ગ્રુપનાં એકાઉન્ટ ધ્યાનમાં લે છે, પછી તમારા આર્ગ્યુમેન્ટ્સની આગળ `--continue` મૂકે છે. જે એકાઉન્ટનો ઇતિહાસ `local` હોય તે કોઈની સાથે શેર કરતાં નથી, તેથી એવા એકાઉન્ટમાંથી `--continue` હંમેશાં નિષ્ફળ જાય છે. પહેલાં `ccam share <name> --history on` વડે શેરિંગ ચાલુ કરો ([શેરિંગ](/docs/sharing) જુઓ).

## સલામતી અને ખાસ કિસ્સા

- લૉગિન વગરનાં એકાઉન્ટ ક્યારેય પસંદ થતાં નથી. લૉગિન થયેલું બીજું કોઈ એકાઉન્ટ ન હોય, ત્યારે સાદું `ccam next` `no logged-in account other than <name>` સાથે અટકે છે.
- `--continue` સાથે અને કોઈ એકાઉન્ટ ઇતિહાસ શેર ન કરતું હોય ત્યારે: `` no other account shares conversation history with <name>. Turn it on with `ccam share <name> --history on` ``.
- `--auto` સાથે અને લૉગિન થયેલું કોઈ એકાઉન્ટ ન હોય ત્યારે: `no logged-in account to pick`. જ્યારે દરેક એકાઉન્ટ ભરાઈ ગયું હોય કે તેનો વપરાશ અજાણ્યો હોય: `` no account with known usage and headroom (see `ccam usage`) ``.
- `--auto` `--dry-run` સાથે પણ નેટવર્ક request કરે છે. તે ફક્ત વાંચે છે, અને ક્યારેય ટોકન ફાઇલો લખતું નથી.
- પસંદ કરેલું એકાઉન્ટ `ccam <name>` ના જ પાથથી શરૂ થાય છે, તેથી એ જ તપાસો લાગુ પડે છે, જેમાં એ જ ઇતિહાસ શેર કરતું બીજું Claude Code આ ફોલ્ડરમાં પહેલેથી ચાલતું હોય ત્યારની ચેતવણી પણ સામેલ છે.
- `last-used` ત્યારે જ લખાય છે જ્યારે Claude Code ખરેખર શરૂ થાય. `--dry-run` તેને અડતું નથી, તેથી dry run rotation ને આગળ ખસેડતું નથી.
