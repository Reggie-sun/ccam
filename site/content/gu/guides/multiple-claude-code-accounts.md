દરેક એકાઉન્ટને પોતાનું કૉન્ફિગરેશન ફોલ્ડર આપો. Claude Code આ ફોલ્ડર `CLAUDE_CONFIG_DIR` environment variable પરથી વાંચે છે, અને દરેક ફોલ્ડરમાં પોતાનું લૉગિન, સેટિંગ્સ અને ઇતિહાસ હોય છે, તેથી દરેક એકાઉન્ટ લૉગિન રહે છે અને તમે તેમને એકસાથે ચલાવી શકો છો. તમે આ હાથથી શેલ alias વડે સેટ કરી શકો છો, અથવા ccam ને તે કરવા દઈ શકો છો.

## હાથથી કેવી રીતે સેટ કરવું?

આ એ જ રીત છે જે [Claude Code ના દસ્તાવેજીકરણમાં વર્ણવેલી છે](https://code.claude.com/docs/en/authentication#log-in-with-multiple-accounts). દરેક વધારાના એકાઉન્ટ માટે `~/.bashrc` કે `~/.zshrc` માં એક લાઇન ઉમેરો:

```sh
alias claude-work='CLAUDE_CONFIG_DIR=~/.claude-work claude'
```

નવું ટર્મિનલ ખોલો અને `claude-work` ચલાવો. ફોલ્ડર નવું હોવાથી Claude Code તમને લૉગિન કરવા કહે છે. ત્યાર પછી `claude` તમારું પહેલું એકાઉન્ટ છે અને `claude-work` બીજું. દરેક એકાઉન્ટ માટે એક alias ઉમેરો, અને દરેકને પોતાનું ફોલ્ડર આપો.

WSL વગરના Windows પર, તમારી પ્રોફાઇલ (`notepad $PROFILE`) માં એક PowerShell function આ જ કામ કરે છે:

```powershell
function claude-work { $env:CLAUDE_CONFIG_DIR = "$HOME\.claude-work"; try { claude @args } finally { Remove-Item Env:CLAUDE_CONFIG_DIR } }
```

## alias વાળી રીતમાં શું ખૂટે છે?

બે એકાઉન્ટ માટે આ સારું કામ કરે છે. જાણવા જેવી બાબતો:

- દરેક ફોલ્ડર ખાલી શરૂ થાય છે: કોઈ સેટિંગ્સ નહીં, કોઈ `CLAUDE.md` નહીં, કોઈ MCP સર્વર નહીં, કોઈ agents કે skills નહીં. તમને જે જોઈએ તે તમે કૉપિ કે લિંક કરો છો, અને નકલોને સરખી રાખવાનું કામ જાતે કરો છો.
- Alias ફક્ત interactive શેલમાં જ હોય છે. સ્ક્રિપ્ટ, Makefile અને બીજા પ્રોગ્રામ તેમને જોઈ શકતા નથી.
- MCP સર્વર લૉગિનની બાજુમાં `.claude.json` માં રહે છે, તેથી તેમને ફોલ્ડર વચ્ચે સહેલાઈથી લિંક કરી શકાતા નથી.
- વાતચીત જે એકાઉન્ટમાં શરૂ થઈ હોય ત્યાં જ રહે છે, તેથી તમે તેને બીજા એકાઉન્ટમાં ચાલુ રાખી શકતા નથી.
- બધાં એકાઉન્ટનો વપરાશ એકસાથે બતાવે એવું કંઈ નથી.

## શું હું તેના બદલે /login વડે એકાઉન્ટ સ્વિચ કરી શકું?

હા, જો તમે ક્યારેક જ સ્વિચ કરતા હો. Claude Code ની અંદર `/login` ટાઇપ કરવાથી તમે જે ફોલ્ડરમાં છો તેનું [એકાઉન્ટ બદલાય છે](https://code.claude.com/docs/en/quickstart). એક સમયે ફક્ત એક જ એકાઉન્ટ લૉગિન રહે છે, તેથી દરેક સ્વિચ વખતે તમારે ફરી લૉગિન કરવું પડે છે, અને તમે બે એકાઉન્ટ સાથે-સાથે ચલાવી શકતા નથી. અલગ ફોલ્ડર આ બંને મુશ્કેલી ટાળે છે.

## ccam વડે કેવી રીતે સેટ કરવું?

ccam આ જ વિચારને આપમેળે કરે છે અને ખૂટતા ભાગ ઉમેરે છે:

```sh
curl -fsSL https://ccam.dev/install.sh | sh
ccam add personal
ccam add work --shortcut ccwork
```

હવે `ccam personal` અને `ccam work` બંને એકાઉન્ટ શરૂ કરે છે, અને `ccwork` પણ, એટલે કે તમે work એકાઉન્ટને આપેલો શૉર્ટકટ. તે alias નહીં પણ ખરેખરા પ્રોગ્રામ છે, તેથી સ્ક્રિપ્ટમાં પણ કામ કરે છે. યાદીમાંથી એકાઉન્ટ પસંદ કરવા માટે ફક્ત `ccam` ચલાવો, અને કોઈ એકાઉન્ટને ડિફૉલ્ટ બનાવવા `ccam use work` ચલાવો.

સેટિંગ્સ, `CLAUDE.md`, MCP સર્વર અને એક્સટેન્શન્સ શરૂઆતથી જ શેર થાય છે. `ccam next --continue` વાતચીતને બીજા એકાઉન્ટમાં લઈ જાય છે, અને શેર કરેલો વાતચીતનો ઇતિહાસ, જે તમે ચાલુ કરી શકો છો, તેને એક જ વાતચીત રાખે છે. `ccam usage` બધાં એકાઉન્ટનો 5 કલાકનો અને સાપ્તાહિક વપરાશ એકસાથે બતાવે છે.

જો તમે પહેલેથી `~/.claude` વાપરતા હો, તો એ એકાઉન્ટ ફરી ઉમેરવાને બદલે `ccam import` ચલાવો, અથવા તેનાં સેટિંગ્સ, MCP સર્વર અને એક્સટેન્શન્સ શેર કરેલાં સેટિંગ્સમાં કૉપિ કરવા `ccam migrate` ચલાવો.

## કયું એકાઉન્ટ ચાલી રહ્યું છે તે કેવી રીતે ખબર પડે?

Claude Code ની અંદર, `/status` બતાવે છે કે તમે કયા એકાઉન્ટમાં લૉગિન છો. ccam સાથે એક વાર `ccam statusline install` ચલાવો, પછી સ્ટેટસ લાઇન હંમેશાં એકાઉન્ટનું નામ અને તેનો વપરાશ બતાવે છે, ઉદાહરણ તરીકે `[work] · Opus · 5h 24% · 7d 41%`.

## શું આ Windows અને WSL પર કામ કરે છે?

Claude Code [Windows પર સીધું અને WSL ની અંદર ચાલે છે](https://code.claude.com/docs/en/setup). `CLAUDE_CONFIG_DIR` બંનેમાં કામ કરે છે, તેથી સીધા Windows પર ઉપરનો alias કે PowerShell function પૂરતો છે. ccam પણ Windows પર સીધું ચાલે છે: તેને PowerShell માં `irm https://ccam.dev/install.ps1 | iex` વડે, કે WSL ની અંદર Linux કમાન્ડ વડે ઇન્સ્ટૉલ કરો. શૉર્ટકટ `ccwork.exe` બને છે, અને `settings.json` જેવી ફાઇલો શેર કરવા Developer Mode જોઈએ ([ccam ઇન્સ્ટૉલ કરો](/docs/install)).

## સમસ્યાનું નિવારણ

**Claude Code મને દર વખતે લૉગિન કરવા કહે છે.** નવા ફોલ્ડરમાં પહેલી વાર શરૂ કરતી વખતે તે હંમેશાં પૂછે છે. જો તે વારંવાર પૂછતું રહે, તો લૉગિનની મુદત પૂરી થઈ ગઈ છે અથવા તે દૂર થઈ ગયું છે: `ccam login work` ચલાવો (અથવા alias એક વાર શરૂ કરીને લૉગિન કરો).

**કોઈ MCP સર્વર ફક્ત એક જ એકાઉન્ટમાં દેખાય છે.** સેશનની અંદર `claude mcp add` વડે ઉમેરેલા સર્વર એ જ એકાઉન્ટના હોય છે, અને `-s user` વગર ફક્ત એ ફોલ્ડરના. કોઈ સર્વરને બધાં એકાઉન્ટમાં લઈ જવા `ccam mcp import work <server>` વાપરો.

**એકાઉન્ટ વચ્ચે સેટિંગ્સ અલગ છે.** `ccam share work` બતાવે છે કે એકાઉન્ટ શું શેર કરે છે અને કયા ગ્રુપ દ્વારા; `ccam group join default work` શું બદલાશે તે બતાવ્યા પછી તેને `default` જે શેર કરે છે તે શેર કરતું કરે છે. `ccam doctor --fix` તૂટેલી લિંક સુધારે છે અને જે ફાઇલ બદલે તે દરેકનો બૅકઅપ રાખે છે.

**બે એકાઉન્ટ એક જ વાતચીત ખોલે છે.** એક જ વાતચીત પર એક જ સમયે બે એકાઉન્ટમાં કામ કરવાનું ટાળો. જો તમે પ્રયત્ન કરો તો ccam તમને ચેતવે છે.

## મારે કઈ રીત પસંદ કરવી?

બે એકાઉન્ટ અને કંઈ શેર ન કરવું હોય, તો alias પૂરતું છે. જ્યારે તમને શેર કરેલાં સેટિંગ્સ અને MCP સર્વર, વધુ એકાઉન્ટ, એક નજરમાં વપરાશ કે વાતચીત ચાલુ રાખવાની સુવિધા જોઈએ, ત્યારે ccam તમારું જાતે સંભાળવાનું કામ બચાવે છે. [alias સાથેની સરખામણી](/compare/aliases) તફાવતો બાજુ-બાજુમાં બતાવે છે, અને [ccam અને બીજાં એકાઉન્ટ સ્વિચર](/compare/account-switchers) એક જ લૉગિન બદલતાં ટૂલ વિશે જણાવે છે.

તમે ઘણાં એકાઉન્ટ વાપરી શકો કે નહીં, તે દરેક એકાઉન્ટની શરતો પર આધાર રાખે છે. તેમ કરતાં પહેલાં શરતો તપાસો.

**Team અને Enterprise સીટ.** આપમેળે થતી પસંદગી (`ccam next`, `--fallback`, `ccam pick`, ડેશબોર્ડની `n` કી, અને તમે ચાલુ કરો ત્યારે [`auto_switch`](/features/next#auto-switch)) એક જ Claude Team કે Enterprise સંસ્થાની સીટો વચ્ચે પણ સ્વિચ કરે છે. Anthropic નું સહાય કેન્દ્ર કહે છે કે "Each seat on a Team plan is assigned to one named individual, and only that person may use it" (Team પ્લાનની દરેક સીટ નામથી નક્કી કરેલી એક વ્યક્તિને ફાળવવામાં આવે છે, અને ફક્ત એ વ્યક્તિ જ તેનો ઉપયોગ કરી શકે છે) અને "Users can't route their work through another user's account to use that user's remaining usage" (વપરાશકર્તાઓ બીજા વપરાશકર્તાના એકાઉન્ટ મારફતે પોતાનું કામ ચલાવીને એ વપરાશકર્તાનો બાકી રહેલો વપરાશ વાપરી શકતા નથી) ([Team પ્લાન](https://support.claude.com/en/articles/12004354-purchase-and-manage-seats-on-team-plans#h_b8a7d07129); [Enterprise પ્લાન](https://support.claude.com/en/articles/13393991-purchase-and-manage-seats-on-enterprise-plans#h_fa6b9cade0) માટે પણ એવું જ). તેથી સીટો વચ્ચે આપમેળે થતી પસંદગી વાપરવાથી Anthropic ની શરતોનું ઉલ્લંઘન થઈ શકે છે. સીટો વચ્ચે તેને વાપરવું કે નહીં એ તમારો નિર્ણય છે: તેના પર આધાર રાખતાં પહેલાં તમારી સંસ્થા અને Anthropic પાસેથી ખાતરી કરી લો. અંગત પ્લાન (Pro, Max) ઉપરની નોંધમાં આવરી લેવાયા છે.
