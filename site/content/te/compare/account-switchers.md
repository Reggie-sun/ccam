Claude Code ఖాతాలను మార్చే టూల్స్ రెండు పద్ధతుల్లో ఒకదాన్ని అనుసరిస్తాయి. చాలావరకు ఒకే `~/.claude` ఫోల్డర్ లోపల లాగిన్‌ను మారుస్తాయి, కాబట్టి ఒకేసారి ఒక ఖాతా మాత్రమే యాక్టివ్‌గా ఉంటుంది. ccam తో సహా మరికొన్ని, `CLAUDE_CONFIG_DIR` తో ప్రతి ఖాతాకు దాని సొంత ఫోల్డర్ ఇస్తాయి, కాబట్టి ప్రతి ఖాతా సైన్ ఇన్ అయ్యే ఉంటుంది, అనేక ఖాతాలు ఒకేసారి రన్ కాగలవు. ccam షేర్డ్ సెట్టింగ్‌లు, MCP సర్వర్లను జోడిస్తుంది, ఒక సంభాషణను మరో ఖాతా ఫోల్డర్‌లో కొనసాగిస్తుంది.

## ఒకే లాగిన్‌ను మార్చడమా, వేర్వేరు ఫోల్డర్‌లా?

**లాగిన్‌ను మార్చడం** ఒకే సెట్ సెట్టింగ్‌లు, MCP సర్వర్లు, చరిత్రను ఉంచుతుంది, ఎందుకంటే ఫోల్డర్ ఒక్కటే. మారడం వేగంగా ఉంటుంది, రన్ అవుతున్న సెషన్ కొత్త లాగిన్‌ను అందుకోగలదు. కానీ ఒకేసారి ఒక ఖాతా మాత్రమే యాక్టివ్‌గా ఉంటుంది, అన్ని టెర్మినల్‌లు, ఎడిటర్‌లకు ఒకేసారి.

మార్చడానికి, టూల్ మిగతా ప్రతి ఖాతా లాగిన్ కాపీని దాచి ఉంచి, దాన్ని సరైన చోట రాస్తుంది. Claude Code ఒక లాగిన్‌ను రెన్యూ చేసేటప్పుడు అందులోని refresh token ను మార్చేస్తుంది, కాబట్టి దాచిన ప్రతి కాపీ రన్ అవుతున్న సెషన్‌లతో సమకాలీకరణలో ఉండాలి. మారిన తర్వాత ఖాతాలు లాగ్ అవుట్ అవ్వడం, మళ్లీ `/login` అవసరం అవ్వడం ఈ ప్రాజెక్ట్‌లు తరచుగా సరిచేసే సమస్యల్లో ఉన్నాయి.

**వేర్వేరు ఫోల్డర్‌లు** అనేది [Claude Code డాక్యుమెంటేషన్ వివరించే](https://code.claude.com/docs/en/authentication#log-in-with-multiple-accounts) పద్ధతి. ప్రతి ఖాతా లాగిన్ అయ్యే ఉంటుంది, work, personal సెషన్‌లను పక్కపక్కనే రన్ చేయవచ్చు. ప్రతి లాగిన్ దాని సొంత ఫోల్డర్‌లోనే ఉంటుంది, అక్కడ Claude Code దాన్ని ఎప్పటిలాగే రెన్యూ చేస్తుంది. దీనికి చెల్లించే మూల్యం: ఏదైనా టూల్ షేర్ చేయకపోతే, ప్రతి ఫోల్డర్ దాని సొంత సెట్టింగ్‌లు, MCP సర్వర్లు, చరిత్రతో మొదలవుతుంది.

## ccam బాగా చేసేవి

### లాగిన్‌లు Claude Code ఉంచిన చోటే ఉంటాయి

ccam ఎప్పుడూ ఒక Claude లాగిన్‌ను ఒక చోట నుంచి మరో చోటికి కాపీ చేయదు. ప్రతి ఖాతా లాగిన్ దాని సొంత ఫోల్డర్‌లో, లేదా macOS లో ఆ ఫోల్డర్‌కే చెందిన Keychain ఐటెమ్‌లో ఉంటుంది, దాన్ని రెన్యూ చేసేది Claude Code. సమకాలీకరణ తప్పే దాచిన కాపీ ఏదీ ఉండదు. `ccam import` తో నమోదు చేసిన ఇప్పటికే ఉన్న `~/.claude`, సాధారణ `claude` వాడే అదే Keychain ఐటెమ్‌ను ఉంచుకుంటుంది, కాబట్టి ఏ విధంగా ప్రారంభించినా అది సైన్ ఇన్ అయ్యే ఉంటుంది.

మీరు `ccam usage --refresh` రన్ చేసినప్పుడు మాత్రమే ccam గడువు ముగిసిన token ను తానే రెన్యూ చేస్తుంది. ముందుగా ఒక లాక్ తీసుకుంటుంది. ఆ ఖాతా రన్ అవుతుంటే (Claude Code ఎలా ప్రారంభమైనా సరే, బ్యాక్‌గ్రౌండ్ సెషన్‌లు, వాటి daemon తో సహా), Claude Code తానే ఆ లాగిన్‌ను రెన్యూ చేస్తుంటే నిరాకరిస్తుంది, కాబట్టి రన్ అవుతున్న సెషన్ కింద ఎప్పుడూ token ను మార్చదు.

### మీకూ Claude Code కూ మధ్య ఏదీ రన్ అవ్వదు

ccam ఒక ఫైల్ చదివి, దాని లింక్‌లను తనిఖీ చేసి, తన స్థానంలో `claude` ను నడుపుతుంది (`exec`). మీరు పని చేస్తున్నప్పుడు ccam ప్రాసెస్, wrapper, ప్రాక్సీ, daemon ఏవీ ఉండవు: standard input, signals, exit code Claude Code కే చెందుతాయి, దాని అభ్యర్థనలు నేరుగా Anthropic కి వెళ్తాయి. Windows ఒక ప్రాసెస్‌ను మార్చలేదు, కాబట్టి అక్కడ ccam అదే console తో Claude Code ను ప్రారంభించి, దాని exit code కోసం వేచి ఉంటుంది, ఇంకేమీ చేయదు.

ఈ విధంగా ఒక ఖాతాను ప్రారంభించడం సుమారు 4 ms మాత్రమే జోడిస్తుంది, 95వ percentile వద్ద 6 ms లోపు, గరిష్ఠ మెమరీ 8 MB ([`scripts/perf-check.sh`](https://github.com/jhyunwoo/ccam/blob/main/scripts/perf-check.sh), hyperfine తో, 300 రన్‌లు). అదే ల్యాప్‌టాప్‌లో, ఏ ప్రోగ్రామ్ ఏమీ చేయకముందే, Python interpreter ను ప్రారంభించడానికే 13 ms, Node.js కి 31 ms పడుతుంది.

### ఏమి షేర్ అవుతుందో గ్రూప్‌లు నిర్ణయిస్తాయి

MCP సర్వర్లు, `settings.json`, `CLAUDE.md`, ఎక్స్‌టెన్షన్‌లు (agents, commands, skills, plugins), సంభాషణ చరిత్ర అనేవి ఐదు వేర్వేరు అంశాలు. ఒక గ్రూప్ తాను షేర్ చేసే అంశాలను, తనలోని ఖాతాలను పేర్కొంటుంది. కాబట్టి రెండు work ఖాతాలు ఒక `work` గ్రూప్‌లో చరిత్రను షేర్ చేసుకోవచ్చు, ఒక personal ఖాతా తన సొంత చరిత్రను ఉంచుకోవచ్చు, మూడూ `default` ద్వారా ఒకే MCP సర్వర్లను షేర్ చేసుకోవచ్చు. `ccam group set work --add memory` గ్రూప్‌లోని ప్రతి ఖాతాను ఒకే ప్లాన్‌లో తరలిస్తుంది; [డాష్‌బోర్డ్](/features/dashboard) అదే పనిని చెక్‌బాక్స్‌లతో చేస్తుంది, ఒక ఖాతాకు ఇప్పటికే మరో గ్రూప్ నుంచి అందుతున్న అంశాన్ని బూడిద రంగులో చూపిస్తుంది.

- MCP సర్వర్లు లాంచ్ సమయంలో `--mcp-config` తో అందించబడతాయి, కాబట్టి డిఫాల్ట్‌గా ఒక లాంచ్ `.claude.json` ను తాకదు; అది Claude Code రన్ అవుతున్నప్పుడు తిరిగి రాసే ఫైల్. ccam అక్కడ ఆ విషయం ముందే చెప్పే దశల్లో మాత్రమే, Claude Code లాక్ కింద, బ్యాకప్‌తో రాస్తుంది: అడిగిన తర్వాత Remote Control కోసం, ఒక ఖాతా MCP షేరింగ్ నుంచి బయటకు వెళ్లినప్పుడు లేదా తిరిగి చేరినప్పుడు, `ccam mcp import` కోసం. `ccam mcp add` ఒక సర్వర్‌ను మొత్తం గ్రూప్‌కు ఒక్కసారే జోడిస్తుంది.
- మిగతా అంశాలు గ్రూప్ ఫోల్డర్‌లోకి లింక్‌లు, కాబట్టి ఒక ఖాతాలో చేసిన మార్పు మిగతా వాటిలో వెంటనే కనిపిస్తుంది. లాంచ్ సమయంలో ఏదీ కాపీ అవ్వదు.
- లాగిన్‌లు, `.claude.json`, రన్ అవుతున్న స్థితి ఎప్పుడూ షేర్ అవ్వవు.

### ప్రతి మార్పు ముందుగా చూపించబడుతుంది, బ్యాకప్ అవుతుంది

`ccam group`, `ccam migrate` ఏదైనా తరలించే ముందు ఒక ప్లాన్‌ను ప్రింట్ చేసి అడుగుతాయి. ఒక ఖాతాకూ దాని గ్రూప్‌కూ మధ్య ఒక ఫైల్ వేరుగా ఉంటే, మీరే ఎంచుకుంటారు: గ్రూప్‌ది ఉంచడం, మీది వాడడం, లేదా JSON ను విలీనం చేయడం; ఫోల్డర్‌ల లోపల గ్రూప్ కాపీనే ఉంటుంది, వేరుగా ఉన్న ఫైల్‌ల పేర్లను ప్లాన్ చెబుతుంది. అసలు ఫైల్‌లు `.ccam-backup/<time>/` కి వెళ్తాయి, తీసివేసిన ఖాతా లాగ్ అవుట్ అవుతుంది, దాని ఫోల్డర్ ఒక ట్రాష్ ఫోల్డర్‌కు వెళ్తుంది, ఫైల్‌లు ఒకే rename తో మార్చబడతాయి, కాబట్టి మధ్యలో ఆగిన రాత పాత ఫైల్‌ను అలాగే వదిలేస్తుంది. లాంచ్, షేరింగ్, మైగ్రేషన్, షార్ట్‌కట్‌లు, అప్‌డేట్‌లు, రిపేర్లు ఏమి చేస్తాయో `--dry-run` చూపిస్తుంది. `ccam doctor --fix` విరిగిన లింక్‌లను, అనుమతులను సరిచేస్తుంది.

### తదుపరి ఖాతాలో అదే సంభాషణ

`ccam next --auto --continue` అన్ని ఖాతాలను ఒకేసారి వాటి వినియోగం అడిగి, ఎక్కువ అవకాశం ఉన్న ఖాతాను తెరిచి, సంభాషణను కొనసాగిస్తుంది. షేర్డ్ చరిత్ర ఉంటే అది అదే సంభాషణ; లేకపోతే Claude Code దాన్ని కొత్త ఖాతాలోకి కాపీ చేస్తుంది (`--resume <file> --fork-session`), మొదటి సమాధానం ఎన్ని టోకెన్‌లను మళ్లీ చదువుతుందో ccam చెబుతుంది. ఒక పరిమితి సెషన్‌ను ఆపినప్పుడు, ccam ప్లగిన్ hook ఒక నోటిఫికేషన్ చూపిస్తుంది, `/ccam:switch` సంభాషణను ముందుకు అప్పగిస్తుంది. ఎప్పుడు మారాలో మీరే నిర్ణయిస్తారు; బ్యాక్‌గ్రౌండ్‌లో ఏదీ మీ వినియోగాన్ని గమనించదు, ఆటోమేటిక్ ఎంపికలు ఒకే సంస్థలోనే ఉంటాయి, కాబట్టి కంపెనీ సంభాషణ పొరపాటున వ్యక్తిగత ఖాతాలోకి ఎప్పుడూ చేరదు. ఒక ఖాతా 90% కి చేరగానే స్టేటస్ లైన్ ఈ కమాండ్‌ను సూచిస్తుంది.

స్క్రిప్ట్‌లు మీ కోసం వేచి ఉండలేవు, కాబట్టి `ccam --fallback work -p "…"` వాటి కోసం మారుస్తుంది: ఖాతా తన పరిమితిని చేరినప్పుడు, అదే కమాండ్ ఎక్కువ అవకాశం ఉన్న ఖాతాగా మళ్లీ రన్ అవుతుంది, పూర్తయిన రన్ output మాత్రమే ప్రింట్ అవుతుంది. వినియోగ పరిమితి కాని వైఫల్యం ఉన్నది ఉన్నట్టే అందించబడుతుంది. సమాంతర workers కోసం, `ccam pick` ప్రతి దానికీ అవకాశం ఉన్న వేరే ఖాతాను ఇస్తుంది, ఏ ఖాతాలోనూ అవకాశం మిగలనప్పుడు రెండూ కోడ్ 75 తో నిష్క్రమిస్తాయి.

**Team, Enterprise సీట్లు.** ఆటోమేటిక్ ఎంపిక (`ccam next`, `--fallback`, `ccam pick`, డాష్‌బోర్డ్‌లోని `n`) ఒకే Claude Team లేదా Enterprise సంస్థలోని సీట్ల మధ్య కూడా మారుస్తుంది. Anthropic సహాయ కేంద్రం "Each seat on a Team plan is assigned to one named individual, and only that person may use it" (Team ప్లాన్‌లోని ప్రతి సీటు పేరుతో నిర్దేశించిన ఒక వ్యక్తికి కేటాయించబడుతుంది, ఆ వ్యక్తి మాత్రమే దాన్ని ఉపయోగించవచ్చు) అని, "Users can't route their work through another user's account to use that user's remaining usage" (యూజర్లు మరో యూజర్‌కు మిగిలి ఉన్న వినియోగాన్ని వాడుకోవడానికి తమ పనిని ఆ యూజర్ ఖాతా ద్వారా మళ్లించకూడదు) అని చెబుతుంది ([Team ప్లాన్‌లు](https://support.claude.com/en/articles/12004354-purchase-and-manage-seats-on-team-plans#h_b8a7d07129); [Enterprise ప్లాన్‌లకు](https://support.claude.com/en/articles/13393991-purchase-and-manage-seats-on-enterprise-plans#h_fa6b9cade0) కూడా ఇదే వర్తిస్తుంది). కాబట్టి సీట్ల మధ్య ఆటోమేటిక్ ఎంపికను ఉపయోగించడం Anthropic నిబంధనల ఉల్లంఘన కావచ్చు. దానిపై ఆధారపడే ముందు మీ సంస్థను, Anthropic ను సంప్రదించి నిర్ధారించుకోండి. వ్యక్తిగత ప్లాన్‌ల (Pro, Max) గురించి [తరచుగా అడిగే ప్రశ్నలలోని నిబంధనల గమనిక](/docs/faq#am-i-allowed-to-use-several-claude-code-accounts) చెబుతుంది.

### ప్రతి ఫోల్డర్‌లో సరైన ఖాతా

`ccam folder work ~/code/company` ఆ ఫోల్డర్ లోపల ఖాతా పేరు లేని ప్రతి లాంచ్‌ను `work` ను ఉపయోగించేలా చేస్తుంది, మీ మిగతా ప్రాజెక్ట్‌లు డిఫాల్ట్ ఖాతానే ఉపయోగిస్తాయి. ఈ సెట్టింగ్ ప్రతి లాంచ్ చదివే అదే `config.toml` లో ఉంటుంది, కాబట్టి దీనికి సమయం పట్టదు.

### ఒకే బైనరీ, తనిఖీ చేసిన డౌన్‌లోడ్‌లు

ccam అనేది Linux, macOS, Windows కోసం సుమారు 10 MB ఉన్న static బైనరీ, ఇన్‌స్టాల్ చేయాల్సిన runtime ఏదీ లేదు. ఇన్‌స్టాల్ స్క్రిప్ట్‌లు (`install.sh`, `install.ps1`), `ccam update` ప్రతి డౌన్‌లోడ్‌ను release యొక్క SHA-256 checksums తో తనిఖీ చేస్తాయి, ccam అడగకుండా ఎప్పుడూ అప్‌డేట్ అవ్వదు. దీనిలో telemetry లేదు: అది చేసే అభ్యర్థనలు మీ ఖాతాల కోసం Anthropic కి చేసే వినియోగ లుకప్‌లు (సమాంతరంగా, 3 సెకన్ల పరిమితి, 60 సెకన్ల cache తో), డాష్‌బోర్డ్ తెరుచుకున్నప్పుడు తాజా release గురించి GitHub ను అడిగే ప్రశ్న, మీరు అడిగే డౌన్‌లోడ్‌లు మాత్రమే. `usage_source = "claude"` తో అవి కూడా Claude Code ద్వారానే వెళ్తాయి, ccam ఏ టోకెన్‌నూ తాకదు.

## ఇతర టూల్స్ ఎక్కడ ఎక్కువ చేస్తాయి

- ఒక ఖాతా వినియోగ పరిమితిని దాటినప్పుడు claude-swap, clauth, cux, CAAM, CCSwitcher రన్ అవుతున్న ఇంటరాక్టివ్ సెషన్‌ను తామే మార్చగలవు. ccam `-p` రన్‌లను `--fallback` తో మారుస్తుంది, ఇంటరాక్టివ్ సెషన్‌లను మీకే వదిలేస్తుంది, పరిమితి వద్ద ఒక నోటిఫికేషన్‌తో, `/ccam:switch` తో.
- Developer Mode లేని Windows లో ccam ఫోల్డర్‌లను షేర్ చేస్తుంది కానీ `settings.json` వంటి ఒంటరి ఫైల్‌లను షేర్ చేయలేదు (అప్పుడు మొదటి `ccam add` MCP సర్వర్లను, ఎక్స్‌టెన్షన్‌లను మాత్రమే షేర్ చేస్తుంది); claude-swap, CCS అక్కడ వాటిని కాపీ చేస్తాయి.
- CCSwitcher, Claude Switcher, claude-swap macOS మెనూ బార్‌లో వినియోగాన్ని చూపిస్తాయి.
- CCS, clausona, CAAM, clauth, ccswap, Claude Switcher Codex ను, ఇతర కోడింగ్ ఏజెంట్లను కూడా నిర్వహిస్తాయి.
- clausona ఖాతా వారీగా extensions ను ఆన్, ఆఫ్ కూడా చేస్తుంది (ccam యొక్క `ccam ext` వాటిని చూపిస్తుంది మాత్రమే), లోకల్ టోకెన్ ఖర్చును లెక్కిస్తుంది, tmux లోనూ ఇతర టెర్మినల్స్‌లోనూ workers గుంపును నడిపే Claude Code plugins ను అందిస్తుంది.
- CAAM, CCSwitcher, Claude Switcher Homebrew తో ఇన్‌స్టాల్ అవుతాయి, clauth, CAAM తమ release checksums పై సంతకం చేస్తాయి. ccam తన స్క్రిప్ట్, ఒక `.deb`, లేదా `go install` తో ఇన్‌స్టాల్ అవుతుంది, checksums ను సంతకం లేకుండా తనిఖీ చేస్తుంది.

## ఏది సరిపోతుంది?

మీరు ఒకేసారి ఒక ఖాతా మాత్రమే ఉపయోగిస్తుంటే, లేదా రన్ అవుతున్న సెషన్‌లు ఆటోమేటిక్‌గా మారాలనుకుంటే, లాగిన్‌ను మార్చే టూల్‌ను ఎంచుకోండి. ఖాతాలను పక్కపక్కనే, ఒకే షేర్డ్ సెటప్‌తో, తదుపరి ఖాతాలో అదే సంభాషణతో, Claude Code పక్కన ఏదీ రన్ అవ్వకుండా Linux, macOS లేదా Windows లో కావాలంటే ccam ను ఎంచుకోండి. ఏమీ షేర్ చేయనవసరం లేకపోతే, [సాధారణ షెల్ అలియాస్‌లు](/compare/aliases) సరిపోతాయి.

అనేక ఖాతాలను ఉపయోగించవచ్చా అనేది ప్రతి ఖాతా నిబంధనలపై ఆధారపడి ఉంటుంది. ఉపయోగించే ముందు వాటిని తనిఖీ చేయండి.
