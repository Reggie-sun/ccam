`~/.claude` కు బదులుగా ఏ ఫోల్డర్‌ను ఉపయోగించాలో `CLAUDE_CONFIG_DIR` Claude Code కు చెబుతుంది. ఖాతాకు సంబంధించిన ప్రతిదీ అక్కడే ఉంటుంది: లాగిన్, సెట్టింగ్‌లు, MCP సర్వర్లు, ప్లగిన్‌లు, సంభాషణ చరిత్ర. దాన్ని వేర్వేరు ఫోల్డర్‌లకు సూచిస్తే వేర్వేరు ఖాతాలు వస్తాయి.

```sh
CLAUDE_CONFIG_DIR=~/.claude-work claude
```

## CLAUDE_CONFIG_DIR కు అధికారిక మద్దతు ఉందా?

అవును. Claude Code దాన్ని తన [ఎన్విరాన్‌మెంట్ వేరియబుల్స్](https://code.claude.com/docs/en/env-vars) జాబితాలో కాన్ఫిగరేషన్ ఫోల్డర్‌ను మార్చే మార్గంగా, "useful for running multiple accounts side by side" అని పేర్కొంటుంది. దాని [ఆథెంటికేషన్ గైడ్](https://code.claude.com/docs/en/authentication#log-in-with-multiple-accounts) అనేక ఖాతాలతో లాగిన్ అవ్వడానికి దీన్నే ఉపయోగిస్తుంది. దీన్ని మీ షెల్‌లో లేదా యూజర్ సెట్టింగ్‌లలో సెట్ చేయవచ్చు, కానీ ప్రాజెక్ట్ సెట్టింగ్‌లలో కాదు.

## ఫోల్డర్‌లో ఏమి ఉంటుంది?

Claude Code 2.1.309 తో తనిఖీ చేసినది:

| పాత్ | విషయాలు | షేర్ చేయవచ్చా |
| --- | --- | --- |
| `.credentials.json` | లాగిన్ టోకెన్‌లు (Linux, Windows), MCP OAuth టోకెన్‌లు | లేదు |
| `.claude.json` | ఖాతా వివరాలు, యూజర్ MCP సర్వర్లు, ప్రాజెక్ట్ వారీ స్థితి | లేదు (MCP సర్వర్లు విడిగా) |
| `settings.json` | అనుమతులు, హుక్‌లు, మోడల్, స్టేటస్ లైన్, ప్లగిన్‌లు | అవును |
| `CLAUDE.md` | గ్లోబల్ సూచనలు | అవును |
| `agents/`, `commands/`, `skills/`, `plugins/` | ఎక్స్‌టెన్షన్లు | అవును |
| `projects/` | `.jsonl` ఫైళ్లుగా సంభాషణలు, ప్రాజెక్ట్ వారీ మెమరీ | అవును |
| `history.jsonl` | ప్రాంప్ట్ చరిత్ర | అవును |
| `sessions/`, `shell-snapshots/`, `cache/`, ఇతరాలు | రన్‌టైమ్ స్థితి | లేదు |

## ఎక్కడ ఇబ్బందులు ఎదురవుతాయి?

**`CLAUDE_CONFIG_DIR` లేకుండా, `.claude.json` `~/.claude` లోపల ఉండదు.** అప్పుడు Claude Code దాన్ని ఫోల్డర్ పక్కన `~/.claude.json` వద్ద ఉంచుతుంది. మీరు `CLAUDE_CONFIG_DIR=~/.claude` ఉపయోగించడం మొదలుపెడితే, Claude Code బదులుగా `~/.claude/.claude.json` కోసం వెతుకుతుంది, మీ ఖాతాను కనుగొనలేదు. `ccam import` ఈ రెండింటినీ లింక్ చేసి దీన్ని పరిష్కరిస్తుంది. `CLAUDE_CONFIG_DIR=~/.claude` తో ఇంతకు ముందు రన్ చేసినందువల్ల `~/.claude` కు ఇప్పటికే సొంత `.claude.json` ఉంటే, ccam రెండు ఫైళ్లను అలాగే వదిలేసి ఆ విషయం చెబుతుంది, ఎందుకంటే ఏది సరైనదో మీకు మాత్రమే తెలుసు.

**macOS లో లాగిన్ ఫోల్డర్‌లో కాకుండా కీచైన్‌లో ఉంటుంది.** Claude Code దాన్ని `Claude Code-credentials` అనే పేరుతో నిల్వ చేస్తుంది. `CLAUDE_CONFIG_DIR` సెట్ చేసి ఉంటే, ఆ పేరు చివర `-`, ఫోల్డర్ పాత్ యొక్క SHA-256 లోని మొదటి 8 hex అంకెలు కూడా వస్తాయి. కీచైన్ ఐటమ్ యొక్క account పేరు `$USER`. కాబట్టి వేర్వేరు ఫోల్డర్‌లకు వేర్వేరు కీచైన్ ఎంట్రీలు వస్తాయి, తరలించిన లేదా పేరు మార్చిన ఫోల్డర్ తన లాగిన్‌ను కోల్పోతుంది; అందుకే macOS లో `ccam rename` ఫోల్డర్ పేరును మార్చదు. కీచైన్ రాయడాన్ని నిరాకరిస్తే, [దాని డాక్యుమెంటేషన్](https://code.claude.com/docs/en/authentication#credential-management) వివరించినట్లు Claude Code ఫోల్డర్‌లోని `.credentials.json` ను ఉపయోగిస్తుంది.

**ప్రతి సైన్-ఇన్ ఫోల్డర్‌లో ఉండదు.** API కీ లేని Claude Console సైన్-ఇన్ ఫోల్డర్ బయట నిల్వ అవుతుంది, కాబట్టి వేర్వేరు ఫోల్డర్‌లు అలాంటి రెండు సైన్-ఇన్‌లను వేరుగా ఉంచలేవు. claude.ai లాగిన్‌లు, API కీలు ఫోల్డర్ వారీగా ఉంటాయి.

## Windows లో ఫోల్డర్ ఎక్కడ ఉంటుంది?

డిఫాల్ట్‌గా ఇది `%USERPROFILE%\.claude`. లాగిన్ దాని లోపలి `.credentials.json` లో ఉంటుంది, లేదా Claude Code ను Windows Credential Manager ఉపయోగించేలా సెట్ చేసి ఉంటే, macOS లో లాగే ఫోల్డర్ పాత్ నుంచి తయారైన పేరుతో అందులో ఉంటుంది. ప్రతి అదనపు ఖాతాకు, Linux, macOS లో లాగే, `CLAUDE_CONFIG_DIR` ను మరో ఫోల్డర్‌కు సెట్ చేయండి.

## ఫోల్డర్‌లు ఫైళ్లను షేర్ చేయగలవా?

సింబాలిక్ లింక్‌లు పనిచేస్తాయి: Claude Code లింక్ చేసిన `settings.json` లేదా `projects/` ఫోల్డర్ ద్వారా చదువుతుంది, రాస్తుంది, లింక్‌ను అలాగే ఉంచుతుంది. MCP సర్వర్లు మినహాయింపు, ఎందుకంటే అవి లాగిన్‌తో `.claude.json` ను పంచుకుంటాయి; వాటిని బదులుగా `--mcp-config` తో ఇవ్వండి.

ccam సరిగ్గా ఈ నియమాలపైనే నిర్మించబడింది. అది ఫోల్డర్‌లను ఎలా లింక్ చేస్తుందో [షేరింగ్](/docs/sharing) లో, మొత్తం చిత్రం కోసం [అనేక ఖాతాల గైడ్](/guides/multiple-claude-code-accounts) చూడండి.
