ప్రతి ఖాతాకు సొంత ఫోల్డర్ ఉంటుంది, కానీ అందులోని చాలా వరకు వేరుగా ఉండాల్సిన అవసరం లేదు. ఏమి షేర్ అవుతుందో, ఎవరి మధ్య షేర్ అవుతుందో ఒక **గ్రూప్** చెబుతుంది: గ్రూప్‌లోని ప్రతి ఖాతా ఆ అంశాలను `~/.local/share/ccam/groups/<group>/` అనే ఒకే ఫోల్డర్‌కు లింక్ చేస్తుంది, కాబట్టి అవన్నీ ఒకే కాపీని చదువుతాయి, అందులోనే రాస్తాయి. లాగిన్ టోకెన్‌లు ఎప్పుడూ షేర్ కావు.

ఒక ఖాతా అనేక గ్రూప్‌లలో ఉండవచ్చు, కానీ ప్రతి అంశం ఒకే గ్రూప్ నుంచి వస్తుంది. సాధారణ సెటప్ అంటే సెట్టింగ్‌లు, ఎక్స్‌టెన్షన్ల కోసం ఒక గ్రూప్, రెండు ఖాతాల మధ్య సంభాషణ చరిత్ర కోసం రెండో గ్రూప్:

```toml
[[group]]
name = 'default'
items = ['mcp', 'settings', 'memory', 'extensions']
members = ['personal', 'work', 'side']

[[group]]
name = 'team'
items = ['history']
members = ['work', 'side']
```

మీరు జోడించే మొదటి ఖాతా `default` ను సృష్టిస్తుంది, మీరు వేరే చెప్పకపోతే తర్వాతి ఖాతాలు అందులో చేరతాయి.

## వినియోగం

```sh
ccam group                                        # the groups, what they share, their accounts
ccam group show default                           # items, accounts, folder and MCP servers
ccam group add team --items history --members work,side
ccam group set default --add history              # all accounts in default start sharing history
ccam group set default --remove history --fresh   # stop sharing; accounts start without it
ccam group set team --items history,memory --from work   # the group starts from work's copies
ccam group join team personal                     # personal starts sharing team's items
ccam group join team personal --replace           # first leave the group that shares those items now
ccam group leave team side                        # side keeps a copy of team's items
ccam group rename team pair                       # the folder keeps its name
ccam group remove pair --leave                    # its accounts keep a copy; folder to the trash
ccam share work                                   # what work shares, and through which group
ccam --dry-run group set default --add history    # print the plan, change nothing
```

```console
$ ccam group
Group    Shares                          Accounts
default  mcp settings memory extensions  personal, work, side
team     history                         work, side

$ ccam share work
Sharing for work
  mcp         MCP servers                        group default
  settings    settings.json                      group default
  memory      global CLAUDE.md                   group default
  extensions  agents, commands, skills, plugins  group default
  history     conversation history               group team
Groups: default, team. Change them with `ccam group`.
```

డేటాను తరలించే ప్రతి కమాండ్ ఒక ప్రణాళికను ప్రింట్ చేసి, గ్రూప్ కాపీ నుంచి వేరుగా ఉన్న ప్రతి ఫైల్ గురించి అడిగి, ఏదైనా మార్చే ముందు `Proceed? [y/N]` అని అడుగుతుంది:

```console
$ ccam group set default --add history
Plan (paths in /home/me/.local/share/ccam):
personal: +history (group default)
  move     projects, history.jsonl: profiles/personal → groups/default (first content of the group)
  link     projects, history.jsonl, file-history, tasks, paste-cache: profiles/personal → groups/default
work: +history (group default)
  merge    new files in projects: profiles/work → groups/default
  conflict profiles/work/history.jsonl ↔ groups/default/history.jsonl: merge by line
  back up  projects, history.jsonl: profiles/work → profiles/work/.ccam-backup/20261023-213057
  link     projects, history.jsonl, file-history, tasks, paste-cache: profiles/work → groups/default
  Note: projects: 1 file differs from the group's copy (-home-me-code-app/s1.jsonl); the group's is kept, the account's stays in profiles/work/.ccam-backup/20261023-213057/projects
Proceed? [y/N]
```

ఇవే మార్పులను మీరు [డాష్‌బోర్డ్](/features/dashboard) లోని **Groups** ట్యాబ్‌లో చేయవచ్చు; ఒక ఖాతా గ్రూప్‌లను ఎంచుకోవడానికి దానిపై `s` నొక్కండి.

## అంశాలు

| అంశం | ఏమి కవర్ చేస్తుంది |
| --- | --- |
| `mcp` | MCP సర్వర్లు, గ్రూప్ యొక్క `mcp.json` ద్వారా ([షేర్ చేసిన MCP సర్వర్లు](/features/mcp)) |
| `settings` | `settings.json` |
| `memory` | గ్లోబల్ `CLAUDE.md` |
| `extensions` | `agents/`, `commands/`, `skills/`, `plugins/`, `output-styles/`, `rules/` |
| `history` | `projects/`, `history.jsonl`, కాబట్టి మరో ఖాతా `--continue` చేయగలదు |

ఖాతా గ్రూప్‌లలో ఏదీ ఒక అంశాన్ని షేర్ చేయకపోతే, ఆ అంశం ఖాతా సొంత ఫోల్డర్‌లోనే ఉంటుంది.

## కమాండ్‌లు, ఆప్షన్లు

| కమాండ్ | ఏమి చేస్తుంది |
| --- | --- |
| `ccam group` లేదా `ccam group list` | గ్రూప్‌లను జాబితా చేస్తుంది |
| `ccam group show <group>` | గ్రూప్ ఏమి షేర్ చేస్తుంది, దాని ఖాతాలు, దాని ఫోల్డర్, MCP సర్వర్లు |
| `ccam group add <group> --items <items> [--members <accounts>]` | ఒక గ్రూప్‌ను సృష్టిస్తుంది; దాని ఖాతాల అంశాలు అందులోకి తరలుతాయి |
| `ccam group set <group> --add <items> \| --remove <items> \| --items <items>` | గ్రూప్ ఏమి షేర్ చేస్తుందో, అందులోని ప్రతి ఖాతా కోసం మారుస్తుంది |
| `ccam group join <group> <account>...` | ఖాతాలను గ్రూప్‌లో చేరుస్తుంది |
| `ccam group leave <group> <account>...` | ఖాతాలను బయటకు తీస్తుంది; ప్రతిదీ MCP సర్వర్లతో సహా ఒక కాపీని ఉంచుకుంటుంది |
| `ccam group rename <group> <new-name>` | కాన్ఫిగ్‌లో మాత్రమే పేరు మారుస్తుంది |
| `ccam group remove <group> [--leave]` | ఒక గ్రూప్‌ను తీసివేస్తుంది |

| ఆప్షన్ | ఏమి చేస్తుంది | డిఫాల్ట్ |
| --- | --- | --- |
| `--from <account>` | `add`, `set`: ఏ ఖాతా కాపీ ముందుగా గ్రూప్‌లోకి వెళ్తుందో | డిఫాల్ట్ ఖాతా, ఆపై నంబర్ క్రమంలో |
| `--replace` | `join`: అవే అంశాలను షేర్ చేసే గ్రూప్‌ల నుంచి ముందుగా బయటకు వస్తుంది | ఆఫ్ |
| `--fresh` | ఒక అంశాన్ని షేర్ చేయడం ఆపే ఖాతాలు కాపీతో కాకుండా అది లేకుండా మొదలవుతాయి (ఇంపోర్ట్ చేసిన ఫోల్డర్ అయినా ఒక కాపీని ఉంచుకుంటుంది) | ఆఫ్ |
| `--leave` | `remove`: ముందుగా గ్రూప్ ఖాతాలను బయటకు తీస్తుంది | గ్రూప్‌లో ఖాతాలు ఉన్నప్పుడు అవసరం |
| `--prefer <group\|mine\|merge>` | ఘర్షణలను ఎలా నిర్ణయించాలి | అడుగుతుంది; `--yes` తో, ప్రతి ఫైల్ డిఫాల్ట్ |
| `-y`, `--yes` | అడగకుండా రన్ చేస్తుంది; ఘర్షణలు `--prefer` ను అనుసరిస్తాయి | ఆఫ్ |
| `--dry-run` (గ్లోబల్) | ప్రణాళికను ప్రింట్ చేస్తుంది, ఏదీ మార్చదు | ఆఫ్ |

ఖాతాలను పేరు లేదా నంబర్ ద్వారా ఇవ్వవచ్చు; అంశాలను కామాలతో వేరు చేసిన జాబితాగా. `ccam add` `--group <group>` (మళ్లీ మళ్లీ ఇవ్వవచ్చు) లేదా `--no-group` ను తీసుకుంటుంది.

## ఇది ఎలా పనిచేస్తుంది

సంబంధిత ఫైళ్లు:

- `~/.config/ccam/config.toml`: `[[group]]` ఎంట్రీలు: `name`, `items`, `members`, ఫోల్డర్ పేరు వేరుగా ఉన్నప్పుడు `dir`.
- `~/.local/share/ccam/profiles/<name>/`: ఖాతా యొక్క `CLAUDE_CONFIG_DIR`.
- `~/.local/share/ccam/groups/<folder>/`: షేర్ చేసిన కాపీలు.

`config.toml` చదవబడినప్పుడు, ప్రతి ఖాతా గ్రూప్‌లు ఒక్కో అంశానికి ఒక ఫోల్డర్‌గా పరిష్కరించబడతాయి. ఐదు ఖాతాలకు దీనికి సుమారు 25 µs పడుతుంది, కాబట్టి ప్రారంభం ఇప్పటికీ `config.toml` ను మాత్రమే చదువుతుంది. ఒక ఖాతాకు ఒక అంశం రెండు గ్రూప్‌ల నుంచి వచ్చే కాన్ఫిగ్ ఎర్రర్, అది సరిచేసే వరకు ఏదీ ప్రారంభం కాదు.

మార్పు కాన్ఫిగ్ కాపీపై పనిచేస్తుంది:

1. కమాండ్ కాపీని ఎడిట్ చేస్తుంది (`AddGroup`, `SetGroupItems`, `JoinGroup` …), అది నియమాలను తనిఖీ చేస్తుంది.
2. ccam పాతదాన్ని, కొత్తదాన్ని పోల్చి, అంశాలు మారే ప్రతి ఖాతా కోసం ఒక ప్రణాళికను నిర్మిస్తుంది (`internal/group`, `share.Build`). ప్రణాళికలు ఒకదాని తర్వాత ఒకటి నిర్మించబడతాయి, ముందు వాటివి గ్రూప్ ఫోల్డర్‌లలో ఏమి పెడతాయో ప్రతిదీ చూస్తుంది, కాబట్టి మొదటి ఖాతా మాత్రమే తన కాపీని లోపలికి తరలిస్తుంది. గ్రూప్ మొదటి కాపీ ఈ క్రమంలో వస్తుంది: గ్రూప్ ఫోల్డర్ (దానిలో ఇప్పటికే ఒకటి ఉంటే), `--from` ఖాతా, డిఫాల్ట్ ఖాతా, ఆపై మిగతా ఖాతాలు నంబర్ క్రమంలో.
3. ఆ ఖాతాలలో ఒకటి రన్ అవుతుంటే, Claude Code ఎలా ప్రారంభమైనా సరే (``work is running; quit Claude Code there first, then change the groups (`ccam agents` lists the sessions)``), Windows లో Developer Mode లేకుండా ఒక ఫైల్‌కు లింక్ అవసరమైతే, ccam తిరస్కరిస్తుంది.
4. ccam ఘర్షణలను పరిష్కరిస్తుంది (అడగడం ద్వారా, లేదా `--prefer` తో), ప్రణాళికను ప్రింట్ చేసి నిర్ధారణ అడుగుతుంది.
5. సేవ్ చేయడానికి సరిగ్గా ముందు, ccam మళ్లీ తనిఖీ చేస్తుంది. ccam మీ సమాధానాల కోసం వేచి ఉన్నప్పుడు ఒక ఖాతా ప్రారంభమైతే, మార్పు ఆగిపోతుంది; ఈలోగా మరో ccam ప్రాసెస్ అవే గ్రూప్‌లను మార్చినా అది ఆగిపోతుంది (`the groups changed while this plan waited; nothing was moved, make the change again`). ఏదైనా తరలించే ముందు కొత్త కాన్ఫిగ్ సేవ్ అవుతుంది, మార్పు `~/.local/state/ccam/group-change.json` లో నమోదు అవుతుంది. ఒక దశ మధ్యలో ఆగితే, ఆ నోట్ అలాగే ఉంటుంది: `ccam doctor --fix` మార్పును దాని క్రమంలో, మీరు ఇచ్చిన సమాధానాలతో, MCP దశలతో సహా పూర్తి చేస్తుంది, అప్పటి వరకు మరే గ్రూప్ మార్పు మొదలవదు (``the last group change stopped halfway; finish it with `ccam doctor --fix` first``).
6. MCP దశలు ముందుగా రన్ అవుతాయి. ఖాతాలు ఒక గ్రూప్ నుంచి extensions ను బయటకు తీసినప్పుడు, గ్రూప్ ప్లగిన్ జాబితాల పాత్‌లు ఒక ఖాతా ఫోల్డర్ ద్వారా వెళ్లే ప్రతి చోటా, అవి గ్రూప్ ఫోల్డర్‌కు చూపేలా మార్చబడతాయి (ప్రణాళికలో `group plugin lists:`). ఆపై ప్రణాళికలు క్రమంగా రన్ అవుతాయి. ప్రతి దశ డేటాను గ్రూప్‌లోకి లేదా బ్యాకప్ ఫోల్డర్‌లోకి తరలిస్తుంది; గ్రూప్ కాపీకి సరిగ్గా ఒకేలా ఉన్న ఫైళ్లు మాత్రమే బ్యాకప్ కాకుండా తొలగించబడతాయి.

ccam ప్రతి అంశం కవర్ చేసే పాత్‌ల అనుమతి జాబితాను ఉంచుకుంటుంది (`share.Layout`). అందులో లేనిది ఏదీ ఎప్పుడూ గ్రూప్‌ను చేరదు. ccam `.credentials.json`, `.claude.json` ను ఎప్పుడూ షేర్ చేయనివిగా కూడా పేర్కొంటుంది (`share.Never`), వాటిలో ఏదైనా ఎప్పుడైనా లేఅవుట్‌లో కనిపిస్తే అంతర్గత ఎర్రర్‌తో ఆగుతుంది (`Build`). `mcp` అంశానికి పాత్‌లు లేవు: సర్వర్ జాబితా `.claude.json` లోపల ఉంటుంది, కాబట్టి [MCP షేరింగ్](/features/mcp) గ్రూప్ `mcp.json` ద్వారా పనిచేస్తుంది.

`side` చరిత్రను షేర్ చేయడం మొదలుపెట్టినప్పుడు, గ్రూప్‌లో ఇప్పటికే కంటెంట్ ఉంటే, `projects/` అనే ఒక ఫోల్డర్‌కు జరిగేది ఇది:

<!-- motion:share-on -->

ఆ పాత్ వద్ద గ్రూప్‌లో ఇంకా ఏమీ లేకపోతే, దాన్ని షేర్ చేసే మొదటి ఖాతా ఇదే, దాని ఫోల్డర్ ఉన్నది ఉన్నట్లుగా అక్కడికి తరలించబడుతుంది. లేకపోతే గ్రూప్‌లో లేని ప్రతి ఫైల్ గ్రూప్‌లోకి తరలుతుంది, రెండు వైపులా ఉన్న ఫైళ్లు ఖాతా ఫోల్డర్‌లోనే ఉంటాయి, కాబట్టి గ్రూప్ వెర్షన్ ఉంచబడుతుంది. గ్రూప్‌దానికి సరిగ్గా ఒకేలా ఉన్న ఫైళ్లు తొలగించబడతాయి, భిన్నంగా ఉన్నవాటి పేర్లను ప్రణాళిక చెబుతుంది (`Note: projects: 1 file differs from the group's copy (…); the group's is kept, the account's stays in …`).

ఆపై ఖాతా ఫోల్డర్ ఖాతా ఫోల్డర్‌లోని `.ccam-backup/<time>/` కు వెళ్తుంది, దాని స్థానంలో ఒక లింక్ వస్తుంది. గ్రూప్ ఎంట్రీ స్వయంగా చేరుతున్న ఖాతా సొంత ఎంట్రీకి లింక్ అయితే, దాని స్థానంలో ఖాతా కంటెంట్ గ్రూప్‌లోకి వెళ్తుంది. సంభాషణ ఫైళ్లకు వాటి సెషన్ ID పేరు ఉంటుంది, కాబట్టి అనేక ఖాతాల చరిత్రలు ఘర్షణ లేకుండా కలిసిపోతాయి. `plugins/` రిజిస్ట్రీలు ఖాతా ఫోల్డర్ ద్వారా వెళ్లే పూర్తి పాత్‌లను నిల్వ చేస్తాయి; ccam వాటిని గ్రూప్ ఫోల్డర్‌కు చూపేలా మారుస్తుంది, గ్రూప్‌లో ఇప్పటికే రిజిస్ట్రీ ఉంటే ఖాతా ఎంట్రీలను అందులో మెర్జ్ చేస్తుంది.

బయటకు రావడం లింక్‌ను తిరగబెడుతుంది:

<!-- motion:share-off -->

ccam ముందుగా గ్రూప్ ప్రస్తుత కంటెంట్‌ను ఖాతా ఫోల్డర్‌లోని `.ccam-backup/incomplete-<name>` లోకి కాపీ చేస్తుంది, కాపీ పూర్తయిన తర్వాతే లింక్‌ను భర్తీ చేస్తుంది. కాపీ మధ్యలో ఆగితే, లింక్ అలాగే ఉంటుంది, `ccam doctor --fix` మళ్లీ కాపీ చేస్తుంది (అలాంటి ముగింపు ప్రణాళిక `restore <entry>: … (copied back from the group before a stop)` అని చూపిస్తుంది). ఇతర ఖాతాల కోసం గ్రూప్ తన కంటెంట్‌ను ఉంచుకుంటుంది.

- ప్రణాళిక సృష్టించినప్పటిలాగే లింక్ ఇంకా groups ఫోల్డర్ లోపలికి చూపిస్తేనే ccam లింక్‌ను తీసివేస్తుంది. ఆ తర్వాత మారిన పాత్, ఉదాహరణకు లింక్ ఉన్న చోట అసలు ఫైల్, ఉన్నది ఉన్నట్లుగా వదిలేయబడుతుంది, మార్పు ఆగిపోతుంది.
- `--fresh` తో, కాపీ దాటవేయబడుతుంది.
- ఫోల్డర్ ఇంకా ఖాళీగా ఉన్న గ్రూప్‌కు ఒక అంశాన్ని తరలించే ఖాతా తాను చూసిన దాని కాపీని తీసుకువస్తుంది, కాబట్టి దాని ఫైళ్లు దాని దగ్గరే ఉంటాయి. ఆ కాపీ పూర్తయ్యే వరకు `<group>/.ccam-incomplete-<name>` లో సిద్ధం చేయబడుతుంది.
- MCP ను షేర్ చేయడం ఆపే ఖాతా గ్రూప్ సర్వర్లను ఉంచుకుంటుంది: అవి దాని సొంత `.claude.json` లోకి వెళ్తాయి (బ్యాకప్ ఉంచబడుతుంది), ఖాతాకు ఇప్పటికే అదే పేరుతో సర్వర్ ఉన్న చోట తప్ప, ఆ సర్వర్ అలాగే ఉంటుంది. `--fresh` తో, బదులుగా లోడ్ అవ్వడం ఆగిపోయే సర్వర్లను ప్రణాళిక జాబితాగా చూపిస్తుంది. మళ్లీ చేరితే ఎవరూ మార్చని కాపీలు తీసివేయబడతాయి.
- `extensions` నుంచి బయటకు వెళ్తే, బయటకు వెళ్తున్న ఖాతా ఫోల్డర్ ద్వారా పాత్‌లు వెళ్లిన చోట, గ్రూప్ ప్లగిన్ జాబితాలు కూడా గ్రూప్ ఫోల్డర్‌కు చూపేలా మార్చబడతాయి; ఇతర ఖాతాలకు, మళ్లీ రాసిన పాత్‌లు అవే ప్లగిన్‌లకు దారితీస్తాయి.

రెండు వైపులా వేరే కంటెంట్‌తో ఉన్న ఒకే ఫైల్ ఘర్షణ:

<!-- motion:share-conflict -->

`settings.json` వంటి ఒంటరి ఫైళ్ల కోసం మీరే ఎంచుకుంటారు; ఫోల్డర్‌ల లోపల గ్రూప్ కాపీనే ఉంటుంది, భిన్నంగా ఉన్న ఫైళ్ల పేర్లను ప్రణాళిక చెబుతుంది. ఎంపికలు ఫైల్‌పై ఆధారపడి ఉంటాయి; మొదటిది డిఫాల్ట్:

| ఫైల్ | ఎంపికలు |
| --- | --- |
| `history.jsonl` | `merge by line`, `keep group`, `use mine` |
| ఇతర `.json` ఫైళ్లు | `keep group`, `use mine`, `merge JSON` |
| మిగతావి | `keep group`, `use mine` |

`merge JSON` ఆబ్జెక్ట్‌లను రికర్సివ్‌గా మెర్జ్ చేస్తుంది, అర్రేలను నకళ్లు లేకుండా కలుపుతుంది, రెండు వైపులా ఒకే కీని వేరుగా సెట్ చేస్తే గ్రూప్ విలువను ఉంచుతుంది, కాబట్టి ఇతర ఖాతాలకు ఏ మార్పూ కనిపించదు. `keep group` తప్ప ప్రతి ఎంపిక ముందుగా గ్రూప్ కాపీని ఖాతా యొక్క `.ccam-backup/<time>/group/` లో సేవ్ చేస్తుంది. మీ సొంత ఫైల్ ఎప్పుడూ బ్యాకప్‌కు వెళ్తుంది.

ప్రతి ప్రారంభంలో, ccam లేఅవుట్‌లోని ప్రతి పాత్‌ను `lstat`, `readlink` మాత్రమే ఉపయోగించి ఖాతా గ్రూప్‌లతో పోలుస్తుంది (`share.Check`). లేని లింక్ అక్కడికక్కడే సృష్టించబడుతుంది. లింక్ ఉండాల్సిన చోట అసలు ఫైల్, తప్పు చోటికి లింక్, లేదా పాతబడిన లింక్ ప్రారంభాన్ని ఆపి, `ccam doctor --fix` ను సూచిస్తుంది.

### పేరు మార్చడం, తీసివేయడం, పాత ఫార్మాట్

- `ccam group rename` కాన్ఫిగ్‌ను మాత్రమే మారుస్తుంది. ఫోల్డర్ తన పేరును ఉంచుకుంటుంది, గ్రూప్ దాన్ని `dir` గా నమోదు చేస్తుంది, కాబట్టి ఏదీ తరలదు, ఏదీ కోల్పోదు.
- మీరు `--leave` జోడిస్తే తప్ప, ఖాతాలు ఉన్న గ్రూప్‌ను `ccam group remove` తిరస్కరిస్తుంది. అప్పుడు ప్రతి ఖాతా ఒక కాపీని ఉంచుకుంటుంది, మరో గ్రూప్ ఆ ఫోల్డర్‌ను ఉపయోగిస్తే తప్ప అది `~/.local/share/ccam/trash/` కు వెళ్తుంది.
- గ్రూప్‌లకు ముందు, `config.toml` ప్రతి ఖాతాకు ఒక `[profile.share]` టేబుల్‌ను నిల్వ చేసేది. ccam ఆ ఫార్మాట్‌ను ఏదీ తరలించకుండా గ్రూప్‌లుగా చదువుతుంది. మొదటి సేవ్‌లో అది కొత్త ఫార్మాట్‌ను రాసి, పాత ఫైల్‌ను `config.toml.bak` గా ఉంచుతుంది. అవే ఖాతాలు షేర్ చేసిన అంశాలు ఫోల్డర్ పేరుతో ఒకే గ్రూప్ అవుతాయి; మిగతావాటికి `default-history` వంటి పేర్లు వస్తాయి, అవి అదే ఫోల్డర్‌ను ఉపయోగిస్తూనే ఉంటాయి.

### Windows లో

Windows symbolic links ను Developer Mode (Settings > System > For developers) లో లేదా అడ్మినిస్ట్రేటర్‌కు మాత్రమే సృష్టిస్తుంది. ఆ హక్కు లేకపోతే, షేర్డ్ ఫోల్డర్ directory junction అవుతుంది, Claude Code కు అది అలాగే పనిచేస్తుంది. షేర్డ్ ఫైల్ (`settings.json`, `CLAUDE.md`, `history.jsonl`) symbolic link మాత్రమే కాగలదు, కాబట్టి అలాంటి లింక్ అవసరమైన గ్రూప్ మార్పు ఏదైనా తరలక ముందే తిరస్కరించబడుతుంది. అదే కారణంతో, అక్కడ మొదటి `ccam add` `mcp`, `extensions` తో మాత్రమే `default` గ్రూప్‌ను సృష్టించి ఆ విషయం చెబుతుంది, సెట్టింగ్‌లు, memory లేదా చరిత్రను షేర్ చేసే గ్రూప్‌లోకి `ccam add --group` తిరస్కరించబడుతుంది.

## భద్రత, ప్రత్యేక సందర్భాలు

- **రన్ అవుతున్న ఖాతాలు.** మార్పు తరలించే ఖాతాలలో ఒకదానిగా Claude Code రన్ అవుతున్నప్పుడు, దాన్ని ccam ప్రారంభించినా లేకపోయినా (సాధారణ `claude`, ఒక IDE, బ్యాక్‌గ్రౌండ్ సెషన్‌లు), ఆ మార్పు తిరస్కరించబడుతుంది, ఎందుకంటే సెషన్ ఆ ఫైళ్లలోనే రాస్తూ ఉంటుంది. సేవ్ చేయడానికి సరిగ్గా ముందు ఈ తనిఖీ మళ్లీ జరుగుతుంది. బయటకు రావడం, చేరడం పేర్కొన్న ఖాతాను మాత్రమే ప్రభావితం చేస్తాయి; `extensions` నుంచి బయటకు రావడం గ్రూప్ ప్లగిన్ జాబితాల్లోని పాత్‌లను కూడా మళ్లీ రాస్తుంది, ఇతరులకు వాటి అర్థాన్ని మార్చకుండా. `--dry-run` అయినా ప్రణాళికను ప్రింట్ చేస్తుంది.
- **బ్యాకప్‌లు.** ప్రతి ప్రణాళికకు ఖాతా ఫోల్డర్‌లో సొంత `.ccam-backup/<time>/` ఫోల్డర్ ఉంటుంది. ccam వాటిని ఎప్పుడూ తొలగించదు.
- **మీ సొంత లింక్‌లు.** ఒక పాత్ ఇప్పటికే మీరు చేసిన లింక్ అయితే, ఉదాహరణకు dotfiles రిపోజిటరీకి, గ్రూప్ ఖాళీగా ఉంటే, ccam లింక్ లక్ష్యాన్ని గ్రూప్‌లోకి కాపీ చేసి, లింక్‌ను బ్యాకప్‌కు తరలిస్తుంది. లక్ష్యాన్ని ముట్టుకోదు.
- **ఇంపోర్ట్ చేసిన ఫోల్డర్‌లు.** `ccam import` తో ఉన్న చోటే నమోదైన ఖాతా (`~/.claude` వంటిది) ఉన్న చోటే మారుతుంది, కాబట్టి సాధారణ `claude` కూడా మార్పును చూస్తుంది; ప్రణాళిక ఆ విషయం చెబుతుంది. అది గ్రూప్ నుంచి బయటకు వెళ్లినప్పుడు, `--fresh` తో కూడా, ఎప్పుడూ ఒక కాపీని ఉంచుకుంటుంది, ఖాతాను మరచిపోయే ముందు `ccam remove` దాన్ని అదే విధంగా దాని గ్రూప్‌ల నుంచి బయటకు తీస్తుంది. అది గ్రూప్‌లో ఉన్నంతవరకు దాని షేర్డ్ ఫైళ్లు గ్రూప్ ఫోల్డర్‌లో ఉంటాయి, కాబట్టి `~/.local/share/ccam` ను తొలగించే ముందు ఖాతాను తీసివేయండి (లేదా గ్రూప్‌ల నుంచి బయటకు రండి).
- **ఒకే ఫోల్డర్‌లో రెండు ఖాతాలు.** చరిత్రను షేర్ చేసే ఖాతాలు ఒకే ఫైళ్లలో రాస్తాయి. ఒక ఖాతా ఇప్పటికే రన్ అవుతున్న ఫోల్డర్‌లో రెండో ఖాతా ప్రారంభమైనప్పుడు, ccam హెచ్చరించి అడుగుతుంది.
- **చేతితో చేసిన మార్పులు.** `members` లో ఖాతా కాని పేరు ఉంటే, ccam దాన్ని పట్టించుకోదు, `ccam doctor` దాన్ని నివేదిస్తుంది. `local`, `on`, `off`, `none` పేర్లు గ్రూప్ పేర్లు కాలేవు.
