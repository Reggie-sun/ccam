`ccam next` మీరు పేరు చెప్పకుండానే Claude Code ను మరో ఖాతాగా తెరుస్తుంది. ఒక ఖాతా తన వినియోగ పరిమితిని చేరుకున్నప్పుడు దీన్ని ఉపయోగించండి: సాధారణ `ccam next` మీరు చివరిగా ఉపయోగించిన ఖాతా తర్వాతి ఖాతాను తీసుకుంటుంది, `--auto` తన 5 గంటల విండోలో ఎక్కువ అవకాశం ఉన్న ఖాతాను తీసుకుంటుంది, `--continue` చివరి సంభాషణను కొత్త ఖాతాలో కొనసాగిస్తుంది.

## వినియోగం

```sh
ccam next                       # the account after the one you used last
ccam next --auto                # the account with the lowest 5-hour usage
ccam next --continue            # the next account that shares history, with claude --continue
ccam next -c --auto             # both: lowest usage among accounts sharing history
ccam next -- -p "summarize"     # pass arguments to claude after --
ccam --dry-run next --auto      # print the choice and the command, start nothing
```

```console
$ ccam --dry-run next
→ personal → work
CLAUDE_CONFIG_DIR=/home/you/.local/share/ccam/profiles/work /usr/local/bin/claude
```

ccam మార్పును స్టాండర్డ్ ఎర్రర్‌లో `→ <from> → <to>` గా ప్రింట్ చేసి, ఆపై `ccam <name>` చేసే విధంగానే కొత్త ఖాతాగా Claude Code ను ప్రారంభిస్తుంది. `<from>` అంటే మీరు చివరిగా ఉపయోగించిన ఖాతా. `--` తర్వాతి ఆర్గ్యుమెంట్‌లు మార్పు లేకుండా `claude` కు వెళ్తాయి.

## ఆప్షన్లు

| ఆప్షన్ | ఏమి చేస్తుంది | డిఫాల్ట్ |
| --- | --- | --- |
| `--auto` | అతి తక్కువ 5 గంటల వినియోగం ఉన్న లాగిన్ అయిన ఖాతాను ఎంచుకుంటుంది, 100% వద్ద ఉన్న ఖాతాలను వదిలేస్తుంది | ఆఫ్ |
| `-c`, `--continue` | మీరు చివరిగా ఉపయోగించిన ఖాతాతో సంభాషణ చరిత్రను షేర్ చేసే ఖాతాలను మాత్రమే పరిగణించి, `claude --continue` ను ప్రారంభిస్తుంది | ఆఫ్ |
| `-- <claude args>` | ccam సొంత ఆర్గ్యుమెంట్‌ల తర్వాత `claude` కు పంపే ఆర్గ్యుమెంట్‌లు | ఏమీ లేవు |
| `--dry-run` | పాటిస్తుంది: Claude Code ను ప్రారంభించకుండా, ప్రారంభాన్ని నమోదు చేయకుండా, `→ <from> → <to>` ను, తాను రన్ చేసే కమాండ్ లైన్‌ను ప్రింట్ చేస్తుంది | ఆఫ్ |

`--auto`, `--continue` కలిసి పనిచేస్తాయి. `--continue` తో, `--continue` మీ సొంత ఆర్గ్యుమెంట్‌ల ముందు పెట్టబడుతుంది.

## ఇది ఎలా పనిచేస్తుంది

ccam ద్వారా జరిగే ప్రతి ప్రారంభం సమయాన్ని `~/.local/state/ccam/last-used/<name>` లో రాస్తుంది. `ccam next` ఈ ఫైళ్లను చదివి, ఏ ఖాతాలు లాగిన్ అయి ఉన్నాయో తనిఖీ చేసి, ఎంచుకుంటుంది.

1. `cli.candidates` `config.toml` నుంచి ప్రతి ఖాతాకు ఒక `next.Candidate` ను తయారు చేస్తుంది: ఖాతా, దాని చివరి ప్రారంభ సమయం (`launcher.LastUsed`), దానికి లాగిన్ ఉందా లేదా (`creds.Has`: చదవగలిగే `.credentials.json`, లేదా macOS లో ఒక Keychain ఐటమ్).
2. `--auto` లేకుండా, `next.Rotate` ఖాతాలను స్లాట్ నంబర్ ప్రకారం క్రమబద్ధీకరించి, అత్యంత ఇటీవల ప్రారంభించిన దాన్ని కనుగొంటుంది. మీరు దాని నుంచే మారుతున్నారు. ఇంకా ఏ ఖాతా ప్రారంభించబడకపోతే, అది అతి తక్కువ స్లాట్.
3. అక్కడి నుంచి అది స్లాట్ క్రమంలో ముందుకు వెళ్తుంది, చివరి స్లాట్ నుంచి మొదటిదానికి తిరిగి చుట్టుకుంటుంది, లాగిన్ అయిన మొదటి ఖాతాను తిరిగి ఇస్తుంది.
4. `launcher.LaunchWith` ఎంచుకున్న ఖాతాను `ccam <name>` చేసే విధంగానే సిద్ధం చేసి ప్రారంభిస్తుంది: ఖాతా లింక్‌లను తనిఖీ చేస్తుంది, MCP షేరింగ్‌ను వర్తింపజేస్తుంది, సెషన్‌ను నమోదు చేస్తుంది, `syscall.Exec` ద్వారా ccam ను `claude` తో భర్తీ చేస్తుంది.

ఈ ప్రయాణం చివరిగా ఉపయోగించిన ఖాతా వద్ద మొదలై, దాని తర్వాత లాగిన్ అయిన మొదటి ఖాతా వద్ద ఆగుతుంది:

`work` అత్యంత ఇటీవల ప్రారంభించబడింది, కాబట్టి ప్రయాణం దాని తర్వాత మొదలవుతుంది. `side` కు లాగిన్ లేదు కాబట్టి వదిలేయబడుతుంది, `lab` ఎంచుకోబడుతుంది. `lab` కూడా లాగ్ అవుట్ అయి ఉంటే, ప్రయాణం `personal` కు చుట్టుకునేది (డయాగ్రామ్‌లోని `% len`). రొటేషన్ మీరు మొదలుపెట్టిన ఖాతాను ఎప్పుడూ తిరిగి ఇవ్వదు: లాగిన్ అయిన మరో ఖాతా లేకపోతే, అది ఒక ఎర్రర్‌తో ఆగుతుంది.

### --auto

`--auto` స్లాట్ క్రమం బదులు వినియోగం ఆధారంగా నిర్ణయిస్తుంది. `cli.pickAuto` లాగిన్ అయిన ఖాతాలను ఉంచుకుని, `ccam usage` ఉపయోగించే అదే `Fetcher.FetchAll` తో వాటన్నింటి వినియోగాన్ని ఒకేసారి అడిగి, `usage.Best()` ను ఎంచుకోనిస్తుంది:

<!-- motion:next-auto -->

`usage.Best()` అతి తక్కువ 5 గంటల శాతాన్ని తీసుకుంటుంది, 100% వద్ద ఉన్న లేదా 5 గంటల వినియోగం తెలియని ఖాతాలను వదిలేస్తుంది. ఈ లుకప్ `ccam usage` నియమాలను పాటిస్తుంది: 60 సెకన్ల కంటే కొత్త సంఖ్యలు మళ్లీ ఉపయోగించబడతాయి, ప్రతి ఖాతాకు 3 సెకన్లు ఉంటాయి, సమాధానం ఇవ్వని లేదా లాగిన్ గడువు ముగిసిన ఖాతాను దాని సేవ్ చేసిన సంఖ్యలతో అంచనా వేస్తుంది. రీసెట్ సమయం దాటిన సేవ్ చేసిన విండో 0% గా లెక్కించబడుతుంది, కాబట్టి ఆ తర్వాత విండో రీసెట్ అయిన ఖాతా వదిలివేయబడదు. `--auto` ఎప్పుడూ టోకెన్‌లను పునరుద్ధరించదు. సాధారణ రొటేషన్‌లా కాకుండా, మీరు చివరిగా ఉపయోగించిన ఖాతాకు ఇంకా ఎక్కువ అవకాశం ఉంటే `--auto` దాన్నే ఎంచుకోవచ్చు.

### --continue

Claude Code యొక్క `--continue` ప్రస్తుత ఫోల్డర్‌లోని అత్యంత ఇటీవలి సంభాషణను తెరుస్తుంది, కొత్త ఖాతా ఆ సంభాషణను చూడగలిగితేనే ఇది పనిచేస్తుంది. కాబట్టి `--continue` తో, మీరు చివరిగా ఉపయోగించిన ఖాతా ఉన్న అదే `history` గ్రూప్‌లోని ఖాతాలను మాత్రమే ccam పరిగణించి, ఆపై మీ ఆర్గ్యుమెంట్‌ల ముందు `--continue` ను పెడుతుంది. చరిత్ర `local` గా ఉన్న ఖాతాలు ఎవరితోనూ షేర్ చేయవు, కాబట్టి అలాంటి ఖాతా నుంచి `--continue` ఎప్పుడూ విఫలమవుతుంది. ముందుగా `ccam share <name> --history on` తో షేరింగ్ ఆన్ చేయండి ([షేరింగ్](/docs/sharing) చూడండి).

## భద్రత, ప్రత్యేక సందర్భాలు

- లాగిన్ లేని ఖాతాలు ఎప్పుడూ ఎంచుకోబడవు. లాగిన్ అయిన మరో ఖాతా లేకపోతే, సాధారణ `ccam next` `no logged-in account other than <name>` తో ఆగుతుంది.
- `--continue` తో, చరిత్రను షేర్ చేసే ఖాతా ఏదీ లేనప్పుడు: `` no other account shares conversation history with <name>. Turn it on with `ccam share <name> --history on` ``.
- `--auto` తో, లాగిన్ అయిన ఖాతా ఏదీ లేనప్పుడు: `no logged-in account to pick`. ప్రతి ఖాతా నిండిపోయినప్పుడు లేదా దాని వినియోగం తెలియనప్పుడు: `` no account with known usage and headroom (see `ccam usage`) ``.
- `--dry-run` తో కూడా `--auto` నెట్‌వర్క్ అభ్యర్థనలు చేస్తుంది. అది చదువుతుంది మాత్రమే, టోకెన్ ఫైళ్లలో ఎప్పుడూ రాయదు.
- ఎంచుకున్న ఖాతా `ccam <name>` ఉన్న అదే మార్గం ద్వారా ప్రారంభమవుతుంది, కాబట్టి అవే తనిఖీలు వర్తిస్తాయి, అదే చరిత్రను షేర్ చేసే మరో Claude Code ఈ ఫోల్డర్‌లో ఇప్పటికే రన్ అవుతున్నప్పుడు వచ్చే హెచ్చరికతో సహా.
- Claude Code నిజంగా ప్రారంభమైనప్పుడు మాత్రమే `last-used` రాయబడుతుంది. `--dry-run` దాన్ని ముట్టుకోదు, కాబట్టి డ్రై రన్ రొటేషన్‌ను ముందుకు జరపదు.
