`ccam next` మీరు పేరు చెప్పకుండానే Claude Code ను మరో ఖాతాగా తెరుస్తుంది. ఒక ఖాతా తన వినియోగ పరిమితిని చేరుకున్నప్పుడు దీన్ని ఉపయోగించండి: సాధారణ `ccam next` మీరు చివరిగా ఉపయోగించిన ఖాతా తర్వాతి ఖాతాను తీసుకుంటుంది, `--auto` ఎక్కువ అవకాశం ఉన్న ఖాతాను తీసుకుంటుంది, `--continue` ఈ ఫోల్డర్ యొక్క చివరి సంభాషణను కొత్త ఖాతాకు తీసుకువెళ్తుంది, ఆ రెండూ చరిత్రను షేర్ చేసినా చేయకపోయినా. Claude Code లోపల, ఒక పరిమితి సెషన్‌ను ఆపినప్పుడు [ccam ప్లగిన్](#inside-claude-code) మీకు చెబుతుంది, `/ccam:switch` సంభాషణను ముందుకు అప్పగిస్తుంది. `claude -p` రన్ చేసే స్క్రిప్ట్‌ల కోసం, `ccam --fallback` ఆ మార్పును తనంతట తానే చేస్తుంది (చూడండి [పరిమితి వద్ద మళ్లీ రన్ చేయడం](#run-again-at-the-limit)).

## వినియోగం

```sh
ccam next                       # the account after the one you used last
ccam next --auto                # the account with the most room
ccam next --continue            # carry this folder's last conversation on as the next account
ccam next -c --auto             # both: the conversation, on the account with the most room
ccam next --auto --max-usage 80 # prefer accounts below 80%
ccam next --auto --strategy balance   # the weekly quota that would go unused first
ccam next --auto --cross-org    # also accounts of other organizations
ccam next --auto --wait         # nobody has room: wait for the first reset (up to 5 hours)
ccam next -- -p "summarize"     # pass arguments to claude after --
ccam --dry-run next --auto      # print the choice and the command, start nothing
```

```console
$ ccam --dry-run next --auto --continue
→ personal → work (12% of its 5 hours used, the least)
  continuing "Fix the flaky tests" (about 182k tokens); work does not share personal's history, so Claude Code copies it into work
CLAUDE_CONFIG_DIR=/home/you/.local/share/ccam/profiles/work /usr/local/bin/claude --resume /home/you/.local/share/ccam/profiles/personal/projects/-home-you-code-app/4f1c….jsonl --fork-session
```

ccam మార్పును స్టాండర్డ్ ఎర్రర్‌లో `→ <from> → <to>` గా, `--auto` ఎంపికకు కారణంతో సహా ప్రింట్ చేసి, ఆపై `ccam <name>` చేసే విధంగానే కొత్త ఖాతాగా Claude Code ను ప్రారంభిస్తుంది. `<from>` అంటే మీరు చివరిగా ఉపయోగించిన ఖాతా, లేదా `--continue` తో సంభాషణ చెందిన ఖాతా. `--` తర్వాతి ఆర్గ్యుమెంట్‌లు మార్పు లేకుండా `claude` కు వెళ్తాయి.

## ఆప్షన్లు

| ఆప్షన్ | ఏమి చేస్తుంది | డిఫాల్ట్ |
| --- | --- | --- |
| `--auto` | వినియోగం ఆధారంగా (కింద చూడండి) లాగిన్ అయిన ఖాతాను ఎంచుకుంటుంది, 100% వద్ద ఉన్న ఖాతాలను వదిలేస్తుంది | ఆఫ్ |
| `--max-usage <1-100>` | `--auto` తో: ఈ వినియోగం కంటే తక్కువ ఉన్న ఖాతాలకు ప్రాధాన్యం ఇస్తుంది | `auto_max_usage`, లేకపోతే 100 |
| `--strategy headroom\|expiring\|balance` | `--auto` తో: అతి తక్కువ 5 గంటల వినియోగం, అన్నిటికంటే ముందు వచ్చే 5 గంటల రీసెట్, లేదా అన్నిటికంటే ముందు వృథా అయ్యే వారపు కోటా | `auto_strategy`, లేకపోతే `headroom` |
| `--cross-org` | `--auto` తో: మరో సంస్థకు చెందిన ఖాతాలను కూడా ఎంచుకుంటుంది (కింద చూడండి) | `cross_org`, లేకపోతే ఆఫ్ |
| `--wait[=<duration>]` | `--auto` తో: ఏ ఖాతాలోనూ అవకాశం లేనప్పుడు, మొదటి ఖాతా రీసెట్ అయ్యే వరకు, గరిష్ఠంగా ఇంత సేపు వేచి ఉంటుంది | ఆఫ్; ఒంటరిగా ఇస్తే `5h` |
| `-c`, `--continue` | ఈ ఫోల్డర్ యొక్క చివరి సంభాషణను కొత్త ఖాతాగా కొనసాగిస్తుంది (కింద చూడండి) | ఆఫ్ |
| `-- <claude args>` | ccam సొంత ఆర్గ్యుమెంట్‌ల తర్వాత `claude` కు పంపే ఆర్గ్యుమెంట్‌లు | ఏమీ లేవు |
| `--dry-run` | పాటిస్తుంది: Claude Code ను ప్రారంభించకుండా, ప్రారంభాన్ని నమోదు చేయకుండా, `→ <from> → <to>` ను, తాను రన్ చేసే కమాండ్ లైన్‌ను ప్రింట్ చేస్తుంది | ఆఫ్ |

`--auto`, `--continue` కలిసి పనిచేస్తాయి. `--continue` తో, `--resume` ఆర్గ్యుమెంట్‌లు మీ సొంత ఆర్గ్యుమెంట్‌ల ముందు పెట్టబడతాయి.

## ఇది ఎలా పనిచేస్తుంది

ccam ద్వారా జరిగే ప్రతి ప్రారంభం సమయాన్ని `~/.local/state/ccam/last-used/<name>` లో రాస్తుంది. `ccam next` ఈ ఫైళ్లను చదివి, ఏ ఖాతాలు లాగిన్ అయి ఉన్నాయో తనిఖీ చేసి, ఎంచుకుంటుంది.

1. `cli.candidates` `config.toml` నుంచి ప్రతి ఖాతాకు ఒక `next.Candidate` ను తయారు చేస్తుంది: ఖాతా, దాని చివరి ప్రారంభ సమయం (`launcher.LastUsed`), దానికి లాగిన్ ఉందా లేదా (`creds.Has`: చదవగలిగే `.credentials.json`, లేదా macOS లో ఒక Keychain ఐటమ్).
2. `--auto` లేకుండా, `next.Rotate` ఖాతాలను స్లాట్ నంబర్ ప్రకారం క్రమబద్ధీకరించి, అత్యంత ఇటీవల ప్రారంభించిన దాన్ని కనుగొంటుంది. మీరు దాని నుంచే మారుతున్నారు. ఇంకా ఏ ఖాతా ప్రారంభించబడకపోతే, అది అతి తక్కువ స్లాట్.
3. అక్కడి నుంచి అది స్లాట్ క్రమంలో ముందుకు వెళ్తుంది, చివరి స్లాట్ నుంచి మొదటిదానికి తిరిగి చుట్టుకుంటుంది, లాగిన్ అయిన మొదటి ఖాతాను తిరిగి ఇస్తుంది.
4. `launcher.LaunchWith` ఎంచుకున్న ఖాతాను `ccam <name>` చేసే విధంగానే సిద్ధం చేసి ప్రారంభిస్తుంది: ఖాతా లింక్‌లను తనిఖీ చేస్తుంది, MCP షేరింగ్‌ను వర్తింపజేస్తుంది, సెషన్‌ను నమోదు చేస్తుంది, `syscall.Exec` ద్వారా ccam ను `claude` తో భర్తీ చేస్తుంది.

ఈ ప్రయాణం చివరిగా ఉపయోగించిన ఖాతా వద్ద మొదలై, దాని తర్వాత లాగిన్ అయిన మొదటి ఖాతా వద్ద ఆగుతుంది:

`work` అత్యంత ఇటీవల ప్రారంభించబడింది, కాబట్టి ప్రయాణం దాని తర్వాత మొదలవుతుంది. `side` కు లాగిన్ లేదు కాబట్టి వదిలేయబడుతుంది, `lab` ఎంచుకోబడుతుంది. `lab` కూడా లాగ్ అవుట్ అయి ఉంటే, ప్రయాణం `personal` కు చుట్టుకునేది (డయాగ్రామ్‌లోని `% len`). రొటేషన్ మీరు మొదలుపెట్టిన ఖాతాను ఎప్పుడూ తిరిగి ఇవ్వదు: లాగిన్ అయిన మరో ఖాతా లేకపోతే, అది ఒక ఎర్రర్‌తో ఆగుతుంది.

### --auto

`--auto` స్లాట్ క్రమం బదులు వినియోగం ఆధారంగా నిర్ణయిస్తుంది. `cli.pickAuto` లాగిన్ అయిన ఖాతాలను ఉంచుకుని, `ccam usage` ఉపయోగించే అదే `Fetcher.FetchAll` తో వాటన్నింటి వినియోగాన్ని ఒకేసారి అడిగి, `usage.Policy.Choose()` ను ఎంచుకోనిస్తుంది:

<!-- motion:next-auto -->

ఒక ఖాతాను దాని 5 గంటల, వారపు విండోలతో అంచనా వేస్తారు, Claude Code కోసం ఇచ్చిన ఆర్గ్యుమెంట్‌లలో `--model` ఉంటే ఆ మోడల్ వారపు విండోతో కూడా (పేరులో `opus`, `sonnet`, `haiku` లేదా `fable`). `Policy.Choose()` ఖాతాలను మూడు వర్గాలుగా విభజిస్తుంది:

1. **అవకాశం ఉన్నవి**: ప్రతి విండో `auto_max_usage` (`config.toml`, డిఫాల్ట్ 100) కంటే తక్కువ. వాటిలో strategy ఎంచుకుంటుంది: `headroom` (డిఫాల్ట్) అతి తక్కువ 5 గంటల వినియోగాన్ని తీసుకుంటుంది; `expiring` అన్నిటికంటే ముందు రీసెట్ అయ్యే 5 గంటల విండోను తీసుకుంటుంది, కాబట్టి దాని మిగిలిన quota కోల్పోక ముందే ఉపయోగించబడుతుంది; `balance` వారం రీసెట్ అయ్యే వరకు రోజుకు ఎక్కువ వారపు quota మిగిలి ఉన్న ఖాతాను తీసుకుంటుంది, రన్ అవుతున్న ప్రతి ccam సెషన్‌ను దానికి వ్యతిరేకంగా లెక్కిస్తూ, కాబట్టి వారపు quota వృథా కాదు, సమాంతర సెషన్‌లు పంచబడతాయి.
2. **మించినవి**: 100% కంటే తక్కువ, కానీ `auto_max_usage` వద్ద లేదా అంతకంటే ఎక్కువ. ఏ ఖాతాలోనూ అవకాశం లేనప్పుడే ఉపయోగించబడతాయి, అతి తక్కువ 5 గంటల వినియోగం ముందుగా.
3. **నిండినవి**: 100% వద్ద ఒక విండో, లేదా తెలియని 5 గంటల వినియోగం. ఎప్పుడూ ఎంచుకోబడవు.

```toml
# ~/.config/ccam/config.toml
auto_max_usage = 80        # keep 20% of each account for interactive work
auto_strategy = "expiring"
```

**సంస్థలు.** ఆటోమేటిక్ ఎంపికలు మీరు వదిలే ఖాతా లాంటి ఖాతాల దగ్గరే ఉంటాయి: అదే team లేదా enterprise సంస్థ, లేదా వ్యక్తిగత ప్లాన్‌లు (Pro, Max) కలిసి, కాబట్టి కంపెనీ ఖాతా నుంచి వచ్చిన పని వ్యక్తిగత ఖాతాలో కొనసాగదు, అలాగే వ్యక్తిగత పని కంపెనీ ఖాతాలో కొనసాగదు. ప్రతి ఖాతా సంస్థను ccam దాని లాగిన్ నుంచి తెలుసుకుంటుంది (`ccam login` దాన్ని నమోదు చేస్తుంది; పాత లాగిన్‌లు `.claude.json` నుంచి చదవబడతాయి); ccam చెప్పలేని ఖాతా ఎక్కడైనా సరిపోతుంది. ఒకే Claude ఖాతాలోకి లాగిన్ అయిన రెండు ఫోల్డర్‌లు దాని పరిమితులను పంచుకుంటాయి, కాబట్టి ఒకటి మరొకదాని స్థానాన్ని ఎప్పుడూ తీసుకోదు. `--cross-org`, లేదా `config.toml` లో `cross_org = true`, సంస్థ నియమాన్ని ఎత్తివేస్తుంది.

ఏదీ ఎంచుకోలేనప్పుడు, ccam కోడ్ 75 (`EX_TEMPFAIL`) తో నిష్క్రమిస్తుంది, కాబట్టి స్క్రిప్ట్ "తర్వాత ప్రయత్నించు" ను వైఫల్యం నుంచి వేరు చేయగలదు. `--wait` తో, బదులుగా అది మొదటి నిండిన ఖాతా అడ్డుకుంటున్న విండో రీసెట్ అయ్యే వరకు నిద్రిస్తుంది (రీసెట్ సమయం తర్వాత 30 సెకన్లకు, ఎండ్‌పాయింట్ కొత్త విండోను చూపించినప్పుడు), `ccam: no account has room; waiting until 15:10` అని ప్రింట్ చేసి, మళ్లీ ఎంచుకుంటుంది; ఏ ఖాతా ఎప్పుడు రీసెట్ అవుతుందో చెప్పనప్పుడు, 10 నిమిషాల తర్వాత మళ్లీ చూస్తుంది. వేచి ఉండటం ముగిసే లోపు ఏదీ ఖాళీ కాకపోతే, 75 తో నిష్క్రమిస్తుంది. ఈ లుకప్ `ccam usage` నియమాలను పాటిస్తుంది: 60 సెకన్ల కంటే కొత్త సంఖ్యలు మళ్లీ ఉపయోగించబడతాయి, ప్రతి ఖాతాకు 3 సెకన్లు ఉంటాయి, సమాధానం ఇవ్వని లేదా లాగిన్ గడువు ముగిసిన ఖాతాను దాని సేవ్ చేసిన సంఖ్యలతో అంచనా వేస్తుంది. రీసెట్ సమయం దాటిన సేవ్ చేసిన విండో 0% గా లెక్కించబడుతుంది, కాబట్టి ఆ తర్వాత విండో రీసెట్ అయిన ఖాతా వదిలివేయబడదు. `--auto` ఎప్పుడూ టోకెన్‌లను పునరుద్ధరించదు. సాధారణ రొటేషన్‌లా కాకుండా, మీరు చివరిగా ఉపయోగించిన ఖాతాకు ఇంకా ఎక్కువ అవకాశం ఉంటే `--auto` దాన్నే ఎంచుకోవచ్చు.

### --continue

1. ccam ప్రతి ఖాతాలో ఈ ఫోల్డర్ యొక్క చివరి సంభాషణ కోసం చూస్తుంది: `projects/<folder>/` లోని అత్యంత కొత్త `<session>.jsonl` (ఫోల్డర్ పేరు అంటే working ఫోల్డర్, అందులో అక్షరం లేదా అంకె కాని ప్రతి అక్షరం `-` గా మార్చబడుతుంది, Claude Code పేరు పెట్టే విధంగానే). సెషన్ ఒక నోట్ వదిలి ఉంటే (వినియోగ పరిమితి లేదా `/ccam:switch`, కింద చూడండి), ఆ తర్వాత కొత్తదేమీ రాయబడకపోతే, బదులుగా సరిగ్గా ఆ సెషన్ ఉపయోగించబడుతుంది.
2. అది చెందిన ఖాతా నుంచే మీరు మారుతున్నారు, కొత్త ఖాతా పైన చెప్పినట్లుగా, అదే సంస్థలో ఎంచుకోబడుతుంది.
3. కొత్త ఖాతా ఆ చరిత్రను షేర్ చేస్తే (అదే గ్రూప్ ఫోల్డర్), ccam `claude --resume <session id>` ను, అంటే సరిగ్గా ఆ సంభాషణనే, ప్రారంభిస్తుంది (`--continue` అయితే ఫోల్డర్‌లో ఏది అత్యంత కొత్తదో దాన్ని తెరుస్తుంది).
4. లేకపోతే అది `claude --resume <the conversation's file> --fork-session` ను ప్రారంభిస్తుంది: Claude Code మొత్తం సంభాషణను, కొత్త సెషన్ id తో, కొత్త ఖాతా సొంత చరిత్రలోకి కాపీ చేస్తుంది, అసలుది ఉన్నట్లే ఉంటుంది. అప్పటి నుంచి కొత్త ఖాతా `--continue` దాన్ని కనుగొంటుంది.

సంభాషణ ఎంత పెద్దదో ccam చెబుతుంది: కొత్త ఖాతా తన మొదటి సమాధానంతో దాన్నంతా మళ్లీ చదువుతుంది. prompt caches సంస్థల మధ్య ఎప్పుడూ షేర్ కావు, కాబట్టి `--cross-org` తో ఆ మొదటి సమాధానానికి పూర్తి పరిమాణం ఖర్చవుతుంది. ఒక గ్రూప్‌లో `history` ను షేర్ చేయడం కాపీని నివారిస్తుంది, ఒకే సంభాషణను ఉంచుతుంది, `/rewind` కోడ్‌ను పునరుద్ధరించే checkpoints (`file-history/`) ను కూడా షేర్ చేస్తుంది.

## Claude Code లోపల

[ccam ప్లగిన్](/docs/install#claude-code-plugin) రెండు hooks ను జోడిస్తుంది (Claude Code 2.1.78 లేదా తర్వాతి వెర్షన్):

- ఒక turn వినియోగ పరిమితి వద్ద ఆగినప్పుడు (`You've hit your session limit`, వారపు లేదా మోడల్ పరిమితి), అది సంభాషణను గుర్తుపెట్టి, సపోర్ట్ చేసే టెర్మినల్‌లలో (iTerm2, WezTerm, Windows Terminal, kitty, Ghostty) డెస్క్‌టాప్ నోటిఫికేషన్‌ను చూపిస్తుంది: `ccam: work hit its 5-hour limit (resets 3:45pm). ccam next --continue carries on as another account.` సర్వర్ చేసే చిన్న throttle లేదా API కీ rate limit వినియోగ పరిమితి కాదు, వాటిని అలాగే వదిలేస్తుంది. Claude Code 2.1.234, తర్వాతి వెర్షన్‌లు కూడా సెషన్‌లో వేచి ఉండి, 5 గంటల రీసెట్ తర్వాత తమంతట తామే కొనసాగుతాయి; బదులుగా మారే ఎంపికను నోటిఫికేషన్ మీకు ఇస్తుంది.
- `/ccam:switch [account]` సంభాషణను గుర్తుపెట్టి, ఏ అభ్యర్థనా చేయక ముందే turn ను ముగిస్తుంది: `/exit` టైప్ చేయండి, ఆపై `ccam next --continue` దాన్ని మీరు పేర్కొన్న ఖాతాగా, లేదా తర్వాతి ఖాతాగా కొనసాగిస్తుంది.

నోట్ `~/.local/state/ccam/handoff/<account>.json` లో 12 గంటల పాటు ఉంటుంది, తర్వాతి సెషన్ ప్రారంభం కాబోతున్నప్పుడు ఒక్కసారే ఉపయోగించబడుతుంది; విఫలమైన ప్రారంభం దాన్ని తర్వాతి ప్రయత్నం కోసం అలాగే వదిలేస్తుంది. Claude Code షెల్‌లో `cd` చేసిన తర్వాత కూడా, అది సెషన్ ప్రారంభమైన ఫోల్డర్‌కే చెందుతుంది. అందులో పేర్కొన్న ఖాతా ఆ తర్వాత పేరు మార్చబడినా లేదా తీసివేయబడినా, ccam ఆ విషయం చెప్పి, ఎప్పటిలాగే ఎంచుకుంటుంది. `config.toml` లో `relay = true` తో, ccam తన స్థానాన్ని Claude Code కు ఇవ్వకుండా ఇంటరాక్టివ్ సెషన్‌ల పక్కనే ఉంటుంది, `/ccam:switch` తర్వాత ఆ సెషన్ సంభాషణను తనంతట తానే కొనసాగిస్తుంది (మరో సెషన్ వదిలిన నోట్‌పై అది చర్య తీసుకోదు). దానికి ప్రతి సెషన్‌కు వేచి ఉండే ఒక ccam ప్రాసెస్ ఖర్చవుతుంది, అందుకే అది డిఫాల్ట్‌గా ఆఫ్‌లో ఉంటుంది. రిలే చేయబడిన సెషన్ `ccam next --continue` తో ప్రారంభమవుతుంది, మొదటి సెషన్‌ను ప్రారంభించినప్పుడు ఇచ్చిన `--model` వంటి ఆర్గ్యుమెంట్‌లు లేకుండా.

## పరిమితి వద్ద మళ్లీ రన్ చేయడం

`ccam next` ఆగిపోయిన ఇంటరాక్టివ్ సెషన్ కోసం. నాన్-ఇంటరాక్టివ్ రన్, అంటే స్క్రిప్ట్‌లో లేదా షెడ్యూల్ చేసిన job లో ఉన్న `claude -p`, మీ కోసం వేచి ఉండలేదు, కాబట్టి ఖాతా పేరుకు ముందు `--fallback` పెడితే ccam దాని కోసం మారుస్తుంది:

```sh
ccam --fallback work -p "fix the failing tests" --output-format json
ccam --fallback -p "summarise" < notes.txt      # the folder's account or the default
ccam run --fallback work -p "review the diff"
```

```console
$ ccam --fallback personal -p "summarise" < notes.txt
ccam: personal reached its usage limit; running the command again as work
Summary: …
```

1. `--fallback` `-p` లేదా `--print` తో మాత్రమే పనిచేస్తుంది; లేకపోతే ccam ఆగిపోయి `ccam next --auto --continue` ను సూచిస్తుంది.
2. స్టాండర్డ్ ఇన్‌పుట్ ఒక్కసారి చదవబడి ప్రతి ప్రయత్నానికీ ఇవ్వబడుతుంది.
3. ccam `exec` కు బదులుగా `claude` ను చైల్డ్ ప్రాసెస్‌గా ప్రారంభించి, దాని స్టాండర్డ్ అవుట్‌పుట్‌ను ఆపి ఉంచుతుంది, స్టాండర్డ్ ఎర్రర్‌ను వచ్చినట్లే అందిస్తుంది.
4. `claude` 0 తో నిష్క్రమించినప్పుడు, లేదా వేరే కారణంతో విఫలమైనప్పుడు, ఆపి ఉంచిన అవుట్‌పుట్, ఎగ్జిట్ కోడ్ మార్పు లేకుండా అందించబడతాయి.
5. Claude Code సందేశం అలా చెప్పినప్పుడు (`You've hit your limit`, `usage limit reached`), లేదా ఖాతా వినియోగ లుకప్ దాని 5 గంటల లేదా వారపు విండోను 100% వద్ద చూపినప్పుడు, వైఫల్యాన్ని వినియోగ పరిమితిగా పరిగణిస్తారు.
6. అప్పుడు ఆ ప్రయత్నం అవుట్‌పుట్ వదిలేయబడి, అదే కమాండ్ మరో లాగిన్ అయిన ఖాతాగా రన్ అవుతుంది: అతి తక్కువ 5 గంటల వినియోగం ఉన్నది, ఆ తర్వాత వినియోగాన్ని లుకప్ చేయలేని ఖాతాలు, నంబర్ క్రమంలో. 100% వద్ద ఉన్న ఖాతాలు వదిలేయబడతాయి, ప్రతి ఖాతా గరిష్ఠంగా ఒక్కసారే ప్రయత్నించబడుతుంది.
7. ఆర్గ్యుమెంట్‌లలో `-c`, `--continue`, `-r` లేదా `--resume` ఉంటే, సంభాషణ దొరికేలా, అదే history గ్రూప్‌లోని ఖాతాలు మాత్రమే ప్రయత్నించబడతాయి.
8. `--auto` లాగే, అదే సంస్థకు చెందిన ఖాతాలు మాత్రమే ప్రయత్నించబడతాయి (`cross_org = true` దీన్ని ఎత్తివేస్తుంది).

తదుపరి ఖాతా `--auto` యొక్క అవే నియమాలతో ఎంచుకోబడుతుంది (`auto_max_usage`, `auto_strategy`, `--model` విండో). ఏ ఖాతా మిగలనప్పుడు, ccam చివరి ప్రయత్నం అవుట్‌పుట్‌ను ప్రింట్ చేసి, లాగిన్ అయిన ఏ ఖాతాలోనూ అవకాశం మిగల్లేదని చెప్పి, కోడ్ 75 తో నిష్క్రమిస్తుంది. ఖాతా పేరుకు ముందు `--wait` తో (`ccam --fallback --wait=2h work -p …`), బదులుగా అది మొదటి ఖాతా రీసెట్ అయ్యే వరకు వేచి ఉండి, ఆ తర్వాత అన్ని ఖాతాలను మళ్లీ ప్రయత్నించవచ్చు; ఇప్పుడే పరిమితిని చేరిన ఖాతా వెంటనే మళ్లీ రన్ కాకుండా, అది ఎప్పుడూ ముందుగా కనీసం ఒక్కసారి నిద్రిస్తుంది. `ccam --dry-run --fallback work -p …` మొదటి ప్రయత్నం కమాండ్‌ను ప్రింట్ చేస్తుంది.

ఇంటరాక్టివ్ సెషన్‌లు తమంతట తామే మారవు. బదులుగా, `ccam statusline install` తో, 5 గంటల లేదా వారపు వినియోగం 90% కి చేరగానే స్టేటస్ లైన్ `→ ccam next --auto --continue` ను జోడిస్తుంది ([వినియోగ పరిమితులు](/features/usage)).

## భద్రత, ప్రత్యేక సందర్భాలు

- లాగిన్ లేని ఖాతాలు ఎప్పుడూ ఎంచుకోబడవు. లాగిన్ అయిన మరో ఖాతా లేకపోతే, సాధారణ `ccam next` `no logged-in account other than <name>` తో ఆగుతుంది.
- `--continue` తో, ఫోల్డర్‌లో సంభాషణ లేనప్పుడు: `no account has a conversation in <folder> to continue`.
- సంస్థ నియమం ఏ ఖాతానూ మిగల్చనప్పుడు: `` no logged-in account to pick among <name>'s (<organization>); --cross-org also looks at the others ``.
- `--auto` తో, లాగిన్ అయిన ఖాతా ఏదీ లేనప్పుడు: `no logged-in account to pick`. ప్రతి ఖాతా నిండిపోయినప్పుడు లేదా దాని వినియోగం తెలియనప్పుడు: `` no account with known usage and headroom (see `ccam usage`) ``. రెండూ exit కోడ్ 75 తో ముగుస్తాయి.
- `--max-usage`, `--strategy`, `--wait`, `--cross-org` `--auto` తో మాత్రమే పనిచేస్తాయి, 1-100 బయటి విలువ లేదా వేరే strategy తిరస్కరించబడుతుంది.
- fork సంభాషణను కాపీ చేస్తుంది, ఖాతా ఇతర స్థితిని కాదు: చరిత్ర షేర్ కాకపోతే, అసలు ఖాతా `file-history/` లోని checkpoints వెంట రావు.
- `--dry-run` తో కూడా `--auto` నెట్‌వర్క్ అభ్యర్థనలు చేస్తుంది. అది చదువుతుంది మాత్రమే, టోకెన్ ఫైళ్లలో ఎప్పుడూ రాయదు.
- ఎంచుకున్న ఖాతా `ccam <name>` ఉన్న అదే మార్గం ద్వారా ప్రారంభమవుతుంది, కాబట్టి అవే తనిఖీలు వర్తిస్తాయి, అదే చరిత్రను షేర్ చేసే మరో Claude Code ఈ ఫోల్డర్‌లో ఇప్పటికే రన్ అవుతున్నప్పుడు వచ్చే హెచ్చరికతో సహా.
- Claude Code నిజంగా ప్రారంభమైనప్పుడు మాత్రమే `last-used` రాయబడుతుంది. `--dry-run` దాన్ని ముట్టుకోదు, కాబట్టి డ్రై రన్ రొటేషన్‌ను ముందుకు జరపదు.
- ఒక ప్రయత్నం ముగిసే వరకు `--fallback` స్టాండర్డ్ అవుట్‌పుట్‌ను ఆపి ఉంచుతుంది, కాబట్టి `--output-format stream-json` వంటి స్ట్రీమింగ్ అవుట్‌పుట్ చివర్లో ఒకేసారి వస్తుంది. పరిమితిని చేరక ముందు మొదటి ప్రయత్నం మార్చిన ఫైల్‌లు మారినట్లే ఉంటాయి; తదుపరి ప్రయత్నం prompt ను మళ్లీ మొదలుపెడుతుంది.
