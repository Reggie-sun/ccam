`ccam doctor` మీ ccam ఇన్‌స్టాలేషన్‌ను తనిఖీ చేస్తుంది: Claude Code బైనరీ, ప్రతి ఖాతా ఫోల్డర్, లాగిన్, షేర్ లింక్‌లు, షేర్ చేసిన MCP సర్వర్లు, వినియోగ ఎండ్‌పాయింట్, మీ షార్ట్‌కట్ కమాండ్‌లు. `ccam doctor --fix` డేటా కోల్పోకుండా చేయగలిగిన వాటిని సరిచేస్తుంది, తాను భర్తీ చేసే ఏ ఫైల్‌నైనా ముందుగా బ్యాకప్ ఫోల్డర్‌కు తరలిస్తుంది. `ccam <name>` షేర్ లింక్ సమస్యతో ఆగినప్పుడు, మీరు ఫైళ్లను చేతితో పునరుద్ధరించిన తర్వాత, లేదా Claude Code అప్‌డేట్ తర్వాత దీన్ని రన్ చేయండి.

## వినియోగం

```sh
ccam doctor                  # check everything, change nothing
ccam doctor --fix            # check, then repair what is safe to repair
ccam --dry-run doctor --fix  # report only: what --fix would repair and set aside
```

మొదటి లైన్ ప్రతి ఖాతాను ఒకేసారి గుర్తిస్తుంది, కాబట్టి ఇంకేదైనా చదవక ముందే సమస్యలు ఎక్కడ ఉన్నాయో మీకు కనిపిస్తుంది. దాని కింద, ప్రతి ఖాతాకు ఒక బాక్స్ ఉంటుంది, ఏ ఖాతాకూ చెందని ఫలితాలు (Claude Code, ఎన్విరాన్‌మెంట్ వేరియబుల్స్, ప్లగిన్లు, MCP సర్వర్లు, షార్ట్‌కట్‌లు, ఫోల్డర్ నియమాలు, గ్రూప్‌లు, సెట్టింగ్‌లు) ఒక `General` బాక్స్‌లోకి వెళ్తాయి. బాక్స్ శీర్షిక ఖాతా యొక్క అత్యంత తీవ్రమైన గుర్తును, దానికి ఎన్ని సమస్యలు ఉన్నాయో చూపిస్తుంది. లోపలి ప్రతి వరుస తనిఖీ చేసిన ఒక విభాగం, ఎల్లప్పుడూ `Folder`, `Login`, `Share links` ఆ క్రమంలో, తర్వాత మిగతావి, ఒక గుర్తుతో: `✔` సరే, `ℹ` సమాచారం, `⚠` హెచ్చరిక, `✘` ఎర్రర్. ఏ సమస్యా లేని ఫోల్డర్ `✔ Folder  OK` ను చూపిస్తుంది.

టెర్మినల్‌లో బాక్స్‌లు దాని వెడల్పుకు సరిపోతాయి, పొడవైన సందేశాలు తర్వాతి లైన్‌కు చుట్టబడతాయి, టెర్మినల్ సొంత రంగుల్లో (`NO_COLOR` వాటిని ఆపేస్తుంది). బాక్స్ ఎప్పుడూ 29 కాలమ్‌ల కంటే సన్నగా ఉండదు, కాబట్టి ఇరుకైన టెర్మినల్‌లో ఏ పదమూ కత్తిరించబడదు. పైప్ లేదా ఫైల్‌కు పంపినప్పుడు, అవుట్‌పుట్‌లో రంగులు ఉండవు, ఏ సందేశమూ చుట్టబడదు లేదా కత్తిరించబడదు, కాబట్టి `ccam doctor | grep settings.json` మొత్తం లైన్‌ను కనుగొంటుంది; అప్పుడు ప్రతి బాక్స్ పొడవైన లైన్ అంత వెడల్పు ఉంటుంది. డాష్‌బోర్డ్ Health ట్యాబ్ అవే బాక్స్‌లను చూపిస్తుంది.

## ఆప్షన్లు

| ఆప్షన్ | ఏమి చేస్తుంది | డిఫాల్ట్ |
| --- | --- | --- |
| `--fix` | సురక్షితంగా సరిచేయగలిగిన వాటిని సరిచేస్తుంది (మారిన ఫైళ్లు బ్యాకప్ అవుతాయి) | ఆఫ్ |
| `--dry-run` (గ్లోబల్) | ప్రతి తనిఖీని రన్ చేస్తుంది కానీ `--fix` ఉన్నా ఏదీ సరిచేయదు | ఆఫ్ |

`ccam doctor` ఆర్గ్యుమెంట్‌లు తీసుకోదు. ఇది `--dry-run` ను పాటిస్తుంది: `ccam --dry-run doctor --fix` `ccam doctor` ఫలితాలను ప్రింట్ చేసి, `--fix` పక్కన పెట్టేవాటిని జోడిస్తుంది, ఏదీ మార్చదు:

```text
ℹ settings.json differs from the group's copy: --fix would use the group's, and move this account's copy to /home/me/.local/share/ccam/profiles/personal/.ccam-backup/20261023-212543/settings.json
```

కనీసం ఒక `✘` ఫలితం సరిచేయబడకుండా మిగిలితే ఎగ్జిట్ కోడ్ `1`, లేకపోతే `0`. హెచ్చరికలు, సమాచారం ఎప్పుడూ రన్‌ను విఫలం చేయవు. `--fix` లేకుండా రన్ విఫలమైనప్పుడు, ccam ఒక ఖాళీ లైన్‌తో, `` `ccam doctor --fix` repairs what it can. `` తో ముగుస్తుంది. లోడ్ చేయలేని కాన్ఫిగ్ కూడా `1` తో, ఒక `ccam:` ఎర్రర్‌తో ముగుస్తుంది.

## ఇది ఎలా పనిచేస్తుంది

`internal/cli/doctor.go` `~/.config/ccam/config.toml` ను లోడ్ చేసి `internal/doctor/doctor.go` లోని `doctor.Run` ను పిలుస్తుంది, అది తనిఖీలను ఒక స్థిరమైన క్రమంలో రన్ చేసి ఫలితాలను తిరిగి ఇస్తుంది, ప్రతిదానితో అది చెందిన ఖాతా, తనిఖీ చేసిన విభాగం. `tui.HealthReport` వాటిని బాక్స్‌లుగా గ్రూప్ చేస్తుంది. `--fix` `Options.Fix` గా పంపబడుతుంది, డ్రై రన్‌లో అది false గా సెట్ అవుతుంది.

<!-- motion:doctor-checks -->

మధ్య భాగం ప్రతి ఖాతాకు ఒకసారి రన్ అవుతుంది. తనిఖీలు, ప్రతిదానికి `--fix` ఏమి చేస్తుందో:

1. **Claude Code వెర్షన్** (`checkClaude`). లాంచర్ చేసే విధంగానే `claude` బైనరీని కనుగొని `claude --version` ను రన్ చేస్తుంది. బైనరీ లేకపోవడం, ఎగ్జిక్యూటబుల్ ఫైల్ కాని `claude_bin`, లేదా `--version` విఫలమవడం ఎర్రర్. సరిచేయడం లేదు.
2. **ఎన్విరాన్‌మెంట్‌లో క్రెడెన్షియల్స్** (`checkAuthEnv`). `CLAUDE_CODE_OAUTH_TOKEN`, `ANTHROPIC_API_KEY` లేదా `ANTHROPIC_AUTH_TOKEN` సెట్ అయి ఉంటే హెచ్చరిస్తుంది: ఆ షెల్ నుంచి ప్రారంభించిన ప్రతి ఖాతా దాన్ని వారసత్వంగా పొందుతుంది, Claude Code ఖాతా సొంత లాగిన్ కంటే దానికే ప్రాధాన్యం ఇస్తుంది. సరిచేయడం లేదు; దాన్ని మీరే అన్‌సెట్ చేయండి.
3. **ఫోల్డర్** (`checkProfile`). ఖాతా ఫోల్డర్ లేకపోవడం ఎర్రర్, అది ఆ ఖాతా తనిఖీలను ముగిస్తుంది. గ్రూప్ లేదా ఇతర బిట్‌లు ఏవైనా సెట్ అయిన అనుమతులు హెచ్చరిక; `--fix` `chmod 0700` ను రన్ చేస్తుంది. `~/.claude.json` పక్కన సొంత `.claude.json` ఉన్న ఇంపోర్ట్ చేసిన `~/.claude` సమాచారం: అప్పుడు `ccam main`, సాధారణ `claude` వేర్వేరు లాగిన్ వివరాలను, MCP సర్వర్లను ఉంచుకుంటాయి. Windows లో permission bits లేవు, కాబట్టి అక్కడ ఈ తనిఖీ, కింద ఉన్న `0600` తనిఖీ వదిలేయబడతాయి; మీ యూజర్ ప్రొఫైల్‌లోని ఫోల్డర్ దాని access list తో రక్షించబడుతుంది.
4. **లాగిన్ ఫైల్** (`checkCredentials`). `.credentials.json` `lstat` తో తనిఖీ చేయబడుతుంది. సింలింక్ ఎర్రర్, ఎందుకంటే ప్రతి ఖాతాకు సొంత టోకెన్ ఉండాలి, దాన్ని సరిచేయదు. `0600` కాని మోడ్ హెచ్చరిక; `--fix` `chmod 0600` ను రన్ చేస్తుంది. ఆపై లాగిన్ చదవబడుతుంది (macOS లో ముందుగా Keychain నుంచి). లాగిన్ లేకపోవడం, లేదా లాగిన్ లేని లాగిన్ ఫైల్, `ccam login <name>` ను సూచించే హెచ్చరిక. గడువు ముగిసిన రిఫ్రెష్ టోకెన్, లేదా సర్వర్ తిరస్కరించిన తర్వాత Claude Code క్లియర్ చేసిన లాగిన్, `` login expired → `ccam login <name>` `` ఎర్రర్; గడువు ముగిసిన యాక్సెస్ టోకెన్ కేవలం సమాచారం, ఎందుకంటే Claude Code తదుపరి ప్రారంభంలో దాన్ని పునరుద్ధరిస్తుంది. Windows Credential Manager లో ఉంచిన లాగిన్ సమాచారం, ఎందుకంటే ccam దాన్ని చదవలేదు. చెల్లుబాటు అయ్యే లాగిన్ ఫోల్డర్ ఇప్పుడు లాగిన్ అయి ఉన్న ఇమెయిల్‌ను, ప్లాన్‌ను చూపిస్తుంది (`login valid (dev@company.com, Claude Team · Acme)`). వీటిలో ఏదీ సరిచేయబడదు; `ccam login --expired` అవసరమైన ప్రతి ఖాతాలో లాగిన్ చేస్తుంది.
5. **షేర్ లింక్‌లు** (`share.Check`). `lstat`, `readlink` ను మాత్రమే ఉపయోగించి, `share.Layout` లోని ప్రతి పాత్‌ను ఖాతా గ్రూప్‌లతో పోలుస్తుంది. ఇది ఐదు రకాలను నివేదిస్తుంది: లేని లింక్, వేరే చోటికి చూపే లింక్, లింక్ ఉండాల్సిన చోట అసలు ఫైల్, ఇప్పుడు లోకల్ అయిన అంశం కోసం మిగిలిపోయిన లింక్, గ్రూప్ ఫోల్డర్ లేని సరైన లింక్ (`the group folder it links to is missing (…), so Claude Code cannot save there (ccam doctor --fix makes it)`; లాంచ్ దీన్ని తనిఖీ చేయదు). లేని లింక్, లేని గ్రూప్ ఫోల్డర్ హెచ్చరికలు, మిగతావి ఎర్రర్‌లు. గ్రూప్ నుంచి వెనక్కి కాపీ చేయడం మధ్యలో ఆగిపోతే అది కూడా నివేదించబడుతుంది: `--fix` సిద్ధం చేసిన పూర్తి కాపీని దాని స్థానంలో పెడుతుంది, కానీ ఆ తర్వాత (ఒక లాంచ్ ద్వారా) ఆ పాత్ కొత్తగా సృష్టించబడి ఉంటే, మీరే సరిచూసుకోవడానికి పూర్తి కాపీ ఉన్న ఫోల్డర్ పేరును చెబుతుంది. ccam తర్వాతి వెర్షన్‌లో ఒక అంశానికి జోడించిన పాత్‌లు (చరిత్ర కోసం `file-history/`, `tasks/`, `paste-cache/`, సెట్టింగ్‌ల కోసం `keybindings.json`) ఖాతా దగ్గర ఇంకా సొంత కాపీ ఉన్నంత వరకు కేవలం హెచ్చరిక మాత్రమే: `is not shared with the group yet (ccam doctor --fix shares it; if the group has its own copy, that one is kept and this one backed up)`. వాటి కోసం లాంచ్ ఎప్పుడూ ఆగదు.
6. **తెలియని ఎంట్రీలు** (`checkUnknownEntries`). ccam కు తెలియని (`share.Known`) ఖాతా ఫోల్డర్‌లోని టాప్-లెవెల్ పేర్లను, Claude Code లేఅవుట్ మారిందనే సూచనగా జాబితా చేస్తుంది. కేవలం సమాచారం.
7. **ప్లగిన్ పాత్‌లు** (`checkPlugins`). ప్లగిన్ రిజిస్ట్రీలు (`installed_plugins.json`, `known_marketplaces.json`) పూర్తి పాత్‌లను నిల్వ చేస్తాయి. ప్రతి గ్రూప్ `plugins/` లో, ఒక ఖాతా ఫోల్డర్ ద్వారా వెళ్లే పాత్‌లు ఆ ఖాతా తీసివేయబడినప్పుడు లేదా పేరు మారినప్పుడు పాడవుతాయి. `--fix` వాటిని `profile.RewritePluginPaths` తో, రిజిస్ట్రీ ఫైల్ యొక్క అటామిక్ రైట్‌తో, గ్రూప్ ఫోల్డర్‌కు మళ్లీ రాస్తుంది.
8. **MCP సర్వర్లు** (`checkMCP`). ప్రతి గ్రూప్ `mcp.json` ను ఒకసారి లోడ్ చేస్తుంది. చదవలేని ఫైల్ ఎర్రర్; `mcp.Validate` లో విఫలమైన సర్వర్ హెచ్చరిక. ఏ ఖాతా లోడ్ చేయని, సాధారణ `claude` యొక్క `~/.claude.json` లోని సర్వర్లు హెచ్చరిక, వాటిని కాపీ చేసే `ccam migrate --mcp` కమాండ్‌ను అది చెబుతుంది (అనేక గ్రూప్‌లు MCP ని షేర్ చేస్తే `--group <a|b>` తో). ఒక గ్రూప్‌లో ఒకే ఖాతాకు ఉన్న సర్వర్లు సమాచారం, వాటిని షేర్ చేసే `ccam mcp import` కమాండ్‌తో; ఇతర ఖాతాలు సైన్ ఇన్ అయిన MCP సర్వర్లకు సైన్ ఇన్ కాని ఖాతాకు `/mcp` తో సైన్ ఇన్ చేయమని హెచ్చరిక వస్తుంది (ccam ఎప్పుడూ సైన్-ఇన్‌లను కాపీ చేయదు). సరిచేయడం లేదు.
9. **వినియోగ రెస్పాన్స్ ఫార్మాట్** (`checkUsageFormat`). కాష్ లేకుండా, ఒక ఖాతా సమాధానం ఇచ్చే వరకు ఒకదాని తర్వాత ఒకటి వినియోగ ఎండ్‌పాయింట్‌ను అడుగుతుంది, అంతా ఒకే 4 సెకన్ల పరిమితిలో. `usage_source = "claude"` తో, బదులుగా అది ఒక ఖాతా కోసం Claude Code ను అడుగుతుంది. రెస్పాన్స్ ఇకపై పార్స్ కాకపోతే, `ccam usage` స్టేటస్ లైన్ కాష్‌కు మారుతుందని హెచ్చరిస్తుంది; ఏ ఖాతా సమాధానం ఇవ్వకపోతే, ఆ విషయాన్ని సమాచారంగా చెబుతుంది (`could not check the usage response format: …`). నెట్‌వర్క్‌ను ఉపయోగించే ఏకైక తనిఖీ ఇదే.
10. **షార్ట్‌కట్‌లు** (`checkShims`). ఒక ఖాతాకు షార్ట్‌కట్ ఉన్నప్పుడు మాత్రమే. `~/.local/bin` లో లేని లింక్‌లు హెచ్చరిక, ఇంకా పాత ccam ను (భర్తీ చేయబడిన లేదా తరలించబడిన దాన్ని) రన్ చేసే, ccam సృష్టించిన షార్ట్‌కట్‌లు కూడా హెచ్చరికే (`shortcuts in <bin> that run another ccam (one replaced or moved): …`); `--fix` `shim.Install` ను పిలుస్తుంది, అది ccam సృష్టించి `~/.local/state/ccam/shortcuts.json` లో నమోదు చేసిన లింక్‌లను మాత్రమే సృష్టిస్తుంది, పునరుద్ధరిస్తుంది, ఇతర ఫైళ్లను ఎప్పుడూ ముట్టుకోదు. ఆ లింక్‌లలో ప్రతిదీ సృష్టించబడినప్పుడు మాత్రమే హెచ్చరిక `→ fixed` తో ముగుస్తుంది; ఒకటి సృష్టించలేకపోతే, కారణం జోడించబడుతుంది. ఇంకా ఇన్‌స్టాల్ అయి ఉన్న మరో ccam ను రన్ చేసే షార్ట్‌కట్ పనిచేస్తుంది, అది సమాచారం; `--fix` దాన్ని ఈ ccam వైపు చూపేలా చేస్తుంది. `PATH` లో లేని bin ఫోల్డర్ హెచ్చరిక, దాన్ని సరిచేయదు.
11. **ఫోల్డర్‌లు** (`checkFolders`). [`ccam folder`](/features/folder) ఎంట్రీలు ఉన్నప్పుడు మాత్రమే. ఖాతా లేని ఎంట్రీ ఎర్రర్, ఫోల్డర్ లేకుండా పోయిన ఎంట్రీ హెచ్చరిక. రెండింటినీ సరిచేయదు, ఎందుకంటే ఎంట్రీని తీసివేస్తే అక్కడ ఏ ఖాతా ప్రారంభమవుతుందో మారిపోతుంది.
12. **గ్రూప్‌లు, సెట్టింగ్‌లు** (`checkGroups`). ఖాతా కాని గ్రూప్ సభ్యుడు, పేరు తర్వాత ccam కమాండ్‌గా మారిన ఖాతా (దాన్ని `ccam run <name>` తో ప్రారంభించండి లేదా పేరు మార్చండి), తెలియని `theme` లేదా `usage_source`, ccam చదవని `config.toml` లైన్లు హెచ్చరికలు. చివరివి సాధారణంగా `[[group]]`, `[[profile]]` లేదా `[[folder]]` టేబుల్ కింద రాసిన సెట్టింగ్, అక్కడ అది ఆ టేబుల్‌కే చెందుతుంది (`config.toml line 43: relay is read as part of the [profile.login] table above it; settings for all accounts go above the first [[group]], [[profile]] or [[folder]]`); అది సరిచేసే వరకు కాన్ఫిగ్‌ను మార్చే కమాండ్‌లు నిరాకరిస్తాయి. సరిచేయడం లేదు.
13. **లాగిన్‌లు** (`checkIdentities`). ప్రతి ఫోల్డర్ ఎవరిగా లాగిన్ అయి ఉందో దాని `.claude.json` నుంచి చదువుతుంది. `ccam login` నమోదు చేసిన ఖాతా కాకుండా ఇప్పుడు వేరే ఖాతాలోకి లాగిన్ అయిన ఫోల్డర్ (ఉదాహరణకు సెషన్ లోపల `/login` తర్వాత) హెచ్చరిక; లాగిన్ రికార్డ్ లేని ఖాతా, ఉదాహరణకు ఇంపోర్ట్ చేసినది లేదా పాత ccam సృష్టించినది, దాని నమోదైన ఇమెయిల్‌తో పోల్చబడుతుంది. మరో ఫోల్డర్ లాగే అదే Claude ఖాతాలోకి లాగిన్ అయిన ఫోల్డర్ కూడా హెచ్చరికే: ఆ రెండూ తమ వినియోగ పరిమితులను పంచుకుంటాయి. మరో ఫోల్డర్‌కు ఉన్న లాగిన్ టోకెన్‌నే కలిగి ఉన్న ఫోల్డర్, అంటే కాపీ చేసిన ఫోల్డర్ (సాధారణ `claude` యొక్క `~/.claude` తో సహా), ఎర్రర్, ఎందుకంటే ముందుగా ఏది రెన్యూ చేస్తే అది మరొకదాన్ని లాగ్ అవుట్ చేస్తుంది; దానికి సొంత లాగిన్ ఇవ్వడానికి `ccam login <name>` రన్ చేయండి. సరిచేయడం లేదు.

ఖాతాల కంటే ముందు, మధ్యలో ఆగిపోయిన **గ్రూప్‌ల మార్పు** `General` బాక్స్‌లో ఎర్రర్: ``the last change of groups stopped halfway (ccam doctor --fix finishes it; noted in ~/.local/state/ccam/group-change.json)``. `--fix` దాన్ని ప్లాన్ చేసిన క్రమంలోనే, దాని ఘర్షణలకు ఇచ్చిన సమాధానాలతో పూర్తి చేస్తుంది; అప్పటి వరకు మరే గ్రూప్‌ల మార్పు, పేరు మార్పు లేదా తీసివేత మొదలవదు. అది పూర్తయ్యే వరకు అందులోని ఖాతాలకు లేని లింక్‌లు మాత్రమే సృష్టించబడతాయి. దాన్ని పూర్తి చేయలేకపోతే, ఆ ఫైల్‌ను తీసివేస్తే మార్పులో మిగిలిన భాగాన్ని వదులుకున్నట్టే అని ఎర్రర్ చెబుతుంది. `ccam --dry-run doctor --fix` క్రమాన్ని (`--fix finishes it in its order (b, a, c), with the answers given to its conflicts`), ప్రతి ఖాతా భాగం ఏమి పక్కన పెడుతుందో చూపిస్తుంది. మరో ccam ఇప్పుడే చేస్తున్న మార్పు సమాచారం, అది రన్ అవుతున్నప్పుడు `--fix` ఏ షేర్ లింక్‌లనూ సరిచేయదు (`its share links are not repaired while another ccam changes the groups; …`). సరిచేస్తున్నప్పుడు `--fix` `~/.local/state/ccam/group-change.lock` ను పట్టి ఉంచుతుంది, ఒక మార్పును పూర్తి చేసిన తర్వాత `config.toml` ను మళ్లీ చదువుతుంది.

### షేర్ లింక్‌లను సరిచేయడం

ప్రారంభ మార్గం లేని లింక్‌ను అక్కడికక్కడే సృష్టిస్తుంది, కానీ డేటా కోల్పోయే అవకాశం ఉన్న దేనికైనా ఆగి ఇక్కడికి సూచిస్తుంది:

```console
$ ccam work
ccam: stopped because of share link problems:
  /home/me/.local/share/ccam/profiles/work/CLAUDE.md: set to shared but is a real file, not a link
Repair them with `ccam doctor --fix`, then run again
```

ఏ షేర్ లింక్ సమస్యకైనా, `--fix` ఖాతా షేర్ సెట్టింగ్‌లను ప్రస్తుత స్థితిగా, లక్ష్య స్థితిగా రెండింటిగా ఇచ్చి `share.Build` ను పిలుస్తుంది, ఆపై `Plan.Apply`. `Build` ప్రతి దశను డిస్క్‌లో ఉన్నదాని నుంచి మళ్లీ తయారు చేస్తుంది, `ccam group` మార్పు ఉపయోగించే అదే ప్రణాళిక, కాబట్టి సరిచేయడం గ్రూప్‌లో చేరే అవే నియమాలను పాటిస్తుంది.

<!-- motion:doctor-repair -->

ఇక్కడ `settings.json` ఒక అసలు ఫైల్. గ్రూప్‌లో ఇప్పటికే వేరే `settings.json` ఉంది కాబట్టి, ఘర్షణ తన డిఫాల్ట్ ఎంపిక `KeepGroup` ను తీసుకుంటుంది, కాబట్టి గ్రూప్ కాపీ ఉంటుంది. ఖాతా ఫైల్ ఖాతా ఫోల్డర్‌లోని `.ccam-backup/<time>/settings.json` కు తరలుతుంది, `os.Symlink` పాత్‌ను గ్రూప్‌కు లింక్ చేస్తుంది. `--fix` ఆ విషయం చెబుతుంది: `settings.json differed from the group's copy, which it now uses; this account's copy is in …`. ఇతర సందర్భాలు:

- గ్రూప్‌లో ఇంకా కాపీ లేకపోతే, ఖాతా ఫైల్ గ్రూప్‌లోకి తరలి దాని మొదటి కంటెంట్ అవుతుంది.
- ఫోల్డర్ అయితే, గ్రూప్‌లో లేని ఫైళ్లు గ్రూప్‌లోకి తరలుతాయి. గ్రూప్ దగ్గర బైట్ బైట్ ఒకేలా ఉన్న ఫైళ్లు వదిలేయబడతాయి, భిన్నంగా ఉన్నవి బ్యాకప్‌కు వెళ్తాయి, ఒక నోట్‌లో వాటి పేర్లు ఉంటాయి (`projects: 1 file differs from the group's copy (-w/memory/MEMORY.md); the group's is kept, the account's stays in …`).
- లేని గ్రూప్ ఫోల్డర్ ముందుగా సృష్టించబడుతుంది.
- `history.jsonl` కు, డిఫాల్ట్ `merge by line`: గ్రూప్ లైన్లు, ఆపై మీ కొత్తవి. గ్రూప్ యొక్క మునుపటి కాపీ `.ccam-backup/<time>/group/` లో సేవ్ అవుతుంది.
- మరో గ్రూప్‌కు ఉన్న లింక్ భర్తీ చేయబడుతుంది. ccam బయట ఉన్న ఫోల్డర్‌కు ఉన్న లింక్ బ్యాకప్‌కు వెళ్తుంది, గ్రూప్ ఖాళీగా ఉంటే దాని కంటెంట్ గ్రూప్‌కు మొదటి కంటెంట్ అవుతుంది.
- ఇప్పుడు లోకల్ అయిన అంశం కోసం మిగిలిన లింక్ తీసివేయబడుతుంది, ఖాతాకు గ్రూప్ కంటెంట్ కాపీ లభిస్తుంది.

లింక్‌లను తీసివేయడం, గ్రూప్ దగ్గర ఇప్పటికే బైట్ బైట్ ఒకేలా ఉన్న ఫైళ్లను వదిలేయడం తప్ప, ప్రతి దశ డేటాను గ్రూప్‌లోకి లేదా బ్యాకప్ ఫోల్డర్‌లోకి తరలిస్తుంది. ఏదీ పోదు.

## భద్రత, ప్రత్యేక సందర్భాలు

- సాధారణ `ccam doctor` ఎప్పుడూ ఏదీ మార్చదు. స్క్రిప్ట్‌లలో నిశ్చింతగా ఉండటానికి `--fix` తో `--dry-run` ను ఉపయోగించండి.
- రన్ అవుతున్న ఖాతా కోసం, Claude Code ఎలా ప్రారంభమైనా సరే, `doctor --fix` లేని లింక్‌లను, లేని గ్రూప్ ఫోల్డర్‌లను మాత్రమే తయారు చేస్తుంది, దాని వల్ల ఏదీ పోదు. ఇంకేదైనా మిగిలి ఉంటే, అది `` is running; quit Claude Code there, then run `ccam doctor --fix` again to repair the rest `` ను జోడిస్తుంది, ఎందుకంటే సరిచేయడం తరలించే ఫైళ్లలో సెషన్ రాస్తూనే ఉంటుంది.
- షేర్ సరిచేయడం విఫలమైతే, ccam ఆ ఖాతాకు `could not repair share links: <error>` అని నివేదించి, దాని తెలియని ఎంట్రీల తనిఖీని దాటవేస్తుంది. ఇతర ఖాతాలు ఇంకా తనిఖీ చేయబడతాయి.
- `ccam group` మార్పు మధ్యలో విఫలమైతే, కొత్త గ్రూప్‌లు ఇప్పటికే సేవ్ అయి ఉంటాయి, ఆ మార్పు `~/.local/state/ccam/group-change.json` లో నమోదు అవుతుంది; `ccam doctor --fix` తో పూర్తి చేయమని ccam చెబుతుంది, అది MCP దశలతో సహా మిగతా భాగాన్ని పూర్తి చేస్తుంది.
- సింలింక్ అయిన `.credentials.json`, గడువు ముగిసిన లాగిన్, ఎన్విరాన్‌మెంట్ క్రెడెన్షియల్స్ నివేదించబడతాయి కానీ ఎప్పుడూ మార్చబడవు.
- ప్లగిన్ రిజిస్ట్రీ మార్పులు అటామిక్‌గా రాయబడతాయి కానీ `.ccam-backup/` కు కాపీ కావు.
