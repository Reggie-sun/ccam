`ccam usage` ప్రతి ఖాతాకు, ప్రతి పరిమితిలో ఎంత ఉపయోగించబడిందో చూపిస్తుంది: 5 గంటల పరిమితి, వారపు పరిమితి, ప్రతి మోడల్ సొంత వారపు పరిమితి (Fable వంటిది). ప్రతి పరిమితికి ఒక బార్, అది రీసెట్ అయ్యే వరకు సమయం ఉంటాయి. ఏ ఖాతాకు అవకాశం మిగిలి ఉందో చూడటానికి, పెద్ద పనిని మొదలుపెట్టే ముందు, లేదా పరిమితి దగ్గరలో ఉందని Claude Code చెప్పినప్పుడు దీన్ని ఉపయోగించండి. `ccam statusline` Claude Code కోసం స్టేటస్ లైన్ కమాండ్: ఇది Claude Code లోపల ఖాతా పేరును, వినియోగాన్ని చూపిస్తుంది, `ccam usage` కోసం సంఖ్యలను సేవ్ చేస్తుంది. వినియోగం వెనుక ఉన్న టోకెన్‌లు, అంచనా ఖర్చుల కోసం, `ccam ccusage` ప్రతి ఖాతా సంభాషణలపై [ccusage](https://ccusage.com) ను రన్ చేస్తుంది ([కింద చూడండి](#tokens-and-costs-ccam-ccusage)).

## వినియోగం

```sh
ccam usage                  # every account, once
ccam u                      # the same, shorter
ccam usage --watch          # redraw every 60 seconds until Ctrl+C
ccam usage --watch=10       # redraw every 10 seconds
ccam usage -v               # add where the numbers came from
ccam usage --json           # machine-readable, one object per account
ccam usage --source cache   # saved numbers only, no network
ccam usage --refresh        # also renew expired logins of accounts that are not running
ccam usage --source claude  # let Claude Code look it up: ccam sends no token
ccam statusline install     # set the status line in every account's settings.json
```

ప్రతి ఖాతాకు దాని సంఖ్య, పేరు, సంఖ్యలు ఎంత పాతవో చెప్పే ఒక లైన్ ఉంటుంది; `(cached)` అంటే అవి ఎండ్‌పాయింట్ నుంచి కాకుండా సేవ్ చేసిన ఫైల్ నుంచి వచ్చాయి. దాని కింద, ప్రతి పరిమితికి ఒక లైన్ 20 సెల్‌ల బార్‌ను, శాతాన్ని, విండో రీసెట్ అయ్యే వరకు సమయాన్ని చూపిస్తుంది: `5-hour`, `Weekly` (అన్ని మోడళ్లు), తర్వాత `Fable` వంటి ప్రతి మోడల్ సొంత వారపు విండో. ఖాతాకు లేని విండో `-` చూపిస్తుంది. శాతం 80% వద్ద పసుపు రంగులోకి, 100% వద్ద ఎరుపు రంగులోకి మారుతుంది.

ఒక విండో నిండినందువల్ల Claude Code ఒక అభ్యర్థనను తిరస్కరిస్తే, సేవ్ చేసిన సంఖ్యలు ఏమి చెప్పినా, ఆ విండో రీసెట్ అయ్యే వరకు 100% చూపిస్తుంది ([పరిమితి రికార్డ్](#the-limit-record) చూడండి). టెర్మినల్‌లో ప్రతి ఖాతా వెంటనే `fetching…` గా కనిపిస్తుంది, అది సమాధానం ఇచ్చినప్పుడు దాని లైన్లు గీయబడతాయి.

మీకు ఒకటి కంటే ఎక్కువ ఖాతాలు ఉన్నప్పుడు మాత్రమే కనిపించే చివరి లైన్, [`ccam next --auto`](/features/next) ఎంచుకునే ఖాతా పేరును చెబుతుంది. అది అవే నియమాలను పాటిస్తుంది:

- `auto_max_usage`, `auto_strategy`;
- రన్ అవుతున్న సెషన్‌లు;
- `cross_org` సెట్ చేయకపోతే, చివరిగా ఉపయోగించిన ఖాతా సంస్థకు చెందిన ఖాతాలు మాత్రమే;
- 100% వద్ద ఉన్న ప్రతి విండో వదిలేయబడుతుంది, కాబట్టి వారం నిండిన ఖాతా పేరు ఎప్పుడూ రాదు.

డిఫాల్ట్ `headroom` strategy తో అది `→ Most headroom: <name>` అని చూపిస్తుంది; `expiring` లేదా `balance` తో అది కారణాన్ని ఇస్తుంది, ఉదాహరణకు `→ next --auto picks personal: its 5-hour window resets first, in 1h 12m (40% of its 5 hours used)`.

**Team, Enterprise సీట్లు.** ఆటోమేటిక్ ఖాతా ఎంపిక (`ccam next`, `--fallback`, `ccam pick`, డాష్‌బోర్డ్‌లోని `n`, మీరు ఆన్ చేసిన తర్వాత [`auto_switch`](/features/next#auto-switch)) ఒకే Claude Team లేదా Enterprise సంస్థలోని సీట్ల మధ్య కూడా మారుస్తుంది, ఇది Anthropic నిబంధనల ఉల్లంఘన కావచ్చు. దానిపై ఆధారపడే ముందు [తరచుగా అడిగే ప్రశ్నలు](/docs/faq#am-i-allowed-to-use-several-claude-code-accounts) చదివి, మీ సంస్థను, Anthropic ను సంప్రదించి నిర్ధారించుకోండి.

లాగిన్ కాని ఖాతా `not logged in → ccam login <name>` ను, API కీ ఖాతా `no limits (API)` ను చూపిస్తాయి. గడువు ముగిసిన యాక్సెస్ టోకెన్ ``access token expired; `ccam <name>` renews it when it starts`` అని చూపిస్తుంది, సేవ్ చేసిన సంఖ్యలు ఏవైనా ఉంటే వాటి పైన: Claude Code తదుపరి ప్రారంభంలో దాన్ని పునరుద్ధరిస్తుంది. పూర్తిగా గడువు ముగిసిన లాగిన్, దాని రిఫ్రెష్ టోకెన్ గడువు ముగిసినందువల్ల లేదా సర్వర్ తిరస్కరించిన తర్వాత Claude Code దాన్ని క్లియర్ చేసినందువల్ల, `` login expired → `ccam login <name>` `` అని చూపిస్తుంది.

`ccam statusline install` తర్వాత, Claude Code `[work] · Opus · 5h 24% · 7d 41%` వంటి లైన్‌ను చూపిస్తుంది.

## ఆప్షన్లు

| ఆప్షన్ | ఏమి చేస్తుంది | డిఫాల్ట్ |
| --- | --- | --- |
| `--json` | నివేదికలను JSON గా ప్రింట్ చేస్తుంది: `name`, `slot`, `status`, `limits` (ఖాతాకు usage credits ఆన్ అయి ఉంటే `credits` తో), `source`, `at`, `error`, పరిమితి రికార్డ్ విండోలను 100% కు సెట్ చేసినప్పుడు `limited`, `limited_windows`. ఖాతాలు లేకపోతే అది `[]` ను ప్రింట్ చేస్తుంది | ఆఫ్ |
| `--watch[=N]` | మీరు Ctrl+C నొక్కే వరకు ప్రతి `N` సెకన్లకు మళ్లీ గీస్తుంది. ఒంటరి `--watch`, లేదా 0 లేదా అంతకంటే తక్కువ విలువ అంటే 60. విలువ `=` తర్వాత వస్తుంది: `--watch 10` ఒక సూచనతో తిరస్కరించబడుతుంది | ఆఫ్ |
| `-v`, `--verbose` | ప్రతి ఖాతా కింద ఒక `source:` లైన్‌ను జోడిస్తుంది: దాని సంఖ్యలు ఎక్కడి నుంచి వచ్చాయో (వినియోగ ఎండ్‌పాయింట్, Claude Code, స్టేటస్ లైన్, సేవ్ చేసిన ఫైల్, లేదా Claude Code నివేదించిన వినియోగ పరిమితి). పరిమితి రికార్డ్ సంఖ్యలను అధిగమించినప్పుడు, `Weekly full: Claude Code reported the usage limit 1h 0m ago, so 100% until the reset` వంటి లైన్ దాని తర్వాత వస్తుంది | ఆఫ్ |
| `--no-cache` | 60 సెకన్ల కాష్‌ను పట్టించుకోకుండా ఎండ్‌పాయింట్‌ను మళ్లీ అడుగుతుంది | ఆఫ్ |
| `--source live\|claude\|cache` | `live` ఖాతా టోకెన్‌తో ఎండ్‌పాయింట్‌ను అడుగుతుంది; `claude` దాన్ని Claude Code చేత చూపిస్తుంది (కింద చూడండి); `cache` సేవ్ చేసిన సంఖ్యలను మాత్రమే చూపిస్తుంది | `usage_source`, లేకపోతే `live` |
| `--refresh` | గడువు ముగిసిన యాక్సెస్ టోకెన్‌లను పునరుద్ధరిస్తుంది, రన్ అవ్వని ఖాతాలకు మాత్రమే. ఒక పునరుద్ధరణకు 30 సెకన్ల వరకు పట్టవచ్చు | ఆఫ్ |
| `--dry-run` | అంగీకరిస్తుంది: `ccam usage` తన సొంత కాష్ తప్ప ఏదీ మార్చదు. `--refresh` తో కలిపి ఇస్తే తిరస్కరిస్తుంది: `--dry-run cannot be combined with --refresh, which rewrites login tokens` | ఆఫ్ |

మరే `--source` విలువైనా `--source must be live, claude or cache` తో విఫలమవుతుంది. `ccam usage` ఆర్గ్యుమెంట్‌లు తీసుకోదు.

### Claude Code నుంచే వినియోగం

`config.toml` పైభాగంలో (మొదటి `[[group]]`, `[[profile]]` లేదా `[[folder]]` కంటే పైన) `usage_source = "claude"` తో, లేదా `--source claude` తో, ccam లాగిన్ టోకెన్‌ను అసలు చదవదు. ప్రతి ఖాతా కోసం అది ఖాతా ఫోల్డర్‌లో `claude -p --input-format stream-json --output-format stream-json --verbose --safe-mode --no-session-persistence` ను ప్రారంభించి, స్టాండర్డ్ ఇన్‌పుట్‌పై Claude Code యొక్క `get_usage` అభ్యర్థనను పంపుతుంది (Claude Code 2.1.270 లేదా తర్వాతి వెర్షన్). Claude Code తన సొంత లాగిన్‌తో వినియోగాన్ని చూసి 5 గంటల, వారపు, మోడల్ విండోలతో సమాధానం ఇస్తుంది.

`--safe-mode` ఖాతా hooks, MCP సర్వర్లు, ప్లగిన్లు ప్రారంభం కాకుండా ఆపుతుంది, ఏ సెషన్ సేవ్ అవ్వదు. ప్రతి ఖాతాకు ఒక Claude Code ప్రారంభం (సుమారు ఒక సెకను) అవసరం, కాబట్టి ఈ సోర్స్ `live` కంటే నెమ్మదిగా ఉంటుంది. ఖాతాలను ఒకేసారి అడుగుతుంది, ప్రతిదానికి 20 సెకన్ల timeout తో, 60 సెకన్ల కాష్ ఎప్పటిలాగే వర్తిస్తుంది.

యాక్సెస్ టోకెన్ గడువు ముగిసిన, లేదా 5 నిమిషాల్లో ముగిసే లాగిన్‌కు 50 సెకన్లు లభిస్తాయి, ఎందుకంటే Claude Code ప్రారంభమయ్యేటప్పుడు దాన్ని పునరుద్ధరిస్తుంది, మధ్యలో ఆపిన పునరుద్ధరణ లాగిన్‌ను పోగొట్టవచ్చు. ccam ఒక లుకప్‌ను వదులుకుంటే, SIGTERM తో నిష్క్రమించమని Claude Code ను అడుగుతుంది, కాబట్టి Claude Code తాను మొదలుపెట్టిన పునరుద్ధరణను పూర్తి చేస్తుంది (Windows లో SIGTERM లేదు, కాబట్టి అక్కడ ప్రాసెస్ ముగించబడుతుంది).

పూర్తిగా గడువు ముగిసిన లాగిన్ Claude Code ను ప్రారంభించకుండానే `` login expired → `ccam login <name>` `` అని చూపిస్తుంది. Claude Code ఈ అభ్యర్థనను ప్రయోగాత్మకమైనదిగా గుర్తిస్తుంది, కాబట్టి అది సమాధానం ఇవ్వడం ఆపేస్తే, ccam సేవ్ చేసిన సంఖ్యలను చూపిస్తుంది, `ccam doctor` దాన్ని నివేదిస్తుంది. తన సొంత లుకప్ విఫలమైందని Claude Code సమాధానం ఇచ్చినప్పుడు, ccam పరిమితులు లేని ప్లాన్‌ను కాకుండా, `the usage endpoint gave Claude Code no usage (it may be refusing lookups for now)` తో సేవ్ చేసిన సంఖ్యలను చూపిస్తుంది.

`--dry-run` తో, ccam Claude Code ను ప్రారంభించదు, ఎందుకంటే Claude Code ఖాతా ఫోల్డర్‌లో రాస్తుంది; బదులుగా అది సేవ్ చేసిన సంఖ్యలను చూపిస్తుంది. `usage_source` `live` లేదా `claude` ను తీసుకుంటుంది; `cache` కేవలం `--source` ఎంపిక.

`ccam statusline` స్టాండర్డ్ ఇన్‌పుట్ నుంచి Claude Code స్టేటస్ లైన్ JSON ను చదువుతుంది. దాని ఏకైక ఆప్షన్ `--wrap <command>`: ఇప్పటికే ఉన్న స్టేటస్ లైన్ కమాండ్, దాని మొదటి అవుట్‌పుట్ లైన్ ముందు ఖాతా పేరు పెట్టబడుతుంది. `ccam statusline install` ఆప్షన్లు తీసుకోదు. రెండూ `--dry-run` ను `` --dry-run is not supported by `ccam statusline`; nothing was changed `` తో తిరస్కరిస్తాయి.

## టోకెన్‌లు, ఖర్చులు: `ccam ccusage`

ఒక ఖాతా ప్రతి పరిమితిలో ఎంత ఉపయోగించిందో `ccam usage` చూపిస్తుంది. [ccusage](https://ccusage.com) అయితే Claude Code సంభాషణ లాగ్‌లలోని టోకెన్‌లను, అంచనా ఖర్చులను లెక్కిస్తుంది. సొంతంగా అది Claude Code లాగ్‌ల కోసం `~/.claude`, `~/.config/claude` లలో (లేదా `CLAUDE_CONFIG_DIR` పేర్కొనే ఫోల్డర్‌లలో) మాత్రమే వెతుకుతుంది, కాబట్టి అది చూడగలిగే ఏకైక ccam ఖాతా `~/.claude` వద్ద ఉన్న చోటే ఇంపోర్ట్ చేయబడిన ఖాతా. `ccam ccusage` సంభాషణలు ఉన్న ప్రతి ఖాతా ఫోల్డర్‌ను `CLAUDE_CONFIG_DIR` లో సెట్ చేసి దాన్ని రన్ చేస్తుంది, కాబట్టి ఒకే నివేదిక వాటన్నింటినీ కవర్ చేస్తుంది:

```sh
ccam ccusage                           # every account, ccusage's daily report
ccam ccusage daily --breakdown         # cost per model
ccam ccusage claude monthly --json     # Claude Code alone, as JSON
ccam ccusage -a work blocks --active   # one account's current 5-hour block
ccam ccusage -a work,side weekly       # these accounts, and any that share their history
```

ccam ముందుగా తన సొంత ఆప్షన్లను చదువుతుంది: `-a` (`--account`) ఖాతా పేర్లు లేదా సంఖ్యలను కామాలతో వేరు చేసి గానీ, ఆప్షన్‌ను మళ్లీ ఇచ్చి గానీ తీసుకుంటుంది; `--dry-run` కమాండ్‌ను రన్ చేయకుండా దాన్ని ప్రింట్ చేస్తుంది. ccam ఆప్షన్ కాని మొదటి ఆర్గ్యుమెంట్ నుంచి, ప్రతిదీ మార్పు లేకుండా ccusage కు వెళ్తుంది; `ccam ccusage -- --help` ccusage సొంత సహాయాన్ని చూపిస్తుంది. ccam ఇన్‌స్టాల్ అయి ఉన్న `ccusage` ను రన్ చేస్తుంది, అది లేకపోతే `bun x ccusage` ను, అదీ లేకపోతే `npx ccusage@latest` ను రన్ చేస్తుంది; ఈ చివరి రెండూ ccusage ను npm నుంచి తెచ్చుకుంటాయి. వీటిలో ఏదీ లేనప్పుడు, Node.js, Bun లేదా ccusage ను ఇన్‌స్టాల్ చేయమని అది చెబుతుంది. Linux, macOS లలో ccusage ccam స్థానాన్ని తీసుకుంటుంది; Windows లో ccam దాని కోసం వేచి ఉండి, దాని ఎగ్జిట్ కోడ్‌తో నిష్క్రమిస్తుంది. WSL లోపల, Windows డ్రైవ్‌లో ఉన్న `ccusage`, `bun` లేదా `npx` ను ccam దాటవేస్తుంది, ఎందుకంటే అది ఖాతా ఫోల్డర్‌లు లేకుండా Windows ప్రోగ్రామ్‌గా రన్ అవుతుంది.

- సంభాషణలు ఉన్న ఫోల్డర్‌లు (ఒక `projects` ఫోల్డర్) గల ఖాతాలను నివేదిక కవర్ చేస్తుంది. ఖాతాలు ఒక గ్రూప్ ద్వారా షేర్ చేసే సంభాషణ ఒక్కసారి మాత్రమే లెక్కించబడుతుంది.
- `-a` తో, ఒక గ్రూప్ ద్వారా తన చరిత్రను షేర్ చేసే ఖాతా మొత్తం గ్రూప్ సంభాషణలను తీసుకువస్తుంది, అవి ఎవరివో ccam చెబుతుంది: `ccam: work shares its conversation history with personal, so the report counts their conversations too`.
- `blocks` 5 గంటల విండోలను చూపిస్తుంది, ప్రతి ఖాతాకు దాని సొంత విండోలు ఉంటాయి, కాబట్టి పైన చూపినట్లు దాని కోసం ఒకే ఖాతాను పేర్కొనండి.
- మీరు ఒకదాన్ని పేర్కొనకపోతే, ccusage తనకు కనిపించే Codex వంటి ఇతర కోడింగ్ టూల్స్‌ను కూడా నివేదిస్తుంది: `ccam ccusage claude daily` అంటే Claude Code మాత్రమే.
- ccam దాన్ని రన్ చేస్తున్నప్పుడు, ccusage తన సెట్టింగ్‌లను (`ccusage.json`) `./.ccusage` నుంచి, ఖాతా ఫోల్డర్‌ల నుంచి మాత్రమే చదువుతుంది. `--config` మరో ఫైల్‌ను పేర్కొంటుంది: `ccam ccusage daily --config ~/.config/claude/ccusage.json`.
- పాత్‌లో కామా ఉన్న ఫోల్డర్‌ను ccusage రెండు ఫోల్డర్‌లుగా చదువుతుంది, కాబట్టి ccam దాన్ని తిరస్కరించి ఆ ఖాతా పేరును చెబుతుంది; `-a` తో ఆ ఖాతాను వదిలేయండి.
- `ccusage` ఒక ccam కమాండ్, కాబట్టి ccusage అనే పేరున్న ఖాతా `ccam run ccusage` తో ప్రారంభమవుతుంది; `ccam doctor` ఆ విషయం చెబుతుంది.

## ఇది ఎలా పనిచేస్తుంది

`ccam usage` చూపించే సంఖ్యలు రెండు చోట్ల నుంచి వస్తాయి: ప్రతి ఖాతా సొంత లాగిన్‌తో పిలిచే Anthropic యొక్క డాక్యుమెంట్ చేయని వినియోగ ఎండ్‌పాయింట్ `GET https://api.anthropic.com/api/oauth/usage`, Claude Code తన స్టేటస్ లైన్ కమాండ్‌కు అందించే విలువలు. ఇదంతా `internal/usage` లో ఉంటుంది.

1. ccam `config.toml` ను లోడ్ చేసి, ప్రతి ఖాతాకు ఒక `usage.Account` ను తయారు చేస్తుంది (`cli.usageCmd`): దాని ఫోల్డర్ `~/.local/share/ccam/profiles/<name>/`, దాని సెషన్ మార్కర్లు (ఖాతా ఫోల్డర్‌లోని Claude Code సొంత రికార్డులతో కలిపి, అది రన్ అవుతుందో లేదో అవి చెబుతాయి), అది ఉన్న చోటే ఇంపోర్ట్ చేయబడిందా లేదా.
2. ccam ప్రతి ఖాతాకు ఒక goroutine తో, అన్ని ఖాతాలను ఒకేసారి లుకప్ చేస్తుంది (`Fetcher.FetchAll`). అవన్నీ ఒకే `http.Client` ను షేర్ చేస్తాయి, కాబట్టి ఎండ్‌పాయింట్‌కు కనెక్షన్‌లు మళ్లీ ఉపయోగించబడతాయి. కనెక్ట్ అవ్వడానికి 2 s పట్టవచ్చు, ప్రతి ఖాతాకు మొత్తం 3 s లభిస్తాయి. రీడైరెక్ట్ టోకెన్‌ను వేరే చోటికి మళ్లీ పంపుతుంది కాబట్టి క్లయింట్ రీడైరెక్ట్‌లను అనుసరించదు, సమాధానంలో గరిష్ఠంగా 1 MB మాత్రమే చదువుతుంది.
3. ప్రతి ఖాతా పూర్తయినప్పుడు, దాని వరుస మళ్లీ గీయబడుతుంది. విఫలమైన లేదా సమయానికి సమాధానం ఇవ్వని ఖాతా సేవ్ చేసిన సంఖ్యలకు మారుతుంది, కాబట్టి ఒక నెమ్మదైన ఖాతా ఎప్పుడూ ఇతరులను ఆపదు.

డయాగ్రామ్‌లో, ప్రతి ఖాతా తన సొంత goroutine లో లుకప్ చేయబడుతుంది, సమయం మించిన ఖాతా బదులుగా తన సేవ్ చేసిన సంఖ్యలను చూపిస్తుంది:

<!-- motion:usage-fetch -->

`personal`, `work` సమయానికి సమాధానం ఇచ్చి లైవ్ సంఖ్యలను చూపిస్తాయి. `side` కు 3 s కంటే ఎక్కువ పడుతుంది, కాబట్టి ccam బదులుగా దాని సేవ్ చేసిన సంఖ్యలను చూపిస్తుంది (`fallback()`). ఆపై ccam ప్రతి ఖాతాకు ఒక బ్లాక్‌ను గీసి (`usage.Table()`), చివరి లైన్‌లో పేర్కొన్న ఖాతాను ఎంచుకుంటుంది (`usage.Best()`).

ఒక ఖాతా కోసం, ccam ఈ తనిఖీలను క్రమంగా చేస్తుంది (`Fetcher.Fetch`):

<!-- motion:usage-cache -->

1. `--source cache` తో, అది నేరుగా `fallback()` కు వెళ్తుంది.
2. `--no-cache` సెట్ కాకపోతే, `~/.local/state/ccam/usage/<name>.json` లో 60 సెకన్ల (`CacheTTL`) కంటే తక్కువ క్రితం కొలిచిన లైవ్ ఫలితం ఉపయోగించబడుతుంది, ఇప్పటి సమయం ప్రకారం అంచనా వేసి: ఆ తర్వాత రీసెట్ అయిన విండో 0% చూపిస్తుంది, గడియారం కంటే ముందు తేదీ ఉన్న ఫైల్ తాజాదిగా లెక్కించబడదు. `ccam usage` ను వరుసగా రెండుసార్లు రన్ చేస్తే ఒక్కో ఖాతాకు ఒక అభ్యర్థన మాత్రమే.
3. ccam `.credentials.json` ను (లేదా macOS Keychain ను) మార్చకుండా చదివి, `claudeAiOauth` కీని మాత్రమే డీకోడ్ చేస్తుంది (`readCredentials()`). సబ్‌స్క్రిప్షన్ లాగిన్ లేకపోతే `not logged in`, లేదా `.claude.json` లో API కీ ఉంటే `no limits (API)`. రిఫ్రెష్ టోకెన్ గడువు ముగిసిన, లేదా Claude Code క్లియర్ చేసిన లాగిన్ `` login expired → `ccam login <name>` `` అవుతుంది, దాని కోసం లుకప్ జరగదు.
4. గడువు ముగిసిన యాక్సెస్ టోకెన్ ఉపయోగించబడదు. `--refresh` లేకుండా, ఖాతా తన సేవ్ చేసిన సంఖ్యలను ``access token expired; `ccam <name>` renews it when it starts`` తో చూపిస్తుంది.
5. లేకపోతే ccam ఎండ్‌పాయింట్‌ను పిలుస్తుంది. 401 లేదా 403 గడువు ముగిసిన లాగిన్‌గా (`login expired: authentication failed (401)`), మరే ఇతర స్టేటస్ లేదా చదవలేని బాడీ ఎర్రర్‌గా లెక్కించబడతాయి, రెండూ సేవ్ చేసిన సంఖ్యలకు మారతాయి. Ctrl+C తో ముగిసిన లుకప్ `cancelled` అని చెబుతుంది. 429 అంటే ఈ ఖాతా కోసం ఎండ్‌పాయింట్‌కు చాలా ఎక్కువ అభ్యర్థనలు వచ్చాయని అర్థం: ccam మళ్లీ అడగాల్సిన సమయంతో (`Retry-After`, లేదా 5 నిమిషాలు, గరిష్ఠంగా ఒక గంట) `<name>.pause` ను రాస్తుంది, `rate limited by the usage endpoint; asking again after 15:10` తో సేవ్ చేసిన సంఖ్యలను చూపిస్తుంది, అప్పటి వరకు `--no-cache` తో కూడా ఆ ఖాతా కోసం ఎండ్‌పాయింట్‌ను పిలవదు. వెంటనే మళ్లీ ప్రయత్నిస్తే rate limit మరింత పొడిగించబడుతుంది అంతే.
6. మంచి సమాధానం అది కొలిచిన సమయంతో `<name>.json` లో రాయబడుతుంది.

సేవ్ చేసిన సంఖ్యల కోసం, ccam అత్యంత కొత్త సేవ్ చేసిన లుకప్‌ను (`<name>.json`, లేదా Claude Code లుకప్‌ల నుంచి వచ్చే `<name>.claude.json`) తీసుకుంటుంది, దాని తర్వాత `<name>.statusline.json` రాయబడి ఉంటే, స్టేటస్ లైన్ యొక్క 5 గంటల, వారపు విండోలను దానిపై పెడుతుంది (`fallback()`); స్టేటస్ లైన్‌లో లేని మోడల్ విండోలు లుకప్ సేవ్ చేసినట్లే ఉంటాయి. సేవ్ చేసిన సంఖ్యలను చూపించే ముందు, అది ప్రతి విండో రీసెట్ సమయాన్ని తనిఖీ చేస్తుంది: సంఖ్యలు సేవ్ అయినప్పటి నుంచి రీసెట్ అయిన విండో 0% చూపిస్తుంది, ఎందుకంటే పాత శాతం ఇక చెల్లదు. అందుకే పైన `personal` రీసెట్ సమయం లేకుండా `0%` చూపిస్తుంది.

ఎండ్‌పాయింట్‌కు రెండు రెస్పాన్స్ ఫార్మాట్‌లు ఉన్నాయి. కొత్తదానిలో `session` (5 గంటలు), `weekly_all`, `weekly_scoped` (మోడల్ వారీ) ఎంట్రీలతో `limits` అర్రే ఉంటుంది. పాతదానిలో `five_hour`, `seven_day`, `seven_day_opus`, `seven_day_sonnet` ఆబ్జెక్ట్‌లు ఉంటాయి. ccam రెండింటినీ చదువుతుంది (`ParseLive`): `limits` అర్రే గెలుస్తుంది, అది కవర్ చేయని వాటిని పాత ఆబ్జెక్ట్‌లు నింపుతాయి. అసలు పరిమితులే లేని బాడీ మారిన ఫార్మాట్‌గా నివేదించబడుతుంది, దాని గురించి `ccam doctor` మీకు చెబుతుంది.

### పరిమితి రికార్డ్

Claude Code ఒక turn ను వినియోగ పరిమితి వద్ద ఆపినప్పుడు, [ccam ప్లగిన్](/docs/install#claude-code-plugin) hook తిరస్కరించిన అభ్యర్థనను సంభాషణ నుంచి చదువుతుంది: ఏ విండో నిండింది (5 గంటల, వారపు, Opus లేదా Sonnet), అది ఎప్పుడు రీసెట్ అవుతుంది. అది దాన్ని `~/.local/state/ccam/usage/<name>.limit.json` లో రాస్తుంది. ప్రతి సోర్స్ నుంచి తనకు తెలిసిన మిగతా అన్నింటిపై ccam ఈ రికార్డ్‌ను వర్తింపజేస్తుంది (`Fetch`): సేవ్ చేసిన సంఖ్యలు ఎంత పాతవైనా, ఎంత తక్కువైనా, అందులోని ప్రతి విండో దాని రీసెట్ వరకు 100% గా లెక్కించబడుతుంది, కాబట్టి `ccam next --auto`, `ccam pick`, `--fallback`, [`auto_switch`](/features/next#auto-switch) అప్పటి వరకు ఆ ఖాతాను మళ్లీ ఎంచుకోవు.

ఇంకేమీ తెలియకపోతే, ఖాతా చూపించేది ఆ రికార్డ్ మాత్రమే (`-v` తో `source: the usage limit Claude Code reported`). ఎవరూ పర్యవేక్షించని సెషన్‌లు (`-p` రన్‌లు, బ్యాక్‌గ్రౌండ్ సెషన్‌లు) ఏ రికార్డ్‌నూ రాయవు, సంస్థ విధించిన ఆపివేత (ఉదాహరణకు, వినియోగం అయిపోయినప్పుడు లేదా ఒక గ్రూప్ పరిమితి $0 అయినప్పుడు) కూడా రాయదు, ఎందుకంటే దాని అడ్మిన్‌లు దాన్ని ఎప్పుడైనా ఎత్తివేయగలరు. వేరే Claude ఖాతాలోకి `ccam login` రికార్డ్‌ను తొలగిస్తుంది; ఫైల్‌ను తొలగించడం కూడా దాన్ని క్లియర్ చేస్తుంది.

### టోకెన్‌లను పునరుద్ధరించడం

రిఫ్రెష్ టోకెన్‌లు మారుతూ ఉంటాయి: ఒకదాన్ని పునరుద్ధరిస్తే మీకు కొత్త రిఫ్రెష్ టోకెన్ లభిస్తుంది, పాతది చెల్లకుండా పోతుంది. అదే ఖాతాగా Claude Code రన్ అవుతున్నప్పుడు ccam లాగిన్‌ను పునరుద్ధరిస్తే, ఆ సెషన్ సైన్ అవుట్ అవుతుంది. కాబట్టి మీరు `--refresh` ఇస్తే తప్ప, `ccam usage` టోకెన్‌లను చదువుతుంది, ఎప్పుడూ రాయదు. అప్పుడు ccam (`Fetcher.refresh`):

1. `ccam import` తో ఉన్న చోటే నమోదైన ఖాతాలను తిరస్కరిస్తుంది, ఎందుకంటే ccam కు తెలియకుండా సాధారణ `claude` ఆ లాగిన్‌ను ఉపయోగించవచ్చు;
2. macOS Keychain లో నిల్వ ఉన్న లాగిన్‌లను తిరస్కరిస్తుంది;
3. `~/.local/state/ccam/locks/profile-<name>.refresh.lock` అనే లాక్ ఫైల్‌ను తీసుకుంటుంది, కాబట్టి రెండు ccam ప్రాసెస్‌లు ఒకే టోకెన్‌ను ఎప్పుడూ రెండూ పునరుద్ధరించవు; అది పట్టి ఉన్నంతసేపు, ఖాతా `token not renewed: another ccam process is using this login right now (a refresh, rename, remove or logout)` అని చూపిస్తుంది. `ccam rename`, `remove`, `logout` కూడా దాన్ని తీసుకుంటాయి, పునరుద్ధరణ జరుగుతున్నప్పుడు నిరాకరిస్తాయి;
4. లాక్ కింద, ఖాతా సెషన్ రన్ అవుతుంటే, అది ఎలా ప్రారంభమైనా సరే (ccam ద్వారా, సాధారణ `claude`, ఒక IDE, లేదా బ్యాక్‌గ్రౌండ్ సెషన్, దాని వెనుక ఉండి లాగిన్‌ను తానే పునరుద్ధరించే daemon), తిరస్కరిస్తుంది, మరో ప్రాసెస్ ఇప్పటికే టోకెన్‌ను పునరుద్ధరించి ఉంటే అభ్యర్థనను దాటవేస్తుంది;
5. ఖాతా ఫోల్డర్‌లో Claude Code తన సొంత పునరుద్ధరణ లాక్‌లను (`.oauth_refresh.lock`, `<folder>.lock`) పట్టి ఉన్నప్పుడు ఏమీ పంపదు: ఆ సమయంలో Claude Code ఆ లాగిన్‌ను పునరుద్ధరిస్తోంది;
6. రిఫ్రెష్ టోకెన్‌ను టోకెన్ ఎండ్‌పాయింట్‌కు పంపి, సమాధానం కోసం 30 సెకన్ల వరకు వేచి ఉంటుంది, Claude Code తన సొంత పునరుద్ధరణలకు ఇచ్చే సమయం అదే. ఒకసారి పంపిన అభ్యర్థన ఎప్పుడూ మధ్యలో ఆపబడదు, Ctrl+C తో కూడా కాదు: సర్వర్ ఇప్పటికే రిఫ్రెష్ టోకెన్‌ను మార్చి ఉండవచ్చు, దాని సమాధానంలో మాత్రమే కొత్త లాగిన్ ఉంటుంది. Ctrl+C లేదా hangup ఇతర లుకప్‌లను ముగిస్తుంది, సమాధానం సేవ్ అయిన తర్వాత ccam నిష్క్రమిస్తుంది (Ctrl+C తర్వాత 130);
7. Claude Code రైట్ లాక్ (`.storage-write.lock`) కింద సేవ్ చేస్తుంది, ఆ సమయంలో ఉన్న `.credentials.json` లో టోకెన్ ఫీల్డ్‌లను మాత్రమే మారుస్తుంది: ఈలోగా Claude Code రాసింది (ఒక MCP సైన్-ఇన్) అలాగే ఉంటుంది, ఈలోగా Claude Code పునరుద్ధరించిన లాగిన్ ఉంచబడుతుంది, లాగ్ అవుట్ ఎప్పుడూ రద్దు చేయబడదు. సమాధానం కొత్త రిఫ్రెష్ టోకెన్ జీవితకాలాన్ని ఇచ్చినప్పుడు, Claude Code చేసినట్లే అది `refreshTokenExpiresAt` గా నిల్వ అవుతుంది.

జరగని రిఫ్రెష్ కారణాన్ని, ఖాతా లైన్‌పై లేదా దాని సేవ్ చేసిన సంఖ్యల పైన, చెబుతుంది: ఉదాహరణకు `token not renewed: a session is running`, లేదా అభ్యర్థన పంపినా దాని సమాధానాన్ని ఉపయోగించలేకపోయినా, సేవ్ చేయలేకపోయినా `login may be lost: …`, ఆ తర్వాత Claude Code మిమ్మల్ని లాగిన్ చేయమని అడిగితే `ccam login <name>` రన్ చేయమనే సలహాతో.

### స్టేటస్ లైన్ కలెక్టర్

Claude Code స్టేటస్ లైన్ కమాండ్‌ను రన్ చేసి దానికి ఒక JSON డాక్యుమెంట్‌ను పైప్ చేస్తుంది. ccam దాని నుంచి మోడల్ పేరును, `rate_limits` ను చదువుతుంది:

<!-- motion:usage-statusline -->

1. ccam Claude Code ను ప్రారంభించేటప్పుడు సెట్ చేసే `CCAM_PROFILE` నుంచి, లేకపోతే `CLAUDE_CONFIG_DIR` ను ఖాతా ఫోల్డర్‌లతో సరిపోల్చి, ఖాతాను కనుగొంటుంది (`runStatusline`).
2. ccam `rate_limits.five_hour`, `rate_limits.seven_day` ను చదువుతుంది (`ParseStatusLine`). API కీ ఖాతాలకు, లేదా సెషన్ మొదటి రెస్పాన్స్‌కు ముందు, JSON లో రేట్ లిమిట్‌లు ఉండవు; అప్పుడు ఏదీ సేవ్ కాదు.
3. ccam `~/.local/state/ccam/usage/<name>.statusline.json` ను రాస్తుంది (`SaveStatusLine`). ఎండ్‌పాయింట్ సమాధానం ఇవ్వనప్పుడు `ccam usage` దాన్ని ఉపయోగిస్తుంది.
4. ccam `[name] · model · 5h N% · 7d N%` ను ప్రింట్ చేస్తుంది. `--wrap` తో, అది అదే ఇన్‌పుట్‌తో `sh -c` ద్వారా మీ కమాండ్‌ను రన్ చేసి, Claude Code స్టేటస్ లైన్‌ను చూపించే విధంగానే దాని అవుట్‌పుట్‌ను ప్రింట్ చేస్తుంది: ఖాళీ కాని ప్రతి లైన్, మొదటి లైన్ ముందు `[name]` తో. విఫలమైన కమాండ్ ఖాతా పేరును మాత్రమే చూపిస్తుంది. Windows లో అది కమాండ్‌ను Claude Code లాగే రన్ చేస్తుంది: Git Bash ఇన్‌స్టాల్ అయి ఉంటే దానితో, లేకపోతే PowerShell తో.
5. 5 గంటల లేదా వారపు వినియోగం 90% లేదా అంతకంటే ఎక్కువ ఉండి, మరో ఖాతా ఉన్నప్పుడు, లైన్ `→ ccam next --auto --continue` తో ముగుస్తుంది, ఉదాహరణకు `[work] · Opus · 5h 93% · 7d 41% · → ccam next --auto --continue`.

వ్రాప్ చేసిన కమాండ్‌కు సొంత సమయ పరిమితి లేదు: Claude Code స్టేటస్ లైన్ కమాండ్‌కు 10 నిమిషాలు ఇస్తుంది, కొత్త అప్‌డేట్ మొదలైనప్పుడు ఒక రన్‌ను ఆపుతుంది, కాబట్టి నెమ్మదైన కమాండ్ ccam లేకుండా ఎలా కనిపిస్తుందో అలాగే కనిపిస్తుంది. Claude Code ccam ను ముగించినప్పుడు, కమాండ్ కూడా ముగుస్తుంది (Linux, macOS లలో అది ప్రారంభించిన ప్రతి ప్రాసెస్‌తో సహా).

`ccam statusline install` ప్రతి ఖాతా `settings.json` లో `statusLine` ను రాస్తుంది, ఆ ఆబ్జెక్ట్ ఇతర కీలను, ఉదాహరణకు `padding`, `refreshInterval`, `hideVimModeIndicator` ను ఉంచుతుంది. ఒక ఖాతాకు ఇప్పటికే స్టేటస్ లైన్ కమాండ్ ఉంటే, ccam దాన్ని `--wrap '<old command>'` గా ఉంచుతుంది; Windows లో `--wrap-base64 <base64>` గా, దానికి ఏ షెల్‌లోనూ కోటింగ్ అవసరం లేదు. స్టేటస్ లైన్ ఇప్పటికే ccam ను రన్ చేస్తుంటే (వేరే పాత్ నుంచి అయినా, లేదా పాత వెర్షన్ రాసిన విధంగా కోట్ చేసినదైనా), ccam దాన్ని వ్రాప్ చేయకుండా భర్తీ చేస్తుంది, అది వ్రాప్ చేసే కమాండ్‌ను ఉంచుతుంది.

Windows లో ccam పాత్ forward slashes తో, హోమ్ ఫోల్డర్‌కు `~` తో రాయబడుతుంది (`~/.local/bin/ccam.exe statusline`), దీన్ని Git Bash, PowerShell రెండూ అర్థం చేసుకుంటాయి. కోట్‌లు అవసరమైన పాత్ Claude Code ఉపయోగించే షెల్ కోసం పూర్తిగా రాయబడుతుంది: Git Bash కు `'…'`, PowerShell కు `& '…'`. గ్రూప్ ద్వారా షేర్ చేసిన `settings.json` దాని లింక్ ద్వారా ఒకసారి రాయబడుతుంది, కాబట్టి గ్రూప్‌లోని ప్రతి ఖాతాకు అది అందుతుంది. దాన్ని మళ్లీ రన్ చేస్తే ఇప్పటికే ccam ను ఉపయోగిస్తున్న ఫైళ్లకు `(already set)` అని ప్రింట్ అవుతుంది.

## భద్రత, ప్రత్యేక సందర్భాలు

- మీరు `--refresh` ఇస్తే తప్ప `ccam usage` ఎప్పుడూ టోకెన్ ఫైల్‌ను మార్చదు. యాక్సెస్ టోకెన్ గడువు ముగిసినప్పుడు, ఆ ఖాతాను `ccam <name>` తో ఒక్కసారి రన్ చేయండి, Claude Code దాన్ని పునరుద్ధరిస్తుంది. పూర్తిగా గడువు ముగిసిన లాగిన్‌కు `ccam login <name>` అవసరం.
- `--refresh` రన్ అవుతున్న ఖాతాలను (Claude Code ccam లేకుండా ప్రారంభించినప్పటికీ), ఇంపోర్ట్ చేసిన ఖాతాలను, Keychain లాగిన్‌లను ఎప్పుడూ ముట్టుకోదు. తిరస్కరించిన రిఫ్రెష్ సేవ్ చేసిన సంఖ్యలను, కారణాన్ని (`token not renewed: …`) చూపిస్తుంది.
- వినియోగ ఎండ్‌పాయింట్ బహిరంగంగా డాక్యుమెంట్ చేయబడలేదు, మారవచ్చు. అది మారినప్పుడు, మీకు ఇంకా సేవ్ చేసిన సంఖ్యలు కనిపిస్తాయి, `ccam doctor` ఫార్మాట్ మార్పును నివేదిస్తుంది.
- సేవ్ చేసిన సంఖ్యలు, సమాధానం రెండూ లేకపోతే, ఖాతా లైన్ `lookup failed:` ను, కారణాన్ని చూపిస్తుంది, ఉదాహరణకు `--source cache` తో `no saved usage`.
- కాష్ ఫైళ్లలో శాతాలు, రీసెట్ సమయాలు మాత్రమే ఉంటాయి, ఎప్పుడూ టోకెన్‌లు ఉండవు.
