`ccam next` เปิด Claude Code ด้วยบัญชีอื่นโดยที่คุณไม่ต้องระบุชื่อ ใช้เมื่อบัญชีถึงขีดจำกัดการใช้งาน: `ccam next` แบบธรรมดาจะเลือกบัญชีถัดจากบัญชีที่คุณใช้ล่าสุด `--auto` จะเลือกบัญชีที่เหลือโควตามากที่สุด และ `--continue` จะพาการสนทนาล่าสุดของโฟลเดอร์นี้ไปยังบัญชีใหม่ ไม่ว่าทั้งสองบัญชีจะใช้ประวัติร่วมกันหรือไม่ ภายใน Claude Code [ปลั๊กอิน ccam](#inside-claude-code) จะบอกคุณเมื่อขีดจำกัดทำให้เซสชันหยุด และ `/ccam:switch` จะส่งต่อการสนทนาไป สำหรับสคริปต์ที่รัน `claude -p` นั้น `ccam --fallback` จะสลับบัญชีให้เอง (ดู [รันอีกครั้งเมื่อถึงขีดจำกัด](#run-again-at-the-limit))

## การใช้งาน

```sh
ccam next                       # the account after the one you used last
ccam next --auto                # the account with the most room
ccam next --continue            # carry this folder's last conversation on as the next account
ccam next -c --auto             # both: the conversation, on the account with the most room
ccam next --auto --max-usage 80 # prefer accounts below 80%
ccam next --auto --strategy balance   # the weekly quota that would go unused first
ccam next --auto --cross-org    # also accounts of other organizations
ccam next --auto --wait         # nobody has room: wait for the first reset (up to 5 hours)
ccam next -c --auto -- --dangerously-skip-permissions   # claude's own options go after --
ccam --dry-run next --auto      # print the choice and the command, start nothing
```

```console
$ ccam --dry-run next --auto --continue
→ personal → work (12% of its 5 hours used, the least)
  continuing "Fix the flaky tests" (about 182k tokens); work does not share personal's history, so Claude Code copies it into work
CLAUDE_CONFIG_DIR=/home/you/.local/share/ccam/profiles/work /usr/local/bin/claude --resume /home/you/.local/share/ccam/profiles/personal/projects/-home-you-code-app/4f1c….jsonl --fork-session
```

ccam พิมพ์การสลับเป็น `→ <from> → <to>` ทาง standard error พร้อมเหตุผลของการเลือกด้วย `--auto` จากนั้นเริ่ม Claude Code ด้วยบัญชีใหม่แบบเดียวกับ `ccam <name>` `<from>` คือบัญชีที่คุณใช้ล่าสุด หรือเมื่อใช้ `--continue` คือบัญชีที่เป็นเจ้าของการสนทนานั้น อาร์กิวเมนต์หลัง `--` จะส่งต่อให้ `claude` โดยไม่เปลี่ยนแปลง

## ตัวเลือก

| ตัวเลือก | สิ่งที่ทำ | ค่าเริ่มต้น |
| --- | --- | --- |
| `--auto` | เลือกบัญชีที่เข้าสู่ระบบแล้วตามการใช้งาน (ดูด้านล่าง) โดยข้ามบัญชีที่ใช้ไปถึง 100% | ปิด |
| `--max-usage <1-100>` | ใช้กับ `--auto`: เลือกบัญชีที่ใช้งานต่ำกว่าค่านี้ก่อน | `auto_max_usage` หากไม่มีคือ 100 |
| `--strategy headroom\|expiring\|balance` | ใช้กับ `--auto`: การใช้งาน 5 ชั่วโมงต่ำที่สุด ช่วง 5 ชั่วโมงที่จะรีเซ็ตเร็วที่สุด หรือโควตารายสัปดาห์ที่จะถูกปล่อยทิ้งโดยไม่ได้ใช้ก่อน | `auto_strategy` หากไม่มีคือ `headroom` |
| `--cross-org` | ใช้กับ `--auto`: เลือกบัญชีขององค์กรอื่นด้วย (ดูด้านล่าง) | `cross_org` หากไม่มีคือปิด |
| `--wait[=<duration>]` | ใช้กับ `--auto`: เมื่อไม่มีบัญชีใดเหลือโควตา ให้รอบัญชีแรกที่รีเซ็ต นานไม่เกินค่านี้ | ปิด; `5h` เมื่อระบุโดยไม่มีค่า |
| `-c`, `--continue` | พาการสนทนาล่าสุดของโฟลเดอร์นี้ไปต่อด้วยบัญชีใหม่ (ดูด้านล่าง) | ปิด |
| `-- <claude args>` | อาร์กิวเมนต์ที่ส่งให้ `claude` ต่อจากอาร์กิวเมนต์ของ ccam เอง | ไม่มี |
| `--dry-run` | รองรับ: พิมพ์ `→ <from> → <to>` และบรรทัดคำสั่งที่จะรัน โดยไม่เริ่ม Claude Code และไม่บันทึกการเริ่ม | ปิด |

`--auto` และ `--continue` ใช้ร่วมกันได้ เมื่อใช้ `--continue` อาร์กิวเมนต์ `--resume` จะถูกวางไว้ก่อนอาร์กิวเมนต์ของคุณ

ตัวเลือกของ Claude Code เอง เช่น `--dangerously-skip-permissions` หรือ `--model` ต้องวางไว้หลัง `--` ต่างจาก `ccam <name>` ที่ส่งต่อทุกอย่างหลังชื่อไปให้ `ccam next` อ่านอาร์กิวเมนต์เอง ดังนั้นหากไม่มี `--` จะหยุดพร้อมข้อความ `ccam: unknown flag: --dangerously-skip-permissions`

## วิธีการทำงาน

การเริ่มทุกครั้งผ่าน ccam จะเขียนเวลาลงใน `~/.local/state/ccam/last-used/<name>` `ccam next` อ่านไฟล์เหล่านี้ ตรวจว่าบัญชีใดเข้าสู่ระบบแล้ว แล้วจึงเลือก

1. `cli.candidates` สร้าง `next.Candidate` หนึ่งรายการต่อบัญชีจาก `config.toml`: ได้แก่ บัญชี เวลาที่เริ่มครั้งล่าสุด (`launcher.LastUsed`) และบัญชีนั้นมีการเข้าสู่ระบบหรือไม่ (`creds.Has`: มี `.credentials.json` ที่อ่านได้ หรือบน macOS มีรายการในพวงกุญแจ (Keychain))
2. หากไม่ใส่ `--auto` `next.Rotate` จะเรียงบัญชีตามหมายเลขสล็อตและหาบัญชีที่เริ่มล่าสุด ซึ่งคือบัญชีที่คุณกำลังสลับออก หากยังไม่มีบัญชีใดถูกเริ่มเลย จะใช้สล็อตต่ำสุด
3. จากตรงนั้นจะไล่ไปข้างหน้าตามลำดับสล็อต วนจากสล็อตสุดท้ายกลับไปสล็อตแรก และคืนบัญชีแรกที่เข้าสู่ระบบแล้ว
4. `launcher.LaunchWith` เตรียมและเริ่มบัญชีที่เลือกเหมือนกับที่ `ccam <name>` ทำทุกประการ: ตรวจลิงก์ของบัญชี ใช้การตั้งค่า MCP ที่ใช้ร่วมกัน ลงทะเบียนเซสชัน และแทนที่ ccam ด้วย `claude` ผ่าน `syscall.Exec`

การไล่เริ่มที่บัญชีที่ใช้ล่าสุด และหยุดที่บัญชีแรกที่เข้าสู่ระบบแล้วซึ่งอยู่ถัดไป:

`work` ถูกเริ่มล่าสุด การไล่จึงเริ่มต่อจากบัญชีนี้ `side` ไม่มีการเข้าสู่ระบบจึงถูกข้าม และเลือก `lab` หาก `lab` ออกจากระบบไปแล้วด้วย การไล่จะวนกลับไปที่ `personal` (`% len` ในแผนภาพ) การหมุนเวียนไม่มีทางคืนบัญชีที่คุณเริ่มต้นมา: หากไม่มีบัญชีอื่นที่เข้าสู่ระบบแล้ว จะหยุดพร้อมข้อผิดพลาด

### --auto

`--auto` ตัดสินจากการใช้งานแทนลำดับสล็อต `cli.pickAuto` เก็บบัญชีที่เข้าสู่ระบบแล้วไว้ สอบถามการใช้งานของทุกบัญชีพร้อมกันด้วย `Fetcher.FetchAll` ตัวเดียวกับที่ `ccam usage` ใช้ และให้ `usage.Policy.Choose()` เป็นผู้เลือก:

<!-- motion:next-auto -->

บัญชีจะถูกตัดสินจากช่วง 5 ชั่วโมงและรายสัปดาห์ และเมื่อมี `--model` อยู่ในอาร์กิวเมนต์สำหรับ Claude Code (หลัง `--`) ก็จะดูช่วงรายสัปดาห์ของโมเดลนั้นด้วย (`opus`, `sonnet`, `haiku` หรือ `fable` ในชื่อ) `Policy.Choose()` แบ่งบัญชีออกเป็นสามกลุ่ม:

1. **มีโควตาเหลือ**: ทุกช่วงต่ำกว่า `auto_max_usage` (`config.toml` ค่าเริ่มต้น 100) กลยุทธ์จะเลือกจากกลุ่มนี้: `headroom` (ค่าเริ่มต้น) เลือกบัญชีที่ใช้งาน 5 ชั่วโมงต่ำที่สุด `expiring` เลือกช่วง 5 ชั่วโมงที่จะรีเซ็ตเร็วที่สุด เพื่อให้ใช้โควตาที่เหลือก่อนที่จะหายไป ส่วน `balance` เลือกบัญชีที่เหลือโควตารายสัปดาห์ต่อวันมากที่สุดจนกว่าสัปดาห์ของบัญชีนั้นจะรีเซ็ต โดยนับเซสชัน ccam ที่กำลังทำงานแต่ละเซสชันหักออกจากบัญชีนั้นด้วย โควตารายสัปดาห์จึงไม่ถูกปล่อยทิ้ง และเซสชันที่ทำงานขนานกันจะกระจายออกไป
2. **เกิน**: ต่ำกว่า 100% แต่เท่ากับหรือเกิน `auto_max_usage` ใช้เฉพาะเมื่อไม่มีบัญชีใดมีโควตาเหลือ โดยเลือกบัญชีที่ใช้งาน 5 ชั่วโมงต่ำที่สุดก่อน
3. **เต็ม**: มีช่วงใดช่วงหนึ่งอยู่ที่ 100% หรือไม่ทราบการใช้งาน 5 ชั่วโมง ไม่ถูกเลือกเด็ดขาด

```toml
# ~/.config/ccam/config.toml
auto_max_usage = 80        # keep 20% of each account for interactive work
auto_strategy = "expiring"
```

**องค์กร** การเลือกอัตโนมัติจะอยู่กับบัญชีที่เหมือนกับบัญชีที่คุณออกมา: องค์กรแบบ Team หรือ Enterprise เดียวกัน หรือแพ็กเกจส่วนตัว (Pro, Max) ด้วยกัน งานจากบัญชีบริษัทจึงไม่ไปทำต่อในบัญชีส่วนตัว และในทางกลับกันก็เช่นกัน ccam รู้องค์กรของแต่ละบัญชีจากการเข้าสู่ระบบ (`ccam login` บันทึกไว้ ส่วนการเข้าสู่ระบบรุ่นเก่าจะอ่านจาก `.claude.json`) บัญชีที่ ccam บอกองค์กรไม่ได้จะถือว่าเข้ากับองค์กรใดก็ได้ โฟลเดอร์สองโฟลเดอร์ที่เข้าสู่ระบบด้วยบัญชี Claude เดียวกันใช้ขีดจำกัดร่วมกัน จึงไม่มีโฟลเดอร์ใดรับช่วงต่อจากอีกโฟลเดอร์หนึ่ง `--cross-org` หรือ `cross_org = true` ใน `config.toml` จะยกเลิกกฎเรื่ององค์กรนี้

เมื่อเลือกบัญชีใดไม่ได้ ccam จะออกด้วยรหัส 75 (`EX_TEMPFAIL`) เพื่อให้สคริปต์แยก "ลองใหม่ภายหลัง" ออกจากความล้มเหลวได้ เมื่อใช้ `--wait` ccam จะพักรอจนกว่าช่วงที่ปิดกั้นของบัญชีที่เต็มบัญชีแรกจะรีเซ็ต (30 วินาทีหลังเวลารีเซ็ต ซึ่งเป็นตอนที่ endpoint แสดงช่วงใหม่) พิมพ์ `ccam: no account has room; waiting until 15:10` แล้วเลือกใหม่อีกครั้ง หากไม่มีบัญชีใดบอกเวลารีเซ็ต จะกลับมาดูอีกครั้งหลัง 10 นาที หากไม่มีบัญชีใดว่างก่อนหมดเวลารอ จะออกด้วยรหัส 75 การสอบถามทำตามกฎของ `ccam usage`: ตัวเลขที่ดึงมาเมื่อไม่ถึง 60 วินาทีที่แล้วจะถูกนำกลับมาใช้ แต่ละบัญชีมีเวลา 3 วินาที และบัญชีที่ไม่ตอบกลับหรือการเข้าสู่ระบบหมดอายุแล้วจะถูกตัดสินจากตัวเลขที่บันทึกไว้ ช่วงเวลาที่บันทึกไว้ซึ่งเลยเวลารีเซ็ตไปแล้วจะนับเป็น 0% บัญชีที่ช่วงเวลารีเซ็ตไปแล้วจึงไม่ถูกมองข้าม `--auto` ไม่เคยต่ออายุโทเค็น ต่างจากการหมุนเวียนแบบธรรมดา `--auto` อาจเลือกบัญชีที่คุณใช้ล่าสุดได้หากบัญชีนั้นยังเหลือโควตามากที่สุด

### --continue

1. ccam ค้นหาการสนทนาล่าสุดของโฟลเดอร์นี้ในทุกบัญชี: `<session>.jsonl` ที่ใหม่ที่สุดใน `projects/<folder>/` (ชื่อโฟลเดอร์คือโฟลเดอร์ที่ทำงานอยู่ โดยเปลี่ยนทุกอักขระที่ไม่ใช่ตัวอักษรหรือตัวเลขเป็น `-` ตามที่ Claude Code ตั้งชื่อ) หากเซสชันทิ้งบันทึกไว้ (จากขีดจำกัดการใช้งานหรือ `/ccam:switch` ดูด้านล่าง) และไม่มีอะไรใหม่กว่าถูกเขียนหลังจากนั้น จะใช้เซสชันนั้นแทน
2. บัญชีที่เป็นเจ้าของการสนทนาคือบัญชีที่คุณสลับออก และบัญชีใหม่จะถูกเลือกตามข้างต้นภายในองค์กรเดียวกัน
3. หากบัญชีใหม่ใช้ประวัตินั้นร่วมกัน (โฟลเดอร์กลุ่มเดียวกัน) ccam จะเริ่ม `claude --resume <session id>` ซึ่งก็คือการสนทนานั้นเอง (`--continue` จะเปิดการสนทนาที่ใหม่ที่สุดในโฟลเดอร์ ไม่ว่าจะเป็นการสนทนาใด)
4. หากไม่ได้ใช้ร่วมกัน ccam จะเริ่ม `claude --resume <the conversation's file> --fork-session`: Claude Code จะคัดลอกการสนทนาทั้งหมดภายใต้ session id ใหม่ไปยังประวัติของบัญชีใหม่เอง และต้นฉบับจะยังคงเหมือนเดิม จากนั้น `--continue` ของบัญชีใหม่จะพบการสนทนานั้น

ccam จะบอกว่าการสนทนามีขนาดเท่าไร: บัญชีใหม่จะอ่านการสนทนาทั้งหมดอีกครั้งในคำตอบแรก prompt cache ไม่เคยใช้ร่วมกันระหว่างองค์กร ดังนั้นเมื่อใช้ `--cross-org` คำตอบแรกนั้นจะคิดเต็มขนาด การใช้ `history` ร่วมกันในกลุ่มช่วยเลี่ยงการคัดลอก ทำให้เป็นการสนทนาเดียว และยังใช้ checkpoint ที่ `/rewind` ใช้กู้คืนโค้ดร่วมกันด้วย (`file-history/`)

## ภายใน Claude Code

[ปลั๊กอิน ccam](/docs/install#claude-code-plugin) เพิ่ม hook สองตัว (Claude Code 2.1.78 ขึ้นไป):

- เมื่อเทิร์นหนึ่งหยุดเพราะถึงขีดจำกัดการใช้งาน (`You've hit your session limit` ขีดจำกัดรายสัปดาห์ หรือขีดจำกัดของโมเดล) hook จะจดการสนทนาไว้และแสดงการแจ้งเตือนบนเดสก์ท็อปในเทอร์มินัลที่รองรับ (iTerm2, WezTerm, Windows Terminal, kitty, Ghostty): `ccam: work hit its 5-hour limit (resets 3:45pm). ccam next --continue carries on as another account.` การจำกัดความเร็วสั้น ๆ ของเซิร์ฟเวอร์หรือ rate limit ของ API key ไม่ใช่ขีดจำกัดการใช้งานและจะไม่ถูกแตะต้อง Claude Code 2.1.234 ขึ้นไปยังรออยู่ในเซสชันและทำต่อเองหลังช่วง 5 ชั่วโมงรีเซ็ตด้วย การแจ้งเตือนจึงให้คุณเลือกสลับบัญชีแทนได้
- `/ccam:switch [account]` จะจดการสนทนาไว้และจบเทิร์นก่อนที่จะมีคำขอใด ๆ: พิมพ์ `/exit` จากนั้น `ccam next --continue` จะพาการสนทนาไปต่อด้วยบัญชีที่คุณระบุ หรือบัญชีถัดไป

บันทึกนี้อยู่ใน `~/.local/state/ccam/handoff/<account>.json` เป็นเวลา 12 ชั่วโมงและจะถูกใช้เพียงครั้งเดียวเมื่อเซสชันถัดไปกำลังจะเริ่ม หากการเริ่มล้มเหลว บันทึกจะยังอยู่ให้ลองครั้งถัดไป บันทึกเป็นของโฟลเดอร์ที่เซสชันเริ่มต้น แม้จะ `cd` ไปที่อื่นในเชลล์ของ Claude Code แล้วก็ตาม หากบัญชีที่บันทึกระบุไว้ถูกเปลี่ยนชื่อหรือถูกลบไปแล้ว ccam จะแจ้งเรื่องนี้และเลือกบัญชีตามปกติ เมื่อตั้ง `relay = true` ใน `config.toml` ccam จะอยู่ข้างเซสชันแบบโต้ตอบแทนการแทนที่ตัวเองด้วย Claude Code และหลัง `/ccam:switch` ccam จะพาการสนทนาของเซสชันนั้นไปต่อเอง (บันทึกที่เซสชันอื่นทิ้งไว้จะไม่ถูกนำมาใช้) ซึ่งต้องมีโปรเซส ccam ที่รออยู่หนึ่งโปรเซสต่อเซสชัน จึงปิดไว้เป็นค่าเริ่มต้น เซสชันที่ถูกส่งต่อจะเริ่มด้วย `ccam next --continue` โดยไม่มีอาร์กิวเมนต์ที่ใช้ตอนเริ่มเซสชันแรก เช่น `--model`

## รันอีกครั้งเมื่อถึงขีดจำกัด

`ccam next` ใช้สำหรับเซสชันแบบโต้ตอบที่หยุดไปแล้ว การรันแบบไม่โต้ตอบ เช่น `claude -p` ในสคริปต์หรืองานตามกำหนดเวลา รอคุณไม่ได้ การใส่ `--fallback` ไว้หน้าชื่อบัญชีจึงให้ ccam สลับบัญชีแทนให้:

```sh
ccam --fallback work -p "fix the failing tests" --output-format json
ccam --fallback -p "summarise" < notes.txt      # the folder's account or the default
ccam run --fallback work -p "review the diff"
```

```console
$ ccam --fallback personal -p "summarise" < notes.txt
ccam: personal reached its usage limit; running the command again as work
Summary: …
```

1. `--fallback` ใช้ได้เฉพาะร่วมกับ `-p` หรือ `--print` เท่านั้น มิฉะนั้น ccam จะหยุดและแนะนำ `ccam next --auto --continue` แทน
2. อินพุตมาตรฐานถูกอ่านครั้งเดียวและส่งให้ทุกครั้งที่ลอง
3. ccam เริ่ม `claude` เป็นโปรเซสลูกแทนการใช้ `exec` กักเอาต์พุตมาตรฐานไว้ก่อน และส่ง standard error ผ่านออกไปทันทีที่ได้รับ
4. เมื่อ `claude` ออกด้วยรหัส 0 หรือล้มเหลวด้วยสาเหตุอื่น เอาต์พุตที่กักไว้และรหัสออกจะถูกส่งต่อโดยไม่เปลี่ยนแปลง
5. ความล้มเหลวจะนับว่าเป็นขีดจำกัดการใช้งานเมื่อข้อความของ Claude Code ระบุเช่นนั้น (`You've hit your limit`, `usage limit reached`) หรือเมื่อการดูการใช้งานของบัญชีแสดงว่าช่วง 5 ชั่วโมงหรือรายสัปดาห์อยู่ที่ 100%
6. จากนั้นเอาต์พุตของการลองครั้งนั้นจะถูกทิ้ง และคำสั่งเดิมจะรันด้วยบัญชีอื่นที่เข้าสู่ระบบอยู่: บัญชีที่ใช้งาน 5 ชั่วโมงน้อยที่สุด ตามด้วยบัญชีที่ดูการใช้งานไม่ได้ เรียงตามหมายเลข บัญชีที่อยู่ที่ 100% จะถูกข้าม และแต่ละบัญชีจะถูกลองไม่เกินหนึ่งครั้ง
7. หากมี `-c`, `--continue`, `-r` หรือ `--resume` อยู่ในอาร์กิวเมนต์ จะลองเฉพาะบัญชีที่อยู่ในกลุ่มประวัติเดียวกัน เพื่อให้หาการสนทนาเจอ
8. จะลองเฉพาะบัญชีขององค์กรเดียวกัน เช่นเดียวกับ `--auto` (`cross_org = true` จะยกเลิกข้อนี้)

บัญชีถัดไปจะถูกเลือกด้วยกฎเดียวกับ `--auto` (`auto_max_usage`, `auto_strategy` และช่วงของ `--model`) เมื่อไม่มีบัญชีเหลือ ccam จะพิมพ์เอาต์พุตของการลองครั้งสุดท้าย แจ้งว่าไม่มีบัญชีที่เข้าสู่ระบบอยู่บัญชีใดเหลือโควตา และออกด้วยรหัส 75 เมื่อใส่ `--wait` ไว้ก่อนชื่อบัญชี (`ccam --fallback --wait=2h work -p …`) ccam จะรอให้บัญชีแรกรีเซ็ตแทน แล้วอาจลองทุกบัญชีอีกครั้ง โดยจะพักรออย่างน้อยหนึ่งครั้งก่อนเสมอ บัญชีที่เพิ่งถึงขีดจำกัดจึงไม่ถูกรันซ้ำทันที `ccam --dry-run --fallback work -p …` จะพิมพ์คำสั่งของการลองครั้งแรก

เซสชันแบบโต้ตอบจะไม่ถูกสลับเอง แต่เมื่อใช้ `ccam statusline install` แถบสถานะจะเพิ่ม `→ ccam next --auto --continue` เมื่อการใช้งาน 5 ชั่วโมงหรือรายสัปดาห์ถึง 90% ([ขีดจำกัดการใช้งาน](/features/usage))

## ความปลอดภัยและกรณีพิเศษ

- บัญชีที่ไม่มีการเข้าสู่ระบบจะไม่ถูกเลือกเลย หากไม่มีบัญชีอื่นที่เข้าสู่ระบบแล้ว `ccam next` แบบธรรมดาจะหยุดด้วย `no logged-in account other than <name>`
- เมื่อใช้ `--continue` และไม่มีการสนทนาในโฟลเดอร์: `no account has a conversation in <folder> to continue`
- เมื่อกฎเรื่ององค์กรทำให้ไม่เหลือบัญชีให้เลือก: `` no logged-in account to pick among <name>'s (<organization>); --cross-org also looks at the others ``
- เมื่อใช้ `--auto` และไม่มีบัญชีที่เข้าสู่ระบบแล้ว: `no logged-in account to pick` เมื่อทุกบัญชีเต็มหรือไม่ทราบการใช้งาน: `` no account with known usage and headroom (see `ccam usage`) `` ทั้งสองกรณีจบด้วยรหัสออก 75
- `--max-usage`, `--strategy`, `--wait` และ `--cross-org` ใช้ได้เฉพาะกับ `--auto` และค่าที่อยู่นอกช่วง 1-100 หรือกลยุทธ์อื่นจะถูกปฏิเสธ
- fork คัดลอกการสนทนา ไม่ได้คัดลอกสถานะอื่นของบัญชี: checkpoint ใน `file-history/` ของบัญชีเดิมจะไม่ตามมาด้วย เว้นแต่จะใช้ประวัติร่วมกัน
- `--auto` ส่งคำขอผ่านเครือข่ายแม้จะใส่ `--dry-run` โดยจะอ่านเท่านั้น และไม่เคยเขียนไฟล์โทเค็น
- บัญชีที่เลือกจะเริ่มผ่านเส้นทางเดียวกับ `ccam <name>` จึงผ่านการตรวจแบบเดียวกัน รวมถึงคำเตือนเมื่อมี Claude Code อีกตัวที่ใช้ประวัติเดียวกันกำลังทำงานอยู่ในโฟลเดอร์นี้
- `last-used` จะถูกเขียนเฉพาะเมื่อ Claude Code เริ่มทำงานจริง `--dry-run` จะไม่แตะไฟล์นี้ การทดลองรันจึงไม่ทำให้การหมุนเวียนเลื่อนไปข้างหน้า
- `--fallback` กักเอาต์พุตมาตรฐานไว้จนกว่าการลองแต่ละครั้งจะจบ เอาต์พุตแบบสตรีมอย่าง `--output-format stream-json` จึงมาถึงทีเดียวตอนท้าย ไฟล์ที่การลองครั้งแรกแก้ไขไปก่อนถึงขีดจำกัดจะยังคงถูกแก้ไขอยู่ การลองครั้งถัดไปจะเริ่มพรอมต์ใหม่ตั้งแต่ต้น
