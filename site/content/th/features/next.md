`ccam next` เปิด Claude Code ด้วยบัญชีอื่นโดยที่คุณไม่ต้องระบุชื่อ ใช้เมื่อบัญชีถึงขีดจำกัดการใช้งาน: `ccam next` แบบธรรมดาจะเลือกบัญชีถัดจากบัญชีที่คุณใช้ล่าสุด `--auto` จะเลือกบัญชีที่เหลือโควตามากที่สุด และ `--continue` จะพาการสนทนาล่าสุดของโฟลเดอร์นี้ไปยังบัญชีใหม่ ไม่ว่าทั้งสองบัญชีจะใช้ประวัติร่วมกันหรือไม่ ภายใน Claude Code [ปลั๊กอิน ccam](#inside-claude-code) จะบอกคุณเมื่อขีดจำกัดทำให้เซสชันหยุด และ `/ccam:switch` จะส่งต่อการสนทนาไป สำหรับสคริปต์ที่รัน `claude -p` นั้น `ccam --fallback` จะสลับบัญชีให้เอง (ดู [รันอีกครั้งเมื่อถึงขีดจำกัด](#run-again-at-the-limit))

**ที่นั่ง (seat) ของ Team และ Enterprise** การเลือกอัตโนมัติ (`ccam next`, `--fallback`, `ccam pick` และปุ่ม `n` ในแดชบอร์ด) จะสลับระหว่างที่นั่งต่าง ๆ ในองค์กร Claude Team หรือ Enterprise เดียวกันด้วย ศูนย์ช่วยเหลือของ Anthropic ระบุว่า "Each seat on a Team plan is assigned to one named individual, and only that person may use it" (แต่ละที่นั่งในแพ็กเกจ Team จะกำหนดให้กับบุคคลที่ระบุชื่อเพียงคนเดียว และมีเพียงบุคคลนั้นที่ใช้ได้) และ "Users can't route their work through another user's account to use that user's remaining usage" (ผู้ใช้ไม่สามารถส่งงานของตนผ่านบัญชีของผู้ใช้คนอื่นเพื่อใช้ปริมาณการใช้งานที่เหลืออยู่ของผู้ใช้คนนั้นได้) ([แพ็กเกจ Team](https://support.claude.com/en/articles/12004354-purchase-and-manage-seats-on-team-plans#h_b8a7d07129) ส่วน [แพ็กเกจ Enterprise](https://support.claude.com/en/articles/13393991-purchase-and-manage-seats-on-enterprise-plans#h_fa6b9cade0) ก็เช่นเดียวกัน) ดังนั้น การใช้การเลือกอัตโนมัติระหว่างที่นั่งต่าง ๆ จึงอาจละเมิดข้อกำหนดของ Anthropic โปรดสอบถามองค์กรของคุณและ Anthropic ก่อนที่จะพึ่งพาการเลือกอัตโนมัติ สำหรับแพ็กเกจส่วนตัว (Pro, Max) ดูที่ [หมายเหตุเรื่องข้อกำหนดในคำถามที่พบบ่อย](/docs/faq#am-i-allowed-to-use-several-claude-code-accounts)

## การใช้งาน

```sh
ccam next                       # the account after the one you used last
ccam next --auto                # the account with the most room
ccam next --continue            # carry this folder's last conversation on as the next account
ccam next -c --auto             # both: the conversation, on the account with the most room
ccam next --auto --max-usage 80 # prefer accounts below 80%
ccam next --auto --strategy balance   # the weekly quota that would go unused first
ccam next --auto --cross-org    # also accounts of other organizations
ccam next --auto --wait         # nobody has room: wait for the first reset (up to 5 hours)
ccam next -c --auto -- --dangerously-skip-permissions   # claude's own options go after --
ccam --dry-run next --auto      # print the choice and the command, start nothing
```

```console
$ ccam --dry-run next --auto --continue
→ personal → work (12% of its 5 hours used, the least)
  continuing "Fix the flaky tests" (about 182k tokens); work does not share personal's history, so Claude Code copies it into work
CLAUDE_CONFIG_DIR=/home/you/.local/share/ccam/profiles/work CCAM_PROFILE=work /usr/local/bin/claude --resume /home/you/.local/share/ccam/profiles/personal/projects/-home-you-code-app/4f1c….jsonl --fork-session
```

ccam พิมพ์การสลับเป็น `→ <from> → <to>` ทาง standard error พร้อมเหตุผลของการเลือกด้วย `--auto` จากนั้นเริ่ม Claude Code ด้วยบัญชีใหม่แบบเดียวกับ `ccam <name>` `<from>` คือบัญชีที่คุณใช้ล่าสุด หรือเมื่อใช้ `--continue` คือบัญชีที่เป็นเจ้าของการสนทนานั้น อาร์กิวเมนต์หลัง `--` จะส่งต่อให้ `claude` โดยไม่เปลี่ยนแปลง

## ตัวเลือก

| ตัวเลือก | สิ่งที่ทำ | ค่าเริ่มต้น |
| --- | --- | --- |
| `--auto` | เลือกบัญชีที่เข้าสู่ระบบแล้วตามการใช้งาน (ดูด้านล่าง) โดยข้ามบัญชีที่ใช้ไปถึง 100% | ปิด |
| `--max-usage <1-100>` | ใช้กับ `--auto`: เลือกบัญชีที่ใช้งานต่ำกว่าค่านี้ก่อน | `auto_max_usage` หากไม่มีคือ 100 |
| `--strategy headroom\|expiring\|balance` | ใช้กับ `--auto`: การใช้งาน 5 ชั่วโมงต่ำที่สุด ช่วง 5 ชั่วโมงที่จะรีเซ็ตเร็วที่สุด หรือโควตารายสัปดาห์ที่จะถูกปล่อยทิ้งโดยไม่ได้ใช้ก่อน | `auto_strategy` หากไม่มีคือ `headroom` |
| `--cross-org` | ใช้กับ `--auto`: เลือกบัญชีขององค์กรอื่นด้วย (ดูด้านล่าง) | `cross_org` หากไม่มีคือปิด |
| `--wait[=<duration>]` | ใช้กับ `--auto`: เมื่อไม่มีบัญชีใดเหลือโควตา ให้รอบัญชีแรกที่รีเซ็ต นานไม่เกินค่านี้ ค่าต้องอยู่หลัง `=`: `--wait 2h` จะถูกปฏิเสธพร้อมคำแนะนำ `--wait takes its value after '=': --wait=2h` | ปิด; `5h` เมื่อระบุโดยไม่มีค่า |
| `-c`, `--continue` | พาการสนทนาล่าสุดของโฟลเดอร์นี้ไปต่อด้วยบัญชีใหม่ (ดูด้านล่าง) | ปิด |
| `-- <claude args>` | อาร์กิวเมนต์ที่ส่งให้ `claude` ต่อจากอาร์กิวเมนต์ของ ccam เอง | ไม่มี |
| `--dry-run` | รองรับ: พิมพ์ `→ <from> → <to>` และบรรทัดคำสั่งที่จะรัน โดยไม่เริ่ม Claude Code และไม่บันทึกการเริ่ม | ปิด |

`--auto` และ `--continue` ใช้ร่วมกันได้ เมื่อใช้ `--continue` อาร์กิวเมนต์ `--resume` จะถูกวางไว้ก่อนอาร์กิวเมนต์ของคุณ

ตัวเลือกของ Claude Code เอง เช่น `--dangerously-skip-permissions` หรือ `--model` ต้องวางไว้หลัง `--` ต่างจาก `ccam <name>` ที่ส่งต่อทุกอย่างหลังชื่อไปให้ `ccam next` อ่านอาร์กิวเมนต์เอง ดังนั้นหากไม่มี `--` จะหยุดพร้อมข้อความ `ccam: unknown flag: --dangerously-skip-permissions`

## วิธีการทำงาน

การเริ่มทุกครั้งผ่าน ccam จะเขียนเวลาลงใน `~/.local/state/ccam/last-used/<name>` `ccam next` อ่านไฟล์เหล่านี้ ตรวจว่าบัญชีใดเข้าสู่ระบบแล้ว แล้วจึงเลือก

1. `cli.candidates` สร้าง `next.Candidate` หนึ่งรายการต่อบัญชีจาก `config.toml`: ได้แก่ บัญชี เวลาที่เริ่มครั้งล่าสุด (`launcher.LastUsed`) และบัญชีนั้นมีการเข้าสู่ระบบที่ใช้งานได้หรือไม่ (`creds.Has`: การเข้าสู่ระบบ Claude ใน `.credentials.json` หรือบน macOS ในพวงกุญแจ (Keychain) ที่ยังไม่หมดอายุทั้งหมดและไม่ถูก Claude Code ล้างไป) โฟลเดอร์ที่ใช้ API key แทน (การเข้าสู่ระบบ Console หรือบัญชีที่เพิ่มด้วย `ccam add --api`) ไม่มีขีดจำกัดของแพ็กเกจและจะไม่ถูกเลือกเลย
2. หากไม่ใส่ `--auto` `next.Rotate` จะเรียงบัญชีตามหมายเลขสล็อตและหาบัญชีที่เริ่มล่าสุด ซึ่งคือบัญชีที่คุณกำลังสลับออก หากยังไม่มีบัญชีใดถูกเริ่มเลย จะใช้สล็อตต่ำสุด
3. จากตรงนั้นจะไล่ไปข้างหน้าตามลำดับสล็อต วนจากสล็อตสุดท้ายกลับไปสล็อตแรก และคืนบัญชีแรกที่เข้าสู่ระบบแล้ว
4. `launcher.LaunchWith` เตรียมและเริ่มบัญชีที่เลือกเหมือนกับที่ `ccam <name>` ทำทุกประการ: ตรวจลิงก์ของบัญชี ใช้การตั้งค่า MCP ที่ใช้ร่วมกัน ลงทะเบียนเซสชัน และแทนที่ ccam ด้วย `claude` ผ่าน `syscall.Exec`

การไล่เริ่มที่บัญชีที่ใช้ล่าสุด และหยุดที่บัญชีแรกที่เข้าสู่ระบบแล้วซึ่งอยู่ถัดไป:

<!-- motion:next-rotate -->

`work` ถูกเริ่มล่าสุด การไล่จึงเริ่มต่อจากบัญชีนี้ `side` ไม่มีการเข้าสู่ระบบจึงถูกข้าม และเลือก `lab` หาก `lab` ออกจากระบบไปแล้วด้วย การไล่จะวนกลับไปที่ `personal` (`% len` ในแผนภาพ) การหมุนเวียนไม่มีทางคืนบัญชีที่คุณเริ่มต้นมา: หากไม่มีบัญชีอื่นที่เข้าสู่ระบบแล้ว จะหยุดพร้อมข้อผิดพลาด

### --auto

`--auto` ตัดสินจากการใช้งานแทนลำดับสล็อต `cli.pickAuto` เก็บบัญชีที่เข้าสู่ระบบแล้วไว้ สอบถามการใช้งานของทุกบัญชีพร้อมกันด้วย `Fetcher.FetchAll` ตัวเดียวกับที่ `ccam usage` ใช้ และให้ `usage.Policy.Choose()` เป็นผู้เลือก:

<!-- motion:next-auto -->

บัญชีจะถูกตัดสินจากช่วง 5 ชั่วโมงและรายสัปดาห์ และเมื่อมี `--model` อยู่ในอาร์กิวเมนต์สำหรับ Claude Code (หลัง `--`) ก็จะดูช่วงรายสัปดาห์ของโมเดลนั้นด้วย (`opus`, `sonnet`, `haiku` หรือ `fable` ในชื่อ) `Policy.Choose()` แบ่งบัญชีออกเป็นสามกลุ่ม:

1. **มีโควตาเหลือ**: ทุกช่วงต่ำกว่า `auto_max_usage` (`config.toml` ค่าเริ่มต้น 100) กลยุทธ์จะเลือกจากกลุ่มนี้: `headroom` (ค่าเริ่มต้น) เลือกบัญชีที่ใช้งาน 5 ชั่วโมงต่ำที่สุด `expiring` เลือกช่วง 5 ชั่วโมงที่จะรีเซ็ตเร็วที่สุด เพื่อให้ใช้โควตาที่เหลือก่อนที่จะหายไป ส่วน `balance` เลือกบัญชีที่เหลือโควตารายสัปดาห์ต่อวันมากที่สุดจนกว่าสัปดาห์ของบัญชีนั้นจะรีเซ็ต โดยนับเซสชัน ccam ที่กำลังทำงานแต่ละเซสชันหักออกจากบัญชีนั้นด้วย โควตารายสัปดาห์จึงไม่ถูกปล่อยทิ้ง และเซสชันที่ทำงานขนานกันจะกระจายออกไป
2. **เกิน**: ต่ำกว่า 100% แต่เท่ากับหรือเกิน `auto_max_usage` ใช้เฉพาะเมื่อไม่มีบัญชีใดมีโควตาเหลือ โดยเลือกบัญชีที่ใช้งาน 5 ชั่วโมงต่ำที่สุดก่อน
3. **เต็ม**: มีช่วงใดช่วงหนึ่งอยู่ที่ 100% หรือไม่ทราบการใช้งาน 5 ชั่วโมง ไม่ถูกเลือกเด็ดขาด

ช่วงหนึ่งจะนับเป็น 100% จนกว่าจะรีเซ็ต เมื่อ Claude Code ปฏิเสธคำขอในช่วงนั้น: hook ของ[ปลั๊กอิน ccam](#inside-claude-code)จะบันทึกไว้ (`~/.local/state/ccam/usage/<name>.limit.json`) ไม่ว่าตัวเลขที่บันทึกไว้จะเป็นเท่าใด ดังนั้นบัญชีที่เพิ่งถึงขีดจำกัดจะไม่ถูกเลือกอีกก่อนรีเซ็ต แม้ตัวเลขของบัญชีจะเก่าแล้วก็ตาม

การตั้งค่าสำหรับทุกบัญชีต้องอยู่ที่ด้านบนสุดของ `config.toml` เหนือ `[[group]]`, `[[profile]]` หรือ `[[folder]]` ตัวแรก การตั้งค่าที่อยู่ใต้ตารางใดตารางหนึ่งจะเป็นของตารางนั้น: ccam จะระบุถึงการตั้งค่านั้นทุกครั้งที่เริ่ม และคำสั่งที่บันทึกการตั้งค่าจะปฏิเสธจนกว่าจะย้ายมันขึ้นไป

```toml
# ~/.config/ccam/config.toml
auto_max_usage = 80        # keep 20% of each account for interactive work
auto_strategy = "expiring"
```

**องค์กร** การเลือกอัตโนมัติจะอยู่กับบัญชีที่เหมือนกับบัญชีที่คุณออกมา: องค์กรแบบ Team หรือ Enterprise เดียวกัน หรือแพ็กเกจส่วนตัว (Pro, Max) ด้วยกัน งานจากบัญชีบริษัทจึงไม่ไปทำต่อในบัญชีส่วนตัว และในทางกลับกันก็เช่นกัน ccam รู้องค์กรของแต่ละบัญชีจากการเข้าสู่ระบบ (`ccam login` บันทึกไว้ ส่วนการเข้าสู่ระบบรุ่นเก่าจะอ่านจาก `.claude.json`) บัญชีที่ ccam บอกองค์กรไม่ได้จะถือว่าเข้ากับองค์กรใดก็ได้ โฟลเดอร์สองโฟลเดอร์ที่เข้าสู่ระบบด้วยบัญชี Claude เดียวกันใช้ขีดจำกัดร่วมกัน จึงไม่มีโฟลเดอร์ใดรับช่วงต่อจากอีกโฟลเดอร์หนึ่ง `--cross-org` หรือ `cross_org = true` ใน `config.toml` จะยกเลิกกฎเรื่ององค์กรนี้

เมื่อเลือกบัญชีใดไม่ได้ ccam จะออกด้วยรหัส 75 (`EX_TEMPFAIL`) เพื่อให้สคริปต์แยก "ลองใหม่ภายหลัง" ออกจากความล้มเหลวได้ เมื่อใช้ `--wait` ccam จะพักรอจนกว่าช่วงที่ปิดกั้นของบัญชีที่เต็มบัญชีแรกจะรีเซ็ต (30 วินาทีหลังเวลารีเซ็ต ซึ่งเป็นตอนที่ endpoint แสดงช่วงใหม่) พิมพ์ `ccam: no account has room; waiting until 15:10` แล้วเลือกใหม่อีกครั้ง หากไม่มีบัญชีใดบอกเวลารีเซ็ต จะกลับมาดูอีกครั้งหลัง 10 นาที หากไม่มีบัญชีใดว่างก่อนหมดเวลารอ จะออกด้วยรหัส 75 การสอบถามทำตามกฎของ `ccam usage`: ตัวเลขที่ดึงมาเมื่อไม่ถึง 60 วินาทีที่แล้วจะถูกนำกลับมาใช้ แต่ละบัญชีมีเวลา 3 วินาที บัญชีที่ไม่ตอบกลับหรือโทเค็นการเข้าถึงหมดอายุแล้วจะถูกตัดสินจากตัวเลขที่บันทึกไว้ และบันทึกขีดจำกัดจะทับตัวเลขเหล่านั้น ช่วงเวลาที่บันทึกไว้ซึ่งเลยเวลารีเซ็ตไปแล้วจะนับเป็น 0% บัญชีที่ช่วงเวลารีเซ็ตไปแล้วจึงไม่ถูกมองข้าม `--auto` ไม่เคยต่ออายุโทเค็น ต่างจากการหมุนเวียนแบบธรรมดา `--auto` อาจเลือกบัญชีที่คุณใช้ล่าสุดได้หากบัญชีนั้นยังเหลือโควตามากที่สุด

### --continue

1. ccam ค้นหาการสนทนาล่าสุดของโฟลเดอร์นี้ในทุกบัญชี: จากไฟล์ `<session>.jsonl` ใน `projects/<folder>/` (ชื่อโฟลเดอร์คือโฟลเดอร์ที่ทำงานอยู่หลังแปลงลิงก์เป็นพาธจริงแล้ว โดยเปลี่ยนทุกอักขระที่ไม่ใช่ตัวอักษรหรือตัวเลขเป็น `-` ตามที่ Claude Code ตั้งชื่อ) จะเลือกไฟล์ที่มีพรอมต์หรือคำตอบล่าสุด เซสชันที่ไม่มีทั้งสองอย่าง เช่น เซสชันที่รันเพียง `/mcp`, `/usage` หรือ `/status` หรือไฟล์ว่าง จะถูกข้าม หากเซสชันทิ้งบันทึกไว้ (จากขีดจำกัดการใช้งานหรือ `/ccam:switch` ดูด้านล่าง) และไม่มีการสนทนาใดที่มีพรอมต์หรือคำตอบหลังจากบันทึกนั้นเกิน 2 นาที จะใช้เซสชันนั้นแทน แถวที่ Claude Code เขียนตอน `/exit` ไม่นับ
2. บัญชีที่เป็นเจ้าของการสนทนาคือบัญชีที่คุณสลับออก และบัญชีใหม่จะถูกเลือกตามข้างต้นภายในองค์กรเดียวกัน เมื่อหลายบัญชีใช้ประวัตินั้นร่วมกัน การสนทนาจะเป็นของบัญชีที่ `.claude.json` ระบุว่ารันการสนทนานั้นล่าสุด (`lastSessionId`) มิฉะนั้นจะเป็นของบัญชีที่ใช้ล่าสุด
3. หากบัญชีใหม่ใช้ประวัตินั้นร่วมกัน (โฟลเดอร์กลุ่มเดียวกัน) ccam จะเริ่ม `claude --resume <session id>` ซึ่งก็คือการสนทนานั้นเอง (`--continue` จะเปิดการสนทนาที่ใหม่ที่สุดในโฟลเดอร์ ไม่ว่าจะเป็นการสนทนาใด)
4. หากไม่ได้ใช้ร่วมกัน ccam จะเริ่ม `claude --resume <the conversation's file> --fork-session`: Claude Code จะคัดลอกการสนทนาทั้งหมดภายใต้ session id ใหม่ไปยังประวัติของบัญชีใหม่เอง และต้นฉบับจะยังคงเหมือนเดิม จากนั้น `--continue` ของบัญชีใหม่จะพบการสนทนานั้น

ccam จะบอกว่าการสนทนามีขนาดเท่าไร: บัญชีใหม่จะอ่านการสนทนาทั้งหมดอีกครั้งในคำตอบแรก prompt cache ไม่เคยใช้ร่วมกันระหว่างองค์กร และแพ็กเกจส่วนตัวแต่ละแพ็กเกจก็เป็นองค์กรของตัวเอง ดังนั้นเมื่อสองบัญชีอยู่ต่างองค์กรกัน ccam จะเพิ่มข้อความ `prompt caches are not shared between organizations, so the first reply reads it all again` เมื่อบัญชีเดิมลงชื่อเข้าใช้เซิร์ฟเวอร์ MCP ที่บัญชีใหม่ยังไม่ได้ลงชื่อเข้าใช้ ccam จะระบุชื่อเซิร์ฟเวอร์เหล่านั้น: `work is not signed in to MCP servers personal is: linear (sign in with /mcp there; sign-ins are not shared)` การใช้ `history` ร่วมกันในกลุ่มช่วยเลี่ยงการคัดลอก ทำให้เป็นการสนทนาเดียว และยังใช้ checkpoint ที่ `/rewind` ใช้กู้คืนโค้ดร่วมกันด้วย (`file-history/`)

## ภายใน Claude Code

[ปลั๊กอิน ccam](/docs/install#claude-code-plugin) เพิ่ม hook สองตัว (Claude Code 2.1.78 ขึ้นไป):

- เมื่อเทิร์นหนึ่งหยุดเพราะถึงขีดจำกัดการใช้งาน hook จะจดการสนทนาไว้และแสดงการแจ้งเตือนบนเดสก์ท็อปในเทอร์มินัลที่รองรับ (iTerm2, WezTerm, Windows Terminal, kitty, Ghostty): ``ccam: work hit its 5-hour limit (resets 3:45pm). `ccam next --continue` carries on as another account.`` hook รู้จักทุกข้อความที่ Claude Code นับว่าเป็นขีดจำกัดการใช้งาน: ขีดจำกัด 5 ชั่วโมง รายสัปดาห์ แบบทั่วไป และของโมเดล (`You've hit your session limit`, `You've hit your limit`, `You've reached your …` สำหรับโควตาของโมเดล) เครดิตการใช้งานและขีดจำกัดการใช้จ่าย และองค์กรที่หยุดบัญชีไว้ เมื่อ Claude Code เขียนคำขอที่ถูกปฏิเสธลงในการสนทนาแล้ว hook จะบันทึกช่วงที่เต็มไว้จนกว่าจะรีเซ็ตด้วย ([บันทึกขีดจำกัด](/features/usage#the-limit-record)) ยกเว้นการหยุดโดยองค์กร ซึ่งผู้ดูแลยกเลิกได้ทุกเมื่อ การจำกัดความเร็วสั้น ๆ ของเซิร์ฟเวอร์หรือ rate limit ของ API key ไม่ใช่ขีดจำกัดการใช้งานและจะไม่ถูกแตะต้อง เช่นเดียวกับการหยุดของ subagent และเซสชันที่ไม่มีใครนั่งอยู่ (`-p`, เซสชันเบื้องหลัง) Claude Code 2.1.234 ขึ้นไปยังรออยู่ในเซสชันและทำต่อเองหลังช่วง 5 ชั่วโมงรีเซ็ตด้วย การแจ้งเตือนจึงให้คุณเลือกสลับบัญชีแทนได้
- `/ccam:switch [account]` จะจดการสนทนาไว้และจบเทิร์นก่อนที่จะมีคำขอใด ๆ: พิมพ์ `/exit` จากนั้น `ccam next --continue` จะพาการสนทนาไปต่อด้วยบัญชีที่คุณระบุ หรือบัญชีถัดไป ในเซสชันที่ยังไม่มีการสนทนา คำสั่งนี้จะแจ้งว่าไม่มีอะไรให้พาไปต่อ

บันทึกนี้อยู่ใน `~/.local/state/ccam/handoff/<account>/<session>.json` หนึ่งไฟล์ต่อเซสชัน สองเซสชันของบัญชีเดียวกันจึงไม่เขียนทับบันทึกของกันและกัน บันทึกจะถูกเก็บไว้ 12 ชั่วโมงและถูกใช้เพียงครั้งเดียวเมื่อเซสชันถัดไปกำลังจะเริ่ม หากการเริ่มล้มเหลว บันทึกจะยังอยู่ให้ลองครั้งถัดไป บันทึกเป็นของโฟลเดอร์ที่เซสชันเริ่มต้น แม้จะ `cd` ไปที่อื่นในเชลล์ของ Claude Code แล้วก็ตาม `ccam rename` จะอัปเดตชื่อในบันทึก หากบัญชีที่บันทึกระบุไว้ถูกลบไปแล้ว ccam จะแจ้งเรื่องนี้และเลือกบัญชีตามปกติ

### การส่งต่อ (relay)

เมื่อตั้ง `relay = true` ที่ด้านบนสุดของ `config.toml` ccam จะอยู่ข้างเซสชันแบบโต้ตอบแทนการแทนที่ตัวเองด้วย Claude Code และหลัง `/ccam:switch` ccam จะพาการสนทนาของเซสชันนั้นไปต่อเอง (บันทึกที่เซสชันอื่นทิ้งไว้จะไม่ถูกนำมาใช้): hook จะจบ Claude Code แล้ว ccam จะรัน `ccam next --continue` พร้อมบันทึกของเซสชันนั้น หากไม่ได้ระบุบัญชี จะเลือกบัญชีที่เหลือโควตามากที่สุด โดยนับโมเดลของการสนทนาด้วย บน Windows hook จบ Claude Code ไม่ได้: ให้พิมพ์ `/exit` แล้ว ccam จะทำต่อ วิธีนี้ต้องมีโปรเซส ccam ที่รออยู่หนึ่งโปรเซสต่อเซสชัน จึงปิดไว้เป็นค่าเริ่มต้น

เซสชันที่ถูกส่งต่อจะคงสิ่งที่การเปิดการสนทนาต่อไม่ได้คืนให้: ตัวเลือกอย่าง `--add-dir`, `--mcp-config` รายการเครื่องมือ `--settings`, `--plugin-dir` และตัวเลือกของ system prompt รวมถึงโหมดสิทธิ์ของการสนทนาและระดับ effort ของเซสชัน Claude Code เองจะคืน `--model`, `--name` และ `--agent` จากการสนทนา ส่วนอย่างอื่น (`--worktree`, `--debug`, `--remote-control` และตัวเลือกที่ ccam ไม่รู้จัก) จะถูกระบุใน `ccam: not carried over: …` การสลับจะไม่ถามคำถามเรื่องประวัติที่ใช้ร่วมกัน และสิ่งที่คุณพิมพ์ระหว่างที่การสลับทำงานจะถูกทิ้ง

การส่งต่อจะทำต่อเฉพาะเมื่อ Claude Code จบลงตามที่ `/ccam:switch` ขอไว้: ไม่ทำเมื่อคุณพิมพ์ `/exit` ก่อน กด Ctrl+C ระหว่างที่กำลังจบ หรือ ccam ได้รับสัญญาณ hangup หรือสัญญาณอื่น และไม่ทำเมื่อเทอร์มินัลหายไปแล้ว บันทึกจะยังอยู่ และ `ccam next --continue` จะพาการสนทนาไปต่อภายหลังได้ เซสชันที่เริ่มภายใต้การส่งต่อของ ccam รุ่นเก่า หรือเซสชันที่ไม่มีใครนั่งอยู่ (`-p`, เซสชันเบื้องหลัง) จะไม่ถูก hook จบ แต่จะได้รับข้อความให้ `/exit` แทน `claude remote-control` ทำงานโดยไม่มีการส่งต่อ

## รันอีกครั้งเมื่อถึงขีดจำกัด

`ccam next` ใช้สำหรับเซสชันแบบโต้ตอบที่หยุดไปแล้ว การรันแบบไม่โต้ตอบ เช่น `claude -p` ในสคริปต์หรืองานตามกำหนดเวลา รอคุณไม่ได้ การใส่ `--fallback` ไว้หน้าชื่อบัญชีจึงให้ ccam สลับบัญชีแทนให้:

```sh
ccam --fallback work -p "fix the failing tests" --output-format json
ccam --fallback -p "summarise" < notes.txt      # the folder's account or the default
ccam run --fallback work -p "review the diff"
```

```console
$ ccam --fallback personal -p "summarise" < notes.txt
ccam: personal reached its usage limit; running the command again as work
Summary: …
```

1. `--fallback` ใช้ได้เฉพาะร่วมกับ `-p` หรือ `--print` เท่านั้น มิฉะนั้น ccam จะหยุดและแนะนำ `ccam next --auto --continue` แทน
2. อินพุตมาตรฐานที่ส่งผ่านไปป์จะถูกอ่านครั้งเดียว ไม่เกิน 10 MiB และส่งให้ทุกครั้งที่ลอง เช่นเดียวกับ Claude Code ccam จะรอให้อินพุตเริ่มเข้ามาไม่เกิน 3 วินาที (ยกเว้นเมื่อใช้ `--input-format stream-json`) ไปป์ที่เปิดค้างไว้โดยไม่ส่งอะไรมาจะทำให้การรันไม่มีอินพุต พร้อมข้อความหนึ่งบรรทัดทาง standard error
3. ccam เริ่ม `claude` เป็นโปรเซสลูกแทนการใช้ `exec` กักเอาต์พุตมาตรฐานไว้ก่อน และส่ง standard error ผ่านออกไปทันทีที่ได้รับ
4. เมื่อ `claude` ออกด้วยรหัส 0 หรือล้มเหลวด้วยสาเหตุอื่น เอาต์พุตที่กักไว้และรหัสออกจะถูกส่งต่อโดยไม่เปลี่ยนแปลง การรันที่จบเพราะสัญญาณ (รหัสออกเกิน 128) ก็เช่นกัน: การรันนั้นถูกขอให้หยุด และจะไม่ถูกรันอีก
5. ความล้มเหลวจะนับว่าเป็นขีดจำกัดการใช้งานเมื่อข้อความของ Claude Code ระบุเช่นนั้น ซึ่งคือข้อความขีดจำกัดการใช้งานใดก็ได้ที่ [hook](#inside-claude-code) รู้จัก รวมถึงภายในเอาต์พุต `--output-format json` หรือ `stream-json` หรือเมื่อการใช้งานของบัญชีแสดงว่าช่วง 5 ชั่วโมง รายสัปดาห์ หรือของ `--model` อยู่ที่ 100% (รวมถึงบันทึกขีดจำกัด)
6. จากนั้นเอาต์พุตของการลองครั้งนั้นจะถูกทิ้ง และคำสั่งเดิมจะรันด้วยบัญชีอื่นที่เข้าสู่ระบบอยู่: บัญชีที่ใช้งาน 5 ชั่วโมงน้อยที่สุด ตามด้วยบัญชีที่ดูการใช้งานไม่ได้ เรียงตามหมายเลข บัญชีที่อยู่ที่ 100% จะถูกข้าม บัญชีที่เข้าสู่ระบบด้วย API key จะไม่ถูกลองเลย และแต่ละบัญชีจะถูกลองไม่เกินหนึ่งครั้ง
7. หากมี `-c`, `--continue`, `-r` หรือ `--resume` อยู่ในอาร์กิวเมนต์ จะลองเฉพาะบัญชีที่อยู่ในกลุ่มประวัติเดียวกัน เพื่อให้หาการสนทนาเจอ
8. จะลองเฉพาะบัญชีขององค์กรเดียวกัน เช่นเดียวกับ `--auto` (`cross_org = true` จะยกเลิกข้อนี้)

บัญชีถัดไปจะถูกเลือกด้วยกฎเดียวกับ `--auto` (`auto_max_usage`, `auto_strategy` และช่วงของ `--model`) เมื่อไม่มีบัญชีเหลือ ccam จะพิมพ์เอาต์พุตของการลองครั้งสุดท้าย แจ้งว่าไม่มีบัญชีที่เข้าสู่ระบบอยู่บัญชีใดเหลือโควตา และออกด้วยรหัส 75 เมื่อใส่ `--wait` ไว้ก่อนชื่อบัญชี (`ccam --fallback --wait=2h work -p …`) ccam จะรอให้บัญชีแรกรีเซ็ตแทน แล้วอาจลองทุกบัญชีอีกครั้ง โดยจะพักรออย่างน้อยหนึ่งครั้งก่อนเสมอ บัญชีที่เพิ่งถึงขีดจำกัดจึงไม่ถูกรันซ้ำทันที ระยะเวลานี้จำกัดการรอทั้งหมดของการรันรวมกัน ไม่ใช่แต่ละครั้ง หากเขียนโดยเว้นวรรค (`--wait 30m`) จะถูกปฏิเสธพร้อมคำแนะนำเดียวกับ `ccam next` ส่วน `--` ที่นำหน้าอาร์กิวเมนต์ของ Claude Code ใช้ได้เหมือนการเริ่มทุกแบบ (`ccam --fallback work -- -p …`) `ccam --dry-run --fallback work -p …` จะพิมพ์คำสั่งของการลองครั้งแรก

เซสชันแบบโต้ตอบจะไม่ถูกสลับเอง แต่เมื่อใช้ `ccam statusline install` แถบสถานะจะเพิ่ม `→ ccam next --auto --continue` เมื่อการใช้งาน 5 ชั่วโมงหรือรายสัปดาห์ถึง 90% ([ขีดจำกัดการใช้งาน](/features/usage))

## ความปลอดภัยและกรณีพิเศษ

- บัญชีที่ไม่มีการเข้าสู่ระบบจะไม่ถูกเลือกเลย หากไม่มีบัญชีอื่นที่เข้าสู่ระบบแล้ว `ccam next` แบบธรรมดาจะหยุดด้วย `no logged-in account other than <name>`
- เมื่อใช้ `--continue` และไม่มีการสนทนาในโฟลเดอร์: `no account has a conversation in <folder> to continue`
- เมื่อกฎเรื่ององค์กรทำให้ไม่เหลือบัญชีให้เลือก: `` no logged-in account to pick among <name>'s (<organization>); --cross-org also looks at the others ``
- เมื่อใช้ `--auto` และไม่มีบัญชีที่เข้าสู่ระบบแล้ว: `no logged-in account to pick` เมื่อทุกบัญชีเต็มหรือไม่ทราบการใช้งาน: `` no account with known usage and headroom (see `ccam usage`) `` ทั้งสองกรณีจบด้วยรหัสออก 75
- `--max-usage`, `--strategy`, `--wait` และ `--cross-org` ใช้ได้เฉพาะกับ `--auto` และค่าที่อยู่นอกช่วง 1-100 หรือกลยุทธ์อื่นจะถูกปฏิเสธ
- fork คัดลอกการสนทนา ไม่ได้คัดลอกสถานะอื่นของบัญชี: checkpoint ใน `file-history/` ของบัญชีเดิมจะไม่ตามมาด้วย เว้นแต่จะใช้ประวัติร่วมกัน
- `--auto` ส่งคำขอผ่านเครือข่ายแม้จะใส่ `--dry-run` โดยจะอ่านเท่านั้น และไม่เคยเขียนไฟล์โทเค็น
- บัญชีที่เลือกจะเริ่มผ่านเส้นทางเดียวกับ `ccam <name>` จึงผ่านการตรวจแบบเดียวกัน รวมถึงคำเตือนเมื่อมี Claude Code อีกตัวที่ใช้ประวัติเดียวกันกำลังทำงานอยู่ในโฟลเดอร์นี้
- `last-used` จะถูกเขียนเฉพาะเมื่อ Claude Code เริ่มทำงานจริง `--dry-run` จะไม่แตะไฟล์นี้ การทดลองรันจึงไม่ทำให้การหมุนเวียนเลื่อนไปข้างหน้า
- `--fallback` กักเอาต์พุตมาตรฐานไว้จนกว่าการลองแต่ละครั้งจะจบ เอาต์พุตแบบสตรีมอย่าง `--output-format stream-json` จึงมาถึงทีเดียวตอนท้าย ไคลเอนต์ที่สตรีมอินพุต `stream-json` และรอคำตอบก่อนส่งเพิ่มจะใช้ `--fallback` ไม่ได้ ไฟล์ที่การลองครั้งแรกแก้ไขไปก่อนถึงขีดจำกัดจะยังคงถูกแก้ไขอยู่ การลองครั้งถัดไปจะเริ่มพรอมต์ใหม่ตั้งแต่ต้น
