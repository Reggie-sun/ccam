`ccam ext` ตอบคำถามว่า "ทำไม skill นี้ (หรือเซิร์ฟเวอร์ MCP นี้) ใช้ได้ในบัญชีหนึ่งแต่ใช้ไม่ได้ในอีกบัญชี?" โดยแสดงรายการส่วนขยายที่ Claude Code โหลดสำหรับทุกบัญชี และแหล่งที่มาของแต่ละรายการ: กลุ่มที่ใช้ร่วมกัน โฟลเดอร์ของบัญชีเอง หรือโปรเจกต์ที่คุณอยู่ ใต้ตารางจะแสดงสิ่งที่ทำให้ส่วนขยายโหลดไม่ได้อย่างที่คุณคาดไว้ คำสั่งนี้อ่านอย่างเดียว

## การใช้งาน

```sh
ccam ext              # every account
ccam ext work         # one account
ccam ext --json       # for scripts
```

```console
$ ccam ext
Skills
          personal   work
  half    account !  -
  review  -          default

Commands
          personal  work
  deploy  default   default

MCP servers
       personal   work
  ctx  default !  default

Hooks (commands per event)
              personal     work
  PreToolUse  1 (default)  1 (default)

This project (/home/me/code/app):
  commands: ship
  MCP servers: fs

Sources: a group name (shared), account (its own folder), local (its own, for this folder only), - (not loaded); (off): installed, not turned on.
! personal: MCP server ctx is defined differently in group default's mcp.json and .claude.json
! personal: half: no SKILL.md, so Claude Code does not load it
```

แต่ละช่องระบุแหล่งที่มาของรายการนั้นในบัญชีนั้น: กลุ่มที่ใช้ร่วมกัน (`default`) `account` เมื่อรายการอยู่ในโฟลเดอร์ของบัญชีเอง `local` สำหรับเซิร์ฟเวอร์ MCP ที่บัญชีมีไว้สำหรับโฟลเดอร์นี้เท่านั้น หรือ `-` เมื่อบัญชีไม่มีรายการนั้น ปลั๊กอินที่ติดตั้งไว้แต่ไม่ได้เปิดใช้จะแสดง `(off)` ต่อจากแหล่งที่มา `!` ทำเครื่องหมายรายการที่มีปัญหา โดยมีคำอธิบายอยู่ใต้ตาราง ปัญหาที่ไม่ได้เป็นของบัญชีใด เช่น เซิร์ฟเวอร์ที่มีเฉพาะใน `claude` แบบปกติ จะอยู่ท้ายสุดโดยไม่มีชื่อบัญชี `ccam ext --json` พิมพ์รายงานเดียวกัน (`accounts` โปรเจกต์ และ `problems`) โดยมี `remote` บนเซิร์ฟเวอร์ MCP ที่ Claude Code เข้าถึงผ่านเครือข่าย เมื่อไม่มีบัญชีใดจะพิมพ์รายงานพร้อม `accounts: []`

## สิ่งที่อ่าน

| ประเภท | ตำแหน่ง | แหล่งที่แสดง |
| --- | --- | --- |
| Skill | แต่ละโฟลเดอร์ใน `skills/` ที่มี `SKILL.md` | กลุ่มที่ `skills/` ลิงก์ไป หรือ `account` |
| คำสั่ง, agent | ไฟล์ `.md` ใต้ `commands/` และ `agents/` โฟลเดอร์ย่อยแสดงเป็น `folder/name` | กลุ่ม หรือ `account` |
| ปลั๊กอิน | `plugins/installed_plugins.json` เปิดหรือปิดด้วย `enabledPlugins` ในการตั้งค่าของบัญชีและของโปรเจกต์ ปลั๊กอินที่ติดตั้งไว้สำหรับโปรเจกต์เดียวจะปรากฏเฉพาะในโปรเจกต์นั้น | กลุ่ม หรือ `account` และ `(off)` เมื่อไม่ได้เปิดใช้ |
| เซิร์ฟเวอร์ MCP | `mcp.json` ของกลุ่ม (เมื่อใช้ MCP ร่วมกัน) `.claude.json` ของบัญชี (เซิร์ฟเวอร์ของบัญชีเอง และเซิร์ฟเวอร์ที่มีไว้สำหรับโฟลเดอร์นี้เท่านั้น) และเซิร์ฟเวอร์ของปลั๊กอินของบัญชี ในรูป `plugin:<plugin>:<server>` | กลุ่ม `account` หรือ `local` |
| Hook | `hooks` ใน `settings.json` นับแยกตามเหตุการณ์ | กลุ่ม หรือ `account` |
| โปรเจกต์นี้ | `.claude/skills`, `.claude/commands`, `.claude/agents`, `.claude/settings.json`, `.claude/settings.local.json` และ `.mcp.json` ในโฟลเดอร์ปัจจุบัน | แสดงครั้งเดียว บัญชีที่ยังไม่ได้เชื่อถือโฟลเดอร์จะได้รับปัญหาสำหรับเซิร์ฟเวอร์ใน `.mcp.json` |

## ปัญหาที่รายงาน

- **ลิงก์เสีย**: ลิงก์ใน `skills/`, `commands/` หรือ `agents/` ที่เป้าหมายหายไปแล้ว หรือโฟลเดอร์ที่ใช้ร่วมกัน (`skills`, `commands`, `agents`, `plugins`) ที่ลิงก์ไปยังตำแหน่งที่ไม่มีอยู่ (ซ่อมด้วย `ccam doctor --fix` ซึ่งจะสร้างโฟลเดอร์กลุ่มที่หายไปขึ้นใหม่)
- **โฟลเดอร์ skill ที่ไม่มี `SKILL.md`**: Claude Code จะข้ามโฟลเดอร์นั้น
- **เซิร์ฟเวอร์ MCP ที่กำหนดไว้ต่างกันในสองที่**: `mcp.json` ของกลุ่มกับ `.claude.json` ของบัญชี หรือที่ใดที่หนึ่งในสองที่นั้นกับ `.mcp.json` ของโปรเจกต์ การตั้งค่าเหมือนกันในทั้งสองที่ (ซึ่ง `mcp_strategy = "sync"` เขียนไว้) ไม่ถือเป็นปัญหา ย้ายเซิร์ฟเวอร์ของบัญชีเข้าไปในกลุ่มด้วย `ccam mcp import <account> <server>`
- **`installed_plugins.json` ที่ไม่ใช่ JSON ที่ถูกต้อง** ปลั๊กอินที่ `enabledPlugins` ไม่ได้ระบุชื่อ และปลั๊กอินที่โฟลเดอร์หายไป
- **เซิร์ฟเวอร์ที่มีเพียงบัญชีเดียวโหลด**: เซิร์ฟเวอร์ที่อยู่เฉพาะใน `.claude.json` ของบัญชีนี้ ซึ่งบัญชีอื่นในกลุ่มไม่ได้โหลด และเซิร์ฟเวอร์ในขอบเขต local ของบัญชีสำหรับโฟลเดอร์นี้ (สิ่งที่ `claude mcp add` ทำหากไม่ใส่ `-s user`) แต่ละรายการจะมาพร้อมคำสั่ง `ccam mcp import` ที่ใช้แบ่งปันเซิร์ฟเวอร์นั้น เซิร์ฟเวอร์ใน `~/.claude.json` ของ `claude` แบบปกติที่ไม่มีบัญชีใดโหลดจะมาพร้อมคำสั่ง `ccam migrate --mcp`
- **เซิร์ฟเวอร์ของโปรเจกต์ที่รอการอนุมัติ**: บัญชียังไม่ได้เชื่อถือโฟลเดอร์ Claude Code จึงจะถามหนึ่งครั้ง และจนกว่าจะถึงตอนนั้น เซิร์ฟเวอร์ใน `.mcp.json` ของโปรเจกต์จะรออยู่ ปัญหาจะบอกว่าอนุมัติได้ที่ใด: `"enabledMcpjsonServers"` ใน `settings.json` ของบัญชีในกลุ่มการตั้งค่า หรือของบัญชีนี้ ความเชื่อถือที่ให้กับ worktree หลักของ git repository จะมีผลใน worktree อื่นของ repository นั้นด้วย
- **การลงชื่อเข้าใช้และ connector**: เซิร์ฟเวอร์ MCP ที่ต้องลงชื่อเข้าใช้ในบัญชีนี้ ขณะที่อีกบัญชีหนึ่งลงชื่อเข้าใช้แล้ว (การลงชื่อเข้าใช้มีผลกับบัญชีเดียวเท่านั้น ให้ลงชื่อเข้าใช้ด้วย `/mcp`) และ connector ของ claude.ai ที่บัญชีอื่นเคยใช้แต่บัญชีนี้ยังไม่เคยใช้

## ความปลอดภัยและกรณีพิเศษ

- `ccam ext` ไม่เปลี่ยนแปลงสิ่งใดและไม่ส่งคำขอผ่านเครือข่าย อ่านชื่อเซิร์ฟเวอร์และจำนวน hook เท่านั้น ไม่เคยอ่านค่าของ `env` หรือ header ในนิยาม MCP สำหรับการตรวจการลงชื่อเข้าใช้ จะอ่านชื่อการลงชื่อเข้าใช้ MCP ในการเข้าสู่ระบบของแต่ละบัญชี (บน macOS จากพวงกุญแจ (Keychain)) ไม่เคยอ่านโทเค็น และอ่านเฉพาะบัญชีที่โหลดเซิร์ฟเวอร์ซึ่งบัญชีอื่นโหลดด้วย
- คำสั่งนี้แสดงสิ่งที่อยู่บนดิสก์ เซิร์ฟเวอร์ที่ถูกบล็อกโดยการตั้งค่าที่มีการจัดการจะยังคงปรากฏอยู่ ส่วนปลั๊กอินที่ปิดในการตั้งค่าจะแสดง `(off)`
- รันในโฟลเดอร์โปรเจกต์เพื่อรวมโฟลเดอร์ `.claude` และ `.mcp.json` ของโปรเจกต์นั้นด้วย
