`ccam doctor` ตรวจสอบการติดตั้ง ccam ของคุณ ได้แก่ ไบนารีของ Claude Code โฟลเดอร์ การเข้าสู่ระบบ และลิงก์ที่ใช้ร่วมกันของทุกบัญชี เซิร์ฟเวอร์ MCP ที่ใช้ร่วมกัน endpoint การใช้งาน และคำสั่งลัดของคุณ `ccam doctor --fix` ซ่อมแซมส่วนที่ทำได้โดยไม่ทำให้ข้อมูลสูญหาย และย้ายไฟล์ที่จะถูกแทนที่ไปไว้ในโฟลเดอร์สำรองก่อน ให้รันคำสั่งนี้เมื่อ `ccam <name>` หยุดทำงานเพราะปัญหาลิงก์ที่ใช้ร่วมกัน หลังจากที่คุณกู้คืนไฟล์ด้วยตัวเอง หรือหลังจากอัปเดต Claude Code

## การใช้งาน

```sh
ccam doctor                  # check everything, change nothing
ccam doctor --fix            # check, then repair what is safe to repair
ccam --dry-run doctor --fix  # report only: what --fix would repair and set aside
```

บรรทัดแรกแสดงเครื่องหมายของทุกบัญชีพร้อมกัน คุณจึงเห็นว่าปัญหาอยู่ที่ใดก่อนจะอ่านส่วนอื่น ด้านล่างนั้น แต่ละบัญชีจะมีกล่องของตัวเอง ส่วนผลการตรวจที่ไม่ได้เป็นของบัญชีใด (Claude Code, ตัวแปรสภาพแวดล้อม, ปลั๊กอิน, เซิร์ฟเวอร์ MCP, คำสั่งลัด, กฎของโฟลเดอร์, กลุ่ม และการตั้งค่า) จะอยู่ในกล่อง `General` หัวกล่องแสดงเครื่องหมายที่ร้ายแรงที่สุดของบัญชีและจำนวนปัญหาที่มี แต่ละแถวในกล่องคือหนึ่งด้านที่ถูกตรวจ โดยเป็น `Folder`, `Login` และ `Share links` ตามลำดับนี้เสมอ แล้วตามด้วยด้านอื่น ๆ พร้อมเครื่องหมาย: `✔` ปกติ, `ℹ` ข้อมูล, `⚠` คำเตือน, `✘` ข้อผิดพลาด โฟลเดอร์ที่ไม่มีปัญหาใดจะแสดง `✔ Folder  OK`

```console

 │ ⚠ Login        .credentials.json permissions are 644 (should be 0600) →   │
 │                fixed                                                      │
 │ ✔              login valid (me@example.com, Claude Team · Acme)           │
 │ ✘ Share links  /home/me/.local/share/ccam/profiles/personal/settings.json │
 │                : set to shared but is a real file, not a link → fixed     │
 │ ℹ              settings.json differed from the group's copy, which it now │
 │                uses; this account's copy is in                            │
 │                /home/me/.local/share/ccam/profiles/personal/.ccam-        │

 │ ✔ Usage        usage lookup OK                                            │
 ╰───────────────────────────────────────────────────────────────────────────╯
```

บนเทอร์มินัล กล่องจะพอดีกับความกว้างของเทอร์มินัลและข้อความยาวจะถูกตัดขึ้นบรรทัดใหม่ โดยใช้สีของเทอร์มินัลเอง (`NO_COLOR` ปิดสี) กล่องจะไม่แคบกว่า 29 คอลัมน์ ดังนั้นบนเทอร์มินัลที่แคบจะไม่มีคำใดถูกตัดขาด เมื่อส่งออกไปยังไปป์หรือไฟล์ ผลลัพธ์จะไม่มีสีและไม่มีข้อความใดถูกตัดขึ้นบรรทัดใหม่หรือถูกตัดทอน `ccam doctor | grep settings.json` จึงพบบรรทัดทั้งบรรทัด และทุกกล่องจะกว้างเท่ากับบรรทัดที่ยาวที่สุด แท็บ Health ของแดชบอร์ดแสดงกล่องแบบเดียวกัน

## ตัวเลือก

| ตัวเลือก | สิ่งที่ทำ | ค่าเริ่มต้น |
| --- | --- | --- |
| `--fix` | ซ่อมแซมส่วนที่ซ่อมได้อย่างปลอดภัย (ไฟล์ที่เปลี่ยนจะถูกสำรองไว้) | ปิด |
| `--dry-run` (global) | รันการตรวจทุกรายการแต่ไม่ซ่อมสิ่งใด แม้จะใส่ `--fix` | ปิด |

`ccam doctor` ไม่รับอาร์กิวเมนต์ และรองรับ `--dry-run`: `ccam --dry-run doctor --fix` พิมพ์ผลการตรวจของ `ccam doctor` เพิ่มสิ่งที่ `--fix` จะแยกเก็บไว้ และไม่เปลี่ยนแปลงสิ่งใด:

```text
ℹ settings.json differs from the group's copy: --fix would use the group's, and move this account's copy to /home/me/.local/share/ccam/profiles/personal/.ccam-backup/20261023-212543/settings.json
```

รหัสออก (exit code) เป็น `1` เมื่อยังมีผลการตรวจ `✘` อย่างน้อยหนึ่งรายการที่ไม่ได้ซ่อม และเป็น `0` ในกรณีอื่น คำเตือนและข้อมูลไม่ทำให้การรันล้มเหลว เมื่อการรันล้มเหลวโดยไม่ได้ใส่ `--fix` ccam จะจบด้วยบรรทัดว่างและ `` `ccam doctor --fix` repairs what it can. `` การตั้งค่าที่โหลดไม่ได้ก็จะจบด้วย `1` และข้อผิดพลาด `ccam:` เช่นกัน

## วิธีการทำงาน

`internal/cli/doctor.go` โหลด `~/.config/ccam/config.toml` แล้วเรียก `doctor.Run` ใน `internal/doctor/doctor.go` ซึ่งรันการตรวจตามลำดับที่กำหนดไว้และส่งผลการตรวจกลับมา โดยแต่ละรายการระบุบัญชีที่เป็นเจ้าของและด้านที่ถูกตรวจ `tui.HealthReport` จัดผลการตรวจเหล่านั้นเป็นกล่อง `--fix` ถูกส่งต่อเป็น `Options.Fix` และตั้งเป็น false เมื่อเป็นการทดลองรัน (dry run)

<!-- motion:doctor-checks -->

ส่วนตรงกลางจะรันหนึ่งครั้งต่อบัญชี การตรวจแต่ละรายการและสิ่งที่ `--fix` ทำ:

1. **เวอร์ชันของ Claude Code** (`checkClaude`) หาไบนารี `claude` แบบเดียวกับที่ตัวเริ่มโปรแกรมทำ แล้วรัน `claude --version` ไบนารีที่หาไม่พบ `claude_bin` ที่ไม่ใช่ไฟล์ที่รันได้ หรือ `--version` ที่ล้มเหลวถือเป็นข้อผิดพลาด ไม่มีการซ่อม
2. **ข้อมูลเข้าสู่ระบบในตัวแปรสภาพแวดล้อม** (`checkAuthEnv`) เตือนเมื่อมีการตั้ง `CLAUDE_CODE_OAUTH_TOKEN`, `ANTHROPIC_API_KEY` หรือ `ANTHROPIC_AUTH_TOKEN` เพราะทุกบัญชีที่เริ่มจากเชลล์นั้นจะได้รับค่านี้ไปด้วย และ Claude Code จะใช้ค่านี้ก่อนการเข้าสู่ระบบของบัญชีเอง ไม่มีการซ่อม ให้ยกเลิกการตั้งค่าเอง
3. **โฟลเดอร์** (`checkProfile`) โฟลเดอร์บัญชีที่หายไปถือเป็นข้อผิดพลาดและยุติการตรวจของบัญชีนั้น สิทธิ์ที่มีบิตของ group หรือ other ตั้งอยู่ถือเป็นคำเตือน และ `--fix` จะรัน `chmod 0700` `~/.claude` ที่นำเข้าซึ่งมี `.claude.json` ของตัวเองอยู่ข้าง `~/.claude.json` ถือเป็นข้อมูล: `ccam main` และ `claude` แบบปกติจะเก็บรายละเอียดการเข้าสู่ระบบและเซิร์ฟเวอร์ MCP แยกกัน Windows ไม่มีบิตสิทธิ์ การตรวจนี้และการตรวจ `0600` ด้านล่างจึงถูกข้ามบน Windows โดยโฟลเดอร์ในโปรไฟล์ผู้ใช้ของคุณได้รับการปกป้องด้วยรายการควบคุมการเข้าถึง (access list) ของโฟลเดอร์นั้น
4. **ไฟล์เข้าสู่ระบบ** (`checkCredentials`) ตรวจ `.credentials.json` ด้วย `lstat` ลิงก์สัญลักษณ์ถือเป็นข้อผิดพลาด เพราะแต่ละบัญชีต้องมีโทเค็นของตัวเอง และจะไม่ถูกซ่อม โหมดที่ไม่ใช่ `0600` ถือเป็นคำเตือน และ `--fix` จะรัน `chmod 0600` จากนั้นจะอ่านการเข้าสู่ระบบ (บน macOS จะอ่านจากพวงกุญแจ (Keychain) ก่อน) หากไม่มีการเข้าสู่ระบบ หรือไฟล์เข้าสู่ระบบไม่มีการเข้าสู่ระบบอยู่ จะเป็นคำเตือนที่แนะนำ `ccam login <name>` refresh token ที่หมดอายุ หรือการเข้าสู่ระบบที่ Claude Code ล้างไปหลังจากเซิร์ฟเวอร์ปฏิเสธ คือข้อผิดพลาด `` login expired → `ccam login <name>` `` ส่วน access token ที่หมดอายุเป็นเพียงข้อมูล เพราะ Claude Code จะต่ออายุให้เมื่อเริ่มครั้งถัดไป การเข้าสู่ระบบที่เก็บไว้ใน Windows Credential Manager เป็นข้อมูล เพราะ ccam อ่านไม่ได้ การเข้าสู่ระบบที่ยังใช้ได้จะแสดงอีเมลที่โฟลเดอร์เข้าสู่ระบบอยู่ในตอนนี้และแพ็กเกจ (`login valid (dev@company.com, Claude Team · Acme)`) รายการเหล่านี้จะไม่ถูกซ่อม แต่ `ccam login --expired` จะเข้าสู่ระบบทุกบัญชีที่ต้องเข้าใหม่
5. **ลิงก์ที่ใช้ร่วมกัน** (`share.Check`) เปรียบเทียบทุกพาธใน `share.Layout` กับกลุ่มของบัญชี โดยใช้เพียง `lstat` และ `readlink` รายงานปัญหาห้าแบบ ได้แก่ ลิงก์ที่หายไป ลิงก์ที่ชี้ไปที่อื่น ไฟล์จริงในตำแหน่งที่ควรเป็นลิงก์ ลิงก์ที่หลงเหลืออยู่ของรายการที่ตอนนี้เป็นของบัญชีเอง และลิงก์ที่ถูกต้องแต่โฟลเดอร์กลุ่มหายไป (`the group folder it links to is missing (…), so Claude Code cannot save there (ccam doctor --fix makes it)` การเริ่มบัญชีไม่ตรวจข้อนี้) ลิงก์ที่หายไปและโฟลเดอร์กลุ่มที่หายไปถือเป็นคำเตือน ส่วนแบบอื่นถือเป็นข้อผิดพลาด การคัดลอกกลับจากกลุ่มที่หยุดกลางคันก็จะถูกรายงานด้วย: `--fix` จะนำสำเนาที่เตรียมไว้ครบถ้วนมาวางแทน แต่เมื่อพาธนั้นถูกสร้างใหม่ไปแล้ว (โดยการเริ่มบัญชี) จะระบุโฟลเดอร์ที่มีสำเนาครบถ้วนให้คุณจัดการเอง พาธที่ถูกเพิ่มเข้าในรายการใน ccam รุ่นหลัง (`file-history/`, `tasks/` และ `paste-cache/` สำหรับประวัติ และ `keybindings.json` สำหรับการตั้งค่า) เป็นเพียงคำเตือนตราบที่บัญชียังมีสำเนาของตัวเองอยู่: `is not shared with the group yet (ccam doctor --fix shares it; if the group has its own copy, that one is kept and this one backed up)` การเริ่มบัญชีจะไม่หยุดเพราะพาธเหล่านี้
6. **รายการที่ไม่รู้จัก** (`checkUnknownEntries`) แสดงชื่อระดับบนสุดในโฟลเดอร์บัญชีที่ ccam ไม่รู้จัก (`share.Known`) เพื่อบอกเป็นนัยว่าโครงสร้างของ Claude Code อาจเปลี่ยนไป เป็นข้อมูลเท่านั้น
7. **พาธปลั๊กอิน** (`checkPlugins`) รีจิสทรีปลั๊กอิน (`installed_plugins.json`, `known_marketplaces.json`) เก็บพาธแบบสัมบูรณ์ ใน `plugins/` ของแต่ละกลุ่ม พาธที่ผ่านโฟลเดอร์ของบัญชีหนึ่งจะใช้ไม่ได้เมื่อบัญชีนั้นถูกลบหรือเปลี่ยนชื่อ `--fix` จะเขียนพาธเหล่านั้นใหม่ให้ชี้ไปที่โฟลเดอร์ของกลุ่มด้วย `profile.RewritePluginPaths` ซึ่งเขียนไฟล์รีจิสทรีแบบ atomic
8. **เซิร์ฟเวอร์ MCP** (`checkMCP`) โหลด `mcp.json` ของแต่ละกลุ่มหนึ่งครั้ง ไฟล์ที่อ่านไม่ได้ถือเป็นข้อผิดพลาด และเซิร์ฟเวอร์ที่ไม่ผ่าน `mcp.Validate` ถือเป็นคำเตือน เซิร์ฟเวอร์ใน `~/.claude.json` ของ `claude` แบบปกติที่ไม่มีบัญชีใดโหลดถือเป็นคำเตือนที่ระบุคำสั่ง `ccam migrate --mcp` ที่ใช้คัดลอกเซิร์ฟเวอร์เหล่านั้น (พร้อม `--group <a|b>` เมื่อหลายกลุ่มใช้ MCP ร่วมกัน) เซิร์ฟเวอร์ที่มีเพียงบัญชีเดียวในกลุ่มถือเป็นข้อมูลพร้อมคำสั่ง `ccam mcp import` ที่ใช้แบ่งปันเซิร์ฟเวอร์เหล่านั้น และบัญชีที่ยังไม่ได้ลงชื่อเข้าใช้เซิร์ฟเวอร์ MCP ที่บัญชีอื่นลงชื่อเข้าใช้แล้วจะได้รับคำเตือนให้ลงชื่อเข้าใช้ด้วย `/mcp` (ccam ไม่เคยคัดลอกการลงชื่อเข้าใช้) ไม่มีการซ่อม
9. **รูปแบบคำตอบการใช้งาน** (`checkUsageFormat`) สอบถาม endpoint การใช้งานโดยไม่ใช้แคช ทีละบัญชีจนกว่าจะมีบัญชีที่ได้รับคำตอบ ทั้งหมดภายในเวลาจำกัด 4 วินาทีครั้งเดียว เมื่อตั้ง `usage_source = "claude"` จะถาม Claude Code สำหรับบัญชีหนึ่งแทน หากพาร์สคำตอบไม่ได้แล้ว จะเตือนว่า `ccam usage` จะหันไปใช้แคชของแถบสถานะแทน เมื่อไม่มีบัญชีใดได้รับคำตอบ จะแจ้งเป็นข้อมูล (`could not check the usage response format: …`) นี่เป็นการตรวจเพียงรายการเดียวที่ใช้เครือข่าย
10. **คำสั่งลัด** (`checkShims`) ตรวจเฉพาะเมื่อมีบัญชีที่มีคำสั่งลัด ลิงก์ที่หายไปใน `~/.local/bin` ถือเป็นคำเตือน เช่นเดียวกับคำสั่งลัดที่ ccam สร้างแต่ยังรัน ccam รุ่นเก่าที่ถูกแทนที่หรือย้ายไปแล้ว (`shortcuts in <bin> that run another ccam (one replaced or moved): …`) `--fix` จะเรียก `shim.Install` ซึ่งสร้างและต่ออายุเฉพาะลิงก์ที่ ccam สร้างและบันทึกไว้ใน `~/.local/state/ccam/shortcuts.json` และไม่แตะไฟล์อื่นเลย คำเตือนจะลงท้ายด้วย `→ fixed` ก็ต่อเมื่อสร้างลิงก์เหล่านั้นได้ทุกลิงก์ หากสร้างลิงก์ใดไม่ได้ จะเพิ่มเหตุผลไว้ คำสั่งลัดที่รัน ccam อีกตัวซึ่งยังติดตั้งอยู่ยังใช้งานได้และถือเป็นข้อมูล `--fix` จะชี้คำสั่งลัดนั้นมาที่ ccam ตัวนี้ โฟลเดอร์ bin ที่ไม่อยู่ใน `PATH` ถือเป็นคำเตือนและจะไม่ถูกซ่อม
11. **โฟลเดอร์ของบัญชี** (`checkFolders`) ตรวจเฉพาะเมื่อมีรายการ [`ccam folder`](/features/folder) รายการที่บัญชีไม่มีอยู่ถือเป็นข้อผิดพลาด และรายการที่โฟลเดอร์หายไปแล้วถือเป็นคำเตือน ทั้งสองแบบจะไม่ถูกซ่อม เพราะการลบรายการจะเปลี่ยนบัญชีที่เริ่มในโฟลเดอร์นั้น
12. **กลุ่มและการตั้งค่า** (`checkGroups`) สมาชิกกลุ่มที่ไม่ใช่บัญชี บัญชีที่ชื่อกลายเป็นคำสั่งของ ccam ไปแล้ว (เริ่มบัญชีนั้นด้วย `ccam run <name>` หรือเปลี่ยนชื่อ) ค่า `theme` หรือ `usage_source` ที่ไม่รู้จัก และบรรทัดของ `config.toml` ที่ ccam ไม่อ่าน ถือเป็นคำเตือน อย่างหลังมักเป็นการตั้งค่าที่เขียนไว้ใต้ตาราง `[[group]]`, `[[profile]]` หรือ `[[folder]]` ซึ่งทำให้เป็นของตารางนั้น (`config.toml line 43: relay is read as part of the [profile.login] table above it; settings for all accounts go above the first [[group]], [[profile]] or [[folder]]`) คำสั่งที่เปลี่ยนการตั้งค่าจะปฏิเสธจนกว่าจะแก้ไข ไม่มีการซ่อม
13. **การเข้าสู่ระบบ** (`checkIdentities`) อ่านจาก `.claude.json` ว่าแต่ละโฟลเดอร์เข้าสู่ระบบในชื่อใด โฟลเดอร์ที่ตอนนี้เข้าสู่ระบบด้วยบัญชีอื่นที่ไม่ใช่บัญชีที่ `ccam login` บันทึกไว้ (เช่น หลังใช้ `/login` ภายในเซสชัน) ถือเป็นคำเตือน บัญชีที่ไม่มีบันทึกการเข้าสู่ระบบ เช่น บัญชีที่นำเข้าหรือสร้างโดย ccam รุ่นเก่า จะถูกเปรียบเทียบด้วยอีเมลที่บันทึกไว้ โฟลเดอร์ที่เข้าสู่ระบบด้วยบัญชี Claude เดียวกันกับอีกโฟลเดอร์หนึ่งก็ถือเป็นคำเตือนเช่นกัน เพราะทั้งสองใช้ขีดจำกัดการใช้งานร่วมกัน โฟลเดอร์ที่ถือโทเค็นการเข้าสู่ระบบเดียวกับอีกโฟลเดอร์หนึ่ง ซึ่งก็คือโฟลเดอร์ที่ถูกคัดลอก (รวมถึง `~/.claude` ของ `claude` แบบปกติ) ถือเป็นข้อผิดพลาด เพราะโฟลเดอร์ใดต่ออายุก่อนจะทำให้อีกโฟลเดอร์หลุดจากระบบ ให้รัน `ccam login <name>` เพื่อให้โฟลเดอร์นั้นมีการเข้าสู่ระบบของตัวเอง ไม่มีการซ่อม

ก่อนการตรวจบัญชี **การเปลี่ยนกลุ่ม**ที่หยุดกลางคันถือเป็นข้อผิดพลาดในกล่อง `General`: ``the last change of groups stopped halfway (ccam doctor --fix finishes it; noted in ~/.local/state/ccam/group-change.json)`` `--fix` จะทำให้เสร็จตามลำดับที่วางแผนไว้ โดยใช้คำตอบที่ให้ไว้กับความขัดแย้งของการเปลี่ยนแปลงนั้น จนกว่าจะเสร็จ การเปลี่ยนกลุ่ม การเปลี่ยนชื่อ หรือการลบอื่นจะไม่เริ่ม บัญชีที่อยู่ในการเปลี่ยนแปลงนั้นจะได้รับเพียงการสร้างลิงก์ที่หายไปจนกว่าจะเสร็จ หากทำให้เสร็จไม่ได้ ข้อผิดพลาดจะบอกว่าการลบไฟล์นั้นหมายถึงการยกเลิกส่วนที่เหลือของการเปลี่ยนแปลง `ccam --dry-run doctor --fix` จะแสดงลำดับ (`--fix finishes it in its order (b, a, c), with the answers given to its conflicts`) และสิ่งที่ส่วนของแต่ละบัญชีจะแยกเก็บไว้ การเปลี่ยนแปลงที่ ccam อื่นกำลังดำเนินการอยู่ในขณะนี้ถือเป็นข้อมูล และขณะที่ทำงานอยู่ `--fix` จะไม่ซ่อมลิงก์ที่ใช้ร่วมกัน (`its share links are not repaired while another ccam changes the groups; …`) `--fix` จะถือ `~/.local/state/ccam/group-change.lock` ไว้ระหว่างซ่อม และอ่าน `config.toml` ใหม่หลังจากทำการเปลี่ยนแปลงเสร็จ

### การซ่อมลิงก์ที่ใช้ร่วมกัน

เส้นทางการเริ่มโปรแกรมจะสร้างลิงก์ที่หายไปให้ทันที แต่จะหยุดเมื่อพบสิ่งใดที่อาจทำให้ข้อมูลสูญหาย และแนะนำให้มาที่คำสั่งนี้:

```console
$ ccam work
ccam: stopped because of share link problems:
  /home/me/.local/share/ccam/profiles/work/CLAUDE.md: set to shared but is a real file, not a link
Repair them with `ccam doctor --fix`, then run again
```

สำหรับปัญหาลิงก์ที่ใช้ร่วมกันทุกแบบ `--fix` จะเรียก `share.Build` โดยใช้การตั้งค่าการใช้ร่วมกันของบัญชีเป็นทั้งสถานะปัจจุบันและสถานะเป้าหมาย แล้วตามด้วย `Plan.Apply` `Build` สร้างทุกขั้นตอนขึ้นใหม่จากสิ่งที่อยู่บนดิสก์ ซึ่งเป็นแผนเดียวกับที่การเปลี่ยนแปลงด้วย `ccam group` ใช้ การซ่อมจึงทำตามกฎเดียวกับการเข้าร่วมกลุ่ม

<!-- motion:doctor-repair -->

ในตัวอย่างนี้ `settings.json` เป็นไฟล์จริง เนื่องจากกลุ่มมี `settings.json` ที่ต่างกันอยู่แล้ว ความขัดแย้งจึงใช้ตัวเลือกเริ่มต้น `KeepGroup` และสำเนาของกลุ่มยังคงอยู่ ไฟล์ของบัญชีจะถูกย้ายไปที่ `.ccam-backup/<time>/settings.json` ภายในโฟลเดอร์ของบัญชี และ `os.Symlink` จะลิงก์พาธนั้นไปยังกลุ่ม `--fix` จะแจ้งไว้: `settings.json differed from the group's copy, which it now uses; this account's copy is in …` กรณีอื่น ๆ:

- หากกลุ่มยังไม่มีสำเนา ไฟล์ของบัญชีจะถูกย้ายเข้าไปในกลุ่มและกลายเป็นเนื้อหาแรกของกลุ่ม
- สำหรับโฟลเดอร์ ไฟล์ที่กลุ่มยังไม่มีจะถูกย้ายเข้าไปในกลุ่ม ไฟล์ที่กลุ่มมีเหมือนกันทุกไบต์จะถูกทิ้ง ส่วนไฟล์ที่ต่างกันจะไปอยู่ในที่สำรอง โดยระบุไว้ในหมายเหตุ (`projects: 1 file differs from the group's copy (-w/memory/MEMORY.md); the group's is kept, the account's stays in …`)
- โฟลเดอร์กลุ่มที่หายไปจะถูกสร้างขึ้นก่อน
- สำหรับ `history.jsonl` ค่าเริ่มต้นคือ `merge by line`: บรรทัดของกลุ่มก่อน แล้วตามด้วยบรรทัดใหม่ของคุณ สำเนาเดิมของกลุ่มจะถูกเก็บไว้ใน `.ccam-backup/<time>/group/`
- ลิงก์ที่ชี้ไปยังกลุ่มอื่นจะถูกแทนที่ ลิงก์ที่ชี้ไปยังโฟลเดอร์นอก ccam จะไปอยู่ในที่สำรอง และเนื้อหาของโฟลเดอร์นั้นจะกลายเป็นเนื้อหาเริ่มต้นของกลุ่มหากกลุ่มยังว่างอยู่
- ลิงก์ที่หลงเหลืออยู่ของรายการที่ตอนนี้เป็นของบัญชีเองจะถูกลบ และบัญชีจะได้รับสำเนาของเนื้อหาในกลุ่ม

นอกจากการลบลิงก์และการทิ้งไฟล์ที่กลุ่มมีเหมือนกันทุกไบต์อยู่แล้ว ทุกขั้นตอนจะย้ายข้อมูลเข้าไปในกลุ่มหรือโฟลเดอร์สำรอง ไม่มีสิ่งใดสูญหาย

## ความปลอดภัยและกรณีพิเศษ

- `ccam doctor` แบบธรรมดาจะไม่เปลี่ยนแปลงสิ่งใดเลย ในสคริปต์ให้ใช้ `--dry-run` คู่กับ `--fix` เพื่อความแน่ใจ
- สำหรับบัญชีที่กำลังทำงานอยู่ ไม่ว่า Claude Code จะถูกเริ่มด้วยวิธีใด `doctor --fix` จะสร้างเฉพาะลิงก์ที่หายไปและโฟลเดอร์กลุ่มที่หายไป ซึ่งไม่ทำให้สิ่งใดสูญหาย เมื่อยังมีสิ่งอื่นเหลืออยู่ จะเพิ่มข้อความ `` is running; quit Claude Code there, then run `ccam doctor --fix` again to repair the rest `` เพราะเซสชันยังคงเขียนลงไฟล์ที่การซ่อมจะย้าย
- หากการซ่อมการใช้ร่วมกันล้มเหลว ccam จะรายงาน `could not repair share links: <error>` สำหรับบัญชีนั้นและข้ามการตรวจรายการที่ไม่รู้จัก บัญชีอื่นยังคงถูกตรวจตามปกติ
- หากการเปลี่ยนแปลงด้วย `ccam group` ล้มเหลวกลางคัน กลุ่มใหม่จะถูกบันทึกไว้แล้ว และการเปลี่ยนแปลงจะถูกบันทึกไว้ใน `~/.local/state/ccam/group-change.json` ccam จะบอกให้คุณทำต่อให้เสร็จด้วย `ccam doctor --fix` ซึ่งจะดำเนินการส่วนที่เหลือ รวมถึงขั้นตอน MCP ด้วย
- `.credentials.json` ที่เป็นลิงก์สัญลักษณ์ การเข้าสู่ระบบที่หมดอายุ และข้อมูลเข้าสู่ระบบในตัวแปรสภาพแวดล้อม จะถูกรายงานแต่ไม่ถูกเปลี่ยนแปลง
- การเขียนรีจิสทรีปลั๊กอินใหม่จะเขียนแบบ atomic แต่ไม่ได้คัดลอกไปไว้ใน `.ccam-backup/`
