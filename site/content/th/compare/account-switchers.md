เครื่องมือสลับบัญชี Claude Code ใช้แนวทางใดแนวทางหนึ่งจากสองแบบ ส่วนใหญ่สลับการเข้าสู่ระบบภายในโฟลเดอร์ `~/.claude` เพียงโฟลเดอร์เดียว จึงใช้งานได้ทีละบัญชี ส่วนเครื่องมืออื่นรวมถึง ccam ให้แต่ละบัญชีมีโฟลเดอร์ของตัวเองด้วย `CLAUDE_CONFIG_DIR` ทุกบัญชีจึงยังเข้าสู่ระบบอยู่และรันหลายบัญชีพร้อมกันได้ ccam ยังเพิ่มการใช้การตั้งค่าและเซิร์ฟเวอร์ MCP ร่วมกัน และสนทนาต่อในโฟลเดอร์ของอีกบัญชีหนึ่งได้

## สลับการเข้าสู่ระบบชุดเดียว หรือแยกโฟลเดอร์?

**การสลับการเข้าสู่ระบบ** มีการตั้งค่า เซิร์ฟเวอร์ MCP และประวัติเพียงชุดเดียว เพราะมีโฟลเดอร์เดียว การสลับทำได้เร็ว และเซสชันที่กำลังทำงานอยู่ก็รับการเข้าสู่ระบบใหม่ได้ แต่ใช้งานได้ทีละบัญชีเท่านั้น สำหรับทุกเทอร์มินัลและทุกเอดิเตอร์พร้อมกัน

ในการสลับ เครื่องมือจะเก็บสำเนาการเข้าสู่ระบบของบัญชีอื่นทุกบัญชีไว้ แล้วเขียนกลับเข้าที่เดิมเมื่อสลับ Claude Code เปลี่ยน refresh token ในการเข้าสู่ระบบทุกครั้งที่ต่ออายุ สำเนาที่เก็บไว้แต่ละชุดจึงต้องตามให้ทันเซสชันที่กำลังทำงานอยู่เสมอ บัญชีที่หลุดออกจากระบบหรือต้อง `/login` ใหม่หลังสลับเป็นหนึ่งในปัญหาที่โปรเจกต์เหล่านี้แก้บ่อยที่สุด

**การแยกโฟลเดอร์** เป็นวิธีที่[เอกสารของ Claude Code อธิบายไว้](https://code.claude.com/docs/en/authentication#log-in-with-multiple-accounts) ทุกบัญชียังเข้าสู่ระบบอยู่ และคุณรันเซสชันงานกับเซสชันส่วนตัวควบคู่กันได้ การเข้าสู่ระบบแต่ละชุดอยู่ในโฟลเดอร์ของตัวเอง และ Claude Code ต่ออายุที่นั่นตามปกติ ข้อแลกเปลี่ยนคือแต่ละโฟลเดอร์เริ่มต้นด้วยการตั้งค่า เซิร์ฟเวอร์ MCP และประวัติของตัวเอง เว้นแต่จะมีเครื่องมือช่วยให้ใช้ร่วมกัน

## จุดเด่นของ ccam

### การเข้าสู่ระบบอยู่ที่เดิมที่ Claude Code วางไว้

ccam ไม่เคยคัดลอกการเข้าสู่ระบบ Claude จากที่หนึ่งไปอีกที่หนึ่ง การเข้าสู่ระบบของแต่ละบัญชีอยู่ในโฟลเดอร์ของตัวเอง หรือบน macOS อยู่ในรายการพวงกุญแจ (Keychain) ของโฟลเดอร์นั้นเอง และ Claude Code เป็นโปรแกรมที่ต่ออายุให้ ไม่มีสำเนาที่เก็บไว้ซึ่งอาจไม่ตรงกันได้ `~/.claude` เดิมที่ลงทะเบียนด้วย `ccam import` ยังใช้รายการพวงกุญแจ (Keychain) เดียวกับที่ `claude` ธรรมดาใช้ จึงยังเข้าสู่ระบบอยู่ไม่ว่าจะเปิดด้วยวิธีไหน

ccam ต่ออายุโทเค็นที่หมดอายุเองก็ต่อเมื่อคุณรัน `ccam usage --refresh` เท่านั้น โดยจะล็อกก่อนและปฏิเสธหากบัญชีนั้นกำลังทำงานอยู่ จึงไม่เคยเปลี่ยนโทเค็นใต้เซสชันที่ยังทำงานอยู่

### ไม่มีอะไรทำงานคั่นระหว่างคุณกับ Claude Code

ccam อ่านไฟล์หนึ่งไฟล์ ตรวจลิงก์ แล้วแทนที่ตัวเองด้วย `claude` (`exec`) ระหว่างที่คุณทำงานจะไม่มีโปรเซสของ ccam ไม่มี wrapper พร็อกซี หรือ daemon อินพุตมาตรฐาน สัญญาณ และรหัสออกเป็นของ Claude Code และคำขอของมันส่งตรงไปยัง Anthropic Windows แทนที่โปรเซสไม่ได้ บน Windows ccam จึงเริ่ม Claude Code ด้วยคอนโซลเดียวกันและรอรหัสออกของมัน โดยไม่ทำอย่างอื่น

การเริ่มบัญชีด้วยวิธีนี้ใช้เวลาเพิ่มประมาณ 4 ms ต่ำกว่า 6 ms ที่เปอร์เซ็นไทล์ที่ 95 และใช้หน่วยความจำสูงสุด 8 MB ([`scripts/perf-check.sh`](https://github.com/jhyunwoo/ccam/blob/main/scripts/perf-check.sh) กับ hyperfine 300 รอบ) บนแล็ปท็อปเครื่องเดียวกัน แค่เริ่มตัวแปลภาษา Python ก็ใช้ 13 ms และ Node.js ใช้ 31 ms ก่อนที่โปรแกรมจะได้ทำอะไรเลย

### กลุ่มเป็นตัวกำหนดว่าจะใช้อะไรร่วมกัน

เซิร์ฟเวอร์ MCP, `settings.json`, `CLAUDE.md`, ส่วนขยาย (เอเจนต์ คำสั่ง สกิล ปลั๊กอิน) และประวัติการสนทนาเป็นห้ารายการที่แยกจากกัน กลุ่มหนึ่งระบุรายการที่ใช้ร่วมกันและบัญชีที่อยู่ในกลุ่ม บัญชีงานสองบัญชีจึงใช้ประวัติร่วมกันในกลุ่ม `work` ได้ ขณะที่บัญชีส่วนตัวเก็บประวัติของตัวเองไว้ และทั้งสามบัญชีใช้เซิร์ฟเวอร์ MCP ชุดเดียวกันผ่าน `default` `ccam group set work --add memory` ย้ายทุกบัญชีของกลุ่มด้วยแผนเดียว ส่วน[แดชบอร์ด](/features/dashboard)ทำแบบเดียวกันด้วยช่องทำเครื่องหมาย และแสดงรายการที่บัญชีได้รับจากกลุ่มอื่นอยู่แล้วเป็นสีเทา

- เซิร์ฟเวอร์ MCP ส่งผ่าน `--mcp-config` ตอนเปิด ค่าเริ่มต้นของ ccam จึงไม่เคยแก้ไข `.claude.json` ซึ่งเป็นไฟล์ที่ Claude Code เขียนทับระหว่างทำงาน `ccam mcp add` เพิ่มเซิร์ฟเวอร์ครั้งเดียวให้ทั้งกลุ่ม
- รายการอื่นเป็นลิงก์ไปยังโฟลเดอร์ของกลุ่ม การเปลี่ยนแปลงในบัญชีหนึ่งจึงปรากฏในบัญชีอื่นทันที ไม่มีอะไรถูกคัดลอกตอนเปิด
- การเข้าสู่ระบบ `.claude.json` และสถานะการทำงานไม่เคยถูกใช้ร่วมกัน

### ทุกการเปลี่ยนแปลงแสดงให้ดูก่อนและสำรองไว้

`ccam group` และ `ccam migrate` พิมพ์แผนและถามก่อนย้ายสิ่งใด เมื่อไฟล์ในบัญชีกับในกลุ่มต่างกัน คุณเป็นผู้เลือก: เก็บของกลุ่มไว้ ใช้ของคุณ หรือรวม JSON ไฟล์ต้นฉบับไปอยู่ที่ `.ccam-backup/<time>/` โฟลเดอร์ของบัญชีที่ลบไปอยู่ในโฟลเดอร์ถังขยะ และไฟล์ถูกแทนที่ด้วยการเปลี่ยนชื่อครั้งเดียว การเขียนที่ถูกขัดจังหวะจึงยังเหลือไฟล์เดิมไว้ `--dry-run` แสดงว่าการเปิด การใช้ร่วมกัน การย้าย คำสั่งลัด การอัปเดต และการซ่อมจะทำอะไร `ccam doctor --fix` ซ่อมลิงก์และสิทธิ์ที่เสีย

### สนทนาเดิมต่อในบัญชีถัดไป

`ccam next --auto --continue` จะถามการใช้งานจากทุกบัญชีพร้อมกัน เปิดบัญชีที่เหลือโควตามากที่สุด และสนทนาต่อ เมื่อใช้ประวัติร่วมกันจะเป็นการสนทนาเดียวกัน หากไม่ได้ใช้ร่วมกัน Claude Code จะคัดลอกการสนทนาไปยังบัญชีใหม่ (`--resume <file> --fork-session`) และ ccam จะบอกว่าคำตอบแรกต้องอ่านซ้ำกี่โทเค็น เมื่อขีดจำกัดทำให้เซสชันหยุด hook ของปลั๊กอิน ccam จะแสดงการแจ้งเตือน และ `/ccam:switch` จะส่งต่อการสนทนาไป คุณเป็นผู้ตัดสินใจว่าจะสลับเมื่อไร ไม่มีอะไรเฝ้าดูการใช้งานของคุณอยู่เบื้องหลัง และการเลือกอัตโนมัติจะอยู่ภายในองค์กรเดียว การสนทนาของบริษัทจึงไม่มีทางไปอยู่ในบัญชีส่วนตัวโดยไม่ตั้งใจ แถบสถานะจะแนะนำคำสั่งนี้เมื่อบัญชีใช้งานถึง 90%

สคริปต์รอคุณไม่ได้ `ccam --fallback work -p "…"` จึงสลับแทนให้: เมื่อบัญชีถึงขีดจำกัด คำสั่งเดิมจะรันอีกครั้งด้วยบัญชีที่เหลือโควตามากที่สุด และพิมพ์เฉพาะผลลัพธ์ของการรันที่ทำงานจนจบ ความล้มเหลวที่ไม่ใช่ขีดจำกัดการใช้งานจะส่งต่อไปตามเดิม สำหรับ worker ที่ทำงานขนานกัน `ccam pick` จะให้บัญชีที่ยังเหลือโควตาแก่แต่ละ worker คนละบัญชี และทั้งสองคำสั่งจะออกด้วยรหัส 75 เมื่อไม่มีบัญชีใดเหลือโควตา

### บัญชีที่ใช่ในแต่ละโฟลเดอร์

`ccam folder work ~/code/company` ทำให้ทุกการเปิดที่ไม่ระบุชื่อบัญชีภายในโฟลเดอร์นั้นใช้ `work` ขณะที่โปรเจกต์อื่นของคุณยังใช้บัญชีเริ่มต้น การตั้งค่านี้อยู่ใน `config.toml` ไฟล์เดียวกับที่ทุกการเปิดอ่านอยู่แล้ว จึงไม่เสียเวลาเพิ่ม

### ไบนารีเดียว ดาวน์โหลดที่ผ่านการตรวจสอบ

ccam เป็นไบนารีแบบ static ขนาดประมาณ 10 MB ไม่ต้องติดตั้ง runtime ใด ๆ สำหรับ Linux, macOS และ Windows สคริปต์ติดตั้ง (`install.sh`, `install.ps1`) และ `ccam update` ตรวจทุกไฟล์ที่ดาวน์โหลดกับ checksum SHA-256 ของรีลีส และ ccam ไม่เคยตรวจหาอัปเดตเอง ไม่มีการเก็บข้อมูลการใช้งาน (telemetry): คำขอเดียวที่ ccam ส่งคือการถามการใช้งานบัญชีของคุณจาก Anthropic (แบบขนาน จำกัดเวลา 3 วินาที และแคช 60 วินาที) และการดาวน์โหลดที่คุณสั่ง เมื่อตั้ง `usage_source = "claude"` แม้แต่คำขอเหล่านั้นก็ส่งผ่าน Claude Code และ ccam ไม่เคยแตะโทเค็นเลย

## สิ่งที่เครื่องมืออื่นทำได้มากกว่า

- claude-swap, clauth, cux, CAAM และ CCSwitcher สลับเซสชันแบบโต้ตอบที่กำลังทำงานอยู่ได้เองเมื่อบัญชีใช้งานเกินเกณฑ์ ส่วน ccam สลับการรันแบบ `-p` ด้วย `--fallback` และปล่อยเซสชันแบบโต้ตอบให้คุณเป็นผู้สลับ โดยมีการแจ้งเตือนเมื่อถึงขีดจำกัดและมี `/ccam:switch`
- บน Windows ที่ไม่ได้เปิด Developer Mode ccam ใช้โฟลเดอร์ร่วมกันได้ แต่ใช้ไฟล์เดี่ยวอย่าง `settings.json` ร่วมกันไม่ได้ ส่วน claude-swap และ CCS คัดลอกไฟล์เหล่านั้นแทน
- CCSwitcher, Claude Switcher และ claude-swap แสดงการใช้งานในแถบเมนูของ macOS
- CCS, clausona, CAAM, clauth, ccswap และ Claude Switcher จัดการ Codex และ coding agent อื่นด้วย
- clausona ยังเปิดและปิดส่วนขยายแยกตามบัญชีได้ (`ccam ext` ของ ccam แค่แสดงเท่านั้น) ติดตามค่าใช้จ่ายโทเค็นในเครื่อง และมีปลั๊กอิน Claude Code ที่รัน worker จำนวนมากใน tmux และเทอร์มินัลอื่น
- CAAM, CCSwitcher และ Claude Switcher ติดตั้งด้วย Homebrew ได้ และ clauth กับ CAAM ลงลายเซ็นให้ checksum ของรีลีส ส่วน ccam ติดตั้งด้วยสคริปต์ของตัวเอง `.deb` หรือ `go install` และตรวจ checksum โดยไม่มีลายเซ็น

## แบบไหนเหมาะกับคุณ?

เลือกเครื่องมือที่สลับการเข้าสู่ระบบ หากคุณใช้ทีละบัญชี หรือต้องการให้เซสชันที่กำลังทำงานสลับอัตโนมัติ เลือก ccam หากคุณต้องการใช้หลายบัญชีควบคู่กัน มีการตั้งค่าชุดเดียวที่ใช้ร่วมกัน สนทนาเดิมต่อในบัญชีถัดไป และไม่มีอะไรทำงานอยู่ข้าง ๆ Claude Code บน Linux, macOS หรือ Windows หากไม่ต้องใช้อะไรร่วมกันเลย [shell alias ธรรมดา](/compare/aliases) ก็เพียงพอ

การใช้หลายบัญชีได้หรือไม่ขึ้นอยู่กับข้อกำหนดของแต่ละบัญชี โปรดตรวจสอบก่อนใช้งาน
