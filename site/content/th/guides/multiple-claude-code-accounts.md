ให้แต่ละบัญชีมีโฟลเดอร์การตั้งค่าของตัวเอง Claude Code อ่านโฟลเดอร์จากตัวแปรสภาพแวดล้อม `CLAUDE_CONFIG_DIR` และแต่ละโฟลเดอร์เก็บการเข้าสู่ระบบ การตั้งค่า และประวัติของตัวเองไว้ ทุกบัญชีจึงยังเข้าสู่ระบบอยู่เสมอ และคุณรันหลายบัญชีพร้อมกันได้ คุณตั้งค่านี้เองได้ด้วย shell alias หรือให้ ccam จัดการให้ก็ได้

## ตั้งค่าเองได้อย่างไร?

นี่คือแนวทางที่[เอกสารของ Claude Code อธิบายไว้](https://code.claude.com/docs/en/authentication#log-in-with-multiple-accounts) เพิ่มหนึ่งบรรทัดต่อบัญชีเพิ่มเติมแต่ละบัญชีลงใน `~/.bashrc` หรือ `~/.zshrc`:

```sh
alias claude-work='CLAUDE_CONFIG_DIR=~/.claude-work claude'
```

เปิดเทอร์มินัลใหม่แล้วรัน `claude-work` Claude Code จะขอให้คุณเข้าสู่ระบบ เพราะโฟลเดอร์นั้นเป็นโฟลเดอร์ใหม่ ต่อจากนี้ `claude` คือบัญชีแรกของคุณ และ `claude-work` คือบัญชีที่สอง เพิ่ม alias หนึ่งตัวต่อหนึ่งบัญชี โดยแต่ละตัวใช้โฟลเดอร์ของตัวเอง

บน Windows ที่ไม่มี WSL ฟังก์ชัน PowerShell ในโปรไฟล์ของคุณ (`notepad $PROFILE`) ก็ทำแบบเดียวกันได้:

```powershell
function claude-work { $env:CLAUDE_CONFIG_DIR = "$HOME\.claude-work"; try { claude @args } finally { Remove-Item Env:CLAUDE_CONFIG_DIR } }
```

## วิธี alias ยังขาดอะไรบ้าง?

วิธีนี้ใช้ได้ดีสำหรับสองบัญชี สิ่งที่ควรรู้:

- แต่ละโฟลเดอร์เริ่มต้นแบบว่างเปล่า: ไม่มีการตั้งค่า ไม่มี `CLAUDE.md` ไม่มีเซิร์ฟเวอร์ MCP ไม่มีเอเจนต์หรือสกิล คุณต้องคัดลอกหรือลิงก์สิ่งที่ต้องการ และคอยทำให้สำเนาตรงกันด้วยตัวเอง
- alias มีอยู่เฉพาะใน shell แบบโต้ตอบเท่านั้น สคริปต์ Makefile และโปรแกรมอื่นมองไม่เห็น alias
- เซิร์ฟเวอร์ MCP อยู่ใน `.claude.json` ข้างกับการเข้าสู่ระบบ จึงลิงก์ระหว่างโฟลเดอร์แบบง่าย ๆ ไม่ได้
- การสนทนาอยู่ในบัญชีที่เริ่มต้นเท่านั้น คุณจึงสนทนาต่อในอีกบัญชีหนึ่งไม่ได้
- ไม่มีอะไรแสดงการใช้งานของทุกบัญชีในคราวเดียว

## สลับบัญชีด้วย /login แทนได้ไหม?

ได้ หากคุณสลับเป็นครั้งคราว การพิมพ์ `/login` ใน Claude Code จะ[สลับบัญชี](https://code.claude.com/docs/en/quickstart)ของโฟลเดอร์ที่คุณใช้อยู่ แต่ละครั้งจะเข้าสู่ระบบได้เพียงบัญชีเดียว คุณจึงต้องเข้าสู่ระบบใหม่ทุกครั้งที่สลับ และรันสองบัญชีควบคู่กันไม่ได้ การแยกโฟลเดอร์ช่วยเลี่ยงทั้งสองปัญหานี้

## ตั้งค่าด้วย ccam ได้อย่างไร?

ccam ทำแนวคิดเดียวกันนี้ให้เป็นอัตโนมัติ และเพิ่มส่วนที่ขาดหายไป:

```sh
curl -fsSL https://ccam.dev/install.sh | sh
ccam add personal
ccam add work --shortcut ccwork
```

ตอนนี้ `ccam personal` และ `ccam work` จะเริ่มทั้งสองบัญชี และ `ccwork` ซึ่งเป็นคำสั่งลัดที่คุณตั้งให้บัญชีงานก็เช่นกัน เพราะคำสั่งเหล่านี้เป็นโปรแกรมจริงไม่ใช่ alias จึงใช้ในสคริปต์ได้ด้วย รัน `ccam` อย่างเดียวเพื่อเลือกบัญชีจากรายการ และรัน `ccam use work` เพื่อตั้งบัญชีหนึ่งเป็นค่าเริ่มต้น

การตั้งค่า `CLAUDE.md` เซิร์ฟเวอร์ MCP และส่วนขยายใช้ร่วมกันตั้งแต่แรก และคุณเปิดใช้ประวัติการสนทนาร่วมกันได้ เพื่อสนทนาต่อในอีกบัญชีหนึ่งด้วย `ccam next --continue` ส่วน `ccam usage` แสดงการใช้งาน 5 ชั่วโมงและรายสัปดาห์ของทุกบัญชีในคราวเดียว

หากคุณใช้ `~/.claude` อยู่แล้ว ให้รัน `ccam import` แทนการเพิ่มบัญชีนั้นใหม่ หรือรัน `ccam migrate` เพื่อคัดลอกการตั้งค่า เซิร์ฟเวอร์ MCP และส่วนขยายของโฟลเดอร์นั้นไปยังการตั้งค่าที่ใช้ร่วมกัน

## จะรู้ได้อย่างไรว่ากำลังใช้บัญชีไหนอยู่?

ใน Claude Code คำสั่ง `/status` จะแสดงบัญชีที่คุณเข้าสู่ระบบอยู่ หากใช้ ccam ให้รัน `ccam statusline install` ครั้งเดียว แล้วแถบสถานะจะแสดงชื่อบัญชีและการใช้งานตลอดเวลา เช่น `[work] · Opus · 5h 24% · 7d 41%`

## ใช้บน Windows และ WSL ได้ไหม?

Claude Code ทำงาน[บน Windows โดยตรงและภายใน WSL](https://code.claude.com/docs/en/setup) `CLAUDE_CONFIG_DIR` ใช้ได้ทั้งสองแบบ ดังนั้นบน Windows แบบเนทีฟ alias หรือฟังก์ชัน PowerShell ข้างต้นก็เพียงพอ ccam ก็ทำงานบน Windows แบบเนทีฟได้เช่นกัน: ติดตั้งใน PowerShell ด้วย `irm https://ccam.dev/install.ps1 | iex` หรือติดตั้งภายใน WSL ด้วยคำสั่งของ Linux คำสั่งลัดจะกลายเป็น `ccwork.exe` และการใช้ไฟล์อย่าง `settings.json` ร่วมกันต้องเปิด Developer Mode ([ติดตั้ง ccam](/docs/install))

## การแก้ไขปัญหา

**Claude Code ขอให้เข้าสู่ระบบทุกครั้ง** การเริ่มครั้งแรกในโฟลเดอร์ใหม่จะขอให้เข้าสู่ระบบเสมอ หากยังขออยู่เรื่อย ๆ แสดงว่าการเข้าสู่ระบบหมดอายุหรือถูกลบไป ให้รัน `ccam login work` (หรือรัน alias หนึ่งครั้งแล้วเข้าสู่ระบบ)

**เซิร์ฟเวอร์ MCP ปรากฏในบัญชีเดียว** เซิร์ฟเวอร์ที่เพิ่มภายในเซสชันด้วย `claude mcp add` จะเป็นของบัญชีนั้น ย้ายไปยังทุกบัญชีได้ด้วย `ccam mcp import work <server>`

**การตั้งค่าแต่ละบัญชีไม่เหมือนกัน** `ccam share work` แสดงสิ่งที่บัญชีนั้นใช้ร่วมกัน ส่วน `ccam share work --settings on` จะใช้การตั้งค่าของบัญชีนั้นร่วมกัน หลังจากแสดงให้ดูก่อนว่าจะมีอะไรเปลี่ยน `ccam doctor --fix` ซ่อมลิงก์ที่เสียและสำรองทุกไฟล์ที่เปลี่ยนไว้

**สองบัญชีเปิดการสนทนาเดียวกัน** หลีกเลี่ยงการทำงานในการสนทนาเดียวกันด้วยสองบัญชีพร้อมกัน ccam จะเตือนเมื่อคุณพยายามทำเช่นนั้น

## ควรเลือกแบบไหน?

สำหรับสองบัญชีที่ไม่ใช้อะไรร่วมกัน alias ก็เพียงพอ เมื่อคุณต้องการใช้การตั้งค่าและเซิร์ฟเวอร์ MCP ร่วมกัน ใช้บัญชีมากขึ้น ดูการใช้งานได้ในพริบตา หรือสนทนาต่อข้ามบัญชี ccam จะช่วยลดงานจัดการเหล่านี้ [การเปรียบเทียบกับ alias](/compare/aliases) แสดงความแตกต่างแบบเทียบกันทีละข้อ และ [ccam กับเครื่องมือสลับบัญชีอื่น ๆ](/compare/account-switchers) อธิบายเครื่องมือที่สลับการเข้าสู่ระบบเพียงชุดเดียวแทน

การใช้หลายบัญชีได้หรือไม่ขึ้นอยู่กับข้อกำหนดของแต่ละบัญชี โปรดตรวจสอบก่อนใช้งาน
