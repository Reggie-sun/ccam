ابزارهای تعویض حساب Claude Code یکی از دو روش را به کار می‌برند. بیشترشان ورود را داخل تنها پوشه `~/.claude` عوض می‌کنند، پس در هر لحظه فقط یک حساب فعال است. برخی دیگر، از جمله ccam، با `CLAUDE_CONFIG_DIR` به هر حساب پوشه خودش را می‌دهند، پس هر حساب وارد‌شده باقی می‌ماند و چند حساب می‌توانند هم‌زمان اجرا شوند. ccam اشتراک تنظیمات و سرورهای MCP را هم اضافه می‌کند و یک گفتگو را در پوشه حساب دیگری ادامه می‌دهد.

## تعویض یک ورود یا پوشه‌های جداگانه؟

**تعویض ورود** یک مجموعه تنظیمات، سرورهای MCP و تاریخچه را نگه می‌دارد، چون فقط یک پوشه وجود دارد. جابه‌جایی سریع است و نشستی که در حال اجراست می‌تواند ورود جدید را بگیرد. اما در هر لحظه فقط یک حساب فعال است، آن هم برای همه ترمینال‌ها و ویرایشگرها با هم.

برای تعویض، ابزار از ورود هر حساب دیگر یک نسخه نگه می‌دارد و آن را سر جایش می‌نویسد. Claude Code هر بار که ورود را تمدید می‌کند توکن تمدید (refresh token) آن را عوض می‌کند، پس هر نسخه ذخیره‌شده باید با نشست‌های در حال اجرا هماهنگ بماند. حساب‌هایی که پس از تعویض از حساب خارج می‌شوند یا دوباره به `/login` نیاز دارند، از رایج‌ترین مشکلاتی هستند که این پروژه‌ها رفع می‌کنند.

**پوشه‌های جداگانه** همان روشی است که [مستندات Claude Code شرح می‌دهد](https://code.claude.com/docs/en/authentication#log-in-with-multiple-accounts). هر حساب وارد‌شده باقی می‌ماند و می‌توانید یک نشست کاری و یک نشست شخصی را کنار هم اجرا کنید. هر ورود در پوشه خودش می‌ماند و Claude Code طبق معمول آن را همان‌جا تمدید می‌کند. بهای آن این است که هر پوشه با تنظیمات، سرورهای MCP و تاریخچه خودش شروع می‌شود، مگر اینکه ابزاری آن‌ها را مشترک کند.

## نقاط قوت ccam

### ورودها همان‌جا می‌مانند که Claude Code گذاشته است

ccam هرگز یک ورود Claude را از جایی به جای دیگر کپی نمی‌کند. ورود هر حساب در پوشه خودش می‌ماند، یا در macOS در مورد Keychain مخصوص همان پوشه، و برنامه‌ای که آن را تمدید می‌کند Claude Code است. هیچ نسخه ذخیره‌شده‌ای وجود ندارد که از هماهنگی خارج شود. یک `~/.claude` موجود که با `ccam import` ثبت شود، همان مورد Keychain را نگه می‌دارد که `claude` معمولی استفاده می‌کند، پس در هر دو حالت وارد‌شده باقی می‌ماند.

ccam فقط وقتی `ccam usage --refresh` را اجرا کنید یک توکن منقضی‌شده را خودش تمدید می‌کند. اول یک قفل می‌گیرد و تا وقتی آن حساب در حال اجراست، Claude Code به هر شکلی که شروع شده باشد (از جمله نشست‌های پس‌زمینه و daemon آن‌ها)، و تا وقتی خود Claude Code در حال تمدید آن ورود است، سر باز می‌زند، پس هرگز توکنی را زیر یک نشست زنده عوض نمی‌کند.

### به‌طور پیش‌فرض، هیچ چیز بین شما و Claude Code اجرا نمی‌شود

ccam یک فایل را می‌خواند، پیوندهایش را بررسی می‌کند و خودش را با `claude` جایگزین می‌کند (`exec`). به‌طور پیش‌فرض، هنگام کار هیچ فرایند ccam، پوشش، پراکسی یا daemon وجود ندارد: ورودی استاندارد، سیگنال‌ها و کد خروج متعلق به Claude Code هستند و درخواست‌هایش مستقیم به Anthropic می‌روند. Windows نمی‌تواند یک فرایند را جایگزین کند، پس آنجا ccam برنامه Claude Code را با همان کنسول اجرا می‌کند و منتظر کد خروجش می‌ماند، بی‌آنکه کار دیگری انجام دهد. با `relay = true` یا `auto_switch = true`، ccam به همین شکل در کنار نشست‌های تعاملی در حال اجرا می‌ماند تا بتواند گفتگو را در حساب دیگری ادامه دهد؛ درخواست‌های Claude Code همچنان مستقیم به Anthropic می‌روند.

اجرای یک حساب به این روش حدود 4 ms اضافه می‌کند، در صدک ۹۵ کمتر از 6 ms، با اوج حافظه 8 MB ([`scripts/perf-check.sh`](https://github.com/jhyunwoo/ccam/blob/main/scripts/perf-check.sh) با hyperfine، ۳۰۰ اجرا). روی همان لپ‌تاپ، فقط راه‌اندازی مفسر Python ۱۳ میلی‌ثانیه و Node.js ۳۱ میلی‌ثانیه طول می‌کشد، پیش از آنکه برنامه‌ای کاری انجام دهد.

### گروه‌ها تعیین می‌کنند چه چیزی مشترک شود

سرورهای MCP، `settings.json`، `CLAUDE.md`، افزونه‌ها (agents، commands، skills، plugins) و تاریخچه گفتگو پنج مورد جداگانه‌اند. یک گروه مواردی را که مشترک می‌کند و حساب‌های عضوش را نام می‌برد، پس دو حساب کاری می‌توانند تاریخچه را در گروه `work` مشترک کنند، در حالی که یک حساب شخصی تاریخچه خودش را نگه می‌دارد، و هر سه از طریق `default` همان سرورهای MCP را مشترک دارند. `ccam group set work --add memory` همه حساب‌های گروه را در یک برنامه به‌روز می‌کند؛ [داشبورد](/features/dashboard) همین کار را با کادرهای انتخاب انجام می‌دهد و موردی را که یک حساب از قبل از گروه دیگری می‌گیرد کم‌رنگ نشان می‌دهد.

- سرورهای MCP هنگام اجرا با `--mcp-config` داده می‌شوند، پس یک اجرا به‌طور پیش‌فرض هرگز به `.claude.json`، فایلی که Claude Code در حین اجرا بازنویسی می‌کند، دست نمی‌زند. ccam فقط در مرحله‌هایی که این را اعلام می‌کنند، زیر قفل Claude Code و با یک نسخه پشتیبان، در آن می‌نویسد: برای Remote Control پس از پرسیدن، وقتی حسابی از اشتراک MCP بیرون می‌رود یا دوباره به آن می‌پیوندد، و برای `ccam mcp import`. `ccam mcp add` یک سرور را یک بار برای کل گروه اضافه می‌کند.
- موارد دیگر پیوندهایی به پوشه گروه هستند، پس تغییری که در یک حساب داده شود بلافاصله در بقیه دیده می‌شود. هنگام اجرا هیچ چیز کپی نمی‌شود.
- ورودها، `.claude.json` و وضعیت در حال اجرا هرگز مشترک نمی‌شوند.

### هر تغییر اول نشان داده و پشتیبان‌گیری می‌شود

`ccam group` و `ccam migrate` پیش از جابه‌جا کردن هر چیزی یک برنامه چاپ می‌کنند و می‌پرسند. وقتی فایلی بین یک حساب و گروهش فرق دارد، انتخاب با شماست: نسخه گروه را نگه دارید، نسخه خودتان را به کار ببرید یا JSON را ادغام کنید؛ درون پوشه‌ها نسخه گروه می‌ماند و برنامه فایل‌هایی را که فرق دارند نام می‌برد. نسخه‌های اصلی به `.ccam-backup/<time>/` می‌روند، حساب حذف‌شده از سیستم خارج می‌شود و پوشه‌اش به یک پوشه زباله‌دان می‌رود و فایل‌ها با یک تغییر نام جایگزین می‌شوند، پس نوشتنی که نیمه‌کاره قطع شود فایل قدیمی را باقی می‌گذارد. `--dry-run` نشان می‌دهد اجرا، اشتراک، مهاجرت، میان‌برها، به‌روزرسانی‌ها و تعمیرها چه خواهند کرد. `ccam doctor --fix` پیوندها و مجوزهای خراب را تعمیر می‌کند.

### همان گفتگو در حساب بعدی

`ccam next --auto --continue` مصرف همه حساب‌ها را هم‌زمان می‌پرسد، حسابی با بیشترین ظرفیت را باز می‌کند و گفتگو را ادامه می‌دهد. با تاریخچه مشترک همان گفتگوست؛ بدون آن، Claude Code گفتگو را در حساب جدید کپی می‌کند (`--resume <file> --fork-session`) و ccam می‌گوید پاسخ اول چند توکن را دوباره می‌خواند.

وقتی سقف مصرف یک نشست را متوقف کند، هوک پلاگین ccam یک اعلان نشان می‌دهد و `/ccam:switch` گفتگو را به حساب دیگر می‌سپارد. به‌طور پیش‌فرض، زمان جابه‌جایی را شما تعیین می‌کنید. با روشن بودن `auto_switch` (Linux، macOS)، ccam خودش نشست را جابه‌جا می‌کند، اما فقط پس از آنکه Claude Code آن را در سقف مصرف متوقف کرده باشد، و فقط به حسابی از همان نوع حسابی که از آن می‌رود: صندلی دیگری از همان سازمان، یا طرح شخصی دیگری ([جزئیات](/features/next#auto-switch)).

هیچ چیز مصرف شما را در پس‌زمینه زیر نظر نمی‌گیرد، و به‌طور پیش‌فرض انتخاب‌های خودکار هرگز کار را از یک سازمان Team یا Enterprise بیرون یا به درون آن نمی‌برند، پس یک گفتگوی شرکتی هرگز به‌اشتباه در یک حساب شخصی نمی‌افتد. وقتی مصرف یک حساب به ۹۰٪ برسد، خط وضعیت این فرمان را پیشنهاد می‌کند.

اسکریپت‌ها نمی‌توانند منتظر شما بمانند، پس `ccam --fallback work -p "…"` به جای آن‌ها جابه‌جا می‌شود: وقتی حساب به سقفش برسد، همان فرمان دوباره با حسابی که بیشترین ظرفیت را دارد اجرا می‌شود و فقط خروجی اجرایی که به پایان رسیده چاپ می‌شود. خطایی که از سقف مصرف نباشد همان‌طور که هست منتقل می‌شود. برای کارگرهای موازی، `ccam pick` به هر کدام حساب متفاوتی می‌دهد که ظرفیت دارد، و هر دو فرمان وقتی هیچ حسابی ظرفیتی نداشته باشد با کد ۷۵ خارج می‌شوند.

### حساب مناسب در هر پوشه

`ccam folder work ~/code/company` باعث می‌شود هر اجرای بدون نام حساب در آن پوشه از `work` استفاده کند، در حالی که بقیه پروژه‌های شما همان حساب پیش‌فرض را نگه می‌دارند. این تنظیم در همان `config.toml` است که هر اجرا می‌خواند، پس هیچ زمانی نمی‌گیرد.

### یک فایل اجرایی، دانلودهای بررسی‌شده

ccam یک فایل اجرایی ایستا با حجم حدود 10 MB است و هیچ محیط اجرایی برای نصب نمی‌خواهد، برای Linux، macOS و Windows. اسکریپت‌های نصب (`install.sh`، `install.ps1`) و `ccam update` هر دانلود را با چک‌سام‌های SHA-256 نسخه منتشرشده بررسی می‌کنند و ccam هرگز بدون پرسیدن به‌روز نمی‌شود. هیچ تله‌متری ندارد: تنها درخواست‌هایی که می‌فرستد، پرس‌وجوهای مصرف حساب‌های شما از Anthropic است، به‌صورت موازی با سقف زمانی ۳ ثانیه و حافظه نهان ۶۰ ثانیه‌ای، بررسی نسخه جدیدتر در GitHub توسط داشبورد هنگام باز شدنش، و دانلودهایی که خودتان درخواست می‌کنید. با `usage_source = "claude"` حتی این درخواست‌ها هم از طریق Claude Code انجام می‌شوند و ccam هیچ توکنی نمی‌فرستد.

## جاهایی که ابزارهای دیگر بیشتر انجام می‌دهند

- claude-swap، clauth، cux، CAAM و CCSwitcher می‌توانند وقتی مصرف یک حساب از آستانه بگذرد، یک نشست تعاملی در حال اجرا را خودشان جابه‌جا کنند. ccam اجراهای `-p` را با `--fallback` جابه‌جا می‌کند، و یک نشست تعاملی را فقط با روشن بودن `auto_switch` (Linux، macOS) و فقط پس از آنکه Claude Code آن را در سقف مصرف متوقف کرده باشد، خودش جابه‌جا می‌کند؛ در غیر این صورت خودتان آن را جابه‌جا می‌کنید، با یک اعلان هنگام رسیدن به سقف و `/ccam:switch`.
- در Windows بدون Developer Mode، ccam پوشه‌ها را مشترک می‌کند اما نمی‌تواند فایل‌های تکی مانند `settings.json` را مشترک کند (آن‌وقت نخستین `ccam add` فقط سرورهای MCP و افزونه‌ها را مشترک می‌کند)؛ claude-swap و CCS در آنجا به جای آن کپی‌شان می‌کنند.
- CCSwitcher، Claude Switcher و claude-swap مصرف را در نوار منوی macOS نشان می‌دهند.
- CCS، clausona، CAAM، clauth، ccswap و Claude Switcher، Codex و دیگر عامل‌های کدنویسی را هم مدیریت می‌کنند.
- clausona همچنین افزونه‌ها را برای هر حساب روشن و خاموش می‌کند (`ccam ext` در ccam فقط آن‌ها را نشان می‌دهد)، هزینه توکن را خودش به‌صورت محلی دنبال می‌کند (ccam این کار را به [ccusage](https://ccusage.com) می‌سپارد: `ccam ccusage`) و پلاگین‌هایی برای Claude Code دارد که ناوگانی از کارگرها را در tmux و ترمینال‌های دیگر اجرا می‌کنند.
- CAAM، CCSwitcher و Claude Switcher با Homebrew نصب می‌شوند و clauth و CAAM چک‌سام‌های نسخه‌هایشان را امضا می‌کنند. ccam با اسکریپت خودش، یک بسته `.deb` یا `go install` نصب می‌شود و چک‌سام‌ها را بدون امضا بررسی می‌کند.

## کدام مناسب شماست؟

اگر در هر لحظه از یک حساب استفاده می‌کنید، یا می‌خواهید یک نشست در حال اجرا بدون راه‌اندازی دوباره حسابش را عوض کند، حتی پیش از رسیدن به سقف، ابزاری را انتخاب کنید که ورود را عوض می‌کند. اگر حساب‌ها را کنار هم، یک پیکربندی مشترک، همان گفتگو را در حساب بعدی و، به‌طور پیش‌فرض، هیچ چیزی در کنار Claude Code در حال اجرا نمی‌خواهید، روی Linux، macOS یا Windows، ccam را انتخاب کنید. اگر به هیچ اشتراکی نیاز ندارید، [نام‌های مستعار ساده شل](/compare/aliases) کافی‌اند.

اینکه اجازه دارید از بیش از یک حساب استفاده کنید یا نه، به شرایطی بستگی دارد که برای هر حساب اعمال می‌شود. پیش از شروع، آن شرایط را بخوانید.

**صندلی‌های Team و Enterprise.** انتخاب خودکار حساب (`ccam next`، `--fallback`، `ccam pick`، کلید `n` در داشبورد و، وقتی آن را روشن کنید، [`auto_switch`](/features/next#auto-switch)) میان صندلی‌های همان سازمان Claude Team یا Enterprise هم جابه‌جا می‌شود، که ممکن است شرایط Anthropic را نقض کند. پیش از آنکه به آن تکیه کنید، [پرسش‌های متداول](/docs/faq#am-i-allowed-to-use-several-claude-code-accounts) را بخوانید و از سازمان خود و Anthropic بپرسید.
