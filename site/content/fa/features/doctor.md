`ccam doctor` نصب ccam شما را بررسی می‌کند: فایل اجرایی Claude Code، پوشه، ورود و پیوندهای اشتراک هر حساب، سرورهای MCP مشترک، نقطه پایانی مصرف و فرمان‌های میان‌بر شما. `ccam doctor --fix` آنچه را بدون از دست رفتن داده ممکن است تعمیر می‌کند و هر فایلی را که جایگزین می‌کند ابتدا به یک پوشه پشتیبان منتقل می‌کند. وقتی `ccam <name>` به دلیل مشکل پیوند اشتراک متوقف می‌شود، پس از بازگرداندن دستی فایل‌ها یا پس از به‌روزرسانی Claude Code آن را اجرا کنید.

## نحوه استفاده

```sh
ccam doctor                  # check everything, change nothing
ccam doctor --fix            # check, then repair what is safe to repair
ccam --dry-run doctor --fix  # report only: what --fix would repair and set aside
```

خط اول همه حساب‌ها را یک‌جا علامت‌گذاری می‌کند تا پیش از خواندن هر چیز دیگری ببینید مشکلات کجا هستند. زیر آن، هر حساب یک کادر دارد و یافته‌هایی که به هیچ حسابی تعلق ندارند (Claude Code، متغیرهای محیطی، افزونه‌ها، سرورهای MCP، میان‌برها، قواعد پوشه، گروه‌ها و تنظیمات، `auto_switch`) در کادر `General` قرار می‌گیرند. عنوان کادر بدترین علامت حساب و تعداد مشکلات آن را نشان می‌دهد. هر ردیف داخل کادر یک حوزه بررسی‌شده است، همیشه ابتدا `Folder`، `Login` و `Share links` به همین ترتیب و سپس بقیه، با یک علامت: `✔` درست، `ℹ` اطلاعات، `⚠` هشدار، `✘` خطا. پوشه‌ای که مشکلی ندارد `✔ Folder  OK` را نشان می‌دهد.

```console
$ ccam doctor

 │ ✔ Claude Code  Claude Code 2.1.309 (Claude Code)                          │

 │ ⚠ Shortcuts    missing shortcuts in /home/me/.local/bin: ccp              │

 ╭─ ✘ personal · 3 problems ─────────────────────────────────────────────────╮
 │ ⚠ Folder       folder permissions are 755 (should be 0700)                │
 │ ℹ              unknown entries (ccam knows the folder layout of Claude    │
 │                Code 2.1.309; it may have changed): newthing               │
 │ ⚠ Login        .credentials.json permissions are 644 (should be 0600)     │
 │ ✔              login valid (me@example.com, Claude Team · Acme)           │
 │ ✘ Share links  /home/me/.local/share/ccam/profiles/personal/settings.json │
 │                : set to shared but is a real file, not a link             │
 │ ✔ Usage        usage lookup OK                                            │

 │ ⚠ Login        not logged in → `ccam login work`                          │

`ccam doctor --fix` repairs what it can.
```

با `--fix`، هر یافته‌ای که تعمیر شده با `→ fixed` تمام می‌شود و دیگر مشکل به حساب نمی‌آید:

```console

 ╰───────────────────────────────────────────────────────────────────────────╯
```

در ترمینال، کادرها به اندازه عرض آن درمی‌آیند و پیام‌های طولانی به خط بعد می‌روند، با رنگ‌های خود ترمینال (`NO_COLOR` آن‌ها را خاموش می‌کند). عرض یک کادر هرگز کمتر از ۲۹ ستون نیست، پس در ترمینال باریک هیچ واژه‌ای بریده نمی‌شود. وقتی خروجی به یک لوله یا فایل فرستاده شود، رنگی ندارد و هیچ پیامی شکسته یا بریده نمی‌شود، پس `ccam doctor | grep settings.json` کل خط را پیدا می‌کند؛ در این حالت عرض هر کادر به اندازه طولانی‌ترین خط است. زبانه Health داشبورد همین کادرها را نشان می‌دهد.

## گزینه‌ها

| گزینه | کاری که انجام می‌دهد | پیش‌فرض |
| --- | --- | --- |
| `--fix` | آنچه را تعمیرش بی‌خطر است تعمیر می‌کند (از فایل‌های تغییریافته پشتیبان گرفته می‌شود) | خاموش |
| `--dry-run` (سراسری) | همه بررسی‌ها را اجرا می‌کند اما حتی با `--fix` چیزی را تعمیر نمی‌کند | خاموش |

`ccam doctor` آرگومانی نمی‌پذیرد. از `--dry-run` پیروی می‌کند: `ccam --dry-run doctor --fix` یافته‌های `ccam doctor` را چاپ می‌کند، آنچه را `--fix` کنار می‌گذاشت اضافه می‌کند و چیزی را تغییر نمی‌دهد:

```text
ℹ settings.json differs from the group's copy: --fix would use the group's, and move this account's copy to /home/me/.local/share/ccam/profiles/personal/.ccam-backup/20261023-212543/settings.json
```

کد خروج وقتی دست‌کم یک یافته `✘` تعمیرنشده بماند `1` و در غیر این صورت `0` است. هشدارها و اطلاعات هرگز اجرا را ناموفق نمی‌کنند. وقتی اجرا بدون `--fix` ناموفق باشد، ccam با یک خط خالی و `` `ccam doctor --fix` repairs what it can. `` تمام می‌شود. پیکربندی‌ای که بارگذاری نشود هم با `1` و یک خطای `ccam:` تمام می‌شود.

## نحوه کار

`internal/cli/doctor.go` فایل `~/.config/ccam/config.toml` را بارگذاری می‌کند و `doctor.Run` را در `internal/doctor/doctor.go` فرا می‌خواند که بررسی‌ها را به ترتیبی ثابت اجرا می‌کند و یافته‌ها را، هر کدام همراه با حسابی که به آن تعلق دارد و حوزه‌ای که بررسی کرده، برمی‌گرداند. `tui.HealthReport` آن‌ها را در کادرها گروه‌بندی می‌کند. `--fix` به‌صورت `Options.Fix` منتقل می‌شود که در اجرای آزمایشی false است.

بخش میانی برای هر حساب یک بار اجرا می‌شود. بررسی‌ها و کاری که `--fix` برای هر یک انجام می‌دهد:

1. **نسخه Claude Code** (`checkClaude`). فایل اجرایی `claude` را همان‌طور که اجراکننده پیدا می‌کند پیدا می‌کند و `claude --version` را اجرا می‌کند. نبودن فایل اجرایی، `claude_bin`ی که فایل اجرایی نیست، یا ناموفق بودن `--version` خطاست. تعمیری ندارد.
2. **اطلاعات ورود در محیط** (`checkAuthEnv`). وقتی `CLAUDE_CODE_OAUTH_TOKEN`، `ANTHROPIC_API_KEY` یا `ANTHROPIC_AUTH_TOKEN` تنظیم شده باشد هشدار می‌دهد: هر حسابی که از آن shell اجرا شود آن را به ارث می‌برد و Claude Code آن را به ورود خود حساب ترجیح می‌دهد. تعمیری ندارد؛ خودتان آن را حذف کنید.
3. **پوشه** (`checkProfile`). نبودن پوشه حساب خطاست و بررسی‌های آن حساب را پایان می‌دهد. مجوزهایی که هر بیتی برای گروه یا دیگران داشته باشند هشدارند؛ `--fix` فرمان `chmod 0700` را اجرا می‌کند. یک `~/.claude` واردشده که کنار `~/.claude.json` یک `.claude.json` از خودش دارد اطلاعات است: در این صورت `ccam main` و `claude` معمولی جزئیات ورود و سرورهای MCP جداگانه نگه می‌دارند. Windows بیت مجوز ندارد، پس این بررسی و بررسی `0600` در ادامه آنجا انجام نمی‌شوند؛ پوشه‌ای که در پروفایل کاربری شماست با فهرست دسترسی خودش محافظت می‌شود.
4. **فایل ورود** (`checkCredentials`). `.credentials.json` با `lstat` بررسی می‌شود. پیوند نمادین خطاست، چون هر حساب باید توکن خودش را داشته باشد، و تعمیر نمی‌شود. مجوزی غیر از `0600` هشدار است؛ `--fix` فرمان `chmod 0600` را اجرا می‌کند. سپس ورود خوانده می‌شود (روی macOS ابتدا از Keychain). نبودن ورود، یا فایل ورودی که ورودی در آن نیست، هشداری است که به `ccam login <name>` ارجاع می‌دهد. توکن تمدید منقضی‌شده، یا ورودی که Claude Code پس از رد شدن توسط سرور پاک کرده، خطای `` login expired → `ccam login <name>` `` است؛ توکن دسترسی منقضی‌شده فقط اطلاعات است، چون Claude Code آن را در اجرای بعدی تمدید می‌کند. ورودی که در Credential Manager سیستم Windows نگه داشته می‌شود اطلاعات است، چون ccam نمی‌تواند آن را بخواند. ورود معتبر ایمیلی را که پوشه اکنون با آن وارد شده و طرح اشتراک را نشان می‌دهد (`login valid (dev@company.com, Claude Team · Acme)`). هیچ‌کدام از این‌ها تعمیر نمی‌شوند؛ `ccam login --expired` به همه حساب‌هایی که نیاز دارند وارد می‌شود.
5. **پیوندهای اشتراک** (`share.Check`). هر مسیر در `share.Layout` را با گروه‌های حساب مقایسه می‌کند و فقط از `lstat` و `readlink` استفاده می‌کند. پنج نوع مشکل را گزارش می‌دهد: پیوند گم‌شده، پیوندی که به جای دیگری اشاره می‌کند، فایل واقعی در جایی که باید پیوند باشد، پیوند باقی‌مانده برای موردی که اکنون محلی است، و پیوند درستی که پوشه گروهش وجود ندارد (`the group folder it links to is missing (…), so Claude Code cannot save there (ccam doctor --fix makes it)`؛ اجرا این را بررسی نمی‌کند). پیوند گم‌شده و پوشه گروه گم‌شده هشدارند و بقیه خطا هستند. کپی برگشتی از گروه که نیمه‌کاره متوقف شده باشد هم گزارش می‌شود: `--fix` یک کپی کامل آماده‌شده را سر جایش می‌گذارد، اما وقتی مسیر از آن پس دوباره ساخته شده باشد (با یک اجرا)، پوشه‌ای را که کپی کامل در آن است نام می‌برد تا خودتان آن را مرتب کنید. مسیرهایی که در نسخه‌ای جدیدتر از ccam به یک مورد اضافه شده‌اند (`file-history/`، `tasks/` و `paste-cache/` برای تاریخچه، `keybindings.json` برای تنظیمات) تا وقتی حساب هنوز نسخه خودش را دارد فقط هشدارند: `is not shared with the group yet (ccam doctor --fix shares it; if the group has its own copy, that one is kept and this one backed up)`. اجرا هرگز به خاطر آن‌ها متوقف نمی‌شود.
6. **ورودی‌های ناشناخته** (`checkUnknownEntries`). نام‌های سطح بالای پوشه حساب را که ccam نمی‌شناسد (`share.Known`) فهرست می‌کند، به‌عنوان نشانه‌ای از اینکه ساختار Claude Code تغییر کرده است. فقط اطلاعات است.
7. **مسیرهای افزونه** (`checkPlugins`). فهرست‌های افزونه (`installed_plugins.json`، `known_marketplaces.json`) مسیرهای مطلق ذخیره می‌کنند. در `plugins/` هر گروه، مسیرهایی که از پوشه یک حساب می‌گذرند با حذف یا تغییر نام آن حساب خراب می‌شوند. `--fix` آن‌ها را با `profile.RewritePluginPaths`، که فایل فهرست را به‌صورت اتمی می‌نویسد، به پوشه گروه بازنویسی می‌کند.
8. **سرورهای MCP** (`checkMCP`). `mcp.json` هر گروه را یک بار بارگذاری می‌کند. فایلی که خوانده نشود خطاست؛ سروری که از `mcp.Validate` رد نشود هشدار است. سرورهایی در `~/.claude.json` مربوط به `claude` معمولی که هیچ حسابی بارگذاری‌شان نمی‌کند هشداری هستند که فرمان `ccam migrate --mcp` را که آن‌ها را کپی می‌کند نام می‌برد (با `--group <a|b>` وقتی چند گروه MCP را به اشتراک می‌گذارند). سرورهایی که فقط یک حساب از یک گروه دارد اطلاعاتی همراه با فرمان `ccam mcp import` هستند که آن‌ها را به اشتراک می‌گذارد، و حسابی که وارد سرورهای MCP نشده در حالی که حساب‌های دیگر وارد شده‌اند هشداری می‌گیرد که با `/mcp` وارد شود (ccam هرگز ورودها را کپی نمی‌کند). تعمیری ندارد.
9. **قالب پاسخ مصرف** (`checkUsageFormat`). بدون حافظه نهان، از نقطه پایانی مصرف برای حساب‌ها یکی پس از دیگری پرس‌وجو می‌کند تا یکی پاسخ دهد، همه در یک محدودیت ۴ ثانیه‌ای. با `usage_source = "claude"` به جای آن برای یک حساب از Claude Code می‌پرسد. اگر پاسخ دیگر قابل تجزیه نباشد، هشدار می‌دهد که `ccam usage` به حافظه نهان خط وضعیت برمی‌گردد؛ وقتی هیچ حسابی پاسخ ندهد، این را به‌عنوان اطلاعات می‌گوید (`could not check the usage response format: …`). این تنها بررسی‌ای است که از شبکه استفاده می‌کند.
10. **میان‌برها** (`checkShims`). فقط وقتی حسابی میان‌بر داشته باشد. پیوندهای گم‌شده در `~/.local/bin` هشدارند، و همچنین میان‌برهایی که ccam ساخته و هنوز یک ccam قدیمی‌تر را اجرا می‌کنند، ccamی که جایگزین یا جابه‌جا شده است (`shortcuts in <bin> that run another ccam (one replaced or moved): …`)؛ `--fix` تابع `shim.Install` را فرا می‌خواند که فقط پیوندهایی را که ccam ساخته و در `~/.local/state/ccam/shortcuts.json` ثبت کرده است می‌سازد و تازه می‌کند، و هرگز به فایل‌های دیگر دست نمی‌زند. هشدار فقط وقتی با `→ fixed` تمام می‌شود که همه آن پیوندها ساخته شده باشند؛ اگر یکی ساخته نشود، دلیلش اضافه می‌شود. میان‌بری که ccam دیگری را اجرا می‌کند که هنوز نصب است کار می‌کند و اطلاعات است؛ `--fix` آن را به این ccam هدایت می‌کند. پوشه bin که در `PATH` نباشد هشدار است و تعمیر نمی‌شود.
11. **پوشه‌ها** (`checkFolders`). فقط وقتی ورودی‌های [`ccam folder`](/features/folder) وجود داشته باشند. ورودی‌ای که حسابش وجود ندارد خطاست و ورودی‌ای که پوشه‌اش از بین رفته هشدار است. هیچ‌کدام تعمیر نمی‌شوند، چون حذف یک ورودی حسابی را که آنجا اجرا می‌شود تغییر می‌دهد.
12. **گروه‌ها و تنظیمات** (`checkGroups`). عضو گروهی که حساب نیست، حسابی که نامش از آن پس به یک فرمان ccam تبدیل شده (آن را با `ccam run <name>` اجرا کنید یا نامش را تغییر دهید)، یک `theme` یا `usage_source` ناشناخته، و خط‌هایی از `config.toml` که ccam نمی‌خواند هشدارند. مورد آخر معمولاً تنظیمی است که زیر یک جدول `[[group]]`، `[[profile]]` یا `[[folder]]` نوشته شده و به همان جدول تعلق دارد (`config.toml line 43: relay is read as part of the [profile.login] table above it; settings for all accounts go above the first [[group]], [[profile]] or [[folder]]`)؛ فرمان‌هایی که پیکربندی را تغییر می‌دهند تا رفع آن سر باز می‌زنند. تعمیری ندارد.
13. **ورودها** (`checkIdentities`). می‌خواند که هر پوشه از روی `.claude.json` خودش به چه حسابی وارد شده است. پوشه‌ای که اکنون به حسابی جز آنچه `ccam login` ثبت کرده وارد شده است (برای مثال پس از `/login` درون یک نشست) هشدار است؛ حسابی که سابقه ورود ندارد، مانند یک حساب واردشده یا حسابی که با یک ccam قدیمی‌تر ساخته شده، با ایمیل ثبت‌شده‌اش مقایسه می‌شود. پوشه‌ای که به همان حساب Claude پوشه دیگری وارد شده باشد هم هشدار است: آن دو سقف‌های مصرف مشترکی دارند. پوشه‌ای که همان توکن ورود پوشه دیگری را دارد، یعنی یک پوشه کپی‌شده (از جمله `~/.claude` مربوط به `claude` معمولی)، خطاست، چون هر کدام زودتر آن را تمدید کند دیگری را از سیستم خارج می‌کند؛ برای دادن ورود جداگانه به آن، `ccam login <name>` را اجرا کنید. تعمیری ندارد.
14. **`auto_switch`** (`checkAutoSwitch`). فقط وقتی `auto_switch = true` باشد. اطلاعاتی در کادر `General` می‌گوید `auto_switch` چه می‌کند و به [توضیح آن](/features/next#auto-switch) پیوند می‌دهد. برای هر طرح دارای صندلی در میان حساب‌ها (Claude Team، Claude Enterprise)، یک خط آن‌ها را نام می‌برد، می‌گوید که `auto_switch` یک نشست را میان صندلی‌های یک سازمان جابه‌جا می‌کند، قاعده صندلی Anthropic را همراه با پیوند مرکز راهنما نقل می‌کند و تصمیم را به شما وامی‌گذارد. Claude Code قدیمی‌تر از 2.1.214، که فرایند خود را به هوک‌ها نمی‌گوید (`CLAUDE_PID`)، در آنجا هشدار است، چون هیچ نشستی را نمی‌توان جابه‌جا کرد. حسابی که پلاگین ccam را ندارد، یا پلاگینش خاموش است، در کادر خودش هشداری می‌گیرد همراه با فرمانی که آن را در Claude Code درست می‌کند: `auto_switch is on, but work does not have the ccam plugin, so its sessions are not moved. In Claude Code as work: /plugin install ccam --marketplace jhyunwoo/ccam` (یا `/plugin enable ccam@ccam`). حساب‌های کلید API کنار گذاشته می‌شوند. در Windows تنها خط این است: `auto_switch is ignored on Windows; with relay = true, /ccam:switch and then /exit carry a conversation on.` تعمیری ندارد.

پیش از حساب‌ها، یک **تغییر گروه‌ها** که نیمه‌کاره متوقف شده باشد خطایی در کادر `General` است: ``the last change of groups stopped halfway (ccam doctor --fix finishes it; noted in ~/.local/state/ccam/group-change.json)``. `--fix` آن را به ترتیبی که برنامه‌ریزی شده بود، با پاسخ‌هایی که به تعارض‌هایش داده شده بود، تمام می‌کند؛ تا آن زمان هیچ تغییر گروه، تغییر نام یا حذف دیگری شروع نمی‌شود. حساب‌هایی که در آن هستند تا پایان آن فقط پیوندهای گم‌شده‌شان ساخته می‌شود. اگر نتوان آن را تمام کرد، خطا می‌گوید که حذف آن فایل از بقیه تغییر چشم می‌پوشد. `ccam --dry-run doctor --fix` ترتیب را نشان می‌دهد (`--fix finishes it in its order (b, a, c), with the answers given to its conflicts`) و اینکه بخش هر حساب چه چیزی را کنار می‌گذاشت. تغییری که ccam دیگری همین حالا انجام می‌دهد اطلاعات است، و تا وقتی در جریان است `--fix` هیچ پیوند اشتراکی را تعمیر نمی‌کند (`its share links are not repaired while another ccam changes the groups; …`). `--fix` هنگام تعمیر `~/.local/state/ccam/group-change.lock` را نگه می‌دارد و پس از تمام کردن یک تغییر، `config.toml` را دوباره می‌خواند.

### تعمیر پیوندهای اشتراک

مسیر اجرا پیوند گم‌شده را همان‌جا می‌سازد، اما برای هر چیزی که ممکن است داده را از بین ببرد متوقف می‌شود و شما را به اینجا ارجاع می‌دهد:

```console
$ ccam work
ccam: stopped because of share link problems:
  /home/me/.local/share/ccam/profiles/work/CLAUDE.md: set to shared but is a real file, not a link
Repair them with `ccam doctor --fix`, then run again
```

برای هر مشکل پیوند اشتراک، `--fix` تابع `share.Build` را با تنظیمات اشتراک حساب هم به‌عنوان وضعیت فعلی و هم وضعیت هدف فرا می‌خواند و سپس `Plan.Apply` را. `Build` همه مراحل را از آنچه روی دیسک هست دوباره به دست می‌آورد، همان برنامه‌ای که یک تغییر `ccam group` استفاده می‌کند، بنابراین تعمیر از همان قواعد پیوستن به یک گروه پیروی می‌کند.

<!-- motion:doctor-repair -->

در اینجا `settings.json` یک فایل واقعی است. چون گروه از قبل `settings.json` متفاوتی دارد، تعارض با انتخاب پیش‌فرض خود، `KeepGroup`، حل می‌شود و نسخه گروه باقی می‌ماند. فایل حساب به `.ccam-backup/<time>/settings.json` داخل پوشه حساب منتقل می‌شود و `os.Symlink` مسیر را به گروه پیوند می‌دهد. `--fix` این را می‌گوید: `settings.json differed from the group's copy, which it now uses; this account's copy is in …`. موارد دیگر:

- اگر گروه هنوز نسخه‌ای نداشته باشد، فایل حساب به گروه منتقل می‌شود و نخستین محتوای آن می‌شود.
- برای یک پوشه، فایل‌هایی که گروه ندارد به گروه منتقل می‌شوند. فایل‌هایی که گروه بایت به بایت همان‌ها را دارد کنار گذاشته می‌شوند، و آن‌هایی که فرق دارند به پشتیبان می‌روند و در یک یادداشت نام برده می‌شوند (`projects: 1 file differs from the group's copy (-w/memory/MEMORY.md); the group's is kept, the account's stays in …`).
- پوشه گروه گم‌شده ابتدا ساخته می‌شود.
- برای `history.jsonl`، پیش‌فرض `merge by line` است: خطوط گروه و سپس خطوط جدید شما. نسخه قبلی گروه در `.ccam-backup/<time>/group/` ذخیره می‌شود.
- پیوند به گروه دیگر جایگزین می‌شود. پیوند به پوشه‌ای بیرون از ccam به پشتیبان می‌رود و اگر گروه خالی باشد، محتوای آن نخستین محتوای گروه می‌شود.
- پیوندی که برای موردی که اکنون محلی است باقی مانده حذف می‌شود و حساب یک نسخه از محتوای گروه را می‌گیرد.

به جز حذف پیوندها و کنار گذاشتن فایل‌هایی که گروه بایت به بایت همان‌ها را دارد، هر مرحله داده را به گروه یا پوشه پشتیبان منتقل می‌کند. هیچ چیزی از دست نمی‌رود.

## ایمنی و موارد خاص

- `ccam doctor` بدون گزینه هرگز چیزی را تغییر نمی‌دهد. برای اطمینان در اسکریپت‌ها، `--dry-run` را همراه `--fix` به کار ببرید.
- برای حسابی که در حال اجراست، Claude Code به هر شکلی که شروع شده باشد، `doctor --fix` فقط پیوندهای ناموجود و پوشه‌های گروه ناموجود را می‌سازد، که چیزی را از دست نمی‌دهد. وقتی چیز دیگری باقی بماند، `` is running; quit Claude Code there, then run `ccam doctor --fix` again to repair the rest `` را اضافه می‌کند، چون نشست همچنان در فایل‌هایی می‌نویسد که تعمیر آن‌ها را جابه‌جا می‌کرد.
- اگر تعمیر اشتراک ناموفق باشد، ccam برای آن حساب `could not repair share links: <error>` را گزارش می‌دهد و بررسی ورودی‌های ناشناخته آن را رد می‌کند. حساب‌های دیگر همچنان بررسی می‌شوند.
- اگر یک تغییر `ccam group` در میانه کار ناموفق شود، گروه‌های جدید از قبل ذخیره شده‌اند و تغییر در `~/.local/state/ccam/group-change.json` یادداشت می‌شود؛ ccam به شما می‌گوید کار را با `ccam doctor --fix` تمام کنید که بقیه آن را، از جمله مرحله‌های MCP، انجام می‌دهد.
- `.credentials.json` پیوندشده، ورود منقضی‌شده و اطلاعات ورود محیطی گزارش می‌شوند اما هرگز تغییر داده نمی‌شوند.
- بازنویسی فهرست‌های افزونه به‌صورت اتمی نوشته می‌شود اما در `.ccam-backup/` کپی نمی‌شود.
