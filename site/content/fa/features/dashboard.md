`ccam` بدون آرگومان، وقتی ورودی و خروجی استاندارد ترمینال باشند، یک داشبورد تمام‌صفحه باز می‌کند؛ در غیر این صورت `ccam list` را چاپ می‌کند. داشبورد هر حساب را همراه با مصرف و گروه‌هایش نشان می‌دهد و همان کارهایی را انجام می‌دهد که فرمان‌ها انجام می‌دهند: اجرا، افزودن، ورود، تغییر گروه‌ها، تعیین قواعد پوشه، فهرست کردن نشست‌های پس‌زمینه، بررسی و تعمیر. اجرای یک حساب، یا وصل شدن به یک نشست پس‌زمینه، داشبورد را می‌بندد؛ افزودن حساب یا ورود، ترمینال را برای لحظه‌ای در اختیار آن می‌گذارد و سپس به داشبورد برمی‌گردد.

```console
 ccam v0.10.0 · 3 accounts · 2 groups     ✔ default · ▸ this folder · • running

  Accounts   Agents   Groups   Folders   Extensions   Health    auto_switch off
 Your Claude accounts and their usage limits; enter launches the selected one.

    # Account      5-hour       Weekly       Fable        Last  Groups
   1. personal ✔   ████▍░  72%  ██▌░░░  41%  █████▎  88%  -     default
 ❯ 2. work      ▸• █▌░░░░  25%  ██████ 100%  ▋░░░░░  10%  -     default team
   3. side         ✘ not logged in                        -     no group

 enter to launch · n for most room · a to add · s for groups · ? for shortcuts
```

خط زیر نام زبانه‌ها در یک جمله می‌گوید زبانه فعلی برای چیست. در ترمینال عریض‌تر، زبانه Accounts ایمیل هر حساب را هم نشان می‌دهد. انتهای خط نام زبانه‌ها، در همه زبانه‌ها، نشان می‌دهد که [`auto_switch`](/features/next#auto-switch) روشن است یا نه (Linux و macOS؛ Windows این تنظیم را نادیده می‌گیرد). وقتی روشن باشد، زبانه Health فهرست می‌کند که هنوز چه چیزی برایش لازم است: Claude Code 2.1.214 یا جدیدتر، و روشن بودن پلاگین ccam در هر حسابی که با اشتراک Claude وارد می‌شود.

داشبورد هر بار که باز می‌شود، در پس‌زمینه از GitHub می‌پرسد که آیا نسخه جدیدتری از ccam وجود دارد؛ نخستین قاب هرگز منتظر آن نمی‌ماند و وقتی آفلاین هستید چیزی نشان داده نمی‌شود. اگر نسخه جدیدتری باشد، خطی زیر عنوان آن را پیشنهاد می‌کند:

```console
 ● ccam 0.10.2 is available (you have 0.10.1) · press U to update
```

`U` اول می‌پرسد و سپس به همان روش [`ccam update`](/features/update) به‌روزرسانی می‌کند: نسخه با چک‌سام‌های SHA-256 خودش بررسی می‌شود و در یک گام جای ccam را می‌گیرد. داشبوردی که در آن هستید هنوز نسخه قدیمی است، پس از آن خارج شوید و `ccam` را دوباره اجرا کنید. وقتی به‌روزرسانی در اینجا ممکن نباشد، مثلاً برای نسخه‌ای از ccam که از بسته `.deb` نصب شده، داشبورد همان توصیه `ccam update` را نشان می‌دهد و پیشنهاد را نگه می‌دارد.

نخستین قاب فقط از روی `config.toml` رسم می‌شود، در زمانی بسیار کمتر از ۱۰۰ میلی‌ثانیه؛ مصرف هر حساب به محض پاسخ دادن آن پر می‌شود. هر سقف نوار خودش را دارد: پنجره ۵ ساعته، پنجره هفتگی برای همه مدل‌ها، و پنجره هفتگی ویژه Fable؛ `-` یعنی حساب چنین پنجره‌ای ندارد. یک درصد در ۸۰٪ زرد و در ۱۰۰٪ قرمز می‌شود. اگر پرس‌وجویی ناموفق باشد، مقدارهای حافظه نهان کم‌رنگ نشان داده می‌شوند. پنجره‌ای که Claude Code پر گزارش کرده تا بازنشانی‌اش ۱۰۰٪ نشان می‌دهد. توکن دسترسی منقضی‌شده یک `⚠ token expired` کم‌رنگ نشان می‌دهد (Claude Code آن را در اجرای بعدی تمدید می‌کند)، در حالی که `⚠ login expired` یعنی حساب به `ccam login` نیاز دارد.

## زبانه‌ها

| زبانه | آنچه نشان می‌دهد | کلیدها |
| --- | --- | --- |
| Accounts | شماره، نام، ایمیل، نوارهای ۵ ساعته، هفتگی و Fable، آخرین استفاده، گروه‌ها؛ `✔` حساب پیش‌فرض، `▸` حساب این پوشه، `•` در حال اجرا (از جمله Claude Code که بدون ccam شروع شده است: `claude` معمولی، یک IDE، نشست‌های پس‌زمینه و daemon آن‌ها) | پایین‌تر |
| Agents | آنچه [`ccam agents`](/features/agents) فهرست می‌کند: نشست‌های پس‌زمینه و نشست‌های باز همه حساب‌ها، با وضعیت، پوشه و زمان شروعشان (پایین‌تر) | `enter` وصل شدن (مانند `ccam attach`)، `x` توقف، `r` بارگذاری دوباره |
| Groups | هر گروه، آنچه به اشتراک می‌گذارد و حساب‌هایش، و حساب‌هایی که در هیچ گروهی نیستند | `enter` ویرایش، `n` جدید، `e` تغییر نام، `x` حذف |
| Folders | قواعد [`ccam folder`](/features/folder) و قاعده‌ای که اینجا اعمال می‌شود، حتی وقتی از طریق یک پیوند نمادین به پوشه رسیده‌اید (قواعد جدید با پیوندهای حل‌شده ذخیره می‌شوند) | `n` استفاده از یک حساب در اینجا، `enter` تغییر، `x` حذف |
| Extensions | آنچه [`ccam ext`](/features/ext) نشان می‌دهد، هر افزونه یک بار همراه با گروه‌هایی که از آن‌ها می‌آید، `off:` حساب‌هایی که یک پلاگین در آن‌ها روشن نیست، سرورهای خود حساب که فقط برای این پوشه اعمال می‌شوند، `This folder's project`، و مشکلاتی که به هیچ حسابی تعلق ندارند | `r` بارگذاری دوباره |
| Health | آنچه [`ccam doctor`](/features/doctor) گزارش می‌دهد، به‌صورت یک کادر برای هر حساب (پایین‌تر) | `f` تعمیر کادر انتخاب‌شده، `F` تعمیر همه (`doctor --fix`)، `↑`/`↓` جابه‌جایی بین کادرها |

`←`/`→` یا `Tab` زبانه‌ها را عوض می‌کنند، `?` کلیدهای زبانه فعلی را فهرست می‌کند، `r` مصرف را با دور زدن حافظه نهان کوتاه‌مدت تازه می‌کند و زبانه‌های Agents، Extensions و Health را دوباره بارگذاری می‌کند، و `q` یا `Esc` خارج می‌شود.

## زبانه Health

زبانه Health هنگام باز شدن، بررسی‌های [`ccam doctor`](/features/doctor) را اجرا می‌کند و همان نما را رسم می‌کند: خط اولی با یک علامت برای هر حساب، و سپس یک کادر برای هر حساب. هر ردیف در یک کادر یک حوزه بررسی‌شده است، ابتدا `Folder`، `Login` و `Share links`، با علامت `✔` درست، `ℹ` اطلاعات، `⚠` هشدار یا `✘` خطا، تا فوراً ببینید کدام حساب مشکل دارد و کجا. یافته‌هایی که به هیچ حسابی تعلق ندارند در کادر `General` قرار می‌گیرند.

```console
 ✘ personal   ⚠ work

 ╭─ ✘ personal · 3 problems ─────────────────────────────────────────────────╮
 │ ⚠ Folder       folder permissions are 755 (should be 0700)                │
 │ ℹ              unknown entries (ccam knows the folder layout of Claude    │
 │                Code 2.1.309; it may have changed): newthing               │
 │ ⚠ Login        .credentials.json permissions are 644 (should be 0600)     │
 │ ✔              login valid (me@example.com, Claude Team · Acme)           │
 │ ✘ Share links  /home/me/.local/share/ccam/profiles/personal/settings.json │
 │                : set to shared but is a real file, not a link             │
 │ ✔ Usage        usage lookup OK                                            │
 ╰───────────────────────────────────────────────────────────────────────────╯
 ╭─ ⚠ work · 1 problem ──────────────────────────────────────────────────────╮
 │ ✔ Folder       OK                                                         │
 │ ⚠ Login        not logged in → `ccam login work`                          │
 │ ✔ Share links  share links OK                                             │
 ╰───────────────────────────────────────────────────────────────────────────╯

 4 problems; f repairs the selected box, F all of them (ccam doctor --fix).
```

`↑`/`↓` از کادری به کادر دیگر می‌روند و کادر انتخاب‌شده حاشیه‌ای به رنگ تأکیدی دارد. `f` فقط کادر انتخاب‌شده را تعمیر می‌کند، همان‌طور که `ccam doctor --fix` تعمیر می‌کند: در کادر یک حساب فقط همان حساب را تعمیر می‌کند و در کادر `General` یافته‌هایی را که به هیچ حسابی تعلق ندارند (مسیرهای افزونه‌ها و میان‌برها)؛ بقیه حساب‌ها فقط دوباره بررسی می‌شوند. ابتدا می‌پرسد (``Like `ccam doctor --fix`: missing links and group folders are made, and a real file where a link belongs is backed up first; where the group has its own copy, the account then sees the group's. Nothing is lost.``)، و کادری که چیزی برای تعمیر ندارد فقط می‌گوید `nothing to repair in <name>`. `F` همه چیز را یک‌جا تعمیر می‌کند، مانند `ccam doctor --fix`، و `r` دوباره بررسی می‌کند.

## زبانه Agents

زبانه Agents همان چیزی را نشان می‌دهد که [`ccam agents`](/features/agents) چاپ می‌کند: نشست‌های پس‌زمینه و نشست‌های باز همه حساب‌ها، همراه با حسابی که هر کدام به آن تعلق دارد. وقتی زبانه را برای نخستین بار باز می‌کنید، با `r`، پس از یک توقف و پس از تغییری در پیکربندی، از Claude Code همه حساب‌ها هم‌زمان می‌پرسد (`claude agents --json`، هر کدام با مهلت ۱۵ ثانیه) و تا وقتی همه پاسخ دهند `Asking every account's Claude Code for its sessions…` را نشان می‌دهد.

```console
  Accounts   Agents   Groups   Folders   Extensions   Health    auto_switch off
 Background agents and open sessions of every account; enter attaches to one.

    Account   ID        Name   State          Folder      Started
 ❯  work      -         -      open (busy)    ~/code/web  now
    personal  49ec0028  probe  blocked, idle  ~/code/app  12m

 ✘ lab: could not list its sessions: exit status 1 'claude agents --json' is
   not available in this environment.

 enter to attach · x to stop · r to reload · ? for shortcuts
```

`State` وضعیت یک نشست پس‌زمینه و کاری است که فرایندش انجام می‌دهد، یا برای یک نشست تعاملی `open`، مانند `ccam agents`. اگر نتوان از حسابی پرسید، یک خط `✘` زیر فهرست آنچه Claude Code گفته است را نشان می‌دهد، مانند `lab` در بالا که نمای عامل آن خاموش است. نشست‌های پس‌زمینه پایان‌یافته کنار گذاشته می‌شوند (`ccam agents --all` آن‌ها را فهرست می‌کند)، و وقتی همه حساب‌ها پاسخ داده باشند و هیچ‌کدام نشستی نداشته باشد، زبانه می‌گوید ``No sessions. Start one in the background with `ccam <account> --bg "…"`.`` در ترمینال باریک، زبانه ابتدا `Started`، سپس `Name` و سپس `Folder` را کنار می‌گذارد و مسیر پوشه‌های طولانی را از سمت چپ کوتاه می‌کند.

`Enter` روی یک نشست پس‌زمینه داشبورد را می‌بندد و نشست را در همین ترمینال با حساب خودش باز می‌کند، همان‌طور که `ccam attach <id>` انجام می‌دهد؛ داشبورد برنمی‌گردد (در Claude Code، `←` به نمای عامل آن و `Ctrl+Z` به شل می‌رود). نشست باز شناسه‌ای ندارد، پس `Enter` و `x` فقط می‌گویند که یک نشست پس‌زمینه لازم است. `x` اول می‌پرسد، با `No, keep it` انتخاب‌شده: ``It runs as personal. Like `ccam personal stop 49ec0028`, Claude Code stops it and keeps its conversation, which `ccam attach 49ec0028` opens again.`` با پاسخ بله، ccam فرمان `claude stop <id>` را با همان حساب اجرا می‌کند، ``49ec0028 (personal) stopped; `ccam attach 49ec0028` opens it again`` یا دلیل ناتوانی‌اش را می‌گوید، و فهرست را دوباره می‌خواند.

## تغییر گروه‌ها

در زبانه Groups، `Enter` ویرایشگر را باز می‌کند: موارد در سمت چپ، حساب‌ها در سمت راست، `Tab` برای جابه‌جایی بین آن‌ها و `Space` برای روشن و خاموش کردن. موردی که یکی از حساب‌ها از قبل از گروه دیگری می‌گیرد، همراه با دلیل آن کم‌رنگ نشان داده می‌شود، و همچنین حسابی که یک مورد را دو بار می‌گرفت؛ هر مورد فقط از یک گروه می‌تواند بیاید. `Enter` برنامه را نشان می‌دهد:

```console
 ──────────────────────────────────────────────────────────────────────────────
  Groups of side

  ● side  +history (group team)
    ⎿  link     projects, history.jsonl: profiles/side → groups/team

  Do you want to apply this plan?
  ❯ 1. Yes
    2. No
```

اگر فایلی با نسخه گروه متفاوت باشد، ccam ابتدا می‌پرسد چه کند (نسخه گروه نگه داشته شود، نسخه من استفاده شود یا ادغام شوند). سپس تغییر در پس‌زمینه با همان کد [`ccam group`](/features/share) اجرا می‌شود: ابتدا پیکربندی ذخیره می‌شود، داده‌های هر حساب به ترتیب جابه‌جا می‌شوند و نسخه‌های اصلی به `.ccam-backup/` می‌روند؛ حسابی که از اشتراک MCP بیرون می‌رود سرورهای گروه را در `.claude.json` خود نگه می‌دارد.

تغییری که داده‌های یک حساب در حال اجرا را جابه‌جا می‌کرد، همراه با نام آن حساب رد می‌شود، حتی وقتی آن حساب در مدتی که برنامه باز بود شروع شده باشد، و برنامه‌ای که به دلیل تغییر گروه‌ها توسط فرایند ccam دیگری کهنه شده باشد با `the groups changed while this plan waited; nothing was moved, make the change again` رد می‌شود. تا وقتی فرایند ccam دیگری گروه‌ها را تغییر می‌دهد، یک تغییر، تغییر نام یا حذف تازه می‌گوید `another ccam process is changing the groups right now`؛ پس از تغییری که نیمه‌کاره متوقف شده باشد، منتظر می‌مانند تا `F` در زبانه Health (یا `ccam doctor --fix`) آن را تمام کند.

## افزودن یک حساب

`a` دستیاری را باز می‌کند که `ccam add` هم در ترمینال از آن استفاده می‌کند:

1. نام حساب.
2. روش ورود آن: اشتراک Claude همین حالا (در مرورگر)، یک [کلید API](/features/api)، یا اشتراک Claude بعداً.
3. برای کلید API: جایی که ccam کلید را در هر اجرا از آن می‌خواند (`env:NAME` یا `command:COMMAND`)، نقطه پایانی، روش فرستادن کلید و مدل.
4. گروه‌هایی که حساب به آن‌ها می‌پیوندد، با `default` علامت‌خورده (اگر هنوز گروهی وجود نداشته باشد، آنچه گروه `default` به اشتراک خواهد گذاشت).
5. یک فرمان میان‌بر، اگر بخواهید.
6. خلاصه‌ای برای تأیید.

`Esc` یک مرحله به عقب برمی‌گردد و در مرحله اول دستیار را می‌بندد.

## حذف یک حساب

`x` پیش از هر کاری می‌پرسد، با No انتخاب‌شده، و می‌گوید حذف چه می‌کند: `It is logged out first (its login is revoked), then its folder goes to ccam's trash; the groups' shared files stay.` برای حساب کلید API ورودی برای باطل کردن وجود ندارد، و وقتی حساب دیگری همان ورود را دارد، از سیستم خارج نمی‌شود. یک حساب واردشده پوشه‌اش را نگه می‌دارد: `It was imported, so its folder /home/me/.claude stays where it is: it leaves its groups first and keeps a copy of what they share, then ccam forgets it.`

## رنگ‌ها

رنگ‌ها از نقش‌های رابط ترمینالی Claude Code پیروی می‌کنند تا ccam در کنار آن آشنا به نظر برسد؛ نام گروه‌ها رنگی برگرفته از نامشان می‌گیرند. ccam پس‌زمینه ترمینال را از خود ترمینال می‌پرسد و یک پوسته روشن یا تیره انتخاب می‌کند. خودتان می‌توانید یکی را در بالای `config.toml`، بالای نخستین `[[group]]`، `[[profile]]` یا `[[folder]]`، تعیین کنید:

```toml
theme = 'dark'   # auto (default), dark, light, dark-daltonized, light-daltonized, dark-ansi, light-ansi
```

پوسته‌های `-daltonized` برای کوررنگی قرمز و سبز هستند و پوسته‌های `-ansi` از ۱۶ رنگ خود ترمینال استفاده می‌کنند. `NO_COLOR` رنگ‌ها را خاموش می‌کند.

## ایمنی و موارد خاص

- داشبورد همان تابع‌هایی را فرا می‌خواند که فرمان‌ها فرا می‌خوانند، بنابراین همه قواعد برقرارند: برنامه پیش از جابه‌جایی داده، رد کردن تغییر برای حساب‌های در حال اجرا، نسخه‌های پشتیبان، و توکن‌های ورودی که هرگز از یک حساب بیرون نمی‌روند.
- داشبورد اجرای آزمایشی ندارد: `ccam --dry-run` بدون نام حساب چاپ می‌کند که حساب این پوشه چگونه آغاز می‌شود، و `o` روی یک حساب، اجرای آزمایشی همان یک اجرا را پیشنهاد می‌دهد.
- ترمینال پیش از شروع Claude Code یا باز شدن صفحه ورود به حالت عادی برمی‌گردد.
- در صفحه‌ای که برای یک پنجره گفتگو بیش از حد کوچک است، ابتدا ردیف‌های زبانه کنار گذاشته می‌شوند؛ خط‌ها به‌جای شکستن، با `…` کوتاه می‌شوند. در صفحه‌ای کوتاه، سپس خط‌های خالی و توضیح زبانه کنار گذاشته می‌شوند تا خط راهنمای کلیدها دیده شود. زیر ۴۰ ستون یا ۸ ردیف، داشبورد فقط `Too small: ccam needs 40x8 (now 36x7)` را نشان می‌دهد.
- `Ctrl+C` در حالی که یک تغییر، حذف، به‌روزرسانی یا تعمیر در حال اعمال است، منتظر آن می‌ماند: خط وضعیت می‌گوید `ccam quits when it is done.`
- پس از اینکه `U` ccam را به‌روز کرد، وقتی داشبورد از افزودن یک حساب یا ورود برمی‌گردد، پیشنهاد دوباره نمی‌آید.
