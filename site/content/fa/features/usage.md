`ccam usage` نشان می‌دهد هر حساب چه مقدار از سقف ۵ ساعته، سقف هفتگی و سقف هفتگی ویژه هر مدل (مانند Fable) را مصرف کرده است، با یک نوار برای هر سقف همراه با زمان باقی‌مانده تا بازنشانی آن. پیش از شروع یک کار طولانی، یا وقتی Claude Code به شما می‌گوید به سقف نزدیک شده‌اید، از آن استفاده کنید تا ببینید کدام حساب هنوز ظرفیت دارد. `ccam statusline` فرمان خط وضعیت برای Claude Code است: نام حساب و مصرف آن را داخل Claude Code نشان می‌دهد و عددها را برای `ccam usage` ذخیره می‌کند.

## استفاده

```sh
ccam usage                  # every account, once
ccam u                      # the same, shorter
ccam usage --watch          # redraw every 60 seconds until Ctrl+C
ccam usage --watch=10       # redraw every 10 seconds
ccam usage -v               # add where the numbers came from
ccam usage --json           # machine-readable, one object per account
ccam usage --source cache   # saved numbers only, no network
ccam usage --refresh        # also renew expired logins of accounts not running
ccam usage --source claude  # let Claude Code look it up: ccam sends no token
ccam statusline install     # set the status line in every account's settings.json
```

```console
$ ccam usage

   Weekly   ██████████████░░░░░░  70%  resets in 2d 16h

   5-hour   █████░░░░░░░░░░░░░░░  24%  resets in 2h 29m
   Weekly   ████████░░░░░░░░░░░░  41%  resets in 3d 11h
```

هر حساب یک خط با شماره، نام و میزان قدیمی بودن عددهایش دارد؛ `(cached)` یعنی عددها از یک فایل ذخیره‌شده آمده‌اند، نه از نقطه پایانی. زیر آن، برای هر سقف یک خط یک نوار ۲۰ خانه‌ای، درصد و زمان باقی‌مانده تا بازنشانی پنجره را نشان می‌دهد: `5-hour`، `Weekly` (همه مدل‌ها)، و سپس پنجره هفتگی ویژه هر مدل، مانند `Fable`. پنجره‌ای که حساب ندارد `-` را نشان می‌دهد. یک درصد از ۸۰٪ زرد و در ۱۰۰٪ قرمز می‌شود. پنجره‌ای که Claude Code پر گزارش کرده، وقتی درخواستی را در سقف مصرف رد کرده است، تا بازنشانی‌اش ۱۰۰٪ نشان می‌دهد، هر چه عددهای ذخیره‌شده بگویند ([ثبت سقف مصرف](#the-limit-record) را ببینید). در ترمینال همه حساب‌ها بلافاصله با `fetching…` نمایش داده می‌شوند و خط‌های هر حساب به محض پاسخ دادن آن رسم می‌شوند. خط آخر حسابی را نام می‌برد که [`ccam next --auto`](/features/next) با همان قواعد انتخاب می‌کرد (`auto_max_usage`، `auto_strategy`، نشست‌های در حال اجرا، فقط حساب‌های سازمان آخرین حساب استفاده‌شده مگر آنکه `cross_org` تنظیم شده باشد، و کنار گذاشتن هر پنجره‌ای که به ۱۰۰٪ رسیده، پس حسابی که سهمیه هفته‌اش پر شده هرگز نام برده نمی‌شود) و فقط وقتی نمایش داده می‌شود که بیش از یک حساب داشته باشید. با راهبرد پیش‌فرض `headroom` این خط `→ Most headroom: <name>` است؛ با `expiring` یا `balance` دلیل را می‌گوید، مانند `→ next --auto picks personal: its 5-hour window resets first, in 1h 12m (40% of its 5 hours used)`.

**صندلی‌های Team و Enterprise.** انتخاب خودکار (`ccam next`، `--fallback`، `ccam pick`، کلید `n` در داشبورد، و [`auto_switch`](/features/next#auto-switch) وقتی آن را روشن کنید) میان صندلی‌های همان سازمان Claude Team یا Enterprise هم جابه‌جا می‌شود. مرکز راهنمای Anthropic می‌گوید: «Each seat on a Team plan is assigned to one named individual, and only that person may use it» (هر صندلی در طرح Team به نام یک فرد مشخص اختصاص داده می‌شود و فقط همان شخص اجازه دارد از آن استفاده کند) و «Users can't route their work through another user's account to use that user's remaining usage» (کاربران نمی‌توانند کار خود را از طریق حساب کاربر دیگری انجام دهند تا از سهمیه مصرف باقی‌مانده آن کاربر استفاده کنند) ([طرح‌های Team](https://support.claude.com/en/articles/12004354-purchase-and-manage-seats-on-team-plans#h_b8a7d07129)؛ و همین‌طور برای [طرح‌های Enterprise](https://support.claude.com/en/articles/13393991-purchase-and-manage-seats-on-enterprise-plans#h_fa6b9cade0)). بنابراین استفاده از انتخاب خودکار میان صندلی‌ها ممکن است شرایط Anthropic را نقض کند. اینکه در آنجا از آن استفاده کنید یا نه، تصمیم خودتان است: پیش از آنکه به آن تکیه کنید، از سازمان خود و Anthropic بپرسید. برای طرح‌های شخصی (Pro، Max)، [توضیح شرایط در پرسش‌های متداول](/docs/faq#am-i-allowed-to-use-several-claude-code-accounts) را ببینید.

حسابی که وارد نشده است `not logged in → ccam login <name>` را نشان می‌دهد و حساب کلید API پیام `no limits (API)` را. توکن دسترسی منقضی‌شده ``access token expired; `ccam <name>` renews it when it starts`` را نشان می‌دهد، اگر عدد ذخیره‌شده‌ای باشد بالای آن‌ها: Claude Code آن را در اجرای بعدی تمدید می‌کند. ورودی که به‌طور کامل منقضی شده است، چون توکن تمدیدش منقضی شده یا Claude Code پس از آنکه سرور آن را رد کرد پاکش کرده است، `` login expired → `ccam login <name>` `` را نشان می‌دهد.

پس از `ccam statusline install`، Claude Code خطی مانند `[work] · Opus · 5h 24% · 7d 41%` را نشان می‌دهد.

| `--no-cache` | حافظه نهان ۶۰ ثانیه‌ای را نادیده می‌گیرد و دوباره از نقطه پایانی می‌پرسد | خاموش |

### مصرف از خود Claude Code

با `usage_source = "claude"` در بالای `config.toml` (بالای نخستین `[[group]]`، `[[profile]]` یا `[[folder]]`)، یا `--source claude`، ccam اصلاً توکن ورود را نمی‌خواند. برای هر حساب، `claude -p --input-format stream-json --output-format stream-json --verbose --safe-mode --no-session-persistence` را در پوشه حساب اجرا می‌کند و درخواست `get_usage` را در ورودی استاندارد به Claude Code می‌فرستد (Claude Code 2.1.270 یا جدیدتر)؛ Claude Code مصرف را با ورود خودش می‌پرسد و با پنجره‌های ۵ ساعته، هفتگی و ویژه هر مدل پاسخ می‌دهد. `--safe-mode` نمی‌گذارد هوک‌ها، سرورهای MCP و پلاگین‌های حساب اجرا شوند و هیچ نشستی ذخیره نمی‌شود. هر حساب یک بار راه‌اندازی Claude Code، حدود یک ثانیه، زمان می‌برد، پس این منبع از `live` کندتر است؛ از حساب‌ها هم‌زمان پرسیده می‌شود، هر کدام در ۲۰ ثانیه، و حافظه نهان ۶۰ ثانیه‌ای طبق معمول اعمال می‌شود. ورودی که توکن دسترسی‌اش منقضی شده یا تا ۵ دقیقه دیگر منقضی می‌شود ۵۰ ثانیه فرصت می‌گیرد، چون Claude Code هنگام شروع آن را تمدید می‌کند و تمدیدی که نیمه‌کاره قطع شود ممکن است ورود را از بین ببرد. پرس‌وجویی که رها شود با SIGTERM از Claude Code می‌خواهد پایان یابد تا تمدیدی را که شروع کرده تمام کند (Windows چنین سیگنالی ندارد؛ آنجا Claude Code متوقف می‌شود). ورودی که به‌طور کامل منقضی شده است، بدون اجرای Claude Code، `` login expired → `ccam login <name>` `` را نشان می‌دهد. Claude Code این درخواست را آزمایشی علامت زده است، پس اگر دیگر پاسخ ندهد، ccam عددهای ذخیره‌شده را نشان می‌دهد و `ccam doctor` آن را گزارش می‌کند. وقتی Claude Code پاسخ دهد که پرس‌وجوی خودش ناموفق بوده، ccam عددهای ذخیره‌شده را با `the usage endpoint gave Claude Code no usage (it may be refusing lookups for now)` نشان می‌دهد، نه طرحی بدون سقف. یک `--dry-run` Claude Code را اجرا نمی‌کند (Claude Code در پوشه حساب می‌نویسد) و عددهای ذخیره‌شده را نشان می‌دهد. `usage_source` مقدار `live` یا `claude` را می‌پذیرد؛ `cache` فقط یکی از گزینه‌های `--source` است. `ccam usage` هیچ آرگومانی نمی‌گیرد.

`ccam statusline` JSON خط وضعیت Claude Code را از ورودی استاندارد می‌خواند. تنها گزینه آن `--wrap <command>` است: یک فرمان خط وضعیت موجود که نام حساب پیش از نخستین خط خروجی آن قرار می‌گیرد. `ccam statusline install` هیچ گزینه‌ای نمی‌گیرد. هر دو `--dry-run` را با `` --dry-run is not supported by `ccam statusline`; nothing was changed `` رد می‌کنند.

## چگونه کار می‌کند

عددها از دو جا می‌آیند: نقطه پایانی مصرف Anthropic که مستند نشده است، یعنی `GET https://api.anthropic.com/api/oauth/usage`، که با ورود خود هر حساب فراخوانی می‌شود، و مقدارهایی که Claude Code به فرمان خط وضعیت خود می‌دهد. همه این‌ها در `internal/usage` قرار دارد.

1. `cli.usageCmd` فایل `config.toml` را بارگذاری می‌کند و برای هر حساب یک `usage.Account` می‌سازد: پوشه آن `~/.local/share/ccam/profiles/<name>/`، نشانگرهای نشست آن (که همراه با سوابق خود Claude Code در پوشه حساب نشان می‌دهند در حال اجراست یا نه) و اینکه آیا در همان محل وارد شده است.
2. `Fetcher.FetchAll` برای هر حساب یک goroutine آغاز می‌کند. همه آن‌ها یک `http.Client` مشترک دارند، بنابراین اتصال‌ها به نقطه پایانی دوباره استفاده می‌شوند. برقراری اتصال می‌تواند ۲ ثانیه طول بکشد و هر حساب روی هم ۳ ثانیه فرصت دارد. کلاینت هدایت‌ها را دنبال نمی‌کند، چون یک هدایت توکن را به جای دیگری می‌فرستد، و حداکثر ۱ MB از پاسخ را می‌خواند.
3. با تمام شدن کار هر حساب، ردیف آن دوباره رسم می‌شود. حسابی که ناموفق باشد یا به‌موقع پاسخ ندهد به عددهای ذخیره‌شده برمی‌گردد، بنابراین یک حساب کند هرگز بقیه را معطل نمی‌کند.

هر حساب در goroutine خودش با نقطه پایانی کار می‌کند؛ حسابی که مهلتش تمام شود به‌جای آن عددهای ذخیره‌شده خود را نشان می‌دهد.

`personal` و `work` به‌موقع پاسخ می‌دهند و عددهای زنده را نشان می‌دهند. `side` بیش از ۳ ثانیه طول می‌کشد، پس `fallback()` به جای آن عددهای ذخیره‌شده‌اش را نشان می‌دهد. `usage.Table()` برای هر حساب یک بلوک رسم می‌کند و `usage.Best()` حسابی را که در خط آخر نام برده می‌شود انتخاب می‌کند.

برای یک حساب، `Fetcher.Fetch` این بررسی‌ها را به ترتیب انجام می‌دهد:

<!-- motion:usage-cache -->

1. با `--source cache`، مستقیم به `fallback()` می‌رود.
2. مگر اینکه `--no-cache` تنظیم شده باشد، یک نتیجه زنده در `~/.local/state/ccam/usage/<name>.json` که کمتر از ۶۰ ثانیه (`CacheTTL`) پیش اندازه‌گیری شده باشد، با سنجش نسبت به همین لحظه، استفاده می‌شود: پنجره‌ای که از آن پس بازنشانی شده ۰٪ نشان می‌دهد و فایلی که تاریخش از ساعت جلوتر باشد تازه به حساب نمی‌آید. اجرای دو بار پشت سر هم `ccam usage` برای هر حساب فقط یک درخواست هزینه دارد.
3. `readCredentials()` فایل `.credentials.json` (یا Keychain سیستم macOS) را بدون تغییر می‌خواند و فقط کلید `claudeAiOauth` رمزگشایی می‌شود. نبودن ورود اشتراکی یعنی `not logged in`، یا `no limits (API)` وقتی `.claude.json` یک کلید API دارد. ورودی که توکن تمدیدش منقضی شده، یا Claude Code آن را پاک کرده است، `` login expired → `ccam login <name>` `` است و پرس‌وجو نمی‌شود.
4. توکن دسترسی منقضی‌شده استفاده نمی‌شود. بدون `--refresh`، حساب عددهای ذخیره‌شده خود را همراه با ``access token expired; `ccam <name>` renews it when it starts`` نشان می‌دهد.
5. در غیر این صورت ccam نقطه پایانی را فراخوانی می‌کند. پاسخ 401 یا 403 به‌عنوان ورود منقضی‌شده (`login expired: authentication failed (401)`) و هر وضعیت دیگر یا بدنه‌ای که نتواند بخواند به‌عنوان خطا به حساب می‌آید و در هر دو حالت به عددهای ذخیره‌شده برمی‌گردد. پرس‌وجویی که با Ctrl+C پایان یابد `cancelled` می‌گوید. پاسخ 429 یعنی از نقطه پایانی بیش از حد پرسیده می‌شود: ccam فایل `<name>.pause` را با زمان پرسش بعدی می‌نویسد (`Retry-After`، یا ۵ دقیقه، حداکثر یک ساعت)، عددهای ذخیره‌شده را با `rate limited by the usage endpoint; asking again after 15:10` نشان می‌دهد و تا آن زمان، حتی با `--no-cache`، نقطه پایانی را برای آن حساب فراخوانی نمی‌کند. تلاش دوباره بلافاصله فقط محدودیت را طولانی‌تر می‌کند.
6. پاسخ درست همراه با زمان اندازه‌گیری در `<name>.json` نوشته می‌شود.

`fallback()` تازه‌ترین پرس‌وجوی ذخیره‌شده را برمی‌دارد (`<name>.json`، یا `<name>.claude.json` از پرس‌وجوهای Claude Code) و وقتی `<name>.statusline.json` پس از آن نوشته شده باشد، پنجره‌های ۵ ساعته و هفتگی خط وضعیت را روی آن قرار می‌دهد؛ پنجره‌های مدل، که خط وضعیت آن‌ها را ندارد، همان‌طور که پرس‌وجو ذخیره کرده است می‌مانند. پیش از نشان دادن عددهای ذخیره‌شده، زمان بازنشانی هر پنجره را بررسی می‌کند: پنجره‌ای که پس از ذخیره عددها بازنشانی شده باشد ۰٪ نشان می‌دهد، چون درصد قدیمی دیگر معتبر نیست. به همین دلیل `personal` در بالا `0%` را بدون زمان بازنشانی نشان می‌دهد.

نقطه پایانی دو قالب پاسخ دارد. قالب جدیدتر یک آرایه `limits` با ورودی‌های `session` (۵ ساعته)، `weekly_all` و `weekly_scoped` (ویژه هر مدل) دارد. قالب قدیمی‌تر شیءهای `five_hour`، `seven_day`، `seven_day_opus` و `seven_day_sonnet` را دارد. `ParseLive` هر دو را می‌خواند: آرایه `limits` اولویت دارد و شیءهای قدیمی آنچه را که آن پوشش نمی‌دهد کامل می‌کنند. بدنه‌ای که هیچ سقفی نداشته باشد به‌عنوان قالب تغییرکرده گزارش می‌شود و `ccam doctor` آن را به شما اطلاع می‌دهد.

### ثبت سقف مصرف

وقتی Claude Code یک نوبت را در سقف مصرف متوقف کند، هوک [پلاگین ccam](/docs/install#claude-code-plugin) درخواست ردشده را از گفتگو می‌خواند: کدام پنجره پر بوده است (۵ ساعته، هفتگی، Opus یا Sonnet) و کی بازنشانی می‌شود. این را در `~/.local/state/ccam/usage/<name>.limit.json` می‌نویسد. `Fetch` این ثبت را روی هر چیز دیگری که از هر منبعی می‌داند قرار می‌دهد: هر پنجره‌ای که در آن است تا بازنشانی‌اش ۱۰۰٪ حساب می‌شود، هر قدر هم عددهای ذخیره‌شده قدیمی یا پایین باشند، پس `ccam next --auto`، `ccam pick`، `--fallback` و [`auto_switch`](/features/next#auto-switch) آن حساب را پیش از آن زمان دوباره انتخاب نمی‌کنند. وقتی چیز دیگری معلوم نباشد، حساب فقط همین ثبت را نشان می‌دهد (`source: the usage limit Claude Code reported` با `-v`). نشست‌هایی که کسی پشتشان ننشسته است (`-p`، نشست‌های پس‌زمینه) هیچ ثبتی نمی‌نویسند، و توقف از سوی سازمان (تمام شدن مصرف، گروهی که روی $0 تنظیم شده) هم ثبتی نمی‌نویسد، چون مدیرانش هر زمان می‌توانند آن را بردارند. `ccam login` به حساب Claude دیگر این ثبت را کنار می‌گذارد؛ پاک کردن فایل هم آن را پاک می‌کند.

### تمدید توکن‌ها

توکن‌های تمدید چرخشی‌اند: تمدید یکی از آن‌ها یک توکن تمدید جدید به شما می‌دهد و توکن قبلی را باطل می‌کند. اگر ccam ورود را در حالی تمدید کند که Claude Code با همان حساب در حال اجراست، آن نشست از حساب خارج می‌شود. بنابراین `ccam usage` توکن‌ها را می‌خواند و هرگز آن‌ها را نمی‌نویسد، مگر اینکه `--refresh` را بدهید. در آن صورت `Fetcher.refresh`:

1. حساب‌هایی را که با `ccam import` در همان محل ثبت شده‌اند رد می‌کند، چون `claude` معمولی ممکن است بدون اطلاع ccam از آن ورود استفاده کند؛
2. ورودهایی را که در Keychain سیستم macOS ذخیره شده‌اند رد می‌کند؛
3. یک فایل قفل، `~/.local/state/ccam/locks/profile-<name>.refresh.lock`، می‌گیرد تا دو فرایند ccam هرگز یک توکن را دو بار تمدید نکنند؛ تا وقتی این قفل گرفته شده است، حساب `token not renewed: another ccam is using this login right now (a refresh, rename, remove or logout)` را نشان می‌دهد. `ccam rename`، `remove` و `logout` هم آن را می‌گیرند و تا وقتی تمدیدی در جریان است سر باز می‌زنند؛
4. زیر قفل، اگر نشستی از آن حساب در حال اجرا باشد رد می‌کند، به هر شکلی که شروع شده باشد (از طریق ccam، `claude` معمولی، یک IDE، یا یک نشست پس‌زمینه و daemon پشت آن، که خودش ورود را تمدید می‌کند)، و اگر فرایند دیگری توکن را از قبل تمدید کرده باشد از درخواست صرف‌نظر می‌کند؛
5. تا وقتی Claude Code قفل‌های تمدید خودش را در پوشه حساب نگه داشته است (`.oauth_refresh.lock`، `<folder>.lock`) چیزی نمی‌فرستد: Claude Code همان لحظه در حال تمدید آن ورود است؛
6. توکن تمدید را به نقطه پایانی توکن می‌فرستد و تا ۳۰ ثانیه، همان زمانی که Claude Code به تمدیدهای خودش می‌دهد، منتظر پاسخ می‌ماند. درخواستی که یک بار فرستاده شده هرگز قطع نمی‌شود، حتی با Ctrl+C، چون ممکن است سرور توکن تمدید را از قبل عوض کرده باشد و فقط پاسخ آن هنوز ورود را نگه دارد: Ctrl+C یا یک hangup پرس‌وجوهای دیگر را پایان می‌دهد و ccam پس از ذخیره شدن پاسخ خارج می‌شود (پس از Ctrl+C با کد ۱۳۰)؛
7. زیر قفل نوشتن Claude Code (`.storage-write.lock`) ذخیره می‌کند و فقط فیلدهای توکن `.credentials.json` را، به همان شکلی که در آن لحظه هست، تغییر می‌دهد: آنچه Claude Code در این مدت نوشته است (یک ورود MCP) می‌ماند، ورودی که Claude Code در این مدت تمدید کرده نگه داشته می‌شود و یک خروج هرگز برگردانده نمی‌شود. وقتی پاسخ طول عمر توکن تمدید جدید را بدهد، مانند کاری که Claude Code می‌کند، به‌صورت `refreshTokenExpiresAt` ذخیره می‌شود.

تمدیدی که انجام نشود دلیلش را می‌گوید، در خط حساب یا بالای عددهای ذخیره‌شده‌اش: برای مثال `token not renewed: a session is running`، یا `login may be lost: …` وقتی درخواستی فرستاده شده اما پاسخش را نتوان به کار برد یا ذخیره کرد، همراه با این توصیه که اگر Claude Code سپس از شما خواست وارد شوید، `ccam login <name>` را اجرا کنید.

### جمع‌آوری‌کننده خط وضعیت

Claude Code فرمان خط وضعیت را اجرا می‌کند و یک سند JSON را به ورودی آن می‌فرستد. ccam نام مدل و `rate_limits` را از آن می‌خواند:

<!-- motion:usage-statusline -->

1. `runStatusline` حساب را از `CCAM_PROFILE` پیدا می‌کند که ccam هنگام اجرای Claude Code تنظیم می‌کند، یا در غیر این صورت با مقایسه `CLAUDE_CONFIG_DIR` با پوشه‌های حساب‌ها.
2. `ParseStatusLine` مقدارهای `rate_limits.five_hour` و `rate_limits.seven_day` را می‌خواند. برای حساب‌های کلید API، یا پیش از نخستین پاسخ نشست، JSON هیچ سقف نرخی ندارد؛ در این حالت چیزی ذخیره نمی‌شود.
3. `SaveStatusLine` فایل `~/.local/state/ccam/usage/<name>.statusline.json` را می‌نویسد. `ccam usage` وقتی نقطه پایانی پاسخ ندهد از آن استفاده می‌کند.
4. ccam خط `[name] · model · 5h N% · 7d N%` را چاپ می‌کند. با `--wrap`، فرمان شما را با همان ورودی از طریق `sh -c` اجرا می‌کند و خروجی آن را به همان شکلی چاپ می‌کند که Claude Code یک خط وضعیت را نشان می‌دهد: هر خطی که خالی نباشد، با `[name]` پیش از نخستین خط. فرمانی که ناموفق باشد فقط نام حساب را نشان می‌دهد. در Windows فرمان را همان‌طور اجرا می‌کند که Claude Code اجرا می‌کند: با Git Bash اگر نصب باشد، وگرنه با PowerShell.
5. وقتی مصرف ۵ ساعته یا هفتگی ۹۰٪ یا بیشتر باشد و حساب دیگری وجود داشته باشد، خط با `→ ccam next --auto --continue` تمام می‌شود، برای مثال `[work] · Opus · 5h 93% · 7d 41% · → ccam next --auto --continue`.

فرمان پیچیده‌شده محدودیت زمانی خودش را ندارد: Claude Code به فرمان خط وضعیت ۱۰ دقیقه فرصت می‌دهد و وقتی به‌روزرسانی تازه‌تری شروع شود اجرا را متوقف می‌کند، پس یک فرمان کند همان‌طور نمایش داده می‌شود که بدون ccam نمایش داده می‌شد. وقتی Claude Code به ccam پایان دهد، فرمان هم پایان می‌یابد (در Linux و macOS همراه با همه فرایندهایی که شروع کرده است).

`ccam statusline install` مقدار `statusLine` را در `settings.json` هر حساب می‌نویسد و کلیدهای دیگر آن شیء، مانند `padding`، `refreshInterval` و `hideVimModeIndicator`، را نگه می‌دارد. وقتی یک حساب از قبل فرمان خط وضعیت داشته باشد، ccam آن را به شکل `--wrap '<old command>'` نگه می‌دارد؛ در Windows به شکل `--wrap-base64 <base64>`، که در هیچ‌کدام از دو پوسته به نقل‌قول نیاز ندارد. خط وضعیتی که از قبل یک ccam را اجرا می‌کند، از مسیری دیگر یا با نقل‌قول به شیوه‌ای که یک ccam قدیمی‌تر می‌نوشت، به جای پیچیده شدن جایگزین می‌شود و آنچه را می‌پیچید نگه می‌دارد. در Windows مسیر ccam با اسلش رو به جلو و `~` برای پوشه خانه نوشته می‌شود (`~/.local/bin/ccam.exe statusline`)، که هم Git Bash و هم PowerShell آن را می‌فهمند. مسیری که به نقل‌قول نیاز دارد به‌طور کامل برای پوسته‌ای که Claude Code به کار می‌برد نوشته می‌شود: `'…'` برای Git Bash، `& '…'` برای PowerShell. `settings.json` که از طریق یک گروه به اشتراک گذاشته شده است یک بار و از طریق پیوند خود نوشته می‌شود، بنابراین همه حساب‌های گروه آن را دریافت می‌کنند. اجرای دوباره آن برای فایل‌هایی که از قبل از ccam استفاده می‌کنند `(already set)` را چاپ می‌کند.

## ایمنی و حالت‌های خاص

- `ccam usage` هرگز فایل توکن را تغییر نمی‌دهد، مگر اینکه `--refresh` را بدهید. وقتی یک توکن دسترسی منقضی شده باشد، حساب را یک بار با `ccam <name>` اجرا کنید تا Claude Code آن را تمدید کند. ورودی که به‌طور کامل منقضی شده باشد به `ccam login <name>` نیاز دارد.
- `--refresh` هرگز به حساب‌های در حال اجرا (حتی وقتی Claude Code بدون ccam شروع شده باشد)، حساب‌های واردشده یا ورودهای Keychain دست نمی‌زند. تمدیدی که رد شود عددهای ذخیره‌شده و دلیل آن را نشان می‌دهد (`token not renewed: …`).
- نقطه پایانی مصرف به‌طور عمومی مستند نشده است و ممکن است تغییر کند. وقتی تغییر کند، همچنان عددهای ذخیره‌شده را می‌بینید و `ccam doctor` تغییر قالب را گزارش می‌دهد.
- وقتی نه عدد ذخیره‌شده‌ای باشد و نه پاسخی، خط حساب `lookup failed:` و دلیل آن را نشان می‌دهد، برای مثال `no saved usage` با `--source cache`.
- فایل‌های حافظه نهان فقط درصدها و زمان‌های بازنشانی را نگه می‌دارند، هرگز توکن‌ها را.
