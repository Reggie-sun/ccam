`ccam usage` برای هر حساب نشان می‌دهد چه مقدار از هر سقف مصرف شده است: سقف ۵ ساعته، سقف هفتگی و سقف هفتگی ویژه هر مدل (مانند Fable). هر سقف یک نوار و زمان باقی‌مانده تا بازنشانی‌اش را می‌گیرد. پیش از شروع یک کار طولانی، یا وقتی Claude Code به شما می‌گوید به سقف نزدیک شده‌اید، از آن استفاده کنید تا ببینید کدام حساب هنوز ظرفیت دارد. `ccam statusline` فرمان خط وضعیت برای Claude Code است: نام حساب و مصرف آن را داخل Claude Code نشان می‌دهد و عددها را برای `ccam usage` ذخیره می‌کند. برای دیدن توکن‌ها و هزینه‌های تخمینی پشت این مصرف، `ccam ccusage` ابزار [ccusage](https://ccusage.com) را روی گفتگوهای همه حساب‌ها اجرا می‌کند ([پایین‌تر](#tokens-and-costs-ccam-ccusage)).

## استفاده

```sh
ccam usage                  # every account, once
ccam u                      # the same, shorter
ccam usage --watch          # redraw every 60 seconds until Ctrl+C
ccam usage --watch=10       # redraw every 10 seconds
ccam usage -v               # add where the numbers came from
ccam usage --json           # machine-readable, one object per account
ccam usage --source cache   # saved numbers only, no network
ccam usage --refresh        # also renew expired logins of accounts that are not running
ccam usage --source claude  # let Claude Code look it up: ccam sends no token
ccam statusline install     # set the status line in every account's settings.json
```

هر حساب یک خط با شماره، نام و میزان قدیمی بودن عددهایش دارد؛ `(cached)` یعنی عددها از یک فایل ذخیره‌شده آمده‌اند، نه از نقطه پایانی. زیر آن، برای هر سقف یک خط یک نوار ۲۰ خانه‌ای، درصد و زمان باقی‌مانده تا بازنشانی پنجره را نشان می‌دهد: `5-hour`، `Weekly` (همه مدل‌ها)، و سپس پنجره هفتگی ویژه هر مدل، مانند `Fable`. پنجره‌ای که حساب ندارد `-` را نشان می‌دهد. یک درصد در ۸۰٪ زرد و در ۱۰۰٪ قرمز می‌شود.

اگر Claude Code درخواستی را به این دلیل رد کرده باشد که یک پنجره پر بوده است، آن پنجره تا بازنشانی‌اش ۱۰۰٪ نشان می‌دهد، هر چه عددهای ذخیره‌شده بگویند ([ثبت سقف مصرف](#the-limit-record) را ببینید). در ترمینال همه حساب‌ها بلافاصله با `fetching…` نمایش داده می‌شوند و خط‌های هر حساب به محض پاسخ دادن آن رسم می‌شوند.

خط آخر، که فقط وقتی بیش از یک حساب داشته باشید نمایش داده می‌شود، حسابی را نام می‌برد که [`ccam next --auto`](/features/next) انتخاب می‌کرد. این خط از همان قواعد پیروی می‌کند:

- `auto_max_usage` و `auto_strategy`؛
- نشست‌های در حال اجرا؛
- فقط حساب‌های سازمان آخرین حساب استفاده‌شده، مگر آنکه `cross_org` تنظیم شده باشد؛
- هر پنجره‌ای که به ۱۰۰٪ رسیده کنار گذاشته می‌شود، پس حسابی که سهمیه هفته‌اش پر شده هرگز نام برده نمی‌شود.

با راهبرد پیش‌فرض `headroom` این خط `→ Most headroom: <name>` است؛ با `expiring` یا `balance` دلیل را می‌گوید، مانند `→ next --auto picks personal: its 5-hour window resets first, in 1h 12m (40% of its 5 hours used)`.

**صندلی‌های Team و Enterprise.** انتخاب خودکار حساب (`ccam next`، `--fallback`، `ccam pick`، کلید `n` در داشبورد و، وقتی آن را روشن کنید، [`auto_switch`](/features/next#auto-switch)) میان صندلی‌های همان سازمان Claude Team یا Enterprise هم جابه‌جا می‌شود، که ممکن است شرایط Anthropic را نقض کند. پیش از آنکه به آن تکیه کنید، [پرسش‌های متداول](/docs/faq#am-i-allowed-to-use-several-claude-code-accounts) را بخوانید و از سازمان خود و Anthropic بپرسید.

حسابی که وارد نشده است `not logged in → ccam login <name>` را نشان می‌دهد و حساب کلید API پیام `no limits (API)` را. توکن دسترسی منقضی‌شده ``access token expired; `ccam <name>` renews it when it starts`` را نشان می‌دهد، بالای عددهای ذخیره‌شده، اگر وجود داشته باشند: Claude Code آن را در اجرای بعدی تمدید می‌کند. ورودی که به‌طور کامل منقضی شده است، چون توکن تمدیدش منقضی شده یا Claude Code پس از آنکه سرور آن را رد کرد پاکش کرده است، `` login expired → `ccam login <name>` `` را نشان می‌دهد.

پس از `ccam statusline install`، Claude Code خطی مانند `[work] · Opus · 5h 24% · 7d 41%` را نشان می‌دهد.

## گزینه‌ها

| گزینه | کاری که انجام می‌دهد | پیش‌فرض |
| --- | --- | --- |
| `--json` | گزارش‌ها را به‌صورت JSON چاپ می‌کند: `name`، `slot`، `status`، `limits` (همراه با `credits` وقتی اعتبار مصرف حساب روشن است)، `source`، `at`، `error`، و `limited` و `limited_windows` وقتی یک ثبت سقف مصرف پنجره‌هایی را ۱۰۰٪ می‌کند. وقتی حسابی وجود نداشته باشد `[]` را چاپ می‌کند | خاموش |
| `--watch[=N]` | هر `N` ثانیه دوباره رسم می‌کند تا Ctrl+C را بزنید. `--watch` به‌تنهایی، یا مقدار ۰ یا کمتر، یعنی ۶۰. مقدار پس از `=` می‌آید: `--watch 10` با یک راهنمایی رد می‌شود | خاموش |
| `-v`، `--verbose` | زیر هر حساب یک خط `source:` اضافه می‌کند: عددهای آن از کجا آمده‌اند (نقطه پایانی مصرف، Claude Code، خط وضعیت، یک فایل ذخیره‌شده، یا سقف مصرفی که Claude Code گزارش کرده است). وقتی یک ثبت سقف مصرف عددها را کنار بزند، پس از آن خطی مانند `Weekly full: Claude Code reported the usage limit 1h 0m ago, so 100% until the reset` می‌آید | خاموش |
| `--no-cache` | حافظه نهان ۶۰ ثانیه‌ای را نادیده می‌گیرد و دوباره از نقطه پایانی می‌پرسد | خاموش |
| `--source live\|claude\|cache` | `live` با توکن حساب از نقطه پایانی می‌پرسد؛ `claude` از Claude Code می‌خواهد آن را بپرسد (پایین‌تر)؛ `cache` فقط عددهای ذخیره‌شده را نشان می‌دهد | `usage_source`، در غیر این صورت `live` |
| `--refresh` | توکن‌های دسترسی منقضی‌شده را تمدید می‌کند، فقط برای حساب‌هایی که در حال اجرا نیستند. یک تمدید ممکن است تا ۳۰ ثانیه طول بکشد | خاموش |
| `--dry-run` | پذیرفته می‌شود: `ccam usage` به جز حافظه نهان خودش چیزی را تغییر نمی‌دهد. همراه با `--refresh` رد می‌شود: `--dry-run cannot be combined with --refresh, which rewrites login tokens` | خاموش |

هر مقدار دیگری برای `--source` با `--source must be live, claude or cache` خطا می‌دهد. `ccam usage` هیچ آرگومانی نمی‌گیرد.

### مصرف از خود Claude Code

با `usage_source = "claude"` در بالای `config.toml` (بالای نخستین `[[group]]`، `[[profile]]` یا `[[folder]]`)، یا `--source claude`، ccam اصلاً توکن ورود را نمی‌خواند. برای هر حساب، `claude -p --input-format stream-json --output-format stream-json --verbose --safe-mode --no-session-persistence` را در پوشه حساب اجرا می‌کند و درخواست `get_usage` را در ورودی استاندارد به Claude Code می‌فرستد (Claude Code 2.1.270 یا جدیدتر). Claude Code مصرف را با ورود خودش می‌پرسد و با پنجره‌های ۵ ساعته، هفتگی و ویژه هر مدل پاسخ می‌دهد.

`--safe-mode` نمی‌گذارد هوک‌ها، سرورهای MCP و پلاگین‌های حساب اجرا شوند و هیچ نشستی ذخیره نمی‌شود. هر حساب به یک بار راه‌اندازی Claude Code (حدود یک ثانیه) نیاز دارد، پس این منبع از `live` کندتر است. از حساب‌ها هم‌زمان پرسیده می‌شود، هر کدام با مهلت ۲۰ ثانیه، و حافظه نهان ۶۰ ثانیه‌ای طبق معمول اعمال می‌شود.

ورودی که توکن دسترسی‌اش منقضی شده یا تا ۵ دقیقه دیگر منقضی می‌شود ۵۰ ثانیه فرصت می‌گیرد، چون Claude Code هنگام شروع آن را تمدید می‌کند و تمدیدی که نیمه‌کاره قطع شود ممکن است ورود را از بین ببرد. اگر ccam از یک پرس‌وجو دست بکشد، با SIGTERM از Claude Code می‌خواهد خارج شود تا Claude Code تمدیدی را که شروع کرده تمام کند (Windows سیگنال SIGTERM ندارد، پس آنجا فرایند خاتمه داده می‌شود).

ورودی که به‌طور کامل منقضی شده است، بدون اجرای Claude Code، `` login expired → `ccam login <name>` `` را نشان می‌دهد. Claude Code این درخواست را آزمایشی علامت زده است، پس اگر دیگر پاسخ ندهد، ccam عددهای ذخیره‌شده را نشان می‌دهد و `ccam doctor` آن را گزارش می‌کند. وقتی Claude Code پاسخ دهد که پرس‌وجوی خودش ناموفق بوده، ccam عددهای ذخیره‌شده را با `the usage endpoint gave Claude Code no usage (it may be refusing lookups for now)` نشان می‌دهد، نه طرحی بدون سقف.

با `--dry-run`، ccam Claude Code را اجرا نمی‌کند، چون Claude Code در پوشه حساب می‌نویسد؛ به جای آن عددهای ذخیره‌شده را نشان می‌دهد. `usage_source` مقدار `live` یا `claude` را می‌پذیرد؛ `cache` فقط یکی از گزینه‌های `--source` است.

`ccam statusline` JSON خط وضعیت Claude Code را از ورودی استاندارد می‌خواند. تنها گزینه آن `--wrap <command>` است: یک فرمان خط وضعیت موجود که نام حساب پیش از نخستین خط خروجی آن قرار می‌گیرد. `ccam statusline install` هیچ گزینه‌ای نمی‌گیرد. هر دو `--dry-run` را با `` --dry-run is not supported by `ccam statusline`; nothing was changed `` رد می‌کنند.

## توکن‌ها و هزینه‌ها: `ccam ccusage`

`ccam usage` نشان می‌دهد یک حساب چه مقدار از هر سقف را مصرف کرده است. اما [ccusage](https://ccusage.com) توکن‌ها و هزینه‌های تخمینی را در فایل‌های گفتگوی Claude Code می‌شمارد. ccusage به‌تنهایی فقط در `~/.claude` و `~/.config/claude` (یا در پوشه‌هایی که `CLAUDE_CONFIG_DIR` مشخص می‌کند) دنبال فایل‌های گفتگوی Claude Code می‌گردد، پس تنها حساب ccam که می‌تواند ببیند، حسابی است که در همان جای خود در `~/.claude` وارد شده است. `ccam ccusage` آن را اجرا می‌کند و `CLAUDE_CONFIG_DIR` را روی پوشه‌های همه حساب‌هایی که گفتگو دارند تنظیم می‌کند، تا یک گزارش همه آن‌ها را پوشش دهد:

```sh
ccam ccusage                           # every account, ccusage's daily report
ccam ccusage daily --breakdown         # cost per model
ccam ccusage claude monthly --json     # Claude Code alone, as JSON
ccam ccusage -a work blocks --active   # one account's current 5-hour block
ccam ccusage -a work,side weekly       # these accounts, and any that share their history
```

ccam ابتدا گزینه‌های خودش را می‌خواند: `-a` (`--account`) نام یا شماره حساب‌ها را می‌گیرد، جداشده با ویرگول یا با تکرار گزینه، و `--dry-run` فرمان را به‌جای اجرا چاپ می‌کند. از نخستین آرگومانی که جزو گزینه‌های ccam نیست به بعد، همه چیز بدون تغییر به ccusage می‌رسد؛ `ccam ccusage -- --help` راهنمای خود ccusage را نشان می‌دهد. ccam اگر `ccusage` نصب شده باشد همان را اجرا می‌کند، در غیر این صورت `bun x ccusage` و اگر آن هم نشد `npx ccusage@latest` را؛ این دو آخری آن را از npm دریافت می‌کنند. اگر هیچ‌کدام در دسترس نباشد، ccam از شما می‌خواهد Node.js، Bun یا ccusage را نصب کنید. در Linux و macOS، ccusage جای ccam را می‌گیرد؛ در Windows، ccam منتظر آن می‌ماند و با کد خروج ccusage پایان می‌یابد. در WSL، ccam از هر `ccusage`، `bun` یا `npx` که روی یک درایو Windows باشد صرف‌نظر می‌کند، چون چنین برنامه‌ای به‌صورت برنامه Windows و بدون پوشه‌های حساب‌ها اجرا می‌شد.

- گزارش، حساب‌هایی را پوشش می‌دهد که در پوشه‌شان گفتگو هست (یک پوشه `projects`). گفتگویی که چند حساب از طریق یک گروه به اشتراک می‌گذارند فقط یک بار شمرده می‌شود.
- با `-a`، حسابی که تاریخچه‌اش را از طریق یک گروه به اشتراک می‌گذارد، گفتگوهای کل گروه را هم با خود می‌آورد و ccam می‌گوید این گفتگوها متعلق به کیست: `ccam: work shares its conversation history with personal, so the report counts their conversations too`.
- `blocks` پنجره‌های ۵ ساعته را نشان می‌دهد و هر حساب پنجره‌های خودش را دارد، پس برای آن فقط یک حساب را نام ببرید، مانند نمونه بالا.
- ccusage ابزارهای کدنویسی دیگری را هم که پیدا کند، مانند Codex، گزارش می‌کند، مگر اینکه یکی را نام ببرید: `ccam ccusage claude daily` فقط Claude Code را نشان می‌دهد.
- وقتی ccam آن را اجرا می‌کند، ccusage تنظیماتش (`ccusage.json`) را فقط از `./.ccusage` و پوشه‌های حساب‌ها می‌خواند. `--config` فایل دیگری را مشخص می‌کند: `ccam ccusage daily --config ~/.config/claude/ccusage.json`.
- ccusage پوشه‌ای را که مسیرش ویرگول دارد دو پوشه می‌خواند، پس ccam آن را نمی‌پذیرد و نام حساب را می‌گوید؛ آن حساب را با `-a` کنار بگذارید.
- `ccusage` یکی از فرمان‌های ccam است، پس حسابی با نام ccusage با `ccam run ccusage` اجرا می‌شود؛ `ccam doctor` هم این را می‌گوید.

## چگونه کار می‌کند

عددهای `ccam usage` از دو جا می‌آیند: نقطه پایانی مصرف Anthropic که مستند نشده است، یعنی `GET https://api.anthropic.com/api/oauth/usage`، که با ورود خود هر حساب فراخوانی می‌شود، و مقدارهایی که Claude Code به فرمان خط وضعیت خود می‌دهد. همه این‌ها در `internal/usage` قرار دارد.

1. ccam فایل `config.toml` را بارگذاری می‌کند و برای هر حساب یک `usage.Account` می‌سازد (`cli.usageCmd`): پوشه آن `~/.local/share/ccam/profiles/<name>/`، نشانگرهای نشست آن (که همراه با سوابق خود Claude Code در پوشه حساب نشان می‌دهند در حال اجراست یا نه) و اینکه آیا در همان محل وارد شده است.
2. ccam همه حساب‌ها را هم‌زمان پرس‌وجو می‌کند، با یک goroutine برای هر حساب (`Fetcher.FetchAll`). همه آن‌ها یک `http.Client` مشترک دارند، بنابراین اتصال‌ها به نقطه پایانی دوباره استفاده می‌شوند. برقراری اتصال می‌تواند ۲ ثانیه طول بکشد و هر حساب روی هم ۳ ثانیه فرصت دارد. کلاینت هدایت‌ها را دنبال نمی‌کند، چون یک هدایت توکن را به جای دیگری می‌فرستد، و حداکثر ۱ MB از پاسخ را می‌خواند.
3. با تمام شدن کار هر حساب، ردیف آن دوباره رسم می‌شود. حسابی که ناموفق باشد یا به‌موقع پاسخ ندهد به عددهای ذخیره‌شده برمی‌گردد، بنابراین یک حساب کند هرگز بقیه را معطل نمی‌کند.

در نمودار، هر حساب در goroutine خودش پرس‌وجو می‌شود و حسابی که مهلتش تمام شود به‌جای آن عددهای ذخیره‌شده خود را نشان می‌دهد:

`personal` و `work` به‌موقع پاسخ می‌دهند و عددهای زنده را نشان می‌دهند. `side` بیش از ۳ ثانیه طول می‌کشد، پس ccam به جای آن عددهای ذخیره‌شده‌اش را نشان می‌دهد (`fallback()`). سپس ccam برای هر حساب یک بلوک رسم می‌کند (`usage.Table()`) و حسابی را که در خط آخر نام برده می‌شود انتخاب می‌کند (`usage.Best()`).

<!-- motion:usage-cache -->

1. با `--source cache`، مستقیم به `fallback()` می‌رود.
2. مگر اینکه `--no-cache` تنظیم شده باشد، یک نتیجه زنده در `~/.local/state/ccam/usage/<name>.json` که کمتر از ۶۰ ثانیه (`CacheTTL`) پیش اندازه‌گیری شده باشد، با سنجش نسبت به همین لحظه، استفاده می‌شود: پنجره‌ای که از آن پس بازنشانی شده ۰٪ نشان می‌دهد و فایلی که تاریخش از ساعت جلوتر باشد تازه به حساب نمی‌آید. اجرای دو بار پشت سر هم `ccam usage` برای هر حساب فقط یک درخواست هزینه دارد.
3. ccam فایل `.credentials.json` (یا Keychain سیستم macOS) را بدون تغییر می‌خواند و فقط کلید `claudeAiOauth` را رمزگشایی می‌کند (`readCredentials()`). نبودن ورود اشتراکی یعنی `not logged in`، یا `no limits (API)` وقتی `.claude.json` یک کلید API دارد. ورودی که توکن تمدیدش منقضی شده، یا Claude Code آن را پاک کرده است، `` login expired → `ccam login <name>` `` است و پرس‌وجو نمی‌شود.
4. توکن دسترسی منقضی‌شده استفاده نمی‌شود. بدون `--refresh`، حساب عددهای ذخیره‌شده خود را همراه با ``access token expired; `ccam <name>` renews it when it starts`` نشان می‌دهد.
5. در غیر این صورت ccam نقطه پایانی را فراخوانی می‌کند. پاسخ 401 یا 403 به‌عنوان ورود منقضی‌شده (`login expired: authentication failed (401)`) و هر وضعیت دیگر یا بدنه‌ای که نتواند بخواند به‌عنوان خطا به حساب می‌آید و در هر دو حالت به عددهای ذخیره‌شده برمی‌گردد. پرس‌وجویی که با Ctrl+C پایان یابد `cancelled` می‌گوید. پاسخ 429 یعنی نقطه پایانی برای این حساب درخواست‌های بیش از حدی دریافت کرده است: ccam فایل `<name>.pause` را با زمان پرسش بعدی می‌نویسد (`Retry-After`، یا ۵ دقیقه، حداکثر یک ساعت)، عددهای ذخیره‌شده را با `rate limited by the usage endpoint; asking again after 15:10` نشان می‌دهد و تا آن زمان، حتی با `--no-cache`، نقطه پایانی را برای آن حساب فراخوانی نمی‌کند. تلاش دوباره بلافاصله فقط محدودیت نرخ را طولانی‌تر می‌کند.
6. پاسخ درست همراه با زمان اندازه‌گیری در `<name>.json` نوشته می‌شود.

برای عددهای ذخیره‌شده، ccam تازه‌ترین پرس‌وجوی ذخیره‌شده را برمی‌دارد (`<name>.json`، یا `<name>.claude.json` از پرس‌وجوهای Claude Code) و وقتی `<name>.statusline.json` پس از آن نوشته شده باشد، پنجره‌های ۵ ساعته و هفتگی خط وضعیت را روی آن قرار می‌دهد (`fallback()`)؛ پنجره‌های مدل، که خط وضعیت آن‌ها را ندارد، همان‌طور که پرس‌وجو ذخیره کرده است می‌مانند. پیش از نشان دادن عددهای ذخیره‌شده، زمان بازنشانی هر پنجره را بررسی می‌کند: پنجره‌ای که پس از ذخیره عددها بازنشانی شده باشد ۰٪ نشان می‌دهد، چون درصد قدیمی دیگر معتبر نیست. به همین دلیل `personal` در بالا `0%` را بدون زمان بازنشانی نشان می‌دهد.

نقطه پایانی دو قالب پاسخ دارد. قالب جدیدتر یک آرایه `limits` با ورودی‌های `session` (۵ ساعته)، `weekly_all` و `weekly_scoped` (ویژه هر مدل) دارد. قالب قدیمی‌تر شیءهای `five_hour`، `seven_day`، `seven_day_opus` و `seven_day_sonnet` را دارد. ccam هر دو را می‌خواند (`ParseLive`): آرایه `limits` اولویت دارد و شیءهای قدیمی آنچه را که آن پوشش نمی‌دهد کامل می‌کنند. بدنه‌ای که هیچ سقفی نداشته باشد به‌عنوان قالب تغییرکرده گزارش می‌شود و `ccam doctor` آن را به شما اطلاع می‌دهد.

### ثبت سقف مصرف

وقتی Claude Code یک نوبت را در سقف مصرف متوقف کند، هوک [پلاگین ccam](/docs/install#claude-code-plugin) درخواست ردشده را از گفتگو می‌خواند: کدام پنجره پر بوده است (۵ ساعته، هفتگی، Opus یا Sonnet) و کی بازنشانی می‌شود. این را در `~/.local/state/ccam/usage/<name>.limit.json` می‌نویسد. ccam این ثبت را روی هر چیز دیگری که از هر منبعی می‌داند اعمال می‌کند (`Fetch`): هر پنجره‌ای که در آن است تا بازنشانی‌اش ۱۰۰٪ حساب می‌شود، هر قدر هم عددهای ذخیره‌شده قدیمی یا پایین باشند، پس `ccam next --auto`، `ccam pick`، `--fallback` و [`auto_switch`](/features/next#auto-switch) آن حساب را پیش از آن زمان دوباره انتخاب نمی‌کنند.

وقتی چیز دیگری معلوم نباشد، حساب فقط همین ثبت را نشان می‌دهد (`source: the usage limit Claude Code reported` با `-v`). نشست‌های بدون حضور کاربر (اجراهای `-p` و نشست‌های پس‌زمینه) هیچ ثبتی نمی‌نویسند، و توقفی که سازمان تعیین کرده است (برای مثال وقتی مصرف سازمان تمام شده یا سقف یک گروه $0 است) هم ثبتی نمی‌نویسد، چون مدیرانش هر زمان می‌توانند آن را بردارند. `ccam login` به حساب Claude دیگر این ثبت را کنار می‌گذارد؛ پاک کردن فایل هم آن را پاک می‌کند.

### تمدید توکن‌ها

توکن‌های تمدید چرخشی‌اند: تمدید یکی از آن‌ها یک توکن تمدید جدید به شما می‌دهد و توکن قبلی را باطل می‌کند. اگر ccam ورود را در حالی تمدید کند که Claude Code با همان حساب در حال اجراست، آن نشست از حساب خارج می‌شود. بنابراین `ccam usage` توکن‌ها را می‌خواند و هرگز آن‌ها را نمی‌نویسد، مگر اینکه `--refresh` را بدهید. در آن صورت ccam (`Fetcher.refresh`):

1. حساب‌هایی را که با `ccam import` در همان محل ثبت شده‌اند رد می‌کند، چون `claude` معمولی ممکن است بدون اطلاع ccam از آن ورود استفاده کند؛
2. ورودهایی را که در Keychain سیستم macOS ذخیره شده‌اند رد می‌کند؛
3. یک فایل قفل، `~/.local/state/ccam/locks/profile-<name>.refresh.lock`، می‌گیرد تا هرگز دو فرایند ccam هر دو یک توکن را تمدید نکنند؛ تا وقتی این قفل گرفته شده است، حساب `token not renewed: another ccam process is using this login right now (a refresh, rename, remove or logout)` را نشان می‌دهد. `ccam rename`، `remove` و `logout` هم آن را می‌گیرند و تا وقتی تمدیدی در جریان است سر باز می‌زنند؛
4. زیر قفل، اگر نشستی از آن حساب در حال اجرا باشد رد می‌کند، به هر شکلی که شروع شده باشد (از طریق ccam، `claude` معمولی، یک IDE، یا یک نشست پس‌زمینه و daemon پشت آن، که خودش ورود را تمدید می‌کند)، و اگر فرایند دیگری توکن را از قبل تمدید کرده باشد از درخواست صرف‌نظر می‌کند؛
5. تا وقتی Claude Code قفل‌های تمدید خودش را در پوشه حساب نگه داشته است (`.oauth_refresh.lock`، `<folder>.lock`) چیزی نمی‌فرستد: Claude Code همان لحظه در حال تمدید آن ورود است؛
6. توکن تمدید را به نقطه پایانی توکن می‌فرستد و تا ۳۰ ثانیه، همان زمانی که Claude Code به تمدیدهای خودش می‌دهد، منتظر پاسخ می‌ماند. درخواستی که فرستاده شد هرگز قطع نمی‌شود، حتی با Ctrl+C: ممکن است سرور توکن تمدید را از قبل عوض کرده باشد و فقط پاسخ آن ورود جدید را در خود دارد. Ctrl+C یا یک hangup پرس‌وجوهای دیگر را پایان می‌دهد و ccam پس از ذخیره شدن پاسخ خارج می‌شود (پس از Ctrl+C با کد ۱۳۰)؛
7. زیر قفل نوشتن Claude Code (`.storage-write.lock`) ذخیره می‌کند و فقط فیلدهای توکن `.credentials.json` را، به همان شکلی که در آن لحظه هست، تغییر می‌دهد: آنچه Claude Code در این مدت نوشته است (یک ورود MCP) می‌ماند، ورودی که Claude Code در این مدت تمدید کرده نگه داشته می‌شود و یک خروج هرگز برگردانده نمی‌شود. وقتی پاسخ طول عمر توکن تمدید جدید را بدهد، مانند کاری که Claude Code می‌کند، به‌صورت `refreshTokenExpiresAt` ذخیره می‌شود.

تمدیدی که انجام نشود دلیلش را می‌گوید، در خط حساب یا بالای عددهای ذخیره‌شده‌اش: برای مثال `token not renewed: a session is running`، یا `login may be lost: …` وقتی درخواستی فرستاده شده اما پاسخش را نتوان به کار برد یا ذخیره کرد، همراه با این توصیه که اگر Claude Code سپس از شما خواست وارد شوید، `ccam login <name>` را اجرا کنید.

### جمع‌آوری‌کننده خط وضعیت

Claude Code فرمان خط وضعیت را اجرا می‌کند و یک سند JSON را به ورودی آن می‌فرستد. ccam نام مدل و `rate_limits` را از آن می‌خواند:

<!-- motion:usage-statusline -->

1. ccam حساب را از `CCAM_PROFILE` پیدا می‌کند که ccam هنگام اجرای Claude Code تنظیم می‌کند، یا در غیر این صورت با مقایسه `CLAUDE_CONFIG_DIR` با پوشه‌های حساب‌ها (`runStatusline`).
2. ccam مقدارهای `rate_limits.five_hour` و `rate_limits.seven_day` را می‌خواند (`ParseStatusLine`). برای حساب‌های کلید API، یا پیش از نخستین پاسخ نشست، JSON هیچ سقف نرخی ندارد؛ در این حالت چیزی ذخیره نمی‌شود.
3. ccam فایل `~/.local/state/ccam/usage/<name>.statusline.json` را می‌نویسد (`SaveStatusLine`). `ccam usage` وقتی نقطه پایانی پاسخ ندهد از آن استفاده می‌کند.
4. ccam خط `[name] · model · 5h N% · 7d N%` را چاپ می‌کند. با `--wrap`، فرمان شما را با همان ورودی از طریق `sh -c` اجرا می‌کند و خروجی آن را به همان شکلی چاپ می‌کند که Claude Code یک خط وضعیت را نشان می‌دهد: هر خطی که خالی نباشد، با `[name]` پیش از نخستین خط. فرمانی که ناموفق باشد فقط نام حساب را نشان می‌دهد. در Windows فرمان را همان‌طور اجرا می‌کند که Claude Code اجرا می‌کند: با Git Bash اگر نصب باشد، در غیر این صورت با PowerShell.
5. وقتی مصرف ۵ ساعته یا هفتگی ۹۰٪ یا بیشتر باشد و حساب دیگری وجود داشته باشد، خط با `→ ccam next --auto --continue` تمام می‌شود، برای مثال `[work] · Opus · 5h 93% · 7d 41% · → ccam next --auto --continue`.

فرمان پیچیده‌شده محدودیت زمانی خودش را ندارد: Claude Code به فرمان خط وضعیت ۱۰ دقیقه فرصت می‌دهد و وقتی به‌روزرسانی تازه‌تری شروع شود اجرا را متوقف می‌کند، پس یک فرمان کند همان‌طور نمایش داده می‌شود که بدون ccam نمایش داده می‌شد. وقتی Claude Code به ccam پایان دهد، فرمان هم پایان می‌یابد (در Linux و macOS همراه با همه فرایندهایی که شروع کرده است).

`ccam statusline install` مقدار `statusLine` را در `settings.json` هر حساب می‌نویسد و کلیدهای دیگر آن شیء، مانند `padding`، `refreshInterval` و `hideVimModeIndicator`، را نگه می‌دارد. وقتی یک حساب از قبل فرمان خط وضعیت داشته باشد، ccam آن را به شکل `--wrap '<old command>'` نگه می‌دارد؛ در Windows به شکل `--wrap-base64 <base64>`، که در هیچ‌کدام از دو پوسته به نقل‌قول نیاز ندارد. اگر خط وضعیت از قبل ccam را اجرا کند (از مسیری دیگر، یا با نقل‌قول به شیوه‌ای که نسخه قدیمی‌تری می‌نوشت)، ccam به جای پیچیدن آن، جایگزینش می‌کند و فرمانی را که می‌پیچید نگه می‌دارد.

در Windows مسیر ccam با اسلش رو به جلو و `~` برای پوشه خانه نوشته می‌شود (`~/.local/bin/ccam.exe statusline`)، که هم Git Bash و هم PowerShell آن را می‌فهمند. مسیری که به نقل‌قول نیاز دارد به‌طور کامل برای پوسته‌ای که Claude Code به کار می‌برد نوشته می‌شود: `'…'` برای Git Bash، `& '…'` برای PowerShell. `settings.json` که از طریق یک گروه به اشتراک گذاشته شده است یک بار و از طریق پیوند خود نوشته می‌شود، بنابراین همه حساب‌های گروه آن را دریافت می‌کنند. اجرای دوباره آن برای فایل‌هایی که از قبل از ccam استفاده می‌کنند `(already set)` را چاپ می‌کند.

## ایمنی و حالت‌های خاص

- `ccam usage` هرگز فایل توکن را تغییر نمی‌دهد، مگر اینکه `--refresh` را بدهید. وقتی یک توکن دسترسی منقضی شده باشد، حساب را یک بار با `ccam <name>` اجرا کنید تا Claude Code آن را تمدید کند. ورودی که به‌طور کامل منقضی شده باشد به `ccam login <name>` نیاز دارد.
- `--refresh` هرگز به حساب‌های در حال اجرا (حتی وقتی Claude Code بدون ccam شروع شده باشد)، حساب‌های واردشده یا ورودهای Keychain دست نمی‌زند. تمدیدی که رد شود عددهای ذخیره‌شده و دلیل آن را نشان می‌دهد (`token not renewed: …`).
- نقطه پایانی مصرف به‌طور عمومی مستند نشده است و ممکن است تغییر کند. وقتی تغییر کند، همچنان عددهای ذخیره‌شده را می‌بینید و `ccam doctor` تغییر قالب را گزارش می‌دهد.
- وقتی نه عدد ذخیره‌شده‌ای باشد و نه پاسخی، خط حساب `lookup failed:` و دلیل آن را نشان می‌دهد، برای مثال `no saved usage` با `--source cache`.
- فایل‌های حافظه نهان فقط درصدها و زمان‌های بازنشانی را نگه می‌دارند، هرگز توکن‌ها را.
