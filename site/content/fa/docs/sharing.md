هر حساب ورود خود را جداگانه نگه می‌دارد. همه چیزهای دیگر را می‌توان از طریق **گروه‌ها** به اشتراک گذاشت: یک گروه مواردی را که به اشتراک می‌گذارد و حساب‌های عضوش را نام می‌برد، و ccam فایل‌های هر یک از آن حساب‌ها را به پوشه گروه پیوند می‌دهد، بنابراین تغییری که در یک حساب ایجاد شود در همه آن‌ها دیده می‌شود.

## چه چیزهایی را می‌توان به اشتراک گذاشت

| مورد | آنچه مشترک می‌شود |
| --- | --- |
| `mcp` | سرورهای MCP: فایل `mcp.json` گروه که هنگام اجرا به Claude Code داده می‌شود |
| `settings` | `settings.json`: مجوزها، hookها، مدل، خط وضعیت |
| `memory` | فایل سراسری `CLAUDE.md` |
| `extensions` | `agents/`، `commands/`، `skills/`، `plugins/`، `output-styles/`، `rules/` |
| `history` | تاریخچه گفتگو: `projects/` و `history.jsonl` |

نخستین حساب شما گروه `default` را می‌سازد که همه چیز را به جز تاریخچه گفتگو به اشتراک می‌گذارد، و حساب‌های بعدی به آن می‌پیوندند.

فایل‌های ورود `.credentials.json` و `.claude.json` هرگز به اشتراک گذاشته نمی‌شوند. ccam فقط مسیرهای یک فهرست ثابت را پیوند می‌دهد و این دو فایل در آن فهرست نیستند.

این صفحه کارهای روزمره را پوشش می‌دهد. همه گزینه‌ها در صفحه‌های ویژگی‌ها توضیح داده شده‌اند: [اشتراک‌گذاری با گروه‌ها](/features/share)، [سرورهای MCP مشترک](/features/mcp) و [کپی کردن یک پیکربندی موجود](/features/migrate).

## گروه‌ها

```sh
ccam group                                   # the groups, what they share, their accounts
ccam group set default --add history         # every account in default shares history
ccam group add team --items history --members work,side
```

یک حساب می‌تواند در چند گروه باشد، اما هر مورد فقط از یک گروه می‌آید. پس برای اینکه تاریخچه را بین `work` و `side` به اشتراک بگذارید اما نه با حساب‌های دیگرتان، تاریخچه را بیرون از `default` نگه دارید و مانند بالا به آن دو گروهی مخصوص خودشان بدهید. `ccam share work` نشان می‌دهد یک حساب چه چیزهایی را و از طریق کدام گروه به اشتراک می‌گذارد. [داشبورد](/features/dashboard) همین کار را در زبانه Groups خود انجام می‌دهد.

## وقتی یک حساب اشتراک‌گذاری را آغاز می‌کند

وقتی یک حساب اشتراک‌گذاری یک مورد را آغاز می‌کند (به گروهی می‌پیوندد، یا گروهش آن مورد را اضافه می‌کند)، ccam:

1. برای هر حساب برنامه‌ای از همه فایل‌هایی که جابه‌جا، کپی یا پیوند خواهد داد چاپ می‌کند و پیش از شروع از شما می‌پرسد؛
2. اگر گروه هنوز خالی باشد، فایل‌های حساب را به پوشه گروه منتقل می‌کند، وگرنه فایل‌هایی را که گروه هنوز ندارد اضافه می‌کند؛
3. وقتی یک فایل در دو طرف متفاوت باشد، می‌پرسد که نسخه گروه نگه داشته شود، نسخه شما استفاده شود یا JSON آن‌ها ادغام شود؛
4. نسخه اصلی شما را در `.ccam-backup/<time>/` داخل پوشه حساب نگه می‌دارد؛
5. نسخه اصلی را با پیوندی به گروه جایگزین می‌کند.

نام فایل‌های گفتگو از شناسه نشست آن‌ها گرفته می‌شود، بنابراین تاریخچه چند حساب بدون تداخل با هم ترکیب می‌شود.

تا وقتی Claude Code با یک حساب در حال اجراست، ccam آن حساب را تغییر نمی‌دهد، Claude Code به هر شکلی که شروع شده باشد (نشست‌های پس‌زمینه هم)، چون نشست همچنان در فایل‌هایی که جابه‌جا می‌شوند می‌نویسد. ابتدا آن را ببندید. ccam درست پیش از ذخیره کردن دوباره بررسی می‌کند، پس نشستی که در مدت انتظار برنامه شروع شده باشد هم شناسایی می‌شود.

## وقتی یک حساب اشتراک‌گذاری را متوقف می‌کند

```sh
ccam group leave team work                   # work leaves the group
ccam group set default --remove history      # nobody in default shares history any more
```

پیوند حذف می‌شود و حساب یک نسخه از محتوای فعلی گروه را برای خودش می‌گیرد؛ سرورهای MCP گروه در `.claude.json` خود آن حساب، کنار سرورهای خودش، قرار می‌گیرند. برای اینکه به‌جای آن از صفر شروع کنید، `--fresh` را اضافه کنید؛ آن‌وقت برنامه سرورهای MCP را که دیگر بارگذاری نمی‌شوند فهرست می‌کند. یک پوشه واردشده مانند `~/.claude` همیشه یک نسخه نگه می‌دارد. گروه محتوای خود را برای حساب‌های دیگر نگه می‌دارد.

## کپی کردن یک پیکربندی موجود

اگر پیش از ccam از Claude Code استفاده کرده‌اید، تنظیمات شما در `~/.claude` است. `ccam migrate` آن‌ها را در یک گروه کپی می‌کند تا همه حساب‌هایی که این موارد را به اشتراک می‌گذارند آن‌ها را داشته باشند:

```sh
ccam migrate
```

در ترمینال، ccam ابتدا فهرستی از موارد را برای انتخاب نشان می‌دهد. همه چیز به جز تاریخچه گفتگو علامت خورده است؛ برای تغییر یک مورد Space و برای دیدن برنامه Enter را بزنید. مواردی که پوشه چیزی برایشان ندارد با `not found` مشخص می‌شوند.

چه چیزهایی کپی می‌شود:

- `settings.json` و فایل سراسری `CLAUDE.md`؛
- افزونه‌های `agents/`، `commands/`، `skills/`، `plugins/`، `output-styles/` و `rules/`؛
- سرورهای MCP کاربر، یعنی بخش `mcpServers` در `~/.claude.json`، به فایل `mcp.json` گروه؛
- تاریخچه گفتگو (`projects/` و `history.jsonl`)، اما فقط وقتی `--history` را اضافه کنید.

پوشه مبدأ فقط خوانده می‌شود: هیچ چیزی در آن جابه‌جا، پیوند یا تغییر داده نمی‌شود و `claude` معمولی مثل قبل کار می‌کند. فایل‌های ورود `.credentials.json` و `.claude.json` هرگز در گروه کپی نمی‌شوند.

سرورهای MCP که با OAuth وارد می‌شوند توکن‌های خود را در اطلاعات ورود نگه می‌دارند، نه در فهرست سرورها. ccam این ورودها را کپی نمی‌کند: یک ورود کپی‌شده همان توکن تازه‌سازی را دارد و نخستین تمدید، همه دارندگان دیگر را از آن سرور خارج می‌کند، از جمله `~/.claude`. برنامه و خلاصه پایانی حساب‌هایی را نام می‌برند که باید خودشان با `/mcp` وارد سرورها شوند.

ccam پیش از کپی کردن هر چیزی، برنامه را چاپ می‌کند و از شما می‌پرسد:

```console
$ ccam migrate
Copy from /home/me/.claude into group default (/home/me/.local/share/ccam/groups/default):
  mcp         ~/.claude.json  new: context7, fs
  settings    settings.json   new: 80 B
  memory      CLAUDE.md       new: 31 B
  extensions  agents/         add 1 file the group lacks (17 B)
              commands/       add 1 file the group lacks (15 B)
              skills/         add 1 file the group lacks (32 B)
              not found, skipped: plugins/, output-styles/, rules/
  Conversation history (projects/, history.jsonl) is not included; add --history to copy it.
Copy these into group default? [y/N] y
✓ Copied into group default: 2 MCP servers, settings.json, CLAUDE.md, agents/, commands/, skills/
Group default: personal
To share them:
  ccam group join default work
```

در پایان، ccam حساب‌های گروه را فهرست می‌کند. اگر گروه هنوز یکی از موارد را به اشتراک نگذارد، یا برخی حساب‌ها در آن نباشند، فرمان‌های `ccam group` را که این را تغییر می‌دهند چاپ می‌کند.

وقتی گروه از قبل نسخه متفاوتی از یک فایل دارد، ccam همان‌طور که هنگام روشن کردن اشتراک‌گذاری می‌پرسد، از شما می‌پرسد: نسخه گروه نگه داشته شود یا نسخه شما استفاده شود. `settings.json` و دیگر فایل‌های JSON را می‌توان ادغام هم کرد و `history.jsonl` را خط به خط. نسخه‌های قبلی گروه در `.ccam-backup/<time>/` درون پوشه گروه ذخیره می‌شوند.

| گزینه | اثر |
| --- | --- |
| `--settings`، `--memory`، `--extensions`، `--mcp`، `--history` | فقط مواردی را که نام می‌برید کپی می‌کند، بدون فهرست انتخاب؛ بدون آن‌ها و بیرون از ترمینال، همه چیز به جز تاریخچه گفتگو |
| `-g`، `--group <group>` | به‌جای `default` در این گروه کپی می‌کند |
| `-y`، `--yes` | بدون پرسش کپی می‌کند؛ وقتی فایلی متفاوت باشد، نسخه گروه را نگه می‌دارد |

`--dry-run` را پیش از فرمان بگذارید، مانند `ccam --dry-run migrate`، تا برنامه را بدون کپی کردن چیزی ببینید. برای کپی از پوشه‌ای دیگر، نام آن را بدهید: `ccam migrate ~/.claude-work --group work`.

## سرورهای MCP

Claude Code سرورهای MCP را همراه با اطلاعات ورود در `.claude.json` ذخیره می‌کند، بنابراین نمی‌توان آن فایل را به اشتراک گذاشت. ccam سرورهای مشترک را در `mcp.json` گروه نگه می‌دارد و Claude Code را با `--mcp-config=<group>/mcp.json` اجرا می‌کند. گزینه‌های `--mcp-config` خود شما همچنان روی آن اعمال می‌شوند.

```sh
ccam mcp add fs -- npx -y @modelcontextprotocol/server-filesystem ~/code
ccam mcp list
```

سروری که داخل یک نشست با `claude mcp add` اضافه کنید فقط برای همان حساب ذخیره می‌شود، و برای پوشه‌ای که در آن بودید (دامنه local خود Claude Code؛ `-s user` آن را در همه پوشه‌ها مال آن حساب می‌کند). دفعه بعد که آن حساب را اجرا کنید، ccam نام سرور را همراه با پوشه‌اش و فرمانی را که آن را به گروه منتقل می‌کند نشان می‌دهد:

```sh
ccam mcp import work gh
```

اگر گروه از قبل سرور دیگری با همین نام داشته باشد، ccam آن را رد می‌کند و این را اعلام می‌کند. `--force` سرور گروه را جایگزین می‌کند و `mcp.json` قدیمی را در پوشه `.ccam-backup/` گروه نگه می‌دارد.

سرورهای MCP که با OAuth وارد می‌شوند توکن‌های خود را کنار اطلاعات ورود حساب ذخیره می‌کنند، پس باید در هر حساب یک بار با `/mcp` به آن‌ها مجوز بدهید. `ccam ext` و `ccam doctor` سرورهایی را نام می‌برند که یک حساب واردشان نشده اما حساب دیگری وارد شده است.

اگر ترجیح می‌دهید سرورها در `claude mcp list` و `/mcp` به شکل سرورهای عادی کاربر دیده شوند، در بالای `~/.config/ccam/config.toml`، بالای نخستین `[[group]]`، `[[profile]]` یا `[[folder]]`، مقدار `mcp_strategy = "sync"` را تنظیم کنید. در این حالت ccam پیش از اجرا، آن‌ها را با استفاده از قفل فایل خود Claude Code و با نسخه پشتیبان در `.claude.json` هر حساب می‌نویسد. سروری که حساب با همان نام از خودش دارد مال همان حساب می‌ماند و ccam این را می‌گوید.

## دو حساب در یک پوشه

حساب‌هایی که تاریخچه گفتگو را به اشتراک می‌گذارند در فایل‌های یکسانی می‌نویسند. اگر Claude Code دومی را در پوشه‌ای اجرا کنید که حساب دیگری از همان گروه در آن در حال اجراست، ccam به شما هشدار می‌دهد و می‌پرسد که ادامه دهد یا نه.

## وقتی چیزی خراب می‌شود

```sh
ccam doctor
ccam doctor --fix
```

اگر یک مسیر مشترک به فایل عادی تبدیل شده باشد، برای مثال پس از آنکه یک نسخه پشتیبان را دستی بازگردانده‌اید، ccam پیش از اجرای Claude Code متوقف می‌شود و شما را به `ccam doctor --fix` ارجاع می‌دهد؛ این فرمان آن را دوباره به گروه پیوند می‌دهد: اگر گروه نسخه‌ای نداشته باشد، فایل نسخه گروه می‌شود، و در غیر این صورت گروه نسخه خودش را نگه می‌دارد و نسخه شما به یک نسخه پشتیبان می‌رود که `--fix` نامش را می‌برد. تغییری در گروه‌ها که نیمه‌کاره متوقف شده باشد هم با `ccam doctor --fix` تمام می‌شود.
