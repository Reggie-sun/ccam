Claude Code اکاؤنٹس تبدیل کرنے والے ٹولز دو میں سے ایک طریقہ اپناتے ہیں۔ زیادہ تر ٹولز ایک ہی `~/.claude` فولڈر کے اندر لاگ اِن بدل دیتے ہیں، اس لیے ایک وقت میں ایک ہی اکاؤنٹ فعال ہوتا ہے۔ کچھ دوسرے، جن میں ccam بھی شامل ہے، `CLAUDE_CONFIG_DIR` کے ذریعے ہر اکاؤنٹ کو اس کا اپنا فولڈر دیتے ہیں، اس لیے ہر اکاؤنٹ لاگ اِن رہتا ہے اور کئی اکاؤنٹس بیک وقت چل سکتے ہیں۔ ccam اس کے ساتھ سیٹنگز اور MCP سرورز کی شیئرنگ بھی دیتا ہے، اور گفتگو کو دوسرے اکاؤنٹ کے فولڈر میں جاری رکھتا ہے۔

## ایک لاگ اِن بدلنا یا الگ فولڈرز؟

**لاگ اِن بدلنے** میں سیٹنگز، MCP سرورز اور ہسٹری کا ایک ہی سیٹ رہتا ہے، کیونکہ فولڈر ایک ہی ہوتا ہے۔ اکاؤنٹ جلدی بدلتا ہے، اور چلتا ہوا سیشن نیا لاگ اِن لے سکتا ہے۔ لیکن ایک وقت میں صرف ایک اکاؤنٹ فعال ہوتا ہے، اور وہ بھی تمام ٹرمینلز اور ایڈیٹرز کے لیے ایک ساتھ۔

لاگ اِن بدلنے کے لیے ٹول ہر دوسرے اکاؤنٹ کے لاگ اِن کی ایک کاپی رکھتا ہے اور اسے اس کی جگہ لکھ دیتا ہے۔ Claude Code لاگ اِن کی تجدید کرتے وقت اس کا ریفریش ٹوکن بدل دیتا ہے، اس لیے ہر محفوظ کاپی کو چلتے ہوئے سیشنز کے ساتھ ہم آہنگ رکھنا پڑتا ہے۔ اکاؤنٹ بدلنے کے بعد لاگ آؤٹ ہو جانے والے یا دوبارہ `/login` مانگنے والے اکاؤنٹس ان مسائل میں شامل ہیں جنہیں یہ پروجیکٹس سب سے زیادہ ٹھیک کرتے ہیں۔

**الگ فولڈرز** وہ طریقہ ہے جو [Claude Code کی دستاویزات میں بیان کیا گیا ہے](https://code.claude.com/docs/en/authentication#log-in-with-multiple-accounts)۔ ہر اکاؤنٹ لاگ اِن رہتا ہے، اور آپ کام اور ذاتی سیشن ساتھ ساتھ چلا سکتے ہیں۔ ہر لاگ اِن اپنے فولڈر میں رہتا ہے، جہاں Claude Code معمول کے مطابق اس کی تجدید کرتا ہے۔ اس کی قیمت یہ ہے کہ ہر فولڈر اپنی سیٹنگز، MCP سرورز اور ہسٹری کے ساتھ شروع ہوتا ہے، جب تک کوئی ٹول انہیں شیئر نہ کرے۔

## ccam کیا اچھا کرتا ہے

### لاگ اِنز وہیں رہتے ہیں جہاں Claude Code نے انہیں رکھا

ccam کبھی Claude لاگ اِن کو ایک جگہ سے دوسری جگہ کاپی نہیں کرتا۔ ہر اکاؤنٹ کا لاگ اِن اس کے اپنے فولڈر میں رہتا ہے، یا macOS پر اس فولڈر کے اپنے Keychain آئٹم میں، اور اس کی تجدید Claude Code ہی کرتا ہے۔ کوئی محفوظ کاپی نہیں جو ہم آہنگی کھو دے۔ `ccam import` سے رجسٹر کیا گیا موجودہ `~/.claude` وہی Keychain آئٹم رکھتا ہے جو عام `claude` استعمال کرتا ہے، اس لیے وہ دونوں طرح لاگ اِن رہتا ہے۔

ccam کسی میعاد ختم ٹوکن کی خود تجدید صرف تب کرتا ہے جب آپ `ccam usage --refresh` چلائیں۔ یہ پہلے ایک لاک لیتا ہے اور جب تک وہ اکاؤنٹ چل رہا ہو انکار کرتا ہے، چاہے Claude Code کسی بھی طرح شروع ہوا ہو (بیک گراؤنڈ سیشنز اور ان کا daemon بھی)، اور جب Claude Code خود وہ لاگ اِن تازہ کر رہا ہو تب بھی، اس لیے یہ کبھی کسی چلتے سیشن کے نیچے ٹوکن نہیں بدلتا۔

### آپ اور Claude Code کے درمیان کچھ نہیں چلتا

ccam ایک فائل پڑھتا ہے، اس کے لنکس جانچتا ہے اور خود کو `claude` سے بدل دیتا ہے (`exec`)۔ کام کے دوران کوئی ccam پروسیس، ریپر، پراکسی یا ڈیمن نہیں ہوتا: اسٹینڈرڈ اِن پٹ، سگنلز اور ایگزٹ کوڈ Claude Code کے ہوتے ہیں، اور اس کی درخواستیں سیدھی Anthropic کو جاتی ہیں۔ Windows کسی پروسیس کو بدل نہیں سکتا، اس لیے وہاں ccam اسی کنسول کے ساتھ Claude Code شروع کرتا ہے اور اس کے ایگزٹ کوڈ کا انتظار کرتا ہے، اور کچھ نہیں کرتا۔

اس طرح اکاؤنٹ شروع کرنے میں تقریباً 4 ms لگتے ہیں، 95ویں پرسنٹائل پر 6 ms سے کم، اور زیادہ سے زیادہ میموری 8 MB ([`scripts/perf-check.sh`](https://github.com/jhyunwoo/ccam/blob/main/scripts/perf-check.sh) کے ساتھ hyperfine، 300 رنز)۔ اسی لیپ ٹاپ پر، کسی پروگرام کے کچھ کرنے سے پہلے صرف Python انٹرپریٹر شروع ہونے میں 13 ms اور Node.js میں 31 ms لگتے ہیں۔

### گروپس طے کرتے ہیں کہ کیا شیئر ہو

MCP سرورز، `settings.json`، `CLAUDE.md`، ایکسٹینشنز (ایجنٹس، کمانڈز، اسکلز، پلگ اِنز) اور گفتگو کی ہسٹری پانچ الگ آئٹمز ہیں۔ ایک گروپ ان آئٹمز کا نام لیتا ہے جو وہ شیئر کرتا ہے اور ان اکاؤنٹس کا جو اس میں ہیں، اس لیے دو کام والے اکاؤنٹس `work` گروپ میں ہسٹری شیئر کر سکتے ہیں جبکہ ایک ذاتی اکاؤنٹ اپنی ہسٹری الگ رکھتا ہے، اور تینوں `default` کے ذریعے ایک ہی MCP سرورز شیئر کرتے ہیں۔ `ccam group set work --add memory` گروپ کے ہر اکاؤنٹ کو ایک ہی پلان میں منتقل کرتا ہے؛ [ڈیش بورڈ](/features/dashboard) چیک باکسز سے یہی کرتا ہے اور اس آئٹم کو مدھم کر دیتا ہے جو کسی اکاؤنٹ کو پہلے ہی کسی دوسرے گروپ سے مل رہا ہو۔

- MCP سرورز لانچ کے وقت `--mcp-config` سے دیے جاتے ہیں، اس لیے ڈیفالٹ طور پر لانچ `.claude.json` کو، جو وہ فائل ہے جسے Claude Code چلتے وقت دوبارہ لکھتا ہے، نہیں چھیڑتا۔ ccam وہاں صرف ان مراحل میں لکھتا ہے جو یہ بتاتے ہیں، Claude Code کے لاک کے تحت اور بیک اپ کے ساتھ: Remote Control کے لیے پوچھنے کے بعد، جب کوئی اکاؤنٹ MCP شیئرنگ چھوڑے یا دوبارہ شامل ہو، اور `ccam mcp import` کے لیے۔ `ccam mcp add` پورے گروپ کے لیے ایک ہی بار سرور جوڑ دیتا ہے۔
- باقی آئٹمز گروپ فولڈر کی طرف لنکس ہیں، اس لیے ایک اکاؤنٹ میں کی گئی تبدیلی فوراً دوسروں میں نظر آتی ہے۔ لانچ کے وقت کچھ کاپی نہیں ہوتا۔
- لاگ اِنز، `.claude.json` اور چلتی ہوئی حالت کبھی شیئر نہیں ہوتے۔

### ہر تبدیلی پہلے دکھائی جاتی ہے اور اس کا بیک اپ بنتا ہے

`ccam group` اور `ccam migrate` کچھ بھی منتقل کرنے سے پہلے ایک پلان دکھاتے اور پوچھتے ہیں۔ جب کوئی فائل اکاؤنٹ اور اس کے گروپ میں مختلف ہو تو آپ چنتے ہیں: گروپ والی رکھیں، اپنی استعمال کریں، یا JSON کو ملا دیں؛ فولڈرز کے اندر گروپ والی کاپی رہتی ہے اور پلان مختلف فائلوں کے نام بتاتا ہے۔ اصل فائلیں `.ccam-backup/<time>/` میں جاتی ہیں، ہٹایا گیا اکاؤنٹ لاگ آؤٹ ہوتا ہے اور اس کا فولڈر ٹریش فولڈر میں جاتا ہے، اور فائلیں ایک ہی rename میں بدلی جاتی ہیں، اس لیے ادھوری رہ جانے والی تحریر پرانی فائل کو برقرار چھوڑتی ہے۔ `--dry-run` دکھاتا ہے کہ لانچ، شیئرنگ، مائیگریشن، شارٹ کٹس، اپ ڈیٹس اور مرمت کیا کریں گے۔ `ccam doctor --fix` ٹوٹے ہوئے لنکس اور اجازتیں ٹھیک کرتا ہے۔

### اگلے اکاؤنٹ میں وہی گفتگو

`ccam next --auto --continue` تمام اکاؤنٹس سے ایک ساتھ ان کا استعمال پوچھتا ہے، سب سے زیادہ گنجائش والا اکاؤنٹ کھولتا ہے اور گفتگو جاری رکھتا ہے۔ شیئر شدہ ہسٹری کے ساتھ یہ وہی گفتگو ہوتی ہے؛ اس کے بغیر Claude Code اسے نئے اکاؤنٹ میں کاپی کر دیتا ہے (`--resume <file> --fork-session`)، اور ccam بتاتا ہے کہ پہلا جواب کتنے ٹوکنز دوبارہ پڑھے گا۔ جب کوئی حد سیشن کو روک دے تو ccam پلگ اِن کا ہُک ایک اطلاع دکھاتا ہے، اور `/ccam:switch` گفتگو آگے سونپ دیتا ہے۔ کب بدلنا ہے یہ آپ طے کرتے ہیں؛ پس منظر میں کوئی چیز آپ کے استعمال پر نظر نہیں رکھتی، اور خودکار انتخاب ایک ہی تنظیم کے اندر رہتے ہیں، اس لیے کمپنی کی گفتگو کبھی غلطی سے کسی نجی اکاؤنٹ پر نہیں پہنچتی۔ جب کوئی اکاؤنٹ 90% تک پہنچ جائے تو اسٹیٹس لائن یہ کمانڈ تجویز کرتی ہے۔

اسکرپٹس آپ کا انتظار نہیں کر سکتے، اس لیے `ccam --fallback work -p "…"` ان کے لیے اکاؤنٹ بدلتا ہے: جب اکاؤنٹ اپنی حد کو پہنچ جائے تو وہی کمانڈ سب سے زیادہ گنجائش والے اکاؤنٹ سے دوبارہ چلتی ہے، اور صرف اس رن کا آؤٹ پٹ پرنٹ ہوتا ہے جو مکمل ہوا۔ جو ناکامی استعمال کی حد کی وجہ سے نہ ہو وہ جوں کی توں آگے دی جاتی ہے۔ متوازی ورکرز کے لیے `ccam pick` ہر ایک کو گنجائش والا الگ اکاؤنٹ دیتا ہے، اور جب کسی اکاؤنٹ میں گنجائش نہ بچے تو دونوں کوڈ 75 کے ساتھ باہر نکلتے ہیں۔

**Team اور Enterprise سیٹیں۔** خودکار انتخاب (`ccam next`، `--fallback`، `ccam pick`، ڈیش بورڈ کی `n` کلید) ایک ہی Claude Team یا Enterprise تنظیم کی سیٹوں کے درمیان بھی اکاؤنٹ بدلتا ہے۔ Anthropic کا ہیلپ سینٹر کہتا ہے کہ "Each seat on a Team plan is assigned to one named individual, and only that person may use it" (کسی Team پلان کی ہر سیٹ ایک نامزد فرد کو تفویض کی جاتی ہے، اور صرف اسی شخص کو اسے استعمال کرنے کی اجازت ہے) اور "Users can't route their work through another user's account to use that user's remaining usage" (صارفین کسی دوسرے صارف کا باقی ماندہ استعمال کام میں لانے کے لیے اپنا کام اس کے اکاؤنٹ کے ذریعے نہیں چلا سکتے) ([Team پلانز](https://support.claude.com/en/articles/12004354-purchase-and-manage-seats-on-team-plans#h_b8a7d07129)؛ اسی طرح [Enterprise پلانز](https://support.claude.com/en/articles/13393991-purchase-and-manage-seats-on-enterprise-plans#h_fa6b9cade0) کے لیے بھی)۔ اس لیے سیٹوں کے درمیان خودکار انتخاب استعمال کرنے سے Anthropic کی شرائط کی خلاف ورزی ہو سکتی ہے۔ اس پر انحصار کرنے سے پہلے اپنی تنظیم اور Anthropic سے تصدیق کر لیں۔ ذاتی پلانز (Pro، Max) کی بات [عام سوالات میں شرائط والے نوٹ](/docs/faq#am-i-allowed-to-use-several-claude-code-accounts) میں کی گئی ہے۔

### ہر فولڈر میں صحیح اکاؤنٹ

`ccam folder work ~/code/company` اس فولڈر کے اندر اکاؤنٹ کے نام کے بغیر ہر لانچ کو `work` استعمال کرواتا ہے، جبکہ آپ کے باقی پروجیکٹس ڈیفالٹ اکاؤنٹ پر رہتے ہیں۔ یہ سیٹنگ اسی `config.toml` میں رہتی ہے جسے ہر لانچ پڑھتا ہے، اس لیے اس میں کوئی وقت نہیں لگتا۔

### ایک بائنری، جانچے ہوئے ڈاؤن لوڈز

ccam تقریباً 10 MB کی ایک اسٹیٹک بائنری ہے جس کے لیے کوئی رن ٹائم انسٹال نہیں کرنا پڑتا، Linux، macOS اور Windows کے لیے۔ انسٹال اسکرپٹس (`install.sh`، `install.ps1`) اور `ccam update` ہر ڈاؤن لوڈ کو ریلیز کے SHA-256 چیک سمز سے جانچتے ہیں، اور ccam پوچھے بغیر کبھی اپ ڈیٹ نہیں ہوتا۔ اس میں کوئی ٹیلی میٹری نہیں: یہ صرف آپ کے اکاؤنٹس کے لیے Anthropic سے استعمال کی معلومات مانگتا ہے، متوازی طور پر 3 سیکنڈ کی حد اور 60 سیکنڈ کے کیش کے ساتھ، ڈیش بورڈ کھلنے پر GitHub سے تازہ ترین ریلیز کے بارے میں پوچھتا ہے، اور وہ ڈاؤن لوڈز کرتا ہے جو آپ کہیں۔ `usage_source = "claude"` کے ساتھ یہ معلومات بھی Claude Code کے ذریعے آتی ہیں، اور ccam کبھی کسی ٹوکن کو ہاتھ نہیں لگاتا۔

## جہاں دوسرے ٹولز زیادہ کرتے ہیں

- claude-swap، clauth، cux، CAAM اور CCSwitcher کسی اکاؤنٹ کے استعمال کی حد پار کرنے پر چلتے ہوئے انٹرایکٹو سیشن کا اکاؤنٹ خود بدل سکتے ہیں۔ ccam `--fallback` کے ساتھ `-p` رنز کا اکاؤنٹ بدلتا ہے اور انٹرایکٹو سیشنز آپ پر چھوڑتا ہے، حد پر ایک اطلاع اور `/ccam:switch` کے ساتھ۔
- Developer Mode کے بغیر Windows پر ccam فولڈرز شیئر کرتا ہے لیکن `settings.json` جیسی اکیلی فائلیں شیئر نہیں کر سکتا (تب پہلا `ccam add` صرف MCP سرورز اور ایکسٹینشنز شیئر کرتا ہے)؛ claude-swap اور CCS وہاں انہیں کاپی کر دیتے ہیں۔
- CCSwitcher، Claude Switcher اور claude-swap استعمال کو macOS مینو بار میں دکھاتے ہیں۔
- CCS، clausona، CAAM، clauth، ccswap اور Claude Switcher، Codex اور دوسرے کوڈنگ ایجنٹس کو بھی سنبھالتے ہیں۔
- clausona ہر اکاؤنٹ کے لیے ایکسٹینشنز آن اور آف بھی کرتا ہے (ccam کا `ccam ext` انہیں صرف دکھاتا ہے)، ٹوکنز کی لاگت لوکل طور پر ٹریک کرتا ہے، اور ایسے Claude Code پلگ اِنز کے ساتھ آتا ہے جو tmux اور دوسرے ٹرمینلز میں ورکرز کے پورے بیڑے چلاتے ہیں۔
- CAAM، CCSwitcher اور Claude Switcher، Homebrew سے انسٹال ہوتے ہیں، اور clauth اور CAAM اپنے ریلیز چیک سمز پر دستخط کرتے ہیں۔ ccam اپنے اسکرپٹ، ایک `.deb` یا `go install` سے انسٹال ہوتا ہے، اور چیک سمز کو بغیر دستخط کے جانچتا ہے۔

## کون سا موزوں ہے؟

اگر آپ ایک وقت میں ایک اکاؤنٹ استعمال کرتے ہیں یا چاہتے ہیں کہ چلتے ہوئے سیشنز خود بخود بدلیں تو لاگ اِن بدلنے والا ٹول چنیں۔ اگر آپ اکاؤنٹس ساتھ ساتھ، ایک شیئر شدہ سیٹ اپ، اگلے اکاؤنٹ میں وہی گفتگو اور Claude Code کے ساتھ کچھ نہ چلنا چاہتے ہیں، Linux، macOS یا Windows پر، تو ccam چنیں۔ اگر آپ کو کچھ بھی شیئر نہیں کرنا تو [سادہ شیل ایلیاسز](/compare/aliases) کافی ہیں۔

آپ کئی اکاؤنٹس استعمال کر سکتے ہیں یا نہیں، یہ ہر اکاؤنٹ کی شرائط پر منحصر ہے۔ ایسا کرنے سے پہلے انہیں دیکھ لیں۔
