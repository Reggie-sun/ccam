جب کوئی اکاؤنٹ استعمال کی حد تک پہنچ جائے (جسے اکثر rate limit کہا جاتا ہے) تو آپ کے پاس دو راستے ہیں: حد ری سیٹ ہونے تک انتظار کریں، یا وہی گفتگو ابھی اپنے کسی دوسرے اکاؤنٹ پر جاری رکھیں۔ ccam کے ساتھ دوسرے راستے کے لیے ایک کمانڈ کافی ہے، `ccam next --auto --continue`۔

## Claude Code کی کون سی حدیں ہیں؟

Pro اور Max پلانز پر Claude Code کی [5 گھنٹے کی سیشن حد اور ایک ہفتہ وار حد](https://support.claude.com/en/articles/11145838-using-claude-code-with-your-pro-or-max-plan) ہوتی ہے۔ دونوں حدیں ویب اور ایپس والے Claude کے ساتھ مشترک ہیں، اور استعمال دونوں میں ایک ساتھ شمار ہوتا ہے۔ جب ایک ختم ہو جائے تو Claude Code [ایک پیغام دکھاتا ہے](https://code.claude.com/docs/en/errors#youve-hit-your-session-limit)، جیسے "You've hit your session limit · resets 3:45pm"۔ ماڈل بدلنے سے فائدہ نہیں ہوتا، کیونکہ یہ حدیں تمام ماڈلز پر لاگو ہوتی ہیں۔

## پہلا راستہ: ری سیٹ کا انتظار کریں

اگر آپ کے پاس ایک ہی اکاؤنٹ ہے تو انتظار کریں۔ Claude Code کے حالیہ ورژن [کھلے سیشن میں انتظار کرتے ہیں](https://code.claude.com/docs/en/interactive-mode#wait-for-a-usage-limit-to-reset) اور حد ری سیٹ ہوتے ہی خود کام جاری رکھتے ہیں۔ Claude Code کے اندر `/usage` دکھاتا ہے کہ آپ نے اپنے پلان کی حدوں میں سے کتنا استعمال کر لیا ہے۔

## دوسرا راستہ: ابھی دوسرے اکاؤنٹ پر جاری رکھیں

اگر آپ کے پاس دوسرا اکاؤنٹ ہے تو آپ وہی گفتگو فوراً جاری رکھ سکتے ہیں۔ اسے ایک بار سیٹ اپ کریں:

```sh
curl -fsSL https://ccam.dev/install.sh | sh
ccam add personal
ccam add work
ccam group set default --add history
ccam statusline install
```

اب کام کے دوران اسٹیٹس لائن اکاؤنٹ اور اس کا 5 گھنٹے کا استعمال دکھاتی ہے، اس لیے حد اچانک سامنے نہیں آتی۔

جب حد پوری ہو جائے تو Claude Code سے باہر نکلیں (`/exit`)، پھر:

```sh
ccam usage
```

```console
 1 personal  just now
   5-hour   ████████████████████ 100%  resets in 22m
   Weekly   ██████████████░░░░░░  68%  resets in 1d 9h
 2 work      just now
   5-hour   ██░░░░░░░░░░░░░░░░░░   8%  resets in 4h 12m
   Weekly   ████░░░░░░░░░░░░░░░░  19%  resets in 5d 2h
→ Most headroom: work   (open it with ccam next --auto)
```

سب سے زیادہ گنجائش والے اکاؤنٹ میں گفتگو کھولیں:

```sh
ccam next --auto --continue
```

Claude Code، `work` کے طور پر موجودہ فولڈر کی سب سے حالیہ گفتگو کے ساتھ شروع ہوتا ہے، جس میں اب تک کی ہر بات شامل ہوتی ہے۔ ہسٹری شیئر کرنے (اوپر `ccam group set default --add history`) کا مطلب ہے کہ دونوں اکاؤنٹس ایک ہی گفتگو پر کام کرتے ہیں؛ اس کے بغیر Claude Code گفتگو کو `work` میں کاپی کر دیتا ہے، اور ccam بتاتا ہے کہ پہلے جواب کو کتنے ٹوکنز دوبارہ پڑھنے ہوں گے۔

Claude Code میں [ccam پلگ اِن](/docs/install#claude-code-plugin) کے ساتھ، جو سیشن اپنی حد پر رک جائے وہ ایک اطلاع دکھاتا ہے اور بھری ہوئی ونڈو ریکارڈ کر لیتا ہے، اس لیے `ccam next --auto` اس اکاؤنٹ کو اس کے ری سیٹ سے پہلے دوبارہ نہیں چنتا۔ `/ccam:switch` (یا `/ccam:switch work`) گفتگو کو `ccam next --continue` کے لیے نوٹ کر لیتا ہے، اس لیے یہ ٹھیک وہی گفتگو جاری رکھتا ہے۔

**Team اور Enterprise سیٹیں۔** خودکار اکاؤنٹ انتخاب (`ccam next`، `--fallback`، `ccam pick`، ڈیش بورڈ کی `n` کلید اور، جب آپ اسے آن کریں تو، [`auto_switch`](/features/next#auto-switch)) ایک ہی Claude Team یا Enterprise تنظیم کی سیٹوں کے درمیان بھی اکاؤنٹ بدلتا ہے، جس سے Anthropic کی شرائط کی خلاف ورزی ہو سکتی ہے۔ اس پر انحصار کرنے سے پہلے [عام سوالات](/docs/faq#am-i-allowed-to-use-several-claude-code-accounts) پڑھیں اور اپنی تنظیم اور Anthropic سے تصدیق کر لیں۔

## کیا ccam خود بخود اکاؤنٹ تبدیل کرتا ہے؟

صرف تب جب آپ اسے آن کریں۔

- ڈیفالٹ طور پر آپ کے کام کے دوران ccam چل نہیں رہا ہوتا: یہ Claude Code کو شروع کرتا ہے اور خود کو اس سے بدل دیتا ہے، اس لیے اکاؤنٹ کب بدلنا ہے یہ آپ طے کرتے ہیں۔ `ccam next --auto` وہ اکاؤنٹ چنتا ہے جس کا 5 گھنٹے کا استعمال سب سے کم ہو، ان اکاؤنٹس کو چھوڑ دیتا ہے جو 100% پر ہوں یا لاگ اِن نہ ہوں، اور ایک ہی Team یا Enterprise تنظیم کے اندر، یا ذاتی پلانز کے درمیان ہی رہتا ہے۔
- `config.toml` میں `relay = true` کے ساتھ ccam اس کے بجائے سیشن کے ساتھ ساتھ چلتا رہتا ہے، اس لیے `/ccam:switch` گفتگو خود جاری رکھتا ہے، سیشن کے آپشنز، اجازتوں کا موڈ اور effort لیول برقرار رکھتے ہوئے۔
- `auto_switch = true` کے ساتھ (Linux اور macOS؛ تجرباتی) ccam اکاؤنٹ خود بھی بدل دیتا ہے: جب Claude Code سیشن کو اس کی حد پر روک دے اور اسی قسم کے کسی دوسرے اکاؤنٹ میں گنجائش ہو، تو ccam سیشن ختم کر کے گفتگو وہاں جاری رکھتا ہے ([شرائط اور لاگت](/features/next#auto-switch))۔

کچھ دوسرے ٹولز اس کی بجائے چلتے ہوئے سیشن کا لاگ اِن بدل دیتے ہیں؛ [ccam اور دوسرے اکاؤنٹ سوئچرز](/compare/account-switchers) میں یہ فرق بیان کیا گیا ہے۔

## یاد رکھنے کی باتیں

- `ccam next --continue` اسی فولڈر میں چلائیں جس میں آپ کام کر رہے تھے؛ گفتگو ہر پروجیکٹ فولڈر کے حساب سے الگ محفوظ ہوتی ہے۔
- ایک ہی گفتگو پر بیک وقت دو اکاؤنٹس چلانے سے گریز کریں۔ اگر آپ ایسا کرنے کی کوشش کریں تو ccam آپ کو خبردار کرتا ہے۔
- شیئر شدہ ہسٹری کے بغیر گفتگو دوسرے اکاؤنٹ میں کاپی ہو جاتی ہے اور دونوں کاپیاں اپنے اپنے راستے چلتی ہیں؛ وہ checkpoints جن سے `/rewind` کوڈ بحال کرتا ہے، پہلے اکاؤنٹ کے پاس رہتے ہیں۔
- نئے اکاؤنٹ پر پہلا پیغام معمول سے زیادہ حد استعمال کر سکتا ہے، کیونکہ اس اکاؤنٹ نے ابھی گفتگو کو کیش نہیں کیا ہوتا۔ `ccam next --continue --brief` اس کے بجائے اسے ایک مختصر خلاصے سے شروع کرتا ہے۔
- آپ اس طرح اکاؤنٹس کے درمیان تبدیل کر سکتے ہیں یا نہیں، یہ ہر اکاؤنٹ پر لاگو ہونے والی شرائط پر منحصر ہے۔

تمام آپشنز کے لیے [استعمال کی حدیں](/features/usage) اور [اگلے اکاؤنٹ پر جانا](/features/next) دیکھیں۔
