ccam ایک چھوٹا کمانڈ لائن ٹول ہے ان لوگوں کے لیے جو ایک ہی کمپیوٹر پر Claude Code کے ایک سے زیادہ اکاؤنٹس استعمال کرتے ہیں: ایک ذاتی اور ایک کام کا اکاؤنٹ، یا کسی ایک طویل پروجیکٹ کے لیے کئی اکاؤنٹس۔

## مسئلہ

Claude Code، `CLAUDE_CONFIG_DIR` کے ذریعے کئی اکاؤنٹس کی سہولت دیتا ہے: ہر اکاؤنٹ کے لیے ایک فولڈر۔ عملی طور پر ہر فولڈر ایک الگ جزیرہ ہوتا ہے۔ سیٹنگز، `CLAUDE.md`، MCP سرورز، ایجنٹس اور اسکلز ہر فولڈر میں دوبارہ سیٹ اپ کرنے پڑتے ہیں اور ہاتھ سے آپس میں ہم آہنگ رکھنے پڑتے ہیں۔ گفتگو وہیں رہتی ہے جہاں شروع ہوئی تھی۔ اور جب کوئی اکاؤنٹ اپنی استعمال کی حد تک پہنچ جاتا ہے تو یہ آپ کو آزمانے پر ہی پتا چلتا ہے۔

## ccam کیا کرتا ہے

- `ccam add` فولڈر بناتا ہے، لاگ اِن چلاتا ہے اور اکاؤنٹ کو ایک شارٹ کٹ دیتا ہے: `claude1`، `claude2` وغیرہ۔
- `ccam work` اور `claude2` اس اکاؤنٹ کے طور پر Claude Code شروع کرتے ہیں اور ہر آرگیومنٹ بغیر تبدیلی کے آگے بھیجتے ہیں۔
- MCP سرورز، سیٹنگز، `CLAUDE.md` اور ایکسٹینشنز لنکس کے ذریعے شیئر ہوتے ہیں، ہر آئٹم اور ہر اکاؤنٹ کے لیے الگ الگ۔ لاگ اِن کبھی شیئر نہیں ہوتے۔
- `ccam usage` ہر اکاؤنٹ کا 5 گھنٹے اور ہفتہ وار استعمال دکھاتا ہے؛ `ccam next --continue` گفتگو کو اگلے اکاؤنٹ میں وہیں سے جاری رکھتا ہے۔

## کام میں رکاوٹ نہ بننا

جو ٹول آپ ہر سیشن سے پہلے چلاتے ہیں، اس کا بوجھ محسوس نہیں ہونا چاہیے۔ ccam ایک کنفیگریشن فائل پڑھتا ہے، ہر شیئر شدہ لنک کو ایک ایک سسٹم کال سے چیک کرتا ہے، اور پھر خود کو `claude` سے بدل دیتا ہے۔ یہ تقریباً 4 ملی سیکنڈ کا اضافہ کرتا ہے، اور جب آپ کام کر رہے ہوتے ہیں تو یہ چل نہیں رہا ہوتا۔

یہ آپ کی فائلوں کے معاملے میں بھی محتاط ہے۔ شیئرنگ میں ہر تبدیلی شروع ہونے سے پہلے ایک منصوبہ پرنٹ کرتی ہے اور اصل فائلیں ایک بیک اپ فولڈر میں رکھتی ہے۔ `ccam doctor` لنکس، اجازتیں اور لاگ اِن چیک کرتا ہے، اور جو کچھ محفوظ طریقے سے ٹھیک ہو سکے اسے ٹھیک کرتا ہے۔

## آزما کر دیکھیں

```sh
curl -fsSL https://ccam.dev/install.sh | sh
ccam add
```
