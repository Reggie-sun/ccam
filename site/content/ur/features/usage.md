`ccam usage` دکھاتا ہے کہ ہر اکاؤنٹ نے 5 گھنٹے کی حد، ہفتہ وار حد اور ہر ماڈل کی اپنی ہفتہ وار حد (جیسے Fable) کا کتنا حصہ استعمال کر لیا ہے، ہر حد کے لیے ایک بار کے ساتھ اور یہ کہ اس کے ری سیٹ ہونے میں کتنا وقت باقی ہے۔ کوئی لمبا کام شروع کرنے سے پہلے، یا جب Claude Code بتائے کہ حد قریب ہے، اسے چلا کر دیکھیں کہ کس اکاؤنٹ میں گنجائش باقی ہے۔ `ccam statusline`، Claude Code کے لیے اسٹیٹس لائن کمانڈ ہے: یہ Claude Code کے اندر اکاؤنٹ کا نام اور استعمال دکھاتی ہے اور اعداد `ccam usage` کے لیے محفوظ کرتی ہے۔

## استعمال

```sh
ccam usage                  # every account, once
ccam u                      # the same, shorter
ccam usage --watch          # redraw every 60 seconds until Ctrl+C
ccam usage --watch=10       # redraw every 10 seconds
ccam usage -v               # add where the numbers came from
ccam usage --json           # machine-readable, one object per account
ccam usage --source cache   # saved numbers only, no network
ccam usage --refresh        # also renew expired logins of accounts not running
ccam usage --source claude  # let Claude Code look it up: ccam sends no token
ccam statusline install     # set the status line in every account's settings.json
```

ہر اکاؤنٹ کو ایک لائن ملتی ہے جس میں اس کا نمبر، نام اور یہ ہوتا ہے کہ اس کے اعداد کتنے پرانے ہیں؛ `(cached)` کا مطلب ہے کہ وہ اینڈ پوائنٹ سے نہیں بلکہ ایک محفوظ فائل سے آئے ہیں۔ اس کے نیچے ہر حد کی ایک لائن 20 خانوں کی بار، فیصد اور ونڈو کے ری سیٹ ہونے تک کا وقت دکھاتی ہے: `5-hour`، `Weekly` (تمام ماڈلز)، پھر ہر ماڈل کی اپنی ہفتہ وار ونڈو، جیسے `Fable`۔ جو ونڈو اکاؤنٹ کے پاس نہ ہو وہ `-` دکھاتی ہے۔ فیصد 80% سے پیلا اور 100% پر سرخ ہو جاتا ہے۔ جس ونڈو کو Claude Code نے، استعمال کی حد پر کوئی درخواست رد کرتے ہوئے، بھری ہوئی بتایا ہو وہ اپنے ری سیٹ تک 100% دکھاتی ہے، چاہے محفوظ اعداد کچھ بھی کہیں ([حد کا ریکارڈ](#the-limit-record) دیکھیں)۔ ٹرمینل پر ہر اکاؤنٹ فوراً `fetching…` کے ساتھ ظاہر ہوتا ہے، اور جیسے ہی وہ جواب دیتا ہے اس کی لائنیں بن جاتی ہیں۔ آخری لائن اس اکاؤنٹ کا نام بتاتی ہے جسے [`ccam next --auto`](/features/next) انہی اصولوں سے چنتا (`auto_max_usage`، `auto_strategy`، چلتے سیشنز، صرف آخری بار استعمال کیے گئے اکاؤنٹ کی تنظیم کے اکاؤنٹس جب تک `cross_org` مقرر نہ ہو، اور 100% پر ہر ونڈو چھوڑ دی جاتی ہے، اس لیے جس اکاؤنٹ کا ہفتہ بھر چکا ہو اس کا نام کبھی نہیں آتا)، اور یہ صرف تب نظر آتی ہے جب آپ کے ایک سے زیادہ اکاؤنٹس ہوں۔ ڈیفالٹ `headroom` حکمتِ عملی کے ساتھ اس میں `→ Most headroom: <name>` لکھا ہوتا ہے؛ `expiring` یا `balance` کے ساتھ یہ وجہ بتاتی ہے، جیسے `→ next --auto picks personal: its 5-hour window resets first, in 1h 12m (40% of its 5 hours used)`۔

**Team اور Enterprise سیٹیں۔** خودکار انتخاب (`ccam next`، `--fallback`، `ccam pick`، ڈیش بورڈ کی `n` کلید، اور جب آپ اسے آن کریں تو [`auto_switch`](/features/next#auto-switch)) ایک ہی Claude Team یا Enterprise تنظیم کی سیٹوں کے درمیان بھی اکاؤنٹ بدلتا ہے۔ Anthropic کا ہیلپ سینٹر کہتا ہے کہ "Each seat on a Team plan is assigned to one named individual, and only that person may use it" (کسی Team پلان کی ہر سیٹ ایک نامزد فرد کو تفویض کی جاتی ہے، اور صرف اسی شخص کو اسے استعمال کرنے کی اجازت ہے) اور "Users can't route their work through another user's account to use that user's remaining usage" (صارفین کسی دوسرے صارف کا باقی ماندہ استعمال کام میں لانے کے لیے اپنا کام اس کے اکاؤنٹ کے ذریعے نہیں چلا سکتے) ([Team پلانز](https://support.claude.com/en/articles/12004354-purchase-and-manage-seats-on-team-plans#h_b8a7d07129)؛ اسی طرح [Enterprise پلانز](https://support.claude.com/en/articles/13393991-purchase-and-manage-seats-on-enterprise-plans#h_fa6b9cade0) کے لیے بھی)۔ اس لیے سیٹوں کے درمیان خودکار انتخاب استعمال کرنے سے Anthropic کی شرائط کی خلاف ورزی ہو سکتی ہے۔ وہاں اسے استعمال کرنا ہے یا نہیں، یہ آپ کا فیصلہ ہے: اس پر انحصار کرنے سے پہلے اپنی تنظیم اور Anthropic سے تصدیق کر لیں۔ ذاتی پلانز (Pro، Max) کی بات [عام سوالات میں شرائط والے نوٹ](/docs/faq#am-i-allowed-to-use-several-claude-code-accounts) میں کی گئی ہے۔

جو اکاؤنٹ لاگ اِن نہ ہو وہ `not logged in → ccam login <name>` دکھاتا ہے، اور API key والا اکاؤنٹ `no limits (API)` دکھاتا ہے۔ میعاد ختم ایکسیس ٹوکن ``access token expired; `ccam <name>` renews it when it starts`` دکھاتا ہے، اگر محفوظ اعداد ہوں تو ان کے اوپر: Claude Code اگلی بار شروع ہونے پر اس کی تجدید کر دیتا ہے۔ جس لاگ اِن کی پوری میعاد ختم ہو چکی ہو، کیونکہ اس کے ریفریش ٹوکن کی میعاد ختم ہو گئی یا سرور کے انکار کے بعد Claude Code نے اسے مٹا دیا، وہ `` login expired → `ccam login <name>` `` دکھاتا ہے۔

`ccam statusline install` کے بعد Claude Code ایک لائن دکھاتا ہے، جیسے `[work] · Opus · 5h 24% · 7d 41%`۔

## آپشنز

| آپشن | کیا کرتا ہے | ڈیفالٹ |
| --- | --- | --- |
| `--json` | رپورٹس JSON میں پرنٹ کرتا ہے: `name`، `slot`، `status`، `limits` (جب اکاؤنٹ میں usage credits آن ہوں تو `credits` کے ساتھ)، `source`، `at`، `error`، اور جب کوئی حد کا ریکارڈ ونڈوز کو 100% پر مقرر کرے تو `limited` اور `limited_windows`۔ کوئی اکاؤنٹ نہ ہو تو یہ `[]` پرنٹ کرتا ہے | بند |
| `--watch[=N]` | Ctrl+C دبانے تک ہر `N` سیکنڈ بعد دوبارہ بناتا ہے۔ صرف `--watch`، یا 0 یا اس سے کم قدر، کا مطلب 60 ہے۔ قدر `=` کے بعد آتی ہے: `--watch 10` ایک اشارے کے ساتھ رد کر دیا جاتا ہے | بند |
| `-v`، `--verbose` | ہر اکاؤنٹ کے نیچے ایک `source:` لائن شامل کرتا ہے: اس کے اعداد کہاں سے آئے (یوزج اینڈ پوائنٹ، Claude Code، اسٹیٹس لائن، ایک محفوظ فائل، یا وہ استعمال کی حد جو Claude Code نے بتائی)۔ جب کوئی حد کا ریکارڈ اعداد پر غالب ہو تو اس کے بعد `Weekly full: Claude Code reported the usage limit 1h 0m ago, so 100% until the reset` جیسی لائن آتی ہے | بند |
| `--no-cache` | 60 سیکنڈ کا کیش نظر انداز کر کے اینڈ پوائنٹ سے دوبارہ پوچھتا ہے | بند |
| `--source live\|claude\|cache` | `live` اکاؤنٹ کے ٹوکن سے اینڈ پوائنٹ سے پوچھتا ہے؛ `claude` یہ کام Claude Code سے کرواتا ہے (نیچے)؛ `cache` صرف محفوظ اعداد دکھاتا ہے | `usage_source`، ورنہ `live` |
| `--refresh` | میعاد ختم ہونے والے ایکسیس ٹوکنز کی تجدید کرتا ہے، صرف ان اکاؤنٹس کے لیے جو چل نہیں رہے۔ ایک تجدید میں 30 سیکنڈ تک لگ سکتے ہیں | بند |
| `--dry-run` | قبول ہے: `ccam usage` اپنے کیش کے سوا کچھ تبدیل نہیں کرتا۔ `--refresh` کے ساتھ مسترد ہوتا ہے: `--dry-run cannot be combined with --refresh, which rewrites login tokens` | بند |

`--source` کی کوئی بھی دوسری قدر `--source must be live, claude or cache` کے ساتھ ناکام ہوتی ہے۔

### خود Claude Code سے استعمال

`config.toml` میں سب سے اوپر (پہلے `[[group]]`، `[[profile]]` یا `[[folder]]` سے اوپر) `usage_source = "claude"`، یا `--source claude` کے ساتھ، ccam لاگ اِن ٹوکن بالکل نہیں پڑھتا۔ ہر اکاؤنٹ کے لیے یہ اکاؤنٹ کے فولڈر میں `claude -p --input-format stream-json --output-format stream-json --verbose --safe-mode --no-session-persistence` شروع کرتا ہے اور اسٹینڈرڈ اِن پٹ پر Claude Code کی `get_usage` درخواست بھیجتا ہے (Claude Code 2.1.270 یا بعد کا)؛ Claude Code اپنے لاگ اِن سے استعمال معلوم کرتا ہے اور 5 گھنٹے، ہفتہ وار اور ماڈل کی ونڈوز کے ساتھ جواب دیتا ہے۔ `--safe-mode` اکاؤنٹ کے hooks، MCP سرورز اور پلگ اِنز کو شروع ہونے سے روکتا ہے، اور کوئی سیشن محفوظ نہیں ہوتا۔ ہر اکاؤنٹ کے لیے Claude Code ایک بار شروع ہوتا ہے، تقریباً ایک سیکنڈ، اس لیے یہ ذریعہ `live` سے سست ہے؛ اکاؤنٹس سے ایک ساتھ پوچھا جاتا ہے، ہر ایک 20 سیکنڈ کے اندر، اور 60 سیکنڈ کا کیش معمول کے مطابق لاگو ہوتا ہے۔ جس لاگ اِن کے ایکسیس ٹوکن کی میعاد ختم ہو چکی ہو، یا 5 منٹ کے اندر ختم ہونے والی ہو، اسے 50 سیکنڈ ملتے ہیں، کیونکہ Claude Code شروع ہوتے وقت اس کی تجدید کرتا ہے اور بیچ میں کٹ جانے والی تجدید لاگ اِن کھو سکتی ہے۔ جو تلاش ترک کر دی جائے وہ Claude Code کو SIGTERM کے ساتھ ختم ہونے کو کہتی ہے، تاکہ وہ شروع کی ہوئی تجدید مکمل کر لے (Windows میں ایسا کوئی سگنل نہیں؛ وہاں اسے روک دیا جاتا ہے)۔ جس لاگ اِن کی پوری میعاد ختم ہو چکی ہو وہ Claude Code شروع کیے بغیر `` login expired → `ccam login <name>` `` دکھاتا ہے۔ Claude Code اس درخواست کو تجرباتی قرار دیتا ہے، اس لیے اگر یہ جواب دینا بند کر دے تو ccam محفوظ اعداد دکھاتا ہے اور `ccam doctor` اس کی اطلاع دیتا ہے۔ جب Claude Code جواب دے کہ اس کی اپنی تلاش ناکام ہوئی، تو ccam محفوظ اعداد `the usage endpoint gave Claude Code no usage (it may be refusing lookups for now)` کے ساتھ دکھاتا ہے، نہ کہ بغیر حدوں والا پلان۔ `--dry-run` Claude Code شروع نہیں کرتا (وہ اکاؤنٹ کے فولڈر میں لکھتا ہے) اور محفوظ اعداد دکھاتا ہے۔ `usage_source`، `live` یا `claude` لیتا ہے؛ `cache` صرف `--source` کا انتخاب ہے۔ `ccam usage` کوئی آرگیومنٹ نہیں لیتا۔

`ccam statusline`، Claude Code کی اسٹیٹس لائن JSON اسٹینڈرڈ اِن پٹ سے پڑھتا ہے۔ اس کا واحد آپشن `--wrap <command>` ہے: اسٹیٹس لائن کی ایک موجودہ کمانڈ، جس کے آؤٹ پٹ کی پہلی لائن کے شروع میں اکاؤنٹ کا نام لگ جاتا ہے۔ `ccam statusline install` کوئی آپشن نہیں لیتا۔ دونوں `--dry-run` کو `` --dry-run is not supported by `ccam statusline`; nothing was changed `` کے ساتھ مسترد کرتے ہیں۔

## یہ کیسے کام کرتا ہے

اعداد دو جگہوں سے آتے ہیں: Anthropic کا غیر دستاویزی usage اینڈ پوائنٹ، `GET https://api.anthropic.com/api/oauth/usage`، جسے ہر اکاؤنٹ کے اپنے لاگ اِن سے کال کیا جاتا ہے، اور وہ قدریں جو Claude Code اپنی اسٹیٹس لائن کمانڈ کو دیتا ہے۔ یہ سب `internal/usage` میں ہے۔

1. `cli.usageCmd`، `config.toml` لوڈ کرتا ہے اور ہر اکاؤنٹ کے لیے ایک `usage.Account` بناتا ہے: اس کا فولڈر `~/.local/share/ccam/profiles/<name>/`، اس کے سیشن مارکرز (اکاؤنٹ فولڈر میں Claude Code کے اپنے ریکارڈز کے ساتھ مل کر یہ بتاتے ہیں کہ وہ چل رہا ہے یا نہیں) اور یہ کہ وہ اپنی جگہ پر امپورٹ کیا گیا تھا یا نہیں۔
2. `Fetcher.FetchAll` ہر اکاؤنٹ کے لیے ایک goroutine شروع کرتا ہے۔ یہ سب ایک ہی `http.Client` شیئر کرتے ہیں، اس لیے اینڈ پوائنٹ سے کنکشنز دوبارہ استعمال ہوتے ہیں۔ کنکشن بنانے میں 2 s لگ سکتے ہیں، اور ہر اکاؤنٹ کو کل 3 s ملتے ہیں۔ کلائنٹ ری ڈائریکٹس پر عمل نہیں کرتا، کیونکہ ری ڈائریکٹ ٹوکن کو کسی اور جگہ دوبارہ بھیج دے گا، اور جواب کا زیادہ سے زیادہ 1 MB پڑھتا ہے۔
3. جیسے ہی ہر اکاؤنٹ مکمل ہوتا ہے، اس کی قطار دوبارہ بنتی ہے۔ جو اکاؤنٹ ناکام ہو یا وقت پر جواب نہ دے وہ محفوظ اعداد پر چلا جاتا ہے، اس لیے ایک سست اکاؤنٹ کبھی باقیوں کو نہیں روکتا۔

ہر اکاؤنٹ اینڈ پوائنٹ کے لیے اپنی goroutine میں چلتا ہے؛ جس کا وقت ختم ہو جائے وہ اس کے بجائے اپنے محفوظ اعداد دکھاتا ہے۔

`personal` اور `work` وقت پر جواب دیتے ہیں اور تازہ اعداد دکھاتے ہیں۔ `side` کو 3 s سے زیادہ لگتے ہیں، اس لیے `fallback()` اس کے بجائے اس کے محفوظ اعداد دکھاتا ہے۔ `usage.Table()` ہر اکاؤنٹ کا ایک بلاک بناتا ہے اور `usage.Best()` وہ اکاؤنٹ چنتا ہے جس کا نام آخری لائن میں آتا ہے۔

ایک اکاؤنٹ کے لیے `Fetcher.Fetch` یہ جانچ اسی ترتیب سے کرتا ہے:

<!-- motion:usage-cache -->

1. `--source cache` کے ساتھ یہ سیدھا `fallback()` پر جاتا ہے۔
2. جب تک `--no-cache` نہ لگا ہو، `~/.local/state/ccam/usage/<name>.json` میں 60 سیکنڈ (`CacheTTL`) سے کم پہلے ناپا گیا تازہ نتیجہ استعمال ہوتا ہے، موجودہ وقت کے لحاظ سے پرکھ کر: جو ونڈو اس کے بعد ری سیٹ ہو چکی ہو وہ 0% دکھاتی ہے، اور جس فائل کی تاریخ گھڑی سے آگے کی ہو وہ تازہ شمار نہیں ہوتی۔ `ccam usage` کو لگاتار دو بار چلانے پر ہر اکاؤنٹ کی صرف ایک درخواست جاتی ہے۔
3. `readCredentials()`، `.credentials.json` (یا macOS Keychain) کو تبدیل کیے بغیر پڑھتا ہے، اور صرف `claudeAiOauth` key ڈی کوڈ ہوتی ہے۔ سبسکرپشن لاگ اِن نہ ہو تو `not logged in`، یا جب `.claude.json` میں API key ہو تو `no limits (API)`۔ جس لاگ اِن کے ریفریش ٹوکن کی میعاد ختم ہو چکی ہو، یا جسے Claude Code نے مٹا دیا ہو، وہ `` login expired → `ccam login <name>` `` ہے اور اس کا استعمال معلوم نہیں کیا جاتا۔
4. میعاد ختم ہونے والا ایکسیس ٹوکن استعمال نہیں ہوتا۔ `--refresh` کے بغیر اکاؤنٹ اپنے محفوظ اعداد ``access token expired; `ccam <name>` renews it when it starts`` کے ساتھ دکھاتا ہے۔
5. ورنہ ccam اینڈ پوائنٹ کو کال کرتا ہے۔ 401 یا 403 کو میعاد ختم ہونے والا لاگ اِن سمجھا جاتا ہے (`login expired: authentication failed (401)`)، کوئی اور اسٹیٹس یا ایسا جواب جو پڑھا نہ جا سکے غلطی شمار ہوتا ہے، اور دونوں صورتوں میں محفوظ اعداد دکھائے جاتے ہیں۔ Ctrl+C سے ختم ہونے والی تلاش `cancelled` کہتی ہے۔ 429 کا مطلب ہے کہ اینڈ پوائنٹ سے بہت زیادہ بار پوچھا جا رہا ہے: ccam دوبارہ پوچھنے کے وقت کے ساتھ `<name>.pause` لکھتا ہے (`Retry-After`، یا 5 منٹ، زیادہ سے زیادہ ایک گھنٹہ)، `rate limited by the usage endpoint; asking again after 15:10` کے ساتھ محفوظ اعداد دکھاتا ہے، اور تب تک اس اکاؤنٹ کے لیے اینڈ پوائنٹ کو کال نہیں کرتا، `--no-cache` کے ساتھ بھی نہیں۔ فوراً دوبارہ کوشش کرنا صرف حد کو جاری رکھے گا۔
6. درست جواب ناپنے کے وقت کے ساتھ `<name>.json` میں لکھا جاتا ہے۔

`fallback()` سب سے نئی محفوظ تلاش لیتا ہے (`<name>.json`، یا Claude Code کی تلاشوں سے `<name>.claude.json`) اور، جب `<name>.statusline.json` اس کے بعد لکھی گئی ہو، تو اسٹیٹس لائن کی 5 گھنٹے اور ہفتہ وار ونڈوز اس کے اوپر رکھ دیتا ہے؛ ماڈل کی ونڈوز، جو اسٹیٹس لائن میں نہیں ہوتیں، ویسی ہی رہتی ہیں جیسی تلاش نے محفوظ کیں۔ محفوظ اعداد دکھانے سے پہلے یہ ہر ونڈو کے ری سیٹ کا وقت جانچتا ہے: جو ونڈو اعداد محفوظ ہونے کے بعد ری سیٹ ہو چکی ہو وہ 0% دکھاتی ہے، کیونکہ پرانا فیصد اب درست نہیں۔ اسی لیے اوپر `personal`، ری سیٹ کے وقت کے بغیر `0%` دکھاتا ہے۔

اینڈ پوائنٹ کے جواب کے دو فارمیٹ ہیں۔ نئے فارمیٹ میں ایک `limits` array ہوتا ہے جس میں `session` (5 گھنٹے)، `weekly_all` اور `weekly_scoped` (ماڈل کے لحاظ سے) اینٹریز ہوتی ہیں۔ پرانے فارمیٹ میں `five_hour`، `seven_day`، `seven_day_opus` اور `seven_day_sonnet` آبجیکٹس ہوتے ہیں۔ `ParseLive` دونوں پڑھتا ہے: `limits` array کو ترجیح ملتی ہے، اور جو وہ شامل نہ کرے وہ پرانے آبجیکٹس سے بھرا جاتا ہے۔ جس جواب میں کوئی حد ہی نہ ہو اسے بدلا ہوا فارمیٹ بتایا جاتا ہے، جس کے بارے میں `ccam doctor` آپ کو بتاتا ہے۔

### حد کا ریکارڈ

جب Claude Code کسی باری کو استعمال کی حد پر روکتا ہے تو [ccam پلگ اِن](/docs/install#claude-code-plugin) کا ہُک گفتگو سے رد کی گئی درخواست پڑھتا ہے: کون سی ونڈو بھری ہوئی تھی (5 گھنٹے، ہفتہ وار، Opus یا Sonnet) اور وہ کب ری سیٹ ہوگی۔ یہ اسے `~/.local/state/ccam/usage/<name>.limit.json` میں لکھتا ہے۔ `Fetch` یہ ریکارڈ ہر ذریعے سے حاصل باقی تمام معلومات کے اوپر رکھتا ہے: اس میں درج ہر ونڈو اپنے ری سیٹ تک 100% شمار ہوتی ہے، محفوظ اعداد کتنے ہی پرانے یا کم ہوں، اس لیے `ccam next --auto`، `ccam pick`، `--fallback` اور [`auto_switch`](/features/next#auto-switch) اس سے پہلے اس اکاؤنٹ کو دوبارہ نہیں چنتے۔ اگر کچھ اور معلوم نہ ہو تو اکاؤنٹ صرف یہی ریکارڈ دکھاتا ہے (`-v` کے ساتھ `source: the usage limit Claude Code reported`)۔ جن سیشنز کے سامنے کوئی نہیں بیٹھا (`-p`، بیک گراؤنڈ سیشنز) وہ کوئی ریکارڈ نہیں لکھتے، اور نہ ہی تنظیم کی طرف سے روکا جانا (استعمال ختم، $0 پر مقرر گروپ)، جسے اس کے ایڈمن کسی بھی وقت ہٹا سکتے ہیں۔ کسی دوسرے Claude اکاؤنٹ میں `ccam login` ریکارڈ ہٹا دیتا ہے؛ فائل حذف کرنے سے بھی یہ صاف ہو جاتا ہے۔

### ٹوکنز کی تجدید

ریفریش ٹوکنز بدلتے رہتے ہیں: ایک کی تجدید سے نیا ریفریش ٹوکن ملتا ہے اور پرانا ناکارہ ہو جاتا ہے۔ اگر ccam لاگ اِن کی تجدید اس وقت کرے جب Claude Code اسی اکاؤنٹ کے طور پر چل رہا ہو، تو وہ سیشن سائن آؤٹ ہو جائے گا۔ اس لیے `ccam usage` ٹوکنز پڑھتا ہے اور انہیں کبھی نہیں لکھتا، جب تک آپ `--refresh` نہ دیں۔ تب `Fetcher.refresh`:

1. `ccam import` سے اپنی جگہ پر رجسٹر کیے گئے اکاؤنٹس کو مسترد کرتا ہے، کیونکہ سادہ `claude` ccam کے علم کے بغیر وہ لاگ اِن استعمال کر سکتا ہے؛
2. macOS Keychain میں محفوظ لاگ اِن مسترد کرتا ہے؛
3. ایک لاک فائل لیتا ہے، `~/.local/state/ccam/locks/profile-<name>.refresh.lock`، تاکہ دو ccam پروسیس کبھی ایک ہی ٹوکن کی دو بار تجدید نہ کریں؛ جب تک یہ لاک تھاما ہوا ہو، اکاؤنٹ `token not renewed: another ccam is using this login right now (a refresh, rename, remove or logout)` دکھاتا ہے۔ `ccam rename`، `remove` اور `logout` بھی یہ لاک لیتے ہیں، اور تجدید چلنے کے دوران انکار کرتے ہیں؛
4. لاک کے تحت، اکاؤنٹ کا کوئی سیشن چل رہا ہو تو انکار کرتا ہے، چاہے وہ کسی بھی طرح شروع ہوا ہو (ccam کے ذریعے، سادہ `claude`، کوئی IDE، یا کوئی بیک گراؤنڈ سیشن اور اس کے پیچھے daemon، جو خود لاگ اِن کی تجدید کرتا ہے)، اور اگر کوئی دوسرا پروسیس پہلے ہی ٹوکن کی تجدید کر چکا ہو تو درخواست چھوڑ دیتا ہے؛
5. جب تک Claude Code اکاؤنٹ فولڈر میں تجدید کے اپنے لاک (`.oauth_refresh.lock`، `<folder>.lock`) تھامے رکھے، کچھ نہیں بھیجتا: اس وقت Claude Code خود وہ لاگ اِن تازہ کر رہا ہوتا ہے؛
6. ریفریش ٹوکن، ٹوکن اینڈ پوائنٹ کو بھیجتا ہے اور جواب کا 30 سیکنڈ تک انتظار کرتا ہے، اتنا ہی وقت جتنا Claude Code اپنی تجدیدوں کو دیتا ہے۔ ایک بار بھیجی گئی درخواست کبھی بیچ میں نہیں کاٹی جاتی، Ctrl+C سے بھی نہیں، کیونکہ ہو سکتا ہے سرور ریفریش ٹوکن پہلے ہی بدل چکا ہو اور اب صرف اس کا جواب ہی لاگ اِن کو بچائے رکھے: Ctrl+C یا hangup باقی تلاشیں ختم کر دیتا ہے، اور جواب محفوظ ہونے کے بعد ccam باہر نکلتا ہے (Ctrl+C کے بعد 130 کے ساتھ)؛
7. Claude Code کے لکھنے کے لاک (`.storage-write.lock`) کے تحت محفوظ کرتا ہے اور `.credentials.json` کی اُس وقت کی حالت میں صرف ٹوکن والے فیلڈز بدلتا ہے: اس دوران Claude Code نے جو لکھا ہو (کوئی MCP سائن اِن) وہ برقرار رہتا ہے، اس دوران Claude Code کا تازہ کیا ہوا لاگ اِن رکھا جاتا ہے، اور لاگ آؤٹ کبھی واپس نہیں پلٹایا جاتا۔ جب جواب نئے ریفریش ٹوکن کی مدت بتائے تو وہ `refreshTokenExpiresAt` کے طور پر محفوظ کی جاتی ہے، جیسے Claude Code کرتا ہے۔

جو تجدید مکمل نہ ہو وہ وجہ بتاتی ہے، اکاؤنٹ کی لائن پر یا اس کے محفوظ اعداد کے اوپر: مثلاً `token not renewed: a session is running`، یا `login may be lost: …` جب درخواست بھیجی گئی ہو لیکن اس کا جواب استعمال یا محفوظ نہ ہو سکا ہو، اس مشورے کے ساتھ کہ اگر Claude Code پھر لاگ اِن کرنے کو کہے تو `ccam login <name>` چلائیں۔

### اسٹیٹس لائن کلیکٹر

Claude Code اسٹیٹس لائن کمانڈ چلاتا ہے اور اسے ایک JSON دستاویز دیتا ہے۔ ccam اس میں سے ماڈل کا نام اور `rate_limits` پڑھتا ہے:

<!-- motion:usage-statusline -->

1. `runStatusline` اکاؤنٹ کو `CCAM_PROFILE` سے تلاش کرتا ہے، جسے ccam، Claude Code شروع کرتے وقت مقرر کرتا ہے، ورنہ `CLAUDE_CONFIG_DIR` کو اکاؤنٹ فولڈرز سے ملا کر۔
2. `ParseStatusLine`، `rate_limits.five_hour` اور `rate_limits.seven_day` پڑھتا ہے۔ API key والے اکاؤنٹس کے لیے، یا سیشن کے پہلے جواب سے پہلے، JSON میں ریٹ لمٹس نہیں ہوتیں؛ تب کچھ محفوظ نہیں ہوتا۔
3. `SaveStatusLine`، `~/.local/state/ccam/usage/<name>.statusline.json` لکھتا ہے۔ جب اینڈ پوائنٹ جواب نہ دے تو `ccam usage` اسے استعمال کرتا ہے۔
4. ccam `[name] · model · 5h N% · 7d N%` پرنٹ کرتا ہے۔ `--wrap` کے ساتھ یہ آپ کی کمانڈ کو اسی اِن پٹ کے ساتھ `sh -c` سے چلاتا ہے اور اس کا آؤٹ پٹ ویسے ہی پرنٹ کرتا ہے جیسے Claude Code اسٹیٹس لائن دکھاتا ہے: ہر وہ لائن جو خالی نہ ہو، پہلی کے شروع میں `[name]` کے ساتھ۔ ناکام ہونے والی کمانڈ صرف اکاؤنٹ کا نام دکھاتی ہے۔ Windows پر یہ کمانڈ ویسے ہی چلاتا ہے جیسے Claude Code چلاتا ہے: Git Bash انسٹال ہو تو اس سے، ورنہ PowerShell سے۔
5. جب 5 گھنٹے یا ہفتہ وار استعمال 90% یا اس سے زیادہ ہو اور کوئی دوسرا اکاؤنٹ موجود ہو تو لائن `→ ccam next --auto --continue` پر ختم ہوتی ہے، مثلاً `[work] · Opus · 5h 93% · 7d 41% · → ccam next --auto --continue`۔

لپیٹی گئی کمانڈ کی اپنی کوئی وقت کی حد نہیں: Claude Code اسٹیٹس لائن کمانڈ کو 10 منٹ دیتا ہے اور جب کوئی نئی اپ ڈیٹ شروع ہو تو جاری رن روک دیتا ہے، اس لیے سست کمانڈ ویسے ہی دکھائی دیتی ہے جیسے ccam کے بغیر دکھائی دیتی۔ جب Claude Code، ccam کو ختم کرتا ہے تو کمانڈ بھی ختم ہو جاتی ہے (Linux اور macOS پر اس کے شروع کیے ہوئے ہر پروسیس کے ساتھ)۔

`ccam statusline install` ہر اکاؤنٹ کی `settings.json` میں `statusLine` لکھتا ہے اور آبجیکٹ کی باقی keys، جیسے `padding`، `refreshInterval` اور `hideVimModeIndicator`، برقرار رکھتا ہے۔ جب کسی اکاؤنٹ میں پہلے سے اسٹیٹس لائن کی کمانڈ ہو تو ccam اسے `--wrap '<old command>'` کی صورت میں برقرار رکھتا ہے؛ Windows پر `--wrap-base64 <base64>` کی صورت میں، جسے کسی بھی شیل میں quotes کی ضرورت نہیں۔ جو اسٹیٹس لائن پہلے سے کوئی ccam چلاتی ہو، کسی دوسرے راستے سے یا اس طرح quote کی ہوئی جیسے کسی پرانے ccam نے لکھی تھی، اسے لپیٹنے کے بجائے بدل دیا جاتا ہے، اور جو کچھ وہ لپیٹتی ہے وہ برقرار رہتا ہے۔ Windows پر ccam کا پاتھ فارورڈ سلیش اور ہوم فولڈر کے لیے `~` کے ساتھ لکھا جاتا ہے (`~/.local/bin/ccam.exe statusline`)، جسے Git Bash اور PowerShell دونوں سمجھتے ہیں۔ جس راستے کو quotes کی ضرورت ہو وہ اس شیل کے لیے پورا لکھا جاتا ہے جو Claude Code استعمال کرتا ہے: Git Bash کے لیے `'…'`، PowerShell کے لیے `& '…'`۔ کسی گروپ کے ذریعے شیئر کی گئی `settings.json` اپنے لنک کے ذریعے ایک بار لکھی جاتی ہے، اس لیے گروپ کے ہر اکاؤنٹ کو یہ مل جاتی ہے۔ دوبارہ چلانے پر ان فائلوں کے لیے `(already set)` پرنٹ ہوتا ہے جو پہلے سے ccam استعمال کر رہی ہیں۔

## حفاظت اور خاص صورتیں

- `ccam usage` کبھی ٹوکن فائل تبدیل نہیں کرتا جب تک آپ `--refresh` نہ دیں۔ جب کسی ایکسیس ٹوکن کی میعاد ختم ہو جائے تو اکاؤنٹ کو ایک بار `ccam <name>` سے چلائیں، Claude Code اس کی تجدید کر دے گا۔ جس لاگ اِن کی پوری میعاد ختم ہو چکی ہو اسے `ccam login <name>` چاہیے۔
- `--refresh` کبھی چلتے ہوئے اکاؤنٹس (تب بھی جب Claude Code، ccam کے بغیر شروع ہوا ہو)، امپورٹ کیے گئے اکاؤنٹس یا Keychain لاگ اِن کو نہیں چھیڑتا۔ مسترد کی گئی تجدید محفوظ اعداد اور وجہ (`token not renewed: …`) دکھاتی ہے۔
- usage اینڈ پوائنٹ عوامی طور پر دستاویزی نہیں ہے اور بدل سکتا ہے۔ جب ایسا ہو تو آپ کو پھر بھی محفوظ اعداد نظر آتے ہیں، اور `ccam doctor` فارمیٹ کی تبدیلی کی اطلاع دیتا ہے۔
- محفوظ اعداد اور جواب دونوں نہ ہوں تو اکاؤنٹ کی لائن میں `lookup failed:` اور وجہ دکھتی ہے، مثلاً `--source cache` کے ساتھ `no saved usage`۔
- کیش فائلوں میں صرف فیصد اور ری سیٹ کے اوقات ہوتے ہیں، کبھی ٹوکنز نہیں۔
