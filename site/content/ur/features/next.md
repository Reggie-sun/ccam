`ccam next`، Claude Code کو کسی دوسرے اکاؤنٹ کے طور پر کھولتا ہے، بغیر اس کے کہ آپ اس کا نام لیں۔ اسے تب استعمال کریں جب کوئی اکاؤنٹ اپنی استعمال کی حد تک پہنچ جائے: سادہ `ccam next` آخری بار استعمال کیے گئے اکاؤنٹ کے بعد والا اکاؤنٹ لیتا ہے، `--auto` وہ اکاؤنٹ لیتا ہے جس میں سب سے زیادہ گنجائش ہو، اور `--continue` اس فولڈر کی آخری گفتگو نئے اکاؤنٹ میں لے جاتا ہے، چاہے دونوں ہسٹری شیئر کرتے ہوں یا نہیں۔ Claude Code کے اندر، [ccam پلگ اِن](#inside-claude-code) آپ کو بتاتا ہے جب کوئی حد سیشن کو روک دے، اور `/ccam:switch` گفتگو آگے سونپ دیتا ہے۔ `claude -p` چلانے والے اسکرپٹس کے لیے `ccam --fallback` یہ تبدیلی خود کرتا ہے (دیکھیں [حد پر دوبارہ چلانا](#run-again-at-the-limit))۔

## استعمال

```sh
ccam next                       # the account after the one you used last
ccam next --auto                # the account with the most room
ccam next --continue            # carry this folder's last conversation on as the next account
ccam next -c --auto             # both: the conversation, on the account with the most room
ccam next --auto --max-usage 80 # prefer accounts below 80%
ccam next --auto --strategy balance   # the weekly quota that would go unused first
ccam next --auto --cross-org    # also accounts of other organizations
ccam next --auto --wait         # nobody has room: wait for the first reset (up to 5 hours)
ccam next -c --auto -- --dangerously-skip-permissions   # claude's own options go after --
ccam --dry-run next --auto      # print the choice and the command, start nothing
```

```console
$ ccam --dry-run next --auto --continue
→ personal → work (12% of its 5 hours used, the least)
  continuing "Fix the flaky tests" (about 182k tokens); work does not share personal's history, so Claude Code copies it into work
CLAUDE_CONFIG_DIR=/home/you/.local/share/ccam/profiles/work /usr/local/bin/claude --resume /home/you/.local/share/ccam/profiles/personal/projects/-home-you-code-app/4f1c….jsonl --fork-session
```

ccam تبدیلی کو اسٹینڈرڈ ایرر پر `→ <from> → <to>` کی صورت میں پرنٹ کرتا ہے، `--auto` کے انتخاب کی وجہ کے ساتھ، پھر Claude Code کو نئے اکاؤنٹ کے طور پر اسی طرح شروع کرتا ہے جیسے `ccam <name>` کرتا ہے۔ `<from>` وہ اکاؤنٹ ہے جو آپ نے آخری بار استعمال کیا، یا `--continue` کے ساتھ وہ اکاؤنٹ جس کی یہ گفتگو ہے۔ `--` کے بعد والے آرگیومنٹس بغیر تبدیلی کے `claude` کو جاتے ہیں۔

## آپشنز

| آپشن | کیا کرتا ہے | ڈیفالٹ |
| --- | --- | --- |
| `--auto` | لاگ اِن شدہ اکاؤنٹ استعمال کی بنیاد پر چنتا ہے (نیچے دیکھیں)، اور 100% والے اکاؤنٹس چھوڑ دیتا ہے | بند |
| `--max-usage <1-100>` | `--auto` کے ساتھ: اس استعمال سے کم والے اکاؤنٹس کو ترجیح دیتا ہے | `auto_max_usage`، ورنہ 100 |
| `--strategy headroom\|expiring\|balance` | `--auto` کے ساتھ: سب سے کم 5 گھنٹے کا استعمال، 5 گھنٹے کا سب سے جلد ری سیٹ، یا وہ ہفتہ وار کوٹا جو سب سے پہلے بغیر استعمال کے رہ جاتا | `auto_strategy`، ورنہ `headroom` |
| `--cross-org` | `--auto` کے ساتھ: کسی دوسری تنظیم کے اکاؤنٹس بھی چنتا ہے (نیچے دیکھیں) | `cross_org`، ورنہ بند |
| `--wait[=<duration>]` | `--auto` کے ساتھ: جب کسی اکاؤنٹ میں گنجائش نہ ہو تو پہلے اکاؤنٹ کے ری سیٹ ہونے کا انتظار کرتا ہے، زیادہ سے زیادہ اتنی دیر | بند؛ اکیلا دیا جائے تو `5h` |
| `-c`، `--continue` | اس فولڈر کی آخری گفتگو نئے اکاؤنٹ کے طور پر جاری رکھتا ہے (نیچے دیکھیں) | بند |
| `-- <claude args>` | ccam کے اپنے آرگیومنٹس کے بعد `claude` کو دیے جانے والے آرگیومنٹس | کوئی نہیں |
| `--dry-run` | لاگو ہوتا ہے: Claude Code شروع کیے یا لانچ ریکارڈ کیے بغیر `→ <from> → <to>` اور وہ کمانڈ لائن پرنٹ کرتا ہے جو چلائی جاتی | بند |

`--auto` اور `--continue` ایک ساتھ کام کرتے ہیں۔ `--continue` کے ساتھ، `--resume` والے آرگیومنٹس آپ کے اپنے آرگیومنٹس سے پہلے رکھے جاتے ہیں۔

Claude Code کے اپنے آپشنز، جیسے `--dangerously-skip-permissions` یا `--model`، `--` کے بعد آتے ہیں۔ `ccam <name>` کے برعکس، جو نام کے بعد سب کچھ آگے بھیج دیتا ہے، `ccam next` اپنے آرگیومنٹس خود پڑھتا ہے، اس لیے `--` کے بغیر یہ `ccam: unknown flag: --dangerously-skip-permissions` کے ساتھ رک جاتا ہے۔

## یہ کیسے کام کرتا ہے

ccam کے ذریعے ہر لانچ وقت کو `~/.local/state/ccam/last-used/<name>` میں لکھتا ہے۔ `ccam next` یہ فائلیں پڑھتا ہے، دیکھتا ہے کہ کون سے اکاؤنٹس لاگ اِن ہیں، اور انتخاب کرتا ہے۔

1. `cli.candidates`، `config.toml` سے ہر اکاؤنٹ کے لیے ایک `next.Candidate` بناتا ہے: اکاؤنٹ، اس کے آخری لانچ کا وقت (`launcher.LastUsed`) اور یہ کہ اس کا لاگ اِن ہے یا نہیں (`creds.Has`: پڑھنے کے قابل `.credentials.json`، یا macOS پر Keychain آئٹم)۔
2. `--auto` کے بغیر، `next.Rotate` اکاؤنٹس کو سلاٹ نمبر کے لحاظ سے ترتیب دیتا ہے اور سب سے حال میں لانچ کیا گیا اکاؤنٹ تلاش کرتا ہے۔ یہی وہ اکاؤنٹ ہے جس سے آپ ہٹ رہے ہیں۔ اگر ابھی تک کوئی اکاؤنٹ لانچ نہیں ہوا تو یہ سب سے کم سلاٹ والا ہوتا ہے۔
3. وہاں سے یہ سلاٹ کی ترتیب میں آگے بڑھتا ہے، آخری سلاٹ سے واپس پہلے پر گھومتا ہے، اور پہلا لاگ اِن شدہ اکاؤنٹ لوٹاتا ہے۔
4. `launcher.LaunchWith` چنے گئے اکاؤنٹ کو بالکل اسی طرح تیار اور شروع کرتا ہے جیسے `ccam <name>` کرتا: یہ اکاؤنٹ کے لنکس جانچتا ہے، MCP شیئرنگ لاگو کرتا ہے، سیشن رجسٹر کرتا ہے اور `syscall.Exec` کے ذریعے ccam کی جگہ `claude` چلا دیتا ہے۔

یہ گردش آخری بار استعمال کیے گئے اکاؤنٹ سے شروع ہوتی ہے اور اس کے بعد پہلے لاگ اِن شدہ اکاؤنٹ پر رک جاتی ہے:

`work` سب سے حال میں لانچ ہوا تھا، اس لیے گردش اس کے بعد سے شروع ہوتی ہے۔ `side` کا کوئی لاگ اِن نہیں، اس لیے اسے چھوڑ دیا جاتا ہے، اور `lab` چنا جاتا ہے۔ اگر `lab` بھی لاگ آؤٹ ہوتا تو گردش گھوم کر `personal` پر آ جاتی (ڈایاگرام میں `% len`)۔ گردش کبھی وہ اکاؤنٹ نہیں لوٹاتی جہاں سے آپ نے شروع کیا: اگر کوئی دوسرا لاگ اِن شدہ اکاؤنٹ نہ ہو تو یہ غلطی کے ساتھ رک جاتی ہے۔

### --auto

`--auto` سلاٹ کی ترتیب کے بجائے استعمال کی بنیاد پر فیصلہ کرتا ہے۔ `cli.pickAuto` لاگ اِن شدہ اکاؤنٹس رکھتا ہے، اسی `Fetcher.FetchAll` سے جو `ccam usage` استعمال کرتا ہے ان سب کا استعمال ایک ساتھ پوچھتا ہے، اور انتخاب `usage.Policy.Choose()` پر چھوڑ دیتا ہے:

<!-- motion:next-auto -->

ہر اکاؤنٹ کو اس کی 5 گھنٹے اور ہفتہ وار ونڈوز سے پرکھا جاتا ہے، اور جب Claude Code کے آرگیومنٹس میں `--model` ہو (`--` کے بعد) تو اس ماڈل کی ہفتہ وار ونڈو سے بھی (نام میں `opus`، `sonnet`، `haiku` یا `fable`)۔ `Policy.Choose()` اکاؤنٹس کو تین حصوں میں بانٹتا ہے:

1. **گنجائش**: ہر ونڈو `auto_max_usage` (`config.toml`، ڈیفالٹ 100) سے کم۔ ان میں سے حکمتِ عملی چنتی ہے: `headroom` (ڈیفالٹ) سب سے کم 5 گھنٹے کا استعمال لیتا ہے؛ `expiring` وہ 5 گھنٹے کی ونڈو لیتا ہے جو سب سے جلد ری سیٹ ہو، تاکہ اس کا بچا ہوا کوٹا ضائع ہونے سے پہلے استعمال ہو جائے؛ `balance` وہ اکاؤنٹ لیتا ہے جس کے ہفتے کے ری سیٹ تک فی دن سب سے زیادہ ہفتہ وار کوٹا بچا ہو، اور ہر چلتے ccam سیشن کو اس کے حساب میں شمار کرتا ہے، تاکہ ہفتہ وار کوٹا بغیر استعمال کے نہ رہ جائے اور متوازی سیشنز بٹ جائیں۔
2. **حد سے اوپر**: 100% سے کم لیکن `auto_max_usage` کے برابر یا اس سے زیادہ۔ صرف تب استعمال ہوتا ہے جب کسی اکاؤنٹ میں گنجائش نہ ہو، سب سے کم 5 گھنٹے کے استعمال والا پہلے۔
3. **بھرا ہوا**: کوئی ونڈو 100% پر، یا نامعلوم 5 گھنٹے کا استعمال۔ کبھی نہیں چنا جاتا۔

```toml
# ~/.config/ccam/config.toml
auto_max_usage = 80        # keep 20% of each account for interactive work
auto_strategy = "expiring"
```

**تنظیمیں۔** خودکار انتخاب ان اکاؤنٹس تک رہتے ہیں جو اس اکاؤنٹ جیسے ہوں جسے آپ چھوڑ رہے ہیں: وہی ٹیم یا انٹرپرائز تنظیم، یا ذاتی پلانز (Pro، Max) ایک ساتھ، تاکہ کمپنی کے اکاؤنٹ کا کام کسی نجی اکاؤنٹ پر جاری نہ ہو اور نہ اس کے الٹ۔ ccam ہر اکاؤنٹ کی تنظیم اس کے لاگ اِن سے جانتا ہے (`ccam login` اسے ریکارڈ کرتا ہے؛ پرانے لاگ اِنز کے لیے یہ `.claude.json` سے پڑھی جاتی ہے)؛ جس اکاؤنٹ کی تنظیم یہ نہ بتا سکے وہ کہیں بھی فٹ ہو جاتا ہے۔ ایک ہی Claude اکاؤنٹ میں لاگ اِن دو فولڈرز اس کی حدیں شیئر کرتے ہیں، اس لیے ایک کبھی دوسرے کی جگہ نہیں لیتا۔ `--cross-org`، یا `config.toml` میں `cross_org = true`، تنظیم کا اصول ہٹا دیتا ہے۔

جب کچھ نہ چنا جا سکے تو ccam کوڈ 75 (`EX_TEMPFAIL`) کے ساتھ باہر نکلتا ہے، تاکہ اسکرپٹ "بعد میں کوشش کریں" کو ناکامی سے الگ پہچان سکے۔ `--wait` کے ساتھ یہ اس کے بجائے تب تک رکتا ہے جب تک پہلے بھرے ہوئے اکاؤنٹ کی روکنے والی ونڈو ری سیٹ نہ ہو جائے (ری سیٹ کے وقت سے 30 سیکنڈ بعد، جب اینڈ پوائنٹ نئی ونڈو دکھاتا ہے)، `ccam: no account has room; waiting until 15:10` پرنٹ کرتا ہے، اور دوبارہ چنتا ہے؛ جب کوئی اکاؤنٹ یہ نہ بتائے کہ وہ کب ری سیٹ ہوگا، تو یہ 10 منٹ بعد دوبارہ دیکھتا ہے۔ اگر انتظار ختم ہونے سے پہلے کچھ خالی نہ ہو تو یہ 75 کے ساتھ باہر نکلتا ہے۔ یہ تلاش `ccam usage` کے اصولوں پر چلتی ہے: 60 سیکنڈ سے کم پرانے اعداد دوبارہ استعمال ہوتے ہیں، ہر اکاؤنٹ کے پاس 3 سیکنڈ ہوتے ہیں، اور جو اکاؤنٹ جواب نہ دے، یا جس کے لاگ اِن کی میعاد ختم ہو چکی ہو، اس کا فیصلہ اس کے محفوظ اعداد سے ہوتا ہے۔ جس محفوظ ونڈو کا ری سیٹ کا وقت گزر چکا ہو وہ 0% شمار ہوتی ہے، اس لیے جس اکاؤنٹ کی ونڈو اس دوران ری سیٹ ہو چکی ہو اسے نظر انداز نہیں کیا جاتا۔ `--auto` کبھی ٹوکنز کی تجدید نہیں کرتا۔ سادہ گردش کے برعکس، `--auto` آخری بار استعمال کیا گیا اکاؤنٹ بھی چن سکتا ہے اگر اس میں اب بھی سب سے زیادہ گنجائش ہو۔

### --continue

1. ccam ہر اکاؤنٹ میں اس فولڈر کی آخری گفتگو تلاش کرتا ہے: `projects/<folder>/` میں سب سے نئی `<session>.jsonl` (فولڈر کا نام ورکنگ فولڈر ہوتا ہے جس میں حرف یا ہندسے کے سوا ہر کیریکٹر `-` میں بدل دیا جاتا ہے، جیسے Claude Code اسے نام دیتا ہے)۔ اگر سیشن نے کوئی نوٹ چھوڑا ہو (استعمال کی حد یا `/ccam:switch`، نیچے دیکھیں) اور اس کے بعد کچھ نیا نہ لکھا گیا ہو، تو اس کے بجائے ٹھیک وہی سیشن استعمال ہوتا ہے۔
2. جس اکاؤنٹ کی یہ گفتگو ہے وہی وہ اکاؤنٹ ہے جس سے آپ ہٹ رہے ہیں، اور نیا اکاؤنٹ اوپر کی طرح، اسی تنظیم کے اندر، چنا جاتا ہے۔
3. اگر نیا اکاؤنٹ وہ ہسٹری شیئر کرتا ہے (ایک ہی گروپ فولڈر)، تو ccam `claude --resume <session id>` شروع کرتا ہے، یعنی ٹھیک وہی گفتگو (`--continue` فولڈر میں جو بھی گفتگو سب سے نئی ہو اسے کھول دیتا)۔
4. ورنہ یہ `claude --resume <the conversation's file> --fork-session` شروع کرتا ہے: Claude Code پوری گفتگو ایک نئی سیشن id کے تحت نئے اکاؤنٹ کی اپنی ہسٹری میں کاپی کر دیتا ہے، اور اصل جوں کی توں رہتی ہے۔ اس کے بعد نئے اکاؤنٹ کا `--continue` اسے ڈھونڈ لیتا ہے۔

ccam بتاتا ہے کہ گفتگو کتنی بڑی ہے: نیا اکاؤنٹ اپنے پہلے جواب کے ساتھ یہ پوری دوبارہ پڑھتا ہے۔ پرامپٹ کیش کبھی تنظیموں کے درمیان شیئر نہیں ہوتے، اس لیے `--cross-org` کے ساتھ اس پہلے جواب کی لاگت پورے سائز کی ہوتی ہے۔ کسی گروپ میں `history` شیئر کرنے سے کاپی کی ضرورت نہیں پڑتی، ایک ہی گفتگو رہتی ہے، اور وہ checkpoints بھی شیئر ہوتے ہیں جن سے `/rewind` کوڈ بحال کرتا ہے (`file-history/`)۔

## Claude Code کے اندر

[ccam پلگ اِن](/docs/install#claude-code-plugin) دو hooks شامل کرتا ہے (Claude Code 2.1.78 یا بعد کا):

- جب کوئی باری استعمال کی حد پر رک جائے (`You've hit your session limit`، ہفتہ وار یا کسی ماڈل کی حد)، تو یہ گفتگو نوٹ کر لیتا ہے اور ان ٹرمینلز میں جو اس کی سہولت دیتے ہیں (iTerm2، WezTerm، Windows Terminal، kitty، Ghostty) ڈیسک ٹاپ اطلاع دکھاتا ہے: `ccam: work hit its 5-hour limit (resets 3:45pm). ccam next --continue carries on as another account.` سرور کی مختصر رکاوٹ یا کسی API key کی rate limit استعمال کی حد نہیں ہے اور اسے چھیڑا نہیں جاتا۔ Claude Code 2.1.234 اور بعد کے ورژن سیشن میں انتظار بھی کرتے ہیں اور 5 گھنٹے کے ری سیٹ کے بعد خود جاری رکھتے ہیں؛ اطلاع آپ کو اس کے بجائے اکاؤنٹ بدلنے کا اختیار دیتی ہے۔
- `/ccam:switch [account]` گفتگو نوٹ کرتا ہے اور کوئی درخواست بھیجے جانے سے پہلے باری ختم کر دیتا ہے: `/exit` ٹائپ کریں، پھر `ccam next --continue` اسے جاری رکھتا ہے، اس اکاؤنٹ کے طور پر جس کا آپ نے نام لیا یا اگلے اکاؤنٹ کے طور پر۔

نوٹ `~/.local/state/ccam/handoff/<account>.json` میں 12 گھنٹے رہتا ہے اور ایک بار استعمال ہوتا ہے، جب اگلا سیشن شروع ہونے والا ہو؛ ناکام لانچ اسے اگلی کوشش کے لیے چھوڑ دیتا ہے۔ یہ اسی فولڈر کا ہوتا ہے جس میں سیشن شروع ہوا تھا، چاہے Claude Code کے شیل میں `cd` کر لیا گیا ہو۔ اگر اس میں درج اکاؤنٹ کا نام بعد میں بدل دیا گیا ہو یا اسے ہٹا دیا گیا ہو، تو ccam یہ بتا دیتا ہے اور معمول کے مطابق انتخاب کرتا ہے۔ `config.toml` میں `relay = true` کے ساتھ، ccam خود کو Claude Code سے بدلنے کے بجائے انٹرایکٹو سیشنز کے ساتھ رہتا ہے، اور `/ccam:switch` کے بعد اس سیشن کی گفتگو خود جاری رکھتا ہے (کسی دوسرے سیشن کے چھوڑے ہوئے نوٹ پر عمل نہیں کیا جاتا)۔ اس کی قیمت ہر سیشن کے لیے ایک انتظار کرتا ccam پروسیس ہے، اسی لیے یہ ڈیفالٹ طور پر بند ہے۔ ریلے کیا گیا سیشن `ccam next --continue` سے شروع ہوتا ہے، ان آرگیومنٹس کے بغیر جن کے ساتھ پہلا سیشن شروع کیا گیا تھا، جیسے `--model`۔

## حد پر دوبارہ چلانا

`ccam next` اس انٹرایکٹو سیشن کے لیے ہے جو رک گیا ہو۔ غیر انٹرایکٹو رن، یعنی کسی اسکرپٹ یا شیڈول شدہ جاب میں `claude -p`، آپ کا انتظار نہیں کر سکتا، اس لیے اکاؤنٹ کے نام سے پہلے `--fallback` لگانے سے ccam اس کے لیے اکاؤنٹ بدل دیتا ہے:

```sh
ccam --fallback work -p "fix the failing tests" --output-format json
ccam --fallback -p "summarise" < notes.txt      # the folder's account or the default
ccam run --fallback work -p "review the diff"
```

```console
$ ccam --fallback personal -p "summarise" < notes.txt
ccam: personal reached its usage limit; running the command again as work
Summary: …
```

1. `--fallback` صرف `-p` یا `--print` کے ساتھ کام کرتا ہے؛ ورنہ ccam رک جاتا ہے اور `ccam next --auto --continue` کی طرف اشارہ کرتا ہے۔
2. اسٹینڈرڈ اِن پٹ ایک بار پڑھا جاتا ہے اور ہر کوشش کو دیا جاتا ہے۔
3. ccam، `exec` کے بجائے `claude` کو چائلڈ پروسیس کے طور پر شروع کرتا ہے، اس کا اسٹینڈرڈ آؤٹ پٹ روک کر رکھتا ہے، اور اسٹینڈرڈ ایرر کو جیسے جیسے آئے آگے دیتا ہے۔
4. جب `claude` 0 کے ساتھ باہر نکلے، یا کسی اور وجہ سے ناکام ہو، تو روکا ہوا آؤٹ پٹ اور ایگزٹ کوڈ بغیر تبدیلی کے آگے دیے جاتے ہیں۔
5. ناکامی کو استعمال کی حد مانا جاتا ہے جب Claude Code کا پیغام یہ کہے (`You've hit your limit`، `usage limit reached`)، یا جب اکاؤنٹ کے استعمال کی معلومات میں اس کی 5 گھنٹے یا ہفتہ وار ونڈو 100% پر ہو۔
6. پھر اس کوشش کا آؤٹ پٹ چھوڑ دیا جاتا ہے اور وہی کمانڈ کسی دوسرے لاگ اِن اکاؤنٹ سے چلتی ہے: سب سے کم 5 گھنٹے کے استعمال والا، پھر وہ اکاؤنٹس جن کا استعمال معلوم نہ ہو سکے، نمبر کی ترتیب سے۔ 100% والے اکاؤنٹس چھوڑ دیے جاتے ہیں، اور ہر اکاؤنٹ زیادہ سے زیادہ ایک بار آزمایا جاتا ہے۔
7. اگر آرگیومنٹس میں `-c`، `--continue`، `-r` یا `--resume` ہو تو صرف اسی ہسٹری گروپ کے اکاؤنٹس آزمائے جاتے ہیں، تاکہ گفتگو مل سکے۔
8. صرف اسی تنظیم کے اکاؤنٹس آزمائے جاتے ہیں، جیسے `--auto` کے ساتھ (`cross_org = true` یہ پابندی ہٹا دیتا ہے)۔

اگلا اکاؤنٹ انہی اصولوں سے چنا جاتا ہے جن سے `--auto` (`auto_max_usage`، `auto_strategy`، `--model` کی ونڈو)۔ جب کوئی اکاؤنٹ باقی نہ رہے تو ccam آخری کوشش کا آؤٹ پٹ پرنٹ کرتا ہے، بتاتا ہے کہ کسی لاگ اِن اکاؤنٹ میں گنجائش باقی نہیں، اور کوڈ 75 کے ساتھ باہر نکلتا ہے۔ اکاؤنٹ کے نام سے پہلے `--wait` کے ساتھ (`ccam --fallback --wait=2h work -p …`)، یہ اس کے بجائے پہلے اکاؤنٹ کے ری سیٹ ہونے کا انتظار کرتا ہے، پھر ہر اکاؤنٹ دوبارہ آزما سکتا ہے؛ یہ ہمیشہ پہلے کم از کم ایک بار رکتا ہے، تاکہ جو اکاؤنٹ ابھی اپنی حد کو پہنچا ہو وہ فوراً دوبارہ نہ چلے۔ `ccam --dry-run --fallback work -p …` پہلی کوشش کی کمانڈ پرنٹ کرتا ہے۔

انٹرایکٹو سیشنز خود بخود نہیں بدلتے۔ اس کے بجائے، `ccam statusline install` کے ساتھ، جب 5 گھنٹے یا ہفتہ وار استعمال 90% تک پہنچے تو اسٹیٹس لائن `→ ccam next --auto --continue` شامل کر دیتی ہے ([استعمال کی حدیں](/features/usage))۔

## حفاظت اور خاص صورتیں

- لاگ اِن کے بغیر اکاؤنٹس کبھی نہیں چنے جاتے۔ اگر کوئی دوسرا لاگ اِن شدہ اکاؤنٹ نہ ہو تو سادہ `ccam next`، `no logged-in account other than <name>` کے ساتھ رک جاتا ہے۔
- `--continue` کے ساتھ اور جب فولڈر میں کوئی گفتگو نہ ہو: `no account has a conversation in <folder> to continue`۔
- جب تنظیم کا اصول کوئی اکاؤنٹ نہ چھوڑے: `` no logged-in account to pick among <name>'s (<organization>); --cross-org also looks at the others ``۔
- `--auto` کے ساتھ اور جب کوئی لاگ اِن شدہ اکاؤنٹ نہ ہو: `no logged-in account to pick`۔ جب ہر اکاؤنٹ بھرا ہوا ہو یا اس کا استعمال نامعلوم ہو: `` no account with known usage and headroom (see `ccam usage`) ``۔ دونوں ایگزٹ کوڈ 75 پر ختم ہوتے ہیں۔
- `--max-usage`، `--strategy`، `--wait` اور `--cross-org` صرف `--auto` کے ساتھ کام کرتے ہیں، اور 1-100 سے باہر کی قدر یا کوئی دوسری حکمتِ عملی رد کر دی جاتی ہے۔
- فورک گفتگو کاپی کرتا ہے، اکاؤنٹ کی باقی حالت نہیں: اصل اکاؤنٹ کے `file-history/` کے checkpoints ساتھ نہیں آتے جب تک ہسٹری شیئر نہ ہو۔
- `--auto`، `--dry-run` کے ساتھ بھی نیٹ ورک درخواستیں بھیجتا ہے۔ یہ صرف پڑھتا ہے، اور کبھی ٹوکن فائلیں نہیں لکھتا۔
- چنا گیا اکاؤنٹ اسی راستے سے شروع ہوتا ہے جس سے `ccam <name>`، اس لیے وہی جانچ لاگو ہوتی ہے، بشمول اس انتباہ کے جب اسی ہسٹری کو شیئر کرنے والا کوئی دوسرا Claude Code پہلے سے اس فولڈر میں چل رہا ہو۔
- `last-used` صرف تب لکھا جاتا ہے جب Claude Code واقعی شروع ہو۔ `--dry-run` اسے نہیں چھیڑتا، اس لیے ڈرائی رن گردش کو آگے نہیں بڑھاتا۔
- `--fallback` کوشش ختم ہونے تک اسٹینڈرڈ آؤٹ پٹ روک کر رکھتا ہے، اس لیے `--output-format stream-json` جیسا اسٹریمنگ آؤٹ پٹ آخر میں ایک ساتھ آتا ہے۔ جو فائلیں پہلی کوشش نے حد تک پہنچنے سے پہلے بدلیں وہ بدلی ہی رہتی ہیں؛ اگلی کوشش پرامپٹ کو نئے سرے سے شروع کرتی ہے۔
