`ccam ext` اس سوال کا جواب دیتا ہے کہ "یہ اسکل (یا MCP سرور) ایک اکاؤنٹ میں کیوں کام کرتی ہے اور دوسرے میں کیوں نہیں؟"۔ یہ ہر اکاؤنٹ کے لیے وہ ایکسٹینشنز دکھاتا ہے جو Claude Code لوڈ کرتا ہے، اور یہ کہ ہر ایک کہاں سے آتی ہے: کوئی شیئر گروپ، اکاؤنٹ کا اپنا فولڈر، یا وہ پروجیکٹ جس میں آپ ہیں۔ ٹیبل کے نیچے یہ وہ چیزیں دکھاتا ہے جو کسی ایکسٹینشن کو آپ کی توقع کے مطابق لوڈ ہونے سے روکتی ہیں۔ یہ صرف پڑھتا ہے۔

## استعمال

```sh
ccam ext              # every account
ccam ext work         # one account
ccam ext --json       # for scripts
```

```console
$ ccam ext
Skills
          personal   work
  half    account !  -
  review  -          default

Commands
          personal  work
  deploy  default   default

MCP servers
       personal   work
  ctx  default !  default

Hooks (commands per event)
              personal     work
  PreToolUse  1 (default)  1 (default)

This project (/home/me/code/app):
  commands: ship
  MCP servers: fs

Sources: a group name (shared), account (its own folder), local (its own, for this folder only), - (not loaded); (off): installed, not turned on.
! personal: MCP server ctx is defined differently in group default's mcp.json and .claude.json
! personal: half: no SKILL.md, so Claude Code does not load it
```

ہر خانہ اس اکاؤنٹ میں اس آئٹم کا ماخذ بتاتا ہے: شیئر گروپ (`default`)، `account` جب وہ اکاؤنٹ کے اپنے فولڈر میں ہو، `local` اس MCP سرور کے لیے جو اکاؤنٹ کے پاس صرف اسی فولڈر کے لیے ہو، یا `-` جب اکاؤنٹ کے پاس وہ نہ ہو۔ جو پلگ اِن انسٹال ہو لیکن آن نہ ہو اس کے ماخذ کے بعد `(off)` آتا ہے۔ `!` کسی مسئلے والے آئٹم کو نشان زد کرتا ہے، جس کی وضاحت ٹیبل کے نیچے ہوتی ہے؛ جو مسائل کسی اکاؤنٹ سے متعلق نہیں، جیسے وہ سرورز جو صرف سادہ `claude` کے پاس ہیں، آخر میں بغیر نام کے آتے ہیں۔ `ccam ext --json` یہی رپورٹ پرنٹ کرتا ہے (`accounts`، پروجیکٹ، `problems`)، ان MCP سرورز پر `remote` کے ساتھ جن تک Claude Code نیٹ ورک کے ذریعے پہنچتا ہے؛ کوئی اکاؤنٹ نہ ہو تو یہ `accounts: []` کے ساتھ رپورٹ پرنٹ کرتا ہے۔

## یہ کیا پڑھتا ہے

| قسم | کہاں | دکھایا گیا ماخذ |
| --- | --- | --- |
| اسکلز | `skills/` میں ہر وہ فولڈر جس میں `SKILL.md` ہو | وہ گروپ جس سے `skills/` لنک ہے، یا `account` |
| کمانڈز، ایجنٹس | `commands/` اور `agents/` کے نیچے `.md` فائلیں، ذیلی فولڈرز `folder/name` کی صورت میں | گروپ، یا `account` |
| پلگ اِنز | `plugins/installed_plugins.json`، جنہیں اکاؤنٹ اور پروجیکٹ کی سیٹنگز میں `enabledPlugins` آن یا آف کرتا ہے؛ صرف ایک پروجیکٹ کے لیے انسٹال کیا گیا پلگ اِن صرف اسی پروجیکٹ میں دکھائی دیتا ہے | گروپ، یا `account`؛ آن نہ ہو تو `(off)` |
| MCP سرورز | گروپ کی `mcp.json` (جب MCP شیئر ہو)، اکاؤنٹ کی `.claude.json` (اس کے اپنے سرورز، اور وہ جو اس کے پاس صرف اسی فولڈر کے لیے ہیں)، اور اس کے پلگ اِنز کے سرورز، `plugin:<plugin>:<server>` کی صورت میں | گروپ، `account` یا `local` |
| ہُکس | `settings.json` میں `hooks`، ہر ایونٹ کے حساب سے گنے گئے | گروپ، یا `account` |
| یہ پروجیکٹ | موجودہ فولڈر میں `.claude/skills`، `.claude/commands`، `.claude/agents`، `.claude/settings.json`، `.claude/settings.local.json` اور `.mcp.json` | ایک بار دکھایا جاتا ہے؛ جس اکاؤنٹ نے فولڈر پر اعتماد نہ کیا ہو اسے اس کے `.mcp.json` سرورز کے لیے ایک مسئلہ دکھایا جاتا ہے |

## یہ کون سے مسائل بتاتا ہے

- **ٹوٹے ہوئے لنکس**: `skills/`، `commands/` یا `agents/` میں کوئی لنک جس کا ہدف موجود نہ رہا ہو، یا کوئی شیئر شدہ فولڈر (`skills`، `commands`، `agents`، `plugins`) جو کسی غائب جگہ سے لنک ہو (اسے `ccam doctor --fix` سے ٹھیک کریں، جو غائب گروپ فولڈر دوبارہ بنا دیتا ہے)۔
- **`SKILL.md` کے بغیر اسکل فولڈر**: Claude Code اسے چھوڑ دیتا ہے۔
- **دو جگہوں پر مختلف طرح سے متعین MCP سرور**: گروپ کی `mcp.json` اور اکاؤنٹ کی `.claude.json`، یا ان میں سے ایک اور پروجیکٹ کی `.mcp.json`۔ دونوں جگہوں پر ایک جیسی سیٹنگز (جو `mcp_strategy = "sync"` لکھتا ہے) مسئلہ نہیں۔ کسی اکاؤنٹ کا اپنا سرور `ccam mcp import <account> <server>` سے گروپ میں منتقل کریں۔
- **`installed_plugins.json` جو درست JSON نہ ہو**، ایسا پلگ اِن جس کا نام `enabledPlugins` میں نہ ہو، اور ایسا پلگ اِن جس کا فولڈر غائب ہو۔
- **سرورز جو صرف ایک اکاؤنٹ لوڈ کرتا ہے**: ایسا سرور جو صرف اس اکاؤنٹ کی `.claude.json` میں ہو، جسے اس کے گروپ کے دوسرے اکاؤنٹس لوڈ نہیں کرتے، اور ایسا سرور جو اس فولڈر کے لیے اکاؤنٹ کے local اسکوپ میں ہو (`claude mcp add` یہی کرتا ہے جب تک `-s user` نہ دیا جائے)۔ ہر ایک کے ساتھ وہ `ccam mcp import` کمانڈ آتی ہے جو اسے شیئر کرتی ہے۔ سادہ `claude` کی `~/.claude.json` کے وہ سرورز جنہیں کوئی اکاؤنٹ لوڈ نہیں کرتا، `ccam migrate --mcp` کمانڈ کے ساتھ آتے ہیں۔
- **منظوری کا منتظر پروجیکٹ سرور**: اکاؤنٹ نے ابھی فولڈر پر اعتماد نہیں کیا، اس لیے Claude Code ایک بار پوچھتا ہے، اور تب تک پروجیکٹ کی `.mcp.json` کے سرورز انتظار کرتے ہیں۔ مسئلہ بتاتا ہے کہ انہیں کہاں منظور کریں: سیٹنگز گروپ کے اکاؤنٹس کی، یا اس اکاؤنٹ کی، `settings.json` میں `"enabledMcpjsonServers"`۔ کسی git ریپوزٹری کے مرکزی worktree کو دیا گیا اعتماد اس کے دوسرے worktrees میں بھی شمار ہوتا ہے۔
- **سائن اِن اور کنیکٹرز**: ایسا MCP سرور جسے اس اکاؤنٹ میں سائن اِن چاہیے جبکہ کوئی دوسرا اکاؤنٹ اس میں سائن اِن ہے (ایک سائن اِن صرف ایک اکاؤنٹ کے لیے ہوتا ہے؛ `/mcp` سے سائن اِن کریں)، اور claude.ai کے وہ کنیکٹرز جو کسی دوسرے اکاؤنٹ نے استعمال کیے ہیں اور اس نے نہیں۔

## حفاظت اور خاص صورتیں

- `ccam ext` کچھ نہیں بدلتا اور کوئی نیٹ ورک درخواست نہیں بھیجتا۔ یہ سرورز کے نام اور ہُکس کی تعداد پڑھتا ہے، MCP تعریفوں میں `env` یا ہیڈرز کی قدریں کبھی نہیں۔ سائن اِن کی جانچ کے لیے یہ ہر اکاؤنٹ کے لاگ اِن میں MCP سائن اِن کے نام پڑھتا ہے (macOS پر Keychain سے)، ٹوکنز کبھی نہیں، اور صرف ان اکاؤنٹس کے لیے جو کوئی ایسا سرور لوڈ کرتے ہیں جسے کوئی دوسرا اکاؤنٹ بھی لوڈ کرتا ہے۔
- یہ وہی دکھاتا ہے جو ڈسک پر ہے۔ جو سرور منیجڈ سیٹنگز نے روکا ہو وہ پھر بھی دکھائی دیتا ہے؛ سیٹنگز میں بند پلگ اِن `(off)` دکھاتا ہے۔
- اسے پروجیکٹ کے فولڈر میں چلائیں تاکہ اس پروجیکٹ کا `.claude` فولڈر اور `.mcp.json` بھی شامل ہوں۔
