## کیا ccam، Anthropic کا سرکاری ٹول ہے؟

نہیں۔ ccam ایک غیر سرکاری اوپن سورس پروجیکٹ ہے۔ اس کا Anthropic سے کوئی تعلق نہیں، اور نہ ہی Anthropic اس کی توثیق کرتا ہے۔ یہ `CLAUDE_CONFIG_DIR` سیٹنگ استعمال کرتا ہے، جسے [Claude Code کی دستاویزات](https://code.claude.com/docs/en/env-vars) کئی اکاؤنٹس ساتھ ساتھ چلانے کے لیے بیان کرتی ہیں۔

## کیا مجھے Claude Code کے کئی اکاؤنٹس استعمال کرنے کی اجازت ہے؟

یہ ہر اکاؤنٹ کی شرائط پر منحصر ہے، اور کام کے اکاؤنٹس کے معاملے میں آپ کے ادارے کی پالیسی پر بھی: Pro اور Max کے لیے Anthropic کی [Consumer Terms](https://www.anthropic.com/legal/consumer-terms)، Team اور Enterprise کے لیے اس کی [Commercial Terms](https://www.anthropic.com/legal/commercial-terms)، اور سب کے لیے اس کی [Usage Policy](https://www.anthropic.com/legal/aup)۔ کئی اکاؤنٹس استعمال کرنے سے پہلے انہیں چیک کریں۔ ccam کسی اکاؤنٹ کی حدیں نہ بڑھاتا ہے، نہ ملاتا ہے اور نہ چھپاتا ہے، اور ہر اکاؤنٹ اب بھی اپنی حد پر رک جاتا ہے۔ یہ آپ کا کام آپ کے کسی دوسرے اکاؤنٹ پر منتقل کرتا ہے جب آپ کہیں، یا جب آپ [`auto_switch`](/features/next#auto-switch) (Linux اور macOS) آن کریں تو کسی حد پر خود بخود۔ اسے استعمال کرنے سے پہلے چیک کریں کہ یہ آپ کے اکاؤنٹس کے لیے جائز ہے یا نہیں؛ فیصلہ آپ کا ہے۔

**Team اور Enterprise سیٹیں۔** خودکار اکاؤنٹ انتخاب (`ccam next`، `--fallback`، `ccam pick`، ڈیش بورڈ کی `n` کلید اور جب آپ اسے آن کریں تو [`auto_switch`](/features/next#auto-switch)) ایک ہی Claude Team یا Enterprise تنظیم کی سیٹوں کے درمیان بھی اکاؤنٹ بدلتا ہے۔ Anthropic کا ہیلپ سینٹر کہتا ہے کہ "Each seat on a Team plan is assigned to one named individual, and only that person may use it" (کسی Team پلان کی ہر سیٹ ایک نامزد فرد کو تفویض کی جاتی ہے، اور صرف اسی شخص کو اسے استعمال کرنے کی اجازت ہے) اور "Users can't route their work through another user's account to use that user's remaining usage" (صارفین کسی دوسرے صارف کا باقی ماندہ استعمال کام میں لانے کے لیے اپنا کام اس کے اکاؤنٹ کے ذریعے نہیں چلا سکتے) ([Team پلانز](https://support.claude.com/en/articles/12004354-purchase-and-manage-seats-on-team-plans#h_b8a7d07129)؛ اسی طرح [Enterprise پلانز](https://support.claude.com/en/articles/13393991-purchase-and-manage-seats-on-enterprise-plans#h_fa6b9cade0) کے لیے بھی)۔ اس لیے سیٹوں کے درمیان خودکار انتخاب استعمال کرنے سے Anthropic کی شرائط کی خلاف ورزی ہو سکتی ہے۔ وہاں اسے استعمال کرنا ہے یا نہیں، یہ آپ کا فیصلہ ہے: اس پر انحصار کرنے سے پہلے اپنی تنظیم اور Anthropic سے تصدیق کر لیں۔ ذاتی پلانز (Pro، Max) کی بات اوپر والے پیراگراف میں کی گئی ہے۔

## کیا ccam استعمال کی حدوں کو بائی پاس کرتا ہے؟

کسی اکاؤنٹ کی اپنی حد سے آگے نہیں: ہر اکاؤنٹ کی اپنی حدیں برقرار رہتی ہیں اور وہ ان پر رک جاتا ہے، اور ccam انہیں نہ بڑھاتا ہے، نہ ملاتا ہے اور نہ چھپاتا ہے۔ ccam یہ حدیں دکھاتا ہے، اور جب ایک اکاؤنٹ کی حد ختم ہو جائے تو آپ کو اپنے کسی دوسرے اکاؤنٹ پر کام جاری رکھنے دیتا ہے؛ `auto_switch` آن ہو تو یہ کام خود کر دیتا ہے (اگلا سوال دیکھیں)۔ ایک ہی Team یا Enterprise تنظیم کی سیٹوں کے درمیان، کسی دوسری سیٹ پر کام جاری رکھنا اس سیٹ کا باقی ماندہ استعمال خرچ کرتا ہے، جسے Anthropic کا ہیلپ سینٹر کسی دوسرے صارف کی سیٹ کے لیے ممنوع قرار دیتا ہے (اوپر Team اور Enterprise سیٹیں دیکھیں)۔

## کیا ccam سیشن کے اپنی حد تک پہنچنے پر خود اکاؤنٹ بدل سکتا ہے؟

صرف تب جب آپ اسے آن کریں۔ `~/.config/ccam/config.toml` میں سب سے اوپر `auto_switch = true` کے ساتھ (Linux اور macOS؛ ڈیفالٹ طور پر بند اور تجرباتی)، جب Claude Code کسی انٹرایکٹو سیشن کو (جو ccam نے شروع کیا ہو) 5 گھنٹے، ہفتہ وار، Opus یا Sonnet کی حد پر روک دے، تو ccam سیشن ختم کر کے گفتگو آپ کے کسی ایسے دوسرے اکاؤنٹ کے طور پر جاری رکھتا ہے جس میں گنجائش ہو: اسی Team یا Enterprise تنظیم کی کوئی دوسری سیٹ، یا کوئی دوسرا ذاتی پلان (Pro، Max)۔ یہ حد سے پہلے کبھی اکاؤنٹ نہیں بدلتا، پس منظر میں کبھی آپ کے استعمال پر نظر نہیں رکھتا، اور کبھی کام کو کسی Team یا Enterprise تنظیم سے باہر یا اس کے اندر نہیں لے جاتا۔

سیٹوں پر یہ آپ کا کام ایک سیٹ سے دوسری سیٹ پر لے جاتا ہے، جس سے Anthropic کی شرائط کی خلاف ورزی ہو سکتی ہے (اوپر Team اور Enterprise سیٹیں دیکھیں)۔ ذاتی پلانز کے لیے Anthropic کی شرائط اس بارے میں واضح نہیں ہیں: Consumer Terms سروسز تک "through automated or non-human means" (خودکار یا غیر انسانی ذرائع سے) رسائی سے منع کرتی ہیں جب تک Anthropic واضح طور پر اجازت نہ دے، اور ایک منتقلی آپ کی طرف سے ایک پیغام بھیجتی ہے۔ اسے آن کرنا آپ کا فیصلہ ہے۔

[`auto_switch`](/features/next#auto-switch) ہر شرط اور یہ بتاتا ہے کہ ایک منتقلی کی لاگت کیا ہے۔

## میں ایک کمپیوٹر پر Claude Code کے دو اکاؤنٹس کیسے استعمال کروں؟

ہر اکاؤنٹ کو `CLAUDE_CONFIG_DIR` کے ساتھ اس کا اپنا کنفیگریشن فولڈر دیں۔ ccam یہ کام آپ کے لیے کرتا ہے: ہر اکاؤنٹ کے لیے `ccam add` چلائیں، پھر انہیں `ccam personal` اور `ccam work` سے شروع کریں، یا ایسے شارٹ کٹس سے جن کے نام آپ خود رکھیں، جیسے `ccwork`۔ [گائیڈ](/guides/multiple-claude-code-accounts) یہ بھی دکھاتی ہے کہ یہ کام ہاتھ سے کیسے کیا جائے۔

## میں دوسرے اکاؤنٹ پر گفتگو کیسے جاری رکھوں؟

فولڈر میں `ccam next --continue` چلائیں: یہ فولڈر کی آخری گفتگو اگلے اکاؤنٹ پر لے جاتا ہے (سب سے زیادہ گنجائش والے اکاؤنٹ کے لیے `--auto`)۔ Claude Code کے اندر، [ccam پلگ اِن](/docs/install#claude-code-plugin) کا `/ccam:switch` اسی سیشن کے لیے یہی کام کرتا ہے جس میں آپ ہیں۔ جب دونوں اکاؤنٹس گفتگو کی ہسٹری شیئر کرتے ہوں (`ccam group set default --add history`، یا ان کا اپنا ایک گروپ: `ccam group add pair --items history --members work,side`) تو نیا اکاؤنٹ بالکل وہی گفتگو کھولتا ہے؛ ورنہ Claude Code اسے نئے اکاؤنٹ کی ہسٹری میں کاپی کر دیتا ہے۔ نئے اکاؤنٹ کو پوری گفتگو کے بجائے ایک مختصر خلاصے سے شروع کرنے کے لیے `--brief` شامل کریں۔

## کیا ccam میرا لاگ اِن دیکھتا یا کہیں بھیجتا ہے؟

ccam آپ کا Claude لاگ اِن کبھی اکاؤنٹس کے درمیان شیئر یا کاپی نہیں کرتا، اور MCP سرورز کے سائن اِن بھی کبھی کاپی نہیں کرتا۔ یہ کسی اکاؤنٹ کا ایکسیس ٹوکن صرف اس لیے پڑھتا ہے کہ Anthropic کے usage اینڈ پوائنٹ سے اسی اکاؤنٹ کا استعمال معلوم کرے: `ccam usage`، ڈیش بورڈ، `ccam doctor` اور خودکار انتخاب (`ccam next --auto`، `ccam pick`، `--fallback`، اور جب کوئی سیشن اپنی حد تک پہنچے تو `auto_switch`) کے لیے۔ میعاد ختم ٹوکن کی تجدید یہ صرف `ccam usage --refresh` سے کرتا ہے؛ `usage_source = "claude"` کے ساتھ یہ کہیں کوئی ٹوکن نہیں بھیجتا اور محفوظ لاگ اِن (فائل، یا macOS Keychain کا اندراج) صرف یہ جاننے کے لیے پڑھتا ہے کہ وہ اب بھی کام کرتا ہے یا نہیں۔ `ccam ext` اور `ccam doctor` کسی اکاؤنٹ کے MCP سائن اِن کے نام پڑھتے ہیں، ان کے ٹوکن کبھی نہیں۔ ccam میں کوئی ٹیلی میٹری نہیں ہے۔ ان درخواستوں کے علاوہ یہ خود سے صرف ایک درخواست کرتا ہے: ڈیش بورڈ GitHub پر ccam کی نئی ریلیز کی جانچ کرتا ہے، اور اس میں آپ یا آپ کے اکاؤنٹس کے بارے میں کچھ نہیں ہوتا۔

## میں ریموٹ سرور پر سائن اِن کیسے کروں؟

SSH سیشن میں معمول کے مطابق `ccam add` یا `ccam login <name>` چلائیں۔ Claude Code سرور پر سائن اِن کا انتظار کرتا ہے، اس لیے آپ کے کمپیوٹر کا براؤزر ایک ایسے `http://localhost:<port>/callback?code=…` صفحے پر رک جاتا ہے جو لوڈ نہیں ہوتا۔ وہ ایڈریس براؤزر سے کاپی کریں اور ٹرمینل میں پیسٹ کریں: ccam اسے سرور پر موجود Claude Code کو دے دیتا ہے، جو سائن اِن مکمل کر دیتا ہے۔ اس ایڈریس میں ایک بار استعمال ہونے والا کوڈ ہوتا ہے، اس لیے اسے کسی کے ساتھ شیئر نہ کریں۔

## میرے اکاؤنٹس کہاں محفوظ ہوتے ہیں؟

`~/.local/share/ccam/profiles/<name>/` میں، ہر اکاؤنٹ کے لیے ایک فولڈر۔ macOS پر لاگ اِن بذاتِ خود Keychain میں رہتا ہے، جہاں Claude Code اسے اسی فولڈر سے اخذ کیے گئے ایک نام کے تحت رکھتا ہے، اس لیے `ccam rename` وہاں فولڈر کا پرانا نام برقرار رکھتا ہے۔

## میرے موجودہ ~/.claude کا کیا ہوگا؟

کچھ نہیں، جب تک آپ `ccam import` یا `ccam migrate` نہ چلائیں۔ امپورٹ فولڈر کو اس کی جگہ پر ہی رجسٹر کرتا ہے، اس لیے سادہ `claude` اور `ccam <name>` وہی اکاؤنٹ اور سیٹنگز استعمال کرتے رہتے ہیں۔ `ccam migrate` اس کی سیٹنگز، `CLAUDE.md`، ایکسٹینشنز اور MCP سرورز کو شیئر شدہ `default` گروپ میں کاپی کرتا ہے اور فولڈر کو صرف پڑھتا ہے۔

## ccam کن سسٹمز پر چلتا ہے؟

Linux (Ubuntu، Debian، Fedora، Arch، Alpine اور دیگر)، macOS اور Windows 10 اور 11، براہِ راست یا WSL کے اندر۔ Windows پر `settings.json` جیسی فائلیں شیئر کرنے کے لیے Developer Mode درکار ہے؛ شیئر کیے گئے فولڈرز اس کے بغیر بھی کام کرتے ہیں، اور اس کے بغیر پہلا `ccam add`، `default` گروپ صرف MCP سرورز اور ایکسٹینشنز کے ساتھ بناتا ہے ([Windows پر شیئرنگ](/features/share#on-windows))۔

## کوئی MCP سرور صرف ایک اکاؤنٹ میں کیوں نظر آتا ہے؟

سیشن کے اندر `claude mcp add` سے شامل کیے گئے سرورز صرف اسی اکاؤنٹ کے لیے محفوظ ہوتے ہیں، اور `-s user` کے بغیر صرف موجودہ فولڈر کے لیے۔ اگلی بار جب آپ وہ اکاؤنٹ شروع کریں گے تو ccam آپ کو اس کے بارے میں بتائے گا، اور `ccam mcp list` اور `ccam ext` انہیں دکھاتے ہیں؛ سرور کو `ccam mcp import <account> <server>` سے شیئر شدہ گروپ میں منتقل کریں۔

## کیا ccam سے Claude Code سست ہو جاتا ہے؟

ccam کے ذریعے Claude Code شروع کرنے میں تقریباً 4 ملی سیکنڈ کا اضافہ ہوتا ہے، جو ایک لیپ ٹاپ پر `scripts/perf-check.sh` سے ناپا گیا۔ ccam ایک چھوٹی فائل پڑھتا ہے، شیئر کیے گئے لنکس چیک کرتا ہے اور پھر خود کو `claude` سے بدل دیتا ہے، اس لیے ڈیفالٹ طور پر جب آپ کام کر رہے ہوتے ہیں تو یہ چل نہیں رہا ہوتا۔ Windows کسی پروسیس کو بدل نہیں سکتا، اس لیے وہاں ccam Claude Code شروع کرتا ہے اور اس کا انتظار کرتا ہے، اور کچھ نہیں کرتا۔ `relay` یا `auto_switch` آن ہو تو ccam اسی طرح ہر انٹرایکٹو سیشن کے ساتھ ساتھ چلتا رہتا ہے، تاکہ گفتگو کسی دوسرے اکاؤنٹ پر جاری رکھ سکے۔

## میں ccam کو اپ ڈیٹ کیسے کروں؟

`ccam update` چلائیں۔ یہ تازہ ترین ریلیز ڈاؤن لوڈ کرتا ہے، اس کا چیک سم جانچتا ہے اور `ccam` فائل بدل دیتا ہے؛ `ccam update --check` صرف یہ بتاتا ہے کہ کوئی نئی ریلیز موجود ہے یا نہیں۔ ڈیش بورڈ بھی بتاتا ہے جب کوئی نئی ریلیز موجود ہو، اور `U` پوچھنے کے بعد اسے انسٹال کرتا ہے؛ ccam کبھی خود سے اپ ڈیٹ نہیں ہوتا۔ اگر آپ نے `.deb` پیکیج انسٹال کیا تھا تو اس کے بجائے نئی `.deb` کو apt سے انسٹال کریں۔ [اپ ڈیٹ کرنا](/docs/install#update) دیکھیں۔

## میں ccam کو اَن انسٹال کیسے کروں؟

ہر اکاؤنٹ کا شارٹ کٹ `ccam shortcut <account> --remove` سے ہٹائیں۔ اگر آپ نے `~/.claude` امپورٹ کیا تھا اور وہ کسی گروپ میں ہے تو پہلے اس کے لیے `ccam remove <name>` چلائیں، تاکہ اسے اس چیز کی کاپی واپس مل جائے جو وہ شیئر کرتا ہے۔ پھر `~/.local/bin` سے `ccam` حذف کریں، اور اگر اکاؤنٹس کی مزید ضرورت نہیں تو `~/.config/ccam`، `~/.local/share/ccam` اور `~/.local/state/ccam` ہٹا دیں۔ [انسٹال](/docs/install#uninstall) دیکھیں۔
