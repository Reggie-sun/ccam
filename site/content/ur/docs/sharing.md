ہر اکاؤنٹ اپنا لاگ اِن الگ رکھتا ہے۔ باقی سب کچھ **گروپس** کے ذریعے شیئر کیا جا سکتا ہے: گروپ بتاتا ہے کہ وہ کون سے آئٹمز شیئر کرتا ہے اور اس میں کون سے اکاؤنٹس ہیں، اور ccam ان میں سے ہر اکاؤنٹ کی فائلوں کو گروپ کے فولڈر سے لنک کرتا ہے، اس لیے ایک اکاؤنٹ میں کی گئی تبدیلی ان سب میں نظر آتی ہے۔

## کیا کچھ شیئر کیا جا سکتا ہے

| آئٹم | کیا شیئر ہوتا ہے |
| --- | --- |
| `mcp` | MCP سرورز: گروپ کی `mcp.json`، جو شروع ہوتے وقت Claude Code کو دی جاتی ہے |
| `settings` | `settings.json`: اجازتیں، ہُکس، ماڈل، اسٹیٹس لائن |
| `memory` | گلوبل `CLAUDE.md` |
| `extensions` | `agents/`، `commands/`، `skills/`، `plugins/`، `output-styles/`، `rules/` |
| `history` | گفتگو کی ہسٹری: `projects/` اور `history.jsonl` |

آپ کا پہلا اکاؤنٹ گروپ `default` بناتا ہے، جو گفتگو کی ہسٹری کے سوا سب کچھ شیئر کرتا ہے، اور بعد کے اکاؤنٹس اس میں شامل ہو جاتے ہیں۔

لاگ اِن کی فائلیں `.credentials.json` اور `.claude.json` کبھی شیئر نہیں ہوتیں۔ ccam صرف ایک طے شدہ فہرست میں موجود راستوں کو لنک کرتا ہے، اور یہ دونوں فائلیں اس فہرست میں نہیں ہیں۔

یہ صفحہ روزمرہ کے کام بیان کرتا ہے۔ ہر آپشن کی تفصیل خصوصیات کے صفحات پر ہے: [گروپس کے ساتھ شیئرنگ](/features/share)، [شیئر کیے گئے MCP سرورز](/features/mcp) اور [موجودہ سیٹ اپ کاپی کرنا](/features/migrate)۔

## گروپس

```sh
ccam group                                   # the groups, what they share, their accounts
ccam group set default --add history         # every account in default shares history
ccam group add team --items history --members work,side
```

ایک اکاؤنٹ کئی گروپس میں ہو سکتا ہے، لیکن ہر آئٹم صرف ایک گروپ سے آتا ہے۔ اس لیے اگر `work` اور `side` کے درمیان ہسٹری شیئر کرنی ہو لیکن آپ کے دوسرے اکاؤنٹس کے ساتھ نہیں، تو ہسٹری کو `default` سے باہر رکھیں اور ان دونوں کو ان کا اپنا گروپ دیں، جیسا کہ اوپر ہے۔ `ccam share work` دکھاتا ہے کہ کوئی اکاؤنٹ کیا شیئر کرتا ہے اور کس گروپ کے ذریعے۔ [ڈیش بورڈ](/features/dashboard) اپنے Groups ٹیب پر یہی کام کرتا ہے۔

## جب کوئی اکاؤنٹ شیئرنگ شروع کرے

جب کوئی اکاؤنٹ کسی آئٹم کو شیئر کرنا شروع کرتا ہے (وہ کسی گروپ میں شامل ہوتا ہے، یا اس کا گروپ وہ آئٹم شامل کرتا ہے) تو ccam:

1. ہر اکاؤنٹ کے لیے ہر اس فائل کا منصوبہ پرنٹ کرتا ہے جسے وہ منتقل، کاپی یا لنک کرے گا، اور شروع کرنے سے پہلے آپ سے پوچھتا ہے؛
2. اگر گروپ ابھی خالی ہے تو اکاؤنٹ کی فائلیں گروپ فولڈر میں منتقل کرتا ہے، ورنہ وہ فائلیں شامل کرتا ہے جو گروپ میں ابھی موجود نہیں؛
3. جب ایک ہی فائل دونوں جگہ مختلف ہو تو پوچھتا ہے کہ گروپ کا ورژن رکھا جائے، آپ کا ورژن استعمال کیا جائے، یا JSON کو ملا دیا جائے؛
4. آپ کی اصل فائل اکاؤنٹ فولڈر کے اندر `.ccam-backup/<time>/` میں محفوظ رکھتا ہے؛
5. اصل فائل کی جگہ گروپ کا لنک لگا دیتا ہے۔

گفتگو کی فائلوں کے نام ان کے سیشن ID پر رکھے جاتے ہیں، اس لیے کئی اکاؤنٹس کی ہسٹریاں بغیر کسی ٹکراؤ کے یکجا ہو جاتی ہیں۔

جب Claude Code کسی اکاؤنٹ کے طور پر چل رہا ہو، چاہے وہ کسی بھی طرح شروع ہوا ہو (بیک گراؤنڈ سیشنز بھی)، تو ccam اس اکاؤنٹ کو تبدیل نہیں کرتا، کیونکہ سیشن ان فائلوں میں لکھتا رہتا ہے جو منتقل کی جا رہی ہوتی ہیں۔ پہلے اسے بند کریں۔ ccam محفوظ کرنے سے عین پہلے دوبارہ جانچتا ہے، اس لیے جو سیشن پلان کے انتظار کے دوران شروع ہوا ہو وہ بھی پکڑا جاتا ہے۔

## جب کوئی اکاؤنٹ شیئرنگ بند کرے

```sh
ccam group leave team work                   # work leaves the group
ccam group set default --remove history      # nobody in default shares history any more
```

لنک ہٹا دیا جاتا ہے اور اکاؤنٹ کو گروپ کے موجودہ مواد کی اپنی کاپی مل جاتی ہے؛ گروپ کے MCP سرورز اس کی اپنی `.claude.json` میں، اس کے اپنے سرورز کے ساتھ، چلے جاتے ہیں۔ اس کے بجائے خالی حالت سے شروع کرنے کے لیے `--fresh` شامل کریں؛ تب پلان ان MCP سرورز کی فہرست دیتا ہے جو لوڈ ہونا بند ہو جائیں گے۔ `~/.claude` جیسا امپورٹ کیا گیا فولڈر ہمیشہ ایک کاپی رکھتا ہے۔ گروپ اپنا مواد دوسرے اکاؤنٹس کے لیے برقرار رکھتا ہے۔

## موجودہ سیٹ اپ کاپی کریں

اگر آپ ccam سے پہلے Claude Code استعمال کرتے تھے تو آپ کی سیٹنگز `~/.claude` میں ہیں۔ `ccam migrate` انہیں ایک گروپ میں کاپی کرتا ہے، تاکہ وہ آئٹمز شیئر کرنے والے ہر اکاؤنٹ کو یہ مل جائیں:

```sh
ccam migrate
```

ٹرمینل پر ccam پہلے آئٹمز کی ایک چیک لسٹ دکھاتا ہے۔ گفتگو کی ہسٹری کے سوا سب کچھ چیک ہوتا ہے؛ کسی آئٹم کو بدلنے کے لیے Space اور پلان دیکھنے کے لیے Enter دبائیں۔ جن آئٹمز کے لیے فولڈر میں کچھ نہیں ہوتا ان پر `not found` لکھا ہوتا ہے۔

یہ کیا کاپی کرتا ہے:

- `settings.json` اور گلوبل `CLAUDE.md`؛
- ایکسٹینشنز `agents/`، `commands/`، `skills/`، `plugins/`، `output-styles/` اور `rules/`؛
- آپ کے یوزر MCP سرورز، یعنی `~/.claude.json` کی `mcpServers` اینٹری، گروپ کی `mcp.json` میں؛
- گفتگو کی ہسٹری (`projects/` اور `history.jsonl`)، لیکن صرف تب جب آپ `--history` لگائیں۔

سورس فولڈر کو صرف پڑھا جاتا ہے: اس میں کچھ بھی منتقل، لنک یا تبدیل نہیں ہوتا، اور سادہ `claude` پہلے کی طرح کام کرتا رہتا ہے۔ لاگ اِن فائلیں `.credentials.json` اور `.claude.json` کبھی گروپ میں کاپی نہیں ہوتیں۔

جو MCP سرورز OAuth سے سائن اِن کرتے ہیں وہ اپنے ٹوکنز سرورز کی فہرست میں نہیں بلکہ لاگ اِن میں رکھتے ہیں۔ ccam یہ سائن اِن کاپی نہیں کرتا: کاپی کیے گئے سائن اِن میں وہی ریفریش ٹوکن ہوتا ہے، اور پہلی تجدید باقی ہر رکھنے والے کو، `~/.claude` سمیت، اس سرور سے لاگ آؤٹ کر دیتی ہے۔ پلان اور خلاصہ ان اکاؤنٹس کے نام بتاتے ہیں جو `/mcp` سے خود سرورز میں سائن اِن کریں۔

کچھ بھی کاپی کرنے سے پہلے ccam منصوبہ دکھاتا ہے اور پوچھتا ہے:

```console
$ ccam migrate
Copy from /home/me/.claude into group default (/home/me/.local/share/ccam/groups/default):
  mcp         ~/.claude.json  new: context7, fs
  settings    settings.json   new: 80 B
  memory      CLAUDE.md       new: 31 B
  extensions  agents/         add 1 file the group lacks (17 B)
              commands/       add 1 file the group lacks (15 B)
              skills/         add 1 file the group lacks (32 B)
              not found, skipped: plugins/, output-styles/, rules/
  Conversation history (projects/, history.jsonl) is not included; add --history to copy it.
Copy these into group default? [y/N] y
✓ Copied into group default: 2 MCP servers, settings.json, CLAUDE.md, agents/, commands/, skills/
Group default: personal
To share them:
  ccam group join default work
```

آخر میں ccam گروپ کے اکاؤنٹس کی فہرست دکھاتا ہے۔ اگر گروپ ابھی ان آئٹمز میں سے کوئی شیئر نہیں کرتا، یا کچھ اکاؤنٹس اس میں نہیں ہیں، تو یہ وہ `ccam group` کمانڈز دکھاتا ہے جو اسے بدلتی ہیں۔

جب گروپ کے پاس کسی فائل کی پہلے سے مختلف کاپی ہو تو ccam، شیئرنگ آن کرتے وقت کی طرح، پوچھتا ہے: گروپ کی کاپی رکھیں یا اپنی استعمال کریں۔ `settings.json` اور دوسری JSON فائلیں ضم بھی کی جا سکتی ہیں، اور `history.jsonl` لائن بہ لائن۔ گروپ کی پچھلی کاپیاں گروپ فولڈر کے اندر `.ccam-backup/<time>/` میں محفوظ ہوتی ہیں۔

| آپشن | اثر |
| --- | --- |
| `--settings`، `--memory`، `--extensions`، `--mcp`، `--history` | صرف وہ آئٹمز کاپی کریں جن کا نام لیا گیا ہو، چیک لسٹ کے بغیر؛ ان کے بغیر اور ٹرمینل سے باہر، گفتگو کی ہسٹری کے سوا سب کچھ |
| `-g`، `--group <group>` | `default` کی بجائے اس گروپ میں کاپی کریں |
| `-y`، `--yes` | بغیر پوچھے کاپی کریں؛ فائل مختلف ہو تو گروپ کی کاپی رکھیں |

کچھ کاپی کیے بغیر منصوبہ دیکھنے کے لیے کمانڈ سے پہلے `--dry-run` لگائیں، جیسے `ccam --dry-run migrate`۔ کسی دوسرے فولڈر سے کاپی کرنے کے لیے اس کا نام دیں: `ccam migrate ~/.claude-work --group work`۔

## MCP سرورز

Claude Code، MCP سرورز کو لاگ اِن کے ساتھ `.claude.json` میں رکھتا ہے، اس لیے یہ فائل شیئر نہیں کی جا سکتی۔ ccam شیئر کیے گئے سرورز کو گروپ کی `mcp.json` میں رکھتا ہے اور Claude Code کو `--mcp-config=<group>/mcp.json` کے ساتھ شروع کرتا ہے۔ آپ کے اپنے `--mcp-config` آپشنز بھی اس کے اوپر لاگو رہتے ہیں۔

```sh
ccam mcp add fs -- npx -y @modelcontextprotocol/server-filesystem ~/code
ccam mcp list
```

جو سرور آپ کسی سیشن کے اندر `claude mcp add` سے شامل کرتے ہیں وہ صرف اسی اکاؤنٹ کے لیے، اور اسی فولڈر کے لیے جس میں آپ تھے، محفوظ ہوتا ہے (Claude Code کا local اسکوپ؛ `-s user` اسے ہر فولڈر میں اس اکاؤنٹ کا سرور بنا دیتا ہے)۔ اگلی بار جب آپ وہ اکاؤنٹ شروع کریں گے تو ccam اس سرور کا نام، اس کے فولڈر کے ساتھ، اور وہ کمانڈ بتائے گا جو اسے گروپ میں منتقل کرتی ہے:

```sh
ccam mcp import work gh
```

اگر گروپ میں اسی نام کا کوئی مختلف سرور پہلے سے موجود ہو تو ccam اسے چھوڑ دیتا ہے اور یہ بتا دیتا ہے۔ `--force` گروپ کا سرور بدل دیتا ہے اور پرانی `mcp.json` گروپ کے `.ccam-backup/` فولڈر میں رکھ لیتا ہے۔

جو MCP سرورز OAuth سے سائن اِن کرتے ہیں وہ اپنے ٹوکنز اکاؤنٹ کے لاگ اِن کے ساتھ محفوظ کرتے ہیں، اس لیے ہر اکاؤنٹ میں `/mcp` سے انہیں ایک بار اجازت دیں۔ `ccam ext` اور `ccam doctor` ان سرورز کے نام بتاتے ہیں جن میں کوئی اکاؤنٹ سائن اِن نہیں جبکہ کوئی دوسرا اکاؤنٹ سائن اِن ہے۔

اگر آپ چاہتے ہیں کہ سرورز `claude mcp list` اور `/mcp` میں عام یوزر سرورز کے طور پر نظر آئیں تو `~/.config/ccam/config.toml` میں سب سے اوپر، پہلے `[[group]]`، `[[profile]]` یا `[[folder]]` سے اوپر، `mcp_strategy = "sync"` سیٹ کریں۔ اس صورت میں ccam شروع کرنے سے پہلے انہیں ہر اکاؤنٹ کی `.claude.json` میں لکھ دیتا ہے، Claude Code کے اپنے فائل لاک کے تحت اور بیک اپ کے ساتھ۔ اگر اکاؤنٹ کا اپنا کوئی سرور اسی نام سے ہو تو وہ اکاؤنٹ کا ہی رہتا ہے، اور ccam یہ بتا دیتا ہے۔

## ایک ہی فولڈر میں دو اکاؤنٹس

جو اکاؤنٹس گفتگو کی ہسٹری شیئر کرتے ہیں وہ ایک ہی فائلوں میں لکھتے ہیں۔ اگر آپ کسی ایسے فولڈر میں دوسرا Claude Code شروع کریں جہاں اسی گروپ کا کوئی اور اکاؤنٹ پہلے سے چل رہا ہو تو ccam آپ کو خبردار کرتا ہے اور پوچھتا ہے کہ جاری رکھنا ہے یا نہیں۔

## جب کچھ خراب ہو جائے

```sh
ccam doctor
ccam doctor --fix
```

اگر کوئی شیئر شدہ راستہ عام فائل بن گیا ہو، مثلاً جب آپ نے ہاتھ سے کوئی بیک اپ بحال کیا ہو، تو ccam، Claude Code شروع کرنے سے پہلے رک جاتا ہے اور `ccam doctor --fix` کی طرف اشارہ کرتا ہے، جو اسے دوبارہ گروپ سے لنک کر دیتا ہے: اگر گروپ کے پاس کوئی کاپی نہ ہو تو یہ فائل گروپ کی کاپی بن جاتی ہے، ورنہ گروپ اپنی کاپی رکھتا ہے اور آپ کی فائل بیک اپ میں چلی جاتی ہے، جس کا نام `--fix` بتاتا ہے۔ گروپس کی جو تبدیلی ادھوری رک گئی ہو اسے بھی `ccam doctor --fix` مکمل کرتا ہے۔
