ہر اکاؤنٹ اپنا لاگ اِن الگ رکھتا ہے۔ باقی سب کچھ آئٹم بہ آئٹم شیئر کیا جا سکتا ہے: ccam اکاؤنٹ کی فائل یا فولڈر کو ایک شیئر شدہ گروپ فولڈر سے لنک کرتا ہے، اس لیے ایک اکاؤنٹ میں کی گئی تبدیلی اس گروپ کے تمام اکاؤنٹس میں نظر آتی ہے۔

## کیا کچھ شیئر کیا جا سکتا ہے

| آئٹم | آپشن | کیا شیئر ہوتا ہے |
| --- | --- | --- |
| MCP سرورز | `--mcp` | گروپ کی `mcp.json`، جو شروع ہوتے وقت Claude Code کو دی جاتی ہے |
| سیٹنگز | `--settings` | `settings.json`: اجازتیں، ہُکس، ماڈل، اسٹیٹس لائن |
| گلوبل میموری | `--memory` | `CLAUDE.md` |
| ایکسٹینشنز | `--extensions` | `agents/`، `commands/`، `skills/`، `plugins/`، `output-styles/`، `rules/` |
| گفتگو کی ہسٹری | `--history` | `projects/` اور `history.jsonl` |

نئے اکاؤنٹس گفتگو کی ہسٹری کے سوا سب کچھ شیئر کرتے ہیں۔

لاگ اِن کی فائلیں `.credentials.json` اور `.claude.json` کبھی شیئر نہیں ہوتیں۔ ccam صرف ایک طے شدہ فہرست میں موجود راستوں کو لنک کرتا ہے، اور یہ دونوں فائلیں اس فہرست میں نہیں ہیں۔

## گروپس

`on` کا مطلب `default` گروپ ہے۔ آپ کوئی نام بھی دے سکتے ہیں، تاکہ کوئی آئٹم صرف کچھ اکاؤنٹس کے درمیان شیئر ہو:

```sh
ccam share work --history team
ccam share side --history team
```

اب `work` اور `side` آپس میں گفتگو شیئر کرتے ہیں، لیکن آپ کے دوسرے اکاؤنٹس کے ساتھ نہیں۔

## شیئرنگ آن کرنا

جب کوئی اکاؤنٹ کسی آئٹم کو شیئر کرنا شروع کرتا ہے تو ccam:

1. ہر اس فائل کا منصوبہ پرنٹ کرتا ہے جسے وہ منتقل، کاپی یا لنک کرے گا، اور شروع کرنے سے پہلے آپ سے پوچھتا ہے؛
2. اگر گروپ ابھی خالی ہے تو اکاؤنٹ کی فائلیں گروپ فولڈر میں منتقل کرتا ہے، ورنہ وہ فائلیں شامل کرتا ہے جو گروپ میں ابھی موجود نہیں؛
3. جب ایک ہی فائل دونوں جگہ مختلف ہو تو پوچھتا ہے کہ گروپ کا ورژن رکھا جائے، آپ کا ورژن استعمال کیا جائے، یا JSON کو ملا دیا جائے؛
4. آپ کی اصل فائل اکاؤنٹ فولڈر کے اندر `.ccam-backup/<time>/` میں محفوظ رکھتا ہے؛
5. اصل فائل کی جگہ گروپ کا لنک لگا دیتا ہے۔

گفتگو کی فائلوں کے نام ان کے سیشن ID پر رکھے جاتے ہیں، اس لیے کئی اکاؤنٹس کی ہسٹریاں بغیر کسی ٹکراؤ کے یکجا ہو جاتی ہیں۔

## شیئرنگ بند کرنا

```sh
ccam share work --history off
```

لنک ہٹا دیا جاتا ہے اور اکاؤنٹ کو گروپ کے موجودہ مواد کی اپنی کاپی مل جاتی ہے۔ اس کے بجائے خالی حالت سے شروع کرنے کے لیے `--fresh` شامل کریں۔ گروپ اپنا مواد دوسرے اکاؤنٹس کے لیے برقرار رکھتا ہے۔

## MCP سرورز

Claude Code، MCP سرورز کو لاگ اِن کے ساتھ `.claude.json` میں رکھتا ہے، اس لیے یہ فائل شیئر نہیں کی جا سکتی۔ ccam شیئر کیے گئے سرورز کو گروپ کی `mcp.json` میں رکھتا ہے اور Claude Code کو `--mcp-config=<group>/mcp.json` کے ساتھ شروع کرتا ہے۔ آپ کے اپنے `--mcp-config` آپشنز بھی اس کے اوپر لاگو رہتے ہیں۔

```sh
ccam mcp add fs -- npx -y @modelcontextprotocol/server-filesystem ~/code
ccam mcp list
```

جو سرور آپ کسی سیشن کے اندر `claude mcp add` سے شامل کرتے ہیں وہ صرف اسی اکاؤنٹ کے لیے محفوظ ہوتا ہے۔ اگلی بار جب آپ وہ اکاؤنٹ شروع کریں گے تو ccam اس سرور کا نام اور وہ کمانڈ بتائے گا جو اسے گروپ میں منتقل کرتی ہے:

```sh
ccam mcp import work gh
```

جو MCP سرورز OAuth سے سائن اِن کرتے ہیں وہ اپنے ٹوکنز اکاؤنٹ کے لاگ اِن کے ساتھ محفوظ کرتے ہیں، اس لیے ہر اکاؤنٹ میں انہیں ایک بار اجازت دیں۔

اگر آپ چاہتے ہیں کہ سرورز `claude mcp list` اور `/mcp` میں عام یوزر سرورز کے طور پر نظر آئیں تو `~/.config/ccam/config.toml` میں `mcp_strategy = "sync"` سیٹ کریں۔ اس صورت میں ccam شروع کرنے سے پہلے انہیں ہر اکاؤنٹ کی `.claude.json` میں لکھ دیتا ہے، Claude Code کے اپنے فائل لاک کے تحت اور بیک اپ کے ساتھ۔

## ایک ہی فولڈر میں دو اکاؤنٹس

جو اکاؤنٹس گفتگو کی ہسٹری شیئر کرتے ہیں وہ ایک ہی فائلوں میں لکھتے ہیں۔ اگر آپ کسی ایسے فولڈر میں دوسرا Claude Code شروع کریں جہاں اسی گروپ کا کوئی اور اکاؤنٹ پہلے سے چل رہا ہو تو ccam آپ کو خبردار کرتا ہے اور پوچھتا ہے کہ جاری رکھنا ہے یا نہیں۔

## جب کچھ خراب ہو جائے

```sh
ccam doctor
ccam doctor --fix
```

اگر کوئی شیئر شدہ راستہ عام فائل بن گیا ہو، مثلاً جب آپ نے ہاتھ سے کوئی بیک اپ بحال کیا ہو، تو ccam، Claude Code شروع کرنے سے پہلے رک جاتا ہے اور `ccam doctor --fix` کی طرف اشارہ کرتا ہے، جو اس فائل کو گروپ میں ضم کر دیتا ہے اور بیک اپ رکھتا ہے۔
