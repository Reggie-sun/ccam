हर अकाउंट का अपना लॉगिन रहता है। बाक़ी सब कुछ **ग्रुप** के ज़रिए साझा किया जा सकता है: एक ग्रुप उन आइटम के नाम बताता है जिन्हें वह साझा करता है और उसमें शामिल अकाउंट्स के भी, और ccam उन अकाउंट्स की फ़ाइलों को ग्रुप के फ़ोल्डर से लिंक करता है, इसलिए एक अकाउंट में किया गया बदलाव उन सभी में दिखता है।

## क्या साझा किया जा सकता है

| आइटम | क्या साझा होता है |
| --- | --- |
| `mcp` | MCP सर्वर: ग्रुप की `mcp.json`, जो शुरू होते समय Claude Code को दी जाती है |
| `settings` | `settings.json`: अनुमतियाँ, hooks, मॉडल, स्टेटस लाइन |
| `memory` | ग्लोबल `CLAUDE.md` |
| `extensions` | `agents/`, `commands/`, `skills/`, `plugins/`, `output-styles/`, `rules/` |
| `history` | बातचीत का इतिहास: `projects/` और `history.jsonl` |

आपका पहला अकाउंट `default` ग्रुप बनाता है, जो बातचीत के इतिहास को छोड़कर सब कुछ साझा करता है, और बाद के अकाउंट उसमें शामिल होते हैं।

लॉगिन फ़ाइलें `.credentials.json` और `.claude.json` कभी साझा नहीं होतीं। ccam केवल एक तय सूची के पाथ लिंक करता है, और ये दोनों उस सूची में नहीं हैं।

यह पेज रोज़मर्रा के काम बताता है। हर विकल्प का विवरण सुविधा पेजों पर है: [ग्रुप के साथ साझा करना](/features/share), [साझा MCP सर्वर](/features/mcp) और [मौजूदा सेटअप कॉपी करना](/features/migrate)।

## ग्रुप

```sh
ccam group                                   # the groups, what they share, their accounts
ccam group set default --add history         # every account in default shares history
ccam group add team --items history --members work,side
```

एक अकाउंट कई ग्रुप में हो सकता है, लेकिन हर आइटम केवल एक ही ग्रुप से आता है। इसलिए `work` और `side` के बीच इतिहास साझा करने के लिए, लेकिन आपके दूसरे अकाउंट्स के साथ नहीं, इतिहास को `default` से बाहर रखें और दोनों को उनका अपना ग्रुप दें, जैसा ऊपर है। `ccam share work` दिखाता है कि कोई अकाउंट क्या साझा करता है और किस ग्रुप के ज़रिए। [डैशबोर्ड](/features/dashboard) अपने Groups टैब पर यही करता है।

## जब कोई अकाउंट साझा करना शुरू करता है

जब कोई अकाउंट किसी आइटम को साझा करना शुरू करता है (वह किसी ग्रुप में शामिल होता है, या उसका ग्रुप वह आइटम जोड़ता है), तो ccam:

1. हर अकाउंट के लिए उस हर फ़ाइल की योजना प्रिंट करता है जिसे वह move, copy या link करेगा, और शुरू करने से पहले पूछता है;
2. अगर ग्रुप अभी ख़ाली है तो अकाउंट की फ़ाइलें ग्रुप फ़ोल्डर में move करता है, वरना वे फ़ाइलें जोड़ता है जो ग्रुप में अभी नहीं हैं;
3. जब एक ही फ़ाइल अलग हो, तो पूछता है कि ग्रुप का वर्ज़न रखें, आपका इस्तेमाल करें, या JSON को merge करें;
4. आपकी मूल फ़ाइल को अकाउंट फ़ोल्डर के अंदर `.ccam-backup/<time>/` में रखता है;
5. मूल फ़ाइल की जगह ग्रुप का लिंक लगा देता है।

बातचीत की फ़ाइलों के नाम उनके session ID पर होते हैं, इसलिए कई अकाउंट्स के इतिहास बिना टकराव के एक साथ जुड़ जाते हैं।

जब Claude Code उस अकाउंट के रूप में चल रहा हो, तब ccam उस अकाउंट को नहीं बदलता, चाहे वह किसी भी तरह शुरू हुआ हो (background sessions समेत), क्योंकि session उन फ़ाइलों में लिखता रहता है जिन्हें move किया जा रहा है। पहले उसे बंद करें। ccam सेव करने से ठीक पहले फिर से जाँचता है, इसलिए जब ccam आपके जवाब का इंतज़ार कर रहा था, उस दौरान शुरू हुआ session भी पकड़ में आ जाता है।

## जब कोई अकाउंट साझा करना बंद करता है

```sh
ccam group leave team work                   # work leaves the group
ccam group set default --remove history      # nobody in default shares history any more
```

लिंक हट जाता है और अकाउंट को ग्रुप की मौजूदा सामग्री की अपनी कॉपी मिल जाती है; ग्रुप के MCP सर्वर उसकी अपनी `.claude.json` में, उसके अपने सर्वरों के बगल में चले जाते हैं। इसकी बजाय ख़ाली शुरुआत करने के लिए `--fresh` जोड़ें; तब योजना उन MCP सर्वरों की सूची देती है जो लोड होना बंद कर देते हैं। `~/.claude` जैसा import किया गया फ़ोल्डर हमेशा एक कॉपी रखता है। ग्रुप अपनी सामग्री दूसरे अकाउंट्स के लिए रखे रहता है।

## मौजूदा सेटअप कॉपी करें

अगर आपने ccam से पहले Claude Code इस्तेमाल किया है, तो आपकी सेटिंग्स `~/.claude` में हैं। `ccam migrate` उन्हें एक ग्रुप में कॉपी करता है, ताकि उन आइटम को साझा करने वाले हर अकाउंट को वे मिल जाएँ:

```sh
ccam migrate
```

टर्मिनल पर ccam पहले आइटम की एक चेकलिस्ट दिखाता है। बातचीत के इतिहास को छोड़कर सब कुछ चुना हुआ होता है; किसी आइटम को बदलने के लिए Space और योजना देखने के लिए Enter दबाएँ। जिन आइटम के लिए फ़ोल्डर में कुछ नहीं है, उन पर `not found` लिखा होता है।

यह क्या कॉपी करता है:

- `settings.json` और ग्लोबल `CLAUDE.md`;
- एक्सटेंशन `agents/`, `commands/`, `skills/`, `plugins/`, `output-styles/` और `rules/`;
- आपके user MCP सर्वर, यानी `~/.claude.json` की `mcpServers` एंट्री, ग्रुप की `mcp.json` में;
- बातचीत का इतिहास (`projects/` और `history.jsonl`), लेकिन केवल तब जब आप `--history` जोड़ें।

स्रोत फ़ोल्डर को केवल पढ़ा जाता है: उसमें कुछ भी move, link या बदला नहीं जाता, और सादा `claude` पहले की तरह काम करता रहता है। लॉगिन फ़ाइलें `.credentials.json` और `.claude.json` कभी ग्रुप में कॉपी नहीं होतीं।

जो MCP सर्वर OAuth से साइन इन करते हैं, वे अपने tokens सर्वर सूची में नहीं, लॉगिन में रखते हैं। ccam ये साइन-इन कॉपी नहीं करता: कॉपी किए गए साइन-इन में वही refresh token होता है, और पहला renewal उस सर्वर से हर दूसरे धारक को लॉग आउट कर देता है, `~/.claude` को भी। योजना और सारांश उन अकाउंट्स के नाम बताते हैं जिन्हें `/mcp` से उन सर्वरों में ख़ुद साइन इन करना होगा।

कुछ भी कॉपी करने से पहले ccam योजना प्रिंट करता है और पूछता है:

```console
$ ccam migrate
Copy from /home/me/.claude into group default (/home/me/.local/share/ccam/groups/default):
  mcp         ~/.claude.json  new: context7, fs
  settings    settings.json   new: 80 B
  memory      CLAUDE.md       new: 31 B
  extensions  agents/         add 1 file the group lacks (17 B)
              commands/       add 1 file the group lacks (15 B)
              skills/         add 1 file the group lacks (32 B)
              not found, skipped: plugins/, output-styles/, rules/
  Conversation history (projects/, history.jsonl) is not included; add --history to copy it.
Copy these into group default? [y/N] y
✓ Copied into group default: 2 MCP servers, settings.json, CLAUDE.md, agents/, commands/, skills/
Group default: personal
To share them:
  ccam group join default work
```

आख़िर में ccam ग्रुप के अकाउंट्स की सूची दिखाता है। अगर ग्रुप अभी आइटम में से कोई साझा नहीं करता, या कुछ अकाउंट उसमें नहीं हैं, तो यह वे `ccam group` कमांड प्रिंट करता है जो इसे बदलती हैं।

जब ग्रुप में किसी फ़ाइल की अलग कॉपी पहले से हो, तो ccam वैसे ही पूछता है जैसे साझा करना चालू करते समय: ग्रुप की कॉपी रखें या अपनी इस्तेमाल करें। `settings.json` और दूसरी JSON फ़ाइलें merge भी की जा सकती हैं, और `history.jsonl` लाइन-दर-लाइन। ग्रुप की पिछली कॉपियाँ ग्रुप फ़ोल्डर के अंदर `.ccam-backup/<time>/` में सहेजी जाती हैं।

| विकल्प | असर |
| --- | --- |
| `--settings`, `--memory`, `--extensions`, `--mcp`, `--history` | केवल नाम दिए गए आइटम कॉपी करें, चेकलिस्ट के बिना। टर्मिनल के बाहर, किसी आइटम flag के बिना, ccam बातचीत के इतिहास को छोड़कर सब कुछ कॉपी करता है। |
| `-g`, `--group <group>` | `default` की बजाय इस ग्रुप में कॉपी करें |
| `-y`, `--yes` | बिना पूछे कॉपी करें; कोई फ़ाइल अलग हो तो ग्रुप की कॉपी रखें |

कुछ भी कॉपी किए बिना योजना देखने के लिए कमांड से पहले `--dry-run` लगाएँ, जैसे `ccam --dry-run migrate`। किसी दूसरे फ़ोल्डर से कॉपी करने के लिए उसका नाम दें: `ccam migrate ~/.claude-work --group work`।

## MCP सर्वर

Claude Code MCP सर्वर `.claude.json` में, लॉगिन के साथ ही रखता है, इसलिए यह फ़ाइल साझा नहीं की जा सकती। ccam साझा सर्वर ग्रुप की `mcp.json` में रखता है और Claude Code को `--mcp-config=<group>/mcp.json` के साथ शुरू करता है। आपके अपने `--mcp-config` विकल्प इसके ऊपर लागू होते रहते हैं।

```sh
ccam mcp add fs -- npx -y @modelcontextprotocol/server-filesystem ~/code
ccam mcp list
```

Session के अंदर `claude mcp add` से जोड़ा गया सर्वर केवल उसी अकाउंट के लिए सेव होता है, और उसी फ़ोल्डर के लिए जिसमें आप थे (Claude Code का local scope; `-s user` उसे हर फ़ोल्डर में अकाउंट के लिए उपलब्ध बना देता है)। अगली बार जब आप वह अकाउंट शुरू करते हैं, तो ccam उस सर्वर का नाम, उसके फ़ोल्डर के साथ, बताता है और वह कमांड भी जो उसे ग्रुप में move करती है:

```sh
ccam mcp import work gh
```

अगर ग्रुप में उसी नाम का कोई अलग सर्वर पहले से है, तो ccam उसे छोड़ देता है और यह बताता है। `--force` ग्रुप के सर्वर को बदल देता है और पुरानी `mcp.json` को ग्रुप के `.ccam-backup/` फ़ोल्डर में रखता है।

जो MCP सर्वर OAuth से साइन इन करते हैं, वे अपने tokens अकाउंट के लॉगिन के साथ रखते हैं, इसलिए हर अकाउंट में `/mcp` से उनमें एक बार साइन इन करें। `ccam ext` और `ccam doctor` उन सर्वरों के नाम बताते हैं जिनमें कोई अकाउंट साइन इन नहीं है जबकि कोई दूसरा अकाउंट है।

अगर आप चाहते हैं कि सर्वर `claude mcp list` और `/mcp` में सामान्य user सर्वर की तरह दिखें, तो `~/.config/ccam/config.toml` में सबसे ऊपर, पहले `[[group]]`, `[[profile]]` या `[[folder]]` से ऊपर, `mcp_strategy = "sync"` सेट करें। तब ccam शुरू करने से पहले उन्हें हर अकाउंट की `.claude.json` में लिखता है, Claude Code के अपने file lock के तहत और बैकअप के साथ। अगर अकाउंट का अपना कोई सर्वर किसी ग्रुप सर्वर के नाम वाला है, तो ccam अकाउंट का सर्वर रखता है और यह बताता है।

## एक ही फ़ोल्डर में दो अकाउंट

जो अकाउंट बातचीत का इतिहास साझा करते हैं, वे एक ही फ़ाइलों में लिखते हैं। अगर आप किसी ऐसे फ़ोल्डर में दूसरा Claude Code session शुरू करते हैं जहाँ उसी ग्रुप का कोई दूसरा अकाउंट पहले से चल रहा है, तो ccam आपको चेतावनी देता है और पूछता है कि जारी रखना है या नहीं।

## जब कुछ टूट जाए

```sh
ccam doctor
ccam doctor --fix
```

अगर कोई साझा पाथ सामान्य फ़ाइल बन गया है, उदाहरण के लिए जब आपने हाथ से कोई बैकअप restore किया हो, तो ccam Claude Code शुरू करने से पहले रुक जाता है और `ccam doctor --fix` की ओर इशारा करता है। यह fix पाथ को फिर से ग्रुप से लिंक करता है: जब ग्रुप के पास कोई कॉपी न हो तो फ़ाइल ग्रुप की कॉपी बन जाती है; वरना ग्रुप अपनी कॉपी रखता है, और आपकी फ़ाइल एक बैकअप में चली जाती है जिसका नाम `--fix` बताता है। बीच में रुका ग्रुप का बदलाव भी `ccam doctor --fix` पूरा करता है।
