`CLAUDE_CONFIG_DIR` указывает Claude Code, какую папку использовать вместо `~/.claude`. Всё, что относится к аккаунту, хранится там: данные входа, настройки, MCP-серверы, плагины и история разговоров. Если указывать разные папки, получаются отдельные аккаунты.

```sh
CLAUDE_CONFIG_DIR=~/.claude-work claude
```

## Поддерживается ли CLAUDE_CONFIG_DIR официально?

Да. Claude Code перечисляет её среди своих [переменных окружения](https://code.claude.com/docs/en/env-vars) как способ переопределить папку конфигурации, «полезный для одновременной работы нескольких аккаунтов», а его [руководство по аутентификации](https://code.claude.com/docs/en/authentication#log-in-with-multiple-accounts) использует её для входа в несколько аккаунтов. Задать её можно в оболочке или в пользовательских настройках, но не в настройках проекта.

## Что находится в папке?

Проверено с Claude Code 2.1.309:

| Путь | Содержимое | Можно сделать общим |
| --- | --- | --- |
| `.credentials.json` | Токены входа (Linux, Windows), OAuth-токены MCP | Нет |
| `.claude.json` | Данные аккаунта, пользовательские MCP-серверы, состояние по проектам | Нет (MCP-серверы отдельно) |
| `settings.json` | Права доступа, хуки, модель, строка состояния, плагины | Да |
| `CLAUDE.md` | Глобальные инструкции | Да |
| `agents/`, `commands/`, `skills/`, `plugins/` | Расширения | Да |
| `projects/` | Разговоры в виде файлов `.jsonl`, память по проектам | Да |
| `history.jsonl` | История запросов | Да |
| `sessions/`, `shell-snapshots/`, `cache/` и другие | Состояние во время работы | Нет |

## На чём часто спотыкаются?

**Без `CLAUDE_CONFIG_DIR` файл `.claude.json` находится не внутри `~/.claude`.** В этом случае Claude Code хранит его в `~/.claude.json`, рядом с папкой. Если вы начнёте использовать `CLAUDE_CONFIG_DIR=~/.claude`, Claude Code будет искать `~/.claude/.claude.json` и не найдёт ваш аккаунт. `ccam import` решает это, связывая эти два пути. Если в `~/.claude` уже есть собственный `.claude.json`, оставшийся от более раннего запуска с `CLAUDE_CONFIG_DIR=~/.claude`, ccam оставляет оба файла и сообщает об этом, поскольку только вы знаете, какой из них правильный.

**В macOS данные входа хранятся в Связке ключей, а не в папке.** Claude Code сохраняет их под именем `Claude Code-credentials`, к которому, если задан `CLAUDE_CONFIG_DIR`, добавляются `-` и первые 8 шестнадцатеричных цифр SHA-256 пути к папке, для учётной записи, названной в `$USER`. Поэтому разные папки получают разные записи в Связке ключей, а папка, которую переместили или переименовали, теряет свой вход; именно поэтому в macOS `ccam rename` сохраняет имя папки. Если Связка ключей отказывает в записи, Claude Code использует вместо неё `.credentials.json` в папке, как описано в [его документации](https://code.claude.com/docs/en/authentication#credential-management).

**Не всякий вход хранится в папке.** Вход через Claude Console без API-ключа хранится за её пределами, поэтому отдельные папки не разделяют два таких входа. Входы через claude.ai и API-ключи хранятся отдельно для каждой папки.

## Где находится папка в Windows?

По умолчанию это `%USERPROFILE%\.claude`, а данные входа лежат внутри неё в `.credentials.json` или, если Claude Code настроен на его использование, в диспетчере учётных данных Windows под именем, составленным из пути к папке, как в macOS. Для каждого дополнительного аккаунта задайте в `CLAUDE_CONFIG_DIR` другую папку, так же как на Linux и macOS.

## Можно ли сделать файлы общими для папок?

Символические ссылки работают: Claude Code читает и пишет через связанный `settings.json` или папку `projects/` и сохраняет ссылку. Исключение составляют MCP-серверы, потому что они находятся в `.claude.json` вместе с данными входа; передавайте их через `--mcp-config`.

ccam построен именно на этих правилах. Как он связывает папки, описано в разделе [общий доступ](/docs/sharing), а общая картина в [руководстве по нескольким аккаунтам](/guides/multiple-claude-code-accounts).
