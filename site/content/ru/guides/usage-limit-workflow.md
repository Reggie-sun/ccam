Когда аккаунт достигает лимита использования (его часто называют rate limit), есть два варианта: дождаться сброса лимита или прямо сейчас продолжить тот же разговор в другом своём аккаунте. С ccam второй вариант занимает одну команду, `ccam next --auto --continue`.

## Какие лимиты есть у Claude Code?

В планах Pro и Max у Claude Code есть [лимит сеанса на пять часов и недельный лимит](https://support.claude.com/en/articles/11145838-using-claude-code-with-your-pro-or-max-plan). Оба лимита общие с Claude в браузере и в приложениях, и использование засчитывается в оба одновременно. Когда один из них исчерпан, Claude Code [показывает сообщение](https://code.claude.com/docs/en/errors#youve-hit-your-session-limit) вроде «You've hit your session limit · resets 3:45pm». Смена модели не поможет, потому что лимиты действуют на все модели.

## Вариант 1: дождаться сброса

Если аккаунт один, подождите. Последние версии Claude Code [ждут в открытом сеансе](https://code.claude.com/docs/en/interactive-mode#wait-for-a-usage-limit-to-reset) и сами продолжают задачу после сброса лимита. `/usage` внутри Claude Code показывает, какую часть лимитов вашего плана вы уже израсходовали.

## Вариант 2: сразу продолжить в другом аккаунте

Если у вас есть второй аккаунт, можно сразу продолжить тот же разговор. Настройте всё один раз:

```sh
curl -fsSL https://ccam.dev/install.sh | sh
ccam add personal
ccam add work
ccam group set default --add history
ccam statusline install
```

Теперь во время работы строка состояния показывает аккаунт и его использование за 5 часов, так что лимит не станет неожиданностью.

Когда лимит достигнут, выйдите из Claude Code (`/exit`), затем выполните:

```sh
ccam usage
```

```console
 1 personal  just now
   5-hour   ████████████████████ 100%  resets in 22m
   Weekly   ██████████████░░░░░░  68%  resets in 1d 9h
 2 work      just now
   5-hour   ██░░░░░░░░░░░░░░░░░░   8%  resets in 4h 12m
   Weekly   ████░░░░░░░░░░░░░░░░  19%  resets in 5d 2h
→ Most headroom: work   (open it with ccam next --auto)
```

Откройте разговор в аккаунте с наибольшим запасом:

```sh
ccam next --auto --continue
```

Claude Code запустится как `work` с последним разговором текущей папки, включая всё, что было сказано до этого. Общая история (`ccam group set default --add history` выше) сохраняет его одним разговором; без неё Claude Code копирует разговор в `work`, и ccam сообщает, сколько токенов этот первый ответ прочитает заново.

С [плагином ccam](/docs/install#claude-code-plugin) в Claude Code сеанс, остановившийся на лимите, показывает уведомление и записывает заполненное окно, поэтому `ccam next --auto` не выберет этот аккаунт снова до его сброса, а `/ccam:switch` (или `/ccam:switch work`) записывает разговор для `ccam next --continue`, так что ничего не нужно угадывать.

**Места в тарифах Team и Enterprise.** При автоматическом выборе (`ccam next`, `--fallback`, `ccam pick`, клавиша `n` на панели, а также [`auto_switch`](/features/next#auto-switch), если вы его включите) ccam переключается и между местами одной и той же организации Claude Team или Enterprise. В справочном центре Anthropic ([тарифы Team](https://support.claude.com/en/articles/12004354-purchase-and-manage-seats-on-team-plans#h_b8a7d07129); аналогично для [тарифов Enterprise](https://support.claude.com/en/articles/13393991-purchase-and-manage-seats-on-enterprise-plans#h_fa6b9cade0)) сказано: «Each seat on a Team plan is assigned to one named individual, and only that person may use it» (каждое место в тарифе Team закреплено за одним конкретным человеком, и пользоваться им может только этот человек) и «Users can't route their work through another user's account to use that user's remaining usage» (пользователи не могут направлять свою работу через аккаунт другого пользователя, чтобы расходовать оставшийся лимит этого пользователя). Поэтому использование автоматического выбора между местами может нарушать условия Anthropic. Пользоваться ли им в этом случае, решать вам: прежде чем на него полагаться, уточните это у своей организации и у Anthropic. О личных тарифах (Pro, Max) см. [примечание об условиях в FAQ](/docs/faq#am-i-allowed-to-use-several-claude-code-accounts).

## Переключает ли ccam аккаунты автоматически?

Только если вы это включите. По умолчанию, пока вы работаете, ccam не запущен: он запускает Claude Code и заменяет себя им, поэтому когда переключаться, решаете вы, а `ccam next --auto` выбирает аккаунт с наименьшим использованием за 5 часов, пропускает аккаунты, у которых 100% или не выполнен вход, и остаётся в пределах одной организации Team или Enterprise либо среди личных тарифов. С `relay = true` в `config.toml` ccam вместо этого ждёт рядом с сеансом, поэтому `/ccam:switch` продолжает работу сам, сохраняя параметры сеанса, режим разрешений и уровень усилий. С `auto_switch = true` (Linux и macOS; экспериментальная функция) ccam и переключается сам: когда Claude Code останавливает сеанс на его лимите, а у другого такого же аккаунта есть запас, ccam завершает сеанс и продолжает разговор там ([условия и издержки](/features/next#auto-switch)). Некоторые другие инструменты вместо этого подменяют вход в работающем сеансе; в чём разница, объясняет статья [ccam и другие переключатели аккаунтов](/compare/account-switchers).

## Что стоит учитывать

- Выполняйте `ccam next --continue` в той же папке, где работали; разговоры хранятся по папкам проектов.
- Не запускайте два аккаунта на одном и том же разговоре одновременно. ccam предупредит, если вы попытаетесь.
- Без общей истории разговор копируется в другой аккаунт, и две копии развиваются независимо; контрольные точки, из которых `/rewind` восстанавливает код, остаются у первого аккаунта.
- Первое сообщение в новом аккаунте может израсходовать больше лимита, чем обычно, потому что у этого аккаунта разговор ещё не закэширован. `ccam next --continue --brief` вместо этого начинает его с краткой сводки.
- Можно ли так переключаться между аккаунтами, зависит от условий каждого аккаунта.

Все параметры `ccam usage` и `ccam next` описаны в разделе [лимиты использования](/docs/usage-limits).
