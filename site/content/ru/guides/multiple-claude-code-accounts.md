Дайте каждому аккаунту собственную папку конфигурации. Claude Code берёт путь к папке из переменной окружения `CLAUDE_CONFIG_DIR`, а в каждой папке хранятся свои данные входа, настройки и история, поэтому каждый аккаунт остаётся авторизованным и их можно запускать одновременно. Это можно настроить вручную через псевдоним оболочки или поручить ccam.

## Как настроить это вручную?

Этот способ [описан в документации Claude Code](https://code.claude.com/docs/en/authentication#log-in-with-multiple-accounts). Добавьте в `~/.bashrc` или `~/.zshrc` по строке на каждый дополнительный аккаунт:

```sh
alias claude-work='CLAUDE_CONFIG_DIR=~/.claude-work claude'
```

Откройте новый терминал и выполните `claude-work`. Claude Code попросит войти, потому что папка новая. После этого `claude` будет вашим первым аккаунтом, а `claude-work` вторым. Для каждого аккаунта добавьте свой псевдоним со своей папкой.

В Windows без WSL то же самое делает функция PowerShell в вашем профиле (`notepad $PROFILE`):

```powershell
function claude-work { $env:CLAUDE_CONFIG_DIR = "$HOME\.claude-work"; try { claude @args } finally { Remove-Item Env:CLAUDE_CONFIG_DIR } }
```

## Чего не хватает при подходе с псевдонимами?

Для двух аккаунтов он работает хорошо. Что нужно знать:

- Каждая папка начинается пустой: ни настроек, ни `CLAUDE.md`, ни MCP-серверов, ни агентов или навыков. Всё нужное вы копируете или связываете ссылками и сами следите, чтобы копии не расходились.
- Псевдонимы существуют только в интерактивных оболочках. Скрипты, Makefile и другие программы их не видят.
- MCP-серверы хранятся в `.claude.json` рядом с данными входа, поэтому их нельзя просто связать ссылкой между папками.
- Разговоры остаются в том аккаунте, где начались, поэтому продолжить разговор в другом аккаунте нельзя.
- Нет ничего, что показывало бы использование всех аккаунтов сразу.

## Можно ли вместо этого переключать аккаунты через /login?

Да, если переключаться приходится лишь изредка. Команда `/login` внутри Claude Code [переключает аккаунт](https://code.claude.com/docs/en/quickstart) той папки, в которой вы работаете. Вход выполнен только в один аккаунт за раз, поэтому при каждом переключении приходится входить заново, а запустить два аккаунта параллельно нельзя. Отдельные папки снимают оба ограничения.

## Как настроить это с ccam?

ccam автоматизирует ту же идею и добавляет недостающее:

```sh
curl -fsSL https://ccam.dev/install.sh | sh
ccam add personal
ccam add work --shortcut ccwork
```

Теперь `ccam personal` и `ccam work` запускают два аккаунта, как и `ccwork`, короткая команда, которую вы задали рабочему аккаунту. Это настоящие программы, а не псевдонимы, поэтому они работают и в скриптах. Запустите `ccam` без аргументов, чтобы выбрать аккаунт из списка, или `ccam use work`, чтобы сделать аккаунт основным.

Настройки, `CLAUDE.md`, MCP-серверы и расширения общие с самого начала, а если включить общую историю разговоров, можно продолжить разговор в другом аккаунте командой `ccam next --continue`. `ccam usage` показывает использование за 5 часов и за неделю для всех аккаунтов сразу.

Если вы уже пользуетесь `~/.claude`, выполните `ccam import` вместо того, чтобы добавлять этот аккаунт заново, или `ccam migrate`, чтобы скопировать его настройки, MCP-серверы и расширения в общие настройки.

## Как узнать, какой аккаунт запущен?

Внутри Claude Code команда `/status` показывает аккаунт, в который выполнен вход. С ccam один раз выполните `ccam statusline install`, и строка состояния будет постоянно показывать имя аккаунта и его использование, например `[work] · Opus · 5h 24% · 7d 41%`.

## Работает ли это в Windows и WSL?

Claude Code работает [нативно в Windows и внутри WSL](https://code.claude.com/docs/en/setup). `CLAUDE_CONFIG_DIR` действует в обоих случаях, поэтому в Windows без WSL достаточно псевдонима или функции PowerShell, описанных выше. ccam тоже работает в Windows нативно: установите его в PowerShell командой `irm https://ccam.dev/install.ps1 | iex` или внутри WSL командой для Linux. Короткие команды становятся `ccwork.exe`, а для общего доступа к файлам, например `settings.json`, нужен режим разработчика ([Установка ccam](/docs/install)).

## Устранение неполадок

**Claude Code каждый раз просит войти.** При первом запуске в новой папке вход нужен всегда. Если Claude Code продолжает просить, срок действия входа истёк или данные входа удалены: выполните `ccam login work` (или один раз запустите псевдоним и войдите).

**MCP-сервер виден только в одном аккаунте.** Серверы, добавленные внутри сеанса через `claude mcp add`, принадлежат этому аккаунту. Чтобы сервер появился во всех аккаунтах, выполните `ccam mcp import work <server>`.

**Настройки в аккаунтах различаются.** `ccam share work` выводит, что у аккаунта общее и через какую группу; `ccam group join default work` делает так, чтобы он делил то же, что делит `default`, предварительно показав, что изменится. `ccam doctor --fix` чинит сломанные ссылки и сохраняет резервную копию каждого файла, который меняет.

**Два аккаунта открывают один и тот же разговор.** Не работайте с одним разговором в двух аккаунтах одновременно. ccam предупредит, если вы попытаетесь.

## Что выбрать?

Для двух аккаунтов, когда ничего общего не нужно, достаточно псевдонима. Если нужны общие настройки и MCP-серверы, больше аккаунтов, использование всех аккаунтов на одном экране или продолжение разговоров, ccam избавит от ручного учёта. В [сравнении с псевдонимами](/compare/aliases) различия приведены рядом, а в статье [ccam и другие переключатели аккаунтов](/compare/account-switchers) рассмотрены инструменты, которые вместо этого подменяют один вход.

Можно ли использовать несколько аккаунтов, зависит от условий каждого аккаунта. Проверьте их заранее.
