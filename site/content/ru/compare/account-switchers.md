Инструменты для переключения аккаунтов Claude Code используют один из двух подходов. Большинство подменяют данные входа внутри единственной папки `~/.claude`, поэтому одновременно активен только один аккаунт. Другие, в том числе ccam, дают каждому аккаунту собственную папку через `CLAUDE_CONFIG_DIR`, поэтому все аккаунты остаются авторизованными и несколько из них могут работать одновременно. ccam добавляет к этому общие настройки и MCP-серверы и умеет продолжить разговор в папке другого аккаунта.

## Подменять один вход или завести отдельные папки?

**При подмене входа** остаётся один набор настроек, MCP-серверов и истории, потому что папка всего одна. Переключение происходит быстро, и работающий сеанс может подхватить новый вход. Но активен только один аккаунт за раз, сразу для всех терминалов и редакторов.

Чтобы подменить вход, инструмент хранит копию данных входа каждого другого аккаунта и записывает её на место. Обновляя вход, Claude Code заменяет в нём токен обновления, поэтому каждую сохранённую копию приходится согласовывать с работающими сеансами. Аккаунты, которые после переключения оказываются разлогинены или снова требуют `/login`, — одна из проблем, которые эти проекты исправляют чаще всего.

**Отдельные папки** — это способ, [описанный в документации Claude Code](https://code.claude.com/docs/en/authentication#log-in-with-multiple-accounts). Каждый аккаунт остаётся авторизованным, и можно запустить рабочий и личный сеансы рядом. Данные входа каждого аккаунта остаются в его папке, где Claude Code обновляет их как обычно. Цена в том, что у каждой папки изначально свои настройки, MCP-серверы и история, если только инструмент не сделает их общими.

## Сравнение инструментов

Данные взяты из документации и исходного кода каждого проекта 20 октября 2026 года (clausona: v0.12.0-beta). «Не описано» значит, что проект об этом не сообщает, а не что функции нет.

| --- | --- | --- | --- | --- | --- |
| ccam | Отдельные папки | Да | Да, `ccam usage` | Уведомление в сессии; `ccam next --auto --continue` или `/ccam:switch` переносит разговор в аккаунт с наибольшим запасом, с общей историей или без неё, а при включённом `auto_switch` (Linux, macOS) сессия переходит туда сама; `ccam --fallback` сам перезапускает там задания `-p`, а `ccam pick` распределяет рабочие процессы | Linux, macOS, Windows |

| [clauth](https://github.com/uwuclxdy/clauth) | Подменяет вход; отдельные папки через `clauth start` | Да, через `clauth start` | Да | Переключается по цепочке резервных аккаунтов | Linux, macOS, Windows |

| [Claude Switcher](https://github.com/Symbioose/claude-account-switcher) | Подменяет вход | Нет | Да | Переключение при 100% по желанию | macOS |

ccswap — это форк claude-swap, который также управляет входами в Codex. [claude-account](https://github.com/hamzarehmandeveloper/claude-account), [claude-multiprofile](https://github.com/jmdarre-v/claude-multiprofile) и [claude-code-profiles](https://github.com/quinnjr/claude-code-profiles) тоже дают каждому аккаунту собственную папку. Некоторые из этих инструментов работают и с другими агентами для программирования, например Codex или Gemini.

## Как они устроены

| --- | --- | --- | --- | --- |

| clauth | Rust | clauth остаётся родительским процессом | Да, когда подменяет вход | Весь `~/.claude` или ничего |
| CAAM | Go | Зависит от режима; необязательный демон | Да, в режиме хранилища | Определяется режимом; MCP-серверы копируются при каждом запуске |
| cux | Go | Вокруг `claude` остаётся обёртка | Да | Всё: одна папка |
| CCSwitcher, Claude Switcher | Приложения для macOS (Swift, Python) | Приложение в строке меню | Да | Всё: одна папка |

## Сильные стороны ccam

### Данные входа остаются там, куда их положил Claude Code

ccam никогда не копирует данные входа Claude из одного места в другое. Вход каждого аккаунта остаётся в его собственной папке, а в macOS — в отдельном элементе Связки ключей для этой папки, и обновляет его сам Claude Code. Нет сохранённой копии, которая могла бы разойтись с оригиналом. Существующая папка `~/.claude`, зарегистрированная через `ccam import`, сохраняет элемент Связки ключей, которым пользуется обычный `claude`, поэтому она остаётся авторизованной в обоих случаях.

ccam сам обновляет просроченный токен, только когда вы запускаете `ccam usage --refresh`. Сначала он берёт блокировку и отказывается работать, пока этот аккаунт запущен, как бы ни был запущен Claude Code (в том числе фоновые сеансы и их демон), и пока сам Claude Code обновляет этот вход, поэтому никогда не меняет токен под работающим сеансом.

### По умолчанию между вами и Claude Code ничего не работает

ccam читает один файл, проверяет свои ссылки и заменяет себя на `claude` (`exec`). По умолчанию, пока вы работаете, нет ни процесса ccam, ни обёртки, ни прокси, ни демона: стандартный ввод, сигналы и код выхода принадлежат Claude Code, а его запросы идут напрямую в Anthropic. Windows не умеет заменять процесс, поэтому там ccam запускает Claude Code в той же консоли и ждёт его кода выхода, больше ничего не делая. С `relay = true` или `auto_switch = true` ccam точно так же ждёт рядом с интерактивными сессиями, чтобы перенести разговор в другой аккаунт; запросы Claude Code по-прежнему идут напрямую в Anthropic.

Запуск аккаунта таким способом добавляет около 4 мс, меньше 6 мс на 95-м процентиле, при пиковом потреблении памяти 8 МБ ([`scripts/perf-check.sh`](https://github.com/jhyunwoo/ccam/blob/main/scripts/perf-check.sh) с hyperfine, 300 запусков). На том же ноутбуке один только запуск интерпретатора Python занимает 13 мс, а Node.js — 31 мс, ещё до того, как программа что-то сделает.

### Что делить, решают группы

MCP-серверы, `settings.json`, `CLAUDE.md`, расширения (агенты, команды, навыки, плагины) и история разговоров — это пять отдельных элементов. Группа называет элементы, которые она делит, и входящие в неё аккаунты, поэтому два рабочих аккаунта могут делить историю в группе `work`, личный аккаунт хранит свою, а все три используют одни и те же MCP-серверы через `default`. `ccam group set work --add memory` переносит все аккаунты группы одним планом; [панель](/features/dashboard) делает то же самое флажками и показывает серым элемент, который аккаунт уже получает из другой группы.

- MCP-серверы передаются при запуске через `--mcp-config`, поэтому по умолчанию запуск не трогает `.claude.json` — файл, который Claude Code перезаписывает во время работы. ccam пишет туда только на шагах, которые об этом сообщают, под блокировкой Claude Code и с резервной копией: для Remote Control после вопроса, когда аккаунт выходит из общего доступа к MCP или возвращается в него, и для `ccam mcp import`. `ccam mcp add` добавляет сервер один раз для всей группы.
- Остальные элементы — это ссылки на папку группы, поэтому изменение в одном аккаунте сразу видно в остальных. При запуске ничего не копируется.
- Данные входа, `.claude.json` и состояние работы никогда не становятся общими.

### Каждое изменение сначала показывается и сохраняется в резервной копии

`ccam group` и `ccam migrate` выводят план и спрашивают, прежде чем что-то перемещать. Если файл в аккаунте отличается от файла в группе, выбираете вы: оставить версию группы, взять свою или объединить JSON; внутри папок остаётся копия группы, а план называет отличающиеся файлы. Оригиналы попадают в `.ccam-backup/<time>/`, из удалённого аккаунта выполняется выход, а его папка попадает в папку корзины, а файлы заменяются одним переименованием, поэтому прерванная запись оставляет старый файл. `--dry-run` показывает, что сделали бы запуск, общий доступ, миграция, ярлыки, обновления и исправления. `ccam doctor --fix` чинит сломанные ссылки и права доступа.

### Тот же разговор в следующем аккаунте

`ccam next --auto --continue` одновременно запрашивает использование у всех аккаунтов, открывает тот, где больше всего запаса, и продолжает разговор. С общей историей это тот же разговор; без неё Claude Code копирует его в новый аккаунт (`--resume <file> --fork-session`), и ccam сообщает, сколько токенов первый ответ прочитает заново. Когда лимит останавливает сессию, хук плагина ccam показывает уведомление, а `/ccam:switch` передаёт разговор дальше. По умолчанию когда переключаться, решаете вы. При включённом `auto_switch` (Linux, macOS) ccam сам переносит сессию, но только после того, как Claude Code остановил её на лимите, и только в такой же аккаунт, как тот, который она покидает: другое место той же организации или другой личный тариф ([подробнее](/features/next#auto-switch)). Ничто не следит за вашим использованием в фоне, а автоматический выбор по умолчанию никогда не выводит работу из организации Team или Enterprise и не переносит её в такую организацию, поэтому рабочий разговор никогда случайно не окажется в личном аккаунте. Строка состояния подсказывает эту команду, когда аккаунт доходит до 90%.

Скрипты не могут ждать вас, поэтому `ccam --fallback work -p "…"` переключается за них: когда аккаунт достигает лимита, та же команда запускается снова от имени аккаунта с наибольшим запасом, и выводится только результат завершившегося запуска. Ошибка, не связанная с лимитом использования, передаётся как есть. Для параллельных рабочих процессов `ccam pick` выдаёт каждому свой аккаунт с запасом, и обе команды завершаются с кодом 75, когда запаса нет ни у одного аккаунта.

**Места в тарифах Team и Enterprise.** При автоматическом выборе (`ccam next`, `--fallback`, `ccam pick`, клавиша `n` на панели, а также [`auto_switch`](/features/next#auto-switch), если вы его включите) ccam переключается и между местами одной и той же организации Claude Team или Enterprise. В справочном центре Anthropic ([тарифы Team](https://support.claude.com/en/articles/12004354-purchase-and-manage-seats-on-team-plans#h_b8a7d07129); аналогично для [тарифов Enterprise](https://support.claude.com/en/articles/13393991-purchase-and-manage-seats-on-enterprise-plans#h_fa6b9cade0)) сказано: «Each seat on a Team plan is assigned to one named individual, and only that person may use it» (каждое место в тарифе Team закреплено за одним конкретным человеком, и пользоваться им может только этот человек) и «Users can't route their work through another user's account to use that user's remaining usage» (пользователи не могут направлять свою работу через аккаунт другого пользователя, чтобы расходовать оставшийся лимит этого пользователя). Поэтому использование автоматического выбора между местами может нарушать условия Anthropic. Пользоваться ли им в этом случае, решать вам: прежде чем на него полагаться, уточните это у своей организации и у Anthropic. О личных тарифах (Pro, Max) см. [примечание об условиях в FAQ](/docs/faq#am-i-allowed-to-use-several-claude-code-accounts).

### Нужный аккаунт в каждой папке

`ccam folder work ~/code/company` делает так, что каждый запуск без имени аккаунта внутри этой папки использует `work`, а остальные ваши проекты сохраняют аккаунт по умолчанию. Настройка хранится в том же `config.toml`, который читает каждый запуск, поэтому не стоит времени.

### Один бинарный файл, проверенные загрузки

ccam — статический бинарный файл размером около 10 МБ для Linux, macOS и Windows, которому не нужна отдельно устанавливаемая среда выполнения. Скрипты установки (`install.sh`, `install.ps1`) и `ccam update` проверяют каждую загрузку по контрольным суммам SHA-256 релиза, а ccam никогда не обновляется, не спросив вас. Телеметрии нет: единственные запросы, которые он делает, — это запросы использования ваших аккаунтов к Anthropic, параллельно, с лимитом 3 секунды и кэшем на 60 секунд, запрос панели к GitHub о последнем релизе при её открытии и загрузки, о которых вы попросили. С `usage_source = "claude"` даже эти запросы идут через Claude Code, и ccam не отправляет никаких токенов.

## В чём другие инструменты умеют больше

- claude-swap, clauth, cux, CAAM и CCSwitcher могут сами переключать запущенную интерактивную сессию, когда аккаунт превышает порог использования. ccam переключает запуски `-p` с помощью `--fallback`, а интерактивную сессию переносит сам, только если включён `auto_switch` (Linux, macOS), и только после того, как Claude Code остановил её на лимите; в остальных случаях её переносите вы, с уведомлением на лимите и `/ccam:switch`.
- В Windows без режима разработчика ccam делает общими папки, но не может сделать общими отдельные файлы, например `settings.json` (тогда первый `ccam add` делает общими только MCP-серверы и расширения); claude-swap и CCS в этом случае их копируют.
- CCSwitcher, Claude Switcher и claude-swap показывают использование в строке меню macOS.
- CCS, clausona, CAAM, clauth, ccswap и Claude Switcher также управляют Codex и другими агентами для программирования.
- clausona также включает и выключает расширения для каждого аккаунта (`ccam ext` в ccam только показывает их), подсчитывает локальную стоимость токенов и поставляет плагины Claude Code, которые запускают группы рабочих процессов в tmux и других терминалах.
- CAAM, CCSwitcher и Claude Switcher устанавливаются через Homebrew, а clauth и CAAM подписывают контрольные суммы своих релизов. ccam устанавливается своим скриптом, пакетом `.deb` или через `go install` и проверяет контрольные суммы без подписи.

## Что вам подойдёт?

Выберите инструмент с подменой входа, если вы пользуетесь одним аккаунтом за раз или хотите, чтобы запущенные сессии переключались до лимита или подменой входа. Выберите ccam, если вам нужны аккаунты, работающие рядом, одна общая настройка, тот же разговор в следующем аккаунте и, по умолчанию, ничего лишнего, работающего рядом с Claude Code, на Linux, macOS или Windows. Если ничего общего не нужно, достаточно [обычных псевдонимов оболочки](/compare/aliases).

Можно ли использовать несколько аккаунтов, зависит от условий каждого аккаунта. Проверьте их заранее.
