`ccam usage` показывает для каждого аккаунта, какая часть каждого лимита использована: 5-часового лимита, недельного лимита и собственного недельного лимита каждой модели (например, Fable). `ccam next --auto` открывает аккаунт с наибольшим запасом, а `--continue` переносит текущий разговор.

```console
$ ccam usage
 1 personal  just now
   5-hour   ██████████████░░░░░░  72%  resets in 1h 40m
   Weekly   ████████░░░░░░░░░░░░  41%  resets in 3d 6h
   Fable    ██████████████████░░  88%  resets in 1d 6h
 2 work      just now
   5-hour   ██░░░░░░░░░░░░░░░░░░   8%  resets in 4h 12m
   Weekly   ████░░░░░░░░░░░░░░░░  19%  resets in 5d 2h
   Fable    █░░░░░░░░░░░░░░░░░░░   3%  resets in 5d 2h
 3 side      12m ago (cached)
   5-hour   ████████████████████ 100%  resets in 22m
   Weekly   ██████████████░░░░░░  68%  resets in 1d 9h
   Fable    ████████░░░░░░░░░░░░  40%  resets in 1d 9h
→ Most headroom: work   (open it with ccam next --auto)
```

Для каждого аккаунта выводится строка с давностью его данных, затем по полосе на каждый лимит со временем до сброса: 5-часовое окно, недельное окно для всех моделей и собственное недельное окно каждой модели, например Fable. Полоса становится жёлтой на 80% и красной на 100%. Последняя строка называет аккаунт, который открыл бы `ccam next --auto`; с `auto_strategy = "expiring"` или `"balance"` вместо этого выводится `→ next --auto picks <name>: <reason>`.

**Места в тарифах Team и Enterprise.** Автоматический выбор аккаунта (`ccam next`, `--fallback`, `ccam pick`, клавиша `n` на панели и, если вы его включите, [`auto_switch`](/features/next#auto-switch)) переключается и между местами одной и той же организации Claude Team или Enterprise, что может нарушать условия Anthropic. Прочитайте [FAQ](/docs/faq#am-i-allowed-to-use-several-claude-code-accounts) и уточните это у своей организации и у Anthropic, прежде чем на него полагаться.

## Откуда берутся данные

ccam запрашивает эндпоинт использования Anthropic для всех аккаунтов одновременно, используя собственный вход каждого аккаунта. Он ждёт не более 3 секунд на аккаунт и показывает каждый аккаунт, как только тот ответит.

Этот эндпоинт публично не документирован и может измениться. Если запрос не удался, ccam показывает последние известные данные и помечает их как кэшированные. Окно, которое сбросилось после сохранения этих данных, показывает 0%. `ccam doctor` сообщит, если формат ответа изменился.

Когда Claude Code останавливает сессию на лимите использования, [плагин ccam](/docs/install#claude-code-plugin) записывает, какое окно заполнилось и когда оно сбросится. До этого момента окно показывает 100%, что бы ни говорили остальные данные, поэтому `ccam next --auto` и `--fallback` не выбирают этот аккаунт снова слишком рано.

Данные, полученные менее 60 секунд назад, используются повторно. Параметры:

| Параметр | Действие |
| --- | --- |
| `--watch[=seconds]` | Обновлять непрерывно, по умолчанию каждые 60 секунд |
| `--json` | Машиночитаемый вывод |
| `-v` | Дополнительно показать, откуда взяты данные каждого аккаунта |
| `--no-cache` | Всегда запрашивать заново |
| `--source cache` | Никогда не запрашивать; показывать только сохранённые данные |

## Истёкшие входы

Когда токен доступа аккаунта истёк, ccam его не обновляет, потому что обновление во время сессии Claude Code, использующей тот же вход, может привести к выходу из аккаунта в этой сессии. Аккаунт показывает ``access token expired; `ccam <name>` renews it when it starts``: запустите его один раз командой `ccam <name>`, и Claude Code обновит токен сам. Вход, который истёк полностью или который очистил Claude Code, показывает `` login expired → `ccam login <name>` `` и требует нового входа.

`ccam usage --refresh` сам обновляет истёкшие токены, но только для аккаунтов без работающей сессии Claude Code, как бы эта сессия ни была запущена. Он никогда не обновляет данные входа, хранящиеся в Связке ключей macOS или в импортированной папке `~/.claude`, а обновление может занять до 30 секунд.

## Использование в строке состояния

```sh
ccam statusline install
```

После этого Claude Code показывает в строке состояния имя аккаунта и его использование, например `[work] · Opus · 5h 24% · 7d 41%`. Начиная с 90%, строка также подсказывает `ccam next --auto --continue`. Если у вас уже есть команда для строки состояния, ccam сохраняет её и добавляет имя аккаунта в начало. Строка состояния также сохраняет свои данные, и `ccam usage` использует их, когда эндпоинт не отвечает.

## Переключение

```sh
ccam next             # the account after the one you used last
ccam next --auto      # the account with the lowest 5-hour usage
ccam next --continue  # continue this folder's conversation on the next account
```

`ccam next` пропускает аккаунты, в которые не выполнен вход, а `--auto` пропускает аккаунты на 100% (в том числе окно, которое Claude Code сообщил заполненным, до его сброса) и аккаунты другой организации. Если у двух аккаунтов общая история разговоров, `--continue` открывает тот же разговор; иначе Claude Code копирует его в новый аккаунт. См. разделы [общий доступ](/docs/sharing) и [переход к следующему аккаунту](/features/next#continue).

С `auto_switch = true` в начале `config.toml` (Linux и macOS; по умолчанию выключено) ccam сам делает это переключение, когда Claude Code останавливает интерактивную сессию на её лимите, а у другого аккаунта того же вида (места в той же организации или другого личного тарифа) есть запас. Когда он срабатывает и чего никогда не делает, см. в разделе [`auto_switch`](/features/next#auto-switch).

Для скриптов и заданий по расписанию, которые запускают `claude -p`, поставьте `--fallback` перед именем аккаунта. Когда этот аккаунт достигает лимита, ccam снова выполняет ту же команду от имени аккаунта с наибольшим запасом, и выводится только результат завершившегося запуска:

```sh
ccam --fallback work -p "review the diff" --output-format json
```

Как ccam принимает решение, см. в разделе [Повторный запуск при лимите](/features/next#run-again-at-the-limit).

В [руководстве по работе с лимитом использования](/guides/usage-limit-workflow) разобран полный пример.
