У каждого аккаунта своя папка, но большая часть её содержимого не обязана быть отдельной. **Группа** определяет, что делится и кем: каждый аккаунт группы связывает эти элементы с одной папкой, `~/.local/share/ccam/groups/<group>/`, поэтому все они читают и записывают одну и ту же копию. Токены входа никогда не бывают общими.

Аккаунт может состоять в нескольких группах, но каждый элемент берётся только из одной группы. Типичная настройка: одна группа для настроек и расширений и вторая для истории разговоров между двумя аккаунтами:

```toml
[[group]]
name = 'default'
items = ['mcp', 'settings', 'memory', 'extensions']
members = ['personal', 'work', 'side']

[[group]]
name = 'team'
items = ['history']
members = ['work', 'side']
```

Первый добавленный аккаунт создаёт `default`, а последующие аккаунты вступают в неё, если вы не укажете иное.

## Использование

```sh
ccam group                                        # the groups, what they share, their accounts
ccam group show default                           # items, accounts, folder and MCP servers
ccam group add team --items history --members work,side
ccam group set default --add history              # every account in default moves together
ccam group set default --remove history --fresh   # stop sharing; accounts start without it
ccam group set team --items history,memory --from work   # work's CLAUDE.md goes in first
ccam group join team personal                     # personal starts sharing team's items
ccam group join team personal --replace           # leave the group that shares them now
ccam group leave team side                        # side keeps a copy of team's items
ccam group rename team pair                       # the folder keeps its name
ccam group remove pair --leave                    # its accounts keep a copy; folder to the trash
ccam share work                                   # what work shares, and through which group
ccam --dry-run group set default --add history    # print the plan, change nothing
```

```console
$ ccam group
Group    Shares                          Accounts
default  mcp settings memory extensions  personal, work, side
team     history                         work, side

$ ccam share work
Sharing for work
  mcp         MCP servers                        group default
  settings    settings.json                      group default
  memory      global CLAUDE.md                   group default
  extensions  agents, commands, skills, plugins  group default
  history     conversation history               group team
Groups: default, team. Change them with `ccam group`.
```

Каждая команда, которая перемещает данные, выводит план, спрашивает про каждый файл, который отличается от копии группы, и задаёт вопрос `Proceed? [y/N]`, прежде чем что-либо изменить:

```console
$ ccam group set default --add history
Plan (paths in /home/me/.local/share/ccam):
personal: +history (group default)
  move     projects, history.jsonl: profiles/personal → groups/default (first content of the group)
  link     projects, history.jsonl: profiles/personal → groups/default
work: +history (group default)
  merge    new files in projects: profiles/work → groups/default
  conflict profiles/work/history.jsonl ↔ groups/default/history.jsonl: merge by line
  back up  projects, history.jsonl: profiles/work → profiles/work/.ccam-backup/20261020-153012
  link     projects, history.jsonl: profiles/work → groups/default
Proceed? [y/N]
```

Те же изменения доступны на вкладке **Groups** [панели](/features/dashboard), а `s` на аккаунте выбирает его группы.

## Элементы

| Элемент | Что он охватывает |
| --- | --- |
| `mcp` | MCP-серверы, через `mcp.json` группы ([Общие MCP-серверы](/features/mcp)) |
| `settings` | `settings.json` |
| `memory` | глобальный `CLAUDE.md` |
| `extensions` | `agents/`, `commands/`, `skills/`, `plugins/`, `output-styles/`, `rules/` |
| `history` | `projects/` и `history.jsonl`, чтобы другой аккаунт мог выполнить `--continue` |

Элемент, который не делит ни одна группа аккаунта, остаётся в собственной папке аккаунта.

## Команды и параметры

| Команда | Действие |
| --- | --- |
| `ccam group` или `ccam group list` | показать список групп |
| `ccam group show <group>` | что делит группа, её аккаунты, её папка и MCP-серверы |
| `ccam group add <group> --items <items> [--members <accounts>]` | создать группу; элементы её аккаунтов перемещаются в неё |
| `ccam group set <group> --add <items> \| --remove <items> \| --items <items>` | изменить, что делит группа, для каждого её аккаунта |
| `ccam group join <group> <account>...` | добавить аккаунты в группу |
| `ccam group leave <group> <account>...` | вывести аккаунты из группы; каждый сохраняет копию |
| `ccam group rename <group> <new-name>` | переименовать только в конфигурации |
| `ccam group remove <group> [--leave]` | удалить группу |

| Параметр | Действие | По умолчанию |
| --- | --- | --- |
| `--from <account>` | `add`, `set`: аккаунт, чья копия первой попадает в группу | аккаунт по умолчанию, затем по номеру |
| `--replace` | `join`: сначала выйти из групп, которые делят те же элементы | выкл. |
| `--fresh` | аккаунты, которые перестают делить элемент, начинают без него, а не с копией | выкл. |
| `--leave` | `remove`: сначала вывести аккаунты группы | нужен, если в группе есть аккаунты |
| `--prefer <group\|mine\|merge>` | как решать конфликты | спрашивать; с `--yes` вариант по умолчанию для каждого файла |
| `-y`, `--yes` | выполнить без вопросов; конфликты решаются по `--prefer` | выкл. |
| `--dry-run` (глобальный) | вывести план и ничего не менять | выкл. |

Аккаунты указываются по имени или номеру, элементы — списком через запятую. `ccam add` принимает `--group <group>` (можно повторять) или `--no-group`.

## Как это работает

Участвующие файлы:

- `~/.config/ccam/config.toml`: записи `[[group]]`: `name`, `items`, `members` и, если имя папки отличается, `dir`.
- `~/.local/share/ccam/profiles/<name>/`: `CLAUDE_CONFIG_DIR` аккаунта.
- `~/.local/share/ccam/groups/<folder>/`: общие копии.

При чтении `config.toml` группы каждого аккаунта сводятся к одной папке на элемент. Для пяти аккаунтов это занимает около 25 мкс, поэтому запуск по-прежнему читает только `config.toml`. Конфигурация, в которой аккаунт получал бы элемент из двух групп, считается ошибкой, и ничего не запускается, пока её не исправят.

Изменение выполняется над копией конфигурации:

1. Команда редактирует копию (`AddGroup`, `SetGroupItems`, `JoinGroup` …), которая проверяет правила.
2. `internal/group` сравнивает старое и новое состояние и для каждого аккаунта, чьи элементы меняются, строит план через `share.Build`. Планы строятся один за другим, и каждый видит, что предыдущие положат в папки групп, поэтому свою копию переносит только первый аккаунт. Первая копия берётся из папки группы, если в ней уже что-то есть, затем из `--from`, затем из аккаунта по умолчанию, затем из остальных по номеру.
3. ccam отказывается работать, если один из этих аккаунтов запущен, а в Windows без режима разработчика — если для файла понадобилась бы ссылка.
4. Конфликты решаются в ответ на вопрос или через `--prefer`, план выводится, и ccam спрашивает подтверждение.
5. Новая конфигурация сохраняется до того, как что-либо перемещается. Если шаг останавливается на середине, `ccam doctor --fix` и повторный запуск строят свой план к сохранённым группам и завершают изменение.
6. Планы выполняются по порядку. Каждый шаг перемещает данные в группу или в папку резервных копий; ничего не удаляется.

`share.Layout` представляет собой список разрешённых путей, которые охватывает каждый элемент. Всё, чего нет в этом списке, никогда не попадает в группу. `share.Never` называет `.credentials.json` и `.claude.json`, и `Build` останавливается с внутренней ошибкой, если один из них вдруг появится в структуре. У элемента `mcp` нет путей: список серверов хранится внутри `.claude.json`, поэтому [общий доступ к MCP](/features/mcp) работает через `mcp.json` группы.

Вот что происходит с одной папкой, `projects/`, когда `side` начинает делить историю, а в группе уже есть содержимое:

<!-- motion:share-on -->

Если в группе по этому пути ещё ничего нет, аккаунт делит его первым, и его папка перемещается туда как есть. Иначе каждый файл, которого нет в группе, перемещается в группу, а файлы, существующие с обеих сторон, остаются в папке аккаунта, поэтому сохраняется версия группы. Затем папка аккаунта перемещается в `.ccam-backup/<time>/` внутри папки аккаунта, а на её место ставится ссылка. Файлы разговоров называются по идентификатору сессии, поэтому истории из нескольких аккаунтов объединяются без конфликтов. Реестры `plugins/` хранят абсолютные пути через папку аккаунта; ccam перенаправляет их на папку группы и объединяет записи аккаунта с реестром, который уже есть в группе.

Выход из группы возвращает ссылку обратно:

<!-- motion:share-off -->

ccam удаляет ссылку, только если она указывает внутрь папки групп, а затем копирует текущее содержимое группы в аккаунт. С `--fresh` копирование пропускается. Группа сохраняет своё содержимое для остальных аккаунтов. Аккаунт, который переносит элемент в группу, чья папка ещё пуста, приносит копию того, что видел, поэтому сохраняет свои файлы; MCP-серверы переносятся так же. Аккаунт, который перестаёт делить MCP, теряет серверы, которые ccam скопировал в его `.claude.json` (резервная копия сохраняется), поскольку они пришли из группы.

Отдельный файл, который существует с обеих сторон с разным содержимым, считается конфликтом:

<!-- motion:share-conflict -->

Для `history.jsonl` предлагаются `merge by line`, `keep group` и `use mine`, с объединением на первом месте. Для других файлов `.json` предлагаются `keep group`, `use mine` и `merge JSON`. Для всего остального предлагаются `keep group` и `use mine`. `merge JSON` рекурсивно объединяет объекты, соединяет массивы без повторов и сохраняет значение группы, когда обе стороны задают одному ключу разные значения, поэтому остальные аккаунты не замечают изменений. Каждый вариант, кроме `keep group`, сначала сохраняет копию группы в `.ccam-backup/<time>/group/` в папке аккаунта. Ваш собственный файл всегда попадает в резервную копию.

При каждом запуске `share.Check` сравнивает каждый путь структуры с группами аккаунта, используя только `lstat` и `readlink`. Отсутствующая ссылка создаётся на месте. Настоящий файл там, где должна быть ссылка, ссылка не туда или устаревшая ссылка останавливают запуск и указывают на `ccam doctor --fix`.

### Переименование, удаление и старый формат

- `ccam group rename` меняет только конфигурацию. Папка сохраняет своё имя, и группа записывает его как `dir`, поэтому ничего не перемещается и ничего нельзя потерять.
- `ccam group remove` отказывается удалять группу с аккаунтами, если не добавить `--leave`. Тогда каждый аккаунт сохраняет копию, а папка перемещается в `~/.local/share/ccam/trash/`, если её не использует другая группа.
- До появления групп `config.toml` хранил таблицу `[profile.share]` для каждого аккаунта. ccam читает этот формат как группы, ничего не перемещая. При первом сохранении он записывает новый формат и сохраняет старый файл как `config.toml.bak`. Элементы, которые делят одни и те же аккаунты, становятся одной группой с именем папки; остальные получают имена вроде `default-history` и продолжают использовать ту же папку.

### В Windows

Windows создаёт символические ссылки только в режиме разработчика (Параметры > Система > Для разработчиков) или для администратора. Без этого права общая папка становится точкой соединения каталогов (junction), которая для Claude Code работает так же. Общий файл (`settings.json`, `CLAUDE.md`, `history.jsonl`) может быть только символической ссылкой, поэтому изменение группы, которому она нужна, отклоняется до того, как что-либо перемещается.

## Безопасность и особые случаи

- **Запущенные аккаунты.** Изменение отклоняется, пока Claude Code работает от имени одного из аккаунтов, которые оно перемещает, потому что сессия продолжает записывать в эти файлы. Выход и вступление касаются только названного аккаунта. `--dry-run` всё равно выводит план.
- **Резервные копии.** Каждый план получает собственную папку `.ccam-backup/<time>/` в папке аккаунта. ccam никогда их не удаляет.
- **Ваши собственные ссылки.** Если путь уже является созданной вами ссылкой, например на репозиторий dotfiles, а группа пуста, ccam копирует цель ссылки в группу, а саму ссылку перемещает в резервную копию. Цель не затрагивается.
- **Импортированные папки.** Аккаунт, зарегистрированный на месте через `ccam import` (например, `~/.claude`), меняется на месте, поэтому изменение видит и обычный `claude`; план сообщает об этом.
- **Два аккаунта в одной папке.** Аккаунты, которые делят историю, записывают одни и те же файлы. Когда второй из них запускается в папке, где уже работает первый, ccam предупреждает и спрашивает.
- **Правка вручную.** Участник, который не является аккаунтом, игнорируется, и `ccam doctor` сообщает о нём. Имена `local`, `on`, `off` и `none` не могут быть именами групп.
