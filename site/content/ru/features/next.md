`ccam next` открывает Claude Code от имени другого аккаунта, не требуя указывать его имя. Используйте его, когда аккаунт достиг лимита использования: обычный `ccam next` берёт аккаунт, следующий за последним использованным, `--auto` берёт аккаунт с наибольшим запасом, а `--continue` переносит последний разговор этой папки в новый аккаунт, независимо от того, общая ли у них история. Внутри Claude Code [плагин ccam](#inside-claude-code) сообщает, когда лимит останавливает сессию, а `/ccam:switch` передаёт разговор дальше. Для скриптов, которые запускают `claude -p`, `ccam --fallback` делает переключение сам (см. [Повторный запуск при лимите](#run-again-at-the-limit)).

**Места в тарифах Team и Enterprise.** При автоматическом выборе (`ccam next`, `--fallback`, `ccam pick`, клавиша `n` на панели) ccam переключается и между местами одной и той же организации Claude Team или Enterprise. В справочном центре Anthropic ([тарифы Team](https://support.claude.com/en/articles/12004354-purchase-and-manage-seats-on-team-plans#h_b8a7d07129); аналогично для [тарифов Enterprise](https://support.claude.com/en/articles/13393991-purchase-and-manage-seats-on-enterprise-plans#h_fa6b9cade0)) сказано: «Each seat on a Team plan is assigned to one named individual, and only that person may use it» (каждое место в тарифе Team закреплено за одним конкретным человеком, и пользоваться им может только этот человек) и «Users can't route their work through another user's account to use that user's remaining usage» (пользователи не могут направлять свою работу через аккаунт другого пользователя, чтобы расходовать оставшийся лимит этого пользователя). Поэтому использование автоматического выбора между местами может нарушать условия Anthropic. Прежде чем на него полагаться, уточните это у своей организации и у Anthropic. О личных тарифах (Pro, Max) см. [примечание об условиях в FAQ](/docs/faq#am-i-allowed-to-use-several-claude-code-accounts).

## Использование

```sh
ccam next                       # the account after the one you used last
ccam next --auto                # the account with the most room
ccam next --continue            # carry this folder's last conversation on as the next account
ccam next -c --auto             # both: the conversation, on the account with the most room
ccam next --auto --max-usage 80 # prefer accounts below 80%
ccam next --auto --strategy balance   # the weekly quota that would go unused first
ccam next --auto --cross-org    # also accounts of other organizations
ccam next --auto --wait         # nobody has room: wait for the first reset (up to 5 hours)
ccam next -c --auto -- --dangerously-skip-permissions   # claude's own options go after --
ccam --dry-run next --auto      # print the choice and the command, start nothing
```

```console
$ ccam --dry-run next --auto --continue
→ personal → work (12% of its 5 hours used, the least)
  continuing "Fix the flaky tests" (about 182k tokens); work does not share personal's history, so Claude Code copies it into work
CLAUDE_CONFIG_DIR=/home/you/.local/share/ccam/profiles/work CCAM_PROFILE=work /usr/local/bin/claude --resume /home/you/.local/share/ccam/profiles/personal/projects/-home-you-code-app/4f1c….jsonl --fork-session
```

ccam выводит переключение в виде `→ <from> → <to>` в стандартный поток ошибок, для выбора `--auto` с причиной, а затем запускает Claude Code от имени нового аккаунта так же, как `ccam <name>`. `<from>` означает последний использованный аккаунт, а с `--continue` аккаунт, которому принадлежит разговор. Аргументы после `--` передаются в `claude` без изменений.

## Параметры

| Параметр | Действие | По умолчанию |
| --- | --- | --- |
| `--auto` | Выбрать аккаунт с входом по использованию (см. ниже), пропуская аккаунты со 100% | выкл. |
| `--max-usage <1-100>` | С `--auto`: предпочитать аккаунты ниже этого использования | `auto_max_usage`, иначе 100 |
| `--strategy headroom\|expiring\|balance` | С `--auto`: наименьшее использование за 5 часов, ближайший сброс 5-часового окна или недельная квота, которая первой осталась бы неиспользованной | `auto_strategy`, иначе `headroom` |
| `--cross-org` | С `--auto`: выбирать также аккаунты другой организации (см. ниже) | `cross_org`, иначе выкл. |
| `--wait[=<duration>]` | С `--auto`: если ни у одного аккаунта нет запаса, ждать сброса первого из них, но не дольше этого времени. Значение указывается после `=`: `--wait 2h` отклоняется с подсказкой `--wait takes its value after '=': --wait=2h` | выкл.; `5h`, если указан без значения |
| `-c`, `--continue` | Перенести последний разговор этой папки в новый аккаунт (см. ниже) | выкл. |
| `-- <claude args>` | Аргументы, передаваемые в `claude` после собственных аргументов ccam | нет |
| `--dry-run` | Учитывается: выводит `→ <from> → <to>` и командную строку, которую выполнил бы, не запуская Claude Code и не записывая запуск | выкл. |

`--auto` и `--continue` можно использовать вместе. С `--continue` аргументы `--resume` ставятся перед вашими.

Собственные опции Claude Code, например `--dangerously-skip-permissions` или `--model`, указываются после `--`. В отличие от `ccam <name>`, который передаёт дальше всё, что идёт после имени, `ccam next` сам разбирает свои аргументы, поэтому без `--` он останавливается с `ccam: unknown flag: --dangerously-skip-permissions`.

## Как это работает

Каждый запуск через ccam записывает время в `~/.local/state/ccam/last-used/<name>`. `ccam next` читает эти файлы, проверяет, в каких аккаунтах выполнен вход, и делает выбор.

1. `cli.candidates` строит по одному `next.Candidate` на аккаунт из `config.toml`: аккаунт, время его последнего запуска (`launcher.LastUsed`) и наличие рабочего входа (`creds.Has`: вход Claude в `.credentials.json` или, в macOS, в Связке ключей, который не истёк целиком и не был очищен Claude Code). Папка, которая вместо этого использует ключ API (вход через Console или аккаунт, добавленный через `ccam add --api`), не имеет лимитов тарифа и никогда не выбирается.
2. Без `--auto` `next.Rotate` сортирует аккаунты по номеру слота и находит аккаунт, запущенный последним. С него вы и переключаетесь. Если ни один аккаунт ещё не запускался, это аккаунт с наименьшим слотом.
3. Оттуда он идёт вперёд по порядку слотов, переходя от последнего слота к первому, и возвращает первый аккаунт, в котором выполнен вход.
4. `launcher.LaunchWith` подготавливает и запускает выбранный аккаунт точно так же, как `ccam <name>`: проверяет ссылки аккаунта, применяет общий доступ к MCP, регистрирует сессию и заменяет ccam на `claude` через `syscall.Exec`.

Обход начинается с последнего использованного аккаунта и останавливается на первом аккаунте с входом после него:

<!-- motion:next-rotate -->

`work` запускался последним, поэтому обход начинается после него. У `side` нет входа, он пропускается, и выбирается `lab`. Если бы из `lab` тоже был выполнен выход, обход вернулся бы к `personal` (`% len` на схеме). Ротация никогда не возвращает аккаунт, с которого она началась: если другого аккаунта с входом нет, она завершается ошибкой.

### --auto

`--auto` выбирает по использованию, а не по порядку слотов. `cli.pickAuto` оставляет аккаунты с входом, одновременно запрашивает использование всех этих аккаунтов через тот же `Fetcher.FetchAll`, что и `ccam usage`, и передаёт выбор `usage.Policy.Choose()`:

<!-- motion:next-auto -->

Аккаунт оценивается по его 5-часовому и недельному окнам, а если среди аргументов для Claude Code (после `--`) есть `--model`, то и по недельному окну этой модели (`opus`, `sonnet`, `haiku` или `fable` в названии). `Policy.Choose()` делит аккаунты на три группы:

1. **Есть запас**: каждое окно ниже `auto_max_usage` (`config.toml`, по умолчанию 100). Среди них выбирает стратегия: `headroom` (по умолчанию) берёт наименьшее использование за 5 часов; `expiring` берёт 5-часовое окно, которое сбросится раньше всех, чтобы его оставшаяся квота была использована, пока не пропала; `balance` берёт аккаунт, у которого больше всего недельной квоты осталось на каждый день до сброса его недели, засчитывая против него каждую запущенную сессию ccam, чтобы недельная квота не оставалась неиспользованной, а параллельные сессии распределялись.
2. **Выше порога**: ниже 100%, но на уровне `auto_max_usage` или выше. Используются, только если ни у одного аккаунта нет запаса, начиная с наименьшего использования за 5 часов.
3. **Заполнены**: окно на 100% или неизвестное использование за 5 часов. Никогда не выбираются.

Окно считается заполненным на 100% до своего сброса, если Claude Code отклонил там запрос: это записывает хук [плагина ccam](#inside-claude-code) (`~/.local/state/ccam/usage/<name>.limit.json`), что бы ни говорили сохранённые данные. Поэтому аккаунт, только что достигший лимита, не выбирается снова до сброса, даже если его данные устарели.

Настройки для всех аккаунтов пишутся в начале `config.toml`, над первым `[[group]]`, `[[profile]]` или `[[folder]]`. Настройка под одной из этих таблиц относится к ней: ccam называет её при каждом запуске, а команды, которые сохраняют конфигурацию, отказываются работать, пока её не перенесут.

```toml
# ~/.config/ccam/config.toml
auto_max_usage = 80        # keep 20% of each account for interactive work
auto_strategy = "expiring"
```

**Организации.** Автоматический выбор остаётся среди аккаунтов того же рода, что и покидаемый: та же организация Team или Enterprise либо личные тарифы (Pro, Max) вместе, поэтому работа из рабочего аккаунта не продолжается в личном и наоборот. ccam знает организацию каждого аккаунта по его входу (`ccam login` записывает её; для старых входов она читается из `.claude.json`); аккаунт, организацию которого определить нельзя, подходит куда угодно. Две папки, вошедшие в один и тот же аккаунт Claude, делят его лимиты, поэтому одна никогда не подменяет другую. `--cross-org` или `cross_org = true` в `config.toml` снимает правило организаций.

Когда выбрать нечего, ccam завершается с кодом 75 (`EX_TEMPFAIL`), чтобы скрипт мог отличить «попробуйте позже» от ошибки. С `--wait` он вместо этого ждёт, пока сбросится блокирующее окно первого заполненного аккаунта (через 30 секунд после времени сброса, когда эндпоинт показывает новое окно), выводит `ccam: no account has room; waiting until 15:10` и выбирает снова; если ни один аккаунт не сообщает, когда сбросится, он проверяет снова через 10 минут. Если до конца ожидания ничего не освободится, он завершается с кодом 75. Запрос подчиняется правилам `ccam usage`: данные моложе 60 секунд используются повторно, на каждый аккаунт отводится 3 секунды, аккаунт, который не отвечает или чей токен доступа истёк, оценивается по сохранённым данным, а поверх них ложится запись о лимите. Сохранённое окно, время сброса которого прошло, считается за 0%, поэтому аккаунт, окно которого с тех пор сбросилось, не пропускается. `--auto` никогда не обновляет токены. В отличие от обычной ротации, `--auto` может выбрать последний использованный аккаунт, если у него по-прежнему наибольший запас.

### --continue

1. ccam ищет последний разговор этой папки во всех аккаунтах: из файлов `<session>.jsonl` в `projects/<folder>/` (имя папки — это рабочая папка с раскрытыми ссылками, в которой каждый символ, кроме букв и цифр, заменён на `-`, как его называет Claude Code) выбирается тот, где самый новый запрос или ответ. Сессии без них, например сессия, в которой выполнялись только `/mcp`, `/usage` или `/status`, или пустой файл, пропускаются. Если сессия оставила заметку (лимит использования или `/ccam:switch`, см. ниже) и ни в одном разговоре нет запроса или ответа более чем через 2 минуты после неё, используется именно эта сессия; строки, которые Claude Code записывает при `/exit`, не учитываются.
2. Аккаунт, которому он принадлежит, считается тем, с которого вы переключаетесь, а новый аккаунт выбирается, как описано выше, в пределах той же организации. Когда эту историю делят несколько аккаунтов, разговор принадлежит тому, чей `.claude.json` говорит, что он вёл этот разговор последним (`lastSessionId`), а иначе — последнему использованному.
3. Если новый аккаунт делит эту историю (та же папка группы), ccam запускает `claude --resume <session id>`, то есть именно этот разговор (`--continue` открыл бы самый новый разговор в папке, каким бы он ни был).
4. Иначе он запускает `claude --resume <the conversation's file> --fork-session`: Claude Code копирует весь разговор под новым идентификатором сессии в собственную историю нового аккаунта, а оригинал остаётся как был. С этого момента `--continue` нового аккаунта находит его.

ccam сообщает размер разговора: новый аккаунт перечитывает его целиком в своём первом ответе. Кэши запросов никогда не делятся между организациями, а каждый личный тариф — это отдельная организация, поэтому, когда два аккаунта принадлежат разным, ccam добавляет `prompt caches are not shared between organizations, so the first reply reads it all again`. Когда старый аккаунт вошёл в MCP-серверы, в которые не вошёл новый, ccam называет их: `work is not signed in to MCP servers personal is: linear (sign in with /mcp there; sign-ins are not shared)`. Общая `history` в группе позволяет обойтись без копии, сохраняет один разговор и, кроме того, делает общими контрольные точки, из которых `/rewind` восстанавливает код (`file-history/`).

## Внутри Claude Code

[Плагин ccam](/docs/install#claude-code-plugin) добавляет два хука (Claude Code 2.1.78 или новее):

- Когда ход останавливается на лимите использования, он записывает разговор и показывает уведомление на рабочем столе в терминалах, которые это поддерживают (iTerm2, WezTerm, Windows Terminal, kitty, Ghostty): ``ccam: work hit its 5-hour limit (resets 3:45pm). `ccam next --continue` carries on as another account.`` Он знает каждое сообщение, которое Claude Code считает лимитом использования: 5-часовой, недельный, обычный лимит и лимит модели (`You've hit your session limit`, `You've hit your limit`, `You've reached your …` для квоты модели), кредиты использования и лимиты расходов, а также организацию, которая остановила аккаунт. Когда Claude Code записал отклонённый запрос в разговор, хук также записывает заполненное окно до его сброса ([запись о лимите](/features/usage#the-limit-record)), кроме остановки организацией, которую её администраторы могут снять в любой момент. Кратковременное ограничение со стороны сервера или ограничение частоты запросов ключа API не является лимитом использования и не обрабатывается, как и остановка субагента и сессии, за которыми никто не сидит (`-p`, фоновые сессии). Claude Code 2.1.234 и новее также ждёт в сессии и сам продолжает работу после сброса 5-часового окна; уведомление даёт вам возможность вместо этого переключиться.
- `/ccam:switch [account]` записывает разговор и завершает ход до того, как будет отправлен какой-либо запрос: введите `/exit`, после чего `ccam next --continue` продолжит разговор от имени указанного аккаунта или следующего. В сессии, где ещё нет разговора, он сообщает, что переносить нечего.

Заметка хранится в `~/.local/state/ccam/handoff/<account>/<session>.json`, по одному файлу на сессию, поэтому две сессии одного аккаунта никогда не перезаписывают заметки друг друга. Она хранится 12 часов и используется один раз, когда вот-вот начнётся следующая сессия; если запуск не удался, она остаётся для следующей попытки. Она относится к папке, в которой началась сессия, даже после `cd` в оболочке Claude Code. `ccam rename` обновляет имена в ней; если указанный в ней аккаунт с тех пор удалён, ccam сообщает об этом и выбирает как обычно.

### Relay

С `relay = true` в начале `config.toml` ccam остаётся рядом с интерактивными сессиями вместо того, чтобы заменять себя на Claude Code, и после `/ccam:switch` сам переносит разговор этой сессии (заметку, оставленную другой сессией, он не обрабатывает): хук завершает Claude Code, и ccam выполняет `ccam next --continue` с заметкой этой сессии. Если аккаунт не указан, берётся аккаунт с наибольшим запасом с учётом модели разговора. В Windows хук не может завершить Claude Code: введите `/exit`, и ccam продолжит. Это стоит одного ожидающего процесса ccam на сессию, поэтому по умолчанию режим выключен.

Переданная сессия сохраняет то, что не восстанавливает возобновление разговора: параметры вроде `--add-dir`, `--mcp-config`, списков инструментов, `--settings`, `--plugin-dir` и параметров системного запроса, режим разрешений разговора и уровень усилий сессии. `--model`, `--name` и `--agent` Claude Code сам восстанавливает из разговора. Всё остальное (`--worktree`, `--debug`, `--remote-control`, параметры, которых ccam не знает) называется в `ccam: not carried over: …`. Переключение никогда не задаёт вопрос об общей истории, а то, что вы ввели во время него, отбрасывается.

Relay продолжает, только когда Claude Code завершился так, как просил `/ccam:switch`: не тогда, когда вы сначала ввели `/exit`, нажали Ctrl+C во время завершения или ccam получил сигнал разрыва связи или другой сигнал, и не тогда, когда терминала больше нет. Тогда заметка остаётся, и `ccam next --continue` перенесёт разговор позже. Сессию, запущенную под relay более старого ccam, или сессию, за которой никто не сидит (`-p`, фоновые сессии), хук не завершает; вместо этого она получает сообщение про `/exit`. `claude remote-control` работает без relay.

## Повторный запуск при лимите

`ccam next` предназначен для остановившейся интерактивной сессии. Неинтерактивный запуск, `claude -p` в скрипте или задании по расписанию, не может ждать вас, поэтому `--fallback` перед именем аккаунта позволяет ccam переключиться за него:

```sh
ccam --fallback work -p "fix the failing tests" --output-format json
ccam --fallback -p "summarise" < notes.txt      # the folder's account or the default
ccam run --fallback work -p "review the diff"
```

```console
$ ccam --fallback personal -p "summarise" < notes.txt
ccam: personal reached its usage limit; running the command again as work
Summary: …
```

1. `--fallback` работает только вместе с `-p` или `--print`; иначе ccam останавливается и указывает на `ccam next --auto --continue`.
2. Стандартный ввод из канала читается один раз, до 10 МиБ, и передаётся каждой попытке. Как и Claude Code, ccam ждёт его начала не более 3 секунд (кроме `--input-format stream-json`); канал, который остаётся открытым и ничего не передаёт, оставляет запуск без ввода, с сообщением в стандартном потоке ошибок.
3. ccam запускает `claude` как дочерний процесс вместо `exec`, придерживает его стандартный вывод и передаёт стандартный поток ошибок по мере поступления.
4. Когда `claude` завершается с кодом 0 или с ошибкой по другой причине, придержанный вывод и код возврата передаются без изменений. Так же обрабатывается запуск, завершённый сигналом (код возврата больше 128): его попросили остановиться, и он не запускается снова.
5. Ошибка считается достижением лимита использования, когда об этом говорит сообщение Claude Code — любое из сообщений о лимите использования, которые знает [хук](#inside-claude-code), в том числе внутри вывода `--output-format json` или `stream-json`, — или когда использование аккаунта показывает его 5-часовое, недельное окно или окно `--model` на 100% (включая запись о лимите).
6. Тогда вывод этой попытки отбрасывается, и та же команда запускается от имени другого аккаунта с входом: сначала с наименьшим использованием за 5 часов, затем аккаунты, использование которых узнать не удалось, в порядке номеров. Аккаунты на 100% пропускаются, аккаунты со входом по ключу API никогда не пробуются, и каждый аккаунт пробуется не более одного раза.
7. Если среди аргументов есть `-c`, `--continue`, `-r` или `--resume`, пробуются только аккаунты из той же группы истории, чтобы разговор можно было найти.
8. Пробуются только аккаунты той же организации, как и с `--auto` (`cross_org = true` снимает это ограничение).

Следующий аккаунт выбирается по тем же правилам, что и в `--auto` (`auto_max_usage`, `auto_strategy`, окно `--model`). Когда аккаунтов не осталось, ccam выводит результат последней попытки, сообщает, что ни у одного аккаунта с входом не осталось запаса, и завершается с кодом 75. С `--wait` перед именем аккаунта (`ccam --fallback --wait=2h work -p …`) он вместо этого ждёт сброса первого аккаунта, после чего может снова попробовать все аккаунты; сначала он всегда хотя бы раз ждёт, чтобы аккаунт, только что достигший лимита, не запускался снова сразу же. Длительность ограничивает всё ожидание запуска в целом, а не каждое ожидание. Если записать её через пробел (`--wait 30m`), она отклоняется с той же подсказкой, что и в `ccam next`. Начальный `--` перед аргументами Claude Code работает так же, как при любом запуске (`ccam --fallback work -- -p …`). `ccam --dry-run --fallback work -p …` выводит команду первой попытки.

Интерактивные сессии сами не переключаются. Вместо этого с `ccam statusline install` строка состояния добавляет `→ ccam next --auto --continue`, как только использование за 5 часов или за неделю доходит до 90% ([Лимиты использования](/features/usage)).

## Безопасность и особые случаи

- Аккаунты без входа никогда не выбираются. Если другого аккаунта с входом нет, обычный `ccam next` завершается с сообщением `no logged-in account other than <name>`.
- С `--continue`, если в папке нет разговора: `no account has a conversation in <folder> to continue`.
- Если после правила организаций не остаётся ни одного аккаунта: `` no logged-in account to pick among <name>'s (<organization>); --cross-org also looks at the others ``.
- С `--auto`, если нет ни одного аккаунта с входом: `no logged-in account to pick`. Если каждый аккаунт заполнен или его использование неизвестно: `` no account with known usage and headroom (see `ccam usage`) ``. В обоих случаях код выхода 75.
- `--max-usage`, `--strategy`, `--wait` и `--cross-org` работают только с `--auto`, а значение вне диапазона 1-100 или другая стратегия отклоняются.
- Ответвление копирует разговор, но не остальное состояние аккаунта: контрольные точки из `file-history/` исходного аккаунта не переносятся, если история не общая.
- `--auto` выполняет сетевые запросы даже с `--dry-run`. Он только читает и никогда не записывает файлы токенов.
- Выбранный аккаунт запускается тем же путём, что и `ccam <name>`, поэтому действуют те же проверки, включая предупреждение, когда в этой папке уже работает другой Claude Code с той же историей.
- `last-used` записывается, только когда Claude Code действительно запускается. `--dry-run` его не трогает, поэтому пробный запуск не сдвигает ротацию.
- `--fallback` придерживает стандартный вывод до конца попытки, поэтому потоковый вывод, например `--output-format stream-json`, приходит одним куском в конце. Клиент, который передаёт ввод `stream-json` потоком и ждёт ответов, прежде чем отправить ещё, не может использовать `--fallback`. Файлы, которые первая попытка изменила до достижения лимита, остаются изменёнными; следующая попытка начинает запрос заново.
