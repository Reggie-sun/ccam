`ccam next` открывает Claude Code от имени другого аккаунта, не требуя указывать его имя. Используйте его, когда аккаунт достиг лимита использования: обычный `ccam next` берёт аккаунт, следующий за последним использованным, `--auto` берёт аккаунт с наибольшим запасом, а `--continue` переносит последний разговор этой папки в новый аккаунт, независимо от того, общая ли у них история. Внутри Claude Code [плагин ccam](#inside-claude-code) сообщает, когда лимит останавливает сессию, а `/ccam:switch` передаёт разговор дальше. Для скриптов, которые запускают `claude -p`, `ccam --fallback` делает переключение сам (см. [Повторный запуск при лимите](#run-again-at-the-limit)).

## Использование

```sh
ccam next                       # the account after the one you used last
ccam next --auto                # the account with the most room
ccam next --continue            # carry this folder's last conversation on as the next account
ccam next -c --auto             # both: the conversation, on the account with the most room
ccam next --auto --max-usage 80 # prefer accounts below 80%
ccam next --auto --strategy balance   # the weekly quota that would go unused first
ccam next --auto --cross-org    # also accounts of other organizations
ccam next --auto --wait         # nobody has room: wait for the first reset (up to 5 hours)
ccam next -c --auto -- --dangerously-skip-permissions   # claude's own options go after --
ccam --dry-run next --auto      # print the choice and the command, start nothing
```

```console
$ ccam --dry-run next --auto --continue
→ personal → work (12% of its 5 hours used, the least)
  continuing "Fix the flaky tests" (about 182k tokens); work does not share personal's history, so Claude Code copies it into work
CLAUDE_CONFIG_DIR=/home/you/.local/share/ccam/profiles/work /usr/local/bin/claude --resume /home/you/.local/share/ccam/profiles/personal/projects/-home-you-code-app/4f1c….jsonl --fork-session
```

ccam выводит переключение в виде `→ <from> → <to>` в стандартный поток ошибок, для выбора `--auto` с причиной, а затем запускает Claude Code от имени нового аккаунта так же, как `ccam <name>`. `<from>` означает последний использованный аккаунт, а с `--continue` аккаунт, которому принадлежит разговор. Аргументы после `--` передаются в `claude` без изменений.

## Параметры

| Параметр | Действие | По умолчанию |
| --- | --- | --- |
| `--auto` | Выбрать аккаунт с входом по использованию (см. ниже), пропуская аккаунты со 100% | выкл. |
| `--max-usage <1-100>` | С `--auto`: предпочитать аккаунты ниже этого использования | `auto_max_usage`, иначе 100 |
| `--strategy headroom\|expiring\|balance` | С `--auto`: наименьшее использование за 5 часов, ближайший сброс 5-часового окна или недельная квота, которая первой осталась бы неиспользованной | `auto_strategy`, иначе `headroom` |
| `--cross-org` | С `--auto`: выбирать также аккаунты другой организации (см. ниже) | `cross_org`, иначе выкл. |
| `--wait[=<duration>]` | С `--auto`: если ни у одного аккаунта нет запаса, ждать сброса первого из них, но не дольше этого времени | выкл.; `5h`, если указан без значения |
| `-c`, `--continue` | Перенести последний разговор этой папки в новый аккаунт (см. ниже) | выкл. |
| `-- <claude args>` | Аргументы, передаваемые в `claude` после собственных аргументов ccam | нет |
| `--dry-run` | Учитывается: выводит `→ <from> → <to>` и командную строку, которую выполнил бы, не запуская Claude Code и не записывая запуск | выкл. |

`--auto` и `--continue` можно использовать вместе. С `--continue` аргументы `--resume` ставятся перед вашими.

Собственные опции Claude Code, например `--dangerously-skip-permissions` или `--model`, указываются после `--`. В отличие от `ccam <name>`, который передаёт дальше всё, что идёт после имени, `ccam next` сам разбирает свои аргументы, поэтому без `--` он останавливается с `ccam: unknown flag: --dangerously-skip-permissions`.

## Как это работает

Каждый запуск через ccam записывает время в `~/.local/state/ccam/last-used/<name>`. `ccam next` читает эти файлы, проверяет, в каких аккаунтах выполнен вход, и делает выбор.

1. `cli.candidates` строит по одному `next.Candidate` на аккаунт из `config.toml`: аккаунт, время его последнего запуска (`launcher.LastUsed`) и наличие входа (`creds.Has`: читаемый `.credentials.json` или, в macOS, элемент Связки ключей).
2. Без `--auto` `next.Rotate` сортирует аккаунты по номеру слота и находит аккаунт, запущенный последним. С него вы и переключаетесь. Если ни один аккаунт ещё не запускался, это аккаунт с наименьшим слотом.
3. Оттуда он идёт вперёд по порядку слотов, переходя от последнего слота к первому, и возвращает первый аккаунт, в котором выполнен вход.
4. `launcher.LaunchWith` подготавливает и запускает выбранный аккаунт точно так же, как `ccam <name>`: проверяет ссылки аккаунта, применяет общий доступ к MCP, регистрирует сессию и заменяет ccam на `claude` через `syscall.Exec`.

Обход начинается с последнего использованного аккаунта и останавливается на первом аккаунте с входом после него:

<!-- motion:next-rotate -->

`work` запускался последним, поэтому обход начинается после него. У `side` нет входа, он пропускается, и выбирается `lab`. Если бы из `lab` тоже был выполнен выход, обход вернулся бы к `personal` (`% len` на схеме). Ротация никогда не возвращает аккаунт, с которого она началась: если другого аккаунта с входом нет, она завершается ошибкой.

### --auto

`--auto` выбирает по использованию, а не по порядку слотов. `cli.pickAuto` оставляет аккаунты с входом, одновременно запрашивает использование всех этих аккаунтов через тот же `Fetcher.FetchAll`, что и `ccam usage`, и передаёт выбор `usage.Policy.Choose()`:

<!-- motion:next-auto -->

Аккаунт оценивается по его 5-часовому и недельному окнам, а если среди аргументов для Claude Code (после `--`) есть `--model`, то и по недельному окну этой модели (`opus`, `sonnet`, `haiku` или `fable` в названии). `Policy.Choose()` делит аккаунты на три группы:

1. **Есть запас**: каждое окно ниже `auto_max_usage` (`config.toml`, по умолчанию 100). Среди них выбирает стратегия: `headroom` (по умолчанию) берёт наименьшее использование за 5 часов; `expiring` берёт 5-часовое окно, которое сбросится раньше всех, чтобы его оставшаяся квота была использована, пока не пропала; `balance` берёт аккаунт, у которого больше всего недельной квоты осталось на каждый день до сброса его недели, засчитывая против него каждую запущенную сессию ccam, чтобы недельная квота не оставалась неиспользованной, а параллельные сессии распределялись.
2. **Выше порога**: ниже 100%, но на уровне `auto_max_usage` или выше. Используются, только если ни у одного аккаунта нет запаса, начиная с наименьшего использования за 5 часов.
3. **Заполнены**: окно на 100% или неизвестное использование за 5 часов. Никогда не выбираются.

```toml
# ~/.config/ccam/config.toml
auto_max_usage = 80        # keep 20% of each account for interactive work
auto_strategy = "expiring"
```

**Организации.** Автоматический выбор остаётся среди аккаунтов того же рода, что и покидаемый: та же организация Team или Enterprise либо личные тарифы (Pro, Max) вместе, поэтому работа из рабочего аккаунта не продолжается в личном и наоборот. ccam знает организацию каждого аккаунта по его входу (`ccam login` записывает её; для старых входов она читается из `.claude.json`); аккаунт, организацию которого определить нельзя, подходит куда угодно. Две папки, вошедшие в один и тот же аккаунт Claude, делят его лимиты, поэтому одна никогда не подменяет другую. `--cross-org` или `cross_org = true` в `config.toml` снимает правило организаций.

Когда выбрать нечего, ccam завершается с кодом 75 (`EX_TEMPFAIL`), чтобы скрипт мог отличить «попробуйте позже» от ошибки. С `--wait` он вместо этого ждёт, пока сбросится блокирующее окно первого заполненного аккаунта (через 30 секунд после времени сброса, когда эндпоинт показывает новое окно), выводит `ccam: no account has room; waiting until 15:10` и выбирает снова; если ни один аккаунт не сообщает, когда сбросится, он проверяет снова через 10 минут. Если до конца ожидания ничего не освободится, он завершается с кодом 75. Запрос подчиняется правилам `ccam usage`: данные моложе 60 секунд используются повторно, на каждый аккаунт отводится 3 секунды, а аккаунт, который не отвечает или чей вход истёк, оценивается по сохранённым данным. Сохранённое окно, время сброса которого прошло, считается за 0%, поэтому аккаунт, окно которого с тех пор сбросилось, не пропускается. `--auto` никогда не обновляет токены. В отличие от обычной ротации, `--auto` может выбрать последний использованный аккаунт, если у него по-прежнему наибольший запас.

### --continue

1. ccam ищет последний разговор этой папки во всех аккаунтах: самый новый `<session>.jsonl` в `projects/<folder>/` (имя папки — это рабочая папка, в которой каждый символ, кроме букв и цифр, заменён на `-`, как его называет Claude Code). Если сессия оставила заметку (лимит использования или `/ccam:switch`, см. ниже) и с тех пор ничего новее не записано, используется именно эта сессия.
2. Аккаунт, которому он принадлежит, считается тем, с которого вы переключаетесь, а новый аккаунт выбирается, как описано выше, в пределах той же организации.
3. Если новый аккаунт делит эту историю (та же папка группы), ccam запускает `claude --resume <session id>`, то есть именно этот разговор (`--continue` открыл бы самый новый разговор в папке, каким бы он ни был).
4. Иначе он запускает `claude --resume <the conversation's file> --fork-session`: Claude Code копирует весь разговор под новым идентификатором сессии в собственную историю нового аккаунта, а оригинал остаётся как был. С этого момента `--continue` нового аккаунта находит его.

ccam сообщает размер разговора: новый аккаунт перечитывает его целиком в своём первом ответе. Кэши запросов никогда не делятся между организациями, поэтому с `--cross-org` этот первый ответ стоит полного размера. Общая `history` в группе позволяет обойтись без копии, сохраняет один разговор и, кроме того, делает общими контрольные точки, из которых `/rewind` восстанавливает код (`file-history/`).

## Внутри Claude Code

[Плагин ccam](/docs/install#claude-code-plugin) добавляет два хука (Claude Code 2.1.78 или новее):

- Когда ход останавливается на лимите использования (`You've hit your session limit`, недельный лимит или лимит модели), он записывает разговор и показывает уведомление на рабочем столе в терминалах, которые это поддерживают (iTerm2, WezTerm, Windows Terminal, kitty, Ghostty): `ccam: work hit its 5-hour limit (resets 3:45pm). ccam next --continue carries on as another account.` Кратковременное ограничение со стороны сервера или ограничение частоты запросов ключа API не является лимитом использования и не обрабатывается. Claude Code 2.1.234 и новее также ждёт в сессии и сам продолжает работу после сброса 5-часового окна; уведомление даёт вам возможность вместо этого переключиться.
- `/ccam:switch [account]` записывает разговор и завершает ход до того, как будет отправлен какой-либо запрос: введите `/exit`, после чего `ccam next --continue` продолжит разговор от имени указанного аккаунта или следующего.

Заметка хранится в `~/.local/state/ccam/handoff/<account>.json` 12 часов и используется один раз, когда вот-вот начнётся следующая сессия; если запуск не удался, она остаётся для следующей попытки. Она относится к папке, в которой началась сессия, даже после `cd` в оболочке Claude Code. Если указанный в ней аккаунт с тех пор переименован или удалён, ccam сообщает об этом и выбирает как обычно. С `relay = true` в `config.toml` ccam остаётся рядом с интерактивными сессиями вместо того, чтобы заменять себя на Claude Code, и после `/ccam:switch` сам переносит разговор этой сессии (заметку, оставленную другой сессией, он не обрабатывает). Это стоит одного ожидающего процесса ccam на сессию, поэтому по умолчанию режим выключен. Переданная сессия запускается с `ccam next --continue`, без аргументов, с которыми была запущена первая, например `--model`.

## Повторный запуск при лимите

`ccam next` предназначен для остановившейся интерактивной сессии. Неинтерактивный запуск, `claude -p` в скрипте или задании по расписанию, не может ждать вас, поэтому `--fallback` перед именем аккаунта позволяет ccam переключиться за него:

```sh
ccam --fallback work -p "fix the failing tests" --output-format json
ccam --fallback -p "summarise" < notes.txt      # the folder's account or the default
ccam run --fallback work -p "review the diff"
```

```console
$ ccam --fallback personal -p "summarise" < notes.txt
ccam: personal reached its usage limit; running the command again as work
Summary: …
```

1. `--fallback` работает только вместе с `-p` или `--print`; иначе ccam останавливается и указывает на `ccam next --auto --continue`.
2. Стандартный ввод читается один раз и передаётся каждой попытке.
3. ccam запускает `claude` как дочерний процесс вместо `exec`, придерживает его стандартный вывод и передаёт стандартный поток ошибок по мере поступления.
4. Когда `claude` завершается с кодом 0 или с ошибкой по другой причине, придержанный вывод и код возврата передаются без изменений.
5. Ошибка считается достижением лимита использования, когда об этом говорит сообщение Claude Code (`You've hit your limit`, `usage limit reached`) или когда запрос использования аккаунта показывает его 5-часовое или недельное окно на 100%.
6. Тогда вывод этой попытки отбрасывается, и та же команда запускается от имени другого аккаунта с входом: сначала с наименьшим использованием за 5 часов, затем аккаунты, использование которых узнать не удалось, в порядке номеров. Аккаунты на 100% пропускаются, и каждый аккаунт пробуется не более одного раза.
7. Если среди аргументов есть `-c`, `--continue`, `-r` или `--resume`, пробуются только аккаунты из той же группы истории, чтобы разговор можно было найти.
8. Пробуются только аккаунты той же организации, как и с `--auto` (`cross_org = true` снимает это ограничение).

Следующий аккаунт выбирается по тем же правилам, что и в `--auto` (`auto_max_usage`, `auto_strategy`, окно `--model`). Когда аккаунтов не осталось, ccam выводит результат последней попытки, сообщает, что ни у одного аккаунта с входом не осталось запаса, и завершается с кодом 75. С `--wait` перед именем аккаунта (`ccam --fallback --wait=2h work -p …`) он вместо этого ждёт сброса первого аккаунта, после чего может снова попробовать все аккаунты; сначала он всегда хотя бы раз ждёт, чтобы аккаунт, только что достигший лимита, не запускался снова сразу же. `ccam --dry-run --fallback work -p …` выводит команду первой попытки.

Интерактивные сессии сами не переключаются. Вместо этого с `ccam statusline install` строка состояния добавляет `→ ccam next --auto --continue`, как только использование за 5 часов или за неделю доходит до 90% ([Лимиты использования](/features/usage)).

## Безопасность и особые случаи

- Аккаунты без входа никогда не выбираются. Если другого аккаунта с входом нет, обычный `ccam next` завершается с сообщением `no logged-in account other than <name>`.
- С `--continue`, если в папке нет разговора: `no account has a conversation in <folder> to continue`.
- Если после правила организаций не остаётся ни одного аккаунта: `` no logged-in account to pick among <name>'s (<organization>); --cross-org also looks at the others ``.
- С `--auto`, если нет ни одного аккаунта с входом: `no logged-in account to pick`. Если каждый аккаунт заполнен или его использование неизвестно: `` no account with known usage and headroom (see `ccam usage`) ``. В обоих случаях код выхода 75.
- `--max-usage`, `--strategy`, `--wait` и `--cross-org` работают только с `--auto`, а значение вне диапазона 1-100 или другая стратегия отклоняются.
- Ответвление копирует разговор, но не остальное состояние аккаунта: контрольные точки из `file-history/` исходного аккаунта не переносятся, если история не общая.
- `--auto` выполняет сетевые запросы даже с `--dry-run`. Он только читает и никогда не записывает файлы токенов.
- Выбранный аккаунт запускается тем же путём, что и `ccam <name>`, поэтому действуют те же проверки, включая предупреждение, когда в этой папке уже работает другой Claude Code с той же историей.
- `last-used` записывается, только когда Claude Code действительно запускается. `--dry-run` его не трогает, поэтому пробный запуск не сдвигает ротацию.
- `--fallback` придерживает стандартный вывод до конца попытки, поэтому потоковый вывод, например `--output-format stream-json`, приходит одним куском в конце. Файлы, которые первая попытка изменила до достижения лимита, остаются изменёнными; следующая попытка начинает запрос заново.
