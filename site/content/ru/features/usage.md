`ccam usage` показывает для каждого аккаунта, какая часть каждого лимита использована: 5-часового лимита, недельного лимита и собственного недельного лимита каждой модели (например, Fable). Для каждого лимита выводится полоса и время до его сброса. Запускайте его перед долгой задачей или когда Claude Code сообщает, что лимит близок, чтобы увидеть, у какого аккаунта остался запас. `ccam statusline` служит командой строки состояния для Claude Code: он показывает имя аккаунта и использование внутри Claude Code и сохраняет данные для `ccam usage`. А токены и оценочную стоимость, из которых складывается это использование, показывает `ccam ccusage`: он запускает [ccusage](https://ccusage.com) по разговорам всех аккаунтов ([ниже](#tokens-and-costs-ccam-ccusage)).

## Использование

```sh
ccam usage                  # every account, once
ccam u                      # the same, shorter
ccam usage --watch          # redraw every 60 seconds until Ctrl+C
ccam usage --watch=10       # redraw every 10 seconds
ccam usage -v               # add where the numbers came from
ccam usage --json           # machine-readable, one object per account
ccam usage --source cache   # saved numbers only, no network
ccam usage --refresh        # also renew expired logins of accounts that are not running
ccam usage --source claude  # let Claude Code look it up: ccam sends no token
ccam statusline install     # set the status line in every account's settings.json
```

```console
$ ccam usage
 1 personal  9h 36m ago (cached)
   5-hour   ░░░░░░░░░░░░░░░░░░░░   0%
   Weekly   ██████████████░░░░░░  70%  resets in 2d 16h
   Fable    ██░░░░░░░░░░░░░░░░░░  12%  resets in 2d 16h
 2 work      just now (cached)
   5-hour   █████░░░░░░░░░░░░░░░  24%  resets in 2h 29m
   Weekly   ████████░░░░░░░░░░░░  41%  resets in 3d 11h
   Fable    ███████████░░░░░░░░░  55%  resets in 5d 2h
 3 side      access token expired; `ccam side` renews it when it starts
→ Most headroom: personal   (open it with ccam next --auto)
```

Для каждого аккаунта выводится строка с его номером, именем и давностью данных; `(cached)` означает, что они взяты из сохранённого файла, а не от эндпоинта. Под ней для каждого лимита идёт строка с полосой из 20 ячеек, процентом и временем до сброса окна: `5-hour`, `Weekly` (все модели), затем собственное недельное окно каждой модели, например `Fable`. Окно, которого у аккаунта нет, показывается как `-`. Процент становится жёлтым на 80% и красным на 100%.

Если Claude Code отклонил запрос, потому что окно было заполнено, это окно показывает 100% до своего сброса, что бы ни говорили сохранённые данные (см. [запись о лимите](#the-limit-record)). В терминале все аккаунты появляются сразу как `fetching…`, и строки каждого рисуются, когда он отвечает.

Последняя строка, которая выводится, только если у вас больше одного аккаунта, называет аккаунт, который выбрал бы [`ccam next --auto`](/features/next). Она следует тем же правилам:

- `auto_max_usage` и `auto_strategy`;
- запущенные сессии;
- только аккаунты организации последнего использованного аккаунта, если не задан `cross_org`;
- каждое окно на 100% пропускается, поэтому аккаунт с заполненной неделей никогда не называется.

Со стратегией по умолчанию `headroom` она выглядит как `→ Most headroom: <name>`; с `expiring` или `balance` она указывает причину, например `→ next --auto picks personal: its 5-hour window resets first, in 1h 12m (40% of its 5 hours used)`.

**Места в тарифах Team и Enterprise.** Автоматический выбор аккаунта (`ccam next`, `--fallback`, `ccam pick`, клавиша `n` на панели и, если вы его включите, [`auto_switch`](/features/next#auto-switch)) переключается и между местами одной и той же организации Claude Team или Enterprise, что может нарушать условия Anthropic. Прочитайте [FAQ](/docs/faq#am-i-allowed-to-use-several-claude-code-accounts) и уточните это у своей организации и у Anthropic, прежде чем на него полагаться.

Аккаунт без входа показывает `not logged in → ccam login <name>`, а аккаунт с ключом API показывает `no limits (API)`. Истёкший токен доступа показывается как ``access token expired; `ccam <name>` renews it when it starts``, над сохранёнными данными, если они есть: Claude Code обновит его при следующем запуске. Вход, который истёк полностью, потому что истёк его токен обновления или Claude Code очистил его после того, как сервер его отклонил, показывается как `` login expired → `ccam login <name>` ``.

После `ccam statusline install` Claude Code показывает строку вида `[work] · Opus · 5h 24% · 7d 41%`.

## Параметры

| Параметр | Действие | По умолчанию |
| --- | --- | --- |
| `--json` | Вывести отчёты в формате JSON: `name`, `slot`, `status`, `limits` (с `credits`, если у аккаунта включены кредиты использования), `source`, `at`, `error`, а также `limited` и `limited_windows`, когда запись о лимите устанавливает окна на 100%. Без аккаунтов выводит `[]` | выкл. |
| `--watch[=N]` | Перерисовывать каждые `N` секунд, пока вы не нажмёте Ctrl+C. `--watch` без значения или значение 0 и меньше означает 60. Значение указывается после `=`: `--watch 10` отклоняется с подсказкой | выкл. |
| `-v`, `--verbose` | Добавить под каждым аккаунтом строку `source:`: откуда взяты его данные (эндпоинт использования, Claude Code, строка состояния, сохранённый файл или лимит использования, о котором сообщил Claude Code). Когда запись о лимите имеет приоритет над данными, следом идёт строка вида `Weekly full: Claude Code reported the usage limit 1h 0m ago, so 100% until the reset` | выкл. |
| `--no-cache` | Не учитывать 60-секундный кэш и запросить эндпоинт заново | выкл. |
| `--source live\|claude\|cache` | `live` запрашивает эндпоинт с токеном аккаунта; `claude` поручает запрос Claude Code (см. ниже); `cache` показывает только сохранённые данные | `usage_source`, иначе `live` |
| `--refresh` | Обновить истёкшие токены доступа, только для аккаунтов, которые не запущены. Обновление может занять до 30 секунд | выкл. |
| `--dry-run` | Принимается: `ccam usage` не меняет ничего, кроме собственного кэша. Отклоняется вместе с `--refresh`: `--dry-run cannot be combined with --refresh, which rewrites login tokens` | выкл. |

Любое другое значение `--source` завершается ошибкой `--source must be live, claude or cache`. `ccam usage` не принимает аргументов.

### Использование от самого Claude Code

С `usage_source = "claude"` в начале `config.toml` (над первым `[[group]]`, `[[profile]]` или `[[folder]]`) или с `--source claude` ccam вообще не читает токен входа. Для каждого аккаунта он запускает `claude -p --input-format stream-json --output-format stream-json --verbose --safe-mode --no-session-persistence` в папке аккаунта и отправляет в стандартный ввод запрос Claude Code `get_usage` (Claude Code 2.1.270 или новее). Claude Code узнаёт использование через собственный вход и отвечает 5-часовым, недельным и модельными окнами.

`--safe-mode` не даёт запуститься хукам, MCP-серверам и плагинам аккаунта, и сессия не сохраняется. Каждый аккаунт требует одного запуска Claude Code (примерно секунду), поэтому этот источник медленнее `live`. Аккаунты опрашиваются одновременно, каждый с тайм-аутом 20 секунд, и 60-секундный кэш действует как обычно.

Вход, токен доступа которого истёк или истечёт в течение 5 минут, получает 50 секунд, поскольку Claude Code обновляет его при запуске, а прерванное обновление может привести к потере входа. Если ccam отказывается от запроса, он просит Claude Code завершиться через SIGTERM, чтобы Claude Code закончил начатое обновление (в Windows нет SIGTERM, поэтому там процесс принудительно завершается).

Вход, который истёк полностью, показывает `` login expired → `ccam login <name>` `` без запуска Claude Code. Claude Code помечает этот запрос как экспериментальный, поэтому, если он перестанет отвечать, ccam покажет сохранённые данные, а `ccam doctor` сообщит об этом. Когда Claude Code отвечает, что его собственный запрос не удался, ccam показывает сохранённые данные с `the usage endpoint gave Claude Code no usage (it may be refusing lookups for now)`, а не тариф без лимитов.

С `--dry-run` ccam не запускает Claude Code, потому что Claude Code пишет в папку аккаунта; вместо этого он показывает сохранённые данные. `usage_source` принимает `live` или `claude`; `cache` можно выбрать только через `--source`.

`ccam statusline` читает JSON строки состояния Claude Code из стандартного ввода. Его единственный параметр `--wrap <command>`: существующая команда строки состояния, перед первой строкой вывода которой ставится имя аккаунта. `ccam statusline install` не принимает параметров. Обе команды отклоняют `--dry-run` с сообщением `` --dry-run is not supported by `ccam statusline`; nothing was changed ``.

## Токены и стоимость: `ccam ccusage`

`ccam usage` показывает, какую часть каждого лимита использовал аккаунт. [ccusage](https://ccusage.com) же подсчитывает токены и оценочную стоимость по журналам разговоров Claude Code. Сам по себе он ищет журналы Claude Code только в `~/.claude` и `~/.config/claude` (или в папках, указанных в `CLAUDE_CONFIG_DIR`), поэтому единственный аккаунт ccam, который он может увидеть, — это аккаунт, импортированный на месте в `~/.claude`. `ccam ccusage` запускает его, задав в `CLAUDE_CONFIG_DIR` папки всех аккаунтов, в которых есть разговоры, так что один отчёт охватывает их все:

```sh
ccam ccusage                           # every account, ccusage's daily report
ccam ccusage daily --breakdown         # cost per model
ccam ccusage claude monthly --json     # Claude Code alone, as JSON
ccam ccusage -a work blocks --active   # one account's current 5-hour block
ccam ccusage -a work,side weekly       # these accounts, and any that share their history
```

Сначала ccam читает свои параметры: `-a` (`--account`) принимает имена или номера аккаунтов, через запятую или с повторением параметра, а `--dry-run` выводит команду вместо того, чтобы её выполнить. Начиная с первого другого аргумента всё передаётся в ccusage без изменений; `ccam ccusage -- --help` показывает собственную справку ccusage. ccam запускает `ccusage`, если он установлен, иначе `bun x ccusage`, а если и его нет — `npx ccusage@latest`; два последних загружают ccusage из npm. Если нет ни одного из них, ccam предлагает установить Node.js, Bun или ccusage. В Linux и macOS ccusage занимает место ccam; в Windows ccam ждёт его и завершается с его кодом выхода. В WSL ccam пропускает `ccusage`, `bun` или `npx`, лежащие на диске Windows: они запустились бы как программы Windows без папок аккаунтов.

- Отчёт охватывает аккаунты, в папках которых есть разговоры (папка `projects`). Разговор, общий для нескольких аккаунтов через группу, учитывается один раз.
- С `-a` аккаунт, у которого история разговоров общая через группу, приносит в отчёт разговоры всей группы, и ccam сообщает, чьи они: `ccam: work shares its conversation history with personal, so the report counts their conversations too`.
- `blocks` показывает 5-часовые окна, а у каждого аккаунта они свои, поэтому указывайте для него один аккаунт, как выше.
- ccusage также включает в отчёт другие найденные инструменты для программирования, например Codex, если вы не назовёте один из них: `ccam ccusage claude daily` показывает только Claude Code.
- Когда его запускает ccam, ccusage читает свои настройки (`ccusage.json`) только из `./.ccusage` и папок аккаунтов. `--config` указывает другой файл: `ccam ccusage daily --config ~/.config/claude/ccusage.json`.
- Папку, в пути которой есть запятая, ccusage прочитал бы как две папки, поэтому ccam отказывается с ней работать и называет аккаунт; исключите этот аккаунт с помощью `-a`.
- `ccusage` — команда ccam, поэтому аккаунт с именем ccusage запускается через `ccam run ccusage`; `ccam doctor` об этом сообщает.

## Как это работает

Данные, которые показывает `ccam usage`, берутся из двух источников: недокументированного эндпоинта использования Anthropic, `GET https://api.anthropic.com/api/oauth/usage`, который вызывается с собственным входом каждого аккаунта, и значений, которые Claude Code передаёт своей команде строки состояния. Весь этот код находится в `internal/usage`.

1. ccam загружает `config.toml` и строит по одному `usage.Account` на аккаунт (`cli.usageCmd`): его папка `~/.local/share/ccam/profiles/<name>/`, его метки сессий (вместе с собственными записями Claude Code в папке аккаунта они показывают, запущен ли он) и признак того, был ли он импортирован на месте.
2. ccam запрашивает все аккаунты одновременно, по одной горутине на аккаунт (`Fetcher.FetchAll`). Все они используют один `http.Client`, поэтому соединения с эндпоинтом переиспользуются. На подключение отводится до 2 с, а на каждый аккаунт всего 3 с. Клиент не переходит по перенаправлениям, так как перенаправление отправило бы токен куда-то ещё, и читает не больше 1 МБ ответа.
3. Когда аккаунт завершает запрос, его строка перерисовывается. Аккаунт, запрос которого не удался или не уложился во время, переходит на сохранённые данные, поэтому один медленный аккаунт никогда не задерживает остальные.

На схеме каждый аккаунт запрашивается в своей горутине, а тот, у которого истекло время, показывает вместо этого сохранённые данные:

<!-- motion:usage-fetch -->

`personal` и `work` отвечают вовремя и показывают актуальные данные. `side` отвечает дольше 3 с, поэтому ccam вместо этого показывает его сохранённые данные (`fallback()`). Затем ccam рисует блок для каждого аккаунта (`usage.Table()`) и выбирает аккаунт, названный в последней строке (`usage.Best()`).

Для одного аккаунта ccam выполняет проверки в таком порядке (`Fetcher.Fetch`):

<!-- motion:usage-cache -->

1. С `--source cache` он сразу переходит к `fallback()`.
2. Если не задан `--no-cache`, используется актуальный результат в `~/.local/state/ccam/usage/<name>.json`, измеренный менее 60 секунд назад (`CacheTTL`), оцениваемый на текущий момент: окно, которое с тех пор сбросилось, показывает 0%, а файл, датированный позже текущего времени часов, не считается свежим. Два запуска `ccam usage` подряд стоят одного запроса на аккаунт.
3. `readCredentials()` читает `.credentials.json` (или Связку ключей macOS), не изменяя его, и декодирует только ключ `claudeAiOauth`. Отсутствие входа по подписке означает `not logged in` или `no limits (API)`, если `.claude.json` содержит ключ API. Вход, токен обновления которого истёк или который очистил Claude Code, даёт `` login expired → `ccam login <name>` `` и не запрашивается.
4. Истёкший токен доступа не используется. Без `--refresh` аккаунт показывает сохранённые данные с ``access token expired; `ccam <name>` renews it when it starts``.
5. Иначе ccam обращается к эндпоинту. Ответ 401 или 403 считается истёкшим входом (`login expired: authentication failed (401)`), любой другой статус или нечитаемое тело ответа считаются ошибкой, и в обоих случаях используются сохранённые данные. Запрос, прерванный через Ctrl+C, сообщает `cancelled`. Ответ 429 означает, что к эндпоинту обращаются слишком часто: ccam записывает `<name>.pause` со временем следующего запроса (`Retry-After` или 5 минут, но не больше часа), показывает сохранённые данные с `rate limited by the usage endpoint; asking again after 15:10` и до этого времени не обращается к эндпоинту для этого аккаунта, даже с `--no-cache`. Немедленный повтор только продлил бы ограничение.
6. Успешный ответ записывается в `<name>.json` вместе со временем измерения.

Для сохранённых данных ccam берёт самый новый сохранённый запрос (`<name>.json` или `<name>.claude.json` из запросов через Claude Code) и, если `<name>.statusline.json` записан после него, накладывает поверх 5-часовое и недельное окна строки состояния (`fallback()`); модельные окна, которых в строке состояния нет, остаются такими, какими их сохранил запрос. Прежде чем показать сохранённые данные, он проверяет время сброса каждого окна: окно, которое сбросилось после сохранения данных, показывает 0%, потому что старый процент больше не действует. Поэтому `personal` выше показывает `0%` без времени сброса.

У эндпоинта два формата ответа. Более новый содержит массив `limits` с записями `session` (5 часов), `weekly_all` и `weekly_scoped` (по моделям). Более старый содержит объекты `five_hour`, `seven_day`, `seven_day_opus` и `seven_day_sonnet`. ccam читает оба (`ParseLive`): приоритет у массива `limits`, а старые объекты дополняют то, что он не охватывает. Тело ответа без лимитов считается изменившимся форматом, о чём сообщает `ccam doctor`.

### Запись о лимите

Когда Claude Code останавливает ход на лимите использования, хук [плагина ccam](/docs/install#claude-code-plugin) читает из разговора отклонённый запрос: какое окно заполнилось (5-часовое, недельное, Opus или Sonnet) и когда оно сбросится. Он записывает это в `~/.local/state/ccam/usage/<name>.limit.json`. ccam применяет эту запись поверх всего остального, что он знает, из любого источника (`Fetch`): каждое окно в ней считается заполненным на 100% до своего сброса, как бы ни были стары или малы сохранённые данные, поэтому `ccam next --auto`, `ccam pick`, `--fallback` и [`auto_switch`](/features/next#auto-switch) не выбирают этот аккаунт снова до этого момента.

Если больше ничего не известно, аккаунт показывает одну только запись (`source: the usage limit Claude Code reported` с `-v`). Сессии без участия пользователя (запуски `-p` и фоновые сессии) записи не создают, как и остановка, установленная организацией (например, когда у неё кончилось использование или лимит группы равен $0), которую её администраторы могут снять в любой момент. `ccam login` в другой аккаунт Claude удаляет запись; удаление файла тоже её очищает.

### Обновление токенов

Токены обновления меняются при каждом использовании: обновление выдаёт новый токен обновления и делает старый недействительным. Если бы ccam обновил вход, пока Claude Code работает от имени того же аккаунта, эта сессия вышла бы из аккаунта. Поэтому `ccam usage` читает токены и никогда их не записывает, если вы не передали `--refresh`. В этом случае ccam (`Fetcher.refresh`):

1. отклоняет аккаунты, зарегистрированные на месте через `ccam import`, поскольку обычный `claude` может использовать этот вход без ведома ccam;
2. отклоняет входы, хранящиеся в Связке ключей macOS;
3. берёт файл блокировки `~/.local/state/ccam/locks/profile-<name>.refresh.lock`, чтобы два процесса ccam никогда не обновляли один и тот же токен оба; пока она удерживается, аккаунт показывает `token not renewed: another ccam process is using this login right now (a refresh, rename, remove or logout)`. `ccam rename`, `remove` и `logout` тоже её берут и отказываются работать, пока идёт обновление;
4. под блокировкой отказывается работать, если запущена сессия аккаунта, как бы она ни была запущена (через ccam, обычным `claude`, из IDE или как фоновая сессия с демоном за ней, который сам обновляет вход), и пропускает запрос, если другой процесс уже обновил токен;
5. ничего не отправляет, пока Claude Code удерживает собственные блокировки обновления в папке аккаунта (`.oauth_refresh.lock`, `<folder>.lock`): в этот момент Claude Code сам обновляет этот вход;
6. отправляет токен обновления на эндпоинт токенов и ждёт ответа до 30 секунд — столько же, сколько Claude Code даёт своим обновлениям. Отправленный запрос никогда не прерывается, даже через Ctrl+C: сервер мог уже сменить токен обновления, и только его ответ содержит новый вход. Ctrl+C или разрыв связи завершают остальные запросы, а ccam завершается (с кодом 130 после Ctrl+C), как только ответ сохранён;
7. сохраняет под блокировкой записи Claude Code (`.storage-write.lock`) и меняет только поля токенов в `.credentials.json` в его состоянии на тот момент: то, что Claude Code записал за это время (вход MCP), остаётся, вход, который Claude Code за это время обновил, сохраняется, а выход никогда не отменяется. Когда ответ сообщает срок действия нового токена обновления, он сохраняется как `refreshTokenExpiresAt`, как это делает Claude Code.

Обновление, которое не прошло, сообщает причину в строке аккаунта или над его сохранёнными данными: например, `token not renewed: a session is running` или `login may be lost: …`, когда запрос был отправлен, но его ответ не удалось использовать или сохранить, с советом выполнить `ccam login <name>`, если Claude Code затем попросит вас войти.

### Сборщик данных строки состояния

Claude Code запускает команду строки состояния и передаёт ей через конвейер JSON-документ. ccam читает из него имя модели и `rate_limits`:

<!-- motion:usage-statusline -->

1. ccam определяет аккаунт по `CCAM_PROFILE`, который ccam задаёт при запуске Claude Code, а иначе сопоставляет `CLAUDE_CONFIG_DIR` с папками аккаунтов (`runStatusline`).
2. ccam читает `rate_limits.five_hour` и `rate_limits.seven_day` (`ParseStatusLine`). Для аккаунтов с ключом API, а также до первого ответа в сессии, в JSON нет лимитов; тогда ничего не сохраняется.
3. ccam записывает `~/.local/state/ccam/usage/<name>.statusline.json` (`SaveStatusLine`). `ccam usage` использует его, когда эндпоинт не отвечает.
4. ccam выводит `[name] · model · 5h N% · 7d N%`. С `--wrap` он запускает вашу команду через `sh -c` с тем же вводом и выводит её вывод так, как Claude Code показывает строку состояния: каждую непустую строку, с `[name]` перед первой. Если команда завершилась ошибкой, показывается только имя аккаунта. В Windows он запускает команду так же, как Claude Code: через Git Bash, если он установлен, иначе через PowerShell.
5. Когда использование за 5 часов или за неделю составляет 90% или больше и есть другой аккаунт, строка заканчивается на `→ ccam next --auto --continue`, например `[work] · Opus · 5h 93% · 7d 41% · → ccam next --auto --continue`.

У обёрнутой команды нет собственного ограничения времени: Claude Code даёт команде строки состояния 10 минут и останавливает запуск, когда начинается более новое обновление, поэтому медленная команда отображается так же, как без ccam. Когда Claude Code завершает ccam, команда тоже завершается (в Linux и macOS — вместе со всеми запущенными ею процессами).

`ccam statusline install` записывает `statusLine` в `settings.json` каждого аккаунта и сохраняет другие ключи объекта, например `padding`, `refreshInterval` и `hideVimModeIndicator`. Если у аккаунта уже есть команда строки состояния, ccam сохраняет её как `--wrap '<old command>'`, а в Windows — как `--wrap-base64 <base64>`, что не требует кавычек ни в одной оболочке. Если строка состояния уже запускает ccam (по другому пути или в кавычках так, как записывала более старая версия), ccam заменяет её, а не оборачивает, и сохраняет команду, которую она оборачивает.

В Windows путь к ccam записывается с прямыми косыми чертами и `~` вместо домашней папки (`~/.local/bin/ccam.exe statusline`), что понимают и Git Bash, и PowerShell. Путь, которому нужны кавычки, записывается полностью для оболочки, которую использует Claude Code: `'…'` для Git Bash, `& '…'` для PowerShell. `settings.json`, общий через группу, записывается один раз через его ссылку, поэтому его получает каждый аккаунт группы. Повторный запуск выводит `(already set)` для файлов, которые уже используют ccam.

## Безопасность и особые случаи

- `ccam usage` никогда не меняет файл токенов, если вы не передали `--refresh`. Если истёк токен доступа, запустите аккаунт один раз командой `ccam <name>`, и Claude Code обновит его. Входу, который истёк полностью, нужен `ccam login <name>`.
- `--refresh` никогда не трогает запущенные аккаунты (в том числе когда Claude Code запущен без ccam), импортированные аккаунты и входы из Связки ключей. При отказе в обновлении показываются сохранённые данные и причина (`token not renewed: …`).
- Эндпоинт использования публично не документирован и может измениться. В этом случае вы всё равно увидите сохранённые данные, а `ccam doctor` сообщит об изменении формата.
- Если сохранённых данных нет и ответа нет, строка аккаунта показывает `lookup failed:` и причину, например `no saved usage` с `--source cache`.
- Файлы кэша содержат только проценты и время сброса, но никогда не токены.
