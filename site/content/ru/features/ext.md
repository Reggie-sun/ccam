`ccam ext` отвечает на вопрос «почему этот навык (или MCP-сервер) работает в одном аккаунте и не работает в другом?». Для каждого аккаунта он перечисляет расширения, которые загружает Claude Code, и откуда берётся каждое из них: из группы общего доступа, из собственной папки аккаунта или из проекта, в котором вы находитесь. Под таблицей он перечисляет то, что мешает расширению загружаться так, как вы ожидаете. Он только читает.

## Использование

```sh
ccam ext              # every account
ccam ext work         # one account
ccam ext --json       # for scripts
```

```console
$ ccam ext
Skills
          personal   work
  half    account !  -
  review  -          default

Commands
          personal  work
  deploy  default   default

MCP servers
       personal   work
  ctx  default !  default

Hooks (commands per event)
              personal     work
  PreToolUse  1 (default)  1 (default)

This project (/home/me/code/app):
  commands: ship
  MCP servers: fs

Sources: a group name (shared), account (its own folder), local (its own, for this folder only), - (not loaded); (off): installed, not turned on.
! personal: MCP server ctx is defined differently in group default's mcp.json and .claude.json
! personal: half: no SKILL.md, so Claude Code does not load it
```

Ячейка называет источник этого элемента в этом аккаунте: группу общего доступа (`default`), `account`, если элемент лежит в собственной папке аккаунта, `local` для MCP-сервера, который есть у аккаунта только для этой папки, или `-`, если у аккаунта его нет. Плагин, который установлен, но не включён, показывает `(off)` после источника. `!` отмечает элемент с проблемой, которая объясняется под таблицей; проблемы, не относящиеся ни к одному аккаунту, например серверы, которые есть только у обычного `claude`, идут последними без имени. `ccam ext --json` выводит тот же отчёт (`accounts`, проект, `problems`), с `remote` у MCP-серверов, к которым Claude Code обращается по сети; без аккаунтов он выводит отчёт с `accounts: []`.

## Что он читает

| Вид | Где | Показанный источник |
| --- | --- | --- |
| Навыки | каждая папка в `skills/` с `SKILL.md` | группа, на которую ссылается `skills/`, или `account` |
| Команды, агенты | файлы `.md` в `commands/` и `agents/`, подпапки как `folder/name` | группа или `account` |
| Плагины | `plugins/installed_plugins.json`, включаются или выключаются через `enabledPlugins` в настройках аккаунта и проекта; плагин, установленный только для одного проекта, появляется только в этом проекте | группа или `account`; `(off)`, если не включён |
| MCP-серверы | `mcp.json` группы (если MCP общий), `.claude.json` аккаунта (его собственные серверы и те, что есть у него только для этой папки) и серверы его плагинов в виде `plugin:<plugin>:<server>` | группа, `account` или `local` |
| Хуки | `hooks` в `settings.json`, с подсчётом по событиям | группа или `account` |
| Этот проект | `.claude/skills`, `.claude/commands`, `.claude/agents`, `.claude/settings.json`, `.claude/settings.local.json` и `.mcp.json` в текущей папке | выводится один раз; аккаунт, который не доверяет папке, получает проблему для серверов её `.mcp.json` |

## Какие проблемы он сообщает

- **Сломанные ссылки**: ссылка в `skills/`, `commands/` или `agents/`, цель которой пропала, или общая папка (`skills`, `commands`, `agents`, `plugins`), которая ссылается на несуществующее место (исправьте это командой `ccam doctor --fix`, которая заново создаёт отсутствующую папку группы).
- **Папка навыка без `SKILL.md`**: Claude Code её пропускает.
- **MCP-сервер, по-разному определённый в двух местах**: в `mcp.json` группы и в `.claude.json` аккаунта или в одном из них и в `.mcp.json` проекта. Одинаковые настройки в обоих местах (их записывает `mcp_strategy = "sync"`) проблемой не считаются. Перенесите собственный сервер аккаунта в группу командой `ccam mcp import <account> <server>`.
- **`installed_plugins.json`, который не является корректным JSON**, плагин, который не назван в `enabledPlugins`, и плагин, папка которого отсутствует.
- **Серверы, которые загружает только один аккаунт**: сервер только в `.claude.json` этого аккаунта, который не загружают остальные аккаунты его группы, и сервер в локальной области аккаунта для этой папки (так делает `claude mcp add` без `-s user`). Для каждого указывается команда `ccam mcp import`, которая делает его общим. Для серверов в `~/.claude.json` обычного `claude`, которые не загружает ни один аккаунт, указывается команда `ccam migrate --mcp`.
- **Сервер проекта, ожидающий одобрения**: аккаунт ещё не доверяет папке, поэтому Claude Code один раз спрашивает, а до тех пор серверы `.mcp.json` проекта ждут. Проблема сообщает, где их одобрить: `"enabledMcpjsonServers"` в `settings.json` аккаунтов группы настроек или этого аккаунта. Доверие, данное основному рабочему дереву git-репозитория, действует и в других его рабочих деревьях.
- **Входы и коннекторы**: MCP-сервер, которому в этом аккаунте нужен вход, хотя другой аккаунт в него вошёл (вход действует только для одного аккаунта; войдите через `/mcp`), и коннекторы claude.ai, которыми пользовался другой аккаунт, а этот нет.

## Безопасность и особые случаи

- `ccam ext` ничего не меняет и не выполняет сетевых запросов. Он читает имена серверов и количество хуков, но никогда не читает значения `env` или заголовков в определениях MCP. Для проверки входов он читает названия входов MCP в данных входа каждого аккаунта (в macOS из Связки ключей), но никогда не токены, и только для аккаунтов, которые загружают сервер, загружаемый и другим аккаунтом.
- Он показывает то, что лежит на диске. Сервер, заблокированный управляемыми настройками, всё равно отображается; плагин, выключенный в настройках, показывает `(off)`.
- Запустите его в папке проекта, чтобы включить папку `.claude` и `.mcp.json` этого проекта.
