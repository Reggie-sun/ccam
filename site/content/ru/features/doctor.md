`ccam doctor` проверяет вашу установку ccam: исполняемый файл Claude Code, папку, вход и ссылки общего доступа каждого аккаунта, общие MCP-серверы, эндпоинт использования и ваши короткие команды. `ccam doctor --fix` исправляет то, что можно исправить без потери данных, и предварительно перемещает каждый заменяемый файл в папку резервных копий. Запускайте его, когда `ccam <name>` останавливается из-за проблемы со ссылкой общего доступа, после того как вы восстановили файлы вручную, или после обновления Claude Code.

## Использование

```sh
ccam doctor                  # check everything, change nothing
ccam doctor --fix            # check, then repair what is safe to repair
ccam --dry-run doctor --fix  # report only: what --fix would repair and set aside
```

Первая строка сразу отмечает все аккаунты, поэтому вы видите, где проблемы, ещё до того, как прочтёте что-то другое. Под ней у каждого аккаунта своя рамка, а результаты, не относящиеся ни к одному аккаунту (Claude Code, переменные окружения, плагины, MCP-серверы, короткие команды, правила папок, группы и настройки, `auto_switch`), попадают в рамку `General`. В заголовке рамки указаны худшая отметка аккаунта и число его проблем. Каждая строка внутри соответствует одной проверенной области, всегда сначала `Folder`, `Login` и `Share links` в этом порядке, затем остальные, с отметкой: `✔` всё в порядке, `ℹ` информация, `⚠` предупреждение, `✘` ошибка. Папка без проблем показывает `✔ Folder  OK`.

```console
$ ccam doctor
```

В терминале рамки подстраиваются под ширину терминала, длинные сообщения переносятся, а используются собственные цвета терминала (`NO_COLOR` отключает их). Рамка никогда не бывает уже 29 столбцов, поэтому в узком терминале ни одно слово не обрезается. При выводе в конвейер или файл цветов нет и ни одно сообщение не переносится и не обрезается, поэтому `ccam doctor | grep settings.json` находит строку целиком; каждая рамка тогда имеет ширину самой длинной строки. Вкладка Health панели показывает те же рамки.

## Параметры

| Параметр | Действие | По умолчанию |
| --- | --- | --- |
| `--fix` | Исправить то, что безопасно исправить (для изменённых файлов создаются резервные копии) | выкл. |
| `--dry-run` (глобальный) | Выполнить все проверки, но ничего не исправлять, даже с `--fix` | выкл. |

`ccam doctor` не принимает аргументов. Он поддерживает `--dry-run`: `ccam --dry-run doctor --fix` выводит результаты `ccam doctor`, добавляет то, что `--fix` отложил бы в сторону, и ничего не меняет:

```text
ℹ settings.json differs from the group's copy: --fix would use the group's, and move this account's copy to /home/me/.local/share/ccam/profiles/personal/.ccam-backup/20261023-212543/settings.json
```

Код возврата равен `1`, если остался хотя бы один неисправленный результат `✘`, и `0` в остальных случаях. Предупреждения и информация никогда не приводят к ошибке. Если запуск без `--fix` завершился ошибкой, ccam в конце выводит пустую строку и `` `ccam doctor --fix` repairs what it can. ``. Если конфигурацию не удаётся загрузить, команда также завершается с `1` и ошибкой `ccam:`.

## Как это работает

Проверки выполняются в фиксированном порядке, а результаты выводятся в одной рамке на аккаунт. ccam загружает `~/.config/ccam/config.toml` (`internal/cli/doctor.go`) и выполняет проверки; каждый результат называет аккаунт, к которому он относится, и проверенную область (`doctor.Run` в `internal/doctor/doctor.go`). Затем он группирует результаты в рамки (`tui.HealthReport`). `--fix` передаётся как `Options.Fix`, а в пробном запуске устанавливается в false.

<!-- motion:doctor-checks -->

Средний блок выполняется один раз для каждого аккаунта. Проверки и то, что делает `--fix` для каждой из них:

1. **Версия Claude Code** (`checkClaude`). Находит исполняемый файл `claude` так же, как это делает запуск, и выполняет `claude --version`. Отсутствующий исполняемый файл, `claude_bin`, который не является исполняемым файлом, или ошибка `--version` считаются ошибкой. Не исправляется.
2. **Данные входа в окружении** (`checkAuthEnv`). Предупреждает, если задана `CLAUDE_CODE_OAUTH_TOKEN`, `ANTHROPIC_API_KEY` или `ANTHROPIC_AUTH_TOKEN`: каждый аккаунт, запущенный из этой оболочки, наследует её, и Claude Code предпочитает её собственному входу аккаунта. Не исправляется; удалите переменную сами.
3. **Папка** (`checkProfile`). Отсутствующая папка аккаунта считается ошибкой и завершает проверки этого аккаунта. Права, в которых установлены биты группы или остальных, дают предупреждение; `--fix` выполняет `chmod 0700`. Импортированная `~/.claude` с собственным `.claude.json` рядом с `~/.claude.json` даёт информацию: тогда `ccam main` и обычный `claude` хранят раздельные данные входа и MCP-серверы. В Windows нет битов прав, поэтому там эта проверка и проверка `0600` ниже пропускаются; папку в вашем профиле пользователя защищает её список доступа.
4. **Файл входа** (`checkCredentials`). `.credentials.json` проверяется через `lstat`. Символическая ссылка считается ошибкой, потому что у каждого аккаунта должен быть собственный токен, и не исправляется. Права, отличные от `0600`, дают предупреждение; `--fix` выполняет `chmod 0600`.

   Затем читается вход (в macOS сначала из Связки ключей). Отсутствующий вход или файл входа, в котором нет входа, дают предупреждение со ссылкой на `ccam login <name>`. Истёкший токен обновления или вход, который Claude Code очистил после того, как сервер его отклонил, дают ошибку `` login expired → `ccam login <name>` ``; истёкший токен доступа считается только информацией, так как Claude Code обновит его при следующем запуске. Вход, хранящийся в диспетчере учётных данных Windows, даёт информацию, поскольку ccam не может его прочитать. Действующий вход показывает email, под которым папка вошла сейчас, и тариф (`login valid (dev@company.com, Claude Team · Acme)`). Ничего из этого не исправляется; `ccam login --expired` выполняет вход во все аккаунты, которым он нужен.
5. **Ссылки общего доступа** (`share.Check`). Сравнивает каждый путь в `share.Layout` с группами аккаунта, используя только `lstat` и `readlink`. Сообщает о пяти видах проблем: отсутствующая ссылка, ссылка, указывающая в другое место, настоящий файл там, где должна быть ссылка, оставшаяся ссылка для элемента, который теперь локальный, и правильная ссылка, папка группы которой отсутствует (`the group folder it links to is missing (…), so Claude Code cannot save there (ccam doctor --fix makes it)`; запуск это не проверяет). Отсутствующая ссылка и отсутствующая папка группы дают предупреждения, остальные случаи считаются ошибками.

   Сообщается и о копировании обратно из группы, остановившемся на полпути: `--fix` ставит на место полную подготовленную копию, но если с тех пор запуск заново создал путь, он называет папку с полной копией, чтобы вы разобрались сами. Пути, добавленные к элементу в более поздней версии ccam (`file-history/`, `tasks/` и `paste-cache/` для истории, `keybindings.json` для настроек), дают только предупреждение, пока у аккаунта ещё есть собственная копия: `is not shared with the group yet (ccam doctor --fix shares it; if the group has its own copy, that one is kept and this one backed up)`. Запуск из-за них никогда не останавливается.
6. **Неизвестные записи** (`checkUnknownEntries`). Перечисляет имена верхнего уровня в папке аккаунта, которых ccam не знает (`share.Known`), как подсказку, что структура Claude Code изменилась. Только информация.
7. **Пути плагинов** (`checkPlugins`). Реестры плагинов (`installed_plugins.json`, `known_marketplaces.json`) хранят абсолютные пути. В `plugins/` каждой группы пути, проходящие через папку одного аккаунта, ломаются, когда этот аккаунт удаляют или переименовывают. `--fix` переписывает их на папку группы через `profile.RewritePluginPaths`, атомарно записывая файл реестра.
8. **MCP-серверы** (`checkMCP`). Загружает `mcp.json` каждой группы один раз. Файл, который не удаётся прочитать, считается ошибкой; сервер, не прошедший `mcp.Validate`, даёт предупреждение. Серверы в `~/.claude.json` обычного `claude`, которые не загружает ни один аккаунт, дают предупреждение с командой `ccam migrate --mcp`, которая их копирует (с `--group <a|b>`, когда MCP делят несколько групп). Серверы, которые есть только у одного аккаунта группы, дают информацию с командой `ccam mcp import`, которая делает их общими, а аккаунт, не вошедший в MCP-серверы, в которые вошли другие аккаунты, получает предупреждение войти через `/mcp` (ccam никогда не копирует данные входа). Не исправляется.
9. **Формат ответа об использовании** (`checkUsageFormat`). Запрашивает эндпоинт использования без кэша для одного аккаунта за другим, пока какой-нибудь не ответит, в пределах одного общего тайм-аута в 4 секунды. С `usage_source = "claude"` вместо этого он запрашивает Claude Code для одного аккаунта. Если ответ больше не разбирается, выводится предупреждение, что `ccam usage` переходит на кэш строки состояния; если не ответил ни один аккаунт, он сообщает об этом как информацию (`could not check the usage response format: …`). Это единственная проверка, которая обращается к сети.
10. **Короткие команды** (`checkShims`). Только если у аккаунта есть короткая команда. Отсутствующие ссылки в `~/.local/bin` дают предупреждение, как и созданные ccam короткие команды, которые всё ещё запускают более старую версию ccam, заменённую или перемещённую (`shortcuts in <bin> that run another ccam (one replaced or moved): …`); `--fix` вызывает `shim.Install`, который создаёт и обновляет только ссылки, созданные ccam и записанные в `~/.local/state/ccam/shortcuts.json`, и никогда не трогает другие файлы. Предупреждение заканчивается на `→ fixed`, только если каждая из этих ссылок создана; если какую-то создать не удалось, добавляется причина. Короткая команда, которая запускает другой ccam, всё ещё установленный, работает, поэтому `ccam doctor` показывает её только как информацию; `--fix` направляет её на этот исполняемый файл ccam. Папка bin, которой нет в `PATH`, даёт предупреждение и не исправляется.
11. **Папки** (`checkFolders`). Только если есть записи [`ccam folder`](/features/folder). Запись, аккаунт которой не существует, считается ошибкой, а запись, папки которой больше нет, даёт предупреждение. Ни то, ни другое не исправляется, потому что удаление записи изменило бы, какой аккаунт там запускается.
12. **Группы и настройки** (`checkGroups`). Участник группы, который не является аккаунтом, аккаунт, чьё имя с тех пор стало командой ccam (запускайте его через `ccam run <name>` или переименуйте), неизвестные `theme` или `usage_source`, а также строки `config.toml`, которые ccam не читает, дают предупреждения. Последние — обычно настройка, размещённая под таблицей `[[group]]`, `[[profile]]` или `[[folder]]`, из-за чего она становится частью этой таблицы (`config.toml line 43: relay is read as part of the [profile.login] table above it; settings for all accounts go above the first [[group]], [[profile]] or [[folder]]`); команды, которые меняют конфигурацию, отказываются работать, пока это не исправлено. Не исправляется.
13. **Входы** (`checkIdentities`). Читает из `.claude.json` каждой папки, под каким аккаунтом выполнен вход. Папка, в которой теперь выполнен вход в другой аккаунт, а не в тот, который записал `ccam login` (например, после `/login` внутри сессии), даёт предупреждение; аккаунт без записи о входе, например импортированный или созданный более старой версией ccam, сравнивается по записанному email. Папка, вошедшая в тот же аккаунт Claude, что и другая, тоже даёт предупреждение: у них общие лимиты использования. Папка, содержащая тот же токен входа, что и другая, то есть скопированная папка (включая `~/.claude` обычного `claude`), считается ошибкой, поскольку тот, кто обновит его первым, выведет другого из системы; выполните `ccam login <name>`, чтобы дать ей собственный вход. Не исправляется.
14. **`auto_switch`** (`checkAutoSwitch`). Только при `auto_switch = true`. Информация в рамке `General` сообщает, что делает `auto_switch`, и ссылается на [его описание](/features/next#auto-switch). Для каждого тарифа с местами среди аккаунтов (Claude Team, Claude Enterprise) отдельная строка называет эти аккаунты, сообщает, что `auto_switch` переносит сессию между местами одной организации, цитирует правило Anthropic о местах со ссылкой на справочный центр и оставляет решение за вами. Версии Claude Code старше 2.1.214, которые не сообщают хукам свой процесс (`CLAUDE_PID`), дают там предупреждение, поскольку ни одну сессию перенести нельзя.

    Аккаунт без плагина ccam или с выключенным плагином получает предупреждение в собственной рамке с командой, которая исправляет это в Claude Code: `auto_switch is on, but work does not have the ccam plugin, so its sessions are not moved. In Claude Code as work: /plugin install ccam --marketplace jhyunwoo/ccam` (или `/plugin enable ccam@ccam`). Аккаунты с ключом API не учитываются. В Windows выводится только строка `auto_switch is ignored on Windows; with relay = true, /ccam:switch followed by /exit still moves a conversation to another account.` Не исправляется.

Перед аккаунтами **изменение групп**, остановившееся на полпути, даёт ошибку в рамке `General`: ``the last group change stopped halfway (ccam doctor --fix finishes it; noted in ~/.local/state/ccam/group-change.json)``. `--fix` завершает его в запланированном порядке, с ответами, данными на его конфликты; до этого не начинается ни другое изменение групп, ни переименование, ни удаление. Пока оно не завершено, ccam только создаёт отсутствующие ссылки для затронутых аккаунтов. Если завершить его невозможно, ошибка сообщает, что удаление этого файла отменяет остаток изменения.

`ccam --dry-run doctor --fix` показывает порядок (`--fix finishes it in its order (b, a, c), with the answers given to its conflicts`) и то, что часть каждого аккаунта отложила бы в сторону. Изменение групп, которое прямо сейчас выполняет другой процесс ccam, даёт информацию, и пока оно идёт, `--fix` не исправляет ссылки общего доступа (`its share links are not repaired while another ccam changes the groups; …`). `--fix` держит `~/.local/state/ccam/group-change.lock`, пока исправляет, и заново читает `config.toml` после завершения изменения.

### Исправление ссылок общего доступа

При запуске отсутствующая ссылка создаётся на месте, но всё, что может привести к потере данных, останавливает запуск и отправляет сюда:

```console
$ ccam work
ccam: stopped because of share link problems:
  /home/me/.local/share/ccam/profiles/work/CLAUDE.md: set to shared but is a real file, not a link
Repair them with `ccam doctor --fix`, then run again
```

При любой проблеме со ссылкой общего доступа `--fix` вызывает `share.Build`, передавая настройки общего доступа аккаунта и как текущее, и как целевое состояние, а затем `Plan.Apply`. ccam заново выводит каждый шаг из того, что находится на диске (`Build`), и получает тот же план, что и изменение через `ccam group`, поэтому исправление следует тем же правилам, что и вступление в группу.

<!-- motion:doctor-repair -->

Здесь `settings.json` является настоящим файлом. Поскольку в группе уже есть другой `settings.json`, для конфликта выбирается вариант по умолчанию, `keep group` (`KeepGroup` на схеме), и копия группы остаётся. Файл аккаунта перемещается в `.ccam-backup/<time>/settings.json` внутри папки аккаунта, а ccam связывает путь с группой (`os.Symlink`). `--fix` сообщает об этом: `settings.json differed from the group's copy, which it now uses; this account's copy is in …`. Другие случаи:

- Если у группы ещё нет копии, файл аккаунта перемещается в группу и становится её первым содержимым.
- Для папки файлы, которых нет в группе, перемещаются в группу. Файлы, идентичные копии группы, удаляются, а отличающиеся попадают в резервную копию и называются в заметке (`projects: 1 file differs from the group's copy (-w/memory/MEMORY.md); the group's is kept, the account's stays in …`).
- Отсутствующая папка группы сначала создаётся.
- Для `history.jsonl` по умолчанию используется `merge by line`: строки группы, затем ваши новые строки. Прежняя копия группы сохраняется в `.ccam-backup/<time>/group/`.
- Ссылка на другую группу заменяется. Ссылка на папку вне ccam попадает в резервную копию, а её содержимое становится начальным содержимым группы, если группа пуста.
- Оставшаяся ссылка для элемента, который теперь локальный, удаляется, и аккаунт получает копию содержимого группы.

Кроме удаления ссылок и удаления файлов, идентичных копии группы, каждый шаг перемещает данные в группу или в папку резервных копий. Ничего не теряется.

## Безопасность и особые случаи

- Обычный `ccam doctor` никогда ничего не меняет. В скриптах для надёжности используйте `--dry-run` вместе с `--fix`.
- Для запущенного аккаунта, как бы ни был запущен Claude Code, `doctor --fix` только создаёт отсутствующие ссылки и отсутствующие папки групп, что ничего не теряет. Если остаётся что-то ещё, он добавляет `` is running; quit Claude Code there, then run `ccam doctor --fix` again to repair the rest ``, потому что сессия продолжает записывать в файлы, которые исправление переместило бы.
- Если исправить общий доступ не удалось, ccam сообщает `could not repair share links: <error>` для этого аккаунта и пропускает для него проверку неизвестных записей. Остальные аккаунты всё равно проверяются.
- Если изменение через `ccam group` прерывается на середине, новые группы уже сохранены, а изменение записано в `~/.local/state/ccam/group-change.json`; ccam предлагает завершить работу командой `ccam doctor --fix`, которая выполняет его остаток, включая шаги MCP.
- О символической ссылке на `.credentials.json`, истёкшем входе и данных входа в окружении сообщается, но они никогда не изменяются.
- Перезапись реестров плагинов выполняется атомарно, но не копируется в `.ccam-backup/`.
