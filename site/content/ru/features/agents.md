Claude Code хранит фоновые сессии (`claude --bg`, просмотр агентов) отдельно для каждого аккаунта: `claude agents` показывает только сессии того аккаунта, от имени которого он запущен. `ccam agents` одновременно опрашивает все аккаунты и выводит их сессии вместе, а `ccam attach <id>` открывает фоновую сессию от имени того аккаунта, который её запустил.

## Использование

```sh
ccam work --bg "fix the flaky test"   # start one in the background, as work
ccam agents                           # every account's sessions
ccam agents --all                     # also finished background sessions
ccam agents --json                    # for scripts
ccam attach 49ec0028                  # open it, as the account that started it
ccam attach 49ec                      # a unique start of the id is enough
```

```console
$ ccam agents
Account   ID        Name   State           Folder      Started
work      -         -      open (busy)     ~/code/web  just now
personal  49ec0028  probe  blocked, idle   ~/code/app  12m ago
Open a background session with `ccam attach <id>`.
```

`State` показывает состояние фоновой сессии (`working`, `blocked`, `done`, `failed`, `stopped`) и то, чем занят её процесс (`busy`, `waiting`, `idle`); открытая интерактивная сессия показывается как `open`.

## Параметры

| Параметр | Действие | По умолчанию |
| --- | --- | --- |
| `--all` | Показывать также фоновые сессии, которые завершены, завершились ошибкой или остановлены | выкл. |
| `--json` | Вывести сессии в формате JSON, каждую с аккаунтом (`account`), которому она принадлежит | выкл. |

`ccam attach <id> [claude args]` передаёт аргументы после идентификатора в `claude attach`. С `--dry-run` он выводит команду.

## Как это работает

1. Для каждого аккаунта ccam запускает `claude agents --json` (с `--all`, если он указан) с `CLAUDE_CONFIG_DIR` аккаунта, для всех аккаунтов одновременно, на каждый не дольше 15 секунд. Так читается собственный список сессий аккаунта, а фоновая служба Claude Code не запускается.
2. Каждая запись получает имя аккаунта, а список сортируется по времени запуска, сначала новые. Аккаунт, который не ответил, называется в стандартном потоке ошибок и не попадает в список, а ccam затем завершается с кодом 1, чтобы скрипт не принял ошибку за пустой список.
3. `ccam attach` ищет `jobs/<id>` в папке каждого аккаунта, где Claude Code хранит фоновую сессию, и запускает `claude attach <id>` от имени этого аккаунта так же, как `ccam <name>` запускает Claude Code.

## Безопасность и особые случаи

- Идентификаторы фоновых сессий принадлежат одному аккаунту: `claude attach`, запущенный от имени другого аккаунта, не может их найти, и именно эту проблему решает `ccam attach`.
- У двух аккаунтов могут оказаться сессии, идентификаторы которых начинаются одинаково; тогда `ccam attach` называет обе и просит указать идентификатор подробнее.
- ccam передаёт свои общие MCP-серверы в Claude Code через `--mcp-config=<file>` одним аргументом, который принимают `claude agents` и `claude attach`; фоновые сессии продолжают использовать этот файл при перезапуске.
- Фоновая служба аккаунта с ключом API берёт ключ из оболочки, которая её запустила. Запускайте первую фоновую сессию такого аккаунта через ccam (`ccam gw --bg …`), чтобы у службы был ключ.
