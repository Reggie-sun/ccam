`ccam update` скачивает выпуск ccam с GitHub, проверяет его по `checksums.txt` выпуска и заменяет работающий исполняемый файл одним переименованием. Используйте его, если вы установили ccam скриптом установки или из архива. [Панель](/features/dashboard) тоже запрашивает у GitHub последний выпуск при каждом открытии и предлагает его по `U`, что после вопроса выполняет те же шаги. Другие команды никогда не обращаются к GitHub, поэтому они работают без сети точно так же.

## Использование

```sh
ccam update                    # install the latest release
ccam update --check            # only say whether a newer release exists
ccam update --version v0.3.0   # install that release, even an older one
ccam --dry-run update          # show what would be downloaded and replaced
```

```console
$ ccam update --check
ccam 0.5.0 is available (you have 0.4.0). Run `ccam update`.
$ ccam --dry-run update
Would update ccam 0.4.0 → 0.5.0:
  download  https://github.com/jhyunwoo/ccam/releases/download/v0.5.0/ccam_linux_amd64.tar.gz
  verify    with https://github.com/jhyunwoo/ccam/releases/download/v0.5.0/checksums.txt
  replace   /home/you/.local/bin/ccam
$ ccam update
→ downloading https://github.com/jhyunwoo/ccam/releases/download/v0.5.0/ccam_linux_amd64.tar.gz
✓ Updated ccam 0.4.0 → 0.5.0 (/home/you/.local/bin/ccam)
```

Если более нового выпуска нет, ccam выводит `ccam 0.4.0 is up to date.` и ничего не меняет. Если `--version` указывает версию, которая у вас уже установлена, выводится `ccam 0.4.0 is already installed.`

## Параметры

| Параметр | Действие | По умолчанию |
| --- | --- | --- |
| `--check` | Только сообщить, есть ли более новый выпуск | выкл. |
| `--version <tag>` | Установить этот тег выпуска, например `v0.3.0`, новее или старше текущего | последний |
| `--dry-run` | Поддерживается: находит последний тег (если `--version` не указывает другой), выполняет те же проверки исполняемого файла и выводит пути загрузки, контрольной суммы и замены, ничего не скачивая | выкл. |

`--check` и `--version` нельзя использовать вместе. Тег должен иметь вид `vMAJOR.MINOR.PATCH` с необязательным суффиксом предварительного выпуска или сборки; начальную `v` можно опустить. Всё остальное завершается ошибкой, например `--version takes a release tag such as v0.3.0, not "1.2"`.

Переменная окружения `CCAM_RELEASES_URL` заменяет `https://github.com/jhyunwoo/ccam/releases`, например для зеркала или для тестов. Структура должна быть такой же: `<url>/latest` перенаправляет на `<url>/tag/<tag>`, а файлы выпуска находятся по адресу `<url>/download/<tag>/<asset>`.

## Как это работает

ccam проверяет загрузку, прежде чем трогать установленный исполняемый файл, и заменяет его одним переименованием. Код находится в `internal/update`, который импортирует только `ccam update`. Путь запуска никогда его не вызывает.

1. ccam находит работающий исполняемый файл через `os.Executable` и разрешает символические ссылки через `filepath.EvalSymlinks` (`cli.updateCmd`). Заменяется именно этот реальный путь.
2. Без `--version` ccam запрашивает `<releases>/latest`, не переходя по перенаправлению (`Updater.Latest`), и читает тег из заголовка `Location` (`…/tag/v0.5.0`). Используется страница выпусков, а не GitHub API, поэтому ограничение API в 60 запросов в час не действует. Поиск прерывается по тайм-ауту через 10 секунд.
3. ccam проверяет тег по строгому шаблону (`parseVersion`). Тег попадает в адреса загрузки и в выводимую команду оболочки, поэтому ничто с `/`, `%`, пробелами или символами оболочки не проходит. Затем ccam сравнивает его с работающей версией (`compareVersions`); предварительный выпуск считается более ранним, чем сам выпуск.
4. ccam решает, может ли он вообще заменить исполняемый файл (`managed()`, `writable()`; см. ниже).
5. ccam одновременно скачивает `ccam_<os>_<arch>.tar.gz` (в Windows `ccam_windows_<arch>.zip`) и `checksums.txt`, отводя на обе загрузки 2 минуты (`Updater.Fetch`). Каждая загрузка ограничена 256 МБ.
6. SHA-256 архива должен совпасть с его строкой в `checksums.txt`, прежде чем произойдёт что-либо ещё. Отсутствующая строка или другая контрольная сумма останавливают обновление с сообщением `nothing was changed`.
7. ccam читает tar и берёт первый обычный файл с именем `ccam` (`extract()`; `extractZip` берёт `ccam.exe` из zip). Папки, ссылки и другие записи игнорируются, а исполняемый файл тоже ограничен 256 МБ.
8. ccam записывает новый исполняемый файл через `fsutil.AtomicWrite` (`Updater.Install`): временный файл `.ccam.tmp*` рядом с исполняемым файлом, с битами прав старого файла, сбрасывается на диск и переименовывается поверх старого.

Архив и `checksums.txt` скачиваются параллельно, и ничего не записывается, пока контрольная сумма не совпадёт. Переименование атомарно, поэтому сбой или заполненный диск оставляют либо старый исполняемый файл, либо новый, но никогда не половину. Короткие команды, например `~/.local/bin/ccwork`, являются символическими ссылками на исполняемый файл ccam, поэтому они запускают новую версию без каких-либо изменений.

В Windows файл работающей программы нельзя заменить или удалить, только переименовать. ccam записывает новый исполняемый файл в `ccam.exe.new`, переименовывает работающий `ccam.exe` в `ccam.exe.old`, а новый файл — в `ccam.exe` (`Updater.Install`). Если последний шаг не удался, старый исполняемый файл переименовывается обратно. Следующее обновление удаляет те файлы `ccam.exe.old`, которые может; пока сессия ещё работает из более раннего `ccam.exe.old`, работающий исполняемый файл вместо этого становится `ccam.exe.old-<time>`. Короткие команды, которые являются жёсткими, а не символическими ссылками ([Короткие команды](/features/shortcuts)), обновляются сразу после этого, поэтому они тоже запускают новую версию; это касается созданных ccam жёстких ссылок на любую более старую версию ccam, а не только на только что заменённый исполняемый файл.

### Установка из пакета

Копия ccam, установленная из `.deb`, принадлежит apt, и если заменить её в обход apt, база данных пакетов перестанет соответствовать файлу. Перед загрузкой ccam проверяет, кому принадлежит исполняемый файл:

<!-- motion:update-managed -->

1. Исполняемый файл в `/usr/bin`, `/bin`, `/usr/sbin` или `/sbin` считается управляемым пакетным менеджером.
2. В остальных местах, если установлен `dpkg` и `dpkg -S <path>` выполняется успешно, файл тоже считается управляемым пакетным менеджером.
3. Иначе ccam создаёт и удаляет временный файл `.ccam-update-*` рядом с исполняемым файлом, чтобы убедиться, что может туда записывать.

Для исполняемого файла, управляемого пакетным менеджером, ccam останавливается и выводит шаги для apt:

```console
$ ccam update
ccam: /usr/bin/ccam was installed by a package, so `ccam update` leaves it alone.
To update the .deb, download ccam_0.5.0_linux_amd64.deb from https://github.com/jhyunwoo/ccam/releases/tag/v0.5.0 and run:
  sudo apt install ./ccam_0.5.0_linux_amd64.deb
Or install a copy in ~/.local/bin with the install script:
  curl -fsSL https://ccam.dev/install.sh | sh
```

В системах, отличных от Linux, выводится только строка со скриптом установки: в Windows это `irm https://ccam.dev/install.ps1 | iex`. Если в папку нельзя записывать, ccam предлагает заново запустить скрипт установки, который устанавливает ccam в `~/.local/bin`.

## Безопасность и особые случаи

- Сборка для разработки сообщает версию `dev` и не имеет выпуска для сравнения, поэтому `ccam update` и `ccam update --check` её отклоняют. `ccam update --version vX.Y.Z` устанавливает выпуск поверх неё. О сборках, сделанных через `go install`, см. [Установка ccam](/docs/install#other-ways-to-install).
- Неудачная загрузка, отсутствующий файл для вашей платформы или несовпадение контрольной суммы оставляют установленный исполняемый файл как был.
- Несуществующий выпуск завершается ошибкой `there is no release <tag>`. Если GitHub отвечает отказом HTTP 403 или 429, ccam сообщает, что это, вероятно, ограничение частоты запросов, и предлагает повторить попытку позже.
- `--check` только читает. Он не проверяет, управляется ли исполняемый файл пакетным менеджером и доступен ли он для записи.
- `--version` с более старым тегом позволяет откатиться на предыдущую версию.
