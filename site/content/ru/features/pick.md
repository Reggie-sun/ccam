`ccam pick` выводит имя аккаунта с входом и наибольшим запасом, чтобы скрипт мог запустить с ним Claude Code. Рабочие процессы, запущенные одновременно, получают разные аккаунты, пока аккаунтов с запасом достаточно, поэтому пакет заданий `claude -p` распределяется по вашим аккаунтам, а не исчерпывает один.

**Места в тарифах Team и Enterprise.** Автоматический выбор аккаунта (`ccam next`, `--fallback`, `ccam pick`, клавиша `n` на панели и, если вы его включите, [`auto_switch`](/features/next#auto-switch)) переключается и между местами одной и той же организации Claude Team или Enterprise, что может нарушать условия Anthropic. Прочитайте [FAQ](/docs/faq#am-i-allowed-to-use-several-claude-code-accounts) и уточните это у своей организации и у Anthropic, прежде чем на него полагаться.

## Использование

```sh
ccam "$(ccam pick)" -p "fix the failing tests"
for task in parse lint docs; do
  ccam "$(ccam pick)" -p "do the $task task" > "$task.json" &
done; wait
ccam pick --json                      # the account and its usage
ccam pick --model opus                # also count the Opus weekly limit
ccam pick --max-usage 80 --strategy expiring
ccam pick --strategy balance          # most weekly quota left per day; fewer sessions first
ccam pick --cross-org                 # also accounts of other organizations
ccam pick --wait=2h                   # nobody has room: wait for a reset
ccam --fallback "$(ccam pick)" -p "…" # also switch if this account hits its limit mid-job
```

```console
$ ccam pick --json
{
  "name": "work",
  "slot": 2,
  "email": "dev@company.com",
  "five_hour": { "percent": 12, "resets_at": "2026-10-20T15:10:00Z", "known": true },
  "weekly": { "percent": 41, "resets_at": "2026-10-24T09:00:00Z", "known": true },
  "source": "live",
  "reason": "12% of its 5 hours used, the least"
}
```

Коды выхода: `0` с именем в стандартном выводе, `75` (`EX_TEMPFAIL`), когда ни у одного аккаунта нет запаса или ни в одном не выполнен вход, `1` для других ошибок, например неверного флага.

## Параметры

| Параметр | Действие | По умолчанию |
| --- | --- | --- |
| `--json` | Вывести аккаунт, его использование за 5 часов и за неделю, источник данных и причину выбора | выкл. |
| `--model <model>` | Учитывать также недельное окно этой модели, например `opus` | нет |
| `--max-usage <1-100>` | Предпочитать аккаунты ниже этого использования | `auto_max_usage`, иначе 100 |
| `--strategy headroom\|expiring\|balance` | Наименьшее использование за 5 часов, ближайший сброс 5-часового окна или больше всего недельной квоты, оставшейся на день | `auto_strategy`, иначе `headroom` |
| `--cross-org` | Выбирать также аккаунты других организаций | `cross_org`, иначе выкл. |
| `--wait[=<duration>]` | Если ни у одного аккаунта нет запаса, ждать сброса первого из них, но не дольше этого времени. Значение указывается после `=`: `--wait 30m` отклоняется с подсказкой `--wait takes its value after '=': --wait=30m` | выкл.; `5h`, если указан без значения |
| `--dry-run` | Выбрать, не записывая выбор | выкл. |

## Как это работает

1. ccam перечисляет аккаунты с входом (у аккаунтов с ключом API и входов через Console нет лимитов, и они не учитываются) в организации аккаунта, который запустила бы эта папка (см. [организации](/features/next#auto)); папка, вошедшая в тот же аккаунт Claude, что и он, тоже не учитывается.
2. Он берёт блокировку (`~/.local/state/ccam/picks.lock`), поэтому одновременные выборы выполняются по очереди.
3. Он одновременно запрашивает использование всех аккаунтов так же, как `ccam usage`, с кэшем на 60 секунд. Окно, которое Claude Code сообщил заполненным, считается заполненным на 100% до своего сброса ([запись о лимите](/features/usage#the-limit-record)), поэтому аккаунт, только что достигший лимита, исключается, даже если его сохранённые данные ещё показывают запас.
4. Аккаунты, выбранные за последние 2 минуты командой `ccam pick` или [`auto_switch`](/features/next#auto-switch), перенёсшим туда сессию (`~/.local/state/ccam/picks/<name>`; выбор с меткой времени в будущем не учитывается), сначала исключаются, а среди остальных выбирают [правила выбора](/features/next#auto) `ccam next --auto`: сначала аккаунты ниже `auto_max_usage`, по стратегии, и никогда не аккаунт на 100%. Если из-за этого пропущен аккаунт, который правила выбрали бы в ином случае, `reason` в `--json` говорит об этом: `30% of its 5 hours used; work was picked a moment ago`.
5. Если все аккаунты с запасом недавно уже выбирались, правила снова выбирают среди всех них, поэтому при трёх аккаунтах четвёртый рабочий процесс делит один из них.
6. Выбор записывается, блокировка снимается, и выводится имя.

Окно в 2 минуты нужно потому, что использование нового задания появляется в данных не сразу: без него пять рабочих процессов, запущенных вместе, все увидели бы один и тот же аккаунт как аккаунт с наибольшим запасом.

## Безопасность и особые случаи

- `ccam pick` только читает использование и записывает время выбора; он никогда не обновляет и не читает токены сверх того, что делает `ccam usage`.
- Выбор не резервирует аккаунт. Через 2 минуты два скрипта всё равно могут запуститься на одном аккаунте; используйте `--fallback`, чтобы продолжить, когда этот аккаунт достигнет лимита.
- Ожидание с `--wait` не держит блокировку, поэтому другие выборы тем временем продолжаются.
- `ccam pick` не учитывает [`ccam folder`](/features/folder): он выбирает только по использованию.
