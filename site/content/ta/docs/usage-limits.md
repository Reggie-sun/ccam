ஒவ்வொரு கணக்கும் 5 மணி நேர வரம்பு, வாராந்திர வரம்பு மற்றும் ஒவ்வொரு model-இன் சொந்த வாராந்திர வரம்பு (Fable போன்றது) ஆகியவற்றில் எவ்வளவு பயன்படுத்தியுள்ளது என்று `ccam usage` காட்டுகிறது. `ccam next --auto` அதிக இடம் உள்ள கணக்கைத் திறக்கிறது, `--continue` தற்போதைய உரையாடலை அதற்குக் கொண்டு செல்கிறது.

ஒவ்வொரு கணக்குக்கும் அதன் எண்கள் எவ்வளவு பழையவை என்று சொல்லும் ஒரு வரி வருகிறது, பிறகு ஒவ்வொரு வரம்புக்கும் ஒரு பட்டை, அது மீட்டமைக்கப்படும் வரையிலான நேரத்துடன்: 5 மணி நேர window, எல்லா model-களுக்குமான வாராந்திர window, Fable போன்ற ஒவ்வொரு model-இன் சொந்த வாராந்திர window. 80% முதல் பட்டை மஞ்சளாகவும், 100%-இல் சிவப்பாகவும் மாறும். கடைசி வரி `ccam next --auto` திறக்கும் கணக்கைக் குறிப்பிடுகிறது; `auto_strategy = "expiring"` அல்லது `"balance"` உடன், அதற்குப் பதிலாக அது `→ next --auto picks <name>: <reason>` எனக் காட்டும்.

**Team மற்றும் Enterprise இருக்கைகள்.** தானியங்கித் தேர்வு (`ccam next`, `--fallback`, `ccam pick`, டாஷ்போர்டின் `n`) ஒரே Claude Team அல்லது Enterprise நிறுவனத்தின் இருக்கைகளுக்கு இடையேயும் மாறுகிறது. Anthropic-இன் உதவி மையம் "Each seat on a Team plan is assigned to one named individual, and only that person may use it" (Team திட்டத்தின் ஒவ்வொரு இருக்கையும் பெயர் குறிப்பிடப்பட்ட ஒரு நபருக்கு ஒதுக்கப்படுகிறது, அந்த நபர் மட்டுமே அதைப் பயன்படுத்தலாம்) என்றும், "Users can't route their work through another user's account to use that user's remaining usage" (மற்றொரு பயனரின் மீதமுள்ள பயன்பாட்டைப் பயன்படுத்திக்கொள்ள, பயனர்கள் தங்கள் வேலையை அந்தப் பயனரின் கணக்கு வழியாக அனுப்ப முடியாது) என்றும் கூறுகிறது ([Team திட்டங்கள்](https://support.claude.com/en/articles/12004354-purchase-and-manage-seats-on-team-plans#h_b8a7d07129); இதேபோல் [Enterprise திட்டங்களுக்கும்](https://support.claude.com/en/articles/13393991-purchase-and-manage-seats-on-enterprise-plans#h_fa6b9cade0)). எனவே, இருக்கைகளுக்கு இடையே தானியங்கித் தேர்வைப் பயன்படுத்துவது Anthropic-இன் விதிமுறைகளை மீறக்கூடும். அதை நம்பியிருக்கும் முன், உங்கள் நிறுவனத்திடமும் Anthropic-இடமும் கேட்டு உறுதிசெய்துகொள்ளுங்கள். தனிப்பட்ட திட்டங்கள் (Pro, Max) பற்றி [அடிக்கடி கேட்கப்படும் கேள்விகளில் உள்ள விதிமுறைக் குறிப்பு](/docs/faq#am-i-allowed-to-use-several-claude-code-accounts) விளக்குகிறது.

## எண்கள் எங்கிருந்து வருகின்றன

ccam ஒவ்வொரு கணக்கின் சொந்த உள்நுழைவைப் பயன்படுத்தி, எல்லாக் கணக்குகளுக்கும் ஒரே நேரத்தில் Anthropic-இன் usage endpoint-இடம் கேட்கிறது. ஒவ்வொரு கணக்குக்கும் அதிகபட்சம் 3 வினாடிகள் காத்திருந்து, ஒவ்வொரு கணக்கும் பதில் அளித்தவுடன் அதைக் காட்டுகிறது.

இந்த endpoint பொதுவில் ஆவணப்படுத்தப்படவில்லை, மாறக்கூடும். ஒரு கோரிக்கை தோல்வியடைந்தால், ccam கடைசியாகத் தெரிந்த எண்களைக் காட்டி, அவற்றை cache என்று குறிக்கிறது. அந்த எண்கள் சேமிக்கப்பட்ட பிறகு மீட்டமைக்கப்பட்ட கால அளவு 0% எனக் காட்டும். பதிலின் வடிவம் மாறியிருந்தால் `ccam doctor` உங்களுக்குச் சொல்லும்.

Claude Code ஓர் அமர்வைப் பயன்பாட்டு வரம்பில் நிறுத்தும்போது, எந்தக் கால அளவு நிரம்பியது, அது எப்போது மீட்டமைக்கப்படும் என்பதை [ccam plugin](/docs/install#claude-code-plugin) பதிவு செய்கிறது. அதுவரை, மற்ற எண்கள் என்ன சொன்னாலும் அந்தக் கால அளவு 100% எனக் காட்டும், அதனால் `ccam next --auto`-உம் `--fallback`-உம் அந்தக் கணக்கை மிக விரைவாக மீண்டும் தேர்ந்தெடுப்பதில்லை.

60 வினாடிகளுக்குள் பெறப்பட்ட எண்கள் மீண்டும் பயன்படுத்தப்படும். Options:

| Option | விளைவு |
| --- | --- |
| `--watch[=seconds]` | தொடர்ந்து புதுப்பிக்கும், இயல்பாக ஒவ்வொரு 60 வினாடிக்கும் |
| `--json` | இயந்திரம் படிக்கக்கூடிய வெளியீடு |
| `-v` | ஒவ்வொரு கணக்கின் எண்களும் எங்கிருந்து வந்தன என்பதையும் காட்டும் |
| `--no-cache` | எப்போதும் மீண்டும் கேட்கும் |
| `--source cache` | ஒருபோதும் கேட்காது; சேமித்த எண்களை மட்டும் காட்டும் |

## காலாவதியான உள்நுழைவுகள்

ஒரு கணக்கின் access token காலாவதியானால், ccam அதைப் புதுப்பிப்பதில்லை. ஏனெனில், ஒரு Claude Code அமர்வு அதே உள்நுழைவைப் பயன்படுத்தும்போது அதைப் புதுப்பித்தால், அந்த அமர்வு வெளியேற்றப்படக்கூடும். அந்தக் கணக்கு ``access token expired; `ccam <name>` renews it when it starts`` எனக் காட்டும்: `ccam <name>` மூலம் அதை ஒருமுறை தொடங்குங்கள், Claude Code அதைப் புதுப்பிக்கும். முழுவதுமாகக் காலாவதியான, அல்லது Claude Code அழித்த உள்நுழைவு `` login expired → `ccam login <name>` `` எனக் காட்டும், அதற்குப் புதிய உள்நுழைவு தேவை.

`ccam usage --refresh` காலாவதியான tokens-ஐத் தானே புதுப்பிக்கிறது, ஆனால் இயங்காத கணக்குகளுக்கு மட்டுமே, Claude Code எப்படித் தொடங்கப்பட்டிருந்தாலும் சரி. macOS Keychain-இல் அல்லது இறக்குமதி செய்யப்பட்ட `~/.claude`-இல் சேமிக்கப்பட்ட உள்நுழைவுகளை அது ஒருபோதும் புதுப்பிப்பதில்லை, ஒரு புதுப்பிப்புக்கு 30 வினாடிகள் வரை ஆகலாம்.

## நிலை வரியில் பயன்பாடு

```sh
ccam statusline install
```

அதன் பிறகு Claude Code, கணக்கின் பெயரையும் அதன் பயன்பாட்டையும் நிலை வரியில் காட்டும், எடுத்துக்காட்டாக `[work] · Opus · 5h 24% · 7d 41%`. 90%-இலிருந்து, அந்த வரி `ccam next --auto --continue`-ஐயும் பரிந்துரைக்கிறது. உங்களிடம் ஏற்கெனவே ஒரு status line கட்டளை இருந்தால், ccam அதை வைத்துக்கொண்டு, அதற்கு முன் கணக்கின் பெயரைச் சேர்க்கும். நிலை வரி தன் எண்களைச் சேமிக்கவும் செய்கிறது; endpoint பதில் அளிக்காதபோது `ccam usage` அவற்றைப் பயன்படுத்தும்.

## கணக்கு மாற்றம்

```sh
ccam next             # the account after the one you used last
ccam next --auto      # the account with the lowest 5-hour usage
ccam next --continue  # carry this folder's conversation on as the next account
```

`ccam next` உள்நுழையாத கணக்குகளைத் தவிர்க்கிறது, `--auto` 100%-இல் உள்ள கணக்குகளையும் (Claude Code நிரம்பியதாகத் தெரிவித்த கால அளவும், அதன் மீட்டமைப்பு வரை) வேறொரு நிறுவனத்தின் கணக்குகளையும் தவிர்க்கிறது. இரண்டு கணக்குகளும் உரையாடல் வரலாற்றைப் பகிர்ந்தால், `--continue` அதே உரையாடலைத் திறக்கும்; இல்லையென்றால் Claude Code அதைப் புதிய கணக்குக்குள் நகலெடுக்கும். [பகிர்வு](/docs/sharing), [அடுத்த கணக்குக்கு மாறுதல்](/features/next#continue) பாருங்கள்.

`claude -p` இயக்கும் scripts-க்கும் திட்டமிட்ட jobs-க்கும், கணக்குப் பெயருக்கு முன் `--fallback` வையுங்கள். அந்தக் கணக்கு தன் வரம்பை எட்டும்போது, ccam அதே கட்டளையை அதிக இடம் உள்ள கணக்காக மீண்டும் இயக்குகிறது, முடிந்த இயக்கத்தின் output மட்டுமே அச்சிடப்படுகிறது:

```sh
ccam --fallback work -p "review the diff" --output-format json
```

ccam எப்படி முடிவு செய்கிறது என்பதற்கு [வரம்பில் மீண்டும் இயக்குதல்](/features/next#run-again-at-the-limit) பக்கத்தைப் பாருங்கள்.

[பயன்பாட்டு வரம்பு வழிகாட்டி](/guides/usage-limit-workflow) ஒரு முழு எடுத்துக்காட்டை விளக்குகிறது.
