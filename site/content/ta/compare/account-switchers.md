Claude Code கணக்குகளை மாற்றும் கருவிகள் இரண்டு அணுகுமுறைகளில் ஒன்றைப் பின்பற்றுகின்றன. பெரும்பாலானவை ஒரே `~/.claude` கோப்புறைக்குள் உள்நுழைவை மாற்றுகின்றன, அதனால் ஒரு நேரத்தில் ஒரு கணக்கு மட்டுமே செயலில் இருக்கும். ccam உட்படச் சில கருவிகள் `CLAUDE_CONFIG_DIR` மூலம் ஒவ்வொரு கணக்குக்கும் தனிக் கோப்புறையைக் கொடுக்கின்றன, அதனால் ஒவ்வொரு கணக்கும் உள்நுழைந்த நிலையிலேயே இருக்கும், பல கணக்குகள் ஒரே நேரத்தில் இயங்கலாம். ccam பகிரப்பட்ட அமைப்புகளையும் MCP சர்வர்களையும் சேர்க்கிறது, ஓர் உரையாடலை வேறொரு கணக்கின் கோப்புறையில் தொடரவும் உதவுகிறது.

## ஒரே உள்நுழைவை மாற்றுவதா, தனித்தனி கோப்புறைகளா?

**உள்நுழைவை மாற்றுவதில்** ஒரே ஒரு கோப்புறைதான் இருப்பதால், அமைப்புகள், MCP சர்வர்கள், வரலாறு ஆகியவை ஒரே தொகுப்பாக இருக்கும். மாற்றம் வேகமானது, இயங்கும் session புதிய உள்நுழைவை எடுத்துக்கொள்ளலாம். ஆனால் ஒரு நேரத்தில் ஒரு கணக்கு மட்டுமே செயலில் இருக்கும், அதுவும் எல்லா டெர்மினல்களுக்கும் editors-க்கும் ஒரே நேரத்தில்.

மாற்றுவதற்காக, கருவி மற்ற ஒவ்வொரு கணக்கின் உள்நுழைவையும் நகலாக வைத்திருந்து, அதை உரிய இடத்தில் எழுதுகிறது. Claude Code ஓர் உள்நுழைவைப் புதுப்பிக்கும்போது அதிலுள்ள refresh token-ஐ மாற்றிவிடுகிறது, அதனால் சேமித்த ஒவ்வொரு நகலும் இயங்கும் sessions-உடன் ஒத்திசைவில் இருக்க வேண்டும். மாற்றிய பிறகு கணக்குகள் வெளியேற்றப்படுவதும், மீண்டும் `/login` தேவைப்படுவதும் இந்தத் திட்டங்கள் அடிக்கடி சரிசெய்யும் சிக்கல்களில் அடங்கும்.

**தனித்தனி கோப்புறைகள்** என்பது [Claude Code ஆவணங்கள் விவரிக்கும்](https://code.claude.com/docs/en/authentication#log-in-with-multiple-accounts) முறை. ஒவ்வொரு கணக்கும் உள்நுழைந்த நிலையிலேயே இருக்கும், ஒரு வேலை session-ஐயும் ஒரு தனிப்பட்ட session-ஐயும் பக்கம் பக்கமாக இயக்கலாம். ஒவ்வொரு உள்நுழைவும் அதன் சொந்தக் கோப்புறையிலேயே இருக்கும், அங்கே Claude Code வழக்கம்போல் அதைப் புதுப்பிக்கிறது. இதன் விலை: ஏதாவது ஒரு கருவி பகிராவிட்டால், ஒவ்வொரு கோப்புறையும் தன் சொந்த அமைப்புகள், MCP சர்வர்கள், வரலாற்றுடன் தொடங்குகிறது.

## ccam எதைச் சிறப்பாகச் செய்கிறது

### உள்நுழைவுகள் Claude Code வைத்த இடத்திலேயே இருக்கின்றன

ccam ஒருபோதும் ஒரு Claude உள்நுழைவை ஓர் இடத்திலிருந்து இன்னோர் இடத்துக்கு நகலெடுப்பதில்லை. ஒவ்வொரு கணக்கின் உள்நுழைவும் அதன் சொந்தக் கோப்புறையில், அல்லது macOS-இல் அந்தக் கோப்புறைக்கே உரிய Keychain உருப்படியில் இருக்கிறது, அதைப் புதுப்பிப்பது Claude Code-தான். ஒத்திசைவு தவறக்கூடிய சேமித்த நகல் எதுவும் இல்லை. `ccam import` மூலம் பதிவுசெய்யப்பட்ட ஏற்கெனவே உள்ள `~/.claude`, சாதாரண `claude` பயன்படுத்தும் அதே Keychain உருப்படியை வைத்துக்கொள்கிறது, அதனால் எந்த வழியில் தொடங்கினாலும் அது உள்நுழைந்த நிலையிலேயே இருக்கும்.

நீங்கள் `ccam usage --refresh` இயக்கும்போது மட்டுமே காலாவதியான token-ஐ ccam தானே புதுப்பிக்கிறது. அது முதலில் ஒரு பூட்டை எடுக்கிறது; அந்தக் கணக்கு இயங்கிக்கொண்டிருக்கும்போது, Claude Code எப்படித் தொடங்கப்பட்டிருந்தாலும் (பின்னணி sessions-உம் அவற்றின் daemon-உம் உட்பட), Claude Code தானே அந்த உள்நுழைவைப் புதுப்பித்துக்கொண்டிருக்கும்போதும் அது மறுக்கிறது, அதனால் இயங்கும் session-இன் கீழ் அது ஒருபோதும் token-ஐ மாற்றுவதில்லை.

### இயல்பாக, உங்களுக்கும் Claude Code-க்கும் இடையே எதுவும் இயங்குவதில்லை

ccam ஒரு கோப்பைப் படித்து, அதன் இணைப்புகளைச் சரிபார்த்து, தன் இடத்தில் `claude`-ஐ இயக்குகிறது (`exec`). இயல்பாக, நீங்கள் வேலை செய்யும்போது ccam process, wrapper, proxy, daemon எதுவும் இல்லை: standard input, signals, exit code ஆகியவை Claude Code-க்கு உரியவை, அதன் கோரிக்கைகள் நேரடியாக Anthropic-க்குச் செல்கின்றன. Windows-ஆல் ஒரு process-ஐ மாற்ற முடியாது, அதனால் அங்கே ccam அதே console-உடன் Claude Code-ஐத் தொடங்கி, அதன் exit code-க்காகக் காத்திருக்கிறது, வேறு எதுவும் செய்வதில்லை. `relay = true` அல்லது `auto_switch = true` இருந்தால், ccam இதே முறையில் interactive அமர்வுகளின் அருகில் காத்திருக்கிறது, அதனால் அது ஓர் உரையாடலை வேறொரு கணக்காகத் தொடர முடியும்; Claude Code-இன் கோரிக்கைகள் அப்போதும் நேரடியாக Anthropic-க்கே செல்கின்றன.

இப்படி ஒரு கணக்கைத் தொடங்குவது சுமார் 4 ms மட்டுமே சேர்க்கிறது, 95-ஆவது percentile-இல் 6 ms-க்குக் கீழ், உச்ச நினைவகம் 8 MB ([`scripts/perf-check.sh`](https://github.com/jhyunwoo/ccam/blob/main/scripts/perf-check.sh), hyperfine உடன், 300 ஓட்டங்கள்). அதே laptop-இல், ஒரு நிரல் எதையும் செய்யத் தொடங்குவதற்கு முன்பே, Python interpreter-ஐத் தொடங்க மட்டும் 13 ms, Node.js-க்கு 31 ms ஆகிறது.

### எது பகிரப்படுகிறது என்பதைக் குழுக்கள் முடிவு செய்கின்றன

MCP சர்வர்கள், `settings.json`, `CLAUDE.md`, extensions (agents, commands, skills, plugins), உரையாடல் வரலாறு ஆகியவை ஐந்து தனித்தனி உருப்படிகள். ஒரு குழு தான் பகிரும் உருப்படிகளையும் அதிலுள்ள கணக்குகளையும் பெயரிடுகிறது. அதனால் இரண்டு வேலைக் கணக்குகள் ஒரு `work` குழுவில் வரலாற்றைப் பகிரலாம், ஒரு தனிப்பட்ட கணக்கு தன் சொந்த வரலாற்றை வைத்துக்கொள்ளலாம், மூன்றும் `default` வழியாக ஒரே MCP சர்வர்களைப் பகிரலாம். `ccam group set work --add memory` குழுவின் எல்லாக் கணக்குகளையும் ஒரே திட்டத்தில் நகர்த்துகிறது; [டாஷ்போர்டு](/features/dashboard) இதையே checkboxes மூலம் செய்கிறது, ஒரு கணக்கு ஏற்கெனவே வேறொரு குழுவிடமிருந்து பெறும் உருப்படியைச் சாம்பல் நிறமாக்குகிறது.

- MCP சர்வர்கள் தொடக்கத்தில் `--mcp-config` மூலம் கொடுக்கப்படுகின்றன, அதனால் இயல்பாக ஒரு தொடக்கம் `.claude.json`-ஐத் தொடுவதில்லை; அது Claude Code இயங்கும்போது மீண்டும் எழுதும் கோப்பு. அப்படிச் சொல்லும் படிகளில் மட்டுமே, Claude Code-இன் பூட்டின் கீழ், ஒரு காப்புப்பிரதியுடன், ccam அங்கே எழுதுகிறது: கேட்ட பிறகு Remote Control-க்கு, ஒரு கணக்கு MCP பகிர்விலிருந்து விலகும்போது அல்லது மீண்டும் சேரும்போது, `ccam mcp import`-க்கு. `ccam mcp add` ஒரு சர்வரை முழுக் குழுவுக்கும் ஒரே முறை சேர்க்கிறது.
- மற்ற உருப்படிகள் குழுக் கோப்புறைக்கான இணைப்புகள், அதனால் ஒரு கணக்கில் செய்த மாற்றம் மற்றவற்றில் உடனே தெரியும். தொடக்கத்தில் எதுவும் நகலெடுக்கப்படுவதில்லை.
- உள்நுழைவுகள், `.claude.json`, இயங்கும் நிலை ஆகியவை ஒருபோதும் பகிரப்படுவதில்லை.

### ஒவ்வொரு மாற்றமும் முதலில் காட்டப்பட்டு, காப்புப்பிரதி எடுக்கப்படுகிறது

`ccam group`, `ccam migrate` ஆகியவை எதையும் நகர்த்தும் முன் ஒரு திட்டத்தை அச்சிட்டு உங்களிடம் கேட்கின்றன. ஒரு கணக்குக்கும் அதன் குழுவுக்கும் இடையே ஒரு கோப்பு வேறுபட்டால், நீங்களே தேர்ந்தெடுக்கிறீர்கள்: குழுவுடையதை வைத்துக்கொள்வது, உங்களுடையதைப் பயன்படுத்துவது, அல்லது JSON-ஐ இணைப்பது; கோப்புறைகளுக்குள் குழுவின் நகல் அப்படியே இருக்கும், வேறுபடும் கோப்புகளைத் திட்டம் பெயரிடுகிறது. மூலக் கோப்புகள் `.ccam-backup/<time>/`-க்குச் செல்கின்றன, நீக்கப்பட்ட கணக்கு வெளியேற்றப்பட்டு அதன் கோப்புறை ஒரு குப்பைக் கோப்புறைக்குச் செல்கிறது, கோப்புகள் ஒரே rename-இல் மாற்றப்படுகின்றன, அதனால் இடையில் நின்றுபோன எழுதுதல் பழைய கோப்பை அப்படியே விட்டுவிடுகிறது. தொடங்குதல், பகிர்தல், இடம்பெயர்த்தல், shortcuts, புதுப்பிப்புகள், பழுதுபார்ப்புகள் என்ன செய்யும் என்பதை `--dry-run` காட்டுகிறது. `ccam doctor --fix` உடைந்த இணைப்புகளையும் அனுமதிகளையும் சரிசெய்கிறது.

### அடுத்த கணக்கில் அதே உரையாடல்

`ccam next --auto --continue` எல்லாக் கணக்குகளிடமும் ஒரே நேரத்தில் பயன்பாட்டைக் கேட்டு, அதிக இடம் உள்ள கணக்கைத் திறந்து, உரையாடலைத் தொடர்கிறது. பகிரப்பட்ட வரலாற்றுடன் அது அதே உரையாடல்; அது இல்லாவிட்டால், Claude Code உரையாடலைப் புதிய கணக்குக்குள் நகலெடுக்கிறது (`--resume <file> --fork-session`), முதல் பதில் எத்தனை tokens-ஐ மீண்டும் படிக்கும் என்பதை ccam சொல்கிறது. ஒரு வரம்பு அமர்வை நிறுத்தும்போது, ccam plugin-இன் hook ஓர் அறிவிப்பைக் காட்டுகிறது, `/ccam:switch` உரையாடலை அடுத்த கணக்கிடம் ஒப்படைக்கிறது. இயல்பாக, எப்போது மாற்றுவது என்று நீங்களே முடிவு செய்கிறீர்கள். `auto_switch` இயக்கத்தில் இருந்தால் (Linux, macOS), ccam அமர்வைத் தானே நகர்த்துகிறது, ஆனால் Claude Code அதை ஒரு வரம்பில் நிறுத்திய பிறகு மட்டுமே, அது விட்டுச்செல்லும் கணக்கைப் போன்ற கணக்குக்கு மட்டுமே: அதே நிறுவனத்தின் வேறொரு இருக்கை, அல்லது வேறொரு தனிப்பட்ட திட்டம் ([விவரங்கள்](/features/next#auto-switch)). பின்னணியில் எதுவும் உங்கள் பயன்பாட்டைக் கண்காணிப்பதில்லை, இயல்பாக, தானியங்கித் தேர்வுகள் ஒருபோதும் வேலையை ஒரு Team அல்லது Enterprise நிறுவனத்திலிருந்து வெளியே நகர்த்துவதில்லை, அதற்குள்ளும் நகர்த்துவதில்லை, அதனால் ஒரு நிறுவன உரையாடல் தவறுதலாக ஒரு தனிப்பட்ட கணக்கில் போய்ச் சேராது. ஒரு கணக்கு 90%-ஐ எட்டியதும் நிலை வரி இந்தக் கட்டளையைப் பரிந்துரைக்கிறது.

Scripts உங்களுக்காகக் காத்திருக்க முடியாது, அதனால் `ccam --fallback work -p "…"` அவற்றுக்காக மாற்றுகிறது: கணக்கு தன் வரம்பை எட்டும்போது, அதே கட்டளை அதிக இடம் உள்ள கணக்காக மீண்டும் இயங்குகிறது, முடிந்த இயக்கத்தின் output மட்டுமே அச்சிடப்படுகிறது. பயன்பாட்டு வரம்பு அல்லாத தோல்வி அப்படியே கடத்தப்படுகிறது. இணையான workers-க்கு, `ccam pick` ஒவ்வொன்றுக்கும் இடம் உள்ள வேறொரு கணக்கைக் கொடுக்கிறது, எந்தக் கணக்கிலும் இடம் இல்லாதபோது இரண்டும் code 75 உடன் வெளியேறுகின்றன.

**Team மற்றும் Enterprise இருக்கைகள்.** தானியங்கித் தேர்வு (`ccam next`, `--fallback`, `ccam pick`, டாஷ்போர்டின் `n`, நீங்கள் இயக்கும்போது [`auto_switch`](/features/next#auto-switch)) ஒரே Claude Team அல்லது Enterprise நிறுவனத்தின் இருக்கைகளுக்கு இடையேயும் மாறுகிறது. Anthropic-இன் உதவி மையம் "Each seat on a Team plan is assigned to one named individual, and only that person may use it" (Team திட்டத்தின் ஒவ்வொரு இருக்கையும் பெயர் குறிப்பிடப்பட்ட ஒரு நபருக்கு ஒதுக்கப்படுகிறது, அந்த நபர் மட்டுமே அதைப் பயன்படுத்தலாம்) என்றும், "Users can't route their work through another user's account to use that user's remaining usage" (மற்றொரு பயனரின் மீதமுள்ள பயன்பாட்டைப் பயன்படுத்திக்கொள்ள, பயனர்கள் தங்கள் வேலையை அந்தப் பயனரின் கணக்கு வழியாக அனுப்ப முடியாது) என்றும் கூறுகிறது ([Team திட்டங்கள்](https://support.claude.com/en/articles/12004354-purchase-and-manage-seats-on-team-plans#h_b8a7d07129); இதேபோல் [Enterprise திட்டங்களுக்கும்](https://support.claude.com/en/articles/13393991-purchase-and-manage-seats-on-enterprise-plans#h_fa6b9cade0)). எனவே, இருக்கைகளுக்கு இடையே தானியங்கித் தேர்வைப் பயன்படுத்துவது Anthropic-இன் விதிமுறைகளை மீறக்கூடும். அங்கே அதைப் பயன்படுத்துவதா என்பது உங்கள் முடிவு: அதை நம்பியிருக்கும் முன், உங்கள் நிறுவனத்திடமும் Anthropic-இடமும் கேட்டு உறுதிசெய்துகொள்ளுங்கள். தனிப்பட்ட திட்டங்கள் (Pro, Max) பற்றி [அடிக்கடி கேட்கப்படும் கேள்விகளில் உள்ள விதிமுறைக் குறிப்பு](/docs/faq#am-i-allowed-to-use-several-claude-code-accounts) விளக்குகிறது.

### ஒவ்வொரு கோப்புறையிலும் சரியான கணக்கு

`ccam folder work ~/code/company` அந்தக் கோப்புறைக்குள் கணக்குப் பெயர் இல்லாத ஒவ்வொரு தொடக்கத்தையும் `work`-ஐப் பயன்படுத்த வைக்கிறது, உங்கள் மற்ற திட்டங்கள் இயல்புக் கணக்கையே பயன்படுத்துகின்றன. இந்த அமைப்பு ஒவ்வொரு தொடக்கமும் படிக்கும் அதே `config.toml`-இல் இருக்கிறது, அதனால் அதற்கு நேரம் எதுவும் ஆகாது.

### ஒரே binary, சரிபார்க்கப்பட்ட பதிவிறக்கங்கள்

ccam என்பது Linux, macOS, Windows-க்கான சுமார் 10 MB அளவுள்ள ஒரு static binary, நிறுவ வேண்டிய runtime எதுவும் இல்லை. நிறுவல் scripts-உம் (`install.sh`, `install.ps1`) `ccam update`-உம் ஒவ்வொரு பதிவிறக்கத்தையும் release-இன் SHA-256 checksums-உடன் சரிபார்க்கின்றன, ccam கேட்காமல் ஒருபோதும் புதுப்பித்துக்கொள்வதில்லை. அதில் telemetry இல்லை: அது செய்யும் கோரிக்கைகள் உங்கள் கணக்குகளுக்காக Anthropic-இடம் செய்யும் பயன்பாட்டுத் தேடல்கள் (இணையாக, 3 வினாடி வரம்புடன், 60 வினாடி cache உடன்), டாஷ்போர்டு திறக்கும்போது சமீபத்திய release பற்றி GitHub-இடம் கேட்கும் கேள்வி, நீங்கள் கேட்கும் பதிவிறக்கங்கள் மட்டுமே. `usage_source = "claude"` உடன், அவையும் Claude Code வழியாகவே செல்கின்றன, ccam எந்த token-ஐயும் அனுப்புவதில்லை.

## பிற கருவிகள் எதில் அதிகம் செய்கின்றன

- ஒரு கணக்கு குறிப்பிட்ட பயன்பாட்டு அளவைத் தாண்டும்போது claude-swap, clauth, cux, CAAM, CCSwitcher இயங்கும் interactive session-ஐத் தாமாகவே மாற்றலாம். ccam `-p` இயக்கங்களை `--fallback` மூலம் மாற்றுகிறது; ஓர் interactive session-ஐ அது தானாக நகர்த்துவது `auto_switch` இயக்கத்தில் இருக்கும்போது மட்டுமே (Linux, macOS), அதுவும் Claude Code அதை ஒரு வரம்பில் நிறுத்திய பிறகு மட்டுமே; இல்லையெனில், வரம்பில் ஓர் அறிவிப்புடனும் `/ccam:switch` உடனும் நீங்களே அதை நகர்த்துகிறீர்கள்.
- Developer Mode இல்லாத Windows-இல் ccam கோப்புறைகளைப் பகிர்கிறது, ஆனால் `settings.json` போன்ற தனிக் கோப்புகளைப் பகிர முடியாது (அப்போது முதல் `ccam add` MCP சர்வர்களையும் extensions-ஐயும் மட்டுமே பகிர்கிறது); claude-swap-உம் CCS-உம் அங்கே அவற்றை நகலெடுக்கின்றன.
- CCSwitcher, Claude Switcher, claude-swap ஆகியவை macOS menu bar-இல் பயன்பாட்டைக் காட்டுகின்றன.
- CCS, clausona, CAAM, clauth, ccswap, Claude Switcher ஆகியவை Codex-ஐயும் பிற coding agents-ஐயும் நிர்வகிக்கின்றன.
- clausona கணக்கு வாரியாக extensions-ஐ இயக்கவும் அணைக்கவும் செய்கிறது (ccam-இன் `ccam ext` அவற்றைக் காட்ட மட்டுமே செய்கிறது), local token செலவைக் கண்காணிக்கிறது, tmux-இலும் பிற terminals-இலும் workers கூட்டத்தை இயக்கும் Claude Code plugins-ஐயும் வழங்குகிறது.
- CAAM, CCSwitcher, Claude Switcher ஆகியவை Homebrew மூலம் நிறுவப்படுகின்றன, clauth-உம் CAAM-உம் தங்கள் release checksums-இல் கையொப்பமிடுகின்றன. ccam அதன் script, ஒரு `.deb`, அல்லது `go install` மூலம் நிறுவப்படுகிறது, checksums-ஐக் கையொப்பம் இல்லாமல் சரிபார்க்கிறது.

## எது பொருந்தும்?

ஒரு நேரத்தில் ஒரு கணக்கைப் பயன்படுத்தினால், அல்லது இயங்கும் sessions வரம்புக்கு முன்பே அல்லது உள்நுழைவை மாற்றுவதன் மூலம் மாற வேண்டுமென்றால், உள்நுழைவை மாற்றும் கருவியைத் தேர்ந்தெடுங்கள். கணக்குகளைப் பக்கம் பக்கமாக இயக்கவும், ஒரே பகிரப்பட்ட அமைப்பு, அடுத்த கணக்கில் அதே உரையாடல், இயல்பாக Claude Code-க்குப் பக்கத்தில் எதுவும் இயங்காத நிலை ஆகியவை Linux, macOS அல்லது Windows-இல் வேண்டுமென்றால் ccam-ஐத் தேர்ந்தெடுங்கள். எதுவும் பகிர வேண்டாம் என்றால், [எளிய shell aliases](/compare/aliases) போதும்.

பல கணக்குகளைப் பயன்படுத்த உங்களுக்கு அனுமதி உள்ளதா என்பது ஒவ்வொரு கணக்கின் விதிமுறைகளைப் பொறுத்தது. அதற்கு முன் அவற்றைச் சரிபாருங்கள்.
