ஒவ்வொரு கணக்குக்கும் தனிக் கோப்புறை உண்டு, ஆனால் அதிலுள்ள பெரும்பாலானவை தனியாக இருக்க வேண்டியதில்லை. எது பகிரப்படுகிறது, யாரால் என்பதை ஒரு **குழு** சொல்கிறது: குழுவின் ஒவ்வொரு கணக்கும் அந்த உருப்படிகளை `~/.local/share/ccam/groups/<group>/` என்ற ஒரே கோப்புறையுடன் இணைக்கிறது, அதனால் அவை அனைத்தும் ஒரே நகலைப் படித்து எழுதுகின்றன. உள்நுழைவு tokens ஒருபோதும் பகிரப்படுவதில்லை.

ஒரு கணக்கு பல குழுக்களில் இருக்கலாம், ஆனால் ஒவ்வோர் உருப்படியும் ஒரே ஒரு குழுவிலிருந்து மட்டுமே வரும். வழக்கமான அமைப்பு இது: அமைப்புகளுக்கும் நீட்டிப்புகளுக்கும் ஒரு குழு, இரண்டு கணக்குகளுக்கு இடையிலான உரையாடல் வரலாற்றுக்கு இரண்டாவது குழு:

```toml
[[group]]
name = 'default'
items = ['mcp', 'settings', 'memory', 'extensions']
members = ['personal', 'work', 'side']

[[group]]
name = 'team'
items = ['history']
members = ['work', 'side']
```

நீங்கள் சேர்க்கும் முதல் கணக்கு `default`-ஐ உருவாக்குகிறது, நீங்கள் வேறு விதமாகச் சொல்லாவிட்டால் பின்னர் சேர்க்கும் கணக்குகள் அதில் இணைகின்றன.

## பயன்பாடு

```sh
ccam group                                        # the groups, what they share, their accounts
ccam group show default                           # items, accounts, folder and MCP servers
ccam group add team --items history --members work,side
ccam group set default --add history              # every account in default moves together
ccam group set default --remove history --fresh   # stop sharing; accounts start without it
ccam group set team --items history,memory --from work   # work's CLAUDE.md goes in first
ccam group join team personal                     # personal starts sharing team's items
ccam group join team personal --replace           # leave the group that shares them now
ccam group leave team side                        # side keeps a copy of team's items
ccam group rename team pair                       # the folder keeps its name
ccam group remove pair --leave                    # its accounts keep a copy; folder to the trash
ccam share work                                   # what work shares, and through which group
ccam --dry-run group set default --add history    # print the plan, change nothing
```

```console
$ ccam group
Group    Shares                          Accounts
default  mcp settings memory extensions  personal, work, side
team     history                         work, side

$ ccam share work
Sharing for work
  mcp         MCP servers                        group default
  settings    settings.json                      group default
  memory      global CLAUDE.md                   group default
  extensions  agents, commands, skills, plugins  group default
  history     conversation history               group team
Groups: default, team. Change them with `ccam group`.
```

தரவை நகர்த்தும் ஒவ்வொரு கட்டளையும் ஒரு திட்டத்தை அச்சிட்டு, குழுவின் நகலிலிருந்து வேறுபடும் ஒவ்வொரு கோப்பைப் பற்றியும் கேட்டு, எதையும் மாற்றும் முன் `Proceed? [y/N]` என்று கேட்கும்:

```console
$ ccam group set default --add history
Plan (paths in /home/me/.local/share/ccam):
personal: +history (group default)
  move     projects, history.jsonl: profiles/personal → groups/default (first content of the group)
  link     projects, history.jsonl: profiles/personal → groups/default
work: +history (group default)
  merge    new files in projects: profiles/work → groups/default
  conflict profiles/work/history.jsonl ↔ groups/default/history.jsonl: merge by line
  back up  projects, history.jsonl: profiles/work → profiles/work/.ccam-backup/20261020-153012
  link     projects, history.jsonl: profiles/work → groups/default
Proceed? [y/N]
```

இதே மாற்றங்கள் [டாஷ்போர்டின்](/features/dashboard) **Groups** தாவலிலும் உள்ளன; ஒரு கணக்கின் மீது `s` அழுத்தினால் அதன் குழுக்களைத் தேர்ந்தெடுக்கலாம்.

## உருப்படிகள்

| உருப்படி | என்ன உள்ளடக்கும் |
| --- | --- |
| `mcp` | MCP சர்வர்கள், குழுவின் `mcp.json` வழியாக ([பகிரப்பட்ட MCP சர்வர்கள்](/features/mcp)) |
| `settings` | `settings.json` |
| `memory` | உலகளாவிய `CLAUDE.md` |
| `extensions` | `agents/`, `commands/`, `skills/`, `plugins/`, `output-styles/`, `rules/` |
| `history` | `projects/` மற்றும் `history.jsonl`, அதனால் மற்றொரு கணக்கு `--continue` செய்ய முடியும் |

கணக்கின் எந்தக் குழுவும் பகிராத உருப்படி, கணக்கின் சொந்தக் கோப்புறையிலேயே இருக்கும்.

## கட்டளைகளும் options-உம்

| கட்டளை | என்ன செய்யும் |
| --- | --- |
| `ccam group` அல்லது `ccam group list` | குழுக்களைப் பட்டியலிடும் |
| `ccam group show <group>` | குழு எதைப் பகிர்கிறது, அதன் கணக்குகள், அதன் கோப்புறை, MCP சர்வர்கள் |
| `ccam group add <group> --items <items> [--members <accounts>]` | ஒரு குழுவை உருவாக்கும்; அதன் கணக்குகளின் உருப்படிகள் அதற்குள் நகரும் |
| `ccam group set <group> --add <items> \| --remove <items> \| --items <items>` | குழு பகிர்வதை, அதிலுள்ள ஒவ்வொரு கணக்குக்கும் மாற்றும் |
| `ccam group join <group> <account>...` | கணக்குகளைக் குழுவில் சேர்க்கும் |
| `ccam group leave <group> <account>...` | கணக்குகளைக் குழுவிலிருந்து எடுக்கும்; ஒவ்வொன்றும் ஒரு நகலை வைத்திருக்கும் |
| `ccam group rename <group> <new-name>` | config-இல் மட்டும் மறுபெயரிடும் |
| `ccam group remove <group> [--leave]` | ஒரு குழுவை நீக்கும் |

| Option | என்ன செய்யும் | இயல்புநிலை |
| --- | --- | --- |
| `--from <account>` | `add`, `set`: எந்தக் கணக்கின் நகல் முதலில் குழுவுக்குள் செல்லும் | இயல்புநிலைக் கணக்கு, பிறகு எண் வரிசைப்படி |
| `--replace` | `join`: அதே உருப்படிகளைப் பகிரும் குழுக்களிலிருந்து முதலில் வெளியேறும் | off |
| `--fresh` | ஓர் உருப்படியைப் பகிர்வதை நிறுத்தும் கணக்குகள், நகலுடன் அல்லாமல் அது இல்லாமல் தொடங்கும் | off |
| `--leave` | `remove`: குழுவின் கணக்குகளை முதலில் வெளியே எடுக்கும் | குழுவில் கணக்குகள் இருக்கும்போது தேவை |
| `--prefer <group\|mine\|merge>` | முரண்பாடுகளை எப்படி முடிவு செய்வது | கேட்கும்; `--yes` உடன், ஒவ்வொரு கோப்பின் இயல்புநிலை |
| `-y`, `--yes` | கேட்காமல் இயங்கும்; முரண்பாடுகள் `--prefer`-ஐப் பின்பற்றும் | off |
| `--dry-run` (global) | திட்டத்தை அச்சிடும், எதையும் மாற்றாது | off |

கணக்குகளைப் பெயராலோ எண்ணாலோ குறிப்பிடலாம்; உருப்படிகளைக் காற்புள்ளியால் பிரித்த பட்டியலாகக் கொடுக்கலாம். `ccam add` `--group <group>` (பலமுறை கொடுக்கலாம்) அல்லது `--no-group`-ஐ ஏற்கும்.

## இது எப்படி வேலை செய்கிறது

தொடர்புடைய கோப்புகள்:

- `~/.config/ccam/config.toml`: `[[group]]` பதிவுகள்: `name`, `items`, `members`, கோப்புறையின் பெயர் வேறுபடும்போது `dir`.
- `~/.local/share/ccam/profiles/<name>/`: கணக்கின் `CLAUDE_CONFIG_DIR`.
- `~/.local/share/ccam/groups/<folder>/`: பகிரப்பட்ட நகல்கள்.

`config.toml` படிக்கப்படும்போது, ஒவ்வொரு கணக்கின் குழுக்களும் ஒவ்வோர் உருப்படிக்கும் ஒரு கோப்புறையாகத் தீர்க்கப்படுகின்றன. ஐந்து கணக்குகளுக்கு இது சுமார் 25 µs எடுக்கும், அதனால் தொடக்கம் இப்போதும் `config.toml`-ஐ மட்டுமே படிக்கிறது. ஒரு கணக்குக்கு ஓர் உருப்படி இரண்டு குழுக்களிலிருந்து கிடைக்கும்படியான config பிழையாகும், அது சரிசெய்யப்படும் வரை எதுவும் தொடங்காது.

ஒரு மாற்றம் config-இன் ஒரு நகலின் மீது வேலை செய்கிறது:

1. கட்டளை அந்த நகலைத் திருத்துகிறது (`AddGroup`, `SetGroupItems`, `JoinGroup` …), அது விதிகளைச் சரிபார்க்கிறது.
2. `internal/group` பழையதையும் புதியதையும் ஒப்பிட்டு, உருப்படிகள் மாறும் ஒவ்வொரு கணக்குக்கும் `share.Build` மூலம் ஒரு திட்டத்தை உருவாக்குகிறது. திட்டங்கள் ஒன்றன்பின் ஒன்றாக உருவாக்கப்படுகின்றன, ஒவ்வொன்றும் முந்தையவை குழுக் கோப்புறைகளுக்குள் எதை வைக்கும் என்பதைப் பார்க்கிறது, அதனால் முதல் கணக்கு மட்டுமே தன் நகலை உள்ளே நகர்த்துகிறது. முதல் நகல், குழுக் கோப்புறையிடம் ஏற்கெனவே ஒன்று இருந்தால் அதிலிருந்து வரும்; இல்லையென்றால் `--from`, பிறகு இயல்புநிலைக் கணக்கு, பிறகு மற்றவை எண் வரிசைப்படி.
3. அந்தக் கணக்குகளில் ஒன்று இயங்கிக்கொண்டிருந்தால் ccam மறுக்கும்; Developer Mode இல்லாத Windows-இல், ஒரு கோப்புக்கு இணைப்பு தேவைப்பட்டாலும் மறுக்கும்.
4. முரண்பாடுகள் கேள்வி மூலமாகவோ `--prefer` மூலமாகவோ முடிவு செய்யப்படுகின்றன, திட்டம் அச்சிடப்படுகிறது, ccam கேட்கிறது.
5. எதுவும் நகர்வதற்கு முன் புதிய config சேமிக்கப்படுகிறது. ஒரு படி பாதியில் நின்றால், `ccam doctor --fix`-உம் மீண்டும் இயக்குவதும் சேமித்த குழுக்களை நோக்கித் தங்கள் திட்டத்தை உருவாக்கி, மாற்றத்தை முடிக்கும்.
6. திட்டங்கள் வரிசையாக இயங்குகின்றன. ஒவ்வொரு படியும் தரவைக் குழுவுக்குள்ளோ காப்புப்பிரதிக் கோப்புறைக்குள்ளோ நகர்த்துகிறது; எதுவும் நீக்கப்படுவதில்லை.

`share.Layout` என்பது ஒவ்வோர் உருப்படியும் உள்ளடக்கும் பாதைகளின் அனுமதிப் பட்டியல். அதில் இல்லாத எதுவும் ஒருபோதும் குழுவை அடைய முடியாது. `share.Never` `.credentials.json` மற்றும் `.claude.json`-ஐப் பெயரிடுகிறது, அவற்றில் ஏதேனும் ஒன்று layout-இல் தோன்றினால் `Build` ஓர் உள் பிழையுடன் நின்றுவிடும். `mcp` உருப்படிக்குப் பாதைகள் இல்லை: சர்வர் பட்டியல் `.claude.json`-க்குள் இருக்கிறது, அதனால் [MCP பகிர்வு](/features/mcp) குழுவின் `mcp.json` வழியாக வேலை செய்கிறது.

`side` வரலாற்றைப் பகிரத் தொடங்கும்போது, குழுவிடம் ஏற்கெனவே உள்ளடக்கம் இருந்தால், `projects/` என்ற ஒரு கோப்புறைக்கு நடப்பது இதுதான்:

அந்தப் பாதையில் குழுவிடம் இன்னும் எதுவும் இல்லையென்றால், அதைப் பகிரும் முதல் கணக்கு இதுவே, அதன் கோப்புறை அப்படியே அங்கே நகர்த்தப்படும். இல்லையென்றால் குழுவிடம் இல்லாத ஒவ்வொரு கோப்பும் குழுவுக்குள் நகர்த்தப்படும், இரு பக்கங்களிலும் உள்ள கோப்புகள் கணக்கின் கோப்புறையிலேயே இருக்கும், அதனால் குழுவின் பதிப்பு வைக்கப்படுகிறது. பிறகு கணக்கின் கோப்புறை, கணக்குக் கோப்புறைக்குள் `.ccam-backup/<time>/`-க்குச் செல்கிறது, அதன் இடத்தில் ஓர் இணைப்பு வருகிறது. உரையாடல் கோப்புகள் அவற்றின் session ID-யின் பெயரில் உள்ளன, அதனால் பல கணக்குகளின் வரலாறுகள் முரண்பாடின்றி ஒன்றிணையும். `plugins/` registries கணக்குக் கோப்புறை வழியான absolute பாதைகளைச் சேமிக்கின்றன; ccam அவற்றைக் குழுவின் கோப்புறைக்குத் திருப்பி, குழுவிடம் ஏற்கெனவே உள்ள registry-உடன் கணக்கின் உள்ளீடுகளை ஒன்றிணைக்கிறது.

வெளியேறுவது இணைப்பைத் தலைகீழாக்குகிறது:

<!-- motion:share-off -->

இணைப்பு groups கோப்புறைக்குள் சுட்டினால் மட்டுமே ccam அதை நீக்குகிறது, பிறகு குழுவின் தற்போதைய உள்ளடக்கத்தைக் கணக்குக்குள் நகலெடுக்கிறது. `--fresh` உடன் நகலெடுப்பது தவிர்க்கப்படும். மற்ற கணக்குகளுக்காகக் குழு அதன் உள்ளடக்கத்தை வைத்திருக்கும். கோப்புறை இன்னும் காலியாக உள்ள ஒரு குழுவுக்கு ஓர் உருப்படியை நகர்த்தும் கணக்கு, தான் பார்த்தவற்றின் நகலைக் கொண்டுவருகிறது, அதனால் அதன் கோப்புகள் அதனிடமே இருக்கும்; MCP சர்வர்களும் அதே வழியில் வருகின்றன. MCP பகிர்வதை நிறுத்தும் கணக்கு, ccam அதன் `.claude.json`-க்குள் நகலெடுத்த சர்வர்களை இழக்கும் (ஒரு காப்புப்பிரதி வைக்கப்படும்), ஏனெனில் அவை குழுவிலிருந்து வந்தவை.

இரு பக்கங்களிலும் வேறுபட்ட உள்ளடக்கத்துடன் உள்ள ஒரு தனிக் கோப்பு முரண்பாடு ஆகும்:

<!-- motion:share-conflict -->

`history.jsonl` `merge by line`, `keep group`, `use mine` ஆகியவற்றை வழங்கும், ஒன்றிணைத்தல் முதலில். மற்ற `.json` கோப்புகள் `keep group`, `use mine`, `merge JSON` ஆகியவற்றை வழங்கும். மற்ற எதுவும் `keep group` மற்றும் `use mine`-ஐ வழங்கும். `merge JSON` objects-ஐ recursive ஆக ஒன்றிணைக்கிறது, arrays-ஐ நகல்கள் இல்லாமல் இணைக்கிறது, இரு பக்கங்களும் ஒரே key-ஐ வேறுபட்ட மதிப்புகளுடன் அமைத்தால் குழுவின் மதிப்பை வைத்திருக்கிறது, அதனால் மற்ற கணக்குகள் எந்த மாற்றத்தையும் காணாது. `keep group` தவிர ஒவ்வொரு தேர்வும் முதலில் குழுவின் நகலைக் கணக்கின் `.ccam-backup/<time>/group/`-இல் சேமிக்கிறது. உங்கள் சொந்தக் கோப்பு எப்போதும் காப்புப்பிரதிக்குச் செல்லும்.

ஒவ்வொரு தொடக்கத்திலும், `share.Check` layout-இல் உள்ள ஒவ்வொரு பாதையையும் கணக்கின் குழுக்களுடன் `lstat` மற்றும் `readlink`-ஐ மட்டும் பயன்படுத்தி ஒப்பிடுகிறது. இல்லாத இணைப்பு அந்த இடத்திலேயே உருவாக்கப்படும். இணைப்பு இருக்க வேண்டிய இடத்தில் உண்மையான கோப்பு, தவறான இடத்துக்கான இணைப்பு, அல்லது காலாவதியான இணைப்பு இருந்தால் தொடக்கம் நின்று, `ccam doctor --fix`-ஐச் சுட்டிக்காட்டும்.

### மறுபெயரிடுதல், நீக்குதல், பழைய வடிவம்

- `ccam group rename` config-ஐ மட்டுமே மாற்றுகிறது. கோப்புறை தன் பெயரை வைத்திருக்கும், குழு அதை `dir` ஆகப் பதிவு செய்யும், அதனால் எதுவும் நகர்வதில்லை, எதுவும் இழக்கப்படவும் முடியாது.
- கணக்குகள் உள்ள குழுவை, நீங்கள் `--leave` சேர்க்காவிட்டால், `ccam group remove` மறுக்கும். அப்போது ஒவ்வொரு கணக்கும் ஒரு நகலை வைத்திருக்கும், வேறொரு குழு அந்தக் கோப்புறையைப் பயன்படுத்தாவிட்டால் அது `~/.local/share/ccam/trash/`-க்குச் செல்லும்.
- குழுக்களுக்கு முன், `config.toml` ஒவ்வொரு கணக்குக்கும் ஒரு `[profile.share]` அட்டவணையைச் சேமித்தது. ccam அந்த வடிவத்தை எதையும் நகர்த்தாமல் குழுக்களாகப் படிக்கிறது. முதல் சேமிப்பில் அது புதிய வடிவத்தை எழுதி, பழைய கோப்பை `config.toml.bak` ஆக வைத்திருக்கும். ஒரே கணக்குகளால் பகிரப்படும் உருப்படிகள் கோப்புறையின் பெயரிலான ஒரே குழுவாகின்றன; மற்றவை `default-history` போன்ற பெயர்களைப் பெற்று, அதே கோப்புறையைத் தொடர்ந்து பயன்படுத்துகின்றன.

### Windows-இல்

Windows, Developer Mode-இல் (Settings > System > For developers) அல்லது administrator-க்கு மட்டுமே symbolic links-ஐ உருவாக்குகிறது. அந்த உரிமை இல்லாமல், பகிரப்பட்ட கோப்புறை ஒரு directory junction ஆகிறது, Claude Code-க்கு அது அதே போல வேலை செய்யும். பகிரப்பட்ட கோப்பு (`settings.json`, `CLAUDE.md`, `history.jsonl`) symbolic link ஆக மட்டுமே இருக்க முடியும், அதனால் அது தேவைப்படும் குழு மாற்றம் எதுவும் நகர்வதற்கு முன்பே மறுக்கப்படும்.

## பாதுகாப்பும் விளிம்பு நிலைகளும்

- **இயங்கும் கணக்குகள்.** ஒரு மாற்றம் நகர்த்தும் கணக்குகளில் ஒன்றாக Claude Code இயங்கும்போது அந்த மாற்றம் மறுக்கப்படும், ஏனெனில் அமர்வு அந்தக் கோப்புகளில் தொடர்ந்து எழுதுகிறது. வெளியேறுவதும் இணைவதும் குறிப்பிடப்பட்ட கணக்கை மட்டுமே பாதிக்கும். `--dry-run` அப்போதும் திட்டத்தை அச்சிடும்.
- **காப்புப்பிரதிகள்.** ஒவ்வொரு திட்டத்துக்கும் கணக்குக் கோப்புறையில் தனி `.ccam-backup/<time>/` கோப்புறை கிடைக்கும். ccam அவற்றை ஒருபோதும் நீக்குவதில்லை.
- **உங்கள் சொந்த இணைப்புகள்.** ஒரு பாதை நீங்கள் உருவாக்கிய இணைப்பாக ஏற்கெனவே இருந்தால், எடுத்துக்காட்டாக ஒரு dotfiles repository-க்கு, குழு காலியாக இருந்தால், ccam இணைப்பின் இலக்கைக் குழுவுக்குள் நகலெடுத்து, இணைப்பையே காப்புப்பிரதிக்கு நகர்த்தும். இலக்கு தொடப்படாது.
- **இறக்குமதி செய்த கோப்புறைகள்.** `ccam import` மூலம் இருந்த இடத்திலேயே பதிவுசெய்யப்பட்ட கணக்கு (`~/.claude` போன்றது) அதே இடத்தில் மாறும், அதனால் வெறும் `claude`-உம் மாற்றத்தைக் காணும்; திட்டம் இதைச் சொல்லும்.
- **ஒரே கோப்புறையில் இரண்டு கணக்குகள்.** வரலாற்றைப் பகிரும் கணக்குகள் ஒரே கோப்புகளில் எழுதுகின்றன. ஏற்கெனவே ஒன்று இயங்கும் கோப்புறையில் இரண்டாவது கணக்கு தொடங்கினால், ccam எச்சரித்துக் கேட்கும்.
- **கைத் திருத்தங்கள்.** கணக்காக இல்லாத member புறக்கணிக்கப்பட்டு, `ccam doctor` மூலம் தெரிவிக்கப்படும். `local`, `on`, `off`, `none` ஆகிய பெயர்கள் குழுப் பெயர்களாக இருக்க முடியாது.
