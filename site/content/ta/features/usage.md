ஒவ்வொரு கணக்கும் 5 மணி நேர வரம்பு, வாராந்திர வரம்பு மற்றும் ஒவ்வொரு model-இன் சொந்த வாராந்திர வரம்பு (Fable போன்றது) ஆகியவற்றில் எவ்வளவு பயன்படுத்தியுள்ளது என்பதை, ஒவ்வொரு வரம்புக்கும் ஒரு பட்டையாக, அது மீட்டமைக்கப்படும் வரையிலான நேரத்துடன் `ccam usage` காட்டுகிறது. நீண்ட வேலையைத் தொடங்கும் முன், அல்லது வரம்பு நெருங்குவதாக Claude Code சொல்லும்போது, எந்தக் கணக்கில் இன்னும் இடம் உள்ளது என்று பார்க்க இதைப் பயன்படுத்துங்கள். `ccam statusline` என்பது Claude Code-க்கான நிலை வரிக் கட்டளை: அது கணக்கின் பெயரையும் பயன்பாட்டையும் Claude Code-க்குள் காட்டி, எண்களை `ccam usage`-க்காகச் சேமிக்கிறது.

## பயன்பாடு

```sh
ccam usage                  # every account, once
ccam u                      # the same, shorter
ccam usage --watch          # redraw every 60 seconds until Ctrl+C
ccam usage --watch=10       # redraw every 10 seconds
ccam usage -v               # add where the numbers came from
ccam usage --json           # machine-readable, one object per account
ccam usage --source cache   # saved numbers only, no network
ccam usage --refresh        # also renew expired logins of accounts not running
ccam usage --source claude  # let Claude Code look it up: ccam sends no token
ccam statusline install     # set the status line in every account's settings.json
```

ஒவ்வொரு கணக்குக்கும் அதன் எண், பெயர், அதன் எண்கள் எவ்வளவு பழையவை என்பதுடன் ஒரு வரி வருகிறது; `(cached)` என்றால் அவை endpoint-இலிருந்து அல்ல, சேமிக்கப்பட்ட கோப்பிலிருந்து வருகின்றன. அதன் கீழ், ஒவ்வொரு வரம்புக்கும் ஒரு வரி 20 கட்டப் பட்டை, சதவீதம், கால அளவு மீட்டமைக்கப்படும் வரையிலான நேரம் ஆகியவற்றைக் காட்டும்: `5-hour`, `Weekly` (எல்லா model-களும்), பிறகு `Fable` போன்ற ஒவ்வொரு model-இன் சொந்த வாராந்திர கால அளவு. கணக்குக்கு இல்லாத கால அளவு `-` எனக் காட்டும். சதவீதம் 80% முதல் மஞ்சளாகவும் 100%-இல் சிவப்பாகவும் மாறும். Claude Code பயன்பாட்டு வரம்பில் ஒரு கோரிக்கையை மறுத்தபோது நிரம்பியதாகத் தெரிவித்த கால அளவு, சேமித்த எண்கள் என்ன சொன்னாலும், அதன் மீட்டமைப்பு வரை 100% எனக் காட்டும் ([வரம்புப் பதிவு](#the-limit-record) பாருங்கள்). டெர்மினலில் ஒவ்வொரு கணக்கும் உடனே `fetching…` எனத் தோன்றும், அது பதில் அளிக்கும்போது அதன் வரிகள் வரையப்படும். கடைசி வரி, [`ccam next --auto`](/features/next) அதே விதிகளால் தேர்ந்தெடுக்கும் கணக்கைப் பெயரிடும் (`auto_max_usage`, `auto_strategy`, இயங்கும் அமர்வுகள், `cross_org` அமைக்கப்படாவிட்டால் கடைசியாகப் பயன்படுத்திய கணக்கின் நிறுவனத்தின் கணக்குகள் மட்டும், 100%-இல் உள்ள ஒவ்வொரு கால அளவும் தவிர்க்கப்படும், அதனால் வாரம் நிரம்பிய கணக்கு ஒருபோதும் பெயரிடப்படாது), உங்களிடம் ஒன்றுக்கு மேற்பட்ட கணக்குகள் இருந்தால் மட்டுமே அது தோன்றும். இயல்புநிலை `headroom` strategy உடன் அது `→ Most headroom: <name>` எனக் காட்டும்; `expiring` அல்லது `balance` உடன், `→ next --auto picks personal: its 5-hour window resets first, in 1h 12m (40% of its 5 hours used)` போன்ற காரணத்தைத் தரும்.

**Team மற்றும் Enterprise இருக்கைகள்.** தானியங்கித் தேர்வு (`ccam next`, `--fallback`, `ccam pick`, டாஷ்போர்டின் `n`, நீங்கள் இயக்கும்போது [`auto_switch`](/features/next#auto-switch)) ஒரே Claude Team அல்லது Enterprise நிறுவனத்தின் இருக்கைகளுக்கு இடையேயும் மாறுகிறது. Anthropic-இன் உதவி மையம் "Each seat on a Team plan is assigned to one named individual, and only that person may use it" (Team திட்டத்தின் ஒவ்வொரு இருக்கையும் பெயர் குறிப்பிடப்பட்ட ஒரு நபருக்கு ஒதுக்கப்படுகிறது, அந்த நபர் மட்டுமே அதைப் பயன்படுத்தலாம்) என்றும், "Users can't route their work through another user's account to use that user's remaining usage" (மற்றொரு பயனரின் மீதமுள்ள பயன்பாட்டைப் பயன்படுத்திக்கொள்ள, பயனர்கள் தங்கள் வேலையை அந்தப் பயனரின் கணக்கு வழியாக அனுப்ப முடியாது) என்றும் கூறுகிறது ([Team திட்டங்கள்](https://support.claude.com/en/articles/12004354-purchase-and-manage-seats-on-team-plans#h_b8a7d07129); இதேபோல் [Enterprise திட்டங்களுக்கும்](https://support.claude.com/en/articles/13393991-purchase-and-manage-seats-on-enterprise-plans#h_fa6b9cade0)). எனவே, இருக்கைகளுக்கு இடையே தானியங்கித் தேர்வைப் பயன்படுத்துவது Anthropic-இன் விதிமுறைகளை மீறக்கூடும். அங்கே அதைப் பயன்படுத்துவதா என்பது உங்கள் முடிவு: அதை நம்பியிருக்கும் முன், உங்கள் நிறுவனத்திடமும் Anthropic-இடமும் கேட்டு உறுதிசெய்துகொள்ளுங்கள். தனிப்பட்ட திட்டங்கள் (Pro, Max) பற்றி [அடிக்கடி கேட்கப்படும் கேள்விகளில் உள்ள விதிமுறைக் குறிப்பு](/docs/faq#am-i-allowed-to-use-several-claude-code-accounts) விளக்குகிறது.

உள்நுழையாத கணக்கு `not logged in → ccam login <name>` எனக் காட்டும், API key கணக்கு `no limits (API)` எனக் காட்டும். காலாவதியான access token, சேமித்த எண்கள் இருந்தால் அவற்றுக்கு மேலே, ``access token expired; `ccam <name>` renews it when it starts`` எனக் காட்டும்: அடுத்த தொடக்கத்தில் Claude Code அதைப் புதுப்பிக்கும். refresh token காலாவதியானதாலோ, சர்வர் மறுத்த பிறகு Claude Code அழித்ததாலோ முழுவதுமாகக் காலாவதியான உள்நுழைவு `` login expired → `ccam login <name>` `` எனக் காட்டும்.

`ccam statusline install`-க்குப் பிறகு, Claude Code `[work] · Opus · 5h 24% · 7d 41%` போன்ற ஒரு வரியைக் காட்டும்.

## Options

| Option | என்ன செய்யும் | இயல்புநிலை |
| --- | --- | --- |
| `--json` | அறிக்கைகளை JSON ஆக அச்சிடும்: `name`, `slot`, `status`, `limits` (கணக்கில் usage credits இயக்கத்தில் இருந்தால் `credits` உடன்), `source`, `at`, `error`, வரம்புப் பதிவு கால அளவுகளை 100%-க்கு அமைக்கும்போது `limited`, `limited_windows`. கணக்குகள் இல்லாதபோது `[]` அச்சிடும் | off |
| `--watch[=N]` | நீங்கள் Ctrl+C அழுத்தும் வரை ஒவ்வொரு `N` வினாடிக்கும் மீண்டும் வரையும். `--watch` மட்டும், அல்லது 0 அல்லது அதற்குக் குறைவான மதிப்பு, 60 எனப் பொருள்படும். மதிப்பு `=`-க்குப் பிறகு வர வேண்டும்: `--watch 10` ஒரு குறிப்புடன் மறுக்கப்படும் | off |
| `-v`, `--verbose` | ஒவ்வொரு கணக்கின் கீழும் ஒரு `source:` வரியைச் சேர்க்கும்: அதன் எண்கள் எங்கிருந்து வந்தன (usage endpoint, Claude Code, நிலை வரி, சேமித்த கோப்பு, அல்லது Claude Code தெரிவித்த பயன்பாட்டு வரம்பு). வரம்புப் பதிவு எண்களின் மேல் பொருந்தும்போது, `Weekly full: Claude Code reported the usage limit 1h 0m ago, so 100% until the reset` போன்ற ஒரு வரி பின்தொடரும் | off |
| `--no-cache` | 60 வினாடி cache-ஐப் புறக்கணித்து endpoint-இடம் மீண்டும் கேட்கும் | off |
| `--source live\|claude\|cache` | `live` கணக்கின் token உடன் endpoint-இடம் கேட்கும்; `claude` Claude Code-ஐக் கொண்டு தேடச் செய்யும் (கீழே); `cache` சேமித்த எண்களை மட்டுமே காட்டும் | `usage_source`, இல்லையெனில் `live` |
| `--refresh` | காலாவதியான access tokens-ஐப் புதுப்பிக்கும், இயங்காத கணக்குகளுக்கு மட்டும். ஒரு புதுப்பிப்புக்கு 30 வினாடிகள் வரை ஆகலாம் | off |
| `--dry-run` | ஏற்கப்படும்: `ccam usage` தன் சொந்த cache-ஐத் தவிர எதையும் மாற்றுவதில்லை. `--refresh` உடன் சேர்த்தால் மறுக்கப்படும்: `--dry-run cannot be combined with --refresh, which rewrites login tokens` | off |

வேறு எந்த `--source` மதிப்பும் `--source must be live, claude or cache` என்று தோல்வியடையும்.

### Claude Code-இடமிருந்தே பயன்பாடு

`config.toml`-இன் மேற்பகுதியில் (முதல் `[[group]]`, `[[profile]]` அல்லது `[[folder]]`-க்கு மேலே) `usage_source = "claude"` இருந்தால், அல்லது `--source claude` உடன், ccam உள்நுழைவு token-ஐப் படிப்பதே இல்லை. ஒவ்வொரு கணக்குக்கும் அது கணக்கின் கோப்புறையில் `claude -p --input-format stream-json --output-format stream-json --verbose --safe-mode --no-session-persistence`-ஐத் தொடங்கி, Claude Code-இன் `get_usage` கோரிக்கையை standard input-இல் அனுப்புகிறது (Claude Code 2.1.270 அல்லது பிந்தையது); Claude Code தன் சொந்த உள்நுழைவுடன் பயன்பாட்டைத் தேடி, 5 மணி நேர, வாராந்திர, model கால அளவுகளுடன் பதில் அளிக்கிறது. `--safe-mode` கணக்கின் hooks, MCP சர்வர்கள், plugins தொடங்காமல் தடுக்கிறது, எந்த அமர்வும் சேமிக்கப்படுவதில்லை. ஒவ்வொரு கணக்குக்கும் ஒரு Claude Code தொடக்கம், சுமார் ஒரு வினாடி, ஆகும், அதனால் இந்த மூலம் `live`-ஐ விட மெதுவானது; கணக்குகள் ஒரே நேரத்தில் கேட்கப்படுகின்றன, ஒவ்வொன்றும் 20 வினாடிகளுக்குள், 60 வினாடி cache வழக்கம்போல் பொருந்தும். access token காலாவதியான, அல்லது 5 நிமிடங்களுக்குள் காலாவதியாகும் உள்நுழைவுக்கு 50 வினாடிகள் கிடைக்கும், ஏனெனில் Claude Code தொடங்கும்போது அதைப் புதுப்பிக்கிறது, இடையில் துண்டிக்கப்பட்ட புதுப்பிப்பு உள்நுழைவை இழக்கச் செய்யக்கூடும். கைவிடப்படும் தேடல், SIGTERM மூலம் முடிக்கும்படி Claude Code-இடம் கேட்கிறது, அதனால் அது தொடங்கிய புதுப்பிப்பை முடிக்கிறது (Windows-இல் அத்தகைய signal இல்லை; அங்கே அது நிறுத்தப்படுகிறது). முழுவதுமாகக் காலாவதியான உள்நுழைவு, Claude Code-ஐத் தொடங்காமலே `` login expired → `ccam login <name>` `` எனக் காட்டும். Claude Code அந்தக் கோரிக்கையைச் சோதனை நிலையில் உள்ளதாகக் குறிக்கிறது, அதனால் அது பதில் அளிப்பதை நிறுத்தினால், ccam சேமித்த எண்களைக் காட்டும், `ccam doctor` அதைத் தெரிவிக்கும். தன் சொந்தத் தேடல் தோல்வியடைந்தது என்று Claude Code பதில் அளிக்கும்போது, ccam வரம்புகள் இல்லாத plan-ஐ அல்ல, `the usage endpoint gave Claude Code no usage (it may be refusing lookups for now)` உடன் சேமித்த எண்களைக் காட்டும். `--dry-run` Claude Code-ஐத் தொடங்காது (அது கணக்கின் கோப்புறையில் எழுதும்), சேமித்த எண்களைக் காட்டும். `usage_source` `live` அல்லது `claude`-ஐ ஏற்கும்; `cache` ஒரு `--source` தேர்வு மட்டுமே. `ccam usage` எந்த argument-ஐயும் ஏற்காது.

`ccam statusline` Claude Code-இன் நிலை வரி JSON-ஐ standard input-இலிருந்து படிக்கிறது. அதன் ஒரே option `--wrap <command>`: ஏற்கெனவே உள்ள ஒரு நிலை வரிக் கட்டளை, அதன் வெளியீட்டின் முதல் வரிக்கு முன் கணக்கின் பெயர் சேர்க்கப்படும். `ccam statusline install` எந்த option-ஐயும் ஏற்காது. இரண்டும் `--dry-run`-ஐ `` --dry-run is not supported by `ccam statusline`; nothing was changed `` என்று மறுக்கும்.

## இது எப்படி வேலை செய்கிறது

எண்கள் இரண்டு இடங்களிலிருந்து வருகின்றன: ஒவ்வொரு கணக்கின் சொந்த உள்நுழைவுடன் அழைக்கப்படும் Anthropic-இன் ஆவணப்படுத்தப்படாத usage endpoint `GET https://api.anthropic.com/api/oauth/usage`, மற்றும் Claude Code தன் நிலை வரிக் கட்டளைக்குக் கொடுக்கும் மதிப்புகள். இவை அனைத்தும் `internal/usage`-இல் உள்ளன.

1. `cli.usageCmd` `config.toml`-ஐ ஏற்றி, ஒவ்வொரு கணக்குக்கும் ஒரு `usage.Account`-ஐ உருவாக்குகிறது: அதன் கோப்புறை `~/.local/share/ccam/profiles/<name>/`, அதன் அமர்வுக் குறிப்பான்கள் (கணக்குக் கோப்புறையில் உள்ள Claude Code-இன் சொந்தப் பதிவுகளுடன் சேர்ந்து, அது இயங்குகிறதா என்று அவை சொல்கின்றன), அது இருந்த இடத்திலேயே இறக்குமதி செய்யப்பட்டதா என்பது.
2. `Fetcher.FetchAll` ஒவ்வொரு கணக்குக்கும் ஒரு goroutine-ஐத் தொடங்குகிறது. அவை அனைத்தும் ஒரே `http.Client`-ஐப் பகிர்கின்றன, அதனால் endpoint-க்கான இணைப்புகள் மீண்டும் பயன்படுத்தப்படுகின்றன. இணைப்புக்கு 2 s ஆகலாம், ஒவ்வொரு கணக்குக்கும் மொத்தம் 3 s கிடைக்கும். redirect token-ஐ வேறிடத்துக்கு மீண்டும் அனுப்பிவிடும் என்பதால் client redirects-ஐப் பின்தொடராது, பதிலில் அதிகபட்சம் 1 MB மட்டுமே படிக்கும்.
3. ஒவ்வொரு கணக்கும் முடியும்போது, அதன் வரிசை மீண்டும் வரையப்படும். தோல்வியடையும் அல்லது நேரத்துக்குள் பதில் அளிக்காத கணக்கு சேமித்த எண்களுக்குத் திரும்பும், அதனால் ஒரு மெதுவான கணக்கு மற்றவற்றை ஒருபோதும் தாமதப்படுத்தாது.

ஒவ்வொரு கணக்கும் endpoint-க்கு எதிராகத் தன் சொந்த goroutine-இல் இயங்குகிறது; நேரம் கடந்துவிடும் கணக்கு அதற்குப் பதிலாகச் சேமித்த எண்களைக் காட்டும்.

<!-- motion:usage-fetch -->

`personal` மற்றும் `work` நேரத்துக்குள் பதில் அளித்து நேரடி எண்களைக் காட்டுகின்றன. `side` 3 s-க்கு மேல் எடுக்கிறது, அதனால் `fallback()` அதற்குப் பதிலாக அதன் சேமித்த எண்களைக் காட்டுகிறது. `usage.Table()` ஒவ்வொரு கணக்குக்கும் ஒரு தொகுதியை வரைகிறது, `usage.Best()` கடைசி வரியில் பெயரிடப்படும் கணக்கைத் தேர்ந்தெடுக்கிறது.

ஒரு கணக்குக்கு, `Fetcher.Fetch` இந்தச் சரிபார்ப்புகளை வரிசையாகச் செய்கிறது:

<!-- motion:usage-cache -->

1. `--source cache` கொடுத்தால், அது நேரடியாக `fallback()`-க்குச் செல்லும்.
2. `--no-cache` அமைக்கப்படாவிட்டால், `~/.local/state/ccam/usage/<name>.json`-இல் 60 வினாடிகளுக்குள் (`CacheTTL`) அளவிடப்பட்ட நேரடி முடிவு, இப்போதைய நிலையில் மதிப்பிடப்பட்டுப் பயன்படுத்தப்படும்: அதன் பிறகு மீட்டமைக்கப்பட்ட கால அளவு 0% எனக் காட்டும், கடிகாரத்தை விட முன்னால் தேதியிட்ட கோப்பு புதியதாகக் கருதப்படாது. `ccam usage`-ஐத் தொடர்ந்து இருமுறை இயக்கினால் ஒவ்வொரு கணக்குக்கும் ஒரே ஒரு கோரிக்கை மட்டுமே செலவாகும்.
3. `readCredentials()` `.credentials.json`-ஐ (அல்லது macOS Keychain-ஐ) மாற்றாமல் படிக்கிறது, `claudeAiOauth` key மட்டுமே decode செய்யப்படுகிறது. subscription உள்நுழைவு இல்லையென்றால் `not logged in`, அல்லது `.claude.json`-இல் API key இருந்தால் `no limits (API)`. refresh token காலாவதியான, அல்லது Claude Code அழித்த உள்நுழைவு `` login expired → `ccam login <name>` `` ஆகும், அது தேடப்படாது.
4. காலாவதியான access token பயன்படுத்தப்படுவதில்லை. `--refresh` இல்லாமல், கணக்கு அதன் சேமித்த எண்களை ``access token expired; `ccam <name>` renews it when it starts`` உடன் காட்டும்.
5. இல்லையென்றால் ccam endpoint-ஐ அழைக்கிறது. 401 அல்லது 403 காலாவதியான உள்நுழைவாகக் கருதப்படும் (`login expired: authentication failed (401)`), வேறு எந்த status-உம் அல்லது படிக்க முடியாத body-உம் பிழையாகக் கருதப்படும், இரண்டுமே சேமித்த எண்களுக்குத் திரும்பும். Ctrl+C மூலம் முடிக்கப்பட்ட தேடல் `cancelled` என்று சொல்லும். 429 என்றால் endpoint மிக அடிக்கடி கேட்கப்படுகிறது என்று பொருள்: ccam மீண்டும் கேட்க வேண்டிய நேரத்துடன் (`Retry-After`, அல்லது 5 நிமிடங்கள், அதிகபட்சம் ஒரு மணி நேரம்) `<name>.pause`-ஐ எழுதி, `rate limited by the usage endpoint; asking again after 15:10` என்று சேமித்த எண்களைக் காட்டி, அதுவரை `--no-cache` உடனும் அந்தக் கணக்குக்கு endpoint-ஐ அழைக்காது. உடனே மீண்டும் முயன்றால் வரம்பு நீடிக்க மட்டுமே செய்யும்.
6. சரியான பதில், அது அளவிடப்பட்ட நேரத்துடன் `<name>.json`-இல் எழுதப்படும்.

`fallback()` மிகப் புதிய சேமித்த தேடலை (`<name>.json`, அல்லது Claude Code-இன் தேடல்களிலிருந்து `<name>.claude.json`) எடுத்து, அதற்குப் பிறகு `<name>.statusline.json` எழுதப்பட்டிருந்தால், நிலை வரியின் 5 மணி நேர, வாராந்திரக் கால அளவுகளை அதன் மேல் வைக்கிறது; நிலை வரியிடம் இல்லாத model கால அளவுகள் தேடல் சேமித்தபடியே இருக்கும். சேமித்த எண்களைக் காட்டும் முன், அது ஒவ்வொரு கால அளவின் மீட்டமைப்பு நேரத்தையும் சரிபார்க்கிறது: எண்கள் சேமிக்கப்பட்ட பிறகு மீட்டமைக்கப்பட்ட கால அளவு 0% எனக் காட்டும், ஏனெனில் பழைய சதவீதம் இனி பொருந்தாது. அதனால்தான் மேலே உள்ள `personal` மீட்டமைப்பு நேரம் இல்லாமல் `0%` காட்டுகிறது.

endpoint-க்கு இரண்டு பதில் வடிவங்கள் உள்ளன. புதியதில் `session` (5 மணி நேரம்), `weekly_all`, `weekly_scoped` (model-வாரியாக) உள்ளீடுகளுடன் ஒரு `limits` array உள்ளது. பழையதில் `five_hour`, `seven_day`, `seven_day_opus`, `seven_day_sonnet` objects உள்ளன. `ParseLive` இரண்டையும் படிக்கிறது: `limits` array முன்னுரிமை பெறும், அது உள்ளடக்காதவற்றைப் பழைய objects நிரப்பும். வரம்புகளே இல்லாத body மாறிய வடிவமாகத் தெரிவிக்கப்படும், அதைப் பற்றி `ccam doctor` உங்களுக்குச் சொல்லும்.

### வரம்புப் பதிவு

Claude Code ஒரு turn-ஐப் பயன்பாட்டு வரம்பில் நிறுத்தும்போது, [ccam plugin](/docs/install#claude-code-plugin)-இன் hook மறுக்கப்பட்ட கோரிக்கையை உரையாடலிலிருந்து படிக்கிறது: எந்தக் கால அளவு நிரம்பியது (5 மணி நேரம், வாராந்திரம், Opus அல்லது Sonnet), அது எப்போது மீட்டமைக்கப்படும். அதை அது `~/.local/state/ccam/usage/<name>.limit.json`-இல் எழுதுகிறது. `Fetch` எல்லா மூலங்களிலிருந்தும் தனக்குத் தெரிந்த மற்ற எல்லாவற்றின் மேலும் இந்தப் பதிவை வைக்கிறது: அதிலுள்ள ஒவ்வொரு கால அளவும், சேமித்த எண்கள் எவ்வளவு பழையவையாகவோ குறைவாகவோ இருந்தாலும், அதன் மீட்டமைப்பு வரை 100% ஆகக் கணக்கிடப்படுகிறது, அதனால் `ccam next --auto`, `ccam pick`, `--fallback`, [`auto_switch`](/features/next#auto-switch) ஆகியவை அதுவரை அந்தக் கணக்கை மீண்டும் தேர்ந்தெடுப்பதில்லை. வேறு எதுவும் தெரியாதபோது, அந்தப் பதிவு மட்டுமே கணக்கு காட்டுவது (`-v` உடன் `source: the usage limit Claude Code reported`). யாரும் அமர்ந்திருக்காத அமர்வுகள் (`-p`, பின்னணி அமர்வுகள்) எந்தப் பதிவையும் எழுதுவதில்லை, நிறுவனத்தின் நிறுத்தமும் (பயன்பாடு தீர்ந்தது, $0-க்கு அமைக்கப்பட்ட குழு) எழுதுவதில்லை, ஏனெனில் அதன் admins அதை எப்போது வேண்டுமானாலும் நீக்கலாம். வேறொரு Claude கணக்கில் `ccam login` செய்வது பதிவைக் கைவிடுகிறது; கோப்பை நீக்குவதும் அதை அழிக்கிறது.

### Tokens-ஐப் புதுப்பித்தல்

Refresh tokens சுழற்சி முறையில் மாறும்: ஒன்றைப் புதுப்பித்தால் புதிய refresh token கிடைக்கும், பழையது செல்லாததாகிவிடும். அதே கணக்காக Claude Code இயங்கிக்கொண்டிருக்கும்போது ccam உள்நுழைவைப் புதுப்பித்தால், அந்த அமர்வு வெளியேற்றப்படும். அதனால் நீங்கள் `--refresh` கொடுக்காதவரை, `ccam usage` tokens-ஐப் படிக்கும், ஒருபோதும் எழுதாது. கொடுத்தால் `Fetcher.refresh`:

1. `ccam import` மூலம் இருந்த இடத்திலேயே பதிவுசெய்யப்பட்ட கணக்குகளை மறுக்கும், ஏனெனில் ccam-க்குத் தெரியாமல் வெறும் `claude` அந்த உள்நுழைவைப் பயன்படுத்தக்கூடும்;
2. macOS Keychain-இல் சேமிக்கப்பட்ட உள்நுழைவுகளை மறுக்கும்;
3. இரண்டு ccam processes ஒரே token-ஐ இருமுறை புதுப்பிக்காமல் இருக்க, `~/.local/state/ccam/locks/profile-<name>.refresh.lock` என்ற lock கோப்பை எடுக்கும்; அது பிடிக்கப்பட்டிருக்கும்போது, கணக்கு `token not renewed: another ccam is using this login right now (a refresh, rename, remove or logout)` எனக் காட்டும். `ccam rename`, `remove`, `logout` ஆகியவையும் அதை எடுக்கின்றன, புதுப்பிப்பு இயங்கும்போது மறுக்கின்றன;
4. lock-இன் கீழ், அந்தக் கணக்கின் அமர்வு, அது எப்படித் தொடங்கப்பட்டிருந்தாலும் (ccam வழியாக, வெறும் `claude`, ஒரு IDE, அல்லது ஒரு பின்னணி அமர்வும் அதன் பின்னால் உள்ள, உள்நுழைவைத் தானே புதுப்பிக்கும் daemon-உம்), இயங்கிக்கொண்டிருந்தால் மறுக்கும், மற்றொரு process ஏற்கெனவே token-ஐப் புதுப்பித்திருந்தால் கோரிக்கையைத் தவிர்க்கும்;
5. கணக்குக் கோப்புறையில் Claude Code தன் சொந்தப் புதுப்பிப்பு locks-ஐ (`.oauth_refresh.lock`, `<folder>.lock`) பிடித்திருக்கும்போது எதையும் அனுப்பாது: அப்போது Claude Code அந்த உள்நுழைவைப் புதுப்பித்துக்கொண்டிருக்கிறது;
6. refresh token-ஐ token endpoint-க்கு அனுப்பி, Claude Code தன் சொந்தப் புதுப்பிப்புகளுக்குக் கொடுக்கும் நேரமான 30 வினாடிகள் வரை பதிலுக்காகக் காத்திருக்கும். ஒருமுறை அனுப்பப்பட்ட கோரிக்கை, Ctrl+C-ஆல் கூட, ஒருபோதும் துண்டிக்கப்படாது, ஏனெனில் சர்வர் ஏற்கெனவே refresh token-ஐ மாற்றியிருக்கலாம், அதன் பதில் மட்டுமே இன்னும் உள்நுழைவைக் காக்கிறது: Ctrl+C அல்லது hangup மற்ற தேடல்களை முடிக்கும், பதில் சேமிக்கப்பட்டதும் ccam வெளியேறும் (Ctrl+C-க்குப் பிறகு 130);
7. Claude Code-இன் எழுதுதல் lock-இன் (`.storage-write.lock`) கீழ் சேமித்து, அந்த நேரத்தில் உள்ளபடியே `.credentials.json`-இன் token புலங்களை மட்டுமே மாற்றும்: இடையில் Claude Code எழுதியவை (ஒரு MCP உள்நுழைவு) அப்படியே இருக்கும், இடையில் Claude Code புதுப்பித்த உள்நுழைவு வைக்கப்படும், வெளியேற்றம் ஒருபோதும் மாற்றியமைக்கப்படாது. புதிய refresh token-இன் ஆயுட்காலத்தைப் பதில் கொடுத்தால், Claude Code செய்வது போலவே அது `refreshTokenExpiresAt` ஆகச் சேமிக்கப்படும்.

நிறைவேறாத புதுப்பிப்பு காரணத்தை, கணக்கு வரியிலோ அதன் சேமித்த எண்களுக்கு மேலோ சொல்லும்: எடுத்துக்காட்டாக `token not renewed: a session is running`, அல்லது கோரிக்கை அனுப்பப்பட்டும் அதன் பதிலைப் பயன்படுத்தவோ சேமிக்கவோ முடியாதபோது `login may be lost: …`, அதன் பிறகு Claude Code உள்நுழையச் சொன்னால் `ccam login <name>` இயக்கும்படியான ஆலோசனையுடன்.

### நிலை வரி சேகரிப்பான்

Claude Code நிலை வரிக் கட்டளையை இயக்கி, அதற்கு ஒரு JSON ஆவணத்தை pipe செய்கிறது. ccam அதிலிருந்து model பெயரையும் `rate_limits`-ஐயும் படிக்கிறது:

<!-- motion:usage-statusline -->

1. `runStatusline` கணக்கை `CCAM_PROFILE`-இலிருந்து கண்டுபிடிக்கிறது, இதை ccam Claude Code-ஐத் தொடங்கும்போது அமைக்கிறது; இல்லையென்றால் `CLAUDE_CONFIG_DIR`-ஐக் கணக்குக் கோப்புறைகளுடன் ஒப்பிட்டுக் கண்டுபிடிக்கிறது.
2. `ParseStatusLine` `rate_limits.five_hour` மற்றும் `rate_limits.seven_day`-ஐப் படிக்கிறது. API key கணக்குகளுக்கோ, அமர்வின் முதல் பதிலுக்கு முன்போ JSON-இல் rate limits இருக்காது; அப்போது எதுவும் சேமிக்கப்படாது.
3. `SaveStatusLine` `~/.local/state/ccam/usage/<name>.statusline.json`-ஐ எழுதுகிறது. endpoint பதில் அளிக்காதபோது `ccam usage` அதைப் பயன்படுத்தும்.
4. ccam `[name] · model · 5h N% · 7d N%` என்று அச்சிடுகிறது. `--wrap` உடன், அது உங்கள் கட்டளையை அதே உள்ளீட்டுடன் `sh -c` மூலம் இயக்கி, Claude Code நிலை வரியைக் காட்டுவது போலவே அதன் வெளியீட்டை அச்சிடும்: வெற்றாக இல்லாத ஒவ்வொரு வரியும், முதல் வரிக்கு முன் `[name]` உடன். தோல்வியடையும் கட்டளை கணக்கின் பெயரை மட்டுமே காட்டும். Windows-இல் அது கட்டளையை Claude Code இயக்குவது போலவே இயக்குகிறது: Git Bash நிறுவப்பட்டிருந்தால் அதனுடன், இல்லையெனில் PowerShell-உடன்.
5. 5 மணி நேர அல்லது வாராந்திரப் பயன்பாடு 90% அல்லது அதற்கு மேல் இருந்து, வேறொரு கணக்கும் இருந்தால், வரி `→ ccam next --auto --continue` உடன் முடிகிறது, எடுத்துக்காட்டாக `[work] · Opus · 5h 93% · 7d 41% · → ccam next --auto --continue`.

wrap செய்யப்பட்ட கட்டளைக்குத் தனக்கென நேர வரம்பு இல்லை: Claude Code ஒரு நிலை வரிக் கட்டளைக்கு 10 நிமிடங்கள் கொடுக்கிறது, புதிய புதுப்பிப்பு தொடங்கும்போது ஓர் இயக்கத்தை நிறுத்துகிறது, அதனால் மெதுவான கட்டளை ccam இல்லாமல் தோன்றுவது போலவே தோன்றும். Claude Code ccam-ஐ முடிக்கும்போது, கட்டளையும் முடியும் (Linux, macOS-இல் அது தொடங்கிய ஒவ்வொரு process உடனும்).

`ccam statusline install` ஒவ்வொரு கணக்கின் `settings.json`-இலும் `statusLine`-ஐ எழுதுகிறது, object-இன் `padding`, `refreshInterval`, `hideVimModeIndicator` போன்ற மற்ற keys-ஐ வைத்திருக்கிறது. ஒரு கணக்கிடம் ஏற்கெனவே நிலை வரிக் கட்டளை இருந்தால், ccam அதை `--wrap '<old command>'` ஆக வைத்திருக்கும்; Windows-இல் `--wrap-base64 <base64>` ஆக, அதற்கு எந்த shell-இலும் மேற்கோள் குறிகள் தேவையில்லை. வேறொரு பாதையிலிருந்தோ, பழைய ccam எழுதியது போல மேற்கோள் குறிகளுடனோ ஏற்கெனவே ஒரு ccam-ஐ இயக்கும் நிலை வரி, அது wrap செய்வதை வைத்துக்கொண்டு, wrap செய்யப்படுவதற்குப் பதிலாக மாற்றப்படும். Windows-இல் ccam-இன் பாதை forward slashes உடனும், home கோப்புறைக்கு `~` உடனும் எழுதப்படுகிறது (`~/.local/bin/ccam.exe statusline`), இதை Git Bash, PowerShell இரண்டும் புரிந்துகொள்ளும். மேற்கோள் குறிகள் தேவைப்படும் பாதை, Claude Code பயன்படுத்தும் shell-க்காக முழுமையாக எழுதப்படும்: Git Bash-க்கு `'…'`, PowerShell-க்கு `& '…'`. ஒரு குழு வழியாகப் பகிரப்படும் `settings.json` அதன் இணைப்பு வழியாக ஒருமுறை மட்டுமே எழுதப்படும், அதனால் குழுவின் ஒவ்வொரு கணக்குக்கும் அது கிடைக்கும். மீண்டும் இயக்கினால், ஏற்கெனவே ccam-ஐப் பயன்படுத்தும் கோப்புகளுக்கு `(already set)` என்று அச்சிடும்.

## பாதுகாப்பும் விளிம்பு நிலைகளும்

- நீங்கள் `--refresh` கொடுக்காதவரை `ccam usage` ஒருபோதும் token கோப்பை மாற்றுவதில்லை. access token காலாவதியானால், `ccam <name>` மூலம் அந்தக் கணக்கை ஒருமுறை இயக்குங்கள், Claude Code அதைப் புதுப்பிக்கும். முழுவதுமாகக் காலாவதியான உள்நுழைவுக்கு `ccam login <name>` தேவை.
- `--refresh` இயங்கும் கணக்குகள் (ccam இல்லாமல் Claude Code தொடங்கப்பட்டிருந்தாலும்), இறக்குமதி செய்யப்பட்ட கணக்குகள், Keychain உள்நுழைவுகள் ஆகியவற்றை ஒருபோதும் தொடுவதில்லை. மறுக்கப்பட்ட புதுப்பிப்பு சேமித்த எண்களையும் காரணத்தையும் காட்டும் (`token not renewed: …`).
- usage endpoint பொதுவில் ஆவணப்படுத்தப்படவில்லை, மாறக்கூடும். அது மாறும்போதும் சேமித்த எண்களை நீங்கள் பார்ப்பீர்கள், `ccam doctor` வடிவ மாற்றத்தைத் தெரிவிக்கும்.
- சேமித்த எண்களும் பதிலும் இல்லாதபோது, கணக்கு வரி `lookup failed:`-ஐயும் காரணத்தையும் காட்டும், எடுத்துக்காட்டாக `--source cache` உடன் `no saved usage`.
- cache கோப்புகள் சதவீதங்களையும் மீட்டமைப்பு நேரங்களையும் மட்டுமே வைத்திருக்கும், tokens-ஐ ஒருபோதும் அல்ல.
