ஒவ்வொரு ccam கணக்கும் தனக்கென உள்நுழைவு கொண்ட ஒரு தனி Claude Code config கோப்புறை. கணக்குகளைச் சேர்க்க, அவற்றில் உள்நுழைய, அவற்றைப் பட்டியலிட, பெயர் மாற்ற, நீக்க இந்தக் கட்டளைகளைப் பயன்படுத்துங்கள். உங்களிடம் ஏற்கெனவே உள்ள கோப்புறைகளையும் அவை பதிவு செய்கின்றன.

## பயன்பாடு

```sh
ccam add                                   # wizard on a terminal: name, sign-in, groups, shortcut
ccam add work --shortcut ccwork            # no wizard: log in, then create the ccwork command
ccam add side --no-login --group default --group team
ccam login side                            # run claude auth login inside the account
ccam login --expired                       # every account that was never logged in or whose login expired
ccam logout side                           # log out: the login and its MCP sign-ins
ccam list                                  # table of accounts; ccam ls is the same
ccam list --json                           # machine-readable
ccam use 2                                 # make slot 2 the default account
ccam rename side personal
ccam remove personal                       # asks, logs out, then moves the folder to the trash
ccam import                                # find ~/.claude and ~/.claude-* and ask about each
ccam import ~/.claude-ops --name ops
ccam completion zsh > "${fpath[1]}/_ccam"
```

ஒரு கட்டளை `<name|number>`-ஐ ஏற்கும் இடங்களில், கணக்கின் பெயரையோ அதன் slot எண்ணையோ (`ccam list`-இல் உள்ள `#` நெடுவரிசை) கொடுக்கலாம்.

`ccam use` எந்தக் கணக்கு இயல்புநிலை என்பதை (`config.toml`-இல் உள்ள `default`) மட்டுமே மாற்றுகிறது.

options இல்லாமல் டெர்மினலில் இயக்கும் `ccam add` ஒரு wizard-ஐத் திறக்கும். அது இந்தப் படிகளைக் கடந்து செல்லும்:

1. நீங்கள் கொடுக்காவிட்டால், கணக்கின் பெயர்;
2. கணக்கு எப்படி உள்நுழையும்: இப்போதே Claude உள்நுழைவு, API key, அல்லது பின்னர் Claude உள்நுழைவு;
3. எந்தக் குழுக்களில் சேர்வது, `default` தேர்வுசெய்யப்பட்ட நிலையில் (இன்னும் குழுக்கள் இல்லையென்றால், `default` குழு எதைப் பகிரும் என்று காட்டும்);
4. `Create a shortcut command for work? [y/N]`;
5. உறுதிப்படுத்த ஒரு சுருக்கம்.

`Esc` ஒரு படி பின்செல்லும். `--group`, `--no-group`, `--shortcut`, `--no-login` ஆகியவற்றில் ஏதேனும் ஒன்று, அல்லது டெர்மினல் இல்லாமல் இயக்குவது (எடுத்துக்காட்டாக, ஒரு pipe-இலிருந்து), wizard-ஐத் தவிர்க்கும். அப்போது பெயர் கட்டாயம், `--shortcut` ஒன்றைப் பெயரிடாவிட்டால் குறுக்குவழி உருவாக்கப்படாது.

`--group` இல்லாவிட்டால், புதிய கணக்கு `default` குழுவில் சேரும். முதல் கணக்கு அதை உருவாக்கும், அது MCP சர்வர்கள், அமைப்புகள், `CLAUDE.md`, நீட்டிப்புகள் ஆகியவற்றைப் பகிரும்; [குழுக்களுடன் பகிர்தல்](/features/share) பாருங்கள். Windows-இல், Developer Mode-இல் மட்டுமே கோப்புகளை இணைக்க முடியும். அது இல்லாமல், முதல் கணக்கு `mcp`, `extensions` ஆகியவற்றை மட்டும் பகிரும் `default`-ஐ உருவாக்கி அதைச் சொல்லும் (`Note: files can be linked on Windows only in Developer Mode (Settings > System > For developers), so group default shares only mcp, extensions. …`); அமைப்புகள், memory அல்லது வரலாற்றைப் பகிரும் ஒரு குழுவுடன் `--group` கொடுத்தால் ccam அதை மறுக்கும்.

`ccam list` slot, பெயர், குறுக்குவழி, மின்னஞ்சல், குழுக்கள், கடைசிப் பயன்பாடு ஆகியவற்றைக் காட்டும், இயல்புநிலைக் கணக்குக்கு முன் `*` இருக்கும். மின்னஞ்சல் என்பது கோப்புறை இப்போது உள்நுழைந்துள்ள மின்னஞ்சல் (அதன் `.claude.json`-இலிருந்து); ccam பதிவு செய்ததிலிருந்து அது வேறுபட்டால், பதிவு செய்யப்பட்டது `(was …)` ஆகப் பின்தொடரும்:

```console
$ ccam list
   #  Name      Shortcut  Email             Groups        Last used
*  1  work      ccwork    user@example.com  default team  -
   2  personal  -         me@side.dev       default       -
```

```console
$ ccam list
   #  Name      Shortcut  Email                                     Groups   Last used
*  1  work      ccwork    other@company.com (was work@example.com)  default  2m ago
```

`--json` உடன், ஒவ்வொரு கணக்கும் `slot`, `shortcut`, `name`, `email` (அட்டவணையில் உள்ளது போல, தற்போதைய உள்நுழைவின் மின்னஞ்சல்), `default`, `dir`, `last_used` (கணக்கு ஒருபோதும் தொடங்கப்படவில்லை என்றால் விடப்படும்), `groups`, `share` ஆகியவற்றைக் கொண்ட ஒரு object. `share` ஒவ்வோர் உருப்படியையும் (`mcp`, `settings`, `memory`, `extensions`, `history`) அது வரும் குழுவுடன், அல்லது `"local"` உடன் இணைக்கும்.

## Options

| Option | என்ன செய்யும் | இயல்புநிலை |
| --- | --- | --- |
| `ccam add --no-login` | உள்நுழையாமல் கணக்கை உருவாக்கும்; பின்னர் `ccam login <name>` மூலம் உள்நுழையுங்கள் | off |
| `ccam add --group <group>` | `default`-க்குப் பதிலாக இந்தக் குழுவில் சேரும். பலமுறை கொடுக்கலாம்; `default` இல்லையென்றால் உருவாக்கப்படும் | `default` |
| `ccam add --no-group` | எந்தக் குழுவிலும் சேராது: கணக்கு எதையும் பகிராது | off |
| `ccam add --shortcut <command>` | இந்தக் குறுக்குவழிக் கட்டளையையும் `~/.local/bin`-இல் உருவாக்கும் | none |
| `ccam add --api --key-from <source>` | உள்நுழைவுக்குப் பதிலாக API key பயன்படுத்தும் கணக்கு; [API key கணக்குகள்](/features/api) பாருங்கள் | off |
| `ccam list --json` | கணக்குகளை JSON ஆக அச்சிடும் | off |
| `ccam remove -y`, `--yes` | கேட்காமல் நீக்கும் | off |
| `ccam logout -y`, `--yes` | கேட்காமல் வெளியேறும் | off |
| `ccam import --name <name>` | நீங்கள் கொடுக்கும் கோப்புறைக்கான கணக்குப் பெயர்; கோப்புறை இல்லாமல் மறுக்கப்படும் (`--name needs a folder: ccam import <folder> --name ops`) | கோப்புறைப் பெயரிலிருந்து பெறப்படும் |
| `ccam import -y`, `--yes` | கண்டுபிடித்த ஒவ்வொரு கோப்புறையையும் கேட்காமல் இறக்குமதி செய்யும் | off |
| `--dry-run` | எதையும் மாற்றாத `ccam list` மற்றும் `ccam completion` இதை ஆதரிக்கும். `add`, `login`, `logout`, `use`, `rename`, `remove`, `import` இதை `` --dry-run is not supported by `ccam add`; nothing was changed `` (கட்டளையைப் பெயரிட்டு) என்று மறுக்கும் | off |

`ccam login` (`--expired` தவிர), `ccam use`, `ccam rename` ஆகியவற்றுக்குச் சொந்த options இல்லை. `ccam completion` `bash`, `zsh` அல்லது `powershell`-ஐ ஏற்கும்; வேறு எதுவும் `only bash, zsh and powershell are supported` என்று தோல்வியடையும்.

கணக்குப் பெயர்கள் `a-z`, `0-9`, `-`, `_` ஆகியவற்றால் ஆன 1 முதல் 32 எழுத்துகள், ஓர் எழுத்து அல்லது இலக்கத்தில் தொடங்க வேண்டும். `ccam 2` என்றால் slot 2 என்பதால், பெயர் முழுவதும் இலக்கங்களாக இருக்க முடியாது. பெயர் ஒரு ccam கட்டளையாகவும் இருக்க முடியாது (`add`, `list`, `ls`, `run`, `use`, `next`, `usage`, `u`, `share`, `mcp`, `login`, `logout`, `rename`, `remove`, `rm`, `import`, `migrate`, `doctor`, `shims`, `shortcut`, `completion`, `help`, `version`, `statusline`, `update`, `folder`, `pick`, `ext`, `group`, `groups`, `hook`, `agents`, `attach`, `ccusage`), அதனால் `ccam <name>` ஒருபோதும் குழப்பமாக இருக்காது. இந்தப் பட்டியல் `internal/config`-இல் உள்ள `config.Reserved`.

## இது எப்படி வேலை செய்கிறது

ஒரு கணக்கைச் சேர்ப்பது அதன் கோப்புறையை உருவாக்கி, அதன் குழுக்களில் சேர்த்து, config-ஐச் சேமித்து, உள்நுழைந்து, குறுக்குவழியை உருவாக்குகிறது, இந்த வரிசையில். `ccam add work --shortcut ccwork` இயக்கும்போது, ccam இந்தப் படிகளை எடுக்கிறது (`internal/cli/profiles.go`-இல் `addProfile`):

<!-- motion:accounts-add -->

1. எதையும் உருவாக்கும் முன், ccam பெயரையும் (`config.ValidateName`) குறுக்குவழியையும் (`shim.Check`) சரிபார்க்கிறது.
2. ccam `0700` mode-உடன் `~/.local/share/ccam/profiles/work/`-ஐ உருவாக்கி, கணக்குக்கு மிகக் குறைந்த காலி slot எண்ணைக் கொடுக்கிறது, அதனால் நீக்கப்பட்ட கணக்கின் எண் மீண்டும் பயன்படுத்தப்படும் (`profile.Add`, `Config.NextSlot`). முதல் கணக்கு இயல்புநிலை ஆகிறது.
3. கணக்கு தன் குழுக்களில் சேர்கிறது (`--group` அல்லது `--no-group` வேறு எதுவும் சொல்லாவிட்டால் `default`; முதல் கணக்கு `default`-ஐ உருவாக்குகிறது), ccam புதிய, காலியான கோப்புறையை அவற்றுடன் இணைக்கிறது, எடுத்துக்காட்டாக `settings.json`-ஐ `groups/default/settings.json`-உடன் (`applyShare`, `share.Build` பிறகு `Apply` உடன்). இது தோல்வியடைந்தால், புதிய கோப்புறை நீக்கப்படும், ஏனெனில் மீதமிருக்கும் கோப்புறை ஒவ்வொரு மறுமுயற்சியையும் `folder already exists` என்று தடுக்கும்.
4. கணக்கு `fsutil.AtomicWrite` மூலம் `~/.config/ccam/config.toml`-இல் சேமிக்கப்படுகிறது: ஒரு தற்காலிகக் கோப்பு, `fsync`, பிறகு `rename`, அதனால் crash ஒருபோதும் பாதி எழுதப்பட்ட config-ஐ விட்டுச்செல்லாது.
5. ccam கணக்குக் கோப்புறைக்கு அமைக்கப்பட்ட `CLAUDE_CONFIG_DIR` உடனும், உள்நுழைவுப் பக்கம் நிரப்பப்பட்டிருக்கக் கணக்கின் கடைசி மின்னஞ்சலுடன் `--email` உடனும், `claude auth login`-ஐத் தொடங்குகிறது (`runLogin`). உள்நுழைவு தோல்வியடைந்தால், கணக்கு அப்படியே இருக்கும், ccam பிழையை அச்சிட்டு, பின்னர் `ccam login work`-ஐ இயக்கச் சொல்லும்.
6. ccam `profiles/work/.claude.json`-இலிருந்து `oauthAccount`-ஐப் படிக்கிறது (`profile.ReadIdentity`): மின்னஞ்சல், கணக்கு மற்றும் நிறுவன IDs, நிறுவனத்தின் பெயர், plan (`claude_max`, `claude_team` …). அந்தக் கோப்பு பல megabytes ஆக இருக்கலாம், அதனால் ccam முழுக் கோப்பையும் parse செய்வதற்குப் பதிலாக அந்த ஒரு key-ஐ மட்டும் தேடுகிறது (`TopLevelValue`). ccam இந்த விவரங்களை `config.toml`-இல் `[profile.login]`-இல் சேமிக்கிறது.
7. ccam `~/.local/bin/ccwork`-ஐ ccam binary-உடன் இணைக்கிறது; அது தொடங்கும்போது `argv[0]`-ஐ `config.toml`-இல் தேடுகிறது. இணைப்பு `~/.local/state/ccam/shortcuts.json`-இல் பதிவு செய்யப்படுகிறது (`shim.Install`). இணைப்பை உருவாக்க முடியாவிட்டாலும் கணக்கு சேர்க்கப்படும், ccam காரணத்தைச் சொல்லும் (`Could not create shortcuts: …`), சுருக்கம் `shortcut: ccwork (not created; see above)` எனக் காட்டும்.

உள்நுழைவுக்குச் சில நிமிடங்கள் ஆகலாம், இடையில் மற்றொரு ccam process config-ஐச் சேமிக்கக்கூடும். அதனால் காத்திருக்கும் கட்டளைகள் `config.toml`-ஐ மீண்டும் ஏற்றி, அந்த ஒரு மாற்றத்தை (இங்கே, மின்னஞ்சல்) பொருத்தி, சேமிக்கின்றன (`env.update`). இதே காரணத்துக்காக `ccam remove` தன் கேள்விக்குப் பிறகு மீண்டும் ஏற்றுகிறது.

`ccam login` ஏற்கெனவே உள்ள கணக்குக்குப் படி 5 மற்றும் 6-ஐ இயக்குகிறது. Claude Code மின்னஞ்சலை உள்நுழைவுப் பக்கத்துக்கான ஒரு குறிப்பாக மட்டுமே எடுத்துக்கொள்கிறது, அதனால் முன்பு இருந்ததைவிட வேறொரு Claude கணக்கில் நீங்கள் உள்நுழைந்துவிடக்கூடும்; ccam புதிய உள்நுழைவை `[profile.login]`-உடன் ஒப்பிட்டு அதைச் சொல்கிறது (`ccam: this login is other@company.com, but work was dev@company.com before.`). அது புதிய உள்நுழைவை வைத்துக்கொண்டு, அதை எப்படித் திரும்பப் பெறுவது என்று சொல்கிறது: ``To undo it, run `ccam login work` again and sign in as dev@company.com.``

வேறொரு Claude கணக்கில் உள்நுழைவது கணக்கின் [வரம்புப் பதிவையும்](/features/usage#the-limit-record) நீக்குகிறது, ஏனெனில் அந்த வரம்புகள் மற்றக் கணக்குக்கு உரியவை. வேறொரு ccam கணக்கு அதே Claude கணக்கில் உள்நுழைந்திருந்தால், அந்த இரண்டும் தங்கள் பயன்பாட்டு வரம்புகளைப் பகிர்ந்துகொள்கின்றன என்று ccam எச்சரிக்கிறது.

`ccam login --expired` ஒருபோதும் உள்நுழையாத, அல்லது உள்நுழைவு காலாவதியான ஒவ்வொரு கணக்கிலும், ஒன்றன்பின் ஒன்றாக உள்நுழைகிறது: அதன் refresh token காலாவதியானது, அல்லது சர்வர் மறுத்த பிறகு Claude Code உள்நுழைவை அழித்தது. முதல் browser திறப்பதற்கு முன், `config.toml`-ஐச் சேமிக்க முடியுமா என்று அது சரிபார்க்கிறது.

`ccam logout` கணக்கில் `claude auth logout`-ஐ இயக்கி, சேமித்த மின்னஞ்சலை அழிக்கிறது; உள்நுழைவுப் பதிவு அப்படியே இருக்கும், அதனால் அடுத்த உள்நுழைவு அதனுடன் சரிபார்க்கப்படும். Claude Code உள்நுழைவை ரத்துசெய்து, கணக்குக்காக அது சேமித்து வைத்திருப்பவற்றை, MCP சர்வர் உள்நுழைவுகள் உட்பட, நீக்குகிறது. அதனால் இவற்றில் ccam முதலில் உங்களை எச்சரித்துக் கேட்கிறது (`--yes` கேள்வியைத் தவிர்க்கும்):

- உள்நுழைவில் MCP உள்நுழைவுகள் இருக்கும்போது;
- கணக்கு இயங்கிக்கொண்டிருக்கும்போது (அதன் அமர்வுகளும் வெளியேற்றப்படும்);
- மற்றொரு கணக்கின் கோப்புறை அதே உள்நுழைவை வைத்திருக்கும்போது (நகலெடுக்கப்பட்ட கோப்புறை), வெளியேற்றம் அதையும் ரத்துசெய்யும்.

எடுத்துக்காட்டாக:

```console
$ ccam logout side
Logging out also removes side's MCP server sign-ins (linear); sign in to them again with /mcp.
Log out side? [y/N]
```

வேறொரு Claude கணக்காக உள்நுழைய `ccam login <name>` மட்டுமே போதும், அது MCP உள்நுழைவுகளை வைத்துக்கொள்ளும்.

கணக்குகள் ஒன்றுக்கு மேற்பட்ட நிறுவனங்களைச் சேர்ந்தவையாக இருக்கும்போது `ccam list` ஒரு `Organization` நெடுவரிசையைச் சேர்க்கிறது (தனிப்பட்ட plans `personal` என்று காட்டும்), `ccam list --json`-இல் ஒவ்வொரு கணக்குக்கும் `plan`, `org` இருக்கும்.

### தொலைநிலைக் கணினியில் உள்நுழைதல்

SSH வழியாக, `claude auth login`-இன் browser பகுதி உடைந்துவிடக்கூடும். Claude Code தொலைநிலைக் கணினியில் உள்ள ஒரு callback சர்வரில் (`http://localhost:<port>/callback`) உள்நுழைவுக்காகக் காத்திருக்கிறது, ஆனால் உள்நுழைவை முடிக்கும் browser உங்கள் கணினியில் இயங்குகிறது, அங்கே அந்த முகவரி எங்கும் செல்லாது, browser `ERR_CONNECTION_REFUSED` போன்ற பிழையைக் காட்டும். முகவரியில் இன்னும் ஒருமுறைக் குறியீடு உள்ளது, அதனால் ccam அதைச் சேர்க்க முடியும்:

<!-- motion:accounts-relay -->

ccam உங்கள் டெர்மினலை Claude Code-இடம் ஒப்படைப்பதில்லை (`runLogin`). அது Claude Code-இன் standard input-ஐ ஒரு pipe-உடன் இணைத்து, நீங்கள் தட்டச்சு செய்யும் ஒவ்வொரு வரியையும் அதற்குள் நகலெடுக்கிறது (`relayLogin`), அதனால் Claude Code-இன் `Paste code here` கேள்வியில் ஒட்டப்படும் குறியீடு இன்னும் வந்துசேரும். ஒரு வரி callback முகவரியாக இருந்தால், host `localhost`, `127.0.0.1` அல்லது `[::1]` ஆக இருந்து, port கொடுக்கப்பட்டு, பாதை `/callback` ஆக இருந்து, `code` மற்றும் `state` இரண்டும் இருந்தால் மட்டுமே ccam அதை ஏற்கிறது; `http://`-ஐ விட்டுவிடலாம் (`callbackURL`). பிறகு ccam browser செய்திருப்பது போலவே, 10 வினாடி timeout உடனும் redirects-ஐப் பின்தொடராமலும், சர்வரில் அந்த முகவரியைக் கோருகிறது (`deliverCallback`). கோரிக்கை காத்திருக்கும் `claude auth login`-இன் callback சர்வரை அடைகிறது (வரைபடத்தில் கோடிட்ட வரி). Claude Code குறியீட்டைப் பெற்று உள்நுழைவைச் சேமிக்கிறது, Linux-இல் கணக்குக் கோப்புறையில் உள்ள `.credentials.json`-இல். ஒட்டப்பட்ட வரி ccam-ஐ ஒருபோதும் வேறொரு host-ஐத் தொடர்புகொள்ள வைக்க முடியாது.

உள்நுழைவு தொடங்கும் முன் ccam இதை அச்சிடும்:

```text
On a remote machine? If your browser ends up on an http://localhost:…/callback page that does not load, paste that address here.
```

வெற்றிபெற்றால் அது `→ Passed the sign-in to Claude Code on this machine.` என்று அச்சிடும்.

உள்நுழைவு டெர்மினலில் உள்ளீட்டுக்குக் காத்திருக்கும்போது, ccam டெர்மினலின் echo மற்றும் line mode-ஐ அணைத்து, நீங்கள் தட்டச்சு செய்யும் ஒவ்வொரு எழுத்துக்கும் ஒரு `*`-ஐக் காட்டுகிறது, அதனால் ஒட்டப்படும் குறியீடோ callback முகவரியோ திரையில் தெரியாது. ccam வரித் திருத்தத்தைத் தானே செய்கிறது (`readLine`): `Enter` வரியை அனுப்புகிறது, `Backspace` ஓர் எழுத்தை அழிக்கிறது, வெற்று வரியில் `Ctrl+D` உள்ளீட்டை முடிக்கிறது. உள்நுழைவு முடியும்போதும், `Ctrl+C`, `SIGTERM` அல்லது `SIGHUP` வரும்போதும் டெர்மினல் மீட்டமைக்கப்படும்; இவை இன்னும் ccam-ஐ முடிக்கும். standard input மற்றும் standard error-இல் டெர்மினல் இல்லாவிட்டால், வரிகள் வந்தபடியே நகலெடுக்கப்படும்.

### பெயர் மாற்றம், நீக்கம், இறக்குமதி

`ccam rename` மற்றும் `ccam remove` கணக்கின் கோப்புறையிலும், கணக்கின் பெயரில் ccam வேறிடங்களில் வைத்திருப்பவற்றிலும் செயல்படுகின்றன. ccam அந்தப் பாதைகளை `nameState`-இல் பட்டியலிடுகிறது:

- `~/.local/state/ccam/last-used/<name>`;
- `~/.local/state/ccam/mcp/<name>`;
- usage caches `~/.local/state/ccam/usage/<name>.json` மற்றும் `<name>.statusline.json`;
- வரம்புப் பதிவு `<name>.limit.json`;
- `~/.local/state/ccam/handoff/<name>/`-இல் உள்ள அமர்வுக் குறிப்புகள்.

`ccam remove work` அவற்றை இந்த வரிசையில் கையாள்கிறது:

<!-- motion:accounts-remove -->

1. `ccam remove` முதலில் கணக்கு இயங்கிக்கொண்டிருந்தால் மறுத்து, பிறகு கேட்கும், நீங்கள் பதிலளித்த பிறகு மீண்டும் சரிபார்க்கும் (கேள்வி திறந்திருந்தபோது தொடங்கிய அமர்வை இது கண்டுபிடிக்கும்).
2. எதையும் மாற்றும் முன் `config.toml`-ஐச் சேமிக்க முடியுமா என்று அது சரிபார்க்கிறது.
3. கணக்கு நீட்டிப்புகளைப் பகிர்ந்தால், ccam குழுவின் `installed_plugins.json` மற்றும் `known_marketplaces.json`-ஐ மாற்றி எழுதுகிறது (`RewritePluginPaths`), ஏனெனில் Claude Code இந்தக் கணக்கின் கோப்புறை வழியாகச் செல்லக்கூடிய absolute plugin பாதைகளைச் சேமிக்கிறது.
4. அடுத்து, நிர்வகிக்கப்படும் கணக்கு (`ccam import` மூலம் பதிவுசெய்யப்பட்டதல்ல, ccam உருவாக்கிய கோப்புறையைக் கொண்ட கணக்கு) வெளியேற்றப்படுகிறது: அதன் கோப்புறையில் `claude auth logout` இயங்குகிறது, அதனால் வேலை செய்யும் எந்த உள்நுழைவும் குப்பையில் காத்திருப்பதில்லை (macOS-இல், அதே பெயருடைய பிந்தைய கணக்கு பெறக்கூடிய, கோப்புறையின் பெயரிடப்பட்ட Keychain உருப்படியிலும் அல்ல). API key கணக்குக்கும், மற்றொரு கணக்கின் கோப்புறை அதே உள்நுழைவை வைத்திருக்கும்போதும் (வெளியேற்றம் அதையும் ரத்துசெய்துவிடும்) இது தவிர்க்கப்படுகிறது. தோல்வியடைந்த வெளியேற்றம் தெரிவிக்கப்படும், நீக்கம் தொடரும்.
5. ccam கோப்புறையை `~/.local/share/ccam/trash/<name>-<time>/`-க்கு நகர்த்துகிறது (`profile.Trash`), கணக்கு `config.toml`-இலிருந்து நீங்குகிறது, அதே பெயருடைய பிந்தைய கணக்கு அவற்றைப் பெறாமல் இருக்க `nameState` பாதைகள் நீக்கப்படுகின்றன, குறுக்குவழி இணைப்பும் நீக்கப்படுகிறது: `✓ side removed (folder moved to /home/you/.local/share/ccam/trash/side-20261023-212306; logged out first)`.

இறுதியில் `config.toml`-ஐச் சேமிக்க முடியாவிட்டால், கோப்புறை குப்பையிலிருந்து திரும்ப வரும். நீக்கப்பட்ட கணக்கை மீட்டெடுக்க, கோப்புறையைக் குப்பையிலிருந்து திரும்ப நகர்த்தி மீண்டும் உள்நுழையுங்கள்.

`ccam rename` கோப்புறையின் பெயரை மாற்றி, அதன் `plugins/`-இல் உள்ள plugin பாதைகளைப் பழைய கோப்புறையிலிருந்து புதியதுக்கு மாற்றி எழுதுகிறது. அது `nameState` பாதைகளைப் புதிய பெயருக்கு நகர்த்துகிறது, கணக்கு இயல்புநிலையாக இருந்திருந்தால் அதை அப்படியே வைத்திருக்கிறது. `ccam next --continue` அமர்வுக் குறிப்புகளை இன்னும் கண்டுபிடிக்கும்படி அவற்றையும் புதுப்பிக்கிறது. குறுக்குவழிக் கட்டளை தன் பெயரை வைத்திருக்கும். plugin மாற்றி எழுதுதல் தோல்வியடைந்தால், அல்லது `config.toml`-ஐச் சேமிக்க முடியாவிட்டால், கோப்புறையின் பெயர் மீண்டும் பழையதாக மாற்றப்படும்.

macOS-இலும், Claude Code உள்நுழைவுகளை Credential Manager-இல் சேமிக்கும்போது Windows-இலும், கோப்புறை தானே தன் பழைய பெயரை வைத்திருக்கும், ஏனெனில் உள்நுழைவும் MCP உள்நுழைவுகளும் கோப்புறையின் பாதையின் கீழ் சேமிக்கப்படுகின்றன, நகர்த்தப்பட்ட கோப்புறை வெளியேற்றப்பட்டுவிடும். அப்போது config புதிய பெயருக்கு அருகில் கோப்புறையை `folder` ஆகப் பதிவு செய்கிறது, ccam `its folder stays …: the macOS Keychain keeps the login under the folder's path` என்று சொல்கிறது.

`ccam import` ஒரு கோப்புறையை அது இருக்கும் இடத்திலேயே, `config.toml`-இல் `dir` ஆகப் பதிவு செய்கிறது. அது அதை ஒருபோதும் நகர்த்துவதோ நகலெடுப்பதோ இல்லை: நகலெடுக்கப்பட்ட refresh token நகல்களை ஒன்றையொன்று வெளியேற்ற வைக்கும்.

கோப்புறை argument இல்லாமல், அது பதிவுசெய்யப்படாத `~/.claude` மற்றும் `~/.claude-*` கோப்புறைகளைத் தேடி, ஒவ்வொன்றைப் பற்றியும் கேட்கும். பெயர்கள் கோப்புறையிலிருந்து வருகின்றன (`~/.claude` என்பது `main`, `~/.claude-work` என்பது `work`, `~/.claude-2` என்பது `acct2`). ccam ஒரு பெயரைப் பெற முடியாவிட்டால், அல்லது பெயர் ஏற்கெனவே எடுக்கப்பட்டிருந்தால், இயக்க வேண்டிய `--name` கட்டளையுடன் அந்தக் கோப்புறையைப் பட்டியலிடும். கண்டுபிடிக்கப்பட்ட கோப்புறை தோல்வியடைந்தால் அது `Skipped <path>: <reason>` எனத் தெரிவிக்கப்படும், மற்றவை இறக்குமதி செய்யப்படும்.

ccam முதலில் தன் எல்லாக் கேள்விகளையும் கேட்டு, பிறகு `config.toml`-ஐ மீண்டும் ஏற்றிக் கோப்புறைகளைப் பதிவு செய்கிறது, அதனால் இடையில் மற்ற ccam கட்டளைகள் சேமித்த மாற்றங்கள் அப்படியே இருக்கும். `✓` வரிகள் சேமிப்புக்குப் பிறகு வரும்.

`CLAUDE_CONFIG_DIR` இல்லாமல், Claude Code `.claude.json`-ஐ உங்கள் home கோப்புறையில் `~/.claude`-க்கு அருகில் வைக்கிறது, அதனால் நீங்கள் `~/.claude`-ஐ இறக்குமதி செய்து அதற்குச் சொந்த `.claude.json` இல்லையென்றால், ccam `~/.claude/.claude.json`-இலிருந்து `~/.claude.json`-க்கு இணைப்பை உருவாக்கும். அப்போது வெறும் `claude`-உம் `ccam main`-உம் ஒரே கணக்கைப் பார்க்கும்.

`~/.claude`-இல் `~/.claude.json`-க்கு அருகில் அதற்கெனச் சொந்தமாக ஒரு `.claude.json` இருந்தால், ccam இரண்டையும் அப்படியே விட்டுவிட்டு அதைச் சொல்கிறது. `ccam main` உள்ளே உள்ளதையும், வெறும் `claude` வெளியே உள்ளதையும் பயன்படுத்தும், அவற்றின் உள்நுழைவு விவரங்களும் MCP சர்வர்களும் தனித்தனியாகவே இருக்கும். ஒன்றை மட்டும் வைத்துக்கொள்ள, உள்ளே உள்ள கோப்பை ஓர் இணைப்பால் மாற்றுங்கள் ([doctor](/features/doctor)-உம் இதைத் தெரிவிக்கிறது).

பதிவுசெய்யப்பட்ட ஒரு கணக்கின் அதே உள்நுழைவைக் கோப்புறை வைத்திருந்தால் (நகலெடுக்கப்பட்ட கோப்புறை), ccam அதைச் சொல்கிறது: எது முதலில் புதுப்பிக்கிறதோ அது மற்றதை வெளியேற்றிவிடும், அதனால் அதைப் பயன்படுத்தும் முன் `ccam login <name>` இயக்குங்கள்.

நீங்கள் ஒரு குழுவில் சேர்க்கும் வரை (`ccam group join <group> <name>`) இறக்குமதி செய்யப்பட்ட கணக்குகள் எந்தக் குழுவிலும் இருக்காது, குறுக்குவழியும் உருவாக்கப்படாது.

`ccam completion bash|zsh` கணக்குப் பெயர்களையும் நிறைவுசெய்யும் ஒரு completion script-ஐ அச்சிடும்.

## பாதுகாப்பும் விளிம்பு நிலைகளும்

- கணக்கு இயங்கும்போது `ccam rename` மற்றும் `ccam remove` மறுக்கும் (`refuseRunning`), ``work is running; quit its Claude Code sessions first (`ccam agents` lists them, `ccam work stop <id>` ends a background one)`` என்று, ஏனெனில் அமர்வு கோப்புறையில் தொடர்ந்து எழுதுகிறது. Claude Code எப்படித் தொடங்கப்பட்டிருந்தாலும் இந்தச் சரிபார்ப்பு அதை உள்ளடக்கும்: ccam வழியாக, வெறும் `claude`, ஒரு IDE, பின்னணி அமர்வுகள், அவற்றின் daemon.
- மற்றொரு ccam process அந்த உள்நுழைவைப் புதுப்பிக்கும்போது அல்லது மாற்றும்போது `ccam rename`, `ccam remove`, `ccam logout` ஆகியவை மறுக்கும்: ``another ccam process is using the login of work right now (a refresh, rename, remove or logout); try again in a moment``.
- மற்றொரு ccam process-இல் குழு மாற்றம் நடந்துகொண்டிருக்கும்போது, `ccam rename`, `ccam remove` ஆகியவை `another ccam process is changing the groups right now; try again when it is done` என்று மறுக்கும்; ஒன்று பாதியில் நின்ற பிறகு, ``the last group change stopped halfway; finish it with `ccam doctor --fix` first`` என்று.
- இறக்குமதி செய்யப்பட்ட கணக்கில் `ccam remove`, வெறும் `claude`-க்காக, கோப்புறையையும் அதன் உள்நுழைவையும் வைத்திருக்கும். கணக்கு குழுக்களில் இருந்தால், அது முதலில் `ccam group leave` செய்வது போலவே அவற்றிலிருந்து விலகுகிறது: பகிரப்பட்ட ஒவ்வோர் உருப்படியும் கோப்புறையில் குழுவுடையதின் நகலாகிறது, குழுவின் MCP சர்வர்கள் அதன் `.claude.json`-க்குள் செல்கின்றன. பிறகு அதன் பதிவு நீக்கப்படுகிறது: `✓ main unregistered (folder ... left in place; it left its groups with a copy of what they share)`. ccam உருவாக்கிய அதன் `.claude.json`-இன் காப்புப்பிரதிகள் `<folder>/.ccam-backup/mcp-<time>`-க்குள் நகர்கின்றன; அவற்றை நகர்த்த முடியாவிட்டால், அவை `~/.local/state/ccam/mcp/<name>/backups`-இல் இருக்கும், செய்தி அதைச் சொல்லும். உங்கள் `~/.claude` குப்பைக்கு நகர்த்தப்படாது.
- இரண்டு கணக்குகளுக்கு ஒரே கோப்புறை இருக்க முடியாது: ஒரு கோப்புறையை இருமுறை பெயரிடும் `config.toml` ஏற்றப்படுவது தோல்வியடையும்.
- `profiles/`-இல் ஏற்கெனவே கோப்புறை உள்ள பெயரை `ccam add` மறுத்து, `ccam import`-ஐச் சுட்டிக்காட்டும். ccam-இன் பழைய பதிப்பு ஒன்று விட்டுச்சென்ற, புதிய கோப்புறையின் பாதைக்கான உள்நுழைவு அல்லது MCP உள்நுழைவுகள் Keychain-இல் இன்னும் இருந்தால், macOS-இல் அது நின்று, அவற்றை நீக்கும் `security delete-generic-password` கட்டளையைப் பெயரிடுகிறது. `config.toml`-ஐச் சேமிக்க முடியாவிட்டால், புதிய கோப்புறை மீண்டும் நீக்கப்படும்.
- `ccam import` ஏற்கெனவே பதிவுசெய்யப்பட்ட கோப்புறை, கோப்புறை அல்லாத பாதை, ஏற்கெனவே எடுக்கப்பட்ட பெயர் ஆகியவற்றை மறுக்கும். கோப்புறை `~/.claude`-இன் நகலாக இருந்தால் (அதே உள்நுழைவு), `~/.claude` தானே பதிவுசெய்யப்படாவிட்டாலும், ccam எச்சரிக்கிறது.
- கணக்கு இயங்கிக்கொண்டிருக்கும்போது `ccam logout` முதலில் கேட்கும்; `ccam login` சரிபார்ப்பதில்லை.
- relay Claude Code-ஐ அடைய முடியாவிட்டால், எடுத்துக்காட்டாக உள்நுழைவு முடிந்த பிறகு, அது காரணத்துடன் `ccam: could not pass the sign-in to Claude Code:` என்று அச்சிடும். HTTP பிழை பொதுவாகக் குறியீடு காலாவதியானது என்று பொருள்; உள்நுழைவை மீண்டும் தொடங்குங்கள்.
