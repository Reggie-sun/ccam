"இந்த skill (அல்லது MCP சர்வர்) ஏன் ஒரு கணக்கில் வேலை செய்கிறது, மற்றொன்றில் இல்லை?" என்ற கேள்விக்கு `ccam ext` பதில் தருகிறது. ஒவ்வொரு கணக்குக்கும், Claude Code ஏற்றும் extensions-ஐயும் ஒவ்வொன்றும் எங்கிருந்து வருகிறது என்பதையும் அது பட்டியலிடுகிறது: ஒரு பகிர்வுக் குழு, கணக்கின் சொந்தக் கோப்புறை, அல்லது நீங்கள் இருக்கும் திட்டம். அட்டவணைக்குக் கீழே, ஒரு extension நீங்கள் எதிர்பார்ப்பது போல் ஏறுவதைத் தடுப்பவற்றை அது பட்டியலிடுகிறது. அது படிக்க மட்டுமே செய்கிறது.

## பயன்பாடு

```sh
ccam ext              # every account
ccam ext work         # one account
ccam ext --json       # for scripts
```

```console
$ ccam ext
Skills
          personal   work
  half    account !  -
  review  -          default

Commands
          personal  work
  deploy  default   default

MCP servers
       personal   work
  ctx  default !  default

Hooks (commands per event)
              personal     work
  PreToolUse  1 (default)  1 (default)

This project (/home/me/code/app):
  commands: ship
  MCP servers: fs

Sources: a group name (shared), account (its own folder), local (its own, for this folder only), - (not loaded); (off): installed, not turned on.
! personal: MCP server ctx is defined differently in group default's mcp.json and .claude.json
! personal: half: no SKILL.md, so Claude Code does not load it
```

ஒவ்வொரு கட்டமும் அந்தக் கணக்கில் அந்த உருப்படியின் மூலத்தைக் குறிக்கிறது: பகிர்வுக் குழு (`default`), அது கணக்கின் சொந்தக் கோப்புறையில் இருந்தால் `account`, கணக்கு இந்தக் கோப்புறைக்கு மட்டும் வைத்திருக்கும் MCP சர்வருக்கு `local`, அல்லது கணக்கிடம் அது இல்லையென்றால் `-`. நிறுவப்பட்டு ஆனால் இயக்கப்படாத plugin அதன் மூலத்துக்குப் பின் `(off)` எனக் காட்டும். `!` சிக்கல் உள்ள உருப்படியைக் குறிக்கிறது, அது அட்டவணைக்குக் கீழே விளக்கப்படுகிறது; வெறும் `claude`-இடம் மட்டும் உள்ள சர்வர்கள் போன்ற, எந்தக் கணக்கையும் சாராத சிக்கல்கள் பெயர் இல்லாமல் கடைசியில் வரும். `ccam ext --json` அதே அறிக்கையை (`accounts`, திட்டம், `problems`) அச்சிடுகிறது, Claude Code network வழியாக அடையும் MCP சர்வர்களில் `remote` உடன்; கணக்குகள் இல்லாதபோது அது `accounts: []` உடன் அறிக்கையை அச்சிடுகிறது.

## அது எதைப் படிக்கிறது

| வகை | எங்கே | காட்டப்படும் மூலம் |
| --- | --- | --- |
| Skills | `skills/`-இல் `SKILL.md` உள்ள ஒவ்வொரு கோப்புறையும் | `skills/` இணைக்கும் குழு, அல்லது `account` |
| Commands, agents | `commands/`, `agents/` கீழ் உள்ள `.md` கோப்புகள், துணைக் கோப்புறைகள் `folder/name` ஆக | குழு, அல்லது `account` |
| Plugins | `plugins/installed_plugins.json`, கணக்கின் மற்றும் திட்டத்தின் அமைப்புகளில் உள்ள `enabledPlugins` மூலம் இயக்கப்படும் அல்லது அணைக்கப்படும்; ஒரு திட்டத்துக்கு மட்டும் நிறுவப்பட்ட plugin அந்தத் திட்டத்தில் மட்டுமே தோன்றும் | குழு, அல்லது `account`; இயக்கப்படாதபோது `(off)` |
| MCP சர்வர்கள் | குழுவின் `mcp.json` (MCP பகிரப்படும்போது), கணக்கின் `.claude.json` (அதன் சொந்த சர்வர்கள், இந்தக் கோப்புறைக்கு மட்டும் அது வைத்திருப்பவை), அதன் plugins-இன் சர்வர்கள், `plugin:<plugin>:<server>` ஆக | குழு, `account` அல்லது `local` |
| Hooks | `settings.json`-இல் உள்ள `hooks`, நிகழ்வு வாரியாக எண்ணப்படுகின்றன | குழு, அல்லது `account` |
| இந்தத் திட்டம் | தற்போதைய கோப்புறையில் உள்ள `.claude/skills`, `.claude/commands`, `.claude/agents`, `.claude/settings.json`, `.claude/settings.local.json`, `.mcp.json` | ஒருமுறை பட்டியலிடப்படும்; கோப்புறையை இன்னும் நம்பாத (trust செய்யாத) கணக்குக்கு, அதன் `.mcp.json` சர்வர்கள் பற்றி ஒரு சிக்கல் காட்டப்படும் |

## அது தெரிவிக்கும் சிக்கல்கள்

- **உடைந்த இணைப்புகள்**: `skills/`, `commands/` அல்லது `agents/`-இல் இலக்கு காணாமல் போன இணைப்பு, அல்லது இல்லாத இடத்துக்கு இணைக்கும் பகிரப்பட்ட கோப்புறை (`skills`, `commands`, `agents`, `plugins`) (`ccam doctor --fix` மூலம் சரிசெய்யுங்கள், அது இல்லாத குழுக் கோப்புறையை மீண்டும் உருவாக்கும்).
- **`SKILL.md` இல்லாத skill கோப்புறை**: Claude Code அதைத் தவிர்க்கிறது.
- **இரண்டு இடங்களில் வேறுவிதமாக வரையறுக்கப்பட்ட MCP சர்வர்**: குழுவின் `mcp.json`, கணக்கின் `.claude.json`, அல்லது அவற்றில் ஒன்றும் திட்டத்தின் `.mcp.json`-உம். இரண்டு இடங்களிலும் ஒரே அமைப்புகள் இருந்தால் (`mcp_strategy = "sync"` எழுதுவது அதுதான்) அது சிக்கல் அல்ல. கணக்கின் சொந்தச் சர்வரை `ccam mcp import <account> <server>` மூலம் குழுவுக்கு நகர்த்துங்கள்.
- **சரியான JSON இல்லாத `installed_plugins.json`**, `enabledPlugins` பெயரிடாத plugin, கோப்புறை காணாமல் போன plugin.
- **ஒரே ஒரு கணக்கு மட்டும் ஏற்றும் சர்வர்கள்**: இந்தக் கணக்கின் `.claude.json`-இல் மட்டும் உள்ள, அதன் குழுவின் மற்ற கணக்குகள் ஏற்றாத சர்வர், இந்தக் கோப்புறைக்கான கணக்கின் local scope-இல் உள்ள சர்வர் (`-s user` கொடுக்காவிட்டால் `claude mcp add` செய்வது இதுதான்). ஒவ்வொன்றும் அதைப் பகிரும் `ccam mcp import` கட்டளையுடன் வரும். வெறும் `claude`-இன் `~/.claude.json`-இல் உள்ள, எந்தக் கணக்கும் ஏற்றாத சர்வர்கள் `ccam migrate --mcp` கட்டளையுடன் வரும்.
- **ஒப்புதலுக்காகக் காத்திருக்கும் திட்டச் சர்வர்**: கணக்கு இன்னும் கோப்புறையை நம்பவில்லை, அதனால் Claude Code ஒருமுறை கேட்கும், அதுவரை திட்டத்தின் `.mcp.json` சர்வர்கள் காத்திருக்கும். அவற்றை எங்கே ஒப்புதல் அளிப்பது என்று சிக்கல் சொல்கிறது: settings குழுவின் கணக்குகளின், அல்லது இந்தக் கணக்கின், `settings.json`-இல் `"enabledMcpjsonServers"`. ஒரு git repository-இன் main worktree-க்குக் கொடுத்த நம்பிக்கை அதன் மற்ற worktrees-இலும் செல்லும்.
- **உள்நுழைவுகளும் connectors-உம்**: மற்றொரு கணக்கு உள்நுழைந்திருக்கும்போது, இந்தக் கணக்கில் உள்நுழைவு தேவைப்படும் MCP சர்வர் (ஓர் உள்நுழைவு ஒரு கணக்குக்கு மட்டுமே செல்லும்; `/mcp` மூலம் உள்நுழையுங்கள்), மற்றொரு கணக்கு பயன்படுத்திய, இந்தக் கணக்கு பயன்படுத்தாத claude.ai connectors.

## பாதுகாப்பும் விளிம்பு நிலைகளும்

- `ccam ext` எதையும் மாற்றுவதில்லை, network கோரிக்கைகள் எதையும் செய்வதில்லை. அது சர்வர் பெயர்களையும் hook எண்ணிக்கைகளையும் படிக்கிறது, MCP வரையறைகளில் உள்ள `env` அல்லது headers-இன் மதிப்புகளை ஒருபோதும் அல்ல. உள்நுழைவுச் சரிபார்ப்புக்கு, அது ஒவ்வொரு கணக்கின் உள்நுழைவில் உள்ள MCP உள்நுழைவுகளின் பெயர்களை (macOS-இல் Keychain-இலிருந்து) படிக்கிறது, tokens-ஐ ஒருபோதும் அல்ல, அதுவும் மற்றொரு கணக்கும் ஏற்றும் சர்வரை ஏற்றும் கணக்குகளுக்கு மட்டுமே.
- அது disk-இல் உள்ளதைக் காட்டுகிறது. managed settings-ஆல் தடுக்கப்பட்ட சர்வர் அப்போதும் தோன்றும்; அமைப்புகளில் அணைக்கப்பட்ட plugin `(off)` எனக் காட்டும்.
- அந்தத் திட்டத்தின் `.claude` கோப்புறையையும் `.mcp.json`-ஐயும் சேர்க்க, அதைத் திட்டக் கோப்புறையில் இயக்குங்கள்.
