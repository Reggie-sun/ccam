`ccam next` நீங்கள் பெயரிடாமலே மற்றொரு கணக்காக Claude Code-ஐத் திறக்கிறது. ஒரு கணக்கு அதன் பயன்பாட்டு வரம்பை அடையும்போது இதைப் பயன்படுத்துங்கள்: வெறும் `ccam next` நீங்கள் கடைசியாகப் பயன்படுத்தியதற்கு அடுத்த கணக்கை எடுக்கும், `--auto` அதிக இடம் உள்ள கணக்கை எடுக்கும், `--continue` இந்தக் கோப்புறையின் கடைசி உரையாடலை, இரண்டு கணக்குகளும் வரலாற்றைப் பகிர்ந்தாலும் பகிராவிட்டாலும், புதிய கணக்குக்குக் கொண்டுசெல்லும். Claude Code-க்குள், ஒரு வரம்பு அமர்வை நிறுத்தும்போது [ccam plugin](#inside-claude-code) உங்களுக்குச் சொல்லும், `/ccam:switch` உரையாடலை ஒப்படைக்கும். `claude -p` இயக்கும் scripts-க்கு, `ccam --fallback` அந்த மாற்றத்தைத் தானாகவே செய்கிறது (பார்க்க [வரம்பில் மீண்டும் இயக்குதல்](#run-again-at-the-limit)).

**Team மற்றும் Enterprise இருக்கைகள்.** தானியங்கித் தேர்வு (`ccam next`, `--fallback`, `ccam pick`, டாஷ்போர்டின் `n`) ஒரே Claude Team அல்லது Enterprise நிறுவனத்தின் இருக்கைகளுக்கு இடையேயும் மாறுகிறது. Anthropic-இன் உதவி மையம் "Each seat on a Team plan is assigned to one named individual, and only that person may use it" (Team திட்டத்தின் ஒவ்வொரு இருக்கையும் பெயர் குறிப்பிடப்பட்ட ஒரு நபருக்கு ஒதுக்கப்படுகிறது, அந்த நபர் மட்டுமே அதைப் பயன்படுத்தலாம்) என்றும், "Users can't route their work through another user's account to use that user's remaining usage" (மற்றொரு பயனரின் மீதமுள்ள பயன்பாட்டைப் பயன்படுத்திக்கொள்ள, பயனர்கள் தங்கள் வேலையை அந்தப் பயனரின் கணக்கு வழியாக அனுப்ப முடியாது) என்றும் கூறுகிறது ([Team திட்டங்கள்](https://support.claude.com/en/articles/12004354-purchase-and-manage-seats-on-team-plans#h_b8a7d07129); இதேபோல் [Enterprise திட்டங்களுக்கும்](https://support.claude.com/en/articles/13393991-purchase-and-manage-seats-on-enterprise-plans#h_fa6b9cade0)). எனவே, இருக்கைகளுக்கு இடையே தானியங்கித் தேர்வைப் பயன்படுத்துவது Anthropic-இன் விதிமுறைகளை மீறக்கூடும். அதை நம்பியிருக்கும் முன், உங்கள் நிறுவனத்திடமும் Anthropic-இடமும் கேட்டு உறுதிசெய்துகொள்ளுங்கள். தனிப்பட்ட திட்டங்கள் (Pro, Max) பற்றி [அடிக்கடி கேட்கப்படும் கேள்விகளில் உள்ள விதிமுறைக் குறிப்பு](/docs/faq#am-i-allowed-to-use-several-claude-code-accounts) விளக்குகிறது.

## பயன்பாடு

```sh
ccam next                       # the account after the one you used last
ccam next --auto                # the account with the most room
ccam next --continue            # carry this folder's last conversation on as the next account
ccam next -c --auto             # both: the conversation, on the account with the most room
ccam next --auto --max-usage 80 # prefer accounts below 80%
ccam next --auto --strategy balance   # the weekly quota that would go unused first
ccam next --auto --cross-org    # also accounts of other organizations
ccam next --auto --wait         # nobody has room: wait for the first reset (up to 5 hours)
ccam next -c --auto -- --dangerously-skip-permissions   # claude's own options go after --
ccam --dry-run next --auto      # print the choice and the command, start nothing
```

```console
$ ccam --dry-run next --auto --continue
→ personal → work (12% of its 5 hours used, the least)
  continuing "Fix the flaky tests" (about 182k tokens); work does not share personal's history, so Claude Code copies it into work
CLAUDE_CONFIG_DIR=/home/you/.local/share/ccam/profiles/work CCAM_PROFILE=work /usr/local/bin/claude --resume /home/you/.local/share/ccam/profiles/personal/projects/-home-you-code-app/4f1c….jsonl --fork-session
```

ccam மாற்றத்தை, `--auto` தேர்வுக்கான காரணத்துடன், standard error-இல் `→ <from> → <to>` என அச்சிட்டு, பிறகு `ccam <name>` செய்வது போலவே புதிய கணக்காக Claude Code-ஐத் தொடங்குகிறது. `<from>` என்பது நீங்கள் கடைசியாகப் பயன்படுத்திய கணக்கு, அல்லது `--continue` உடன், உரையாடல் சேர்ந்த கணக்கு. `--`-க்குப் பின் உள்ள arguments மாற்றமின்றி `claude`-க்குச் செல்லும்.

## Options

| Option | என்ன செய்யும் | இயல்புநிலை |
| --- | --- | --- |
| `--auto` | 100%-இல் உள்ள கணக்குகளைத் தவிர்த்து, பயன்பாட்டின்படி (கீழே பாருங்கள்) உள்நுழைந்த கணக்கைத் தேர்ந்தெடுக்கும் | off |
| `--max-usage <1-100>` | `--auto` உடன்: இந்தப் பயன்பாட்டுக்குக் கீழ் உள்ள கணக்குகளுக்கு முன்னுரிமை தரும் | `auto_max_usage`, இல்லையெனில் 100 |
| `--strategy headroom\|expiring\|balance` | `--auto` உடன்: மிகக் குறைந்த 5 மணி நேரப் பயன்பாடு, மிக விரைவான 5 மணி நேர மீட்டமைப்பு, அல்லது முதலில் பயன்படுத்தப்படாமல் போகக்கூடிய வாராந்திர quota | `auto_strategy`, இல்லையெனில் `headroom` |
| `--cross-org` | `--auto` உடன்: வேறொரு நிறுவனத்தின் கணக்குகளையும் தேர்ந்தெடுக்கும் (கீழே பாருங்கள்) | `cross_org`, இல்லையெனில் off |
| `--wait[=<duration>]` | `--auto` உடன்: எந்தக் கணக்கிலும் இடம் இல்லாதபோது, முதல் கணக்கு மீட்டமைக்கப்படும் வரை, அதிகபட்சம் இவ்வளவு நேரம் காத்திருக்கும். மதிப்பு `=`-க்குப் பிறகு வர வேண்டும்: `--wait 2h` என்பது `--wait takes its value after '=': --wait=2h` என்ற குறிப்புடன் மறுக்கப்படும் | off; தனியாகக் கொடுத்தால் `5h` |
| `-c`, `--continue` | இந்தக் கோப்புறையின் கடைசி உரையாடலைப் புதிய கணக்காகத் தொடரும் (கீழே பாருங்கள்) | off |
| `-- <claude args>` | ccam-இன் சொந்த arguments-க்குப் பின் `claude`-க்கு அனுப்பப்படும் arguments | none |
| `--dry-run` | மதிக்கப்படும்: Claude Code-ஐத் தொடங்காமலும் தொடக்கத்தைப் பதிவு செய்யாமலும், `→ <from> → <to>`-ஐயும் அது இயக்கும் கட்டளை வரியையும் அச்சிடும் | off |

`--auto`, `--continue` இரண்டும் சேர்ந்து வேலை செய்யும். `--continue` கொடுத்தால், `--resume` arguments உங்கள் சொந்த arguments-க்கு முன் வைக்கப்படும்.

`--dangerously-skip-permissions` அல்லது `--model` போன்ற Claude Code-இன் சொந்த options `--`-க்குப் பிறகு வர வேண்டும். பெயருக்குப் பிறகு உள்ள அனைத்தையும் அப்படியே அனுப்பும் `ccam <name>` போல அல்லாமல், `ccam next` தன் arguments-ஐத் தானே படிக்கிறது, எனவே `--` இல்லாமல் அது `ccam: unknown flag: --dangerously-skip-permissions` என்று நின்றுவிடும்.

## இது எப்படி வேலை செய்கிறது

ccam வழியான ஒவ்வொரு தொடக்கமும் நேரத்தை `~/.local/state/ccam/last-used/<name>`-இல் எழுதுகிறது. `ccam next` இந்தக் கோப்புகளைப் படித்து, எந்தக் கணக்குகள் உள்நுழைந்துள்ளன என்று சரிபார்த்து, தேர்ந்தெடுக்கிறது.

1. `cli.candidates` `config.toml`-இலிருந்து ஒவ்வொரு கணக்குக்கும் ஒரு `next.Candidate`-ஐ உருவாக்குகிறது: கணக்கு, அதன் கடைசித் தொடக்க நேரம் (`launcher.LastUsed`), அதற்கு வேலை செய்யும் உள்நுழைவு உள்ளதா என்பது (`creds.Has`: `.credentials.json`-இல், அல்லது macOS-இல் Keychain-இல், முழுவதுமாகக் காலாவதியாகாத, Claude Code அழிக்காத ஒரு Claude உள்நுழைவு). அதற்குப் பதிலாக API key பயன்படுத்தும் கோப்புறைக்கு (Console உள்நுழைவு, அல்லது `ccam add --api` மூலம் சேர்த்த கணக்கு) plan வரம்புகள் இல்லை, அது ஒருபோதும் தேர்ந்தெடுக்கப்படாது.
2. `--auto` இல்லாமல், `next.Rotate` கணக்குகளை slot எண்ணின்படி வரிசைப்படுத்தி, மிகச் சமீபத்தில் தொடங்கப்பட்டதைக் கண்டுபிடிக்கிறது. அதுதான் நீங்கள் விட்டு மாறும் கணக்கு. இதுவரை எந்தக் கணக்கும் தொடங்கப்படவில்லை என்றால், அது மிகக் குறைந்த slot.
3. அங்கிருந்து அது slot வரிசையில் முன்னோக்கிச் சென்று, கடைசி slot-இலிருந்து முதலாவதுக்குச் சுற்றி வந்து, உள்நுழைந்துள்ள முதல் கணக்கைத் திருப்பித் தருகிறது.
4. `launcher.LaunchWith` தேர்ந்தெடுக்கப்பட்ட கணக்கை `ccam <name>` செய்வது போலவே தயார்செய்து தொடங்குகிறது: கணக்கின் இணைப்புகளைச் சரிபார்க்கிறது, MCP பகிர்வைப் பொருத்துகிறது, அமர்வைப் பதிவு செய்கிறது, `syscall.Exec` மூலம் ccam-ஐ `claude`-ஆல் மாற்றுகிறது.

தேடல் கடைசியாகப் பயன்படுத்திய கணக்கிலிருந்து தொடங்கி, அதற்குப் பின் உள்நுழைந்துள்ள முதல் கணக்கில் நிற்கிறது:

`work` மிகச் சமீபத்தில் தொடங்கப்பட்டது, அதனால் தேடல் அதற்குப் பின் தொடங்குகிறது. `side`-க்கு உள்நுழைவு இல்லை, அது தவிர்க்கப்படுகிறது, `lab` தேர்ந்தெடுக்கப்படுகிறது. `lab`-உம் வெளியேறியிருந்தால், தேடல் `personal`-க்குச் சுற்றி வந்திருக்கும் (வரைபடத்தில் `% len`). சுழற்சி நீங்கள் தொடங்கிய கணக்கை ஒருபோதும் திருப்பித் தராது: உள்நுழைந்த வேறு கணக்கு இல்லையென்றால், அது பிழையுடன் நின்றுவிடும்.

### --auto

`--auto` slot வரிசைக்குப் பதிலாகப் பயன்பாட்டின்படி முடிவு செய்கிறது. `cli.pickAuto` உள்நுழைந்த கணக்குகளை வைத்துக்கொண்டு, `ccam usage` பயன்படுத்தும் அதே `Fetcher.FetchAll` மூலம் அவற்றின் பயன்பாட்டை ஒரே நேரத்தில் கேட்டு, `usage.Policy.Choose()` தேர்ந்தெடுக்க விடுகிறது:

ஒரு கணக்கு அதன் 5 மணி நேர மற்றும் வாராந்திரக் கால அளவுகளால் மதிப்பிடப்படுகிறது, Claude Code-க்கான arguments-இல் (`--`-க்குப் பிறகு) `--model` இருந்தால் அந்த model-இன் வாராந்திரக் கால அளவாலும் (பெயரில் `opus`, `sonnet`, `haiku` அல்லது `fable`). `Policy.Choose()` கணக்குகளை மூன்றாகப் பிரிக்கிறது:

1. **இடம் உள்ளவை**: ஒவ்வொரு கால அளவும் `auto_max_usage`-க்குக் (`config.toml`, இயல்புநிலை 100) கீழ். அவற்றுள் strategy தேர்ந்தெடுக்கிறது: `headroom` (இயல்புநிலை) மிகக் குறைந்த 5 மணி நேரப் பயன்பாட்டை எடுக்கிறது; `expiring` மிக விரைவில் மீட்டமைக்கப்படும் 5 மணி நேரக் கால அளவை எடுக்கிறது, அதனால் அதன் மீதமுள்ள quota இழக்கப்படும் முன் பயன்படுத்தப்படுகிறது; `balance` தன் வாரம் மீட்டமைக்கப்படும் வரை ஒரு நாளுக்கு அதிக வாராந்திர quota மீதமுள்ள கணக்கை எடுக்கிறது, இயங்கும் ஒவ்வொரு ccam அமர்வையும் அதற்கு எதிராகக் கணக்கிடுகிறது, அதனால் வாராந்திர quota பயன்படுத்தப்படாமல் விடப்படுவதில்லை, இணையான அமர்வுகள் பரவுகின்றன.
2. **மேலே உள்ளவை**: 100%-க்குக் கீழ், ஆனால் `auto_max_usage`-இல் அல்லது அதற்கு மேல். எந்தக் கணக்கிலும் இடம் இல்லாதபோது மட்டுமே பயன்படுத்தப்படுகின்றன, மிகக் குறைந்த 5 மணி நேரப் பயன்பாடு முதலில்.
3. **நிரம்பியவை**: 100%-இல் ஒரு கால அளவு, அல்லது தெரியாத 5 மணி நேரப் பயன்பாடு. ஒருபோதும் தேர்ந்தெடுக்கப்படாது.

Claude Code ஒரு கால அளவில் கோரிக்கையை மறுத்தபோது, அந்தக் கால அளவு அதன் மீட்டமைப்பு வரை 100% ஆகக் கணக்கிடப்படுகிறது: சேமித்த எண்கள் என்ன சொன்னாலும், [ccam plugin](#inside-claude-code)-இன் hook அதைப் பதிவு செய்கிறது (`~/.local/state/ccam/usage/<name>.limit.json`). அதனால் இப்போதுதான் வரம்பை எட்டிய கணக்கு, அதன் எண்கள் பழையவையாக இருந்தாலும், மீட்டமைப்புக்கு முன் மீண்டும் தேர்ந்தெடுக்கப்படாது.

எல்லாக் கணக்குகளுக்குமான அமைப்புகள் `config.toml`-இன் மேற்பகுதியில், முதல் `[[group]]`, `[[profile]]` அல்லது `[[folder]]`-க்கு மேலே இருக்க வேண்டும். அவற்றில் ஒன்றுக்குக் கீழே உள்ள அமைப்பு அந்த table-க்கு உரியதாகிவிடும்: ccam ஒவ்வொரு தொடக்கத்திலும் அதைப் பெயரிடுகிறது, அது நகர்த்தப்படும் வரை config-ஐச் சேமிக்கும் கட்டளைகள் மறுக்கும்.

```toml
# ~/.config/ccam/config.toml
auto_max_usage = 80        # keep 20% of each account for interactive work
auto_strategy = "expiring"
```

**நிறுவனங்கள்.** தானியங்கித் தேர்வுகள் நீங்கள் விட்டுச்செல்லும் கணக்கைப் போன்ற கணக்குகளுக்குள்ளேயே இருக்கின்றன: அதே team அல்லது enterprise நிறுவனம், அல்லது தனிப்பட்ட plans (Pro, Max) ஒன்றாக, அதனால் நிறுவனக் கணக்கின் வேலை ஒரு தனிப்பட்ட கணக்கில் தொடர்வதில்லை, தலைகீழாகவும் இல்லை. ஒவ்வொரு கணக்கின் நிறுவனத்தையும் ccam அதன் உள்நுழைவிலிருந்து அறிகிறது (`ccam login` அதைப் பதிவு செய்கிறது; பழைய உள்நுழைவுகள் `.claude.json`-இலிருந்து படிக்கப்படுகின்றன); ccam-ஆல் அறிய முடியாத கணக்கு எங்கும் பொருந்தும். ஒரே Claude கணக்கில் உள்நுழைந்த இரண்டு கோப்புறைகள் அதன் வரம்புகளைப் பகிர்கின்றன, அதனால் ஒன்று மற்றொன்றிடமிருந்து ஒருபோதும் பொறுப்பேற்பதில்லை. `--cross-org`, அல்லது `config.toml`-இல் `cross_org = true`, நிறுவன விதியை நீக்குகிறது.

எதையும் தேர்ந்தெடுக்க முடியாதபோது, ccam code 75 (`EX_TEMPFAIL`) உடன் வெளியேறுகிறது, அதனால் ஒரு script "பிறகு முயலுங்கள்" என்பதைத் தோல்வியிலிருந்து பிரித்தறிய முடியும். `--wait` உடன், அதற்குப் பதிலாக முதல் நிரம்பிய கணக்கின் தடுக்கும் கால அளவு மீட்டமைக்கப்படும் வரை (மீட்டமைப்பு நேரத்துக்கு 30 வினாடிகள் பிறகு, endpoint புதிய கால அளவைக் காட்டும்போது) உறங்கி, `ccam: no account has room; waiting until 15:10` என்று அச்சிட்டு, மீண்டும் தேர்ந்தெடுக்கிறது; எந்தக் கணக்கும் எப்போது மீட்டமைக்கப்படும் என்று சொல்லாதபோது, 10 நிமிடங்களுக்குப் பிறகு மீண்டும் பார்க்கிறது. காத்திருப்பு முடியும் முன் எதுவும் விடுபடாவிட்டால், 75 உடன் வெளியேறுகிறது. தேடல் `ccam usage`-இன் விதிகளைப் பின்பற்றுகிறது: 60 வினாடிகளுக்குள் பெறப்பட்ட எண்கள் மீண்டும் பயன்படுத்தப்படும், ஒவ்வொரு கணக்குக்கும் 3 வினாடிகள் உண்டு, பதில் அளிக்காத அல்லது access token காலாவதியான கணக்கு அதன் சேமித்த எண்களால் மதிப்பிடப்படும், வரம்புப் பதிவு அவற்றின் மேல் பொருந்தும். மீட்டமைப்பு நேரம் கடந்துவிட்ட சேமித்த கால அளவு 0% ஆகக் கருதப்படும், அதனால் இடையில் கால அளவு மீட்டமைக்கப்பட்ட கணக்கு புறக்கணிக்கப்படாது. `--auto` ஒருபோதும் tokens-ஐப் புதுப்பிப்பதில்லை. வெறும் சுழற்சியைப் போலன்றி, நீங்கள் கடைசியாகப் பயன்படுத்திய கணக்கில் இன்னும் அதிக இடம் இருந்தால் `--auto` அதையே தேர்ந்தெடுக்கக்கூடும்.

### --continue

1. ccam ஒவ்வொரு கணக்கிலும் இந்தக் கோப்புறையின் கடைசி உரையாடலைத் தேடுகிறது: `projects/<folder>/`-இல் உள்ள `<session>.jsonl` கோப்புகளில் (கோப்புறைப் பெயர் என்பது, Claude Code பெயரிடுவது போலவே, links தீர்க்கப்பட்டு, எழுத்து அல்லது இலக்கம் அல்லாத ஒவ்வொரு எழுத்தும் `-` ஆக மாற்றப்பட்ட வேலைக் கோப்புறை), மிகப் புதிய prompt அல்லது பதில் உள்ளது. அவை இல்லாத அமர்வுகள், எடுத்துக்காட்டாக `/mcp`, `/usage` அல்லது `/status` மட்டுமே இயக்கிய அமர்வு, அல்லது காலியான கோப்பு, தவிர்க்கப்படுகின்றன. ஓர் அமர்வு ஒரு குறிப்பை விட்டுச்சென்றிருந்து (பயன்பாட்டு வரம்பு அல்லது `/ccam:switch`, கீழே பாருங்கள்), அதற்கு 2 நிமிடங்களுக்கு மேல் பிறகு எந்த உரையாடலிலும் prompt அல்லது பதில் இல்லையென்றால், அதற்குப் பதிலாக அந்தக் குறிப்பிட்ட அமர்வு பயன்படுத்தப்படுகிறது; `/exit`-இல் Claude Code எழுதும் வரிசைகள் கணக்கில் கொள்ளப்படுவதில்லை.
2. அது சேர்ந்த கணக்கிலிருந்துதான் நீங்கள் மாறுகிறீர்கள், புதிய கணக்கு மேலே உள்ளபடியே, அதே நிறுவனத்துக்குள் தேர்ந்தெடுக்கப்படுகிறது. பல கணக்குகள் அந்த வரலாற்றைப் பகிரும்போது, உரையாடலைக் கடைசியாக இயக்கியது தான் என்று எந்தக் கணக்கின் `.claude.json` சொல்கிறதோ (`lastSessionId`) அதற்கு அது சேரும், இல்லையெனில் கடைசியாகப் பயன்படுத்திய கணக்குக்கு.
3. புதிய கணக்கு அந்த வரலாற்றைப் பகிர்ந்தால் (அதே குழுக் கோப்புறை), ccam `claude --resume <session id>`-ஐத் தொடங்குகிறது, அதாவது அதே உரையாடலை (`--continue` என்றால் கோப்புறையில் எது மிகப் புதியதோ அதைத் திறந்திருக்கும்).
4. இல்லையென்றால் அது `claude --resume <the conversation's file> --fork-session`-ஐத் தொடங்குகிறது: Claude Code முழு உரையாடலையும், ஒரு புதிய session id-இன் கீழ், புதிய கணக்கின் சொந்த வரலாற்றுக்குள் நகலெடுக்கிறது, மூலம் அப்படியே இருக்கும். அதன் பிறகு புதிய கணக்கின் `--continue` அதைக் கண்டுபிடிக்கும்.

உரையாடல் எவ்வளவு பெரியது என்று ccam சொல்கிறது: புதிய கணக்கு தன் முதல் பதிலுடன் அதை முழுவதும் மீண்டும் படிக்கிறது. Prompt caches நிறுவனங்களுக்கு இடையே ஒருபோதும் பகிரப்படுவதில்லை, ஒவ்வொரு தனிப்பட்ட plan-உம் தனக்கென ஒரு நிறுவனம், அதனால் இரண்டு கணக்குகளும் வெவ்வேறு நிறுவனங்களைச் சேர்ந்தவையாக இருக்கும்போது ccam `prompt caches are not shared between organizations, so the first reply reads it all again` என்பதைச் சேர்க்கிறது. பழைய கணக்கு உள்நுழைந்துள்ள MCP சர்வர்களில் புதிய கணக்கு உள்நுழையவில்லை என்றால், ccam அவற்றைப் பெயரிடுகிறது: `work is not signed in to MCP servers personal is: linear (sign in with /mcp there; sign-ins are not shared)`. ஒரு குழுவில் `history`-ஐப் பகிர்வது நகலெடுப்பைத் தவிர்க்கிறது, ஒரே உரையாடலை வைத்திருக்கிறது, `/rewind` code-ஐ மீட்டெடுக்கும் checkpoints-ஐயும் (`file-history/`) பகிர்கிறது.

## Claude Code-க்குள்

[ccam plugin](/docs/install#claude-code-plugin) இரண்டு hooks-ஐச் சேர்க்கிறது (Claude Code 2.1.78 அல்லது பிந்தையது):

- ஒரு turn பயன்பாட்டு வரம்பில் நிற்கும்போது, அது உரையாடலைக் குறித்து வைத்து, அதை ஆதரிக்கும் டெர்மினல்களில் (iTerm2, WezTerm, Windows Terminal, kitty, Ghostty) ஒரு desktop அறிவிப்பைக் காட்டுகிறது: ``ccam: work hit its 5-hour limit (resets 3:45pm). `ccam next --continue` carries on as another account.`` Claude Code பயன்பாட்டு வரம்பாகக் கருதும் ஒவ்வொரு செய்தியையும் அது அறியும்: 5 மணி நேர, வாராந்திர, சாதாரண, model வரம்புகள் (`You've hit your session limit`, `You've hit your limit`, ஒரு model-இன் ஒதுக்கீட்டுக்கு `You've reached your …`), usage credits, spend limits, கணக்கை நிறுத்திய நிறுவனம். மறுக்கப்பட்ட கோரிக்கையை Claude Code உரையாடலில் எழுதியிருந்தால், hook நிரம்பிய கால அளவை அதன் மீட்டமைப்பு வரை பதிவும் செய்கிறது ([வரம்புப் பதிவு](/features/usage#the-limit-record)), நிறுவனத்தின் நிறுத்தத்தைத் தவிர, ஏனெனில் அதன் admins அதை எப்போது வேண்டுமானாலும் நீக்கலாம். சர்வரின் குறுகிய throttle அல்லது ஒரு API key-இன் rate limit பயன்பாட்டு வரம்பு அல்ல, அவை விடப்படுகின்றன; subagent-இன் நிறுத்தமும், யாரும் அமர்ந்திருக்காத அமர்வுகளும் (`-p`, பின்னணி அமர்வுகள்) அப்படியே. Claude Code 2.1.234 மற்றும் பிந்தையவை அமர்விலேயே காத்திருந்து, 5 மணி நேர மீட்டமைப்புக்குப் பிறகு தாமாகவே தொடர்கின்றன; அதற்குப் பதிலாக மாறும் தேர்வை அறிவிப்பு உங்களுக்குத் தருகிறது.
- `/ccam:switch [account]` உரையாடலைக் குறித்து வைத்து, எந்தக் கோரிக்கையும் செய்யப்படும் முன் turn-ஐ முடிக்கிறது: `/exit` என்று தட்டச்சு செய்யுங்கள், பிறகு `ccam next --continue` அதை, நீங்கள் பெயரிட்ட கணக்காகவோ அடுத்த கணக்காகவோ தொடர்கிறது. இன்னும் உரையாடல் இல்லாத அமர்வில், தொடர எதுவும் இல்லை என்று அது சொல்கிறது.

குறிப்பு `~/.local/state/ccam/handoff/<account>/<session>.json`-இல் இருக்கும், ஒவ்வோர் அமர்வுக்கும் ஒரு கோப்பு, அதனால் ஒரு கணக்கின் இரண்டு அமர்வுகள் ஒன்றின் குறிப்பை மற்றொன்று ஒருபோதும் மேலெழுதாது. அது 12 மணி நேரம் வைக்கப்பட்டு, அடுத்த அமர்வு தொடங்கவிருக்கும்போது ஒருமுறை மட்டுமே பயன்படுத்தப்படும்; தோல்வியடையும் தொடக்கம் அதை அடுத்த முயற்சிக்காக விட்டுவைக்கும். Claude Code-இன் shell-இல் `cd` செய்த பிறகும், அது அமர்வு தொடங்கிய கோப்புறைக்கே சொந்தமானது. `ccam rename` அதிலுள்ள பெயர்களைப் புதுப்பிக்கிறது; அது குறிப்பிடும் கணக்கு அதன் பிறகு நீக்கப்பட்டிருந்தால், ccam அதைச் சொல்லிவிட்டு வழக்கம்போலத் தேர்ந்தெடுக்கும்.

### Relay

`config.toml`-இன் மேற்பகுதியில் `relay = true` இருந்தால், ccam தன் இடத்தில் Claude Code-ஐ இயக்குவதற்குப் பதிலாக interactive அமர்வுகளின் அருகிலேயே இருக்கும், `/ccam:switch`-க்குப் பிறகு அந்த அமர்வின் உரையாடலைத் தானாகவே தொடரும் (வேறோர் அமர்வு விட்டுச்சென்ற குறிப்பின்படி அது செயல்படாது): hook Claude Code-ஐ முடிக்கிறது, ccam அந்த அமர்வின் குறிப்புடன் `ccam next --continue`-ஐ இயக்குகிறது. கணக்கு பெயரிடப்படாவிட்டால், உரையாடலின் model-ஐயும் கணக்கிட்டு, அதிக இடம் உள்ள கணக்கை எடுக்கிறது. Windows-இல் hook Claude Code-ஐ முடிக்க முடியாது: `/exit` என்று தட்டச்சு செய்யுங்கள், ccam தொடரும். அதற்கு ஒவ்வோர் அமர்வுக்கும் காத்திருக்கும் ஒரு ccam process செலவாகும், அதனால்தான் இது இயல்பாக off.

ஓர் உரையாடலைத் தொடர்வது (resume) மீட்டெடுக்காதவற்றை relay செய்யப்பட்ட அமர்வு வைத்துக்கொள்கிறது: `--add-dir`, `--mcp-config`, tool பட்டியல்கள், `--settings`, `--plugin-dir`, system prompt options போன்ற options, உரையாடலின் permission mode, அமர்வின் effort level. `--model`, `--name`, `--agent` ஆகியவற்றை Claude Code தானே உரையாடலிலிருந்து மீட்டெடுக்கிறது. வேறு எதுவும் (`--worktree`, `--debug`, `--remote-control`, ccam-க்குத் தெரியாத options) `ccam: not carried over: …`-இல் பெயரிடப்படும். மாற்றம் பகிரப்பட்ட வரலாறு பற்றிய கேள்வியை ஒருபோதும் கேட்பதில்லை, அது இயங்கும்போது நீங்கள் தட்டச்சு செய்தவை கைவிடப்படும்.

`/ccam:switch` கேட்டபடி Claude Code முடிந்தால் மட்டுமே relay தொடர்கிறது: நீங்கள் முதலில் `/exit` தட்டச்சு செய்தபோது, அது முடியும்போது Ctrl+C அழுத்தியபோது, ccam-க்கு hangup அல்லது வேறு signal வந்தபோது, டெர்மினல் இல்லாமல் போனபோது அல்ல. அப்போது குறிப்பு அப்படியே இருக்கும், `ccam next --continue` பின்னர் உரையாடலைத் தொடரும். பழைய ccam-இன் relay-இன் கீழ் தொடங்கிய அமர்வையோ, யாரும் அமர்ந்திருக்காத அமர்வையோ (`-p`, பின்னணி அமர்வுகள்) hook முடிப்பதில்லை; அதற்குப் பதிலாக அது `/exit` செய்தியைப் பெறும். `claude remote-control` relay இல்லாமல் இயங்குகிறது.

## வரம்பில் மீண்டும் இயக்குதல்

`ccam next` நின்றுபோன interactive அமர்வுக்கானது. interactive அல்லாத இயக்கம், அதாவது ஒரு script-இல் அல்லது திட்டமிட்ட job-இல் உள்ள `claude -p`, உங்களுக்காகக் காத்திருக்க முடியாது, அதனால் கணக்குப் பெயருக்கு முன் `--fallback` வைத்தால் ccam அதற்காக மாற்றுகிறது:

```sh
ccam --fallback work -p "fix the failing tests" --output-format json
ccam --fallback -p "summarise" < notes.txt      # the folder's account or the default
ccam run --fallback work -p "review the diff"
```

```console
$ ccam --fallback personal -p "summarise" < notes.txt
ccam: personal reached its usage limit; running the command again as work
Summary: …
```

1. `--fallback` `-p` அல்லது `--print` உடன் மட்டுமே வேலை செய்யும்; இல்லையெனில் ccam நின்று `ccam next --auto --continue`-ஐச் சுட்டிக்காட்டும்.
2. pipe வழியாக வரும் standard input, 10 MiB வரை, ஒருமுறை படிக்கப்பட்டு ஒவ்வொரு முயற்சிக்கும் கொடுக்கப்படுகிறது. Claude Code போலவே, அது தொடங்க ccam அதிகபட்சம் 3 வினாடிகள் காத்திருக்கிறது (`--input-format stream-json` உடன் அல்ல); திறந்தே இருந்து எதையும் அனுப்பாத pipe, standard error-இல் ஒரு வரியுடன், இயக்கத்துக்கு உள்ளீடு எதுவும் கொடுக்காது.
3. ccam `exec`-க்குப் பதிலாக `claude`-ஐ child process ஆகத் தொடங்கி, அதன் standard output-ஐ நிறுத்தி வைத்து, standard error-ஐ வரும்போதே கடத்துகிறது.
4. `claude` 0 உடன் வெளியேறினால், அல்லது வேறு காரணத்தால் தோல்வியடைந்தால், நிறுத்தி வைத்த output-உம் exit code-உம் மாற்றமின்றிக் கடத்தப்படுகின்றன. signal மூலம் முடிந்த இயக்கமும் (128-க்கு மேலான exit code) அப்படியே: அது நிறுத்தும்படி கேட்கப்பட்டது, மீண்டும் இயக்கப்படாது.
5. Claude Code-இன் செய்தி அப்படிச் சொன்னால், அதாவது [hook](#inside-claude-code) அறியும் பயன்பாட்டு வரம்புச் செய்திகளில் ஏதேனும் ஒன்று, `--output-format json` அல்லது `stream-json` output-க்குள்ளும், அல்லது கணக்கின் பயன்பாடு அதன் 5 மணி நேர, வாராந்திர அல்லது `--model` கால அளவை 100%-இல் காட்டினால் (வரம்புப் பதிவு உட்பட), தோல்வி பயன்பாட்டு வரம்பாகக் கருதப்படுகிறது.
6. அப்போது அந்த முயற்சியின் output கைவிடப்பட்டு, அதே கட்டளை வேறொரு உள்நுழைந்த கணக்காக இயங்குகிறது: மிகக் குறைந்த 5 மணி நேரப் பயன்பாடு உள்ளது, பிறகு பயன்பாட்டைத் தேட முடியாத கணக்குகள், எண் வரிசையில். 100%-இல் உள்ள கணக்குகள் தவிர்க்கப்படுகின்றன, API key உள்நுழைவு உள்ள கணக்குகள் ஒருபோதும் முயற்சிக்கப்படுவதில்லை, ஒவ்வொரு கணக்கும் அதிகபட்சம் ஒருமுறை முயற்சிக்கப்படுகிறது.
7. arguments-இல் `-c`, `--continue`, `-r` அல்லது `--resume` இருந்தால், உரையாடலைக் கண்டுபிடிக்க முடியும்படி, அதே history குழுவில் உள்ள கணக்குகள் மட்டுமே முயற்சிக்கப்படுகின்றன.
8. `--auto` போலவே, அதே நிறுவனத்தின் கணக்குகள் மட்டுமே முயற்சிக்கப்படுகின்றன (`cross_org = true` இதை நீக்குகிறது).

அடுத்த கணக்கு `--auto`-இன் அதே விதிகளால் தேர்ந்தெடுக்கப்படுகிறது (`auto_max_usage`, `auto_strategy`, `--model` கால அளவு). எந்தக் கணக்கும் மீதம் இல்லாதபோது, ccam கடைசி முயற்சியின் output-ஐ அச்சிட்டு, உள்நுழைந்த எந்தக் கணக்கிலும் இடம் இல்லை என்று சொல்லி, code 75 உடன் வெளியேறுகிறது. கணக்குப் பெயருக்கு முன் `--wait` கொடுத்தால் (`ccam --fallback --wait=2h work -p …`), அதற்குப் பதிலாக முதல் கணக்கு மீட்டமைக்கப்படும் வரை காத்திருந்து, பிறகு எல்லாக் கணக்குகளையும் மீண்டும் முயலக்கூடும்; இப்போதுதான் வரம்பை எட்டிய கணக்கு உடனே மீண்டும் இயங்காதபடி, அது எப்போதும் முதலில் குறைந்தது ஒருமுறை உறங்குகிறது. அந்தக் கால அளவு ஒவ்வொரு காத்திருப்புக்கும் அல்ல, இயக்கத்தின் எல்லாக் காத்திருப்புக்கும் சேர்த்து வரம்பு. இடைவெளியுடன் எழுதினால் (`--wait 30m`), `ccam next`-இன் அதே குறிப்புடன் அது மறுக்கப்படும். Claude Code-இன் arguments-க்கு முன் வரும் `--`, எந்தத் தொடக்கத்திலும் போலவே வேலை செய்யும் (`ccam --fallback work -- -p …`). `ccam --dry-run --fallback work -p …` முதல் முயற்சியின் கட்டளையை அச்சிடுகிறது.

interactive அமர்வுகள் தாமாக மாறுவதில்லை. அதற்குப் பதிலாக, `ccam statusline install` உடன், 5 மணி நேர அல்லது வாராந்திரப் பயன்பாடு 90%-ஐ எட்டியதும் நிலை வரி `→ ccam next --auto --continue`-ஐச் சேர்க்கிறது ([பயன்பாட்டு வரம்புகள்](/features/usage)).

## பாதுகாப்பும் விளிம்பு நிலைகளும்

- உள்நுழைவு இல்லாத கணக்குகள் ஒருபோதும் தேர்ந்தெடுக்கப்படாது. உள்நுழைந்த வேறு கணக்கு இல்லையென்றால், வெறும் `ccam next` `no logged-in account other than <name>` என்று நின்றுவிடும்.
- `--continue` கொடுத்து, கோப்புறையில் உரையாடல் எதுவும் இல்லையென்றால்: `no account has a conversation in <folder> to continue`.
- நிறுவன விதி எந்தக் கணக்கையும் விட்டுவைக்காதபோது: `` no logged-in account to pick among <name>'s (<organization>); --cross-org also looks at the others ``.
- `--auto` கொடுத்து, உள்நுழைந்த கணக்கு எதுவும் இல்லையென்றால்: `no logged-in account to pick`. ஒவ்வொரு கணக்கும் நிரம்பியிருந்தால் அல்லது அதன் பயன்பாடு தெரியாவிட்டால்: `` no account with known usage and headroom (see `ccam usage`) ``. இரண்டும் exit code 75 உடன் முடிகின்றன.
- `--max-usage`, `--strategy`, `--wait`, `--cross-org` ஆகியவை `--auto` உடன் மட்டுமே வேலை செய்யும், 1-100-க்கு வெளியே உள்ள மதிப்பும் வேறு strategy-உம் மறுக்கப்படும்.
- fork உரையாடலை நகலெடுக்கிறது, கணக்கின் மற்ற நிலையை அல்ல: வரலாறு பகிரப்படாவிட்டால், மூலக் கணக்கின் `file-history/`-இல் உள்ள checkpoints உடன் வருவதில்லை.
- `--dry-run` உடனும் `--auto` network கோரிக்கைகளைச் செய்யும். அது படிக்க மட்டுமே செய்யும், token கோப்புகளை ஒருபோதும் எழுதாது.
- தேர்ந்தெடுக்கப்பட்ட கணக்கு `ccam <name>`-இன் அதே பாதை வழியாகத் தொடங்குகிறது, அதனால் அதே சரிபார்ப்புகள் பொருந்தும், அதே வரலாற்றைப் பகிரும் மற்றொரு Claude Code இந்தக் கோப்புறையில் ஏற்கெனவே இயங்கும்போது வரும் எச்சரிக்கை உட்பட.
- Claude Code உண்மையில் தொடங்கும்போது மட்டுமே `last-used` எழுதப்படும். `--dry-run` அதைத் தொடுவதில்லை, அதனால் dry run சுழற்சியை முன்னோக்கி நகர்த்தாது.
- ஒரு முயற்சி முடியும் வரை `--fallback` standard output-ஐ நிறுத்தி வைக்கிறது, அதனால் `--output-format stream-json` போன்ற streaming output இறுதியில் ஒரே துண்டாக வருகிறது. `stream-json` உள்ளீட்டை stream செய்து, மேலும் அனுப்பும் முன் பதில்களுக்காகக் காத்திருக்கும் client `--fallback`-ஐப் பயன்படுத்த முடியாது. வரம்பை எட்டும் முன் முதல் முயற்சி மாற்றிய கோப்புகள் மாற்றப்பட்டபடியே இருக்கும்; அடுத்த முயற்சி prompt-ஐ மீண்டும் தொடங்குகிறது.
