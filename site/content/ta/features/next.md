`ccam next` நீங்கள் பெயரிடாமலே மற்றொரு கணக்காக Claude Code-ஐத் திறக்கிறது. ஒரு கணக்கு அதன் பயன்பாட்டு வரம்பை அடையும்போது இதைப் பயன்படுத்துங்கள். மாறுவதற்கு நான்கு வழிகள் உள்ளன:

- வெறும் `ccam next` நீங்கள் கடைசியாகப் பயன்படுத்தியதற்கு அடுத்த கணக்கை எடுக்கும், `--auto` அதிக இடம் உள்ள கணக்கை எடுக்கும். `--continue` இந்தக் கோப்புறையின் கடைசி உரையாடலை, இரண்டு கணக்குகளும் வரலாற்றைப் பகிர்ந்தாலும் பகிராவிட்டாலும், புதிய கணக்கில் தொடரும்.
- Claude Code-க்குள், ஒரு வரம்பு அமர்வை நிறுத்தும்போது [ccam plugin](#inside-claude-code) உங்களுக்குச் சொல்லும், `/ccam:switch` உரையாடலை ஒப்படைக்கும்.
- `claude -p` இயக்கும் scripts-க்கு, `ccam --fallback` அந்த மாற்றத்தைத் தானாகவே செய்கிறது (பார்க்க [வரம்பில் மீண்டும் இயக்குதல்](#run-again-at-the-limit)).
- [`auto_switch`](#auto-switch) இயக்கத்தில் இருந்தால் (Linux, macOS), Claude Code தன் வரம்பில் நிறுத்தும் interactive அமர்வையும் ccam நகர்த்துகிறது.

**Team மற்றும் Enterprise இருக்கைகள்.** தானியங்கிக் கணக்குத் தேர்வு (`ccam next`, `--fallback`, `ccam pick`, டாஷ்போர்டின் `n`, நீங்கள் இயக்கிய பிறகு [`auto_switch`](/features/next#auto-switch)) ஒரே Claude Team அல்லது Enterprise நிறுவனத்தின் இருக்கைகளுக்கு இடையேயும் மாறுகிறது, இது Anthropic-இன் விதிமுறைகளை மீறக்கூடும். அதை நம்பியிருக்கும் முன், [அடிக்கடி கேட்கப்படும் கேள்விகளைப்](/docs/faq#am-i-allowed-to-use-several-claude-code-accounts) படித்து, உங்கள் நிறுவனத்திடமும் Anthropic-இடமும் கேட்டு உறுதிசெய்துகொள்ளுங்கள்.

## பயன்பாடு

```sh
ccam next                       # the account after the one you used last
ccam next --auto                # the account with the most room
ccam next --continue            # continue this folder's last conversation on the next account
ccam next -c --auto             # both: the conversation, on the account with the most room
ccam next -c --brief            # a new conversation that starts from a summary of the last one
ccam next --auto --max-usage 80 # prefer accounts below 80%
ccam next --auto --strategy balance   # the most weekly quota left per day
ccam next --auto --cross-org    # also accounts of other organizations
ccam next --auto --wait         # nobody has room: wait for the first reset (up to 5 hours)
ccam next -c --auto -- --dangerously-skip-permissions   # claude's own options go after --
ccam --dry-run next --auto      # print the choice and the command, start nothing
```

```console
$ ccam --dry-run next --auto --continue
→ personal → work (12% of its 5 hours used, the least)
  continuing "Fix the flaky tests" (about 182k tokens); work does not share personal's history, so Claude Code copies it into work
CLAUDE_CONFIG_DIR=/home/you/.local/share/ccam/profiles/work CCAM_PROFILE=work /usr/local/bin/claude --resume /home/you/.local/share/ccam/profiles/personal/projects/-home-you-code-app/4f1c….jsonl --fork-session
```

ccam மாற்றத்தை, `--auto` தேர்வுக்கான காரணத்துடன், standard error-இல் `→ <from> → <to>` என அச்சிட்டு, பிறகு `ccam <name>` செய்வது போலவே புதிய கணக்காக Claude Code-ஐத் தொடங்குகிறது. `<from>` என்பது நீங்கள் கடைசியாகப் பயன்படுத்திய கணக்கு, அல்லது `--continue` உடன், உரையாடல் சேர்ந்த கணக்கு. `--`-க்குப் பின் உள்ள arguments மாற்றமின்றி `claude`-க்குச் செல்லும்.

## Options

| Option | என்ன செய்யும் | இயல்புநிலை |
| --- | --- | --- |
| `--auto` | 100%-இல் உள்ள கணக்குகளைத் தவிர்த்து, பயன்பாட்டின்படி (கீழே பாருங்கள்) உள்நுழைந்த கணக்கைத் தேர்ந்தெடுக்கும் | off |
| `--max-usage <1-100>` | `--auto` உடன்: இந்தப் பயன்பாட்டுக்குக் கீழ் உள்ள கணக்குகளுக்கு முன்னுரிமை தரும் | `auto_max_usage`, இல்லையெனில் 100 |
| `--strategy headroom\|expiring\|balance` | `--auto` உடன்: மிகக் குறைந்த 5 மணி நேரப் பயன்பாடு, மிக விரைவான 5 மணி நேர மீட்டமைப்பு, அல்லது ஒரு நாளுக்கு அதிக வாராந்திர quota மீதமுள்ளது | `auto_strategy`, இல்லையெனில் `headroom` |
| `--cross-org` | `--auto` உடன்: வேறொரு நிறுவனத்தின் கணக்குகளையும் தேர்ந்தெடுக்கும் (கீழே பாருங்கள்) | `cross_org`, இல்லையெனில் off |
| `--wait[=<duration>]` | `--auto` உடன்: எந்தக் கணக்கிலும் இடம் இல்லாதபோது, முதல் கணக்கு மீட்டமைக்கப்படும் வரை, அதிகபட்சம் இவ்வளவு நேரம் காத்திருக்கும். மதிப்பு `=`-க்குப் பிறகு வர வேண்டும்: `--wait 2h` என்பது `--wait takes its value after '=': --wait=2h` என்ற குறிப்புடன் மறுக்கப்படும் | off; தனியாகக் கொடுத்தால் `5h` |
| `-c`, `--continue` | இந்தக் கோப்புறையின் கடைசி உரையாடலைப் புதிய கணக்காகத் தொடரும் (கீழே பாருங்கள்) | off |
| `--brief` | `--continue` உடன்: கடைசி உரையாடல் முழுவதையும் தொடர்வதற்குப் பதிலாக, அதைப் பற்றிய ccam-இன் சுருக்கத்திலிருந்து புதிய கணக்காக ஒரு புதிய உரையாடலைத் தொடங்கும் ([கீழே பாருங்கள்](#brief)) | off |
| `-- <claude args>` | ccam-இன் சொந்த arguments-க்குப் பின் `claude`-க்கு அனுப்பப்படும் arguments | none |
| `--dry-run` | ஆதரிக்கப்படும்: Claude Code-ஐத் தொடங்காமலும் தொடக்கத்தைப் பதிவு செய்யாமலும், `→ <from> → <to>`-ஐயும் அது இயக்கும் கட்டளை வரியையும் அச்சிடும் | off |

`--auto`, `--continue` இரண்டும் சேர்ந்து வேலை செய்யும். `--continue` கொடுத்தால், `--resume` arguments உங்கள் சொந்த arguments-க்கு முன் வைக்கப்படும்.

`--dangerously-skip-permissions` அல்லது `--model` போன்ற Claude Code-இன் சொந்த options `--`-க்குப் பிறகு வர வேண்டும். பெயருக்குப் பிறகு உள்ள அனைத்தையும் அப்படியே அனுப்பும் `ccam <name>` போல அல்லாமல், `ccam next` தன் arguments-ஐத் தானே படிக்கிறது, எனவே `--` இல்லாமல் அது `ccam: unknown flag: --dangerously-skip-permissions` என்று நின்றுவிடும்.

## இது எப்படி வேலை செய்கிறது

ccam வழியான ஒவ்வொரு தொடக்கமும் நேரத்தை `~/.local/state/ccam/last-used/<name>`-இல் எழுதுகிறது. `ccam next` இந்தக் கோப்புகளைப் படித்து, எந்தக் கணக்குகள் உள்நுழைந்துள்ளன என்று சரிபார்த்து, தேர்ந்தெடுக்கிறது.

1. ccam `config.toml`-இலிருந்து ஒவ்வொரு கணக்குக்கும் ஒரு `next.Candidate`-ஐ உருவாக்குகிறது (`cli.candidates`): கணக்கு, அதன் கடைசித் தொடக்க நேரம் (`launcher.LastUsed`), அதற்கு வேலை செய்யும் உள்நுழைவு உள்ளதா என்பது (`creds.Has`: `.credentials.json`-இல், அல்லது macOS-இல் Keychain-இல், முழுவதுமாகக் காலாவதியாகாத, Claude Code அழிக்காத ஒரு Claude உள்நுழைவு). அதற்குப் பதிலாக API key பயன்படுத்தும் கோப்புறைக்கு (Console உள்நுழைவு, அல்லது `ccam add --api` மூலம் சேர்த்த கணக்கு) plan வரம்புகள் இல்லை, அது ஒருபோதும் தேர்ந்தெடுக்கப்படாது.
2. `--auto` இல்லாமல், ccam கணக்குகளை slot எண்ணின்படி வரிசைப்படுத்தி, மிகச் சமீபத்தில் தொடங்கப்பட்டதைக் கண்டுபிடிக்கிறது (`next.Rotate`). அதுதான் நீங்கள் விட்டு மாறும் கணக்கு. இதுவரை எந்தக் கணக்கும் தொடங்கப்படவில்லை என்றால், அது மிகக் குறைந்த slot.
3. அங்கிருந்து அது slot வரிசையில் முன்னோக்கிச் சென்று, கடைசி slot-இலிருந்து முதலாவதுக்குச் சுற்றி வந்து, உள்நுழைந்துள்ள முதல் கணக்கைத் திருப்பித் தருகிறது.
4. ccam தேர்ந்தெடுக்கப்பட்ட கணக்கை `ccam <name>` செய்வது போலவே தயார்செய்து தொடங்குகிறது (`launcher.LaunchWith`): கணக்கின் இணைப்புகளைச் சரிபார்க்கிறது, MCP பகிர்வைப் பொருத்துகிறது, அமர்வைப் பதிவு செய்கிறது, `syscall.Exec` மூலம் ccam-ஐ `claude`-ஆல் மாற்றுகிறது.

தேடல் கடைசியாகப் பயன்படுத்திய கணக்கிலிருந்து தொடங்கி, அதற்குப் பின் உள்நுழைந்துள்ள முதல் கணக்கில் நிற்கிறது:

`work` மிகச் சமீபத்தில் தொடங்கப்பட்டது, அதனால் தேடல் அதற்குப் பின் தொடங்குகிறது. `side`-க்கு உள்நுழைவு இல்லை, அது தவிர்க்கப்படுகிறது, `lab` தேர்ந்தெடுக்கப்படுகிறது. `lab`-உம் வெளியேறியிருந்தால், தேடல் `personal`-க்குச் சுற்றி வந்திருக்கும் (வரைபடத்தில் `% len`). சுழற்சி நீங்கள் தொடங்கிய கணக்கை ஒருபோதும் திருப்பித் தராது: உள்நுழைந்த வேறு கணக்கு இல்லையென்றால், அது பிழையுடன் நின்றுவிடும்.

### --auto

`--auto` slot வரிசைக்குப் பதிலாகப் பயன்பாட்டின்படி முடிவு செய்கிறது. ccam உள்நுழைந்த கணக்குகளை வைத்துக்கொண்டு, `ccam usage` செய்வது போலவே அவற்றின் பயன்பாட்டை ஒரே நேரத்தில் கேட்டு (`Fetcher.FetchAll`), கீழே உள்ள விதிகளின்படி தேர்ந்தெடுக்கிறது (`cli.pickAuto`, `usage.Policy.Choose()`):

<!-- motion:next-auto -->

ஒரு கணக்கு அதன் 5 மணி நேர மற்றும் வாராந்திரக் கால அளவுகளால் மதிப்பிடப்படுகிறது, Claude Code-க்கான arguments-இல் (`--`-க்குப் பிறகு) `--model` இருந்தால் அந்த model-இன் வாராந்திரக் கால அளவாலும் (பெயரில் `opus`, `sonnet`, `haiku` அல்லது `fable`). ccam கணக்குகளை மூன்று அடுக்குகளாகப் பிரிக்கிறது (`Policy.Choose()`):

1. **இடம் உள்ளவை**: ஒவ்வொரு கால அளவும் `auto_max_usage`-க்குக் (`config.toml`, இயல்புநிலை 100) கீழ். அவற்றுள் strategy தேர்ந்தெடுக்கிறது: `headroom` (இயல்புநிலை) மிகக் குறைந்த 5 மணி நேரப் பயன்பாட்டை எடுக்கிறது; `expiring` மிக விரைவில் மீட்டமைக்கப்படும் 5 மணி நேரக் கால அளவை எடுக்கிறது, அதனால் அதன் மீதமுள்ள quota இழக்கப்படும் முன் பயன்படுத்தப்படுகிறது; `balance` தன் வாரம் மீட்டமைக்கப்படும் வரை ஒரு நாளுக்கு அதிக வாராந்திர quota மீதமுள்ள கணக்கை எடுக்கிறது, இயங்கும் ஒவ்வொரு ccam அமர்வையும் அதற்கு எதிராகக் கணக்கிடுகிறது, அதனால் வாராந்திர quota பயன்படுத்தப்படாமல் விடப்படுவதில்லை, இணையான அமர்வுகள் பரவுகின்றன.
2. **மேலே உள்ளவை**: 100%-க்குக் கீழ், ஆனால் `auto_max_usage`-இல் அல்லது அதற்கு மேல். எந்தக் கணக்கிலும் இடம் இல்லாதபோது மட்டுமே பயன்படுத்தப்படுகின்றன; மிகக் குறைந்த 5 மணி நேரப் பயன்பாடு உள்ளது முதலில் வரும்.
3. **நிரம்பியவை**: 100%-இல் ஒரு கால அளவு, அல்லது தெரியாத 5 மணி நேரப் பயன்பாடு. ஒருபோதும் தேர்ந்தெடுக்கப்படாது.

Claude Code ஒரு கால அளவில் கோரிக்கையை மறுத்தபோது, அந்தக் கால அளவு அதன் மீட்டமைப்பு வரை 100% ஆகக் கணக்கிடப்படுகிறது: சேமித்த எண்கள் என்ன சொன்னாலும், [ccam plugin](#inside-claude-code)-இன் hook அதைப் பதிவு செய்கிறது (`~/.local/state/ccam/usage/<name>.limit.json`). அதனால் இப்போதுதான் வரம்பை எட்டிய கணக்கு, அதன் எண்கள் பழையவையாக இருந்தாலும், மீட்டமைப்புக்கு முன் மீண்டும் தேர்ந்தெடுக்கப்படாது.

எல்லாக் கணக்குகளுக்குமான அமைப்புகள் `config.toml`-இன் மேற்பகுதியில், முதல் `[[group]]`, `[[profile]]` அல்லது `[[folder]]`-க்கு மேலே இருக்க வேண்டும். அவற்றில் ஒன்றுக்குக் கீழே உள்ள அமைப்பு அந்த table-க்கு உரியதாகிவிடும்: ccam ஒவ்வொரு தொடக்கத்திலும் அதைப் பற்றி எச்சரிக்கிறது, அது நகர்த்தப்படும் வரை config-ஐச் சேமிக்கும் கட்டளைகள் மறுக்கும்.

```toml
# ~/.config/ccam/config.toml
auto_max_usage = 80        # keep 20% of each account for interactive work
auto_strategy = "expiring"
```

**நிறுவனங்கள்.** தானியங்கித் தேர்வுகள் நீங்கள் விட்டுச்செல்லும் கணக்கின் அதே வகையைச் சேர்ந்த கணக்குகளுக்குள்ளேயே இருக்கின்றன: அதே Team அல்லது Enterprise நிறுவனத்தின் இருக்கைகள், அல்லது தனிப்பட்ட plans (Pro, Max), அதனால் நிறுவனக் கணக்கின் வேலை ஒரு தனிப்பட்ட கணக்கில் தொடர்வதில்லை, தலைகீழாகவும் இல்லை. ஒவ்வொரு கணக்கின் நிறுவனத்தையும் ccam அதன் உள்நுழைவிலிருந்து அறிகிறது (`ccam login` அதைப் பதிவு செய்கிறது; பழைய உள்நுழைவுகள் `.claude.json`-இலிருந்து படிக்கப்படுகின்றன); ccam நிறுவனத்தை அறிய முடியாத கணக்கை எந்தக் கணக்குடனும் பொருத்தலாம். ஒரே Claude கணக்கில் உள்நுழைந்த இரண்டு கோப்புறைகள் அதன் வரம்புகளைப் பகிர்கின்றன, அதனால் ஒன்று மற்றொன்றிடமிருந்து ஒருபோதும் பொறுப்பேற்பதில்லை. `--cross-org`, அல்லது `config.toml`-இல் `cross_org = true`, நிறுவன விதியை நீக்குகிறது.

எதையும் தேர்ந்தெடுக்க முடியாதபோது, ccam code 75 (`EX_TEMPFAIL`) உடன் வெளியேறுகிறது, அதனால் ஒரு script "பிறகு முயலுங்கள்" என்பதைத் தோல்வியிலிருந்து பிரித்தறிய முடியும். `--wait` உடன், அதற்குப் பதிலாக முதல் நிரம்பிய கணக்கின் தடுக்கும் கால அளவு மீட்டமைக்கப்படும் வரை (மீட்டமைப்பு நேரத்துக்கு 30 வினாடிகள் பிறகு, endpoint புதிய கால அளவைக் காட்டும்போது) உறங்கி, `ccam: no account has room; waiting until 15:10` என்று அச்சிட்டு, மீண்டும் தேர்ந்தெடுக்கிறது; எந்தக் கணக்கும் எப்போது மீட்டமைக்கப்படும் என்று சொல்லாதபோது, 10 நிமிடங்களுக்குப் பிறகு மீண்டும் பார்க்கிறது. காத்திருப்பு முடியும் முன் எதுவும் விடுபடாவிட்டால், 75 உடன் வெளியேறுகிறது.

தேடல் `ccam usage`-இன் விதிகளைப் பின்பற்றுகிறது: 60 வினாடிகளுக்கும் குறைவான பழைய எண்கள் மீண்டும் பயன்படுத்தப்படும், ஒவ்வொரு கணக்கின் தேடலும் 3 வினாடிகளில் timeout ஆகும், பதில் அளிக்காத அல்லது access token காலாவதியான கணக்கு அதன் சேமித்த எண்களால் மதிப்பிடப்படும், வரம்புப் பதிவு அவற்றை மீறும். மீட்டமைப்பு நேரம் கடந்துவிட்ட சேமித்த கால அளவு 0% ஆகக் கருதப்படும், அதனால் இடையில் கால அளவு மீட்டமைக்கப்பட்ட கணக்கு தவிர்க்கப்படாது. `--auto` ஒருபோதும் tokens-ஐப் புதுப்பிப்பதில்லை. வெறும் சுழற்சியைப் போலன்றி, நீங்கள் கடைசியாகப் பயன்படுத்திய கணக்கில் இன்னும் அதிக இடம் இருந்தால் `--auto` அதையே தேர்ந்தெடுக்கக்கூடும்.

### --continue

1. ccam ஒவ்வொரு கணக்கிலும் இந்தக் கோப்புறையின் கடைசி உரையாடலைத் தேடுகிறது: `projects/<folder>/`-இல் உள்ள `<session>.jsonl` கோப்புகளில் (கோப்புறைப் பெயர் என்பது, Claude Code பெயரிடுவது போலவே, links தீர்க்கப்பட்டு, எழுத்து அல்லது இலக்கம் அல்லாத ஒவ்வொரு எழுத்தும் `-` ஆக மாற்றப்பட்ட வேலைக் கோப்புறை), மிகப் புதிய prompt அல்லது பதில் உள்ளது. அவை இல்லாத அமர்வுகள், எடுத்துக்காட்டாக `/mcp`, `/usage` அல்லது `/status` மட்டுமே இயக்கிய அமர்வு, அல்லது காலியான கோப்பு, தவிர்க்கப்படுகின்றன. ஓர் அமர்வு ஒரு குறிப்பை விட்டுச்சென்றிருந்து (பயன்பாட்டு வரம்பு அல்லது `/ccam:switch`, கீழே பாருங்கள்), அதற்கு 2 நிமிடங்களுக்கு மேல் பிறகு எந்த உரையாடலிலும் prompt அல்லது பதில் இல்லையென்றால், அதற்குப் பதிலாக அந்தக் குறிப்பிட்ட அமர்வு பயன்படுத்தப்படுகிறது; `/exit`-இல் Claude Code எழுதும் வரிசைகள் கணக்கில் கொள்ளப்படுவதில்லை.
2. அது சேர்ந்த கணக்கிலிருந்துதான் நீங்கள் மாறுகிறீர்கள், புதிய கணக்கு மேலே உள்ளபடியே, அதே நிறுவனத்துக்குள் தேர்ந்தெடுக்கப்படுகிறது. பல கணக்குகள் அந்த வரலாற்றைப் பகிரும்போது, உரையாடலைக் கடைசியாக இயக்கியது தான் என்று எந்தக் கணக்கின் `.claude.json` சொல்கிறதோ (`lastSessionId`) அதற்கு அது சேரும், இல்லையெனில் கடைசியாகப் பயன்படுத்திய கணக்குக்கு.
3. புதிய கணக்கு அந்த வரலாற்றைப் பகிர்ந்தால் (அதே குழுக் கோப்புறை), ccam `claude --resume <session id>`-ஐத் தொடங்குகிறது, அதாவது அதே உரையாடலை (`--continue` என்றால் கோப்புறையில் எது மிகப் புதியதோ அதைத் திறந்திருக்கும்).
4. இல்லையென்றால் அது `claude --resume <the conversation's file> --fork-session`-ஐத் தொடங்குகிறது: Claude Code முழு உரையாடலையும், ஒரு புதிய session ID-இன் கீழ், புதிய கணக்கின் சொந்த வரலாற்றுக்குள் நகலெடுக்கிறது, மூலம் அப்படியே இருக்கும். அதன் பிறகு புதிய கணக்கின் `--continue` அதைக் கண்டுபிடிக்கும்.

உரையாடல் எவ்வளவு பெரியது என்று ccam சொல்கிறது: புதிய கணக்கு தன் முதல் பதிலுடன் அதை முழுவதும் மீண்டும் படிக்கிறது. Prompt caches நிறுவனங்களுக்கு இடையே ஒருபோதும் பகிரப்படுவதில்லை, ஒவ்வொரு தனிப்பட்ட plan-உம் தனக்கென ஒரு நிறுவனம், அதனால் இரண்டு கணக்குகளும் வெவ்வேறு நிறுவனங்களைச் சேர்ந்தவையாக இருக்கும்போது ccam `prompt caches are not shared between organizations, so the first reply reads it all again` என்பதைச் சேர்க்கிறது. பழைய கணக்கு உள்நுழைந்துள்ள MCP சர்வர்களில் புதிய கணக்கு உள்நுழையவில்லை என்றால், ccam அவற்றைப் பெயரிடுகிறது: `work is not signed in to MCP servers that personal is signed in to: linear (sign in with /mcp there; sign-ins are not shared)`. ஒரு குழுவில் `history`-ஐப் பகிர்வது நகலெடுப்பைத் தவிர்க்கிறது, ஒரே உரையாடலை வைத்திருக்கிறது, `/rewind` code-ஐ மீட்டெடுக்கும் checkpoints-ஐயும் (`file-history/`) பகிர்கிறது.

### --brief

`--continue` முழு உரையாடலையும் தொடர்கிறது, புதிய கணக்கு தன் முதல் பதிலுடன் அதை முழுவதும் மீண்டும் படிக்கிறது. `ccam next --continue --brief` அதற்குப் பதிலாக ஒரு புதிய உரையாடலைத் தொடங்குகிறது, பழைய உரையாடலைப் பற்றி ccam எந்த model-இடமும் கேட்காமல் எழுதும் சுருக்கத்திலிருந்து:

```console
$ ccam next --auto --continue --brief
→ personal → work (12% of its 5 hours used, the least)
  starting a new conversation with ccam's summary of "Fix the flaky tests" instead of resuming it (about 182k tokens)
  summary (6k characters): /home/you/.local/state/ccam/brief/4f1c….md
```

சுருக்கத்தில், இந்த வரிசையில், சொல்ல ஏதேனும் இருக்கும் இடங்களில் மட்டும், இவை இருக்கும்:

1. உரையாடலின் தலைப்பு;
2. ஒரு விவரம் தேவைப்படும்போது Claude தேடுவதற்காக, அதன் transcript-இன் பாதை;
3. நான்குக்கு மேல் கோரிக்கைகள் இருந்தால், உங்கள் முதல் கோரிக்கை;
4. Claude Code உரையாடலைக் கடைசியாகச் சுருக்கியபோது (compact) எழுதிய சுருக்கம்;
5. உங்கள் கடைசி நான்கு கோரிக்கைகள், `!` கட்டளைகளும் slash commands-உம் நீங்கள் தட்டச்சு செய்தபடியே;
6. Claude-இன் கடைசிப் பதில்;
7. todo பட்டியல்;
8. Claude கடைசியாக மாற்றிய 10 கோப்புகள்;
9. கோப்புறையின் `git status --short --branch`, 800 எழுத்துகள் வரை.

todo பட்டியல் அதிகபட்சம் 10 உருப்படிகளை வைத்திருக்கும்: முடிந்த உருப்படிகள் முதலில் நீக்கப்படும், பிறகு மிகத் தொலைவில் உள்ள படிகள், அதனால் தற்போதைய படியும் அடுத்த படிகளும் இருக்கும். நீண்ட பகுதிகள் நடுவில் வெட்டப்படும், முழுச் சுருக்கமும் 16,000 எழுத்துகளுக்குக் கீழ் இருக்கும்.

ccam அதை `~/.local/state/ccam/brief/<session>.md`-ஆக, உங்களால் மட்டுமே படிக்கக்கூடியதாகச் சேமிக்கிறது, அடுத்த `--brief` 7 நாட்களுக்கு மேல் பழைய சுருக்கங்களை நீக்குகிறது. Claude Code ஒரே prompt உடன் தொடங்கி, அது குறிப்பிடும் கோப்பை இணைக்கிறது: `Read @"<the summary>", the summary ccam wrote of my earlier Claude Code conversation, which is not loaded here. Then reply with one or two sentences on where the work stands, and wait for my next message.` `--`-க்குப் பிறகு நீங்கள் கொடுக்கும் prompt கடைசி வாக்கியத்தின் இடத்தைப் பிடிக்கிறது (`Then: <your prompt>`), `--`-க்குப் பிறகு உள்ள உங்கள் மற்ற options அதைத் தொடர்கின்றன.

Claude Code ஒரு mention-ஐ `"`-இல் முடித்து, `#`-இல் வெட்டுகிறது, அதனால் சுருக்கத்தின் பாதையில் இவற்றில் ஏதேனும் இருந்தால், ccam அதை வேலைக் கோப்புறையைச் சார்ந்த அதன் பாதையால் குறிப்பிடுகிறது; அந்தப் பாதையிலும் ஒன்று இருந்தால், prompt கோப்பைப் பெயரிடுகிறது, Claude அதைத் தன் Read tool மூலம் படிக்கிறது, கோப்பு வேலைக் கோப்புறைகளுக்கு வெளியே இருப்பதால் அது முதலில் கேட்கிறது (Manual mode-இல் ஒரு `-p` இயக்கத்தில், Claude Code அந்த வாசிப்பை மறுக்கிறது, Claude சுருக்கம் இல்லாமலே தொடர்கிறது).

`ccam --dry-run next --continue --brief` சுருக்கத்தை அச்சிடுகிறது, எதையும் சேமிப்பதில்லை. பழைய உரையாடல் அப்படியே இருக்கும், புதியதுக்குச் சுருக்கம் சொல்வது மட்டுமே தெரியும், அதனால் நீங்கள் அங்கே வந்து சேர்ந்த வழியின் ஒவ்வொரு விவரத்தையும் விடப் பணி முக்கியமானதாக இருக்கும்போது `--brief` பயன்படுத்துங்கள். `--continue` இல்லாமல், ccam `--brief works with --continue` என்று நின்றுவிடும்; உரையாடலைப் படிக்க முடியாதபோது அல்லது அதில் சுருக்க எதுவும் இல்லாதபோது, அது நின்று, `--brief` இல்லாத `ccam next --continue` அதை முழுமையாகத் தொடரும் என்று சொல்கிறது. [relay](#relay)-உம் [`auto_switch`](#auto-switch)-உம் எப்போதும் முழு உரையாடலையும் தொடர்கின்றன. Claude Code-இன் சொந்த `--brief` option, அதன் மற்ற options போலவே, `--`-க்குப் பிறகு வரும்.

## Claude Code-க்குள்

[ccam plugin](/docs/install#claude-code-plugin) இரண்டு hooks-ஐச் சேர்க்கிறது (Claude Code 2.1.78 அல்லது பிந்தையது):

- ஒரு turn பயன்பாட்டு வரம்பில் நிற்கும்போது, அது உரையாடலைக் குறித்து வைத்து, அதை ஆதரிக்கும் டெர்மினல்களில் (iTerm2, WezTerm, Windows Terminal, kitty, Ghostty) ஒரு desktop அறிவிப்பைக் காட்டுகிறது: ``ccam: work hit its 5-hour limit (resets 3:45pm). `ccam next --continue` continues the conversation on another account.``

  Claude Code பயன்பாட்டு வரம்பாகக் கருதும் ஒவ்வொரு செய்தியையும் அது அறியும்: 5 மணி நேர, வாராந்திர, சாதாரண, model வரம்புகள் (`You've hit your session limit`, `You've hit your limit`, ஒரு model-இன் ஒதுக்கீட்டுக்கு `You've reached your …`), usage credits, spend limits, கணக்கை நிறுத்திய நிறுவனம்.

  மறுக்கப்பட்ட கோரிக்கையை Claude Code உரையாடலில் எழுதியிருந்தால், hook நிரம்பிய கால அளவை அதன் மீட்டமைப்பு வரை பதிவும் செய்கிறது ([வரம்புப் பதிவு](/features/usage#the-limit-record)), ஒரு நிறுவனம் அமைத்த நிறுத்தத்தைத் தவிர, ஏனெனில் அதன் admins அதை எப்போது வேண்டுமானாலும் நீக்கலாம். சர்வரின் குறுகிய throttle அல்லது ஒரு API key-இன் rate limit பயன்பாட்டு வரம்பு அல்ல, அவை விடப்படுகின்றன; subagent-இன் நிறுத்தமும், கவனிப்பாரற்ற அமர்வுகளும் (`-p` இயக்கங்கள், பின்னணி அமர்வுகள்) அப்படியே.

  Claude Code 2.1.234 மற்றும் பிந்தையவை அமர்விலேயே காத்திருந்து, 5 மணி நேர மீட்டமைப்புக்குப் பிறகு தாமாகவே தொடர்கின்றன; அதற்குப் பதிலாக மாறும் தேர்வை அறிவிப்பு உங்களுக்குத் தருகிறது, [`auto_switch`](#auto-switch) இயக்கத்தில் இருந்தால் (Linux, macOS), வேறொரு கணக்கில் இடம் இருக்கும்போது ccam உங்களுக்காக மாற்றுகிறது. வேறு எந்தக் கணக்கும் பொறுப்பேற்க முடியாதபோது, அதாவது அதே Team அல்லது Enterprise நிறுவனத்தைச் சேர்ந்த வேறு கணக்கு இல்லாதபோது, அல்லது வேறு தனிப்பட்ட திட்டம் இல்லாதபோது (`cross_org` இயக்கத்தில் இருந்தால், வேறு எந்த Claude கணக்கும் பொறுப்பேற்கலாம்), அறிவிப்பு அதற்குப் பதிலாக `You have no other personal plans, so ccam cannot move this conversation.` அல்லது `You have no other accounts in Acme, so ccam cannot move this conversation.` என்று முடிகிறது.
- `/ccam:switch [account]` உரையாடலைக் குறித்து வைத்து, எந்தக் கோரிக்கையும் செய்யப்படும் முன் turn-ஐ முடிக்கிறது: `/exit` என்று தட்டச்சு செய்யுங்கள், பிறகு நீங்கள் பெயரிட்ட கணக்கில் (அல்லது அடுத்த கணக்கில்) அதைத் தொடர `ccam next --continue` இயக்குங்கள். இன்னும் உரையாடல் இல்லாத அமர்வில், தொடர எதுவும் இல்லை என்று அது சொல்கிறது.

குறிப்பு `~/.local/state/ccam/handoff/<account>/<session>.json`-இல் இருக்கும், ஒவ்வோர் அமர்வுக்கும் ஒரு கோப்பு, அதனால் ஒரு கணக்கின் இரண்டு அமர்வுகள் ஒன்றின் குறிப்பை மற்றொன்று ஒருபோதும் மேலெழுதாது. அது 12 மணி நேரம் வைக்கப்பட்டு, அடுத்த அமர்வு தொடங்கவிருக்கும்போது ஒருமுறை மட்டுமே பயன்படுத்தப்படும்; தோல்வியடையும் தொடக்கம் அதை அடுத்த முயற்சிக்காக விட்டுவைக்கும். Claude Code-இன் shell-இல் `cd` செய்த பிறகும், அது அமர்வு தொடங்கிய கோப்புறைக்கே சொந்தமானது. `ccam rename` அதிலுள்ள பெயர்களைப் புதுப்பிக்கிறது; அது குறிப்பிடும் கணக்கு அதன் பிறகு நீக்கப்பட்டிருந்தால், ccam அதைச் சொல்லிவிட்டு வழக்கம்போலத் தேர்ந்தெடுக்கும்.

### Relay

`config.toml`-இன் மேற்பகுதியில் `relay = true` இருந்தால், ccam தன் இடத்தில் Claude Code-ஐ இயக்குவதற்குப் பதிலாக interactive அமர்வுகளுடன் சேர்ந்து இயங்கிக்கொண்டிருக்கும், `/ccam:switch`-க்குப் பிறகு அந்த அமர்வின் உரையாடலைத் தானாகவே தொடரும் (வேறோர் அமர்வு விட்டுச்சென்ற குறிப்பின்படி அது செயல்படாது): hook Claude Code-ஐ முடிக்கிறது, ccam அந்த அமர்வின் குறிப்புடன் `ccam next --continue`-ஐ இயக்குகிறது. கணக்கு பெயரிடப்படாவிட்டால், உரையாடலின் model-ஐயும் கணக்கிட்டு, அதிக இடம் உள்ள கணக்கை எடுக்கிறது. Windows-இல் hook Claude Code-ஐ முடிக்க முடியாது: `/exit` என்று தட்டச்சு செய்யுங்கள், ccam அதைத் தொடரும். அதற்கு ஒவ்வோர் அமர்வுக்கும் காத்திருக்கும் ஒரு ccam process செலவாகும், அதனால்தான் இது இயல்பாக off.

ஓர் உரையாடலைத் தொடர்வது (resume) மீட்டெடுக்காதவற்றை relay செய்யப்பட்ட அமர்வு வைத்துக்கொள்கிறது: `--add-dir`, `--mcp-config`, tool பட்டியல்கள், `--settings`, `--plugin-dir`, system prompt options போன்ற options, உரையாடலின் permission mode, அமர்வின் effort level. `--model`, `--name`, `--agent` ஆகியவற்றை Claude Code தானே உரையாடலிலிருந்து மீட்டெடுக்கிறது. வேறு எதுவும் (`--worktree`, `--debug`, `--remote-control`, ccam-க்குத் தெரியாத options) `ccam: not carried over: …`-இல் பெயரிடப்படும். மாற்றம் பகிரப்பட்ட வரலாறு பற்றிய கேள்வியை ஒருபோதும் கேட்பதில்லை, அது இயங்கும்போது நீங்கள் தட்டச்சு செய்தவை கைவிடப்படும்.

`/ccam:switch` கேட்டபடி Claude Code முடிந்தால் மட்டுமே relay உரையாடலைத் தொடர்கிறது: நீங்கள் முதலில் `/exit` தட்டச்சு செய்தபோது, அது முடியும்போது Ctrl+C அழுத்தியபோது, ccam-க்கு hangup அல்லது வேறு signal வந்தபோது, டெர்மினல் இல்லாமல் போனபோது அல்ல. அப்போது குறிப்பு அப்படியே இருக்கும், `ccam next --continue` பின்னர் அதைத் தொடரும். ccam-இன் பழைய பதிப்பின் relay-இன் கீழ் தொடங்கிய அமர்வையோ, கவனிப்பாரற்ற அமர்வையோ (`-p` இயக்கங்கள், பின்னணி அமர்வுகள்) hook முடிப்பதில்லை; அதற்குப் பதிலாக அது `/exit` செய்தியைப் பெறும். `claude remote-control` relay இல்லாமல் இயங்குகிறது.

### `auto_switch`

`config.toml`-இன் மேற்பகுதியில் `auto_switch = true` இருந்தால் (Linux, macOS), Claude Code ஓர் அமர்வைப் பயன்பாட்டு வரம்பில் நிறுத்தும்போது ccam அதைத் தானாகவே வேறொரு கணக்குக்கு நகர்த்துகிறது: plugin-இன் hook இடம் உள்ள வேறொரு கணக்கைத் தேர்ந்தெடுத்து Claude Code-ஐ முடிக்கிறது, அமர்வுடன் சேர்ந்து இயங்கும் ccam, `/ccam:switch`-க்குப் பிறகு [relay](#relay) செய்வது போலவே, உரையாடலை அங்கே தொடர்கிறது. இது இயல்பாக அணைக்கப்பட்டுள்ளது, சோதனை நிலையில் உள்ளது.

# ~/.config/ccam/config.toml

இவை அனைத்தும் பொருந்தும்போது மட்டுமே ccam ஓர் அமர்வை நகர்த்துகிறது:

1. ccam அதை ஒரு டெர்மினலில் தொடங்கி, அதனுடன் சேர்ந்து இயங்கிக்கொண்டிருக்கிறது. `auto_switch` [relay](#relay)-ஐ இயக்குகிறது, அதனால் அதை அமைத்த பிறகு நீங்கள் தொடங்கும் interactive அமர்வுகளுக்கு இது பொருந்தும். அதற்கு முன், அல்லது பழைய ccam-இன் கீழ் தொடங்கிய அமர்வுக்கு, ``This session started before auto_switch was on or under an older ccam, so ccam cannot move it: type /exit, then run `ccam next --continue`.`` என்று முடியும் அறிவிப்பு கிடைக்கிறது. கவனிப்பாரற்ற அமர்வுகள் (`-p` இயக்கங்கள், பின்னணி அமர்வுகள்), `claude remote-control`, ccam இல்லாமல் தொடங்கிய Claude Code ஆகியவை ஒருபோதும் நகர்த்தப்படுவதில்லை.
2. கணக்கில் [ccam plugin](/docs/install#claude-code-plugin) இயக்கத்தில் உள்ளது, அது Claude Code 2.1.214 அல்லது பிந்தையதை இயக்குகிறது; அந்தப் பதிப்பு தன் process ID-ஐ hook-க்கு அனுப்புகிறது (`CLAUDE_PID`).
3. அந்தக் கணக்கின் 5 மணி நேர, வாராந்திர, Opus அல்லது Sonnet வரம்புக்காக மறுக்கப்பட்ட கோரிக்கையை, அது மீட்டமைக்கப்படும் நேரத்துடன், Claude Code உரையாடலில் எழுதியது. spend limit, usage credits தீர்வது, ஒரு நிறுவனம் அமைத்த நிறுத்தம், Fable ஒதுக்கீடு (`You've reached your Fable limit.`), சர்வர் throttle, API key-இன் rate limit, subagent-இன் நிறுத்தம் ஆகியவை ஒருபோதும் அமர்வை நகர்த்துவதில்லை.
4. கணக்கின் plan ccam-க்குத் தெரியும், அதன் `.claude.json`-இலிருந்து அல்லது `ccam login` பதிவு செய்ததிலிருந்து. இல்லையெனில் அறிவிப்பு `ccam does not know personal's plan, so auto_switch leaves this session.` என்று முடிகிறது.
5. அமர்வு Remote Control-உடன் இணைக்கப்படவில்லை. வேறொரு கணக்காக அது நீங்கள் அதை இயக்கும் app-உடன் மீண்டும் இணையாது, அதனால் அது அப்படியே இருக்கும், அறிவிப்பு அதைச் சொல்லும்.
6. வரம்பு இப்போதிலிருந்து 15 நிமிடங்களுக்கு மேல் கழித்து மீட்டமைக்கப்படுகிறது. இதைவிடக் குறைவான காத்திருப்புக்கு ccam அமர்வை Claude Code-இடம் விடுகிறது: `ccam: personal hit its 5-hour limit, which resets in 9m; ccam leaves this session to wait for it.`
7. வரம்புக்குப் பிறகு நீங்கள் எந்த prompt-ஐயும் தட்டச்சு செய்யவில்லை.
8. வேறொரு கணக்கில் இடம் உள்ளது. நீங்கள் விட்டுச்செல்லும் கணக்கின் அதே வகையைச் சேர்ந்த கணக்குகளுக்குள், [`--auto`](#auto) செய்வது போலவே ccam தேர்ந்தெடுக்கிறது (`auto_max_usage`, `auto_strategy`, உரையாடலின் model): அதே Team அல்லது Enterprise நிறுவனத்தின் வேறொரு இருக்கை, அல்லது வேறொரு தனிப்பட்ட திட்டம் (Pro, Max). `cross_org`-உம் `--cross-org`-உம் இங்கே பொருந்தாது. அந்தக் கணக்கு:
   - Claude Code புதுப்பிக்கக்கூடிய உள்நுழைவுடன் உள்நுழைந்திருக்க வேண்டும்;
   - அதே Claude கணக்கில் உள்நுழைந்திருக்கக் கூடாது;
   - API key பயன்படுத்தக் கூடாது;
   - ccam-க்குத் தெரிந்த plan கொண்டிருக்க வேண்டும்;
   - ccam-இன் சொந்தப் பயன்பாட்டுத் தேடல் காட்டும் அளவுக்கு, usage credits இயக்கத்தில் இருக்கக் கூடாது;
   - Claude Code-இல் இந்தக் கோப்புறையை நம்பியிருக்க (trust) வேண்டும்.

   கடைசி இரண்டு நிபந்தனைகள் இடம் உள்ள எல்லாக் கணக்குகளையும் விலக்கும்போது, அறிவிப்பு அவற்றைப் பெயரிடுகிறது: `side has not trusted this folder yet, so the conversation was not moved there. Open the folder once as side to allow it.` அல்லது `side has room but its usage credits are on, so auto_switch did not move the conversation there; /ccam:switch side moves it.` [வரம்புப் பதிவு](/features/usage#the-limit-record) உள்ள கால அளவு நிரம்பியதாகக் கணக்கிடப்படுகிறது, கடைசி 2 நிமிடங்களில் வேறோர் அமர்வு நகர்ந்த கணக்கு மற்றவற்றுக்குப் பின் வருகிறது. தேர்வு சுமார் 6 வினாடிகளுக்குள் செய்யப்பட வேண்டும்; பயன்பாட்டுத் தேடல்கள் அதைவிட அதிக நேரம் எடுத்தால், அமர்வு அப்படியே இருக்கும். `usage_source = "claude"` உடன், `auto_switch` சேமித்த எண்களை மட்டுமே வைத்து முடிவு செய்கிறது, usage credits இயக்கத்தில் உள்ளதா என்பதை ccam Claude Code-இன் தேடலிலிருந்தோ நிலை வரியிலிருந்தோ அறிய முடியாது, அதனால் அவை அணைக்கப்பட்டுள்ளதாகக் கருதுகிறது.

பிறகு hook Claude Code-ஐ முடிக்கிறது, அதனுடன் சேர்ந்து இயங்கும் ccam, அதை ஆதரிக்கும் டெர்மினல்களில் ஒரு desktop அறிவிப்பைக் காட்டுகிறது, எடுத்துக்காட்டாக `ccam: personal hit its 5-hour limit (resets 3:29am). Moving this conversation to side (12% of its 5 hours used, the least).` அது மேலே உள்ள எடுத்துக்காட்டு output-இன் முதல் வரியை அச்சிட்டு, தேர்ந்தெடுத்த கணக்காக அந்த அமர்வுக்கு `ccam next --continue`-ஐ இயக்குகிறது; அது தன் மற்ற இரண்டு வரிகளையும் அச்சிட்டு, [relay](#relay) செய்வது போலவே, அமர்வின் options, permission mode, effort level ஆகியவற்றுடன் Claude Code-ஐத் தொடங்குகிறது. புதிய அமர்வின் முதல் செய்தி இந்த நிலையான உரை, உங்கள் சார்பில் ccam அனுப்பும் ஒரே விஷயம் இதுதான் (`/ccam:switch`-க்குப் பிறகான நகர்வு எதையும் அனுப்புவதில்லை):

```text
Your usage limit was reached and ccam moved this conversation to another account. Continue the task you were working on when the limit was reached; do not repeat work that is already complete.
```

அந்தக் கணக்கும் தன் வரம்பை எட்டினால், அங்கேயும் இதுவே நடக்கும். வரம்புப் பதிவுகள், மீட்டமைப்புக்கு முன் ஒரு கணக்குக்குச் சங்கிலி திரும்பிச் செல்வதைத் தடுக்கின்றன, அதனால் எல்லாக் கணக்குகளும் நிரம்பியிருக்கும்போது அமர்வு கடைசிக் கணக்கிலேயே இருக்கும்.

வேறு எந்தக் கணக்கிலும் இடம் இல்லாதபோது, எதுவும் நகர்வதில்லை: Claude Code வழக்கம்போல வரம்பைக் கையாள்கிறது, அமர்விலேயே காத்திருந்து அல்லது தன் தேர்வுகளை வழங்கி, எந்தக் கணக்கு முதலில் விடுபடும் என்று அறிவிப்பு சொல்கிறது, எடுத்துக்காட்டாக `ccam: personal hit its 5-hour limit (resets 3:29am). None of your other personal plans has room now; side frees up first, at 12:30am. Claude Code waits for personal here; /ccam:switch side after 12:30am moves it sooner.` இருக்கைகளுக்கு அது `None of your other accounts in Acme has room now` என்று சொல்கிறது. தொடங்கிவிட்ட நகர்வை நிறுத்த, Claude Code மூடும்போது Ctrl+C அழுத்துங்கள்: ``ccam: switch cancelled. Run `ccam next --continue` later to continue the conversation.``

ஒரு நகர்வுக்குச் செலவுகள் உண்டு. Claude Code மீண்டும் தொடங்குகிறது, அதற்குச் சில வினாடிகள் ஆகும், Claude தொடங்கிய பின்னணி shells, dev servers, agents ஆகியவை பழைய அமர்வுடன் நின்றுவிடும். [`--continue`](#continue) போலவே, புதிய கணக்கு தன் முதல் பதிலுடன் முழு உரையாடலையும் மீண்டும் படிக்கிறது, அது எவ்வளவு பெரியது என்று ccam சொல்கிறது; ஒரு நகர்வு ஒருபோதும் [`--brief`](#brief)-ஐப் பயன்படுத்துவதில்லை.

Claude Code ஒரு வரம்பைத் தெரிவிக்கும் முன் `auto_switch` ஒருபோதும் மாறுவதில்லை, பின்னணியில் உங்கள் பயன்பாட்டை ஒருபோதும் கண்காணிப்பதில்லை, ஓர் உள்நுழைவை ஒருபோதும் நகலெடுப்பதோ, புதுப்பிப்பதோ, அனுப்புவதோ இல்லை. Windows-இல் அது புறக்கணிக்கப்படுகிறது, `ccam doctor` அதைச் சொல்கிறது; அங்கே, `relay = true` உடன், `/ccam:switch`-உம் `/exit`-உம் அப்போதும் ஓர் உரையாடலை வேறொரு கணக்குக்கு நகர்த்துகின்றன.

**Anthropic-இன் விதிமுறைகள்.** Team, Enterprise இருக்கைகளில், `auto_switch` உங்கள் வேலையை அதே நிறுவனத்தின் வேறொரு இருக்கைக்கு நகர்த்துகிறது. Anthropic-இன் உதவி மையம் "Each seat on a Team plan is assigned to one named individual, and only that person may use it" (Team திட்டத்தின் ஒவ்வொரு இருக்கையும் பெயர் குறிப்பிடப்பட்ட ஒரு நபருக்கு ஒதுக்கப்படுகிறது, அந்த நபர் மட்டுமே அதைப் பயன்படுத்தலாம்) என்றும், "Users can't route their work through another user's account to use that user's remaining usage" (மற்றொரு பயனரின் மீதமுள்ள பயன்பாட்டைப் பயன்படுத்திக்கொள்ள, பயனர்கள் தங்கள் வேலையை அந்தப் பயனரின் கணக்கு வழியாக அனுப்ப முடியாது) என்றும் கூறுகிறது ([Team திட்டங்கள்](https://support.claude.com/en/articles/12004354-purchase-and-manage-seats-on-team-plans#h_b8a7d07129); இதேபோல் [Enterprise திட்டங்களுக்கும்](https://support.claude.com/en/articles/13393991-purchase-and-manage-seats-on-enterprise-plans#h_fa6b9cade0)).

தனிப்பட்ட திட்டங்களுக்கு (Pro, Max), உங்கள் சொந்தக் கணக்குகள் ஒரு வரம்பில் தானாக ஒன்றுக்கொன்று பொறுப்பேற்கலாமா என்று Anthropic-இன் விதிமுறைகள் சொல்லவில்லை. Anthropic வெளிப்படையாக அனுமதிக்காத வரை, [Consumer Terms](https://www.anthropic.com/legal/consumer-terms) சேவைகளை "through automated or non-human means, whether through a bot, script, or otherwise" (bot, script அல்லது வேறு வழியில், தானியங்கி அல்லது மனிதரல்லாத வழிகளில்) அணுகுவதைத் தடுக்கின்றன, ஒரு நகர்வு மேலே உள்ள நிலையான செய்தியை உங்கள் சார்பில் அனுப்புகிறது. நவம்பர் 12, 2026 அன்று நடைமுறைக்கு வரும் [Usage Policy](https://www.anthropic.com/legal/aup), தான் தடைசெய்பவற்றில் "Intentionally bypass or interfere with capabilities, restrictions, or guardrails established within our products" (எங்கள் தயாரிப்புகளில் நிறுவப்பட்ட திறன்கள், கட்டுப்பாடுகள் அல்லது பாதுகாப்பு வரம்புகளை வேண்டுமென்றே தவிர்ப்பது அல்லது அவற்றில் குறுக்கிடுவது) என்பதைப் பட்டியலிடுகிறது.

`auto_switch` இந்த விதிமுறைகளுக்கு இணங்குகிறது என்று ccam கூறவில்லை. அதை இயக்குவது உங்கள் முடிவு, அதன் இடரும் உங்களுடையதே: விதிமுறைகள் மீறப்பட்டதாக Anthropic கருதினால், அது ஒரு கணக்கையோ, ஒரு Team அல்லது Enterprise நிறுவனத்தின் அணுகலையோ இடைநிறுத்தலாம்.

`auto_switch` இயக்கத்தில் இருக்கும்போது, ccam plugin இல்லாத கணக்கு பற்றியும், 2.1.214-ஐ விடப் பழைய Claude Code பதிப்புகள் பற்றியும் `ccam doctor` எச்சரிக்கிறது, இருக்கைகளுக்கு Anthropic-இன் இருக்கை விதியை மீண்டும் சொல்கிறது ([சரிபார்ப்புகள்](/features/doctor)).

## வரம்பில் மீண்டும் இயக்குதல்

`ccam next` நின்றுபோன interactive அமர்வுக்கானது. interactive அல்லாத இயக்கம், அதாவது ஒரு script-இல் அல்லது திட்டமிட்ட job-இல் உள்ள `claude -p`, உங்களுக்காகக் காத்திருக்க முடியாது, அதனால் கணக்குப் பெயருக்கு முன் `--fallback` வைத்தால் ccam அதற்காக மாற்றுகிறது:

```sh
ccam --fallback work -p "fix the failing tests" --output-format json
ccam --fallback -p "summarise" < notes.txt      # the folder's account or the default
ccam run --fallback work -p "review the diff"
```

```console
$ ccam --fallback personal -p "summarise" < notes.txt
ccam: personal reached its usage limit; running the command again as work
Summary: …
```

1. `--fallback` `-p` அல்லது `--print` உடன் மட்டுமே வேலை செய்யும்; இல்லையெனில் ccam நின்று `ccam next --auto --continue`-ஐச் சுட்டிக்காட்டும்.
2. pipe வழியாக வரும் standard input, 10 MiB வரை, ஒருமுறை படிக்கப்பட்டு ஒவ்வொரு முயற்சிக்கும் கொடுக்கப்படுகிறது. Claude Code போலவே, அது தொடங்க ccam அதிகபட்சம் 3 வினாடிகள் காத்திருக்கிறது (`--input-format stream-json` உடன் தவிர); ஒரு pipe திறந்தே இருந்து ஆனால் எதையும் அனுப்பாவிட்டால், இயக்கத்துக்கு உள்ளீடு எதுவும் கிடைக்காது, ccam இதை standard error-இல் குறிப்பிடும்.
3. ccam `exec`-க்குப் பதிலாக `claude`-ஐ child process ஆகத் தொடங்கி, அதன் standard output-ஐ நிறுத்தி வைத்து, standard error-ஐ வரும்போதே கடத்துகிறது.
4. `claude` 0 உடன் வெளியேறினால், அல்லது வேறு காரணத்தால் தோல்வியடைந்தால், நிறுத்தி வைத்த output-உம் exit code-உம் மாற்றமின்றிக் கடத்தப்படுகின்றன. signal மூலம் முடிந்த இயக்கமும் (128-க்கு மேலான exit code) அப்படியே: அது நிறுத்தும்படி கேட்கப்பட்டது, மீண்டும் இயக்கப்படாது.
5. Claude Code-இன் செய்தி அப்படிச் சொன்னால், அதாவது [hook](#inside-claude-code) அறியும் பயன்பாட்டு வரம்புச் செய்திகளில் ஏதேனும் ஒன்று, `--output-format json` அல்லது `stream-json` output-க்குள்ளும், அல்லது கணக்கின் பயன்பாடு அதன் 5 மணி நேர, வாராந்திர அல்லது `--model` கால அளவை 100%-இல் காட்டினால் (வரம்புப் பதிவு உட்பட), தோல்வி பயன்பாட்டு வரம்பாகக் கருதப்படுகிறது.
6. அப்போது அந்த முயற்சியின் output கைவிடப்பட்டு, அதே கட்டளை வேறொரு உள்நுழைந்த கணக்காக இயங்குகிறது: மிகக் குறைந்த 5 மணி நேரப் பயன்பாடு உள்ளது, பிறகு பயன்பாட்டைத் தேட முடியாத கணக்குகள், எண் வரிசையில். 100%-இல் உள்ள கணக்குகள் தவிர்க்கப்படுகின்றன, API key உள்நுழைவு உள்ள கணக்குகள் ஒருபோதும் முயற்சிக்கப்படுவதில்லை, ஒவ்வொரு கணக்கும் அதிகபட்சம் ஒருமுறை முயற்சிக்கப்படுகிறது.
7. arguments-இல் `-c`, `--continue`, `-r` அல்லது `--resume` இருந்தால், உரையாடலைக் கண்டுபிடிக்க முடியும்படி, அதே history குழுவில் உள்ள கணக்குகள் மட்டுமே முயற்சிக்கப்படுகின்றன.
8. `--auto` போலவே, அதே நிறுவனத்தின் கணக்குகள் மட்டுமே முயற்சிக்கப்படுகின்றன (`cross_org = true` இதை நீக்குகிறது).

அடுத்த கணக்கு `--auto`-இன் அதே விதிகளால் தேர்ந்தெடுக்கப்படுகிறது (`auto_max_usage`, `auto_strategy`, `--model` கால அளவு). எந்தக் கணக்கும் மீதம் இல்லாதபோது, ccam கடைசி முயற்சியின் output-ஐ அச்சிட்டு, உள்நுழைந்த எந்தக் கணக்கிலும் இடம் இல்லை என்று சொல்லி, code 75 உடன் வெளியேறுகிறது. கணக்குப் பெயருக்கு முன் `--wait` கொடுத்தால் (`ccam --fallback --wait=2h work -p …`), அதற்குப் பதிலாக முதல் கணக்கு மீட்டமைக்கப்படும் வரை காத்திருந்து, பிறகு எல்லாக் கணக்குகளையும் மீண்டும் முயலக்கூடும்; இப்போதுதான் வரம்பை எட்டிய கணக்கு உடனே மீண்டும் இயங்காதபடி, அது எப்போதும் முதலில் குறைந்தது ஒருமுறை உறங்குகிறது. அந்தக் கால அளவு ஒவ்வொரு காத்திருப்பையும் அல்ல, இயக்கத்தின் மொத்தக் காத்திருப்பு நேரத்தை வரம்பிடுகிறது. இடைவெளியுடன் எழுதினால் (`--wait 30m`), `ccam next`-இன் அதே குறிப்புடன் அது மறுக்கப்படும். Claude Code-இன் arguments-க்கு முன் வரும் `--`, எந்தத் தொடக்கத்திலும் போலவே வேலை செய்யும் (`ccam --fallback work -- -p …`). `ccam --dry-run --fallback work -p …` முதல் முயற்சியின் கட்டளையை அச்சிடுகிறது.

[`auto_switch`](#auto-switch)-ஐ நீங்கள் இயக்காவிட்டால், interactive அமர்வுகள் தாமாக மாறுவதில்லை. `ccam statusline install` உடன், 5 மணி நேர அல்லது வாராந்திரப் பயன்பாடு 90%-ஐ எட்டியதும் நிலை வரி `→ ccam next --auto --continue`-ஐச் சேர்க்கிறது ([பயன்பாட்டு வரம்புகள்](/features/usage)).

## பாதுகாப்பும் விளிம்பு நிலைகளும்

- உள்நுழைவு இல்லாத கணக்குகள் ஒருபோதும் தேர்ந்தெடுக்கப்படாது. உள்நுழைந்த வேறு கணக்கு இல்லையென்றால், வெறும் `ccam next` `no logged-in account other than <name>` என்று நின்றுவிடும்.
- `--continue` கொடுத்து, கோப்புறையில் உரையாடல் எதுவும் இல்லையென்றால்: `no account has a conversation in <folder> to continue`.
- நிறுவன விதி எந்தக் கணக்கையும் விட்டுவைக்காதபோது: `` no logged-in account to pick among <name>'s (<organization>); --cross-org also looks at the others ``.
- `--auto` கொடுத்து, உள்நுழைந்த கணக்கு எதுவும் இல்லையென்றால்: `no logged-in account to pick`. ஒவ்வொரு கணக்கும் நிரம்பியிருந்தால் அல்லது அதன் பயன்பாடு தெரியாவிட்டால்: `` no account with known usage and headroom (see `ccam usage`) ``. இரண்டும் exit code 75 உடன் முடிகின்றன.
- `--max-usage`, `--strategy`, `--wait`, `--cross-org` ஆகியவை `--auto` உடன் மட்டுமே வேலை செய்யும், 1-100-க்கு வெளியே உள்ள மதிப்பும் தெரியாத strategy-உம் மறுக்கப்படும்.
- fork உரையாடலை நகலெடுக்கிறது, கணக்கின் மற்ற நிலையை அல்ல: வரலாறு பகிரப்படாவிட்டால், மூலக் கணக்கின் `file-history/`-இல் உள்ள checkpoints உடன் வருவதில்லை.
- `--dry-run` உடனும் `--auto` network கோரிக்கைகளைச் செய்யும். அது படிக்க மட்டுமே செய்யும், token கோப்புகளை ஒருபோதும் எழுதாது.
- தேர்ந்தெடுக்கப்பட்ட கணக்கு `ccam <name>`-இன் அதே பாதை வழியாகத் தொடங்குகிறது, அதனால் அதே சரிபார்ப்புகள் பொருந்தும், அதே வரலாற்றைப் பகிரும் மற்றொரு Claude Code அமர்வு இந்தக் கோப்புறையில் ஏற்கெனவே இயங்கும்போது வரும் எச்சரிக்கை உட்பட.
- Claude Code உண்மையில் தொடங்கும்போது மட்டுமே `last-used` எழுதப்படும். `--dry-run` அதைத் தொடுவதில்லை, அதனால் dry run சுழற்சியை முன்னோக்கி நகர்த்தாது.
- ஒரு முயற்சி முடியும் வரை `--fallback` standard output-ஐ நிறுத்தி வைக்கிறது, அதனால் `--output-format stream-json` போன்ற streaming output இறுதியில் ஒரே துண்டாக வருகிறது. `stream-json` உள்ளீட்டை stream செய்து, மேலும் அனுப்பும் முன் பதில்களுக்காகக் காத்திருக்கும் client `--fallback`-ஐப் பயன்படுத்த முடியாது. வரம்பை எட்டும் முன் முதல் முயற்சி மாற்றிய கோப்புகள் மாற்றப்பட்டபடியே இருக்கும்; அடுத்த முயற்சி prompt-ஐ மீண்டும் தொடங்குகிறது.
