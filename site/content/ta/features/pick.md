`ccam pick` அதிக இடம் உள்ள உள்நுழைந்த கணக்கின் பெயரை அச்சிடுகிறது, ஒரு script அதைக் கொண்டு Claude Code-ஐத் தொடங்கலாம். இடம் உள்ள கணக்குகள் போதுமான அளவு இருக்கும் வரை, ஒரே நேரத்தில் தொடங்கும் ஒவ்வொரு worker-உம் வெவ்வேறு கணக்கைப் பெறுகிறது, அதனால் `claude -p` jobs தொகுப்பு ஒரே கணக்கைத் தீர்த்துவிடுவதற்குப் பதிலாக உங்கள் கணக்குகளிடையே பரவுகிறது.

**Team மற்றும் Enterprise இருக்கைகள்.** தானியங்கிக் கணக்குத் தேர்வு (`ccam next`, `--fallback`, `ccam pick`, டாஷ்போர்டின் `n`, நீங்கள் இயக்கிய பிறகு [`auto_switch`](/features/next#auto-switch)) ஒரே Claude Team அல்லது Enterprise நிறுவனத்தின் இருக்கைகளுக்கு இடையேயும் மாறுகிறது, இது Anthropic-இன் விதிமுறைகளை மீறக்கூடும். அதை நம்பியிருக்கும் முன், [அடிக்கடி கேட்கப்படும் கேள்விகளைப்](/docs/faq#am-i-allowed-to-use-several-claude-code-accounts) படித்து, உங்கள் நிறுவனத்திடமும் Anthropic-இடமும் கேட்டு உறுதிசெய்துகொள்ளுங்கள்.

## பயன்பாடு

```sh
ccam "$(ccam pick)" -p "fix the failing tests"
for task in parse lint docs; do
  ccam "$(ccam pick)" -p "do the $task task" > "$task.json" &
done; wait
ccam pick --json                      # the account and its usage
ccam pick --model opus                # also count the Opus weekly limit
ccam pick --max-usage 80 --strategy expiring
ccam pick --strategy balance          # most weekly quota left per day; fewer sessions first
ccam pick --cross-org                 # also accounts of other organizations
ccam pick --wait=2h                   # nobody has room: wait for a reset
ccam --fallback "$(ccam pick)" -p "…" # also switch if this account hits its limit mid-job
```

```console
$ ccam pick --json
{
  "name": "work",
  "slot": 2,
  "email": "dev@company.com",
  "five_hour": { "percent": 12, "resets_at": "2026-10-20T15:10:00Z", "known": true },
  "weekly": { "percent": 41, "resets_at": "2026-10-24T09:00:00Z", "known": true },
  "source": "live",
  "reason": "12% of its 5 hours used, the least"
}
```

வெளியேறும் codes: standard output-இல் ஒரு பெயருடன் `0`, எந்தக் கணக்கிலும் இடம் இல்லாதபோது அல்லது எதுவும் உள்நுழையாதபோது `75` (`EX_TEMPFAIL`), தவறான flag போன்ற பிற பிழைகளுக்கு `1`.

## Options

| Option | என்ன செய்யும் | இயல்புநிலை |
| --- | --- | --- |
| `--json` | கணக்கு, அதன் 5 மணி நேர மற்றும் வாராந்திரப் பயன்பாடு, எண்கள் எங்கிருந்து வருகின்றன, அது ஏன் தேர்ந்தெடுக்கப்பட்டது என்பதை அச்சிடும் | off |
| `--model <model>` | அந்த model-இன் வாராந்திரக் கால அளவையும் கணக்கிடும், உதாரணமாக `opus` | none |
| `--max-usage <1-100>` | இந்தப் பயன்பாட்டுக்குக் கீழ் உள்ள கணக்குகளுக்கு முன்னுரிமை தரும் | `auto_max_usage`, இல்லையெனில் 100 |
| `--strategy headroom\|expiring\|balance` | மிகக் குறைந்த 5 மணி நேரப் பயன்பாடு, மிக விரைவான 5 மணி நேர மீட்டமைப்பு, அல்லது ஒரு நாளுக்கு அதிக வாராந்திர quota மீதமுள்ளது | `auto_strategy`, இல்லையெனில் `headroom` |
| `--cross-org` | பிற நிறுவனங்களின் கணக்குகளையும் தேர்ந்தெடுக்கும் | `cross_org`, இல்லையெனில் off |
| `--wait[=<duration>]` | எந்தக் கணக்கிலும் இடம் இல்லாதபோது, முதல் கணக்கு மீட்டமைக்கப்படும் வரை, அதிகபட்சம் இவ்வளவு நேரம் காத்திருக்கும். மதிப்பு `=`-க்குப் பிறகு வர வேண்டும்: `--wait 30m` என்பது `--wait takes its value after '=': --wait=30m` என்ற குறிப்புடன் மறுக்கப்படும் | off; தனியாகக் கொடுத்தால் `5h` |
| `--dry-run` | தேர்வைப் பதிவு செய்யாமல் தேர்ந்தெடுக்கும் | off |

## இது எப்படி வேலை செய்கிறது

1. இந்தக் கோப்புறை தொடங்கும் கணக்கின் நிறுவனத்தில் உள்ள உள்நுழைந்த கணக்குகளை ccam பட்டியலிடுகிறது (API key கணக்குகளுக்கும் Console உள்நுழைவுகளுக்கும் வரம்புகள் இல்லை, அவை விலக்கப்படுகின்றன; [நிறுவனங்கள்](/features/next#auto) பாருங்கள்); அந்தக் கணக்கின் அதே Claude கணக்கில் உள்நுழைந்த கோப்புறையும் விலக்கப்படுகிறது.
2. அது ஒரு lock-ஐ (`~/.local/state/ccam/picks.lock`) எடுக்கிறது, அதனால் ஒரே நேரத்தில் இயங்கும் தேர்வுகள் ஒன்றன்பின் ஒன்றாக நடக்கின்றன.
3. `ccam usage` செய்வது போலவே, 60 வினாடி cache உடன், எல்லாக் கணக்குகளின் பயன்பாட்டையும் ஒரே நேரத்தில் பார்க்கிறது. Claude Code நிரம்பியதாகத் தெரிவித்த கால அளவு அதன் மீட்டமைப்பு வரை 100% ஆகக் கணக்கிடப்படுகிறது ([வரம்புப் பதிவு](/features/usage#the-limit-record)), அதனால் இப்போதுதான் வரம்பை எட்டிய கணக்கு, அதன் சேமித்த எண்கள் இன்னும் இடம் இருப்பதாகக் காட்டினாலும், விலக்கப்படும்.
4. கடைசி 2 நிமிடங்களில் `ccam pick` தேர்ந்தெடுத்த, அல்லது [`auto_switch`](/features/next#auto-switch) ஓர் அமர்வை நகர்த்திய கணக்குகள் (`~/.local/state/ccam/picks/<name>`; எதிர்கால நேர முத்திரை கொண்ட தேர்வு கணக்கில் கொள்ளப்படாது) முதலில் விலக்கப்படுகின்றன, மீதமுள்ளவற்றில் `ccam next --auto`-இன் [தேர்வு விதிகள்](/features/next#auto) தேர்ந்தெடுக்கின்றன: முதலில் `auto_max_usage`-க்குக் கீழ் உள்ளவை, strategy-யின்படி, 100%-இல் உள்ள கணக்கை ஒருபோதும் அல்ல. விதிகள் இல்லையெனில் தேர்ந்தெடுக்கும் கணக்கை இது தவிர்த்தால், `--json`-இன் `reason` அதைச் சொல்கிறது: `30% of its 5 hours used; work was picked a moment ago`.
5. இடம் உள்ள ஒவ்வொரு கணக்கும் சமீபத்தில் தேர்ந்தெடுக்கப்பட்டிருந்தால், விதிகள் மீண்டும் அவை அனைத்திலிருந்தும் தேர்ந்தெடுக்கின்றன, அதனால் மூன்று கணக்குகள் இருக்கும்போது, நான்காவது worker அவற்றில் ஒன்றைப் பகிர்கிறது.
6. தேர்வு பதிவு செய்யப்பட்டு lock விடுவிக்கப்படுகிறது, பிறகு பெயர் அச்சிடப்படுகிறது.

2 நிமிடக் கால அளவு முக்கியம், ஏனெனில் ஒரு புதிய job-இன் பயன்பாடு எண்களில் தெரிய சிறிது நேரம் ஆகும்: அது இல்லாவிட்டால், ஒன்றாகத் தொடங்கும் ஐந்து workers அனைத்தும் ஒரே கணக்கை அதிக இடம் உள்ளதாகப் பார்க்கும்.

## பாதுகாப்பும் விளிம்பு நிலைகளும்

- `ccam pick` பயன்பாட்டைப் படித்து, தேர்வு நேரத்தை மட்டுமே எழுதுகிறது; `ccam usage` செய்வதற்கு மேல் அது ஒருபோதும் tokens-ஐப் புதுப்பிப்பதோ படிப்பதோ இல்லை.
- ஒரு தேர்வு கணக்கை முன்பதிவு செய்வதில்லை. 2 நிமிடங்களுக்குப் பிறகும் இரண்டு scripts ஒரே கணக்கில் தொடங்கக்கூடும்; அந்தக் கணக்கு வரம்பை எட்டும்போது மீள `--fallback`-ஐப் பயன்படுத்துங்கள்.
- `--wait` உடன் காத்திருக்கும்போது எந்த lock-உம் பிடிக்கப்படுவதில்லை, அதனால் இடையில் மற்ற தேர்வுகள் தொடர்கின்றன.
- `ccam pick` [`ccam folder`](/features/folder)-ஐப் புறக்கணிக்கிறது: அது பயன்பாட்டின்படி மட்டுமே தேர்ந்தெடுக்கிறது.
