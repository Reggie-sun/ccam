`ccam doctor` உங்கள் ccam நிறுவலைச் சரிபார்க்கிறது: Claude Code binary, ஒவ்வொரு கணக்கின் கோப்புறை, உள்நுழைவு, பகிர்வு இணைப்புகள், பகிரப்பட்ட MCP சர்வர்கள், usage endpoint, உங்கள் குறுக்குவழிக் கட்டளைகள். `ccam doctor --fix` தரவை இழக்காமல் செய்யக்கூடியவற்றைச் சரிசெய்கிறது, அது மாற்றும் எந்தக் கோப்பையும் முதலில் ஒரு காப்புப்பிரதிக் கோப்புறைக்கு நகர்த்துகிறது. `ccam <name>` பகிர்வு இணைப்புச் சிக்கலுடன் நிற்கும்போது, கோப்புகளைக் கையால் மீட்டெடுத்த பிறகு, அல்லது Claude Code புதுப்பிப்புக்குப் பிறகு இதை இயக்குங்கள்.

## பயன்பாடு

```sh
ccam doctor                  # check everything, change nothing
ccam doctor --fix            # check, then repair what is safe to repair
ccam --dry-run doctor --fix  # report only: what --fix would repair and set aside
```

முதல் வரி எல்லாக் கணக்குகளையும் ஒரே நேரத்தில் குறிக்கிறது, அதனால் வேறு எதையும் படிக்கும் முன்பே சிக்கல்கள் எங்கே உள்ளன என்று பார்க்கலாம். அதன் கீழ், ஒவ்வொரு கணக்குக்கும் ஒரு பெட்டி கிடைக்கிறது, எந்தக் கணக்கையும் சாராத கண்டுபிடிப்புகள் (Claude Code, சூழல் மாறிகள், plugins, MCP servers, shortcuts, கோப்புறை விதிகள், குழுக்கள், அமைப்புகள், `auto_switch`) ஒரு `General` பெட்டியில் செல்கின்றன. பெட்டியின் தலைப்பு கணக்கின் மோசமான குறியையும் அதற்கு எத்தனை சிக்கல்கள் உள்ளன என்பதையும் காட்டுகிறது. உள்ளே உள்ள ஒவ்வொரு வரிசையும் சரிபார்க்கப்பட்ட ஒரு பகுதி, எப்போதும் `Folder`, `Login`, `Share links` இந்த வரிசையில், பிறகு மற்றவை, ஒரு குறியுடன்: `✔` சரி, `ℹ` தகவல், `⚠` எச்சரிக்கை, `✘` பிழை. எந்தச் சிக்கலும் இல்லாத கோப்புறை `✔ Folder  OK` எனக் காட்டும்.

டெர்மினலில், பெட்டிகள் டெர்மினலின் அகலத்துக்குப் பொருந்துகின்றன, நீண்ட செய்திகள் அடுத்த வரிக்குச் செல்கின்றன, டெர்மினலின் சொந்த நிறங்கள் பயன்படுத்தப்படுகின்றன (`NO_COLOR` அவற்றை அணைக்கிறது). ஒரு பெட்டி ஒருபோதும் 29 நெடுவரிசைகளை விடக் குறுகியதாக இருக்காது, அதனால் குறுகிய டெர்மினலில் எந்தச் சொல்லும் வெட்டப்படாது. pipe அல்லது கோப்புக்கு அனுப்பப்படும்போது, வெளியீட்டில் நிறங்கள் இருக்காது, எந்தச் செய்தியும் மடிக்கப்படவோ வெட்டப்படவோ இல்லை, அதனால் `ccam doctor | grep settings.json` முழு வரியையும் கண்டுபிடிக்கும்; அப்போது ஒவ்வொரு பெட்டியும் மிக நீண்ட வரியின் அகலத்தில் இருக்கும். டாஷ்போர்டின் Health tab அதே பெட்டிகளைக் காட்டுகிறது.

## Options

| Option | என்ன செய்யும் | இயல்புநிலை |
| --- | --- | --- |
| `--fix` | பாதுகாப்பாகப் பழுதுநீக்கக்கூடியவற்றைச் சரிசெய்யும் (மாற்றப்பட்ட கோப்புகள் காப்புப்பிரதி எடுக்கப்படும்) | off |
| `--dry-run` (global) | ஒவ்வொரு சரிபார்ப்பையும் இயக்கும், ஆனால் `--fix` உடனும் எதையும் சரிசெய்யாது | off |

`ccam doctor` எந்த argument-ஐயும் ஏற்காது. அது `--dry-run`-ஐ ஆதரிக்கும்: `ccam --dry-run doctor --fix` `ccam doctor`-இன் கண்டுபிடிப்புகளை அச்சிட்டு, `--fix` எவற்றை ஒதுக்கி வைக்கும் என்பதையும் சேர்த்து, எதையும் மாற்றாது:

```text
ℹ settings.json differs from the group's copy: --fix would use the group's, and move this account's copy to /home/me/.local/share/ccam/profiles/personal/.ccam-backup/20261023-212543/settings.json
```

குறைந்தது ஒரு `✘` கண்டுபிடிப்பு சரிசெய்யப்படாமல் இருந்தால் exit code `1`, இல்லையென்றால் `0`. எச்சரிக்கைகளும் தகவல்களும் ஒருபோதும் இயக்கத்தைத் தோல்வியடையச் செய்யாது. `--fix` இல்லாமல் இயக்கம் தோல்வியடைந்தால், ccam ஒரு வெற்று வரியுடனும் `` `ccam doctor --fix` repairs what it can. `` உடனும் முடியும். ஏற்ற முடியாத config-உம் `1` மற்றும் ஒரு `ccam:` பிழையுடன் முடியும்.

## இது எப்படி வேலை செய்கிறது

சரிபார்ப்புகள் ஒரு நிலையான வரிசையில் இயங்குகின்றன, கண்டுபிடிப்புகள் ஒவ்வொரு கணக்குக்கும் ஒரு பெட்டியில் தோன்றுகின்றன. ccam `~/.config/ccam/config.toml`-ஐ ஏற்றி (`internal/cli/doctor.go`) சரிபார்ப்புகளை இயக்குகிறது; ஒவ்வொரு கண்டுபிடிப்பும் அது சேர்ந்த கணக்கையும் அது சரிபார்த்த பகுதியையும் பெயரிடுகிறது (`internal/doctor/doctor.go`-இல் `doctor.Run`). பிறகு அது கண்டுபிடிப்புகளைப் பெட்டிகளாகத் தொகுக்கிறது (`tui.HealthReport`). `--fix` `Options.Fix` ஆக அனுப்பப்படுகிறது, dry run-இல் அது false ஆக அமைக்கப்படும்.

<!-- motion:doctor-checks -->

நடுப் பகுதி ஒவ்வொரு கணக்குக்கும் ஒருமுறை இயங்கும். சரிபார்ப்புகளும், ஒவ்வொன்றுக்கும் `--fix` என்ன செய்கிறது என்பதும்:

1. **Claude Code பதிப்பு** (`checkClaude`). launcher செய்வது போலவே `claude` binary-ஐக் கண்டறிந்து `claude --version`-ஐ இயக்குகிறது. binary இல்லாமை, இயக்கக்கூடிய கோப்பாக இல்லாத `claude_bin`, தோல்வியடையும் `--version` ஆகியவை பிழைகள். சரிசெய்தல் இல்லை.
2. **சூழலில் உள்ள credentials** (`checkAuthEnv`). `CLAUDE_CODE_OAUTH_TOKEN`, `ANTHROPIC_API_KEY` அல்லது `ANTHROPIC_AUTH_TOKEN` அமைக்கப்பட்டிருந்தால் எச்சரிக்கிறது: அந்த shell-இலிருந்து தொடங்கும் ஒவ்வொரு கணக்கும் அதைப் பெறும், Claude Code கணக்கின் சொந்த உள்நுழைவை விட அதற்கு முன்னுரிமை கொடுக்கும். சரிசெய்தல் இல்லை; அதை நீங்களே நீக்குங்கள்.
3. **கோப்புறை** (`checkProfile`). கணக்குக் கோப்புறை இல்லாதது பிழை, அந்தக் கணக்கின் சரிபார்ப்புகள் அங்கேயே முடியும். group அல்லது other bits ஏதேனும் அமைக்கப்பட்ட அனுமதிகள் எச்சரிக்கை; `--fix` `chmod 0700`-ஐ இயக்கும். `~/.claude.json`-க்கு அருகில் தனக்கெனச் சொந்தமாக ஒரு `.claude.json` கொண்ட, இறக்குமதி செய்யப்பட்ட `~/.claude` தகவல்: அப்போது `ccam main`-உம் வெறும் `claude`-உம் தனித்தனி உள்நுழைவு விவரங்களையும் MCP சர்வர்களையும் வைத்திருக்கும். Windows-இல் permission bits இல்லை, அதனால் அங்கே இந்தச் சரிபார்ப்பும் கீழே உள்ள `0600` சரிபார்ப்பும் தவிர்க்கப்படுகின்றன; உங்கள் பயனர் சுயவிவரத்தில் உள்ள கோப்புறை அதன் access list மூலம் பாதுகாக்கப்படுகிறது.
4. **உள்நுழைவுக் கோப்பு** (`checkCredentials`). `.credentials.json` `lstat` மூலம் சரிபார்க்கப்படுகிறது. ஒவ்வொரு கணக்குக்கும் சொந்த token இருக்க வேண்டும் என்பதால், symlink பிழை, அது சரிசெய்யப்படாது. `0600` அல்லாத mode எச்சரிக்கை; `--fix` `chmod 0600`-ஐ இயக்கும்.

   பிறகு உள்நுழைவு படிக்கப்படுகிறது (macOS-இல் முதலில் Keychain-இலிருந்து). உள்நுழைவு இல்லாததும், உள்ளே உள்நுழைவு எதுவும் இல்லாத உள்நுழைவுக் கோப்பும் `ccam login <name>`-ஐச் சுட்டும் எச்சரிக்கை. காலாவதியான refresh token, அல்லது சர்வர் மறுத்த பிறகு Claude Code அழித்த உள்நுழைவு, `` login expired → `ccam login <name>` `` பிழை; காலாவதியான access token வெறும் தகவல் மட்டுமே, ஏனெனில் அடுத்த தொடக்கத்தில் Claude Code அதைப் புதுப்பிக்கும். Windows Credential Manager-இல் வைக்கப்பட்ட உள்நுழைவு தகவல், ஏனெனில் ccam-ஆல் அதைப் படிக்க முடியாது. செல்லுபடியாகும் உள்நுழைவு, கோப்புறை இப்போது உள்நுழைந்துள்ள மின்னஞ்சலையும் plan-ஐயும் காட்டும் (`login valid (dev@company.com, Claude Team · Acme)`). இவற்றில் எதுவும் சரிசெய்யப்படாது; `ccam login --expired` தேவைப்படும் ஒவ்வொரு கணக்கிலும் உள்நுழைகிறது.
5. **பகிர்வு இணைப்புகள்** (`share.Check`). `share.Layout`-இல் உள்ள ஒவ்வொரு பாதையையும் கணக்கின் குழுக்களுடன், `lstat` மற்றும் `readlink`-ஐ மட்டும் பயன்படுத்தி ஒப்பிடுகிறது. அது ஐந்து வகைகளைத் தெரிவிக்கிறது: இல்லாத இணைப்பு, வேறிடத்தைச் சுட்டும் இணைப்பு, இணைப்பு இருக்க வேண்டிய இடத்தில் உண்மையான கோப்பு, இப்போது local ஆக உள்ள உருப்படிக்கு மீதமிருக்கும் இணைப்பு, குழுக் கோப்புறை இல்லாத சரியான இணைப்பு (`the group folder it links to is missing (…), so Claude Code cannot save there (ccam doctor --fix makes it)`; தொடக்கம் இதைச் சரிபார்ப்பதில்லை). இல்லாத இணைப்பும் இல்லாத குழுக் கோப்புறையும் எச்சரிக்கைகள், மற்றவை பிழைகள்.

   குழுவிலிருந்து திரும்ப நகலெடுப்பது பாதியில் நின்றிருந்தால் அதுவும் தெரிவிக்கப்படும்: `--fix` தயார்செய்யப்பட்ட முழு நகலை அதன் இடத்தில் வைக்கிறது, ஆனால் அதன் பிறகு ஒரு தொடக்கம் பாதையை மீண்டும் உருவாக்கியிருந்தால், நீங்களே தீர்த்துக்கொள்ளும்படி, முழு நகல் உள்ள கோப்புறையை அது பெயரிடுகிறது. ccam-இன் பிந்தைய பதிப்பில் ஓர் உருப்படியில் சேர்க்கப்பட்ட பாதைகள் (வரலாற்றுக்கு `file-history/`, `tasks/`, `paste-cache/`, அமைப்புகளுக்கு `keybindings.json`), கணக்கிடம் இன்னும் அதன் சொந்த நகல் இருக்கும் வரை எச்சரிக்கை மட்டுமே: `is not shared with the group yet (ccam doctor --fix shares it; if the group has its own copy, that one is kept and this one backed up)`. அவற்றுக்காகத் தொடக்கம் ஒருபோதும் நிற்காது.
6. **தெரியாத உள்ளீடுகள்** (`checkUnknownEntries`). Claude Code அமைப்பு மாறியிருக்கலாம் என்பதற்கான குறிப்பாக, கணக்குக் கோப்புறையில் ccam-க்குத் தெரியாத (`share.Known`) மேல்நிலைப் பெயர்களைப் பட்டியலிடுகிறது. தகவல் மட்டுமே.
7. **Plugin பாதைகள்** (`checkPlugins`). Plugin registries (`installed_plugins.json`, `known_marketplaces.json`) absolute பாதைகளைச் சேமிக்கின்றன. ஒவ்வொரு குழுவின் `plugins/`-இலும், ஒரு கணக்கின் கோப்புறை வழியாகச் செல்லும் பாதைகள் அந்தக் கணக்கு நீக்கப்படும்போதோ பெயர் மாற்றப்படும்போதோ உடைந்துவிடும். `--fix` அவற்றை `profile.RewritePluginPaths` மூலம் குழுக் கோப்புறைக்கு மாற்றி எழுதுகிறது; இது registry கோப்பின் atomic எழுதுதல்.
8. **MCP சர்வர்கள்** (`checkMCP`). ஒவ்வொரு குழுவின் `mcp.json`-ஐயும் ஒருமுறை ஏற்றுகிறது. படிக்க முடியாத கோப்பு பிழை; `mcp.Validate`-இல் தோல்வியடையும் சர்வர் எச்சரிக்கை. வெறும் `claude`-இன் `~/.claude.json`-இல் உள்ள, எந்தக் கணக்கும் ஏற்றாத சர்வர்கள் எச்சரிக்கை, அவற்றை நகலெடுக்கும் `ccam migrate --mcp` கட்டளையுடன் (பல குழுக்கள் MCP-ஐப் பகிரும்போது `--group <a|b>` உடன்). ஒரு குழுவின் ஒரே ஒரு கணக்கிடம் மட்டும் உள்ள சர்வர்கள், அவற்றைப் பகிரும் `ccam mcp import` கட்டளையுடன் தகவல்; மற்ற கணக்குகள் உள்நுழைந்துள்ள MCP சர்வர்களில் உள்நுழையாத கணக்குக்கு `/mcp` மூலம் உள்நுழையச் சொல்லும் எச்சரிக்கை கிடைக்கும் (ccam ஒருபோதும் உள்நுழைவுகளை நகலெடுப்பதில்லை). சரிசெய்தல் இல்லை.
9. **Usage பதில் வடிவம்** (`checkUsageFormat`). cache இல்லாமல், மொத்தமாக ஒரே 4 வினாடி timeout-க்குள், ஒரு கணக்கு பதில் அளிக்கும் வரை ஒன்றன்பின் ஒன்றாக usage endpoint-இடம் கேட்கிறது. `usage_source = "claude"` உடன், அதற்குப் பதிலாக அது ஒரு கணக்குக்காக Claude Code-இடம் கேட்கிறது. பதில் இனி parse ஆகவில்லை என்றால், `ccam usage` நிலை வரி cache-க்குத் திரும்பும் என்று எச்சரிக்கிறது; எந்தக் கணக்கும் பதில் அளிக்காதபோது, அதைத் தகவலாகச் சொல்கிறது (`could not check the usage response format: …`). network-ஐப் பயன்படுத்தும் ஒரே சரிபார்ப்பு இதுதான்.
10. **குறுக்குவழிகள்** (`checkShims`). ஏதாவது ஒரு கணக்குக்குக் குறுக்குவழி இருந்தால் மட்டுமே. `~/.local/bin`-இல் இல்லாத இணைப்புகள் எச்சரிக்கை; மாற்றப்பட்ட அல்லது நகர்த்தப்பட்ட ccam-இன் பழைய பதிப்பை இன்னும் இயக்கும், ccam உருவாக்கிய குறுக்குவழிகளும் எச்சரிக்கை (`shortcuts in <bin> that run another ccam (one replaced or moved): …`); `--fix` `shim.Install`-ஐ அழைக்கிறது, அது ccam உருவாக்கி `~/.local/state/ccam/shortcuts.json`-இல் பதிவு செய்த இணைப்புகளை மட்டுமே உருவாக்கவும் புதுப்பிக்கவும் செய்யும், மற்ற கோப்புகளை ஒருபோதும் தொடாது. அந்த இணைப்புகள் ஒவ்வொன்றும் உருவாக்கப்பட்டால் மட்டுமே எச்சரிக்கை `→ fixed` என்று முடியும்; ஒன்றை உருவாக்க முடியாவிட்டால், காரணம் சேர்க்கப்படும். இன்னும் நிறுவப்பட்டுள்ள வேறொரு ccam-ஐ இயக்கும் குறுக்குவழி வேலை செய்யும், அதனால் `ccam doctor` அதைத் தகவலாக மட்டுமே பட்டியலிடுகிறது; `--fix` அதை இந்த ccam binary-க்குச் சுட்ட வைக்கிறது. `PATH`-இல் இல்லாத bin கோப்புறை எச்சரிக்கை, அது சரிசெய்யப்படாது.
11. **கோப்புறைகள்** (`checkFolders`). [`ccam folder`](/features/folder) பதிவுகள் இருந்தால் மட்டுமே. கணக்கு இல்லாத பதிவு பிழை, கோப்புறை இல்லாமல் போன பதிவு எச்சரிக்கை. இரண்டும் சரிசெய்யப்படுவதில்லை, ஏனெனில் ஒரு பதிவை நீக்கினால் அங்கே எந்தக் கணக்கு தொடங்குகிறது என்பது மாறிவிடும்.
12. **குழுக்களும் அமைப்புகளும்** (`checkGroups`). கணக்கு அல்லாத குழு உறுப்பினர், பெயர் பின்னர் ஒரு ccam கட்டளையாகிவிட்ட கணக்கு (அதை `ccam run <name>` மூலம் தொடங்குங்கள் அல்லது மறுபெயரிடுங்கள்), தெரியாத `theme` அல்லது `usage_source`, ccam படிக்காத `config.toml` வரிகள் ஆகியவை எச்சரிக்கைகள். கடைசி வகை பொதுவாக ஒரு `[[group]]`, `[[profile]]` அல்லது `[[folder]]` table-க்குக் கீழே வைக்கப்பட்ட அமைப்பு, அது அதை அந்த table-இன் பகுதியாக்கிவிடுகிறது (`config.toml line 43: relay is read as part of the [profile.login] table above it; settings for all accounts go above the first [[group]], [[profile]] or [[folder]]`); அது சரிசெய்யப்படும் வரை config-ஐ மாற்றும் கட்டளைகள் மறுக்கும். சரிசெய்தல் இல்லை.
13. **உள்நுழைவுகள்** (`checkIdentities`). ஒவ்வொரு கோப்புறையும் யாராக உள்நுழைந்துள்ளது என்பதை அதன் `.claude.json`-இலிருந்து படிக்கிறது. `ccam login` பதிவு செய்த கணக்கைத் தவிர வேறொரு கணக்கில் இப்போது உள்நுழைந்துள்ள கோப்புறை (எடுத்துக்காட்டாக ஓர் அமர்வுக்குள் `/login`-க்குப் பிறகு) எச்சரிக்கை; உள்நுழைவுப் பதிவு இல்லாத கணக்கு, எடுத்துக்காட்டாக இறக்குமதி செய்யப்பட்டது அல்லது ccam-இன் பழைய பதிப்பு உருவாக்கியது, அதன் பதிவு செய்யப்பட்ட மின்னஞ்சலுடன் ஒப்பிடப்படுகிறது. வேறொரு கோப்புறையின் அதே Claude கணக்கில் உள்நுழைந்துள்ள கோப்புறையும் எச்சரிக்கை: அந்த இரண்டும் தங்கள் பயன்பாட்டு வரம்புகளைப் பகிர்ந்துகொள்கின்றன. வேறொரு கோப்புறையின் அதே login token-ஐ வைத்திருக்கும் கோப்புறை, அதாவது நகலெடுக்கப்பட்ட கோப்புறை (வெறும் `claude`-இன் `~/.claude` உட்பட), பிழை, ஏனெனில் எது முதலில் புதுப்பிக்கிறதோ அது மற்றதை வெளியேற்றிவிடும்; அதற்குச் சொந்த உள்நுழைவைக் கொடுக்க `ccam login <name>` இயக்குங்கள். சரிசெய்தல் இல்லை.
14. **`auto_switch`** (`checkAutoSwitch`). `auto_switch = true` இருக்கும்போது மட்டும். `General` பெட்டியில் உள்ள தகவல், `auto_switch` என்ன செய்கிறது என்று சொல்லி, [அதன் விளக்கத்துக்கு](/features/next#auto-switch) இணைப்பு தருகிறது. கணக்குகளில் இருக்கைகள் உள்ள ஒவ்வொரு plan-க்கும் (Claude Team, Claude Enterprise), ஒரு வரி அவற்றைப் பெயரிட்டு, `auto_switch` ஒரே நிறுவனத்தின் இருக்கைகளுக்கு இடையே அமர்வை நகர்த்துகிறது என்று சொல்லி, Anthropic-இன் இருக்கை விதியை உதவி மையத்தின் இணைப்புடன் மேற்கோள் காட்டி, முடிவை உங்களிடம் விடுகிறது. hooks-க்குத் தங்கள் process-ஐச் (`CLAUDE_PID`) சொல்லாத, 2.1.214-ஐ விடப் பழைய Claude Code பதிப்புகள் அங்கே எச்சரிக்கை, ஏனெனில் எந்த அமர்வையும் நகர்த்த முடியாது.

    ccam plugin இல்லாத, அல்லது plugin அணைக்கப்பட்ட கணக்குக்கு, Claude Code-இல் அதைச் சரிசெய்யும் கட்டளையுடன் அதன் சொந்தப் பெட்டியில் எச்சரிக்கை கிடைக்கிறது: `auto_switch is on, but work does not have the ccam plugin, so its sessions are not moved. In Claude Code as work: /plugin install ccam --marketplace jhyunwoo/ccam` (அல்லது `/plugin enable ccam@ccam`). API key கணக்குகள் விலக்கப்படுகின்றன. Windows-இல் ஒரே வரி `auto_switch is ignored on Windows; with relay = true, /ccam:switch followed by /exit still moves a conversation to another account.` சரிசெய்தல் இல்லை.

கணக்குகளுக்கு முன், பாதியில் நின்ற **குழு மாற்றம்** `General` பெட்டியில் ஒரு பிழை: ``the last group change stopped halfway (ccam doctor --fix finishes it; noted in ~/.local/state/ccam/group-change.json)``. `--fix` அதைத் திட்டமிட்ட வரிசையிலேயே, அதன் முரண்பாடுகளுக்குக் கொடுத்த பதில்களுடன் முடிக்கிறது; அதுவரை வேறு எந்தக் குழு மாற்றமும், மறுபெயரிடுதலும், நீக்கமும் தொடங்காது. அது முடியும் வரை, அதில் உள்ள கணக்குகளுக்கு ccam இல்லாத இணைப்புகளை மட்டுமே உருவாக்கும். அதை முடிக்க முடியாவிட்டால், அந்தக் கோப்பை நீக்குவது மாற்றத்தின் மீதியைக் கைவிடும் என்று பிழை சொல்கிறது.

`ccam --dry-run doctor --fix` வரிசையையும் (`--fix finishes it in its order (b, a, c), with the answers given to its conflicts`), ஒவ்வொரு கணக்கின் பங்கும் எதை ஒதுக்கி வைக்கும் என்பதையும் காட்டுகிறது. மற்றொரு ccam process இப்போது செய்துகொண்டிருக்கும் குழு மாற்றம் தகவல்; அது நடந்துகொண்டிருக்கும்போது `--fix` எந்தப் பகிர்வு இணைப்புகளையும் சரிசெய்வதில்லை (`its share links are not repaired while another ccam changes the groups; …`). பழுதுநீக்கும்போது `--fix` `~/.local/state/ccam/group-change.lock`-ஐப் பிடித்து வைத்திருக்கிறது, ஒரு மாற்றத்தை முடித்த பிறகு `config.toml`-ஐ மீண்டும் படிக்கிறது.

### பகிர்வு இணைப்புகளைச் சரிசெய்தல்

தொடக்கப் பாதை இல்லாத இணைப்பை அந்த இடத்திலேயே உருவாக்குகிறது, ஆனால் தரவை இழக்கக்கூடிய எதற்கும் நின்று இங்கே சுட்டிக்காட்டுகிறது:

```console
$ ccam work
ccam: stopped because of share link problems:
  /home/me/.local/share/ccam/profiles/work/CLAUDE.md: set to shared but is a real file, not a link
Repair them with `ccam doctor --fix`, then run again
```

எந்தப் பகிர்வு இணைப்புச் சிக்கலுக்கும், `--fix` கணக்கின் பகிர்வு அமைப்புகளைத் தற்போதைய நிலையாகவும் இலக்கு நிலையாகவும் கொடுத்து `share.Build`-ஐ அழைக்கிறது, பிறகு `Plan.Apply`-ஐ. ccam வட்டில் உள்ளதிலிருந்து ஒவ்வொரு படியையும் மீண்டும் பெறுகிறது (`Build`), இது ஒரு `ccam group` மாற்றம் பயன்படுத்தும் அதே திட்டத்தைத் தருகிறது, அதனால் பழுதுநீக்கம் ஒரு குழுவில் சேர்வதற்கான அதே விதிகளைப் பின்பற்றுகிறது.

<!-- motion:doctor-repair -->

இங்கே `settings.json` ஓர் உண்மையான கோப்பு. குழுவிடம் ஏற்கெனவே வேறுபட்ட `settings.json` இருப்பதால், முரண்பாடு அதன் இயல்புநிலைத் தேர்வான `keep group`-ஐ (வரைபடத்தில் `KeepGroup`) எடுக்கிறது, அதனால் குழுவின் நகல் அப்படியே இருக்கிறது. கணக்கின் கோப்பு கணக்குக் கோப்புறைக்குள் `.ccam-backup/<time>/settings.json`-க்கு நகர்கிறது, ccam பாதையைக் குழுவுடன் இணைக்கிறது (`os.Symlink`). `--fix` அதைச் சொல்கிறது: `settings.json differed from the group's copy, which it now uses; this account's copy is in …`. மற்ற நிலைகள்:

- குழுவிடம் இன்னும் நகல் இல்லையென்றால், கணக்கின் கோப்பு குழுவுக்குள் நகர்ந்து அதன் முதல் உள்ளடக்கமாகிறது.
- கோப்புறைக்கு, குழுவிடம் இல்லாத கோப்புகள் குழுவுக்குள் நகரும். குழுவின் நகலுக்கு ஒத்த கோப்புகள் நீக்கப்படும், வேறுபடுபவை காப்புப்பிரதிக்குச் சென்று ஒரு குறிப்பில் பெயரிடப்படும் (`projects: 1 file differs from the group's copy (-w/memory/MEMORY.md); the group's is kept, the account's stays in …`).
- இல்லாத குழுக் கோப்புறை முதலில் உருவாக்கப்படும்.
- `history.jsonl`-க்கு, இயல்புநிலை `merge by line`: குழுவின் வரிகள், பிறகு உங்கள் புதிய வரிகள். குழுவின் முந்தைய நகல் `.ccam-backup/<time>/group/`-இல் சேமிக்கப்படும்.
- மற்றொரு குழுவுக்கான இணைப்பு மாற்றப்படும். ccam-க்கு வெளியே உள்ள கோப்புறைக்கான இணைப்பு காப்புப்பிரதிக்குச் செல்லும், குழு காலியாக இருந்தால் அதன் உள்ளடக்கம் குழுவின் தொடக்க உள்ளடக்கமாகும்.
- இப்போது local ஆக உள்ள உருப்படிக்காக மீதமிருக்கும் இணைப்பு நீக்கப்படும், கணக்குக்குக் குழுவின் உள்ளடக்கத்தின் நகல் கிடைக்கும்.

இணைப்புகளை நீக்குவதையும், குழுவின் நகலுக்கு ஒத்த கோப்புகளை நீக்குவதையும் தவிர, ஒவ்வொரு படியும் தரவைக் குழுவுக்குள்ளோ காப்புப்பிரதிக் கோப்புறைக்குள்ளோ நகர்த்துகிறது. எதுவும் இழக்கப்படுவதில்லை.

## பாதுகாப்பும் விளிம்பு நிலைகளும்

- வெறும் `ccam doctor` ஒருபோதும் எதையும் மாற்றுவதில்லை. scripts-இல் உறுதியாக இருக்க `--fix` உடன் `--dry-run` பயன்படுத்துங்கள்.
- இயங்கும் ஒரு கணக்குக்கு, Claude Code எப்படித் தொடங்கப்பட்டிருந்தாலும், `doctor --fix` இல்லாத இணைப்புகளையும் இல்லாத குழுக் கோப்புறைகளையும் மட்டுமே உருவாக்குகிறது, அதனால் எதுவும் இழக்கப்படாது. வேறு ஏதாவது மீதமிருந்தால், `` is running; quit Claude Code there, then run `ccam doctor --fix` again to repair the rest `` என்பதைச் சேர்க்கிறது, ஏனெனில் சரிசெய்தல் நகர்த்தும் கோப்புகளில் அமர்வு தொடர்ந்து எழுதுகிறது.
- பகிர்வுப் பழுதுநீக்கம் தோல்வியடைந்தால், ccam அந்தக் கணக்குக்கு `could not repair share links: <error>` என்று தெரிவித்து, அதன் தெரியாத உள்ளீட்டுச் சரிபார்ப்பைத் தவிர்க்கும். மற்ற கணக்குகள் தொடர்ந்து சரிபார்க்கப்படும்.
- ஒரு `ccam group` மாற்றம் பாதியில் தோல்வியடைந்தால், புதிய குழுக்கள் ஏற்கெனவே சேமிக்கப்பட்டிருக்கும், மாற்றம் `~/.local/state/ccam/group-change.json`-இல் குறிக்கப்படும்; `ccam doctor --fix` மூலம் முடிக்க ccam சொல்லும், அது MCP படிகள் உட்பட மீதியைச் செய்து முடிக்கும்.
- symlink ஆன `.credentials.json`, காலாவதியான உள்நுழைவு, சூழல் credentials ஆகியவை தெரிவிக்கப்படும், ஆனால் ஒருபோதும் மாற்றப்படாது.
- Plugin registry மாற்றங்கள் atomic ஆக எழுதப்படும், ஆனால் `.ccam-backup/`-க்கு நகலெடுக்கப்படாது.
