`ccam work rc` Claude Code-இன் Remote Control-ஐ `work` கணக்காகத் தொடங்குகிறது, அதனால் இந்தக் கணினியில் உள்ள அமர்வுகளை claude.ai/code அல்லது Claude மொபைல் செயலியிலிருந்து கட்டுப்படுத்தலாம். இது `claude rc` போலவே வேலை செய்கிறது, ஒரே ஒரு வேறுபாட்டுடன்: கணக்கு MCP சர்வர்களைப் பகிர்ந்தால், அவற்றைக் கணக்கின் `.claude.json`-க்குள் நகலெடுக்கவா என்று ccam ஒருமுறை கேட்கும், ஏனெனில் Remote Control அமர்வுகள் சர்வர்களைப் படிக்கும் ஒரே இடம் அந்தக் கோப்புதான்.

## தொடங்குதல்

```sh
ccam work rc                          # Remote Control as the account work
ccam 2 rc                             # the account with number 2 (see ccam list)
ccam work remote-control              # the long name of the same command
ccam work rc --name laptop            # options after rc go to Remote Control
ccam work rc --spawn worktree         # each new session in its own git worktree
ccam --dry-run work rc                # print the command instead of running it
```

ஒரு [குறுக்குவழி](/features/shortcuts)-யும் இதே போல் வேலை செய்யும்: `ccwork rc` என்பது `ccam work rc`. நீங்கள் வேலை செய்ய விரும்பும் கோப்புறையில் கட்டளையை இயக்குங்கள், பிறகு `work` பயன்படுத்தும் அதே Claude கணக்கில் உள்நுழைந்த claude.ai/code அல்லது Claude செயலியைத் திறங்கள்.

## Options

இங்கே இரண்டு வகை options சந்திக்கின்றன: ccam-இன் சொந்த options, இவை கணக்கின் பெயருக்கு முன் வரும் அல்லது ccam-இன் அமைப்புகளில் இருக்கும்; Remote Control-இன் options, இவை `rc`-க்குப் பின் வந்து மாற்றமின்றி Claude Code-ஐச் சென்றடையும்.

### ccam options-உம் அமைப்புகளும்

| Option அல்லது அமைப்பு | என்ன செய்யும் | இயல்புநிலை |
| --- | --- | --- |
| `--dry-run` (கணக்குக்கு முன்) | சூழலையும் கட்டளையையும், MCP அறிவிப்பு இருந்தால் அதையும் அச்சிடும். கேட்கவும் செய்யாது, நகலெடுக்கவும் செய்யாது | off |
| `~/.config/ccam/config.toml`-இன் மேற்பகுதியில் `mcp_strategy = "sync"` | Remote Control ஆக இருந்தாலும் இல்லாவிட்டாலும், ஒவ்வொரு தொடக்கத்துக்கு முன்பும் குழுவின் சர்வர்களை `.claude.json`-க்குள் நகலெடுக்கும், அதனால் எதுவும் ஒருபோதும் கேட்கப்படாது | `"flag"` |
| `ccam group leave <group> work` | கணக்குடன் MCP-ஐப் பகிரும் குழுவிலிருந்து கணக்கை வெளியே எடுக்கும். குழுவின் சர்வர்கள் அதன் சொந்தச் சர்வர்களாக அதன் `.claude.json`-க்குள் நகலெடுக்கப்படுகின்றன, அதனால் Remote Control-க்கு அவை கிடைக்கும், எதுவும் கேட்கப்படாது; `--fresh` உடன் அது கணக்கின் சொந்தச் சர்வர்களுடன் மட்டும் தொடங்கும் | `default`-இல் |

கணக்கு MCP சர்வர்களைப் பகிர்ந்து, அதன் `.claude.json`-இல் குழுவின் தற்போதைய பட்டியல் இல்லாதபோது, அல்லது நகலெடுத்த சர்வர் அதிலிருந்து காணாமல் போனபோது, ccam `Copy them into .claude.json (a backup is kept; the account's own servers stay)? [y/N]` என்று கேட்கும். `y` அவற்றை நகலெடுக்கும்; `N` அல்லது Enter அவை இல்லாமல் தொடங்கும்.

### Remote Control options

`rc`-க்குப் பின் உள்ள அனைத்தும் Claude Code-க்குச் சொந்தமானவை. இவை Claude Code 2.1.304-இல் உள்ள `claude remote-control`-இன் options; உங்கள் பதிப்புக்கான பட்டியலை `ccam work rc --help` அச்சிடும்.

| Option | என்ன செய்யும் |
| --- | --- |
| `--name <name>` | claude.ai/code-இல் காட்டப்படும் அமர்வின் பெயர் |
| `--remote-control-session-name-prefix <prefix>` | தானாக உருவாகும் அமர்வுப் பெயர்களுக்கான முன்னொட்டு (இயல்புநிலை: host பெயர்) |
| `-c`, `--continue` | இந்தக் கோப்புறைக்கு Remote Control கடைசியாகப் பதிவுசெய்த அமர்வுடன், சுமார் 4 மணி நேரத்துக்குள், மீண்டும் இணையும் |
| `--session-id <id>` | குறிப்பிட்ட அமர்வுடன் மீண்டும் இணையும் |
| `--permission-mode <mode>` | புதிய அமர்வுகளுக்கான அனுமதி முறை: `acceptEdits`, `auto`, `bypassPermissions`, `default`, `dontAsk` அல்லது `plan` |
| `--spawn <mode>` | `same-dir` (இயல்புநிலை), `worktree` (ஒவ்வொரு அமர்வுக்கும் ஒரு git worktree) அல்லது `session` (ஒரே அமர்வு, அது முடிந்ததும் வெளியேறும்) |
| `--capacity <N>` | `same-dir`, `worktree` முறைகளில் ஒரே நேரத்தில் இயங்கும் அமர்வுகளின் அதிகபட்ச எண்ணிக்கை (இயல்புநிலை 32) |
| `--[no-]create-session-in-dir` | தொடக்கத்திலேயே தற்போதைய கோப்புறையில் முதல் அமர்வை உருவாக்கும் (இயல்புநிலை on) |
| `--[no-]chrome` | புதிய அமர்வுகளுக்கு Claude in Chrome (இயல்புநிலை off) |
| `-d`, `--debug`, `--debug-file <path>`, `-v`, `--verbose` | debug மற்றும் விரிவான வெளியீடு |

Claude Code செய்வது போலவே, options-ஐ அவற்றின் மதிப்புகளுடன் சேர்த்துத் தவிர்த்து, ccam Claude Code-இன் கட்டளையைப் படிக்கிறது, அதனால் `ccam work rc --name laptop`, `ccam work --model opus rc` இரண்டும் Remote Control-ஐத் தொடங்கும். ccam-க்குத் தெரியாத option மதிப்பு இல்லாத ஒன்றாகக் கருதப்படும்; பாதுகாப்பாக இருக்க, `rc`-ஐக் கணக்கின் பெயருக்கு உடனே பின் வையுங்கள்.

## ccam என்ன செய்கிறது

தொடக்கம் வழக்கமான பாதையிலேயே செல்கிறது ([Claude Code-ஐத் தொடங்குதல்](/features/launch)), MCP படியில் மட்டும் ஒரு மாற்றத்துடன்:

1. எந்தத் தொடக்கத்திலும் போலவே, ccam கணக்கைக் கண்டுபிடித்து, அதன் பகிர்வு இணைப்புகளைச் சரிபார்த்து, `claude`-ஐக் கண்டறிகிறது.
2. கட்டளை `rc` அல்லது `remote-control` என்பதைக் கண்டு, `--mcp-config`-ஐ விட்டுவிடுகிறது.
3. கணக்கு MCP சர்வர்களைப் பகிர்ந்தால், குழுவின் `mcp.json`-ஐ `~/.local/state/ccam/mcp/work/`-இல் உள்ள `sync-stamp`-உடன் ஒப்பிட்டு, ஒவ்வொரு குழுச் சர்வரும் இன்னும் `.claude.json`-இல் உள்ளதா என்று சரிபார்க்கிறது. `.claude.json`-இல் ஏற்கெனவே தற்போதைய சர்வர்கள் இருந்தால், அல்லது குழுவிடம் சர்வர்களே இல்லையென்றால், நேராகப் படி 6-க்குச் செல்லும்.
4. இல்லையெனில், அமர்வுகளுக்குக் கிடைக்காமல் போகும் சர்வர்களைப் பெயரிடுகிறது:

   ```console
   $ ccam work rc
   ccam: Remote Control sessions only get MCP servers stored in account work's .claude.json, not the shared MCP servers (ctx, fs).
   Copy them into .claude.json (a backup is kept; the account's own servers stay)? [y/N]
   ```

5. `y` என்றால், `.claude.json`-இன் காப்புப்பிரதியைச் சேமித்து, Claude Code-இன் சொந்த lock-ஐப் பெற்று, குழுவின் சர்வர்களை `mcpServers`-இல் சேர்த்து, கணக்கின் மற்ற சர்வர்களை அப்படியே வைத்திருக்கும்; ஒரு குழுச் சர்வரின் அதே பெயரில் கணக்குக்குச் சொந்தமாக ஒரு சர்வர் இருந்தால், ccam கணக்கின் சர்வரையே வைத்துக்கொண்டு அதைச் சொல்லும். `N` என்றால், டெர்மினல் இல்லாவிட்டால், அல்லது கணக்கு இயங்கிக்கொண்டிருந்தால், எதையும் மாற்றாமல் அதைத் தெரிவிக்கும்:

   ```console
         Starting without them. To copy them before every launch instead, set mcp_strategy = "sync" in ~/.config/ccam/config.toml
   ```

6. அமர்வைப் பதிவுசெய்து, `CLAUDE_CONFIG_DIR`-ஐக் கணக்குக் கோப்புறைக்கு அமைத்து, `exec` மூலம் தன்னை `claude rc` ஆக மாற்றிக்கொள்கிறது.

பிறகு Remote Control ஒரு சர்வராக இயங்கிக்கொண்டே இருக்கும். அது உங்களுக்காகத் தொடங்கும் ஒவ்வொரு அமர்வும் அந்த process-இன் child ஆகும், அதனால் அது `work` ஆக இயங்கும்: `work`-இன் உள்நுழைவு, அமைப்புகள், உரையாடல் வரலாறு ஆகியவற்றுடன், `work`-இன் பயன்பாட்டு வரம்பில் கணக்கிடப்படும். ccam தொடங்கிய Remote Control சர்வர் இயங்கும் வரை ccam அந்தக் கணக்கை இயங்குவதாகக் கருதும். வெறும் `claude remote-control` மூலம் தொடங்கிய சர்வர், அதில் அமர்வுகள் இருக்கும்போது மட்டுமே கணக்கில் கொள்ளப்படும்; இன்னும் அமர்வு இல்லாத சர்வரை ccam-ஆல் பார்க்க முடியாது.

dry run இந்த வேறுபாட்டைக் காட்டுகிறது. சாதாரணத் தொடக்கம் குழுவின் சர்வர்களை argument ஆகக் கொண்டுசெல்லும், Remote Control கொண்டுசெல்லாது:

```console
$ ccam --dry-run work
CLAUDE_CONFIG_DIR=/home/me/.local/share/ccam/profiles/work CCAM_PROFILE=work /home/me/.local/bin/claude --mcp-config=/home/me/.local/share/ccam/groups/default/mcp.json
$ ccam --dry-run work rc
ccam: Remote Control sessions only get MCP servers stored in account work's .claude.json, not the shared MCP servers (ctx, fs).
      Starting without them. To copy them before every launch instead, set mcp_strategy = "sync" in ~/.config/ccam/config.toml
CLAUDE_CONFIG_DIR=/home/me/.local/share/ccam/profiles/work CCAM_PROFILE=work /home/me/.local/bin/claude rc
```

## இது ஏன் இப்படி வேலை செய்கிறது

**Remote Control `--mcp-config`-ஐ ஏற்பதில்லை.** சாதாரணத் தொடக்கங்களில் ccam குழுவின் சர்வர்களை Claude Code-க்கு `--mcp-config=<path>` ஆகக் கொடுக்கிறது, Claude Code-இன் கோப்புகளில் ஒருபோதும் எழுதுவதில்லை. `claude remote-control` தன் கட்டளைப் பெயருக்கு முன் அந்த option-ஐ மறுக்கிறது, பின்னால் எதையும் ஏற்பதில்லை; அதனால் ccam 0.6.0-க்கு முன், MCP சர்வர்களைப் பகிர்ந்த ஒவ்வொரு கணக்குக்கும் `ccam work rc` தோல்வியடைந்தது. இப்போது ccam அந்த option-ஐ விட்டுவிடுகிறது.

**அதன் அமர்வுகள் சர்வர்களை `.claude.json`-இலிருந்து மட்டுமே படிக்கின்றன.** Remote Control தொடங்கும் அமர்வுகள் கட்டளை வரியின் options-ஐப் பெறுவதில்லை. பயனர் MCP சர்வர்களை அவை கண்டுபிடிக்கும் ஒரே இடம் கணக்கின் `.claude.json`. அந்தக் கோப்பில் கணக்கின் உள்நுழைவு விவரங்களும் கோப்புறைவாரி நிலையும் உள்ளன, அதனால் `settings.json`-க்குச் செய்வது போல ccam அதைப் பகிரப்பட்ட நகலுடன் இணைக்க முடியாது. அமர்வுகளுக்குப் பகிரப்பட்ட பட்டியலைக் கொடுக்க ஒரே வழி, சர்வர்களை அதற்குள் நகலெடுப்பதுதான்.

**எழுதுவதற்கு முன் ccam கேட்கிறது.** இயல்புநிலை flag உத்தியில், தொடக்கத்தின்போது ccam `.claude.json`-ஐத் தொடுவதில்லை. அங்கே எழுதியே ஆக வேண்டிய ஒரே தொடக்கம் Remote Control, அதனால் அது முதலில் கேட்கிறது, காப்புப்பிரதி வைக்கிறது, `mcpServers` தவிர வேறு எதையும் தொடுவதில்லை. (தொடக்கங்களுக்கு வெளியே, MCP பகிர்விலிருந்து விலகுவதும் சேர்வதும், `ccam mcp import`-உம் அங்கே எழுதுகின்றன, அவற்றின் திட்டங்கள் சொல்வது போலவே.)

**கணக்கு இயங்கும்போது அது எழுதுவதில்லை.** அமர்வின்போது Claude Code `.claude.json`-ஐ மீண்டும் எழுதுகிறது, வெளியிலிருந்து செய்யப்படும் மாற்றம் தொலைந்துபோகும் அல்லது மேலெழுதப்படும். அதனால்தான் மற்றொரு Remote Control சர்வரும் ccam இல்லாமல் தொடங்கிய Claude Code-உம் உட்பட, கணக்கின் எந்த அமர்வு இயங்கினாலும் ccam நகலெடுப்பதைத் தவிர்க்கிறது.

**ஒவ்வொரு மாற்றத்துக்கும் ஒருமுறை மட்டுமே கேட்கும்.** நகலெடுத்த பிறகு, `sync-stamp` குழுவின் `mcp.json`-இன் மாற்ற நேரத்தை வைத்திருக்கும். அந்தக் கோப்பு மாறும்போது மட்டுமே, எடுத்துக்காட்டாக `ccam mcp add`-க்குப் பிறகு, அல்லது நகலெடுத்த சர்வர் `.claude.json`-இலிருந்து காணாமல் போகும்போது, ccam மீண்டும் கேட்கும். நீங்கள் `N` என்று பதிலளித்தால் இன்னும் நகல் இல்லை, அதனால் ஒவ்வொரு Remote Control தொடக்கத்திலும் கேட்கும்.

**`ccam mcp` நகல்களைப் புதுப்பித்த நிலையில் வைக்கிறது.** பெயர் மோதலில் `.claude.json`-இல் உள்ள உள்ளீடு `--mcp-config`-ஐ விட முன்னுரிமை பெறும், அதனால் பழைய நகல் சாதாரணத் தொடக்கங்களிலும் புதிய வரையறையை மறைத்துவிடும். எனவே `ccam mcp add`, `add-json`, `remove`, `import` ஆகியவையும், `ccam migrate`-உம் இயங்காத ஒவ்வொரு கணக்கின் நகலையும் புதுப்பித்து, ஒரு நகல் மாறியபோது அதைச் சொல்கின்றன:

```console
$ ccam mcp add ctx --url https://mcp.context7.com/mcp
✓ ctx added in group default — applies from the next launch
✓ Updated the copy in account work's .claude.json (made for Remote Control)
```

**டெர்மினல் இல்லையென்றால் பதில் "இல்லை".** Remote Control பெரும்பாலும் script, service அல்லது `nohup`-இலிருந்து இயங்குகிறது, அங்கே பதிலளிக்க யாரும் இல்லை. அப்போது ccam காத்திருக்காமல் சர்வர்கள் இல்லாமல் தொடங்கும்.

## பிரச்சினைகளும் தீர்வுகளும்

### Remote Control அமர்வுகளில் பகிரப்பட்ட MCP சர்வர்கள் இல்லை

கேள்விக்கு `N` என்று பதிலளிக்கப்பட்டது, டெர்மினல் இல்லை, அல்லது கணக்கு இயங்கிக்கொண்டிருந்தது. Remote Control-ஐ நிறுத்தி, கணக்கின் மற்ற அமர்வுகளை மூடி, டெர்மினலில் `ccam work rc`-ஐ மீண்டும் இயக்குங்கள்; `y` என்று பதிலளியுங்கள். இனி கேட்கப்படாமல் இருக்க, `~/.config/ccam/config.toml`-இல் `mcp_strategy = "sync"`-ஐ அமையுங்கள். ஓர் அமர்வில் ஏற்கெனவே உள்ள சர்வர்கள் அது இயங்கும்போது மாறாது, அதனால் நகலெடுத்த பிறகு புதிய அமர்வைத் தொடங்குங்கள்.

### "Account work is running, so its .claude.json is left alone"

`work`-இன் ஓர் அமர்வு இன்னும் திறந்திருக்கிறது: சாதாரண `ccam work`, ஒரு குறுக்குவழி, அல்லது மற்றொரு Remote Control சர்வர். அதிலிருந்து வெளியேறி `ccam work rc`-ஐ மீண்டும் இயக்குங்கள். வேறொரு கணக்கு இயக்கும் அமர்வுகள் கணக்கில் வராது.

### ccam ஒவ்வொரு முறையும் கேட்கிறது

நீங்கள் இன்னும் சர்வர்களை நகலெடுக்கவில்லை. ஒருமுறை `y` என்று பதிலளியுங்கள், அல்லது `mcp_strategy = "sync"`-ஐ அமையுங்கள். Remote Control-இல் சர்வர்கள் ஒருபோதும் வேண்டாமென்றால், அவற்றை வைத்துக்கொள்ளாமல் கணக்குடன் MCP பகிர்வதை நிறுத்துங்கள்: `ccam group leave default work --fresh`, அல்லது அந்தக் கணக்கு இல்லாத தனிக் குழுவில் MCP-ஐ வையுங்கள். வெறும் `ccam group leave` குழுவின் சர்வர்களைக் கணக்கின் `.claude.json`-க்குள் நகலெடுக்கிறது, அதனால் Remote Control-க்கு அவை கிடைக்கும்.

### `ccam work rc` உடனே `--mcp-config` பற்றிய பிழையுடன் தோல்வியடைகிறது

உங்கள் ccam 0.6.0-ஐ விடப் பழையது, அது Remote Control-க்கு `--mcp-config`-ஐ அனுப்புகிறது. `ccam update`-ஐ இயக்குங்கள். தற்போதைய ccam-இலும் இதே பிழை வந்தால், மதிப்பு கொண்ட தெரியாத option ஒன்று `rc`-க்கு முன் வந்துள்ளது என்று பொருள், ccam அந்த மதிப்பைத் தவறாகக் கட்டளையாக எடுத்துக்கொண்டது; `rc`-ஐக் கணக்கின் பெயருக்கு உடனே பின் வையுங்கள்.

### `ccam mcp` மூலம் செய்த மாற்றம் Remote Control-ஐச் சென்றடையவில்லை

`ccam mcp add`, `remove` ஆகியவை இயங்காத கணக்குகளில் மட்டுமே நகல்களைப் புதுப்பிக்கின்றன, அதையும் தெரிவிக்கின்றன: `Note: account work is running, so the copy in its .claude.json stays as it was until its next Remote Control launch.` Remote Control-ஐ நிறுத்தி மீண்டும் தொடங்குங்கள்; மாறிய `mcp.json`-ஐ ccam கண்டு மீண்டும் கேட்கும்.

### குழுவுடையதற்குப் பதிலாக என் சொந்தச் சர்வர் பயன்படுத்தப்படுகிறது

குழுச் சர்வரின் அதே பெயரில் கணக்குக்குச் சொந்தமாக ஒரு சர்வர் இருந்தால், நகல் அதை அப்படியே விட்டுவிட்டு அதைச் சொல்கிறது: `account work has its own MCP servers fs, so group default's servers with those names are not copied there`. குழுவுடையதைப் பயன்படுத்த, கணக்குடையதை நீக்குங்கள் (`claude mcp remove -s user <name>`); உங்கள் பதிப்பை எல்லாக் கணக்குகளுக்கும் கொடுக்க, `ccam mcp import work <server> --force` மூலம் அதைக் குழுவுக்கு நகர்த்துங்கள். `.claude.json`-இன் காப்புப்பிரதிகள் `~/.local/state/ccam/mcp/work/backups/`-இல் உள்ளன, அங்கே மிகப் புதிய ஐந்து வைக்கப்படுகின்றன.

### நகலெடுத்த சர்வர்களை நீக்க வேண்டும்

`ccam mcp remove <server>` ஒரு சர்வரைக் குழுவிலிருந்தும் ஒவ்வொரு நகலிலிருந்தும் நீக்குகிறது. நகலுக்கு முந்தைய நிலைக்குத் திரும்ப, கணக்கின் எந்த அமர்வும் இயங்காதபோது `~/.local/state/ccam/mcp/work/backups/`-இலிருந்து மிகப் புதிய காப்புப்பிரதியை மீட்டெடுங்கள்.

### Remote Control கோப்புறையை நம்பவா என்று கேட்கிறது, அல்லது டெர்மினல் இல்லாமல் வெளியேறுகிறது

கோப்புறை நம்பிக்கை ஒவ்வொரு கணக்குக்கும் தனியாக `.claude.json`-இல் சேமிக்கப்படுகிறது, அதனால் `personal` ஆக நீங்கள் நம்பிய கோப்புறை `work`-க்குப் புதியது. அந்தக் கோப்புறையில் ஒருமுறை `ccam work`-ஐ இயக்கி ஏற்றுக்கொள்ளுங்கள், பிறகு அங்கே Remote Control-ஐத் தொடங்குங்கள்.

### "You must be logged in with a Claude account that has a subscription"

Remote Control-க்கு Claude சந்தா உள்ள உள்நுழைவு தேவை. `ccam list`-இல் கணக்கின் மின்னஞ்சலைச் சரிபாருங்கள், தேவைப்பட்டால் `ccam login work` மூலம் மீண்டும் உள்நுழையுங்கள்.

### அமர்வு தொலைபேசியில் தெரியவில்லை

Claude செயலி அல்லது claude.ai/code வேறொரு Claude கணக்கில் உள்நுழைந்துள்ளது. `work`-க்கு `ccam list` காட்டும் மின்னஞ்சலுடன் அதை ஒப்பிடுங்கள்.

### இந்தக் கோப்புறையில் மற்றொரு Claude Code அமர்வு உரையாடல் வரலாற்றைப் பகிர்கிறது என்று ccam எச்சரிக்கிறது

அதே வரலாற்றுக் குழுவைச் சேர்ந்த மற்றொரு கணக்கு அதே கோப்புறையில் இயங்கிக்கொண்டிருக்கிறது. இரு கணக்குகளிலிருந்தும் ஒரே உரையாடலைத் தொடரும் அமர்வுகள் வரலாற்றைக் குழப்பலாம். அவை வெவ்வேறு உரையாடல்களில் வேலை செய்யும் என்றால் மட்டுமே `y` என்று பதிலளியுங்கள், அல்லது Remote Control-ஐ வேறொரு கோப்புறையில் தொடங்குங்கள்.
