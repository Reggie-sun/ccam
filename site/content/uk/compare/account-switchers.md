Інструменти для перемикання облікових записів Claude Code використовують один із двох підходів. Більшість підміняють дані входу в єдиній теці `~/.claude`, тому одночасно активний лише один обліковий запис. Інші, зокрема ccam, дають кожному обліковому запису власну теку через `CLAUDE_CONFIG_DIR`, тому всі облікові записи лишаються авторизованими й кілька з них можуть працювати одночасно. ccam додає до цього спільні налаштування й сервери MCP і вміє продовжити розмову в теці іншого облікового запису.

## Підміняти один вхід чи мати окремі теки?

**У разі підміни входу** лишається один набір налаштувань, серверів MCP та історії, бо тека лише одна. Перемикання відбувається швидко, і запущений сеанс може підхопити новий вхід. Але активний лише один обліковий запис за раз, одразу для всіх терміналів і редакторів.

Щоб підмінити вхід, інструмент зберігає копію даних входу кожного іншого облікового запису й записує її на місце. Оновлюючи вхід, Claude Code замінює в ньому токен оновлення, тому кожну збережену копію доводиться узгоджувати із запущеними сеансами. Облікові записи, які після перемикання опиняються без входу або знову потребують `/login`, — одна з проблем, які ці проєкти виправляють найчастіше.

**Окремі теки** — це спосіб, [описаний у документації Claude Code](https://code.claude.com/docs/en/authentication#log-in-with-multiple-accounts). Кожен обліковий запис лишається авторизованим, і можна запустити робочий та особистий сеанси поруч. Дані входу кожного облікового запису лишаються в його власній теці, де Claude Code оновлює їх як завжди. Ціна в тому, що кожна тека спочатку має власні налаштування, сервери MCP та історію, якщо тільки інструмент не зробить їх спільними.

## Сильні сторони ccam

### Дані входу лишаються там, куди їх поклав Claude Code

ccam ніколи не копіює дані входу Claude з одного місця в інше. Вхід кожного облікового запису лишається в його власній теці, а на macOS — в окремому елементі в'язки ключів для цієї теки, і оновлює його сам Claude Code. Немає збереженої копії, яка могла б розійтися з оригіналом. Наявна тека `~/.claude`, зареєстрована через `ccam import`, зберігає елемент в'язки ключів, яким користується звичайний `claude`, тому вона лишається авторизованою в обох випадках.

ccam сам оновлює прострочений токен, лише коли ви запускаєте `ccam usage --refresh`. Спершу він бере блокування й відмовляється працювати, якщо цей обліковий запис запущено, тому ніколи не змінює токен під робочим сеансом.

### Між вами й Claude Code нічого не працює

ccam читає один файл, перевіряє свої посилання й замінює себе на `claude` (`exec`). Поки ви працюєте, немає ні процесу ccam, ні обгортки, ні проксі, ні демона: стандартне введення, сигнали й код виходу належать Claude Code, а його запити йдуть напряму до Anthropic. Windows не вміє замінювати процес, тому там ccam запускає Claude Code в тій самій консолі й чекає на його код виходу, нічого іншого не роблячи.

Запуск облікового запису в такий спосіб додає близько 4 мс, менше ніж 6 мс на 95-му процентилі, за пікового споживання пам'яті 8 МБ ([`scripts/perf-check.sh`](https://github.com/jhyunwoo/ccam/blob/main/scripts/perf-check.sh) з hyperfine, 300 запусків). На тому самому ноутбуці лише запуск інтерпретатора Python займає 13 мс, а Node.js — 31 мс, ще до того, як програма щось зробить.

### Що спільне, вирішують групи

Сервери MCP, `settings.json`, `CLAUDE.md`, розширення (агенти, команди, навички, плагіни) та історія розмов — це п'ять окремих елементів. Група називає елементи, які робить спільними, і облікові записи, що до неї входять, тому два робочі облікові записи можуть мати спільну історію в групі `work`, особистий обліковий запис зберігає свою, а всі три користуються тими самими серверами MCP через `default`. `ccam group set work --add memory` переносить усі облікові записи групи за одним планом; [панель керування](/features/dashboard) робить те саме за допомогою прапорців і показує сірим елемент, який обліковий запис уже отримує від іншої групи.

- Сервери MCP передаються під час запуску через `--mcp-config`, тому за замовчуванням ccam ніколи не редагує `.claude.json` — файл, який Claude Code перезаписує під час роботи. `ccam mcp add` додає сервер один раз для всієї групи.
- Решта елементів — це посилання на теку групи, тому зміна в одному обліковому записі одразу видна в інших. Під час запуску нічого не копіюється.
- Дані входу, `.claude.json` і стан роботи ніколи не бувають спільними.

### Кожну зміну спершу показано й збережено в резервній копії

`ccam group` і `ccam migrate` виводять план і питають, перш ніж щось переміщувати. Якщо файл в обліковому записі відрізняється від файлу в групі, вибираєте ви: лишити версію групи, взяти свою або об'єднати JSON. Оригінали потрапляють до `.ccam-backup/<time>/`, тека видаленого облікового запису — до теки кошика, а файли замінюються одним перейменуванням, тому перерваний запис лишає старий файл. `--dry-run` показує, що зробили б запуск, спільний доступ, міграція, ярлики, оновлення та виправлення. `ccam doctor --fix` виправляє зламані посилання й права доступу.

### Та сама розмова в наступному обліковому записі

`ccam next --auto --continue` одночасно запитує використання в усіх облікових записів, відкриває той, де найбільше запасу, і продовжує розмову. Зі спільною історією це та сама розмова; без неї Claude Code копіює її в новий обліковий запис (`--resume <file> --fork-session`), а ccam повідомляє, скільки токенів перша відповідь прочитає повторно. Коли ліміт зупиняє сеанс, хук плагіна ccam показує сповіщення, а `/ccam:switch` передає розмову далі. Коли перемикатися, вирішуєте ви; ніщо не стежить за вашим використанням у фоні, а автоматичний вибір не виходить за межі однієї організації, тому розмова компанії ніколи випадково не потрапить в особистий обліковий запис. Рядок стану підказує цю команду, щойно обліковий запис доходить до 90%.

Скрипти не можуть чекати на вас, тому `ccam --fallback work -p "…"` перемикається замість них: коли обліковий запис досягає ліміту, та сама команда запускається знову від імені облікового запису, де найбільше запасу, і виводиться лише результат запуску, який завершився. Помилка, не пов'язана з лімітом використання, передається як є. Для паралельних робочих процесів `ccam pick` видає кожному інший обліковий запис із запасом, і обидві команди завершуються з кодом 75, коли запасу не лишилося в жодного облікового запису.

### Потрібний обліковий запис у кожній теці

`ccam folder work ~/code/company` робить так, що кожен запуск без назви облікового запису всередині цієї теки використовує `work`, а решта ваших проєктів зберігають обліковий запис за замовчуванням. Налаштування зберігається в тому самому `config.toml`, який читає кожен запуск, тож воно не забирає часу.

### Один бінарний файл, перевірені завантаження

ccam — статичний бінарний файл розміром близько 10 МБ для Linux, macOS і Windows, якому не потрібне окремо встановлюване середовище виконання. Скрипти встановлення (`install.sh`, `install.ps1`) і `ccam update` перевіряють кожне завантаження за контрольними сумами SHA-256 релізу, а сам ccam ніколи не перевіряє оновлення. Телеметрії немає: єдині запити, які він робить, — це запити використання ваших облікових записів до Anthropic, паралельно, з лімітом 3 секунди й кешем на 60 секунд, і завантаження, про які ви попросили. З `usage_source = "claude"` навіть ці запити йдуть через Claude Code, і ccam ніколи не має справи з токеном.

## Де інші інструменти вміють більше

- claude-swap, clauth, cux, CAAM і CCSwitcher можуть самі перемикати запущений інтерактивний сеанс, коли обліковий запис перевищує поріг використання. ccam перемикає запуски `-p` за допомогою `--fallback`, а інтерактивні сеанси лишає вам, зі сповіщенням при ліміті та `/ccam:switch`.
- У Windows без режиму розробника ccam робить спільними теки, але не може зробити спільними окремі файли, як-от `settings.json`; claude-swap і CCS у такому разі їх копіюють.
- CCSwitcher, Claude Switcher і claude-swap показують використання в рядку меню macOS.
- CCS, clausona, CAAM, clauth, ccswap і Claude Switcher також керують Codex та іншими агентами для програмування.
- clausona також вмикає й вимикає розширення для кожного облікового запису (`ccam ext` у ccam лише показує їх), рахує локальну вартість токенів і постачає плагіни Claude Code, які запускають групи робочих процесів у tmux та інших терміналах.
- CAAM, CCSwitcher і Claude Switcher встановлюються через Homebrew, а clauth і CAAM підписують контрольні суми своїх релізів. ccam встановлюється своїм скриптом, пакетом `.deb` або через `go install` і перевіряє контрольні суми без підпису.

## Що вам підійде?

Виберіть інструмент із підміною входу, якщо ви користуєтеся одним обліковим записом за раз або хочете, щоб запущені сеанси перемикалися автоматично. Виберіть ccam, якщо вам потрібні облікові записи, що працюють поруч, одне спільне налаштування, та сама розмова в наступному обліковому записі й нічого зайвого, що працювало б поруч із Claude Code, на Linux, macOS або Windows. Якщо нічого спільного не потрібно, досить [звичайних псевдонімів оболонки](/compare/aliases).

Чи можна користуватися кількома обліковими записами, залежить від умов кожного облікового запису. Перевірте їх заздалегідь.
