Кожен обліковий запис зберігає власний вхід. Усе інше можна спільно використовувати через **групи**: група визначає елементи, які вона спільно використовує, і облікові записи, що до неї входять, а ccam пов'язує файли кожного з цих облікових записів із текою групи, тож зміна, зроблена в одному обліковому записі, з'являється в усіх.

## Що можна спільно використовувати

| Елемент | Що спільно використовується |
| --- | --- |
| `mcp` | сервери MCP: `mcp.json` групи, що передається в Claude Code під час запуску |
| `settings` | `settings.json`: дозволи, хуки, модель, рядок стану |
| `memory` | глобальний `CLAUDE.md` |
| `extensions` | `agents/`, `commands/`, `skills/`, `plugins/`, `output-styles/`, `rules/` |
| `history` | історія розмов: `projects/` і `history.jsonl` |

Ваш перший обліковий запис створює групу `default`, яка спільно використовує все, крім історії розмов, а наступні облікові записи приєднуються до неї.

Файли входу `.credentials.json` і `.claude.json` ніколи не бувають спільними. ccam пов'язує лише шляхи з фіксованого списку, і цих двох у ньому немає.

Ця сторінка присвячена повсякденним завданням. Усі параметри описано на сторінках можливостей: [спільне використання через групи](/features/share), [спільні сервери MCP](/features/mcp) і [копіювання наявного налаштування](/features/migrate).

## Групи

```sh
ccam group                                   # the groups, what they share, their accounts
ccam group set default --add history         # every account in default shares history
ccam group add team --items history --members work,side
```

Обліковий запис може належати до кількох груп, але кожен елемент надходить лише з однієї групи. Тож щоб `work` і `side` мали спільну історію, а інші ваші облікові записи — ні, не додавайте історію до `default` і дайте цим двом окрему групу, як показано вище. `ccam share work` показує, що спільно використовує обліковий запис і через яку групу. [Панель керування](/features/dashboard) робить те саме на вкладці Groups.

## Коли обліковий запис починає спільне використання

Коли обліковий запис починає спільно використовувати елемент (він приєднується до групи або його група додає цей елемент), ccam:

1. виводить план кожного файлу, який він перемістить, скопіює або пов'яже для кожного облікового запису, і запитує дозволу, перш ніж почати;
2. переміщує файли облікового запису до теки групи, якщо група ще порожня, або додає файли, яких у групі ще немає;
3. коли той самий файл відрізняється, запитує, чи залишити версію групи, використати вашу чи об'єднати JSON;
4. зберігає ваш оригінал у `.ccam-backup/<time>/` усередині теки облікового запису;
5. замінює оригінал посиланням на групу.

Файли розмов мають назви за ідентифікатором сеансу, тож історії з кількох облікових записів об'єднуються без конфліктів.

ccam не змінює обліковий запис, поки Claude Code працює від його імені, хоч би як було запущено Claude Code (зокрема фонові сеанси), бо сеанс і далі записує у файли, які переміщуються. Спершу завершіть сеанс. ccam перевіряє ще раз безпосередньо перед збереженням, тож сеанс, запущений, поки план чекав, також буде виявлено.

## Коли обліковий запис припиняє спільне використання

```sh
ccam group leave team work                   # work leaves the group
ccam group set default --remove history      # nobody in default shares history any more
```

Посилання видаляється, і обліковий запис отримує власну копію поточного вмісту групи; сервери MCP групи потрапляють до його власного `.claude.json`, поруч із його власними серверами. Додайте `--fresh`, щоб натомість почати з порожнього стану; тоді план перелічує сервери MCP, які перестануть завантажуватися. Імпортована тека, як-от `~/.claude`, завжди зберігає копію. Група зберігає свій вміст для інших облікових записів.

## Копіювання наявного налаштування

Якщо ви користувалися Claude Code до ccam, ваші налаштування містяться в `~/.claude`. `ccam migrate` копіює їх до групи, щоб їх отримав кожен обліковий запис, який спільно використовує ці елементи:

```sh
ccam migrate
```

У терміналі ccam спершу показує контрольний список елементів. Позначено все, крім історії розмов; натисніть Space, щоб змінити елемент, і Enter, щоб переглянути план. Елементи, для яких у теці нічого немає, позначено `not found`.

Що копіюється:

- `settings.json` і глобальний `CLAUDE.md`;
- розширення `agents/`, `commands/`, `skills/`, `plugins/`, `output-styles/` і `rules/`;
- ваші користувацькі сервери MCP, тобто запис `mcpServers` з `~/.claude.json`, до файлу групи `mcp.json`;
- історія розмов (`projects/` і `history.jsonl`), але лише якщо ви додасте `--history`.

Вихідна тека лише читається: у ній нічого не переміщується, не пов'язується й не змінюється, а звичайний `claude` працює як раніше. Файли входу `.credentials.json` і `.claude.json` ніколи не копіюються до групи.

Сервери MCP, що виконують вхід через OAuth, зберігають свої токени в даних входу, а не в списку серверів. ccam не копіює ці входи: скопійований вхід містить той самий токен оновлення, і перше ж оновлення виводить із цього сервера всіх інших власників, зокрема `~/.claude`. План і підсумок називають облікові записи, які мають самі увійти в сервери через `/mcp`.

Перш ніж щось скопіювати, ccam виводить план і запитує дозволу:

```console
$ ccam migrate
Copy from /home/me/.claude into group default (/home/me/.local/share/ccam/groups/default):
  mcp         ~/.claude.json  new: context7, fs
  settings    settings.json   new: 80 B
  memory      CLAUDE.md       new: 31 B
  extensions  agents/         add 1 file the group lacks (17 B)
              commands/       add 1 file the group lacks (15 B)
              skills/         add 1 file the group lacks (32 B)
              not found, skipped: plugins/, output-styles/, rules/
  Conversation history (projects/, history.jsonl) is not included; add --history to copy it.
Copy these into group default? [y/N] y
✓ Copied into group default: 2 MCP servers, settings.json, CLAUDE.md, agents/, commands/, skills/
Group default: personal
To share them:
  ccam group join default work
```

Наприкінці ccam перелічує облікові записи групи. Якщо група ще не спільно використовує один з елементів або деякі облікові записи не входять до неї, він виводить команди `ccam group`, які це змінюють.

Якщо в групі вже є інша копія файлу, ccam запитує так само, як під час увімкнення спільного використання: залишити копію групи чи використати вашу. `settings.json` та інші файли JSON можна також об'єднати, а `history.jsonl` об'єднати рядок за рядком. Попередні копії групи зберігаються в `.ccam-backup/<time>/` усередині теки групи.

| Параметр | Дія |
| --- | --- |
| `--settings`, `--memory`, `--extensions`, `--mcp`, `--history` | Копіювати лише вказані елементи, без контрольного списку; без них і поза терміналом копіюється все, крім історії розмов |
| `-g`, `--group <group>` | Копіювати до цієї групи замість `default` |
| `-y`, `--yes` | Копіювати без запитань; якщо файл відрізняється, залишити копію групи |

Поставте `--dry-run` перед командою, як у `ccam --dry-run migrate`, щоб побачити план, нічого не копіюючи. Щоб скопіювати з іншої теки, вкажіть її: `ccam migrate ~/.claude-work --group work`.

## Сервери MCP

Claude Code зберігає сервери MCP у `.claude.json` разом із даними входу, тому цей файл не можна спільно використовувати. ccam зберігає спільні сервери в `mcp.json` групи й запускає Claude Code з `--mcp-config=<group>/mcp.json`. Ваші власні параметри `--mcp-config` і далі застосовуються поверх цього.

```sh
ccam mcp add fs -- npx -y @modelcontextprotocol/server-filesystem ~/code
ccam mcp list
```

Сервер, який ви додаєте всередині сеансу командою `claude mcp add`, зберігається лише для цього облікового запису й для теки, у якій ви були (локальна область Claude Code; з `-s user` він належить обліковому запису в усіх теках). Під час наступного запуску цього облікового запису ccam назве сервер разом із його текою і команду, яка переміщує його до групи:

```sh
ccam mcp import work gh
```

Якщо в групі вже є інший сервер із такою назвою, ccam пропускає його й повідомляє про це. `--force` замінює сервер групи й зберігає старий `mcp.json` у теці `.ccam-backup/` групи.

Сервери MCP, що виконують вхід через OAuth, зберігають свої токени разом із даними входу облікового запису, тому авторизуйте їх один раз у кожному обліковому записі через `/mcp`. `ccam ext` і `ccam doctor` називають сервери, у які обліковий запис не увійшов, тоді як інший обліковий запис увійшов.

Якщо ви хочете, щоб сервери з'являлися в `claude mcp list` і `/mcp` як звичайні сервери користувача, задайте `mcp_strategy = "sync"` угорі `~/.config/ccam/config.toml`, над першим `[[group]]`, `[[profile]]` або `[[folder]]`. Тоді ccam перед запуском записує їх у `.claude.json` кожного облікового запису, під власним блокуванням файлу Claude Code і з резервною копією. Власний сервер облікового запису з тією самою назвою лишається за обліковим записом, і ccam про це повідомляє.

## Два облікові записи в одній теці

Облікові записи зі спільною історією розмов записують в одні й ті самі файли. Якщо ви запускаєте другий Claude Code у теці, де вже працює інший обліковий запис тієї самої групи, ccam попереджає вас і запитує, чи продовжувати.

## Коли щось ламається

```sh
ccam doctor
ccam doctor --fix
```

Якщо спільний шлях став звичайним файлом, наприклад після того, як ви вручну відновили резервну копію, ccam зупиняється до запуску Claude Code і вказує на `ccam doctor --fix`, яка знову пов'язує його з групою: файл стає копією групи, якщо в групи її немає, а інакше група зберігає свою, а ваша потрапляє до резервної копії, яку називає `--fix`. Зміну груп, що зупинилася на півдорозі, теж завершує `ccam doctor --fix`.
