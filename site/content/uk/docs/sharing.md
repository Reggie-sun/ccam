Кожен обліковий запис зберігає власний вхід. Усе інше можна спільно використовувати поелементно: ccam пов'язує файл або теку облікового запису зі спільною текою групи, тож зміна, зроблена в одному обліковому записі, з'являється в усіх облікових записах цієї групи.

## Що можна спільно використовувати

| Елемент | Параметр | Що спільно використовується |
| --- | --- | --- |
| Сервери MCP | `--mcp` | `mcp.json` групи, що передається в Claude Code під час запуску |
| Налаштування | `--settings` | `settings.json`: дозволи, хуки, модель, рядок стану |
| Глобальна пам'ять | `--memory` | `CLAUDE.md` |
| Розширення | `--extensions` | `agents/`, `commands/`, `skills/`, `plugins/`, `output-styles/`, `rules/` |
| Історія розмов | `--history` | `projects/` і `history.jsonl` |

Нові облікові записи спільно використовують усе, крім історії розмов.

Файли входу `.credentials.json` і `.claude.json` ніколи не бувають спільними. ccam пов'язує лише шляхи з фіксованого списку, і цих двох у ньому немає.

## Групи

`on` означає групу `default`. Можна також указати назву, щоб елемент спільно використовували лише деякі облікові записи:

```sh
ccam share work --history team
ccam share side --history team
```

Тепер `work` і `side` мають спільні розмови одне з одним, але не з іншими вашими обліковими записами.

## Увімкнення спільного використання

Коли обліковий запис починає спільно використовувати елемент, ccam:

1. виводить план кожного файлу, який він перемістить, скопіює або пов'яже, і запитує дозволу, перш ніж почати;
2. переміщує файли облікового запису до теки групи, якщо група ще порожня, або додає файли, яких у групі ще немає;
3. коли той самий файл відрізняється, запитує, чи залишити версію групи, використати вашу чи об'єднати JSON;
4. зберігає ваш оригінал у `.ccam-backup/<time>/` усередині теки облікового запису;
5. замінює оригінал посиланням на групу.

Файли розмов мають назви за ідентифікатором сеансу, тож історії з кількох облікових записів об'єднуються без конфліктів.

## Вимкнення спільного використання

```sh
ccam share work --history off
```

Посилання видаляється, і обліковий запис отримує власну копію поточного вмісту групи. Додайте `--fresh`, щоб натомість почати з порожнього стану. Група зберігає свій вміст для інших облікових записів.

## Копіювання наявного налаштування

Якщо ви користувалися Claude Code до ccam, ваші налаштування містяться в `~/.claude`. `ccam migrate` копіює їх до групи, щоб їх отримав кожен обліковий запис, який спільно використовує ці елементи:

```sh
ccam migrate
```

Що копіюється:

- `settings.json` і глобальний `CLAUDE.md`;
- розширення `agents/`, `commands/`, `skills/`, `plugins/`, `output-styles/` і `rules/`;
- ваші користувацькі сервери MCP, тобто запис `mcpServers` з `~/.claude.json`, до файлу групи `mcp.json`;
- історія розмов (`projects/` і `history.jsonl`), але лише якщо ви додасте `--history`.

Вихідна тека лише читається: у ній нічого не переміщується, не пов'язується й не змінюється, а звичайний `claude` працює як раніше. Файли входу `.credentials.json` і `.claude.json` ніколи не копіюються.

Перш ніж щось скопіювати, ccam виводить план і запитує дозволу:

```console
$ ccam migrate
Copy from /home/me/.claude into group default (/home/me/.local/share/ccam/groups/default):
  mcp         ~/.claude.json  new: context7, fs
  settings    settings.json   new: 80 B
  memory      CLAUDE.md       new: 31 B
  extensions  agents/         add 1 file the group lacks (17 B)
              commands/       add 1 file the group lacks (15 B)
              skills/         add 1 file the group lacks (32 B)
              not found, skipped: plugins/, output-styles/, rules/
  Conversation history (projects/, history.jsonl) is not included; add --history to copy it.
Copy these into group default? [y/N] y
✓ Copied into group default: 2 MCP servers, settings.json, CLAUDE.md, agents/, commands/, skills/
Accounts that share these through group default:
  mcp         personal
  settings    personal
  memory      personal
  extensions  personal
```

Наприкінці ccam перелічує облікові записи, які спільно використовують кожен елемент через групу. Якщо деякі облікові записи цього не роблять, він виводить команди `ccam share`, що вмикають для них спільне використання.

Якщо в групі вже є інша копія файлу, ccam запитує так само, як під час увімкнення спільного використання: залишити копію групи чи використати вашу. `settings.json` та інші файли JSON можна також об'єднати, а `history.jsonl` об'єднати рядок за рядком. Попередні копії групи зберігаються в `.ccam-backup/<time>/` усередині теки групи.

| Параметр | Дія |
| --- | --- |
| `--settings`, `--memory`, `--extensions`, `--mcp`, `--history` | Копіювати лише вказані елементи; без них копіюється все, крім історії розмов |
| `-g`, `--group <group>` | Копіювати до цієї групи замість `default` |
| `-y`, `--yes` | Копіювати без запитань; якщо файл відрізняється, залишити копію групи |

Поставте `--dry-run` перед командою, як у `ccam --dry-run migrate`, щоб побачити план, нічого не копіюючи. Щоб скопіювати з іншої теки, вкажіть її: `ccam migrate ~/.claude-work --group work`.

## Сервери MCP

Claude Code зберігає сервери MCP у `.claude.json` разом із даними входу, тому цей файл не можна спільно використовувати. ccam зберігає спільні сервери в `mcp.json` групи й запускає Claude Code з `--mcp-config=<group>/mcp.json`. Ваші власні параметри `--mcp-config` і далі застосовуються поверх цього.

```sh
ccam mcp add fs -- npx -y @modelcontextprotocol/server-filesystem ~/code
ccam mcp list
```

Сервер, який ви додаєте всередині сеансу командою `claude mcp add`, зберігається лише для цього облікового запису. Під час наступного запуску цього облікового запису ccam назве сервер і команду, яка переміщує його до групи:

```sh
ccam mcp import work gh
```

Сервери MCP, що виконують вхід через OAuth, зберігають свої токени разом із даними входу облікового запису, тому авторизуйте їх один раз у кожному обліковому записі.

Якщо ви хочете, щоб сервери з'являлися в `claude mcp list` і `/mcp` як звичайні сервери користувача, задайте `mcp_strategy = "sync"` у `~/.config/ccam/config.toml`. Тоді ccam перед запуском записує їх у `.claude.json` кожного облікового запису, під власним блокуванням файлу Claude Code і з резервною копією.

## Два облікові записи в одній теці

Облікові записи зі спільною історією розмов записують в одні й ті самі файли. Якщо ви запускаєте другий Claude Code у теці, де вже працює інший обліковий запис тієї самої групи, ccam попереджає вас і запитує, чи продовжувати.

## Коли щось ламається

```sh
ccam doctor
ccam doctor --fix
```

Якщо спільний шлях став звичайним файлом, наприклад після того, як ви вручну відновили резервну копію, ccam зупиняється до запуску Claude Code і вказує на `ccam doctor --fix`, яка об'єднує файл із групою й зберігає резервну копію.
