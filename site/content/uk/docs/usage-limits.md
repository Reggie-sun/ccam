`ccam usage` показує для кожного облікового запису, яку частку кожного ліміту використано: 5-годинного ліміту, тижневого ліміту й власного тижневого ліміту кожної моделі (наприклад, Fable). `ccam next --auto` відкриває обліковий запис із найбільшим запасом, а `--continue` переносить поточну розмову.

```console
$ ccam usage
 1 personal  just now
   5-hour   ██████████████░░░░░░  72%  resets in 1h 40m
   Weekly   ████████░░░░░░░░░░░░  41%  resets in 3d 6h
   Fable    ██████████████████░░  88%  resets in 1d 6h
 2 work      just now
   5-hour   ██░░░░░░░░░░░░░░░░░░   8%  resets in 4h 12m
   Weekly   ████░░░░░░░░░░░░░░░░  19%  resets in 5d 2h
   Fable    █░░░░░░░░░░░░░░░░░░░   3%  resets in 5d 2h
 3 side      12m ago (cached)
   5-hour   ████████████████████ 100%  resets in 22m
   Weekly   ██████████████░░░░░░  68%  resets in 1d 9h
   Fable    ████████░░░░░░░░░░░░  40%  resets in 1d 9h
→ Most headroom: work   (open it with ccam next --auto)
```

Кожен обліковий запис отримує рядок із давністю його чисел, а під ним по смужці на кожен ліміт із часом до скидання: 5-годинне вікно, тижневе вікно для всіх моделей і власне тижневе вікно кожної моделі, наприклад Fable. Смужка стає жовтою на 80% і червоною на 100%. Останній рядок називає обліковий запис, який відкрив би `ccam next --auto`; з `auto_strategy = "expiring"` або `"balance"` натомість там написано `→ next --auto picks <name>: <reason>`.

**Місця в планах Team і Enterprise.** Автоматичний вибір облікового запису (`ccam next`, `--fallback`, `ccam pick`, `n` на панелі керування, а також, щойно ви його ввімкнете, [`auto_switch`](/features/next#auto-switch)) також перемикає між місцями однієї організації Claude Team або Enterprise, що може порушувати умови Anthropic. Прочитайте [FAQ](/docs/faq#am-i-allowed-to-use-several-claude-code-accounts) і уточніть це у своїй організації та в Anthropic, перш ніж на нього покладатися.

## Звідки беруться ці числа

ccam запитує кінцеву точку використання Anthropic для всіх облікових записів одночасно, використовуючи власні дані входу кожного облікового запису. Він чекає не більше 3 секунд на кожен обліковий запис і показує кожен обліковий запис, щойно той відповість.

Ця кінцева точка не задокументована публічно й може змінитися. Коли запит не вдається, ccam показує останні відомі числа й позначає їх як кешовані. Вікно, яке скинулося після збереження цих чисел, показує 0%. `ccam doctor` повідомляє, якщо формат відповіді змінився.

Коли Claude Code зупиняє сеанс на ліміті використання, [плагін ccam](/docs/install#claude-code-plugin) записує, яке вікно заповнилося і коли воно скинеться. До того часу це вікно показує 100%, хоч би що казали інші числа, тож `ccam next --auto` і `--fallback` не виберуть цей обліковий запис знову зарано.

Числа, отримані менш ніж 60 секунд тому, використовуються повторно. Параметри:

| Параметр | Дія |
| --- | --- |
| `--watch[=seconds]` | Оновлювати безперервно, за замовчуванням кожні 60 секунд |
| `--json` | Машиночитаний вивід |
| `-v` | Також показувати, звідки взялися числа кожного облікового запису |
| `--no-cache` | Завжди запитувати заново |
| `--source cache` | Ніколи не запитувати; показувати лише збережені числа |

## Прострочені входи

Коли токен доступу облікового запису прострочено, ccam не оновлює його, бо оновлення під час сеансу Claude Code з тими самими даними входу може вивести цей сеанс із системи. Обліковий запис показує ``access token expired; `ccam <name>` renews it when it starts``: запустіть його один раз через `ccam <name>`, і Claude Code оновить токен. Вхід, термін дії якого сплив повністю або який очистив Claude Code, показує `` login expired → `ccam login <name>` `` і потребує нового входу.

`ccam usage --refresh` сам оновлює прострочені токени, але лише для облікових записів без запущеного сеансу Claude Code, хоч би як цей сеанс було запущено. Він ніколи не оновлює дані входу, збережені у в'язці ключів macOS або в імпортованій `~/.claude`, а оновлення може тривати до 30 секунд.

## Використання в рядку стану

```sh
ccam statusline install
```

Після цього Claude Code показує назву облікового запису та його використання в рядку стану, наприклад `[work] · Opus · 5h 24% · 7d 41%`. Починаючи з 90%, рядок також підказує `ccam next --auto --continue`. Якщо у вас уже є команда рядка стану, ccam зберігає її й додає назву облікового запису на початок. Рядок стану також зберігає свої числа, які `ccam usage` використовує, коли кінцева точка не відповідає.

## Перемикання

```sh
ccam next             # the account after the one you used last
ccam next --auto      # the account with the lowest 5-hour usage
ccam next --continue  # continue this folder's conversation on the next account
```

`ccam next` пропускає облікові записи, у які не виконано вхід, а `--auto` пропускає облікові записи зі 100% (зокрема вікно, про заповнення якого повідомив Claude Code, до його скидання) і облікові записи іншої організації. Коли два облікові записи мають спільну історію розмов, `--continue` відкриває ту саму розмову; інакше Claude Code копіює її в новий обліковий запис. Див. [спільне використання](/docs/sharing) і [перемикання на наступний обліковий запис](/features/next#continue).

З `auto_switch = true` угорі `config.toml` (Linux і macOS; типово вимкнено) ccam сам робить це перемикання, коли Claude Code зупиняє інтерактивний сеанс на його ліміті, а інший обліковий запис того самого типу (місце в тій самій організації або інший особистий план) має запас. Коли він діє і чого ніколи не робить, див. у розділі [`auto_switch`](/features/next#auto-switch).

Для скриптів і запланованих завдань, які запускають `claude -p`, поставте `--fallback` перед назвою облікового запису. Коли цей обліковий запис досягає ліміту, ccam знову виконує ту саму команду від імені облікового запису, де найбільше запасу, і виводиться лише результат запуску, який завершився:

```sh
ccam --fallback work -p "review the diff" --output-format json
```

Як ccam ухвалює рішення, див. у розділі [Повторний запуск при ліміті](/features/next#run-again-at-the-limit).

[Посібник із роботи з лімітами використання](/guides/usage-limit-workflow) розбирає повний приклад.
