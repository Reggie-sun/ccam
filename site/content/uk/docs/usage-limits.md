`ccam usage` показує, яку частку 5-годинного та тижневого лімітів використав кожен обліковий запис. `ccam next --auto` відкриває обліковий запис із найбільшим запасом, а `--continue` переносить поточну розмову.

```console
$ ccam usage
 Account     5-hour        Resets    Weekly        Resets    As of
 1 personal  ██████░░  72% 1h 40m    ███░░░░░  41% 3d 6h     just now
 2 work      █░░░░░░░   8% 4h 12m    ██░░░░░░  19% 5d 2h     just now
 3 side      ████████ 100% 22m       █████░░░  68% 1d 9h     12m ago (cached)
→ Most headroom: work   (open it with ccam next --auto)
```

Стовпці такі: обліковий запис, 5-годинне використання, час до його скидання, тижневе використання, час до його скидання та давність даних.

## Звідки беруться ці числа

ccam запитує кінцеву точку використання Anthropic для всіх облікових записів одночасно, використовуючи власні дані входу кожного облікового запису. Він чекає не більше 3 секунд на кожен обліковий запис і показує кожен обліковий запис, щойно той відповість.

Ця кінцева точка не задокументована публічно й може змінитися. Коли запит не вдається, ccam показує останні відомі числа й позначає їх як кешовані. Вікно, яке скинулося після збереження цих чисел, показує 0%. `ccam doctor` повідомляє, якщо формат відповіді змінився.

Числа, отримані менш ніж 60 секунд тому, використовуються повторно. Параметри:

| Параметр | Дія |
| --- | --- |
| `--watch [seconds]` | Оновлювати безперервно, за замовчуванням кожні 60 секунд |
| `--json` | Машиночитаний вивід |
| `-v` | Також показувати тижневі ліміти для окремих моделей і джерело кожного числа |
| `--no-cache` | Завжди запитувати заново |
| `--source cache` | Ніколи не запитувати; показувати лише збережені числа |

## Прострочені входи

Коли токен доступу облікового запису прострочено, ccam не оновлює його, бо оновлення під час сеансу Claude Code з тими самими даними входу може вивести цей сеанс із системи. Запустіть обліковий запис один раз через `ccam <name>`, і Claude Code оновить токен.

`ccam usage --refresh` сам оновлює прострочені токени, але лише для облікових записів, які не запущено. Він ніколи не оновлює дані входу, збережені у в'язці ключів macOS або в імпортованій `~/.claude`.

## Використання в рядку стану

```sh
ccam statusline install
```

Після цього Claude Code показує назву облікового запису та його використання в рядку стану, наприклад `[work] · Opus · 5h 24% · 7d 41%`. Починаючи з 90%, рядок також підказує `ccam next --auto --continue`. Якщо у вас уже є команда рядка стану, ccam зберігає її й додає назву облікового запису на початок. Рядок стану також зберігає свої числа, які `ccam usage` використовує, коли кінцева точка не відповідає.

## Перемикання

```sh
ccam next             # the account after the one you used last
ccam next --auto      # the account with the lowest 5-hour usage
ccam next --continue  # the next account that shares your conversation history
```

`ccam next` пропускає облікові записи, у які не виконано вхід, а `--auto` пропускає облікові записи зі 100%. Щоб продовжити розмову, обидва облікові записи мають спільно використовувати історію розмов; див. [спільне використання](/docs/sharing).

Для скриптів і запланованих завдань, які запускають `claude -p`, поставте `--fallback` перед назвою облікового запису. Коли цей обліковий запис досягає ліміту, ccam знову виконує ту саму команду від імені облікового запису, де найбільше запасу, і виводиться лише результат запуску, який завершився:

```sh
ccam --fallback work -p "review the diff" --output-format json
```

Як ccam ухвалює рішення, див. у розділі [Повторний запуск при ліміті](/features/next#run-again-at-the-limit).

[Посібник із роботи з лімітами використання](/guides/usage-limit-workflow) розбирає повний приклад.
