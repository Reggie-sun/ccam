## Чи є ccam офіційним інструментом Anthropic?

Ні. ccam є неофіційним проєктом з відкритим кодом і не пов'язаний з Anthropic та не схвалений нею. Він використовує параметр `CLAUDE_CONFIG_DIR`, який [Claude Code документує](https://code.claude.com/docs/en/env-vars) для одночасної роботи кількох облікових записів.

## Чи можна мені користуватися кількома обліковими записами Claude Code?

Це залежить від умов кожного облікового запису, а для робочих облікових записів також від політики вашої організації. Перевірте їх, перш ніж користуватися кількома обліковими записами. ccam лише полегшує перемикання між обліковими записами, які у вас уже є.

**Місця в планах Team і Enterprise.** Автоматичний вибір (`ccam next`, `--fallback`, `ccam pick`, `n` на панелі керування) також перемикає між місцями однієї організації Claude Team або Enterprise. У довідковому центрі Anthropic сказано: «Each seat on a Team plan is assigned to one named individual, and only that person may use it» (кожне місце в плані Team закріплене за однією конкретною особою, і користуватися ним може лише ця особа) та «Users can't route their work through another user's account to use that user's remaining usage» (користувачі не можуть спрямовувати свою роботу через обліковий запис іншого користувача, щоб використати залишок ліміту цього користувача) ([плани Team](https://support.claude.com/en/articles/12004354-purchase-and-manage-seats-on-team-plans#h_b8a7d07129); так само для [планів Enterprise](https://support.claude.com/en/articles/13393991-purchase-and-manage-seats-on-enterprise-plans#h_fa6b9cade0)). Тому використання автоматичного вибору між місцями може порушувати умови Anthropic. Перш ніж на нього покладатися, уточніть це у своїй організації та в Anthropic. Про особисті плани (Pro, Max) ідеться в абзаці вище.

## Чи обходить ccam ліміти використання?

Ні. Кожен обліковий запис зберігає власні ліміти. ccam показує їх і дає змогу продовжити роботу в іншому вашому обліковому записі, коли в одному ліміт вичерпано.

## Як користуватися двома обліковими записами Claude Code на одному комп'ютері?

Дайте кожному обліковому запису власну теку конфігурації за допомогою `CLAUDE_CONFIG_DIR`. ccam робить це за вас: виконайте `ccam add` для кожного облікового запису, а потім запускайте їх командами `ccam personal` і `ccam work` або короткими командами з назвами, які ви вибираєте самі, наприклад `ccwork`. У [посібнику](/guides/multiple-claude-code-accounts) також показано, як зробити це вручну.

## Як продовжити розмову в іншому обліковому записі?

Виконайте `ccam next --continue` у теці: команда переносить останню розмову теки до наступного облікового запису (`--auto` — до того, де найбільше запасу). Усередині Claude Code `/ccam:switch` із [плагіна ccam](/docs/install#claude-code-plugin) робить те саме для сеансу, у якому ви працюєте. Коли два облікові записи мають спільну історію розмов (`ccam group set default --add history` або їхня власна група: `ccam group add pair --items history --members work,side`), новий обліковий запис відкриває саме цю розмову; інакше Claude Code копіює її в історію нового облікового запису.

## Чи бачить або надсилає ccam мої дані входу?

ccam ніколи не поширює й не копіює ваші дані входу Claude між обліковими записами і ніколи не копіює входи серверів MCP. Він читає токен доступу облікового запису лише для того, щоб запитати в кінцевої точки використання Anthropic дані про використання цього облікового запису, коли ви виконуєте `ccam usage`, `ccam next --auto` або `ccam doctor`, а прострочений токен оновлює лише з `ccam usage --refresh`; з `usage_source = "claude"` він узагалі не читає токен. `ccam ext` і `ccam doctor` читають назви входів MCP облікового запису, але ніколи не їхні токени. ccam не має телеметрії. Окрім цих запитів, єдиний запит, який він робить сам, — це запитання панелі керування до GitHub про найновіший випуск ccam, і воно не містить нічого про вас чи ваші облікові записи.

## Як увійти на віддаленому сервері?

Виконайте `ccam add` або `ccam login <name>` у сеансі SSH як зазвичай. Claude Code чекає на вхід на сервері, тому браузер на вашому комп'ютері зупиняється на сторінці `http://localhost:<port>/callback?code=…`, яка не завантажується. Скопіюйте цю адресу з браузера й вставте її в термінал: ccam передає її Claude Code на сервері, і той завершує вхід. Адреса містить одноразовий код, тому нікому її не передавайте.

## Де зберігаються мої облікові записи?

У `~/.local/share/ccam/profiles/<name>/`, по одній теці на обліковий запис. На macOS Claude Code зберігає самі дані входу у в'язці ключів під назвою, утвореною від цієї теки, тому `ccam rename` залишає там стару назву теки.

## Що станеться з моєю наявною текою ~/.claude?

Нічого, якщо ви не виконаєте `ccam import` або `ccam migrate`. Імпорт реєструє теку там, де вона є, тож звичайний `claude` і `ccam <name>` і далі використовують той самий обліковий запис і ті самі налаштування. `ccam migrate` копіює її налаштування, `CLAUDE.md`, розширення та сервери MCP до спільних налаштувань і лише читає теку.

## Які системи підтримує ccam?

Linux (Ubuntu, Debian, Fedora, Arch, Alpine та інші), macOS і Windows 10 та 11, нативно або всередині WSL. У Windows для спільного використання файлів, як-от `settings.json`, потрібен режим розробника; спільні теки працюють і без нього, а без нього перший `ccam add` створює групу `default` лише із серверами MCP і розширеннями ([спільне використання у Windows](/features/share#on-windows)).

## Чому сервер MCP з'являється лише в одному обліковому записі?

Сервери, додані всередині сеансу командою `claude mcp add`, зберігаються лише для цього облікового запису, а без `-s user` — лише для поточної теки. ccam повідомить вам про це під час наступного запуску облікового запису, а `ccam mcp list` і `ccam ext` їх показують; перемістіть сервер до спільної групи командою `ccam mcp import <account> <server>`.

## Чи сповільнює ccam роботу Claude Code?

Запуск Claude Code через ccam додає приблизно 4 мілісекунди, виміряні за допомогою `scripts/perf-check.sh` на ноутбуці. ccam читає один невеликий файл, перевіряє спільні посилання, а потім замінює себе на `claude`, тож він не залишається запущеним під час вашої роботи. Windows не вміє замінювати процес, тому там ccam запускає Claude Code і чекає на його завершення, нічого іншого не роблячи.

## Як оновити ccam?

Виконайте `ccam update`. Ця команда завантажує найновіший випуск, перевіряє його контрольну суму й замінює файл `ccam`; `ccam update --check` лише повідомляє, чи є новіший випуск. Панель керування теж повідомляє, коли є новіший випуск, і `U` встановлює його після запитання; сам по собі ccam ніколи не оновлюється. Якщо ви встановили пакет `.deb`, натомість встановіть новий `.deb` через apt. Див. [оновлення](/docs/install#update).

## Як видалити ccam?

Видаліть коротку команду кожного облікового запису командою `ccam shortcut <account> --remove`. Якщо ви імпортували `~/.claude` і вона входить до групи, спершу виконайте для неї `ccam remove <name>`, щоб вона отримала назад копію того, що має спільним. Потім видаліть `ccam` з `~/.local/bin`, а також `~/.config/ccam`, `~/.local/share/ccam` і `~/.local/state/ccam`, якщо облікові записи вам більше не потрібні. Див. [встановлення](/docs/install#uninstall).
