## Чи є ccam офіційним інструментом Anthropic?

Ні. ccam є неофіційним проєктом з відкритим кодом і не пов'язаний з Anthropic та не схвалений нею. Він використовує параметр `CLAUDE_CONFIG_DIR`, який [Claude Code документує](https://code.claude.com/docs/en/env-vars) для одночасної роботи кількох облікових записів.

## Чи можна мені користуватися кількома обліковими записами Claude Code?

Це залежить від умов кожного облікового запису, а для робочих облікових записів також від політики вашої організації. Перевірте їх, перш ніж користуватися кількома обліковими записами. ccam лише полегшує перемикання між обліковими записами, які у вас уже є.

## Чи обходить ccam ліміти використання?

Ні. Кожен обліковий запис зберігає власні ліміти. ccam показує їх і дає змогу продовжити роботу в іншому вашому обліковому записі, коли в одному ліміт вичерпано.

## Як користуватися двома обліковими записами Claude Code на одному комп'ютері?

Дайте кожному обліковому запису власну теку конфігурації за допомогою `CLAUDE_CONFIG_DIR`. ccam робить це за вас: виконайте `ccam add` для кожного облікового запису, а потім запускайте їх командами `ccam personal` і `ccam work` або короткими командами з назвами, які ви вибираєте самі, наприклад `ccwork`. У [посібнику](/guides/multiple-claude-code-accounts) також показано, як зробити це вручну.

## Як продовжити розмову в іншому обліковому записі?

Увімкніть спільну історію розмов для двох облікових записів командою `ccam share <name> --history on`, а потім виконайте `ccam next --continue`. Claude Code відкриє найновішу розмову поточної теки в наступному обліковому записі.

## Чи бачить або надсилає ccam мої дані входу?

ccam ніколи не копіює й не поширює дані входу. Він читає токен доступу облікового запису лише для того, щоб запитати в кінцевої точки використання Anthropic дані про використання цього облікового запису, коли ви виконуєте `ccam usage`, `ccam next --auto` або `ccam doctor`. ccam не має телеметрії й нічого не надсилає більше нікуди.

## Де зберігаються мої облікові записи?

У `~/.local/share/ccam/profiles/<name>/`, по одній теці на обліковий запис. На macOS Claude Code зберігає самі дані входу у в'язці ключів під назвою, утвореною від цієї теки.

## Що станеться з моєю наявною текою ~/.claude?

Нічого, якщо ви не виконаєте `ccam import` або `ccam migrate`. Імпорт реєструє теку там, де вона є, тож звичайний `claude` і `ccam <name>` і далі використовують той самий обліковий запис і ті самі налаштування. `ccam migrate` копіює її налаштування, `CLAUDE.md`, розширення та сервери MCP до спільних налаштувань і лише читає теку.

## Які системи підтримує ccam?

Linux (Ubuntu, Debian, Fedora, Arch, Alpine та інші) і macOS. У Windows користуйтеся ним усередині WSL.

## Чому сервер MCP з'являється лише в одному обліковому записі?

Сервери, додані всередині сеансу командою `claude mcp add`, зберігаються лише для цього облікового запису. ccam повідомить вам про це під час наступного запуску облікового запису; перемістіть сервер до спільної групи командою `ccam mcp import <account> <server>`.

## Чи сповільнює ccam роботу Claude Code?

Запуск Claude Code через ccam додає приблизно 4 мілісекунди, виміряні за допомогою `scripts/perf-check.sh` на ноутбуці. ccam читає один невеликий файл, перевіряє спільні посилання, а потім замінює себе на `claude`, тож він не залишається запущеним під час вашої роботи.

## Як оновити ccam?

Виконайте `ccam update`. Ця команда завантажує найновіший випуск, перевіряє його контрольну суму й замінює файл `ccam`; `ccam update --check` лише повідомляє, чи є новіший випуск. Сам по собі ccam ніколи не оновлюється. Якщо ви встановили пакет `.deb`, натомість встановіть новий `.deb` через apt. Див. [оновлення](/docs/install#update).

## Як видалити ccam?

Видаліть коротку команду кожного облікового запису командою `ccam shortcut <account> --remove`, видаліть `ccam` з `~/.local/bin`, а потім `~/.config/ccam`, `~/.local/share/ccam` і `~/.local/state/ccam`, якщо облікові записи вам більше не потрібні. Див. [встановлення](/docs/install#uninstall).
