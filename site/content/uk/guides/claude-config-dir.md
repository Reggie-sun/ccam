`CLAUDE_CONFIG_DIR` вказує Claude Code, яку теку використовувати замість `~/.claude`. Усе, що стосується облікового запису, зберігається там: дані входу, налаштування, сервери MCP, плагіни та історія розмов. Якщо вказати різні теки, ви отримаєте окремі облікові записи.

```sh
CLAUDE_CONFIG_DIR=~/.claude-work claude
```

## Чи підтримується CLAUDE_CONFIG_DIR офіційно?

Так. Claude Code наводить її серед своїх [змінних середовища](https://code.claude.com/docs/en/env-vars) як спосіб перевизначити теку конфігурації, «корисний для одночасної роботи кількох облікових записів», а його [посібник з автентифікації](https://code.claude.com/docs/en/authentication#log-in-with-multiple-accounts) використовує її для входу в кілька облікових записів. Задати її можна в оболонці або в налаштуваннях користувача, але не в налаштуваннях проєкту.

## Що всередині теки?

Перевірено з Claude Code 2.1.302:

| Шлях | Вміст | Можна спільно використовувати |
| --- | --- | --- |
| `.credentials.json` | Токени входу (Linux, Windows), токени OAuth для MCP | Ні |
| `.claude.json` | Дані облікового запису, сервери MCP користувача, стан для кожного проєкту | Ні (сервери MCP окремо) |
| `settings.json` | Дозволи, хуки, модель, рядок стану, плагіни | Так |
| `CLAUDE.md` | Глобальні інструкції | Так |
| `agents/`, `commands/`, `skills/`, `plugins/` | Розширення | Так |
| `projects/` | Розмови у файлах `.jsonl`, пам'ять для кожного проєкту | Так |
| `history.jsonl` | Історія запитів | Так |
| `sessions/`, `shell-snapshots/`, `cache/` та інші | Стан під час роботи | Ні |

## На чому часто помиляються?

**Без `CLAUDE_CONFIG_DIR` файл `.claude.json` лежить не всередині `~/.claude`.** У такому разі Claude Code зберігає його в `~/.claude.json`, поруч із текою. Якщо ви почнете використовувати `CLAUDE_CONFIG_DIR=~/.claude`, Claude Code шукатиме натомість `~/.claude/.claude.json` і не знайде ваш обліковий запис. `ccam import` розв'язує це, пов'язуючи ці два файли.

**На macOS дані входу зберігаються у в'язці ключів, а не в теці.** Claude Code зберігає їх під назвою `Claude Code-credentials`, після якої йде короткий хеш шляху до теки, якщо задано `CLAUDE_CONFIG_DIR`. Тому окремі теки отримують окремі записи у в'язці ключів. Якщо в'язка ключів відмовляє в записі, Claude Code натомість використовує `.credentials.json` у теці, як описано в [його документації](https://code.claude.com/docs/en/authentication#credential-management).

**Не кожен вхід зберігається в теці.** Вхід через Claude Console без ключа API зберігається поза нею, тому окремі теки не розділяють два такі входи. Входи через claude.ai і ключі API зберігаються окремо для кожної теки.

## Де тека у Windows?

За замовчуванням це `%USERPROFILE%\.claude`, а дані входу лежать усередині неї в `.credentials.json`. Для кожного додаткового облікового запису задайте в `CLAUDE_CONFIG_DIR` іншу теку, так само як на Linux і macOS.

## Чи можуть теки мати спільні файли?

Символьні посилання працюють: Claude Code читає й записує через пов'язаний `settings.json` або теку `projects/` і зберігає посилання. Виняток становлять сервери MCP, бо вони ділять `.claude.json` з даними входу; натомість передавайте їх через `--mcp-config`.

ccam побудовано саме на цих правилах. Як він пов'язує теки, див. у розділі [спільне використання](/docs/sharing), а загальну картину описано в [посібнику з кількох облікових записів](/guides/multiple-claude-code-accounts).
