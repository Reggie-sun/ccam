Дайте кожному обліковому запису власну теку конфігурації. Claude Code бере шлях до теки зі змінної середовища `CLAUDE_CONFIG_DIR`, а в кожній теці зберігаються власні дані входу, налаштування та історія, тому кожен обліковий запис лишається авторизованим і їх можна запускати одночасно. Це можна налаштувати вручну через псевдонім оболонки або доручити ccam.

## Як налаштувати це вручну?

Цей спосіб [описано в документації Claude Code](https://code.claude.com/docs/en/authentication#log-in-with-multiple-accounts). Додайте до `~/.bashrc` або `~/.zshrc` по рядку на кожен додатковий обліковий запис:

```sh
alias claude-work='CLAUDE_CONFIG_DIR=~/.claude-work claude'
```

Відкрийте новий термінал і виконайте `claude-work`. Claude Code попросить увійти, бо тека нова. Відтоді `claude` буде вашим першим обліковим записом, а `claude-work` другим.

У Windows без WSL те саме робить функція PowerShell у вашому профілі (`notepad $PROFILE`):

```powershell
function claude-work { $env:CLAUDE_CONFIG_DIR = "$HOME\.claude-work"; try { claude @args } finally { Remove-Item Env:CLAUDE_CONFIG_DIR } }
```

## Чого бракує підходу з псевдонімами?

Для двох облікових записів він працює добре. Що варто знати:

- Кожна тека починається порожньою: ні налаштувань, ні `CLAUDE.md`, ні серверів MCP, ні агентів чи навичок. Усе потрібне ви копіюєте або пов'язуєте посиланнями й самі стежите, щоб копії не розходилися.
- Псевдоніми існують лише в інтерактивних оболонках. Скрипти, Makefile та інші програми їх не бачать.
- Сервери MCP зберігаються в `.claude.json` поруч із даними входу, тому їх не можна просто пов'язати посиланням між теками.
- Розмови лишаються в тому обліковому записі, де почалися, тому продовжити розмову в іншому обліковому записі не вийде.
- Немає нічого, що показувало б використання всіх облікових записів одразу.

## Чи можна натомість перемикати облікові записи через /login?

Так, якщо перемикатися доводиться лише зрідка. Команда `/login` у Claude Code [перемикає обліковий запис](https://code.claude.com/docs/en/quickstart) тієї теки, у якій ви працюєте. Вхід виконано лише в один обліковий запис за раз, тому під час кожного перемикання доводиться входити знову, а запустити два облікові записи паралельно не можна. Окремі теки знімають обидва обмеження.

## Як налаштувати це з ccam?

ccam автоматизує ту саму ідею й додає те, чого бракує:

```sh
curl -fsSL https://ccam.dev/install.sh | sh
ccam add personal
ccam add work --shortcut ccwork
```

Тепер `ccam personal` і `ccam work` запускають два облікові записи, як і `ccwork`, коротка команда, яку ви дали робочому обліковому запису. Це справжні програми, а не псевдоніми, тому вони працюють і в скриптах. Запустіть `ccam` без аргументів, щоб вибрати обліковий запис зі списку, або `ccam use work`, щоб зробити обліковий запис основним.

Налаштування, `CLAUDE.md`, сервери MCP і розширення спільні від початку. `ccam next --continue` продовжує розмову в іншому обліковому записі. Якщо ввімкнути спільну історію розмов, обидва облікові записи працюють з тією самою розмовою, а не з копією. `ccam usage` показує використання за 5 годин і за тиждень для всіх облікових записів одразу.

Якщо ви вже користуєтеся `~/.claude`, виконайте `ccam import` замість того, щоб додавати цей обліковий запис знову, або `ccam migrate`, щоб скопіювати його налаштування, сервери MCP і розширення до спільної групи `default`.

## Як дізнатися, який обліковий запис запущено?

У Claude Code команда `/status` показує обліковий запис, у який виконано вхід. З ccam один раз виконайте `ccam statusline install`, і рядок стану постійно показуватиме назву облікового запису та його використання, наприклад `[work] · Opus · 5h 24% · 7d 41%`.

## Чи працює це у Windows і WSL?

Claude Code працює [нативно у Windows і всередині WSL](https://code.claude.com/docs/en/setup). `CLAUDE_CONFIG_DIR` діє в обох випадках, тому у Windows без WSL достатньо псевдоніма або функції PowerShell, описаних вище. ccam теж працює у Windows нативно: установіть його в PowerShell командою `irm https://ccam.dev/install.ps1 | iex` або всередині WSL командою для Linux. Короткі команди стають `ccwork.exe`, а для спільного використання файлів, як-от `settings.json`, потрібен режим розробника ([Встановлення ccam](/docs/install)).

## Усунення проблем

**Claude Code щоразу просить увійти.** Під час першого запуску в новій теці вхід потрібен завжди. Якщо Claude Code і далі просить, термін дії входу минув або дані входу видалено: виконайте `ccam login work` (або один раз запустіть псевдонім і увійдіть).

**Сервер MCP видно лише в одному обліковому записі.** Сервери, додані всередині сеансу через `claude mcp add`, належать цьому обліковому запису, а без `-s user` — лише цій теці. Щоб сервер з'явився в усіх облікових записах, виконайте `ccam mcp import work <server>`.

**Налаштування в облікових записах різняться.** `ccam share work` виводить, що в облікового запису спільне і через яку групу; `ccam group join default work` робить спільним для нього те, що спільне в `default`, попередньо показавши, що зміниться. `ccam doctor --fix` виправляє зламані посилання й зберігає резервну копію кожного файлу, який змінює.

**Два облікові записи відкривають ту саму розмову.** Не працюйте з однією розмовою у двох облікових записах одночасно. ccam попередить, якщо ви спробуєте.

## Що вибрати?

Для двох облікових записів, коли нічого спільного не потрібно, досить псевдоніма. Якщо потрібні спільні налаштування й сервери MCP, більше облікових записів, використання всіх облікових записів на одному екрані або продовження розмов, ccam позбавить вас ручного обліку. У [порівнянні з псевдонімами](/compare/aliases) відмінності наведено поруч, а стаття [ccam та інші перемикачі облікових записів](/compare/account-switchers) розглядає інструменти, які натомість підміняють один вхід.

Чи можна вам користуватися більш ніж одним обліковим записом, залежить від умов, що діють для кожного з них. Прочитайте ці умови, перш ніж починати.

**Місця в планах Team і Enterprise.** Автоматичний вибір облікового запису (`ccam next`, `--fallback`, `ccam pick`, `n` на панелі керування, а також, щойно ви його ввімкнете, [`auto_switch`](/features/next#auto-switch)) також перемикає між місцями однієї організації Claude Team або Enterprise, що може порушувати умови Anthropic. Прочитайте [FAQ](/docs/faq#am-i-allowed-to-use-several-claude-code-accounts) і уточніть це у своїй організації та в Anthropic, перш ніж на нього покладатися.
