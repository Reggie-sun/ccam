Коли обліковий запис досягає ліміту використання (його часто називають rate limit), є два варіанти: дочекатися скидання ліміту або просто зараз продовжити ту саму розмову в іншому своєму обліковому записі. З ccam другий варіант займає одну команду, `ccam next --auto --continue`.

## Які ліміти має Claude Code?

У планах Pro і Max Claude Code має [5-годинний ліміт сеансу й тижневий ліміт](https://support.claude.com/en/articles/11145838-using-claude-code-with-your-pro-or-max-plan). Обидва ліміти спільні з Claude у браузері та застосунках, і використання зараховується до обох одночасно. Коли один із них вичерпано, Claude Code [показує повідомлення](https://code.claude.com/docs/en/errors#youve-hit-your-session-limit) на зразок «You've hit your session limit · resets 3:45pm». Зміна моделі не допоможе, бо ліміти діють на всі моделі.

## Варіант 1: дочекатися скидання

Якщо обліковий запис один, зачекайте. Останні версії Claude Code [чекають у відкритому сеансі](https://code.claude.com/docs/en/interactive-mode#wait-for-a-usage-limit-to-reset) і самі продовжують завдання після скидання ліміту. `/usage` у Claude Code показує, яку частину лімітів вашого плану ви вже використали.

## Варіант 2: одразу продовжити в іншому обліковому записі

Якщо у вас є другий обліковий запис, можна одразу продовжити ту саму розмову. Налаштуйте все один раз:

```sh
curl -fsSL https://ccam.dev/install.sh | sh
ccam add personal
ccam add work
ccam group set default --add history
ccam statusline install
```

Тепер під час роботи рядок стану показує обліковий запис і його використання за 5 годин, тож ліміт не стане несподіванкою.

Коли ліміт досягнуто, вийдіть із Claude Code (`/exit`), а потім виконайте:

```sh
ccam usage
```

```console
 1 personal  just now
   5-hour   ████████████████████ 100%  resets in 22m
   Weekly   ██████████████░░░░░░  68%  resets in 1d 9h
 2 work      just now
   5-hour   ██░░░░░░░░░░░░░░░░░░   8%  resets in 4h 12m
   Weekly   ████░░░░░░░░░░░░░░░░  19%  resets in 5d 2h
→ Most headroom: work   (open it with ccam next --auto)
```

Відкрийте розмову в обліковому записі, де найбільше запасу:

```sh
ccam next --auto --continue
```

Claude Code запуститься як `work` з останньою розмовою поточної теки, включно з усім, що було сказано досі. Спільна історія (`ccam group set default --add history` вище) зберігає її однією розмовою; без неї Claude Code копіює розмову в `work`, а ccam повідомляє, скільки токенів ця перша відповідь прочитає повторно.

З [плагіном ccam](/docs/install#claude-code-plugin) у Claude Code сеанс, що зупинився на ліміті, показує сповіщення й записує заповнене вікно, тож `ccam next --auto` не вибере цей обліковий запис знову до його скидання, а `/ccam:switch` (або `/ccam:switch work`) записує розмову для `ccam next --continue`, нічого не лишаючи на здогад.

**Місця в планах Team і Enterprise.** Автоматичний вибір (`ccam next`, `--fallback`, `ccam pick`, `n` на панелі керування, а також [`auto_switch`](/features/next#auto-switch), якщо ви його ввімкнете) також перемикає між місцями однієї організації Claude Team або Enterprise. У довідковому центрі Anthropic сказано: «Each seat on a Team plan is assigned to one named individual, and only that person may use it» (кожне місце в плані Team закріплене за однією конкретною особою, і користуватися ним може лише ця особа) та «Users can't route their work through another user's account to use that user's remaining usage» (користувачі не можуть спрямовувати свою роботу через обліковий запис іншого користувача, щоб використати залишок ліміту цього користувача) ([плани Team](https://support.claude.com/en/articles/12004354-purchase-and-manage-seats-on-team-plans#h_b8a7d07129); так само для [планів Enterprise](https://support.claude.com/en/articles/13393991-purchase-and-manage-seats-on-enterprise-plans#h_fa6b9cade0)). Тому використання автоматичного вибору між місцями може порушувати умови Anthropic. Користуватися ним там чи ні, вирішувати вам: перш ніж на нього покладатися, уточніть це у своїй організації та в Anthropic. Про особисті плани (Pro, Max) ідеться в [примітці про умови в FAQ](/docs/faq#am-i-allowed-to-use-several-claude-code-accounts).

## Чи перемикає ccam облікові записи автоматично?

Лише якщо ви це ввімкнете. Типово, поки ви працюєте, ccam не запущено: він запускає Claude Code і замінює себе ним, тож коли перемикатися, вирішуєте ви, а `ccam next --auto` вибирає обліковий запис із найменшим використанням за 5 годин, пропускає ті, що мають 100% або в які не виконано вхід, і лишається в межах однієї організації Team чи Enterprise або серед особистих планів. З `relay = true` у `config.toml` ccam натомість чекає поруч із сеансом, тож `/ccam:switch` продовжує роботу сам, зберігаючи параметри сеансу, режим дозволів і рівень зусиль. З `auto_switch = true` (Linux і macOS; експериментально) ccam ще й сам робить перемикання: коли Claude Code зупиняє сеанс на його ліміті, а інший такий самий обліковий запис має запас, ccam завершує сеанс і продовжує розмову там ([умови й витрати](/features/next#auto-switch)). Деякі інші інструменти натомість підміняють вхід у запущеному сеансі; у чому різниця, пояснює стаття [ccam та інші перемикачі облікових записів](/compare/account-switchers).

## Що варто врахувати

- Виконуйте `ccam next --continue` у тій самій теці, де працювали; розмови зберігаються окремо для кожної теки проєкту.
- Не запускайте два облікові записи на одній розмові одночасно. ccam попередить, якщо ви спробуєте.
- Без спільної історії розмова копіюється в інший обліковий запис, і дві копії далі розвиваються окремо; контрольні точки, з яких `/rewind` відновлює код, лишаються в першому обліковому записі.
- Перше повідомлення в новому обліковому записі може використати більше ліміту, ніж зазвичай, бо цей обліковий запис ще не має розмови в кеші. `ccam next --continue --brief` натомість починає його з короткого підсумку.
- Чи можна так перемикатися між обліковими записами, залежить від умов кожного облікового запису.

Усі параметри `ccam usage` і `ccam next` описано в розділі [ліміти використання](/docs/usage-limits).
