Кожен обліковий запис має власну теку, але більша частина її вмісту не мусить бути окремою. **Група** визначає, що спільно використовується і ким: кожен обліковий запис у групі пов'язує ці елементи з однією текою, `~/.local/share/ccam/groups/<group>/`, тож усі вони читають і записують ту саму копію. Токени входу ніколи не бувають спільними.

Обліковий запис може належати до кількох груп, але кожен елемент надходить лише з однієї групи. Типове налаштування — одна група для налаштувань і розширень і друга для історії розмов між двома обліковими записами:

```toml
[[group]]
name = 'default'
items = ['mcp', 'settings', 'memory', 'extensions']
members = ['personal', 'work', 'side']

[[group]]
name = 'team'
items = ['history']
members = ['work', 'side']
```

Перший доданий вами обліковий запис створює `default`, а наступні облікові записи приєднуються до неї, якщо ви не вкажете інше.

## Використання

```sh
ccam group                                        # the groups, what they share, their accounts
ccam group show default                           # items, accounts, folder and MCP servers
ccam group add team --items history --members work,side
ccam group set default --add history              # every account in default moves together
ccam group set default --remove history --fresh   # stop sharing; accounts start without it
ccam group set team --items history,memory --from work   # work's CLAUDE.md goes in first
ccam group join team personal                     # personal starts sharing team's items
ccam group join team personal --replace           # leave the group that shares them now
ccam group leave team side                        # side keeps a copy of team's items
ccam group rename team pair                       # the folder keeps its name
ccam group remove pair --leave                    # its accounts keep a copy; folder to the trash
ccam share work                                   # what work shares, and through which group
ccam --dry-run group set default --add history    # print the plan, change nothing
```

```console
$ ccam group
Group    Shares                          Accounts
default  mcp settings memory extensions  personal, work, side
team     history                         work, side

$ ccam share work
Sharing for work
  mcp         MCP servers                        group default
  settings    settings.json                      group default
  memory      global CLAUDE.md                   group default
  extensions  agents, commands, skills, plugins  group default
  history     conversation history               group team
Groups: default, team. Change them with `ccam group`.
```

Кожна команда, що переміщує дані, виводить план, запитує про кожен файл, що відрізняється від копії групи, і запитує `Proceed? [y/N]`, перш ніж щось змінити:

```console
$ ccam group set default --add history
Plan (paths in /home/me/.local/share/ccam):
personal: +history (group default)
  move     projects, history.jsonl: profiles/personal → groups/default (first content of the group)
  link     projects, history.jsonl, file-history, tasks, paste-cache: profiles/personal → groups/default
work: +history (group default)
  merge    new files in projects: profiles/work → groups/default
  conflict profiles/work/history.jsonl ↔ groups/default/history.jsonl: merge by line
  back up  projects, history.jsonl: profiles/work → profiles/work/.ccam-backup/20261023-213057
  link     projects, history.jsonl, file-history, tasks, paste-cache: profiles/work → groups/default
  Note: projects: 1 file differs from the group's copy (-home-me-code-app/s1.jsonl); the group's is kept, the account's stays in profiles/work/.ccam-backup/20261023-213057/projects
Proceed? [y/N]
```

Ті самі зміни доступні на вкладці **Groups** [панелі керування](/features/dashboard), а `s` на обліковому записі вибирає його групи.

## Елементи

| Елемент | Що охоплює |
| --- | --- |
| `mcp` | сервери MCP, через `mcp.json` групи ([Спільні сервери MCP](/features/mcp)) |
| `settings` | `settings.json` |
| `memory` | глобальний `CLAUDE.md` |
| `extensions` | `agents/`, `commands/`, `skills/`, `plugins/`, `output-styles/`, `rules/` |
| `history` | `projects/` і `history.jsonl`, щоб інший обліковий запис міг виконати `--continue` |

Елемент, який не спільно використовує жодна група облікового запису, залишається у власній теці облікового запису.

## Команди та параметри

| Команда | Дія |
| --- | --- |
| `ccam group` або `ccam group list` | показати групи |
| `ccam group show <group>` | що спільно використовує група, її облікові записи, її тека й сервери MCP |
| `ccam group add <group> --items <items> [--members <accounts>]` | створити групу; елементи її облікових записів переміщуються до неї |
| `ccam group set <group> --add <items> \| --remove <items> \| --items <items>` | змінити, що спільно використовує група, для кожного облікового запису в ній |
| `ccam group join <group> <account>...` | додати облікові записи до групи |
| `ccam group leave <group> <account>...` | вивести облікові записи з групи; кожен зберігає копію, зокрема сервери MCP |
| `ccam group rename <group> <new-name>` | перейменувати лише в конфігурації |
| `ccam group remove <group> [--leave]` | видалити групу |

| Параметр | Дія | За замовчуванням |
| --- | --- | --- |
| `--from <account>` | `add`, `set`: обліковий запис, чия копія першою потрапляє до групи | обліковий запис за замовчуванням, потім за номером |
| `--replace` | `join`: спершу вийти з груп, які спільно використовують ті самі елементи | вимкнено |
| `--fresh` | облікові записи, що припиняють спільно використовувати елемент, починають без нього замість копії (імпортована тека однаково зберігає копію) | вимкнено |
| `--leave` | `remove`: спершу вивести облікові записи групи | потрібен, коли в групі є облікові записи |
| `--prefer <group\|mine\|merge>` | як вирішувати конфлікти | запитувати; з `--yes` — варіант за замовчуванням для кожного файлу |
| `-y`, `--yes` | виконати без запитань; конфлікти вирішуються згідно з `--prefer` | вимкнено |
| `--dry-run` (глобальний) | вивести план, нічого не змінювати | вимкнено |

Облікові записи вказують за назвою або за номером, елементи — списком через кому. `ccam add` приймає `--group <group>` (можна повторювати) або `--no-group`.

## Як це працює

Задіяні файли:

- `~/.config/ccam/config.toml`: записи `[[group]]`: `name`, `items`, `members` і, коли назва теки відрізняється, `dir`.
- `~/.local/share/ccam/profiles/<name>/`: `CLAUDE_CONFIG_DIR` облікового запису.
- `~/.local/share/ccam/groups/<folder>/`: спільні копії.

Під час читання `config.toml` групи кожного облікового запису зводяться до однієї теки на елемент. Для п'яти облікових записів це займає близько 25 µs, тож запуск і далі читає лише `config.toml`. Конфігурація, в якій обліковий запис отримав би елемент із двох груп, є помилкою, і нічого не запускається, доки її не виправлено.

Зміна працює з копією конфігурації:

1. Команда редагує копію (`AddGroup`, `SetGroupItems`, `JoinGroup` …), перевіряючи правила.
2. `internal/group` порівнює стару й нову конфігурацію і для кожного облікового запису, чиї елементи змінюються, будує план через `share.Build`. Плани будуються один за одним, і кожен бачить, що попередні покладуть до тек груп, тож лише перший обліковий запис переміщує туди свою копію. Перша копія береться з теки групи, якщо в ній уже щось є, потім із `--from`, потім з облікового запису за замовчуванням, а потім з інших за номером.
3. ccam відмовляє, якщо один із цих облікових записів запущено, хоч би як було запущено Claude Code (``work is running; quit Claude Code there first, then change the groups (`ccam agents` lists the sessions)``), а у Windows без режиму розробника — якщо для файлу знадобилося б посилання.
4. Конфлікти вирішуються через запитання або через `--prefer`, план виводиться, і ccam запитує підтвердження.
5. Безпосередньо перед збереженням ccam перевіряє ще раз: обліковий запис, що запустився, поки запитання чекали, зупиняє зміну, як і зміна тих самих груп в іншому ccam (`the groups changed while this plan waited; nothing was moved, make the change again`). Нова конфігурація зберігається до того, як щось переміщується, а зміну записано в `~/.local/state/ccam/group-change.json`. Якщо крок зупиняється посередині, запис лишається: `ccam doctor --fix` завершує зміну в її порядку, з наданими вами відповідями, зокрема кроки MCP, а доти не починається жодна інша зміна груп (``the last change of groups stopped halfway; finish it with `ccam doctor --fix` first``).
6. Кроки MCP виконуються першими. Коли облікові записи виводять розширення з групи, списки плагінів групи спрямовуються на теку групи там, де їхні шляхи проходять через теку облікового запису (`group plugin lists:` у плані). Потім плани виконуються по черзі. Кожен крок переміщує дані до групи або до теки резервних копій; лише файли, які група вже має байт у байт, відкидаються замість резервного копіювання.

`share.Layout` — це список дозволених шляхів, які охоплює кожен елемент. Усе, чого в ньому немає, ніколи не може потрапити до групи. `share.Never` називає `.credentials.json` і `.claude.json`, і `Build` зупиняється з внутрішньою помилкою, якщо хтось із них колись з'явиться в структурі. Елемент `mcp` не має шляхів: список серверів зберігається всередині `.claude.json`, тож [спільне використання MCP](/features/mcp) працює через `mcp.json` групи.

Ось що відбувається з однією текою, `projects/`, коли `side` починає спільно використовувати історію, а група вже має вміст:

<!-- motion:share-on -->

Якщо в групі за цим шляхом ще нічого немає, обліковий запис першим спільно використовує його, і його теку переміщують туди як є. Інакше кожен файл, якого бракує групі, переміщується до групи, а файли, що є з обох боків, залишаються в теці облікового запису, тож версія групи зберігається. Файли, ідентичні файлам групи, відкидаються, а план називає ті, що відрізняються (`Note: projects: 1 file differs from the group's copy (…); the group's is kept, the account's stays in …`). Потім тека облікового запису переходить до `.ccam-backup/<time>/` усередині теки облікового запису, а на її місце стає посилання. Якщо запис групи сам є посиланням на власний запис облікового запису, що приєднується, вміст облікового запису потрапляє до групи на його місце. Файли розмов мають назви за ідентифікатором сеансу, тож історії з кількох облікових записів об'єднуються без конфліктів. Реєстри `plugins/` зберігають абсолютні шляхи через теку облікового запису; ccam спрямовує їх на теку групи й об'єднує записи облікового запису з реєстром, який група вже має.

Вихід із групи змінює посилання у зворотний бік:

<!-- motion:share-off -->

ccam спершу копіює поточний вміст групи до `.ccam-backup/incomplete-<name>` у теці облікового запису й замінює посилання лише тоді, коли копію завершено, тож перерване копіювання лишає посилання на місці, а `ccam doctor --fix` копіює знову (план такого завершення показує `restore <entry>: … (copied back from the group before a stop)`). Він видаляє посилання, лише якщо воно досі вказує всередину теки груп так само, як під час складання плану; шлях, який відтоді змінився, як-от справжній файл на місці посилання, лишається як є, і зміна зупиняється. З `--fresh` копіювання пропускається. Група зберігає свій вміст для інших облікових записів. Обліковий запис, що переносить елемент до групи, тека якої ще порожня, приносить копію того, що бачив, тож зберігає свої файли; ця копія готується в `<group>/.ccam-incomplete-<name>`, доки не буде завершена. Обліковий запис, що припиняє спільно використовувати MCP, зберігає сервери групи: вони потрапляють до його власного `.claude.json` (резервна копія зберігається), поруч із його власними серверами з тими самими назвами, які лишаються. З `--fresh` план натомість перелічує сервери, які перестануть завантажуватися. Повторне приєднання видаляє копії, яких ніхто не змінював. Вихід з `extensions` також спрямовує списки плагінів групи на теку групи там, де їхні шляхи проходили через теку облікового запису, що виходить; для інших облікових записів вони означають те саме.

Окремий файл, що є з обох боків із різним вмістом, є конфліктом:

<!-- motion:share-conflict -->

Ви вибираєте для окремих файлів, як-от `settings.json`; у теках лишається копія групи, а план називає файли, що відрізняються. `history.jsonl` пропонує `merge by line`, `keep group` і `use mine`, з об'єднанням на першому місці. Інші файли `.json` пропонують `keep group`, `use mine` і `merge JSON`. Усе інше пропонує `keep group` і `use mine`. `merge JSON` рекурсивно об'єднує об'єкти, з'єднує масиви без дублікатів і зберігає значення групи, коли обидві сторони задають той самий ключ по-різному, тож інші облікові записи не бачать змін. Кожен варіант, крім `keep group`, спершу зберігає копію групи в `.ccam-backup/<time>/group/` облікового запису. Ваш власний файл завжди потрапляє до резервної копії.

Під час кожного запуску `share.Check` порівнює кожен шлях у структурі з групами облікового запису, використовуючи лише `lstat` і `readlink`. Відсутнє посилання створюється одразу. Справжній файл там, де має бути посилання, посилання не туди або застаріле посилання зупиняє запуск і вказує на `ccam doctor --fix`.

### Перейменування, видалення та старий формат

- `ccam group rename` змінює лише конфігурацію. Тека зберігає свою назву, а група записує її як `dir`, тож нічого не переміщується й нічого не може загубитися.
- `ccam group remove` не видаляє групу з обліковими записами, якщо ви не додасте `--leave`. Тоді кожен обліковий запис зберігає копію, а тека переходить до `~/.local/share/ccam/trash/`, якщо її не використовує інша група.
- До появи груп `config.toml` зберігав таблицю `[profile.share]` для кожного облікового запису. ccam читає цей формат як групи, нічого не переміщуючи. Під час першого збереження він записує новий формат і зберігає старий файл як `config.toml.bak`. Елементи, які спільно використовують ті самі облікові записи, стають однією групою з назвою теки; решта отримують назви на кшталт `default-history` і далі використовують ту саму теку.

### У Windows

Windows створює символьні посилання лише в режимі розробника (Параметри > Система > Для розробників) або для адміністратора. Без цього права спільна тека стає точкою з'єднання каталогів (junction), яка для Claude Code працює так само. Спільний файл (`settings.json`, `CLAUDE.md`, `history.jsonl`) може бути лише символьним посиланням, тому зміна групи, якій воно потрібне, відхиляється ще до того, як щось переміститься. З тієї самої причини перший `ccam add` там створює групу `default` лише з `mcp` і `extensions` і повідомляє про це, а `ccam add --group` до групи, яка спільно використовує налаштування, пам'ять або історію, відхиляється.

## Безпека та граничні випадки

- **Запущені облікові записи.** Зміна відхиляється, поки Claude Code працює від імені одного з облікових записів, які вона переміщує, бо сеанс і далі записує в ці файли, незалежно від того, чи запустив його ccam (звичайний `claude`, IDE, фонові сеанси). Перевірка повторюється безпосередньо перед збереженням. Вихід і приєднання стосуються лише названого облікового запису; вихід з `extensions` також переписує шляхи в списках плагінів групи, не змінюючи того, що вони означають для інших. `--dry-run` усе одно виводить план.
- **Резервні копії.** Кожен план отримує власну теку `.ccam-backup/<time>/` у теці облікового запису. ccam ніколи їх не видаляє.
- **Ваші власні посилання.** Якщо шлях уже є посиланням, яке ви створили, наприклад на репозиторій dotfiles, а група порожня, ccam копіює ціль посилання до групи, а саме посилання переміщує до резервної копії. Ціль не змінюється.
- **Імпортовані теки.** Обліковий запис, зареєстрований на місці через `ccam import` (наприклад, `~/.claude`), змінюється на місці, тож звичайний `claude` теж бачить зміну; план про це повідомляє. Виходячи з групи, він завжди зберігає копію, навіть із `--fresh`, і `ccam remove` саме так виводить його з груп, перш ніж забути обліковий запис. Поки він входить до групи, його спільні файли лежать у теці групи, тож видаліть обліковий запис (або вийдіть із груп), перш ніж видаляти `~/.local/share/ccam`.
- **Два облікові записи в одній теці.** Облікові записи, які спільно використовують історію, записують ті самі файли. Коли другий запускається в теці, де вже працює перший, ccam попереджає й запитує.
- **Ручні зміни.** Учасника, який не є обліковим записом, ccam ігнорує, а `ccam doctor` повідомляє про нього. Назви `local`, `on`, `off` і `none` не можна використовувати як назви груп.
