Claude Code зберігає фонові сеанси (`claude --bg`, перегляд агентів) окремо для кожного облікового запису: `claude agents` показує лише сеанси того облікового запису, від імені якого його запущено. `ccam agents` опитує всі облікові записи одночасно й показує їхні сеанси разом, а `ccam attach <id>` відкриває фоновий сеанс від імені того облікового запису, який його запустив.

## Використання

```sh
ccam work --bg "fix the flaky test"   # start one in the background, as work
ccam agents                           # every account's sessions
ccam agents --all                     # also finished background sessions
ccam agents --json                    # for scripts
ccam attach 49ec0028                  # open it, as the account that started it
ccam attach 49ec                      # a unique start of the id is enough
```

```console
$ ccam agents
Account   ID        Name   State           Folder      Started
work      -         -      open (busy)     ~/code/web  just now
personal  49ec0028  probe  blocked, idle   ~/code/app  12m ago
Open a background session with `ccam attach <id>`.
```

`State` — це стан фонового сеансу (`working`, `blocked`, `done`, `failed`, `stopped`) і те, що робить його процес (`busy`, `waiting`, `idle`); відкритий інтерактивний сеанс показує `open`.

## Параметри

| Параметр | Дія | За замовчуванням |
| --- | --- | --- |
| `--all` | Показувати також фонові сеанси, які завершилися, зазнали невдачі або були зупинені | вимкнено |
| `--json` | Вивести сеанси у форматі JSON, кожен з `account`, до якого він належить | вимкнено |

`ccam attach <id> [claude args]` передає аргументи після ідентифікатора до `claude attach`. З `--dry-run` він виводить команду.

## Як це працює

1. Для кожного облікового запису ccam запускає `claude agents --json` (з `--all`, якщо цей параметр задано) з `CLAUDE_CONFIG_DIR` облікового запису, для всіх одночасно, кожен у межах 15 секунд. Так читається власний список сеансів облікового запису, а фонова служба Claude Code не запускається.
2. Кожен запис отримує назву облікового запису, а список сортується за часом запуску, від найновіших. Обліковий запис, який не відповідає, називається в стандартному потоці помилок і пропускається, після чого ccam завершується з кодом 1, щоб скрипт не сприйняв збій за порожній список.
3. `ccam attach` шукає `jobs/<id>` у теці кожного облікового запису, де Claude Code зберігає фоновий сеанс, і запускає `claude attach <id>` від імені цього облікового запису так само, як `ccam <name>` запускає Claude Code.

## Безпека та граничні випадки

- Ідентифікатори фонових сеансів належать одному обліковому запису: `claude attach`, запущений від імені іншого облікового запису, їх не знайде, і саме це розв'язує `ccam attach`.
- Два облікові записи можуть мати сеанси, ідентифікатори яких починаються однаково; тоді `ccam attach` називає обидва й просить ввести більшу частину ідентифікатора.
- ccam передає свої спільні сервери MCP до Claude Code через `--mcp-config=<file>` в одному аргументі, який приймають `claude agents` і `claude attach`; фонові сеанси продовжують використовувати цей файл після перезапуску.
- Фонова служба облікового запису з ключем API бере ключ з оболонки, яка її запустила. Запускайте перший фоновий сеанс такого облікового запису через ccam (`ccam gw --bg …`), щоб служба отримала ключ.
