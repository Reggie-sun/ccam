`ccam usage` показує, яку частку 5-годинного ліміту, тижневого ліміту й власного тижневого ліміту кожної моделі (наприклад, Fable) використав кожен обліковий запис, у вигляді смужки для кожного ліміту з часом до його скидання. Використовуйте цю команду перед початком довгого завдання або коли Claude Code попереджає, що ліміт близько, щоб побачити, в якого облікового запису ще є запас. `ccam statusline` — це команда рядка стану для Claude Code: вона показує назву облікового запису й використання всередині Claude Code і зберігає числа для `ccam usage`. Щоб побачити токени й орієнтовну вартість, які стоять за цим використанням, `ccam ccusage` запускає [ccusage](https://ccusage.com) для розмов усіх облікових записів ([нижче](#tokens-and-costs-ccam-ccusage)).

## Використання

```sh
ccam usage                  # every account, once
ccam u                      # the same, shorter
ccam usage --watch          # redraw every 60 seconds until Ctrl+C
ccam usage --watch=10       # redraw every 10 seconds
ccam usage -v               # add where the numbers came from
ccam usage --json           # machine-readable, one object per account
ccam usage --source cache   # saved numbers only, no network
ccam usage --refresh        # also renew expired logins of accounts not running
ccam usage --source claude  # let Claude Code look it up: ccam sends no token
ccam statusline install     # set the status line in every account's settings.json
```

```console
$ ccam usage
 1 personal  9h 36m ago (cached)
   5-hour   ░░░░░░░░░░░░░░░░░░░░   0%
   Weekly   ██████████████░░░░░░  70%  resets in 2d 16h
   Fable    ██░░░░░░░░░░░░░░░░░░  12%  resets in 2d 16h
 2 work      just now (cached)
   5-hour   █████░░░░░░░░░░░░░░░  24%  resets in 2h 29m
   Weekly   ████████░░░░░░░░░░░░  41%  resets in 3d 11h
   Fable    ███████████░░░░░░░░░  55%  resets in 5d 2h
 3 side      access token expired; `ccam side` renews it when it starts
→ Most headroom: personal   (open it with ccam next --auto)
```

Кожен обліковий запис отримує рядок із його номером, назвою та давністю чисел; `(cached)` означає, що вони взяті зі збереженого файлу, а не з кінцевої точки. Під ним для кожного ліміту є рядок зі смужкою з 20 клітинок, відсотком і часом до скидання вікна: `5-hour`, `Weekly` (усі моделі), потім власне тижневе вікно кожної моделі, наприклад `Fable`. Вікно, якого обліковий запис не має, показує `-`. Відсоток стає жовтим від 80% і червоним на 100%. Вікно, про заповнення якого повідомив Claude Code, коли відхилив запит на ліміті використання, показує 100% до свого скидання, хоч би що казали збережені числа (див. [запис про ліміт](#the-limit-record)). У терміналі всі облікові записи з'являються одразу як `fetching…`, і їхні рядки малюються, щойно обліковий запис відповідає. Останній рядок називає обліковий запис, який [`ccam next --auto`](/features/next) вибрав би за тими самими правилами (`auto_max_usage`, `auto_strategy`, запущені сеанси, лише облікові записи організації останнього використаного облікового запису, якщо не задано `cross_org`, пропуск кожного вікна на 100%, тож обліковий запис із вичерпаним тижнем ніколи не називається), і з'являється лише тоді, коли у вас більше одного облікового запису. За стратегії `headroom`, що діє за замовчуванням, він має вигляд `→ Most headroom: <name>`; з `expiring` або `balance` він наводить причину, наприклад `→ next --auto picks personal: its 5-hour window resets first, in 1h 12m (40% of its 5 hours used)`.

**Місця в планах Team і Enterprise.** Автоматичний вибір (`ccam next`, `--fallback`, `ccam pick`, `n` на панелі керування, а також [`auto_switch`](/features/next#auto-switch), якщо ви його ввімкнете) також перемикає між місцями однієї організації Claude Team або Enterprise. У довідковому центрі Anthropic сказано: «Each seat on a Team plan is assigned to one named individual, and only that person may use it» (кожне місце в плані Team закріплене за однією конкретною особою, і користуватися ним може лише ця особа) та «Users can't route their work through another user's account to use that user's remaining usage» (користувачі не можуть спрямовувати свою роботу через обліковий запис іншого користувача, щоб використати залишок ліміту цього користувача) ([плани Team](https://support.claude.com/en/articles/12004354-purchase-and-manage-seats-on-team-plans#h_b8a7d07129); так само для [планів Enterprise](https://support.claude.com/en/articles/13393991-purchase-and-manage-seats-on-enterprise-plans#h_fa6b9cade0)). Тому використання автоматичного вибору між місцями може порушувати умови Anthropic. Користуватися ним там чи ні, вирішувати вам: перш ніж на нього покладатися, уточніть це у своїй організації та в Anthropic. Про особисті плани (Pro, Max) ідеться в [примітці про умови в FAQ](/docs/faq#am-i-allowed-to-use-several-claude-code-accounts).

Обліковий запис без входу показує `not logged in → ccam login <name>`, а обліковий запис із ключем API — `no limits (API)`. Прострочений токен доступу показує ``access token expired; `ccam <name>` renews it when it starts``, над збереженими числами, якщо вони є: Claude Code оновить його під час наступного запуску. Вхід, термін дії якого сплив повністю, бо сплив його токен оновлення або Claude Code очистив його після того, як сервер його відхилив, показує `` login expired → `ccam login <name>` ``.

Після `ccam statusline install` Claude Code показує рядок на кшталт `[work] · Opus · 5h 24% · 7d 41%`.

## Параметри

| Параметр | Дія | За замовчуванням |
| --- | --- | --- |
| `--json` | Вивести звіти у форматі JSON: `name`, `slot`, `status`, `limits` (з `credits`, коли в облікового запису ввімкнено кредити використання), `source`, `at`, `error`, а також `limited` і `limited_windows`, коли запис про ліміт встановлює вікна на 100%. Без облікових записів виводить `[]` | вимкнено |
| `--watch[=N]` | Перемальовувати кожні `N` секунд, доки ви не натиснете Ctrl+C. Сам `--watch` або значення 0 чи менше означає 60. Значення ставиться після `=`: `--watch 10` відхиляється з підказкою | вимкнено |
| `-v`, `--verbose` | Додати під кожним обліковим записом рядок `source:`: звідки взялися його числа (кінцева точка використання, Claude Code, рядок стану, збережений файл або ліміт використання, про який повідомив Claude Code). Коли поверх чисел лежить запис про ліміт, слідом іде рядок на кшталт `Weekly full: Claude Code reported the usage limit 1h 0m ago, so 100% until the reset` | вимкнено |
| `--no-cache` | Ігнорувати 60-секундний кеш і знову запитати кінцеву точку | вимкнено |
| `--source live\|claude\|cache` | `live` запитує кінцеву точку з токеном облікового запису; `claude` доручає пошук Claude Code (нижче); `cache` показує лише збережені числа | `usage_source`, інакше `live` |
| `--refresh` | Оновлювати прострочені токени доступу лише для облікових записів, які не запущено. Оновлення може тривати до 30 секунд | вимкнено |
| `--dry-run` | Приймається: `ccam usage` не змінює нічого, крім власного кешу. Відхиляється разом із `--refresh`: `--dry-run cannot be combined with --refresh, which rewrites login tokens` | вимкнено |

Будь-яке інше значення `--source` завершується помилкою `--source must be live, claude or cache`.

### Використання через сам Claude Code

З `usage_source = "claude"` угорі `config.toml` (над першим `[[group]]`, `[[profile]]` або `[[folder]]`) або з `--source claude` ccam узагалі не читає токен входу. Для кожного облікового запису він запускає `claude -p --input-format stream-json --output-format stream-json --verbose --safe-mode --no-session-persistence` у теці облікового запису й надсилає у стандартний ввід запит Claude Code `get_usage` (Claude Code 2.1.270 або новіший); Claude Code шукає використання за власним входом і відповідає 5-годинним, тижневим і модельними вікнами. `--safe-mode` не дає запуститися хукам, серверам MCP і плагінам облікового запису, а сеанс не зберігається. Кожен обліковий запис потребує запуску Claude Code, приблизно секунду, тому це джерело повільніше за `live`; облікові записи опитуються одночасно, кожен у межах 20 секунд, і кеш на 60 секунд діє як завжди. Вхід, токен доступу якого прострочено або спливає протягом 5 хвилин, отримує 50 секунд, бо Claude Code оновлює його під час запуску, а перерване оновлення може втратити вхід. Запит, від якого відмовилися, просить Claude Code завершитися сигналом SIGTERM, щоб той завершив розпочате оновлення (у Windows такого сигналу немає; там його зупиняють). Вхід, термін дії якого сплив повністю, показує `` login expired → `ccam login <name>` `` без запуску Claude Code. Claude Code позначає цей запит як експериментальний, тож якщо він перестане відповідати, ccam покаже збережені числа, а `ccam doctor` про це повідомить. Коли Claude Code відповідає, що його власний запит не вдався, ccam показує збережені числа з `the usage endpoint gave Claude Code no usage (it may be refusing lookups for now)`, а не план без лімітів. `--dry-run` не запускає Claude Code (той пише в теку облікового запису) і показує збережені числа. `usage_source` приймає `live` або `claude`; `cache` — лише варіант для `--source`. `ccam usage` не приймає аргументів.

`ccam statusline` читає JSON рядка стану Claude Code зі стандартного введення. Його єдиний параметр — `--wrap <command>`: наявна команда рядка стану, до першого рядка виводу якої додається назва облікового запису. `ccam statusline install` не має параметрів. Обидві команди відхиляють `--dry-run` з повідомленням `` --dry-run is not supported by `ccam statusline`; nothing was changed ``.

## Токени й вартість: `ccam ccusage`

`ccam usage` показує, яку частку кожного ліміту використав обліковий запис. [ccusage](https://ccusage.com) натомість рахує токени й орієнтовну вартість у журналах розмов Claude Code. Сам по собі він шукає журнали Claude Code лише в `~/.claude` і `~/.config/claude` (або в теках, заданих у `CLAUDE_CONFIG_DIR`), тому з облікових записів ccam бачить щонайбільше один, імпортований на місці в `~/.claude`. `ccam ccusage` запускає його, задавши в `CLAUDE_CONFIG_DIR` теки всіх облікових записів, у яких є розмови, тож один звіт охоплює їх усі:

```sh
ccam ccusage                           # every account, ccusage's daily report
ccam ccusage daily --breakdown         # cost per model
ccam ccusage claude monthly --json     # Claude Code alone, as JSON
ccam ccusage -a work blocks --active   # one account's current 5-hour block
ccam ccusage -a work,side weekly       # these accounts, and any that share their history
```

ccam спершу читає власні параметри: `-a` (`--account`) приймає назви або номери облікових записів через кому чи повторенням параметра, а `--dry-run` виводить команду замість того, щоб її виконати. Починаючи з першого аргументу, що не належить до цих параметрів, усе передається ccusage без змін; `ccam ccusage -- --help` показує власну довідку ccusage. ccam запускає встановлений `ccusage`, інакше `bun x ccusage`, інакше `npx ccusage@latest`; два останні завантажують його з npm. Якщо немає жодного з них, ccam радить установити Node.js, Bun або ccusage. На Linux і macOS ccusage займає місце ccam; у Windows ccam чекає на нього й завершується з його кодом виходу. Усередині WSL ccam пропускає `ccusage`, `bun` або `npx` на диску Windows, бо такий файл запустився б як програма Windows без тек облікових записів.

- Звіт охоплює облікові записи, у теках яких є розмови (тека `projects`). Розмова, яку облікові записи спільно використовують через групу, рахується один раз.
- З `-a` обліковий запис, який спільно використовує свою історію через групу, тягне за собою розмови всієї групи, і ccam каже, чиї саме: `ccam: work shares its conversation history with personal, so the report counts their conversations too`.
- `blocks` показує 5-годинні вікна, а в кожного облікового запису вони свої, тож для цього звіту вкажіть один обліковий запис, як вище.
- ccusage також звітує про інші інструменти для програмування, які знаходить, наприклад Codex, якщо ви не вкажете один із них: `ccam ccusage claude daily` показує лише Claude Code.
- Коли ccusage запущено через ccam, він читає свої налаштування (`ccusage.json`) лише з `./.ccusage` і тек облікових записів. `--config` вказує інший файл: `ccam ccusage daily --config ~/.config/claude/ccusage.json`.
- ccusage прочитав би теку, шлях до якої містить кому, як дві теки, тому ccam відмовляється її брати й називає обліковий запис; залиште цей обліковий запис поза звітом за допомогою `-a`.
- `ccusage` — це команда ccam, тому обліковий запис із назвою ccusage запускається через `ccam run ccusage`; `ccam doctor` про це повідомляє.

## Як це працює

Числа, які показує `ccam usage`, надходять із двох джерел: незадокументованої кінцевої точки використання Anthropic, `GET https://api.anthropic.com/api/oauth/usage`, яку викликають із власним входом кожного облікового запису, і значень, які Claude Code передає своїй команді рядка стану. Усе це міститься в `internal/usage`.

1. `cli.usageCmd` завантажує `config.toml` і будує по одному `usage.Account` на обліковий запис: його теку `~/.local/share/ccam/profiles/<name>/`, його позначки сеансів (разом із власними записами Claude Code у теці облікового запису вони показують, чи він запущений) і чи імпортовано його на місці.
2. `Fetcher.FetchAll` запускає по одній горутині на обліковий запис. Усі вони використовують один `http.Client`, тож з'єднання з кінцевою точкою використовуються повторно. Встановлення з'єднання може тривати 2 с, а кожен обліковий запис загалом має 3 с. Клієнт не переходить за переспрямуваннями, бо переспрямування надіслало б токен деінде, і читає не більше 1 МБ відповіді.
3. Щойно кожен обліковий запис завершує, його рядок перемальовується. Обліковий запис, який зазнає невдачі або не відповідає вчасно, переходить на збережені числа, тож один повільний обліковий запис ніколи не затримує інших.

Кожен обліковий запис звертається до кінцевої точки у власній горутині; той, що перевищує час очікування, натомість показує збережені числа.

<!-- motion:usage-fetch -->

`personal` і `work` відповідають вчасно й показують актуальні числа. `side` відповідає довше за 3 с, тож `fallback()` натомість показує його збережені числа. `usage.Table()` малює блок для кожного облікового запису, а `usage.Best()` вибирає обліковий запис, названий в останньому рядку.

Для одного облікового запису `Fetcher.Fetch` виконує такі перевірки по черзі:

<!-- motion:usage-cache -->

1. З `--source cache` він одразу переходить до `fallback()`.
2. Якщо не задано `--no-cache`, актуальний результат у `~/.local/state/ccam/usage/<name>.json`, виміряний менш ніж 60 секунд тому (`CacheTTL`), використовується з оцінкою на поточний момент: вікно, яке відтоді скинулося, показує 0%, а файл, датований пізніше за час годинника, не вважається свіжим. Два запуски `ccam usage` поспіль коштують один запит на обліковий запис.
3. `readCredentials()` читає `.credentials.json` (або в'язку ключів macOS), не змінюючи його, і декодується лише ключ `claudeAiOauth`. Відсутність входу за підпискою означає `not logged in` або `no limits (API)`, коли `.claude.json` містить ключ API. Вхід, токен оновлення якого прострочено або який очистив Claude Code, є `` login expired → `ccam login <name>` `` і не запитується.
4. Прострочений токен доступу не використовується. Без `--refresh` обліковий запис показує свої збережені числа з ``access token expired; `ccam <name>` renews it when it starts``.
5. Інакше ccam викликає кінцеву точку. 401 або 403 вважається простроченим входом (`login expired: authentication failed (401)`), будь-який інший статус або тіло, яке не вдається прочитати, вважається помилкою, і в обох випадках використовуються збережені числа. Запит, перерваний через Ctrl+C, повідомляє `cancelled`. 429 означає, що до кінцевої точки звертаються надто часто: ccam записує `<name>.pause` із часом наступного запиту (`Retry-After` або 5 хвилин, але не більше години), показує збережені числа з `rate limited by the usage endpoint; asking again after 15:10` і до цього часу не звертається до кінцевої точки для цього облікового запису, навіть з `--no-cache`. Негайний повтор лише продовжив би обмеження.
6. Коректна відповідь записується до `<name>.json` разом із часом вимірювання.

`fallback()` бере найновіший збережений запит (`<name>.json` або `<name>.claude.json` із запитів через Claude Code) і, коли `<name>.statusline.json` записано пізніше, накладає поверх нього 5-годинне й тижневе вікна рядка стану; вікна моделей, яких рядок стану не має, лишаються такими, як їх зберіг запит. Перш ніж показати збережені числа, він перевіряє час скидання кожного вікна: вікно, яке скинулося після збереження чисел, показує 0%, бо старий відсоток уже не актуальний. Саме тому `personal` вище показує `0%` без часу скидання.

Кінцева точка має два формати відповіді. Новіший містить масив `limits` із записами `session` (5-годинний), `weekly_all` і `weekly_scoped` (для окремих моделей). Старіший містить об'єкти `five_hour`, `seven_day`, `seven_day_opus` і `seven_day_sonnet`. `ParseLive` читає обидва: масив `limits` має пріоритет, а старі об'єкти доповнюють те, чого він не охоплює. Тіло без жодних лімітів вважається зміною формату, про яку повідомляє `ccam doctor`.

### Запис про ліміт

Коли Claude Code зупиняє хід на ліміті використання, хук [плагіна ccam](/docs/install#claude-code-plugin) читає відхилений запит із розмови: яке вікно заповнилося (5-годинне, тижневе, Opus чи Sonnet) і коли воно скинеться. Він записує це до `~/.local/state/ccam/usage/<name>.limit.json`. `Fetch` накладає запис поверх усього іншого, що знає, з кожного джерела: кожне вікно в ньому вважається заповненим на 100% до свого скидання, хоч би якими старими чи низькими були збережені числа, тож `ccam next --auto`, `ccam pick`, `--fallback` і [`auto_switch`](/features/next#auto-switch) не виберуть цей обліковий запис знову до того часу. Якщо більше нічого не відомо, обліковий запис показує лише запис (`source: the usage limit Claude Code reported` з `-v`). Сеанси, за якими ніхто не сидить (`-p`, фонові сеанси), запису не створюють, як і зупинка організацією (вичерпане використання, група з лімітом $0), яку її адміністратори можуть зняти будь-коли. `ccam login` в інший обліковий запис Claude скидає запис; видалення файлу теж його очищує.

### Оновлення токенів

Токени оновлення ротуються: оновлення видає новий токен оновлення й робить старий недійсним. Якби ccam оновив вхід, поки Claude Code працює від імені того самого облікового запису, той сеанс було б виведено із системи. Тому `ccam usage` читає токени й ніколи їх не записує, якщо ви не передасте `--refresh`. Тоді `Fetcher.refresh`:

1. відхиляє облікові записи, зареєстровані на місці через `ccam import`, бо звичайний `claude` може використовувати цей вхід без відома ccam;
2. відхиляє входи, збережені у в'язці ключів macOS;
3. бере файл блокування `~/.local/state/ccam/locks/profile-<name>.refresh.lock`, тож два процеси ccam ніколи не оновлюють той самий токен двічі; поки його утримують, обліковий запис показує `token not renewed: another ccam is using this login right now (a refresh, rename, remove or logout)`. `ccam rename`, `remove` і `logout` теж його беруть і відмовляються працювати, поки триває оновлення;
4. під блокуванням відмовляє, якщо запущено сеанс облікового запису, хоч би як його було запущено (через ccam, звичайним `claude`, з IDE або як фоновий сеанс разом із демоном за ним, який сам оновлює вхід), і пропускає запит, якщо інший процес уже оновив токен;
5. нічого не надсилає, поки Claude Code утримує власні блокування оновлення в теці облікового запису (`.oauth_refresh.lock`, `<folder>.lock`): саме тоді Claude Code оновлює цей вхід;
6. надсилає токен оновлення до кінцевої точки токенів і чекає на відповідь до 30 секунд — стільки, скільки Claude Code дає власним оновленням. Уже надісланий запит ніколи не переривається, навіть через Ctrl+C, бо сервер міг уже змінити токен оновлення, і лише його відповідь ще утримує вхід: Ctrl+C або сигнал розриву завершує інші запити, а ccam виходить (з кодом 130 після Ctrl+C), щойно відповідь збережено;
7. зберігає під блокуванням запису Claude Code (`.storage-write.lock`) і змінює лише поля токенів у `.credentials.json` у тому вигляді, який він має на той момент: те, що Claude Code тим часом записав (вхід MCP), лишається, вхід, який Claude Code тим часом оновив, зберігається, а вихід ніколи не скасовується. Коли відповідь повідомляє строк дії нового токена оновлення, він зберігається як `refreshTokenExpiresAt`, як це робить Claude Code.

Оновлення, яке не вдалося, пояснює чому — у рядку облікового запису або над його збереженими числами: наприклад, `token not renewed: a session is running` або `login may be lost: …`, коли запит надіслано, але його відповідь не вдалося використати чи зберегти, з порадою виконати `ccam login <name>`, якщо Claude Code потім попросить вас увійти.

### Збирач рядка стану

Claude Code запускає команду рядка стану й передає їй через конвеєр документ JSON. ccam читає з нього назву моделі та `rate_limits`:

<!-- motion:usage-statusline -->

1. `runStatusline` визначає обліковий запис за `CCAM_PROFILE`, яку ccam задає під час запуску Claude Code, або ж зіставляючи `CLAUDE_CONFIG_DIR` з теками облікових записів.
2. `ParseStatusLine` читає `rate_limits.five_hour` і `rate_limits.seven_day`. Для облікових записів із ключем API або до першої відповіді в сеансі JSON не містить лімітів; тоді нічого не зберігається.
3. `SaveStatusLine` записує `~/.local/state/ccam/usage/<name>.statusline.json`. `ccam usage` використовує цей файл, коли кінцева точка не відповідає.
4. ccam виводить `[name] · model · 5h N% · 7d N%`. З `--wrap` він запускає вашу команду через `sh -c` з тим самим введенням і виводить її результат так, як Claude Code показує рядок стану: кожен непорожній рядок, із `[name]` перед першим. Команда, що завершилася невдало, показує лише назву облікового запису. У Windows він запускає команду так само, як Claude Code: через Git Bash, якщо його встановлено, інакше через PowerShell.
5. Коли 5-годинне або тижневе використання становить 90% або більше й існує інший обліковий запис, рядок закінчується на `→ ccam next --auto --continue`, наприклад `[work] · Opus · 5h 93% · 7d 41% · → ccam next --auto --continue`.

Обгорнута команда не має власного обмеження часу: Claude Code дає команді рядка стану 10 хвилин і зупиняє запуск, коли починається новіше оновлення, тож повільна команда показується так само, як без ccam. Коли Claude Code завершує ccam, команда теж завершується (на Linux і macOS разом з усіма процесами, які вона запустила).

`ccam statusline install` записує `statusLine` у `settings.json` кожного облікового запису й зберігає інші ключі об'єкта, як-от `padding`, `refreshInterval` і `hideVimModeIndicator`. Коли обліковий запис уже має команду рядка стану, ccam зберігає її як `--wrap '<old command>'`; у Windows — як `--wrap-base64 <base64>`, що не потребує лапок у жодній оболонці. Рядок стану, який уже запускає ccam з іншого шляху або взятий у лапки так, як його записав старіший ccam, замінюється, а не обгортається, зі збереженням того, що він обгортає. У Windows шлях до ccam записується з прямими скісними рисками й `~` замість домашньої теки (`~/.local/bin/ccam.exe statusline`), що розуміють і Git Bash, і PowerShell. Шлях, який потребує лапок, записується повністю для оболонки, яку використовує Claude Code: `'…'` для Git Bash, `& '…'` для PowerShell. `settings.json`, спільний через групу, записується один раз через своє посилання, тож його отримує кожен обліковий запис групи. Повторний запуск виводить `(already set)` для файлів, які вже використовують ccam.

## Безпека та граничні випадки

- `ccam usage` ніколи не змінює файл токенів, якщо ви не передасте `--refresh`. Коли токен доступу прострочено, запустіть обліковий запис один раз через `ccam <name>`, і Claude Code оновить його. Вхід, термін дії якого сплив повністю, потребує `ccam login <name>`.
- `--refresh` ніколи не чіпає запущені облікові записи (зокрема коли Claude Code запущено без ccam), імпортовані облікові записи чи входи у в'язці ключів. Відхилене оновлення показує збережені числа й причину (`token not renewed: …`).
- Кінцева точка використання не задокументована публічно й може змінитися. Коли це станеться, ви все одно бачитимете збережені числа, а `ccam doctor` повідомить про зміну формату.
- Якщо збережених чисел немає й відповіді немає, рядок облікового запису показує `lookup failed:` і причину, наприклад `no saved usage` з `--source cache`.
- Файли кешу містять лише відсотки й час скидання, але ніколи не токени.
