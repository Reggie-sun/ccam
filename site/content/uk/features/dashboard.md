`ccam` без аргументів відкриває повноекранну панель керування, коли стандартне введення й виведення є терміналом; інакше він виводить `ccam list`. Панель показує кожен обліковий запис із його використанням і групами та робить те саме, що й команди: запускає, додає, виконує вхід, змінює групи, задає правила тек, показує фонові сеанси, перевіряє й виправляє. Запуск або під'єднання до фонового сеансу закриває панель; додавання облікового запису або вхід ненадовго віддають термінал і потім повертаються до неї.

```console
 ccam v0.10.0 · 3 accounts · 2 groups     ✔ default · ▸ this folder · • running

  Accounts   Agents   Groups   Folders   Extensions   Health    auto_switch off
 Your Claude accounts and their usage limits; enter launches the selected one.

    # Account      5-hour       Weekly       Fable        Last  Groups
   1. personal ✔   ████▍░  72%  ██▌░░░  41%  █████▎  88%  -     default
 ❯ 2. work      ▸• █▌░░░░  25%  ██████ 100%  ▋░░░░░  10%  -     default team
   3. side         ✘ not logged in                        -     no group

 enter to launch · n for most room · a to add · s for groups · ? for shortcuts
```

Рядок під назвами вкладок одним реченням пояснює, для чого поточна вкладка. У ширшому терміналі вкладка Accounts також показує адресу електронної пошти кожного облікового запису. Кінець рядка вкладок на кожній вкладці показує, чи ввімкнено [`auto_switch`](/features/next#auto-switch) (Linux і macOS; у Windows його ігноровано); коли його ввімкнено, вкладка Health каже, що йому ще потрібно: увімкнений плагін ccam у кожному обліковому записі, який входить за підпискою Claude, і Claude Code 2.1.214 або новіший.

Щоразу, коли панель керування відкривається, вона у фоні запитує в GitHub, чи є новіший випуск ccam; перший кадр ніколи на це не чекає, а без мережі нічого не показано. Якщо такий випуск є, рядок під заголовком рекомендує його:

```console
 ● ccam 0.10.2 is available (you have 0.10.1) · press U to update
```

`U` спершу запитує, а потім оновлює так само, як [`ccam update`](/features/update): випуск перевіряється за його контрольними сумами SHA-256 і замінює ccam за один крок. Відкрита панель керування досі працює у старій версії, тож вийдіть і знову запустіть `ccam`. Якщо оновити тут не вдається, наприклад для ccam, встановленого з пакета `.deb`, панель керування показує ту саму пораду, що й `ccam update`, і зберігає пропозицію.

Перший кадр малюється лише з `config.toml`, значно швидше ніж за 100 мс; використання з'являється в міру того, як відповідає кожен обліковий запис. Кожен ліміт має власну смугу: 5-годинне вікно, тижневе вікно для всіх моделей і власне тижневе вікно Fable; `-` означає, що в облікового запису такого вікна немає. Відсоток стає жовтим від 80% і червоним на 100%, а значення з кешу після невдалого запиту показано блідим кольором. Вікно, про заповнення якого повідомив Claude Code, показує 100% до свого скидання. Прострочений токен доступу показано блідим `⚠ token expired` (Claude Code оновить його під час наступного запуску), тоді як `⚠ login expired` означає, що обліковому запису потрібен `ccam login`.

## Вкладки

| Вкладка | Що показує | Клавіші |
| --- | --- | --- |
| Accounts | номер, назву, адресу електронної пошти, смуги 5-годинного, тижневого та Fable-ліміту, останнє використання, групи; `✔` обліковий запис за замовчуванням, `▸` обліковий запис цієї теки, `•` запущений (зокрема Claude Code, запущений без ccam: звичайний `claude`, IDE, фонові сеанси та їхній демон) | нижче |
| Agents | те, що показує [`ccam agents`](/features/agents): фонові сеанси й відкриті сеанси всіх облікових записів з їхнім станом, текою й часом запуску (нижче) | `enter` під'єднатися (як `ccam attach`), `x` зупинити, `r` перезавантажити |
| Groups | кожну групу, що вона спільно використовує, її облікові записи, а також облікові записи без групи | `enter` змінити, `n` нова, `e` перейменувати, `x` видалити |
| Folders | правила [`ccam folder`](/features/folder) і те, яке діє тут, зокрема коли ви потрапили до теки через символьне посилання (нові правила зберігаються з розв'язаними посиланнями) | `n` використовувати обліковий запис тут, `enter` змінити, `x` видалити |
| Extensions | те, що показує [`ccam ext`](/features/ext): кожне розширення один раз разом із групами, з яких воно походить, `off:` — облікові записи, де плагін не ввімкнено, серед власних серверів облікового запису — ті, що є лише для цієї теки, `This folder's project` і проблеми, що не належать жодному обліковому запису | `r` перезавантажити |
| Health | те, про що повідомляє [`ccam doctor`](/features/doctor), у вигляді рамки для кожного облікового запису (нижче) | `f` виправити вибрану рамку, `F` виправити все (`doctor --fix`), `↑`/`↓` переходити між рамками |

`←`/`→` або `Tab` перемикають вкладки, `?` показує клавіші поточної вкладки, `r` знову запитує використання в обхід короткочасного кешу й заново завантажує вкладки Agents, Extensions і Health, а `q` або `Esc` закриває панель.

## Клавіші на вкладці Accounts

| Клавіша | Дія |
| --- | --- |
| `Enter` | Запустити Claude Code від імені вибраного облікового запису |
| `1`–`9` | Перейти до облікового запису з цим номером; щоб перейти до 12, швидко введіть `1` `2`. Запускає лише `Enter` |
| `↑`/`↓`, `k`/`j` | Переміщення |
| `n` | Запустити обліковий запис, який вибрав би [`ccam next --auto`](/features/next) |
| `o` | Запустити з параметрами: `--continue`, `--resume`, інші аргументи або пробний запуск |
| `u` | Подробиці використання: 5-годинне, тижневе вікна та вікна моделей із часом скидання й джерелом чисел |
| `a` | Додати обліковий запис (майстер нижче) |
| `l` | Знову виконати вхід |
| `s` | Вибрати групи облікового запису |
| `d` | Зробити його обліковим записом за замовчуванням |
| `f` | Використовувати його в поточній теці |
| `e` | Перейменувати його |
| `c` | Задати або видалити його коротку команду |
| `x` | Видалити його (спершу запитує, курсор стоїть на No) |

**Місця в планах Team і Enterprise.** Автоматичний вибір (`ccam next`, `--fallback`, `ccam pick`, `n` на панелі керування, а також [`auto_switch`](/features/next#auto-switch), якщо ви його ввімкнете) також перемикає між місцями однієї організації Claude Team або Enterprise. У довідковому центрі Anthropic сказано: «Each seat on a Team plan is assigned to one named individual, and only that person may use it» (кожне місце в плані Team закріплене за однією конкретною особою, і користуватися ним може лише ця особа) та «Users can't route their work through another user's account to use that user's remaining usage» (користувачі не можуть спрямовувати свою роботу через обліковий запис іншого користувача, щоб використати залишок ліміту цього користувача) ([плани Team](https://support.claude.com/en/articles/12004354-purchase-and-manage-seats-on-team-plans#h_b8a7d07129); так само для [планів Enterprise](https://support.claude.com/en/articles/13393991-purchase-and-manage-seats-on-enterprise-plans#h_fa6b9cade0)). Тому використання автоматичного вибору між місцями може порушувати умови Anthropic. Користуватися ним там чи ні, вирішувати вам: перш ніж на нього покладатися, уточніть це у своїй організації та в Anthropic. Про особисті плани (Pro, Max) ідеться в [примітці про умови в FAQ](/docs/faq#am-i-allowed-to-use-several-claude-code-accounts).

## Вкладка Health

Вкладка Health запускає перевірки [`ccam doctor`](/features/doctor), коли ви її відкриваєте, і малює те саме подання: перший рядок із позначкою для кожного облікового запису, а потім рамку для кожного облікового запису. Кожен рядок у рамці — це одна перевірена ділянка, спершу `Folder`, `Login` і `Share links`, з позначкою `✔` гаразд, `ℹ` інформація, `⚠` попередження або `✘` помилка, тож ви одразу бачите, у якого облікового запису проблема і де саме. Результати, що не належать жодному обліковому запису, потрапляють до рамки `General`.

```console
 ✘ personal   ⚠ work

 ╭─ ✘ personal · 3 problems ─────────────────────────────────────────────────╮
 │ ⚠ Folder       folder permissions are 755 (should be 0700)                │
 │ ℹ              unknown entries (ccam knows the folder layout of Claude    │
 │                Code 2.1.309; it may have changed): newthing               │
 │ ⚠ Login        .credentials.json permissions are 644 (should be 0600)     │
 │ ✔              login valid (me@example.com, Claude Team · Acme)           │
 │ ✘ Share links  /home/me/.local/share/ccam/profiles/personal/settings.json │
 │                : set to shared but is a real file, not a link             │
 │ ✔ Usage        usage lookup OK                                            │
 ╰───────────────────────────────────────────────────────────────────────────╯
 ╭─ ⚠ work · 1 problem ──────────────────────────────────────────────────────╮
 │ ✔ Folder       OK                                                         │
 │ ⚠ Login        not logged in → `ccam login work`                          │
 │ ✔ Share links  share links OK                                             │
 ╰───────────────────────────────────────────────────────────────────────────╯

 4 problems; f repairs the selected box, F all of them (ccam doctor --fix).
```

`↑`/`↓` переходять від рамки до рамки, а вибрана рамка має межу акцентного кольору. `f` виправляє лише вибрану рамку так само, як це зробив би `ccam doctor --fix`: у рамці облікового запису виправляється лише цей обліковий запис, а в рамці `General` — результати, що не належать жодному обліковому запису (шляхи плагінів і короткі команди); усі інші облікові записи лише перевіряються знову. Спершу він запитує (``Like `ccam doctor --fix`: missing links and group folders are made, and a real file where a link belongs is backed up first; where the group has its own copy, the account then sees the group's. Nothing is lost.``), а для рамки, у якій нічого виправляти, просто повідомляє `nothing to repair in <name>`. `F` виправляє все одразу, як `ccam doctor --fix`, а `r` перевіряє знову.

## Вкладка Agents

Вкладка Agents показує те, що виводить [`ccam agents`](/features/agents): фонові сеанси й відкриті сеанси всіх облікових записів разом з обліковим записом, якому належить кожен із них. Вона опитує Claude Code усіх облікових записів одночасно (`claude agents --json`, до 15 секунд на кожен), коли ви вперше відкриваєте вкладку, за `r`, після зупинки сеансу та після зміни конфігурації, і показує `Asking every account's Claude Code for its sessions…`, доки не відповідять усі.

```console
  Accounts   Agents   Groups   Folders   Extensions   Health    auto_switch off
 Background agents and open sessions of every account; enter attaches to one.

    Account   ID        Name   State          Folder      Started
 ❯  work      -         -      open (busy)    ~/code/web  now
    personal  49ec0028  probe  blocked, idle  ~/code/app  12m

 ✘ lab: could not list its sessions: exit status 1 'claude agents --json' is
   not available in this environment.

 enter to attach · x to stop · r to reload · ? for shortcuts
```

`State` — це стан фонового сеансу й те, що робить його процес, або `open` для інтерактивного сеансу, як у `ccam agents`. Обліковий запис, який не вдалося опитати, отримує під списком рядок `✘` з тим, що сказав Claude Code, як `lab` вище, у якого вимкнено перегляд агентів. Завершені фонові сеанси не показуються (їх виводить `ccam agents --all`), а коли відповіли всі облікові записи й жоден не має сеансу, вкладка каже ``No sessions. Start one in the background with `ccam <account> --bg "…"`.`` У вузькому терміналі вкладка спершу прибирає `Started`, потім `Name`, потім `Folder` і обрізає довгу теку зліва.

`Enter` на фоновому сеансі закриває панель і відкриває сеанс у цьому терміналі від імені його облікового запису, так само як `ccam attach <id>`; панель не повертається (у Claude Code `←` переходить до його перегляду агентів, а `Ctrl+Z` до оболонки). Відкритий сеанс не має ідентифікатора, тому `Enter` і `x` лише повідомляють, що потрібен фоновий сеанс. `x` спершу питає, починаючи з `No, keep it`: ``It runs as personal. Like `ccam personal stop 49ec0028`, Claude Code stops it and keeps its conversation, which `ccam attach 49ec0028` opens again.`` Якщо ви погодитеся, ccam виконує `claude stop <id>` від імені цього облікового запису, каже ``49ec0028 (personal) stopped; `ccam attach 49ec0028` opens it again`` або чому зупинити не вдалося, і знову читає список.

## Зміна груп

На вкладці Groups клавіша `Enter` відкриває редактор: елементи ліворуч, облікові записи праворуч, `Tab` перемикає між ними, `Space` вмикає або вимикає. Елемент, який один з облікових записів уже отримує з іншої групи, показано сірим разом із причиною; так само показано обліковий запис, який отримав би елемент двічі. Елемент може надходити лише з однієї групи. `Enter` показує план:

```console
 ──────────────────────────────────────────────────────────────────────────────
  Groups of side

  ● side  +history (group team)
    ⎿  link     projects, history.jsonl: profiles/side → groups/team

  Do you want to apply this plan?
  ❯ 1. Yes
    2. No
```

Про файл, який відрізняється від копії групи, спершу запитують (залишити версію групи, використати мою або об'єднати). Потім зміна виконується у фоновому режимі тим самим кодом, що й [`ccam group`](/features/share): спершу зберігається конфігурація, далі дані кожного облікового запису переміщуються по черзі, а оригінали потрапляють до `.ccam-backup/`; обліковий запис, який виходить зі спільного доступу до MCP, зберігає сервери групи у своєму `.claude.json`. Зміну, яка перемістила б дані запущеного облікового запису, буде відхилено з назвою цього облікового запису, зокрема коли обліковий запис запустився, поки план був відкритий, а план, який застарів через зміну груп в іншому ccam, буде відхилено з `the groups changed while this plan waited; nothing was moved, make the change again`. Поки інший ccam змінює групи, нова зміна, перейменування чи видалення повідомляє `another ccam is changing the groups right now`; після зміни, що зупинилася на півдорозі, вони чекають, доки `F` на вкладці Health (або `ccam doctor --fix`) її не завершить.

## Додавання облікового запису

`a` відкриває майстер, який `ccam add` також використовує в терміналі:

1. Назва облікового запису.
2. Спосіб входу: підписка Claude зараз (у браузері), [ключ API](/features/api) або підписка Claude пізніше.
3. Для ключа API: звідки ccam читає ключ під час кожного запуску (`env:NAME` або `command:COMMAND`), кінцева точка, спосіб надсилання ключа й модель.
4. Групи, до яких потрібно приєднатися, з позначеною `default`; поки груп немає, — що спільно використовує група `default`.
5. Коротка команда, якщо вона вам потрібна.
6. Підсумок для підтвердження.

`Esc` повертає на крок назад, а на першому кроці закриває майстер.

## Видалення облікового запису

`x` запитує, перш ніж щось станеться, з курсором на No, і пояснює, що робить видалення: `It is logged out first (its login is revoked), then its folder goes to ccam's trash; the groups' shared files stay.` Для облікового запису з ключем API немає входу, який треба відкликати, а коли інший обліковий запис має той самий вхід, вихід не виконується. Імпортований обліковий запис зберігає свою теку: `It was imported, so its folder /home/me/.claude stays where it is: it leaves its groups first and keeps a copy of what they share, then ccam forgets it.`
## Кольори

Кольори відповідають ролям у терміналовому інтерфейсі Claude Code, тож ccam виглядає поруч із ним природно; назви груп отримують колір залежно від самої назви. ccam запитує в термінала колір його тла й вибирає світлу або темну тему. Задати тему самостійно можна вгорі `config.toml`, над першим `[[group]]`, `[[profile]]` або `[[folder]]`:

```toml
theme = 'dark'   # auto (default), dark, light, dark-daltonized, light-daltonized, dark-ansi, light-ansi
```

Теми `-daltonized` призначені для людей із червоно-зеленою колірною сліпотою, а теми `-ansi` використовують власні 16 кольорів термінала. `NO_COLOR` вимикає кольори.

## Безпека та граничні випадки

- Панель викликає ті самі функції, що й команди, тож діють усі правила: план перед переміщенням даних, відмова для запущених облікових записів, резервні копії та токени входу, які ніколи не залишають обліковий запис.
- Панель не має пробного запуску: `ccam --dry-run` без назви виводить, як запуститься обліковий запис цієї теки, а `o` на обліковому записі пропонує виконати в пробному режимі лише цей один запуск.
- Термінал відновлюється перед тим, як запускається Claude Code або відкривається вхід.
- Якщо екран замалий для діалогу, спершу зникають рядки вкладки; рядки обрізаються з `…`, а не переносяться. На низькому екрані наступними зникають порожні рядки й опис вкладки, щоб рядок клавіш лишився. Менше ніж 40 стовпців або 8 рядків — і панель показує лише `Too small: ccam needs 40x8 (now 36x7)`.
- `Ctrl+C`, поки застосовується зміна, видалення, оновлення чи виправлення, чекає на її завершення: рядок стану повідомляє `ccam quits when it is done.`
- Після того як `U` оновив ccam, пропозиція не з'являється знову, коли панель повертається після додавання облікового запису чи входу.
