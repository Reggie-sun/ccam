`ccam ext` відповідає на запитання «Чому ця навичка (або сервер MCP) працює в одному обліковому записі, але не працює в іншому?» Для кожного облікового запису він перелічує розширення, які завантажує Claude Code, і звідки береться кожне з них: із групи спільного використання, із власної теки облікового запису або з проєкту, у якому ви перебуваєте. Під таблицею він перелічує те, що заважає розширенню завантажуватися так, як ви очікуєте. Він нічого не змінює.

## Використання

```sh
ccam ext              # every account
ccam ext work         # one account
ccam ext --json       # for scripts
```

```console
$ ccam ext
Skills
          personal   work
  half    account !  -
  review  -          default

Commands
          personal  work
  deploy  default   default

MCP servers
       personal   work
  ctx  default !  default

Hooks (commands per event)
              personal     work
  PreToolUse  1 (default)  1 (default)

This project (/home/me/code/app):
  commands: ship
  MCP servers: fs

Sources: a group name (shared), account (its own folder), local (its own, for this folder only), - (not loaded); (off): installed, not turned on.
! personal: MCP server ctx is defined differently in group default's mcp.json and .claude.json
! personal: half: no SKILL.md, so Claude Code does not load it
```

Клітинка називає джерело цього елемента в цьому обліковому записі: групу спільного використання (`default`), `account`, коли елемент лежить у власній теці облікового запису, `local` для сервера MCP, який обліковий запис має лише для цієї теки, або `-`, коли в облікового запису його немає. Плагін, який установлено, але не ввімкнено, показує `(off)` після свого джерела. `!` позначає елемент із проблемою, яку пояснено під таблицею; проблеми, що не належать жодному обліковому запису, як-от сервери, які має лише звичайний `claude`, ідуть останніми без назви. `ccam ext --json` виводить той самий звіт (`accounts`, проєкт, `problems`) з `remote` на серверах MCP, до яких Claude Code звертається через мережу; без облікових записів він виводить звіт з `accounts: []`.

## Що він читає

| Вид | Де | Показане джерело |
| --- | --- | --- |
| Навички | кожна тека в `skills/` з `SKILL.md` | група, на яку посилається `skills/`, або `account` |
| Команди, агенти | файли `.md` у `commands/` і `agents/`, підтеки як `folder/name` | група або `account` |
| Плагіни | `plugins/installed_plugins.json`, увімкнені чи вимкнені через `enabledPlugins` у налаштуваннях облікового запису та проєкту; плагін, установлений лише для одного проєкту, з'являється лише в цьому проєкті | група або `account`; `(off)`, коли не ввімкнено |
| Сервери MCP | `mcp.json` групи (коли MCP спільний), `.claude.json` облікового запису (його власні сервери й ті, що він має лише для цієї теки) і сервери його плагінів як `plugin:<plugin>:<server>` | група, `account` або `local` |
| Хуки | `hooks` у `settings.json`, з підрахунком за подіями | група або `account` |
| Цей проєкт | `.claude/skills`, `.claude/commands`, `.claude/agents`, `.claude/settings.json`, `.claude/settings.local.json` і `.mcp.json` у поточній теці | виводиться один раз; обліковий запис, який не довірив цій теці, отримує проблему для серверів її `.mcp.json` |

## Про які проблеми він повідомляє

- **Зламані посилання**: посилання в `skills/`, `commands/` або `agents/`, ціль якого зникла, або спільна тека (`skills`, `commands`, `agents`, `plugins`), що посилається на відсутнє місце (виправте це командою `ccam doctor --fix`, яка знову створює відсутню теку групи).
- **Тека навички без `SKILL.md`**: Claude Code її пропускає.
- **Сервер MCP, по-різному визначений у двох місцях**: у `mcp.json` групи та в `.claude.json` облікового запису або в одному з них і в `.mcp.json` проєкту. Однакові визначення в обох місцях (їх записує `mcp_strategy = "sync"`) проблемою не вважаються. Перенесіть власний сервер облікового запису до групи командою `ccam mcp import <account> <server>`.
- **`installed_plugins.json`, який не є коректним JSON**, плагін, якого не називає `enabledPlugins`, і плагін, тека якого відсутня.
- **Сервери, які завантажує лише один обліковий запис**: сервер лише в `.claude.json` цього облікового запису, якого не завантажують інші облікові записи його групи, і сервер у локальній області облікового запису для цієї теки (так робить `claude mcp add`, якщо не вказати `-s user`). Кожен супроводжується командою `ccam mcp import`, яка робить його спільним. Сервери в `~/.claude.json` звичайного `claude`, які не завантажує жоден обліковий запис, супроводжуються командою `ccam migrate --mcp`.
- **Сервер проєкту, що чекає на схвалення**: обліковий запис ще не довірив цій теці, тож Claude Code запитає один раз, а доти сервери з `.mcp.json` проєкту чекають. Проблема пояснює, де їх схвалити: `"enabledMcpjsonServers"` у `settings.json` облікових записів групи налаштувань або цього облікового запису. Довіра, надана основному робочому дереву репозиторію git, діє і в інших його робочих деревах.
- **Входи та конектори**: сервер MCP, який потребує входу в цьому обліковому записі, тоді як інший обліковий запис у нього увійшов (вхід діє лише для одного облікового запису; увійдіть через `/mcp`), і конектори claude.ai, якими користувався інший обліковий запис, але не цей.

## Безпека та граничні випадки

- `ccam ext` нічого не змінює й не надсилає мережевих запитів. Він читає назви серверів і кількість хуків, але ніколи не читає значень `env` чи заголовків у визначеннях MCP. Для перевірки входів він читає назви входів MCP у даних входу кожного облікового запису (на macOS — з в'язки ключів), але ніколи не токени, і лише для облікових записів, які завантажують сервер, що його завантажує й інший обліковий запис.
- Він показує те, що лежить на диску. Сервер, заблокований керованими налаштуваннями, однаково відображається; плагін, вимкнений у налаштуваннях, показує `(off)`.
- Запустіть його в теці проєкту, щоб охопити теку `.claude` і `.mcp.json` цього проєкту.
