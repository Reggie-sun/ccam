`ccam doctor` перевіряє ваше встановлення ccam: виконуваний файл Claude Code, теку, вхід і спільні посилання кожного облікового запису, спільні сервери MCP, кінцеву точку використання та ваші короткі команди. `ccam doctor --fix` виправляє те, що може виправити без втрати даних, і спершу переміщує кожен файл, який замінює, до теки резервних копій. Запускайте його, коли `ccam <name>` зупиняється через проблему зі спільним посиланням, після того як ви відновили файли вручну, або після оновлення Claude Code.

## Використання

```sh
ccam doctor                  # check everything, change nothing
ccam doctor --fix            # check, then repair what is safe to repair
ccam --dry-run doctor --fix  # report only: what --fix would repair and set aside
```

Перший рядок позначає всі облікові записи одразу, тож ви бачите, де проблеми, ще до того, як читатимете щось інше. Під ним кожен обліковий запис отримує рамку, а результати, що не належать жодному обліковому запису (Claude Code, змінні середовища, плагіни, сервери MCP, короткі команди, правила тек, групи й налаштування, `auto_switch`), потрапляють до рамки `General`. Заголовок рамки показує найгіршу позначку облікового запису та кількість його проблем. Кожен рядок усередині — це одна перевірена ділянка, завжди `Folder`, `Login` і `Share links` у такому порядку, потім решта, з позначкою: `✔` гаразд, `ℹ` інформація, `⚠` попередження, `✘` помилка. Тека без проблем показує `✔ Folder  OK`.

```console
$ ccam doctor

 │ ⚠ Folder       folder permissions are 755 (should be 0700)                │

 │                Code 2.1.309; it may have changed): newthing               │
 │ ⚠ Login        .credentials.json permissions are 644 (should be 0600)     │
 │ ✔              login valid (me@example.com, Claude Team · Acme)           │
 │ ✘ Share links  /home/me/.local/share/ccam/profiles/personal/settings.json │
 │                : set to shared but is a real file, not a link             │
 │ ✔ Usage        usage lookup OK                                            │

`ccam doctor --fix` repairs what it can.
```

З `--fix` кожен виправлений результат закінчується на `→ fixed` і більше не вважається проблемою:


У терміналі рамки підлаштовуються під його ширину, а довгі повідомлення переносяться, у власних кольорах термінала (`NO_COLOR` вимикає їх). Рамка ніколи не буває вужчою за 29 стовпців, тож на вузькому терміналі жодне слово не обрізається. Коли вивід іде в конвеєр або файл, у ньому немає кольорів і жодне повідомлення не переноситься й не обрізається, тож `ccam doctor | grep settings.json` знаходить увесь рядок; тоді кожна рамка має ширину найдовшого рядка. Вкладка Health панелі керування показує ті самі рамки.

## Параметри

| Параметр | Дія | За замовчуванням |
| --- | --- | --- |
| `--fix` | Виправити те, що безпечно виправити (для змінених файлів створюються резервні копії) | вимкнено |
| `--dry-run` (глобальний) | Виконати всі перевірки, але нічого не виправляти, навіть з `--fix` | вимкнено |

`ccam doctor` не приймає аргументів. Він враховує `--dry-run`: `ccam --dry-run doctor --fix` виводить результати `ccam doctor`, додає те, що `--fix` відклав би вбік, і нічого не змінює:

```text
ℹ settings.json differs from the group's copy: --fix would use the group's, and move this account's copy to /home/me/.local/share/ccam/profiles/personal/.ccam-backup/20261023-212543/settings.json
```

Код виходу дорівнює `1`, коли залишився хоча б один невиправлений результат `✘`, і `0` в інших випадках. Попередження та інформація ніколи не призводять до невдалого завершення. Коли запуск без `--fix` завершується невдало, ccam виводить порожній рядок і `` `ccam doctor --fix` repairs what it can. ``. Конфігурація, яку не вдається завантажити, теж дає `1` і помилку `ccam:`.

## Як це працює

`internal/cli/doctor.go` завантажує `~/.config/ccam/config.toml` і викликає `doctor.Run` у `internal/doctor/doctor.go`, який виконує перевірки у фіксованому порядку й повертає результати, кожен з обліковим записом, якому він належить, і ділянкою, яку він перевірив. `tui.HealthReport` групує їх у рамки. `--fix` передається як `Options.Fix`, що в пробному запуску дорівнює false.

<!-- motion:doctor-checks -->

Середній блок виконується один раз для кожного облікового запису. Перевірки та те, що `--fix` робить для кожної з них:

1. **Версія Claude Code** (`checkClaude`). Знаходить виконуваний файл `claude` так само, як засіб запуску, і виконує `claude --version`. Відсутній виконуваний файл, `claude_bin`, який не є виконуваним файлом, або невдалий `--version` є помилкою. Без виправлення.
2. **Дані входу в середовищі** (`checkAuthEnv`). Попереджає, коли задано `CLAUDE_CODE_OAUTH_TOKEN`, `ANTHROPIC_API_KEY` або `ANTHROPIC_AUTH_TOKEN`: кожен обліковий запис, запущений із цієї оболонки, успадковує змінну, і Claude Code віддає їй перевагу над власним входом облікового запису. Без виправлення; видаліть змінну самостійно.
3. **Тека** (`checkProfile`). Відсутня тека облікового запису є помилкою й завершує перевірки цього облікового запису. Права доступу з будь-якими бітами для групи чи інших є попередженням; `--fix` виконує `chmod 0700`. Імпортована `~/.claude` із власним `.claude.json` поруч із `~/.claude.json` є інформацією: тоді `ccam main` і звичайний `claude` тримають окремі дані входу й сервери MCP. У Windows немає бітів прав доступу, тому там цю перевірку й перевірку `0600` нижче пропущено; теку у вашому профілі користувача захищає її список доступу.
4. **Файл входу** (`checkCredentials`). `.credentials.json` перевіряється через `lstat`. Символьне посилання є помилкою, бо кожен обліковий запис повинен мати власний токен, і не виправляється. Режим, відмінний від `0600`, є попередженням; `--fix` виконує `chmod 0600`. Потім зчитується вхід (на macOS спершу з в'язки ключів). Відсутність входу або файл входу без нього є попередженням, що вказує на `ccam login <name>`. Прострочений токен оновлення або вхід, який Claude Code очистив після того, як сервер його відхилив, дає помилку `` login expired → `ccam login <name>` ``; прострочений токен доступу є лише інформацією, бо Claude Code оновить його під час наступного запуску. Вхід, що зберігається в диспетчері облікових даних Windows, є інформацією, бо ccam не може його прочитати. Дійсний вхід показує адресу електронної пошти, від імені якої тека увійшла зараз, і тарифний план (`login valid (dev@company.com, Claude Team · Acme)`). Жодне з цього не виправляється; `ccam login --expired` виконує вхід у кожен обліковий запис, якому це потрібно.
5. **Спільні посилання** (`share.Check`). Порівнює кожен шлях у `share.Layout` з групами облікового запису, використовуючи лише `lstat` і `readlink`. Повідомляє про п'ять випадків: відсутнє посилання, посилання, що вказує не туди, справжній файл там, де має бути посилання, залишене посилання для елемента, який тепер локальний, і правильне посилання, тека групи якого відсутня (`the group folder it links to is missing (…), so Claude Code cannot save there (ccam doctor --fix makes it)`; запуск цього не перевіряє). Відсутнє посилання й відсутня тека групи є попередженнями, інші випадки — помилками. Також повідомляється про копіювання назад із групи, що зупинилося на півдорозі: `--fix` ставить на місце повну підготовлену копію, але коли шлях відтоді створено заново (запуском), він називає теку з повною копією, щоб ви розібралися з нею самі. Шляхи, додані до елемента в пізнішій версії ccam (`file-history/`, `tasks/` і `paste-cache/` для історії, `keybindings.json` для налаштувань), дають лише попередження, поки обліковий запис має власну копію: `is not shared with the group yet (ccam doctor --fix shares it; if the group has its own copy, that one is kept and this one backed up)`. Запуск через них ніколи не зупиняється.
6. **Невідомі записи** (`checkUnknownEntries`). Перелічує назви верхнього рівня в теці облікового запису, яких ccam не знає (`share.Known`), як підказку, що структура Claude Code змінилася. Лише інформація.
7. **Шляхи до плагінів** (`checkPlugins`). Реєстри плагінів (`installed_plugins.json`, `known_marketplaces.json`) зберігають абсолютні шляхи. У `plugins/` кожної групи шляхи, що проходять через теку одного облікового запису, перестають працювати, коли цей обліковий запис видаляють або перейменовують. `--fix` переписує їх на теку групи через `profile.RewritePluginPaths`, атомарно записуючи файл реєстру.
8. **Сервери MCP** (`checkMCP`). Один раз завантажує `mcp.json` кожної групи. Файл, який не вдається прочитати, є помилкою; сервер, що не проходить `mcp.Validate`, є попередженням. Сервери в `~/.claude.json` звичайного `claude`, які не завантажує жоден обліковий запис, дають попередження з командою `ccam migrate --mcp`, яка їх копіює (з `--group <a|b>`, коли MCP спільно використовують кілька груп). Сервери, які має лише один обліковий запис групи, є інформацією з командою `ccam mcp import`, яка робить їх спільними, а обліковий запис, який не увійшов у сервери MCP, у які увійшли інші облікові записи, отримує попередження увійти через `/mcp` (ccam ніколи не копіює входи). Без виправлення.
9. **Формат відповіді про використання** (`checkUsageFormat`). Запитує кінцеву точку використання без кешу для облікових записів по черзі, доки один не відповість, усе в межах одного обмеження в 4 секунди. З `usage_source = "claude"` він натомість запитує Claude Code для одного облікового запису. Якщо відповідь більше не розбирається, попереджає, що `ccam usage` переходить на кеш рядка стану; коли не відповів жоден обліковий запис, повідомляє про це як інформацію (`could not check the usage response format: …`). Це єдина перевірка, яка використовує мережу.
10. **Короткі команди** (`checkShims`). Лише коли обліковий запис має коротку команду. Відсутні посилання в `~/.local/bin` є попередженням, так само як і короткі команди, створені ccam, які досі запускають старіший ccam, замінений або переміщений (`shortcuts in <bin> that run another ccam (one replaced or moved): …`); `--fix` викликає `shim.Install`, який створює й оновлює лише посилання, створені ccam і записані в `~/.local/state/ccam/shortcuts.json`, і ніколи не чіпає інших файлів. Попередження закінчується на `→ fixed`, лише коли кожне з цих посилань створено; якщо якесь не вдалося, додається причина. Коротка команда, що запускає інший ccam, який досі встановлено, працює і є інформацією; `--fix` спрямовує її на цей ccam. Тека bin, якої немає в `PATH`, є попередженням і не виправляється.
11. **Теки** (`checkFolders`). Лише коли є записи [`ccam folder`](/features/folder). Запис, обліковий запис якого не існує, є помилкою, а запис, теки якого більше немає, є попередженням. Жодне з цього не виправляється, бо видалення запису змінило б, який обліковий запис там запускається.
12. **Групи й налаштування** (`checkGroups`). Учасник групи, який не є обліковим записом, обліковий запис, чия назва відтоді стала командою ccam (запускайте його через `ccam run <name>` або перейменуйте), невідоме значення `theme` чи `usage_source`, а також рядки `config.toml`, які ccam не читає, є попередженнями. Останні — це зазвичай налаштування, записане під таблицею `[[group]]`, `[[profile]]` або `[[folder]]`, де воно належить цій таблиці (`config.toml line 43: relay is read as part of the [profile.login] table above it; settings for all accounts go above the first [[group]], [[profile]] or [[folder]]`); команди, які змінюють конфігурацію, відмовляються працювати, доки це не виправлено. Не виправляється.
13. **Входи** (`checkIdentities`). Зчитує з `.claude.json` кожної теки, від імені кого в ній виконано вхід. Тека, у якій тепер виконано вхід в інший обліковий запис, ніж записав `ccam login` (наприклад, після `/login` усередині сеансу), дає попередження; обліковий запис без запису про вхід, як-от імпортований або створений старішим ccam, порівнюється за записаною електронною поштою. Тека, у якій виконано вхід у той самий обліковий запис Claude, що й в іншій, теж дає попередження: вони ділять ліміти використання. Тека, що містить той самий токен входу, що й інша, тобто скопійована тека (зокрема `~/.claude` звичайного `claude`), є помилкою, бо той, хто оновить його першим, виведе іншого із системи; виконайте `ccam login <name>`, щоб дати їй власний. Не виправляється.
14. **`auto_switch`** (`checkAutoSwitch`). Лише коли `auto_switch = true`. Інформація в рамці `General` пояснює, що робить `auto_switch`, і посилається на [його опис](/features/next#auto-switch). Для кожного плану з місцями серед облікових записів (Claude Team, Claude Enterprise) рядок називає їх, каже, що `auto_switch` переносить сеанс між місцями однієї організації, цитує правило Anthropic щодо місць із посиланням на довідковий центр і залишає вибір за вами. Claude Code, старіший за 2.1.214, який не повідомляє хукам свій процес (`CLAUDE_PID`), дає там попередження, бо жоден сеанс не можна перенести. Обліковий запис без плагіна ccam або з вимкненим плагіном отримує попередження у власній рамці з командою, яка виправляє це в Claude Code: `auto_switch is on, but work does not have the ccam plugin, so its sessions are not moved. In Claude Code as work: /plugin install ccam --marketplace jhyunwoo/ccam` (або `/plugin enable ccam@ccam`). Облікові записи з ключем API пропускаються. У Windows єдиний рядок такий: `auto_switch is ignored on Windows; with relay = true, /ccam:switch and then /exit carry a conversation on.` Не виправляється.

Перед обліковими записами **зміна груп**, що зупинилася на півдорозі, є помилкою в рамці `General`: ``the last change of groups stopped halfway (ccam doctor --fix finishes it; noted in ~/.local/state/ccam/group-change.json)``. `--fix` завершує її в запланованому порядку, з відповідями, наданими на її конфлікти; доти не починається жодна інша зміна груп, перейменування чи видалення. Облікові записи, яких вона стосується, доки її не завершено, отримують лише створення відсутніх посилань. Якщо її не вдається завершити, помилка каже, що видалення цього файлу відмовляється від решти зміни. `ccam --dry-run doctor --fix` показує порядок (`--fix finishes it in its order (b, a, c), with the answers given to its conflicts`) і те, що частина кожного облікового запису відклала б убік. Зміна, яку інший ccam виконує саме зараз, є інформацією, і поки вона триває, `--fix` не виправляє спільних посилань (`its share links are not repaired while another ccam changes the groups; …`). `--fix` тримає `~/.local/state/ccam/group-change.lock`, поки виправляє, і після завершення зміни знову читає `config.toml`.

### Виправлення спільних посилань

Шлях запуску одразу створює відсутнє посилання, але зупиняється на всьому, що може призвести до втрати даних, і відсилає сюди:

```console
$ ccam work
ccam: stopped because of share link problems:
  /home/me/.local/share/ccam/profiles/work/CLAUDE.md: set to shared but is a real file, not a link
Repair them with `ccam doctor --fix`, then run again
```

Для будь-якої проблеми зі спільними посиланнями `--fix` викликає `share.Build` з налаштуваннями спільного використання облікового запису як поточним і цільовим станом, а потім `Plan.Apply`. `Build` заново виводить кожен крок із того, що є на диску, — це той самий план, який використовує зміна через `ccam group`, тож виправлення дотримується тих самих правил, що й приєднання до групи.

<!-- motion:doctor-repair -->

Тут `settings.json` є справжнім файлом. Оскільки група вже має інший `settings.json`, для конфлікту застосовується вибір за замовчуванням, `KeepGroup`, тож копія групи залишається. Файл облікового запису переміщується до `.ccam-backup/<time>/settings.json` усередині теки облікового запису, а `os.Symlink` пов'язує шлях із групою. `--fix` повідомляє про це: `settings.json differed from the group's copy, which it now uses; this account's copy is in …`. Інші випадки:

- Якщо в групі ще немає копії, файл облікового запису переміщується до групи й стає її першим вмістом.
- Для теки файли, яких бракує групі, переміщуються до групи. Файли, які група має байт у байт, відкидаються, а ті, що відрізняються, ідуть до резервної копії й називаються в примітці (`projects: 1 file differs from the group's copy (-w/memory/MEMORY.md); the group's is kept, the account's stays in …`).
- Відсутня тека групи створюється першою.
- Для `history.jsonl` за замовчуванням діє `merge by line`: рядки групи, потім ваші нові. Попередня копія групи зберігається в `.ccam-backup/<time>/group/`.
- Посилання на іншу групу замінюється. Посилання на теку поза ccam іде до резервної копії, а його вміст стає початковим вмістом групи, якщо група порожня.
- Посилання, залишене для елемента, який тепер локальний, видаляється, і обліковий запис отримує копію вмісту групи.

Окрім видалення посилань і відкидання файлів, які група вже має байт у байт, кожен крок переміщує дані до групи або до теки резервних копій. Нічого не втрачається.

## Безпека та граничні випадки

- Звичайний `ccam doctor` ніколи нічого не змінює. У скриптах використовуйте `--dry-run` разом із `--fix`, щоб бути певними.
- Для запущеного облікового запису, хоч би як було запущено Claude Code, `doctor --fix` лише створює відсутні посилання й відсутні теки груп, що нічого не втрачає. Коли лишається щось інше, він додає `` is running; quit Claude Code there, then run `ccam doctor --fix` again to repair the rest ``, бо сеанс і далі записує у файли, які виправлення перемістило б.
- Якщо виправити спільні посилання не вдається, ccam повідомляє `could not repair share links: <error>` для цього облікового запису й пропускає для нього перевірку невідомих записів. Інші облікові записи все одно перевіряються.
- Якщо зміна через `ccam group` зазнає невдачі посередині, нові групи вже збережено, а зміну записано в `~/.local/state/ccam/group-change.json`; ccam радить завершити через `ccam doctor --fix`, який виконує решту зміни, зокрема кроки MCP.
- Про `.credentials.json`, що є символьним посиланням, прострочений вхід і дані входу в середовищі повідомляється, але вони ніколи не змінюються.
- Переписані реєстри плагінів записуються атомарно, але не копіюються до `.ccam-backup/`.
