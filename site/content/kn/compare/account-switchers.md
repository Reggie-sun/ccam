Claude Code ಖಾತೆ ಬದಲಾಯಿಸುವ ಟೂಲ್‌ಗಳು ಎರಡರಲ್ಲಿ ಒಂದು ವಿಧಾನ ಅನುಸರಿಸುತ್ತವೆ. ಹೆಚ್ಚಿನವು ಒಂದೇ `~/.claude` ಫೋಲ್ಡರ್‌ನೊಳಗೆ ಲಾಗಿನ್ ಅನ್ನು ಬದಲಾಯಿಸುತ್ತವೆ, ಆದ್ದರಿಂದ ಒಂದು ಸಮಯದಲ್ಲಿ ಒಂದೇ ಖಾತೆ ಸಕ್ರಿಯವಾಗಿರುತ್ತದೆ. ccam ಸೇರಿದಂತೆ ಇತರವು `CLAUDE_CONFIG_DIR` ಮೂಲಕ ಪ್ರತಿ ಖಾತೆಗೂ ಅದರದೇ ಫೋಲ್ಡರ್ ನೀಡುತ್ತವೆ, ಆದ್ದರಿಂದ ಪ್ರತಿ ಖಾತೆಯೂ ಲಾಗಿನ್ ಆಗಿಯೇ ಇರುತ್ತದೆ ಮತ್ತು ಹಲವನ್ನು ಒಮ್ಮೆಗೇ ರನ್ ಮಾಡಬಹುದು. ccam ಹಂಚಿಕೆಯ ಸೆಟ್ಟಿಂಗ್‌ಗಳು ಮತ್ತು MCP ಸರ್ವರ್‌ಗಳನ್ನು ಸೇರಿಸುತ್ತದೆ, ಮತ್ತು ಸಂಭಾಷಣೆಯನ್ನು ಇನ್ನೊಂದು ಖಾತೆಯ ಫೋಲ್ಡರ್‌ನಲ್ಲಿ ಮುಂದುವರಿಸುತ್ತದೆ.

## ಒಂದೇ ಲಾಗಿನ್ ಬದಲಾಯಿಸುವುದೇ ಅಥವಾ ಪ್ರತ್ಯೇಕ ಫೋಲ್ಡರ್‌ಗಳೇ?

**ಲಾಗಿನ್ ಬದಲಾಯಿಸುವ ವಿಧಾನದಲ್ಲಿ** ಒಂದೇ ಫೋಲ್ಡರ್ ಇರುವುದರಿಂದ ಸೆಟ್ಟಿಂಗ್‌ಗಳು, MCP ಸರ್ವರ್‌ಗಳು ಮತ್ತು ಇತಿಹಾಸ ಒಂದೇ ಸೆಟ್ ಆಗಿರುತ್ತವೆ. ಬದಲಾವಣೆ ವೇಗವಾಗಿರುತ್ತದೆ, ಮತ್ತು ರನ್ ಆಗುತ್ತಿರುವ ಸೆಷನ್ ಹೊಸ ಲಾಗಿನ್ ಅನ್ನು ಪಡೆದುಕೊಳ್ಳಬಹುದು. ಆದರೆ ಒಂದು ಸಮಯದಲ್ಲಿ ಒಂದೇ ಖಾತೆ ಸಕ್ರಿಯವಾಗಿರುತ್ತದೆ, ಎಲ್ಲಾ ಟರ್ಮಿನಲ್‌ಗಳು ಮತ್ತು ಎಡಿಟರ್‌ಗಳಿಗೂ ಒಮ್ಮೆಗೇ.

ಬದಲಾಯಿಸಲು, ಟೂಲ್ ಉಳಿದ ಪ್ರತಿ ಖಾತೆಯ ಲಾಗಿನ್‌ನ ಪ್ರತಿಯನ್ನು ಇಟ್ಟುಕೊಂಡು, ಅದನ್ನು ಸರಿಯಾದ ಜಾಗದಲ್ಲಿ ಬರೆಯುತ್ತದೆ. Claude Code ಲಾಗಿನ್ ಅನ್ನು ನವೀಕರಿಸುವಾಗ ಅದರಲ್ಲಿನ refresh token ಅನ್ನು ಬದಲಾಯಿಸುತ್ತದೆ, ಆದ್ದರಿಂದ ಉಳಿಸಿದ ಪ್ರತಿಯೊಂದು ಪ್ರತಿಯೂ ರನ್ ಆಗುತ್ತಿರುವ ಸೆಷನ್‌ಗಳೊಂದಿಗೆ ಹೊಂದಿಕೆಯಲ್ಲಿರಬೇಕು. ಬದಲಾಯಿಸಿದ ನಂತರ ಖಾತೆಗಳು ಲಾಗ್‌ಔಟ್ ಆಗುವುದು ಅಥವಾ ಮತ್ತೆ `/login` ಬೇಕಾಗುವುದು ಈ ಪ್ರಾಜೆಕ್ಟ್‌ಗಳು ಹೆಚ್ಚಾಗಿ ಸರಿಪಡಿಸುವ ಸಮಸ್ಯೆಗಳಲ್ಲಿ ಸೇರಿವೆ.

**ಪ್ರತ್ಯೇಕ ಫೋಲ್ಡರ್‌ಗಳು** [Claude Code ನ ದಸ್ತಾವೇಜು ವಿವರಿಸುವ](https://code.claude.com/docs/en/authentication#log-in-with-multiple-accounts) ವಿಧಾನ. ಪ್ರತಿ ಖಾತೆಯೂ ಲಾಗಿನ್ ಆಗಿಯೇ ಇರುತ್ತದೆ, ಮತ್ತು ಕೆಲಸದ ಹಾಗೂ ವೈಯಕ್ತಿಕ ಸೆಷನ್‌ಗಳನ್ನು ಅಕ್ಕಪಕ್ಕದಲ್ಲಿ ರನ್ ಮಾಡಬಹುದು. ಪ್ರತಿ ಲಾಗಿನ್ ತನ್ನದೇ ಫೋಲ್ಡರ್‌ನಲ್ಲಿ ಉಳಿಯುತ್ತದೆ, ಅಲ್ಲಿ Claude Code ಅದನ್ನು ಎಂದಿನಂತೆ ನವೀಕರಿಸುತ್ತದೆ. ಇದರ ಬೆಲೆ ಎಂದರೆ, ಯಾವುದಾದರೂ ಟೂಲ್ ಹಂಚದಿದ್ದರೆ, ಪ್ರತಿ ಫೋಲ್ಡರ್ ತನ್ನದೇ ಸೆಟ್ಟಿಂಗ್‌ಗಳು, MCP ಸರ್ವರ್‌ಗಳು ಮತ್ತು ಇತಿಹಾಸದೊಂದಿಗೆ ಆರಂಭವಾಗುತ್ತದೆ.

## ccam ಚೆನ್ನಾಗಿ ಮಾಡುವುದು

### ಲಾಗಿನ್‌ಗಳು Claude Code ಇಟ್ಟ ಜಾಗದಲ್ಲೇ ಉಳಿಯುತ್ತವೆ

ccam ಎಂದಿಗೂ Claude ಲಾಗಿನ್ ಅನ್ನು ಒಂದು ಜಾಗದಿಂದ ಇನ್ನೊಂದಕ್ಕೆ ನಕಲಿಸುವುದಿಲ್ಲ. ಪ್ರತಿ ಖಾತೆಯ ಲಾಗಿನ್ ತನ್ನದೇ ಫೋಲ್ಡರ್‌ನಲ್ಲಿ, ಅಥವಾ macOS ನಲ್ಲಿ ಆ ಫೋಲ್ಡರ್‌ಗೇ ಸೇರಿದ Keychain ಐಟಂನಲ್ಲಿ ಉಳಿಯುತ್ತದೆ, ಮತ್ತು ಅದನ್ನು ನವೀಕರಿಸುವುದು Claude Code. ಹೊಂದಿಕೆ ತಪ್ಪಬಹುದಾದ ಉಳಿಸಿದ ಪ್ರತಿ ಯಾವುದೂ ಇಲ್ಲ. `ccam import` ಮೂಲಕ ನೋಂದಾಯಿಸಿದ ಈಗಾಗಲೇ ಇರುವ `~/.claude`, ಸಾಮಾನ್ಯ `claude` ಬಳಸುವ ಅದೇ Keychain ಐಟಂ ಅನ್ನು ಇಟ್ಟುಕೊಳ್ಳುತ್ತದೆ, ಆದ್ದರಿಂದ ಯಾವ ರೀತಿಯಲ್ಲಿ ಆರಂಭಿಸಿದರೂ ಅದು ಲಾಗಿನ್ ಆಗಿಯೇ ಇರುತ್ತದೆ.

ನೀವು `ccam usage --refresh` ರನ್ ಮಾಡಿದಾಗ ಮಾತ್ರ ccam ಅವಧಿ ಮುಗಿದ token ಅನ್ನು ತಾನೇ ನವೀಕರಿಸುತ್ತದೆ. ಅದು ಮೊದಲು ಲಾಕ್ ತೆಗೆದುಕೊಳ್ಳುತ್ತದೆ ಮತ್ತು ಆ ಖಾತೆ ರನ್ ಆಗುತ್ತಿದ್ದರೆ ನಿರಾಕರಿಸುತ್ತದೆ, ಆದ್ದರಿಂದ ಚಾಲ್ತಿಯಲ್ಲಿರುವ ಸೆಷನ್‌ನ ಕೆಳಗೆ ಅದು ಎಂದಿಗೂ token ಅನ್ನು ಬದಲಾಯಿಸುವುದಿಲ್ಲ.

### ನಿಮ್ಮ ಮತ್ತು Claude Code ನಡುವೆ ಏನೂ ರನ್ ಆಗುವುದಿಲ್ಲ

ccam ಒಂದು ಫೈಲ್ ಓದುತ್ತದೆ, ಅದರ ಲಿಂಕ್‌ಗಳನ್ನು ಪರಿಶೀಲಿಸುತ್ತದೆ ಮತ್ತು ತನ್ನ ಜಾಗದಲ್ಲಿ `claude` ಅನ್ನು ರನ್ ಮಾಡುತ್ತದೆ (`exec`). ನೀವು ಕೆಲಸ ಮಾಡುವಾಗ ccam ಪ್ರೊಸೆಸ್, wrapper, ಪ್ರಾಕ್ಸಿ ಅಥವಾ daemon ಯಾವುದೂ ಇರುವುದಿಲ್ಲ: standard input, signals ಮತ್ತು exit code Claude Code ಗೆ ಸೇರಿವೆ, ಮತ್ತು ಅದರ ವಿನಂತಿಗಳು ನೇರವಾಗಿ Anthropic ಗೆ ಹೋಗುತ್ತವೆ. Windows ಪ್ರೊಸೆಸ್ ಅನ್ನು ಬದಲಾಯಿಸಲು ಸಾಧ್ಯವಿಲ್ಲ, ಆದ್ದರಿಂದ ಅಲ್ಲಿ ccam ಅದೇ console ಜೊತೆ Claude Code ಅನ್ನು ಆರಂಭಿಸಿ ಅದರ exit code ಗಾಗಿ ಕಾಯುತ್ತದೆ, ಬೇರೇನೂ ಮಾಡುವುದಿಲ್ಲ.

ಈ ರೀತಿ ಖಾತೆಯನ್ನು ಆರಂಭಿಸುವುದು ಸುಮಾರು 4 ms ಸೇರಿಸುತ್ತದೆ, 95ನೇ percentile ನಲ್ಲಿ 6 ms ಗಿಂತ ಕಡಿಮೆ, ಗರಿಷ್ಠ ಮೆಮೊರಿ 8 MB ([`scripts/perf-check.sh`](https://github.com/jhyunwoo/ccam/blob/main/scripts/perf-check.sh), hyperfine ಜೊತೆ, 300 ರನ್‌ಗಳು). ಅದೇ ಲ್ಯಾಪ್‌ಟಾಪ್‌ನಲ್ಲಿ, ಪ್ರೋಗ್ರಾಂ ಏನನ್ನೂ ಮಾಡುವ ಮೊದಲೇ, Python interpreter ಅನ್ನು ಆರಂಭಿಸಲು ಮಾತ್ರ 13 ms ಮತ್ತು Node.js ಗೆ 31 ms ಬೇಕಾಗುತ್ತದೆ.

### ಏನನ್ನು ಹಂಚಿಕೊಳ್ಳಬೇಕು ಎಂದು ಗುಂಪುಗಳು ನಿರ್ಧರಿಸುತ್ತವೆ

MCP ಸರ್ವರ್‌ಗಳು, `settings.json`, `CLAUDE.md`, ಎಕ್ಸ್‌ಟೆನ್ಶನ್‌ಗಳು (agents, commands, skills, plugins) ಮತ್ತು ಸಂಭಾಷಣೆ ಇತಿಹಾಸ ಐದು ಪ್ರತ್ಯೇಕ ಐಟಂಗಳು. ಒಂದು ಗುಂಪು ತಾನು ಹಂಚಿಕೊಳ್ಳುವ ಐಟಂಗಳನ್ನು ಮತ್ತು ತನ್ನಲ್ಲಿರುವ ಖಾತೆಗಳನ್ನು ಹೆಸರಿಸುತ್ತದೆ. ಹೀಗಾಗಿ ಎರಡು ಕೆಲಸದ ಖಾತೆಗಳು `work` ಗುಂಪಿನಲ್ಲಿ ಇತಿಹಾಸ ಹಂಚಿಕೊಳ್ಳಬಹುದು, ವೈಯಕ್ತಿಕ ಖಾತೆ ತನ್ನದೇ ಇತಿಹಾಸ ಇಟ್ಟುಕೊಳ್ಳಬಹುದು, ಮತ್ತು ಮೂರೂ `default` ಮೂಲಕ ಒಂದೇ MCP ಸರ್ವರ್‌ಗಳನ್ನು ಹಂಚಿಕೊಳ್ಳಬಹುದು. `ccam group set work --add memory` ಗುಂಪಿನ ಪ್ರತಿ ಖಾತೆಯನ್ನೂ ಒಂದೇ ಯೋಜನೆಯಲ್ಲಿ ಸ್ಥಳಾಂತರಿಸುತ್ತದೆ; [ಡ್ಯಾಶ್‌ಬೋರ್ಡ್](/features/dashboard) ಚೆಕ್‌ಬಾಕ್ಸ್‌ಗಳ ಮೂಲಕ ಅದನ್ನೇ ಮಾಡುತ್ತದೆ, ಮತ್ತು ಖಾತೆ ಈಗಾಗಲೇ ಇನ್ನೊಂದು ಗುಂಪಿನಿಂದ ಪಡೆಯುತ್ತಿರುವ ಐಟಂ ಅನ್ನು ಬೂದು ಬಣ್ಣದಲ್ಲಿ ತೋರಿಸುತ್ತದೆ.

- MCP ಸರ್ವರ್‌ಗಳನ್ನು ಆರಂಭದಲ್ಲಿ `--mcp-config` ಮೂಲಕ ನೀಡಲಾಗುತ್ತದೆ, ಆದ್ದರಿಂದ ಡೀಫಾಲ್ಟ್ ಆಗಿ ccam ಎಂದಿಗೂ `.claude.json` ಅನ್ನು ಎಡಿಟ್ ಮಾಡುವುದಿಲ್ಲ; ಅದು Claude Code ರನ್ ಆಗುತ್ತಿರುವಾಗ ಮರುಬರೆಯುವ ಫೈಲ್. `ccam mcp add` ಒಂದು ಸರ್ವರ್ ಅನ್ನು ಇಡೀ ಗುಂಪಿಗೆ ಒಮ್ಮೆ ಸೇರಿಸುತ್ತದೆ.
- ಉಳಿದ ಐಟಂಗಳು ಗುಂಪಿನ ಫೋಲ್ಡರ್‌ಗೆ ಲಿಂಕ್‌ಗಳು, ಆದ್ದರಿಂದ ಒಂದು ಖಾತೆಯಲ್ಲಿ ಮಾಡಿದ ಬದಲಾವಣೆ ಇತರ ಖಾತೆಗಳಲ್ಲಿ ತಕ್ಷಣ ಕಾಣುತ್ತದೆ. ಆರಂಭದಲ್ಲಿ ಏನನ್ನೂ ನಕಲಿಸಲಾಗುವುದಿಲ್ಲ.
- ಲಾಗಿನ್‌ಗಳು, `.claude.json` ಮತ್ತು ರನ್ ಆಗುತ್ತಿರುವ ಸ್ಥಿತಿಯನ್ನು ಎಂದಿಗೂ ಹಂಚುವುದಿಲ್ಲ.

### ಪ್ರತಿ ಬದಲಾವಣೆಯನ್ನು ಮೊದಲು ತೋರಿಸಿ ಬ್ಯಾಕಪ್ ಮಾಡಲಾಗುತ್ತದೆ

`ccam group` ಮತ್ತು `ccam migrate` ಏನನ್ನಾದರೂ ಸರಿಸುವ ಮೊದಲು ಯೋಜನೆಯನ್ನು ಪ್ರಿಂಟ್ ಮಾಡಿ ಕೇಳುತ್ತವೆ. ಖಾತೆ ಮತ್ತು ಅದರ ಗುಂಪಿನ ನಡುವೆ ಫೈಲ್ ಭಿನ್ನವಾಗಿದ್ದರೆ, ನೀವೇ ಆಯ್ಕೆ ಮಾಡುತ್ತೀರಿ: ಗುಂಪಿನದನ್ನು ಉಳಿಸುವುದು, ನಿಮ್ಮದನ್ನು ಬಳಸುವುದು, ಅಥವಾ JSON ಅನ್ನು ವಿಲೀನಗೊಳಿಸುವುದು. ಮೂಲ ಫೈಲ್‌ಗಳು `.ccam-backup/<time>/` ಗೆ ಹೋಗುತ್ತವೆ, ತೆಗೆದುಹಾಕಿದ ಖಾತೆಯ ಫೋಲ್ಡರ್ ಕಸದ ಫೋಲ್ಡರ್‌ಗೆ ಹೋಗುತ್ತದೆ, ಮತ್ತು ಫೈಲ್‌ಗಳನ್ನು ಒಂದೇ rename ನಲ್ಲಿ ಬದಲಾಯಿಸಲಾಗುತ್ತದೆ, ಆದ್ದರಿಂದ ಅರ್ಧದಲ್ಲಿ ನಿಂತ ಬರಹ ಹಳೆಯ ಫೈಲ್ ಅನ್ನು ಹಾಗೆಯೇ ಬಿಡುತ್ತದೆ. ಆರಂಭ, ಹಂಚಿಕೆ, ಸ್ಥಳಾಂತರ, ಶಾರ್ಟ್‌ಕಟ್‌ಗಳು, ಅಪ್‌ಡೇಟ್‌ಗಳು ಮತ್ತು ದುರಸ್ತಿಗಳು ಏನು ಮಾಡುತ್ತವೆ ಎಂದು `--dry-run` ತೋರಿಸುತ್ತದೆ. `ccam doctor --fix` ಮುರಿದ ಲಿಂಕ್‌ಗಳು ಮತ್ತು ಅನುಮತಿಗಳನ್ನು ಸರಿಪಡಿಸುತ್ತದೆ.

### ಮುಂದಿನ ಖಾತೆಯಲ್ಲಿ ಅದೇ ಸಂಭಾಷಣೆ

`ccam next --auto --continue` ಎಲ್ಲಾ ಖಾತೆಗಳಿಂದ ಒಮ್ಮೆಗೇ ಬಳಕೆಯನ್ನು ಕೇಳಿ, ಹೆಚ್ಚು ಅವಕಾಶ ಇರುವ ಖಾತೆಯನ್ನು ತೆರೆದು, ಸಂಭಾಷಣೆಯನ್ನು ಮುಂದುವರಿಸುತ್ತದೆ. ಹಂಚಿಕೆಯ ಇತಿಹಾಸದೊಂದಿಗೆ ಅದು ಅದೇ ಸಂಭಾಷಣೆ; ಅದಿಲ್ಲದೆ, Claude Code ಅದನ್ನು ಹೊಸ ಖಾತೆಗೆ ನಕಲಿಸುತ್ತದೆ (`--resume <file> --fork-session`), ಮತ್ತು ಮೊದಲ ಉತ್ತರ ಎಷ್ಟು ಟೋಕನ್‌ಗಳನ್ನು ಮತ್ತೆ ಓದುತ್ತದೆ ಎಂದು ccam ಹೇಳುತ್ತದೆ. ಮಿತಿ ಒಂದು ಸೆಷನ್ ಅನ್ನು ನಿಲ್ಲಿಸಿದಾಗ, ccam ಪ್ಲಗಿನ್‌ನ ಹುಕ್ ಅಧಿಸೂಚನೆಯನ್ನು ತೋರಿಸುತ್ತದೆ, ಮತ್ತು `/ccam:switch` ಸಂಭಾಷಣೆಯನ್ನು ಮುಂದಕ್ಕೆ ಒಪ್ಪಿಸುತ್ತದೆ. ಯಾವಾಗ ಬದಲಾಯಿಸಬೇಕು ಎಂದು ನೀವೇ ನಿರ್ಧರಿಸುತ್ತೀರಿ; ಹಿನ್ನೆಲೆಯಲ್ಲಿ ಯಾವುದೂ ನಿಮ್ಮ ಬಳಕೆಯನ್ನು ಗಮನಿಸುವುದಿಲ್ಲ, ಮತ್ತು ಸ್ವಯಂಚಾಲಿತ ಆಯ್ಕೆಗಳು ಒಂದೇ ಸಂಸ್ಥೆಯೊಳಗೆ ಉಳಿಯುತ್ತವೆ, ಹೀಗಾಗಿ ಕಂಪನಿಯ ಸಂಭಾಷಣೆ ಆಕಸ್ಮಿಕವಾಗಿ ಖಾಸಗಿ ಖಾತೆಗೆ ಎಂದಿಗೂ ಹೋಗುವುದಿಲ್ಲ. ಖಾತೆ 90% ತಲುಪಿದಾಗ ಸ್ಟೇಟಸ್ ಲೈನ್ ಈ ಕಮಾಂಡ್ ಅನ್ನು ಸೂಚಿಸುತ್ತದೆ.

ಸ್ಕ್ರಿಪ್ಟ್‌ಗಳು ನಿಮಗಾಗಿ ಕಾಯಲಾರವು, ಆದ್ದರಿಂದ `ccam --fallback work -p "…"` ಅವುಗಳಿಗಾಗಿ ಬದಲಾಯಿಸುತ್ತದೆ: ಖಾತೆ ತನ್ನ ಮಿತಿ ತಲುಪಿದಾಗ, ಅದೇ ಕಮಾಂಡ್ ಹೆಚ್ಚು ಅವಕಾಶ ಇರುವ ಖಾತೆಯಾಗಿ ಮತ್ತೆ ರನ್ ಆಗುತ್ತದೆ, ಮತ್ತು ಪೂರ್ಣಗೊಂಡ ರನ್‌ನ ಔಟ್‌ಪುಟ್ ಮಾತ್ರ ಪ್ರಿಂಟ್ ಆಗುತ್ತದೆ. ಬಳಕೆಯ ಮಿತಿ ಅಲ್ಲದ ವೈಫಲ್ಯವನ್ನು ಹಾಗೆಯೇ ಮುಂದಕ್ಕೆ ಕಳುಹಿಸಲಾಗುತ್ತದೆ. ಸಮಾನಾಂತರ ವರ್ಕರ್‌ಗಳಿಗೆ, `ccam pick` ಪ್ರತಿಯೊಂದಕ್ಕೂ ಅವಕಾಶ ಇರುವ ಬೇರೆ ಖಾತೆಯನ್ನು ನೀಡುತ್ತದೆ, ಮತ್ತು ಯಾವ ಖಾತೆಯಲ್ಲೂ ಅವಕಾಶ ಉಳಿದಿಲ್ಲದಿದ್ದಾಗ ಎರಡೂ ಕೋಡ್ 75 ನೊಂದಿಗೆ ನಿರ್ಗಮಿಸುತ್ತವೆ.

### ಪ್ರತಿ ಫೋಲ್ಡರ್‌ನಲ್ಲಿ ಸರಿಯಾದ ಖಾತೆ

`ccam folder work ~/code/company` ಆ ಫೋಲ್ಡರ್‌ನೊಳಗೆ ಖಾತೆಯ ಹೆಸರಿಲ್ಲದ ಪ್ರತಿ ಆರಂಭವೂ `work` ಅನ್ನು ಬಳಸುವಂತೆ ಮಾಡುತ್ತದೆ, ಉಳಿದ ಪ್ರಾಜೆಕ್ಟ್‌ಗಳು ಡೀಫಾಲ್ಟ್ ಖಾತೆಯನ್ನೇ ಬಳಸುತ್ತವೆ. ಈ ಸೆಟ್ಟಿಂಗ್ ಪ್ರತಿ ಆರಂಭವೂ ಓದುವ ಅದೇ `config.toml` ನಲ್ಲಿ ಇರುತ್ತದೆ, ಆದ್ದರಿಂದ ಇದಕ್ಕೆ ಯಾವುದೇ ಸಮಯ ಹಿಡಿಯುವುದಿಲ್ಲ.

### ಒಂದೇ ಬೈನರಿ, ಪರಿಶೀಲಿಸಿದ ಡೌನ್‌ಲೋಡ್‌ಗಳು

ccam ಸುಮಾರು 10 MB ಇರುವ static ಬೈನರಿ, ಇನ್‌ಸ್ಟಾಲ್ ಮಾಡಬೇಕಾದ runtime ಯಾವುದೂ ಇಲ್ಲ, Linux, macOS ಮತ್ತು Windows ಗಾಗಿ. ಇನ್‌ಸ್ಟಾಲ್ ಸ್ಕ್ರಿಪ್ಟ್‌ಗಳು (`install.sh`, `install.ps1`) ಮತ್ತು `ccam update` ಪ್ರತಿ ಡೌನ್‌ಲೋಡ್ ಅನ್ನು release ನ SHA-256 checksums ಜೊತೆ ಪರಿಶೀಲಿಸುತ್ತವೆ, ಮತ್ತು ccam ಕೇಳದೆ ಎಂದಿಗೂ ಅಪ್‌ಡೇಟ್ ಆಗುವುದಿಲ್ಲ. ಇದರಲ್ಲಿ telemetry ಇಲ್ಲ: ಅದು ಮಾಡುವ ವಿನಂತಿಗಳೆಂದರೆ ನಿಮ್ಮ ಖಾತೆಗಳಿಗಾಗಿ Anthropic ಗೆ ಮಾಡುವ ಬಳಕೆ ಪರಿಶೀಲನೆಗಳು (ಸಮಾನಾಂತರವಾಗಿ, 3 ಸೆಕೆಂಡ್ ಮಿತಿ ಮತ್ತು 60 ಸೆಕೆಂಡ್ cache ಜೊತೆ), ಡ್ಯಾಶ್‌ಬೋರ್ಡ್ ತೆರೆದಾಗ ಇತ್ತೀಚಿನ release ಬಗ್ಗೆ GitHub ಗೆ ಕೇಳುವ ಪ್ರಶ್ನೆ, ಮತ್ತು ನೀವು ಕೇಳುವ ಡೌನ್‌ಲೋಡ್‌ಗಳು ಮಾತ್ರ. `usage_source = "claude"` ಇದ್ದರೆ, ಅವೂ Claude Code ಮೂಲಕವೇ ಹೋಗುತ್ತವೆ, ಮತ್ತು ccam ಎಂದಿಗೂ ಟೋಕನ್ ಅನ್ನು ನಿರ್ವಹಿಸುವುದಿಲ್ಲ.

## ಇತರ ಟೂಲ್‌ಗಳು ಎಲ್ಲಿ ಹೆಚ್ಚು ಮಾಡುತ್ತವೆ

- claude-swap, clauth, cux, CAAM ಮತ್ತು CCSwitcher, ಒಂದು ಖಾತೆ ಬಳಕೆಯ ಮಿತಿಯನ್ನು ದಾಟಿದಾಗ ರನ್ ಆಗುತ್ತಿರುವ ಇಂಟರ್‌ಆಕ್ಟಿವ್ ಸೆಷನ್ ಅನ್ನು ತಾವಾಗಿಯೇ ಬದಲಾಯಿಸಬಲ್ಲವು. ccam `-p` ರನ್‌ಗಳನ್ನು `--fallback` ಮೂಲಕ ಬದಲಾಯಿಸುತ್ತದೆ ಮತ್ತು ಇಂಟರ್‌ಆಕ್ಟಿವ್ ಸೆಷನ್‌ಗಳನ್ನು ನಿಮಗೆ ಬಿಡುತ್ತದೆ, ಮಿತಿಯಲ್ಲಿ ಅಧಿಸೂಚನೆ ಮತ್ತು `/ccam:switch` ಜೊತೆಗೆ.
- Developer Mode ಇಲ್ಲದ Windows ನಲ್ಲಿ, ccam ಫೋಲ್ಡರ್‌ಗಳನ್ನು ಹಂಚಿಕೊಳ್ಳುತ್ತದೆ ಆದರೆ `settings.json` ನಂತಹ ಒಂಟಿ ಫೈಲ್‌ಗಳನ್ನು ಹಂಚಿಕೊಳ್ಳಲು ಸಾಧ್ಯವಿಲ್ಲ; claude-swap ಮತ್ತು CCS ಅಲ್ಲಿ ಅವುಗಳನ್ನು ನಕಲಿಸುತ್ತವೆ.
- CCSwitcher, Claude Switcher ಮತ್ತು claude-swap ಬಳಕೆಯನ್ನು macOS ಮೆನು ಬಾರ್‌ನಲ್ಲಿ ತೋರಿಸುತ್ತವೆ.
- CCS, clausona, CAAM, clauth, ccswap ಮತ್ತು Claude Switcher, Codex ಮತ್ತು ಇತರ ಕೋಡಿಂಗ್ ಏಜೆಂಟ್‌ಗಳನ್ನೂ ನಿರ್ವಹಿಸುತ್ತವೆ.
- clausona ಖಾತೆವಾರು ಎಕ್ಸ್‌ಟೆನ್ಶನ್‌ಗಳನ್ನು ಆನ್ ಮತ್ತು ಆಫ್ ಕೂಡ ಮಾಡುತ್ತದೆ (ccam ನ `ccam ext` ಅವುಗಳನ್ನು ತೋರಿಸುತ್ತದೆ ಮಾತ್ರ), ಸ್ಥಳೀಯ ಟೋಕನ್ ವೆಚ್ಚವನ್ನು ದಾಖಲಿಸುತ್ತದೆ, ಮತ್ತು tmux ಹಾಗೂ ಇತರ ಟರ್ಮಿನಲ್‌ಗಳಲ್ಲಿ ವರ್ಕರ್‌ಗಳ ಗುಂಪನ್ನು ರನ್ ಮಾಡುವ Claude Code ಪ್ಲಗಿನ್‌ಗಳನ್ನು ಒದಗಿಸುತ್ತದೆ.
- CAAM, CCSwitcher ಮತ್ತು Claude Switcher, Homebrew ಮೂಲಕ ಇನ್‌ಸ್ಟಾಲ್ ಆಗುತ್ತವೆ, ಮತ್ತು clauth ಹಾಗೂ CAAM ತಮ್ಮ release checksums ಗೆ ಸಹಿ ಹಾಕುತ್ತವೆ. ccam ತನ್ನ ಸ್ಕ್ರಿಪ್ಟ್, ಒಂದು `.deb` ಅಥವಾ `go install` ಮೂಲಕ ಇನ್‌ಸ್ಟಾಲ್ ಆಗುತ್ತದೆ, ಮತ್ತು checksums ಅನ್ನು ಸಹಿ ಇಲ್ಲದೆ ಪರಿಶೀಲಿಸುತ್ತದೆ.

## ಯಾವುದು ಸೂಕ್ತ?

ನೀವು ಒಂದು ಸಮಯದಲ್ಲಿ ಒಂದೇ ಖಾತೆ ಬಳಸುತ್ತಿದ್ದರೆ, ಅಥವಾ ರನ್ ಆಗುತ್ತಿರುವ ಸೆಷನ್‌ಗಳು ತಾವಾಗಿಯೇ ಬದಲಾಗಬೇಕಿದ್ದರೆ, ಲಾಗಿನ್ ಬದಲಾಯಿಸುವ ಟೂಲ್ ಆಯ್ಕೆಮಾಡಿ. ಖಾತೆಗಳು ಅಕ್ಕಪಕ್ಕದಲ್ಲಿ, ಒಂದೇ ಹಂಚಿಕೆಯ ಸೆಟಪ್, ಮುಂದಿನ ಖಾತೆಯಲ್ಲಿ ಅದೇ ಸಂಭಾಷಣೆ, ಮತ್ತು Claude Code ಪಕ್ಕದಲ್ಲಿ ಏನೂ ರನ್ ಆಗದಿರುವುದು Linux, macOS ಅಥವಾ Windows ನಲ್ಲಿ ಬೇಕಿದ್ದರೆ ccam ಆಯ್ಕೆಮಾಡಿ. ಏನನ್ನೂ ಹಂಚಿಕೊಳ್ಳಬೇಕಿಲ್ಲದಿದ್ದರೆ, [ಸಾಮಾನ್ಯ ಶೆಲ್ ಅಲಿಯಾಸ್‌ಗಳು](/compare/aliases) ಸಾಕು.

ನೀವು ಹಲವು ಖಾತೆಗಳನ್ನು ಬಳಸಬಹುದೇ ಎಂಬುದು ಪ್ರತಿ ಖಾತೆಯ ನಿಯಮಗಳನ್ನು ಅವಲಂಬಿಸಿದೆ. ಬಳಸುವ ಮೊದಲು ಅವುಗಳನ್ನು ಪರಿಶೀಲಿಸಿ.
