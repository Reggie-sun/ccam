## ccam, Anthropic ನ ಅಧಿಕೃತ ಟೂಲ್ ಆಗಿದೆಯೇ?

ಇಲ್ಲ. ccam ಒಂದು ಅನಧಿಕೃತ ಓಪನ್-ಸೋರ್ಸ್ ಪ್ರಾಜೆಕ್ಟ್. ಇದು Anthropic ಜೊತೆ ಸಂಬಂಧ ಹೊಂದಿಲ್ಲ ಮತ್ತು Anthropic ಇದನ್ನು ಅನುಮೋದಿಸಿಲ್ಲ. ಹಲವು ಖಾತೆಗಳನ್ನು ಅಕ್ಕಪಕ್ಕದಲ್ಲಿ ರನ್ ಮಾಡಲು [Claude Code ದಸ್ತಾವೇಜಿನಲ್ಲಿ ವಿವರಿಸಿರುವ](https://code.claude.com/docs/en/env-vars) `CLAUDE_CONFIG_DIR` ಸೆಟ್ಟಿಂಗ್ ಅನ್ನು ಇದು ಬಳಸುತ್ತದೆ.

## ನಾನು ಹಲವು Claude Code ಖಾತೆಗಳನ್ನು ಬಳಸಲು ಅನುಮತಿ ಇದೆಯೇ?

ಅದು ಪ್ರತಿ ಖಾತೆಯ ನಿಯಮಗಳನ್ನು, ಮತ್ತು ಕೆಲಸದ ಖಾತೆಗಳಾದರೆ ನಿಮ್ಮ ಸಂಸ್ಥೆಯ ನೀತಿಯನ್ನು ಅವಲಂಬಿಸಿದೆ. ಹಲವು ಖಾತೆಗಳನ್ನು ಬಳಸುವ ಮೊದಲು ಅವುಗಳನ್ನು ಪರಿಶೀಲಿಸಿ. ನಿಮ್ಮ ಬಳಿ ಈಗಾಗಲೇ ಇರುವ ಖಾತೆಗಳ ನಡುವೆ ಬದಲಾಯಿಸುವುದನ್ನು ccam ಸುಲಭಗೊಳಿಸುತ್ತದೆ, ಅಷ್ಟೇ.

**Team ಮತ್ತು Enterprise ಸೀಟುಗಳು.** ಸ್ವಯಂಚಾಲಿತ ಆಯ್ಕೆ (`ccam next`, `--fallback`, `ccam pick`, ಡ್ಯಾಶ್‌ಬೋರ್ಡ್‌ನ `n`) ಒಂದೇ Claude Team ಅಥವಾ Enterprise ಸಂಸ್ಥೆಯ ಸೀಟುಗಳ ನಡುವೆಯೂ ಬದಲಾಯಿಸುತ್ತದೆ. Anthropic ನ ಸಹಾಯ ಕೇಂದ್ರವು "Each seat on a Team plan is assigned to one named individual, and only that person may use it" (Team ಪ್ಲಾನ್‌ನ ಪ್ರತಿ ಸೀಟನ್ನು ಹೆಸರಿಸಲಾದ ಒಬ್ಬ ವ್ಯಕ್ತಿಗೆ ನಿಯೋಜಿಸಲಾಗುತ್ತದೆ, ಮತ್ತು ಆ ವ್ಯಕ್ತಿ ಮಾತ್ರ ಅದನ್ನು ಬಳಸಬಹುದು) ಮತ್ತು "Users can't route their work through another user's account to use that user's remaining usage" (ಬಳಕೆದಾರರು ಇನ್ನೊಬ್ಬ ಬಳಕೆದಾರರ ಉಳಿದಿರುವ ಬಳಕೆಯನ್ನು ಉಪಯೋಗಿಸಿಕೊಳ್ಳಲು ತಮ್ಮ ಕೆಲಸವನ್ನು ಅವರ ಖಾತೆಯ ಮೂಲಕ ನಡೆಸುವಂತಿಲ್ಲ) ಎಂದು ಹೇಳುತ್ತದೆ ([Team ಪ್ಲಾನ್‌ಗಳು](https://support.claude.com/en/articles/12004354-purchase-and-manage-seats-on-team-plans#h_b8a7d07129); [Enterprise ಪ್ಲಾನ್‌ಗಳಿಗೂ](https://support.claude.com/en/articles/13393991-purchase-and-manage-seats-on-enterprise-plans#h_fa6b9cade0) ಇದೇ ಅನ್ವಯಿಸುತ್ತದೆ). ಆದ್ದರಿಂದ ಸೀಟುಗಳ ನಡುವೆ ಸ್ವಯಂಚಾಲಿತ ಆಯ್ಕೆಯನ್ನು ಬಳಸುವುದು Anthropic ನ ನಿಯಮಗಳನ್ನು ಉಲ್ಲಂಘಿಸಬಹುದು. ಇದನ್ನು ಅವಲಂಬಿಸುವ ಮೊದಲು ನಿಮ್ಮ ಸಂಸ್ಥೆ ಮತ್ತು Anthropic ಬಳಿ ವಿಚಾರಿಸಿ ಖಚಿತಪಡಿಸಿಕೊಳ್ಳಿ. ವೈಯಕ್ತಿಕ ಪ್ಲಾನ್‌ಗಳ (Pro, Max) ಬಗ್ಗೆ ಮೇಲಿನ ಕಂಡಿಕೆ ತಿಳಿಸುತ್ತದೆ.

## ccam ಬಳಕೆಯ ಮಿತಿಗಳನ್ನು ತಪ್ಪಿಸುತ್ತದೆಯೇ?

ಇಲ್ಲ. ಪ್ರತಿ ಖಾತೆಗೂ ಅದರದೇ ಮಿತಿಗಳು ಇರುತ್ತವೆ. ccam ಅವುಗಳನ್ನು ತೋರಿಸುತ್ತದೆ, ಮತ್ತು ಒಂದು ಖಾತೆಯ ಮಿತಿ ಮುಗಿದಾಗ ನಿಮ್ಮದೇ ಇನ್ನೊಂದು ಖಾತೆಯಲ್ಲಿ ಮುಂದುವರಿಸಲು ಅವಕಾಶ ನೀಡುತ್ತದೆ.

## ಒಂದೇ ಕಂಪ್ಯೂಟರ್‌ನಲ್ಲಿ ಎರಡು Claude Code ಖಾತೆಗಳನ್ನು ಹೇಗೆ ಬಳಸುವುದು?

`CLAUDE_CONFIG_DIR` ಮೂಲಕ ಪ್ರತಿ ಖಾತೆಗೂ ಅದರದೇ ಕಾನ್ಫಿಗರೇಶನ್ ಫೋಲ್ಡರ್ ನೀಡಿ. ccam ಇದನ್ನು ನಿಮಗಾಗಿ ಮಾಡುತ್ತದೆ: ಪ್ರತಿ ಖಾತೆಗೂ `ccam add` ರನ್ ಮಾಡಿ, ನಂತರ `ccam personal` ಮತ್ತು `ccam work` ಮೂಲಕ, ಅಥವಾ `ccwork` ನಂತಹ ನೀವೇ ಹೆಸರಿಡುವ ಶಾರ್ಟ್‌ಕಟ್‌ಗಳ ಮೂಲಕ ಅವುಗಳನ್ನು ಆರಂಭಿಸಿ. ಇದನ್ನು ಕೈಯಾರೆ ಹೇಗೆ ಮಾಡುವುದು ಎಂಬುದನ್ನೂ [ಮಾರ್ಗದರ್ಶಿ](/guides/multiple-claude-code-accounts) ತೋರಿಸುತ್ತದೆ.

## ಸಂಭಾಷಣೆಯನ್ನು ಇನ್ನೊಂದು ಖಾತೆಯಲ್ಲಿ ಹೇಗೆ ಮುಂದುವರಿಸುವುದು?

ಫೋಲ್ಡರ್‌ನಲ್ಲಿ `ccam next --continue` ರನ್ ಮಾಡಿ: ಅದು ಫೋಲ್ಡರ್‌ನ ಕೊನೆಯ ಸಂಭಾಷಣೆಯನ್ನು ಮುಂದಿನ ಖಾತೆಗೆ ಕೊಂಡೊಯ್ಯುತ್ತದೆ (ಹೆಚ್ಚು ಅವಕಾಶ ಇರುವ ಖಾತೆಗಾಗಿ `--auto`). Claude Code ಒಳಗೆ, [ccam ಪ್ಲಗಿನ್](/docs/install#claude-code-plugin) ನ `/ccam:switch` ನೀವು ಇರುವ ಸೆಷನ್‌ಗೆ ಅದನ್ನೇ ಮಾಡುತ್ತದೆ. ಎರಡು ಖಾತೆಗಳು ಸಂಭಾಷಣೆಯ ಇತಿಹಾಸವನ್ನು ಹಂಚಿಕೊಂಡಾಗ (`ccam group set default --add history`, ಅಥವಾ ಅವುಗಳಿಗೇ ಸ್ವಂತ ಗುಂಪಿನ ಮೂಲಕ: `ccam group add pair --items history --members work,side`), ಹೊಸ ಖಾತೆ ಅದೇ ಸಂಭಾಷಣೆಯನ್ನು ತೆರೆಯುತ್ತದೆ; ಇಲ್ಲದಿದ್ದರೆ Claude Code ಅದನ್ನು ಹೊಸ ಖಾತೆಯ ಇತಿಹಾಸಕ್ಕೆ ನಕಲಿಸುತ್ತದೆ.

## ccam ನನ್ನ ಲಾಗಿನ್ ಅನ್ನು ನೋಡುತ್ತದೆಯೇ ಅಥವಾ ಕಳುಹಿಸುತ್ತದೆಯೇ?

ccam ಎಂದಿಗೂ ನಿಮ್ಮ Claude ಲಾಗಿನ್ ಅನ್ನು ಖಾತೆಗಳ ನಡುವೆ ಹಂಚಿಕೊಳ್ಳುವುದಿಲ್ಲ ಅಥವಾ ನಕಲಿಸುವುದಿಲ್ಲ, ಮತ್ತು MCP ಸರ್ವರ್‌ಗಳ ಸೈನ್-ಇನ್‌ಗಳನ್ನು ಎಂದಿಗೂ ನಕಲಿಸುವುದಿಲ್ಲ. ನೀವು `ccam usage`, `ccam next --auto` ಅಥವಾ `ccam doctor` ರನ್ ಮಾಡಿದಾಗ ಮಾತ್ರ, ಆ ಖಾತೆಯ ಬಳಕೆಯನ್ನು Anthropic ನ ಬಳಕೆಯ ಎಂಡ್‌ಪಾಯಿಂಟ್‌ನಿಂದ ಕೇಳಲು, ಅದು ಖಾತೆಯ ಆಕ್ಸೆಸ್ ಟೋಕನ್ ಅನ್ನು ಓದುತ್ತದೆ, ಮತ್ತು ಅವಧಿ ಮುಗಿದ ಟೋಕನ್ ಅನ್ನು `ccam usage --refresh` ಮೂಲಕ ಮಾತ್ರ ನವೀಕರಿಸುತ್ತದೆ; `usage_source = "claude"` ಇದ್ದರೆ ಅದು ಟೋಕನ್ ಅನ್ನು ಓದುವುದೇ ಇಲ್ಲ. `ccam ext` ಮತ್ತು `ccam doctor` ಖಾತೆಯ MCP ಸೈನ್-ಇನ್‌ಗಳ ಹೆಸರುಗಳನ್ನು ಓದುತ್ತವೆ, ಅವುಗಳ ಟೋಕನ್‌ಗಳನ್ನು ಎಂದಿಗೂ ಓದುವುದಿಲ್ಲ. ccam ನಲ್ಲಿ ಯಾವುದೇ ಟೆಲಿಮೆಟ್ರಿ ಇಲ್ಲ. ಈ ಪರಿಶೀಲನೆಗಳನ್ನು ಬಿಟ್ಟರೆ, ಅದು ತಾನಾಗಿಯೇ ಮಾಡುವ ಏಕೈಕ ವಿನಂತಿ ಎಂದರೆ ಇತ್ತೀಚಿನ ccam ಬಿಡುಗಡೆಯ ಬಗ್ಗೆ ಡ್ಯಾಶ್‌ಬೋರ್ಡ್ GitHub ಗೆ ಕೇಳುವ ಪ್ರಶ್ನೆ, ಮತ್ತು ಅದರಲ್ಲಿ ನಿಮ್ಮ ಅಥವಾ ನಿಮ್ಮ ಖಾತೆಗಳ ಬಗ್ಗೆ ಏನೂ ಇರುವುದಿಲ್ಲ.

## ರಿಮೋಟ್ ಸರ್ವರ್‌ನಲ್ಲಿ ಸೈನ್ ಇನ್ ಮಾಡುವುದು ಹೇಗೆ?

SSH ಸೆಷನ್‌ನಲ್ಲಿ ಎಂದಿನಂತೆ `ccam add` ಅಥವಾ `ccam login <name>` ರನ್ ಮಾಡಿ. Claude Code ಸರ್ವರ್‌ನಲ್ಲಿ ಸೈನ್-ಇನ್‌ಗಾಗಿ ಕಾಯುತ್ತದೆ, ಆದ್ದರಿಂದ ನಿಮ್ಮ ಕಂಪ್ಯೂಟರ್‌ನ ಬ್ರೌಸರ್ ಕೊನೆಗೆ ಲೋಡ್ ಆಗದ `http://localhost:<port>/callback?code=…` ಪುಟವನ್ನು ತಲುಪುತ್ತದೆ. ಆ ವಿಳಾಸವನ್ನು ಬ್ರೌಸರ್‌ನಿಂದ ನಕಲಿಸಿ ಟರ್ಮಿನಲ್‌ಗೆ ಅಂಟಿಸಿ: ccam ಅದನ್ನು ಸರ್ವರ್‌ನಲ್ಲಿರುವ Claude Code ಗೆ ನೀಡುತ್ತದೆ, ಅದು ಸೈನ್-ಇನ್ ಅನ್ನು ಪೂರ್ಣಗೊಳಿಸುತ್ತದೆ. ವಿಳಾಸದಲ್ಲಿ ಒಮ್ಮೆ ಮಾತ್ರ ಬಳಸಬಹುದಾದ ಕೋಡ್ ಇರುತ್ತದೆ, ಆದ್ದರಿಂದ ಅದನ್ನು ಯಾರೊಂದಿಗೂ ಹಂಚಿಕೊಳ್ಳಬೇಡಿ.

## ನನ್ನ ಖಾತೆಗಳು ಎಲ್ಲಿ ಸಂಗ್ರಹವಾಗಿವೆ?

`~/.local/share/ccam/profiles/<name>/` ನಲ್ಲಿ, ಪ್ರತಿ ಖಾತೆಗೆ ಒಂದು ಫೋಲ್ಡರ್. macOS ನಲ್ಲಿ, Claude Code ಲಾಗಿನ್ ಅನ್ನು Keychain ನಲ್ಲಿ ಇರಿಸುತ್ತದೆ, ಆ ಫೋಲ್ಡರ್‌ನಿಂದ ಪಡೆದ ಒಂದು ಹೆಸರಿನಡಿ; ಆದ್ದರಿಂದ ಅಲ್ಲಿ `ccam rename` ಫೋಲ್ಡರ್‌ನ ಹಳೆಯ ಹೆಸರನ್ನೇ ಉಳಿಸಿಕೊಳ್ಳುತ್ತದೆ.

## ನನ್ನ ಈಗಿರುವ ~/.claude ಗೆ ಏನಾಗುತ್ತದೆ?

ನೀವು `ccam import` ಅಥವಾ `ccam migrate` ರನ್ ಮಾಡದ ಹೊರತು ಏನೂ ಆಗುವುದಿಲ್ಲ. Import ಫೋಲ್ಡರ್ ಅನ್ನು ಅದು ಇರುವಲ್ಲೇ ನೋಂದಾಯಿಸುತ್ತದೆ. ಹೀಗಾಗಿ ಸಾಮಾನ್ಯ `claude` ಮತ್ತು `ccam <name>` ಎರಡೂ ಅದೇ ಖಾತೆ ಮತ್ತು ಸೆಟ್ಟಿಂಗ್‌ಗಳನ್ನು ಬಳಸುತ್ತಲೇ ಇರುತ್ತವೆ. `ccam migrate` ಅದರ ಸೆಟ್ಟಿಂಗ್‌ಗಳು, `CLAUDE.md`, ವಿಸ್ತರಣೆಗಳು ಮತ್ತು MCP ಸರ್ವರ್‌ಗಳನ್ನು ಹಂಚಿಕೆಯ ಸೆಟ್ಟಿಂಗ್‌ಗಳಿಗೆ ನಕಲಿಸುತ್ತದೆ ಮತ್ತು ಫೋಲ್ಡರ್ ಅನ್ನು ಓದುತ್ತದೆ ಅಷ್ಟೇ.

## ccam ಯಾವ ಸಿಸ್ಟಮ್‌ಗಳನ್ನು ಬೆಂಬಲಿಸುತ್ತದೆ?

Linux (Ubuntu, Debian, Fedora, Arch, Alpine ಮತ್ತು ಇತರವು), macOS ಮತ್ತು Windows 10 ಹಾಗೂ 11, ನೇರವಾಗಿ ಅಥವಾ WSL ಒಳಗೆ. Windows ನಲ್ಲಿ, `settings.json` ನಂತಹ ಫೈಲ್‌ಗಳನ್ನು ಹಂಚಿಕೊಳ್ಳಲು Developer Mode ಬೇಕು; ಹಂಚಿಕೊಂಡ ಫೋಲ್ಡರ್‌ಗಳು ಅದಿಲ್ಲದೆಯೂ ಕೆಲಸ ಮಾಡುತ್ತವೆ, ಮತ್ತು ಅದಿಲ್ಲದಿದ್ದಾಗ ಮೊದಲ `ccam add` MCP ಸರ್ವರ್‌ಗಳು ಮತ್ತು ವಿಸ್ತರಣೆಗಳನ್ನು ಮಾತ್ರ ಹೊಂದಿರುವ `default` ಗುಂಪನ್ನು ರಚಿಸುತ್ತದೆ ([Windows ನಲ್ಲಿ ಹಂಚಿಕೆ](/features/share#on-windows)).

## ಒಂದು MCP ಸರ್ವರ್ ಒಂದೇ ಖಾತೆಯಲ್ಲಿ ಮಾತ್ರ ಏಕೆ ಕಾಣಿಸುತ್ತದೆ?

ಸೆಷನ್‌ನೊಳಗೆ `claude mcp add` ಮೂಲಕ ಸೇರಿಸಿದ ಸರ್ವರ್‌ಗಳು ಆ ಖಾತೆಗೆ ಮಾತ್ರ ಸಂಗ್ರಹವಾಗುತ್ತವೆ, ಮತ್ತು `-s user` ಇಲ್ಲದಿದ್ದರೆ ಈಗಿನ ಫೋಲ್ಡರ್‌ಗೆ ಮಾತ್ರ. ಮುಂದಿನ ಬಾರಿ ನೀವು ಆ ಖಾತೆಯನ್ನು ಆರಂಭಿಸಿದಾಗ ccam ಇದನ್ನು ನಿಮಗೆ ತಿಳಿಸುತ್ತದೆ, ಮತ್ತು `ccam mcp list` ಹಾಗೂ `ccam ext` ಅವುಗಳನ್ನು ತೋರಿಸುತ್ತವೆ; `ccam mcp import <account> <server>` ಮೂಲಕ ಸರ್ವರ್ ಅನ್ನು ಹಂಚಿಕೆಯ ಗುಂಪಿಗೆ ಸ್ಥಳಾಂತರಿಸಿ.

## ccam, Claude Code ಅನ್ನು ನಿಧಾನಗೊಳಿಸುತ್ತದೆಯೇ?

ccam ಮೂಲಕ Claude Code ಆರಂಭಿಸುವುದರಿಂದ ಸುಮಾರು 4 ಮಿಲಿಸೆಕೆಂಡ್ ಹೆಚ್ಚಾಗುತ್ತದೆ. ಇದನ್ನು ಒಂದು ಲ್ಯಾಪ್‌ಟಾಪ್‌ನಲ್ಲಿ `scripts/perf-check.sh` ಬಳಸಿ ಅಳೆಯಲಾಗಿದೆ. ccam ಒಂದು ಚಿಕ್ಕ ಫೈಲ್ ಓದುತ್ತದೆ, ಹಂಚಿಕೊಂಡ ಲಿಂಕ್‌ಗಳನ್ನು ಪರಿಶೀಲಿಸುತ್ತದೆ ಮತ್ತು ನಂತರ ತನ್ನನ್ನು `claude` ನಿಂದ ಬದಲಾಯಿಸಿಕೊಳ್ಳುತ್ತದೆ. ಹೀಗಾಗಿ ನೀವು ಕೆಲಸ ಮಾಡುತ್ತಿರುವಾಗ ಅದು ರನ್ ಆಗುತ್ತಿರುವುದಿಲ್ಲ. Windows ಪ್ರೊಸೆಸ್ ಅನ್ನು ಬದಲಾಯಿಸಲು ಸಾಧ್ಯವಿಲ್ಲ, ಆದ್ದರಿಂದ ಅಲ್ಲಿ ccam Claude Code ಅನ್ನು ಆರಂಭಿಸಿ ಅದಕ್ಕಾಗಿ ಕಾಯುತ್ತದೆ, ಬೇರೇನೂ ಮಾಡುವುದಿಲ್ಲ.

## ccam ಅನ್ನು ಅಪ್‌ಡೇಟ್ ಮಾಡುವುದು ಹೇಗೆ?

`ccam update` ರನ್ ಮಾಡಿ. ಅದು ಇತ್ತೀಚಿನ ಬಿಡುಗಡೆಯನ್ನು ಡೌನ್‌ಲೋಡ್ ಮಾಡಿ, ಅದರ ಚೆಕ್‌ಸಮ್ ಪರಿಶೀಲಿಸಿ, `ccam` ಫೈಲ್ ಅನ್ನು ಬದಲಾಯಿಸುತ್ತದೆ; `ccam update --check` ಹೊಸ ಬಿಡುಗಡೆ ಇದೆಯೇ ಎಂಬುದನ್ನು ಮಾತ್ರ ತಿಳಿಸುತ್ತದೆ. ಹೊಸ ಬಿಡುಗಡೆ ಇದ್ದಾಗ ಡ್ಯಾಶ್‌ಬೋರ್ಡ್ ಕೂಡ ತಿಳಿಸುತ್ತದೆ, ಮತ್ತು `U` ಕೇಳಿದ ನಂತರ ಅದನ್ನು ಇನ್‌ಸ್ಟಾಲ್ ಮಾಡುತ್ತದೆ; ccam ಎಂದಿಗೂ ತಾನಾಗಿಯೇ ಅಪ್‌ಡೇಟ್ ಆಗುವುದಿಲ್ಲ. ನೀವು `.deb` ಪ್ಯಾಕೇಜ್ ಇನ್‌ಸ್ಟಾಲ್ ಮಾಡಿದ್ದರೆ, ಬದಲಿಗೆ ಹೊಸ `.deb` ಅನ್ನು apt ಮೂಲಕ ಇನ್‌ಸ್ಟಾಲ್ ಮಾಡಿ. [ಅಪ್‌ಡೇಟ್](/docs/install#update) ನೋಡಿ.

## ccam ಅನ್ನು ಅನ್‌ಇನ್‌ಸ್ಟಾಲ್ ಮಾಡುವುದು ಹೇಗೆ?

ಪ್ರತಿ ಖಾತೆಯ ಶಾರ್ಟ್‌ಕಟ್ ಅನ್ನು `ccam shortcut <account> --remove` ಮೂಲಕ ತೆಗೆದುಹಾಕಿ. ನೀವು `~/.claude` ಅನ್ನು ಇಂಪೋರ್ಟ್ ಮಾಡಿದ್ದು ಅದು ಒಂದು ಗುಂಪಿನಲ್ಲಿದ್ದರೆ, ಮೊದಲು ಅದಕ್ಕಾಗಿ `ccam remove <name>` ರನ್ ಮಾಡಿ, ಇದರಿಂದ ಅದು ಹಂಚಿಕೊಳ್ಳುವುದರ ಒಂದು ಪ್ರತಿ ಅದಕ್ಕೆ ಮರಳಿ ಸಿಗುತ್ತದೆ. ನಂತರ `~/.local/bin` ನಿಂದ `ccam` ಅನ್ನು ಅಳಿಸಿ, ಮತ್ತು ನಿಮಗೆ ಖಾತೆಗಳು ಇನ್ನು ಬೇಡವಾದರೆ `~/.config/ccam`, `~/.local/share/ccam` ಮತ್ತು `~/.local/state/ccam` ಅನ್ನೂ ಅಳಿಸಿ. [ಇನ್‌ಸ್ಟಾಲ್](/docs/install#uninstall) ನೋಡಿ.
