## ccam, Anthropic ನ ಅಧಿಕೃತ ಟೂಲ್ ಆಗಿದೆಯೇ?

ಇಲ್ಲ. ccam ಒಂದು ಅನಧಿಕೃತ ಓಪನ್-ಸೋರ್ಸ್ ಪ್ರಾಜೆಕ್ಟ್. ಇದು Anthropic ಜೊತೆ ಸಂಬಂಧ ಹೊಂದಿಲ್ಲ ಮತ್ತು Anthropic ಇದನ್ನು ಅನುಮೋದಿಸಿಲ್ಲ. ಹಲವು ಖಾತೆಗಳನ್ನು ಅಕ್ಕಪಕ್ಕದಲ್ಲಿ ರನ್ ಮಾಡಲು [Claude Code ದಸ್ತಾವೇಜಿನಲ್ಲಿ ವಿವರಿಸಿರುವ](https://code.claude.com/docs/en/env-vars) `CLAUDE_CONFIG_DIR` ಸೆಟ್ಟಿಂಗ್ ಅನ್ನು ಇದು ಬಳಸುತ್ತದೆ.

## ನಾನು ಹಲವು Claude Code ಖಾತೆಗಳನ್ನು ಬಳಸಲು ಅನುಮತಿ ಇದೆಯೇ?

ಅದು ಪ್ರತಿ ಖಾತೆಯ ನಿಯಮಗಳನ್ನು, ಮತ್ತು ಕೆಲಸದ ಖಾತೆಗಳಾದರೆ ನಿಮ್ಮ ಸಂಸ್ಥೆಯ ನೀತಿಯನ್ನು ಅವಲಂಬಿಸಿದೆ: Pro ಮತ್ತು Max ಗೆ Anthropic ನ [ಗ್ರಾಹಕ ನಿಯಮಗಳು (Consumer Terms)](https://www.anthropic.com/legal/consumer-terms), Team ಮತ್ತು Enterprise ಗೆ ಅದರ [ವಾಣಿಜ್ಯ ನಿಯಮಗಳು (Commercial Terms)](https://www.anthropic.com/legal/commercial-terms), ಮತ್ತು ಎಲ್ಲದಕ್ಕೂ ಅದರ [ಬಳಕೆಯ ನೀತಿ (Usage Policy)](https://www.anthropic.com/legal/aup). ಹಲವು ಖಾತೆಗಳನ್ನು ಬಳಸುವ ಮೊದಲು ಅವುಗಳನ್ನು ಪರಿಶೀಲಿಸಿ. ccam ಯಾವುದೇ ಖಾತೆಯ ಮಿತಿಗಳನ್ನು ಹೆಚ್ಚಿಸುವುದಿಲ್ಲ, ವಿಲೀನಗೊಳಿಸುವುದಿಲ್ಲ ಅಥವಾ ಮರೆಮಾಡುವುದಿಲ್ಲ, ಮತ್ತು ಪ್ರತಿ ಖಾತೆಯೂ ತನ್ನದೇ ಮಿತಿಯಲ್ಲಿ ನಿಲ್ಲುತ್ತದೆ. ನೀವು ಕೇಳಿದಾಗ ಅದು ನಿಮ್ಮ ಕೆಲಸವನ್ನು ನಿಮ್ಮ ಇನ್ನೊಂದು ಖಾತೆಗೆ ಸ್ಥಳಾಂತರಿಸುತ್ತದೆ, ಅಥವಾ ನೀವು [`auto_switch`](/features/next#auto-switch) ಅನ್ನು ಆನ್ ಮಾಡಿದಾಗ (Linux ಮತ್ತು macOS) ಮಿತಿಯಲ್ಲಿ ತಾನಾಗಿಯೇ ಸ್ಥಳಾಂತರಿಸುತ್ತದೆ. ಇದನ್ನು ಬಳಸುವ ಮೊದಲು ಇದು ನಿಮ್ಮ ಖಾತೆಗಳಿಗೆ ಅನುಮತಿತವೇ ಎಂದು ಪರಿಶೀಲಿಸಿ; ನಿರ್ಧಾರ ನಿಮ್ಮದು.

**Team ಮತ್ತು Enterprise ಸೀಟುಗಳು.** ಸ್ವಯಂಚಾಲಿತ ಖಾತೆ ಆಯ್ಕೆ (`ccam next`, `--fallback`, `ccam pick`, ಡ್ಯಾಶ್‌ಬೋರ್ಡ್‌ನ `n` ಮತ್ತು ನೀವು ಆನ್ ಮಾಡಿದಾಗ [`auto_switch`](/features/next#auto-switch)) ಒಂದೇ Claude Team ಅಥವಾ Enterprise ಸಂಸ್ಥೆಯ ಸೀಟುಗಳ ನಡುವೆಯೂ ಬದಲಾಯಿಸುತ್ತದೆ. Anthropic ನ ಸಹಾಯ ಕೇಂದ್ರವು "Each seat on a Team plan is assigned to one named individual, and only that person may use it" (Team ಪ್ಲಾನ್‌ನ ಪ್ರತಿ ಸೀಟನ್ನು ಹೆಸರಿಸಲಾದ ಒಬ್ಬ ವ್ಯಕ್ತಿಗೆ ನಿಯೋಜಿಸಲಾಗುತ್ತದೆ, ಮತ್ತು ಆ ವ್ಯಕ್ತಿ ಮಾತ್ರ ಅದನ್ನು ಬಳಸಬಹುದು) ಮತ್ತು "Users can't route their work through another user's account to use that user's remaining usage" (ಬಳಕೆದಾರರು ಇನ್ನೊಬ್ಬ ಬಳಕೆದಾರರ ಉಳಿದಿರುವ ಬಳಕೆಯನ್ನು ಉಪಯೋಗಿಸಿಕೊಳ್ಳಲು ತಮ್ಮ ಕೆಲಸವನ್ನು ಅವರ ಖಾತೆಯ ಮೂಲಕ ನಡೆಸುವಂತಿಲ್ಲ) ಎಂದು ಹೇಳುತ್ತದೆ ([Team ಪ್ಲಾನ್‌ಗಳು](https://support.claude.com/en/articles/12004354-purchase-and-manage-seats-on-team-plans#h_b8a7d07129); [Enterprise ಪ್ಲಾನ್‌ಗಳಿಗೂ](https://support.claude.com/en/articles/13393991-purchase-and-manage-seats-on-enterprise-plans#h_fa6b9cade0) ಇದೇ ಅನ್ವಯಿಸುತ್ತದೆ). ಆದ್ದರಿಂದ ಸೀಟುಗಳ ನಡುವೆ ಸ್ವಯಂಚಾಲಿತ ಖಾತೆ ಆಯ್ಕೆಯನ್ನು ಬಳಸುವುದು Anthropic ನ ನಿಯಮಗಳನ್ನು ಉಲ್ಲಂಘಿಸಬಹುದು. ಅಲ್ಲಿ ಇದನ್ನು ಬಳಸಬೇಕೆ ಎಂಬುದು ನಿಮ್ಮ ನಿರ್ಧಾರ: ಇದನ್ನು ಅವಲಂಬಿಸುವ ಮೊದಲು ನಿಮ್ಮ ಸಂಸ್ಥೆ ಮತ್ತು Anthropic ಬಳಿ ವಿಚಾರಿಸಿ ಖಚಿತಪಡಿಸಿಕೊಳ್ಳಿ. ವೈಯಕ್ತಿಕ ಪ್ಲಾನ್‌ಗಳ (Pro, Max) ಬಗ್ಗೆ ಮೇಲಿನ ಕಂಡಿಕೆ ತಿಳಿಸುತ್ತದೆ.

## ccam ಬಳಕೆಯ ಮಿತಿಗಳನ್ನು ತಪ್ಪಿಸುತ್ತದೆಯೇ?

ಯಾವುದೇ ಖಾತೆಯ ಸ್ವಂತ ಮಿತಿಯನ್ನು ದಾಟಿ ಅಲ್ಲ: ಪ್ರತಿ ಖಾತೆಯೂ ತನ್ನ ಮಿತಿಗಳನ್ನು ಉಳಿಸಿಕೊಂಡು ಅವುಗಳಲ್ಲಿ ನಿಲ್ಲುತ್ತದೆ, ಮತ್ತು ccam ಅವುಗಳನ್ನು ಹೆಚ್ಚಿಸುವುದಿಲ್ಲ, ವಿಲೀನಗೊಳಿಸುವುದಿಲ್ಲ ಅಥವಾ ಮರೆಮಾಡುವುದಿಲ್ಲ. ccam ಅವುಗಳನ್ನು ತೋರಿಸುತ್ತದೆ, ಮತ್ತು ಒಂದು ಖಾತೆಯ ಮಿತಿ ಮುಗಿದಾಗ ನಿಮ್ಮ ಇನ್ನೊಂದು ಖಾತೆಯಲ್ಲಿ ಮುಂದುವರಿಸಲು ಅವಕಾಶ ನೀಡುತ್ತದೆ; `auto_switch` ಆನ್ ಆಗಿದ್ದರೆ, ಅದನ್ನು ತಾನಾಗಿಯೇ ಮಾಡುತ್ತದೆ (ಮುಂದಿನ ಪ್ರಶ್ನೆ ನೋಡಿ). ಒಂದೇ Team ಅಥವಾ Enterprise ಸಂಸ್ಥೆಯ ಸೀಟುಗಳ ನಡುವೆ, ಇನ್ನೊಂದು ಸೀಟಿನಲ್ಲಿ ಮುಂದುವರಿಸುವುದು ಆ ಸೀಟಿನ ಉಳಿದ ಬಳಕೆಯನ್ನು ಉಪಯೋಗಿಸುತ್ತದೆ, ಮತ್ತು ಇನ್ನೊಬ್ಬ ಬಳಕೆದಾರರ ಸೀಟಿನ ವಿಷಯದಲ್ಲಿ Anthropic ನ ಸಹಾಯ ಕೇಂದ್ರ ಇದನ್ನು ನಿಷೇಧಿಸುತ್ತದೆ (ಮೇಲಿನ Team ಮತ್ತು Enterprise ಸೀಟುಗಳು ನೋಡಿ).

## ಸೆಷನ್ ತನ್ನ ಮಿತಿ ತಲುಪಿದಾಗ ccam ತಾನಾಗಿಯೇ ಖಾತೆ ಬದಲಾಯಿಸಬಲ್ಲದೇ?

ನೀವು ಆನ್ ಮಾಡಿದರೆ ಮಾತ್ರ. `~/.config/ccam/config.toml` ನ ಮೇಲ್ಭಾಗದಲ್ಲಿ `auto_switch = true` ಇದ್ದರೆ (Linux ಮತ್ತು macOS; ಡೀಫಾಲ್ಟ್ ಆಗಿ ಆಫ್, ಮತ್ತು ಪ್ರಾಯೋಗಿಕ), Claude Code ಒಂದು ಇಂಟರ್‌ಆಕ್ಟಿವ್ ಸೆಷನ್ ಅನ್ನು (ccam ಆರಂಭಿಸಿದ ಸೆಷನ್) 5 ಗಂಟೆಯ, ವಾರದ, Opus ಅಥವಾ Sonnet ಮಿತಿಯಲ್ಲಿ ನಿಲ್ಲಿಸಿದಾಗ, ccam ಸೆಷನ್ ಅನ್ನು ಕೊನೆಗೊಳಿಸಿ ಸಂಭಾಷಣೆಯನ್ನು ಅವಕಾಶ ಇರುವ ನಿಮ್ಮ ಇನ್ನೊಂದು ಖಾತೆಯಾಗಿ ಮುಂದುವರಿಸುತ್ತದೆ: ಅದೇ Team ಅಥವಾ Enterprise ಸಂಸ್ಥೆಯ ಇನ್ನೊಂದು ಸೀಟು, ಅಥವಾ ಇನ್ನೊಂದು ವೈಯಕ್ತಿಕ ಪ್ಲಾನ್ (Pro, Max). ಅದು ಮಿತಿಗೆ ಮೊದಲು ಎಂದಿಗೂ ಬದಲಾಯಿಸುವುದಿಲ್ಲ, ಹಿನ್ನೆಲೆಯಲ್ಲಿ ನಿಮ್ಮ ಬಳಕೆಯನ್ನು ಎಂದಿಗೂ ಗಮನಿಸುವುದಿಲ್ಲ, ಮತ್ತು ಕೆಲಸವನ್ನು Team ಅಥವಾ Enterprise ಸಂಸ್ಥೆಯಿಂದ ಹೊರಗೆ, ಅಥವಾ ಅದರೊಳಗೆ, ಎಂದಿಗೂ ಸ್ಥಳಾಂತರಿಸುವುದಿಲ್ಲ.

ಸೀಟುಗಳಲ್ಲಿ ಅದು ನಿಮ್ಮ ಕೆಲಸವನ್ನು ಒಂದು ಸೀಟಿನಿಂದ ಇನ್ನೊಂದಕ್ಕೆ ಸ್ಥಳಾಂತರಿಸುತ್ತದೆ, ಇದು Anthropic ನ ನಿಯಮಗಳನ್ನು ಉಲ್ಲಂಘಿಸಬಹುದು (ಮೇಲಿನ Team ಮತ್ತು Enterprise ಸೀಟುಗಳು ನೋಡಿ). ವೈಯಕ್ತಿಕ ಪ್ಲಾನ್‌ಗಳ ವಿಷಯದಲ್ಲಿ Anthropic ನ ನಿಯಮಗಳು ಇದನ್ನು ಸ್ಪಷ್ಟವಾಗಿ ತಿಳಿಸುವುದಿಲ್ಲ: Anthropic ಸ್ಪಷ್ಟವಾಗಿ ಅನುಮತಿಸದ ಹೊರತು, Consumer Terms ಸೇವೆಗಳನ್ನು "through automated or non-human means" (ಸ್ವಯಂಚಾಲಿತ ಅಥವಾ ಮಾನವೇತರ ವಿಧಾನಗಳ ಮೂಲಕ) ಬಳಸುವುದನ್ನು ನಿಷೇಧಿಸುತ್ತವೆ, ಮತ್ತು ಒಂದು ಸ್ಥಳಾಂತರ ನಿಮ್ಮ ಪರವಾಗಿ ಒಂದು ಸಂದೇಶವನ್ನು ಕಳುಹಿಸುತ್ತದೆ. ಇದನ್ನು ಆನ್ ಮಾಡುವುದು ನಿಮ್ಮ ನಿರ್ಧಾರ.

[`auto_switch`](/features/next#auto-switch) ಪ್ರತಿ ಷರತ್ತನ್ನು ಮತ್ತು ಒಂದು ಸ್ಥಳಾಂತರಕ್ಕೆ ಏನು ವೆಚ್ಚವಾಗುತ್ತದೆ ಎಂಬುದನ್ನು ಪಟ್ಟಿ ಮಾಡುತ್ತದೆ.

## ಒಂದೇ ಕಂಪ್ಯೂಟರ್‌ನಲ್ಲಿ ಎರಡು Claude Code ಖಾತೆಗಳನ್ನು ಹೇಗೆ ಬಳಸುವುದು?

`CLAUDE_CONFIG_DIR` ಮೂಲಕ ಪ್ರತಿ ಖಾತೆಗೂ ಅದರದೇ ಕಾನ್ಫಿಗರೇಶನ್ ಫೋಲ್ಡರ್ ನೀಡಿ. ccam ಇದನ್ನು ನಿಮಗಾಗಿ ಮಾಡುತ್ತದೆ: ಪ್ರತಿ ಖಾತೆಗೂ `ccam add` ರನ್ ಮಾಡಿ, ನಂತರ `ccam personal` ಮತ್ತು `ccam work` ಮೂಲಕ, ಅಥವಾ `ccwork` ನಂತಹ ನೀವೇ ಹೆಸರಿಡುವ ಶಾರ್ಟ್‌ಕಟ್‌ಗಳ ಮೂಲಕ ಅವುಗಳನ್ನು ಆರಂಭಿಸಿ. ಇದನ್ನು ಕೈಯಾರೆ ಹೇಗೆ ಮಾಡುವುದು ಎಂಬುದನ್ನೂ [ಮಾರ್ಗದರ್ಶಿ](/guides/multiple-claude-code-accounts) ತೋರಿಸುತ್ತದೆ.

## ಸಂಭಾಷಣೆಯನ್ನು ಇನ್ನೊಂದು ಖಾತೆಯಲ್ಲಿ ಹೇಗೆ ಮುಂದುವರಿಸುವುದು?

ಫೋಲ್ಡರ್‌ನಲ್ಲಿ `ccam next --continue` ರನ್ ಮಾಡಿ: ಅದು ಫೋಲ್ಡರ್‌ನ ಕೊನೆಯ ಸಂಭಾಷಣೆಯನ್ನು ಮುಂದಿನ ಖಾತೆಗೆ ಕೊಂಡೊಯ್ಯುತ್ತದೆ (ಹೆಚ್ಚು ಅವಕಾಶ ಇರುವ ಖಾತೆಗಾಗಿ `--auto`). Claude Code ಒಳಗೆ, [ccam ಪ್ಲಗಿನ್](/docs/install#claude-code-plugin) ನ `/ccam:switch` ನೀವು ಇರುವ ಸೆಷನ್‌ಗೆ ಅದನ್ನೇ ಮಾಡುತ್ತದೆ. ಎರಡು ಖಾತೆಗಳು ಸಂಭಾಷಣೆಯ ಇತಿಹಾಸವನ್ನು ಹಂಚಿಕೊಂಡಾಗ (`ccam group set default --add history`, ಅಥವಾ ಅವುಗಳಿಗೇ ಸ್ವಂತ ಗುಂಪಿನ ಮೂಲಕ: `ccam group add pair --items history --members work,side`), ಹೊಸ ಖಾತೆ ಅದೇ ಸಂಭಾಷಣೆಯನ್ನು ತೆರೆಯುತ್ತದೆ; ಇಲ್ಲದಿದ್ದರೆ Claude Code ಅದನ್ನು ಹೊಸ ಖಾತೆಯ ಇತಿಹಾಸಕ್ಕೆ ನಕಲಿಸುತ್ತದೆ. ಸಂಪೂರ್ಣ ಸಂಭಾಷಣೆಯ ಬದಲು ಚಿಕ್ಕ ಸಾರಾಂಶದಿಂದ ಹೊಸ ಖಾತೆಯನ್ನು ಆರಂಭಿಸಲು `--brief` ಸೇರಿಸಿ.

## ccam ನನ್ನ ಲಾಗಿನ್ ಅನ್ನು ನೋಡುತ್ತದೆಯೇ ಅಥವಾ ಕಳುಹಿಸುತ್ತದೆಯೇ?

ccam ಎಂದಿಗೂ ನಿಮ್ಮ Claude ಲಾಗಿನ್ ಅನ್ನು ಖಾತೆಗಳ ನಡುವೆ ಹಂಚಿಕೊಳ್ಳುವುದಿಲ್ಲ ಅಥವಾ ನಕಲಿಸುವುದಿಲ್ಲ, ಮತ್ತು MCP ಸರ್ವರ್‌ಗಳ ಸೈನ್-ಇನ್‌ಗಳನ್ನು ಎಂದಿಗೂ ನಕಲಿಸುವುದಿಲ್ಲ. ಆ ಖಾತೆಯ ಬಳಕೆಯನ್ನು Anthropic ನ ಬಳಕೆಯ ಎಂಡ್‌ಪಾಯಿಂಟ್‌ನಿಂದ ಕೇಳಲು ಮಾತ್ರ ಅದು ಖಾತೆಯ ಆಕ್ಸೆಸ್ ಟೋಕನ್ ಅನ್ನು ಓದುತ್ತದೆ: `ccam usage`, ಡ್ಯಾಶ್‌ಬೋರ್ಡ್, `ccam doctor` ಮತ್ತು ಸ್ವಯಂಚಾಲಿತ ಆಯ್ಕೆಗಾಗಿ (`ccam next --auto`, `ccam pick`, `--fallback`, ಮತ್ತು ಸೆಷನ್ ತನ್ನ ಮಿತಿ ತಲುಪಿದಾಗ `auto_switch`). ಅವಧಿ ಮುಗಿದ ಟೋಕನ್ ಅನ್ನು ಅದು `ccam usage --refresh` ಮೂಲಕ ಮಾತ್ರ ನವೀಕರಿಸುತ್ತದೆ; `usage_source = "claude"` ಇದ್ದರೆ ಅದು ಎಲ್ಲಿಗೂ ಯಾವುದೇ ಟೋಕನ್ ಕಳುಹಿಸುವುದಿಲ್ಲ, ಮತ್ತು ಉಳಿಸಿದ ಲಾಗಿನ್ (ಫೈಲ್, ಅಥವಾ macOS Keychain ನಮೂದು) ಇನ್ನೂ ಕೆಲಸ ಮಾಡುತ್ತಿದೆಯೇ ಎಂದು ತಿಳಿಯಲು ಮಾತ್ರ ಅದನ್ನು ಓದುತ್ತದೆ. `ccam ext` ಮತ್ತು `ccam doctor` ಖಾತೆಯ MCP ಸೈನ್-ಇನ್‌ಗಳ ಹೆಸರುಗಳನ್ನು ಓದುತ್ತವೆ, ಅವುಗಳ ಟೋಕನ್‌ಗಳನ್ನು ಎಂದಿಗೂ ಓದುವುದಿಲ್ಲ. ccam ನಲ್ಲಿ ಯಾವುದೇ ಟೆಲಿಮೆಟ್ರಿ ಇಲ್ಲ. ಈ ಪರಿಶೀಲನೆಗಳನ್ನು ಬಿಟ್ಟರೆ, ಅದು ತಾನಾಗಿಯೇ ಮಾಡುವ ಏಕೈಕ ವಿನಂತಿ ಎಂದರೆ ಹೊಸ ccam ಬಿಡುಗಡೆ ಇದೆಯೇ ಎಂದು ಡ್ಯಾಶ್‌ಬೋರ್ಡ್ GitHub ನಲ್ಲಿ ಮಾಡುವ ಪರಿಶೀಲನೆ, ಮತ್ತು ಅದರಲ್ಲಿ ನಿಮ್ಮ ಅಥವಾ ನಿಮ್ಮ ಖಾತೆಗಳ ಬಗ್ಗೆ ಏನೂ ಇರುವುದಿಲ್ಲ.

## ರಿಮೋಟ್ ಸರ್ವರ್‌ನಲ್ಲಿ ಸೈನ್ ಇನ್ ಮಾಡುವುದು ಹೇಗೆ?

SSH ಸೆಷನ್‌ನಲ್ಲಿ ಎಂದಿನಂತೆ `ccam add` ಅಥವಾ `ccam login <name>` ರನ್ ಮಾಡಿ. Claude Code ಸರ್ವರ್‌ನಲ್ಲಿ ಸೈನ್-ಇನ್‌ಗಾಗಿ ಕಾಯುತ್ತದೆ, ಆದ್ದರಿಂದ ನಿಮ್ಮ ಕಂಪ್ಯೂಟರ್‌ನ ಬ್ರೌಸರ್ ಕೊನೆಗೆ ಲೋಡ್ ಆಗದ `http://localhost:<port>/callback?code=…` ಪುಟವನ್ನು ತಲುಪುತ್ತದೆ. ಆ ವಿಳಾಸವನ್ನು ಬ್ರೌಸರ್‌ನಿಂದ ನಕಲಿಸಿ ಟರ್ಮಿನಲ್‌ಗೆ ಅಂಟಿಸಿ: ccam ಅದನ್ನು ಸರ್ವರ್‌ನಲ್ಲಿರುವ Claude Code ಗೆ ನೀಡುತ್ತದೆ, ಅದು ಸೈನ್-ಇನ್ ಅನ್ನು ಪೂರ್ಣಗೊಳಿಸುತ್ತದೆ. ವಿಳಾಸದಲ್ಲಿ ಒಮ್ಮೆ ಮಾತ್ರ ಬಳಸಬಹುದಾದ ಕೋಡ್ ಇರುತ್ತದೆ, ಆದ್ದರಿಂದ ಅದನ್ನು ಯಾರೊಂದಿಗೂ ಹಂಚಿಕೊಳ್ಳಬೇಡಿ.

## ನನ್ನ ಖಾತೆಗಳು ಎಲ್ಲಿ ಸಂಗ್ರಹವಾಗಿವೆ?

`~/.local/share/ccam/profiles/<name>/` ನಲ್ಲಿ, ಪ್ರತಿ ಖಾತೆಗೆ ಒಂದು ಫೋಲ್ಡರ್. macOS ನಲ್ಲಿ, Claude Code ಲಾಗಿನ್ ಅನ್ನು Keychain ನಲ್ಲಿ ಇರಿಸುತ್ತದೆ, ಆ ಫೋಲ್ಡರ್‌ನಿಂದ ಪಡೆದ ಒಂದು ಹೆಸರಿನಡಿ; ಆದ್ದರಿಂದ ಅಲ್ಲಿ `ccam rename` ಫೋಲ್ಡರ್‌ನ ಹಳೆಯ ಹೆಸರನ್ನೇ ಉಳಿಸಿಕೊಳ್ಳುತ್ತದೆ.

## ನನ್ನ ಈಗಿರುವ ~/.claude ಗೆ ಏನಾಗುತ್ತದೆ?

ನೀವು `ccam import` ಅಥವಾ `ccam migrate` ರನ್ ಮಾಡದ ಹೊರತು ಏನೂ ಆಗುವುದಿಲ್ಲ. Import ಫೋಲ್ಡರ್ ಅನ್ನು ಅದು ಇರುವಲ್ಲೇ ನೋಂದಾಯಿಸುತ್ತದೆ. ಹೀಗಾಗಿ ಸಾಮಾನ್ಯ `claude` ಮತ್ತು `ccam <name>` ಎರಡೂ ಅದೇ ಖಾತೆ ಮತ್ತು ಸೆಟ್ಟಿಂಗ್‌ಗಳನ್ನು ಬಳಸುತ್ತಲೇ ಇರುತ್ತವೆ. `ccam migrate` ಅದರ ಸೆಟ್ಟಿಂಗ್‌ಗಳು, `CLAUDE.md`, ವಿಸ್ತರಣೆಗಳು ಮತ್ತು MCP ಸರ್ವರ್‌ಗಳನ್ನು ಹಂಚಿಕೆಯ `default` ಗುಂಪಿಗೆ ನಕಲಿಸುತ್ತದೆ ಮತ್ತು ಫೋಲ್ಡರ್ ಅನ್ನು ಓದುತ್ತದೆ ಅಷ್ಟೇ.

## ccam ಯಾವ ಸಿಸ್ಟಮ್‌ಗಳನ್ನು ಬೆಂಬಲಿಸುತ್ತದೆ?

Linux (Ubuntu, Debian, Fedora, Arch, Alpine ಮತ್ತು ಇತರವು), macOS ಮತ್ತು Windows 10 ಹಾಗೂ 11, ನೇರವಾಗಿ ಅಥವಾ WSL ಒಳಗೆ. Windows ನಲ್ಲಿ, `settings.json` ನಂತಹ ಫೈಲ್‌ಗಳನ್ನು ಹಂಚಿಕೊಳ್ಳಲು Developer Mode ಬೇಕು; ಹಂಚಿಕೊಂಡ ಫೋಲ್ಡರ್‌ಗಳು ಅದಿಲ್ಲದೆಯೂ ಕೆಲಸ ಮಾಡುತ್ತವೆ, ಮತ್ತು ಅದಿಲ್ಲದಿದ್ದಾಗ ಮೊದಲ `ccam add` MCP ಸರ್ವರ್‌ಗಳು ಮತ್ತು ವಿಸ್ತರಣೆಗಳನ್ನು ಮಾತ್ರ ಹೊಂದಿರುವ `default` ಗುಂಪನ್ನು ರಚಿಸುತ್ತದೆ ([Windows ನಲ್ಲಿ ಹಂಚಿಕೆ](/features/share#on-windows)).

## ಒಂದು MCP ಸರ್ವರ್ ಒಂದೇ ಖಾತೆಯಲ್ಲಿ ಮಾತ್ರ ಏಕೆ ಕಾಣಿಸುತ್ತದೆ?

ಸೆಷನ್‌ನೊಳಗೆ `claude mcp add` ಮೂಲಕ ಸೇರಿಸಿದ ಸರ್ವರ್‌ಗಳು ಆ ಖಾತೆಗೆ ಮಾತ್ರ ಸಂಗ್ರಹವಾಗುತ್ತವೆ, ಮತ್ತು `-s user` ಇಲ್ಲದಿದ್ದರೆ ಈಗಿನ ಫೋಲ್ಡರ್‌ಗೆ ಮಾತ್ರ. ಮುಂದಿನ ಬಾರಿ ನೀವು ಆ ಖಾತೆಯನ್ನು ಆರಂಭಿಸಿದಾಗ ccam ಇದನ್ನು ನಿಮಗೆ ತಿಳಿಸುತ್ತದೆ, ಮತ್ತು `ccam mcp list` ಹಾಗೂ `ccam ext` ಅವುಗಳನ್ನು ತೋರಿಸುತ್ತವೆ; `ccam mcp import <account> <server>` ಮೂಲಕ ಸರ್ವರ್ ಅನ್ನು ಹಂಚಿಕೆಯ ಗುಂಪಿಗೆ ಸ್ಥಳಾಂತರಿಸಿ.

## ccam, Claude Code ಅನ್ನು ನಿಧಾನಗೊಳಿಸುತ್ತದೆಯೇ?

ccam ಮೂಲಕ Claude Code ಆರಂಭಿಸುವುದರಿಂದ ಸುಮಾರು 4 ಮಿಲಿಸೆಕೆಂಡ್ ಹೆಚ್ಚಾಗುತ್ತದೆ. ಇದನ್ನು ಒಂದು ಲ್ಯಾಪ್‌ಟಾಪ್‌ನಲ್ಲಿ `scripts/perf-check.sh` ಬಳಸಿ ಅಳೆಯಲಾಗಿದೆ. ccam ಒಂದು ಚಿಕ್ಕ ಫೈಲ್ ಓದುತ್ತದೆ, ಹಂಚಿಕೊಂಡ ಲಿಂಕ್‌ಗಳನ್ನು ಪರಿಶೀಲಿಸುತ್ತದೆ ಮತ್ತು ನಂತರ ತನ್ನನ್ನು `claude` ನಿಂದ ಬದಲಾಯಿಸಿಕೊಳ್ಳುತ್ತದೆ. ಹೀಗಾಗಿ ಡೀಫಾಲ್ಟ್ ಆಗಿ ನೀವು ಕೆಲಸ ಮಾಡುತ್ತಿರುವಾಗ ಅದು ರನ್ ಆಗುತ್ತಿರುವುದಿಲ್ಲ. Windows ಪ್ರೊಸೆಸ್ ಅನ್ನು ಬದಲಾಯಿಸಲು ಸಾಧ್ಯವಿಲ್ಲ, ಆದ್ದರಿಂದ ಅಲ್ಲಿ ccam Claude Code ಅನ್ನು ಆರಂಭಿಸಿ ಅದಕ್ಕಾಗಿ ಕಾಯುತ್ತದೆ, ಬೇರೇನೂ ಮಾಡುವುದಿಲ್ಲ. `relay` ಅಥವಾ `auto_switch` ಆನ್ ಆಗಿದ್ದರೆ, ccam ಪ್ರತಿ ಇಂಟರ್‌ಆಕ್ಟಿವ್ ಸೆಷನ್‌ನ ಜೊತೆಯಲ್ಲೇ ಇದೇ ರೀತಿ ರನ್ ಆಗುತ್ತಿರುತ್ತದೆ, ಹೀಗಾಗಿ ಅದು ಸಂಭಾಷಣೆಯನ್ನು ಇನ್ನೊಂದು ಖಾತೆಯಲ್ಲಿ ಮುಂದುವರಿಸಬಲ್ಲದು.

## ccam ಅನ್ನು ಅಪ್‌ಡೇಟ್ ಮಾಡುವುದು ಹೇಗೆ?

`ccam update` ರನ್ ಮಾಡಿ. ಅದು ಇತ್ತೀಚಿನ ಬಿಡುಗಡೆಯನ್ನು ಡೌನ್‌ಲೋಡ್ ಮಾಡಿ, ಅದರ ಚೆಕ್‌ಸಮ್ ಪರಿಶೀಲಿಸಿ, `ccam` ಫೈಲ್ ಅನ್ನು ಬದಲಾಯಿಸುತ್ತದೆ; `ccam update --check` ಹೊಸ ಬಿಡುಗಡೆ ಇದೆಯೇ ಎಂಬುದನ್ನು ಮಾತ್ರ ತಿಳಿಸುತ್ತದೆ. ಹೊಸ ಬಿಡುಗಡೆ ಇದ್ದಾಗ ಡ್ಯಾಶ್‌ಬೋರ್ಡ್ ಕೂಡ ತಿಳಿಸುತ್ತದೆ, ಮತ್ತು `U` ಕೇಳಿದ ನಂತರ ಅದನ್ನು ಇನ್‌ಸ್ಟಾಲ್ ಮಾಡುತ್ತದೆ; ccam ಎಂದಿಗೂ ತಾನಾಗಿಯೇ ಅಪ್‌ಡೇಟ್ ಆಗುವುದಿಲ್ಲ. ನೀವು `.deb` ಪ್ಯಾಕೇಜ್ ಇನ್‌ಸ್ಟಾಲ್ ಮಾಡಿದ್ದರೆ, ಬದಲಿಗೆ ಹೊಸ `.deb` ಅನ್ನು apt ಮೂಲಕ ಇನ್‌ಸ್ಟಾಲ್ ಮಾಡಿ. [ಅಪ್‌ಡೇಟ್](/docs/install#update) ನೋಡಿ.

## ccam ಅನ್ನು ಅನ್‌ಇನ್‌ಸ್ಟಾಲ್ ಮಾಡುವುದು ಹೇಗೆ?

ಪ್ರತಿ ಖಾತೆಯ ಶಾರ್ಟ್‌ಕಟ್ ಅನ್ನು `ccam shortcut <account> --remove` ಮೂಲಕ ತೆಗೆದುಹಾಕಿ. ನೀವು `~/.claude` ಅನ್ನು ಇಂಪೋರ್ಟ್ ಮಾಡಿದ್ದು ಅದು ಒಂದು ಗುಂಪಿನಲ್ಲಿದ್ದರೆ, ಮೊದಲು ಅದಕ್ಕಾಗಿ `ccam remove <name>` ರನ್ ಮಾಡಿ, ಇದರಿಂದ ಅದು ಹಂಚಿಕೊಳ್ಳುವುದರ ಒಂದು ಪ್ರತಿ ಅದಕ್ಕೆ ಮರಳಿ ಸಿಗುತ್ತದೆ. ನಂತರ `~/.local/bin` ನಿಂದ `ccam` ಅನ್ನು ಅಳಿಸಿ, ಮತ್ತು ನಿಮಗೆ ಖಾತೆಗಳು ಇನ್ನು ಬೇಡವಾದರೆ `~/.config/ccam`, `~/.local/share/ccam` ಮತ್ತು `~/.local/state/ccam` ಅನ್ನೂ ಅಳಿಸಿ. [ಇನ್‌ಸ್ಟಾಲ್](/docs/install#uninstall) ನೋಡಿ.
