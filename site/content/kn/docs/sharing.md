ಪ್ರತಿ ಖಾತೆಯ ಲಾಗಿನ್ ಅದರದೇ ಆಗಿರುತ್ತದೆ. ಉಳಿದ ಎಲ್ಲವನ್ನೂ ಐಟಂವಾರು ಹಂಚಿಕೊಳ್ಳಬಹುದು: ccam ಖಾತೆಯ ಫೈಲ್ ಅಥವಾ ಫೋಲ್ಡರ್ ಅನ್ನು ಹಂಚಿಕೆಯ ಗುಂಪಿನ ಫೋಲ್ಡರ್‌ಗೆ ಲಿಂಕ್ ಮಾಡುತ್ತದೆ. ಹೀಗಾಗಿ ಒಂದು ಖಾತೆಯಲ್ಲಿ ಮಾಡಿದ ಬದಲಾವಣೆ ಆ ಗುಂಪಿನ ಎಲ್ಲಾ ಖಾತೆಗಳಲ್ಲೂ ಕಾಣಿಸುತ್ತದೆ.

## ಏನನ್ನು ಹಂಚಿಕೊಳ್ಳಬಹುದು

| ಐಟಂ | ಆಯ್ಕೆ | ಏನು ಹಂಚಿಕೆಯಾಗುತ್ತದೆ |
| --- | --- | --- |
| MCP ಸರ್ವರ್‌ಗಳು | `--mcp` | ಗುಂಪಿನ `mcp.json`, ಆರಂಭದಲ್ಲಿ Claude Code ಗೆ ರವಾನೆಯಾಗುತ್ತದೆ |
| ಸೆಟ್ಟಿಂಗ್‌ಗಳು | `--settings` | `settings.json`: ಅನುಮತಿಗಳು, hooks, ಮಾಡೆಲ್, ಸ್ಟೇಟಸ್ ಲೈನ್ |
| ಜಾಗತಿಕ ಮೆಮೊರಿ | `--memory` | `CLAUDE.md` |
| ವಿಸ್ತರಣೆಗಳು | `--extensions` | `agents/`, `commands/`, `skills/`, `plugins/`, `output-styles/`, `rules/` |
| ಸಂಭಾಷಣೆಯ ಇತಿಹಾಸ | `--history` | `projects/` ಮತ್ತು `history.jsonl` |

ಹೊಸ ಖಾತೆಗಳು ಸಂಭಾಷಣೆಯ ಇತಿಹಾಸವನ್ನು ಹೊರತುಪಡಿಸಿ ಎಲ್ಲವನ್ನೂ ಹಂಚಿಕೊಳ್ಳುತ್ತವೆ.

ಲಾಗಿನ್ ಫೈಲ್‌ಗಳಾದ `.credentials.json` ಮತ್ತು `.claude.json` ಎಂದಿಗೂ ಹಂಚಿಕೆಯಾಗುವುದಿಲ್ಲ. ccam ಒಂದು ನಿಗದಿತ ಪಟ್ಟಿಯಲ್ಲಿರುವ ಪಾತ್‌ಗಳನ್ನು ಮಾತ್ರ ಲಿಂಕ್ ಮಾಡುತ್ತದೆ, ಮತ್ತು ಈ ಎರಡು ಆ ಪಟ್ಟಿಯಲ್ಲಿಲ್ಲ.

## ಗುಂಪುಗಳು

`on` ಎಂದರೆ `default` ಗುಂಪು. ನೀವು ಒಂದು ಹೆಸರನ್ನೂ ನೀಡಬಹುದು. ಆಗ ಕೆಲವು ಖಾತೆಗಳು ಮಾತ್ರ ಒಂದು ಐಟಂ ಅನ್ನು ಹಂಚಿಕೊಳ್ಳುತ್ತವೆ:

```sh
ccam share work --history team
ccam share side --history team
```

ಈಗ `work` ಮತ್ತು `side` ಪರಸ್ಪರ ಸಂಭಾಷಣೆಗಳನ್ನು ಹಂಚಿಕೊಳ್ಳುತ್ತವೆ, ಆದರೆ ನಿಮ್ಮ ಇತರ ಖಾತೆಗಳೊಂದಿಗೆ ಅಲ್ಲ.

## ಹಂಚಿಕೆಯನ್ನು ಆನ್ ಮಾಡುವುದು

ಒಂದು ಖಾತೆ ಒಂದು ಐಟಂ ಅನ್ನು ಹಂಚಿಕೊಳ್ಳಲು ಆರಂಭಿಸಿದಾಗ, ccam:

1. ತಾನು ಸ್ಥಳಾಂತರಿಸುವ, ನಕಲಿಸುವ ಅಥವಾ ಲಿಂಕ್ ಮಾಡುವ ಪ್ರತಿ ಫೈಲ್‌ನ ಯೋಜನೆಯನ್ನು ಮುದ್ರಿಸುತ್ತದೆ ಮತ್ತು ಆರಂಭಿಸುವ ಮೊದಲು ಕೇಳುತ್ತದೆ;
2. ಗುಂಪು ಇನ್ನೂ ಖಾಲಿಯಾಗಿದ್ದರೆ ಖಾತೆಯ ಫೈಲ್‌ಗಳನ್ನು ಗುಂಪಿನ ಫೋಲ್ಡರ್‌ಗೆ ಸ್ಥಳಾಂತರಿಸುತ್ತದೆ, ಇಲ್ಲದಿದ್ದರೆ ಗುಂಪಿನಲ್ಲಿ ಇನ್ನೂ ಇಲ್ಲದ ಫೈಲ್‌ಗಳನ್ನು ಸೇರಿಸುತ್ತದೆ;
3. ಒಂದೇ ಫೈಲ್ ಬೇರೆ ಬೇರೆಯಾಗಿದ್ದರೆ, ಗುಂಪಿನ ಆವೃತ್ತಿಯನ್ನು ಉಳಿಸಿಕೊಳ್ಳಬೇಕೇ, ನಿಮ್ಮದನ್ನು ಬಳಸಬೇಕೇ, ಅಥವಾ JSON ಅನ್ನು ವಿಲೀನಗೊಳಿಸಬೇಕೇ ಎಂದು ಕೇಳುತ್ತದೆ;
4. ನಿಮ್ಮ ಮೂಲ ಫೈಲ್ ಅನ್ನು ಖಾತೆಯ ಫೋಲ್ಡರ್‌ನೊಳಗಿನ `.ccam-backup/<time>/` ನಲ್ಲಿ ಇರಿಸುತ್ತದೆ;
5. ಮೂಲ ಫೈಲ್‌ನ ಜಾಗದಲ್ಲಿ ಗುಂಪಿಗೆ ಒಂದು ಲಿಂಕ್ ಇರಿಸುತ್ತದೆ.

ಸಂಭಾಷಣೆಯ ಫೈಲ್‌ಗಳಿಗೆ ಅವುಗಳ ಸೆಷನ್ ID ಯ ಹೆಸರು ಇರುತ್ತದೆ. ಹೀಗಾಗಿ ಹಲವು ಖಾತೆಗಳ ಇತಿಹಾಸಗಳು ಯಾವುದೇ ಸಂಘರ್ಷವಿಲ್ಲದೆ ಒಂದಾಗುತ್ತವೆ.

## ಹಂಚಿಕೆಯನ್ನು ಆಫ್ ಮಾಡುವುದು

```sh
ccam share work --history off
```

ಲಿಂಕ್ ತೆಗೆದುಹಾಕಲಾಗುತ್ತದೆ ಮತ್ತು ಖಾತೆಗೆ ಗುಂಪಿನ ಈಗಿನ ವಿಷಯದ ತನ್ನದೇ ಆದ ಪ್ರತಿ ಸಿಗುತ್ತದೆ. ಬದಲಿಗೆ ಖಾಲಿಯಾಗಿ ಆರಂಭಿಸಲು `--fresh` ಸೇರಿಸಿ. ಗುಂಪು ತನ್ನ ವಿಷಯವನ್ನು ಇತರ ಖಾತೆಗಳಿಗಾಗಿ ಉಳಿಸಿಕೊಳ್ಳುತ್ತದೆ.

## MCP ಸರ್ವರ್‌ಗಳು

Claude Code MCP ಸರ್ವರ್‌ಗಳನ್ನು ಲಾಗಿನ್ ಜೊತೆಗೆ `.claude.json` ನಲ್ಲಿ ಸಂಗ್ರಹಿಸುತ್ತದೆ. ಆದ್ದರಿಂದ ಆ ಫೈಲ್ ಅನ್ನು ಹಂಚಿಕೊಳ್ಳಲು ಸಾಧ್ಯವಿಲ್ಲ. ccam ಹಂಚಿಕೊಂಡ ಸರ್ವರ್‌ಗಳನ್ನು ಗುಂಪಿನ `mcp.json` ನಲ್ಲಿ ಇರಿಸುತ್ತದೆ ಮತ್ತು Claude Code ಅನ್ನು `--mcp-config=<group>/mcp.json` ನೊಂದಿಗೆ ಆರಂಭಿಸುತ್ತದೆ. ನಿಮ್ಮದೇ `--mcp-config` ಆಯ್ಕೆಗಳು ಅದರ ಮೇಲೆ ಇನ್ನೂ ಅನ್ವಯವಾಗುತ್ತವೆ.

```sh
ccam mcp add fs -- npx -y @modelcontextprotocol/server-filesystem ~/code
ccam mcp list
```

ಸೆಷನ್‌ನೊಳಗೆ `claude mcp add` ಮೂಲಕ ನೀವು ಸೇರಿಸುವ ಸರ್ವರ್ ಆ ಖಾತೆಗೆ ಮಾತ್ರ ಉಳಿಸಲ್ಪಡುತ್ತದೆ. ಮುಂದಿನ ಬಾರಿ ನೀವು ಆ ಖಾತೆಯನ್ನು ಆರಂಭಿಸಿದಾಗ, ccam ಆ ಸರ್ವರ್‌ನ ಹೆಸರನ್ನು ಮತ್ತು ಅದನ್ನು ಗುಂಪಿಗೆ ಸ್ಥಳಾಂತರಿಸುವ ಕಮಾಂಡ್ ಅನ್ನು ತಿಳಿಸುತ್ತದೆ:

```sh
ccam mcp import work gh
```

OAuth ಮೂಲಕ ಸೈನ್ ಇನ್ ಆಗುವ MCP ಸರ್ವರ್‌ಗಳು ತಮ್ಮ ಟೋಕನ್‌ಗಳನ್ನು ಖಾತೆಯ ಲಾಗಿನ್ ಜೊತೆ ಸಂಗ್ರಹಿಸುತ್ತವೆ. ಆದ್ದರಿಂದ ಪ್ರತಿ ಖಾತೆಯಲ್ಲೂ ಅವುಗಳನ್ನು ಒಮ್ಮೆ ಅಧಿಕೃತಗೊಳಿಸಿ.

ಸರ್ವರ್‌ಗಳು `claude mcp list` ಮತ್ತು `/mcp` ನಲ್ಲಿ ಸಾಮಾನ್ಯ ಬಳಕೆದಾರ ಸರ್ವರ್‌ಗಳಾಗಿ ಕಾಣಬೇಕು ಎಂದು ನೀವು ಬಯಸಿದರೆ, `~/.config/ccam/config.toml` ನಲ್ಲಿ `mcp_strategy = "sync"` ಹೊಂದಿಸಿ. ಆಗ ccam ಆರಂಭಿಸುವ ಮೊದಲು ಅವುಗಳನ್ನು ಪ್ರತಿ ಖಾತೆಯ `.claude.json` ನಲ್ಲಿ ಬರೆಯುತ್ತದೆ. ಇದನ್ನು Claude Code ನ ಸ್ವಂತ ಫೈಲ್ ಲಾಕ್ ಅಡಿಯಲ್ಲಿ ಮತ್ತು ಬ್ಯಾಕಪ್‌ನೊಂದಿಗೆ ಮಾಡುತ್ತದೆ.

## ಒಂದೇ ಫೋಲ್ಡರ್‌ನಲ್ಲಿ ಎರಡು ಖಾತೆಗಳು

ಸಂಭಾಷಣೆಯ ಇತಿಹಾಸವನ್ನು ಹಂಚಿಕೊಳ್ಳುವ ಖಾತೆಗಳು ಒಂದೇ ಫೈಲ್‌ಗಳಿಗೆ ಬರೆಯುತ್ತವೆ. ಅದೇ ಗುಂಪಿನ ಇನ್ನೊಂದು ಖಾತೆ ಈಗಾಗಲೇ ರನ್ ಆಗುತ್ತಿರುವ ಫೋಲ್ಡರ್‌ನಲ್ಲಿ ನೀವು ಎರಡನೇ Claude Code ಆರಂಭಿಸಿದರೆ, ccam ನಿಮ್ಮನ್ನು ಎಚ್ಚರಿಸುತ್ತದೆ ಮತ್ತು ಮುಂದುವರಿಯಬೇಕೇ ಎಂದು ಕೇಳುತ್ತದೆ.

## ಏನಾದರೂ ಕೆಟ್ಟುಹೋದಾಗ

```sh
ccam doctor
ccam doctor --fix
```

ಹಂಚಿಕೊಂಡ ಪಾತ್ ಒಂದು ಸಾಮಾನ್ಯ ಫೈಲ್ ಆಗಿಬಿಟ್ಟಿದ್ದರೆ, ಉದಾಹರಣೆಗೆ ನೀವು ಕೈಯಾರೆ ಬ್ಯಾಕಪ್ ಅನ್ನು ಮರುಸ್ಥಾಪಿಸಿದ ನಂತರ, ccam Claude Code ಆರಂಭಿಸುವ ಮೊದಲೇ ನಿಲ್ಲುತ್ತದೆ ಮತ್ತು `ccam doctor --fix` ಅನ್ನು ಸೂಚಿಸುತ್ತದೆ. ಅದು ಆ ಫೈಲ್ ಅನ್ನು ಗುಂಪಿನೊಂದಿಗೆ ವಿಲೀನಗೊಳಿಸುತ್ತದೆ ಮತ್ತು ಬ್ಯಾಕಪ್ ಇರಿಸುತ್ತದೆ.
