`ccam pick` ಲಾಗಿನ್ ಆಗಿರುವ, ಹೆಚ್ಚು ಅವಕಾಶ ಇರುವ ಖಾತೆಯ ಹೆಸರನ್ನು ಮುದ್ರಿಸುತ್ತದೆ, ಇದರಿಂದ ಸ್ಕ್ರಿಪ್ಟ್ ಆ ಖಾತೆಯಲ್ಲಿ Claude Code ಅನ್ನು ಆರಂಭಿಸಬಹುದು. ಅವಕಾಶ ಇರುವ ಸಾಕಷ್ಟು ಖಾತೆಗಳಿರುವವರೆಗೆ, ಒಂದೇ ಸಮಯದಲ್ಲಿ ಆರಂಭವಾದ ವರ್ಕರ್‌ಗಳಿಗೆ ತಲಾ ಬೇರೆ ಖಾತೆ ಸಿಗುತ್ತದೆ. ಹೀಗಾಗಿ `claude -p` ಕೆಲಸಗಳ ಗುಂಪು ಒಂದೇ ಖಾತೆಯನ್ನು ಖಾಲಿ ಮಾಡುವ ಬದಲು ನಿಮ್ಮ ಖಾತೆಗಳಾದ್ಯಂತ ಹಂಚಿಹೋಗುತ್ತದೆ.

**Team ಮತ್ತು Enterprise ಸೀಟುಗಳು.** ಸ್ವಯಂಚಾಲಿತ ಆಯ್ಕೆ (`ccam next`, `--fallback`, `ccam pick`, ಡ್ಯಾಶ್‌ಬೋರ್ಡ್‌ನ `n`) ಒಂದೇ Claude Team ಅಥವಾ Enterprise ಸಂಸ್ಥೆಯ ಸೀಟುಗಳ ನಡುವೆಯೂ ಬದಲಾಯಿಸುತ್ತದೆ. Anthropic ನ ಸಹಾಯ ಕೇಂದ್ರವು "Each seat on a Team plan is assigned to one named individual, and only that person may use it" (Team ಪ್ಲಾನ್‌ನ ಪ್ರತಿ ಸೀಟನ್ನು ಹೆಸರಿಸಲಾದ ಒಬ್ಬ ವ್ಯಕ್ತಿಗೆ ನಿಯೋಜಿಸಲಾಗುತ್ತದೆ, ಮತ್ತು ಆ ವ್ಯಕ್ತಿ ಮಾತ್ರ ಅದನ್ನು ಬಳಸಬಹುದು) ಮತ್ತು "Users can't route their work through another user's account to use that user's remaining usage" (ಬಳಕೆದಾರರು ಇನ್ನೊಬ್ಬ ಬಳಕೆದಾರರ ಉಳಿದಿರುವ ಬಳಕೆಯನ್ನು ಉಪಯೋಗಿಸಿಕೊಳ್ಳಲು ತಮ್ಮ ಕೆಲಸವನ್ನು ಅವರ ಖಾತೆಯ ಮೂಲಕ ನಡೆಸುವಂತಿಲ್ಲ) ಎಂದು ಹೇಳುತ್ತದೆ ([Team ಪ್ಲಾನ್‌ಗಳು](https://support.claude.com/en/articles/12004354-purchase-and-manage-seats-on-team-plans#h_b8a7d07129); [Enterprise ಪ್ಲಾನ್‌ಗಳಿಗೂ](https://support.claude.com/en/articles/13393991-purchase-and-manage-seats-on-enterprise-plans#h_fa6b9cade0) ಇದೇ ಅನ್ವಯಿಸುತ್ತದೆ). ಆದ್ದರಿಂದ ಸೀಟುಗಳ ನಡುವೆ ಸ್ವಯಂಚಾಲಿತ ಆಯ್ಕೆಯನ್ನು ಬಳಸುವುದು Anthropic ನ ನಿಯಮಗಳನ್ನು ಉಲ್ಲಂಘಿಸಬಹುದು. ಇದನ್ನು ಅವಲಂಬಿಸುವ ಮೊದಲು ನಿಮ್ಮ ಸಂಸ್ಥೆ ಮತ್ತು Anthropic ಬಳಿ ವಿಚಾರಿಸಿ ಖಚಿತಪಡಿಸಿಕೊಳ್ಳಿ. ವೈಯಕ್ತಿಕ ಪ್ಲಾನ್‌ಗಳ (Pro, Max) ಬಗ್ಗೆ [ಪದೇ ಪದೇ ಕೇಳುವ ಪ್ರಶ್ನೆಗಳಲ್ಲಿನ ನಿಯಮಗಳ ಟಿಪ್ಪಣಿ](/docs/faq#am-i-allowed-to-use-several-claude-code-accounts) ತಿಳಿಸುತ್ತದೆ.

## ಬಳಕೆ

```sh
ccam "$(ccam pick)" -p "fix the failing tests"
for task in parse lint docs; do
  ccam "$(ccam pick)" -p "do the $task task" > "$task.json" &
done; wait
ccam pick --json                      # the account and its usage
ccam pick --model opus                # also count the Opus weekly limit
ccam pick --max-usage 80 --strategy expiring
ccam pick --strategy balance          # spread over the weekly quota, fewer running sessions first
ccam pick --cross-org                 # also accounts of other organizations
ccam pick --wait=2h                   # nobody has room: wait for a reset
ccam --fallback "$(ccam pick)" -p "…" # also switch if this account hits its limit mid-job
```

```console
$ ccam pick --json
{
  "name": "work",
  "slot": 2,
  "email": "dev@company.com",
  "five_hour": { "percent": 12, "resets_at": "2026-10-20T15:10:00Z", "known": true },
  "weekly": { "percent": 41, "resets_at": "2026-10-24T09:00:00Z", "known": true },
  "source": "live",
  "reason": "12% of its 5 hours used, the least"
}
```

ನಿರ್ಗಮನ ಕೋಡ್‌ಗಳು: ಸ್ಟ್ಯಾಂಡರ್ಡ್ ಔಟ್‌ಪುಟ್‌ನಲ್ಲಿ ಹೆಸರಿನೊಂದಿಗೆ `0`, ಯಾವ ಖಾತೆಯಲ್ಲೂ ಅವಕಾಶ ಇಲ್ಲದಿದ್ದಾಗ ಅಥವಾ ಯಾವುದೂ ಲಾಗಿನ್ ಆಗಿಲ್ಲದಿದ್ದಾಗ `75` (`EX_TEMPFAIL`), ತಪ್ಪಾದ ಫ್ಲ್ಯಾಗ್‌ನಂತಹ ಇತರ ದೋಷಗಳಿಗೆ `1`.

## ಆಯ್ಕೆಗಳು

| ಆಯ್ಕೆ | ಏನು ಮಾಡುತ್ತದೆ | ಡೀಫಾಲ್ಟ್ |
| --- | --- | --- |
| `--json` | ಖಾತೆ, ಅದರ 5 ಗಂಟೆಯ ಮತ್ತು ವಾರದ ಬಳಕೆ, ಸಂಖ್ಯೆಗಳು ಎಲ್ಲಿಂದ ಬಂದವು ಮತ್ತು ಅದನ್ನು ಏಕೆ ಆಯ್ಕೆಮಾಡಲಾಯಿತು ಎಂಬುದನ್ನು ಮುದ್ರಿಸುತ್ತದೆ | ಆಫ್ |
| `--model <model>` | `opus` ನಂತಹ ಆ ಮಾಡೆಲ್‌ನ ವಾರದ ಅವಧಿಯನ್ನೂ ಎಣಿಸುತ್ತದೆ | ಇಲ್ಲ |
| `--max-usage <1-100>` | ಈ ಬಳಕೆಗಿಂತ ಕೆಳಗಿರುವ ಖಾತೆಗಳಿಗೆ ಆದ್ಯತೆ | `auto_max_usage`, ಇಲ್ಲದಿದ್ದರೆ 100 |
| `--strategy headroom\|expiring\|balance` | ಅತಿ ಕಡಿಮೆ 5 ಗಂಟೆಯ ಬಳಕೆ, ಬೇಗ ಬರುವ 5 ಗಂಟೆಯ ರೀಸೆಟ್, ಅಥವಾ ಮೊದಲು ಬಳಕೆಯಾಗದೆ ಹೋಗುವ ವಾರದ ಕೋಟಾ | `auto_strategy`, ಇಲ್ಲದಿದ್ದರೆ `headroom` |
| `--cross-org` | ಬೇರೆ ಸಂಸ್ಥೆಗಳ ಖಾತೆಗಳನ್ನೂ ಆಯ್ಕೆಮಾಡುತ್ತದೆ | `cross_org`, ಇಲ್ಲದಿದ್ದರೆ ಆಫ್ |
| `--wait[=<duration>]` | ಯಾವ ಖಾತೆಯಲ್ಲೂ ಅವಕಾಶ ಇಲ್ಲದಿದ್ದಾಗ, ಮೊದಲ ಖಾತೆ ರೀಸೆಟ್ ಆಗುವವರೆಗೆ, ಗರಿಷ್ಠ ಇಷ್ಟು ಸಮಯ ಕಾಯುತ್ತದೆ. ಮೌಲ್ಯ `=` ನಂತರ ಬರುತ್ತದೆ: `--wait 30m` ಅನ್ನು `--wait takes its value after '=': --wait=30m` ಎಂಬ ಸುಳಿವಿನೊಂದಿಗೆ ನಿರಾಕರಿಸಲಾಗುತ್ತದೆ | ಆಫ್; ಮೌಲ್ಯವಿಲ್ಲದೆ ನೀಡಿದರೆ `5h` |
| `--dry-run` | ಆಯ್ಕೆಯನ್ನು ದಾಖಲಿಸದೆ ಆಯ್ಕೆಮಾಡುತ್ತದೆ | ಆಫ್ |

## ಇದು ಹೇಗೆ ಕೆಲಸ ಮಾಡುತ್ತದೆ

1. ಈ ಫೋಲ್ಡರ್ ಆರಂಭಿಸುವ ಖಾತೆಯ ಸಂಸ್ಥೆಯಲ್ಲಿ ([ಸಂಸ್ಥೆಗಳು](/features/next#auto) ನೋಡಿ) ಲಾಗಿನ್ ಆಗಿರುವ ಖಾತೆಗಳನ್ನು ccam ಪಟ್ಟಿ ಮಾಡುತ್ತದೆ (API ಕೀ ಖಾತೆಗಳು ಮತ್ತು Console ಲಾಗಿನ್‌ಗಳಿಗೆ ಮಿತಿಗಳಿಲ್ಲ, ಹೀಗಾಗಿ ಅವುಗಳನ್ನು ಬಿಡಲಾಗುತ್ತದೆ); ಅದೇ Claude ಖಾತೆಗೆ ಲಾಗಿನ್ ಆಗಿರುವ ಫೋಲ್ಡರ್ ಅನ್ನೂ ಬಿಡಲಾಗುತ್ತದೆ.
2. ಅದು ಒಂದು ಲಾಕ್ (`~/.local/state/ccam/picks.lock`) ತೆಗೆದುಕೊಳ್ಳುತ್ತದೆ, ಹೀಗಾಗಿ ಒಂದೇ ಸಮಯದಲ್ಲಿ ನಡೆಯುವ ಆಯ್ಕೆಗಳು ಒಂದರ ನಂತರ ಒಂದು ನಡೆಯುತ್ತವೆ.
3. ಅದು `ccam usage` ಮಾಡುವಂತೆಯೇ, 60 ಸೆಕೆಂಡ್ ಕ್ಯಾಶ್‌ನೊಂದಿಗೆ, ಎಲ್ಲಾ ಖಾತೆಗಳ ಬಳಕೆಯನ್ನು ಒಮ್ಮೆಗೇ ನೋಡುತ್ತದೆ. Claude Code ತುಂಬಿದೆ ಎಂದು ವರದಿ ಮಾಡಿದ ಅವಧಿಯನ್ನು ಅದರ ರೀಸೆಟ್‌ವರೆಗೆ 100% ಎಂದು ಎಣಿಸಲಾಗುತ್ತದೆ ([ಮಿತಿ ದಾಖಲೆ](/features/usage#the-limit-record)), ಹೀಗಾಗಿ ಈಗಷ್ಟೇ ತನ್ನ ಮಿತಿ ತಲುಪಿದ ಖಾತೆ, ಅದರ ಉಳಿಸಿದ ಸಂಖ್ಯೆಗಳು ಅವಕಾಶ ತೋರಿಸಿದರೂ, ಹೊರಗೇ ಉಳಿಯುತ್ತದೆ.
4. ಕೊನೆಯ 2 ನಿಮಿಷಗಳಲ್ಲಿ ಆಯ್ಕೆಯಾದ ಖಾತೆಗಳನ್ನು (`~/.local/state/ccam/picks/<name>`; ಗಡಿಯಾರದ ಸಮಯಕ್ಕಿಂತ ನಂತರದ ದಿನಾಂಕದ ಆಯ್ಕೆಯನ್ನು ಎಣಿಸಲಾಗುವುದಿಲ್ಲ) ಮೊದಲು ಬಿಡಲಾಗುತ್ತದೆ, ಮತ್ತು `ccam next --auto` ನ [ಆಯ್ಕೆ ನಿಯಮಗಳು](/features/next#auto) ಉಳಿದವುಗಳಲ್ಲಿ ಆಯ್ಕೆಮಾಡುತ್ತವೆ: ಮೊದಲು `auto_max_usage` ಗಿಂತ ಕೆಳಗಿರುವವು, strategy ಪ್ರಕಾರ, 100% ತಲುಪಿದ ಖಾತೆ ಎಂದಿಗೂ ಅಲ್ಲ.
5. ಅವಕಾಶ ಇರುವ ಪ್ರತಿ ಖಾತೆಯೂ ಇತ್ತೀಚೆಗೆ ಆಯ್ಕೆಯಾಗಿದ್ದರೆ, ನಿಯಮಗಳು ಎಲ್ಲವುಗಳಲ್ಲಿ ಮತ್ತೆ ಆಯ್ಕೆಮಾಡುತ್ತವೆ, ಹೀಗಾಗಿ ಮೂರು ಖಾತೆಗಳ ಮೇಲಿನ ನಾಲ್ಕನೇ ವರ್ಕರ್ ಒಂದನ್ನು ಹಂಚಿಕೊಳ್ಳುತ್ತದೆ.
6. ಆಯ್ಕೆಯನ್ನು ದಾಖಲಿಸಿ ಲಾಕ್ ಬಿಡುಗಡೆ ಮಾಡಲಾಗುತ್ತದೆ, ನಂತರ ಹೆಸರನ್ನು ಮುದ್ರಿಸಲಾಗುತ್ತದೆ.

ಹೊಸ ಕೆಲಸದ ಬಳಕೆ ಸಂಖ್ಯೆಗಳಲ್ಲಿ ಕಾಣಿಸಲು ಸ್ವಲ್ಪ ಸಮಯ ಬೇಕಾಗುವುದರಿಂದ 2 ನಿಮಿಷಗಳ ಅವಧಿ ಮುಖ್ಯ: ಅದಿಲ್ಲದಿದ್ದರೆ, ಒಟ್ಟಿಗೆ ಆರಂಭವಾದ ಐದು ವರ್ಕರ್‌ಗಳೂ ಒಂದೇ ಖಾತೆಯನ್ನು ಹೆಚ್ಚು ಅವಕಾಶ ಇರುವ ಖಾತೆಯಾಗಿ ನೋಡುತ್ತವೆ.

## ಸುರಕ್ಷತೆ ಮತ್ತು ವಿಶೇಷ ಸಂದರ್ಭಗಳು

- `ccam pick` ಬಳಕೆಯನ್ನು ಮಾತ್ರ ಓದುತ್ತದೆ ಮತ್ತು ಆಯ್ಕೆಯ ಸಮಯವನ್ನು ಬರೆಯುತ್ತದೆ; `ccam usage` ಮಾಡುವುದಕ್ಕಿಂತ ಹೆಚ್ಚಾಗಿ ಅದು ಎಂದಿಗೂ ಟೋಕನ್‌ಗಳನ್ನು ನವೀಕರಿಸುವುದಿಲ್ಲ ಅಥವಾ ಓದುವುದಿಲ್ಲ.
- ಆಯ್ಕೆ ಖಾತೆಯನ್ನು ಕಾಯ್ದಿರಿಸುವುದಿಲ್ಲ. 2 ನಿಮಿಷಗಳ ನಂತರ ಎರಡು ಸ್ಕ್ರಿಪ್ಟ್‌ಗಳು ಇನ್ನೂ ಒಂದೇ ಖಾತೆಯಲ್ಲಿ ಆರಂಭವಾಗಬಹುದು; ಆ ಖಾತೆ ತನ್ನ ಮಿತಿ ತಲುಪಿದಾಗ ಚೇತರಿಸಿಕೊಳ್ಳಲು `--fallback` ಬಳಸಿ.
- `--wait` ಜೊತೆ ಕಾಯುವಾಗ ಯಾವ ಲಾಕ್ ಅನ್ನೂ ಹಿಡಿದಿಟ್ಟುಕೊಳ್ಳುವುದಿಲ್ಲ, ಹೀಗಾಗಿ ಆ ಸಮಯದಲ್ಲಿ ಇತರ ಆಯ್ಕೆಗಳು ಮುಂದುವರಿಯುತ್ತವೆ.
- `ccam pick` [`ccam folder`](/features/folder) ಅನ್ನು ಕಡೆಗಣಿಸುತ್ತದೆ: ಅದು ಬಳಕೆಯ ಆಧಾರದಲ್ಲಿ ಮಾತ್ರ ಆಯ್ಕೆಮಾಡುತ್ತದೆ.
