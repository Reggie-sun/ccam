"ಈ ಸ್ಕಿಲ್ (ಅಥವಾ MCP ಸರ್ವರ್) ಒಂದು ಖಾತೆಯಲ್ಲಿ ಕೆಲಸ ಮಾಡುತ್ತದೆ, ಇನ್ನೊಂದರಲ್ಲಿ ಏಕೆ ಇಲ್ಲ?" ಎಂಬ ಪ್ರಶ್ನೆಗೆ `ccam ext` ಉತ್ತರಿಸುತ್ತದೆ. ಅದು ಪ್ರತಿ ಖಾತೆಗೂ Claude Code ಲೋಡ್ ಮಾಡುವ ಎಕ್ಸ್‌ಟೆನ್ಶನ್‌ಗಳನ್ನು ಮತ್ತು ಪ್ರತಿಯೊಂದೂ ಎಲ್ಲಿಂದ ಬಂದಿದೆ ಎಂಬುದನ್ನು ಪಟ್ಟಿ ಮಾಡುತ್ತದೆ: ಹಂಚಿಕೆ ಗುಂಪು, ಖಾತೆಯ ಸ್ವಂತ ಫೋಲ್ಡರ್, ಅಥವಾ ನೀವು ಇರುವ ಪ್ರಾಜೆಕ್ಟ್. ಟೇಬಲ್‌ನ ಕೆಳಗೆ, ಎಕ್ಸ್‌ಟೆನ್ಶನ್ ನೀವು ನಿರೀಕ್ಷಿಸಿದಂತೆ ಲೋಡ್ ಆಗುವುದನ್ನು ತಡೆಯುವ ಸಂಗತಿಗಳನ್ನು ಪಟ್ಟಿ ಮಾಡುತ್ತದೆ. ಅದು ಏನನ್ನೂ ಬದಲಾಯಿಸುವುದಿಲ್ಲ.

## ಬಳಕೆ

```sh
ccam ext              # every account
ccam ext work         # one account
ccam ext --json       # for scripts
```

```console
$ ccam ext
Skills
          personal   work
  half    account !  -
  review  -          default

Commands
          personal  work
  deploy  default   default

MCP servers
       personal   work
  ctx  default !  default

Hooks (commands per event)
              personal     work
  PreToolUse  1 (default)  1 (default)

This project (/home/me/code/app):
  commands: ship
  MCP servers: fs

Sources: a group name (shared), account (its own folder), local (its own, for this folder only), - (not loaded); (off): installed, not turned on.
! personal: MCP server ctx is defined differently in group default's mcp.json and .claude.json
! personal: half: no SKILL.md, so Claude Code does not load it
```

ಪ್ರತಿ ಸೆಲ್ ಆ ಖಾತೆಯಲ್ಲಿ ಆ ಐಟಂನ ಮೂಲವನ್ನು ಹೆಸರಿಸುತ್ತದೆ: ಹಂಚಿಕೆ ಗುಂಪು (`default`), ಖಾತೆಯ ಸ್ವಂತ ಫೋಲ್ಡರ್‌ನಲ್ಲಿದ್ದರೆ `account`, ಖಾತೆಗೆ ಈ ಫೋಲ್ಡರ್‌ಗಾಗಿ ಮಾತ್ರ ಇರುವ MCP ಸರ್ವರ್‌ಗೆ `local`, ಅಥವಾ ಖಾತೆಯಲ್ಲಿ ಅದು ಇಲ್ಲದಿದ್ದರೆ `-`. ಇನ್‌ಸ್ಟಾಲ್ ಆಗಿದ್ದರೂ ಆನ್ ಆಗಿರದ ಪ್ಲಗಿನ್ ಅದರ ಮೂಲದ ನಂತರ `(off)` ತೋರಿಸುತ್ತದೆ. `!` ಸಮಸ್ಯೆಯಿರುವ ಐಟಂ ಅನ್ನು ಗುರುತಿಸುತ್ತದೆ, ಅದನ್ನು ಟೇಬಲ್‌ನ ಕೆಳಗೆ ವಿವರಿಸಲಾಗುತ್ತದೆ; ಯಾವುದೇ ಖಾತೆಗೆ ಸೇರದ ಸಮಸ್ಯೆಗಳು, ಉದಾಹರಣೆಗೆ ಸಾಮಾನ್ಯ `claude` ನಲ್ಲಿ ಮಾತ್ರ ಇರುವ ಸರ್ವರ್‌ಗಳು, ಕೊನೆಯಲ್ಲಿ ಹೆಸರಿಲ್ಲದೆ ಬರುತ್ತವೆ. `ccam ext --json` ಅದೇ ವರದಿಯನ್ನು ಮುದ್ರಿಸುತ್ತದೆ (`accounts`, ಪ್ರಾಜೆಕ್ಟ್, `problems`), Claude Code ನೆಟ್‌ವರ್ಕ್ ಮೂಲಕ ತಲುಪುವ MCP ಸರ್ವರ್‌ಗಳ ಮೇಲೆ `remote` ಜೊತೆ; ಖಾತೆಗಳೇ ಇಲ್ಲದಿದ್ದಾಗ ಅದು `accounts: []` ಇರುವ ವರದಿಯನ್ನು ಮುದ್ರಿಸುತ್ತದೆ.

## ಅದು ಏನನ್ನು ಓದುತ್ತದೆ

| ಪ್ರಕಾರ | ಎಲ್ಲಿ | ತೋರಿಸುವ ಮೂಲ |
| --- | --- | --- |
| ಸ್ಕಿಲ್‌ಗಳು | `SKILL.md` ಇರುವ `skills/` ನಲ್ಲಿನ ಪ್ರತಿ ಫೋಲ್ಡರ್ | `skills/` ಲಿಂಕ್ ಆಗಿರುವ ಗುಂಪು, ಅಥವಾ `account` |
| ಕಮಾಂಡ್‌ಗಳು, ಏಜೆಂಟ್‌ಗಳು | `commands/` ಮತ್ತು `agents/` ಅಡಿಯ `.md` ಫೈಲ್‌ಗಳು, ಉಪಫೋಲ್ಡರ್‌ಗಳು `folder/name` ಆಗಿ | ಗುಂಪು, ಅಥವಾ `account` |
| ಪ್ಲಗಿನ್‌ಗಳು | `plugins/installed_plugins.json`, ಖಾತೆಯ ಮತ್ತು ಪ್ರಾಜೆಕ್ಟ್‌ನ ಸೆಟ್ಟಿಂಗ್‌ಗಳಲ್ಲಿನ `enabledPlugins` ಮೂಲಕ ಆನ್ ಅಥವಾ ಆಫ್; ಒಂದೇ ಪ್ರಾಜೆಕ್ಟ್‌ಗಾಗಿ ಇನ್‌ಸ್ಟಾಲ್ ಮಾಡಿದ ಪ್ಲಗಿನ್ ಆ ಪ್ರಾಜೆಕ್ಟ್‌ನಲ್ಲಿ ಮಾತ್ರ ಕಾಣಿಸುತ್ತದೆ | ಗುಂಪು, ಅಥವಾ `account`; ಆನ್ ಆಗಿರದಿದ್ದಾಗ `(off)` |
| MCP ಸರ್ವರ್‌ಗಳು | ಗುಂಪಿನ `mcp.json` (MCP ಹಂಚಿಕೆಯಾಗಿದ್ದಾಗ), ಖಾತೆಯ `.claude.json` (ಅದರ ಸ್ವಂತ ಸರ್ವರ್‌ಗಳು, ಮತ್ತು ಈ ಫೋಲ್ಡರ್‌ಗಾಗಿ ಮಾತ್ರ ಇರುವವು), ಮತ್ತು ಅದರ ಪ್ಲಗಿನ್‌ಗಳ ಸರ್ವರ್‌ಗಳು, `plugin:<plugin>:<server>` ಆಗಿ | ಗುಂಪು, `account` ಅಥವಾ `local` |
| ಹುಕ್‌ಗಳು | `settings.json` ನಲ್ಲಿನ `hooks`, ಪ್ರತಿ ಈವೆಂಟ್‌ಗೆ ಎಣಿಸಲಾಗಿದೆ | ಗುಂಪು, ಅಥವಾ `account` |
| ಈ ಪ್ರಾಜೆಕ್ಟ್ | ಪ್ರಸ್ತುತ ಫೋಲ್ಡರ್‌ನಲ್ಲಿನ `.claude/skills`, `.claude/commands`, `.claude/agents`, `.claude/settings.json`, `.claude/settings.local.json` ಮತ್ತು `.mcp.json` | ಒಮ್ಮೆ ಪಟ್ಟಿ ಮಾಡಲಾಗುತ್ತದೆ; ಫೋಲ್ಡರ್ ಅನ್ನು ಇನ್ನೂ ನಂಬದ ಖಾತೆಗೆ ಅದರ `.mcp.json` ಸರ್ವರ್‌ಗಳಿಗಾಗಿ ಸಮಸ್ಯೆ ತೋರಿಸಲಾಗುತ್ತದೆ |

## ಅದು ವರದಿ ಮಾಡುವ ಸಮಸ್ಯೆಗಳು

- **ಮುರಿದ ಲಿಂಕ್‌ಗಳು**: ಗುರಿ ಇಲ್ಲವಾಗಿರುವ `skills/`, `commands/` ಅಥವಾ `agents/` ನಲ್ಲಿನ ಲಿಂಕ್, ಅಥವಾ ಕಾಣೆಯಾದ ಸ್ಥಳಕ್ಕೆ ಲಿಂಕ್ ಆಗಿರುವ ಹಂಚಿಕೊಂಡ ಫೋಲ್ಡರ್ (`skills`, `commands`, `agents`, `plugins`) (`ccam doctor --fix` ಮೂಲಕ ಸರಿಪಡಿಸಿ; ಅದು ಇಲ್ಲದ ಗುಂಪಿನ ಫೋಲ್ಡರ್ ಅನ್ನು ಮತ್ತೆ ರಚಿಸುತ್ತದೆ).
- **`SKILL.md` ಇಲ್ಲದ ಸ್ಕಿಲ್ ಫೋಲ್ಡರ್**: Claude Code ಅದನ್ನು ಬಿಟ್ಟುಬಿಡುತ್ತದೆ.
- **ಎರಡು ಸ್ಥಳಗಳಲ್ಲಿ ಬೇರೆ ಬೇರೆಯಾಗಿ ವ್ಯಾಖ್ಯಾನಿಸಿದ MCP ಸರ್ವರ್**: ಗುಂಪಿನ `mcp.json` ಮತ್ತು ಖಾತೆಯ `.claude.json`, ಅಥವಾ ಇವುಗಳಲ್ಲಿ ಒಂದು ಮತ್ತು ಪ್ರಾಜೆಕ್ಟ್‌ನ `.mcp.json`. ಎರಡೂ ಸ್ಥಳಗಳಲ್ಲಿ ಒಂದೇ ರೀತಿಯ ವ್ಯಾಖ್ಯಾನಗಳು ಇರುವುದು (`mcp_strategy = "sync"` ಬರೆಯುವಂತೆ) ಸಮಸ್ಯೆಯಲ್ಲ. ಖಾತೆಯ ಸ್ವಂತ ಸರ್ವರ್ ಅನ್ನು `ccam mcp import <account> <server>` ಮೂಲಕ ಗುಂಪಿಗೆ ಸ್ಥಳಾಂತರಿಸಿ.
- **ಮಾನ್ಯ JSON ಅಲ್ಲದ `installed_plugins.json`**, `enabledPlugins` ಹೆಸರಿಸದ ಪ್ಲಗಿನ್, ಮತ್ತು ಫೋಲ್ಡರ್ ಇಲ್ಲದ ಪ್ಲಗಿನ್.
- **ಒಂದೇ ಖಾತೆ ಲೋಡ್ ಮಾಡುವ ಸರ್ವರ್‌ಗಳು**: ಈ ಖಾತೆಯ `.claude.json` ನಲ್ಲಿ ಮಾತ್ರ ಇದ್ದು ಅದರ ಗುಂಪಿನ ಇತರ ಖಾತೆಗಳು ಲೋಡ್ ಮಾಡದ ಸರ್ವರ್, ಮತ್ತು ಈ ಫೋಲ್ಡರ್‌ಗಾಗಿ ಖಾತೆಯ ಸ್ಥಳೀಯ (local) ವ್ಯಾಪ್ತಿಯಲ್ಲಿರುವ ಸರ್ವರ್ (`-s user` ನೀಡದಿದ್ದರೆ `claude mcp add` ಮಾಡುವುದು ಇದನ್ನೇ). ಪ್ರತಿಯೊಂದರ ಜೊತೆಗೆ ಅದನ್ನು ಹಂಚಿಕೊಳ್ಳುವ `ccam mcp import` ಕಮಾಂಡ್ ಬರುತ್ತದೆ. ಸಾಮಾನ್ಯ `claude` ನ `~/.claude.json` ನಲ್ಲಿದ್ದು ಯಾವ ಖಾತೆಯೂ ಲೋಡ್ ಮಾಡದ ಸರ್ವರ್‌ಗಳ ಜೊತೆಗೆ `ccam migrate --mcp` ಕಮಾಂಡ್ ಬರುತ್ತದೆ.
- **ಅನುಮೋದನೆಗಾಗಿ ಕಾಯುತ್ತಿರುವ ಪ್ರಾಜೆಕ್ಟ್ ಸರ್ವರ್**: ಖಾತೆ ಇನ್ನೂ ಫೋಲ್ಡರ್ ಅನ್ನು ನಂಬಿಲ್ಲ, ಹೀಗಾಗಿ Claude Code ಒಮ್ಮೆ ಕೇಳುತ್ತದೆ, ಮತ್ತು ಅಲ್ಲಿಯವರೆಗೆ ಪ್ರಾಜೆಕ್ಟ್‌ನ `.mcp.json` ಸರ್ವರ್‌ಗಳು ಕಾಯುತ್ತವೆ. ಅವುಗಳನ್ನು ಎಲ್ಲಿ ಅನುಮೋದಿಸಬೇಕು ಎಂದು ಸಮಸ್ಯೆ ತಿಳಿಸುತ್ತದೆ: settings ಗುಂಪಿನ ಖಾತೆಗಳ, ಅಥವಾ ಈ ಖಾತೆಯ `settings.json` ನಲ್ಲಿನ `"enabledMcpjsonServers"`. git ರೆಪೊಸಿಟರಿಯ ಮುಖ್ಯ worktree ಗೆ ನೀಡಿದ ನಂಬಿಕೆ ಅದರ ಇತರ worktree ಗಳಲ್ಲೂ ಅನ್ವಯಿಸುತ್ತದೆ.
- **ಸೈನ್-ಇನ್‌ಗಳು ಮತ್ತು ಕನೆಕ್ಟರ್‌ಗಳು**: ಇನ್ನೊಂದು ಖಾತೆ ಸೈನ್ ಇನ್ ಆಗಿರುವಾಗ ಈ ಖಾತೆಯಲ್ಲಿ ಸೈನ್-ಇನ್ ಬೇಕಾಗಿರುವ MCP ಸರ್ವರ್ (ಸೈನ್-ಇನ್ ಒಂದೇ ಖಾತೆಗೆ ಮಾತ್ರ ಅನ್ವಯಿಸುತ್ತದೆ; `/mcp` ಮೂಲಕ ಸೈನ್ ಇನ್ ಆಗಿ), ಮತ್ತು ಇನ್ನೊಂದು ಖಾತೆ ಬಳಸಿದ ಆದರೆ ಈ ಖಾತೆ ಬಳಸದ claude.ai ಕನೆಕ್ಟರ್‌ಗಳು.

## ಸುರಕ್ಷತೆ ಮತ್ತು ವಿಶೇಷ ಸಂದರ್ಭಗಳು

- `ccam ext` ಏನನ್ನೂ ಬದಲಾಯಿಸುವುದಿಲ್ಲ ಮತ್ತು ಯಾವುದೇ ನೆಟ್‌ವರ್ಕ್ ವಿನಂತಿ ಮಾಡುವುದಿಲ್ಲ. ಅದು ಸರ್ವರ್ ಹೆಸರುಗಳು ಮತ್ತು ಹುಕ್ ಎಣಿಕೆಗಳನ್ನು ಓದುತ್ತದೆ, MCP ವ್ಯಾಖ್ಯಾನಗಳಲ್ಲಿನ `env` ಅಥವಾ ಹೆಡರ್‌ಗಳ ಮೌಲ್ಯಗಳನ್ನು ಎಂದಿಗೂ ಓದುವುದಿಲ್ಲ. ಸೈನ್-ಇನ್ ಪರಿಶೀಲನೆಗಾಗಿ ಅದು ಪ್ರತಿ ಖಾತೆಯ ಲಾಗಿನ್‌ನಲ್ಲಿರುವ MCP ಸೈನ್-ಇನ್‌ಗಳ ಹೆಸರುಗಳನ್ನು ಓದುತ್ತದೆ (macOS ನಲ್ಲಿ Keychain ನಿಂದ), ಟೋಕನ್‌ಗಳನ್ನು ಎಂದಿಗೂ ಓದುವುದಿಲ್ಲ, ಮತ್ತು ಇನ್ನೊಂದು ಖಾತೆಯೂ ಲೋಡ್ ಮಾಡುವ ಸರ್ವರ್ ಅನ್ನು ಲೋಡ್ ಮಾಡುವ ಖಾತೆಗಳಿಗೆ ಮಾತ್ರ ಓದುತ್ತದೆ.
- ಅದು ಡಿಸ್ಕ್‌ನಲ್ಲಿರುವುದನ್ನು ತೋರಿಸುತ್ತದೆ. ನಿರ್ವಹಿತ ಸೆಟ್ಟಿಂಗ್‌ಗಳಿಂದ ತಡೆಹಿಡಿದ ಸರ್ವರ್ ಕೂಡ ಕಾಣಿಸುತ್ತದೆ; ಸೆಟ್ಟಿಂಗ್‌ಗಳಲ್ಲಿ ಆಫ್ ಮಾಡಿದ ಪ್ಲಗಿನ್ `(off)` ತೋರಿಸುತ್ತದೆ.
- ಆ ಪ್ರಾಜೆಕ್ಟ್‌ನ `.claude` ಫೋಲ್ಡರ್ ಮತ್ತು `.mcp.json` ಅನ್ನು ಸೇರಿಸಲು ಪ್ರಾಜೆಕ್ಟ್ ಫೋಲ್ಡರ್‌ನಲ್ಲಿ ಇದನ್ನು ರನ್ ಮಾಡಿ.
