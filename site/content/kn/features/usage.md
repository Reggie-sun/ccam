`ccam usage` ಪ್ರತಿ ಖಾತೆಗೂ, ಪ್ರತಿ ಮಿತಿಯಲ್ಲಿ ಎಷ್ಟು ಬಳಕೆಯಾಗಿದೆ ಎಂದು ತೋರಿಸುತ್ತದೆ: 5 ಗಂಟೆಯ ಮಿತಿ, ವಾರದ ಮಿತಿ ಮತ್ತು ಪ್ರತಿ ಮಾಡೆಲ್‌ನ ಸ್ವಂತ ವಾರದ ಮಿತಿ (ಉದಾಹರಣೆಗೆ Fable). ಪ್ರತಿ ಮಿತಿಗೆ ಒಂದು ಬಾರ್ ಮತ್ತು ಅದು ರೀಸೆಟ್ ಆಗಲು ಉಳಿದ ಸಮಯ ಇರುತ್ತದೆ. ದೀರ್ಘ ಕೆಲಸವನ್ನು ಆರಂಭಿಸುವ ಮೊದಲು, ಅಥವಾ ಮಿತಿ ಹತ್ತಿರವಾಗಿದೆ ಎಂದು Claude Code ಹೇಳಿದಾಗ, ಯಾವ ಖಾತೆಯಲ್ಲಿ ಇನ್ನೂ ಅವಕಾಶ ಇದೆ ಎಂದು ನೋಡಲು ಇದನ್ನು ಬಳಸಿ. `ccam statusline` ಎಂಬುದು Claude Code ಗಾಗಿ ಸ್ಟೇಟಸ್ ಲೈನ್ ಕಮಾಂಡ್: ಇದು Claude Code ಒಳಗೆ ಖಾತೆಯ ಹೆಸರು ಮತ್ತು ಬಳಕೆಯನ್ನು ತೋರಿಸುತ್ತದೆ ಮತ್ತು ಸಂಖ್ಯೆಗಳನ್ನು `ccam usage` ಗಾಗಿ ಉಳಿಸುತ್ತದೆ. ಬಳಕೆಯ ಹಿಂದಿರುವ ಟೋಕನ್‌ಗಳು ಮತ್ತು ಅಂದಾಜು ವೆಚ್ಚಗಳಿಗಾಗಿ, `ccam ccusage` ಪ್ರತಿ ಖಾತೆಯ ಸಂಭಾಷಣೆಗಳ ಮೇಲೆ [ccusage](https://ccusage.com) ಅನ್ನು ರನ್ ಮಾಡುತ್ತದೆ ([ಕೆಳಗೆ](#tokens-and-costs-ccam-ccusage)).

## ಬಳಕೆ

```sh
ccam usage                  # every account, once
ccam u                      # the same, shorter
ccam usage --watch          # redraw every 60 seconds until Ctrl+C
ccam usage --watch=10       # redraw every 10 seconds
ccam usage -v               # add where the numbers came from
ccam usage --json           # machine-readable, one object per account
ccam usage --source cache   # saved numbers only, no network
ccam usage --refresh        # also renew expired logins of accounts that are not running
ccam usage --source claude  # let Claude Code look it up: ccam sends no token
ccam statusline install     # set the status line in every account's settings.json
```

ಪ್ರತಿ ಖಾತೆಗೆ ಅದರ ಸಂಖ್ಯೆ, ಹೆಸರು ಮತ್ತು ಅದರ ಸಂಖ್ಯೆಗಳು ಎಷ್ಟು ಹಳೆಯವು ಎಂಬುದನ್ನು ತೋರಿಸುವ ಒಂದು ಸಾಲು ಇರುತ್ತದೆ; `(cached)` ಎಂದರೆ ಅವು ಎಂಡ್‌ಪಾಯಿಂಟ್‌ನಿಂದಲ್ಲ, ಉಳಿಸಿದ ಫೈಲ್‌ನಿಂದ ಬಂದಿವೆ. ಅದರ ಕೆಳಗೆ, ಪ್ರತಿ ಮಿತಿಗೆ ಒಂದು ಸಾಲು 20 ಕೋಶಗಳ ಬಾರ್, ಶೇಕಡಾವಾರು ಮತ್ತು ಅವಧಿ ರೀಸೆಟ್ ಆಗಲು ಉಳಿದ ಸಮಯವನ್ನು ತೋರಿಸುತ್ತದೆ: `5-hour`, `Weekly` (ಎಲ್ಲಾ ಮಾಡೆಲ್‌ಗಳು), ನಂತರ ಪ್ರತಿ ಮಾಡೆಲ್‌ನ ಸ್ವಂತ ವಾರದ ಅವಧಿ, ಉದಾಹರಣೆಗೆ `Fable`. ಖಾತೆಗೆ ಇಲ್ಲದ ಅವಧಿ `-` ಎಂದು ತೋರಿಸುತ್ತದೆ. ಶೇಕಡಾವಾರು 80% ನಲ್ಲಿ ಹಳದಿ ಮತ್ತು 100% ನಲ್ಲಿ ಕೆಂಪು ಆಗುತ್ತದೆ.

ಅವಧಿ ತುಂಬಿದ್ದರಿಂದ Claude Code ವಿನಂತಿಯನ್ನು ನಿರಾಕರಿಸಿದ್ದರೆ, ಉಳಿಸಿದ ಸಂಖ್ಯೆಗಳು ಏನೇ ಹೇಳಿದರೂ, ಆ ಅವಧಿ ರೀಸೆಟ್ ಆಗುವವರೆಗೆ 100% ತೋರಿಸುತ್ತದೆ ([ಮಿತಿ ದಾಖಲೆ](#the-limit-record) ನೋಡಿ). ಟರ್ಮಿನಲ್‌ನಲ್ಲಿ ಎಲ್ಲಾ ಖಾತೆಗಳು ತಕ್ಷಣ `fetching…` ಆಗಿ ಕಾಣಿಸುತ್ತವೆ, ಮತ್ತು ಪ್ರತಿ ಖಾತೆ ಉತ್ತರಿಸಿದಂತೆ ಅದರ ಸಾಲುಗಳನ್ನು ಬರೆಯಲಾಗುತ್ತದೆ.

ನಿಮಗೆ ಒಂದಕ್ಕಿಂತ ಹೆಚ್ಚು ಖಾತೆಗಳಿದ್ದಾಗ ಮಾತ್ರ ಕಾಣುವ ಕೊನೆಯ ಸಾಲು, [`ccam next --auto`](/features/next) ಆಯ್ಕೆಮಾಡುವ ಖಾತೆಯನ್ನು ಹೆಸರಿಸುತ್ತದೆ. ಅದು ಅದೇ ನಿಯಮಗಳನ್ನು ಅನುಸರಿಸುತ್ತದೆ:

- `auto_max_usage` ಮತ್ತು `auto_strategy`;
- ರನ್ ಆಗುತ್ತಿರುವ ಸೆಷನ್‌ಗಳು;
- `cross_org` ಹೊಂದಿಸದಿದ್ದರೆ, ಕೊನೆಯದಾಗಿ ಬಳಸಿದ ಖಾತೆಯ ಸಂಸ್ಥೆಯ ಖಾತೆಗಳು ಮಾತ್ರ;
- 100% ತಲುಪಿದ ಪ್ರತಿ ಅವಧಿಯನ್ನು ಬಿಟ್ಟುಬಿಡಲಾಗುತ್ತದೆ, ಹೀಗಾಗಿ ವಾರ ತುಂಬಿರುವ ಖಾತೆಯನ್ನು ಎಂದಿಗೂ ಹೆಸರಿಸುವುದಿಲ್ಲ.

ಡೀಫಾಲ್ಟ್ `headroom` strategy ಯೊಂದಿಗೆ ಅದು `→ Most headroom: <name>` ಎಂದಿರುತ್ತದೆ; `expiring` ಅಥವಾ `balance` ಜೊತೆ ಅದು ಕಾರಣವನ್ನು ನೀಡುತ್ತದೆ, ಉದಾಹರಣೆಗೆ `→ next --auto picks personal: its 5-hour window resets first, in 1h 12m (40% of its 5 hours used)`.

**Team ಮತ್ತು Enterprise ಸೀಟುಗಳು.** ಸ್ವಯಂಚಾಲಿತ ಖಾತೆ ಆಯ್ಕೆ (`ccam next`, `--fallback`, `ccam pick`, ಡ್ಯಾಶ್‌ಬೋರ್ಡ್‌ನ `n` ಮತ್ತು, ನೀವು ಆನ್ ಮಾಡಿದ ನಂತರ, [`auto_switch`](/features/next#auto-switch)) ಒಂದೇ Claude Team ಅಥವಾ Enterprise ಸಂಸ್ಥೆಯ ಸೀಟುಗಳ ನಡುವೆಯೂ ಬದಲಾಯಿಸುತ್ತದೆ, ಇದು Anthropic ನ ನಿಯಮಗಳನ್ನು ಉಲ್ಲಂಘಿಸಬಹುದು. ಇದನ್ನು ಅವಲಂಬಿಸುವ ಮೊದಲು [ಪದೇ ಪದೇ ಕೇಳುವ ಪ್ರಶ್ನೆಗಳನ್ನು](/docs/faq#am-i-allowed-to-use-several-claude-code-accounts) ಓದಿ ಮತ್ತು ನಿಮ್ಮ ಸಂಸ್ಥೆ ಹಾಗೂ Anthropic ಬಳಿ ವಿಚಾರಿಸಿ.

ಲಾಗಿನ್ ಆಗದ ಖಾತೆ `not logged in → ccam login <name>` ಎಂದು ತೋರಿಸುತ್ತದೆ, ಮತ್ತು API ಕೀ ಖಾತೆ `no limits (API)` ಎಂದು ತೋರಿಸುತ್ತದೆ. ಅವಧಿ ಮುಗಿದ ಆಕ್ಸೆಸ್ ಟೋಕನ್, ಉಳಿಸಿದ ಸಂಖ್ಯೆಗಳಿದ್ದರೆ ಅವುಗಳ ಮೇಲೆ, ``access token expired; `ccam <name>` renews it when it starts`` ಎಂದು ತೋರಿಸುತ್ತದೆ: ಮುಂದಿನ ಆರಂಭದಲ್ಲಿ Claude Code ಅದನ್ನು ನವೀಕರಿಸುತ್ತದೆ. ಸಂಪೂರ್ಣವಾಗಿ ಅವಧಿ ಮುಗಿದ ಲಾಗಿನ್, ಅದರ ರಿಫ್ರೆಶ್ ಟೋಕನ್‌ನ ಅವಧಿ ಮುಗಿದಿದ್ದರಿಂದ ಅಥವಾ ಸರ್ವರ್ ನಿರಾಕರಿಸಿದ ನಂತರ Claude Code ಅದನ್ನು ತೆರವುಗೊಳಿಸಿದ್ದರಿಂದ, `` login expired → `ccam login <name>` `` ಎಂದು ತೋರಿಸುತ್ತದೆ.

`ccam statusline install` ನಂತರ, Claude Code `[work] · Opus · 5h 24% · 7d 41%` ನಂತಹ ಸಾಲನ್ನು ತೋರಿಸುತ್ತದೆ.

## ಆಯ್ಕೆಗಳು

| ಆಯ್ಕೆ | ಏನು ಮಾಡುತ್ತದೆ | ಡೀಫಾಲ್ಟ್ |
| --- | --- | --- |
| `--json` | ವರದಿಗಳನ್ನು JSON ಆಗಿ ಮುದ್ರಿಸುತ್ತದೆ: `name`, `slot`, `status`, `limits` (ಖಾತೆಯಲ್ಲಿ ಬಳಕೆಯ ಕ್ರೆಡಿಟ್‌ಗಳು ಆನ್ ಆಗಿದ್ದಾಗ `credits` ಜೊತೆ), `source`, `at`, `error`, ಮತ್ತು ಮಿತಿ ದಾಖಲೆ ಅವಧಿಗಳನ್ನು 100% ಗೆ ಹೊಂದಿಸಿದಾಗ `limited` ಹಾಗೂ `limited_windows`. ಖಾತೆಗಳೇ ಇಲ್ಲದಿದ್ದಾಗ ಅದು `[]` ಮುದ್ರಿಸುತ್ತದೆ | off |
| `--watch[=N]` | ನೀವು Ctrl+C ಒತ್ತುವವರೆಗೆ ಪ್ರತಿ `N` ಸೆಕೆಂಡ್‌ಗೆ ಮತ್ತೆ ಬರೆಯುತ್ತದೆ. `--watch` ಒಂದೇ, ಅಥವಾ 0 ಅಥವಾ ಅದಕ್ಕಿಂತ ಕಡಿಮೆ ಮೌಲ್ಯ, 60 ಎಂದರ್ಥ. ಮೌಲ್ಯ `=` ನಂತರ ಬರುತ್ತದೆ: `--watch 10` ಅನ್ನು ಒಂದು ಸುಳಿವಿನೊಂದಿಗೆ ನಿರಾಕರಿಸಲಾಗುತ್ತದೆ | off |
| `-v`, `--verbose` | ಪ್ರತಿ ಖಾತೆಯ ಕೆಳಗೆ `source:` ಸಾಲನ್ನು ಸೇರಿಸುತ್ತದೆ: ಅದರ ಸಂಖ್ಯೆಗಳು ಎಲ್ಲಿಂದ ಬಂದವು (ಬಳಕೆಯ ಎಂಡ್‌ಪಾಯಿಂಟ್, Claude Code, ಸ್ಟೇಟಸ್ ಲೈನ್, ಉಳಿಸಿದ ಫೈಲ್, ಅಥವಾ Claude Code ವರದಿ ಮಾಡಿದ ಬಳಕೆಯ ಮಿತಿ). ಮಿತಿ ದಾಖಲೆ ಸಂಖ್ಯೆಗಳನ್ನು ಮೀರಿಸಿದಾಗ, `Weekly full: Claude Code reported the usage limit 1h 0m ago, so 100% until the reset` ನಂತಹ ಸಾಲು ನಂತರ ಬರುತ್ತದೆ | off |
| `--no-cache` | 60 ಸೆಕೆಂಡ್‌ಗಳ ಕ್ಯಾಶ್ ಅನ್ನು ನಿರ್ಲಕ್ಷಿಸಿ ಎಂಡ್‌ಪಾಯಿಂಟ್ ಅನ್ನು ಮತ್ತೆ ಕೇಳುತ್ತದೆ | off |
| `--source live\|claude\|cache` | `live` ಖಾತೆಯ ಟೋಕನ್‌ನೊಂದಿಗೆ ಎಂಡ್‌ಪಾಯಿಂಟ್ ಅನ್ನು ಕೇಳುತ್ತದೆ; `claude` Claude Code ನಿಂದಲೇ ಹುಡುಕಿಸುತ್ತದೆ (ಕೆಳಗೆ ನೋಡಿ); `cache` ಉಳಿಸಿದ ಸಂಖ್ಯೆಗಳನ್ನು ಮಾತ್ರ ತೋರಿಸುತ್ತದೆ | `usage_source`, ಇಲ್ಲದಿದ್ದರೆ `live` |
| `--refresh` | ಅವಧಿ ಮುಗಿದ ಆಕ್ಸೆಸ್ ಟೋಕನ್‌ಗಳನ್ನು ನವೀಕರಿಸುತ್ತದೆ, ರನ್ ಆಗುತ್ತಿಲ್ಲದ ಖಾತೆಗಳಿಗೆ ಮಾತ್ರ. ಒಂದು ನವೀಕರಣಕ್ಕೆ 30 ಸೆಕೆಂಡ್‌ಗಳವರೆಗೆ ಹಿಡಿಯಬಹುದು | off |
| `--dry-run` | ಸ್ವೀಕರಿಸಲಾಗುತ್ತದೆ: `ccam usage` ತನ್ನ ಕ್ಯಾಶ್ ಹೊರತುಪಡಿಸಿ ಏನನ್ನೂ ಬದಲಾಯಿಸುವುದಿಲ್ಲ. `--refresh` ಜೊತೆ ನಿರಾಕರಿಸಲಾಗುತ್ತದೆ: `--dry-run cannot be combined with --refresh, which rewrites login tokens` | off |

ಬೇರೆ ಯಾವುದೇ `--source` ಮೌಲ್ಯ `--source must be live, claude or cache` ಎಂದು ವಿಫಲವಾಗುತ್ತದೆ. `ccam usage` ಯಾವುದೇ ಆರ್ಗ್ಯುಮೆಂಟ್ ತೆಗೆದುಕೊಳ್ಳುವುದಿಲ್ಲ.

### Claude Code ನಿಂದಲೇ ಬಳಕೆ

`config.toml` ನ ಮೇಲ್ಭಾಗದಲ್ಲಿ (ಮೊದಲ `[[group]]`, `[[profile]]` ಅಥವಾ `[[folder]]` ಗಿಂತ ಮೇಲೆ) `usage_source = "claude"` ಇದ್ದರೆ, ಅಥವಾ `--source claude` ನೀಡಿದರೆ, ccam ಲಾಗಿನ್ ಟೋಕನ್ ಅನ್ನು ಓದುವುದೇ ಇಲ್ಲ. ಪ್ರತಿ ಖಾತೆಗೂ ಅದು ಖಾತೆಯ ಫೋಲ್ಡರ್‌ನಲ್ಲಿ `claude -p --input-format stream-json --output-format stream-json --verbose --safe-mode --no-session-persistence` ಅನ್ನು ಆರಂಭಿಸಿ, Claude Code ನ `get_usage` ವಿನಂತಿಯನ್ನು ಸ್ಟ್ಯಾಂಡರ್ಡ್ ಇನ್‌ಪುಟ್‌ನಲ್ಲಿ ಕಳುಹಿಸುತ್ತದೆ (Claude Code 2.1.270 ಅಥವಾ ನಂತರದ್ದು). Claude Code ತನ್ನದೇ ಲಾಗಿನ್‌ನೊಂದಿಗೆ ಬಳಕೆಯನ್ನು ಹುಡುಕಿ 5 ಗಂಟೆಯ, ವಾರದ ಮತ್ತು ಮಾಡೆಲ್ ವಿಂಡೋಗಳೊಂದಿಗೆ ಉತ್ತರಿಸುತ್ತದೆ.

`--safe-mode` ಖಾತೆಯ ಹುಕ್‌ಗಳು, MCP ಸರ್ವರ್‌ಗಳು ಮತ್ತು ಪ್ಲಗಿನ್‌ಗಳು ಆರಂಭವಾಗದಂತೆ ತಡೆಯುತ್ತದೆ, ಮತ್ತು ಯಾವುದೇ ಸೆಷನ್ ಉಳಿಯುವುದಿಲ್ಲ. ಪ್ರತಿ ಖಾತೆಗೂ ಒಂದು Claude Code ಆರಂಭ (ಸುಮಾರು ಒಂದು ಸೆಕೆಂಡ್) ಬೇಕಾಗುತ್ತದೆ, ಹೀಗಾಗಿ ಈ ಮೂಲ `live` ಗಿಂತ ನಿಧಾನ. ಖಾತೆಗಳನ್ನು ಒಮ್ಮೆಗೇ ಕೇಳಲಾಗುತ್ತದೆ, ಪ್ರತಿಯೊಂದಕ್ಕೂ 20 ಸೆಕೆಂಡ್ ಟೈಮ್‌ಔಟ್‌ನೊಂದಿಗೆ, ಮತ್ತು 60 ಸೆಕೆಂಡ್‌ಗಳ ಕ್ಯಾಶ್ ಎಂದಿನಂತೆ ಅನ್ವಯಿಸುತ್ತದೆ.

ಆಕ್ಸೆಸ್ ಟೋಕನ್‌ನ ಅವಧಿ ಮುಗಿದಿರುವ, ಅಥವಾ 5 ನಿಮಿಷಗಳೊಳಗೆ ಮುಗಿಯುವ ಲಾಗಿನ್‌ಗೆ 50 ಸೆಕೆಂಡ್ ಸಿಗುತ್ತದೆ, ಏಕೆಂದರೆ Claude Code ಆರಂಭವಾಗುವಾಗ ಅದನ್ನು ನವೀಕರಿಸುತ್ತದೆ ಮತ್ತು ಅರ್ಧದಲ್ಲಿ ಕತ್ತರಿಸಿದ ನವೀಕರಣ ಲಾಗಿನ್ ಅನ್ನು ಕಳೆದುಕೊಳ್ಳಬಹುದು. ccam ಒಂದು ಹುಡುಕಾಟವನ್ನು ಕೈಬಿಟ್ಟರೆ, SIGTERM ಮೂಲಕ ನಿರ್ಗಮಿಸುವಂತೆ Claude Code ಅನ್ನು ಕೇಳುತ್ತದೆ, ಹೀಗಾಗಿ Claude Code ತಾನು ಆರಂಭಿಸಿದ ನವೀಕರಣವನ್ನು ಪೂರ್ಣಗೊಳಿಸುತ್ತದೆ (Windows ನಲ್ಲಿ SIGTERM ಇಲ್ಲ, ಹೀಗಾಗಿ ಅಲ್ಲಿ ಪ್ರೊಸೆಸ್ ಅನ್ನು ಕೊನೆಗೊಳಿಸಲಾಗುತ್ತದೆ).

ಸಂಪೂರ್ಣವಾಗಿ ಅವಧಿ ಮುಗಿದ ಲಾಗಿನ್, Claude Code ಅನ್ನು ಆರಂಭಿಸದೆಯೇ, `` login expired → `ccam login <name>` `` ಎಂದು ತೋರಿಸುತ್ತದೆ. Claude Code ಈ ವಿನಂತಿಯನ್ನು ಪ್ರಾಯೋಗಿಕ ಎಂದು ಗುರುತಿಸುತ್ತದೆ, ಹೀಗಾಗಿ ಅದು ಉತ್ತರಿಸುವುದನ್ನು ನಿಲ್ಲಿಸಿದರೆ ccam ಉಳಿಸಿದ ಸಂಖ್ಯೆಗಳನ್ನು ತೋರಿಸುತ್ತದೆ ಮತ್ತು `ccam doctor` ಅದನ್ನು ವರದಿ ಮಾಡುತ್ತದೆ. ತನ್ನದೇ ಹುಡುಕಾಟ ವಿಫಲವಾಯಿತು ಎಂದು Claude Code ಉತ್ತರಿಸಿದಾಗ, ccam ಮಿತಿಗಳಿಲ್ಲದ ಪ್ಲಾನ್ ಅನ್ನಲ್ಲ, ಉಳಿಸಿದ ಸಂಖ್ಯೆಗಳನ್ನು `the usage endpoint gave Claude Code no usage (it may be refusing lookups for now)` ಜೊತೆ ತೋರಿಸುತ್ತದೆ.

`--dry-run` ಇದ್ದಾಗ, Claude Code ಖಾತೆಯ ಫೋಲ್ಡರ್‌ಗೆ ಬರೆಯುವುದರಿಂದ ccam ಅದನ್ನು ಆರಂಭಿಸುವುದಿಲ್ಲ; ಬದಲಿಗೆ ಉಳಿಸಿದ ಸಂಖ್ಯೆಗಳನ್ನು ತೋರಿಸುತ್ತದೆ. `usage_source` `live` ಅಥವಾ `claude` ತೆಗೆದುಕೊಳ್ಳುತ್ತದೆ; `cache` ಕೇವಲ `--source` ಆಯ್ಕೆ.

`ccam statusline` Claude Code ನ ಸ್ಟೇಟಸ್ ಲೈನ್ JSON ಅನ್ನು ಸ್ಟ್ಯಾಂಡರ್ಡ್ ಇನ್‌ಪುಟ್‌ನಿಂದ ಓದುತ್ತದೆ. ಅದರ ಏಕೈಕ ಆಯ್ಕೆ `--wrap <command>`: ಈಗಿರುವ ಸ್ಟೇಟಸ್ ಲೈನ್ ಕಮಾಂಡ್, ಅದರ ಔಟ್‌ಪುಟ್‌ನ ಮೊದಲ ಸಾಲಿನ ಮುಂದೆ ಖಾತೆಯ ಹೆಸರು ಸೇರುತ್ತದೆ. `ccam statusline install` ಯಾವುದೇ ಆಯ್ಕೆ ತೆಗೆದುಕೊಳ್ಳುವುದಿಲ್ಲ. ಎರಡೂ `--dry-run` ಅನ್ನು `` --dry-run is not supported by `ccam statusline`; nothing was changed `` ಎಂದು ನಿರಾಕರಿಸುತ್ತವೆ.

## ಟೋಕನ್‌ಗಳು ಮತ್ತು ವೆಚ್ಚಗಳು: `ccam ccusage`

`ccam usage` ಒಂದು ಖಾತೆ ಪ್ರತಿ ಮಿತಿಯಲ್ಲಿ ಎಷ್ಟನ್ನು ಬಳಸಿದೆ ಎಂದು ತೋರಿಸುತ್ತದೆ. [ccusage](https://ccusage.com) ಇದರ ಬದಲು Claude Code ನ ಸಂಭಾಷಣೆ ಲಾಗ್‌ಗಳಲ್ಲಿರುವ ಟೋಕನ್‌ಗಳು ಮತ್ತು ಅಂದಾಜು ವೆಚ್ಚಗಳನ್ನು ಎಣಿಸುತ್ತದೆ. ತಾನಾಗಿಯೇ ಅದು Claude Code ನ ಲಾಗ್‌ಗಳನ್ನು `~/.claude` ಮತ್ತು `~/.config/claude` ನಲ್ಲಿ (ಅಥವಾ `CLAUDE_CONFIG_DIR` ಹೆಸರಿಸುವ ಫೋಲ್ಡರ್‌ಗಳಲ್ಲಿ) ಮಾತ್ರ ಹುಡುಕುತ್ತದೆ, ಹೀಗಾಗಿ ಅದಕ್ಕೆ ಕಾಣುವ ಏಕೈಕ ccam ಖಾತೆ ಎಂದರೆ `~/.claude` ನಲ್ಲಿ ಇದ್ದಲ್ಲೇ ಇಂಪೋರ್ಟ್ ಮಾಡಿದ ಖಾತೆ. `ccam ccusage` ಸಂಭಾಷಣೆಗಳಿರುವ ಪ್ರತಿ ಖಾತೆಯ ಫೋಲ್ಡರ್‌ಗಳಿಗೆ `CLAUDE_CONFIG_DIR` ಅನ್ನು ಹೊಂದಿಸಿ ಅದನ್ನು ರನ್ ಮಾಡುತ್ತದೆ, ಹೀಗಾಗಿ ಒಂದೇ ವರದಿ ಅವೆಲ್ಲವನ್ನೂ ಒಳಗೊಳ್ಳುತ್ತದೆ:

```sh
ccam ccusage                           # every account, ccusage's daily report
ccam ccusage daily --breakdown         # cost per model
ccam ccusage claude monthly --json     # Claude Code alone, as JSON
ccam ccusage -a work blocks --active   # one account's current 5-hour block
ccam ccusage -a work,side weekly       # these accounts, and any that share their history
```

ccam ಮೊದಲು ತನ್ನದೇ ಆಯ್ಕೆಗಳನ್ನು ಓದುತ್ತದೆ: `-a` (`--account`) ಖಾತೆಯ ಹೆಸರುಗಳನ್ನು ಅಥವಾ ಸಂಖ್ಯೆಗಳನ್ನು ತೆಗೆದುಕೊಳ್ಳುತ್ತದೆ, ಅಲ್ಪವಿರಾಮದಿಂದ ಬೇರ್ಪಡಿಸಿ ಅಥವಾ ಆಯ್ಕೆಯನ್ನು ಹಲವು ಬಾರಿ ನೀಡಿ, ಮತ್ತು `--dry-run` ಕಮಾಂಡ್ ಅನ್ನು ರನ್ ಮಾಡುವ ಬದಲು ಅದನ್ನು ಮುದ್ರಿಸುತ್ತದೆ. ccam ನ ಆಯ್ಕೆಯಲ್ಲದ ಮೊದಲ ಆರ್ಗ್ಯುಮೆಂಟ್‌ನಿಂದ ಮುಂದೆ, ಎಲ್ಲವೂ ಬದಲಾಗದೆ ccusage ಗೆ ಹೋಗುತ್ತದೆ; `ccam ccusage -- --help` ccusage ನ ಸ್ವಂತ ಸಹಾಯವನ್ನು ತೋರಿಸುತ್ತದೆ. `ccusage` ಇನ್‌ಸ್ಟಾಲ್ ಆಗಿದ್ದರೆ ccam ಅದನ್ನು ರನ್ ಮಾಡುತ್ತದೆ, ಇಲ್ಲದಿದ್ದರೆ `bun x ccusage`, ಅದೂ ವಿಫಲವಾದರೆ `npx ccusage@latest`; ಈ ಕೊನೆಯ ಎರಡು ccusage ಅನ್ನು npm ನಿಂದ ತರುತ್ತವೆ. ಇವುಗಳಲ್ಲಿ ಯಾವುದೂ ಲಭ್ಯವಿಲ್ಲದಿದ್ದಾಗ, Node.js, Bun ಅಥವಾ ccusage ಅನ್ನು ಇನ್‌ಸ್ಟಾಲ್ ಮಾಡಲು ಅದು ಹೇಳುತ್ತದೆ. Linux ಮತ್ತು macOS ನಲ್ಲಿ ccusage, ccam ನ ಜಾಗವನ್ನು ಪಡೆಯುತ್ತದೆ; Windows ನಲ್ಲಿ ccam ಅದಕ್ಕಾಗಿ ಕಾಯುತ್ತದೆ ಮತ್ತು ಅದರ ಎಕ್ಸಿಟ್ ಕೋಡ್‌ನೊಂದಿಗೆ ನಿರ್ಗಮಿಸುತ್ತದೆ. WSL ಅಡಿಯಲ್ಲಿ, Windows ಡ್ರೈವ್‌ನಲ್ಲಿರುವ `ccusage`, `bun` ಅಥವಾ `npx` ಅನ್ನು ccam ಬಿಟ್ಟುಬಿಡುತ್ತದೆ, ಏಕೆಂದರೆ ಅದು ಖಾತೆಯ ಫೋಲ್ಡರ್‌ಗಳಿಲ್ಲದೆ Windows ಪ್ರೋಗ್ರಾಂ ಆಗಿ ರನ್ ಆಗುತ್ತದೆ.

- ಫೋಲ್ಡರ್‌ಗಳಲ್ಲಿ ಸಂಭಾಷಣೆಗಳು (ಒಂದು `projects` ಫೋಲ್ಡರ್) ಇರುವ ಖಾತೆಗಳನ್ನು ವರದಿ ಒಳಗೊಳ್ಳುತ್ತದೆ. ಖಾತೆಗಳು ಗುಂಪಿನ ಮೂಲಕ ಹಂಚಿಕೊಳ್ಳುವ ಸಂಭಾಷಣೆಯನ್ನು ಒಮ್ಮೆ ಮಾತ್ರ ಎಣಿಸಲಾಗುತ್ತದೆ.
- `-a` ಜೊತೆ, ಗುಂಪಿನ ಮೂಲಕ ತನ್ನ ಇತಿಹಾಸವನ್ನು ಹಂಚಿಕೊಳ್ಳುವ ಖಾತೆ ಇಡೀ ಗುಂಪಿನ ಸಂಭಾಷಣೆಗಳನ್ನು ತರುತ್ತದೆ, ಮತ್ತು ಅವು ಯಾರವು ಎಂದು ccam ಹೇಳುತ್ತದೆ: `ccam: work shares its conversation history with personal, so the report counts their conversations too`.
- `blocks` 5 ಗಂಟೆಯ ಅವಧಿಗಳನ್ನು ತೋರಿಸುತ್ತದೆ, ಮತ್ತು ಪ್ರತಿ ಖಾತೆಗೂ ತನ್ನದೇ ಅವಧಿಗಳಿವೆ, ಹೀಗಾಗಿ ಮೇಲಿನಂತೆ ಅದಕ್ಕೆ ಒಂದೇ ಖಾತೆಯನ್ನು ಹೆಸರಿಸಿ.
- ನೀವು ಒಂದನ್ನು ಹೆಸರಿಸದ ಹೊರತು, ccusage ತಾನು ಕಂಡುಕೊಳ್ಳುವ ಇತರ ಕೋಡಿಂಗ್ ಟೂಲ್‌ಗಳನ್ನೂ, ಉದಾಹರಣೆಗೆ Codex, ವರದಿ ಮಾಡುತ್ತದೆ: `ccam ccusage claude daily` ಕೇವಲ Claude Code.
- ccam ಅದನ್ನು ರನ್ ಮಾಡುವಾಗ, ccusage ತನ್ನ ಸೆಟ್ಟಿಂಗ್‌ಗಳನ್ನು (`ccusage.json`) `./.ccusage` ಮತ್ತು ಖಾತೆಯ ಫೋಲ್ಡರ್‌ಗಳಿಂದ ಮಾತ್ರ ಓದುತ್ತದೆ. `--config` ಇನ್ನೊಂದು ಫೈಲ್ ಅನ್ನು ಹೆಸರಿಸುತ್ತದೆ: `ccam ccusage daily --config ~/.config/claude/ccusage.json`.
- ಪಾತ್‌ನಲ್ಲಿ ಅಲ್ಪವಿರಾಮ ಇರುವ ಫೋಲ್ಡರ್ ಅನ್ನು ccusage ಎರಡು ಫೋಲ್ಡರ್‌ಗಳೆಂದು ಓದಿಬಿಡುತ್ತದೆ, ಹೀಗಾಗಿ ccam ಅದನ್ನು ನಿರಾಕರಿಸಿ ಆ ಖಾತೆಯನ್ನು ಹೆಸರಿಸುತ್ತದೆ; `-a` ಬಳಸಿ ಆ ಖಾತೆಯನ್ನು ಹೊರಗಿಡಿ.
- `ccusage` ಒಂದು ccam ಕಮಾಂಡ್, ಹೀಗಾಗಿ ccusage ಎಂಬ ಹೆಸರಿನ ಖಾತೆ `ccam run ccusage` ಮೂಲಕ ಆರಂಭವಾಗುತ್ತದೆ; `ccam doctor` ಇದನ್ನು ತಿಳಿಸುತ್ತದೆ.

## ಇದು ಹೇಗೆ ಕೆಲಸ ಮಾಡುತ್ತದೆ

`ccam usage` ನ ಸಂಖ್ಯೆಗಳು ಎರಡು ಕಡೆಯಿಂದ ಬರುತ್ತವೆ: ಪ್ರತಿ ಖಾತೆಯ ಸ್ವಂತ ಲಾಗಿನ್‌ನೊಂದಿಗೆ ಕರೆಯಲಾಗುವ Anthropic ನ ದಾಖಲಾಗದ ಬಳಕೆಯ ಎಂಡ್‌ಪಾಯಿಂಟ್ `GET https://api.anthropic.com/api/oauth/usage`, ಮತ್ತು Claude Code ತನ್ನ ಸ್ಟೇಟಸ್ ಲೈನ್ ಕಮಾಂಡ್‌ಗೆ ನೀಡುವ ಮೌಲ್ಯಗಳು. ಇದೆಲ್ಲವೂ `internal/usage` ನಲ್ಲಿದೆ.

1. ccam `config.toml` ಅನ್ನು ಲೋಡ್ ಮಾಡುತ್ತದೆ ಮತ್ತು ಪ್ರತಿ ಖಾತೆಗೆ ಒಂದು `usage.Account` ರಚಿಸುತ್ತದೆ (`cli.usageCmd`): ಅದರ ಫೋಲ್ಡರ್ `~/.local/share/ccam/profiles/<name>/`, ಅದರ ಸೆಷನ್ ಗುರುತುಗಳು (ಖಾತೆಯ ಫೋಲ್ಡರ್‌ನಲ್ಲಿರುವ Claude Code ನ ಸ್ವಂತ ದಾಖಲೆಗಳೊಂದಿಗೆ, ಅವು ಅದು ಚಾಲನೆಯಲ್ಲಿದೆಯೇ ಎಂದು ತಿಳಿಸುತ್ತವೆ) ಮತ್ತು ಅದನ್ನು ಇದ್ದಲ್ಲೇ ಇಂಪೋರ್ಟ್ ಮಾಡಲಾಗಿದೆಯೇ ಎಂಬುದು.
2. ccam ಪ್ರತಿ ಖಾತೆಯನ್ನು ಒಮ್ಮೆಗೇ, ಪ್ರತಿ ಖಾತೆಗೆ ಒಂದು goroutine ಮೂಲಕ ಹುಡುಕುತ್ತದೆ (`Fetcher.FetchAll`). ಎಲ್ಲವೂ ಒಂದೇ `http.Client` ಅನ್ನು ಹಂಚಿಕೊಳ್ಳುತ್ತವೆ, ಹೀಗಾಗಿ ಎಂಡ್‌ಪಾಯಿಂಟ್‌ಗೆ ಸಂಪರ್ಕಗಳನ್ನು ಮರುಬಳಕೆ ಮಾಡಲಾಗುತ್ತದೆ. ಸಂಪರ್ಕಕ್ಕೆ 2 s ತೆಗೆದುಕೊಳ್ಳಬಹುದು, ಮತ್ತು ಪ್ರತಿ ಖಾತೆಗೆ ಒಟ್ಟು 3 s ಸಿಗುತ್ತದೆ. ಕ್ಲೈಂಟ್ ರೀಡೈರೆಕ್ಟ್‌ಗಳನ್ನು ಅನುಸರಿಸುವುದಿಲ್ಲ, ಏಕೆಂದರೆ ರೀಡೈರೆಕ್ಟ್ ಟೋಕನ್ ಅನ್ನು ಬೇರೆಡೆಗೆ ಮತ್ತೆ ಕಳುಹಿಸುತ್ತದೆ, ಮತ್ತು ಉತ್ತರದ ಗರಿಷ್ಠ 1 MB ಅನ್ನು ಮಾತ್ರ ಓದುತ್ತದೆ.
3. ಪ್ರತಿ ಖಾತೆ ಮುಗಿದಂತೆ ಅದರ ಸಾಲನ್ನು ಮತ್ತೆ ಬರೆಯಲಾಗುತ್ತದೆ. ವಿಫಲವಾದ ಅಥವಾ ಸಮಯಕ್ಕೆ ಉತ್ತರಿಸದ ಖಾತೆ ಉಳಿಸಿದ ಸಂಖ್ಯೆಗಳಿಗೆ ಮರಳುತ್ತದೆ, ಹೀಗಾಗಿ ಒಂದು ನಿಧಾನ ಖಾತೆ ಇತರವನ್ನು ಎಂದಿಗೂ ತಡೆಯುವುದಿಲ್ಲ.

ಚಿತ್ರದಲ್ಲಿ, ಪ್ರತಿ ಖಾತೆಯನ್ನು ತನ್ನದೇ goroutine ನಲ್ಲಿ ಹುಡುಕಲಾಗುತ್ತದೆ, ಮತ್ತು ಸಮಯ ಮೀರಿದ ಖಾತೆ ಬದಲಿಗೆ ತನ್ನ ಉಳಿಸಿದ ಸಂಖ್ಯೆಗಳನ್ನು ತೋರಿಸುತ್ತದೆ:

<!-- motion:usage-fetch -->

`personal` ಮತ್ತು `work` ಸಮಯಕ್ಕೆ ಉತ್ತರಿಸುತ್ತವೆ ಮತ್ತು ನೇರ ಸಂಖ್ಯೆಗಳನ್ನು ತೋರಿಸುತ್ತವೆ. `side` 3 s ಗಿಂತ ಹೆಚ್ಚು ತೆಗೆದುಕೊಳ್ಳುತ್ತದೆ, ಹೀಗಾಗಿ ccam ಬದಲಿಗೆ ಅದರ ಉಳಿಸಿದ ಸಂಖ್ಯೆಗಳನ್ನು ತೋರಿಸುತ್ತದೆ (`fallback()`). ನಂತರ ccam ಪ್ರತಿ ಖಾತೆಗೆ ಒಂದು ಬ್ಲಾಕ್ ಬರೆಯುತ್ತದೆ (`usage.Table()`) ಮತ್ತು ಕೊನೆಯ ಸಾಲಿನಲ್ಲಿ ಹೆಸರಿಸುವ ಖಾತೆಯನ್ನು ಆಯ್ಕೆಮಾಡುತ್ತದೆ (`usage.Best()`).

ಒಂದು ಖಾತೆಗಾಗಿ, ccam ಈ ಪರಿಶೀಲನೆಗಳನ್ನು ಈ ಕ್ರಮದಲ್ಲಿ ಮಾಡುತ್ತದೆ (`Fetcher.Fetch`):

<!-- motion:usage-cache -->

1. `--source cache` ಇದ್ದರೆ, ಅದು ನೇರವಾಗಿ `fallback()` ಗೆ ಹೋಗುತ್ತದೆ.
2. `--no-cache` ಇಲ್ಲದಿದ್ದರೆ, `~/.local/state/ccam/usage/<name>.json` ನಲ್ಲಿರುವ, 60 ಸೆಕೆಂಡ್‌ಗಳಿಗಿಂತ (`CacheTTL`) ಕಡಿಮೆ ಸಮಯದ ಹಿಂದೆ ಅಳೆದ ನೇರ ಫಲಿತಾಂಶವನ್ನು, ಈಗಿನ ಸಮಯಕ್ಕೆ ಅನುಗುಣವಾಗಿ ನಿರ್ಣಯಿಸಿ, ಬಳಸಲಾಗುತ್ತದೆ: ಅಂದಿನಿಂದ ರೀಸೆಟ್ ಆಗಿರುವ ಅವಧಿ 0% ತೋರಿಸುತ್ತದೆ, ಮತ್ತು ಗಡಿಯಾರಕ್ಕಿಂತ ಮುಂದಿನ ದಿನಾಂಕದ ಫೈಲ್ ಅನ್ನು ಹೊಸದು ಎಂದು ಎಣಿಸಲಾಗುವುದಿಲ್ಲ. `ccam usage` ಅನ್ನು ಸತತ ಎರಡು ಬಾರಿ ರನ್ ಮಾಡಿದರೆ ಪ್ರತಿ ಖಾತೆಗೆ ಒಂದೇ ವಿನಂತಿ ಆಗುತ್ತದೆ.
3. ccam `.credentials.json` ಅನ್ನು (ಅಥವಾ macOS Keychain ಅನ್ನು) ಬದಲಾಯಿಸದೆ ಓದುತ್ತದೆ ಮತ್ತು `claudeAiOauth` ಕೀಯನ್ನು ಮಾತ್ರ ಡಿಕೋಡ್ ಮಾಡುತ್ತದೆ (`readCredentials()`). ಚಂದಾದಾರಿಕೆ ಲಾಗಿನ್ ಇಲ್ಲದಿದ್ದರೆ `not logged in`, ಅಥವಾ `.claude.json` ನಲ್ಲಿ API ಕೀ ಇದ್ದರೆ `no limits (API)`. ರಿಫ್ರೆಶ್ ಟೋಕನ್‌ನ ಅವಧಿ ಮುಗಿದ, ಅಥವಾ Claude Code ತೆರವುಗೊಳಿಸಿದ ಲಾಗಿನ್ `` login expired → `ccam login <name>` `` ಆಗಿರುತ್ತದೆ ಮತ್ತು ಅದನ್ನು ಹುಡುಕಲಾಗುವುದಿಲ್ಲ.
4. ಅವಧಿ ಮುಗಿದ ಆಕ್ಸೆಸ್ ಟೋಕನ್ ಅನ್ನು ಬಳಸಲಾಗುವುದಿಲ್ಲ. `--refresh` ಇಲ್ಲದೆ, ಖಾತೆ ತನ್ನ ಉಳಿಸಿದ ಸಂಖ್ಯೆಗಳನ್ನು ``access token expired; `ccam <name>` renews it when it starts`` ಜೊತೆ ತೋರಿಸುತ್ತದೆ.
5. ಇಲ್ಲದಿದ್ದರೆ ccam ಎಂಡ್‌ಪಾಯಿಂಟ್ ಅನ್ನು ಕರೆಯುತ್ತದೆ. 401 ಅಥವಾ 403 ಅನ್ನು ಅವಧಿ ಮುಗಿದ ಲಾಗಿನ್ ಎಂದು ಪರಿಗಣಿಸಲಾಗುತ್ತದೆ (`login expired: authentication failed (401)`), ಬೇರೆ ಯಾವುದೇ ಸ್ಟೇಟಸ್ ಅಥವಾ ಓದಲಾಗದ ಉತ್ತರವನ್ನು ದೋಷ ಎಂದು ಪರಿಗಣಿಸಲಾಗುತ್ತದೆ, ಮತ್ತು ಎರಡೂ ಉಳಿಸಿದ ಸಂಖ್ಯೆಗಳಿಗೆ ಮರಳುತ್ತವೆ. Ctrl+C ನಿಂದ ಮುಗಿದ ಹುಡುಕಾಟ `cancelled` ಎಂದು ಹೇಳುತ್ತದೆ. 429 ಎಂದರೆ ಈ ಖಾತೆಗಾಗಿ ಎಂಡ್‌ಪಾಯಿಂಟ್‌ಗೆ ತುಂಬಾ ಹೆಚ್ಚು ವಿನಂತಿಗಳು ಬಂದಿವೆ: ccam ಮತ್ತೆ ಕೇಳುವ ಸಮಯದೊಂದಿಗೆ (`Retry-After`, ಅಥವಾ 5 ನಿಮಿಷ, ಗರಿಷ್ಠ ಒಂದು ಗಂಟೆ) `<name>.pause` ಅನ್ನು ಬರೆಯುತ್ತದೆ, ಉಳಿಸಿದ ಸಂಖ್ಯೆಗಳನ್ನು `rate limited by the usage endpoint; asking again after 15:10` ಜೊತೆ ತೋರಿಸುತ್ತದೆ, ಮತ್ತು ಆ ಸಮಯದವರೆಗೆ `--no-cache` ಇದ್ದರೂ ಆ ಖಾತೆಗಾಗಿ ಎಂಡ್‌ಪಾಯಿಂಟ್ ಅನ್ನು ಕರೆಯುವುದಿಲ್ಲ. ತಕ್ಷಣ ಮತ್ತೆ ಪ್ರಯತ್ನಿಸಿದರೆ rate limit ಇನ್ನಷ್ಟು ದೀರ್ಘವಾಗುತ್ತದೆ.
6. ಸರಿಯಾದ ಉತ್ತರವನ್ನು ಅಳೆದ ಸಮಯದೊಂದಿಗೆ `<name>.json` ಗೆ ಬರೆಯಲಾಗುತ್ತದೆ.

ಉಳಿಸಿದ ಸಂಖ್ಯೆಗಳಿಗಾಗಿ, ccam ಅತಿ ಹೊಸ ಉಳಿಸಿದ ಹುಡುಕಾಟವನ್ನು (`<name>.json`, ಅಥವಾ Claude Code ನ ಹುಡುಕಾಟಗಳಿಂದ ಬಂದ `<name>.claude.json`) ತೆಗೆದುಕೊಳ್ಳುತ್ತದೆ, ಮತ್ತು ಅದರ ನಂತರ `<name>.statusline.json` ಬರೆಯಲ್ಪಟ್ಟಿದ್ದರೆ, ಸ್ಟೇಟಸ್ ಲೈನ್‌ನ 5 ಗಂಟೆಯ ಮತ್ತು ವಾರದ ಅವಧಿಗಳನ್ನು ಅದರ ಮೇಲೆ ಇರಿಸುತ್ತದೆ (`fallback()`); ಸ್ಟೇಟಸ್ ಲೈನ್‌ನಲ್ಲಿ ಇಲ್ಲದ ಮಾಡೆಲ್ ಅವಧಿಗಳು ಹುಡುಕಾಟ ಉಳಿಸಿದಂತೆಯೇ ಉಳಿಯುತ್ತವೆ. ಉಳಿಸಿದ ಸಂಖ್ಯೆಗಳನ್ನು ತೋರಿಸುವ ಮೊದಲು, ಅದು ಪ್ರತಿ ಅವಧಿಯ ರೀಸೆಟ್ ಸಮಯವನ್ನು ಪರಿಶೀಲಿಸುತ್ತದೆ: ಸಂಖ್ಯೆಗಳನ್ನು ಉಳಿಸಿದ ನಂತರ ರೀಸೆಟ್ ಆಗಿರುವ ಅವಧಿ 0% ತೋರಿಸುತ್ತದೆ, ಏಕೆಂದರೆ ಹಳೆಯ ಶೇಕಡಾವಾರು ಇನ್ನು ಅನ್ವಯಿಸುವುದಿಲ್ಲ. ಅದಕ್ಕಾಗಿಯೇ ಮೇಲಿನ `personal` ರೀಸೆಟ್ ಸಮಯವಿಲ್ಲದೆ `0%` ತೋರಿಸುತ್ತದೆ.

ಎಂಡ್‌ಪಾಯಿಂಟ್‌ಗೆ ಎರಡು ಉತ್ತರ ಸ್ವರೂಪಗಳಿವೆ. ಹೊಸದರಲ್ಲಿ `session` (5 ಗಂಟೆ), `weekly_all` ಮತ್ತು `weekly_scoped` (ಮಾಡೆಲ್‌ವಾರು) ಐಟಂಗಳಿರುವ `limits` ಅರೇ ಇದೆ. ಹಳೆಯದರಲ್ಲಿ `five_hour`, `seven_day`, `seven_day_opus` ಮತ್ತು `seven_day_sonnet` ಆಬ್ಜೆಕ್ಟ್‌ಗಳಿವೆ. ccam ಎರಡನ್ನೂ ಓದುತ್ತದೆ (`ParseLive`): `limits` ಅರೇಗೆ ಆದ್ಯತೆ, ಮತ್ತು ಅದು ಒಳಗೊಳ್ಳದ್ದನ್ನು ಹಳೆಯ ಆಬ್ಜೆಕ್ಟ್‌ಗಳು ತುಂಬುತ್ತವೆ. ಯಾವುದೇ ಮಿತಿಗಳಿಲ್ಲದ ಉತ್ತರವನ್ನು ಬದಲಾದ ಸ್ವರೂಪ ಎಂದು ವರದಿ ಮಾಡಲಾಗುತ್ತದೆ, ಅದರ ಬಗ್ಗೆ `ccam doctor` ನಿಮಗೆ ತಿಳಿಸುತ್ತದೆ.

### ಮಿತಿ ದಾಖಲೆ

Claude Code ಒಂದು ಸರದಿಯನ್ನು ಬಳಕೆಯ ಮಿತಿಯಲ್ಲಿ ನಿಲ್ಲಿಸಿದಾಗ, [ccam ಪ್ಲಗಿನ್](/docs/install#claude-code-plugin) ನ ಹುಕ್ ನಿರಾಕರಿಸಿದ ವಿನಂತಿಯನ್ನು ಸಂಭಾಷಣೆಯಿಂದ ಓದುತ್ತದೆ: ಯಾವ ಅವಧಿ ತುಂಬಿತ್ತು (5 ಗಂಟೆಯ, ವಾರದ, Opus ಅಥವಾ Sonnet) ಮತ್ತು ಅದು ಯಾವಾಗ ರೀಸೆಟ್ ಆಗುತ್ತದೆ. ಅದು ಇದನ್ನು `~/.local/state/ccam/usage/<name>.limit.json` ಗೆ ಬರೆಯುತ್ತದೆ. ccam ತನಗೆ ತಿಳಿದ ಉಳಿದೆಲ್ಲದರ ಮೇಲೆ, ಪ್ರತಿ ಮೂಲದಿಂದ, ಈ ದಾಖಲೆಯನ್ನು ಅನ್ವಯಿಸುತ್ತದೆ (`Fetch`): ಅದರಲ್ಲಿನ ಪ್ರತಿ ಅವಧಿಯನ್ನು, ಉಳಿಸಿದ ಸಂಖ್ಯೆಗಳು ಎಷ್ಟೇ ಹಳೆಯವಾಗಿದ್ದರೂ ಅಥವಾ ಕಡಿಮೆಯಿದ್ದರೂ, ಅದರ ರೀಸೆಟ್‌ವರೆಗೆ 100% ಎಂದು ಎಣಿಸಲಾಗುತ್ತದೆ, ಹೀಗಾಗಿ ಅಲ್ಲಿಯವರೆಗೆ `ccam next --auto`, `ccam pick`, `--fallback` ಮತ್ತು [`auto_switch`](/features/next#auto-switch) ಆ ಖಾತೆಯನ್ನು ಮತ್ತೆ ಆಯ್ಕೆಮಾಡುವುದಿಲ್ಲ.

ಬೇರೇನೂ ತಿಳಿದಿಲ್ಲದಿದ್ದಾಗ, ಖಾತೆ ತೋರಿಸುವುದು ಆ ದಾಖಲೆಯನ್ನು ಮಾತ್ರ (`-v` ಜೊತೆ `source: the usage limit Claude Code reported`). ಯಾರೂ ಗಮನಿಸದ ಸೆಷನ್‌ಗಳು (`-p` ರನ್‌ಗಳು ಮತ್ತು ಹಿನ್ನೆಲೆ ಸೆಷನ್‌ಗಳು) ಯಾವುದೇ ದಾಖಲೆ ಬರೆಯುವುದಿಲ್ಲ, ಸಂಸ್ಥೆ ಹೊಂದಿಸಿದ ನಿಲುಗಡೆಯೂ (ಉದಾಹರಣೆಗೆ, ಅದರ ಬಳಕೆ ಮುಗಿದಾಗ ಅಥವಾ ಒಂದು ಗುಂಪಿನ ಮಿತಿ $0 ಆಗಿದ್ದಾಗ) ಬರೆಯುವುದಿಲ್ಲ, ಏಕೆಂದರೆ ಅದರ ನಿರ್ವಾಹಕರು ಅದನ್ನು ಯಾವಾಗ ಬೇಕಾದರೂ ತೆಗೆದುಹಾಕಬಹುದು. ಇನ್ನೊಂದು Claude ಖಾತೆಗೆ `ccam login` ದಾಖಲೆಯನ್ನು ಕೈಬಿಡುತ್ತದೆ; ಫೈಲ್ ಅನ್ನು ಅಳಿಸಿದರೂ ಅದು ತೆರವಾಗುತ್ತದೆ.

### ಟೋಕನ್‌ಗಳನ್ನು ನವೀಕರಿಸುವುದು

ರಿಫ್ರೆಶ್ ಟೋಕನ್‌ಗಳು ಬದಲಾಗುತ್ತಾ ಇರುತ್ತವೆ: ಒಂದನ್ನು ನವೀಕರಿಸಿದರೆ ಹೊಸ ರಿಫ್ರೆಶ್ ಟೋಕನ್ ಸಿಗುತ್ತದೆ ಮತ್ತು ಹಳೆಯದು ಅಮಾನ್ಯವಾಗುತ್ತದೆ. ಅದೇ ಖಾತೆಯಾಗಿ Claude Code ಚಾಲನೆಯಲ್ಲಿರುವಾಗ ccam ಲಾಗಿನ್ ಅನ್ನು ನವೀಕರಿಸಿದರೆ, ಆ ಸೆಷನ್ ಸೈನ್ ಔಟ್ ಆಗುತ್ತದೆ. ಹೀಗಾಗಿ `ccam usage` ಟೋಕನ್‌ಗಳನ್ನು ಓದುತ್ತದೆ ಮತ್ತು ಎಂದಿಗೂ ಬರೆಯುವುದಿಲ್ಲ, ನೀವು `--refresh` ನೀಡದ ಹೊರತು. ಆಗ ccam (`Fetcher.refresh`):

1. `ccam import` ಮೂಲಕ ಇದ್ದಲ್ಲೇ ನೋಂದಾಯಿಸಿದ ಖಾತೆಗಳನ್ನು ನಿರಾಕರಿಸುತ್ತದೆ, ಏಕೆಂದರೆ ccam ಗೆ ತಿಳಿಯದೆ ಸಾಮಾನ್ಯ `claude` ಆ ಲಾಗಿನ್ ಅನ್ನು ಬಳಸಬಹುದು;
2. macOS Keychain ನಲ್ಲಿ ಸಂಗ್ರಹವಾಗಿರುವ ಲಾಗಿನ್‌ಗಳನ್ನು ನಿರಾಕರಿಸುತ್ತದೆ;
3. `~/.local/state/ccam/locks/profile-<name>.refresh.lock` ಎಂಬ ಲಾಕ್ ಫೈಲ್ ಅನ್ನು ಪಡೆಯುತ್ತದೆ, ಹೀಗಾಗಿ ಎರಡು ccam ಪ್ರಕ್ರಿಯೆಗಳು ಒಂದೇ ಟೋಕನ್ ಅನ್ನು ಎಂದಿಗೂ ಎರಡೂ ನವೀಕರಿಸುವುದಿಲ್ಲ; ಅದು ಹಿಡಿದಿರುವಾಗ, ಖಾತೆ `token not renewed: another ccam process is using this login right now (a refresh, rename, remove or logout)` ಎಂದು ತೋರಿಸುತ್ತದೆ. `ccam rename`, `remove` ಮತ್ತು `logout` ಕೂಡ ಅದನ್ನು ಪಡೆಯುತ್ತವೆ, ಮತ್ತು ನವೀಕರಣ ನಡೆಯುತ್ತಿರುವಾಗ ನಿರಾಕರಿಸುತ್ತವೆ;
4. ಲಾಕ್ ಅಡಿಯಲ್ಲಿ, ಖಾತೆಯ ಸೆಷನ್ ಚಾಲನೆಯಲ್ಲಿದ್ದರೆ, ಅದನ್ನು ಹೇಗೆ ಆರಂಭಿಸಿದ್ದರೂ (ccam ಮೂಲಕ, ಸಾಮಾನ್ಯ `claude`, IDE, ಅಥವಾ ಹಿನ್ನೆಲೆ ಸೆಷನ್ ಮತ್ತು ಲಾಗಿನ್ ಅನ್ನು ತಾನೇ ನವೀಕರಿಸುವ ಅದರ ಹಿಂದಿನ daemon), ನಿರಾಕರಿಸುತ್ತದೆ, ಮತ್ತು ಇನ್ನೊಂದು ಪ್ರಕ್ರಿಯೆ ಈಗಾಗಲೇ ಟೋಕನ್ ಅನ್ನು ನವೀಕರಿಸಿದ್ದರೆ ವಿನಂತಿಯನ್ನು ಬಿಟ್ಟುಬಿಡುತ್ತದೆ;
5. ಖಾತೆಯ ಫೋಲ್ಡರ್‌ನಲ್ಲಿ Claude Code ತನ್ನದೇ ನವೀಕರಣ ಲಾಕ್‌ಗಳನ್ನು (`.oauth_refresh.lock`, `<folder>.lock`) ಹಿಡಿದಿರುವಾಗ ಏನನ್ನೂ ಕಳುಹಿಸುವುದಿಲ್ಲ: ಆಗ Claude Code ಆ ಲಾಗಿನ್ ಅನ್ನು ನವೀಕರಿಸುತ್ತಿರುತ್ತದೆ;
6. ರಿಫ್ರೆಶ್ ಟೋಕನ್ ಅನ್ನು ಟೋಕನ್ ಎಂಡ್‌ಪಾಯಿಂಟ್‌ಗೆ ಕಳುಹಿಸುತ್ತದೆ ಮತ್ತು ಉತ್ತರಕ್ಕಾಗಿ 30 ಸೆಕೆಂಡ್‌ಗಳವರೆಗೆ ಕಾಯುತ್ತದೆ, ಇದು Claude Code ತನ್ನದೇ ನವೀಕರಣಗಳಿಗೆ ನೀಡುವ ಸಮಯ. ಒಮ್ಮೆ ಕಳುಹಿಸಿದ ವಿನಂತಿಯನ್ನು, Ctrl+C ಕೂಡ, ಎಂದಿಗೂ ಅಡ್ಡಿಪಡಿಸುವುದಿಲ್ಲ: ಸರ್ವರ್ ಈಗಾಗಲೇ ರಿಫ್ರೆಶ್ ಟೋಕನ್ ಅನ್ನು ಬದಲಾಯಿಸಿರಬಹುದು, ಮತ್ತು ಅದರ ಉತ್ತರ ಮಾತ್ರ ಹೊಸ ಲಾಗಿನ್ ಅನ್ನು ಹೊಂದಿರುತ್ತದೆ. Ctrl+C ಅಥವಾ hangup ಉಳಿದ ಹುಡುಕಾಟಗಳನ್ನು ಮುಗಿಸುತ್ತದೆ, ಮತ್ತು ಉತ್ತರವನ್ನು ಉಳಿಸಿದ ನಂತರ ccam ನಿರ್ಗಮಿಸುತ್ತದೆ (Ctrl+C ನಂತರ 130);
7. Claude Code ನ ಬರಹ ಲಾಕ್ (`.storage-write.lock`) ಅಡಿಯಲ್ಲಿ ಉಳಿಸುತ್ತದೆ ಮತ್ತು ಆ ಸಮಯದಲ್ಲಿ ಇರುವ `.credentials.json` ನ ಟೋಕನ್ ಕ್ಷೇತ್ರಗಳನ್ನು ಮಾತ್ರ ಬದಲಾಯಿಸುತ್ತದೆ: ಈ ನಡುವೆ Claude Code ಬರೆದದ್ದು (ಒಂದು MCP ಸೈನ್-ಇನ್) ಉಳಿಯುತ್ತದೆ, ಈ ನಡುವೆ Claude Code ನವೀಕರಿಸಿದ ಲಾಗಿನ್ ಅನ್ನು ಉಳಿಸಿಕೊಳ್ಳಲಾಗುತ್ತದೆ, ಮತ್ತು ಲಾಗ್ ಔಟ್ ಅನ್ನು ಎಂದಿಗೂ ರದ್ದುಮಾಡಲಾಗುವುದಿಲ್ಲ. ಉತ್ತರವು ಹೊಸ ರಿಫ್ರೆಶ್ ಟೋಕನ್‌ನ ಜೀವಿತಾವಧಿಯನ್ನು ನೀಡಿದಾಗ, Claude Code ಮಾಡುವಂತೆಯೇ ಅದನ್ನು `refreshTokenExpiresAt` ಆಗಿ ಸಂಗ್ರಹಿಸಲಾಗುತ್ತದೆ.

ನಡೆಯದ ನವೀಕರಣ ಕಾರಣವನ್ನು ಖಾತೆಯ ಸಾಲಿನಲ್ಲಿ ಅಥವಾ ಅದರ ಉಳಿಸಿದ ಸಂಖ್ಯೆಗಳ ಮೇಲೆ ತಿಳಿಸುತ್ತದೆ: ಉದಾಹರಣೆಗೆ `token not renewed: a session is running`, ಅಥವಾ ವಿನಂತಿ ಕಳುಹಿಸಲಾಗಿದ್ದು ಅದರ ಉತ್ತರವನ್ನು ಬಳಸಲು ಅಥವಾ ಉಳಿಸಲು ಸಾಧ್ಯವಾಗದಿದ್ದಾಗ `login may be lost: …`, ನಂತರ Claude Code ಲಾಗಿನ್ ಆಗಲು ಕೇಳಿದರೆ `ccam login <name>` ರನ್ ಮಾಡುವ ಸಲಹೆಯೊಂದಿಗೆ.

### ಸ್ಟೇಟಸ್ ಲೈನ್ ಸಂಗ್ರಾಹಕ

Claude Code ಸ್ಟೇಟಸ್ ಲೈನ್ ಕಮಾಂಡ್ ಅನ್ನು ರನ್ ಮಾಡಿ ಅದಕ್ಕೆ ಒಂದು JSON ಡಾಕ್ಯುಮೆಂಟ್ ಅನ್ನು ಪೈಪ್ ಮಾಡುತ್ತದೆ. ccam ಅದರಿಂದ ಮಾಡೆಲ್ ಹೆಸರು ಮತ್ತು `rate_limits` ಅನ್ನು ಓದುತ್ತದೆ:

<!-- motion:usage-statusline -->

1. ccam ಖಾತೆಯನ್ನು `CCAM_PROFILE` ನಿಂದ ಕಂಡುಹಿಡಿಯುತ್ತದೆ, ಇದನ್ನು ccam Claude Code ಆರಂಭಿಸುವಾಗ ಹೊಂದಿಸುತ್ತದೆ; ಇಲ್ಲದಿದ್ದರೆ `CLAUDE_CONFIG_DIR` ಅನ್ನು ಖಾತೆಯ ಫೋಲ್ಡರ್‌ಗಳೊಂದಿಗೆ ಹೊಂದಿಸಿ ನೋಡುತ್ತದೆ (`runStatusline`).
2. ccam `rate_limits.five_hour` ಮತ್ತು `rate_limits.seven_day` ಅನ್ನು ಓದುತ್ತದೆ (`ParseStatusLine`). API ಕೀ ಖಾತೆಗಳಿಗೆ, ಅಥವಾ ಸೆಷನ್‌ನ ಮೊದಲ ಉತ್ತರದ ಮೊದಲು, JSON ನಲ್ಲಿ ರೇಟ್ ಮಿತಿಗಳಿರುವುದಿಲ್ಲ; ಆಗ ಏನನ್ನೂ ಉಳಿಸಲಾಗುವುದಿಲ್ಲ.
3. ccam `~/.local/state/ccam/usage/<name>.statusline.json` ಅನ್ನು ಬರೆಯುತ್ತದೆ (`SaveStatusLine`). ಎಂಡ್‌ಪಾಯಿಂಟ್ ಉತ್ತರಿಸದಿದ್ದಾಗ `ccam usage` ಇದನ್ನು ಬಳಸುತ್ತದೆ.
4. ccam `[name] · model · 5h N% · 7d N%` ಅನ್ನು ಮುದ್ರಿಸುತ್ತದೆ. `--wrap` ಇದ್ದರೆ, ಅದು ನಿಮ್ಮ ಕಮಾಂಡ್ ಅನ್ನು ಅದೇ ಇನ್‌ಪುಟ್‌ನೊಂದಿಗೆ `sh -c` ಮೂಲಕ ರನ್ ಮಾಡುತ್ತದೆ ಮತ್ತು Claude Code ಸ್ಟೇಟಸ್ ಲೈನ್ ತೋರಿಸುವ ರೀತಿಯಲ್ಲೇ ಅದರ ಔಟ್‌ಪುಟ್ ಅನ್ನು ಮುದ್ರಿಸುತ್ತದೆ: ಖಾಲಿಯಲ್ಲದ ಪ್ರತಿ ಸಾಲು, ಮೊದಲ ಸಾಲಿನ ಮುಂದೆ `[name]` ಜೊತೆ. ವಿಫಲವಾದ ಕಮಾಂಡ್ ಖಾತೆಯ ಹೆಸರನ್ನು ಮಾತ್ರ ತೋರಿಸುತ್ತದೆ. Windows ನಲ್ಲಿ ಅದು Claude Code ಮಾಡುವ ರೀತಿಯಲ್ಲೇ ಕಮಾಂಡ್ ಅನ್ನು ರನ್ ಮಾಡುತ್ತದೆ: Git Bash ಇನ್‌ಸ್ಟಾಲ್ ಆಗಿದ್ದರೆ ಅದರ ಮೂಲಕ, ಇಲ್ಲದಿದ್ದರೆ PowerShell ಮೂಲಕ.
5. 5 ಗಂಟೆಯ ಅಥವಾ ವಾರದ ಬಳಕೆ 90% ಅಥವಾ ಅದಕ್ಕಿಂತ ಹೆಚ್ಚಿದ್ದು ಇನ್ನೊಂದು ಖಾತೆ ಇದ್ದಾಗ, ಸಾಲು `→ ccam next --auto --continue` ನೊಂದಿಗೆ ಕೊನೆಗೊಳ್ಳುತ್ತದೆ, ಉದಾಹರಣೆಗೆ `[work] · Opus · 5h 93% · 7d 41% · → ccam next --auto --continue`.

ಸುತ್ತಿದ ಕಮಾಂಡ್‌ಗೆ ತನ್ನದೇ ಸಮಯ ಮಿತಿ ಇಲ್ಲ: Claude Code ಸ್ಟೇಟಸ್ ಲೈನ್ ಕಮಾಂಡ್‌ಗೆ 10 ನಿಮಿಷ ನೀಡುತ್ತದೆ ಮತ್ತು ಹೊಸ ಅಪ್‌ಡೇಟ್ ಆರಂಭವಾದಾಗ ರನ್ ಅನ್ನು ನಿಲ್ಲಿಸುತ್ತದೆ, ಹೀಗಾಗಿ ನಿಧಾನವಾದ ಕಮಾಂಡ್ ccam ಇಲ್ಲದಿದ್ದರೆ ಹೇಗೆ ಕಾಣುತ್ತಿತ್ತೋ ಹಾಗೆಯೇ ಕಾಣುತ್ತದೆ. Claude Code ccam ಅನ್ನು ಮುಗಿಸಿದಾಗ, ಕಮಾಂಡ್ ಕೂಡ ಮುಗಿಯುತ್ತದೆ (Linux ಮತ್ತು macOS ನಲ್ಲಿ ಅದು ಆರಂಭಿಸಿದ ಪ್ರತಿ ಪ್ರಕ್ರಿಯೆಯೊಂದಿಗೆ).

`ccam statusline install` ಪ್ರತಿ ಖಾತೆಯ `settings.json` ನಲ್ಲಿ `statusLine` ಅನ್ನು ಬರೆಯುತ್ತದೆ ಮತ್ತು `padding`, `refreshInterval` ಮತ್ತು `hideVimModeIndicator` ನಂತಹ ಆಬ್ಜೆಕ್ಟ್‌ನ ಇತರ ಕೀಗಳನ್ನು ಉಳಿಸಿಕೊಳ್ಳುತ್ತದೆ. ಒಂದು ಖಾತೆಗೆ ಈಗಾಗಲೇ ಸ್ಟೇಟಸ್ ಲೈನ್ ಕಮಾಂಡ್ ಇದ್ದಾಗ, ccam ಅದನ್ನು `--wrap '<old command>'` ಆಗಿ ಉಳಿಸಿಕೊಳ್ಳುತ್ತದೆ; Windows ನಲ್ಲಿ `--wrap-base64 <base64>` ಆಗಿ, ಇದಕ್ಕೆ ಯಾವುದೇ ಶೆಲ್‌ನಲ್ಲಿ quoting ಬೇಕಿಲ್ಲ. ಸ್ಟೇಟಸ್ ಲೈನ್ ಈಗಾಗಲೇ ccam ಅನ್ನು ರನ್ ಮಾಡುತ್ತಿದ್ದರೆ (ಬೇರೆ ಪಾತ್‌ನಿಂದ, ಅಥವಾ ಹಳೆಯ ಆವೃತ್ತಿ ಬರೆದ ರೀತಿಯಲ್ಲಿ quote ಮಾಡಿ), ccam ಅದನ್ನು ಸುತ್ತುವ ಬದಲು ಬದಲಾಯಿಸುತ್ತದೆ, ಮತ್ತು ಅದು ಸುತ್ತಿದ್ದ ಕಮಾಂಡ್ ಅನ್ನು ಉಳಿಸಿಕೊಳ್ಳುತ್ತದೆ.

Windows ನಲ್ಲಿ ccam ನ ಪಾತ್ ಅನ್ನು ಫಾರ್ವರ್ಡ್ ಸ್ಲ್ಯಾಶ್‌ಗಳು ಮತ್ತು ಹೋಮ್ ಫೋಲ್ಡರ್‌ಗೆ `~` ಜೊತೆ ಬರೆಯಲಾಗುತ್ತದೆ (`~/.local/bin/ccam.exe statusline`), ಇದನ್ನು Git Bash ಮತ್ತು PowerShell ಎರಡೂ ಅರ್ಥಮಾಡಿಕೊಳ್ಳುತ್ತವೆ. quote ಗಳು ಬೇಕಾದ ಪಾತ್ ಅನ್ನು Claude Code ಬಳಸುವ ಶೆಲ್‌ಗಾಗಿ ಪೂರ್ಣವಾಗಿ ಬರೆಯಲಾಗುತ್ತದೆ: Git Bash ಗೆ `'…'`, PowerShell ಗೆ `& '…'`. ಗುಂಪಿನ ಮೂಲಕ ಹಂಚಿಕೊಂಡ `settings.json` ಅನ್ನು ಅದರ ಲಿಂಕ್ ಮೂಲಕ ಒಮ್ಮೆ ಮಾತ್ರ ಬರೆಯಲಾಗುತ್ತದೆ, ಹೀಗಾಗಿ ಗುಂಪಿನ ಪ್ರತಿ ಖಾತೆಗೂ ಅದು ಸಿಗುತ್ತದೆ. ಇದನ್ನು ಮತ್ತೆ ರನ್ ಮಾಡಿದರೆ, ಈಗಾಗಲೇ ccam ಬಳಸುತ್ತಿರುವ ಫೈಲ್‌ಗಳಿಗೆ `(already set)` ಎಂದು ಮುದ್ರಿಸುತ್ತದೆ.

## ಸುರಕ್ಷತೆ ಮತ್ತು ವಿಶೇಷ ಸಂದರ್ಭಗಳು

- ನೀವು `--refresh` ನೀಡದ ಹೊರತು `ccam usage` ಟೋಕನ್ ಫೈಲ್ ಅನ್ನು ಎಂದಿಗೂ ಬದಲಾಯಿಸುವುದಿಲ್ಲ. ಆಕ್ಸೆಸ್ ಟೋಕನ್‌ನ ಅವಧಿ ಮುಗಿದಾಗ, ಖಾತೆಯನ್ನು `ccam <name>` ಮೂಲಕ ಒಮ್ಮೆ ಆರಂಭಿಸಿ; Claude Code ಅದನ್ನು ನವೀಕರಿಸುತ್ತದೆ. ಸಂಪೂರ್ಣವಾಗಿ ಅವಧಿ ಮುಗಿದ ಲಾಗಿನ್‌ಗೆ `ccam login <name>` ಬೇಕು.
- `--refresh` ಚಾಲನೆಯಲ್ಲಿರುವ ಖಾತೆಗಳು (Claude Code ಅನ್ನು ccam ಇಲ್ಲದೆ ಆರಂಭಿಸಿದ್ದರೂ ಸಹ), ಇಂಪೋರ್ಟ್ ಮಾಡಿದ ಖಾತೆಗಳು ಅಥವಾ Keychain ಲಾಗಿನ್‌ಗಳನ್ನು ಎಂದಿಗೂ ಮುಟ್ಟುವುದಿಲ್ಲ. ನಿರಾಕರಿಸಿದ ನವೀಕರಣ ಉಳಿಸಿದ ಸಂಖ್ಯೆಗಳನ್ನು ಮತ್ತು ಕಾರಣವನ್ನು (`token not renewed: …`) ತೋರಿಸುತ್ತದೆ.
- ಬಳಕೆಯ ಎಂಡ್‌ಪಾಯಿಂಟ್ ಸಾರ್ವಜನಿಕವಾಗಿ ದಾಖಲಾಗಿಲ್ಲ ಮತ್ತು ಬದಲಾಗಬಹುದು. ಅದು ಬದಲಾದಾಗಲೂ ನಿಮಗೆ ಉಳಿಸಿದ ಸಂಖ್ಯೆಗಳು ಕಾಣಿಸುತ್ತವೆ, ಮತ್ತು `ccam doctor` ಸ್ವರೂಪದ ಬದಲಾವಣೆಯನ್ನು ವರದಿ ಮಾಡುತ್ತದೆ.
- ಉಳಿಸಿದ ಸಂಖ್ಯೆಗಳೂ ಇಲ್ಲದೆ ಉತ್ತರವೂ ಇಲ್ಲದಿದ್ದಾಗ, ಖಾತೆಯ ಸಾಲು `lookup failed:` ಮತ್ತು ಕಾರಣವನ್ನು ತೋರಿಸುತ್ತದೆ, ಉದಾಹರಣೆಗೆ `--source cache` ಜೊತೆ `no saved usage`.
- ಕ್ಯಾಶ್ ಫೈಲ್‌ಗಳಲ್ಲಿ ಶೇಕಡಾವಾರುಗಳು ಮತ್ತು ರೀಸೆಟ್ ಸಮಯಗಳು ಮಾತ್ರ ಇರುತ್ತವೆ, ಟೋಕನ್‌ಗಳು ಎಂದಿಗೂ ಇರುವುದಿಲ್ಲ.
