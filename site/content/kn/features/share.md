ಪ್ರತಿ ಖಾತೆಗೆ ತನ್ನದೇ ಫೋಲ್ಡರ್ ಇರುತ್ತದೆ, ಆದರೆ ಅದರಲ್ಲಿರುವ ಹೆಚ್ಚಿನವು ಪ್ರತ್ಯೇಕವಾಗಿರಬೇಕಾಗಿಲ್ಲ. ಏನನ್ನು ಮತ್ತು ಯಾರು ಹಂಚಿಕೊಳ್ಳುತ್ತಾರೆ ಎಂಬುದನ್ನು ಒಂದು **ಗುಂಪು** ಹೇಳುತ್ತದೆ: ಗುಂಪಿನ ಪ್ರತಿ ಖಾತೆಯೂ ಆ ಐಟಂಗಳನ್ನು `~/.local/share/ccam/groups/<group>/` ಎಂಬ ಒಂದೇ ಫೋಲ್ಡರ್‌ಗೆ ಲಿಂಕ್ ಮಾಡುತ್ತದೆ, ಹೀಗಾಗಿ ಅವೆಲ್ಲವೂ ಒಂದೇ ಪ್ರತಿಯನ್ನು ಓದುತ್ತವೆ ಮತ್ತು ಬರೆಯುತ್ತವೆ. ಲಾಗಿನ್ ಟೋಕನ್‌ಗಳನ್ನು ಎಂದಿಗೂ ಹಂಚಿಕೊಳ್ಳಲಾಗುವುದಿಲ್ಲ.

ಒಂದು ಖಾತೆ ಹಲವು ಗುಂಪುಗಳಲ್ಲಿರಬಹುದು, ಆದರೆ ಪ್ರತಿ ಐಟಂ ಒಂದೇ ಗುಂಪಿನಿಂದ ಬರುತ್ತದೆ. ಸಾಮಾನ್ಯ ಸೆಟಪ್ ಎಂದರೆ ಸೆಟ್ಟಿಂಗ್‌ಗಳು ಮತ್ತು ವಿಸ್ತರಣೆಗಳಿಗೆ ಒಂದು ಗುಂಪು, ಮತ್ತು ಎರಡು ಖಾತೆಗಳ ನಡುವಿನ ಸಂಭಾಷಣೆಯ ಇತಿಹಾಸಕ್ಕೆ ಎರಡನೆಯದು:

```toml
[[group]]
name = 'default'
items = ['mcp', 'settings', 'memory', 'extensions']
members = ['personal', 'work', 'side']

[[group]]
name = 'team'
items = ['history']
members = ['work', 'side']
```

ನೀವು ಸೇರಿಸುವ ಮೊದಲ ಖಾತೆ `default` ಅನ್ನು ರಚಿಸುತ್ತದೆ, ಮತ್ತು ನೀವು ಬೇರೆ ಹೇಳದಿದ್ದರೆ ನಂತರದ ಖಾತೆಗಳು ಅದನ್ನು ಸೇರುತ್ತವೆ.

## ಬಳಕೆ

```sh
ccam group                                        # the groups, what they share, their accounts
ccam group show default                           # items, accounts, folder and MCP servers
ccam group add team --items history --members work,side
ccam group set default --add history              # all accounts in default start sharing history
ccam group set default --remove history --fresh   # stop sharing; accounts start without it
ccam group set team --items history,memory --from work   # the group starts from work's copies
ccam group join team personal                     # personal starts sharing team's items
ccam group join team personal --replace           # first leave the group that shares those items now
ccam group leave team side                        # side keeps a copy of team's items
ccam group rename team pair                       # the folder keeps its name
ccam group remove pair --leave                    # its accounts keep a copy; folder to the trash
ccam share work                                   # what work shares, and through which group
ccam --dry-run group set default --add history    # print the plan, change nothing
```

```console
$ ccam group
Group    Shares                          Accounts
default  mcp settings memory extensions  personal, work, side
team     history                         work, side

$ ccam share work
Sharing for work
  mcp         MCP servers                        group default
  settings    settings.json                      group default
  memory      global CLAUDE.md                   group default
  extensions  agents, commands, skills, plugins  group default
  history     conversation history               group team
Groups: default, team. Change them with `ccam group`.
```

ಡೇಟಾವನ್ನು ಸ್ಥಳಾಂತರಿಸುವ ಪ್ರತಿ ಕಮಾಂಡ್ ಒಂದು ಯೋಜನೆಯನ್ನು ಮುದ್ರಿಸುತ್ತದೆ, ಗುಂಪಿನ ಪ್ರತಿಗಿಂತ ಬೇರೆಯಾಗಿರುವ ಪ್ರತಿ ಫೈಲ್ ಬಗ್ಗೆ ಕೇಳುತ್ತದೆ, ಮತ್ತು ಏನನ್ನಾದರೂ ಬದಲಾಯಿಸುವ ಮೊದಲು `Proceed? [y/N]` ಎಂದು ಕೇಳುತ್ತದೆ:

```console
$ ccam group set default --add history
Plan (paths in /home/me/.local/share/ccam):
personal: +history (group default)
  move     projects, history.jsonl: profiles/personal → groups/default (first content of the group)
  link     projects, history.jsonl, file-history, tasks, paste-cache: profiles/personal → groups/default
work: +history (group default)
  merge    new files in projects: profiles/work → groups/default
  conflict profiles/work/history.jsonl ↔ groups/default/history.jsonl: merge by line
  back up  projects, history.jsonl: profiles/work → profiles/work/.ccam-backup/20261023-213057
  link     projects, history.jsonl, file-history, tasks, paste-cache: profiles/work → groups/default
  Note: projects: 1 file differs from the group's copy (-home-me-code-app/s1.jsonl); the group's is kept, the account's stays in profiles/work/.ccam-backup/20261023-213057/projects
Proceed? [y/N]
```

ನೀವು ಇದೇ ಬದಲಾವಣೆಗಳನ್ನು [ಡ್ಯಾಶ್‌ಬೋರ್ಡ್](/features/dashboard) ನ **Groups** ಟ್ಯಾಬ್‌ನಲ್ಲಿ ಮಾಡಬಹುದು; ಒಂದು ಖಾತೆಯ ಗುಂಪುಗಳನ್ನು ಆಯ್ಕೆಮಾಡಲು ಅದರ ಮೇಲೆ `s` ಒತ್ತಿ.

## ಐಟಂಗಳು

| ಐಟಂ | ಏನನ್ನು ಒಳಗೊಳ್ಳುತ್ತದೆ |
| --- | --- |
| `mcp` | ಗುಂಪಿನ `mcp.json` ಮೂಲಕ MCP ಸರ್ವರ್‌ಗಳು ([ಹಂಚಿಕೊಂಡ MCP ಸರ್ವರ್‌ಗಳು](/features/mcp)) |
| `settings` | `settings.json` |
| `memory` | ಜಾಗತಿಕ `CLAUDE.md` |
| `extensions` | `agents/`, `commands/`, `skills/`, `plugins/`, `output-styles/`, `rules/` |
| `history` | `projects/` ಮತ್ತು `history.jsonl`, ಹೀಗಾಗಿ ಇನ್ನೊಂದು ಖಾತೆ `--continue` ಮಾಡಬಹುದು |

ಖಾತೆಯ ಯಾವ ಗುಂಪೂ ಒಂದು ಐಟಂ ಅನ್ನು ಹಂಚಿಕೊಳ್ಳದಿದ್ದರೆ, ಆ ಐಟಂ ಖಾತೆಯ ಸ್ವಂತ ಫೋಲ್ಡರ್‌ನಲ್ಲೇ ಉಳಿಯುತ್ತದೆ.

## ಕಮಾಂಡ್‌ಗಳು ಮತ್ತು ಆಯ್ಕೆಗಳು

| ಕಮಾಂಡ್ | ಏನು ಮಾಡುತ್ತದೆ |
| --- | --- |
| `ccam group` ಅಥವಾ `ccam group list` | ಗುಂಪುಗಳನ್ನು ಪಟ್ಟಿ ಮಾಡುತ್ತದೆ |
| `ccam group show <group>` | ಗುಂಪು ಏನನ್ನು ಹಂಚಿಕೊಳ್ಳುತ್ತದೆ, ಅದರ ಖಾತೆಗಳು, ಅದರ ಫೋಲ್ಡರ್ ಮತ್ತು MCP ಸರ್ವರ್‌ಗಳು |
| `ccam group add <group> --items <items> [--members <accounts>]` | ಗುಂಪನ್ನು ರಚಿಸುತ್ತದೆ; ಅದರ ಖಾತೆಗಳ ಐಟಂಗಳು ಅದರೊಳಗೆ ಸ್ಥಳಾಂತರಗೊಳ್ಳುತ್ತವೆ |
| `ccam group set <group> --add <items> \| --remove <items> \| --items <items>` | ಗುಂಪು ಏನನ್ನು ಹಂಚಿಕೊಳ್ಳುತ್ತದೆ ಎಂಬುದನ್ನು, ಅದರ ಪ್ರತಿ ಖಾತೆಗೂ, ಬದಲಾಯಿಸುತ್ತದೆ |
| `ccam group join <group> <account>...` | ಖಾತೆಗಳನ್ನು ಗುಂಪಿಗೆ ಸೇರಿಸುತ್ತದೆ |
| `ccam group leave <group> <account>...` | ಖಾತೆಗಳನ್ನು ಹೊರತೆಗೆಯುತ್ತದೆ; ಪ್ರತಿಯೊಂದೂ, MCP ಸರ್ವರ್‌ಗಳನ್ನೂ ಸೇರಿಸಿ, ಒಂದು ಪ್ರತಿಯನ್ನು ಉಳಿಸಿಕೊಳ್ಳುತ್ತದೆ |
| `ccam group rename <group> <new-name>` | ಕಾನ್ಫಿಗ್‌ನಲ್ಲಿ ಮಾತ್ರ ಮರುಹೆಸರಿಸುತ್ತದೆ |
| `ccam group remove <group> [--leave]` | ಗುಂಪನ್ನು ತೆಗೆದುಹಾಕುತ್ತದೆ |

| ಆಯ್ಕೆ | ಏನು ಮಾಡುತ್ತದೆ | ಡೀಫಾಲ್ಟ್ |
| --- | --- | --- |
| `--from <account>` | `add`, `set`: ಯಾವ ಖಾತೆಯ ಪ್ರತಿ ಮೊದಲು ಗುಂಪಿಗೆ ಹೋಗುತ್ತದೆ | ಡೀಫಾಲ್ಟ್ ಖಾತೆ, ನಂತರ ಸಂಖ್ಯೆಯ ಕ್ರಮದಲ್ಲಿ |
| `--replace` | `join`: ಅದೇ ಐಟಂಗಳನ್ನು ಹಂಚಿಕೊಳ್ಳುವ ಗುಂಪುಗಳನ್ನು ಮೊದಲು ಬಿಡುತ್ತದೆ | ಆಫ್ |
| `--fresh` | ಒಂದು ಐಟಂ ಹಂಚಿಕೊಳ್ಳುವುದನ್ನು ನಿಲ್ಲಿಸುವ ಖಾತೆಗಳು ಪ್ರತಿಯೊಂದಿಗೆ ಅಲ್ಲ, ಅದಿಲ್ಲದೆ ಆರಂಭವಾಗುತ್ತವೆ (ಇಂಪೋರ್ಟ್ ಮಾಡಿದ ಫೋಲ್ಡರ್ ಆದರೂ ಒಂದು ಪ್ರತಿಯನ್ನು ಉಳಿಸಿಕೊಳ್ಳುತ್ತದೆ) | ಆಫ್ |
| `--leave` | `remove`: ಗುಂಪಿನ ಖಾತೆಗಳನ್ನು ಮೊದಲು ಹೊರತೆಗೆಯುತ್ತದೆ | ಖಾತೆಗಳಿದ್ದಾಗ ಬೇಕು |
| `--prefer <group\|mine\|merge>` | ಸಂಘರ್ಷಗಳನ್ನು ಹೇಗೆ ನಿರ್ಧರಿಸಬೇಕು | ಕೇಳುತ್ತದೆ; `--yes` ಜೊತೆ, ಪ್ರತಿ ಫೈಲ್‌ನ ಡೀಫಾಲ್ಟ್ |
| `-y`, `--yes` | ಕೇಳದೆ ರನ್ ಮಾಡುತ್ತದೆ; ಸಂಘರ್ಷಗಳು `--prefer` ಅನ್ನು ಅನುಸರಿಸುತ್ತವೆ | ಆಫ್ |
| `--dry-run` (ಜಾಗತಿಕ) | ಯೋಜನೆಯನ್ನು ಮುದ್ರಿಸುತ್ತದೆ, ಏನನ್ನೂ ಬದಲಾಯಿಸುವುದಿಲ್ಲ | ಆಫ್ |

ಖಾತೆಗಳನ್ನು ಹೆಸರಿನಿಂದ ಅಥವಾ ಸಂಖ್ಯೆಯಿಂದ ನೀಡಲಾಗುತ್ತದೆ; ಐಟಂಗಳನ್ನು ಅಲ್ಪವಿರಾಮದಿಂದ ಬೇರ್ಪಡಿಸಿದ ಪಟ್ಟಿಯಾಗಿ. `ccam add` `--group <group>` (ಹಲವು ಬಾರಿ ನೀಡಬಹುದು) ಅಥವಾ `--no-group` ತೆಗೆದುಕೊಳ್ಳುತ್ತದೆ.

## ಇದು ಹೇಗೆ ಕೆಲಸ ಮಾಡುತ್ತದೆ

ಒಳಗೊಂಡಿರುವ ಫೈಲ್‌ಗಳು:

- `~/.config/ccam/config.toml`: `[[group]]` ನಮೂದುಗಳು: `name`, `items`, `members` ಮತ್ತು, ಫೋಲ್ಡರ್‌ನ ಹೆಸರು ಬೇರೆಯಾಗಿದ್ದಾಗ, `dir`.
- `~/.local/share/ccam/profiles/<name>/`: ಖಾತೆಯ `CLAUDE_CONFIG_DIR`.
- `~/.local/share/ccam/groups/<folder>/`: ಹಂಚಿಕೊಂಡ ಪ್ರತಿಗಳು.

`config.toml` ಅನ್ನು ಓದಿದಾಗ, ಪ್ರತಿ ಖಾತೆಯ ಗುಂಪುಗಳನ್ನು ಐಟಂಗೆ ಒಂದು ಫೋಲ್ಡರ್ ಎಂಬಂತೆ ಪರಿಹರಿಸಲಾಗುತ್ತದೆ. ಐದು ಖಾತೆಗಳಿಗೆ ಇದಕ್ಕೆ ಸುಮಾರು 25 µs ಬೇಕು, ಹೀಗಾಗಿ ಆರಂಭ ಈಗಲೂ `config.toml` ಅನ್ನು ಮಾತ್ರ ಓದುತ್ತದೆ. ಒಂದು ಖಾತೆಗೆ ಒಂದು ಐಟಂ ಎರಡು ಗುಂಪುಗಳಿಂದ ಸಿಗುವಂತಹ ಕಾನ್ಫಿಗ್ ದೋಷ, ಮತ್ತು ಅದನ್ನು ಸರಿಪಡಿಸುವವರೆಗೆ ಏನೂ ಆರಂಭವಾಗುವುದಿಲ್ಲ.

ಬದಲಾವಣೆ ಕಾನ್ಫಿಗ್‌ನ ಒಂದು ಪ್ರತಿಯ ಮೇಲೆ ಕೆಲಸ ಮಾಡುತ್ತದೆ:

1. ಕಮಾಂಡ್ ಆ ಪ್ರತಿಯನ್ನು ಸಂಪಾದಿಸುತ್ತದೆ (`AddGroup`, `SetGroupItems`, `JoinGroup` …), ಅದು ನಿಯಮಗಳನ್ನು ಪರಿಶೀಲಿಸುತ್ತದೆ.
2. ccam ಹಳೆಯದನ್ನು ಹೊಸದರೊಂದಿಗೆ ಹೋಲಿಸಿ, ಐಟಂಗಳು ಬದಲಾಗುವ ಪ್ರತಿ ಖಾತೆಗೂ ಒಂದು ಯೋಜನೆಯನ್ನು ರಚಿಸುತ್ತದೆ (`internal/group`, `share.Build`). ಯೋಜನೆಗಳನ್ನು ಒಂದರ ನಂತರ ಒಂದರಂತೆ ರಚಿಸಲಾಗುತ್ತದೆ, ಮತ್ತು ಪ್ರತಿಯೊಂದೂ ಹಿಂದಿನವು ಗುಂಪಿನ ಫೋಲ್ಡರ್‌ಗಳಿಗೆ ಏನನ್ನು ಇಡಲಿವೆ ಎಂಬುದನ್ನು ನೋಡುತ್ತದೆ, ಹೀಗಾಗಿ ಮೊದಲ ಖಾತೆ ಮಾತ್ರ ತನ್ನ ಪ್ರತಿಯನ್ನು ಒಳಗೆ ಸ್ಥಳಾಂತರಿಸುತ್ತದೆ. ಗುಂಪಿನ ಮೊದಲ ಪ್ರತಿ ಈ ಕ್ರಮದಲ್ಲಿ ಬರುತ್ತದೆ: ಗುಂಪಿನ ಫೋಲ್ಡರ್ (ಅದರಲ್ಲಿ ಈಗಾಗಲೇ ಇದ್ದರೆ), `--from` ಖಾತೆ, ಡೀಫಾಲ್ಟ್ ಖಾತೆ, ನಂತರ ಉಳಿದ ಖಾತೆಗಳು ಸಂಖ್ಯೆಯ ಕ್ರಮದಲ್ಲಿ.
3. ಆ ಖಾತೆಗಳಲ್ಲಿ ಒಂದು ಚಾಲನೆಯಲ್ಲಿದ್ದರೆ, Claude Code ಅನ್ನು ಹೇಗೆ ಆರಂಭಿಸಿದ್ದರೂ (``work is running; quit Claude Code there first, then change the groups (`ccam agents` lists the sessions)``), ಮತ್ತು Developer Mode ಇಲ್ಲದ Windows ನಲ್ಲಿ ಒಂದು ಫೈಲ್‌ಗೆ ಲಿಂಕ್ ಬೇಕಾದರೆ, ccam ನಿರಾಕರಿಸುತ್ತದೆ.
4. ccam ಸಂಘರ್ಷಗಳನ್ನು ಪರಿಹರಿಸುತ್ತದೆ (ಕೇಳುವ ಮೂಲಕ, ಅಥವಾ `--prefer` ಮೂಲಕ), ಯೋಜನೆಯನ್ನು ಮುದ್ರಿಸುತ್ತದೆ ಮತ್ತು ದೃಢೀಕರಣ ಕೇಳುತ್ತದೆ.
5. ಉಳಿಸುವ ಸ್ವಲ್ಪ ಮೊದಲು, ccam ಮತ್ತೆ ಪರಿಶೀಲಿಸುತ್ತದೆ. ccam ನಿಮ್ಮ ಉತ್ತರಗಳಿಗಾಗಿ ಕಾಯುತ್ತಿದ್ದಾಗ ಒಂದು ಖಾತೆ ಆರಂಭವಾದರೆ, ಬದಲಾವಣೆ ನಿಲ್ಲುತ್ತದೆ; ಈ ನಡುವೆ ಇನ್ನೊಂದು ccam ಪ್ರೊಸೆಸ್ ಅದೇ ಗುಂಪುಗಳನ್ನು ಬದಲಾಯಿಸಿದರೂ ಅದು ನಿಲ್ಲುತ್ತದೆ (`the groups changed while this plan waited; nothing was moved, make the change again`). ಏನಾದರೂ ಸ್ಥಳಾಂತರವಾಗುವ ಮೊದಲೇ ಹೊಸ ಕಾನ್ಫಿಗ್ ಅನ್ನು ಉಳಿಸಲಾಗುತ್ತದೆ, ಮತ್ತು ಬದಲಾವಣೆಯನ್ನು `~/.local/state/ccam/group-change.json` ನಲ್ಲಿ ದಾಖಲಿಸಲಾಗುತ್ತದೆ. ಒಂದು ಹಂತ ಅರ್ಧದಲ್ಲಿ ನಿಂತರೆ, ಆ ದಾಖಲೆ ಉಳಿಯುತ್ತದೆ: `ccam doctor --fix` ಬದಲಾವಣೆಯನ್ನು ಅದರ ಕ್ರಮದಲ್ಲಿ, ನೀವು ನೀಡಿದ ಉತ್ತರಗಳೊಂದಿಗೆ, MCP ಹಂತಗಳನ್ನೂ ಸೇರಿಸಿ, ಪೂರ್ಣಗೊಳಿಸುತ್ತದೆ, ಮತ್ತು ಅಲ್ಲಿಯವರೆಗೆ ಬೇರೆ ಯಾವುದೇ ಗುಂಪು ಬದಲಾವಣೆ ಆರಂಭವಾಗುವುದಿಲ್ಲ (``the last group change stopped halfway; finish it with `ccam doctor --fix` first``).
6. MCP ಹಂತಗಳು ಮೊದಲು ರನ್ ಆಗುತ್ತವೆ. ಖಾತೆಗಳು ಗುಂಪಿನಿಂದ ವಿಸ್ತರಣೆಗಳನ್ನು ಹೊರತೆಗೆದಾಗ, ಗುಂಪಿನ ಪ್ಲಗಿನ್ ಪಟ್ಟಿಗಳ ಪಾತ್‌ಗಳು ಯಾವುದೇ ಖಾತೆಯ ಫೋಲ್ಡರ್ ಮೂಲಕ ಹಾದುಹೋಗುವಲ್ಲೆಲ್ಲಾ ಅವುಗಳನ್ನು ಗುಂಪಿನ ಫೋಲ್ಡರ್‌ಗೆ ಸೂಚಿಸುವಂತೆ ಮಾಡಲಾಗುತ್ತದೆ (ಯೋಜನೆಯಲ್ಲಿ `group plugin lists:`). ನಂತರ ಯೋಜನೆಗಳು ಕ್ರಮವಾಗಿ ರನ್ ಆಗುತ್ತವೆ. ಪ್ರತಿ ಹಂತವೂ ಡೇಟಾವನ್ನು ಗುಂಪಿಗೆ ಅಥವಾ ಬ್ಯಾಕಪ್ ಫೋಲ್ಡರ್‌ಗೆ ಸ್ಥಳಾಂತರಿಸುತ್ತದೆ; ಗುಂಪಿನ ಪ್ರತಿಗೆ ಸಮಾನವಾದ ಫೈಲ್‌ಗಳನ್ನು ಮಾತ್ರ ಬ್ಯಾಕಪ್ ಮಾಡುವ ಬದಲು ಅಳಿಸಲಾಗುತ್ತದೆ.

ccam ಪ್ರತಿ ಐಟಂ ಒಳಗೊಳ್ಳುವ ಪಾತ್‌ಗಳ ಅನುಮತಿ ಪಟ್ಟಿಯನ್ನು ಇಟ್ಟುಕೊಳ್ಳುತ್ತದೆ (`share.Layout`). ಅದರಲ್ಲಿ ಇಲ್ಲದ ಯಾವುದೂ ಎಂದಿಗೂ ಗುಂಪನ್ನು ತಲುಪುವುದಿಲ್ಲ. ccam `.credentials.json` ಮತ್ತು `.claude.json` ಅನ್ನು ಎಂದಿಗೂ ಹಂಚಿಕೊಳ್ಳದವು ಎಂದು ಹೆಸರಿಸುತ್ತದೆ (`share.Never`), ಮತ್ತು ಇವುಗಳಲ್ಲಿ ಯಾವುದಾದರೂ ಲೇಔಟ್‌ನಲ್ಲಿ ಕಾಣಿಸಿಕೊಂಡರೆ ಆಂತರಿಕ ದೋಷದೊಂದಿಗೆ ನಿಲ್ಲುತ್ತದೆ (`Build`). `mcp` ಐಟಂಗೆ ಯಾವುದೇ ಪಾತ್ ಇಲ್ಲ: ಸರ್ವರ್ ಪಟ್ಟಿ `.claude.json` ಒಳಗೆ ಇರುತ್ತದೆ, ಹೀಗಾಗಿ [MCP ಹಂಚಿಕೆ](/features/mcp) ಗುಂಪಿನ `mcp.json` ಮೂಲಕ ಕೆಲಸ ಮಾಡುತ್ತದೆ.

`side` ಇತಿಹಾಸವನ್ನು ಹಂಚಿಕೊಳ್ಳಲು ಆರಂಭಿಸಿದಾಗ ಮತ್ತು ಗುಂಪಿನಲ್ಲಿ ಈಗಾಗಲೇ ವಿಷಯ ಇದ್ದಾಗ, `projects/` ಎಂಬ ಒಂದು ಫೋಲ್ಡರ್‌ಗೆ ಏನಾಗುತ್ತದೆ ಎಂಬುದು ಇಲ್ಲಿದೆ:

<!-- motion:share-on -->

ಆ ಪಾತ್‌ನಲ್ಲಿ ಗುಂಪಿನಲ್ಲಿ ಇನ್ನೂ ಏನೂ ಇಲ್ಲದಿದ್ದರೆ, ಅದನ್ನು ಹಂಚಿಕೊಳ್ಳುವ ಮೊದಲ ಖಾತೆ ಇದೇ, ಮತ್ತು ಅದರ ಫೋಲ್ಡರ್ ಅನ್ನು ಇದ್ದಂತೆಯೇ ಅಲ್ಲಿಗೆ ಸ್ಥಳಾಂತರಿಸಲಾಗುತ್ತದೆ. ಇಲ್ಲದಿದ್ದರೆ ಗುಂಪಿನಲ್ಲಿ ಇಲ್ಲದ ಪ್ರತಿ ಫೈಲ್ ಅನ್ನು ಗುಂಪಿಗೆ ಸ್ಥಳಾಂತರಿಸಲಾಗುತ್ತದೆ, ಮತ್ತು ಎರಡೂ ಕಡೆ ಇರುವ ಫೈಲ್‌ಗಳು ಖಾತೆಯ ಫೋಲ್ಡರ್‌ನಲ್ಲೇ ಉಳಿಯುತ್ತವೆ, ಹೀಗಾಗಿ ಗುಂಪಿನ ಆವೃತ್ತಿ ಉಳಿಯುತ್ತದೆ. ಗುಂಪಿನದಕ್ಕೆ ಸಮಾನವಾದ ಫೈಲ್‌ಗಳನ್ನು ಅಳಿಸಲಾಗುತ್ತದೆ, ಮತ್ತು ಭಿನ್ನವಾಗಿರುವವನ್ನು ಯೋಜನೆ ಹೆಸರಿಸುತ್ತದೆ (`Note: projects: 1 file differs from the group's copy (…); the group's is kept, the account's stays in …`).

ನಂತರ ಖಾತೆಯ ಫೋಲ್ಡರ್ ಖಾತೆ ಫೋಲ್ಡರ್‌ನೊಳಗಿನ `.ccam-backup/<time>/` ಗೆ ಹೋಗುತ್ತದೆ, ಮತ್ತು ಅದರ ಜಾಗದಲ್ಲಿ ಒಂದು ಲಿಂಕ್ ಬರುತ್ತದೆ. ಗುಂಪಿನ ನಮೂದು ತಾನೇ ಸೇರುತ್ತಿರುವ ಖಾತೆಯ ಸ್ವಂತ ನಮೂದಿಗೆ ಲಿಂಕ್ ಆಗಿದ್ದರೆ, ಖಾತೆಯ ವಿಷಯ ಅದರ ಜಾಗದಲ್ಲಿ ಗುಂಪಿಗೆ ಹೋಗುತ್ತದೆ. ಸಂಭಾಷಣೆಯ ಫೈಲ್‌ಗಳಿಗೆ ಅವುಗಳ ಸೆಷನ್ ID ಯ ಹೆಸರು ಇರುತ್ತದೆ, ಹೀಗಾಗಿ ಹಲವು ಖಾತೆಗಳ ಇತಿಹಾಸಗಳು ಸಂಘರ್ಷವಿಲ್ಲದೆ ಒಂದಾಗುತ್ತವೆ. `plugins/` ರಿಜಿಸ್ಟ್ರಿಗಳು ಖಾತೆ ಫೋಲ್ಡರ್ ಮೂಲಕ ಸಂಪೂರ್ಣ ಪಾತ್‌ಗಳನ್ನು ಸಂಗ್ರಹಿಸುತ್ತವೆ; ccam ಅವುಗಳನ್ನು ಗುಂಪಿನ ಫೋಲ್ಡರ್‌ಗೆ ಸೂಚಿಸುವಂತೆ ಮಾಡುತ್ತದೆ, ಮತ್ತು ಗುಂಪಿನಲ್ಲಿ ಈಗಾಗಲೇ ರಿಜಿಸ್ಟ್ರಿ ಇದ್ದರೆ ಖಾತೆಯ ನಮೂದುಗಳನ್ನು ಅದರೊಳಗೆ ವಿಲೀನಗೊಳಿಸುತ್ತದೆ.

ಗುಂಪನ್ನು ಬಿಡುವಾಗ ಲಿಂಕ್ ಹಿಮ್ಮುಖವಾಗುತ್ತದೆ:

<!-- motion:share-off -->

ccam ಮೊದಲು ಗುಂಪಿನ ಈಗಿನ ವಿಷಯವನ್ನು ಖಾತೆ ಫೋಲ್ಡರ್‌ನಲ್ಲಿನ `.ccam-backup/incomplete-<name>` ಗೆ ನಕಲಿಸುತ್ತದೆ, ಮತ್ತು ನಕಲು ಪೂರ್ಣಗೊಂಡ ನಂತರವೇ ಲಿಂಕ್ ಅನ್ನು ಬದಲಾಯಿಸುತ್ತದೆ. ನಕಲು ಅರ್ಧದಲ್ಲಿ ನಿಂತರೆ, ಲಿಂಕ್ ಜಾಗದಲ್ಲೇ ಉಳಿಯುತ್ತದೆ ಮತ್ತು `ccam doctor --fix` ಮತ್ತೆ ನಕಲಿಸುತ್ತದೆ (ಅಂತಹ ಪೂರ್ಣಗೊಳಿಸುವಿಕೆಯ ಯೋಜನೆ `restore <entry>: … (copied back from the group before a stop)` ತೋರಿಸುತ್ತದೆ). ಗುಂಪು ತನ್ನ ವಿಷಯವನ್ನು ಇತರ ಖಾತೆಗಳಿಗಾಗಿ ಉಳಿಸಿಕೊಳ್ಳುತ್ತದೆ.

- ಯೋಜನೆ ರಚಿಸಿದಾಗ ಇದ್ದಂತೆಯೇ ಲಿಂಕ್ ಇನ್ನೂ ಗುಂಪುಗಳ ಫೋಲ್ಡರ್‌ನೊಳಗೆ ಸೂಚಿಸಿದರೆ ಮಾತ್ರ ccam ಲಿಂಕ್ ಅನ್ನು ತೆಗೆದುಹಾಕುತ್ತದೆ. ಅಂದಿನಿಂದ ಬದಲಾದ ಪಾತ್, ಉದಾಹರಣೆಗೆ ಲಿಂಕ್ ಇದ್ದಲ್ಲಿ ನಿಜವಾದ ಫೈಲ್, ಇದ್ದಂತೆಯೇ ಉಳಿಯುತ್ತದೆ ಮತ್ತು ಬದಲಾವಣೆ ನಿಲ್ಲುತ್ತದೆ.
- `--fresh` ಜೊತೆ, ನಕಲನ್ನು ಬಿಟ್ಟುಬಿಡಲಾಗುತ್ತದೆ.
- ಫೋಲ್ಡರ್ ಇನ್ನೂ ಖಾಲಿಯಾಗಿರುವ ಗುಂಪಿಗೆ ಒಂದು ಐಟಂ ಅನ್ನು ಸ್ಥಳಾಂತರಿಸುವ ಖಾತೆ ತಾನು ನೋಡಿದ್ದರ ಪ್ರತಿಯನ್ನು ತರುತ್ತದೆ, ಹೀಗಾಗಿ ಅದರ ಫೈಲ್‌ಗಳು ಉಳಿಯುತ್ತವೆ. ಆ ಪ್ರತಿ ಪೂರ್ಣಗೊಳ್ಳುವವರೆಗೆ ಅದನ್ನು `<group>/.ccam-incomplete-<name>` ನಲ್ಲಿ ಸಿದ್ಧಪಡಿಸಲಾಗುತ್ತದೆ.
- MCP ಹಂಚಿಕೊಳ್ಳುವುದನ್ನು ನಿಲ್ಲಿಸುವ ಖಾತೆ ಗುಂಪಿನ ಸರ್ವರ್‌ಗಳನ್ನು ಉಳಿಸಿಕೊಳ್ಳುತ್ತದೆ: ಅವು ಅದರ ಸ್ವಂತ `.claude.json` ಗೆ ಹೋಗುತ್ತವೆ (ಬ್ಯಾಕಪ್ ಉಳಿಯುತ್ತದೆ), ಖಾತೆಗೆ ಈಗಾಗಲೇ ಅದೇ ಹೆಸರಿನ ಸರ್ವರ್ ಇದ್ದಲ್ಲಿ ಹೊರತು; ಆ ಸರ್ವರ್ ಇದ್ದಂತೆಯೇ ಉಳಿಯುತ್ತದೆ. `--fresh` ಇದ್ದರೆ, ಬದಲಿಗೆ ಲೋಡ್ ಆಗುವುದನ್ನು ನಿಲ್ಲಿಸುವ ಸರ್ವರ್‌ಗಳನ್ನು ಯೋಜನೆ ಪಟ್ಟಿ ಮಾಡುತ್ತದೆ. ಮತ್ತೆ ಸೇರಿದರೆ ಯಾರೂ ಬದಲಾಯಿಸದ ಪ್ರತಿಗಳನ್ನು ತೆಗೆದುಹಾಕಲಾಗುತ್ತದೆ.
- `extensions` ಅನ್ನು ಬಿಡುವುದು, ಬಿಡುತ್ತಿರುವ ಖಾತೆಯ ಫೋಲ್ಡರ್ ಮೂಲಕ ಪಾತ್‌ಗಳು ಹಾದುಹೋಗುತ್ತಿದ್ದಲ್ಲಿ, ಗುಂಪಿನ ಪ್ಲಗಿನ್ ಪಟ್ಟಿಗಳನ್ನು ಗುಂಪಿನ ಫೋಲ್ಡರ್‌ಗೆ ಸೂಚಿಸುವಂತೆಯೂ ಮಾಡುತ್ತದೆ; ಇತರ ಖಾತೆಗಳಿಗೆ, ಮರುಬರೆದ ಪಾತ್‌ಗಳು ಅದೇ ಪ್ಲಗಿನ್‌ಗಳಿಗೆ ಕರೆದೊಯ್ಯುತ್ತವೆ.

ಎರಡೂ ಕಡೆ ಬೇರೆ ಬೇರೆ ವಿಷಯದೊಂದಿಗೆ ಇರುವ ಒಂದೇ ಫೈಲ್ ಸಂಘರ್ಷವಾಗುತ್ತದೆ:

<!-- motion:share-conflict -->

`settings.json` ನಂತಹ ಒಂಟಿ ಫೈಲ್‌ಗಳಿಗೆ ನೀವು ಆಯ್ಕೆಮಾಡುತ್ತೀರಿ; ಫೋಲ್ಡರ್‌ಗಳ ಒಳಗೆ ಗುಂಪಿನ ಪ್ರತಿ ಉಳಿಯುತ್ತದೆ, ಮತ್ತು ಭಿನ್ನವಾಗಿರುವ ಫೈಲ್‌ಗಳನ್ನು ಯೋಜನೆ ಹೆಸರಿಸುತ್ತದೆ. ಆಯ್ಕೆಗಳು ಫೈಲ್ ಅನ್ನು ಅವಲಂಬಿಸಿವೆ; ಮೊದಲನೆಯದು ಡೀಫಾಲ್ಟ್:

| ಫೈಲ್ | ಆಯ್ಕೆಗಳು |
| --- | --- |
| `history.jsonl` | `merge by line`, `keep group`, `use mine` |
| ಇತರ `.json` ಫೈಲ್‌ಗಳು | `keep group`, `use mine`, `merge JSON` |
| ಬೇರೆ ಯಾವುದೇ ಫೈಲ್ | `keep group`, `use mine` |

`merge JSON` ಆಬ್ಜೆಕ್ಟ್‌ಗಳನ್ನು ಪುನರಾವರ್ತಿತವಾಗಿ ವಿಲೀನಗೊಳಿಸುತ್ತದೆ, ಅರೇಗಳನ್ನು ನಕಲುಗಳಿಲ್ಲದೆ ಜೋಡಿಸುತ್ತದೆ, ಮತ್ತು ಎರಡೂ ಕಡೆ ಒಂದೇ ಕೀಗೆ ಬೇರೆ ಮೌಲ್ಯ ಇದ್ದಾಗ ಗುಂಪಿನ ಮೌಲ್ಯವನ್ನು ಉಳಿಸಿಕೊಳ್ಳುತ್ತದೆ, ಹೀಗಾಗಿ ಇತರ ಖಾತೆಗಳಿಗೆ ಯಾವುದೇ ಬದಲಾವಣೆ ಕಾಣುವುದಿಲ್ಲ. `keep group` ಹೊರತುಪಡಿಸಿ ಪ್ರತಿ ಆಯ್ಕೆಯೂ ಮೊದಲು ಗುಂಪಿನ ಪ್ರತಿಯನ್ನು ಖಾತೆಯ `.ccam-backup/<time>/group/` ಗೆ ಉಳಿಸುತ್ತದೆ. ನಿಮ್ಮ ಸ್ವಂತ ಫೈಲ್ ಯಾವಾಗಲೂ ಬ್ಯಾಕಪ್‌ಗೆ ಹೋಗುತ್ತದೆ.

ಪ್ರತಿ ಆರಂಭದಲ್ಲಿ, ccam ಲೇಔಟ್‌ನ ಪ್ರತಿ ಪಾತ್ ಅನ್ನು ಖಾತೆಯ ಗುಂಪುಗಳೊಂದಿಗೆ `lstat` ಮತ್ತು `readlink` ಮಾತ್ರ ಬಳಸಿ ಹೋಲಿಸುತ್ತದೆ (`share.Check`). ಕಾಣೆಯಾದ ಲಿಂಕ್ ಅನ್ನು ಅಲ್ಲೇ ರಚಿಸಲಾಗುತ್ತದೆ. ಲಿಂಕ್ ಇರಬೇಕಾದ ಜಾಗದಲ್ಲಿ ನಿಜವಾದ ಫೈಲ್, ತಪ್ಪು ಸ್ಥಳಕ್ಕೆ ಲಿಂಕ್, ಅಥವಾ ಹಳೆಯ ಲಿಂಕ್ ಇದ್ದರೆ ಆರಂಭ ನಿಂತು `ccam doctor --fix` ಅನ್ನು ಸೂಚಿಸುತ್ತದೆ.

### ಮರುಹೆಸರಿಸುವುದು, ತೆಗೆದುಹಾಕುವುದು ಮತ್ತು ಹಳೆಯ ಸ್ವರೂಪ

- `ccam group rename` ಕಾನ್ಫಿಗ್ ಅನ್ನು ಮಾತ್ರ ಬದಲಾಯಿಸುತ್ತದೆ. ಫೋಲ್ಡರ್ ತನ್ನ ಹೆಸರನ್ನು ಉಳಿಸಿಕೊಳ್ಳುತ್ತದೆ ಮತ್ತು ಗುಂಪು ಅದನ್ನು `dir` ಆಗಿ ದಾಖಲಿಸುತ್ತದೆ, ಹೀಗಾಗಿ ಏನೂ ಸ್ಥಳಾಂತರವಾಗುವುದಿಲ್ಲ ಮತ್ತು ಏನೂ ಕಳೆದುಹೋಗಲು ಸಾಧ್ಯವಿಲ್ಲ.
- ನೀವು `--leave` ಸೇರಿಸದಿದ್ದರೆ, `ccam group remove` ಖಾತೆಗಳಿರುವ ಗುಂಪನ್ನು ನಿರಾಕರಿಸುತ್ತದೆ. ಆಗ ಪ್ರತಿ ಖಾತೆಯೂ ಒಂದು ಪ್ರತಿಯನ್ನು ಉಳಿಸಿಕೊಳ್ಳುತ್ತದೆ, ಮತ್ತು ಇನ್ನೊಂದು ಗುಂಪು ಬಳಸದಿದ್ದರೆ ಫೋಲ್ಡರ್ `~/.local/share/ccam/trash/` ಗೆ ಹೋಗುತ್ತದೆ.
- ಗುಂಪುಗಳಿಗಿಂತ ಮೊದಲು, `config.toml` ಪ್ರತಿ ಖಾತೆಗೆ ಒಂದು `[profile.share]` ಟೇಬಲ್ ಅನ್ನು ಸಂಗ್ರಹಿಸುತ್ತಿತ್ತು. ccam ಆ ಸ್ವರೂಪವನ್ನು ಏನನ್ನೂ ಸ್ಥಳಾಂತರಿಸದೆ ಗುಂಪುಗಳಾಗಿ ಓದುತ್ತದೆ. ಮೊದಲ ಉಳಿಸುವಿಕೆಯಲ್ಲಿ ಅದು ಹೊಸ ಸ್ವರೂಪವನ್ನು ಬರೆಯುತ್ತದೆ ಮತ್ತು ಹಳೆಯ ಫೈಲ್ ಅನ್ನು `config.toml.bak` ಆಗಿ ಇಡುತ್ತದೆ. ಅದೇ ಖಾತೆಗಳು ಹಂಚಿಕೊಳ್ಳುವ ಐಟಂಗಳು ಫೋಲ್ಡರ್‌ನ ಹೆಸರಿನ ಒಂದು ಗುಂಪಾಗುತ್ತವೆ; ಉಳಿದವಕ್ಕೆ `default-history` ನಂತಹ ಹೆಸರುಗಳು ಸಿಗುತ್ತವೆ ಮತ್ತು ಅವು ಅದೇ ಫೋಲ್ಡರ್ ಅನ್ನು ಬಳಸುತ್ತಲೇ ಇರುತ್ತವೆ.

### Windows ನಲ್ಲಿ

Windows Developer Mode (Settings > System > For developers) ನಲ್ಲಿ ಅಥವಾ ನಿರ್ವಾಹಕರಿಗೆ ಮಾತ್ರ ಸಿಂಬಾಲಿಕ್ ಲಿಂಕ್‌ಗಳನ್ನು ರಚಿಸುತ್ತದೆ. ಆ ಹಕ್ಕು ಇಲ್ಲದಿದ್ದರೆ, ಹಂಚಿಕೊಂಡ ಫೋಲ್ಡರ್ directory junction ಆಗುತ್ತದೆ, ಅದು Claude Code ಗೆ ಅದೇ ರೀತಿ ಕೆಲಸ ಮಾಡುತ್ತದೆ. ಹಂಚಿಕೊಂಡ ಫೈಲ್ (`settings.json`, `CLAUDE.md`, `history.jsonl`) ಸಿಂಬಾಲಿಕ್ ಲಿಂಕ್ ಮಾತ್ರ ಆಗಬಲ್ಲದು, ಹೀಗಾಗಿ ಅಂತಹ ಲಿಂಕ್ ಬೇಕಾದ ಗುಂಪಿನ ಬದಲಾವಣೆಯನ್ನು ಏನಾದರೂ ಸ್ಥಳಾಂತರವಾಗುವ ಮೊದಲೇ ನಿರಾಕರಿಸಲಾಗುತ್ತದೆ. ಇದೇ ಕಾರಣಕ್ಕೆ ಅಲ್ಲಿ ಮೊದಲ `ccam add` `mcp` ಮತ್ತು `extensions` ಮಾತ್ರ ಇರುವ `default` ಗುಂಪನ್ನು ರಚಿಸಿ ಅದನ್ನು ತಿಳಿಸುತ್ತದೆ, ಮತ್ತು ಸೆಟ್ಟಿಂಗ್‌ಗಳು, ಮೆಮೊರಿ ಅಥವಾ ಇತಿಹಾಸವನ್ನು ಹಂಚಿಕೊಳ್ಳುವ ಗುಂಪಿಗೆ `ccam add --group` ಅನ್ನು ನಿರಾಕರಿಸಲಾಗುತ್ತದೆ.

## ಸುರಕ್ಷತೆ ಮತ್ತು ವಿಶೇಷ ಸಂದರ್ಭಗಳು

- **ಚಾಲನೆಯಲ್ಲಿರುವ ಖಾತೆಗಳು.** ಬದಲಾವಣೆ ಸ್ಥಳಾಂತರಿಸುವ ಖಾತೆಗಳಲ್ಲಿ ಒಂದಾಗಿ Claude Code ಚಾಲನೆಯಲ್ಲಿರುವಾಗ, ಅದನ್ನು ccam ಆರಂಭಿಸಿರಲಿ ಇಲ್ಲದಿರಲಿ (ಸಾಮಾನ್ಯ `claude`, IDE, ಹಿನ್ನೆಲೆ ಸೆಷನ್‌ಗಳು), ಆ ಬದಲಾವಣೆಯನ್ನು ನಿರಾಕರಿಸಲಾಗುತ್ತದೆ, ಏಕೆಂದರೆ ಸೆಷನ್ ಆ ಫೈಲ್‌ಗಳಿಗೆ ಬರೆಯುತ್ತಲೇ ಇರುತ್ತದೆ. ಉಳಿಸುವ ಸ್ವಲ್ಪ ಮೊದಲು ಪರಿಶೀಲನೆಯನ್ನು ಮತ್ತೆ ಮಾಡಲಾಗುತ್ತದೆ. ಬಿಡುವುದು ಮತ್ತು ಸೇರುವುದು ಹೆಸರಿಸಿದ ಖಾತೆಯ ಮೇಲೆ ಮಾತ್ರ ಪರಿಣಾಮ ಬೀರುತ್ತವೆ; `extensions` ಅನ್ನು ಬಿಡುವುದು ಗುಂಪಿನ ಪ್ಲಗಿನ್ ಪಟ್ಟಿಗಳಲ್ಲಿನ ಪಾತ್‌ಗಳನ್ನೂ ಮರುಬರೆಯುತ್ತದೆ, ಇತರರಿಗೆ ಅವುಗಳ ಅರ್ಥವನ್ನು ಬದಲಾಯಿಸದೆ. `--dry-run` ಆಗಲೂ ಯೋಜನೆಯನ್ನು ಮುದ್ರಿಸುತ್ತದೆ.
- **ಬ್ಯಾಕಪ್‌ಗಳು.** ಪ್ರತಿ ಯೋಜನೆಗೆ ಖಾತೆ ಫೋಲ್ಡರ್‌ನಲ್ಲಿ ತನ್ನದೇ `.ccam-backup/<time>/` ಫೋಲ್ಡರ್ ಸಿಗುತ್ತದೆ. ccam ಅವುಗಳನ್ನು ಎಂದಿಗೂ ಅಳಿಸುವುದಿಲ್ಲ.
- **ನಿಮ್ಮ ಸ್ವಂತ ಲಿಂಕ್‌ಗಳು.** ಒಂದು ಪಾತ್ ಈಗಾಗಲೇ ನೀವು ಮಾಡಿದ ಲಿಂಕ್ ಆಗಿದ್ದರೆ, ಉದಾಹರಣೆಗೆ dotfiles ರೆಪಾಸಿಟರಿಗೆ, ಮತ್ತು ಗುಂಪು ಖಾಲಿಯಾಗಿದ್ದರೆ, ccam ಲಿಂಕ್‌ನ ಗುರಿಯನ್ನು ಗುಂಪಿಗೆ ನಕಲಿಸುತ್ತದೆ ಮತ್ತು ಲಿಂಕ್ ಅನ್ನೇ ಬ್ಯಾಕಪ್‌ಗೆ ಸ್ಥಳಾಂತರಿಸುತ್ತದೆ. ಗುರಿಯನ್ನು ಮುಟ್ಟುವುದಿಲ್ಲ.
- **ಇಂಪೋರ್ಟ್ ಮಾಡಿದ ಫೋಲ್ಡರ್‌ಗಳು.** `ccam import` ಮೂಲಕ ಇದ್ದಲ್ಲೇ ನೋಂದಾಯಿಸಿದ ಖಾತೆ (ಉದಾಹರಣೆಗೆ `~/.claude`) ಇದ್ದಲ್ಲೇ ಬದಲಾಗುತ್ತದೆ, ಹೀಗಾಗಿ ಸಾಮಾನ್ಯ `claude` ಕೂಡ ಬದಲಾವಣೆಯನ್ನು ನೋಡುತ್ತದೆ; ಯೋಜನೆ ಇದನ್ನು ತಿಳಿಸುತ್ತದೆ. ಅದು ಗುಂಪನ್ನು ಬಿಟ್ಟಾಗ, `--fresh` ಇದ್ದರೂ, ಯಾವಾಗಲೂ ಒಂದು ಪ್ರತಿಯನ್ನು ಉಳಿಸಿಕೊಳ್ಳುತ್ತದೆ, ಮತ್ತು ಖಾತೆಯನ್ನು ಮರೆಯುವ ಮೊದಲು `ccam remove` ಅದನ್ನು ಅದೇ ರೀತಿ ಅದರ ಗುಂಪುಗಳಿಂದ ಹೊರತರುತ್ತದೆ. ಅದು ಗುಂಪಿನಲ್ಲಿರುವವರೆಗೆ ಅದರ ಹಂಚಿಕೊಂಡ ಫೈಲ್‌ಗಳು ಗುಂಪಿನ ಫೋಲ್ಡರ್‌ನಲ್ಲಿ ಇರುತ್ತವೆ, ಆದ್ದರಿಂದ `~/.local/share/ccam` ಅನ್ನು ಅಳಿಸುವ ಮೊದಲು ಖಾತೆಯನ್ನು ತೆಗೆದುಹಾಕಿ (ಅಥವಾ ಗುಂಪುಗಳನ್ನು ಬಿಡಿ).
- **ಒಂದೇ ಫೋಲ್ಡರ್‌ನಲ್ಲಿ ಎರಡು ಖಾತೆಗಳು.** ಇತಿಹಾಸವನ್ನು ಹಂಚಿಕೊಳ್ಳುವ ಖಾತೆಗಳು ಒಂದೇ ಫೈಲ್‌ಗಳಿಗೆ ಬರೆಯುತ್ತವೆ. ಒಂದು ಈಗಾಗಲೇ ಚಾಲನೆಯಲ್ಲಿರುವ ಫೋಲ್ಡರ್‌ನಲ್ಲಿ ಎರಡನೆಯದು ಆರಂಭವಾದಾಗ, ccam ಎಚ್ಚರಿಸುತ್ತದೆ ಮತ್ತು ಕೇಳುತ್ತದೆ.
- **ಕೈಯಿಂದ ಮಾಡಿದ ಬದಲಾವಣೆಗಳು.** `members` ಖಾತೆಯಲ್ಲದ ಹೆಸರನ್ನು ಪಟ್ಟಿ ಮಾಡಿದರೆ, ccam ಅದನ್ನು ನಿರ್ಲಕ್ಷಿಸುತ್ತದೆ ಮತ್ತು `ccam doctor` ಅದನ್ನು ವರದಿ ಮಾಡುತ್ತದೆ. `local`, `on`, `off` ಮತ್ತು `none` ಹೆಸರುಗಳು ಗುಂಪಿನ ಹೆಸರುಗಳಾಗಲು ಸಾಧ್ಯವಿಲ್ಲ.
