`ccam next` ನೀವು ಹೆಸರಿಸದೆಯೇ ಇನ್ನೊಂದು ಖಾತೆಯಾಗಿ Claude Code ಅನ್ನು ತೆರೆಯುತ್ತದೆ. ಒಂದು ಖಾತೆ ತನ್ನ ಬಳಕೆಯ ಮಿತಿಯನ್ನು ತಲುಪಿದಾಗ ಇದನ್ನು ಬಳಸಿ. ಬದಲಾಯಿಸಲು ನಾಲ್ಕು ವಿಧಾನಗಳಿವೆ:

- ಸಾಮಾನ್ಯ `ccam next` ನೀವು ಕೊನೆಯದಾಗಿ ಬಳಸಿದ ಖಾತೆಯ ನಂತರದ ಖಾತೆಯನ್ನು ತೆಗೆದುಕೊಳ್ಳುತ್ತದೆ, ಮತ್ತು `--auto` ಹೆಚ್ಚು ಅವಕಾಶ ಇರುವ ಖಾತೆಯನ್ನು ತೆಗೆದುಕೊಳ್ಳುತ್ತದೆ. `--continue` ಈ ಫೋಲ್ಡರ್‌ನ ಕೊನೆಯ ಸಂಭಾಷಣೆಯನ್ನು, ಎರಡು ಖಾತೆಗಳು ಇತಿಹಾಸ ಹಂಚಿಕೊಳ್ಳಲಿ ಬಿಡಲಿ, ಹೊಸ ಖಾತೆಯಲ್ಲಿ ಮುಂದುವರಿಸುತ್ತದೆ.
- Claude Code ಒಳಗೆ, ಮಿತಿ ಒಂದು ಸೆಷನ್ ಅನ್ನು ನಿಲ್ಲಿಸಿದಾಗ [ccam ಪ್ಲಗಿನ್](#inside-claude-code) ನಿಮಗೆ ತಿಳಿಸುತ್ತದೆ, ಮತ್ತು `/ccam:switch` ಸಂಭಾಷಣೆಯನ್ನು ಮುಂದಕ್ಕೆ ಒಪ್ಪಿಸುತ್ತದೆ.
- `claude -p` ರನ್ ಮಾಡುವ ಸ್ಕ್ರಿಪ್ಟ್‌ಗಳಿಗಾಗಿ, `ccam --fallback` ಬದಲಾವಣೆಯನ್ನು ತಾನಾಗಿಯೇ ಮಾಡುತ್ತದೆ ([ಮಿತಿಯಲ್ಲಿ ಮತ್ತೆ ರನ್ ಮಾಡುವುದು](#run-again-at-the-limit) ನೋಡಿ).
- [`auto_switch`](#auto-switch) ಆನ್ ಮಾಡಿದ್ದರೆ (Linux ಮತ್ತು macOS), Claude Code ಮಿತಿಯಲ್ಲಿ ನಿಲ್ಲಿಸುವ ಇಂಟರ್‌ಆಕ್ಟಿವ್ ಸೆಷನ್ ಅನ್ನೂ ccam ಸ್ಥಳಾಂತರಿಸುತ್ತದೆ.

**Team ಮತ್ತು Enterprise ಸೀಟುಗಳು.** ಸ್ವಯಂಚಾಲಿತ ಖಾತೆ ಆಯ್ಕೆ (`ccam next`, `--fallback`, `ccam pick`, ಡ್ಯಾಶ್‌ಬೋರ್ಡ್‌ನ `n` ಮತ್ತು, ನೀವು ಆನ್ ಮಾಡಿದ ನಂತರ, [`auto_switch`](/features/next#auto-switch)) ಒಂದೇ Claude Team ಅಥವಾ Enterprise ಸಂಸ್ಥೆಯ ಸೀಟುಗಳ ನಡುವೆಯೂ ಬದಲಾಯಿಸುತ್ತದೆ, ಇದು Anthropic ನ ನಿಯಮಗಳನ್ನು ಉಲ್ಲಂಘಿಸಬಹುದು. ಇದನ್ನು ಅವಲಂಬಿಸುವ ಮೊದಲು [ಪದೇ ಪದೇ ಕೇಳುವ ಪ್ರಶ್ನೆಗಳನ್ನು](/docs/faq#am-i-allowed-to-use-several-claude-code-accounts) ಓದಿ ಮತ್ತು ನಿಮ್ಮ ಸಂಸ್ಥೆ ಹಾಗೂ Anthropic ಬಳಿ ವಿಚಾರಿಸಿ.

## ಬಳಕೆ

```sh
ccam next                       # the account after the one you used last
ccam next --auto                # the account with the most room
ccam next --continue            # continue this folder's last conversation on the next account
ccam next -c --auto             # both: the conversation, on the account with the most room
ccam next -c --brief            # a new conversation that starts from a summary of the last one
ccam next --auto --max-usage 80 # prefer accounts below 80%
ccam next --auto --strategy balance   # the most weekly quota left per day
ccam next --auto --cross-org    # also accounts of other organizations
ccam next --auto --wait         # nobody has room: wait for the first reset (up to 5 hours)
ccam next -c --auto -- --dangerously-skip-permissions   # claude's own options go after --
ccam --dry-run next --auto      # print the choice and the command, start nothing
```

```console
$ ccam --dry-run next --auto --continue
→ personal → work (12% of its 5 hours used, the least)
  continuing "Fix the flaky tests" (about 182k tokens); work does not share personal's history, so Claude Code copies it into work
CLAUDE_CONFIG_DIR=/home/you/.local/share/ccam/profiles/work CCAM_PROFILE=work /usr/local/bin/claude --resume /home/you/.local/share/ccam/profiles/personal/projects/-home-you-code-app/4f1c….jsonl --fork-session
```

ccam ಬದಲಾವಣೆಯನ್ನು ಸ್ಟ್ಯಾಂಡರ್ಡ್ ಎರರ್‌ನಲ್ಲಿ `→ <from> → <to>` ಎಂದು, `--auto` ಆಯ್ಕೆಯ ಕಾರಣದೊಂದಿಗೆ, ಮುದ್ರಿಸುತ್ತದೆ, ನಂತರ `ccam <name>` ಮಾಡುವಂತೆಯೇ ಹೊಸ ಖಾತೆಯಾಗಿ Claude Code ಅನ್ನು ಆರಂಭಿಸುತ್ತದೆ. `<from>` ನೀವು ಕೊನೆಯದಾಗಿ ಬಳಸಿದ ಖಾತೆ, ಅಥವಾ `--continue` ಇದ್ದರೆ ಸಂಭಾಷಣೆ ಸೇರಿರುವ ಖಾತೆ. `--` ನಂತರದ ಆರ್ಗ್ಯುಮೆಂಟ್‌ಗಳು ಬದಲಾವಣೆ ಇಲ್ಲದೆ `claude` ಗೆ ಹೋಗುತ್ತವೆ.

## ಆಯ್ಕೆಗಳು

| ಆಯ್ಕೆ | ಏನು ಮಾಡುತ್ತದೆ | ಡೀಫಾಲ್ಟ್ |
| --- | --- | --- |
| `--auto` | ಲಾಗಿನ್ ಆಗಿರುವ ಖಾತೆಯನ್ನು ಬಳಕೆಯ ಆಧಾರದಲ್ಲಿ ಆಯ್ಕೆಮಾಡುತ್ತದೆ (ಕೆಳಗೆ ನೋಡಿ); 100% ತಲುಪಿದ ಖಾತೆಗಳನ್ನು ಬಿಟ್ಟುಬಿಡುತ್ತದೆ | ಆಫ್ |
| `--max-usage <1-100>` | `--auto` ಜೊತೆ: ಈ ಬಳಕೆಗಿಂತ ಕೆಳಗಿರುವ ಖಾತೆಗಳಿಗೆ ಆದ್ಯತೆ | `auto_max_usage`, ಇಲ್ಲದಿದ್ದರೆ 100 |
| `--strategy headroom\|expiring\|balance` | `--auto` ಜೊತೆ: ಅತಿ ಕಡಿಮೆ 5 ಗಂಟೆಯ ಬಳಕೆ, ಬೇಗ ಬರುವ 5 ಗಂಟೆಯ ರೀಸೆಟ್ ಅಥವಾ ದಿನಕ್ಕೆ ಅತಿ ಹೆಚ್ಚು ಉಳಿದಿರುವ ವಾರದ ಕೋಟಾ | `auto_strategy`, ಇಲ್ಲದಿದ್ದರೆ `headroom` |
| `--cross-org` | `--auto` ಜೊತೆ: ಬೇರೆ ಸಂಸ್ಥೆಯ ಖಾತೆಗಳನ್ನೂ ಆಯ್ಕೆಮಾಡುತ್ತದೆ (ಕೆಳಗೆ ನೋಡಿ) | `cross_org`, ಇಲ್ಲದಿದ್ದರೆ ಆಫ್ |
| `--wait[=<duration>]` | `--auto` ಜೊತೆ: ಯಾವ ಖಾತೆಯಲ್ಲೂ ಅವಕಾಶ ಇಲ್ಲದಿದ್ದಾಗ, ಮೊದಲ ಖಾತೆ ರೀಸೆಟ್ ಆಗುವವರೆಗೆ, ಗರಿಷ್ಠ ಇಷ್ಟು ಸಮಯ ಕಾಯುತ್ತದೆ. ಮೌಲ್ಯ `=` ನಂತರ ಬರುತ್ತದೆ: `--wait 2h` ಅನ್ನು `--wait takes its value after '=': --wait=2h` ಎಂಬ ಸುಳಿವಿನೊಂದಿಗೆ ನಿರಾಕರಿಸಲಾಗುತ್ತದೆ | ಆಫ್; ಮೌಲ್ಯವಿಲ್ಲದೆ ನೀಡಿದರೆ `5h` |
| `-c`, `--continue` | ಈ ಫೋಲ್ಡರ್‌ನ ಕೊನೆಯ ಸಂಭಾಷಣೆಯನ್ನು ಹೊಸ ಖಾತೆಯಲ್ಲಿ ಮುಂದುವರಿಸುತ್ತದೆ (ಕೆಳಗೆ ನೋಡಿ) | ಆಫ್ |
| `--brief` | `--continue` ಜೊತೆ: ಹಿಂದಿನ ಸಂಭಾಷಣೆಯನ್ನು ಸಂಪೂರ್ಣವಾಗಿ ಮುಂದುವರಿಸುವ ಬದಲು, ccam ಅದರ ಬಗ್ಗೆ ಬರೆದ ಸಾರಾಂಶದಿಂದ ಹೊಸ ಖಾತೆಯಾಗಿ ಹೊಸ ಸಂಭಾಷಣೆಯನ್ನು ಆರಂಭಿಸುತ್ತದೆ ([ಕೆಳಗೆ ನೋಡಿ](#brief)) | ಆಫ್ |
| `-- <claude args>` | ccam ನ ಸ್ವಂತ ಆರ್ಗ್ಯುಮೆಂಟ್‌ಗಳ ನಂತರ `claude` ಗೆ ರವಾನಿಸುವ ಆರ್ಗ್ಯುಮೆಂಟ್‌ಗಳು | ಇಲ್ಲ |
| `--dry-run` | ಬೆಂಬಲಿತ: Claude Code ಅನ್ನು ಆರಂಭಿಸದೆ ಅಥವಾ ಆರಂಭವನ್ನು ದಾಖಲಿಸದೆ, `→ <from> → <to>` ಮತ್ತು ರನ್ ಮಾಡಲಿದ್ದ ಕಮಾಂಡ್ ಲೈನ್ ಅನ್ನು ಮುದ್ರಿಸುತ್ತದೆ | ಆಫ್ |

`--auto` ಮತ್ತು `--continue` ಒಟ್ಟಿಗೆ ಕೆಲಸ ಮಾಡುತ್ತವೆ. `--continue` ಇದ್ದಾಗ, `--resume` ಆರ್ಗ್ಯುಮೆಂಟ್‌ಗಳನ್ನು ನಿಮ್ಮ ಆರ್ಗ್ಯುಮೆಂಟ್‌ಗಳಿಗಿಂತ ಮೊದಲು ಇಡಲಾಗುತ್ತದೆ.

`--dangerously-skip-permissions` ಅಥವಾ `--model` ನಂತಹ Claude Code ನ ಸ್ವಂತ ಆಯ್ಕೆಗಳು `--` ನಂತರ ಬರುತ್ತವೆ. ಹೆಸರಿನ ನಂತರದ ಎಲ್ಲವನ್ನೂ ಮುಂದಕ್ಕೆ ಕಳುಹಿಸುವ `ccam <name>` ನಂತಲ್ಲದೆ, `ccam next` ತನ್ನ ಆರ್ಗ್ಯುಮೆಂಟ್‌ಗಳನ್ನು ತಾನೇ ಓದುತ್ತದೆ, ಆದ್ದರಿಂದ `--` ಇಲ್ಲದಿದ್ದರೆ ಅದು `ccam: unknown flag: --dangerously-skip-permissions` ನೊಂದಿಗೆ ನಿಲ್ಲುತ್ತದೆ.

## ಇದು ಹೇಗೆ ಕೆಲಸ ಮಾಡುತ್ತದೆ

ccam ಮೂಲಕ ಆಗುವ ಪ್ರತಿ ಆರಂಭವೂ ಸಮಯವನ್ನು `~/.local/state/ccam/last-used/<name>` ಗೆ ಬರೆಯುತ್ತದೆ. `ccam next` ಈ ಫೈಲ್‌ಗಳನ್ನು ಓದುತ್ತದೆ, ಯಾವ ಖಾತೆಗಳು ಲಾಗಿನ್ ಆಗಿವೆ ಎಂದು ಪರಿಶೀಲಿಸುತ್ತದೆ, ಮತ್ತು ಆಯ್ಕೆಮಾಡುತ್ತದೆ.

1. ccam `config.toml` ನಿಂದ ಪ್ರತಿ ಖಾತೆಗೆ ಒಂದು `next.Candidate` ರಚಿಸುತ್ತದೆ (`cli.candidates`): ಖಾತೆ, ಅದರ ಕೊನೆಯ ಆರಂಭದ ಸಮಯ (`launcher.LastUsed`) ಮತ್ತು ಅದಕ್ಕೆ ಕೆಲಸ ಮಾಡುವ ಲಾಗಿನ್ ಇದೆಯೇ (`creds.Has`: `.credentials.json` ನಲ್ಲಿ, ಅಥವಾ macOS ನಲ್ಲಿ Keychain ನಲ್ಲಿ, ಸಂಪೂರ್ಣವಾಗಿ ಅವಧಿ ಮುಗಿಯದ ಅಥವಾ Claude Code ತೆರವುಗೊಳಿಸದ Claude ಲಾಗಿನ್). ಬದಲಿಗೆ API ಕೀ ಬಳಸುವ ಫೋಲ್ಡರ್‌ಗೆ (Console ಲಾಗಿನ್, ಅಥವಾ `ccam add --api` ಮೂಲಕ ಸೇರಿಸಿದ ಖಾತೆ) ಪ್ಲಾನ್ ಮಿತಿಗಳಿಲ್ಲ ಮತ್ತು ಅದನ್ನು ಎಂದಿಗೂ ಆಯ್ಕೆಮಾಡಲಾಗುವುದಿಲ್ಲ.
2. `--auto` ಇಲ್ಲದಿದ್ದರೆ, ccam ಖಾತೆಗಳನ್ನು ಸ್ಲಾಟ್ ಸಂಖ್ಯೆಯ ಪ್ರಕಾರ ವಿಂಗಡಿಸಿ, ಇತ್ತೀಚೆಗೆ ಆರಂಭಿಸಿದ ಖಾತೆಯನ್ನು ಹುಡುಕುತ್ತದೆ (`next.Rotate`). ನೀವು ಬದಲಾಯಿಸುತ್ತಿರುವುದು ಆ ಖಾತೆಯಿಂದ. ಯಾವ ಖಾತೆಯನ್ನೂ ಇನ್ನೂ ಆರಂಭಿಸಿಲ್ಲದಿದ್ದರೆ, ಅದು ಅತಿ ಕಡಿಮೆ ಸ್ಲಾಟ್.
3. ಅಲ್ಲಿಂದ ಅದು ಸ್ಲಾಟ್ ಕ್ರಮದಲ್ಲಿ ಮುಂದೆ ಸಾಗುತ್ತದೆ, ಕೊನೆಯ ಸ್ಲಾಟ್‌ನಿಂದ ಮತ್ತೆ ಮೊದಲನೆಯದಕ್ಕೆ ಸುತ್ತಿ ಬರುತ್ತದೆ, ಮತ್ತು ಲಾಗಿನ್ ಆಗಿರುವ ಮೊದಲ ಖಾತೆಯನ್ನು ಹಿಂತಿರುಗಿಸುತ್ತದೆ.
4. ccam ಆಯ್ಕೆಯಾದ ಖಾತೆಯನ್ನು `ccam <name>` ಮಾಡುವಂತೆಯೇ ಸಿದ್ಧಪಡಿಸಿ ಆರಂಭಿಸುತ್ತದೆ (`launcher.LaunchWith`): ಖಾತೆಯ ಲಿಂಕ್‌ಗಳನ್ನು ಪರಿಶೀಲಿಸುತ್ತದೆ, MCP ಹಂಚಿಕೆಯನ್ನು ಅನ್ವಯಿಸುತ್ತದೆ, ಸೆಷನ್ ಅನ್ನು ನೋಂದಾಯಿಸುತ್ತದೆ ಮತ್ತು `syscall.Exec` ಮೂಲಕ ccam ನ ಜಾಗದಲ್ಲಿ `claude` ಅನ್ನು ತರುತ್ತದೆ.

ಈ ಸಾಗುವಿಕೆ ಕೊನೆಯದಾಗಿ ಬಳಸಿದ ಖಾತೆಯಿಂದ ಆರಂಭವಾಗಿ, ಅದರ ನಂತರ ಲಾಗಿನ್ ಆಗಿರುವ ಮೊದಲ ಖಾತೆಯಲ್ಲಿ ನಿಲ್ಲುತ್ತದೆ:

<!-- motion:next-rotate -->

`work` ಅನ್ನು ಇತ್ತೀಚೆಗೆ ಆರಂಭಿಸಲಾಗಿತ್ತು, ಹೀಗಾಗಿ ಸಾಗುವಿಕೆ ಅದರ ನಂತರದಿಂದ ಆರಂಭವಾಗುತ್ತದೆ. `side` ಗೆ ಲಾಗಿನ್ ಇಲ್ಲ, ಅದನ್ನು ಬಿಟ್ಟುಬಿಡಲಾಗುತ್ತದೆ, ಮತ್ತು `lab` ಆಯ್ಕೆಯಾಗುತ್ತದೆ. `lab` ಕೂಡ ಲಾಗ್ ಔಟ್ ಆಗಿದ್ದರೆ, ಸಾಗುವಿಕೆ ಸುತ್ತಿ `personal` ಗೆ ಬರುತ್ತಿತ್ತು (ಚಿತ್ರದಲ್ಲಿನ `% len`). ರೊಟೇಶನ್ ನೀವು ಆರಂಭಿಸಿದ ಖಾತೆಯನ್ನು ಎಂದಿಗೂ ಹಿಂತಿರುಗಿಸುವುದಿಲ್ಲ: ಲಾಗಿನ್ ಆಗಿರುವ ಇನ್ನೊಂದು ಖಾತೆ ಇಲ್ಲದಿದ್ದರೆ, ಅದು ದೋಷದೊಂದಿಗೆ ನಿಲ್ಲುತ್ತದೆ.

### --auto

`--auto` ಸ್ಲಾಟ್ ಕ್ರಮದ ಬದಲು ಬಳಕೆಯ ಆಧಾರದಲ್ಲಿ ನಿರ್ಧರಿಸುತ್ತದೆ. ccam ಲಾಗಿನ್ ಆಗಿರುವ ಖಾತೆಗಳನ್ನು ಉಳಿಸಿಕೊಳ್ಳುತ್ತದೆ, `ccam usage` ಮಾಡುವ ರೀತಿಯಲ್ಲೇ ಅವೆಲ್ಲದರ ಬಳಕೆಯನ್ನು ಒಂದೇ ಸಮಯದಲ್ಲಿ ಕೇಳುತ್ತದೆ (`Fetcher.FetchAll`), ಮತ್ತು ಕೆಳಗಿನ ನಿಯಮಗಳ ಪ್ರಕಾರ ಆಯ್ಕೆಮಾಡುತ್ತದೆ (`cli.pickAuto`, `usage.Policy.Choose()`):

<!-- motion:next-auto -->

ಖಾತೆಯನ್ನು ಅದರ 5 ಗಂಟೆಯ ಮತ್ತು ವಾರದ ಅವಧಿಗಳಿಂದ ನಿರ್ಣಯಿಸಲಾಗುತ್ತದೆ, ಮತ್ತು Claude Code ಗಾಗಿನ ಆರ್ಗ್ಯುಮೆಂಟ್‌ಗಳಲ್ಲಿ (`--` ನಂತರ) `--model` ಇದ್ದರೆ, ಆ ಮಾಡೆಲ್‌ನ ವಾರದ ಅವಧಿಯಿಂದಲೂ (ಹೆಸರಿನಲ್ಲಿ `opus`, `sonnet`, `haiku` ಅಥವಾ `fable`). ccam ಖಾತೆಗಳನ್ನು ಮೂರು ಹಂತಗಳಾಗಿ ವಿಂಗಡಿಸುತ್ತದೆ (`Policy.Choose()`):

1. **ಅವಕಾಶ ಇದೆ**: ಪ್ರತಿ ಅವಧಿಯೂ `auto_max_usage` (`config.toml`, ಡೀಫಾಲ್ಟ್ 100) ಗಿಂತ ಕೆಳಗಿದೆ. ಇವುಗಳಲ್ಲಿ strategy ಆಯ್ಕೆಮಾಡುತ್ತದೆ: `headroom` (ಡೀಫಾಲ್ಟ್) ಅತಿ ಕಡಿಮೆ 5 ಗಂಟೆಯ ಬಳಕೆಯನ್ನು ತೆಗೆದುಕೊಳ್ಳುತ್ತದೆ, `expiring` ಅತಿ ಬೇಗ ರೀಸೆಟ್ ಆಗುವ 5 ಗಂಟೆಯ ಅವಧಿಯನ್ನು ತೆಗೆದುಕೊಳ್ಳುತ್ತದೆ, ಹೀಗಾಗಿ ಅದರ ಉಳಿದ ಕೋಟಾ ಕಳೆದುಹೋಗುವ ಮೊದಲೇ ಬಳಕೆಯಾಗುತ್ತದೆ; `balance` ವಾರ ರೀಸೆಟ್ ಆಗುವವರೆಗೆ ದಿನಕ್ಕೆ ಅತಿ ಹೆಚ್ಚು ವಾರದ ಕೋಟಾ ಉಳಿದಿರುವ ಖಾತೆಯನ್ನು ತೆಗೆದುಕೊಳ್ಳುತ್ತದೆ, ರನ್ ಆಗುತ್ತಿರುವ ಪ್ರತಿ ccam ಸೆಷನ್ ಅನ್ನು ಅದರ ವಿರುದ್ಧ ಎಣಿಸಿ, ಹೀಗಾಗಿ ವಾರದ ಕೋಟಾ ಬಳಕೆಯಾಗದೆ ಉಳಿಯುವುದಿಲ್ಲ ಮತ್ತು ಸಮಾನಾಂತರ ಸೆಷನ್‌ಗಳು ಹಂಚಿಹೋಗುತ್ತವೆ.
2. **ಮಿತಿ ಮೀರಿದೆ**: 100% ಗಿಂತ ಕೆಳಗಿದೆ ಆದರೆ `auto_max_usage` ಅಥವಾ ಅದಕ್ಕಿಂತ ಹೆಚ್ಚಿದೆ. ಯಾವ ಖಾತೆಯಲ್ಲೂ ಅವಕಾಶ ಇಲ್ಲದಿದ್ದಾಗ ಮಾತ್ರ ಬಳಸಲಾಗುತ್ತದೆ; ಅತಿ ಕಡಿಮೆ 5 ಗಂಟೆಯ ಬಳಕೆ ಇರುವ ಖಾತೆ ಮೊದಲು ಬರುತ್ತದೆ.
3. **ತುಂಬಿದೆ**: ಒಂದು ಅವಧಿ 100% ನಲ್ಲಿದೆ, ಅಥವಾ 5 ಗಂಟೆಯ ಬಳಕೆ ತಿಳಿದಿಲ್ಲ. ಎಂದಿಗೂ ಆಯ್ಕೆಯಾಗುವುದಿಲ್ಲ.

Claude Code ಒಂದು ಅವಧಿಯಲ್ಲಿ ವಿನಂತಿಯನ್ನು ನಿರಾಕರಿಸಿದಾಗ, ಆ ಅವಧಿಯನ್ನು ಅದರ ರೀಸೆಟ್‌ವರೆಗೆ 100% ಎಂದು ಎಣಿಸಲಾಗುತ್ತದೆ: [ccam ಪ್ಲಗಿನ್](#inside-claude-code) ನ ಹುಕ್ ಅದನ್ನು ದಾಖಲಿಸುತ್ತದೆ (`~/.local/state/ccam/usage/<name>.limit.json`), ಉಳಿಸಿದ ಸಂಖ್ಯೆಗಳು ಏನೇ ಹೇಳಿದರೂ. ಹೀಗಾಗಿ ಈಗಷ್ಟೇ ತನ್ನ ಮಿತಿ ತಲುಪಿದ ಖಾತೆಯನ್ನು, ಅದರ ಸಂಖ್ಯೆಗಳು ಹಳೆಯದಾಗಿದ್ದರೂ, ರೀಸೆಟ್‌ಗೆ ಮೊದಲು ಮತ್ತೆ ಆಯ್ಕೆಮಾಡಲಾಗುವುದಿಲ್ಲ.

ಎಲ್ಲಾ ಖಾತೆಗಳ ಸೆಟ್ಟಿಂಗ್‌ಗಳು `config.toml` ನ ಮೇಲ್ಭಾಗದಲ್ಲಿ, ಮೊದಲ `[[group]]`, `[[profile]]` ಅಥವಾ `[[folder]]` ಗಿಂತ ಮೇಲೆ ಇರಬೇಕು. ಅವುಗಳಲ್ಲಿ ಒಂದರ ಕೆಳಗಿರುವ ಸೆಟ್ಟಿಂಗ್ ಆ ಟೇಬಲ್‌ಗೆ ಸೇರುತ್ತದೆ: ccam ಪ್ರತಿ ಆರಂಭದಲ್ಲೂ ಅದರ ಬಗ್ಗೆ ಎಚ್ಚರಿಸುತ್ತದೆ, ಮತ್ತು ಕಾನ್ಫಿಗ್ ಅನ್ನು ಉಳಿಸುವ ಕಮಾಂಡ್‌ಗಳು ಅದನ್ನು ಸ್ಥಳಾಂತರಿಸುವವರೆಗೆ ನಿರಾಕರಿಸುತ್ತವೆ.

```toml
# ~/.config/ccam/config.toml
auto_max_usage = 80        # keep 20% of each account for interactive work
auto_strategy = "expiring"
```

**ಸಂಸ್ಥೆಗಳು.** ಸ್ವಯಂಚಾಲಿತ ಆಯ್ಕೆಗಳು ನೀವು ಬಿಡುತ್ತಿರುವ ಖಾತೆಯ ಅದೇ ಬಗೆಯ ಖಾತೆಗಳಲ್ಲೇ ಉಳಿಯುತ್ತವೆ: ಅದೇ Team ಅಥವಾ Enterprise ಸಂಸ್ಥೆಯ ಸೀಟುಗಳು, ಅಥವಾ ವೈಯಕ್ತಿಕ ಪ್ಲಾನ್‌ಗಳು (Pro, Max), ಹೀಗಾಗಿ ಕಂಪನಿಯ ಖಾತೆಯ ಕೆಲಸ ಖಾಸಗಿ ಖಾತೆಯಲ್ಲಿ ಮುಂದುವರಿಯುವುದಿಲ್ಲ, ಅಥವಾ ಅದರ ವಿರುದ್ಧವಾಗಿಯೂ ಇಲ್ಲ. ccam ಪ್ರತಿ ಖಾತೆಯ ಸಂಸ್ಥೆಯನ್ನು ಅದರ ಲಾಗಿನ್‌ನಿಂದ ತಿಳಿಯುತ್ತದೆ (`ccam login` ಅದನ್ನು ದಾಖಲಿಸುತ್ತದೆ; ಹಳೆಯ ಲಾಗಿನ್‌ಗಳನ್ನು `.claude.json` ನಿಂದ ಓದಲಾಗುತ್ತದೆ); ಯಾವ ಖಾತೆಯ ಸಂಸ್ಥೆ ccam ಗೆ ತಿಳಿಯುವುದಿಲ್ಲವೋ ಅದನ್ನು ಯಾವುದೇ ಖಾತೆಯೊಂದಿಗೆ ಹೊಂದಿಸಬಹುದು. ಒಂದೇ Claude ಖಾತೆಗೆ ಲಾಗಿನ್ ಆಗಿರುವ ಎರಡು ಫೋಲ್ಡರ್‌ಗಳು ಅದರ ಮಿತಿಗಳನ್ನು ಹಂಚಿಕೊಳ್ಳುತ್ತವೆ, ಹೀಗಾಗಿ ಒಂದು ಇನ್ನೊಂದರ ಜಾಗವನ್ನು ಎಂದಿಗೂ ತೆಗೆದುಕೊಳ್ಳುವುದಿಲ್ಲ. `--cross-org`, ಅಥವಾ `config.toml` ನಲ್ಲಿ `cross_org = true`, ಸಂಸ್ಥೆಯ ನಿಯಮವನ್ನು ತೆಗೆದುಹಾಕುತ್ತದೆ.

ಯಾವುದನ್ನೂ ಆಯ್ಕೆಮಾಡಲಾಗದಿದ್ದಾಗ, ccam ಕೋಡ್ 75 (`EX_TEMPFAIL`) ನೊಂದಿಗೆ ನಿರ್ಗಮಿಸುತ್ತದೆ, ಹೀಗಾಗಿ ಸ್ಕ್ರಿಪ್ಟ್ "ನಂತರ ಪ್ರಯತ್ನಿಸಿ" ಎಂಬುದನ್ನು ವೈಫಲ್ಯದಿಂದ ಬೇರ್ಪಡಿಸಬಹುದು. `--wait` ಇದ್ದರೆ, ಅದು ಬದಲಿಗೆ ಮೊದಲ ತುಂಬಿದ ಖಾತೆಯ ತಡೆಯುತ್ತಿರುವ ಅವಧಿ ರೀಸೆಟ್ ಆಗುವವರೆಗೆ ಕಾಯುತ್ತದೆ (ರೀಸೆಟ್ ಸಮಯದ 30 ಸೆಕೆಂಡ್ ನಂತರ, ಎಂಡ್‌ಪಾಯಿಂಟ್ ಹೊಸ ಅವಧಿಯನ್ನು ತೋರಿಸಿದಾಗ), `ccam: no account has room; waiting until 15:10` ಎಂದು ಮುದ್ರಿಸುತ್ತದೆ, ಮತ್ತು ಮತ್ತೆ ಆಯ್ಕೆಮಾಡುತ್ತದೆ; ಯಾವ ಖಾತೆಯೂ ಯಾವಾಗ ರೀಸೆಟ್ ಆಗುತ್ತದೆ ಎಂದು ಹೇಳದಿದ್ದರೆ, 10 ನಿಮಿಷಗಳ ನಂತರ ಮತ್ತೆ ನೋಡುತ್ತದೆ. ಕಾಯುವಿಕೆ ಮುಗಿಯುವ ಮೊದಲು ಯಾವುದೂ ಖಾಲಿಯಾಗದಿದ್ದರೆ, ಅದು 75 ನೊಂದಿಗೆ ನಿರ್ಗಮಿಸುತ್ತದೆ.

ಹುಡುಕಾಟವು `ccam usage` ನ ನಿಯಮಗಳನ್ನು ಪಾಲಿಸುತ್ತದೆ: 60 ಸೆಕೆಂಡ್‌ಗಿಂತ ಕಡಿಮೆ ಹಳೆಯ ಸಂಖ್ಯೆಗಳನ್ನು ಮತ್ತೆ ಬಳಸಲಾಗುತ್ತದೆ, ಪ್ರತಿ ಖಾತೆಯ ಹುಡುಕಾಟ 3 ಸೆಕೆಂಡ್ ನಂತರ ಟೈಮ್‌ಔಟ್ ಆಗುತ್ತದೆ, ಉತ್ತರಿಸದ ಅಥವಾ ಆಕ್ಸೆಸ್ ಟೋಕನ್ ಅವಧಿ ಮುಗಿದ ಖಾತೆಯನ್ನು ಅದರ ಉಳಿಸಿದ ಸಂಖ್ಯೆಗಳಿಂದ ನಿರ್ಣಯಿಸಲಾಗುತ್ತದೆ, ಮತ್ತು ಮಿತಿ ದಾಖಲೆ ಅವುಗಳನ್ನು ಮೀರಿಸುತ್ತದೆ. ರೀಸೆಟ್ ಸಮಯ ಕಳೆದಿರುವ ಉಳಿಸಿದ ಅವಧಿಯನ್ನು 0% ಎಂದು ಎಣಿಸಲಾಗುತ್ತದೆ, ಹೀಗಾಗಿ ನಂತರ ಅವಧಿ ರೀಸೆಟ್ ಆಗಿರುವ ಖಾತೆಯನ್ನು ಕಡೆಗಣಿಸಲಾಗುವುದಿಲ್ಲ. `--auto` ಎಂದಿಗೂ ಟೋಕನ್‌ಗಳನ್ನು ನವೀಕರಿಸುವುದಿಲ್ಲ. ಸಾಮಾನ್ಯ ರೊಟೇಶನ್‌ಗಿಂತ ಭಿನ್ನವಾಗಿ, ನೀವು ಕೊನೆಯದಾಗಿ ಬಳಸಿದ ಖಾತೆಯಲ್ಲೇ ಇನ್ನೂ ಹೆಚ್ಚು ಅವಕಾಶವಿದ್ದರೆ `--auto` ಅದನ್ನೇ ಆಯ್ಕೆಮಾಡಬಹುದು.

### --continue

1. ccam ಪ್ರತಿ ಖಾತೆಯಲ್ಲೂ ಈ ಫೋಲ್ಡರ್‌ನ ಕೊನೆಯ ಸಂಭಾಷಣೆಗಾಗಿ ಹುಡುಕುತ್ತದೆ: `projects/<folder>/` ನಲ್ಲಿನ `<session>.jsonl` ಫೈಲ್‌ಗಳಲ್ಲಿ, ಅತಿ ಹೊಸ ಪ್ರಾಂಪ್ಟ್ ಅಥವಾ ಉತ್ತರ ಇರುವುದು (ಫೋಲ್ಡರ್ ಹೆಸರು ಎಂದರೆ ಲಿಂಕ್‌ಗಳನ್ನು ಪರಿಹರಿಸಿದ ಕೆಲಸದ ಫೋಲ್ಡರ್, ಅಕ್ಷರ ಅಥವಾ ಅಂಕಿ ಅಲ್ಲದ ಪ್ರತಿ ಅಕ್ಷರವನ್ನೂ `-` ಆಗಿ ಬದಲಾಯಿಸಿ, Claude Code ಹೆಸರಿಸುವಂತೆಯೇ). ಅಂತಹದು ಇಲ್ಲದ ಸೆಷನ್‌ಗಳನ್ನು, ಉದಾಹರಣೆಗೆ `/mcp`, `/usage` ಅಥವಾ `/status` ಮಾತ್ರ ರನ್ ಮಾಡಿದ ಸೆಷನ್ ಅಥವಾ ಖಾಲಿ ಫೈಲ್ ಅನ್ನು, ಬಿಟ್ಟುಬಿಡಲಾಗುತ್ತದೆ. ಒಂದು ಸೆಷನ್ ಟಿಪ್ಪಣಿ ಬಿಟ್ಟಿದ್ದರೆ (ಬಳಕೆಯ ಮಿತಿ ಅಥವಾ `/ccam:switch`, ಕೆಳಗೆ ನೋಡಿ) ಮತ್ತು ಅದರ ನಂತರ 2 ನಿಮಿಷಕ್ಕಿಂತ ಹೆಚ್ಚು ಸಮಯದ ಬಳಿಕ ಯಾವ ಸಂಭಾಷಣೆಯಲ್ಲೂ ಪ್ರಾಂಪ್ಟ್ ಅಥವಾ ಉತ್ತರ ಇಲ್ಲದಿದ್ದರೆ, ಬದಲಿಗೆ ಅದೇ ಸೆಷನ್ ಅನ್ನು ಬಳಸಲಾಗುತ್ತದೆ; `/exit` ನಲ್ಲಿ Claude Code ಬರೆಯುವ ಸಾಲುಗಳನ್ನು ಎಣಿಸಲಾಗುವುದಿಲ್ಲ.
2. ಅದು ಸೇರಿರುವ ಖಾತೆಯಿಂದ ನೀವು ಬದಲಾಯಿಸುತ್ತೀರಿ, ಮತ್ತು ಹೊಸ ಖಾತೆಯನ್ನು ಮೇಲಿನಂತೆ, ಅದೇ ಸಂಸ್ಥೆಯೊಳಗೆ, ಆಯ್ಕೆಮಾಡಲಾಗುತ್ತದೆ. ಹಲವು ಖಾತೆಗಳು ಆ ಇತಿಹಾಸವನ್ನು ಹಂಚಿಕೊಂಡಾಗ, ಸಂಭಾಷಣೆಯನ್ನು ಕೊನೆಯದಾಗಿ ತಾನು ರನ್ ಮಾಡಿದೆ ಎಂದು ಯಾವ ಖಾತೆಯ `.claude.json` ಹೇಳುತ್ತದೋ (`lastSessionId`) ಆ ಖಾತೆಗೆ ಅದು ಸೇರುತ್ತದೆ, ಇಲ್ಲದಿದ್ದರೆ ಕೊನೆಯದಾಗಿ ಬಳಸಿದ ಖಾತೆಗೆ.
3. ಹೊಸ ಖಾತೆ ಆ ಇತಿಹಾಸವನ್ನು ಹಂಚಿಕೊಂಡರೆ (ಅದೇ ಗುಂಪಿನ ಫೋಲ್ಡರ್), ccam `claude --resume <session id>` ಆರಂಭಿಸುತ್ತದೆ, ಅಂದರೆ ಅದೇ ಸಂಭಾಷಣೆ (`--continue` ಆದರೆ ಫೋಲ್ಡರ್‌ನಲ್ಲಿ ಯಾವುದು ಅತಿ ಹೊಸದೋ ಅದನ್ನು ತೆರೆಯುತ್ತಿತ್ತು).
4. ಇಲ್ಲದಿದ್ದರೆ ಅದು `claude --resume <the conversation's file> --fork-session` ಆರಂಭಿಸುತ್ತದೆ: Claude Code ಇಡೀ ಸಂಭಾಷಣೆಯನ್ನು, ಹೊಸ ಸೆಷನ್ ID ಅಡಿಯಲ್ಲಿ, ಹೊಸ ಖಾತೆಯ ಸ್ವಂತ ಇತಿಹಾಸಕ್ಕೆ ನಕಲಿಸುತ್ತದೆ, ಮತ್ತು ಮೂಲ ಸಂಭಾಷಣೆ ಇದ್ದಂತೆಯೇ ಉಳಿಯುತ್ತದೆ. ಅಲ್ಲಿಂದ ಮುಂದೆ ಹೊಸ ಖಾತೆಯ `--continue` ಅದನ್ನು ಕಂಡುಕೊಳ್ಳುತ್ತದೆ.

ಸಂಭಾಷಣೆ ಎಷ್ಟು ದೊಡ್ಡದು ಎಂದು ccam ಹೇಳುತ್ತದೆ: ಹೊಸ ಖಾತೆ ತನ್ನ ಮೊದಲ ಉತ್ತರದೊಂದಿಗೆ ಅದೆಲ್ಲವನ್ನೂ ಮತ್ತೆ ಓದುತ್ತದೆ. ಪ್ರಾಂಪ್ಟ್ ಕ್ಯಾಶ್‌ಗಳನ್ನು ಸಂಸ್ಥೆಗಳ ನಡುವೆ ಎಂದಿಗೂ ಹಂಚಿಕೊಳ್ಳಲಾಗುವುದಿಲ್ಲ, ಮತ್ತು ಪ್ರತಿ ವೈಯಕ್ತಿಕ ಪ್ಲಾನ್ ತನ್ನದೇ ಸಂಸ್ಥೆ, ಹೀಗಾಗಿ ಎರಡು ಖಾತೆಗಳು ಬೇರೆ ಬೇರೆ ಸಂಸ್ಥೆಗಳಿಗೆ ಸೇರಿದಾಗ ccam `prompt caches are not shared between organizations, so the first reply reads it all again` ಎಂದು ಸೇರಿಸುತ್ತದೆ. ಹೊಸ ಖಾತೆ ಸೈನ್ ಇನ್ ಆಗಿರದ MCP ಸರ್ವರ್‌ಗಳಿಗೆ ಹಳೆಯ ಖಾತೆ ಸೈನ್ ಇನ್ ಆಗಿದ್ದರೆ, ccam ಅವುಗಳನ್ನು ಹೆಸರಿಸುತ್ತದೆ: `work is not signed in to MCP servers that personal is signed in to: linear (sign in with /mcp there; sign-ins are not shared)`. ಗುಂಪಿನಲ್ಲಿ `history` ಹಂಚಿಕೊಳ್ಳುವುದು ನಕಲನ್ನು ತಪ್ಪಿಸುತ್ತದೆ, ಒಂದೇ ಸಂಭಾಷಣೆಯನ್ನು ಉಳಿಸುತ್ತದೆ, ಮತ್ತು `/rewind` ಕೋಡ್ ಅನ್ನು ಮರುಸ್ಥಾಪಿಸುವ ಚೆಕ್‌ಪಾಯಿಂಟ್‌ಗಳನ್ನೂ (`file-history/`) ಹಂಚಿಕೊಳ್ಳುತ್ತದೆ.

### --brief

`--continue` ಸಂಪೂರ್ಣ ಸಂಭಾಷಣೆಯನ್ನು ಮುಂದುವರಿಸುತ್ತದೆ, ಮತ್ತು ಹೊಸ ಖಾತೆ ತನ್ನ ಮೊದಲ ಉತ್ತರದೊಂದಿಗೆ ಅದೆಲ್ಲವನ್ನೂ ಮತ್ತೆ ಓದುತ್ತದೆ. `ccam next --continue --brief` ಬದಲಿಗೆ ಹೊಸ ಸಂಭಾಷಣೆಯನ್ನು ಆರಂಭಿಸುತ್ತದೆ, ಮಾಡೆಲ್ ಅನ್ನು ಕೇಳದೆ ccam ಹಳೆಯ ಸಂಭಾಷಣೆಯ ಬಗ್ಗೆ ಬರೆಯುವ ಸಾರಾಂಶದಿಂದ:

```console
$ ccam next --auto --continue --brief
→ personal → work (12% of its 5 hours used, the least)
  starting a new conversation with ccam's summary of "Fix the flaky tests" instead of resuming it (about 182k tokens)
  summary (6k characters): /home/you/.local/state/ccam/brief/4f1c….md
```

ಸಾರಾಂಶದಲ್ಲಿ ಇವು ಇರುತ್ತವೆ, ಈ ಕ್ರಮದಲ್ಲಿ, ಮತ್ತು ಹೇಳಲು ಏನಾದರೂ ಇರುವಲ್ಲಿ ಮಾತ್ರ:

1. ಸಂಭಾಷಣೆಯ ಶೀರ್ಷಿಕೆ;
2. ಅದರ ಟ್ರಾನ್ಸ್‌ಕ್ರಿಪ್ಟ್‌ನ ಪಾತ್, ವಿವರ ಬೇಕಾದಾಗ Claude ಅದರಲ್ಲಿ ಹುಡುಕಲು;
3. ನಿಮ್ಮ ಮೊದಲ ವಿನಂತಿ, ನಾಲ್ಕಕ್ಕಿಂತ ಹೆಚ್ಚು ವಿನಂತಿಗಳಿದ್ದಾಗ;
4. Claude Code ಕೊನೆಯ ಬಾರಿ ಸಂಭಾಷಣೆಯನ್ನು compact ಮಾಡಿದಾಗ ಬರೆದ ಸಾರಾಂಶ;
5. ನಿಮ್ಮ ಕೊನೆಯ ನಾಲ್ಕು ವಿನಂತಿಗಳು, `!` ಕಮಾಂಡ್‌ಗಳು ಮತ್ತು ಸ್ಲ್ಯಾಶ್ ಕಮಾಂಡ್‌ಗಳನ್ನು ನೀವು ಟೈಪ್ ಮಾಡಿದಂತೆಯೇ;
6. Claude ನ ಕೊನೆಯ ಉತ್ತರ;
7. todo ಪಟ್ಟಿ;
8. Claude ಕೊನೆಯದಾಗಿ ಬದಲಾಯಿಸಿದ 10 ಫೈಲ್‌ಗಳು;
9. ಫೋಲ್ಡರ್‌ನ `git status --short --branch`, 800 ಅಕ್ಷರಗಳವರೆಗೆ.

todo ಪಟ್ಟಿ ಗರಿಷ್ಠ 10 ಐಟಂಗಳನ್ನು ಇಡುತ್ತದೆ: ಮುಗಿದ ಐಟಂಗಳನ್ನು ಮೊದಲು ತೆಗೆದುಹಾಕಲಾಗುತ್ತದೆ, ನಂತರ ಅತ್ಯಂತ ದೂರದ ಮುಂದಿನ ಹಂತಗಳನ್ನು, ಹೀಗಾಗಿ ಈಗಿನ ಹಂತ ಮತ್ತು ಅದರ ನಂತರದ ಹಂತಗಳು ಉಳಿಯುತ್ತವೆ. ಉದ್ದವಾದ ಭಾಗಗಳನ್ನು ಮಧ್ಯದಲ್ಲಿ ಕತ್ತರಿಸಲಾಗುತ್ತದೆ, ಮತ್ತು ಸಂಪೂರ್ಣ ಸಾರಾಂಶ 16,000 ಅಕ್ಷರಗಳೊಳಗೆ ಇರುತ್ತದೆ.

ccam ಅದನ್ನು `~/.local/state/ccam/brief/<session>.md` ಆಗಿ, ನೀವು ಮಾತ್ರ ಓದಬಹುದಾದಂತೆ ಉಳಿಸುತ್ತದೆ, ಮತ್ತು ಮುಂದಿನ `--brief` 7 ದಿನಗಳಿಗಿಂತ ಹಳೆಯ ಸಾರಾಂಶಗಳನ್ನು ತೆಗೆದುಹಾಕುತ್ತದೆ. Claude Code ಒಂದು ಪ್ರಾಂಪ್ಟ್‌ನೊಂದಿಗೆ ಆರಂಭವಾಗುತ್ತದೆ, ಮತ್ತು ಅದು ಉಲ್ಲೇಖಿಸುವ ಫೈಲ್ ಅನ್ನು ಲಗತ್ತಿಸುತ್ತದೆ: `Read @"<the summary>", the summary ccam wrote of my earlier Claude Code conversation, which is not loaded here. Then reply with one or two sentences on where the work stands, and wait for my next message.` `--` ನಂತರ ನೀವು ನೀಡುವ ಪ್ರಾಂಪ್ಟ್ ಕೊನೆಯ ವಾಕ್ಯದ ಜಾಗವನ್ನು ತೆಗೆದುಕೊಳ್ಳುತ್ತದೆ (`Then: <your prompt>`), ಮತ್ತು `--` ನಂತರದ ನಿಮ್ಮ ಇತರ ಆಯ್ಕೆಗಳು ಅದರ ನಂತರ ಬರುತ್ತವೆ.

Claude Code ಒಂದು ಉಲ್ಲೇಖವನ್ನು `"` ನಲ್ಲಿ ಮುಗಿಸುತ್ತದೆ ಮತ್ತು `#` ನಲ್ಲಿ ಕತ್ತರಿಸುತ್ತದೆ, ಹೀಗಾಗಿ ಸಾರಾಂಶದ ಪಾತ್‌ನಲ್ಲಿ ಇವುಗಳಲ್ಲಿ ಯಾವುದಾದರೂ ಇದ್ದಾಗ, ccam ಅದನ್ನು ಕೆಲಸದ ಫೋಲ್ಡರ್‌ಗೆ ಸಾಪೇಕ್ಷವಾದ ಪಾತ್ ಮೂಲಕ ಉಲ್ಲೇಖಿಸುತ್ತದೆ; ಆ ಪಾತ್‌ನಲ್ಲೂ ಒಂದು ಇದ್ದಾಗ, ಪ್ರಾಂಪ್ಟ್ ಫೈಲ್ ಅನ್ನು ಹೆಸರಿಸುತ್ತದೆ, ಮತ್ತು Claude ಅದನ್ನು ತನ್ನ Read ಟೂಲ್‌ನಿಂದ ಓದುತ್ತದೆ, ಫೈಲ್ ಕೆಲಸದ ಫೋಲ್ಡರ್‌ಗಳ ಹೊರಗೆ ಇರುವುದರಿಂದ ಅದು ಮೊದಲು ಅನುಮತಿ ಕೇಳುತ್ತದೆ (Manual ಮೋಡ್‌ನಲ್ಲಿನ `-p` ರನ್‌ನಲ್ಲಿ, Claude Code ಓದುವಿಕೆಯನ್ನು ನಿರಾಕರಿಸುತ್ತದೆ ಮತ್ತು Claude ಸಾರಾಂಶವಿಲ್ಲದೆ ಮುಂದುವರಿಯುತ್ತದೆ).

`ccam --dry-run next --continue --brief` ಸಾರಾಂಶವನ್ನು ಮುದ್ರಿಸುತ್ತದೆ ಮತ್ತು ಏನನ್ನೂ ಉಳಿಸುವುದಿಲ್ಲ. ಹಳೆಯ ಸಂಭಾಷಣೆ ಹಾಗೆಯೇ ಇರುತ್ತದೆ, ಮತ್ತು ಹೊಸ ಸಂಭಾಷಣೆಗೆ ಸಾರಾಂಶ ಹೇಳುವುದು ಮಾತ್ರ ತಿಳಿದಿರುತ್ತದೆ, ಹೀಗಾಗಿ ನೀವು ಅಲ್ಲಿಗೆ ಹೇಗೆ ತಲುಪಿದಿರಿ ಎಂಬ ಪ್ರತಿ ವಿವರಕ್ಕಿಂತ ಕೆಲಸವೇ ಹೆಚ್ಚು ಮುಖ್ಯವಾದಾಗ `--brief` ಬಳಸಿ. `--continue` ಇಲ್ಲದೆ, ccam `--brief works with --continue` ನೊಂದಿಗೆ ನಿಲ್ಲುತ್ತದೆ; ಸಂಭಾಷಣೆಯನ್ನು ಓದಲು ಸಾಧ್ಯವಾಗದಿದ್ದಾಗ ಅಥವಾ ಅದರಲ್ಲಿ ಸಾರಾಂಶ ಮಾಡಲು ಏನೂ ಸಿಗದಿದ್ದಾಗ, ಅದು ನಿಂತು, `--brief` ಇಲ್ಲದ `ccam next --continue` ಅದನ್ನು ಸಂಪೂರ್ಣವಾಗಿ ಮುಂದುವರಿಸುತ್ತದೆ ಎಂದು ಹೇಳುತ್ತದೆ. [ರಿಲೇ](#relay) ಮತ್ತು [`auto_switch`](#auto-switch) ಯಾವಾಗಲೂ ಸಂಪೂರ್ಣ ಸಂಭಾಷಣೆಯನ್ನು ಮುಂದುವರಿಸುತ್ತವೆ. Claude Code ನ ಸ್ವಂತ `--brief` ಆಯ್ಕೆ, ಅದರ ಇತರ ಆಯ್ಕೆಗಳಂತೆ, `--` ನಂತರ ಬರುತ್ತದೆ.

## Claude Code ಒಳಗೆ

[ccam ಪ್ಲಗಿನ್](/docs/install#claude-code-plugin) ಎರಡು ಹುಕ್‌ಗಳನ್ನು ಸೇರಿಸುತ್ತದೆ (Claude Code 2.1.78 ಅಥವಾ ನಂತರದ್ದು):

- ಒಂದು ಸರದಿ ಬಳಕೆಯ ಮಿತಿಯಲ್ಲಿ ನಿಂತಾಗ, ಅದು ಸಂಭಾಷಣೆಯನ್ನು ಗುರುತಿಸಿಟ್ಟು, ಅದನ್ನು ಬೆಂಬಲಿಸುವ ಟರ್ಮಿನಲ್‌ಗಳಲ್ಲಿ (iTerm2, WezTerm, Windows Terminal, kitty, Ghostty) ಡೆಸ್ಕ್‌ಟಾಪ್ ಅಧಿಸೂಚನೆಯನ್ನು ತೋರಿಸುತ್ತದೆ: ``ccam: work hit its 5-hour limit (resets 3:45pm). `ccam next --continue` continues the conversation on another account.``

  Claude Code ಬಳಕೆಯ ಮಿತಿ ಎಂದು ಪರಿಗಣಿಸುವ ಪ್ರತಿ ಸಂದೇಶವೂ ಅದಕ್ಕೆ ತಿಳಿದಿದೆ: 5 ಗಂಟೆಯ, ವಾರದ, ಸಾಮಾನ್ಯ ಮತ್ತು ಮಾಡೆಲ್ ಮಿತಿಗಳು (`You've hit your session limit`, `You've hit your limit`, ಮಾಡೆಲ್‌ನ ಪಾಲಿಗೆ `You've reached your …`), ಬಳಕೆಯ ಕ್ರೆಡಿಟ್‌ಗಳು ಮತ್ತು ಖರ್ಚಿನ ಮಿತಿಗಳು, ಮತ್ತು ಖಾತೆಯನ್ನು ನಿಲ್ಲಿಸಿದ ಸಂಸ್ಥೆ.

  Claude Code ನಿರಾಕರಿಸಿದ ವಿನಂತಿಯನ್ನು ಸಂಭಾಷಣೆಗೆ ಬರೆದಿದ್ದಾಗ, ಹುಕ್ ತುಂಬಿದ ಅವಧಿಯನ್ನೂ ಅದರ ರೀಸೆಟ್‌ವರೆಗೆ ದಾಖಲಿಸುತ್ತದೆ ([ಮಿತಿ ದಾಖಲೆ](/features/usage#the-limit-record)), ಸಂಸ್ಥೆ ಹೊಂದಿಸಿದ ನಿಲುಗಡೆಯನ್ನು ಹೊರತುಪಡಿಸಿ, ಏಕೆಂದರೆ ಅದರ ನಿರ್ವಾಹಕರು ಅದನ್ನು ಯಾವಾಗ ಬೇಕಾದರೂ ತೆಗೆದುಹಾಕಬಹುದು. ಸರ್ವರ್‌ನ ಅಲ್ಪಾವಧಿ ನಿಯಂತ್ರಣ ಅಥವಾ API ಕೀಯ rate limit ಬಳಕೆಯ ಮಿತಿಯಲ್ಲ, ಅವನ್ನು ಹಾಗೆಯೇ ಬಿಡಲಾಗುತ್ತದೆ, ಮತ್ತು subagent ನ ನಿಲುಗಡೆ ಹಾಗೂ ಯಾರೂ ಗಮನಿಸದ ಸೆಷನ್‌ಗಳನ್ನೂ (`-p` ರನ್‌ಗಳು ಮತ್ತು ಹಿನ್ನೆಲೆ ಸೆಷನ್‌ಗಳು) ಹಾಗೆಯೇ ಬಿಡಲಾಗುತ್ತದೆ.

  Claude Code 2.1.234 ಮತ್ತು ನಂತರದ್ದು ಸೆಷನ್‌ನಲ್ಲೇ ಕಾದು 5 ಗಂಟೆಯ ರೀಸೆಟ್ ನಂತರ ತಾನಾಗಿಯೇ ಮುಂದುವರಿಯುತ್ತದೆ; ಅಧಿಸೂಚನೆ ಬದಲಿಗೆ ಖಾತೆ ಬದಲಾಯಿಸುವ ಆಯ್ಕೆಯನ್ನು ನಿಮಗೆ ನೀಡುತ್ತದೆ, ಮತ್ತು [`auto_switch`](#auto-switch) ಆನ್ ಆಗಿದ್ದರೆ (Linux ಮತ್ತು macOS), ಇನ್ನೊಂದು ಖಾತೆಯಲ್ಲಿ ಅವಕಾಶ ಇದ್ದಾಗ ccam ನಿಮಗಾಗಿ ಬದಲಾಯಿಸುತ್ತದೆ. ಬೇರೆ ಯಾವ ಖಾತೆಯೂ ಕೆಲಸ ವಹಿಸಿಕೊಳ್ಳಲು ಸಾಧ್ಯವಿಲ್ಲದಿದ್ದಾಗ, ಅಂದರೆ ಬೇರೆ ಯಾವ ಖಾತೆಯೂ ಅದೇ Team ಅಥವಾ Enterprise ಸಂಸ್ಥೆಗೆ ಸೇರಿಲ್ಲದಿದ್ದಾಗ, ಅಥವಾ ಯಾವುದೂ ಇನ್ನೊಂದು ವೈಯಕ್ತಿಕ ಪ್ಲಾನ್ ಅಲ್ಲದಿದ್ದಾಗ (`cross_org` ಆನ್ ಆಗಿದ್ದರೆ, ಬೇರೆ ಯಾವುದೇ Claude ಖಾತೆ ವಹಿಸಿಕೊಳ್ಳಬಹುದು), ಅಧಿಸೂಚನೆ ಬದಲಿಗೆ `You have no other personal plans, so ccam cannot move this conversation.` ಅಥವಾ `You have no other accounts in Acme, so ccam cannot move this conversation.` ಎಂದು ಕೊನೆಗೊಳ್ಳುತ್ತದೆ.
- `/ccam:switch [account]` ಸಂಭಾಷಣೆಯನ್ನು ಗುರುತಿಸಿಟ್ಟು, ಯಾವುದೇ ವಿನಂತಿ ಮಾಡುವ ಮೊದಲೇ ಸರದಿಯನ್ನು ಮುಗಿಸುತ್ತದೆ: `/exit` ಟೈಪ್ ಮಾಡಿ, ನಂತರ ನೀವು ಹೆಸರಿಸಿದ ಖಾತೆಯಲ್ಲಿ (ಅಥವಾ ಮುಂದಿನ ಖಾತೆಯಲ್ಲಿ) ಅದನ್ನು ಮುಂದುವರಿಸಲು `ccam next --continue` ರನ್ ಮಾಡಿ. ಇನ್ನೂ ಸಂಭಾಷಣೆ ಇಲ್ಲದ ಸೆಷನ್‌ನಲ್ಲಿ, ಮುಂದುವರಿಸಲು ಏನೂ ಇಲ್ಲ ಎಂದು ಅದು ಹೇಳುತ್ತದೆ.

ಟಿಪ್ಪಣಿ `~/.local/state/ccam/handoff/<account>/<session>.json` ನಲ್ಲಿ ಇರುತ್ತದೆ, ಪ್ರತಿ ಸೆಷನ್‌ಗೆ ಒಂದು ಫೈಲ್, ಹೀಗಾಗಿ ಒಂದೇ ಖಾತೆಯ ಎರಡು ಸೆಷನ್‌ಗಳು ಎಂದಿಗೂ ಪರಸ್ಪರರದನ್ನು ತಿದ್ದಿ ಬರೆಯುವುದಿಲ್ಲ. ಅದನ್ನು 12 ಗಂಟೆಗಳ ಕಾಲ ಇಡಲಾಗುತ್ತದೆ ಮತ್ತು ಮುಂದಿನ ಸೆಷನ್ ಆರಂಭವಾಗಲಿರುವಾಗ ಒಮ್ಮೆ ಮಾತ್ರ ಬಳಸಲಾಗುತ್ತದೆ; ಆರಂಭ ವಿಫಲವಾದರೆ ಅದು ಮುಂದಿನ ಪ್ರಯತ್ನಕ್ಕಾಗಿ ಉಳಿಯುತ್ತದೆ. ಅದು ಸೆಷನ್ ಆರಂಭವಾದ ಫೋಲ್ಡರ್‌ಗೆ ಸೇರಿರುತ್ತದೆ, Claude Code ನ ಶೆಲ್‌ನಲ್ಲಿ `cd` ಮಾಡಿದ ನಂತರವೂ. `ccam rename` ಅದರಲ್ಲಿನ ಹೆಸರುಗಳನ್ನು ಅಪ್‌ಡೇಟ್ ಮಾಡುತ್ತದೆ; ಅದರಲ್ಲಿ ಹೆಸರಿಸಿದ ಖಾತೆಯನ್ನು ನಂತರ ತೆಗೆದುಹಾಕಿದ್ದರೆ, ccam ಅದನ್ನು ತಿಳಿಸಿ ಎಂದಿನಂತೆ ಆಯ್ಕೆಮಾಡುತ್ತದೆ.

### ರಿಲೇ

`config.toml` ನ ಮೇಲ್ಭಾಗದಲ್ಲಿ `relay = true` ಇದ್ದರೆ, ccam ತನ್ನ ಜಾಗವನ್ನು Claude Code ಗೆ ಬಿಟ್ಟುಕೊಡುವ ಬದಲು ಇಂಟರ್‌ಆಕ್ಟಿವ್ ಸೆಷನ್‌ಗಳ ಜೊತೆಯಲ್ಲೇ ರನ್ ಆಗುತ್ತಿರುತ್ತದೆ, ಮತ್ತು `/ccam:switch` ನಂತರ ಆ ಸೆಷನ್‌ನ ಸಂಭಾಷಣೆಯನ್ನು ತಾನಾಗಿಯೇ ಮುಂದುವರಿಸುತ್ತದೆ (ಬೇರೆ ಸೆಷನ್ ಬಿಟ್ಟ ಟಿಪ್ಪಣಿಯ ಮೇಲೆ ಅದು ಕ್ರಮ ಕೈಗೊಳ್ಳುವುದಿಲ್ಲ): ಹುಕ್ Claude Code ಅನ್ನು ಮುಗಿಸುತ್ತದೆ, ಮತ್ತು ccam ಆ ಸೆಷನ್‌ನ ಟಿಪ್ಪಣಿಯೊಂದಿಗೆ `ccam next --continue` ರನ್ ಮಾಡುತ್ತದೆ. ಖಾತೆಯನ್ನು ಹೆಸರಿಸದಿದ್ದರೆ, ಸಂಭಾಷಣೆಯ ಮಾಡೆಲ್ ಅನ್ನೂ ಎಣಿಸಿ, ಹೆಚ್ಚು ಅವಕಾಶ ಇರುವ ಖಾತೆಯನ್ನು ಅದು ತೆಗೆದುಕೊಳ್ಳುತ್ತದೆ. Windows ನಲ್ಲಿ ಹುಕ್ Claude Code ಅನ್ನು ಮುಗಿಸಲಾರದು: `/exit` ಟೈಪ್ ಮಾಡಿ, ಮತ್ತು ccam ಸಂಭಾಷಣೆಯನ್ನು ಮುಂದುವರಿಸುತ್ತದೆ. ಇದಕ್ಕೆ ಪ್ರತಿ ಸೆಷನ್‌ಗೂ ಕಾಯುತ್ತಿರುವ ಒಂದು ccam ಪ್ರೊಸೆಸ್ ಬೇಕಾಗುತ್ತದೆ, ಅದಕ್ಕಾಗಿಯೇ ಇದು ಡೀಫಾಲ್ಟ್ ಆಗಿ ಆಫ್.

ಸಂಭಾಷಣೆಯನ್ನು ಮುಂದುವರಿಸುವುದು (resume) ಮರುಸ್ಥಾಪಿಸದಿರುವುದನ್ನು ರಿಲೇ ಮಾಡಿದ ಸೆಷನ್ ಉಳಿಸಿಕೊಳ್ಳುತ್ತದೆ: `--add-dir`, `--mcp-config`, ಟೂಲ್ ಪಟ್ಟಿಗಳು, `--settings`, `--plugin-dir` ಮತ್ತು ಸಿಸ್ಟಮ್ ಪ್ರಾಂಪ್ಟ್ ಆಯ್ಕೆಗಳಂತಹ ಆಯ್ಕೆಗಳು, ಸಂಭಾಷಣೆಯ ಅನುಮತಿ ಮೋಡ್ ಮತ್ತು ಸೆಷನ್‌ನ effort ಮಟ್ಟ. `--model`, `--name` ಮತ್ತು `--agent` ಅನ್ನು Claude Code ತಾನೇ ಸಂಭಾಷಣೆಯಿಂದ ಮರುಸ್ಥಾಪಿಸುತ್ತದೆ. ಉಳಿದ ಯಾವುದನ್ನಾದರೂ (`--worktree`, `--debug`, `--remote-control`, ccam ಗೆ ತಿಳಿಯದ ಆಯ್ಕೆಗಳು) `ccam: not carried over: …` ನಲ್ಲಿ ಹೆಸರಿಸಲಾಗುತ್ತದೆ. ಈ ಬದಲಾವಣೆ ಎಂದಿಗೂ ಹಂಚಿಕೆಯ ಇತಿಹಾಸದ ಪ್ರಶ್ನೆಯನ್ನು ಕೇಳುವುದಿಲ್ಲ, ಮತ್ತು ಅದು ನಡೆಯುತ್ತಿರುವಾಗ ನೀವು ಟೈಪ್ ಮಾಡಿದ್ದನ್ನು ಕೈಬಿಡಲಾಗುತ್ತದೆ.

`/ccam:switch` ಕೇಳಿದ ರೀತಿಯಲ್ಲೇ Claude Code ಮುಗಿದಾಗ ಮಾತ್ರ ರಿಲೇ ಸಂಭಾಷಣೆಯನ್ನು ಮುಂದುವರಿಸುತ್ತದೆ: ನೀವು ಮೊದಲೇ `/exit` ಟೈಪ್ ಮಾಡಿದಾಗ, ಅದು ಮುಗಿಯುತ್ತಿರುವಾಗ Ctrl+C ಒತ್ತಿದಾಗ, ಅಥವಾ ccam ಗೆ hangup ಅಥವಾ ಬೇರೆ signal ಬಂದಾಗ ಅಲ್ಲ, ಮತ್ತು ಟರ್ಮಿನಲ್ ಇಲ್ಲವಾದಾಗಲೂ ಅಲ್ಲ. ಆಗ ಟಿಪ್ಪಣಿ ಉಳಿಯುತ್ತದೆ, ಮತ್ತು `ccam next --continue` ನಂತರ ಅದನ್ನು ಮುಂದುವರಿಸುತ್ತದೆ. ccam ನ ಹಳೆಯ ಆವೃತ್ತಿಯ ರಿಲೇ ಅಡಿಯಲ್ಲಿ ಆರಂಭವಾದ ಸೆಷನ್ ಅನ್ನು, ಅಥವಾ ಯಾರೂ ಗಮನಿಸದ ಸೆಷನ್ ಅನ್ನು (`-p` ರನ್‌ಗಳು ಮತ್ತು ಹಿನ್ನೆಲೆ ಸೆಷನ್‌ಗಳು), ಹುಕ್ ಮುಗಿಸುವುದಿಲ್ಲ; ಬದಲಿಗೆ ಅದಕ್ಕೆ `/exit` ಸಂದೇಶ ಸಿಗುತ್ತದೆ. `claude remote-control` ರಿಲೇ ಇಲ್ಲದೆ ರನ್ ಆಗುತ್ತದೆ.

### `auto_switch`

`config.toml` ನ ಮೇಲ್ಭಾಗದಲ್ಲಿ `auto_switch = true` ಇದ್ದರೆ (Linux ಮತ್ತು macOS), Claude Code ಸೆಷನ್ ಅನ್ನು ಬಳಕೆಯ ಮಿತಿಯಲ್ಲಿ ನಿಲ್ಲಿಸಿದಾಗ ccam ಅದನ್ನು ತಾನಾಗಿಯೇ ಇನ್ನೊಂದು ಖಾತೆಗೆ ಸ್ಥಳಾಂತರಿಸುತ್ತದೆ: ಪ್ಲಗಿನ್‌ನ ಹುಕ್ ಅವಕಾಶ ಇರುವ ಇನ್ನೊಂದು ಖಾತೆಯನ್ನು ಆಯ್ಕೆಮಾಡಿ Claude Code ಅನ್ನು ಮುಗಿಸುತ್ತದೆ, ಮತ್ತು ಸೆಷನ್‌ನ ಜೊತೆಯಲ್ಲೇ ರನ್ ಆಗುತ್ತಿರುವ ccam, `/ccam:switch` ನಂತರ [ರಿಲೇ](#relay) ಮಾಡುವಂತೆಯೇ, ಸಂಭಾಷಣೆಯನ್ನು ಅಲ್ಲಿ ಮುಂದುವರಿಸುತ್ತದೆ. ಇದು ಡೀಫಾಲ್ಟ್ ಆಗಿ ಆಫ್, ಮತ್ತು ಪ್ರಾಯೋಗಿಕ.

```toml
# ~/.config/ccam/config.toml
auto_switch = true   # Linux and macOS; turns the relay on too
```

```console
ccam: personal hit its 5-hour limit; continuing this conversation as side
→ personal → side
  continuing "Fix the flaky tests" (about 182k tokens); prompt caches are not shared between organizations, so the first reply reads it all again; side does not share personal's history, so Claude Code copies it into side
```

ಇವೆಲ್ಲವೂ ನಿಜವಾಗಿದ್ದಾಗ ಮಾತ್ರ ccam ಸೆಷನ್ ಅನ್ನು ಸ್ಥಳಾಂತರಿಸುತ್ತದೆ:

1. ccam ಅದನ್ನು ಟರ್ಮಿನಲ್‌ನಲ್ಲಿ ಆರಂಭಿಸಿ ಅದರ ಜೊತೆಯಲ್ಲೇ ರನ್ ಆಗುತ್ತಿದೆ. `auto_switch` [ರಿಲೇ](#relay) ಅನ್ನು ಆನ್ ಮಾಡುತ್ತದೆ, ಹೀಗಾಗಿ ಇದನ್ನು ಹೊಂದಿಸಿದ ನಂತರ ನೀವು ಆರಂಭಿಸುವ ಇಂಟರ್‌ಆಕ್ಟಿವ್ ಸೆಷನ್‌ಗಳಿಗೆ ಇದು ನಿಜ. ಅದಕ್ಕೂ ಮೊದಲು, ಅಥವಾ ಹಳೆಯ ccam ಅಡಿಯಲ್ಲಿ, ಆರಂಭವಾದ ಸೆಷನ್‌ಗೆ ``This session started before auto_switch was on or under an older ccam, so ccam cannot move it: type /exit, then run `ccam next --continue`.`` ಎಂದು ಕೊನೆಗೊಳ್ಳುವ ಅಧಿಸೂಚನೆ ಸಿಗುತ್ತದೆ. ಯಾರೂ ಗಮನಿಸದ ಸೆಷನ್‌ಗಳು (`-p` ರನ್‌ಗಳು ಮತ್ತು ಹಿನ್ನೆಲೆ ಸೆಷನ್‌ಗಳು), `claude remote-control` ಮತ್ತು ccam ಇಲ್ಲದೆ ಆರಂಭಿಸಿದ Claude Code ಅನ್ನು ಎಂದಿಗೂ ಸ್ಥಳಾಂತರಿಸಲಾಗುವುದಿಲ್ಲ.
2. ಖಾತೆಯಲ್ಲಿ [ccam ಪ್ಲಗಿನ್](/docs/install#claude-code-plugin) ಆನ್ ಆಗಿದೆ ಮತ್ತು ಅದು Claude Code 2.1.214 ಅಥವಾ ನಂತರದ ಆವೃತ್ತಿಯನ್ನು ರನ್ ಮಾಡುತ್ತದೆ, ಅದು ತನ್ನ ಪ್ರೊಸೆಸ್ ID ಯನ್ನು ಹುಕ್‌ಗೆ ನೀಡುತ್ತದೆ (`CLAUDE_PID`).
3. ಆ ಖಾತೆಯ 5 ಗಂಟೆಯ, ವಾರದ, Opus ಅಥವಾ Sonnet ಮಿತಿಗಾಗಿ, Claude Code ನಿರಾಕರಿಸಿದ ವಿನಂತಿಯನ್ನು ಅದು ರೀಸೆಟ್ ಆಗುವ ಸಮಯದೊಂದಿಗೆ ಸಂಭಾಷಣೆಗೆ ಬರೆದಿದೆ. ಖರ್ಚಿನ ಮಿತಿ, ಬಳಕೆಯ ಕ್ರೆಡಿಟ್‌ಗಳು ಮುಗಿಯುವುದು, ಸಂಸ್ಥೆ ಹೊಂದಿಸಿದ ನಿಲುಗಡೆ, Fable ಪಾಲು (`You've reached your Fable limit.`), ಸರ್ವರ್‌ನ ನಿಯಂತ್ರಣ, API ಕೀಯ rate limit ಮತ್ತು subagent ನ ನಿಲುಗಡೆ ಎಂದಿಗೂ ಸೆಷನ್ ಅನ್ನು ಸ್ಥಳಾಂತರಿಸುವುದಿಲ್ಲ.
4. ಖಾತೆಯ ಪ್ಲಾನ್ ccam ಗೆ ತಿಳಿದಿದೆ, ಅದರ `.claude.json` ನಿಂದ ಅಥವಾ `ccam login` ದಾಖಲಿಸಿದ್ದರಿಂದ. ಇಲ್ಲದಿದ್ದರೆ, ಅಧಿಸೂಚನೆ `ccam does not know personal's plan, so auto_switch leaves this session.` ಎಂದು ಕೊನೆಗೊಳ್ಳುತ್ತದೆ.
5. ಸೆಷನ್ Remote Control ಗೆ ಸಂಪರ್ಕಗೊಂಡಿಲ್ಲ. ಇನ್ನೊಂದು ಖಾತೆಯಾಗಿ ಅದು ನೀವು ಅದನ್ನು ನಿಯಂತ್ರಿಸುವ ಆ್ಯಪ್‌ಗೆ ಮತ್ತೆ ಸಂಪರ್ಕಗೊಳ್ಳುವುದಿಲ್ಲ, ಹೀಗಾಗಿ ಅದು ಇದ್ದಲ್ಲೇ ಉಳಿಯುತ್ತದೆ, ಮತ್ತು ಅಧಿಸೂಚನೆ ಅದನ್ನು ತಿಳಿಸುತ್ತದೆ.
6. ಮಿತಿ ಈಗಿನಿಂದ 15 ನಿಮಿಷಗಳಿಗಿಂತ ಹೆಚ್ಚು ಸಮಯದ ನಂತರ ರೀಸೆಟ್ ಆಗುತ್ತದೆ. ಇದಕ್ಕಿಂತ ಕಡಿಮೆ ಕಾಯುವಿಕೆಗೆ ccam ಸೆಷನ್ ಅನ್ನು Claude Code ಗೆ ಬಿಡುತ್ತದೆ: `ccam: personal hit its 5-hour limit, which resets in 9m; ccam leaves this session to wait for it.`
7. ಮಿತಿಯ ನಂತರ ನೀವು ಯಾವುದೇ ಪ್ರಾಂಪ್ಟ್ ಟೈಪ್ ಮಾಡಿಲ್ಲ.
8. ಇನ್ನೊಂದು ಖಾತೆಯಲ್ಲಿ ಅವಕಾಶ ಇದೆ. ccam [`--auto`](#auto) ಮಾಡುವಂತೆಯೇ ಆಯ್ಕೆಮಾಡುತ್ತದೆ (`auto_max_usage`, `auto_strategy`, ಸಂಭಾಷಣೆಯ ಮಾಡೆಲ್), ನೀವು ಬಿಡುವ ಖಾತೆಯ ಅದೇ ಬಗೆಯ ಖಾತೆಗಳ ನಡುವೆ: ಅದೇ Team ಅಥವಾ Enterprise ಸಂಸ್ಥೆಯ ಇನ್ನೊಂದು ಸೀಟು, ಅಥವಾ ಇನ್ನೊಂದು ವೈಯಕ್ತಿಕ ಪ್ಲಾನ್ (Pro, Max). `cross_org` ಮತ್ತು `--cross-org` ಇಲ್ಲಿ ಅನ್ವಯಿಸುವುದಿಲ್ಲ. ಖಾತೆಯು:
   - Claude Code ನವೀಕರಿಸಬಲ್ಲ ಲಾಗಿನ್‌ನೊಂದಿಗೆ ಲಾಗಿನ್ ಆಗಿರಬೇಕು;
   - ಅದೇ Claude ಖಾತೆಗೆ ಲಾಗಿನ್ ಆಗಿರಬಾರದು;
   - API ಕೀ ಬಳಸಬಾರದು;
   - ccam ಗೆ ತಿಳಿದಿರುವ ಪ್ಲಾನ್ ಹೊಂದಿರಬೇಕು;
   - ccam ನ ಸ್ವಂತ ಬಳಕೆ ಹುಡುಕಾಟ ತೋರಿಸುವ ಮಟ್ಟಿಗೆ, ಬಳಕೆಯ ಕ್ರೆಡಿಟ್‌ಗಳು ಆನ್ ಆಗಿರಬಾರದು;
   - Claude Code ನಲ್ಲಿ ಈ ಫೋಲ್ಡರ್ ಅನ್ನು ನಂಬಿರಬೇಕು (trust).

   ಈ ಕೊನೆಯ ಎರಡು ಷರತ್ತುಗಳು ಅವಕಾಶ ಇರುವ ಪ್ರತಿ ಖಾತೆಯನ್ನೂ ಹೊರಗಿಟ್ಟಾಗ, ಅಧಿಸೂಚನೆ ಅವುಗಳನ್ನು ಹೆಸರಿಸುತ್ತದೆ: `side has not trusted this folder yet, so the conversation was not moved there. Open the folder once as side to allow it.` ಅಥವಾ `side has room but its usage credits are on, so auto_switch did not move the conversation there; /ccam:switch side moves it.` [ಮಿತಿ ದಾಖಲೆ](/features/usage#the-limit-record) ಇರುವ ಅವಧಿಯನ್ನು ತುಂಬಿದೆ ಎಂದು ಎಣಿಸಲಾಗುತ್ತದೆ, ಮತ್ತು ಕೊನೆಯ 2 ನಿಮಿಷಗಳಲ್ಲಿ ಇನ್ನೊಂದು ಸೆಷನ್ ಸ್ಥಳಾಂತರಗೊಂಡ ಖಾತೆ ಉಳಿದವುಗಳ ನಂತರ ಬರುತ್ತದೆ. ಆಯ್ಕೆಯನ್ನು ಸುಮಾರು 6 ಸೆಕೆಂಡ್‌ಗಳೊಳಗೆ ಮಾಡಬೇಕು; ಬಳಕೆ ಹುಡುಕಾಟಗಳು ಇದಕ್ಕಿಂತ ಹೆಚ್ಚು ಸಮಯ ತೆಗೆದುಕೊಂಡರೆ, ಸೆಷನ್ ಇದ್ದಲ್ಲೇ ಉಳಿಯುತ್ತದೆ. `usage_source = "claude"` ಇದ್ದಾಗ, `auto_switch` ಉಳಿಸಿದ ಸಂಖ್ಯೆಗಳಿಂದ ಮಾತ್ರ ನಿರ್ಧರಿಸುತ್ತದೆ, ಮತ್ತು ಬಳಕೆಯ ಕ್ರೆಡಿಟ್‌ಗಳು ಆನ್ ಆಗಿವೆಯೇ ಎಂಬುದನ್ನು ccam Claude Code ನ ಹುಡುಕಾಟದಿಂದಾಗಲಿ ಸ್ಟೇಟಸ್ ಲೈನ್‌ನಿಂದಾಗಲಿ ತಿಳಿಯಲಾರದು, ಹೀಗಾಗಿ ಅವು ಆಫ್ ಎಂದು ಭಾವಿಸುತ್ತದೆ.

ನಂತರ ಹುಕ್ Claude Code ಅನ್ನು ಮುಗಿಸುತ್ತದೆ, ಮತ್ತು ಅದರ ಜೊತೆಯಲ್ಲೇ ರನ್ ಆಗುತ್ತಿರುವ ccam, ಬೆಂಬಲಿಸುವ ಟರ್ಮಿನಲ್‌ಗಳಲ್ಲಿ ಡೆಸ್ಕ್‌ಟಾಪ್ ಅಧಿಸೂಚನೆಯನ್ನು ತೋರಿಸುತ್ತದೆ, ಉದಾಹರಣೆಗೆ `ccam: personal hit its 5-hour limit (resets 3:29am). Moving this conversation to side (12% of its 5 hours used, the least).`. ಅದು ಮೇಲಿನ ಉದಾಹರಣೆ ಔಟ್‌ಪುಟ್‌ನ ಮೊದಲ ಸಾಲನ್ನು ಮುದ್ರಿಸಿ, ಆಯ್ಕೆಮಾಡಿದ ಖಾತೆಯಾಗಿ ಆ ಸೆಷನ್‌ಗಾಗಿ `ccam next --continue` ರನ್ ಮಾಡುತ್ತದೆ; ಅದು ತನ್ನ ಉಳಿದ ಎರಡು ಸಾಲುಗಳನ್ನು ಮುದ್ರಿಸಿ, [ರಿಲೇ](#relay) ಮಾಡುವಂತೆಯೇ, ಸೆಷನ್‌ನ ಆಯ್ಕೆಗಳು, ಅನುಮತಿ ಮೋಡ್ ಮತ್ತು effort ಮಟ್ಟದೊಂದಿಗೆ Claude Code ಅನ್ನು ಆರಂಭಿಸುತ್ತದೆ. ಹೊಸ ಸೆಷನ್‌ನ ಮೊದಲ ಸಂದೇಶ ಈ ಸ್ಥಿರ ಪಠ್ಯ, ಇದೊಂದೇ ccam ನಿಮ್ಮ ಪರವಾಗಿ ಕಳುಹಿಸುವ ವಿಷಯ (`/ccam:switch` ನಂತರದ ಸ್ಥಳಾಂತರ ಏನನ್ನೂ ಕಳುಹಿಸುವುದಿಲ್ಲ):

```text
Your usage limit was reached and ccam moved this conversation to another account. Continue the task you were working on when the limit was reached; do not repeat work that is already complete.
```

ಆ ಖಾತೆಯೂ ತನ್ನ ಮಿತಿ ತಲುಪಿದರೆ, ಅಲ್ಲಿಯೂ ಇದೇ ನಡೆಯುತ್ತದೆ. ಮಿತಿ ದಾಖಲೆಗಳು ಸರಪಳಿಯು ಒಂದು ಖಾತೆಗೆ ಅದರ ರೀಸೆಟ್‌ಗೆ ಮೊದಲು ಮರಳದಂತೆ ತಡೆಯುತ್ತವೆ, ಹೀಗಾಗಿ ಎಲ್ಲಾ ಖಾತೆಗಳು ತುಂಬಿದಾಗ ಸೆಷನ್ ಕೊನೆಯ ಖಾತೆಯಲ್ಲೇ ಉಳಿಯುತ್ತದೆ.

ಬೇರೆ ಯಾವ ಖಾತೆಯಲ್ಲೂ ಅವಕಾಶ ಇಲ್ಲದಿದ್ದಾಗ, ಏನೂ ಸ್ಥಳಾಂತರಗೊಳ್ಳುವುದಿಲ್ಲ: Claude Code ಎಂದಿನಂತೆ ಮಿತಿಯನ್ನು ನಿರ್ವಹಿಸುತ್ತದೆ, ಸೆಷನ್‌ನಲ್ಲಿ ಕಾಯುತ್ತದೆ ಅಥವಾ ತನ್ನ ಆಯ್ಕೆಗಳನ್ನು ನೀಡುತ್ತದೆ, ಮತ್ತು ಯಾವ ಖಾತೆ ಮೊದಲು ಮುಕ್ತವಾಗುತ್ತದೆ ಎಂದು ಅಧಿಸೂಚನೆ ಹೇಳುತ್ತದೆ, ಉದಾಹರಣೆಗೆ `ccam: personal hit its 5-hour limit (resets 3:29am). None of your other personal plans has room now; side frees up first, at 12:30am. Claude Code waits for personal here; /ccam:switch side after 12:30am moves it sooner.` ಸೀಟುಗಳಿಗೆ ಅದು `None of your other accounts in Acme has room now` ಎಂದು ಹೇಳುತ್ತದೆ. ಆರಂಭವಾದ ಸ್ಥಳಾಂತರವನ್ನು ನಿಲ್ಲಿಸಲು, Claude Code ಮುಚ್ಚುತ್ತಿರುವಾಗ Ctrl+C ಒತ್ತಿ: ``ccam: switch cancelled. Run `ccam next --continue` later to continue the conversation.``

ಸ್ಥಳಾಂತರಕ್ಕೆ ವೆಚ್ಚಗಳಿವೆ. Claude Code ಮರುಆರಂಭವಾಗುತ್ತದೆ, ಅದಕ್ಕೆ ಕೆಲವು ಸೆಕೆಂಡ್‌ಗಳು ಬೇಕು, ಮತ್ತು Claude ಆರಂಭಿಸಿದ ಹಿನ್ನೆಲೆ ಶೆಲ್‌ಗಳು, dev ಸರ್ವರ್‌ಗಳು ಮತ್ತು ಏಜೆಂಟ್‌ಗಳು ಹಳೆಯ ಸೆಷನ್‌ನೊಂದಿಗೆ ನಿಲ್ಲುತ್ತವೆ. [`--continue`](#continue) ನಂತೆಯೇ ಹೊಸ ಖಾತೆ ತನ್ನ ಮೊದಲ ಉತ್ತರದೊಂದಿಗೆ ಸಂಪೂರ್ಣ ಸಂಭಾಷಣೆಯನ್ನು ಮತ್ತೆ ಓದುತ್ತದೆ, ಮತ್ತು ಅದು ಎಷ್ಟು ದೊಡ್ಡದು ಎಂದು ccam ಹೇಳುತ್ತದೆ; ಸ್ಥಳಾಂತರ ಎಂದಿಗೂ [`--brief`](#brief) ಬಳಸುವುದಿಲ್ಲ.

`auto_switch` Claude Code ಮಿತಿಯನ್ನು ವರದಿ ಮಾಡುವ ಮೊದಲು ಎಂದಿಗೂ ಬದಲಾಯಿಸುವುದಿಲ್ಲ, ಹಿನ್ನೆಲೆಯಲ್ಲಿ ನಿಮ್ಮ ಬಳಕೆಯನ್ನು ಎಂದಿಗೂ ಗಮನಿಸುವುದಿಲ್ಲ, ಮತ್ತು ಲಾಗಿನ್ ಅನ್ನು ಎಂದಿಗೂ ನಕಲಿಸುವುದಿಲ್ಲ, ನವೀಕರಿಸುವುದಿಲ್ಲ ಅಥವಾ ರವಾನಿಸುವುದಿಲ್ಲ. Windows ನಲ್ಲಿ ಅದನ್ನು ನಿರ್ಲಕ್ಷಿಸಲಾಗುತ್ತದೆ, ಮತ್ತು `ccam doctor` ಅದನ್ನು ತಿಳಿಸುತ್ತದೆ; ಅಲ್ಲಿ, `relay = true` ಇದ್ದರೆ, `/ccam:switch` ಮತ್ತು `/exit` ಈಗಲೂ ಸಂಭಾಷಣೆಯನ್ನು ಇನ್ನೊಂದು ಖಾತೆಗೆ ಸ್ಥಳಾಂತರಿಸುತ್ತವೆ.

**Anthropic ನ ನಿಯಮಗಳು.** Team ಮತ್ತು Enterprise ಸೀಟುಗಳಲ್ಲಿ, `auto_switch` ನಿಮ್ಮ ಕೆಲಸವನ್ನು ಅದೇ ಸಂಸ್ಥೆಯ ಇನ್ನೊಂದು ಸೀಟಿಗೆ ಸ್ಥಳಾಂತರಿಸುತ್ತದೆ. Anthropic ನ ಸಹಾಯ ಕೇಂದ್ರವು "Each seat on a Team plan is assigned to one named individual, and only that person may use it" (Team ಪ್ಲಾನ್‌ನ ಪ್ರತಿ ಸೀಟನ್ನು ಹೆಸರಿಸಲಾದ ಒಬ್ಬ ವ್ಯಕ್ತಿಗೆ ನಿಯೋಜಿಸಲಾಗುತ್ತದೆ, ಮತ್ತು ಆ ವ್ಯಕ್ತಿ ಮಾತ್ರ ಅದನ್ನು ಬಳಸಬಹುದು) ಮತ್ತು "Users can't route their work through another user's account to use that user's remaining usage" (ಬಳಕೆದಾರರು ಇನ್ನೊಬ್ಬ ಬಳಕೆದಾರರ ಉಳಿದಿರುವ ಬಳಕೆಯನ್ನು ಉಪಯೋಗಿಸಿಕೊಳ್ಳಲು ತಮ್ಮ ಕೆಲಸವನ್ನು ಅವರ ಖಾತೆಯ ಮೂಲಕ ನಡೆಸುವಂತಿಲ್ಲ) ಎಂದು ಹೇಳುತ್ತದೆ ([Team ಪ್ಲಾನ್‌ಗಳು](https://support.claude.com/en/articles/12004354-purchase-and-manage-seats-on-team-plans#h_b8a7d07129); [Enterprise ಪ್ಲಾನ್‌ಗಳಿಗೂ](https://support.claude.com/en/articles/13393991-purchase-and-manage-seats-on-enterprise-plans#h_fa6b9cade0) ಇದೇ ಅನ್ವಯಿಸುತ್ತದೆ).

ವೈಯಕ್ತಿಕ ಪ್ಲಾನ್‌ಗಳಿಗೆ (Pro, Max), ನಿಮ್ಮ ಸ್ವಂತ ಖಾತೆಗಳು ಮಿತಿಯಲ್ಲಿ ಸ್ವಯಂಚಾಲಿತವಾಗಿ ಒಂದರ ಕೆಲಸವನ್ನು ಇನ್ನೊಂದು ವಹಿಸಿಕೊಳ್ಳಬಹುದೇ ಎಂದು Anthropic ನ ನಿಯಮಗಳು ಹೇಳುವುದಿಲ್ಲ. Anthropic ಸ್ಪಷ್ಟವಾಗಿ ಅನುಮತಿಸದ ಹೊರತು, [ಗ್ರಾಹಕ ನಿಯಮಗಳು (Consumer Terms)](https://www.anthropic.com/legal/consumer-terms) ಸೇವೆಗಳನ್ನು "through automated or non-human means, whether through a bot, script, or otherwise" (ಬಾಟ್, ಸ್ಕ್ರಿಪ್ಟ್ ಅಥವಾ ಬೇರೆ ಯಾವುದರ ಮೂಲಕವೇ ಆಗಲಿ, ಸ್ವಯಂಚಾಲಿತ ಅಥವಾ ಮಾನವೇತರ ವಿಧಾನಗಳ ಮೂಲಕ) ಬಳಸುವುದನ್ನು ನಿಷೇಧಿಸುತ್ತವೆ, ಮತ್ತು ಒಂದು ಸ್ಥಳಾಂತರ ಮೇಲಿನ ಸ್ಥಿರ ಸಂದೇಶವನ್ನು ನಿಮ್ಮ ಪರವಾಗಿ ಕಳುಹಿಸುತ್ತದೆ. ನವೆಂಬರ್ 12, 2026 ರಂದು ಜಾರಿಗೆ ಬರುವ [ಬಳಕೆಯ ನೀತಿ (Usage Policy)](https://www.anthropic.com/legal/aup) ತಾನು ನಿಷೇಧಿಸುವ ವಿಷಯಗಳಲ್ಲಿ "Intentionally bypass or interfere with capabilities, restrictions, or guardrails established within our products" (ನಮ್ಮ ಉತ್ಪನ್ನಗಳಲ್ಲಿ ಸ್ಥಾಪಿಸಲಾದ ಸಾಮರ್ಥ್ಯಗಳು, ನಿರ್ಬಂಧಗಳು ಅಥವಾ ಸುರಕ್ಷಾ ಕ್ರಮಗಳನ್ನು ಉದ್ದೇಶಪೂರ್ವಕವಾಗಿ ಬೈಪಾಸ್ ಮಾಡುವುದು ಅಥವಾ ಅವುಗಳಲ್ಲಿ ಹಸ್ತಕ್ಷೇಪ ಮಾಡುವುದು) ಅನ್ನು ಪಟ್ಟಿ ಮಾಡುತ್ತದೆ.

`auto_switch` ಈ ನಿಯಮಗಳನ್ನು ಪಾಲಿಸುತ್ತದೆ ಎಂದು ccam ಹೇಳಿಕೊಳ್ಳುವುದಿಲ್ಲ. ಇದನ್ನು ಆನ್ ಮಾಡುವುದು ನಿಮ್ಮ ನಿರ್ಧಾರ, ಮತ್ತು ಅಪಾಯವೂ ನಿಮ್ಮದೇ: ನಿಯಮಗಳನ್ನು ಉಲ್ಲಂಘಿಸಲಾಗಿದೆ ಎಂದು Anthropic ಭಾವಿಸಿದಾಗ ಅದು ಖಾತೆಯನ್ನು, ಅಥವಾ Team ಅಥವಾ Enterprise ಸಂಸ್ಥೆಯ ಪ್ರವೇಶವನ್ನು, ಅಮಾನತುಗೊಳಿಸಬಹುದು.

`auto_switch` ಆನ್ ಆಗಿರುವಾಗ, `ccam doctor` ccam ಪ್ಲಗಿನ್ ಇಲ್ಲದ ಖಾತೆಯ ಬಗ್ಗೆ ಮತ್ತು 2.1.214 ಕ್ಕಿಂತ ಹಳೆಯ Claude Code ಆವೃತ್ತಿಗಳ ಬಗ್ಗೆ ಎಚ್ಚರಿಸುತ್ತದೆ, ಮತ್ತು ಸೀಟುಗಳಿಗೆ Anthropic ನ ಸೀಟು ನಿಯಮವನ್ನು ಪುನರಾವರ್ತಿಸುತ್ತದೆ ([ಪರಿಶೀಲನೆಗಳು](/features/doctor)).

## ಮಿತಿಯಲ್ಲಿ ಮತ್ತೆ ರನ್ ಮಾಡುವುದು

`ccam next` ನಿಂತುಹೋದ ಇಂಟರ್‌ಆಕ್ಟಿವ್ ಸೆಷನ್‌ಗಾಗಿ. ಇಂಟರ್‌ಆಕ್ಟಿವ್ ಅಲ್ಲದ ರನ್, ಅಂದರೆ ಸ್ಕ್ರಿಪ್ಟ್ ಅಥವಾ ನಿಗದಿತ ಕೆಲಸದಲ್ಲಿನ `claude -p`, ನಿಮಗಾಗಿ ಕಾಯಲಾರದು, ಆದ್ದರಿಂದ ಖಾತೆಯ ಹೆಸರಿನ ಮುಂದೆ `--fallback` ಹಾಕಿದರೆ ccam ಅದರ ಪರವಾಗಿ ಬದಲಾಯಿಸುತ್ತದೆ:

```sh
ccam --fallback work -p "fix the failing tests" --output-format json
ccam --fallback -p "summarise" < notes.txt      # the folder's account or the default
ccam run --fallback work -p "review the diff"
```

```console
$ ccam --fallback personal -p "summarise" < notes.txt
ccam: personal reached its usage limit; running the command again as work
Summary: …
```

1. `--fallback` `-p` ಅಥವಾ `--print` ಜೊತೆ ಮಾತ್ರ ಕೆಲಸ ಮಾಡುತ್ತದೆ; ಇಲ್ಲದಿದ್ದರೆ ccam ನಿಂತು `ccam next --auto --continue` ಅನ್ನು ಸೂಚಿಸುತ್ತದೆ.
2. ಪೈಪ್ ಮಾಡಿದ ಸ್ಟ್ಯಾಂಡರ್ಡ್ ಇನ್‌ಪುಟ್ ಅನ್ನು, 10 MiB ವರೆಗೆ, ಒಮ್ಮೆ ಓದಿ ಪ್ರತಿ ಪ್ರಯತ್ನಕ್ಕೂ ನೀಡಲಾಗುತ್ತದೆ. Claude Code ನಂತೆಯೇ, ಅದು ಆರಂಭವಾಗಲು ccam ಗರಿಷ್ಠ 3 ಸೆಕೆಂಡ್ ಕಾಯುತ್ತದೆ (`--input-format stream-json` ಇದ್ದಾಗ ಹೊರತುಪಡಿಸಿ); ಪೈಪ್ ತೆರೆದೇ ಇದ್ದು ಏನನ್ನೂ ಕಳುಹಿಸದಿದ್ದರೆ, ರನ್‌ಗೆ ಯಾವುದೇ ಇನ್‌ಪುಟ್ ಸಿಗುವುದಿಲ್ಲ ಮತ್ತು ccam ಇದನ್ನು ಸ್ಟ್ಯಾಂಡರ್ಡ್ ಎರರ್‌ನಲ್ಲಿ ತಿಳಿಸುತ್ತದೆ.
3. ccam `exec` ಬದಲು `claude` ಅನ್ನು ಚೈಲ್ಡ್ ಪ್ರಕ್ರಿಯೆಯಾಗಿ ಆರಂಭಿಸುತ್ತದೆ, ಅದರ ಸ್ಟ್ಯಾಂಡರ್ಡ್ ಔಟ್‌ಪುಟ್ ಅನ್ನು ತಡೆಹಿಡಿಯುತ್ತದೆ, ಮತ್ತು ಸ್ಟ್ಯಾಂಡರ್ಡ್ ಎರರ್ ಅನ್ನು ಬಂದಂತೆಯೇ ಮುಂದಕ್ಕೆ ಕಳುಹಿಸುತ್ತದೆ.
4. `claude` 0 ಜೊತೆ ನಿರ್ಗಮಿಸಿದಾಗ, ಅಥವಾ ಬೇರೆ ಕಾರಣಕ್ಕೆ ವಿಫಲವಾದಾಗ, ತಡೆಹಿಡಿದ ಔಟ್‌ಪುಟ್ ಮತ್ತು ಎಕ್ಸಿಟ್ ಕೋಡ್ ಅನ್ನು ಬದಲಾಯಿಸದೆ ಮುಂದಕ್ಕೆ ಕಳುಹಿಸಲಾಗುತ್ತದೆ. signal ನಿಂದ ಮುಗಿದ ರನ್ (128 ಕ್ಕಿಂತ ಹೆಚ್ಚಿನ ಎಕ್ಸಿಟ್ ಕೋಡ್) ಕೂಡ ಹಾಗೆಯೇ: ಅದನ್ನು ನಿಲ್ಲಲು ಕೇಳಲಾಗಿತ್ತು, ಮತ್ತು ಅದನ್ನು ಮತ್ತೆ ರನ್ ಮಾಡಲಾಗುವುದಿಲ್ಲ.
5. Claude Code ನ ಸಂದೇಶ ಹಾಗೆ ಹೇಳಿದಾಗ, ಅಂದರೆ [ಹುಕ್](#inside-claude-code) ತಿಳಿದಿರುವ ಯಾವುದೇ ಬಳಕೆ-ಮಿತಿ ಸಂದೇಶ, `--output-format json` ಅಥವಾ `stream-json` ಔಟ್‌ಪುಟ್‌ನೊಳಗೂ ಸಹ, ಅಥವಾ ಖಾತೆಯ ಬಳಕೆ ಅದರ 5 ಗಂಟೆಯ, ವಾರದ ಅಥವಾ `--model` ಅವಧಿಯನ್ನು 100% ನಲ್ಲಿ ತೋರಿಸಿದಾಗ (ಮಿತಿ ದಾಖಲೆಯೂ ಸೇರಿ), ವೈಫಲ್ಯವನ್ನು ಬಳಕೆಯ ಮಿತಿ ಎಂದು ಎಣಿಸಲಾಗುತ್ತದೆ.
6. ಆಗ ಆ ಪ್ರಯತ್ನದ ಔಟ್‌ಪುಟ್ ಅನ್ನು ಕೈಬಿಟ್ಟು, ಅದೇ ಕಮಾಂಡ್ ಇನ್ನೊಂದು ಲಾಗಿನ್ ಆದ ಖಾತೆಯಾಗಿ ರನ್ ಆಗುತ್ತದೆ: ಅತಿ ಕಡಿಮೆ 5 ಗಂಟೆಯ ಬಳಕೆಯ ಖಾತೆ, ನಂತರ ಬಳಕೆ ಪರಿಶೀಲಿಸಲಾಗದ ಖಾತೆಗಳು, ಸಂಖ್ಯೆಯ ಕ್ರಮದಲ್ಲಿ. 100% ತಲುಪಿದ ಖಾತೆಗಳನ್ನು ಬಿಟ್ಟುಬಿಡಲಾಗುತ್ತದೆ, API ಕೀ ಲಾಗಿನ್ ಇರುವ ಖಾತೆಗಳನ್ನು ಎಂದಿಗೂ ಪ್ರಯತ್ನಿಸಲಾಗುವುದಿಲ್ಲ, ಮತ್ತು ಪ್ರತಿ ಖಾತೆಯನ್ನು ಗರಿಷ್ಠ ಒಮ್ಮೆ ಪ್ರಯತ್ನಿಸಲಾಗುತ್ತದೆ.
7. ಆರ್ಗ್ಯುಮೆಂಟ್‌ಗಳಲ್ಲಿ `-c`, `--continue`, `-r` ಅಥವಾ `--resume` ಇದ್ದರೆ, ಅದೇ ಇತಿಹಾಸ ಗುಂಪಿನ ಖಾತೆಗಳನ್ನು ಮಾತ್ರ ಪ್ರಯತ್ನಿಸಲಾಗುತ್ತದೆ, ಹೀಗಾಗಿ ಸಂಭಾಷಣೆ ಸಿಗುತ್ತದೆ.
8. `--auto` ನಂತೆಯೇ, ಅದೇ ಸಂಸ್ಥೆಯ ಖಾತೆಗಳನ್ನು ಮಾತ್ರ ಪ್ರಯತ್ನಿಸಲಾಗುತ್ತದೆ (`cross_org = true` ಇದನ್ನು ತೆಗೆದುಹಾಕುತ್ತದೆ).

ಮುಂದಿನ ಖಾತೆಯನ್ನು `--auto` ನ ಅದೇ ನಿಯಮಗಳಿಂದ ಆಯ್ಕೆಮಾಡಲಾಗುತ್ತದೆ (`auto_max_usage`, `auto_strategy`, `--model` ಅವಧಿ). ಯಾವ ಖಾತೆಯೂ ಉಳಿಯದಿದ್ದಾಗ, ccam ಕೊನೆಯ ಪ್ರಯತ್ನದ ಔಟ್‌ಪುಟ್ ಅನ್ನು ಮುದ್ರಿಸುತ್ತದೆ, ಲಾಗಿನ್ ಆದ ಯಾವ ಖಾತೆಯಲ್ಲೂ ಅವಕಾಶ ಉಳಿದಿಲ್ಲ ಎಂದು ಹೇಳುತ್ತದೆ, ಮತ್ತು ಕೋಡ್ 75 ನೊಂದಿಗೆ ನಿರ್ಗಮಿಸುತ್ತದೆ. ಖಾತೆಯ ಹೆಸರಿಗಿಂತ ಮೊದಲು `--wait` ಇದ್ದರೆ (`ccam --fallback --wait=2h work -p …`), ಅದು ಬದಲಿಗೆ ಮೊದಲ ಖಾತೆ ರೀಸೆಟ್ ಆಗುವವರೆಗೆ ಕಾಯುತ್ತದೆ, ನಂತರ ಪ್ರತಿ ಖಾತೆಯನ್ನೂ ಮತ್ತೆ ಪ್ರಯತ್ನಿಸಬಹುದು; ಅದು ಯಾವಾಗಲೂ ಮೊದಲು ಕನಿಷ್ಠ ಒಮ್ಮೆ ಕಾಯುತ್ತದೆ, ಹೀಗಾಗಿ ಈಗಷ್ಟೇ ಮಿತಿ ತಲುಪಿದ ಖಾತೆಯನ್ನು ತಕ್ಷಣ ಮತ್ತೆ ರನ್ ಮಾಡಲಾಗುವುದಿಲ್ಲ. ಅವಧಿಯು ರನ್‌ನ ಒಟ್ಟು ಕಾಯುವ ಸಮಯವನ್ನು ಮಿತಿಗೊಳಿಸುತ್ತದೆ, ಪ್ರತಿ ಕಾಯುವಿಕೆಯನ್ನಲ್ಲ. ಸ್ಪೇಸ್‌ನೊಂದಿಗೆ ಬರೆದರೆ (`--wait 30m`), `ccam next` ನಲ್ಲಿರುವ ಅದೇ ಸುಳಿವಿನೊಂದಿಗೆ ಅದನ್ನು ನಿರಾಕರಿಸಲಾಗುತ್ತದೆ. Claude Code ನ ಆರ್ಗ್ಯುಮೆಂಟ್‌ಗಳ ಮುಂದಿನ `--` ಯಾವುದೇ ಆರಂಭದಲ್ಲಿರುವಂತೆಯೇ ಕೆಲಸ ಮಾಡುತ್ತದೆ (`ccam --fallback work -- -p …`). `ccam --dry-run --fallback work -p …` ಮೊದಲ ಪ್ರಯತ್ನದ ಕಮಾಂಡ್ ಅನ್ನು ಮುದ್ರಿಸುತ್ತದೆ.

ನೀವು [`auto_switch`](#auto-switch) ಅನ್ನು ಆನ್ ಮಾಡದ ಹೊರತು ಇಂಟರ್‌ಆಕ್ಟಿವ್ ಸೆಷನ್‌ಗಳು ತಾವಾಗಿಯೇ ಬದಲಾಗುವುದಿಲ್ಲ. `ccam statusline install` ಜೊತೆ, 5 ಗಂಟೆಯ ಅಥವಾ ವಾರದ ಬಳಕೆ 90% ತಲುಪಿದಾಗ ಸ್ಟೇಟಸ್ ಲೈನ್ `→ ccam next --auto --continue` ಅನ್ನು ಸೇರಿಸುತ್ತದೆ ([ಬಳಕೆಯ ಮಿತಿಗಳು](/features/usage)).

## ಸುರಕ್ಷತೆ ಮತ್ತು ವಿಶೇಷ ಸಂದರ್ಭಗಳು

- ಲಾಗಿನ್ ಇಲ್ಲದ ಖಾತೆಗಳನ್ನು ಎಂದಿಗೂ ಆಯ್ಕೆಮಾಡುವುದಿಲ್ಲ. ಲಾಗಿನ್ ಆಗಿರುವ ಇನ್ನೊಂದು ಖಾತೆ ಇಲ್ಲದಿದ್ದರೆ, ಸಾಮಾನ್ಯ `ccam next` `no logged-in account other than <name>` ಎಂದು ನಿಲ್ಲುತ್ತದೆ.
- `--continue` ಇದ್ದು ಫೋಲ್ಡರ್‌ನಲ್ಲಿ ಯಾವುದೇ ಸಂಭಾಷಣೆ ಇಲ್ಲದಿದ್ದಾಗ: `no account has a conversation in <folder> to continue`.
- ಸಂಸ್ಥೆಯ ನಿಯಮದಿಂದ ಯಾವ ಖಾತೆಯೂ ಉಳಿಯದಿದ್ದಾಗ: `` no logged-in account to pick among <name>'s (<organization>); --cross-org also looks at the others ``.
- `--auto` ಇದ್ದು ಲಾಗಿನ್ ಆಗಿರುವ ಖಾತೆ ಇಲ್ಲದಿದ್ದಾಗ: `no logged-in account to pick`. ಪ್ರತಿ ಖಾತೆಯೂ ತುಂಬಿದ್ದಾಗ ಅಥವಾ ಅದರ ಬಳಕೆ ತಿಳಿಯದಿದ್ದಾಗ: `` no account with known usage and headroom (see `ccam usage`) ``. ಎರಡೂ ನಿರ್ಗಮನ ಕೋಡ್ 75 ನೊಂದಿಗೆ ಕೊನೆಗೊಳ್ಳುತ್ತವೆ.
- `--max-usage`, `--strategy`, `--wait` ಮತ್ತು `--cross-org` `--auto` ಜೊತೆ ಮಾತ್ರ ಕೆಲಸ ಮಾಡುತ್ತವೆ, ಮತ್ತು 1-100 ರ ಹೊರಗಿನ ಮೌಲ್ಯ ಅಥವಾ ಅಪರಿಚಿತ strategy ಅನ್ನು ನಿರಾಕರಿಸಲಾಗುತ್ತದೆ.
- ಫೋರ್ಕ್ ಸಂಭಾಷಣೆಯನ್ನು ನಕಲಿಸುತ್ತದೆ, ಖಾತೆಯ ಇತರ ಸ್ಥಿತಿಯನ್ನಲ್ಲ: ಇತಿಹಾಸ ಹಂಚಿಕೊಂಡಿಲ್ಲದಿದ್ದರೆ ಮೂಲ ಖಾತೆಯ `file-history/` ನ ಚೆಕ್‌ಪಾಯಿಂಟ್‌ಗಳು ಜೊತೆಗೆ ಬರುವುದಿಲ್ಲ.
- `--dry-run` ಇದ್ದರೂ `--auto` ನೆಟ್‌ವರ್ಕ್ ವಿನಂತಿಗಳನ್ನು ಮಾಡುತ್ತದೆ. ಅದು ಓದುತ್ತದೆ ಅಷ್ಟೇ, ಮತ್ತು ಟೋಕನ್ ಫೈಲ್‌ಗಳಿಗೆ ಎಂದಿಗೂ ಬರೆಯುವುದಿಲ್ಲ.
- ಆಯ್ಕೆಯಾದ ಖಾತೆ `ccam <name>` ನ ಅದೇ ಹಾದಿಯಲ್ಲಿ ಆರಂಭವಾಗುತ್ತದೆ, ಹೀಗಾಗಿ ಅದೇ ಪರಿಶೀಲನೆಗಳು ಅನ್ವಯವಾಗುತ್ತವೆ; ಅದೇ ಇತಿಹಾಸ ಹಂಚಿಕೊಳ್ಳುವ ಇನ್ನೊಂದು Claude Code ಸೆಷನ್ ಈ ಫೋಲ್ಡರ್‌ನಲ್ಲಿ ಈಗಾಗಲೇ ಚಾಲನೆಯಲ್ಲಿದ್ದಾಗ ಬರುವ ಎಚ್ಚರಿಕೆಯೂ ಸೇರಿ.
- Claude Code ನಿಜವಾಗಿ ಆರಂಭವಾದಾಗ ಮಾತ್ರ `last-used` ಬರೆಯಲಾಗುತ್ತದೆ. `--dry-run` ಅದನ್ನು ಮುಟ್ಟುವುದಿಲ್ಲ, ಹೀಗಾಗಿ ಡ್ರೈ ರನ್ ರೊಟೇಶನ್ ಅನ್ನು ಮುಂದಕ್ಕೆ ಸರಿಸುವುದಿಲ್ಲ.
- ಪ್ರಯತ್ನ ಮುಗಿಯುವವರೆಗೆ `--fallback` ಸ್ಟ್ಯಾಂಡರ್ಡ್ ಔಟ್‌ಪುಟ್ ಅನ್ನು ತಡೆಹಿಡಿಯುತ್ತದೆ, ಹೀಗಾಗಿ `--output-format stream-json` ನಂತಹ ಸ್ಟ್ರೀಮಿಂಗ್ ಔಟ್‌ಪುಟ್ ಕೊನೆಯಲ್ಲಿ ಒಂದೇ ತುಣುಕಾಗಿ ಬರುತ್ತದೆ. `stream-json` ಇನ್‌ಪುಟ್ ಅನ್ನು ಸ್ಟ್ರೀಮ್ ಮಾಡಿ, ಇನ್ನಷ್ಟು ಕಳುಹಿಸುವ ಮೊದಲು ಉತ್ತರಗಳಿಗಾಗಿ ಕಾಯುವ ಕ್ಲೈಂಟ್ `--fallback` ಅನ್ನು ಬಳಸಲಾರದು. ಮಿತಿ ತಲುಪುವ ಮೊದಲು ಮೊದಲ ಪ್ರಯತ್ನ ಬದಲಾಯಿಸಿದ ಫೈಲ್‌ಗಳು ಬದಲಾದಂತೆಯೇ ಉಳಿಯುತ್ತವೆ; ಮುಂದಿನ ಪ್ರಯತ್ನ ಪ್ರಾಂಪ್ಟ್ ಅನ್ನು ಮೊದಲಿನಿಂದ ಆರಂಭಿಸುತ್ತದೆ.
