`ccam doctor` ನಿಮ್ಮ ccam ಇನ್‌ಸ್ಟಾಲೇಶನ್ ಅನ್ನು ಪರಿಶೀಲಿಸುತ್ತದೆ: Claude Code ಬೈನರಿ, ಪ್ರತಿ ಖಾತೆಯ ಫೋಲ್ಡರ್, ಲಾಗಿನ್ ಮತ್ತು ಹಂಚಿಕೆ ಲಿಂಕ್‌ಗಳು, ಹಂಚಿಕೊಂಡ MCP ಸರ್ವರ್‌ಗಳು, ಬಳಕೆಯ ಎಂಡ್‌ಪಾಯಿಂಟ್ ಮತ್ತು ನಿಮ್ಮ ಶಾರ್ಟ್‌ಕಟ್ ಕಮಾಂಡ್‌ಗಳು. `ccam doctor --fix` ಡೇಟಾ ಕಳೆದುಕೊಳ್ಳದೆ ಸರಿಪಡಿಸಬಹುದಾದ್ದನ್ನು ಸರಿಪಡಿಸುತ್ತದೆ ಮತ್ತು ತಾನು ಬದಲಾಯಿಸುವ ಯಾವುದೇ ಫೈಲ್ ಅನ್ನು ಮೊದಲು ಬ್ಯಾಕಪ್ ಫೋಲ್ಡರ್‌ಗೆ ಸ್ಥಳಾಂತರಿಸುತ್ತದೆ. `ccam <name>` ಹಂಚಿಕೆ ಲಿಂಕ್ ಸಮಸ್ಯೆಯಿಂದ ನಿಂತಾಗ, ಫೈಲ್‌ಗಳನ್ನು ಕೈಯಾರೆ ಮರುಸ್ಥಾಪಿಸಿದ ನಂತರ, ಅಥವಾ Claude Code ಅಪ್‌ಡೇಟ್ ನಂತರ ಇದನ್ನು ರನ್ ಮಾಡಿ.

## ಬಳಕೆ

```sh
ccam doctor                  # check everything, change nothing
ccam doctor --fix            # check, then repair what is safe to repair
ccam --dry-run doctor --fix  # report only: what --fix would repair
```

ಪ್ರತಿ ಫಲಿತಾಂಶವೂ ಒಂದು ಗುರುತಿನೊಂದಿಗೆ ಒಂದು ಸಾಲು: `✓` ಸರಿ, `·` ಮಾಹಿತಿ, `!` ಎಚ್ಚರಿಕೆ, `✗` ದೋಷ. ಖಾತೆಯ ಫಲಿತಾಂಶಗಳು ಖಾತೆಯ ಹೆಸರಿನಿಂದ ಆರಂಭವಾಗುತ್ತವೆ.

```console
$ ccam doctor
✓ Claude Code 2.1.302 (Claude Code) (/home/me/.local/bin/claude)
! personal: folder permissions are 755 (should be 0700)
! personal: .credentials.json permissions are 644 (should be 0600)
✓ personal: login valid (me@example.com)
✗ personal: /home/me/.local/share/ccam/profiles/personal/settings.json: set to shared but is a real file, not a link
· personal: unknown entries (Claude Code layout may have changed): newthing
! work: not logged in → `ccam login work`
✓ work: share links OK
! missing shortcuts in /home/me/.local/bin: ccp

`ccam doctor --fix` repairs what it can.
```

`--fix` ಜೊತೆ, ಸರಿಪಡಿಸಿದ ಪ್ರತಿ ಫಲಿತಾಂಶವೂ `→ fixed` ನಿಂದ ಕೊನೆಗೊಳ್ಳುತ್ತದೆ:

```console
$ ccam doctor --fix
✓ Claude Code 2.1.302 (Claude Code) (/home/me/.local/bin/claude)
! personal: folder permissions are 755 (should be 0700) → fixed
! personal: .credentials.json permissions are 644 (should be 0600) → fixed
✓ personal: login valid (me@example.com)
✗ personal: /home/me/.local/share/ccam/profiles/personal/settings.json: set to shared but is a real file, not a link → fixed
· personal: unknown entries (Claude Code layout may have changed): newthing
! work: not logged in → `ccam login work`
✓ work: share links OK
! missing shortcuts in /home/me/.local/bin: ccp → fixed
```

## ಆಯ್ಕೆಗಳು

| ಆಯ್ಕೆ | ಏನು ಮಾಡುತ್ತದೆ | ಡೀಫಾಲ್ಟ್ |
| --- | --- | --- |
| `--fix` | ಸುರಕ್ಷಿತವಾಗಿ ಸರಿಪಡಿಸಬಹುದಾದ್ದನ್ನು ಸರಿಪಡಿಸುತ್ತದೆ (ಬದಲಾದ ಫೈಲ್‌ಗಳ ಬ್ಯಾಕಪ್ ತೆಗೆದುಕೊಳ್ಳಲಾಗುತ್ತದೆ) | ಆಫ್ |
| `--dry-run` (ಜಾಗತಿಕ) | ಎಲ್ಲಾ ಪರಿಶೀಲನೆಗಳನ್ನು ನಡೆಸುತ್ತದೆ ಆದರೆ `--fix` ಇದ್ದರೂ ಏನನ್ನೂ ಸರಿಪಡಿಸುವುದಿಲ್ಲ | ಆಫ್ |

`ccam doctor` ಯಾವುದೇ ಆರ್ಗ್ಯುಮೆಂಟ್ ತೆಗೆದುಕೊಳ್ಳುವುದಿಲ್ಲ. ಇದು `--dry-run` ಅನ್ನು ಪಾಲಿಸುತ್ತದೆ: `ccam --dry-run doctor --fix` `ccam doctor` ನಂತೆಯೇ ಫಲಿತಾಂಶಗಳನ್ನು ಮುದ್ರಿಸುತ್ತದೆ ಮತ್ತು ಏನನ್ನೂ ಬದಲಾಯಿಸುವುದಿಲ್ಲ.

ಕನಿಷ್ಠ ಒಂದು `✗` ಫಲಿತಾಂಶ ಸರಿಪಡಿಸದೆ ಉಳಿದಾಗ ಎಕ್ಸಿಟ್ ಕೋಡ್ `1`, ಇಲ್ಲದಿದ್ದರೆ `0`. ಎಚ್ಚರಿಕೆಗಳು ಮತ್ತು ಮಾಹಿತಿ ಎಂದಿಗೂ ರನ್ ಅನ್ನು ವಿಫಲಗೊಳಿಸುವುದಿಲ್ಲ. `--fix` ಇಲ್ಲದೆ ರನ್ ವಿಫಲವಾದಾಗ, ccam ಒಂದು ಖಾಲಿ ಸಾಲು ಮತ್ತು `` `ccam doctor --fix` repairs what it can. `` ನೊಂದಿಗೆ ಕೊನೆಗೊಳ್ಳುತ್ತದೆ. ಲೋಡ್ ಮಾಡಲಾಗದ ಕಾನ್ಫಿಗ್ ಕೂಡ `1` ಮತ್ತು ಒಂದು `ccam:` ದೋಷದೊಂದಿಗೆ ಕೊನೆಗೊಳ್ಳುತ್ತದೆ.

## ಇದು ಹೇಗೆ ಕೆಲಸ ಮಾಡುತ್ತದೆ

`internal/cli/doctor.go` `~/.config/ccam/config.toml` ಅನ್ನು ಲೋಡ್ ಮಾಡಿ `internal/doctor/doctor.go` ನಲ್ಲಿರುವ `doctor.Run` ಅನ್ನು ಕರೆಯುತ್ತದೆ; ಅದು ಪರಿಶೀಲನೆಗಳನ್ನು ನಿಗದಿತ ಕ್ರಮದಲ್ಲಿ ನಡೆಸಿ ಫಲಿತಾಂಶಗಳನ್ನು ಹಿಂದಿರುಗಿಸುತ್ತದೆ. `--fix` ಅನ್ನು `Options.Fix` ಆಗಿ ರವಾನಿಸಲಾಗುತ್ತದೆ, ಡ್ರೈ ರನ್‌ನಲ್ಲಿ ಇದು false ಆಗಿರುತ್ತದೆ.

<!-- motion:doctor-checks -->

ಮಧ್ಯದ ಭಾಗ ಪ್ರತಿ ಖಾತೆಗೆ ಒಮ್ಮೆ ನಡೆಯುತ್ತದೆ. ಪರಿಶೀಲನೆಗಳು, ಮತ್ತು ಪ್ರತಿಯೊಂದಕ್ಕೂ `--fix` ಏನು ಮಾಡುತ್ತದೆ:

1. **Claude Code ಆವೃತ್ತಿ** (`checkClaude`). ಲಾಂಚರ್ ಮಾಡುವಂತೆಯೇ `claude` ಬೈನರಿಯನ್ನು ಕಂಡುಹಿಡಿದು `claude --version` ರನ್ ಮಾಡುತ್ತದೆ. ಆವೃತ್ತಿ `2.1.302` ನಿಂದ ಆರಂಭವಾಗದಿದ್ದರೆ (ccam ನ ಫೋಲ್ಡರ್ ವಿನ್ಯಾಸವನ್ನು ಪರಿಶೀಲಿಸಿದ ಆವೃತ್ತಿ, `doctor.LayoutVersion`), ಅದು `· ccam was verified against the folder layout of Claude Code 2.1.302. Any 'unknown entries' below may mean the layout changed` ಅನ್ನು ಸೇರಿಸುತ್ತದೆ. ಬೈನರಿ ಇಲ್ಲದಿರುವುದು ಅಥವಾ `--version` ವಿಫಲವಾಗುವುದು ದೋಷ. ಸರಿಪಡಿಕೆ ಇಲ್ಲ.
2. **ಪರಿಸರದಲ್ಲಿರುವ ಕ್ರೆಡೆನ್ಶಿಯಲ್‌ಗಳು** (`checkAuthEnv`). `CLAUDE_CODE_OAUTH_TOKEN`, `ANTHROPIC_API_KEY` ಅಥವಾ `ANTHROPIC_AUTH_TOKEN` ಹೊಂದಿಸಿದ್ದಾಗ ಎಚ್ಚರಿಸುತ್ತದೆ: ಆ ಶೆಲ್‌ನಿಂದ ಆರಂಭಿಸಿದ ಪ್ರತಿ ಖಾತೆಯೂ ಅದನ್ನು ಪಡೆಯುತ್ತದೆ, ಮತ್ತು Claude Code ಖಾತೆಯ ಸ್ವಂತ ಲಾಗಿನ್‌ಗಿಂತ ಅದಕ್ಕೇ ಆದ್ಯತೆ ನೀಡುತ್ತದೆ. ಸರಿಪಡಿಕೆ ಇಲ್ಲ; ಅದನ್ನು ನೀವೇ ತೆಗೆದುಹಾಕಿ.
3. **ಫೋಲ್ಡರ್** (`checkProfile`). ಖಾತೆಯ ಫೋಲ್ಡರ್ ಇಲ್ಲದಿರುವುದು ದೋಷ, ಮತ್ತು ಅದರೊಂದಿಗೆ ಆ ಖಾತೆಯ ಪರಿಶೀಲನೆಗಳು ಮುಗಿಯುತ್ತವೆ. ಗುಂಪು ಅಥವಾ ಇತರರ ಯಾವುದೇ ಬಿಟ್ ಹೊಂದಿಸಿದ ಅನುಮತಿಗಳು ಎಚ್ಚರಿಕೆ; `--fix` `chmod 0700` ರನ್ ಮಾಡುತ್ತದೆ. Windows ನಲ್ಲಿ ಅನುಮತಿ ಬಿಟ್‌ಗಳು ಇಲ್ಲ, ಆದ್ದರಿಂದ ಅಲ್ಲಿ ಈ ಪರಿಶೀಲನೆ ಮತ್ತು ಕೆಳಗಿನ `0600` ಪರಿಶೀಲನೆಯನ್ನು ಬಿಟ್ಟುಬಿಡಲಾಗುತ್ತದೆ; ನಿಮ್ಮ ಬಳಕೆದಾರ ಪ್ರೊಫೈಲ್‌ನಲ್ಲಿರುವ ಫೋಲ್ಡರ್ ಅನ್ನು ಅದರ ಪ್ರವೇಶ ಪಟ್ಟಿ (access list) ರಕ್ಷಿಸುತ್ತದೆ.
4. **ಲಾಗಿನ್ ಫೈಲ್** (`checkCredentials`). `.credentials.json` ಅನ್ನು `lstat` ಮೂಲಕ ಪರಿಶೀಲಿಸಲಾಗುತ್ತದೆ. ಸಿಮ್‌ಲಿಂಕ್ ದೋಷ, ಏಕೆಂದರೆ ಪ್ರತಿ ಖಾತೆಗೂ ತನ್ನದೇ ಟೋಕನ್ ಇರಬೇಕು, ಮತ್ತು ಅದನ್ನು ಸರಿಪಡಿಸಲಾಗುವುದಿಲ್ಲ. `0600` ಅಲ್ಲದ ಮೋಡ್ ಎಚ್ಚರಿಕೆ; `--fix` `chmod 0600` ರನ್ ಮಾಡುತ್ತದೆ. ನಂತರ ಲಾಗಿನ್ ಅನ್ನು ಓದಲಾಗುತ್ತದೆ (macOS ನಲ್ಲಿ ಮೊದಲು Keychain ನಿಂದ). ಲಾಗಿನ್ ಇಲ್ಲದಿದ್ದರೆ ಅದು `ccam login <name>` ಅನ್ನು ಸೂಚಿಸುವ ಎಚ್ಚರಿಕೆ. ಅವಧಿ ಮುಗಿದ ರಿಫ್ರೆಶ್ ಟೋಕನ್ `login expired` ದೋಷ; ಅವಧಿ ಮುಗಿದ ಆಕ್ಸೆಸ್ ಟೋಕನ್ ಕೇವಲ ಮಾಹಿತಿ, ಏಕೆಂದರೆ ಮುಂದಿನ ಆರಂಭದಲ್ಲಿ Claude Code ಅದನ್ನು ನವೀಕರಿಸುತ್ತದೆ. ಇವುಗಳಲ್ಲಿ ಯಾವುದನ್ನೂ ಸರಿಪಡಿಸಲಾಗುವುದಿಲ್ಲ.
5. **ಹಂಚಿಕೆ ಲಿಂಕ್‌ಗಳು** (`share.Check`). `share.Layout` ನಲ್ಲಿನ ಪ್ರತಿ ಪಾತ್ ಅನ್ನು ಖಾತೆಯ ಹಂಚಿಕೆ ಸೆಟ್ಟಿಂಗ್‌ಗಳೊಂದಿಗೆ ಹೋಲಿಸುತ್ತದೆ, `lstat` ಮತ್ತು `readlink` ಮಾತ್ರ ಬಳಸಿ. ಇದು ನಾಲ್ಕು ಬಗೆಯ ಸಮಸ್ಯೆಗಳನ್ನು ವರದಿ ಮಾಡುತ್ತದೆ: ಇಲ್ಲದ ಲಿಂಕ್, ಬೇರೆಡೆ ತೋರಿಸುವ ಲಿಂಕ್, ಲಿಂಕ್ ಇರಬೇಕಾದಲ್ಲಿ ನಿಜವಾದ ಫೈಲ್, ಮತ್ತು ಈಗ ಸ್ಥಳೀಯವಾಗಿರುವ ಐಟಂಗಾಗಿ ಉಳಿದ ಲಿಂಕ್. ಇಲ್ಲದ ಲಿಂಕ್ ಎಚ್ಚರಿಕೆ, ಉಳಿದವು ದೋಷಗಳು.
6. **ಅಪರಿಚಿತ ನಮೂದುಗಳು** (`checkUnknownEntries`). ccam ಗೆ ತಿಳಿಯದ (`share.Known`) ಖಾತೆಯ ಫೋಲ್ಡರ್‌ನ ಮೇಲ್ಮಟ್ಟದ ಹೆಸರುಗಳನ್ನು, Claude Code ವಿನ್ಯಾಸ ಬದಲಾಗಿದೆ ಎಂಬ ಸುಳಿವಾಗಿ ಪಟ್ಟಿ ಮಾಡುತ್ತದೆ. ಕೇವಲ ಮಾಹಿತಿ.
7. **ಪ್ಲಗಿನ್ ಪಾತ್‌ಗಳು** (`checkPlugins`). ಪ್ಲಗಿನ್ ರಿಜಿಸ್ಟ್ರಿಗಳು (`installed_plugins.json`, `known_marketplaces.json`) ಸಂಪೂರ್ಣ ಪಾತ್‌ಗಳನ್ನು ಸಂಗ್ರಹಿಸುತ್ತವೆ. ಪ್ರತಿ ಗುಂಪಿನ `plugins/` ನಲ್ಲಿ, ಒಂದು ಖಾತೆಯ ಫೋಲ್ಡರ್ ಮೂಲಕ ಹಾದುಹೋಗುವ ಪಾತ್‌ಗಳು ಆ ಖಾತೆಯನ್ನು ತೆಗೆದುಹಾಕಿದಾಗ ಅಥವಾ ಮರುಹೆಸರಿಸಿದಾಗ ಮುರಿಯುತ್ತವೆ. `--fix` ಅವುಗಳನ್ನು `profile.RewritePluginPaths` ಮೂಲಕ ಗುಂಪಿನ ಫೋಲ್ಡರ್‌ಗೆ ಮರುಬರೆಯುತ್ತದೆ; ಇದು ರಿಜಿಸ್ಟ್ರಿ ಫೈಲ್‌ನ ಅಟಾಮಿಕ್ ಬರಹ.
8. **MCP ಸರ್ವರ್‌ಗಳು** (`checkMCP`). ಪ್ರತಿ ಗುಂಪಿನ `mcp.json` ಅನ್ನು ಒಮ್ಮೆ ಲೋಡ್ ಮಾಡುತ್ತದೆ. ಓದಲಾಗದ ಫೈಲ್ ದೋಷ; `mcp.Validate` ನಲ್ಲಿ ವಿಫಲವಾಗುವ ಸರ್ವರ್ ಎಚ್ಚರಿಕೆ. ಸರಿಪಡಿಕೆ ಇಲ್ಲ.
9. **ಬಳಕೆಯ ಉತ್ತರದ ಸ್ವರೂಪ** (`checkUsageFormat`). ಕ್ಯಾಶ್ ಇಲ್ಲದೆ ಮತ್ತು ಸಾಮಾನ್ಯ 3 ಸೆಕೆಂಡ್ ಮಿತಿಯೊಂದಿಗೆ, ಒಂದು ಖಾತೆ ಉತ್ತರಿಸುವವರೆಗೆ ಒಂದರ ನಂತರ ಒಂದು ಖಾತೆಗೆ ಬಳಕೆಯ ಎಂಡ್‌ಪಾಯಿಂಟ್ ಅನ್ನು ಕೇಳುತ್ತದೆ. ಉತ್ತರ ಇನ್ನು ಪಾರ್ಸ್ ಆಗದಿದ್ದರೆ, `ccam usage` ಸ್ಟೇಟಸ್ ಲೈನ್ ಕ್ಯಾಶ್‌ಗೆ ಹಿಂದಿರುಗುತ್ತದೆ ಎಂದು ಎಚ್ಚರಿಸುತ್ತದೆ. ನೆಟ್‌ವರ್ಕ್ ಬಳಸುವ ಏಕೈಕ ಪರಿಶೀಲನೆ ಇದು.
10. **ಶಾರ್ಟ್‌ಕಟ್‌ಗಳು** (`checkShims`). ಯಾವುದಾದರೂ ಖಾತೆಗೆ ಶಾರ್ಟ್‌ಕಟ್ ಇದ್ದಾಗ ಮಾತ್ರ. `~/.local/bin` ನಲ್ಲಿ ಇಲ್ಲದ ಲಿಂಕ್‌ಗಳು ಎಚ್ಚರಿಕೆ; `--fix` `shim.Install` ಅನ್ನು ಕರೆಯುತ್ತದೆ, ಅದು ಇಲ್ಲದ ಲಿಂಕ್‌ಗಳನ್ನು ಮಾತ್ರ ರಚಿಸುತ್ತದೆ ಮತ್ತು ಇತರ ಫೈಲ್‌ಗಳನ್ನು ಎಂದಿಗೂ ಮುಟ್ಟುವುದಿಲ್ಲ. `PATH` ನಲ್ಲಿ ಇಲ್ಲದ bin ಫೋಲ್ಡರ್ ಎಚ್ಚರಿಕೆ ಮತ್ತು ಅದನ್ನು ಸರಿಪಡಿಸಲಾಗುವುದಿಲ್ಲ.
11. **ಫೋಲ್ಡರ್‌ಗಳು** (`checkFolders`). [`ccam folder`](/features/folder) ನಮೂದುಗಳು ಇದ್ದಾಗ ಮಾತ್ರ. ಖಾತೆ ಅಸ್ತಿತ್ವದಲ್ಲಿಲ್ಲದ ನಮೂದು ದೋಷ, ಮತ್ತು ಫೋಲ್ಡರ್ ಇಲ್ಲವಾದ ನಮೂದು ಎಚ್ಚರಿಕೆ. ಯಾವುದನ್ನೂ ಸರಿಪಡಿಸಲಾಗುವುದಿಲ್ಲ, ಏಕೆಂದರೆ ನಮೂದನ್ನು ತೆಗೆದುಹಾಕಿದರೆ ಅಲ್ಲಿ ಯಾವ ಖಾತೆ ಆರಂಭವಾಗುತ್ತದೆ ಎಂಬುದು ಬದಲಾಗುತ್ತದೆ.

### ಹಂಚಿಕೆ ಲಿಂಕ್‌ಗಳ ದುರಸ್ತಿ

ಆರಂಭದ ಮಾರ್ಗ ಇಲ್ಲದ ಲಿಂಕ್ ಅನ್ನು ಅಲ್ಲೇ ರಚಿಸುತ್ತದೆ, ಆದರೆ ಡೇಟಾ ಕಳೆದುಹೋಗಬಹುದಾದ ಯಾವುದಕ್ಕಾದರೂ ನಿಂತು ಇಲ್ಲಿಗೆ ಸೂಚಿಸುತ್ತದೆ:

```console
$ ccam work
ccam: stopped because of share link problems:
  /home/me/.local/share/ccam/profiles/work/CLAUDE.md: set to shared but is a real file, not a link
Repair them with `ccam doctor --fix`, then run again
```

ಯಾವುದೇ ಹಂಚಿಕೆ ಲಿಂಕ್ ಸಮಸ್ಯೆಗೆ, `--fix` ಖಾತೆಯ ಹಂಚಿಕೆ ಸೆಟ್ಟಿಂಗ್‌ಗಳನ್ನು ಈಗಿನ ಸ್ಥಿತಿ ಮತ್ತು ಗುರಿ ಸ್ಥಿತಿ ಎರಡಕ್ಕೂ ನೀಡಿ `share.Build` ಅನ್ನು ಕರೆಯುತ್ತದೆ, ನಂತರ `Plan.Apply`. `Build` ಡಿಸ್ಕ್‌ನಲ್ಲಿ ಇರುವುದರಿಂದ ಪ್ರತಿ ಹಂತವನ್ನೂ ಮತ್ತೆ ಲೆಕ್ಕಹಾಕುತ್ತದೆ, `ccam share` ಬಳಸುವ ಅದೇ ಯೋಜನೆ. ಹೀಗಾಗಿ ದುರಸ್ತಿ ಹಂಚಿಕೆಯನ್ನು ಆನ್ ಮಾಡುವಾಗಿನ ಅದೇ ನಿಯಮಗಳನ್ನು ಅನುಸರಿಸುತ್ತದೆ.

<!-- motion:doctor-repair -->

ಇಲ್ಲಿ `settings.json` ಒಂದು ನಿಜವಾದ ಫೈಲ್. ಗುಂಪಿನಲ್ಲಿ ಈಗಾಗಲೇ ಬೇರೆ `settings.json` ಇರುವುದರಿಂದ, ಸಂಘರ್ಷಕ್ಕೆ ಅದರ ಡೀಫಾಲ್ಟ್ ಆಯ್ಕೆ `KeepGroup` ಅನ್ವಯವಾಗುತ್ತದೆ, ಹೀಗಾಗಿ ಗುಂಪಿನ ಪ್ರತಿ ಉಳಿಯುತ್ತದೆ. ಖಾತೆಯ ಫೈಲ್ ಖಾತೆಯ ಫೋಲ್ಡರ್‌ನೊಳಗಿನ `.ccam-backup/<time>/settings.json` ಗೆ ಹೋಗುತ್ತದೆ, ಮತ್ತು `os.Symlink` ಆ ಪಾತ್ ಅನ್ನು ಗುಂಪಿಗೆ ಲಿಂಕ್ ಮಾಡುತ್ತದೆ. ಇತರ ಸಂದರ್ಭಗಳು:

- ಗುಂಪಿನಲ್ಲಿ ಇನ್ನೂ ಪ್ರತಿ ಇಲ್ಲದಿದ್ದರೆ, ಖಾತೆಯ ಫೈಲ್ ಗುಂಪಿಗೆ ಸ್ಥಳಾಂತರಗೊಂಡು ಅದರ ಮೊದಲ ವಿಷಯವಾಗುತ್ತದೆ.
- ಫೋಲ್ಡರ್‌ಗೆ, ಗುಂಪಿನಲ್ಲಿ ಇಲ್ಲದ ಫೈಲ್‌ಗಳು ಗುಂಪಿಗೆ ಹೋಗುತ್ತವೆ; ಉಳಿದವು ಬ್ಯಾಕಪ್‌ಗೆ ಹೋಗುತ್ತವೆ.
- `history.jsonl` ಗೆ ಡೀಫಾಲ್ಟ್ `merge by line`: ಗುಂಪಿನ ಸಾಲುಗಳು, ನಂತರ ನಿಮ್ಮ ಹೊಸ ಸಾಲುಗಳು. ಗುಂಪಿನ ಹಿಂದಿನ ಪ್ರತಿಯನ್ನು `.ccam-backup/<time>/group/` ನಲ್ಲಿ ಉಳಿಸಲಾಗುತ್ತದೆ.
- ಇನ್ನೊಂದು ಗುಂಪಿಗೆ ಇರುವ ಲಿಂಕ್ ಅನ್ನು ಬದಲಾಯಿಸಲಾಗುತ್ತದೆ. ccam ನ ಹೊರಗಿನ ಫೋಲ್ಡರ್‌ಗೆ ಇರುವ ಲಿಂಕ್ ಬ್ಯಾಕಪ್‌ಗೆ ಹೋಗುತ್ತದೆ, ಮತ್ತು ಗುಂಪು ಖಾಲಿಯಾಗಿದ್ದರೆ ಅದರ ವಿಷಯ ಗುಂಪಿನ ಆರಂಭಿಕ ವಿಷಯವಾಗುತ್ತದೆ.
- ಈಗ ಸ್ಥಳೀಯವಾಗಿರುವ ಐಟಂಗಾಗಿ ಉಳಿದ ಲಿಂಕ್ ಅನ್ನು ತೆಗೆದುಹಾಕಲಾಗುತ್ತದೆ, ಮತ್ತು ಖಾತೆಗೆ ಗುಂಪಿನ ವಿಷಯದ ಒಂದು ಪ್ರತಿ ಸಿಗುತ್ತದೆ.

ಲಿಂಕ್‌ಗಳನ್ನು ತೆಗೆದುಹಾಕುವುದನ್ನು ಬಿಟ್ಟರೆ, ಪ್ರತಿ ಹಂತವೂ ಡೇಟಾವನ್ನು ಗುಂಪಿಗೆ ಅಥವಾ ಬ್ಯಾಕಪ್ ಫೋಲ್ಡರ್‌ಗೆ ಸ್ಥಳಾಂತರಿಸುತ್ತದೆ. ಏನನ್ನೂ ಅಳಿಸಲಾಗುವುದಿಲ್ಲ.

## ಸುರಕ್ಷತೆ ಮತ್ತು ವಿಶೇಷ ಸಂದರ್ಭಗಳು

- ಸಾಮಾನ್ಯ `ccam doctor` ಎಂದಿಗೂ ಏನನ್ನೂ ಬದಲಾಯಿಸುವುದಿಲ್ಲ. ಸ್ಕ್ರಿಪ್ಟ್‌ಗಳಲ್ಲಿ ಖಚಿತವಾಗಿರಲು `--fix` ಜೊತೆ `--dry-run` ಬಳಸಿ.
- ಖಾತೆ ಚಾಲನೆಯಲ್ಲಿದೆಯೇ ಎಂದು `doctor --fix` ಪರಿಶೀಲಿಸುವುದಿಲ್ಲ. ಒಂದು ಖಾತೆಯ ಹಂಚಿಕೆ ಲಿಂಕ್‌ಗಳನ್ನು ಸರಿಪಡಿಸುವ ಮೊದಲು ಆ ಖಾತೆಯ Claude Code ನಿಂದ ನಿರ್ಗಮಿಸಿ, ಏಕೆಂದರೆ ಸೆಷನ್ ಆ ಫೈಲ್‌ಗಳಿಗೆ ಬರೆಯುತ್ತಲೇ ಇರುತ್ತದೆ.
- ಹಂಚಿಕೆ ದುರಸ್ತಿ ವಿಫಲವಾದರೆ, ccam ಆ ಖಾತೆಗೆ `could not repair share links: <error>` ಎಂದು ವರದಿ ಮಾಡುತ್ತದೆ ಮತ್ತು ಅದರ ಅಪರಿಚಿತ ನಮೂದುಗಳ ಪರಿಶೀಲನೆಯನ್ನು ಬಿಟ್ಟುಬಿಡುತ್ತದೆ. ಇತರ ಖಾತೆಗಳನ್ನು ಪರಿಶೀಲಿಸಲಾಗುತ್ತದೆ.
- `ccam share` ಅರ್ಧದಲ್ಲಿ ವಿಫಲವಾದರೆ, ಅದು ಮೊದಲು ಗುರಿ ಸೆಟ್ಟಿಂಗ್‌ಗಳನ್ನು ಉಳಿಸುತ್ತದೆ ಮತ್ತು `ccam doctor --fix` ಮೂಲಕ ಮುಗಿಸಲು ಹೇಳುತ್ತದೆ.
- ಸಿಮ್‌ಲಿಂಕ್ ಆದ `.credentials.json`, ಅವಧಿ ಮುಗಿದ ಲಾಗಿನ್ ಮತ್ತು ಪರಿಸರದ ಕ್ರೆಡೆನ್ಶಿಯಲ್‌ಗಳನ್ನು ವರದಿ ಮಾಡಲಾಗುತ್ತದೆ, ಆದರೆ ಎಂದಿಗೂ ಬದಲಾಯಿಸಲಾಗುವುದಿಲ್ಲ.
- ಪ್ಲಗಿನ್ ರಿಜಿಸ್ಟ್ರಿ ಮರುಬರಹಗಳನ್ನು ಅಟಾಮಿಕ್ ಆಗಿ ಬರೆಯಲಾಗುತ್ತದೆ, ಆದರೆ `.ccam-backup/` ಗೆ ನಕಲಿಸಲಾಗುವುದಿಲ್ಲ.
