`ccam doctor` ನಿಮ್ಮ ccam ಇನ್‌ಸ್ಟಾಲೇಶನ್ ಅನ್ನು ಪರಿಶೀಲಿಸುತ್ತದೆ: Claude Code ಬೈನರಿ, ಪ್ರತಿ ಖಾತೆಯ ಫೋಲ್ಡರ್, ಲಾಗಿನ್ ಮತ್ತು ಹಂಚಿಕೆ ಲಿಂಕ್‌ಗಳು, ಹಂಚಿಕೊಂಡ MCP ಸರ್ವರ್‌ಗಳು, ಬಳಕೆಯ ಎಂಡ್‌ಪಾಯಿಂಟ್ ಮತ್ತು ನಿಮ್ಮ ಶಾರ್ಟ್‌ಕಟ್ ಕಮಾಂಡ್‌ಗಳು. `ccam doctor --fix` ಡೇಟಾ ಕಳೆದುಕೊಳ್ಳದೆ ಸರಿಪಡಿಸಬಹುದಾದ್ದನ್ನು ಸರಿಪಡಿಸುತ್ತದೆ ಮತ್ತು ತಾನು ಬದಲಾಯಿಸುವ ಯಾವುದೇ ಫೈಲ್ ಅನ್ನು ಮೊದಲು ಬ್ಯಾಕಪ್ ಫೋಲ್ಡರ್‌ಗೆ ಸ್ಥಳಾಂತರಿಸುತ್ತದೆ. `ccam <name>` ಹಂಚಿಕೆ ಲಿಂಕ್ ಸಮಸ್ಯೆಯಿಂದ ನಿಂತಾಗ, ಫೈಲ್‌ಗಳನ್ನು ಕೈಯಾರೆ ಮರುಸ್ಥಾಪಿಸಿದ ನಂತರ, ಅಥವಾ Claude Code ಅಪ್‌ಡೇಟ್ ನಂತರ ಇದನ್ನು ರನ್ ಮಾಡಿ.

## ಬಳಕೆ

```sh
ccam doctor                  # check everything, change nothing
ccam doctor --fix            # check, then repair what is safe to repair
ccam --dry-run doctor --fix  # report only: what --fix would repair and set aside
```

ಮೊದಲ ಸಾಲು ಎಲ್ಲಾ ಖಾತೆಗಳನ್ನು ಒಮ್ಮೆಗೇ ಗುರುತಿಸುತ್ತದೆ, ಹೀಗಾಗಿ ಬೇರೆ ಏನನ್ನಾದರೂ ಓದುವ ಮೊದಲೇ ಸಮಸ್ಯೆಗಳು ಎಲ್ಲಿವೆ ಎಂದು ನೀವು ನೋಡುತ್ತೀರಿ. ಅದರ ಕೆಳಗೆ, ಪ್ರತಿ ಖಾತೆಗೆ ಒಂದು ಬಾಕ್ಸ್ ಇರುತ್ತದೆ, ಮತ್ತು ಯಾವುದೇ ಖಾತೆಗೆ ಸೇರದ ಫಲಿತಾಂಶಗಳು (Claude Code, ಪರಿಸರ ವೇರಿಯಬಲ್‌ಗಳು, ಪ್ಲಗಿನ್‌ಗಳು, MCP ಸರ್ವರ್‌ಗಳು, ಶಾರ್ಟ್‌ಕಟ್‌ಗಳು, ಫೋಲ್ಡರ್ ನಿಯಮಗಳು, ಗುಂಪುಗಳು ಮತ್ತು ಸೆಟ್ಟಿಂಗ್‌ಗಳು, `auto_switch`) `General` ಬಾಕ್ಸ್‌ಗೆ ಹೋಗುತ್ತವೆ. ಬಾಕ್ಸ್‌ನ ಶೀರ್ಷಿಕೆ ಖಾತೆಯ ಅತ್ಯಂತ ಕೆಟ್ಟ ಗುರುತನ್ನು ಮತ್ತು ಅದರಲ್ಲಿ ಎಷ್ಟು ಸಮಸ್ಯೆಗಳಿವೆ ಎಂಬುದನ್ನು ತೋರಿಸುತ್ತದೆ. ಒಳಗಿನ ಪ್ರತಿ ಸಾಲು ಪರಿಶೀಲಿಸಿದ ಒಂದು ಕ್ಷೇತ್ರ, ಯಾವಾಗಲೂ `Folder`, `Login` ಮತ್ತು `Share links` ಇದೇ ಕ್ರಮದಲ್ಲಿ, ನಂತರ ಇತರವು, ಒಂದು ಗುರುತಿನೊಂದಿಗೆ: `✔` ಸರಿ, `ℹ` ಮಾಹಿತಿ, `⚠` ಎಚ್ಚರಿಕೆ, `✘` ದೋಷ. ಯಾವುದೇ ತೊಂದರೆ ಇಲ್ಲದ ಫೋಲ್ಡರ್ `✔ Folder  OK` ಎಂದು ತೋರಿಸುತ್ತದೆ.

ಟರ್ಮಿನಲ್‌ನಲ್ಲಿ, ಬಾಕ್ಸ್‌ಗಳು ಟರ್ಮಿನಲ್‌ನ ಅಗಲಕ್ಕೆ ಹೊಂದಿಕೊಳ್ಳುತ್ತವೆ, ಉದ್ದದ ಸಂದೇಶಗಳು ಮುಂದಿನ ಸಾಲಿಗೆ ಸುತ್ತುತ್ತವೆ ಮತ್ತು ಟರ್ಮಿನಲ್‌ನ ಸ್ವಂತ ಬಣ್ಣಗಳನ್ನು ಬಳಸಲಾಗುತ್ತದೆ (`NO_COLOR` ಅವನ್ನು ಆಫ್ ಮಾಡುತ್ತದೆ). ಬಾಕ್ಸ್ ಎಂದಿಗೂ 29 ಕಾಲಮ್‌ಗಳಿಗಿಂತ ಕಿರಿದಾಗಿರುವುದಿಲ್ಲ, ಹೀಗಾಗಿ ಕಿರಿದಾದ ಟರ್ಮಿನಲ್‌ನಲ್ಲಿ ಯಾವುದೇ ಪದ ಕತ್ತರಿಸಲ್ಪಡುವುದಿಲ್ಲ. ಪೈಪ್ ಅಥವಾ ಫೈಲ್‌ಗೆ ಕಳುಹಿಸಿದಾಗ, ಔಟ್‌ಪುಟ್‌ನಲ್ಲಿ ಬಣ್ಣಗಳಿರುವುದಿಲ್ಲ ಮತ್ತು ಯಾವುದೇ ಸಂದೇಶವನ್ನು ಸುತ್ತಲಾಗುವುದಿಲ್ಲ ಅಥವಾ ಕತ್ತರಿಸಲಾಗುವುದಿಲ್ಲ, ಹೀಗಾಗಿ `ccam doctor | grep settings.json` ಪೂರ್ಣ ಸಾಲನ್ನು ಕಂಡುಹಿಡಿಯುತ್ತದೆ; ಆಗ ಪ್ರತಿ ಬಾಕ್ಸ್ ಅತಿ ಉದ್ದದ ಸಾಲಿನಷ್ಟು ಅಗಲವಾಗಿರುತ್ತದೆ. ಡ್ಯಾಶ್‌ಬೋರ್ಡ್‌ನ Health ಟ್ಯಾಬ್ ಇದೇ ಬಾಕ್ಸ್‌ಗಳನ್ನು ತೋರಿಸುತ್ತದೆ.

## ಆಯ್ಕೆಗಳು

| ಆಯ್ಕೆ | ಏನು ಮಾಡುತ್ತದೆ | ಡೀಫಾಲ್ಟ್ |
| --- | --- | --- |
| `--fix` | ಸುರಕ್ಷಿತವಾಗಿ ಸರಿಪಡಿಸಬಹುದಾದ್ದನ್ನು ಸರಿಪಡಿಸುತ್ತದೆ (ಬದಲಾದ ಫೈಲ್‌ಗಳ ಬ್ಯಾಕಪ್ ತೆಗೆದುಕೊಳ್ಳಲಾಗುತ್ತದೆ) | ಆಫ್ |
| `--dry-run` (ಜಾಗತಿಕ) | ಎಲ್ಲಾ ಪರಿಶೀಲನೆಗಳನ್ನು ನಡೆಸುತ್ತದೆ ಆದರೆ `--fix` ಇದ್ದರೂ ಏನನ್ನೂ ಸರಿಪಡಿಸುವುದಿಲ್ಲ | ಆಫ್ |

`ccam doctor` ಯಾವುದೇ ಆರ್ಗ್ಯುಮೆಂಟ್ ತೆಗೆದುಕೊಳ್ಳುವುದಿಲ್ಲ. ಇದು `--dry-run` ಅನ್ನು ಬೆಂಬಲಿಸುತ್ತದೆ: `ccam --dry-run doctor --fix` `ccam doctor` ನ ಫಲಿತಾಂಶಗಳನ್ನು ಮುದ್ರಿಸುತ್ತದೆ, `--fix` ಏನನ್ನು ಪಕ್ಕಕ್ಕೆ ಇಡುತ್ತದೆ ಎಂಬುದನ್ನು ಸೇರಿಸುತ್ತದೆ, ಮತ್ತು ಏನನ್ನೂ ಬದಲಾಯಿಸುವುದಿಲ್ಲ:

```text
ℹ settings.json differs from the group's copy: --fix would use the group's, and move this account's copy to /home/me/.local/share/ccam/profiles/personal/.ccam-backup/20261023-212543/settings.json
```

ಕನಿಷ್ಠ ಒಂದು `✘` ಫಲಿತಾಂಶ ಸರಿಪಡಿಸದೆ ಉಳಿದಾಗ ಎಕ್ಸಿಟ್ ಕೋಡ್ `1`, ಇಲ್ಲದಿದ್ದರೆ `0`. ಎಚ್ಚರಿಕೆಗಳು ಮತ್ತು ಮಾಹಿತಿ ಎಂದಿಗೂ ರನ್ ಅನ್ನು ವಿಫಲಗೊಳಿಸುವುದಿಲ್ಲ. `--fix` ಇಲ್ಲದೆ ರನ್ ವಿಫಲವಾದಾಗ, ccam ಒಂದು ಖಾಲಿ ಸಾಲು ಮತ್ತು `` `ccam doctor --fix` repairs what it can. `` ನೊಂದಿಗೆ ಕೊನೆಗೊಳ್ಳುತ್ತದೆ. ಲೋಡ್ ಮಾಡಲಾಗದ ಕಾನ್ಫಿಗ್ ಕೂಡ `1` ಮತ್ತು ಒಂದು `ccam:` ದೋಷದೊಂದಿಗೆ ಕೊನೆಗೊಳ್ಳುತ್ತದೆ.

## ಇದು ಹೇಗೆ ಕೆಲಸ ಮಾಡುತ್ತದೆ

ಪರಿಶೀಲನೆಗಳು ನಿಗದಿತ ಕ್ರಮದಲ್ಲಿ ನಡೆಯುತ್ತವೆ, ಮತ್ತು ಫಲಿತಾಂಶಗಳು ಪ್ರತಿ ಖಾತೆಗೆ ಒಂದು ಬಾಕ್ಸ್‌ನಲ್ಲಿ ಕಾಣುತ್ತವೆ. ccam `~/.config/ccam/config.toml` ಅನ್ನು ಲೋಡ್ ಮಾಡಿ (`internal/cli/doctor.go`) ಪರಿಶೀಲನೆಗಳನ್ನು ನಡೆಸುತ್ತದೆ; ಪ್ರತಿ ಫಲಿತಾಂಶವೂ ಅದು ಸೇರಿದ ಖಾತೆ ಮತ್ತು ಅದು ಪರಿಶೀಲಿಸಿದ ಕ್ಷೇತ್ರವನ್ನು ಹೆಸರಿಸುತ್ತದೆ (`internal/doctor/doctor.go` ನಲ್ಲಿರುವ `doctor.Run`). ನಂತರ ಅದು ಫಲಿತಾಂಶಗಳನ್ನು ಬಾಕ್ಸ್‌ಗಳಾಗಿ ಗುಂಪು ಮಾಡುತ್ತದೆ (`tui.HealthReport`). `--fix` ಅನ್ನು `Options.Fix` ಆಗಿ ರವಾನಿಸಲಾಗುತ್ತದೆ, ಡ್ರೈ ರನ್‌ನಲ್ಲಿ ಇದು false ಆಗಿರುತ್ತದೆ.

ಮಧ್ಯದ ಭಾಗ ಪ್ರತಿ ಖಾತೆಗೆ ಒಮ್ಮೆ ನಡೆಯುತ್ತದೆ. ಪರಿಶೀಲನೆಗಳು, ಮತ್ತು ಪ್ರತಿಯೊಂದಕ್ಕೂ `--fix` ಏನು ಮಾಡುತ್ತದೆ:

1. **Claude Code ಆವೃತ್ತಿ** (`checkClaude`). ಲಾಂಚರ್ ಮಾಡುವಂತೆಯೇ `claude` ಬೈನರಿಯನ್ನು ಕಂಡುಹಿಡಿದು `claude --version` ರನ್ ಮಾಡುತ್ತದೆ. ಬೈನರಿ ಇಲ್ಲದಿರುವುದು, ಕಾರ್ಯಗತಗೊಳಿಸಬಹುದಾದ ಫೈಲ್ ಅಲ್ಲದ `claude_bin`, ಅಥವಾ `--version` ವಿಫಲವಾಗುವುದು ದೋಷ. ಸರಿಪಡಿಕೆ ಇಲ್ಲ.
2. **ಪರಿಸರದಲ್ಲಿರುವ ಕ್ರೆಡೆನ್ಶಿಯಲ್‌ಗಳು** (`checkAuthEnv`). `CLAUDE_CODE_OAUTH_TOKEN`, `ANTHROPIC_API_KEY` ಅಥವಾ `ANTHROPIC_AUTH_TOKEN` ಹೊಂದಿಸಿದ್ದಾಗ ಎಚ್ಚರಿಸುತ್ತದೆ: ಆ ಶೆಲ್‌ನಿಂದ ಆರಂಭಿಸಿದ ಪ್ರತಿ ಖಾತೆಯೂ ಅದನ್ನು ಪಡೆಯುತ್ತದೆ, ಮತ್ತು Claude Code ಖಾತೆಯ ಸ್ವಂತ ಲಾಗಿನ್‌ಗಿಂತ ಅದಕ್ಕೇ ಆದ್ಯತೆ ನೀಡುತ್ತದೆ. ಸರಿಪಡಿಕೆ ಇಲ್ಲ; ಅದನ್ನು ನೀವೇ ತೆಗೆದುಹಾಕಿ.
3. **ಫೋಲ್ಡರ್** (`checkProfile`). ಖಾತೆಯ ಫೋಲ್ಡರ್ ಇಲ್ಲದಿರುವುದು ದೋಷ, ಮತ್ತು ಅದರೊಂದಿಗೆ ಆ ಖಾತೆಯ ಪರಿಶೀಲನೆಗಳು ಮುಗಿಯುತ್ತವೆ. ಗುಂಪು ಅಥವಾ ಇತರರ ಯಾವುದೇ ಬಿಟ್ ಹೊಂದಿಸಿದ ಅನುಮತಿಗಳು ಎಚ್ಚರಿಕೆ; `--fix` `chmod 0700` ರನ್ ಮಾಡುತ್ತದೆ. `~/.claude.json` ನ ಪಕ್ಕದಲ್ಲಿ ತನ್ನದೇ `.claude.json` ಇರುವ ಇಂಪೋರ್ಟ್ ಮಾಡಿದ `~/.claude` ಮಾಹಿತಿ: ಆಗ `ccam main` ಮತ್ತು ಸಾಮಾನ್ಯ `claude` ಪ್ರತ್ಯೇಕ ಲಾಗಿನ್ ವಿವರಗಳು ಮತ್ತು MCP ಸರ್ವರ್‌ಗಳನ್ನು ಇಟ್ಟುಕೊಳ್ಳುತ್ತವೆ. Windows ನಲ್ಲಿ ಅನುಮತಿ ಬಿಟ್‌ಗಳು ಇಲ್ಲ, ಆದ್ದರಿಂದ ಅಲ್ಲಿ ಈ ಪರಿಶೀಲನೆ ಮತ್ತು ಕೆಳಗಿನ `0600` ಪರಿಶೀಲನೆಯನ್ನು ಬಿಟ್ಟುಬಿಡಲಾಗುತ್ತದೆ; ನಿಮ್ಮ ಬಳಕೆದಾರ ಪ್ರೊಫೈಲ್‌ನಲ್ಲಿರುವ ಫೋಲ್ಡರ್ ಅನ್ನು ಅದರ ಪ್ರವೇಶ ಪಟ್ಟಿ (access list) ರಕ್ಷಿಸುತ್ತದೆ.
4. **ಲಾಗಿನ್ ಫೈಲ್** (`checkCredentials`). `.credentials.json` ಅನ್ನು `lstat` ಮೂಲಕ ಪರಿಶೀಲಿಸಲಾಗುತ್ತದೆ. ಸಿಮ್‌ಲಿಂಕ್ ದೋಷ, ಏಕೆಂದರೆ ಪ್ರತಿ ಖಾತೆಗೂ ತನ್ನದೇ ಟೋಕನ್ ಇರಬೇಕು, ಮತ್ತು ಅದನ್ನು ಸರಿಪಡಿಸಲಾಗುವುದಿಲ್ಲ. `0600` ಅಲ್ಲದ ಮೋಡ್ ಎಚ್ಚರಿಕೆ; `--fix` `chmod 0600` ರನ್ ಮಾಡುತ್ತದೆ.

   ನಂತರ ಲಾಗಿನ್ ಅನ್ನು ಓದಲಾಗುತ್ತದೆ (macOS ನಲ್ಲಿ ಮೊದಲು Keychain ನಿಂದ). ಲಾಗಿನ್ ಇಲ್ಲದಿದ್ದರೆ, ಅಥವಾ ಲಾಗಿನ್ ಫೈಲ್‌ನಲ್ಲಿ ಯಾವುದೇ ಲಾಗಿನ್ ಇಲ್ಲದಿದ್ದರೆ, ಅದು `ccam login <name>` ಅನ್ನು ಸೂಚಿಸುವ ಎಚ್ಚರಿಕೆ. ಅವಧಿ ಮುಗಿದ ರಿಫ್ರೆಶ್ ಟೋಕನ್, ಅಥವಾ ಸರ್ವರ್ ನಿರಾಕರಿಸಿದ ನಂತರ Claude Code ತೆರವುಗೊಳಿಸಿದ ಲಾಗಿನ್, `` login expired → `ccam login <name>` `` ದೋಷ; ಅವಧಿ ಮುಗಿದ ಆಕ್ಸೆಸ್ ಟೋಕನ್ ಕೇವಲ ಮಾಹಿತಿ, ಏಕೆಂದರೆ ಮುಂದಿನ ಆರಂಭದಲ್ಲಿ Claude Code ಅದನ್ನು ನವೀಕರಿಸುತ್ತದೆ. Windows Credential Manager ನಲ್ಲಿ ಇಟ್ಟ ಲಾಗಿನ್ ಮಾಹಿತಿ, ಏಕೆಂದರೆ ccam ಅದನ್ನು ಓದಲಾರದು. ಮಾನ್ಯ ಲಾಗಿನ್ ಫೋಲ್ಡರ್ ಈಗ ಲಾಗಿನ್ ಆಗಿರುವ ಇಮೇಲ್ ಮತ್ತು ಪ್ಲಾನ್ ಅನ್ನು ತೋರಿಸುತ್ತದೆ (`login valid (dev@company.com, Claude Team · Acme)`). ಇವುಗಳಲ್ಲಿ ಯಾವುದನ್ನೂ ಸರಿಪಡಿಸಲಾಗುವುದಿಲ್ಲ; `ccam login --expired` ಅಗತ್ಯವಿರುವ ಪ್ರತಿ ಖಾತೆಗೂ ಲಾಗಿನ್ ಮಾಡುತ್ತದೆ.
5. **ಹಂಚಿಕೆ ಲಿಂಕ್‌ಗಳು** (`share.Check`). `share.Layout` ನಲ್ಲಿನ ಪ್ರತಿ ಪಾತ್ ಅನ್ನು ಖಾತೆಯ ಗುಂಪುಗಳೊಂದಿಗೆ ಹೋಲಿಸುತ್ತದೆ, `lstat` ಮತ್ತು `readlink` ಮಾತ್ರ ಬಳಸಿ. ಇದು ಐದು ಬಗೆಯ ಸಮಸ್ಯೆಗಳನ್ನು ವರದಿ ಮಾಡುತ್ತದೆ: ಇಲ್ಲದ ಲಿಂಕ್, ಬೇರೆಡೆ ತೋರಿಸುವ ಲಿಂಕ್, ಲಿಂಕ್ ಇರಬೇಕಾದಲ್ಲಿ ನಿಜವಾದ ಫೈಲ್, ಈಗ ಸ್ಥಳೀಯವಾಗಿರುವ ಐಟಂಗಾಗಿ ಉಳಿದ ಲಿಂಕ್, ಮತ್ತು ಗುಂಪಿನ ಫೋಲ್ಡರ್ ಇಲ್ಲದ ಸರಿಯಾದ ಲಿಂಕ್ (`the group folder it links to is missing (…), so Claude Code cannot save there (ccam doctor --fix makes it)`; ಆರಂಭ ಇದನ್ನು ಪರಿಶೀಲಿಸುವುದಿಲ್ಲ). ಇಲ್ಲದ ಲಿಂಕ್ ಮತ್ತು ಇಲ್ಲದ ಗುಂಪಿನ ಫೋಲ್ಡರ್ ಎಚ್ಚರಿಕೆಗಳು, ಉಳಿದವು ದೋಷಗಳು.

   ಗುಂಪಿನಿಂದ ಮರಳಿ ನಕಲಿಸುವಿಕೆ ಅರ್ಧದಲ್ಲಿ ನಿಂತಿದ್ದರೆ ಅದನ್ನೂ ವರದಿ ಮಾಡಲಾಗುತ್ತದೆ: `--fix` ಸಿದ್ಧಪಡಿಸಿದ ಸಂಪೂರ್ಣ ಪ್ರತಿಯನ್ನು ಜಾಗದಲ್ಲಿ ಇರಿಸುತ್ತದೆ, ಆದರೆ ಅಂದಿನಿಂದ ಒಂದು ಆರಂಭ ಆ ಪಾತ್ ಅನ್ನು ಮರುರಚಿಸಿದ್ದರೆ, ನೀವೇ ಬಗೆಹರಿಸಲು ಸಂಪೂರ್ಣ ಪ್ರತಿ ಇರುವ ಫೋಲ್ಡರ್ ಅನ್ನು ಅದು ಹೆಸರಿಸುತ್ತದೆ. ccam ನ ನಂತರದ ಆವೃತ್ತಿಯಲ್ಲಿ ಒಂದು ಐಟಂಗೆ ಸೇರಿಸಿದ ಪಾತ್‌ಗಳು (history ಗೆ `file-history/`, `tasks/` ಮತ್ತು `paste-cache/`, settings ಗೆ `keybindings.json`) ಖಾತೆಯ ಬಳಿ ಇನ್ನೂ ತನ್ನದೇ ಪ್ರತಿ ಇರುವವರೆಗೆ ಕೇವಲ ಎಚ್ಚರಿಕೆ: `is not shared with the group yet (ccam doctor --fix shares it; if the group has its own copy, that one is kept and this one backed up)`. ಅವುಗಳಿಗಾಗಿ ಆರಂಭ ಎಂದಿಗೂ ನಿಲ್ಲುವುದಿಲ್ಲ.
6. **ಅಪರಿಚಿತ ನಮೂದುಗಳು** (`checkUnknownEntries`). ccam ಗೆ ತಿಳಿಯದ (`share.Known`) ಖಾತೆಯ ಫೋಲ್ಡರ್‌ನ ಮೇಲ್ಮಟ್ಟದ ಹೆಸರುಗಳನ್ನು, Claude Code ವಿನ್ಯಾಸ ಬದಲಾಗಿದೆ ಎಂಬ ಸುಳಿವಾಗಿ ಪಟ್ಟಿ ಮಾಡುತ್ತದೆ. ಕೇವಲ ಮಾಹಿತಿ.
7. **ಪ್ಲಗಿನ್ ಪಾತ್‌ಗಳು** (`checkPlugins`). ಪ್ಲಗಿನ್ ರಿಜಿಸ್ಟ್ರಿಗಳು (`installed_plugins.json`, `known_marketplaces.json`) ಸಂಪೂರ್ಣ ಪಾತ್‌ಗಳನ್ನು ಸಂಗ್ರಹಿಸುತ್ತವೆ. ಪ್ರತಿ ಗುಂಪಿನ `plugins/` ನಲ್ಲಿ, ಒಂದು ಖಾತೆಯ ಫೋಲ್ಡರ್ ಮೂಲಕ ಹಾದುಹೋಗುವ ಪಾತ್‌ಗಳು ಆ ಖಾತೆಯನ್ನು ತೆಗೆದುಹಾಕಿದಾಗ ಅಥವಾ ಮರುಹೆಸರಿಸಿದಾಗ ಮುರಿಯುತ್ತವೆ. `--fix` ಅವುಗಳನ್ನು `profile.RewritePluginPaths` ಮೂಲಕ ಗುಂಪಿನ ಫೋಲ್ಡರ್‌ಗೆ ಮರುಬರೆಯುತ್ತದೆ; ಇದು ರಿಜಿಸ್ಟ್ರಿ ಫೈಲ್‌ನ ಅಟಾಮಿಕ್ ಬರಹ.
8. **MCP ಸರ್ವರ್‌ಗಳು** (`checkMCP`). ಪ್ರತಿ ಗುಂಪಿನ `mcp.json` ಅನ್ನು ಒಮ್ಮೆ ಲೋಡ್ ಮಾಡುತ್ತದೆ. ಓದಲಾಗದ ಫೈಲ್ ದೋಷ; `mcp.Validate` ನಲ್ಲಿ ವಿಫಲವಾಗುವ ಸರ್ವರ್ ಎಚ್ಚರಿಕೆ. ಸಾಮಾನ್ಯ `claude` ನ `~/.claude.json` ನಲ್ಲಿದ್ದು ಯಾವ ಖಾತೆಯೂ ಲೋಡ್ ಮಾಡದ ಸರ್ವರ್‌ಗಳು ಎಚ್ಚರಿಕೆ, ಅವುಗಳನ್ನು ನಕಲಿಸುವ `ccam migrate --mcp` ಕಮಾಂಡ್‌ನೊಂದಿಗೆ (ಹಲವು ಗುಂಪುಗಳು MCP ಹಂಚಿಕೊಂಡಾಗ `--group <a|b>` ಜೊತೆ). ಗುಂಪಿನ ಒಂದೇ ಖಾತೆಯಲ್ಲಿ ಮಾತ್ರ ಇರುವ ಸರ್ವರ್‌ಗಳು ಮಾಹಿತಿ, ಅವುಗಳನ್ನು ಹಂಚಿಕೊಳ್ಳುವ `ccam mcp import` ಕಮಾಂಡ್‌ನೊಂದಿಗೆ; ಮತ್ತು ಇತರ ಖಾತೆಗಳು ಸೈನ್ ಇನ್ ಆಗಿರುವ MCP ಸರ್ವರ್‌ಗಳಿಗೆ ಸೈನ್ ಇನ್ ಆಗಿರದ ಖಾತೆಗೆ `/mcp` ಮೂಲಕ ಸೈನ್ ಇನ್ ಆಗುವಂತೆ ಎಚ್ಚರಿಕೆ ಸಿಗುತ್ತದೆ (ccam ಎಂದಿಗೂ ಸೈನ್-ಇನ್‌ಗಳನ್ನು ನಕಲಿಸುವುದಿಲ್ಲ). ಸರಿಪಡಿಕೆ ಇಲ್ಲ.
9. **ಬಳಕೆಯ ಉತ್ತರದ ಸ್ವರೂಪ** (`checkUsageFormat`). ಕ್ಯಾಶ್ ಇಲ್ಲದೆ, ಒಂದು ಖಾತೆ ಉತ್ತರಿಸುವವರೆಗೆ ಒಂದರ ನಂತರ ಒಂದು ಖಾತೆಗೆ ಬಳಕೆಯ ಎಂಡ್‌ಪಾಯಿಂಟ್ ಅನ್ನು ಕೇಳುತ್ತದೆ, ಎಲ್ಲವೂ ಒಂದೇ 4 ಸೆಕೆಂಡ್ ಟೈಮ್‌ಔಟ್‌ನೊಳಗೆ. `usage_source = "claude"` ಇದ್ದರೆ, ಬದಲಿಗೆ ಅದು ಒಂದು ಖಾತೆಗಾಗಿ Claude Code ಅನ್ನು ಕೇಳುತ್ತದೆ. ಉತ್ತರ ಇನ್ನು ಪಾರ್ಸ್ ಆಗದಿದ್ದರೆ, `ccam usage` ಸ್ಟೇಟಸ್ ಲೈನ್ ಕ್ಯಾಶ್‌ಗೆ ಹಿಂದಿರುಗುತ್ತದೆ ಎಂದು ಎಚ್ಚರಿಸುತ್ತದೆ; ಯಾವ ಖಾತೆಯೂ ಉತ್ತರಿಸದಿದ್ದಾಗ, ಅದನ್ನು ಮಾಹಿತಿಯಾಗಿ ತಿಳಿಸುತ್ತದೆ (`could not check the usage response format: …`). ನೆಟ್‌ವರ್ಕ್ ಬಳಸುವ ಏಕೈಕ ಪರಿಶೀಲನೆ ಇದು.
10. **ಶಾರ್ಟ್‌ಕಟ್‌ಗಳು** (`checkShims`). ಯಾವುದಾದರೂ ಖಾತೆಗೆ ಶಾರ್ಟ್‌ಕಟ್ ಇದ್ದಾಗ ಮಾತ್ರ. `~/.local/bin` ನಲ್ಲಿ ಇಲ್ಲದ ಲಿಂಕ್‌ಗಳು ಎಚ್ಚರಿಕೆ, ಮತ್ತು ccam ರಚಿಸಿದ, ಇನ್ನೂ ccam ನ ಹಳೆಯ ಆವೃತ್ತಿಯನ್ನು (ಬದಲಾಯಿಸಿದ ಅಥವಾ ಸ್ಥಳಾಂತರಿಸಿದ ಒಂದನ್ನು) ರನ್ ಮಾಡುವ ಶಾರ್ಟ್‌ಕಟ್‌ಗಳೂ ಎಚ್ಚರಿಕೆ (`shortcuts in <bin> that run another ccam (one replaced or moved): …`); `--fix` `shim.Install` ಅನ್ನು ಕರೆಯುತ್ತದೆ, ಅದು ccam ರಚಿಸಿ `~/.local/state/ccam/shortcuts.json` ನಲ್ಲಿ ದಾಖಲಿಸಿದ ಲಿಂಕ್‌ಗಳನ್ನು ಮಾತ್ರ ರಚಿಸುತ್ತದೆ ಮತ್ತು ನವೀಕರಿಸುತ್ತದೆ, ಮತ್ತು ಇತರ ಫೈಲ್‌ಗಳನ್ನು ಎಂದಿಗೂ ಮುಟ್ಟುವುದಿಲ್ಲ. ಆ ಪ್ರತಿಯೊಂದು ಲಿಂಕ್ ರಚನೆಯಾದಾಗ ಮಾತ್ರ ಎಚ್ಚರಿಕೆ `→ fixed` ನಿಂದ ಕೊನೆಗೊಳ್ಳುತ್ತದೆ; ಒಂದನ್ನು ರಚಿಸಲಾಗದಿದ್ದರೆ, ಕಾರಣವನ್ನು ಸೇರಿಸಲಾಗುತ್ತದೆ. ಇನ್ನೂ ಇನ್‌ಸ್ಟಾಲ್ ಆಗಿರುವ ಇನ್ನೊಂದು ccam ಅನ್ನು ರನ್ ಮಾಡುವ ಶಾರ್ಟ್‌ಕಟ್ ಕೆಲಸ ಮಾಡುತ್ತದೆ, ಆದ್ದರಿಂದ `ccam doctor` ಅದನ್ನು ಮಾಹಿತಿಯಾಗಿ ಮಾತ್ರ ಪಟ್ಟಿ ಮಾಡುತ್ತದೆ; `--fix` ಅದನ್ನು ಈ ccam ಬೈನರಿಯ ಕಡೆಗೆ ತೋರಿಸುತ್ತದೆ. `PATH` ನಲ್ಲಿ ಇಲ್ಲದ bin ಫೋಲ್ಡರ್ ಎಚ್ಚರಿಕೆ ಮತ್ತು ಅದನ್ನು ಸರಿಪಡಿಸಲಾಗುವುದಿಲ್ಲ.
11. **ಫೋಲ್ಡರ್‌ಗಳು** (`checkFolders`). [`ccam folder`](/features/folder) ನಮೂದುಗಳು ಇದ್ದಾಗ ಮಾತ್ರ. ಖಾತೆ ಅಸ್ತಿತ್ವದಲ್ಲಿಲ್ಲದ ನಮೂದು ದೋಷ, ಮತ್ತು ಫೋಲ್ಡರ್ ಇಲ್ಲವಾದ ನಮೂದು ಎಚ್ಚರಿಕೆ. ಯಾವುದನ್ನೂ ಸರಿಪಡಿಸಲಾಗುವುದಿಲ್ಲ, ಏಕೆಂದರೆ ನಮೂದನ್ನು ತೆಗೆದುಹಾಕಿದರೆ ಅಲ್ಲಿ ಯಾವ ಖಾತೆ ಆರಂಭವಾಗುತ್ತದೆ ಎಂಬುದು ಬದಲಾಗುತ್ತದೆ.
12. **ಗುಂಪುಗಳು ಮತ್ತು ಸೆಟ್ಟಿಂಗ್‌ಗಳು** (`checkGroups`). ಖಾತೆಯಲ್ಲದ ಗುಂಪಿನ ಸದಸ್ಯ, ಹೆಸರು ನಂತರ ccam ಕಮಾಂಡ್ ಆಗಿಬಿಟ್ಟ ಖಾತೆ (ಅದನ್ನು `ccam run <name>` ಮೂಲಕ ಆರಂಭಿಸಿ ಅಥವಾ ಮರುಹೆಸರಿಸಿ), ಅಪರಿಚಿತ `theme` ಅಥವಾ `usage_source`, ಮತ್ತು ccam ಓದದ `config.toml` ನ ಸಾಲುಗಳು ಎಚ್ಚರಿಕೆಗಳು. ಕೊನೆಯ ಬಗೆ ಸಾಮಾನ್ಯವಾಗಿ `[[group]]`, `[[profile]]` ಅಥವಾ `[[folder]]` ಟೇಬಲ್‌ನ ಕೆಳಗೆ ಇರಿಸಿದ ಸೆಟ್ಟಿಂಗ್ ಆಗಿರುತ್ತದೆ, ಅದು ಅದನ್ನು ಆ ಟೇಬಲ್‌ನ ಭಾಗವನ್ನಾಗಿಸುತ್ತದೆ (`config.toml line 43: relay is read as part of the [profile.login] table above it; settings for all accounts go above the first [[group]], [[profile]] or [[folder]]`); ಅದನ್ನು ಸರಿಪಡಿಸುವವರೆಗೆ ಕಾನ್ಫಿಗ್ ಅನ್ನು ಬದಲಾಯಿಸುವ ಕಮಾಂಡ್‌ಗಳು ನಿರಾಕರಿಸುತ್ತವೆ. ಸರಿಪಡಿಕೆ ಇಲ್ಲ.
13. **ಲಾಗಿನ್‌ಗಳು** (`checkIdentities`). ಪ್ರತಿ ಫೋಲ್ಡರ್ ಯಾರಾಗಿ ಲಾಗಿನ್ ಆಗಿದೆ ಎಂಬುದನ್ನು ಅದರ `.claude.json` ನಿಂದ ಓದುತ್ತದೆ. `ccam login` ದಾಖಲಿಸಿದ ಖಾತೆಗಿಂತ ಬೇರೆ ಖಾತೆಗೆ ಈಗ ಲಾಗಿನ್ ಆಗಿರುವ ಫೋಲ್ಡರ್ (ಉದಾಹರಣೆಗೆ ಸೆಷನ್‌ನೊಳಗೆ `/login` ನಂತರ) ಎಚ್ಚರಿಕೆ; ಲಾಗಿನ್ ದಾಖಲೆ ಇಲ್ಲದ ಖಾತೆಯನ್ನು, ಉದಾಹರಣೆಗೆ ಇಂಪೋರ್ಟ್ ಮಾಡಿದ ಅಥವಾ ccam ನ ಹಳೆಯ ಆವೃತ್ತಿ ರಚಿಸಿದ ಖಾತೆಯನ್ನು, ಅದರ ದಾಖಲಿತ ಇಮೇಲ್ ಮೂಲಕ ಹೋಲಿಸಲಾಗುತ್ತದೆ. ಇನ್ನೊಂದು ಫೋಲ್ಡರ್‌ನ ಅದೇ Claude ಖಾತೆಗೆ ಲಾಗಿನ್ ಆಗಿರುವ ಫೋಲ್ಡರ್ ಕೂಡ ಎಚ್ಚರಿಕೆ: ಅವೆರಡೂ ತಮ್ಮ ಬಳಕೆಯ ಮಿತಿಗಳನ್ನು ಹಂಚಿಕೊಳ್ಳುತ್ತವೆ. ಇನ್ನೊಂದರ ಅದೇ ಲಾಗಿನ್ ಟೋಕನ್ ಹೊಂದಿರುವ ಫೋಲ್ಡರ್, ಅಂದರೆ ನಕಲಿಸಿದ ಫೋಲ್ಡರ್ (ಸಾಮಾನ್ಯ `claude` ನ `~/.claude` ಸೇರಿದಂತೆ), ದೋಷ, ಏಕೆಂದರೆ ಯಾವುದು ಮೊದಲು ಅದನ್ನು ನವೀಕರಿಸುತ್ತದೋ ಅದು ಇನ್ನೊಂದನ್ನು ಲಾಗ್ ಔಟ್ ಮಾಡುತ್ತದೆ; ಅದಕ್ಕೆ ತನ್ನದೇ ಲಾಗಿನ್ ನೀಡಲು `ccam login <name>` ರನ್ ಮಾಡಿ. ಸರಿಪಡಿಕೆ ಇಲ್ಲ.
14. **`auto_switch`** (`checkAutoSwitch`). `auto_switch = true` ಇದ್ದಾಗ ಮಾತ್ರ. `General` ಬಾಕ್ಸ್‌ನಲ್ಲಿನ ಮಾಹಿತಿ `auto_switch` ಏನು ಮಾಡುತ್ತದೆ ಎಂದು ಹೇಳುತ್ತದೆ ಮತ್ತು [ಅದರ ವಿವರಣೆಗೆ](/features/next#auto-switch) ಲಿಂಕ್ ನೀಡುತ್ತದೆ. ಖಾತೆಗಳ ನಡುವೆ ಸೀಟುಗಳಿರುವ ಪ್ರತಿ ಪ್ಲಾನ್‌ಗೆ (Claude Team, Claude Enterprise), ಒಂದು ಸಾಲು ಅವುಗಳನ್ನು ಹೆಸರಿಸುತ್ತದೆ, `auto_switch` ಒಂದು ಸಂಸ್ಥೆಯ ಸೀಟುಗಳ ನಡುವೆ ಸೆಷನ್ ಅನ್ನು ಸ್ಥಳಾಂತರಿಸುತ್ತದೆ ಎಂದು ಹೇಳುತ್ತದೆ, ಸಹಾಯ ಕೇಂದ್ರದ ಲಿಂಕ್‌ನೊಂದಿಗೆ Anthropic ನ ಸೀಟು ನಿಯಮವನ್ನು ಉಲ್ಲೇಖಿಸುತ್ತದೆ, ಮತ್ತು ಆಯ್ಕೆಯನ್ನು ನಿಮಗೆ ಬಿಡುತ್ತದೆ. ಹುಕ್‌ಗಳಿಗೆ ತಮ್ಮ ಪ್ರೊಸೆಸ್ (`CLAUDE_PID`) ಅನ್ನು ತಿಳಿಸದ, 2.1.214 ಕ್ಕಿಂತ ಹಳೆಯ Claude Code ಆವೃತ್ತಿಗಳು ಅಲ್ಲಿ ಎಚ್ಚರಿಕೆ, ಏಕೆಂದರೆ ಯಾವುದೇ ಸೆಷನ್ ಅನ್ನು ಸ್ಥಳಾಂತರಿಸಲು ಆಗುವುದಿಲ್ಲ.

    ccam ಪ್ಲಗಿನ್ ಇಲ್ಲದ, ಅಥವಾ ಪ್ಲಗಿನ್ ಆಫ್ ಆಗಿರುವ ಖಾತೆಗೆ ಅದರ ಸ್ವಂತ ಬಾಕ್ಸ್‌ನಲ್ಲಿ ಎಚ್ಚರಿಕೆ ಸಿಗುತ್ತದೆ, Claude Code ನಲ್ಲಿ ಅದನ್ನು ಸರಿಪಡಿಸುವ ಕಮಾಂಡ್‌ನೊಂದಿಗೆ: `auto_switch is on, but work does not have the ccam plugin, so its sessions are not moved. In Claude Code as work: /plugin install ccam --marketplace jhyunwoo/ccam` (ಅಥವಾ `/plugin enable ccam@ccam`). API ಕೀ ಖಾತೆಗಳನ್ನು ಬಿಡಲಾಗುತ್ತದೆ. Windows ನಲ್ಲಿ ಇರುವ ಏಕೈಕ ಸಾಲು `auto_switch is ignored on Windows; with relay = true, /ccam:switch followed by /exit still moves a conversation to another account.`. ಸರಿಪಡಿಕೆ ಇಲ್ಲ.

ಖಾತೆಗಳಿಗಿಂತ ಮೊದಲು, ಅರ್ಧದಲ್ಲಿ ನಿಂತ **ಗುಂಪು ಬದಲಾವಣೆ** `General` ಬಾಕ್ಸ್‌ನಲ್ಲಿ ದೋಷವಾಗಿರುತ್ತದೆ: ``the last group change stopped halfway (ccam doctor --fix finishes it; noted in ~/.local/state/ccam/group-change.json)``. `--fix` ಅದನ್ನು ಯೋಜಿಸಿದ ಕ್ರಮದಲ್ಲಿ, ಅದರ ಸಂಘರ್ಷಗಳಿಗೆ ನೀಡಿದ ಉತ್ತರಗಳೊಂದಿಗೆ ಪೂರ್ಣಗೊಳಿಸುತ್ತದೆ; ಅಲ್ಲಿಯವರೆಗೆ ಬೇರೆ ಯಾವುದೇ ಗುಂಪು ಬದಲಾವಣೆ, ಮರುಹೆಸರು ಅಥವಾ ತೆಗೆದುಹಾಕುವಿಕೆ ಆರಂಭವಾಗುವುದಿಲ್ಲ. ಅದು ಮುಗಿಯುವವರೆಗೆ, ccam ಅದರಲ್ಲಿರುವ ಖಾತೆಗಳಿಗೆ ಇಲ್ಲದ ಲಿಂಕ್‌ಗಳನ್ನು ಮಾತ್ರ ರಚಿಸುತ್ತದೆ. ಅದನ್ನು ಪೂರ್ಣಗೊಳಿಸಲಾಗದಿದ್ದರೆ, ಆ ಫೈಲ್ ಅನ್ನು ತೆಗೆದುಹಾಕಿದರೆ ಬದಲಾವಣೆಯ ಉಳಿದ ಭಾಗವನ್ನು ಕೈಬಿಟ್ಟಂತಾಗುತ್ತದೆ ಎಂದು ದೋಷ ಹೇಳುತ್ತದೆ.

`ccam --dry-run doctor --fix` ಕ್ರಮವನ್ನು (`--fix finishes it in its order (b, a, c), with the answers given to its conflicts`) ಮತ್ತು ಪ್ರತಿ ಖಾತೆಯ ಭಾಗ ಏನನ್ನು ಪಕ್ಕಕ್ಕೆ ಇಡುತ್ತದೆ ಎಂಬುದನ್ನು ತೋರಿಸುತ್ತದೆ. ಇನ್ನೊಂದು ccam ಪ್ರೊಸೆಸ್ ಈಗ ನಡೆಸುತ್ತಿರುವ ಗುಂಪು ಬದಲಾವಣೆ ಮಾಹಿತಿ, ಮತ್ತು ಅದು ನಡೆಯುತ್ತಿರುವಾಗ `--fix` ಯಾವುದೇ ಹಂಚಿಕೆ ಲಿಂಕ್ ಅನ್ನು ದುರಸ್ತಿ ಮಾಡುವುದಿಲ್ಲ (`its share links are not repaired while another ccam changes the groups; …`). ದುರಸ್ತಿ ಮಾಡುವಾಗ `--fix` `~/.local/state/ccam/group-change.lock` ಅನ್ನು ಹಿಡಿದಿರುತ್ತದೆ, ಮತ್ತು ಬದಲಾವಣೆಯನ್ನು ಪೂರ್ಣಗೊಳಿಸಿದ ನಂತರ `config.toml` ಅನ್ನು ಮತ್ತೆ ಓದುತ್ತದೆ.

### ಹಂಚಿಕೆ ಲಿಂಕ್‌ಗಳ ದುರಸ್ತಿ

ಆರಂಭದ ಮಾರ್ಗ ಇಲ್ಲದ ಲಿಂಕ್ ಅನ್ನು ಅಲ್ಲೇ ರಚಿಸುತ್ತದೆ, ಆದರೆ ಡೇಟಾ ಕಳೆದುಹೋಗಬಹುದಾದ ಯಾವುದಕ್ಕಾದರೂ ನಿಂತು ಇಲ್ಲಿಗೆ ಸೂಚಿಸುತ್ತದೆ:

```console
$ ccam work
ccam: stopped because of share link problems:
  /home/me/.local/share/ccam/profiles/work/CLAUDE.md: set to shared but is a real file, not a link
Repair them with `ccam doctor --fix`, then run again
```

ಯಾವುದೇ ಹಂಚಿಕೆ ಲಿಂಕ್ ಸಮಸ್ಯೆಗೆ, `--fix` ಖಾತೆಯ ಹಂಚಿಕೆ ಸೆಟ್ಟಿಂಗ್‌ಗಳನ್ನು ಈಗಿನ ಸ್ಥಿತಿ ಮತ್ತು ಗುರಿ ಸ್ಥಿತಿ ಎರಡಕ್ಕೂ ನೀಡಿ `share.Build` ಅನ್ನು ಕರೆಯುತ್ತದೆ, ನಂತರ `Plan.Apply`. ccam ಡಿಸ್ಕ್‌ನಲ್ಲಿ ಇರುವುದರಿಂದ ಪ್ರತಿ ಹಂತವನ್ನೂ ಮತ್ತೆ ಲೆಕ್ಕಹಾಕುತ್ತದೆ (`Build`), ಹೀಗಾಗಿ `ccam group` ಬದಲಾವಣೆ ಬಳಸುವ ಅದೇ ಯೋಜನೆ ಸಿಗುತ್ತದೆ. ಹೀಗಾಗಿ ದುರಸ್ತಿ ಗುಂಪನ್ನು ಸೇರುವಾಗಿನ ಅದೇ ನಿಯಮಗಳನ್ನು ಅನುಸರಿಸುತ್ತದೆ.

<!-- motion:doctor-repair -->

ಇಲ್ಲಿ `settings.json` ಒಂದು ನಿಜವಾದ ಫೈಲ್. ಗುಂಪಿನಲ್ಲಿ ಈಗಾಗಲೇ ಬೇರೆ `settings.json` ಇರುವುದರಿಂದ, ಸಂಘರ್ಷಕ್ಕೆ ಅದರ ಡೀಫಾಲ್ಟ್ ಆಯ್ಕೆ `keep group` (ಚಿತ್ರದಲ್ಲಿ `KeepGroup`) ಅನ್ವಯವಾಗುತ್ತದೆ, ಹೀಗಾಗಿ ಗುಂಪಿನ ಪ್ರತಿ ಉಳಿಯುತ್ತದೆ. ಖಾತೆಯ ಫೈಲ್ ಖಾತೆಯ ಫೋಲ್ಡರ್‌ನೊಳಗಿನ `.ccam-backup/<time>/settings.json` ಗೆ ಹೋಗುತ್ತದೆ, ಮತ್ತು ccam ಆ ಪಾತ್ ಅನ್ನು ಗುಂಪಿಗೆ ಲಿಂಕ್ ಮಾಡುತ್ತದೆ (`os.Symlink`). `--fix` ಅದನ್ನು ತಿಳಿಸುತ್ತದೆ: `settings.json differed from the group's copy, which it now uses; this account's copy is in …`. ಇತರ ಸಂದರ್ಭಗಳು:

- ಗುಂಪಿನಲ್ಲಿ ಇನ್ನೂ ಪ್ರತಿ ಇಲ್ಲದಿದ್ದರೆ, ಖಾತೆಯ ಫೈಲ್ ಗುಂಪಿಗೆ ಸ್ಥಳಾಂತರಗೊಂಡು ಅದರ ಮೊದಲ ವಿಷಯವಾಗುತ್ತದೆ.
- ಫೋಲ್ಡರ್‌ಗೆ, ಗುಂಪಿನಲ್ಲಿ ಇಲ್ಲದ ಫೈಲ್‌ಗಳು ಗುಂಪಿಗೆ ಹೋಗುತ್ತವೆ. ಗುಂಪಿನ ಪ್ರತಿಗೆ ಸಮಾನವಾದ ಫೈಲ್‌ಗಳನ್ನು ಅಳಿಸಲಾಗುತ್ತದೆ, ಮತ್ತು ಭಿನ್ನವಾಗಿರುವವು ಬ್ಯಾಕಪ್‌ಗೆ ಹೋಗುತ್ತವೆ; ಅವುಗಳನ್ನು ಒಂದು ಟಿಪ್ಪಣಿಯಲ್ಲಿ ಹೆಸರಿಸಲಾಗುತ್ತದೆ (`projects: 1 file differs from the group's copy (-w/memory/MEMORY.md); the group's is kept, the account's stays in …`).
- ಇಲ್ಲದ ಗುಂಪಿನ ಫೋಲ್ಡರ್ ಅನ್ನು ಮೊದಲು ರಚಿಸಲಾಗುತ್ತದೆ.
- `history.jsonl` ಗೆ ಡೀಫಾಲ್ಟ್ `merge by line`: ಗುಂಪಿನ ಸಾಲುಗಳು, ನಂತರ ನಿಮ್ಮ ಹೊಸ ಸಾಲುಗಳು. ಗುಂಪಿನ ಹಿಂದಿನ ಪ್ರತಿಯನ್ನು `.ccam-backup/<time>/group/` ನಲ್ಲಿ ಉಳಿಸಲಾಗುತ್ತದೆ.
- ಇನ್ನೊಂದು ಗುಂಪಿಗೆ ಇರುವ ಲಿಂಕ್ ಅನ್ನು ಬದಲಾಯಿಸಲಾಗುತ್ತದೆ. ccam ನ ಹೊರಗಿನ ಫೋಲ್ಡರ್‌ಗೆ ಇರುವ ಲಿಂಕ್ ಬ್ಯಾಕಪ್‌ಗೆ ಹೋಗುತ್ತದೆ, ಮತ್ತು ಗುಂಪು ಖಾಲಿಯಾಗಿದ್ದರೆ ಅದರ ವಿಷಯ ಗುಂಪಿನ ಆರಂಭಿಕ ವಿಷಯವಾಗುತ್ತದೆ.
- ಈಗ ಸ್ಥಳೀಯವಾಗಿರುವ ಐಟಂಗಾಗಿ ಉಳಿದ ಲಿಂಕ್ ಅನ್ನು ತೆಗೆದುಹಾಕಲಾಗುತ್ತದೆ, ಮತ್ತು ಖಾತೆಗೆ ಗುಂಪಿನ ವಿಷಯದ ಒಂದು ಪ್ರತಿ ಸಿಗುತ್ತದೆ.

ಲಿಂಕ್‌ಗಳನ್ನು ತೆಗೆದುಹಾಕುವುದು ಮತ್ತು ಗುಂಪಿನ ಪ್ರತಿಗೆ ಸಮಾನವಾದ ಫೈಲ್‌ಗಳನ್ನು ಅಳಿಸುವುದನ್ನು ಬಿಟ್ಟರೆ, ಪ್ರತಿ ಹಂತವೂ ಡೇಟಾವನ್ನು ಗುಂಪಿಗೆ ಅಥವಾ ಬ್ಯಾಕಪ್ ಫೋಲ್ಡರ್‌ಗೆ ಸ್ಥಳಾಂತರಿಸುತ್ತದೆ. ಏನೂ ಕಳೆದುಹೋಗುವುದಿಲ್ಲ.

## ಸುರಕ್ಷತೆ ಮತ್ತು ವಿಶೇಷ ಸಂದರ್ಭಗಳು

- ಸಾಮಾನ್ಯ `ccam doctor` ಎಂದಿಗೂ ಏನನ್ನೂ ಬದಲಾಯಿಸುವುದಿಲ್ಲ. ಸ್ಕ್ರಿಪ್ಟ್‌ಗಳಲ್ಲಿ ಖಚಿತವಾಗಿರಲು `--fix` ಜೊತೆ `--dry-run` ಬಳಸಿ.
- ಚಾಲನೆಯಲ್ಲಿರುವ ಖಾತೆಗೆ, Claude Code ಅನ್ನು ಹೇಗೆ ಆರಂಭಿಸಿದ್ದರೂ, `doctor --fix` ಇಲ್ಲದ ಲಿಂಕ್‌ಗಳು ಮತ್ತು ಇಲ್ಲದ ಗುಂಪಿನ ಫೋಲ್ಡರ್‌ಗಳನ್ನು ಮಾತ್ರ ರಚಿಸುತ್ತದೆ, ಇದರಿಂದ ಏನೂ ಕಳೆದುಹೋಗುವುದಿಲ್ಲ. ಬೇರೆ ಏನಾದರೂ ಉಳಿದಿದ್ದರೆ, ಅದು `` is running; quit Claude Code there, then run `ccam doctor --fix` again to repair the rest `` ಅನ್ನು ಸೇರಿಸುತ್ತದೆ, ಏಕೆಂದರೆ ದುರಸ್ತಿ ಸ್ಥಳಾಂತರಿಸುವ ಫೈಲ್‌ಗಳಿಗೆ ಸೆಷನ್ ಬರೆಯುತ್ತಲೇ ಇರುತ್ತದೆ.
- ಹಂಚಿಕೆ ದುರಸ್ತಿ ವಿಫಲವಾದರೆ, ccam ಆ ಖಾತೆಗೆ `could not repair share links: <error>` ಎಂದು ವರದಿ ಮಾಡುತ್ತದೆ ಮತ್ತು ಅದರ ಅಪರಿಚಿತ ನಮೂದುಗಳ ಪರಿಶೀಲನೆಯನ್ನು ಬಿಟ್ಟುಬಿಡುತ್ತದೆ. ಇತರ ಖಾತೆಗಳನ್ನು ಪರಿಶೀಲಿಸಲಾಗುತ್ತದೆ.
- `ccam group` ಬದಲಾವಣೆ ಅರ್ಧದಲ್ಲಿ ವಿಫಲವಾದರೆ, ಹೊಸ ಗುಂಪುಗಳು ಈಗಾಗಲೇ ಉಳಿದಿರುತ್ತವೆ ಮತ್ತು ಬದಲಾವಣೆಯನ್ನು `~/.local/state/ccam/group-change.json` ನಲ್ಲಿ ದಾಖಲಿಸಲಾಗಿರುತ್ತದೆ; ccam `ccam doctor --fix` ಮೂಲಕ ಮುಗಿಸಲು ಹೇಳುತ್ತದೆ, ಅದು MCP ಹಂತಗಳನ್ನೂ ಒಳಗೊಂಡಂತೆ ಬದಲಾವಣೆಯ ಉಳಿದ ಭಾಗವನ್ನು ನಡೆಸುತ್ತದೆ.
- ಸಿಮ್‌ಲಿಂಕ್ ಆದ `.credentials.json`, ಅವಧಿ ಮುಗಿದ ಲಾಗಿನ್ ಮತ್ತು ಪರಿಸರದ ಕ್ರೆಡೆನ್ಶಿಯಲ್‌ಗಳನ್ನು ವರದಿ ಮಾಡಲಾಗುತ್ತದೆ, ಆದರೆ ಎಂದಿಗೂ ಬದಲಾಯಿಸಲಾಗುವುದಿಲ್ಲ.
- ಪ್ಲಗಿನ್ ರಿಜಿಸ್ಟ್ರಿ ಮರುಬರಹಗಳನ್ನು ಅಟಾಮಿಕ್ ಆಗಿ ಬರೆಯಲಾಗುತ್ತದೆ, ಆದರೆ `.ccam-backup/` ಗೆ ನಕಲಿಸಲಾಗುವುದಿಲ್ಲ.
