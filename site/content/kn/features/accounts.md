ಪ್ರತಿ ccam ಖಾತೆಯೂ ತನ್ನದೇ ಲಾಗಿನ್ ಇರುವ ಪ್ರತ್ಯೇಕ Claude Code ಕಾನ್ಫಿಗ್ ಫೋಲ್ಡರ್. ಖಾತೆಗಳನ್ನು ಸೇರಿಸಲು, ಅವುಗಳಿಗೆ ಸೈನ್ ಇನ್ ಮಾಡಲು, ಪಟ್ಟಿ ಮಾಡಲು, ಮರುಹೆಸರಿಸಲು ಮತ್ತು ತೆಗೆದುಹಾಕಲು ಈ ಕಮಾಂಡ್‌ಗಳನ್ನು ಬಳಸಿ. ಇವು ನಿಮ್ಮ ಬಳಿ ಈಗಾಗಲೇ ಇರುವ ಫೋಲ್ಡರ್‌ಗಳನ್ನೂ ನೋಂದಾಯಿಸುತ್ತವೆ.

## ಬಳಕೆ

```sh
ccam add                                   # wizard on a terminal: name, sign-in, groups, shortcut
ccam add work --shortcut ccwork            # no wizard: log in, then create the ccwork command
ccam add side --no-login --group default --group team
ccam login side                            # run claude auth login inside the account
ccam login --expired                       # every account that was never logged in or whose login expired
ccam logout side                           # log out: the login and its MCP sign-ins
ccam list                                  # table of accounts; ccam ls is the same
ccam list --json                           # machine-readable
ccam use 2                                 # make slot 2 the default account
ccam rename side personal
ccam remove personal                       # asks, logs out, then moves the folder to the trash
ccam import                                # find ~/.claude and ~/.claude-* and ask about each
ccam import ~/.claude-ops --name ops
ccam completion zsh > "${fpath[1]}/_ccam"
```

ಕಮಾಂಡ್ `<name|number>` ತೆಗೆದುಕೊಳ್ಳುವ ಎಲ್ಲೆಡೆ, ನೀವು ಖಾತೆಯ ಹೆಸರನ್ನು ಅಥವಾ ಅದರ ಸ್ಲಾಟ್ ಸಂಖ್ಯೆಯನ್ನು (`ccam list` ನ `#` ಕಾಲಮ್) ನೀಡಬಹುದು.

`ccam use` ಯಾವ ಖಾತೆ ಡೀಫಾಲ್ಟ್ ಎಂಬುದನ್ನು ಮಾತ್ರ ಬದಲಾಯಿಸುತ್ತದೆ (`config.toml` ನಲ್ಲಿ `default`).

ಆಯ್ಕೆಗಳಿಲ್ಲದೆ ಟರ್ಮಿನಲ್‌ನಲ್ಲಿ `ccam add` ರನ್ ಮಾಡಿದರೆ ವಿಜಾರ್ಡ್ ತೆರೆಯುತ್ತದೆ. ಅದು ಈ ಹಂತಗಳ ಮೂಲಕ ಹೋಗುತ್ತದೆ:

1. ಖಾತೆಯ ಹೆಸರು, ನೀವು ಈಗಾಗಲೇ ನೀಡಿಲ್ಲದಿದ್ದರೆ;
2. ಖಾತೆ ಹೇಗೆ ಸೈನ್ ಇನ್ ಆಗುತ್ತದೆ: ಈಗಲೇ Claude ಲಾಗಿನ್, API ಕೀ ಅಥವಾ ನಂತರ Claude ಲಾಗಿನ್;
3. `default` ಗುರುತಿಸಿದ ಸ್ಥಿತಿಯಲ್ಲಿ, ಯಾವ ಗುಂಪುಗಳನ್ನು ಸೇರಬೇಕು (ಗುಂಪುಗಳು ಇನ್ನೂ ಇಲ್ಲದಿದ್ದರೆ, `default` ಗುಂಪು ಏನನ್ನು ಹಂಚಿಕೊಳ್ಳಲಿದೆ ಎಂದು ತೋರಿಸುತ್ತದೆ);
4. `Create a shortcut command for work? [y/N]`;
5. ಖಚಿತಪಡಿಸಲು ಒಂದು ಸಾರಾಂಶ.

`Esc` ಒಂದು ಹಂತ ಹಿಂದಕ್ಕೆ ಹೋಗುತ್ತದೆ. `--group`, `--no-group`, `--shortcut` ಅಥವಾ `--no-login` ಇವುಗಳಲ್ಲಿ ಯಾವುದಾದರೂ ಒಂದು ಇದ್ದರೆ, ಅಥವಾ ಟರ್ಮಿನಲ್ ಇಲ್ಲದೆ (ಉದಾಹರಣೆಗೆ, ಪೈಪ್‌ನಿಂದ) ರನ್ ಮಾಡಿದರೆ, ವಿಜಾರ್ಡ್ ಬರುವುದಿಲ್ಲ. ಆಗ ಹೆಸರು ಕಡ್ಡಾಯ, ಮತ್ತು `--shortcut` ಒಂದು ಹೆಸರನ್ನು ನೀಡದಿದ್ದರೆ ಯಾವುದೇ ಶಾರ್ಟ್‌ಕಟ್ ರಚನೆಯಾಗುವುದಿಲ್ಲ.

`--group` ಇಲ್ಲದಿದ್ದರೆ, ಹೊಸ ಖಾತೆ `default` ಗುಂಪನ್ನು ಸೇರುತ್ತದೆ. ಮೊದಲ ಖಾತೆ ಅದನ್ನು ರಚಿಸುತ್ತದೆ, MCP ಸರ್ವರ್‌ಗಳು, ಸೆಟ್ಟಿಂಗ್‌ಗಳು, `CLAUDE.md` ಮತ್ತು ವಿಸ್ತರಣೆಗಳನ್ನು ಹಂಚಿಕೊಳ್ಳುತ್ತಾ; [ಗುಂಪುಗಳೊಂದಿಗೆ ಹಂಚಿಕೆ](/features/share) ನೋಡಿ. Windows ನಲ್ಲಿ ಫೈಲ್‌ಗಳನ್ನು Developer Mode ನಲ್ಲಿ ಮಾತ್ರ ಲಿಂಕ್ ಮಾಡಬಹುದು. ಅದಿಲ್ಲದಿದ್ದರೆ, ಮೊದಲ ಖಾತೆ `mcp` ಮತ್ತು `extensions` ಮಾತ್ರ ಇರುವ `default` ಅನ್ನು ರಚಿಸುತ್ತದೆ ಮತ್ತು ಅದನ್ನು ತಿಳಿಸುತ್ತದೆ (`Note: files can be linked on Windows only in Developer Mode (Settings > System > For developers), so group default shares only mcp, extensions. …`), ಮತ್ತು ಸೆಟ್ಟಿಂಗ್‌ಗಳು, ಮೆಮೊರಿ ಅಥವಾ ಇತಿಹಾಸವನ್ನು ಹಂಚಿಕೊಳ್ಳುವ ಗುಂಪಿನೊಂದಿಗೆ `--group` ಅನ್ನು ccam ನಿರಾಕರಿಸುತ್ತದೆ.

`ccam list` ಸ್ಲಾಟ್, ಹೆಸರು, ಶಾರ್ಟ್‌ಕಟ್, ಇಮೇಲ್, ಗುಂಪುಗಳು ಮತ್ತು ಕೊನೆಯ ಬಳಕೆಯನ್ನು ತೋರಿಸುತ್ತದೆ, ಡೀಫಾಲ್ಟ್ ಖಾತೆಯ ಮುಂದೆ `*` ಇರುತ್ತದೆ. ಇಮೇಲ್ ಎಂದರೆ ಫೋಲ್ಡರ್ ಈಗ ಲಾಗಿನ್ ಆಗಿರುವ ಇಮೇಲ್ (ಅದರ `.claude.json` ನಿಂದ); ಅದು ccam ದಾಖಲಿಸಿದ ಇಮೇಲ್‌ಗಿಂತ ಭಿನ್ನವಾಗಿದ್ದರೆ, ದಾಖಲಿಸಿದ ಇಮೇಲ್ ಅದರ ನಂತರ `(was …)` ಎಂದು ಬರುತ್ತದೆ:

```console
$ ccam list
   #  Name      Shortcut  Email             Groups        Last used
*  1  work      ccwork    user@example.com  default team  -
   2  personal  -         me@side.dev       default       -
```

```console
$ ccam list
   #  Name      Shortcut  Email                                     Groups   Last used
*  1  work      ccwork    other@company.com (was work@example.com)  default  2m ago
```

`--json` ಜೊತೆ, ಪ್ರತಿ ಖಾತೆಯೂ `slot`, `shortcut`, `name`, `email` (ಕೋಷ್ಟಕದಲ್ಲಿರುವಂತೆ, ಈಗಿನ ಲಾಗಿನ್‌ನದು), `default`, `dir`, `last_used` (ಖಾತೆಯನ್ನು ಎಂದೂ ಆರಂಭಿಸದಿದ್ದರೆ ಇದು ಇರುವುದಿಲ್ಲ), `groups` ಮತ್ತು `share` ಇರುವ ಒಂದು ಆಬ್ಜೆಕ್ಟ್ ಆಗಿರುತ್ತದೆ. `share` ಪ್ರತಿ ಐಟಂ (`mcp`, `settings`, `memory`, `extensions`, `history`) ಅನ್ನು ಅದು ಬರುವ ಗುಂಪಿಗೆ, ಅಥವಾ `"local"` ಗೆ ಹೊಂದಿಸುತ್ತದೆ.

| `--dry-run` | ಏನನ್ನೂ ಬದಲಾಯಿಸದ `ccam list` ಮತ್ತು `ccam completion` ಇದನ್ನು ಬೆಂಬಲಿಸುತ್ತವೆ. `add`, `login`, `logout`, `use`, `rename`, `remove` ಮತ್ತು `import` ಇದನ್ನು `` --dry-run is not supported by `ccam add`; nothing was changed `` (ಕಮಾಂಡ್ ಹೆಸರಿನೊಂದಿಗೆ) ಎಂದು ನಿರಾಕರಿಸುತ್ತವೆ | ಆಫ್ |

`ccam login` (`--expired` ಹೊರತುಪಡಿಸಿ), `ccam use` ಮತ್ತು `ccam rename` ಗೆ ತಮ್ಮದೇ ಆಯ್ಕೆಗಳಿಲ್ಲ. `ccam completion` `bash`, `zsh` ಅಥವಾ `powershell` ತೆಗೆದುಕೊಳ್ಳುತ್ತದೆ; ಬೇರೆ ಯಾವುದೇ ಮೌಲ್ಯ `only bash, zsh and powershell are supported` ಎಂದು ವಿಫಲವಾಗುತ್ತದೆ.

ಖಾತೆಯ ಹೆಸರುಗಳು `a-z`, `0-9`, `-` ಮತ್ತು `_` ಅಕ್ಷರಗಳಿಂದ ಕೂಡಿದ 1 ರಿಂದ 32 ಅಕ್ಷರಗಳಾಗಿರುತ್ತವೆ ಮತ್ತು ಅಕ್ಷರ ಅಥವಾ ಅಂಕಿಯಿಂದ ಆರಂಭವಾಗುತ್ತವೆ. ಹೆಸರು ಸಂಪೂರ್ಣವಾಗಿ ಅಂಕಿಗಳಾಗಿರಬಾರದು, ಏಕೆಂದರೆ `ccam 2` ಎಂದರೆ ಸ್ಲಾಟ್ 2. ಹೆಸರು ccam ಕಮಾಂಡ್ ಕೂಡ ಆಗಿರಬಾರದು (`add`, `list`, `ls`, `run`, `use`, `next`, `usage`, `u`, `share`, `mcp`, `login`, `logout`, `rename`, `remove`, `rm`, `import`, `migrate`, `doctor`, `shims`, `shortcut`, `completion`, `help`, `version`, `statusline`, `update`, `uninstall`, `folder`, `pick`, `ext`, `group`, `groups`, `hook`, `agents`, `attach`, `ccusage`), ಹೀಗಾಗಿ `ccam <name>` ಎಂದಿಗೂ ಅಸ್ಪಷ್ಟವಾಗುವುದಿಲ್ಲ. ಈ ಪಟ್ಟಿ `internal/config` ನಲ್ಲಿರುವ `config.Reserved`.

## ಇದು ಹೇಗೆ ಕೆಲಸ ಮಾಡುತ್ತದೆ

ಖಾತೆಯನ್ನು ಸೇರಿಸುವಾಗ ಅದರ ಫೋಲ್ಡರ್ ರಚನೆಯಾಗುತ್ತದೆ, ಅದು ತನ್ನ ಗುಂಪುಗಳನ್ನು ಸೇರುತ್ತದೆ, ಕಾನ್ಫಿಗ್ ಉಳಿಯುತ್ತದೆ, ಸೈನ್ ಇನ್ ಆಗುತ್ತದೆ ಮತ್ತು ಶಾರ್ಟ್‌ಕಟ್ ರಚನೆಯಾಗುತ್ತದೆ, ಇದೇ ಕ್ರಮದಲ್ಲಿ. ನೀವು `ccam add work --shortcut ccwork` ರನ್ ಮಾಡಿದಾಗ, ccam ಈ ಹಂತಗಳನ್ನು ನಡೆಸುತ್ತದೆ (`internal/cli/profiles.go` ನಲ್ಲಿನ `addProfile`):

<!-- motion:accounts-add -->

1. ಏನನ್ನಾದರೂ ರಚಿಸುವ ಮೊದಲು ccam ಹೆಸರನ್ನು (`config.ValidateName`) ಮತ್ತು ಶಾರ್ಟ್‌ಕಟ್ ಅನ್ನು (`shim.Check`) ಪರಿಶೀಲಿಸುತ್ತದೆ.
2. ccam `0700` ಮೋಡ್‌ನೊಂದಿಗೆ `~/.local/share/ccam/profiles/work/` ಅನ್ನು ರಚಿಸುತ್ತದೆ ಮತ್ತು ಖಾತೆಗೆ ಅತ್ಯಂತ ಕಡಿಮೆ ಖಾಲಿ ಸ್ಲಾಟ್ ಸಂಖ್ಯೆಯನ್ನು ನೀಡುತ್ತದೆ, ಹೀಗಾಗಿ ತೆಗೆದುಹಾಕಿದ ಖಾತೆಯ ಸಂಖ್ಯೆ ಮತ್ತೆ ಬಳಕೆಯಾಗುತ್ತದೆ (`profile.Add`, `Config.NextSlot`). ಮೊದಲ ಖಾತೆ ಡೀಫಾಲ್ಟ್ ಆಗುತ್ತದೆ.
3. ಖಾತೆ ತನ್ನ ಗುಂಪುಗಳನ್ನು ಸೇರುತ್ತದೆ (`--group` ಅಥವಾ `--no-group` ಬೇರೆ ಹೇಳದಿದ್ದರೆ `default`; ಮೊದಲ ಖಾತೆ `default` ಅನ್ನು ರಚಿಸುತ್ತದೆ), ಮತ್ತು ccam ಹೊಸ, ಖಾಲಿ ಫೋಲ್ಡರ್ ಅನ್ನು ಅವುಗಳಿಗೆ ಲಿಂಕ್ ಮಾಡುತ್ತದೆ, ಉದಾಹರಣೆಗೆ `settings.json` ಅನ್ನು `groups/default/settings.json` ಗೆ (`applyShare`, `share.Build` ಮತ್ತು ನಂತರ `Apply` ಮೂಲಕ). ಇದು ವಿಫಲವಾದರೆ ಹೊಸ ಫೋಲ್ಡರ್ ತೆಗೆದುಹಾಕಲಾಗುತ್ತದೆ, ಏಕೆಂದರೆ ಉಳಿದ ಫೋಲ್ಡರ್ ಪ್ರತಿ ಮರುಪ್ರಯತ್ನವನ್ನೂ `folder already exists` ಎಂದು ತಡೆಯುತ್ತದೆ.
4. ಖಾತೆಯನ್ನು `fsutil.AtomicWrite` ಮೂಲಕ `~/.config/ccam/config.toml` ಗೆ ಉಳಿಸಲಾಗುತ್ತದೆ: ಒಂದು ತಾತ್ಕಾಲಿಕ ಫೈಲ್, `fsync`, ನಂತರ `rename`. ಹೀಗಾಗಿ ಕ್ರ್ಯಾಶ್ ಆದರೂ ಅರ್ಧ ಬರೆದ ಕಾನ್ಫಿಗ್ ಉಳಿಯುವುದಿಲ್ಲ.
5. ccam `CLAUDE_CONFIG_DIR` ಅನ್ನು ಖಾತೆಯ ಫೋಲ್ಡರ್‌ಗೆ ಹೊಂದಿಸಿ, ಮತ್ತು ಲಾಗಿನ್ ಪುಟ ತುಂಬಿರುವಂತೆ ಖಾತೆಯ ಕೊನೆಯ ಇಮೇಲ್‌ನೊಂದಿಗೆ `--email` ನೀಡಿ, `claude auth login` ಅನ್ನು ಆರಂಭಿಸುತ್ತದೆ (`runLogin`). ಲಾಗಿನ್ ವಿಫಲವಾದರೆ ಖಾತೆ ಉಳಿಯುತ್ತದೆ, ಮತ್ತು ccam ದೋಷವನ್ನು ಮುದ್ರಿಸಿ ನಂತರ `ccam login work` ರನ್ ಮಾಡಲು ಹೇಳುತ್ತದೆ.
6. ccam `profiles/work/.claude.json` ನಿಂದ `oauthAccount` ಅನ್ನು ಓದುತ್ತದೆ (`profile.ReadIdentity`): ಇಮೇಲ್, ಖಾತೆ ಮತ್ತು ಸಂಸ್ಥೆಯ ID ಗಳು, ಸಂಸ್ಥೆಯ ಹೆಸರು ಮತ್ತು ಪ್ಲಾನ್ (`claude_max`, `claude_team` …). ಆ ಫೈಲ್ ಹಲವು ಮೆಗಾಬೈಟ್ ಇರಬಹುದು, ಹೀಗಾಗಿ ccam ಇಡೀ ಫೈಲ್ ಅನ್ನು ಪಾರ್ಸ್ ಮಾಡುವ ಬದಲು ಆ ಒಂದು ಕೀಗಾಗಿ ಮಾತ್ರ ಹುಡುಕುತ್ತದೆ (`TopLevelValue`). ccam ಈ ವಿವರಗಳನ್ನು `config.toml` ನ `[profile.login]` ನಲ್ಲಿ ಸಂಗ್ರಹಿಸುತ್ತದೆ.
7. ccam `~/.local/bin/ccwork` ಅನ್ನು ccam ಬೈನರಿಗೆ ಲಿಂಕ್ ಮಾಡುತ್ತದೆ (ಬೈನರಿ ಆರಂಭವಾದಾಗ `config.toml` ನಲ್ಲಿ `argv[0]` ಅನ್ನು ಹುಡುಕುತ್ತದೆ), ಮತ್ತು ಲಿಂಕ್ ಅನ್ನು `~/.local/state/ccam/shortcuts.json` ನಲ್ಲಿ ದಾಖಲಿಸುತ್ತದೆ (`shim.Install`). ಲಿಂಕ್ ರಚಿಸಲಾಗದಿದ್ದರೆ, ಖಾತೆಯನ್ನು ಆದರೂ ಸೇರಿಸಲಾಗುತ್ತದೆ, ccam ಕಾರಣವನ್ನು ತಿಳಿಸುತ್ತದೆ (`Could not create shortcuts: …`) ಮತ್ತು ಸಾರಾಂಶ `shortcut: ccwork (not created; see above)` ಎಂದು ತೋರಿಸುತ್ತದೆ.

ಲಾಗಿನ್‌ಗೆ ಕೆಲವು ನಿಮಿಷಗಳು ಬೇಕಾಗಬಹುದು, ಮತ್ತು ಅಷ್ಟರಲ್ಲಿ ಇನ್ನೊಂದು ccam ಪ್ರೊಸೆಸ್ ಕಾನ್ಫಿಗ್ ಅನ್ನು ಉಳಿಸಬಹುದು. ಆದ್ದರಿಂದ ಕಾಯುವ ಕಮಾಂಡ್‌ಗಳು `config.toml` ಅನ್ನು ಮತ್ತೆ ಓದುತ್ತವೆ, ಆ ಒಂದು ಬದಲಾವಣೆಯನ್ನು (ಇಲ್ಲಿ ಇಮೇಲ್) ಅನ್ವಯಿಸುತ್ತವೆ ಮತ್ತು ಉಳಿಸುತ್ತವೆ (`env.update`). ಇದೇ ಕಾರಣಕ್ಕೆ `ccam remove` ತನ್ನ ಪ್ರಶ್ನೆಯ ನಂತರ ಮತ್ತೆ ಓದುತ್ತದೆ.

`ccam login` ಈಗಿರುವ ಖಾತೆಗೆ ಹಂತ 5 ಮತ್ತು 6 ಅನ್ನು ನಡೆಸುತ್ತದೆ. Claude Code ಇಮೇಲ್ ಅನ್ನು ಲಾಗಿನ್ ಪುಟಕ್ಕೆ ಸುಳಿವಾಗಿ ಮಾತ್ರ ಬಳಸುತ್ತದೆ, ಹೀಗಾಗಿ ನೀವು ಹಿಂದಿಗಿಂತ ಬೇರೆ Claude ಖಾತೆಗೆ ಸೈನ್ ಇನ್ ಆಗಬಹುದು; ccam ಹೊಸ ಲಾಗಿನ್ ಅನ್ನು `[profile.login]` ಜೊತೆ ಹೋಲಿಸಿ ಅದನ್ನು ತಿಳಿಸುತ್ತದೆ (`ccam: this login is other@company.com, but work was dev@company.com before.`). ಅದು ಹೊಸ ಲಾಗಿನ್ ಅನ್ನು ಉಳಿಸಿಕೊಂಡು, ಅದನ್ನು ಹೇಗೆ ರದ್ದುಮಾಡುವುದು ಎಂದು ಹೇಳುತ್ತದೆ: ``To undo it, run `ccam login work` again and sign in as dev@company.com.``

ಇನ್ನೊಂದು Claude ಖಾತೆಗೆ ಆದ ಲಾಗಿನ್ ಖಾತೆಯ [ಮಿತಿ ದಾಖಲೆಯನ್ನೂ](/features/usage#the-limit-record) ಕೈಬಿಡುತ್ತದೆ, ಏಕೆಂದರೆ ಆ ಮಿತಿಗಳು ಇನ್ನೊಂದು ಖಾತೆಗೆ ಸೇರಿದ್ದವು. ಇನ್ನೊಂದು ccam ಖಾತೆ ಅದೇ Claude ಖಾತೆಗೆ ಲಾಗಿನ್ ಆಗಿದ್ದರೆ, ಅವೆರಡೂ ತಮ್ಮ ಬಳಕೆಯ ಮಿತಿಗಳನ್ನು ಹಂಚಿಕೊಳ್ಳುತ್ತವೆ ಎಂದು ccam ಎಚ್ಚರಿಸುತ್ತದೆ.

`ccam login --expired` ಎಂದೂ ಲಾಗಿನ್ ಆಗದ ಅಥವಾ ಲಾಗಿನ್ ಅವಧಿ ಮುಗಿದ ಪ್ರತಿ ಖಾತೆಗೂ ಒಂದರ ನಂತರ ಒಂದರಂತೆ ಲಾಗಿನ್ ಮಾಡುತ್ತದೆ: ಅದರ ರಿಫ್ರೆಶ್ ಟೋಕನ್‌ನ ಅವಧಿ ಮುಗಿದಿದ್ದರೆ, ಅಥವಾ ಸರ್ವರ್ ಅದನ್ನು ನಿರಾಕರಿಸಿದ ನಂತರ Claude Code ಲಾಗಿನ್ ಅನ್ನು ತೆರವುಗೊಳಿಸಿದ್ದರೆ. ಮೊದಲ ಬ್ರೌಸರ್ ತೆರೆಯುವ ಮೊದಲು, `config.toml` ಅನ್ನು ಉಳಿಸಬಹುದೇ ಎಂದು ಅದು ಪರಿಶೀಲಿಸುತ್ತದೆ.

`ccam logout` ಖಾತೆಯಲ್ಲಿ `claude auth logout` ರನ್ ಮಾಡುತ್ತದೆ ಮತ್ತು ಉಳಿಸಿದ ಇಮೇಲ್ ಅನ್ನು ಅಳಿಸುತ್ತದೆ; ಲಾಗಿನ್ ದಾಖಲೆ ಉಳಿಯುತ್ತದೆ, ಹೀಗಾಗಿ ಮುಂದಿನ ಲಾಗಿನ್ ಅನ್ನು ಅದರೊಂದಿಗೆ ಹೋಲಿಸಲಾಗುತ್ತದೆ. Claude Code ಲಾಗಿನ್ ಅನ್ನು ರದ್ದುಗೊಳಿಸುತ್ತದೆ ಮತ್ತು ಖಾತೆಗಾಗಿ ತಾನು ಸಂಗ್ರಹಿಸಿದ್ದನ್ನು, MCP ಸರ್ವರ್ ಸೈನ್-ಇನ್‌ಗಳು ಸೇರಿದಂತೆ, ಅಳಿಸುತ್ತದೆ. ಆದ್ದರಿಂದ ಈ ಸಂದರ್ಭಗಳಲ್ಲಿ ccam ಮೊದಲು ಎಚ್ಚರಿಸಿ ಕೇಳುತ್ತದೆ (`--yes` ಪ್ರಶ್ನೆಯನ್ನು ಬಿಟ್ಟುಬಿಡುತ್ತದೆ):

- ಲಾಗಿನ್‌ನಲ್ಲಿ MCP ಸೈನ್-ಇನ್‌ಗಳು ಇದ್ದಾಗ;
- ಖಾತೆ ಚಾಲನೆಯಲ್ಲಿದ್ದಾಗ (ಅದರ ಸೆಷನ್‌ಗಳೂ ಸೈನ್ ಔಟ್ ಆಗುತ್ತವೆ);
- ಇನ್ನೊಂದು ಖಾತೆಯ ಫೋಲ್ಡರ್ ಅದೇ ಲಾಗಿನ್ ಹೊಂದಿದ್ದಾಗ (ನಕಲಿಸಿದ ಫೋಲ್ಡರ್); ಲಾಗ್ ಔಟ್ ಅದನ್ನೂ ರದ್ದುಗೊಳಿಸುತ್ತದೆ.

ಉದಾಹರಣೆಗೆ:

```console
$ ccam logout side
Logging out also removes side's MCP server sign-ins (linear); sign in to them again with /mcp.
Log out side? [y/N]
```

ಇನ್ನೊಂದು Claude ಖಾತೆಯಾಗಿ ಲಾಗಿನ್ ಆಗಲು, `ccam login <name>` ಒಂದೇ ಸಾಕು, ಮತ್ತು ಅದು MCP ಸೈನ್-ಇನ್‌ಗಳನ್ನು ಉಳಿಸಿಕೊಳ್ಳುತ್ತದೆ.

ಖಾತೆಗಳು ಒಂದಕ್ಕಿಂತ ಹೆಚ್ಚು ಸಂಸ್ಥೆಗಳಿಗೆ ಸೇರಿದಾಗ `ccam list` ಒಂದು `Organization` ಕಾಲಮ್ ಸೇರಿಸುತ್ತದೆ (ವೈಯಕ್ತಿಕ ಪ್ಲಾನ್‌ಗಳು `personal` ತೋರಿಸುತ್ತವೆ), ಮತ್ತು `ccam list --json` ಪ್ರತಿ ಖಾತೆಗೂ `plan` ಮತ್ತು `org` ಹೊಂದಿರುತ್ತದೆ.

### ರಿಮೋಟ್ ಯಂತ್ರದಲ್ಲಿ ಸೈನ್ ಇನ್ ಮಾಡುವುದು

SSH ಮೂಲಕ, `claude auth login` ನ ಬ್ರೌಸರ್ ಭಾಗ ಮುರಿಯಬಹುದು. Claude Code ರಿಮೋಟ್ ಯಂತ್ರದಲ್ಲಿರುವ ಕಾಲ್‌ಬ್ಯಾಕ್ ಸರ್ವರ್‌ನಲ್ಲಿ (`http://localhost:<port>/callback`) ಸೈನ್-ಇನ್‌ಗಾಗಿ ಕಾಯುತ್ತದೆ, ಆದರೆ ಸೈನ್-ಇನ್ ಮುಗಿಸುವ ಬ್ರೌಸರ್ ನಿಮ್ಮ ಕಂಪ್ಯೂಟರ್‌ನಲ್ಲಿ ಚಾಲನೆಯಾಗುತ್ತದೆ. ಅಲ್ಲಿ ಆ ವಿಳಾಸ ಎಲ್ಲಿಗೂ ತಲುಪುವುದಿಲ್ಲ, ಮತ್ತು ಬ್ರೌಸರ್ `ERR_CONNECTION_REFUSED` ನಂತಹ ದೋಷ ತೋರಿಸುತ್ತದೆ. ಆದರೂ ಆ ವಿಳಾಸದಲ್ಲಿ ಒಂದು ಬಾರಿಯ ಕೋಡ್ ಇರುತ್ತದೆ, ಹೀಗಾಗಿ ccam ಅದನ್ನು ತಲುಪಿಸಬಲ್ಲದು:

<!-- motion:accounts-relay -->

ccam ನಿಮ್ಮ ಟರ್ಮಿನಲ್ ಅನ್ನು Claude Code ಗೆ ಒಪ್ಪಿಸುವುದಿಲ್ಲ (`runLogin`). ಅದು Claude Code ನ ಸ್ಟ್ಯಾಂಡರ್ಡ್ ಇನ್‌ಪುಟ್ ಅನ್ನು ಒಂದು ಪೈಪ್‌ಗೆ ಜೋಡಿಸುತ್ತದೆ, ಮತ್ತು ನೀವು ಟೈಪ್ ಮಾಡುವ ಪ್ರತಿ ಸಾಲನ್ನು ಅದಕ್ಕೆ ನಕಲಿಸುತ್ತದೆ (`relayLogin`). ಹೀಗಾಗಿ Claude Code ನ `Paste code here` ಪ್ರಾಂಪ್ಟ್‌ನಲ್ಲಿ ಪೇಸ್ಟ್ ಮಾಡಿದ ಕೋಡ್ ಕೂಡ ತಲುಪುತ್ತದೆ. ಒಂದು ಸಾಲು ಕಾಲ್‌ಬ್ಯಾಕ್ ವಿಳಾಸವಾಗಿದ್ದರೆ, ಹೋಸ್ಟ್ `localhost`, `127.0.0.1` ಅಥವಾ `[::1]` ಆಗಿದ್ದರೆ, ಪೋರ್ಟ್ ನೀಡಿದ್ದರೆ, ಪಾತ್ `/callback` ಆಗಿದ್ದರೆ ಮತ್ತು `code` ಹಾಗೂ `state` ಎರಡೂ ಇದ್ದರೆ ಮಾತ್ರ ccam ಅದನ್ನು ಸ್ವೀಕರಿಸುತ್ತದೆ; `http://` ಬಿಟ್ಟುಬಿಡಬಹುದು (`callbackURL`). ನಂತರ ccam ಬ್ರೌಸರ್ ಮಾಡುತ್ತಿದ್ದಂತೆಯೇ, 10 ಸೆಕೆಂಡ್ ಟೈಮ್‌ಔಟ್‌ನೊಂದಿಗೆ ಮತ್ತು ರೀಡೈರೆಕ್ಟ್‌ಗಳನ್ನು ಅನುಸರಿಸದೆ, ಸರ್ವರ್‌ನಲ್ಲಿ ಆ ವಿಳಾಸವನ್ನು ವಿನಂತಿಸುತ್ತದೆ (`deliverCallback`). ವಿನಂತಿ ಕಾಯುತ್ತಿರುವ `claude auth login` ನ ಕಾಲ್‌ಬ್ಯಾಕ್ ಸರ್ವರ್ ಅನ್ನು ತಲುಪುತ್ತದೆ (ಚಿತ್ರದಲ್ಲಿನ ಡ್ಯಾಶ್ ಗೆರೆ). Claude Code ಕೋಡ್ ಪಡೆದು ಲಾಗಿನ್ ಅನ್ನು ಉಳಿಸುತ್ತದೆ, Linux ನಲ್ಲಿ ಖಾತೆಯ ಫೋಲ್ಡರ್‌ನಲ್ಲಿರುವ `.credentials.json` ನಲ್ಲಿ. ಪೇಸ್ಟ್ ಮಾಡಿದ ಸಾಲು ccam ಅನ್ನು ಎಂದಿಗೂ ಬೇರೆ ಹೋಸ್ಟ್ ಅನ್ನು ಸಂಪರ್ಕಿಸುವಂತೆ ಮಾಡಲಾರದು.

ಲಾಗಿನ್ ಆರಂಭವಾಗುವ ಮೊದಲು ccam ಇದನ್ನು ಮುದ್ರಿಸುತ್ತದೆ:

```text
On a remote machine? If your browser ends up on an http://localhost:…/callback page that does not load, paste that address here.
```

ಯಶಸ್ವಿಯಾದಾಗ ಅದು `→ Passed the sign-in to Claude Code on this machine.` ಎಂದು ಮುದ್ರಿಸುತ್ತದೆ.

ಲಾಗಿನ್ ಟರ್ಮಿನಲ್‌ನಲ್ಲಿ ಇನ್‌ಪುಟ್‌ಗಾಗಿ ಕಾಯುತ್ತಿರುವಾಗ, ccam ಟರ್ಮಿನಲ್‌ನ echo ಮತ್ತು line mode ಅನ್ನು ಆಫ್ ಮಾಡುತ್ತದೆ ಮತ್ತು ನೀವು ಟೈಪ್ ಮಾಡುವ ಪ್ರತಿ ಅಕ್ಷರಕ್ಕೂ ಒಂದು `*` ತೋರಿಸುತ್ತದೆ, ಹೀಗಾಗಿ ಪೇಸ್ಟ್ ಮಾಡಿದ ಕೋಡ್ ಅಥವಾ callback ವಿಳಾಸ ಪರದೆಯ ಮೇಲೆ ಕಾಣುವುದಿಲ್ಲ. `readLine` ಸಾಲಿನ ಸಂಪಾದನೆಯನ್ನು ತಾನೇ ಮಾಡುತ್ತದೆ: `Enter` ಸಾಲನ್ನು ಕಳುಹಿಸುತ್ತದೆ, `Backspace` ಒಂದು ಅಕ್ಷರವನ್ನು ಅಳಿಸುತ್ತದೆ, ಮತ್ತು ಖಾಲಿ ಸಾಲಿನಲ್ಲಿ `Ctrl+D` ಇನ್‌ಪುಟ್ ಅನ್ನು ಮುಗಿಸುತ್ತದೆ. ಲಾಗಿನ್ ಮುಗಿದಾಗ ಟರ್ಮಿನಲ್ ಹಿಂದಿನ ಸ್ಥಿತಿಗೆ ಮರಳುತ್ತದೆ, ಮತ್ತು `Ctrl+C`, `SIGTERM` ಅಥವಾ `SIGHUP` ಬಂದಾಗಲೂ ಮರಳುತ್ತದೆ; ಇವು ಈಗಲೂ ccam ಅನ್ನು ಕೊನೆಗೊಳಿಸುತ್ತವೆ. ಸ್ಟ್ಯಾಂಡರ್ಡ್ ಇನ್‌ಪುಟ್ ಮತ್ತು ಸ್ಟ್ಯಾಂಡರ್ಡ್ ಎರರ್‌ನಲ್ಲಿ ಟರ್ಮಿನಲ್ ಇಲ್ಲದಿದ್ದರೆ, ಸಾಲುಗಳು ಬಂದಂತೆಯೇ ನಕಲಾಗುತ್ತವೆ.

### ಮರುಹೆಸರಿಸುವುದು, ತೆಗೆದುಹಾಕುವುದು ಮತ್ತು ಇಂಪೋರ್ಟ್

`ccam rename` ಮತ್ತು `ccam remove` ಖಾತೆಯ ಫೋಲ್ಡರ್ ಮೇಲೆ ಮತ್ತು ccam ಖಾತೆಯ ಹೆಸರಿನಲ್ಲಿ ಬೇರೆಡೆ ಇಟ್ಟಿರುವುದರ ಮೇಲೆ ಕೆಲಸ ಮಾಡುತ್ತವೆ. ccam ಆ ಪಾತ್‌ಗಳನ್ನು `nameState` ನಲ್ಲಿ ಪಟ್ಟಿ ಮಾಡುತ್ತದೆ:

- `~/.local/state/ccam/last-used/<name>`;
- `~/.local/state/ccam/mcp/<name>`;
- ಬಳಕೆಯ ಕ್ಯಾಶ್‌ಗಳಾದ `~/.local/state/ccam/usage/<name>.json` ಹಾಗೂ `<name>.statusline.json`;
- ಮಿತಿ ದಾಖಲೆ `<name>.limit.json`;
- `~/.local/state/ccam/handoff/<name>/` ನಲ್ಲಿರುವ ಸೆಷನ್ ಟಿಪ್ಪಣಿಗಳು.

`ccam remove work` ಅವುಗಳನ್ನು ಈ ಕ್ರಮದಲ್ಲಿ ನಿಭಾಯಿಸುತ್ತದೆ:

<!-- motion:accounts-remove -->

1. ಖಾತೆ ಚಾಲನೆಯಲ್ಲಿದ್ದರೆ `ccam remove` ಮೊದಲು ನಿರಾಕರಿಸುತ್ತದೆ, ಇಲ್ಲದಿದ್ದರೆ ಕೇಳುತ್ತದೆ, ಮತ್ತು ನೀವು ಉತ್ತರಿಸಿದ ನಂತರ ಮತ್ತೆ ಪರಿಶೀಲಿಸುತ್ತದೆ (ಪ್ರಶ್ನೆ ತೆರೆದಿದ್ದಾಗ ಆರಂಭವಾದ ಸೆಷನ್ ಇದರಿಂದ ಪತ್ತೆಯಾಗುತ್ತದೆ).
2. ಏನನ್ನಾದರೂ ಬದಲಾಯಿಸುವ ಮೊದಲು `config.toml` ಅನ್ನು ಉಳಿಸಬಹುದೇ ಎಂದು ಅದು ಪರಿಶೀಲಿಸುತ್ತದೆ.
3. ಖಾತೆ ವಿಸ್ತರಣೆಗಳನ್ನು ಹಂಚಿಕೊಂಡಿದ್ದರೆ, ccam ಗುಂಪಿನ `installed_plugins.json` ಮತ್ತು `known_marketplaces.json` ಅನ್ನು ಮರುಬರೆಯುತ್ತದೆ (`RewritePluginPaths`), ಏಕೆಂದರೆ Claude Code ಈ ಖಾತೆಯ ಫೋಲ್ಡರ್ ಮೂಲಕ ಹಾದುಹೋಗಬಹುದಾದ ಸಂಪೂರ್ಣ ಪ್ಲಗಿನ್ ಪಾತ್‌ಗಳನ್ನು ಸಂಗ್ರಹಿಸುತ್ತದೆ.
4. ನಂತರ ನಿರ್ವಹಿಸಲಾದ ಖಾತೆಯನ್ನು (`ccam import` ಮೂಲಕ ನೋಂದಾಯಿಸಿದ ಖಾತೆಯಲ್ಲ, ccam ತಾನೇ ಫೋಲ್ಡರ್ ರಚಿಸಿದ ಖಾತೆ) ಲಾಗ್ ಔಟ್ ಮಾಡಲಾಗುತ್ತದೆ: ಅದರ ಫೋಲ್ಡರ್‌ನಲ್ಲಿ `claude auth logout` ರನ್ ಆಗುತ್ತದೆ, ಹೀಗಾಗಿ ಕೆಲಸ ಮಾಡುವ ಯಾವುದೇ ಲಾಗಿನ್ ಟ್ರ್ಯಾಶ್‌ನಲ್ಲಿ ಉಳಿಯುವುದಿಲ್ಲ (ಅಥವಾ, macOS ನಲ್ಲಿ, ಫೋಲ್ಡರ್‌ನ ಹೆಸರಿನ Keychain ಐಟಂನಲ್ಲಿ; ಅದೇ ಹೆಸರಿನ ಮುಂದಿನ ಖಾತೆ ಅದನ್ನು ಪಡೆದುಕೊಳ್ಳುತ್ತಿತ್ತು). API ಕೀ ಖಾತೆಗೆ, ಮತ್ತು ಇನ್ನೊಂದು ಖಾತೆಯ ಫೋಲ್ಡರ್ ಅದೇ ಲಾಗಿನ್ ಹೊಂದಿದ್ದಾಗ (ಲಾಗ್ ಔಟ್ ಅದನ್ನೂ ರದ್ದುಗೊಳಿಸುತ್ತಿತ್ತು), ಇದನ್ನು ಬಿಟ್ಟುಬಿಡಲಾಗುತ್ತದೆ. ವಿಫಲವಾದ ಲಾಗ್ ಔಟ್ ಅನ್ನು ತಿಳಿಸಲಾಗುತ್ತದೆ, ಮತ್ತು ತೆಗೆದುಹಾಕುವಿಕೆ ಮುಂದುವರಿಯುತ್ತದೆ.
5. ccam ಫೋಲ್ಡರ್ ಅನ್ನು `~/.local/share/ccam/trash/<name>-<time>/` ಗೆ ಸ್ಥಳಾಂತರಿಸುತ್ತದೆ (`profile.Trash`), ಖಾತೆ `config.toml` ನಿಂದ ಹೊರಹೋಗುತ್ತದೆ, ನಂತರ ಅದೇ ಹೆಸರಿನ ಖಾತೆ ಅವುಗಳನ್ನು ಪಡೆಯದಂತೆ `nameState` ಪಾತ್‌ಗಳನ್ನು ಅಳಿಸಲಾಗುತ್ತದೆ, ಮತ್ತು ಶಾರ್ಟ್‌ಕಟ್ ಲಿಂಕ್ ತೆಗೆದುಹಾಕಲಾಗುತ್ತದೆ: `✓ side removed (folder moved to /home/you/.local/share/ccam/trash/side-20261023-212306; logged out first)`.

ಕೊನೆಗೂ `config.toml` ಅನ್ನು ಉಳಿಸಲಾಗದಿದ್ದರೆ, ಫೋಲ್ಡರ್ ಟ್ರ್ಯಾಶ್‌ನಿಂದ ಮರಳಿ ಬರುತ್ತದೆ. ತೆಗೆದುಹಾಕಿದ ಖಾತೆಯನ್ನು ಮರಳಿ ಪಡೆಯಲು, ಫೋಲ್ಡರ್ ಅನ್ನು ಟ್ರ್ಯಾಶ್‌ನಿಂದ ಹಿಂದಕ್ಕೆ ಸ್ಥಳಾಂತರಿಸಿ ಮತ್ತೆ ಲಾಗಿನ್ ಮಾಡಿ.

`ccam rename` ಫೋಲ್ಡರ್ ಅನ್ನು ಮರುಹೆಸರಿಸುತ್ತದೆ ಮತ್ತು ಅದರ `plugins/` ನಲ್ಲಿನ ಪ್ಲಗಿನ್ ಪಾತ್‌ಗಳನ್ನು ಹಳೆಯ ಫೋಲ್ಡರ್‌ನಿಂದ ಹೊಸದಕ್ಕೆ ಮರುಬರೆಯುತ್ತದೆ. ಅದು `nameState` ಪಾತ್‌ಗಳನ್ನು ಹೊಸ ಹೆಸರಿಗೆ ಸ್ಥಳಾಂತರಿಸುತ್ತದೆ, ಮತ್ತು ಖಾತೆ ಡೀಫಾಲ್ಟ್ ಆಗಿದ್ದರೆ ಅದನ್ನು ಡೀಫಾಲ್ಟ್ ಆಗಿಯೇ ಉಳಿಸುತ್ತದೆ. `ccam next --continue` ಸೆಷನ್ ಟಿಪ್ಪಣಿಗಳನ್ನು ಇನ್ನೂ ಕಂಡುಕೊಳ್ಳುವಂತೆ ಅದು ಅವುಗಳನ್ನೂ ಅಪ್‌ಡೇಟ್ ಮಾಡುತ್ತದೆ. ಶಾರ್ಟ್‌ಕಟ್ ಕಮಾಂಡ್ ತನ್ನ ಹೆಸರನ್ನು ಉಳಿಸಿಕೊಳ್ಳುತ್ತದೆ. ಪ್ಲಗಿನ್ ಮರುಬರಹ ವಿಫಲವಾದರೆ, ಅಥವಾ `config.toml` ಅನ್ನು ಉಳಿಸಲಾಗದಿದ್ದರೆ, ಫೋಲ್ಡರ್‌ಗೆ ಹಳೆಯ ಹೆಸರನ್ನೇ ಮರಳಿ ನೀಡಲಾಗುತ್ತದೆ.

macOS ನಲ್ಲಿ, ಮತ್ತು Claude Code ಲಾಗಿನ್‌ಗಳನ್ನು Credential Manager ನಲ್ಲಿ ಸಂಗ್ರಹಿಸಿದಾಗ Windows ನಲ್ಲಿ, ಫೋಲ್ಡರ್ ತನ್ನ ಹಳೆಯ ಹೆಸರನ್ನೇ ಉಳಿಸಿಕೊಳ್ಳುತ್ತದೆ, ಏಕೆಂದರೆ ಲಾಗಿನ್ ಮತ್ತು MCP ಸೈನ್-ಇನ್‌ಗಳು ಫೋಲ್ಡರ್‌ನ ಪಾತ್ ಅಡಿಯಲ್ಲಿ ಸಂಗ್ರಹವಾಗಿರುತ್ತವೆ, ಮತ್ತು ಸ್ಥಳಾಂತರಿಸಿದ ಫೋಲ್ಡರ್ ಲಾಗ್ ಔಟ್ ಆಗುತ್ತಿತ್ತು. ಆಗ ಕಾನ್ಫಿಗ್ ಹೊಸ ಹೆಸರಿನ ಪಕ್ಕದಲ್ಲಿ ಫೋಲ್ಡರ್ ಅನ್ನು `folder` ಎಂದು ದಾಖಲಿಸುತ್ತದೆ, ಮತ್ತು ccam `its folder stays …: the macOS Keychain keeps the login under the folder's path` ಎಂದು ತಿಳಿಸುತ್ತದೆ.

`ccam import` ಒಂದು ಫೋಲ್ಡರ್ ಅನ್ನು ಅದು ಇರುವಲ್ಲೇ, `config.toml` ನಲ್ಲಿ `dir` ಆಗಿ ನೋಂದಾಯಿಸುತ್ತದೆ. ಅದು ಅದನ್ನು ಎಂದಿಗೂ ಸ್ಥಳಾಂತರಿಸುವುದಿಲ್ಲ ಅಥವಾ ನಕಲಿಸುವುದಿಲ್ಲ: ನಕಲಿಸಿದ ರಿಫ್ರೆಶ್ ಟೋಕನ್ ಪ್ರತಿಗಳು ಒಂದನ್ನೊಂದು ಲಾಗ್ ಔಟ್ ಮಾಡುವಂತೆ ಮಾಡುತ್ತದೆ.

ಫೋಲ್ಡರ್ ಆರ್ಗ್ಯುಮೆಂಟ್ ಇಲ್ಲದಿದ್ದರೆ, ಅದು ನೋಂದಾಯಿಸದ `~/.claude` ಮತ್ತು `~/.claude-*` ಫೋಲ್ಡರ್‌ಗಳಿಗಾಗಿ ಹುಡುಕಿ ಪ್ರತಿಯೊಂದರ ಬಗ್ಗೆ ಕೇಳುತ್ತದೆ. ಹೆಸರುಗಳು ಫೋಲ್ಡರ್‌ನಿಂದ ಬರುತ್ತವೆ (`~/.claude` ಎಂದರೆ `main`, `~/.claude-work` ಎಂದರೆ `work`, `~/.claude-2` ಎಂದರೆ `acct2`). ccam ಹೆಸರನ್ನು ಪಡೆಯಲಾಗದಿದ್ದರೆ, ಅಥವಾ ಹೆಸರು ಈಗಾಗಲೇ ಬಳಕೆಯಲ್ಲಿದ್ದರೆ, ಅದು ಫೋಲ್ಡರ್ ಅನ್ನು ರನ್ ಮಾಡಬೇಕಾದ `--name` ಕಮಾಂಡ್ ಜೊತೆ ಪಟ್ಟಿ ಮಾಡುತ್ತದೆ. ಸಿಕ್ಕ ಫೋಲ್ಡರ್ ವಿಫಲವಾದರೆ ಅದನ್ನು `Skipped <path>: <reason>` ಎಂದು ತಿಳಿಸಲಾಗುತ್ತದೆ ಮತ್ತು ಉಳಿದವು ಇಂಪೋರ್ಟ್ ಆಗುತ್ತವೆ.

ccam ತನ್ನ ಎಲ್ಲಾ ಪ್ರಶ್ನೆಗಳನ್ನು ಮೊದಲು ಕೇಳುತ್ತದೆ, ನಂತರ `config.toml` ಅನ್ನು ಮತ್ತೆ ಓದಿ ಫೋಲ್ಡರ್‌ಗಳನ್ನು ನೋಂದಾಯಿಸುತ್ತದೆ, ಹೀಗಾಗಿ ಈ ನಡುವೆ ಇತರ ccam ಕಮಾಂಡ್‌ಗಳು ಉಳಿಸಿದ ಬದಲಾವಣೆಗಳು ಹಾಗೆಯೇ ಉಳಿಯುತ್ತವೆ. `✓` ಸಾಲುಗಳು ಉಳಿಸಿದ ನಂತರ ಬರುತ್ತವೆ.

`CLAUDE_CONFIG_DIR` ಇಲ್ಲದಿದ್ದಾಗ Claude Code `.claude.json` ಅನ್ನು ನಿಮ್ಮ ಹೋಮ್ ಫೋಲ್ಡರ್‌ನಲ್ಲಿ `~/.claude` ಪಕ್ಕದಲ್ಲಿ ಇಡುತ್ತದೆ. ಹೀಗಾಗಿ ನೀವು `~/.claude` ಅನ್ನು ಇಂಪೋರ್ಟ್ ಮಾಡಿದಾಗ ಅದಕ್ಕೆ ತನ್ನದೇ `.claude.json` ಇಲ್ಲದಿದ್ದರೆ, ccam `~/.claude/.claude.json` ನಿಂದ `~/.claude.json` ಗೆ ಲಿಂಕ್ ರಚಿಸುತ್ತದೆ. ಆಗ ಸಾಮಾನ್ಯ `claude` ಮತ್ತು `ccam main` ಒಂದೇ ಖಾತೆಯನ್ನು ನೋಡುತ್ತವೆ.

`~/.claude` ಗೆ `~/.claude.json` ನ ಪಕ್ಕದಲ್ಲಿ ತನ್ನದೇ `.claude.json` ಇದ್ದರೆ, ccam ಎರಡನ್ನೂ ಹಾಗೆಯೇ ಬಿಡುತ್ತದೆ ಮತ್ತು ಅದನ್ನು ತಿಳಿಸುತ್ತದೆ. `ccam main` ಒಳಗಿನದನ್ನು ಮತ್ತು ಸಾಮಾನ್ಯ `claude` ಹೊರಗಿನದನ್ನು ಬಳಸುತ್ತವೆ, ಹೀಗಾಗಿ ಅವುಗಳ ಲಾಗಿನ್ ವಿವರಗಳು ಮತ್ತು MCP ಸರ್ವರ್‌ಗಳು ಬೇರೆಯಾಗಿಯೇ ಉಳಿಯುತ್ತವೆ. ಒಂದನ್ನೇ ಇಟ್ಟುಕೊಳ್ಳಲು ಒಳಗಿನ ಫೈಲ್ ಅನ್ನು ಲಿಂಕ್‌ನಿಂದ ಬದಲಾಯಿಸಿ ([doctor](/features/doctor) ಕೂಡ ಇದನ್ನು ತಿಳಿಸುತ್ತದೆ).

ನೋಂದಾಯಿತ ಖಾತೆಯಲ್ಲಿರುವ ಅದೇ ಲಾಗಿನ್ ಅನ್ನು ಫೋಲ್ಡರ್ ಹೊಂದಿದ್ದರೆ (ನಕಲಿಸಿದ ಫೋಲ್ಡರ್), ccam ಅದನ್ನು ತಿಳಿಸುತ್ತದೆ: ಯಾವುದು ಮೊದಲು ಅದನ್ನು ನವೀಕರಿಸುತ್ತದೋ ಅದು ಇನ್ನೊಂದನ್ನು ಲಾಗ್ ಔಟ್ ಮಾಡುತ್ತದೆ, ಆದ್ದರಿಂದ ಅದನ್ನು ಬಳಸುವ ಮೊದಲು `ccam login <name>` ರನ್ ಮಾಡಿ.

ನೀವು ಅವುಗಳನ್ನು ಒಂದು ಗುಂಪಿಗೆ ಸೇರಿಸುವವರೆಗೆ (`ccam group join <group> <name>`) ಇಂಪೋರ್ಟ್ ಮಾಡಿದ ಖಾತೆಗಳು ಯಾವ ಗುಂಪಿನಲ್ಲೂ ಇರುವುದಿಲ್ಲ, ಮತ್ತು ಯಾವುದೇ ಶಾರ್ಟ್‌ಕಟ್ ರಚನೆಯಾಗುವುದಿಲ್ಲ.

`ccam completion bash|zsh` ಖಾತೆಯ ಹೆಸರುಗಳನ್ನೂ ಪೂರ್ಣಗೊಳಿಸುವ ಕಂಪ್ಲೀಷನ್ ಸ್ಕ್ರಿಪ್ಟ್ ಅನ್ನು ಮುದ್ರಿಸುತ್ತದೆ.

## ಸುರಕ್ಷತೆ ಮತ್ತು ವಿಶೇಷ ಸಂದರ್ಭಗಳು

- ಖಾತೆ ಚಾಲನೆಯಲ್ಲಿರುವಾಗ `ccam rename` ಮತ್ತು `ccam remove` ``work is running; quit its Claude Code sessions first (`ccam agents` lists them, `ccam work stop <id>` ends a background one)`` ಎಂದು ನಿರಾಕರಿಸುತ್ತವೆ (`refuseRunning`), ಏಕೆಂದರೆ ಸೆಷನ್ ಫೋಲ್ಡರ್‌ಗೆ ಬರೆಯುತ್ತಲೇ ಇರುತ್ತದೆ. Claude Code ಅನ್ನು ಹೇಗೆ ಆರಂಭಿಸಿದ್ದರೂ ಈ ಪರಿಶೀಲನೆ ಅನ್ವಯಿಸುತ್ತದೆ: ccam ಮೂಲಕ, ಸಾಮಾನ್ಯ `claude`, IDE, ಹಿನ್ನೆಲೆ ಸೆಷನ್‌ಗಳು ಮತ್ತು ಅವುಗಳ daemon.
- ಇನ್ನೊಂದು ccam ಪ್ರೊಸೆಸ್ ಆ ಲಾಗಿನ್ ಅನ್ನು ನವೀಕರಿಸುತ್ತಿರುವಾಗ ಅಥವಾ ಬದಲಾಯಿಸುತ್ತಿರುವಾಗ `ccam rename`, `ccam remove` ಮತ್ತು `ccam logout` ``another ccam process is using the login of work right now (a refresh, rename, remove or logout); try again in a moment`` ಎಂದು ನಿರಾಕರಿಸುತ್ತವೆ.
- ಇನ್ನೊಂದು ccam ಪ್ರೊಸೆಸ್‌ನಲ್ಲಿ ಗುಂಪು ಬದಲಾವಣೆ ನಡೆಯುತ್ತಿರುವಾಗ, `ccam rename` ಮತ್ತು `ccam remove` `another ccam process is changing the groups right now; try again when it is done` ಎಂದು ನಿರಾಕರಿಸುತ್ತವೆ; ಬದಲಾವಣೆ ಅರ್ಧದಲ್ಲಿ ನಿಂತ ನಂತರ, ``the last group change stopped halfway; finish it with `ccam doctor --fix` first`` ಎಂದು.
- ಇಂಪೋರ್ಟ್ ಮಾಡಿದ ಖಾತೆಯ ಮೇಲೆ `ccam remove` ಸಾಮಾನ್ಯ `claude` ಗಾಗಿ ಫೋಲ್ಡರ್ ಮತ್ತು ಅದರ ಲಾಗಿನ್ ಅನ್ನು ಉಳಿಸಿಕೊಳ್ಳುತ್ತದೆ. ಖಾತೆ ಗುಂಪುಗಳಲ್ಲಿದ್ದರೆ, ಅದು ಮೊದಲು `ccam group leave` ಮಾಡುವಂತೆ ಅವುಗಳನ್ನು ಬಿಡುತ್ತದೆ: ಪ್ರತಿ ಹಂಚಿಕೊಂಡ ಐಟಂ ಫೋಲ್ಡರ್‌ನಲ್ಲಿ ಗುಂಪಿನದರ ಪ್ರತಿಯಾಗುತ್ತದೆ, ಮತ್ತು ಗುಂಪಿನ MCP ಸರ್ವರ್‌ಗಳು ಅದರ `.claude.json` ಗೆ ಹೋಗುತ್ತವೆ. ನಂತರ ಅದರ ನೋಂದಣಿ ರದ್ದಾಗುತ್ತದೆ: `✓ main unregistered (folder ... left in place; it left its groups with a copy of what they share)`. ccam ರಚಿಸಿದ ಅದರ `.claude.json` ನ ಬ್ಯಾಕಪ್‌ಗಳು `<folder>/.ccam-backup/mcp-<time>` ಗೆ ಹೋಗುತ್ತವೆ; ಅವುಗಳನ್ನು ಸ್ಥಳಾಂತರಿಸಲಾಗದಿದ್ದರೆ, ಅವು `~/.local/state/ccam/mcp/<name>/backups` ನಲ್ಲಿ ಉಳಿಯುತ್ತವೆ ಮತ್ತು ಸಂದೇಶ ಅದನ್ನು ತಿಳಿಸುತ್ತದೆ. ನಿಮ್ಮ `~/.claude` ಟ್ರ್ಯಾಶ್‌ಗೆ ಹೋಗುವುದಿಲ್ಲ.
- ಎರಡು ಖಾತೆಗಳಿಗೆ ಒಂದೇ ಫೋಲ್ಡರ್ ಇರಲು ಸಾಧ್ಯವಿಲ್ಲ: ಒಂದೇ ಫೋಲ್ಡರ್ ಅನ್ನು ಎರಡು ಬಾರಿ ಹೆಸರಿಸುವ `config.toml` ಲೋಡ್ ಆಗಲು ವಿಫಲವಾಗುತ್ತದೆ.
- `profiles/` ನಲ್ಲಿ ಈಗಾಗಲೇ ಫೋಲ್ಡರ್ ಇರುವ ಹೆಸರನ್ನು `ccam add` ನಿರಾಕರಿಸುತ್ತದೆ ಮತ್ತು `ccam import` ಅನ್ನು ಸೂಚಿಸುತ್ತದೆ. macOS ನಲ್ಲಿ, ccam ನ ಹಳೆಯ ಆವೃತ್ತಿ ಬಿಟ್ಟುಹೋದ, ಹೊಸ ಫೋಲ್ಡರ್‌ನ ಪಾತ್‌ಗಾಗಿನ ಲಾಗಿನ್ ಅಥವಾ MCP ಸೈನ್-ಇನ್‌ಗಳು Keychain ನಲ್ಲಿ ಇನ್ನೂ ಇದ್ದಾಗಲೂ ಅದು ನಿಲ್ಲುತ್ತದೆ, ಮತ್ತು ಅವುಗಳನ್ನು ತೆಗೆದುಹಾಕುವ `security delete-generic-password` ಕಮಾಂಡ್ ಅನ್ನು ಹೆಸರಿಸುತ್ತದೆ. `config.toml` ಅನ್ನು ಉಳಿಸಲಾಗದಿದ್ದರೆ, ಹೊಸ ಫೋಲ್ಡರ್ ಅನ್ನು ಮತ್ತೆ ತೆಗೆದುಹಾಕಲಾಗುತ್ತದೆ.
- `ccam import` ಈಗಾಗಲೇ ನೋಂದಾಯಿಸಿದ ಫೋಲ್ಡರ್, ಫೋಲ್ಡರ್ ಅಲ್ಲದ ಪಾತ್, ಮತ್ತು ಈಗಾಗಲೇ ಬಳಕೆಯಲ್ಲಿರುವ ಹೆಸರನ್ನು ನಿರಾಕರಿಸುತ್ತದೆ. ಫೋಲ್ಡರ್ `~/.claude` ನ ಪ್ರತಿಯಾಗಿದ್ದರೆ (ಅದೇ ಲಾಗಿನ್), `~/.claude` ತಾನೇ ನೋಂದಣಿಯಾಗದಿದ್ದರೂ, ccam ಎಚ್ಚರಿಸುತ್ತದೆ.
- ಖಾತೆ ಚಾಲನೆಯಲ್ಲಿದ್ದಾಗ `ccam logout` ಮೊದಲು ಕೇಳುತ್ತದೆ; `ccam login` ಪರಿಶೀಲಿಸುವುದಿಲ್ಲ.
- ರಿಲೇ Claude Code ಅನ್ನು ತಲುಪಲಾಗದಿದ್ದರೆ, ಉದಾಹರಣೆಗೆ ಲಾಗಿನ್ ಮುಗಿದ ನಂತರ, ಅದು ಕಾರಣದೊಂದಿಗೆ `ccam: could not pass the sign-in to Claude Code:` ಎಂದು ಮುದ್ರಿಸುತ್ತದೆ. HTTP ದೋಷ ಸಾಮಾನ್ಯವಾಗಿ ಕೋಡ್‌ನ ಅವಧಿ ಮುಗಿದಿದೆ ಎಂದರ್ಥ; ಲಾಗಿನ್ ಅನ್ನು ಮತ್ತೆ ಆರಂಭಿಸಿ.
