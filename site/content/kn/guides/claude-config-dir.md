`CLAUDE_CONFIG_DIR` ಎಂಬುದು `~/.claude` ಬದಲಿಗೆ ಯಾವ ಫೋಲ್ಡರ್ ಬಳಸಬೇಕು ಎಂದು Claude Code ಗೆ ತಿಳಿಸುತ್ತದೆ. ಖಾತೆಗೆ ಸಂಬಂಧಿಸಿದ ಎಲ್ಲವೂ ಅಲ್ಲಿರುತ್ತದೆ: ಲಾಗಿನ್, ಸೆಟ್ಟಿಂಗ್‌ಗಳು, MCP ಸರ್ವರ್‌ಗಳು, ಪ್ಲಗಿನ್‌ಗಳು ಮತ್ತು ಸಂಭಾಷಣೆಯ ಇತಿಹಾಸ. ಇದನ್ನು ಬೇರೆ ಬೇರೆ ಫೋಲ್ಡರ್‌ಗಳಿಗೆ ಸೂಚಿಸಿದರೆ ನಿಮಗೆ ಪ್ರತ್ಯೇಕ ಖಾತೆಗಳು ಸಿಗುತ್ತವೆ.

```sh
CLAUDE_CONFIG_DIR=~/.claude-work claude
```

## CLAUDE_CONFIG_DIR ಅಧಿಕೃತವಾಗಿ ಬೆಂಬಲಿತವೇ?

ಹೌದು. Claude Code ತನ್ನ [ಎನ್ವಿರಾನ್‌ಮೆಂಟ್ ವೇರಿಯೇಬಲ್‌ಗಳ](https://code.claude.com/docs/en/env-vars) ಪಟ್ಟಿಯಲ್ಲಿ ಇದನ್ನು ಕಾನ್ಫಿಗರೇಶನ್ ಫೋಲ್ಡರ್ ಬದಲಾಯಿಸುವ ವಿಧಾನವಾಗಿ ನೀಡಿದೆ, "useful for running multiple accounts side by side" ಎಂದು. ಅದರ [ದೃಢೀಕರಣ ಮಾರ್ಗದರ್ಶಿ](https://code.claude.com/docs/en/authentication#log-in-with-multiple-accounts) ಹಲವು ಖಾತೆಗಳಿಂದ ಲಾಗಿನ್ ಮಾಡಲು ಇದನ್ನೇ ಬಳಸುತ್ತದೆ. ಇದನ್ನು ನಿಮ್ಮ ಶೆಲ್‌ನಲ್ಲಿ ಅಥವಾ ಬಳಕೆದಾರ ಸೆಟ್ಟಿಂಗ್‌ಗಳಲ್ಲಿ ಹೊಂದಿಸಬಹುದು, ಆದರೆ ಪ್ರಾಜೆಕ್ಟ್‌ನ ಸೆಟ್ಟಿಂಗ್‌ಗಳಲ್ಲಿ ಅಲ್ಲ.

## ಫೋಲ್ಡರ್‌ನೊಳಗೆ ಏನಿದೆ?

Claude Code 2.1.302 ನೊಂದಿಗೆ ಪರಿಶೀಲಿಸಲಾಗಿದೆ:

| ಪಾತ್ | ಒಳಗೊಂಡಿರುವುದು | ಹಂಚಿಕೊಳ್ಳಬಹುದೇ |
| --- | --- | --- |
| `.credentials.json` | ಲಾಗಿನ್ ಟೋಕನ್‌ಗಳು (Linux, Windows), MCP OAuth ಟೋಕನ್‌ಗಳು | ಇಲ್ಲ |
| `.claude.json` | ಖಾತೆಯ ವಿವರಗಳು, ಬಳಕೆದಾರ MCP ಸರ್ವರ್‌ಗಳು, ಪ್ರಾಜೆಕ್ಟ್‌ವಾರು ಸ್ಥಿತಿ | ಇಲ್ಲ (MCP ಸರ್ವರ್‌ಗಳನ್ನು ಪ್ರತ್ಯೇಕವಾಗಿ) |
| `settings.json` | ಅನುಮತಿಗಳು, hooks, ಮಾಡೆಲ್, ಸ್ಟೇಟಸ್ ಲೈನ್, ಪ್ಲಗಿನ್‌ಗಳು | ಹೌದು |
| `CLAUDE.md` | ಜಾಗತಿಕ ಸೂಚನೆಗಳು | ಹೌದು |
| `agents/`, `commands/`, `skills/`, `plugins/` | ವಿಸ್ತರಣೆಗಳು | ಹೌದು |
| `projects/` | `.jsonl` ಫೈಲ್‌ಗಳ ರೂಪದಲ್ಲಿ ಸಂಭಾಷಣೆಗಳು, ಪ್ರಾಜೆಕ್ಟ್‌ವಾರು ಮೆಮೊರಿ | ಹೌದು |
| `history.jsonl` | ಪ್ರಾಂಪ್ಟ್ ಇತಿಹಾಸ | ಹೌದು |
| `sessions/`, `shell-snapshots/`, `cache/` ಮತ್ತು ಇತರವು | ರನ್‌ಟೈಮ್ ಸ್ಥಿತಿ | ಇಲ್ಲ |

## ಜನರು ಎಲ್ಲಿ ಗೊಂದಲಕ್ಕೀಡಾಗುತ್ತಾರೆ?

**`CLAUDE_CONFIG_DIR` ಇಲ್ಲದಿದ್ದಾಗ, `.claude.json` ಎಂಬುದು `~/.claude` ಒಳಗೆ ಇರುವುದಿಲ್ಲ.** ಆಗ Claude Code ಅದನ್ನು ಫೋಲ್ಡರ್‌ನ ಪಕ್ಕದಲ್ಲಿ, `~/.claude.json` ನಲ್ಲಿ ಇರಿಸುತ್ತದೆ. ನೀವು `CLAUDE_CONFIG_DIR=~/.claude` ಬಳಸಲು ಆರಂಭಿಸಿದರೆ, Claude Code ಬದಲಿಗೆ `~/.claude/.claude.json` ಗಾಗಿ ಹುಡುಕುತ್ತದೆ ಮತ್ತು ನಿಮ್ಮ ಖಾತೆ ಅದಕ್ಕೆ ಸಿಗುವುದಿಲ್ಲ. `ccam import` ಈ ಎರಡನ್ನೂ ಲಿಂಕ್ ಮಾಡುವ ಮೂಲಕ ಇದನ್ನು ನಿಭಾಯಿಸುತ್ತದೆ.

**macOS ನಲ್ಲಿ ಲಾಗಿನ್ ಫೋಲ್ಡರ್‌ನಲ್ಲಿ ಇರುವುದಿಲ್ಲ, Keychain ನಲ್ಲಿ ಇರುತ್ತದೆ.** Claude Code ಅದನ್ನು `Claude Code-credentials` ಎಂಬ ಹೆಸರಿನಡಿ ಸಂಗ್ರಹಿಸುತ್ತದೆ; `CLAUDE_CONFIG_DIR` ಹೊಂದಿಸಿದ್ದರೆ, ಅದರ ನಂತರ ಫೋಲ್ಡರ್ ಪಾತ್‌ನ ಒಂದು ಚಿಕ್ಕ ಹ್ಯಾಶ್ ಇರುತ್ತದೆ. ಆದ್ದರಿಂದ ಪ್ರತ್ಯೇಕ ಫೋಲ್ಡರ್‌ಗಳಿಗೆ ಪ್ರತ್ಯೇಕ Keychain ನಮೂದುಗಳು ಸಿಗುತ್ತವೆ. Keychain ಬರೆಯಲು ನಿರಾಕರಿಸಿದರೆ, [ಅದರ ದಸ್ತಾವೇಜು](https://code.claude.com/docs/en/authentication#credential-management) ವಿವರಿಸುವಂತೆ Claude Code ಫೋಲ್ಡರ್‌ನಲ್ಲಿರುವ `.credentials.json` ಅನ್ನು ಬಳಸುತ್ತದೆ.

**ಎಲ್ಲಾ ಸೈನ್-ಇನ್‌ಗಳು ಫೋಲ್ಡರ್‌ನಲ್ಲಿ ಇರುವುದಿಲ್ಲ.** API ಕೀ ಇಲ್ಲದ Claude Console ಸೈನ್-ಇನ್ ಫೋಲ್ಡರ್‌ನ ಹೊರಗೆ ಸಂಗ್ರಹವಾಗುತ್ತದೆ, ಆದ್ದರಿಂದ ಪ್ರತ್ಯೇಕ ಫೋಲ್ಡರ್‌ಗಳು ಅಂತಹ ಎರಡು ಸೈನ್-ಇನ್‌ಗಳನ್ನು ಬೇರ್ಪಡಿಸುವುದಿಲ್ಲ. claude.ai ಲಾಗಿನ್‌ಗಳು ಮತ್ತು API ಕೀಗಳು ಫೋಲ್ಡರ್‌ವಾರು ಇರುತ್ತವೆ.

## Windows ನಲ್ಲಿ ಫೋಲ್ಡರ್ ಎಲ್ಲಿದೆ?

ಡೀಫಾಲ್ಟ್ ಆಗಿ `%USERPROFILE%\.claude`, ಲಾಗಿನ್ ಅದರೊಳಗಿನ `.credentials.json` ನಲ್ಲಿ ಇರುತ್ತದೆ. ಪ್ರತಿ ಹೆಚ್ಚುವರಿ ಖಾತೆಗೆ `CLAUDE_CONFIG_DIR` ಅನ್ನು ಬೇರೆ ಫೋಲ್ಡರ್‌ಗೆ ಹೊಂದಿಸಿ, Linux ಮತ್ತು macOS ನಲ್ಲಿ ಮಾಡುವಂತೆಯೇ.

## ಫೋಲ್ಡರ್‌ಗಳು ಫೈಲ್‌ಗಳನ್ನು ಹಂಚಿಕೊಳ್ಳಬಹುದೇ?

ಸಿಂಬಾಲಿಕ್ ಲಿಂಕ್‌ಗಳು ಕೆಲಸ ಮಾಡುತ್ತವೆ: ಲಿಂಕ್ ಮಾಡಿದ `settings.json` ಅಥವಾ `projects/` ಫೋಲ್ಡರ್ ಮೂಲಕ Claude Code ಓದುತ್ತದೆ ಮತ್ತು ಬರೆಯುತ್ತದೆ, ಮತ್ತು ಲಿಂಕ್ ಅನ್ನು ಹಾಗೆಯೇ ಉಳಿಸುತ್ತದೆ. MCP ಸರ್ವರ್‌ಗಳು ಇದಕ್ಕೆ ಅಪವಾದ, ಏಕೆಂದರೆ ಅವು ಲಾಗಿನ್ ಜೊತೆ `.claude.json` ಅನ್ನು ಹಂಚಿಕೊಳ್ಳುತ್ತವೆ; ಬದಲಿಗೆ ಅವುಗಳನ್ನು `--mcp-config` ಮೂಲಕ ರವಾನಿಸಿ.

ccam ನಿಖರವಾಗಿ ಈ ನಿಯಮಗಳ ಮೇಲೆಯೇ ನಿರ್ಮಿತವಾಗಿದೆ. ಅದು ಫೋಲ್ಡರ್‌ಗಳನ್ನು ಹೇಗೆ ಲಿಂಕ್ ಮಾಡುತ್ತದೆ ಎಂದು ತಿಳಿಯಲು [ಹಂಚಿಕೆ](/docs/sharing) ನೋಡಿ, ಮತ್ತು ಒಟ್ಟಾರೆ ಚಿತ್ರಕ್ಕಾಗಿ [ಹಲವು ಖಾತೆಗಳ ಮಾರ್ಗದರ್ಶಿ](/guides/multiple-claude-code-accounts) ನೋಡಿ.
