प्रत्येक खात्याला स्वतःचा configuration फोल्डर द्या. Claude Code हा फोल्डर `CLAUDE_CONFIG_DIR` environment variable मधून वाचते, आणि प्रत्येक फोल्डरमध्ये स्वतःचे लॉगिन, सेटिंग्ज आणि इतिहास असतो. त्यामुळे प्रत्येक खाते लॉगिन राहते आणि तुम्ही ती एकाच वेळी चालवू शकता. हे तुम्ही शेल alias ने हाताने सेट करू शकता, किंवा ccam ला करू देऊ शकता.

## हे हाताने कसे सेट करायचे?

[Claude Code च्या दस्तऐवजात हीच पद्धत सांगितली आहे](https://code.claude.com/docs/en/authentication#log-in-with-multiple-accounts). प्रत्येक अतिरिक्त खात्यासाठी `~/.bashrc` किंवा `~/.zshrc` मध्ये एक ओळ जोडा:

```sh
alias claude-work='CLAUDE_CONFIG_DIR=~/.claude-work claude'
```

नवीन टर्मिनल उघडा आणि `claude-work` चालवा. फोल्डर नवीन असल्यामुळे Claude Code तुम्हाला लॉगिन करायला सांगते. त्यानंतर `claude` हे तुमचे पहिले खाते आणि `claude-work` दुसरे खाते असते.

WSL शिवाय Windows वर, तुमच्या profile मधील (`notepad $PROFILE`) एक PowerShell function हेच काम करते:

```powershell
function claude-work { $env:CLAUDE_CONFIG_DIR = "$HOME\.claude-work"; try { claude @args } finally { Remove-Item Env:CLAUDE_CONFIG_DIR } }
```

## alias पद्धतीत काय राहून जाते?

दोन खात्यांसाठी हे चांगले काम करते. लक्षात ठेवण्यासारख्या गोष्टी:

- प्रत्येक फोल्डर रिकामा सुरू होतो: सेटिंग्ज नाहीत, `CLAUDE.md` नाही, MCP सर्व्हर नाहीत, agents किंवा skills नाहीत. जे लागते ते तुम्ही कॉपी किंवा लिंक करता, आणि त्या प्रती एकसारख्या ठेवण्याचे काम स्वतः करता.
- Aliases फक्त interactive शेलमध्ये असतात. स्क्रिप्ट्स, Makefiles आणि इतर प्रोग्राम्सना ते दिसत नाहीत.
- MCP सर्व्हर लॉगिनच्या शेजारी `.claude.json` मध्ये असतात, त्यामुळे ते फोल्डर्समध्ये सहज लिंक करता येत नाहीत.
- संभाषणे ज्या खात्यात सुरू झाली त्याच खात्यात राहतात, त्यामुळे ती दुसऱ्या खात्यात पुढे चालू ठेवता येत नाहीत.
- सर्व खात्यांचा वापर एकाच वेळी दाखवणारे काहीही नाही.

## त्याऐवजी /login ने खाते बदलता येते का?

हो, जर तुम्ही कधीतरीच खाते बदलत असाल. Claude Code मध्ये `/login` टाइप केल्यावर तुम्ही ज्या फोल्डरमध्ये आहात त्याचे [खाते बदलते](https://code.claude.com/docs/en/quickstart). एका वेळी एकच खाते लॉगिन असते, त्यामुळे प्रत्येक बदलाच्या वेळी पुन्हा लॉगिन करावे लागते, आणि दोन खाती शेजारी शेजारी चालवता येत नाहीत. वेगळे फोल्डर वापरल्यास या दोन्ही अडचणी टळतात.

## ccam वापरून हे कसे सेट करायचे?

ccam हीच कल्पना स्वयंचलित करते आणि उणिवा भरून काढते:

```sh
curl -fsSL https://ccam.dev/install.sh | sh
ccam add personal
ccam add work --shortcut ccwork
```

आता `ccam personal` आणि `ccam work` ही दोन खाती सुरू करतात, आणि `ccwork` सुद्धा, जो शॉर्टकट तुम्ही work खात्याला दिला. ते aliases नसून खरे प्रोग्राम आहेत, त्यामुळे scripts मध्येही चालतात. यादीतून खाते निवडण्यासाठी फक्त `ccam` चालवा, आणि एखादे खाते डीफॉल्ट करण्यासाठी `ccam use work` चालवा.

सेटिंग्ज, `CLAUDE.md`, MCP सर्व्हर आणि एक्स्टेंशन्स सुरुवातीपासून शेअर होतात. `ccam next --continue` संभाषण दुसऱ्या खात्यावर पुढे चालू ठेवते. तुम्ही शेअर केलेला संभाषण इतिहास चालू केल्यास, दोन्ही खाती प्रतीऐवजी त्याच संभाषणावर काम करतात. `ccam usage` सर्व खात्यांचा 5 तासांचा आणि साप्ताहिक वापर एकाच वेळी दाखवते.

तुम्ही आधीच `~/.claude` वापरत असाल, तर ते खाते पुन्हा जोडण्याऐवजी `ccam import` चालवा, किंवा त्याची सेटिंग्ज, MCP सर्व्हर आणि एक्स्टेंशन्स शेअर केलेल्या `default` गटात कॉपी करण्यासाठी `ccam migrate` चालवा.

## कोणते खाते चालू आहे हे कसे ओळखायचे?

Claude Code मध्ये `/status` तुम्ही कोणत्या खात्यात लॉगिन आहात ते दाखवते. ccam सोबत एकदा `ccam statusline install` चालवा, मग स्टेटस लाइन सतत खात्याचे नाव आणि त्याचा वापर दाखवते, उदाहरणार्थ `[work] · Opus · 5h 24% · 7d 41%`.

## हे Windows आणि WSL वर चालते का?

Claude Code [थेट Windows वर आणि WSL मध्येही](https://code.claude.com/docs/en/setup) चालते. `CLAUDE_CONFIG_DIR` दोन्हीकडे काम करते, त्यामुळे native Windows वर वरील alias किंवा PowerShell function पुरेसे आहे. ccam सुद्धा थेट Windows वर चालते: PowerShell मध्ये `irm https://ccam.dev/install.ps1 | iex` ने ते इन्स्टॉल करा, किंवा WSL मध्ये Linux च्या कमांडने. शॉर्टकट `ccwork.exe` बनतात, आणि `settings.json` सारख्या फाइल्स शेअर करण्यासाठी Developer Mode लागतो ([ccam इन्स्टॉल करा](/docs/install)).

## समस्या निवारण

**Claude Code प्रत्येक वेळी लॉगिन करायला सांगते.** नवीन फोल्डरमध्ये पहिल्यांदा सुरू करताना ते नेहमी विचारते. ते वारंवार विचारत असेल, तर लॉगिनची मुदत संपली आहे किंवा ते काढले गेले आहे: `ccam login work` चालवा (किंवा alias एकदा सुरू करून लॉगिन करा).

**एखादा MCP सर्व्हर फक्त एकाच खात्यात दिसतो.** सत्रात `claude mcp add` ने जोडलेले सर्व्हर त्या खात्याचे असतात, आणि `-s user` शिवाय फक्त त्या फोल्डरचे. एखादा सर्व्हर सर्व खात्यांत नेण्यासाठी `ccam mcp import work <server>` चालवा.

**खात्यांच्या सेटिंग्ज वेगवेगळ्या आहेत.** `ccam share work` ते खाते काय शेअर करते आणि कोणत्या गटामार्फत ते दाखवते; `ccam group join default work` आधी काय बदलेल ते दाखवते आणि मग `default` जे शेअर करतो ते या खात्यालाही शेअर करू देते. `ccam doctor --fix` तुटलेल्या लिंक दुरुस्त करते आणि बदललेल्या प्रत्येक फाइलचा बॅकअप ठेवते.

**दोन खाती एकच संभाषण उघडतात.** एकाच संभाषणावर एकाच वेळी दोन खात्यांमध्ये काम करणे टाळा. तसे करण्याचा प्रयत्न केल्यास ccam तुम्हाला सावध करते.

## कोणते निवडायचे?

दोन खाती आणि काहीही शेअर न करण्यासाठी alias पुरेसा आहे. शेअर केलेल्या सेटिंग्ज आणि MCP सर्व्हर, जास्त खाती, एका नजरेत वापर किंवा संभाषणे पुढे चालू ठेवणे हवे असेल, तेव्हा ccam तुमची ही हिशोबाची कामे वाचवते. [aliases शी तुलना](/compare/aliases) फरक शेजारी शेजारी दाखवते, आणि [ccam आणि इतर account switchers](/compare/account-switchers) त्याऐवजी एकच लॉगिन बदलणाऱ्या टूल्सबद्दल सांगते.

तुम्ही एकापेक्षा जास्त खाती वापरू शकता की नाही हे प्रत्येक खात्याला लागू होणाऱ्या अटींवर अवलंबून आहे. सुरू करण्यापूर्वी त्या अटी वाचा.

**Team आणि Enterprise सीट्स.** आपोआप होणारी खाते निवड (`ccam next`, `--fallback`, `ccam pick`, डॅशबोर्डमधील `n` आणि, तुम्ही चालू केल्यावर, [`auto_switch`](/features/next#auto-switch)) एकाच Claude Team किंवा Enterprise organization मधील सीट्सदरम्यानही खाते बदलते, आणि यामुळे Anthropic च्या अटींचे उल्लंघन होऊ शकते. त्यावर अवलंबून राहण्यापूर्वी [FAQ](/docs/faq#am-i-allowed-to-use-several-claude-code-accounts) वाचा आणि तुमच्या संस्थेकडे आणि Anthropic कडे चौकशी करा.
