`ccam usage` প্রতিটি অ্যাকাউন্টের জন্য দেখায় প্রতিটি সীমার কতটা ব্যবহার হয়েছে: ৫ ঘণ্টার সীমা, সাপ্তাহিক সীমা ও প্রতিটি মডেলের নিজস্ব সাপ্তাহিক সীমা (যেমন Fable)। প্রতিটি সীমার জন্য থাকে একটি বার ও তা রিসেট হওয়া পর্যন্ত সময়। কোন অ্যাকাউন্টে জায়গা বাকি আছে তা দেখতে দীর্ঘ কোনো কাজ শুরুর আগে, বা Claude Code যখন জানায় সীমা কাছে, তখন এটি ব্যবহার করুন। `ccam statusline` হলো Claude Code-এর স্ট্যাটাস লাইন কমান্ড: এটি Claude Code-এর ভেতরে অ্যাকাউন্টের নাম ও ব্যবহার দেখায় এবং `ccam usage`-এর জন্য সংখ্যাগুলো সংরক্ষণ করে। ব্যবহারের পেছনের টোকেন ও আনুমানিক খরচ জানতে `ccam ccusage` সব অ্যাকাউন্টের কথোপকথনের ওপর [ccusage](https://ccusage.com) চালায় ([নিচে](#tokens-and-costs-ccam-ccusage))।

## ব্যবহার

```sh
ccam usage                  # every account, once
ccam u                      # the same, shorter
ccam usage --watch          # redraw every 60 seconds until Ctrl+C
ccam usage --watch=10       # redraw every 10 seconds
ccam usage -v               # add where the numbers came from
ccam usage --json           # machine-readable, one object per account
ccam usage --source cache   # saved numbers only, no network
ccam usage --refresh        # also renew expired logins of accounts that are not running
ccam usage --source claude  # let Claude Code look it up: ccam sends no token
ccam statusline install     # set the status line in every account's settings.json
```

প্রতিটি অ্যাকাউন্ট একটি লাইন পায়, যাতে থাকে তার নম্বর, নাম ও সংখ্যাগুলো কতক্ষণ আগের; `(cached)` মানে সেগুলো এন্ডপয়েন্ট থেকে নয়, সংরক্ষিত ফাইল থেকে এসেছে। তার নিচে প্রতিটি সীমার একটি লাইনে থাকে ২০ ঘরের একটি বার, শতাংশ ও উইন্ডো রিসেট হওয়া পর্যন্ত সময়: `5-hour`, `Weekly` (সব মডেল), তারপর প্রতিটি মডেলের নিজস্ব সাপ্তাহিক উইন্ডো, যেমন `Fable`। অ্যাকাউন্টের যে উইন্ডো নেই তা দেখায় `-`। শতাংশ ৮০%-এ হলুদ আর ১০০%-এ লাল হয়ে যায়।

কোনো উইন্ডো পূর্ণ থাকায় Claude Code কোনো অনুরোধ প্রত্যাখ্যান করলে সেই উইন্ডো রিসেট পর্যন্ত ১০০% দেখায়, সংরক্ষিত সংখ্যা যা-ই বলুক ([সীমার রেকর্ড](#the-limit-record) দেখুন)। টার্মিনালে প্রতিটি অ্যাকাউন্ট সঙ্গে সঙ্গে `fetching…` হিসেবে দেখা যায়, এবং উত্তর দেওয়ার সঙ্গে সঙ্গে তার লাইনগুলো আঁকা হয়।

শেষ লাইনটি, যা শুধু একাধিক অ্যাকাউন্ট থাকলে দেখা যায়, সেই অ্যাকাউন্টের নাম দেয় যা [`ccam next --auto`](/features/next) বেছে নিত। এটি একই নিয়ম মানে:

- `auto_max_usage` ও `auto_strategy`;
- চলমান সেশনগুলো;
- `cross_org` সেট না থাকলে শুধু সর্বশেষ ব্যবহৃত অ্যাকাউন্টের প্রতিষ্ঠানের অ্যাকাউন্ট;
- ১০০%-এ থাকা প্রতিটি উইন্ডো বাদ দেওয়া হয়, তাই যে অ্যাকাউন্টের সপ্তাহ পূর্ণ তার নাম কখনও আসে না।

ডিফল্ট `headroom` কৌশলে লাইনটি হয় `→ Most headroom: <name>`; `expiring` বা `balance`-এ এটি কারণ জানায়, যেমন `→ next --auto picks personal: its 5-hour window resets first, in 1h 12m (40% of its 5 hours used)`।

**Team ও Enterprise সিট।** স্বয়ংক্রিয় অ্যাকাউন্ট বাছাই (`ccam next`, `--fallback`, `ccam pick`, ড্যাশবোর্ডের `n` এবং আপনি চালু করলে [`auto_switch`](/features/next#auto-switch)) একই Claude Team বা Enterprise প্রতিষ্ঠানের সিটগুলোর মধ্যেও বদল করে, যা Anthropic-এর শর্তাবলি লঙ্ঘন করতে পারে। এর ওপর নির্ভর করার আগে [প্রশ্নোত্তর](/docs/faq#am-i-allowed-to-use-several-claude-code-accounts) পড়ুন এবং আপনার প্রতিষ্ঠান ও Anthropic-এর কাছ থেকে জেনে নিন।

লগইন না করা অ্যাকাউন্ট দেখায় `not logged in → ccam login <name>`, আর API কী-এর অ্যাকাউন্ট দেখায় `no limits (API)`। মেয়াদোত্তীর্ণ অ্যাক্সেস টোকেন দেখায় ``access token expired; `ccam <name>` renews it when it starts``, সংরক্ষিত সংখ্যা থাকলে সেগুলোর ওপরে: Claude Code পরের বার চালু হলে সেটি নবায়ন করে। যে লগইনের মেয়াদ পুরোপুরি শেষ, কারণ তার রিফ্রেশ টোকেনের মেয়াদ ফুরিয়েছে বা সার্ভার প্রত্যাখ্যান করার পর Claude Code সেটি মুছে দিয়েছে, সেটি দেখায় `` login expired → `ccam login <name>` ``।

`ccam statusline install`-এর পরে Claude Code `[work] · Opus · 5h 24% · 7d 41%`-এর মতো একটি লাইন দেখায়।

## অপশন

| অপশন | কী করে | ডিফল্ট |
| --- | --- | --- |
| `--json` | রিপোর্টগুলো JSON হিসেবে প্রিন্ট করে: `name`, `slot`, `status`, `limits` (অ্যাকাউন্টে ব্যবহারের ক্রেডিট চালু থাকলে `credits`-সহ), `source`, `at`, `error`, এবং কোনো সীমার রেকর্ড উইন্ডোগুলোকে ১০০% করলে `limited` ও `limited_windows`। কোনো অ্যাকাউন্ট না থাকলে এটি `[]` প্রিন্ট করে | বন্ধ |
| `--watch[=N]` | Ctrl+C না চাপা পর্যন্ত প্রতি `N` সেকেন্ডে আবার আঁকে। শুধু `--watch`, বা 0 বা তার কম মান, মানে 60। মানটি বসে `=`-এর পরে: `--watch 10` একটি ইঙ্গিতসহ প্রত্যাখ্যান করা হয় | বন্ধ |
| `-v`, `--verbose` | প্রতিটি অ্যাকাউন্টের নিচে একটি `source:` লাইন যোগ করে: তার সংখ্যাগুলো কোথা থেকে এসেছে (ব্যবহারের এন্ডপয়েন্ট, Claude Code, স্ট্যাটাস লাইন, সংরক্ষিত ফাইল, বা Claude Code-এর জানানো ব্যবহারের সীমা)। কোনো সীমার রেকর্ড সংখ্যাগুলোকে ছাপিয়ে গেলে এরপর `Weekly full: Claude Code reported the usage limit 1h 0m ago, so 100% until the reset`-এর মতো একটি লাইন আসে | বন্ধ |
| `--no-cache` | ৬০ সেকেন্ডের ক্যাশ উপেক্ষা করে আবার এন্ডপয়েন্টে জিজ্ঞেস করে | বন্ধ |
| `--source live\|claude\|cache` | `live` অ্যাকাউন্টের টোকেন দিয়ে এন্ডপয়েন্টে জিজ্ঞেস করে; `claude` Claude Code-কে দিয়ে খোঁজ করায় (নিচে দেখুন); `cache` শুধু সংরক্ষিত সংখ্যা দেখায় | `usage_source`, অন্যথায় `live` |
| `--refresh` | মেয়াদোত্তীর্ণ অ্যাক্সেস টোকেন নবায়ন করে, শুধু যে অ্যাকাউন্টগুলো চলছে না সেগুলোর জন্য। একটি নবায়নে সর্বোচ্চ ৩০ সেকেন্ড লাগতে পারে | বন্ধ |
| `--dry-run` | গ্রহণ করা হয়: `ccam usage` নিজের ক্যাশ ছাড়া কিছু বদলায় না। `--refresh`-এর সঙ্গে প্রত্যাখ্যান করা হয়: `--dry-run cannot be combined with --refresh, which rewrites login tokens` | বন্ধ |

অন্য যেকোনো `--source` মান `--source must be live, claude or cache` দিয়ে ব্যর্থ হয়। `ccam usage` কোনো আর্গুমেন্ট নেয় না।

### Claude Code-এর নিজের কাছ থেকে ব্যবহার

`config.toml`-এর একেবারে ওপরে (প্রথম `[[group]]`, `[[profile]]` বা `[[folder]]`-এর আগে) `usage_source = "claude"` থাকলে, বা `--source claude` দিলে, ccam লগইন টোকেন একেবারেই পড়ে না। প্রতিটি অ্যাকাউন্টের জন্য এটি অ্যাকাউন্টের ফোল্ডারে `claude -p --input-format stream-json --output-format stream-json --verbose --safe-mode --no-session-persistence` চালু করে এবং স্ট্যান্ডার্ড ইনপুটে Claude Code-এর `get_usage` অনুরোধ পাঠায় (Claude Code 2.1.270 বা তার পরের সংস্করণ)। Claude Code নিজের লগইন দিয়ে ব্যবহার খুঁজে ৫ ঘণ্টা, সাপ্তাহিক ও মডেলের উইন্ডোগুলো দিয়ে উত্তর দেয়।

`--safe-mode` অ্যাকাউন্টের হুক, MCP সার্ভার ও প্লাগইন চালু হতে দেয় না, এবং কোনো সেশন সংরক্ষিত হয় না। প্রতিটি অ্যাকাউন্টে একবার Claude Code চালু করতে হয় (প্রায় এক সেকেন্ড), তাই এই উৎস `live`-এর চেয়ে ধীর। অ্যাকাউন্টগুলোকে একসঙ্গে জিজ্ঞেস করা হয়, প্রতিটি ২০ সেকেন্ডের টাইমআউটসহ, এবং ৬০ সেকেন্ডের ক্যাশ যথারীতি প্রযোজ্য।

যে লগইনের অ্যাক্সেস টোকেনের মেয়াদ শেষ, বা ৫ মিনিটের মধ্যে শেষ হবে, সেটি ৫০ সেকেন্ড পায়, কারণ Claude Code চালু হওয়ার সময় সেটি নবায়ন করে এবং মাঝপথে কেটে দেওয়া নবায়নে লগইন হারিয়ে যেতে পারে। ccam কোনো খোঁজ ছেড়ে দিলে SIGTERM দিয়ে Claude Code-কে বন্ধ হতে বলে, যাতে Claude Code শুরু করা নবায়নটি শেষ করতে পারে (Windows-এ SIGTERM নেই, তাই সেখানে প্রসেসটি বন্ধ করে দেওয়া হয়)।

যে লগইনের মেয়াদ পুরোপুরি শেষ, সেটি Claude Code চালু না করেই `` login expired → `ccam login <name>` `` দেখায়। Claude Code অনুরোধটিকে পরীক্ষামূলক হিসেবে চিহ্নিত করে, তাই এটি উত্তর দেওয়া বন্ধ করলে ccam সংরক্ষিত সংখ্যাগুলো দেখায় এবং `ccam doctor` তা জানায়। Claude Code যখন উত্তর দেয় যে তার নিজের খোঁজ ব্যর্থ হয়েছে, ccam তখন সীমাহীন কোনো প্ল্যান নয়, বরং `the usage endpoint gave Claude Code no usage (it may be refusing lookups for now)`-সহ সংরক্ষিত সংখ্যাগুলো দেখায়।

`--dry-run` দিলে ccam Claude Code চালু করে না, কারণ Claude Code অ্যাকাউন্টের ফোল্ডারে লেখে; এর বদলে এটি সংরক্ষিত সংখ্যাগুলো দেখায়। `usage_source`-এর মান হতে পারে `live` বা `claude`; `cache` শুধু `--source`-এর একটি বিকল্প।

`ccam statusline` স্ট্যান্ডার্ড ইনপুট থেকে Claude Code-এর স্ট্যাটাস লাইন JSON পড়ে। এর একমাত্র অপশন `--wrap <command>`: একটি বিদ্যমান স্ট্যাটাস লাইন কমান্ড, যার আউটপুটের প্রথম লাইনের সামনে অ্যাকাউন্টের নাম বসে। `ccam statusline install` কোনো অপশন নেয় না। দুটোই `--dry-run` প্রত্যাখ্যান করে `` --dry-run is not supported by `ccam statusline`; nothing was changed `` দিয়ে।

## টোকেন ও খরচ: `ccam ccusage`

`ccam usage` দেখায় একটি অ্যাকাউন্ট প্রতিটি সীমার কতটা ব্যবহার করেছে। অন্যদিকে [ccusage](https://ccusage.com) Claude Code-এর কথোপকথনের লগে থাকা টোকেন ও আনুমানিক খরচ গোনে। একা চালালে এটি শুধু `~/.claude` ও `~/.config/claude`-এ (অথবা `CLAUDE_CONFIG_DIR` যে ফোল্ডারগুলোর নাম দেয় সেগুলোতে) Claude Code-এর লগ খোঁজে, তাই ccam-এর যে একমাত্র অ্যাকাউন্টটি এটি দেখতে পারে, সেটি হলো `~/.claude`-এ নিজের জায়গায় ইমপোর্ট করা অ্যাকাউন্ট। `ccam ccusage` কথোপকথন আছে এমন প্রতিটি অ্যাকাউন্টের ফোল্ডার `CLAUDE_CONFIG_DIR`-এ দিয়ে এটি চালায়, ফলে একটি রিপোর্টেই সব অ্যাকাউন্ট থাকে:

```sh
ccam ccusage                           # every account, ccusage's daily report
ccam ccusage daily --breakdown         # cost per model
ccam ccusage claude monthly --json     # Claude Code alone, as JSON
ccam ccusage -a work blocks --active   # one account's current 5-hour block
ccam ccusage -a work,side weekly       # these accounts, and any that share their history
```

ccam আগে নিজের অপশনগুলো পড়ে: `-a` (`--account`) অ্যাকাউন্টের নাম বা নম্বর নেয়, কমা দিয়ে আলাদা করে বা অপশনটি একাধিকবার দিয়ে, আর `--dry-run` কমান্ডটি চালানোর বদলে প্রিন্ট করে। ccam-এর অপশন নয় এমন প্রথম আর্গুমেন্ট থেকে শুরু করে সবকিছু অপরিবর্তিত অবস্থায় ccusage-এ যায়; `ccam ccusage -- --help` ccusage-এর নিজস্ব সাহায্য দেখায়। ccam ইনস্টল করা `ccusage` চালায়, তা না থাকলে `bun x ccusage`, তাও না থাকলে `npx ccusage@latest`, আর শেষের এই দুটি এটিকে npm থেকে নামিয়ে আনে; এগুলোর কোনোটিই না থাকলে ccam আপনাকে Node.js, Bun বা ccusage ইনস্টল করতে বলে। Linux ও macOS-এ ccusage ccam-এর জায়গা নেয়; Windows-এ ccam এটি শেষ হওয়া পর্যন্ত অপেক্ষা করে এবং ccusage-এর এক্সিট কোড নিয়েই বেরিয়ে যায়। WSL-এর ভেতরে ccam কোনো Windows ড্রাইভে থাকা `ccusage`, `bun` বা `npx` এড়িয়ে যায়, কারণ সেটি Windows প্রোগ্রাম হিসেবে চলত এবং অ্যাকাউন্টের ফোল্ডারগুলো পেত না।

- রিপোর্টে সেই অ্যাকাউন্টগুলো থাকে যাদের ফোল্ডারে কথোপকথন আছে (একটি `projects` ফোল্ডার)। যে কথোপকথন কয়েকটি অ্যাকাউন্ট একটি গ্রুপের মাধ্যমে শেয়ার করে, সেটি একবারই গোনা হয়।
- `-a` দিলে, যে অ্যাকাউন্ট একটি গ্রুপের মাধ্যমে তার ইতিহাস শেয়ার করে, সেটি পুরো গ্রুপের কথোপকথন সঙ্গে নিয়ে আসে, এবং ccam জানায় সেগুলো কার: `ccam: work shares its conversation history with personal, so the report counts their conversations too`।
- `blocks` ৫ ঘণ্টার উইন্ডো দেখায়, আর প্রতিটি অ্যাকাউন্টের উইন্ডো আলাদা, তাই এর জন্য একটিমাত্র অ্যাকাউন্টের নাম দিন, ওপরের উদাহরণের মতো।
- আপনি কোনো একটি টুলের নাম না দিলে ccusage নিজের খুঁজে পাওয়া অন্যান্য কোডিং টুলের, যেমন Codex-এর, রিপোর্টও দেয়: `ccam ccusage claude daily` শুধু Claude Code দেখায়।
- ccam যখন এটি চালায়, ccusage তার সেটিংস (`ccusage.json`) শুধু `./.ccusage` ও অ্যাকাউন্টের ফোল্ডারগুলো থেকে পড়ে। `--config` অন্য একটি ফাইলের নাম দেয়: `ccam ccusage daily --config ~/.config/claude/ccusage.json`।
- যে ফোল্ডারের পাথে কমা আছে, ccusage সেটিকে দুটি ফোল্ডার হিসেবে পড়ত, তাই ccam সেটি প্রত্যাখ্যান করে এবং অ্যাকাউন্টটির নাম জানায়; `-a` দিয়ে সেই অ্যাকাউন্টটি বাদ দিন।
- `ccusage` একটি ccam কমান্ড, তাই ccusage নামের অ্যাকাউন্ট চালু করতে হয় `ccam run ccusage` দিয়ে; `ccam doctor` তা জানায়।

## এটি কীভাবে কাজ করে

`ccam usage`-এর সংখ্যাগুলো আসে দুই জায়গা থেকে: Anthropic-এর ডকুমেন্ট না করা ব্যবহার এন্ডপয়েন্ট `GET https://api.anthropic.com/api/oauth/usage`, যা প্রতিটি অ্যাকাউন্টের নিজস্ব লগইন দিয়ে ডাকা হয়, এবং Claude Code তার স্ট্যাটাস লাইন কমান্ডকে যে মানগুলো দেয়। এর সবই আছে `internal/usage`-এ।

1. ccam `config.toml` লোড করে এবং প্রতি অ্যাকাউন্টে একটি `usage.Account` তৈরি করে (`cli.usageCmd`): তার ফোল্ডার `~/.local/share/ccam/profiles/<name>/`, তার সেশন মার্কার (অ্যাকাউন্ট ফোল্ডারে Claude Code-এর নিজস্ব রেকর্ডের সঙ্গে মিলিয়ে এগুলো জানায় এটি চলছে কি না) এবং এটি নিজের জায়গায় ইমপোর্ট করা কি না।
2. ccam একসঙ্গে প্রতিটি অ্যাকাউন্টের খোঁজ করে, প্রতি অ্যাকাউন্টে একটি goroutine দিয়ে (`Fetcher.FetchAll`)। সবগুলো একটি `http.Client` শেয়ার করে, তাই এন্ডপয়েন্টের সংযোগগুলো আবার ব্যবহার হয়। সংযোগে ২ সেকেন্ড লাগতে পারে, এবং প্রতিটি অ্যাকাউন্ট মোট ৩ সেকেন্ড পায়। ক্লায়েন্ট রিডাইরেক্ট অনুসরণ করে না, কারণ রিডাইরেক্ট টোকেনটি অন্য কোথাও আবার পাঠাত, এবং উত্তরের সর্বোচ্চ 1 MB পড়ে।
3. প্রতিটি অ্যাকাউন্ট শেষ হলে তার সারি আবার আঁকা হয়। যে অ্যাকাউন্ট ব্যর্থ হয় বা সময়মতো উত্তর দেয় না, সেটি সংরক্ষিত সংখ্যায় ফিরে যায়, তাই একটি ধীর অ্যাকাউন্ট কখনও অন্যগুলোকে আটকে রাখে না।

ডায়াগ্রামে প্রতিটি অ্যাকাউন্টের খোঁজ নিজস্ব goroutine-এ হয়, এবং যেটির সময় শেষ হয়ে যায় সেটি এর বদলে তার সংরক্ষিত সংখ্যা দেখায়:

<!-- motion:usage-fetch -->

`personal` ও `work` সময়মতো উত্তর দেয় এবং লাইভ সংখ্যা দেখায়। `side` ৩ সেকেন্ডের বেশি নেয়, তাই ccam এর বদলে তার সংরক্ষিত সংখ্যাগুলো দেখায় (`fallback()`)। তারপর ccam প্রতিটি অ্যাকাউন্টের জন্য একটি ব্লক আঁকে (`usage.Table()`) এবং শেষ লাইনে উল্লেখিত অ্যাকাউন্টটি বেছে নেয় (`usage.Best()`)।

একটি অ্যাকাউন্টের জন্য ccam এই যাচাইগুলো ক্রমানুসারে করে (`Fetcher.Fetch`):

<!-- motion:usage-cache -->

1. `--source cache` দিলে এটি সরাসরি `fallback()`-এ যায়।
2. `--no-cache` নির্ধারিত না থাকলে `~/.local/state/ccam/usage/<name>.json`-এ ৬০ সেকেন্ডের (`CacheTTL`) কম আগে মাপা লাইভ ফলাফল ব্যবহার হয়, এখনকার সময় ধরে বিচার করে: এর মধ্যে রিসেট হওয়া উইন্ডো ০% দেখায়, এবং ঘড়ির চেয়ে এগিয়ে থাকা তারিখের ফাইল নতুন হিসেবে গণ্য হয় না। পরপর দুবার `ccam usage` চালালে প্রতি অ্যাকাউন্টে একটি অনুরোধ খরচ হয়।
3. ccam `.credentials.json` (বা macOS Keychain) না বদলে পড়ে এবং শুধু `claudeAiOauth` কী ডিকোড করে (`readCredentials()`)। সাবস্ক্রিপশন লগইন না থাকলে মানে `not logged in`, অথবা `.claude.json`-এ API কী থাকলে `no limits (API)`। যে লগইনের রিফ্রেশ টোকেনের মেয়াদ শেষ, বা যেটি Claude Code মুছে দিয়েছে, সেটি হলো `` login expired → `ccam login <name>` `` এবং তার খোঁজ করা হয় না।
4. মেয়াদোত্তীর্ণ অ্যাক্সেস টোকেন ব্যবহার করা হয় না। `--refresh` ছাড়া অ্যাকাউন্টটি ``access token expired; `ccam <name>` renews it when it starts``-সহ তার সংরক্ষিত সংখ্যা দেখায়।
5. অন্যথায় ccam এন্ডপয়েন্ট ডাকে। 401 বা 403 মেয়াদোত্তীর্ণ লগইন হিসেবে গণ্য হয় (`login expired: authentication failed (401)`), অন্য যেকোনো স্ট্যাটাস বা পড়া যায় না এমন বডি ত্রুটি হিসেবে গণ্য হয়, এবং দুটোই সংরক্ষিত সংখ্যায় ফিরে যায়। Ctrl+C দিয়ে থামানো খোঁজ বলে `cancelled`। 429 মানে এন্ডপয়েন্ট এই অ্যাকাউন্টের জন্য অনেক বেশি অনুরোধ পেয়েছে: ccam আবার জিজ্ঞেস করার সময় দিয়ে `<name>.pause` লেখে (`Retry-After`, নইলে ৫ মিনিট, সর্বোচ্চ এক ঘণ্টা), `rate limited by the usage endpoint; asking again after 15:10` সহ সংরক্ষিত সংখ্যা দেখায়, এবং ততক্ষণ ওই অ্যাকাউন্টের জন্য এন্ডপয়েন্ট ডাকে না, `--no-cache` দিলেও। সঙ্গে সঙ্গে আবার চেষ্টা করলে রেট লিমিট শুধু দীর্ঘায়িত হতো।
6. ভালো উত্তর মাপার সময়সহ `<name>.json`-এ লেখা হয়।

সংরক্ষিত সংখ্যার জন্য ccam সবচেয়ে নতুন সংরক্ষিত খোঁজটি নেয় (`<name>.json`, বা Claude Code-এর খোঁজ থেকে `<name>.claude.json`), এবং `<name>.statusline.json` তার পরে লেখা হয়ে থাকলে স্ট্যাটাস লাইনের ৫ ঘণ্টা ও সাপ্তাহিক উইন্ডো তার ওপরে বসায় (`fallback()`); মডেলের উইন্ডোগুলো, যা স্ট্যাটাস লাইনে থাকে না, খোঁজটি যেমন সংরক্ষণ করেছিল তেমনই থাকে। সংরক্ষিত সংখ্যা দেখানোর আগে এটি প্রতিটি উইন্ডোর রিসেটের সময় যাচাই করে: সংখ্যাগুলো সংরক্ষণের পর যে উইন্ডো রিসেট হয়েছে সেটি ০% দেখায়, কারণ পুরোনো শতাংশ আর প্রযোজ্য নয়। এ কারণেই ওপরে `personal` রিসেটের সময় ছাড়া `0%` দেখায়।

এন্ডপয়েন্টের দুটি রেসপন্স ফরম্যাট আছে। নতুনটিতে আছে একটি `limits` অ্যারে, যাতে `session` (৫ ঘণ্টা), `weekly_all` ও `weekly_scoped` (মডেলভিত্তিক) এন্ট্রি থাকে। পুরোনোটিতে আছে `five_hour`, `seven_day`, `seven_day_opus` ও `seven_day_sonnet` অবজেক্ট। `ParseLive` দুটোই পড়ে: `limits` অ্যারে অগ্রাধিকার পায়, আর পুরোনো অবজেক্টগুলো সেটি যা কভার করে না তা পূরণ করে। কোনো সীমাই নেই এমন বডিকে বদলে যাওয়া ফরম্যাট হিসেবে জানানো হয়, যা `ccam doctor` আপনাকে জানায়।

### সীমার রেকর্ড

Claude Code কোনো টার্ন ব্যবহারের সীমায় থামালে [ccam প্লাগইনের](/docs/install#claude-code-plugin) হুক কথোপকথন থেকে প্রত্যাখ্যাত অনুরোধটি পড়ে: কোন উইন্ডো পূর্ণ ছিল (৫ ঘণ্টা, সাপ্তাহিক, Opus বা Sonnet) এবং সেটি কখন রিসেট হবে। এটি তা `~/.local/state/ccam/usage/<name>.limit.json`-এ লেখে। ccam রেকর্ডটি প্রতিটি উৎস থেকে জানা বাকি সবকিছুর ওপরে প্রয়োগ করে (`Fetch`): এতে থাকা প্রতিটি উইন্ডো রিসেট পর্যন্ত ১০০% গণ্য হয়, সংরক্ষিত সংখ্যা যত পুরোনো বা কমই হোক, তাই `ccam next --auto`, `ccam pick`, `--fallback` ও [`auto_switch`](/features/next#auto-switch) তার আগে অ্যাকাউন্টটি আবার বেছে নেয় না।

আর কিছু জানা না থাকলে অ্যাকাউন্টটি শুধু রেকর্ডটিই দেখায় (`-v` দিলে `source: the usage limit Claude Code reported`)। তত্ত্বাবধানহীন সেশন (`-p` রান ও ব্যাকগ্রাউন্ড সেশন) কোনো রেকর্ড লেখে না, প্রতিষ্ঠানের দেওয়া থামানোও নয় (যেমন ব্যবহার ফুরিয়ে গেলে বা কোনো গ্রুপের সীমা $0 হলে), যা তার অ্যাডমিনরা যেকোনো সময় তুলে নিতে পারেন। অন্য কোনো Claude অ্যাকাউন্টে `ccam login` করলে রেকর্ডটি বাদ যায়; ফাইলটি মুছে ফেললেও তা মুছে যায়।

### টোকেন নবায়ন

রিফ্রেশ টোকেন ঘোরে: একটি নবায়ন করলে আপনি নতুন রিফ্রেশ টোকেন পান এবং পুরোনোটি অকার্যকর হয়। একই অ্যাকাউন্ট হিসেবে Claude Code চলার সময় ccam লগইন নবায়ন করলে ওই সেশনটি সাইন আউট হয়ে যেত। তাই আপনি `--refresh` না দিলে `ccam usage` টোকেন পড়ে কিন্তু কখনও লেখে না। তখন ccam (`Fetcher.refresh`):

1. `ccam import` দিয়ে নিজের জায়গায় নিবন্ধিত অ্যাকাউন্ট প্রত্যাখ্যান করে, কারণ সাধারণ `claude` ccam-এর অজান্তে ওই লগইন ব্যবহার করতে পারে;
2. macOS Keychain-এ সংরক্ষিত লগইন প্রত্যাখ্যান করে;
3. একটি লক ফাইল নেয়, `~/.local/state/ccam/locks/profile-<name>.refresh.lock`, যাতে দুটি ccam প্রসেস কখনও একই টোকেন দুজনেই নবায়ন না করে; লকটি ধরা থাকার সময় অ্যাকাউন্টটি দেখায় `token not renewed: another ccam process is using this login right now (a refresh, rename, remove or logout)`। `ccam rename`, `remove` ও `logout`-ও এটি নেয়, এবং নবায়ন চলার সময় প্রত্যাখ্যান করে;
4. লকের অধীনে, অ্যাকাউন্টের কোনো সেশন চলতে থাকলে প্রত্যাখ্যান করে, সেটি যেভাবেই চালু হোক (ccam-এর মাধ্যমে, সাধারণ `claude`, কোনো IDE, বা কোনো ব্যাকগ্রাউন্ড সেশন ও তার পেছনের daemon, যা নিজেই লগইন নবায়ন করে), এবং অন্য প্রসেস আগেই টোকেন নবায়ন করে থাকলে অনুরোধ বাদ দেয়;
5. অ্যাকাউন্ট ফোল্ডারে Claude Code তার নিজস্ব নবায়ন লক (`.oauth_refresh.lock`, `<folder>.lock`) ধরে রাখার সময় কিছুই পাঠায় না: Claude Code ঠিক তখন ওই লগইন নবায়ন করছে;
6. রিফ্রেশ টোকেন টোকেন এন্ডপয়েন্টে পাঠায় এবং উত্তরের জন্য সর্বোচ্চ ৩০ সেকেন্ড অপেক্ষা করে, Claude Code তার নিজের নবায়নকে যতটা সময় দেয়। একবার পাঠানো অনুরোধ কখনও বাধাগ্রস্ত করা হয় না, Ctrl+C দিয়েও নয়: সার্ভার হয়তো আগেই রিফ্রেশ টোকেন বদলে দিয়েছে, এবং শুধু তার রেসপন্সেই নতুন লগইনটি থাকে। Ctrl+C বা hangup অন্য খোঁজগুলো শেষ করে, এবং উত্তর সংরক্ষিত হলে ccam বেরিয়ে যায় (Ctrl+C-এর পরে 130);
7. Claude Code-এর লেখার লকের (`.storage-write.lock`) অধীনে সংরক্ষণ করে এবং `.credentials.json`-এর তখনকার অবস্থায় শুধু টোকেনের ঘরগুলো বদলায়: এর মধ্যে Claude Code যা লিখেছে (একটি MCP সাইন-ইন) তা থেকে যায়, এর মধ্যে Claude Code যে লগইন নবায়ন করেছে সেটি রাখা হয়, এবং লগআউট কখনও উল্টে দেওয়া হয় না। উত্তরে নতুন রিফ্রেশ টোকেনের মেয়াদ থাকলে তা `refreshTokenExpiresAt` হিসেবে সংরক্ষিত হয়, ঠিক যেমন Claude Code করে।

যে নবায়ন সম্পন্ন হয় না, সেটি কারণ জানায়, অ্যাকাউন্টের লাইনে বা তার সংরক্ষিত সংখ্যার ওপরে: যেমন `token not renewed: a session is running`, অথবা অনুরোধ পাঠানো হলেও তার উত্তর ব্যবহার বা সংরক্ষণ করা না গেলে `login may be lost: …`, এবং তখন Claude Code লগইন করতে বললে `ccam login <name>` চালানোর পরামর্শসহ।

### স্ট্যাটাস লাইন সংগ্রাহক

Claude Code স্ট্যাটাস লাইন কমান্ড চালায় এবং তাতে একটি JSON ডকুমেন্ট পাইপ করে। ccam তা থেকে মডেলের নাম ও `rate_limits` পড়ে:

<!-- motion:usage-statusline -->

1. ccam অ্যাকাউন্টটি খুঁজে বের করে `CCAM_PROFILE` থেকে, যা ccam Claude Code চালু করার সময় নির্ধারণ করে, অথবা অন্যথায় অ্যাকাউন্ট ফোল্ডারগুলোর সঙ্গে `CLAUDE_CONFIG_DIR` মিলিয়ে (`runStatusline`)।
2. ccam `rate_limits.five_hour` ও `rate_limits.seven_day` পড়ে (`ParseStatusLine`)। API কী-এর অ্যাকাউন্টে, বা সেশনের প্রথম রেসপন্সের আগে, JSON-এ কোনো রেট লিমিট থাকে না; তখন কিছুই সংরক্ষিত হয় না।
3. ccam `~/.local/state/ccam/usage/<name>.statusline.json` লেখে (`SaveStatusLine`)। এন্ডপয়েন্ট উত্তর না দিলে `ccam usage` এটি ব্যবহার করে।
4. ccam প্রিন্ট করে `[name] · model · 5h N% · 7d N%`। `--wrap` দিলে এটি একই ইনপুট দিয়ে `sh -c`-এর মাধ্যমে আপনার কমান্ড চালায় এবং তার আউটপুট সেভাবে প্রিন্ট করে যেভাবে Claude Code একটি স্ট্যাটাস লাইন দেখায়: ফাঁকা নয় এমন প্রতিটি লাইন, প্রথমটির সামনে `[name]`। ব্যর্থ কমান্ড শুধু অ্যাকাউন্টের নাম দেখায়। Windows-এ এটি কমান্ডটি সেভাবেই চালায় যেভাবে Claude Code চালায়: Git Bash ইনস্টল থাকলে তা দিয়ে, অন্যথায় PowerShell দিয়ে।
5. ৫ ঘণ্টা বা সাপ্তাহিক ব্যবহার ৯০% বা তার বেশি হলে এবং অন্য কোনো অ্যাকাউন্ট থাকলে, লাইনটি `→ ccam next --auto --continue` দিয়ে শেষ হয়, যেমন `[work] · Opus · 5h 93% · 7d 41% · → ccam next --auto --continue`।

র‍্যাপ করা কমান্ডের নিজস্ব কোনো সময়সীমা নেই: Claude Code স্ট্যাটাস লাইন কমান্ডকে ১০ মিনিট দেয় এবং নতুন কোনো আপডেট শুরু হলে চলমান রানটি থামিয়ে দেয়, তাই ধীর কমান্ড ccam ছাড়া যেমন দেখাত তেমনই দেখায়। Claude Code ccam বন্ধ করলে কমান্ডটিও বন্ধ হয় (Linux ও macOS-এ এর চালু করা প্রতিটি প্রসেসসহ)।

`ccam statusline install` প্রতিটি অ্যাকাউন্টের `settings.json`-এ `statusLine` লেখে এবং অবজেক্টটির অন্য কী-গুলো রেখে দেয়, যেমন `padding`, `refreshInterval` ও `hideVimModeIndicator`। কোনো অ্যাকাউন্টের আগে থেকেই স্ট্যাটাস লাইন কমান্ড থাকলে ccam সেটি `--wrap '<old command>'` হিসেবে রাখে; Windows-এ `--wrap-base64 <base64>` হিসেবে, যাতে কোনো শেলেই উদ্ধৃতিচিহ্ন লাগে না। স্ট্যাটাস লাইন আগে থেকেই ccam চালালে (অন্য পাথ থেকে, বা কোনো পুরোনো সংস্করণ যেভাবে উদ্ধৃতিচিহ্ন দিয়ে লিখত সেভাবে), ccam সেটি র‍্যাপ না করে প্রতিস্থাপন করে, এবং সেটি যে কমান্ড র‍্যাপ করে তা রেখে দেয়।

Windows-এ ccam-এর পাথ ফরোয়ার্ড স্ল্যাশ ও হোম ফোল্ডারের জন্য `~` দিয়ে লেখা হয় (`~/.local/bin/ccam.exe statusline`), যা Git Bash ও PowerShell দুটোই বোঝে। যে পাথে উদ্ধৃতিচিহ্ন দরকার, সেটি Claude Code যে শেল ব্যবহার করে তার জন্য পুরোপুরি লেখা হয়: Git Bash-এর জন্য `'…'`, PowerShell-এর জন্য `& '…'`। গ্রুপের মাধ্যমে শেয়ার করা `settings.json` তার লিংকের মধ্য দিয়ে একবার লেখা হয়, তাই গ্রুপের প্রতিটি অ্যাকাউন্ট সেটি পায়। আবার চালালে যে ফাইলগুলো আগে থেকেই ccam ব্যবহার করে সেগুলোর জন্য `(already set)` প্রিন্ট হয়।

## নিরাপত্তা ও বিশেষ ক্ষেত্র

- আপনি `--refresh` না দিলে `ccam usage` কখনও টোকেন ফাইল বদলায় না। অ্যাক্সেস টোকেনের মেয়াদ শেষ হলে `ccam <name>` দিয়ে অ্যাকাউন্টটি একবার চালান, Claude Code সেটি নবায়ন করবে। যে লগইনের মেয়াদ পুরোপুরি শেষ, তার জন্য `ccam login <name>` দরকার।
- `--refresh` কখনও চলমান অ্যাকাউন্ট (এমনকি Claude Code ccam ছাড়া চালু হলেও), ইমপোর্ট করা অ্যাকাউন্ট বা Keychain লগইন স্পর্শ করে না। প্রত্যাখ্যাত নবায়ন সংরক্ষিত সংখ্যা ও কারণ দেখায় (`token not renewed: …`)।
- ব্যবহার এন্ডপয়েন্ট প্রকাশ্যে ডকুমেন্ট করা নয় এবং বদলে যেতে পারে। বদলালে আপনি তবুও সংরক্ষিত সংখ্যা দেখেন, এবং `ccam doctor` ফরম্যাটের পরিবর্তন জানায়।
- সংরক্ষিত সংখ্যা ও উত্তর কোনোটিই না থাকলে অ্যাকাউন্টের লাইনটি `lookup failed:` ও কারণ দেখায়, যেমন `--source cache` দিলে `no saved usage`।
- ক্যাশ ফাইলে শুধু শতাংশ ও রিসেটের সময় থাকে, কখনও টোকেন নয়।
