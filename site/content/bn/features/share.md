প্রতিটি অ্যাকাউন্টের নিজস্ব ফোল্ডার আছে, কিন্তু তার ভেতরের বেশিরভাগ জিনিস আলাদা রাখার দরকার নেই। একটি **গ্রুপ** ঠিক করে কী শেয়ার হবে এবং কারা শেয়ার করবে: গ্রুপের প্রতিটি অ্যাকাউন্ট ওই আইটেমগুলোকে একটি ফোল্ডার, `~/.local/share/ccam/groups/<group>/`-এর সঙ্গে লিংক করে, তাই সবাই একই কপি পড়ে ও লেখে। লগইন টোকেন কখনও শেয়ার হয় না।

একটি অ্যাকাউন্ট একাধিক গ্রুপে থাকতে পারে, তবে প্রতিটি আইটেম আসে কেবল একটি গ্রুপ থেকে। একটি সাধারণ সেটআপ হলো সেটিংস ও এক্সটেনশনের জন্য একটি গ্রুপ, আর দুটি অ্যাকাউন্টের মধ্যে কথোপকথনের ইতিহাসের জন্য দ্বিতীয় একটি:

```toml
[[group]]
name = 'default'
items = ['mcp', 'settings', 'memory', 'extensions']
members = ['personal', 'work', 'side']

[[group]]
name = 'team'
items = ['history']
members = ['work', 'side']
```

আপনার যোগ করা প্রথম অ্যাকাউন্টটি `default` তৈরি করে, আর আপনি অন্য কিছু না বললে পরের অ্যাকাউন্টগুলো তাতে যোগ দেয়।

## ব্যবহার

```sh
ccam group                                        # the groups, what they share, their accounts
ccam group show default                           # items, accounts, folder and MCP servers
ccam group add team --items history --members work,side
ccam group set default --add history              # all accounts in default start sharing history
ccam group set default --remove history --fresh   # stop sharing; accounts start without it
ccam group set team --items history,memory --from work   # the group starts from work's copies
ccam group join team personal                     # personal starts sharing team's items
ccam group join team personal --replace           # first leave the group that shares those items now
ccam group leave team side                        # side keeps a copy of team's items
ccam group rename team pair                       # the folder keeps its name
ccam group remove pair --leave                    # its accounts keep a copy; folder to the trash
ccam share work                                   # what work shares, and through which group
ccam --dry-run group set default --add history    # print the plan, change nothing
```

```console
$ ccam group
Group    Shares                          Accounts
default  mcp settings memory extensions  personal, work, side
team     history                         work, side

$ ccam share work
Sharing for work
  mcp         MCP servers                        group default
  settings    settings.json                      group default
  memory      global CLAUDE.md                   group default
  extensions  agents, commands, skills, plugins  group default
  history     conversation history               group team
Groups: default, team. Change them with `ccam group`.
```

ডেটা সরায় এমন প্রতিটি কমান্ড একটি পরিকল্পনা প্রিন্ট করে, গ্রুপের কপি থেকে আলাদা প্রতিটি ফাইলের বিষয়ে জিজ্ঞেস করে, এবং কিছু বদলানোর আগে জিজ্ঞেস করে `Proceed? [y/N]`:

```console
$ ccam group set default --add history
Plan (paths in /home/me/.local/share/ccam):
personal: +history (group default)
  move     projects, history.jsonl: profiles/personal → groups/default (first content of the group)
  link     projects, history.jsonl, file-history, tasks, paste-cache: profiles/personal → groups/default
work: +history (group default)
  merge    new files in projects: profiles/work → groups/default
  conflict profiles/work/history.jsonl ↔ groups/default/history.jsonl: merge by line
  back up  projects, history.jsonl: profiles/work → profiles/work/.ccam-backup/20261023-213057
  link     projects, history.jsonl, file-history, tasks, paste-cache: profiles/work → groups/default
  Note: projects: 1 file differs from the group's copy (-home-me-code-app/s1.jsonl); the group's is kept, the account's stays in profiles/work/.ccam-backup/20261023-213057/projects
Proceed? [y/N]
```

একই পরিবর্তনগুলো আপনি [ড্যাশবোর্ডের](/features/dashboard) **Groups** ট্যাবে করতে পারেন; কোনো অ্যাকাউন্টের গ্রুপ বেছে নিতে তাতে `s` চাপুন।

## আইটেম

| আইটেম | কী কী এর আওতায় |
| --- | --- |
| `mcp` | MCP সার্ভার, গ্রুপের `mcp.json`-এর মাধ্যমে ([শেয়ার করা MCP সার্ভার](/features/mcp)) |
| `settings` | `settings.json` |
| `memory` | গ্লোবাল `CLAUDE.md` |
| `extensions` | `agents/`, `commands/`, `skills/`, `plugins/`, `output-styles/`, `rules/` |
| `history` | `projects/` ও `history.jsonl`, যাতে অন্য একটি অ্যাকাউন্ট `--continue` করতে পারে |

অ্যাকাউন্টের কোনো গ্রুপই কোনো আইটেম শেয়ার না করলে সেই আইটেমটি অ্যাকাউন্টের নিজস্ব ফোল্ডারেই থাকে।

## কমান্ড ও অপশন

| কমান্ড | কী করে |
| --- | --- |
| `ccam group` বা `ccam group list` | গ্রুপগুলোর তালিকা দেয় |
| `ccam group show <group>` | গ্রুপটি কী শেয়ার করে, তার অ্যাকাউন্ট, তার ফোল্ডার ও MCP সার্ভার |
| `ccam group add <group> --items <items> [--members <accounts>]` | একটি গ্রুপ তৈরি করে; তার অ্যাকাউন্টগুলোর আইটেম তাতে সরে যায় |
| `ccam group set <group> --add <items> \| --remove <items> \| --items <items>` | গ্রুপটি কী শেয়ার করে তা বদলায়, তার প্রতিটি অ্যাকাউন্টের জন্য |
| `ccam group join <group> <account>...` | অ্যাকাউন্টগুলোকে গ্রুপে রাখে |
| `ccam group leave <group> <account>...` | অ্যাকাউন্টগুলোকে বের করে নেয়; প্রত্যেকে একটি কপি রাখে, MCP সার্ভারসহ |
| `ccam group rename <group> <new-name>` | শুধু কনফিগে নাম বদলায় |
| `ccam group remove <group> [--leave]` | একটি গ্রুপ সরায় |

| অপশন | কী করে | ডিফল্ট |
| --- | --- | --- |
| `--from <account>` | `add`, `set`: যে অ্যাকাউন্টের কপি প্রথমে গ্রুপে যায় | ডিফল্ট অ্যাকাউন্ট, তারপর নম্বর অনুযায়ী |
| `--replace` | `join`: আগে সেই গ্রুপগুলো ছেড়ে দেয় যেগুলো একই আইটেম শেয়ার করে | বন্ধ |
| `--fresh` | যে অ্যাকাউন্টগুলো কোনো আইটেম শেয়ার করা বন্ধ করে, সেগুলো একটি কপির বদলে সেটি ছাড়াই শুরু করে (ইমপোর্ট করা ফোল্ডার তবুও একটি রাখে) | বন্ধ |
| `--leave` | `remove`: আগে গ্রুপের অ্যাকাউন্টগুলোকে বের করে নেয় | গ্রুপে অ্যাকাউন্ট থাকলে দরকার |
| `--prefer <group\|mine\|merge>` | দ্বন্দ্ব কীভাবে মীমাংসা হবে | জিজ্ঞেস করে; `--yes` দিলে প্রতিটি ফাইলের ডিফল্ট |
| `-y`, `--yes` | জিজ্ঞেস না করেই চালায়; দ্বন্দ্ব `--prefer` অনুসরণ করে | বন্ধ |
| `--dry-run` (গ্লোবাল) | পরিকল্পনা প্রিন্ট করে, কিছু বদলায় না | বন্ধ |

অ্যাকাউন্ট দেওয়া হয় নাম বা নম্বর দিয়ে; আইটেম দেওয়া হয় কমা দিয়ে আলাদা করা তালিকা হিসেবে। `ccam add` নেয় `--group <group>` (একাধিকবার দেওয়া যায়) বা `--no-group`।

## এটি কীভাবে কাজ করে

সংশ্লিষ্ট ফাইলগুলো:

- `~/.config/ccam/config.toml`: `[[group]]` এন্ট্রিগুলো: `name`, `items`, `members` এবং, ফোল্ডারের নাম আলাদা হলে, `dir`।
- `~/.local/share/ccam/profiles/<name>/`: অ্যাকাউন্টের `CLAUDE_CONFIG_DIR`।
- `~/.local/share/ccam/groups/<folder>/`: শেয়ার করা কপিগুলো।

`config.toml` পড়ার সময় প্রতিটি অ্যাকাউন্টের গ্রুপগুলো প্রতি আইটেমে একটি ফোল্ডারে রূপান্তরিত হয়। পাঁচটি অ্যাকাউন্টে এতে প্রায় 25 µs লাগে, তাই চালু করার সময় এখনও শুধু `config.toml` পড়া হয়। যে কনফিগে কোনো অ্যাকাউন্ট একটি আইটেম দুটি গ্রুপ থেকে পেত, সেটি একটি ত্রুটি, এবং তা ঠিক না করা পর্যন্ত কিছুই চালু হয় না।

একটি পরিবর্তন কনফিগের একটি কপির ওপর কাজ করে:

1. কমান্ডটি কপিটি সম্পাদনা করে (`AddGroup`, `SetGroupItems`, `JoinGroup` …), যা নিয়মগুলো যাচাই করে।
2. ccam পুরোনো ও নতুন তুলনা করে, এবং যে প্রতিটি অ্যাকাউন্টের আইটেম বদলায় তার জন্য একটি পরিকল্পনা তৈরি করে (`internal/group`, `share.Build`)। পরিকল্পনাগুলো একটির পর একটি তৈরি হয়, এবং প্রতিটি দেখে আগেরগুলো গ্রুপ ফোল্ডারে কী রাখবে, তাই শুধু প্রথম অ্যাকাউন্টটি তার কপি ভেতরে সরায়। গ্রুপের প্রথম কপিটি আসে এই ক্রমে: গ্রুপ ফোল্ডার (যদি সেখানে আগে থেকেই একটি থাকে), `--from` অ্যাকাউন্ট, ডিফল্ট অ্যাকাউন্ট, তারপর বাকি অ্যাকাউন্টগুলো নম্বর অনুযায়ী।
3. ওই অ্যাকাউন্টগুলোর কোনোটি চলতে থাকলে ccam প্রত্যাখ্যান করে, Claude Code যেভাবেই চালু হোক (``work is running; quit Claude Code there first, then change the groups (`ccam agents` lists the sessions)``), এবং Developer Mode ছাড়া Windows-এ কোনো ফাইলের লিংক লাগলেও।
4. ccam দ্বন্দ্বগুলো মীমাংসা করে (জিজ্ঞেস করে, বা `--prefer` দিয়ে), পরিকল্পনাটি প্রিন্ট করে এবং নিশ্চিত করতে বলে।
5. সংরক্ষণের ঠিক আগে ccam আবার পরীক্ষা করে। ccam আপনার উত্তরের অপেক্ষায় থাকার সময় কোনো অ্যাকাউন্ট চালু হলে পরিবর্তনটি থেমে যায়; এর মধ্যে অন্য কোনো ccam প্রসেস একই গ্রুপগুলো বদলালেও থেমে যায় (`the groups changed while this plan waited; nothing was moved, make the change again`)। কিছু সরানোর আগেই নতুন কনফিগ সংরক্ষিত হয়, এবং পরিবর্তনটি `~/.local/state/ccam/group-change.json`-এ লিখে রাখা হয়। কোনো ধাপ মাঝপথে থেমে গেলে লেখাটি থেকে যায়: `ccam doctor --fix` পরিবর্তনটি তার ক্রমে শেষ করে, আপনার দেওয়া উত্তরগুলো দিয়ে, MCP ধাপসহ, এবং ততক্ষণ গ্রুপের অন্য কোনো পরিবর্তন শুরু হয় না (``the last group change stopped halfway; finish it with `ccam doctor --fix` first``)।
6. প্রথমে MCP ধাপগুলো চলে। অ্যাকাউন্টগুলো কোনো গ্রুপ থেকে এক্সটেনশন বের করে নিলে, গ্রুপের প্লাগইন তালিকাগুলোর যেখানে পাথ কোনো অ্যাকাউন্টের ফোল্ডারের মধ্য দিয়ে যায়, সেখানে সেগুলোকে গ্রুপ ফোল্ডারের দিকে নির্দেশ করানো হয় (পরিকল্পনায় `group plugin lists:`)। তারপর পরিকল্পনাগুলো ক্রমানুসারে চলে। প্রতিটি ধাপ ডেটা গ্রুপে বা ব্যাকআপ ফোল্ডারে সরায়; শুধু গ্রুপের কপির সঙ্গে হুবহু এক ফাইলগুলো ব্যাকআপের বদলে মুছে ফেলা হয়।

ccam প্রতিটি আইটেমের আওতাভুক্ত পাথগুলোর একটি অনুমোদিত তালিকা রাখে (`share.Layout`)। এর বাইরের কোনো কিছু কখনও গ্রুপে পৌঁছাতে পারে না। ccam `.credentials.json` ও `.claude.json`-কে কখনও শেয়ার না হওয়া হিসেবেও চিহ্নিত করে (`share.Never`), এবং কোনোটি কখনও কাঠামোতে দেখা দিলে একটি অভ্যন্তরীণ ত্রুটি দিয়ে থেমে যায় (`Build`)। `mcp` আইটেমের কোনো পাথ নেই: সার্ভার তালিকা থাকে `.claude.json`-এর ভেতরে, তাই [MCP শেয়ার](/features/mcp) গ্রুপের `mcp.json`-এর মাধ্যমে কাজ করে।

`side` ইতিহাস শেয়ার করা শুরু করলে এবং গ্রুপে আগে থেকেই বিষয়বস্তু থাকলে একটি ফোল্ডার, `projects/`-এর ক্ষেত্রে যা ঘটে:

গ্রুপে ওই পাথে এখনও কিছু না থাকলে অ্যাকাউন্টটিই প্রথম সেটি শেয়ার করে, এবং তার ফোল্ডারটি যেমন আছে তেমনই সেখানে সরানো হয়। অন্যথায় গ্রুপে না থাকা প্রতিটি ফাইল গ্রুপে সরানো হয়, আর দুই দিকেই থাকা ফাইলগুলো অ্যাকাউন্টের ফোল্ডারে থেকে যায়, তাই গ্রুপের সংস্করণ রাখা হয়। গ্রুপেরটির সঙ্গে হুবহু এক ফাইলগুলো মুছে ফেলা হয়, আর পরিকল্পনাটি আলাদা ফাইলগুলোর নাম দেখায় (`Note: projects: 1 file differs from the group's copy (…); the group's is kept, the account's stays in …`)।

তারপর অ্যাকাউন্টের ফোল্ডারটি অ্যাকাউন্ট ফোল্ডারের ভেতরে `.ccam-backup/<time>/`-এ যায়, এবং তার জায়গায় একটি লিংক বসে। গ্রুপের এন্ট্রিটি নিজেই যদি যোগ দেওয়া অ্যাকাউন্টের নিজস্ব এন্ট্রির লিংক হয়, তাহলে অ্যাকাউন্টের বিষয়বস্তু তার জায়গায় গ্রুপে যায়। কথোপকথনের ফাইলের নাম তাদের সেশন ID অনুযায়ী হয়, তাই একাধিক অ্যাকাউন্টের ইতিহাস কোনো সংঘাত ছাড়াই একত্র হয়। `plugins/` রেজিস্ট্রিগুলো অ্যাকাউন্ট ফোল্ডারের মধ্য দিয়ে পূর্ণ পাথ রাখে; ccam সেগুলোকে গ্রুপের ফোল্ডারে নির্দেশ করায় এবং গ্রুপে আগে থেকেই রেজিস্ট্রি থাকলে অ্যাকাউন্টের এন্ট্রিগুলো তাতে মার্জ করে।

ছেড়ে গেলে লিংকটি উল্টে যায়:

<!-- motion:share-off -->

ccam প্রথমে গ্রুপের বর্তমান বিষয়বস্তু অ্যাকাউন্ট ফোল্ডারের `.ccam-backup/incomplete-<name>`-এ কপি করে, এবং কপিটি সম্পূর্ণ হলেই কেবল লিংকটি বদলায়। কপি মাঝপথে থেমে গেলে লিংকটি যথাস্থানে থাকে এবং `ccam doctor --fix` আবার কপি করে (এমন সমাপ্তির পরিকল্পনা দেখায় `restore <entry>: … (copied back from the group before a stop)`)। অন্য অ্যাকাউন্টগুলোর জন্য গ্রুপ তার বিষয়বস্তু রেখে দেয়।

- ccam লিংকটি সরায় শুধু যদি সেটি পরিকল্পনা তৈরির সময়ের মতোই এখনও groups ফোল্ডারের ভেতরে নির্দেশ করে। এর মধ্যে বদলে যাওয়া পাথ, যেমন লিংকের জায়গায় একটি আসল ফাইল, যেমন আছে তেমনই থাকে এবং পরিবর্তনটি থেমে যায়।
- `--fresh` দিলে কপি বাদ যায়।
- যে অ্যাকাউন্ট কোনো আইটেম এমন গ্রুপে সরায় যার ফোল্ডার এখনও খালি, সেটি যা দেখেছিল তার একটি কপি সঙ্গে আনে, তাই তার ফাইলগুলো থেকে যায়। সম্পূর্ণ না হওয়া পর্যন্ত সেই কপি `<group>/.ccam-incomplete-<name>`-এ রাখা হয়।
- যে অ্যাকাউন্ট MCP শেয়ার করা বন্ধ করে, সেটি গ্রুপের সার্ভারগুলো রাখে: সেগুলো তার নিজস্ব `.claude.json`-এ যায় (একটি ব্যাকআপ রাখা হয়), তবে যেখানে অ্যাকাউন্টের আগে থেকেই একই নামের সার্ভার আছে সেখানে নয়; সেটি যেমন আছে তেমনই থাকে। `--fresh` দিলে পরিকল্পনাটি এর বদলে সেই সার্ভারগুলোর তালিকা দেয় যেগুলো আর লোড হবে না। আবার যোগ দিলে যে কপিগুলো কেউ বদলায়নি সেগুলো সরানো হয়।
- `extensions` ছেড়ে গেলে গ্রুপের প্লাগইন তালিকাগুলোর যেখানে পাথ ছেড়ে যাওয়া অ্যাকাউন্টের ফোল্ডারের মধ্য দিয়ে যেত, সেখানে সেগুলোকেও গ্রুপ ফোল্ডারের দিকে নির্দেশ করানো হয়; অন্য অ্যাকাউন্টগুলোর জন্য নতুন করে লেখা পাথগুলো একই প্লাগইনে নিয়ে যায়।

দুই দিকেই আলাদা বিষয়বস্তু নিয়ে থাকা একটি একক ফাইল হলো দ্বন্দ্ব:

<!-- motion:share-conflict -->

`settings.json`-এর মতো একক ফাইলের জন্য আপনি বেছে নেন; ফোল্ডারের ভেতরে গ্রুপের কপিটিই থাকে, এবং পরিকল্পনাটি আলাদা ফাইলগুলোর নাম দেখায়। পছন্দগুলো ফাইলের ওপর নির্ভর করে; প্রথমটি ডিফল্ট:

| ফাইল | পছন্দ |
| --- | --- |
| `history.jsonl` | `merge by line`, `keep group`, `use mine` |
| অন্য `.json` ফাইল | `keep group`, `use mine`, `merge JSON` |
| বাকি সবকিছু | `keep group`, `use mine` |

`merge JSON` অবজেক্টগুলো রিকার্সিভভাবে মার্জ করে, অ্যারেগুলো ডুপ্লিকেট ছাড়া যুক্ত করে, এবং দুই দিকেই একই কী ভিন্নভাবে নির্ধারিত থাকলে গ্রুপের মান রাখে, তাই অন্য অ্যাকাউন্টগুলো কোনো পরিবর্তন দেখে না। `keep group` ছাড়া প্রতিটি পছন্দ প্রথমে অ্যাকাউন্টের `.ccam-backup/<time>/group/`-এ গ্রুপের কপি সংরক্ষণ করে। আপনার নিজের ফাইল সবসময় ব্যাকআপে যায়।

প্রতিবার চালু করার সময় ccam কাঠামোর প্রতিটি পাথকে অ্যাকাউন্টের গ্রুপগুলোর সঙ্গে শুধু `lstat` ও `readlink` দিয়ে তুলনা করে (`share.Check`)। অনুপস্থিত লিংক সঙ্গে সঙ্গে তৈরি হয়। যেখানে লিংক থাকার কথা সেখানে আসল ফাইল, ভুল জায়গায় লিংক, বা বাসি লিংক চালু করা থামিয়ে দেয় এবং `ccam doctor --fix` দেখিয়ে দেয়।

### নাম বদল, সরানো ও পুরোনো ফরম্যাট

- `ccam group rename` শুধু কনফিগ বদলায়। ফোল্ডারের নাম একই থাকে এবং গ্রুপটি সেটিকে `dir` হিসেবে নথিভুক্ত করে, তাই কিছুই সরে না এবং কিছুই হারাতে পারে না।
- অ্যাকাউন্টসহ একটি গ্রুপ `ccam group remove` প্রত্যাখ্যান করে, যদি না আপনি `--leave` যোগ করেন। তখন প্রতিটি অ্যাকাউন্ট একটি কপি রাখে, এবং অন্য কোনো গ্রুপ ফোল্ডারটি ব্যবহার না করলে সেটি `~/.local/share/ccam/trash/`-এ যায়।
- গ্রুপের আগে `config.toml` প্রতিটি অ্যাকাউন্টের জন্য একটি `[profile.share]` টেবিল রাখত। ccam কিছু না সরিয়েই সেই ফরম্যাটকে গ্রুপ হিসেবে পড়ে। প্রথমবার সংরক্ষণের সময় এটি নতুন ফরম্যাট লেখে এবং পুরোনো ফাইলটি `config.toml.bak` হিসেবে রেখে দেয়। একই অ্যাকাউন্টগুলো যে আইটেমগুলো শেয়ার করে, সেগুলো ফোল্ডারের নামে একটি গ্রুপ হয়; বাকিগুলো `default-history`-এর মতো নাম পায় এবং একই ফোল্ডার ব্যবহার করতে থাকে।

### Windows-এ

Windows সিম্বলিক লিংক তৈরি করে শুধু Developer Mode-এ (Settings > System > For developers) অথবা একজন অ্যাডমিনিস্ট্রেটরের জন্য। সেই অধিকার না থাকলে একটি শেয়ার করা ফোল্ডার একটি ডিরেক্টরি জাংশন হয়ে যায়, যা Claude Code-এর জন্য একইভাবে কাজ করে। একটি শেয়ার করা ফাইল (`settings.json`, `CLAUDE.md`, `history.jsonl`) শুধু সিম্বলিক লিংকই হতে পারে, তাই যে গ্রুপ পরিবর্তনে এমন লিংক লাগে, সেটি কিছু সরানোর আগেই প্রত্যাখ্যান করা হয়। একই কারণে সেখানে প্রথম `ccam add` শুধু `mcp` ও `extensions` নিয়ে `default` গ্রুপ তৈরি করে এবং তা জানায়, আর সেটিংস, মেমরি বা ইতিহাস শেয়ার করা কোনো গ্রুপে `ccam add --group` প্রত্যাখ্যান করা হয়।

## নিরাপত্তা ও বিশেষ ক্ষেত্র

- **চলমান অ্যাকাউন্ট।** কোনো পরিবর্তন যে অ্যাকাউন্টগুলো সরায়, তার কোনোটি হিসেবে Claude Code চলতে থাকলে পরিবর্তনটি প্রত্যাখ্যান করা হয়, কারণ সেশনটি ওই ফাইলগুলোতে লিখতে থাকে, ccam সেটি চালু করুক বা না করুক (সাধারণ `claude`, কোনো IDE, ব্যাকগ্রাউন্ড সেশন)। সংরক্ষণের ঠিক আগে যাচাইটি আবার করা হয়। ছেড়ে যাওয়া ও যোগ দেওয়া শুধু নাম দেওয়া অ্যাকাউন্টটিকেই প্রভাবিত করে; `extensions` ছেড়ে গেলে গ্রুপের প্লাগইন তালিকার পাথও নতুন করে লেখা হয়, অন্যদের জন্য তাদের অর্থ না বদলে। `--dry-run` তবুও পরিকল্পনা প্রিন্ট করে।
- **ব্যাকআপ।** প্রতিটি পরিকল্পনা অ্যাকাউন্ট ফোল্ডারে নিজস্ব `.ccam-backup/<time>/` ফোল্ডার পায়। ccam কখনও এগুলো মুছে ফেলে না।
- **আপনার নিজের লিংক।** কোনো পাথ যদি আগে থেকেই আপনার তৈরি করা একটি লিংক হয়, যেমন একটি dotfiles রিপোজিটরির দিকে, এবং গ্রুপ খালি থাকে, তাহলে ccam লিংকের লক্ষ্যটি গ্রুপে কপি করে এবং লিংকটিকেই ব্যাকআপে সরায়। লক্ষ্যটি স্পর্শ করা হয় না।
- **ইমপোর্ট করা ফোল্ডার।** `ccam import` দিয়ে নিজের জায়গায় নিবন্ধিত অ্যাকাউন্ট (যেমন `~/.claude`) নিজের জায়গাতেই বদলায়, তাই সাধারণ `claude`-ও পরিবর্তনটি দেখে; পরিকল্পনা তা জানায়। এটি কোনো গ্রুপ ছেড়ে গেলে সবসময় একটি কপি রাখে, `--fresh` দিলেও, এবং অ্যাকাউন্টটি ভুলে যাওয়ার আগে `ccam remove` এভাবেই সেটিকে তার গ্রুপগুলো থেকে বের করে নেয়। গ্রুপে থাকা অবস্থায় এর শেয়ার করা ফাইলগুলো গ্রুপ ফোল্ডারে থাকে, তাই `~/.local/share/ccam` মোছার আগে অ্যাকাউন্টটি সরান (অথবা গ্রুপগুলো ছেড়ে দিন)।
- **একই ফোল্ডারে দুটি অ্যাকাউন্ট।** যে অ্যাকাউন্টগুলো ইতিহাস শেয়ার করে, সেগুলো একই ফাইলে লেখে। একটি আগে থেকেই চলছে এমন ফোল্ডারে দ্বিতীয়টি চালু হলে ccam সতর্ক করে এবং জিজ্ঞেস করে।
- **হাতে করা সম্পাদনা।** `members`-এ এমন কোনো নাম থাকলে যা কোনো অ্যাকাউন্ট নয়, ccam সেটি উপেক্ষা করে এবং `ccam doctor` তা জানায়। `local`, `on`, `off` ও `none` নামগুলো গ্রুপের নাম হতে পারে না।
