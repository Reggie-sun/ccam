`ccam usage` প্রতিটি অ্যাকাউন্টের জন্য দেখায় প্রতিটি সীমার কতটা ব্যবহার হয়েছে: ৫ ঘণ্টার সীমা, সাপ্তাহিক সীমা ও প্রতিটি মডেলের নিজস্ব সাপ্তাহিক সীমা (যেমন Fable)। `ccam next --auto` সবচেয়ে বেশি জায়গা থাকা অ্যাকাউন্টটি খোলে, আর `--continue` বর্তমান কথোপকথনটি সঙ্গে নিয়ে যায়।

   Weekly   ████████░░░░░░░░░░░░  41%  resets in 3d 6h
   Fable    ██████████████████░░  88%  resets in 1d 6h

প্রতিটি অ্যাকাউন্ট একটি লাইন পায়, যা জানায় তার সংখ্যাগুলো কতক্ষণ আগের, তারপর প্রতিটি সীমার জন্য একটি বার, রিসেট হওয়া পর্যন্ত সময়সহ: ৫ ঘণ্টার উইন্ডো, সব মডেলের সাপ্তাহিক উইন্ডো, এবং প্রতিটি মডেলের নিজস্ব সাপ্তাহিক উইন্ডো, যেমন Fable। বার ৮০%-এ হলুদ আর ১০০%-এ লাল হয়ে যায়। শেষ লাইনটি সেই অ্যাকাউন্টের নাম দেয় যা `ccam next --auto` খুলত; `auto_strategy = "expiring"` বা `"balance"` থাকলে এর বদলে লাইনটি হয় `→ next --auto picks <name>: <reason>`।

**Team ও Enterprise সিট।** স্বয়ংক্রিয় অ্যাকাউন্ট বাছাই (`ccam next`, `--fallback`, `ccam pick`, ড্যাশবোর্ডের `n` এবং আপনি চালু করলে [`auto_switch`](/features/next#auto-switch)) একই Claude Team বা Enterprise প্রতিষ্ঠানের সিটগুলোর মধ্যেও বদল করে, যা Anthropic-এর শর্তাবলি লঙ্ঘন করতে পারে। এর ওপর নির্ভর করার আগে [প্রশ্নোত্তর](/docs/faq#am-i-allowed-to-use-several-claude-code-accounts) পড়ুন এবং আপনার প্রতিষ্ঠান ও Anthropic-এর কাছ থেকে জেনে নিন।

## সংখ্যাগুলো কোথা থেকে আসে

ccam প্রতিটি অ্যাকাউন্টের নিজস্ব লগইন ব্যবহার করে একই সময়ে সব অ্যাকাউন্টের জন্য Anthropic-এর ব্যবহার এন্ডপয়েন্টে অনুরোধ পাঠায়। প্রতিটি অ্যাকাউন্টের জন্য এটি সর্বোচ্চ ৩ সেকেন্ড অপেক্ষা করে এবং কোনো অ্যাকাউন্টের উত্তর আসামাত্র সেটি দেখায়।

এই এন্ডপয়েন্ট প্রকাশ্যে ডকুমেন্ট করা নয় এবং বদলে যেতে পারে। কোনো অনুরোধ ব্যর্থ হলে ccam সর্বশেষ জানা সংখ্যাগুলো দেখায় এবং সেগুলোকে ক্যাশ করা হিসেবে চিহ্নিত করে। ওই সংখ্যাগুলো সংরক্ষণের পর যে উইন্ডো রিসেট হয়েছে, সেটি ০% দেখায়। রেসপন্সের ফরম্যাট বদলে গেলে `ccam doctor` আপনাকে জানায়।

Claude Code যখন কোনো সেশন ব্যবহারের সীমায় থামিয়ে দেয়, [ccam প্লাগইন](/docs/install#claude-code-plugin) রেকর্ড করে কোন উইন্ডো পূর্ণ হয়েছিল এবং কখন তা রিসেট হবে। ততক্ষণ অন্য সংখ্যা যা-ই বলুক, ওই উইন্ডো ১০০% দেখায়, তাই `ccam next --auto` ও `--fallback` অ্যাকাউন্টটিকে খুব তাড়াতাড়ি আবার বেছে নেয় না।

৬০ সেকেন্ডের কম আগে আনা সংখ্যা আবার ব্যবহার করা হয়। অপশন:

| অপশন | প্রভাব |
| --- | --- |
| `--watch[=seconds]` | ক্রমাগত রিফ্রেশ করে, ডিফল্টভাবে প্রতি ৬০ সেকেন্ডে |
| `--json` | মেশিনে পড়ার উপযোগী আউটপুট |
| `-v` | প্রতিটি অ্যাকাউন্টের সংখ্যা কোথা থেকে এসেছে তাও দেখায় |
| `--no-cache` | সবসময় আবার অনুরোধ পাঠায় |
| `--source cache` | কখনও অনুরোধ পাঠায় না; শুধু সংরক্ষিত সংখ্যা দেখায় |

## মেয়াদোত্তীর্ণ লগইন

কোনো অ্যাকাউন্টের অ্যাক্সেস টোকেনের মেয়াদ শেষ হলে ccam সেটি নবায়ন করে না, কারণ কোনো Claude Code সেশন একই লগইন ব্যবহার করার সময় নবায়ন করলে ওই সেশনটি সাইন আউট হয়ে যেতে পারে। অ্যাকাউন্টটি দেখায় ``access token expired; `ccam <name>` renews it when it starts``: `ccam <name>` দিয়ে এটি একবার চালু করুন, Claude Code সেটি নবায়ন করবে। যে লগইনের মেয়াদ পুরোপুরি শেষ হয়ে গেছে, অথবা যা Claude Code মুছে দিয়েছে, তা দেখায় `` login expired → `ccam login <name>` `` এবং তার জন্য নতুন করে লগইন লাগে।

`ccam usage --refresh` মেয়াদোত্তীর্ণ টোকেন নিজেই নবায়ন করে, কিন্তু শুধু সেই অ্যাকাউন্টগুলোর জন্য যেগুলোর কোনো Claude Code সেশন চলছে না, সেশনটি যেভাবেই চালু হোক। macOS Keychain-এ বা ইমপোর্ট করা `~/.claude`-এ সংরক্ষিত লগইন এটি কখনও নবায়ন করে না, এবং একটি নবায়নে ৩০ সেকেন্ড পর্যন্ত লাগতে পারে।

## স্ট্যাটাস লাইনে ব্যবহার

```sh
ccam statusline install
```

এরপর Claude Code স্ট্যাটাস লাইনে অ্যাকাউন্টের নাম ও তার ব্যবহার দেখায়, যেমন `[work] · Opus · 5h 24% · 7d 41%`। ৯০% থেকে লাইনটি `ccam next --auto --continue`-ও প্রস্তাব করে। আপনার আগে থেকেই কোনো স্ট্যাটাস লাইন কমান্ড থাকলে ccam সেটি রেখে দেয় এবং সামনে অ্যাকাউন্টের নাম বসায়। স্ট্যাটাস লাইন তার সংখ্যাগুলোও সংরক্ষণ করে, এন্ডপয়েন্ট উত্তর না দিলে `ccam usage` সেগুলো ব্যবহার করে।

## অ্যাকাউন্ট বদল

```sh
ccam next             # the account after the one you used last
ccam next --auto      # the account with the lowest 5-hour usage
ccam next --continue  # continue this folder's conversation on the next account
```

`ccam next` লগইন না করা অ্যাকাউন্টগুলো বাদ দেয়, আর `--auto` ১০০%-এ থাকা অ্যাকাউন্ট (Claude Code যে উইন্ডোকে পূর্ণ বলে জানিয়েছে, তার রিসেট পর্যন্ত সেটিসহ) ও অন্য প্রতিষ্ঠানের অ্যাকাউন্টগুলো বাদ দেয়। দুটি অ্যাকাউন্ট কথোপকথনের ইতিহাস শেয়ার করলে `--continue` একই কথোপকথনটি খোলে; না করলে Claude Code সেটি নতুন অ্যাকাউন্টে কপি করে। দেখুন [শেয়ার করা](/docs/sharing) ও [পরের অ্যাকাউন্টে বদল](/features/next#continue)।

`config.toml`-এর একেবারে ওপরে `auto_switch = true` থাকলে (Linux ও macOS; ডিফল্টভাবে বন্ধ), Claude Code কোনো ইন্টারঅ্যাকটিভ সেশন তার সীমায় থামালে এবং একই ধরনের অন্য একটি অ্যাকাউন্টে (একই প্রতিষ্ঠানের একটি সিট, বা অন্য একটি ব্যক্তিগত প্ল্যান) জায়গা থাকলে ccam এই বদলটি নিজেই করে। এটি কখন কাজ করে এবং কী কখনও করে না, তা জানতে দেখুন [`auto_switch`](/features/next#auto-switch)।

`claude -p` চালানো স্ক্রিপ্ট ও নির্ধারিত কাজের জন্য অ্যাকাউন্টের নামের আগে `--fallback` দিন। ওই অ্যাকাউন্ট তার সীমায় পৌঁছালে ccam একই কমান্ড সবচেয়ে বেশি জায়গা থাকা অ্যাকাউন্ট হিসেবে আবার চালায়, এবং শুধু যে রানটি শেষ হয়েছে তার আউটপুট প্রিন্ট হয়:

```sh
ccam --fallback work -p "review the diff" --output-format json
```

ccam কীভাবে সিদ্ধান্ত নেয় তা জানতে [সীমায় আবার চালানো](/features/next#run-again-at-the-limit) দেখুন।
