প্রতিটি অ্যাকাউন্ট নিজের লগইন রাখে। বাকি সবকিছু আইটেম ধরে ধরে শেয়ার করা যায়: ccam অ্যাকাউন্টের ফাইল বা ফোল্ডারকে একটি শেয়ার করা গ্রুপ ফোল্ডারের সঙ্গে লিংক করে, তাই একটি অ্যাকাউন্টে করা পরিবর্তন ওই গ্রুপের সব অ্যাকাউন্টে দেখা যায়।

## কী কী শেয়ার করা যায়

| আইটেম | অপশন | কী শেয়ার হয় |
| --- | --- | --- |
| MCP সার্ভার | `--mcp` | গ্রুপের `mcp.json`, চালু হওয়ার সময় Claude Code-কে দেওয়া হয় |
| সেটিংস | `--settings` | `settings.json`: অনুমতি, হুক, মডেল, স্ট্যাটাস লাইন |
| গ্লোবাল মেমরি | `--memory` | `CLAUDE.md` |
| এক্সটেনশন | `--extensions` | `agents/`, `commands/`, `skills/`, `plugins/`, `output-styles/`, `rules/` |
| কথোপকথনের ইতিহাস | `--history` | `projects/` ও `history.jsonl` |

নতুন অ্যাকাউন্ট কথোপকথনের ইতিহাস ছাড়া বাকি সবকিছু শেয়ার করে।

লগইন ফাইল `.credentials.json` ও `.claude.json` কখনও শেয়ার হয় না। ccam শুধু একটি নির্দিষ্ট তালিকার পাথ লিংক করে, আর এই দুটি সেই তালিকায় নেই।

## গ্রুপ

`on` মানে `default` গ্রুপ। আপনি একটি নামও দিতে পারেন, যাতে শুধু কিছু অ্যাকাউন্ট একটি আইটেম শেয়ার করে:

```sh
ccam share work --history team
ccam share side --history team
```

এখন `work` ও `side` নিজেদের মধ্যে কথোপকথন শেয়ার করে, কিন্তু আপনার অন্য অ্যাকাউন্টগুলোর সঙ্গে নয়।

## শেয়ার চালু করা

কোনো অ্যাকাউন্ট একটি আইটেম শেয়ার করা শুরু করলে ccam:

1. যে ফাইলগুলো সরাবে, কপি করবে বা লিংক করবে তার একটি পরিকল্পনা প্রিন্ট করে, এবং শুরু করার আগে জিজ্ঞেস করে;
2. গ্রুপ এখনও খালি থাকলে অ্যাকাউন্টের ফাইলগুলো গ্রুপ ফোল্ডারে সরায়, অথবা গ্রুপে যে ফাইলগুলো এখনও নেই সেগুলো যোগ করে;
3. একই ফাইল আলাদা হলে জিজ্ঞেস করে গ্রুপের সংস্করণ রাখবেন, আপনারটি ব্যবহার করবেন, নাকি JSON মার্জ করবেন;
4. আপনার মূল ফাইলটি অ্যাকাউন্ট ফোল্ডারের ভেতরে `.ccam-backup/<time>/`-এ রাখে;
5. মূল ফাইলটিকে গ্রুপের একটি লিংক দিয়ে প্রতিস্থাপন করে।

কথোপকথনের ফাইলের নাম তাদের সেশন ID অনুযায়ী হয়, তাই একাধিক অ্যাকাউন্টের ইতিহাস কোনো দ্বন্দ্ব ছাড়াই একত্র হয়।

## শেয়ার বন্ধ করা

```sh
ccam share work --history off
```

লিংকটি সরানো হয় এবং অ্যাকাউন্টটি গ্রুপের বর্তমান বিষয়বস্তুর নিজস্ব একটি কপি পায়। এর বদলে খালি অবস্থা থেকে শুরু করতে `--fresh` যোগ করুন। অন্য অ্যাকাউন্টগুলোর জন্য গ্রুপ তার বিষয়বস্তু রেখে দেয়।

## MCP সার্ভার

Claude Code MCP সার্ভারগুলো লগইনের সঙ্গে একই `.claude.json`-এ রাখে, তাই ওই ফাইল শেয়ার করা যায় না। ccam শেয়ার করা সার্ভারগুলো গ্রুপের `mcp.json`-এ রাখে এবং `--mcp-config=<group>/mcp.json` দিয়ে Claude Code চালু করে। আপনার নিজের `--mcp-config` অপশনগুলো এর ওপরে প্রযোজ্য থাকে।

```sh
ccam mcp add fs -- npx -y @modelcontextprotocol/server-filesystem ~/code
ccam mcp list
```

সেশনের ভেতরে `claude mcp add` দিয়ে যোগ করা সার্ভার শুধু ওই অ্যাকাউন্টের জন্য সংরক্ষিত হয়। পরের বার ওই অ্যাকাউন্ট চালু করলে ccam সার্ভারটির নাম এবং সেটিকে গ্রুপে সরানোর কমান্ড দেখায়:

```sh
ccam mcp import work gh
```

যে MCP সার্ভারগুলো OAuth দিয়ে সাইন ইন করে, সেগুলো তাদের টোকেন অ্যাকাউন্টের লগইনের সঙ্গে রাখে, তাই প্রতিটি অ্যাকাউন্টে একবার করে সেগুলো অনুমোদন করুন।

সার্ভারগুলো যদি আপনি `claude mcp list` ও `/mcp`-এ সাধারণ ব্যবহারকারী সার্ভার হিসেবে দেখতে চান, তাহলে `~/.config/ccam/config.toml`-এ `mcp_strategy = "sync"` নির্ধারণ করুন। তখন ccam চালু করার আগে সেগুলো প্রতিটি অ্যাকাউন্টের `.claude.json`-এ লেখে, Claude Code-এর নিজস্ব ফাইল লকের অধীনে এবং একটি ব্যাকআপসহ।

## একই ফোল্ডারে দুটি অ্যাকাউন্ট

যে অ্যাকাউন্টগুলো কথোপকথনের ইতিহাস শেয়ার করে, সেগুলো একই ফাইলে লেখে। একই গ্রুপের অন্য একটি অ্যাকাউন্ট যে ফোল্ডারে আগে থেকেই চলছে, সেখানে দ্বিতীয় একটি Claude Code চালু করলে ccam আপনাকে সতর্ক করে এবং চালিয়ে যাবেন কি না জিজ্ঞেস করে।

## কিছু ভেঙে গেলে

```sh
ccam doctor
ccam doctor --fix
```

কোনো শেয়ার করা পাথ যদি সাধারণ ফাইলে পরিণত হয়, যেমন আপনি হাতে একটি ব্যাকআপ পুনরুদ্ধার করার পর, তাহলে ccam Claude Code চালু করার আগেই থেমে যায় এবং `ccam doctor --fix` দেখিয়ে দেয়, যা ফাইলটিকে গ্রুপে মার্জ করে এবং একটি ব্যাকআপ রাখে।
